# C0-使用总览：回想内核专家

## 能力清单

| 能力 | 说明 | 入口 |
|---|---|---|
| 多轮回想 | 模型带工具循环找证据并给出 why | runGroundedRecall |
| 快路径 | 确定性种子召回 | runFastRecall |
| 范围解析 | 库名/视图/逗号多值归一、逐次鉴权、视图展开 | resolveRecallTargets |
| 预算与频控 | 次数、超时、并发槽与 20 次/分钟限流 | resolveRecallConfig / acquireRecallSlot |
| 候选组装 | why / nextActions / 读正文门禁 | buildWhy / buildNextActions |
| 内核错误 | 8 个内核码 + 12 个工具码与映射表 | RecallKernelError / toolCodeForKernel |
| 审计 | stderr 单行 JSON 带 [recall] 前缀 | recallLog |

## 能力边界（本专家不做什么）

- 不实现混合检索与原文定位：由只读工具调检索与向量客户端专家
- 不实现 LLM SDK：经 llm-client 注入
- 不实现 Web 界面：归可视化前端专家
- 不写磁盘日志：recallLog 只进 stderr

## 已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|---|---|---|
| 漏传 scope 拿不到可用清单 | 把 zod scope 改回 .required() | 保持 .optional()，由 executeRecall 判空回 RECALL_SCOPE_REQUIRED + available |
| 视图名检索全被丢 | 拿 targets 去做 IO/可见性 | 用 physicalTargets（视图展开，最多 12 个物理库） |
| 改了超时仍被截断 | 只改一侧 | 生效值 = min(find.timeoutMs, recall.hardTimeoutMs) |
| 改 maxRounds 没生效 | rounds 是安全阀 30，不是预算 | 改 find.maxToolCalls（默认 15） |
| 去 ~/.ki/chat 找 recall 日志无果 | 以为有落盘日志 | recallLog 写 stderr 单行 JSON |
