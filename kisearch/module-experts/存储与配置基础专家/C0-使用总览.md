# C0-使用总览：存储与配置基础专家

## 能力清单

本专家覆盖 kisearch 的**数据落盘与配置基座**，提供以下能力：

| 能力 | 说明 | 入口 |
|------|------|------|
| JSON 存储读写 | 带 version 兼容检查的 `readJson` / `writeJson`（自动补 version + updatedAt） | `lib/store.ts` |
| WAL 原子写入 | 临时文件 + 原子 rename + 跨进程文件锁，保证并发安全 | `lib/wal.ts` |
| scope 校验与路径 | scope 合法性校验、kb/{scope} 各 JSON 路径构造、旧格式迁移、scope 生命周期 CLI | `lib/scope.ts` + `src/scope.ts` |
| 配置加载 | YAML/JSON 配置查找、`${ENV_VAR}` apiKey 解析、scope 护栏解析、默认路径恒为 `~/.ki` | `lib/config.ts` |
| 配置字段级校验 | 配置字段名 / 类型 / 取值校验（未知字段 fail-loud 附拼写建议，废弃字段与空值仅告警） | `lib/config-schema.ts` |
| 备份 | scope 目录 tar.gz 快照 + 导入后自动备份 | `lib/backup.ts` |
| 还原 | 从快照覆盖还原 + 可选向量重建 | `src/restore.ts` |
| 导出 | KB → Wiki Markdown 目录（支持 `--group` 子树导出） | `src/export.ts` |
| 诊断 | `ki doctor` 配置健康检查（配置字段 / 可写性 / embedding 连通性 / 维度） | `lib/health-check.ts` |
| 预检 | 写操作前的可写性 / 磁盘空间校验 | `lib/preflight.ts` |
| CLI 参数 | 未知 flag 检测、JSON 错误契约、数值参数解析 | `lib/cli-args.ts` |
| 初始化 | `ki config init` 生成配置（同时创建 dataDir / backupDir / vectorDir） | `src/config.ts` |

> 已移除能力（基线后代码已删除，勿再按旧文档使用）：`lib/diff.ts` 增量 diff（`ki scan-kb diff` 子命令已删）、`src/setup.ts`（Skill 下载）、`src/migrate-keywords.ts`（关键词迁移）、ai-results 备份与 `--from-results` 重放。

## 能力边界（本专家不做什么）

- **不提供**向量检索 / 向量写入接口（由"检索与向量客户端专家"负责，本专家仅通过 `lib/vector-client` 的 `closeEngine` 做生命周期管理）
- **不提供**关系评分 / Group 树业务逻辑（由"关系与索引管理专家"负责）
- **不提供**知识导入 5-Phase 流程（由"知识索引导入专家"负责）
- **不自动备份**：WAL 只保证单次写入原子性，整体备份由用户或 `autoBackup` 显式触发

## 已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|------|----------|----------|
| JSON 文件损坏报 `CORRUPT_JSON` | 手动编辑或进程崩溃导致 JSON 语法错误 | 从备份恢复或 `ki restore` 重建 |
| `ensureScopeDir` 报 scope 未注册 | `scopeMode: strict` 且 scope 不在配置 `scopes` 白名单 | 在配置 `scopes` 中注册后再用 |
| `walWrite` 卡住约 10s 后抢占锁 | 另一进程长时间持锁（超过 10s） | 等待或排查持锁进程；锁陈旧（>30s）会自动抢占 |
| `tar` 命令不可用 | 精简环境无 tar（如部分容器） | 安装 tar（无替代备份通道：ai-results 备份已移除） |
| `setSource` 报 group-index.json 不存在 | 未先执行 `ensureScopeDir` | 先建目录再写 source 块 |
| 备份文件带 `-1` / `-2` 后缀 | 同一秒内多次备份撞名 | 属正常防覆盖行为，无需处理 |
| 配置读到 JSON 提示迁移 | 存在 `config.json` | 建议执行 `ki config init` 生成 YAML |
| 启动报 `CONFIG_FIELD_INVALID: 配置文件字段校验失败` | 配置字段名拼错 / 类型写错 / 枚举值非法（如 `datadir`、`dimension: "4096"`、`scopeMode: strick`） | 按错误列出的字段路径逐项修正，拼写类会附「您是否想输入 "xxx"」建议；超过 10 处只显示前 10 |
| 配置字段写了却不生效 | 用了 YAML 合并键 `<<: *anchor`（解析器不展开）或整段复制文档字段概览导致值为 null | 显式写出字段；整值引用 `*anchor` 可用；跑 `ki doctor` 看「配置字段」告警项 |
| 升级后数据「不见了」 | 默认数据目录已统一为 `~/.ki/kb`（原 `{项目根}/kb`、`~/.ki-data` 不再继承） | 手动迁移旧数据到 `~/.ki/kb`，或在配置中显式指定 `dataDir` |
| `ki scope delete/clear` 报「向量服务暂不可用…拒绝删除」 | 向量库锁被占用或 embedding 环境缺失 | 先确认向量服务可用（`ki scope list` 看 `vectorAvailable`）；**这是刻意设计**——避免只删一层造成 KB/向量两层不一致，不要绕过 |

## 子专家导航

无子专家。本专家为全项目共享的数据与配置基座，其他专家（检索、导入、关系、MCP）均依赖本专家的 `store` / `scope` / `config` / `wal` 能力。
