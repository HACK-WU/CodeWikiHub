## 简介

本文件描述本专家涉及的持久化数据模型与配置结构，供理解数据格式与兼容策略。

## 配置数据模型

`KiConfig`（`config.ts`）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `dataDir` | string | KB 源数据目录（默认 `~/.ki/kb`） |
| `backupDir` | string | 备份根目录（默认 `~/.ki/backup`） |
| `vectorDir` | string | zvec collection 目录（默认 `~/.ki/vector`） |
| `embedding` | `EmbeddingConfig` | `{provider, baseURL, model, dimension, apiKey?}`（provider 不校验枚举，实际提供商由 baseURL 决定） |
| `scopeMode` | `'default' \| 'strict'` | scope 护栏模式 |
| `scopes` | `Record<string, ScopeConfig>` | scope 级配置（见下） |
| `mcp?` | `McpConfig` | `{http: {host?, port?, allowedHosts?}}`（token 不入配置） |
| `_fieldWarnings?` | `ConfigIssue[]` | 字段校验告警（废弃字段 / null scope 条目 / 空字符串），不阻断加载，由 doctor 报告 |
| `_configPath?` | string | 配置文件路径（内部，缺省表示用的是内置默认值） |

**`ScopeConfig`**（`scopes.<name>`）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `kbDir?` | string | scope 级 KB 目录；实际数据落 `{kbDir}/kb/{scope}`（避免污染源码目录） |
| `wikiSync?` | `WikiSyncConfig` | `{enabled, sourceDir?, autoBackfill?}`；enabled/autoBackfill 缺省 true |
| `clean?` | `CleanConfig` | `{enabled, rules?: {bom, frontmatter, htmlComment, mermaid, codePath, codeBlock, emptyChunk, keepShortSamples}, hooks?: string[]}`（清洗实现在导入专家 `lib/clean.ts`，本专家只负责配置解析） |
| `import?` | `ImportConfig` | `{extensions?: string[], maxFileSize?: number}` |

**设计约束**：
- `embedding.apiKey` 支持明文或 `${ENV_VAR}` 引用；`${VAR}` 未设置返回 `undefined`（不做隐式回退）
- `scopeMode` 仅 `'strict'` 启用严格模式，其余（含非法值）归 `'default'`
- MCP token 绝不写入配置文件（安全约定）
- **默认路径恒为 `~/.ki` 用户数据根，不做存量路径继承**；scope 级 `sourceDir` 已删（废弃字段，仅告警）

## 配置校验 Schema 模型

`config-schema.ts` 用声明式 `ConfigNode` 树描述配置结构（与 `docs/configuration.md` 字段表一一对应）：

| `ConfigNode` 字段 | 作用 |
|------|------|
| `type` | `'string' \| 'number' \| 'boolean' \| 'object' \| 'stringArray' \| 'literal'` |
| `values?` | `literal` 的候选值（如 `scopeMode: ['default','strict']`） |
| `fields?` | 固定键对象子表（如 `embedding` 的 provider/baseURL/...） |
| `value?` | 自由键 map 的值节点（如 `scopes` → `SCOPE_ENTRY`） |
| `nullHandling?` | map 条目为 null 时的处理（scopes：降级为 warn） |
| `deprecated?` | 已知废弃字段 → 迁移说明（scope 级 `sourceDir`），命中只告警 |
| `validate?` | 类型通过后的取值校验（`positiveInt` / `portRange` 1-65535 / `httpUrl`） |

问题模型：`ConfigIssue {path, message}`，`path` 为配置文件内字段路径（如 `scopes.monitor.wikiSync.enabled`）。

**归类规则**：未知字段 / 类型不符 / 非法枚举 / 取值非法 / `<<` 合并键 / 空 scope 名 → `errors`（阻断）；废弃字段 / null scope 条目 / 空字符串值 → `warns`；根层 `x-` 前缀键 → 放行不校验。

章节来源：[src/lib/config-schema.ts](file:///root/knowledge-indexer/src/lib/config-schema.ts)（`ConfigNode` / `CONFIG_SCHEMA` / `SCOPE_ENTRY` / `ConfigIssue`）

## GroupIndex 数据模型

`GroupIndex`（`scope.ts`）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `version` | number | 数据版本（当前 1） |
| `scope` | string | scope 名 |
| `groups` | `Record<string, Record<string, unknown>>` | Group 树（嵌套对象） |
| `updatedAt` | string \| null | 更新时间 |
| `source?` | `GroupIndexSource \| null` | `{dir, chunkSize?, chunkOverlap?}` 知识源目录 + 切分参数 |

**旧格式迁移**：`roots` 结构 → `groups` 结构（`migrateGroupIndex`）：
- `roots['项目根']` 的子节点平铺进 `groups`
- 其他 root 保留为一级 `groups[key]`

## RelationsCache 数据模型

`relations-cache.json`（由 `lib/store.ts::writeJson` 维护，结构在业务侧定义）：

```jsonc
{
  "version": 1,
  "scope": "myproj",
  "partition_config": { "hotPercent": 0.3, "warmPercent": 0.5, ... },
  "groups": {
    "项目/API": {
      "hot_relations": [
        { "id": "r1", "text": "用户登录接口", "score": 10, "useCount": 3,
          "lastUsedTime": 1720000000000, "isImported": true,
          "memoryId": "abc...", "sourcePath": "docs/api.md", "isFullText": true }
      ],
      "keywords": ["登录", "认证"],
      "max_hot_count": 10
    }
  },
  "updatedAt": "2026-08-06T00:00:00.000Z"
}
```

**要点**：所有 JSON 均含 `version` 字段（当前 1）；Relation 含 `memoryId` / `sourcePath` / `isFullText` 定位字段。

## 常量与版本

`constants.ts`：
- `CURRENT_DATA_VERSION = 1`：所有 JSON 数据版本
- `MIN_RECORD_INTERVAL_MINUTES = 5` / `MAX_USE_COUNT = 10`：评分防刷参数
- `DEFAULT_PARTITION_CONFIG`：冷热分区配置（hotPercent 0.3 / warmPercent 0.5 / recentHours 48 等）
- `DEFAULT_ROOT_NAME = '项目根'`：默认根节点（仅供旧格式 `roots` 迁移识别）
- `DEFAULT_TAGS = ['ki-search', 'ki-path', 'ki-relation']`：默认查询标签
- `SERVICE_NAME = 'kisearch'`：服务身份标识（healthz / McpServer name / 探活判断共用）
- `parseContentTags(tags?)`：逗号分隔解析自定义 tags，去空去重并过滤内部保留标签
- `KI_ROOT` / `TEMPLATE_DIR`：项目根与模板目录（包内置）
- `getKbBaseDir()`：延迟初始化的 KB 运行时根目录（取 `loadConfig().dataDir`）

> `DiffEntry` / `DiffResult` / `NoSourceResult` 等 diff 模型已随 `lib/diff.ts` 删除。

## 结论

本专家的数据模型统一带 `version` 版本号（支持向前兼容读取与旧格式迁移）；配置模型区分 `scopeMode` 护栏与 `mcp` token 隔离策略，并由声明式 `ConfigNode` schema 在加载期做字段级把关，为全项目数据一致性提供基础。
