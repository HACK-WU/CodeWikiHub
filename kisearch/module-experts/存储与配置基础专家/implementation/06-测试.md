## 简介

本文件描述存储与配置基础专家的测试资产：位置、覆盖、可执行性与缺口。

## 测试位置与框架

| 测试文件 | 覆盖范围 | 框架 |
|----------|----------|------|
| `test/config-doctor.test.ts` | A 段：config 解析与 `scope` 可选字段；**A2 段：config-schema 字段级校验**（未知字段/拼写建议/废弃字段/类型与取值/告警不阻断）；D 段：doctor CLI 退出行为 | jiti + node:assert |
| `test/restore.test.ts` | restore 命令（快照还原 / 向量重建 / 参数校验） | jiti + node:assert |
| `test/scope-mode.test.ts` | scopeMode default/strict 护栏 | jiti + node:assert |
| `test/scope-source.test.mjs` | source 块读写 | node --test |
| `test/scope-isolation.test.ts` | scope 数据隔离 | jiti + node:assert |
| `test/lib.test.ts` | store/scope 等基础库 | jiti + node:assert |
| `test/error-handling.test.ts` | 错误处理（CORRUPT_JSON 等） | jiti + node:assert |
| `test/scope-doc.test.ts` | scope 相关文档/命令 | jiti + node:assert |

运行命令：
```bash
npx jiti test/config-doctor.test.ts        # .ts 用 jiti
node --test test/scope-source.test.mjs     # .mjs 用 node --test
npm run test:all                           # 全量
# ⚠️ 本机跑测试建议剥离 IDE 注入（见下「环境依赖」）
env -u NODE_OPTIONS -u BASH_ENV npx jiti test/config-doctor.test.ts
```

## 覆盖模式

- **WAL 写入**：`lib.test.ts` 覆盖 writeJson 原子性、version 自动补齐
- **scope 校验**：`scope-mode.test.ts` 覆盖 default/strict 两种模式、非法字符拒绝
- **配置字段校验**（A2 段，新增重点）：顶层拼写错误附建议、scope 内未知字段列出可用字段、废弃 `sourceDir` 只告警、自由键 scope 名不误伤、`x-common` 锚点模板放行、`<<` 合并键报错、类型错误（数字/布尔/数组/对象四类）、空值告警、根节点非对象
- **健康检查**：`config-doctor.test.ts` 覆盖各检查项 pass/warn/fail 分支，含新增的「配置字段」项（无告警 pass / 有告警 warn 且带字段路径）
- **doctor CLI 退出行为**：字段类型错误 → 非零退出且 stderr 列出字段路径
- **还原**：`restore.test.ts` 覆盖快照还原与向量重建（含文件系统操作）
- **source 块**：`scope-source.test.mjs` 覆盖 getSource/setSource 与迁移

## 测试可执行性

- **运行命令**：见上表；`.ts` 用 jiti，`.mjs` 用 node --test
- **环境依赖**：
  - `config-doctor.test.ts` 的 embedding 检查 ⚠️ 依赖真实 `SILICONFLOW_API_KEY`（无 key 时走"未配置"分支，仍可跑但覆盖面降级）
  - `restore.test.ts` ⚠️ 依赖文件系统（生成临时 scope）；向量重建分支需 embedding 环境
  - ⚠️ **IDE 注入陷阱**：`NODE_OPTIONS=--require node-language-shim.cjs` 会拦截 fs，批量文件操作可能挂起等确认。测试框架已在 `test/test-config.ts::getTestEnv()` 剥离 `NODE_OPTIONS`/`BASH_ENV`，本机手工跑建议 `env -u NODE_OPTIONS -u BASH_ENV`
- **已知失败**：当前无已知失败（详见 `test/known-failures.md`）

## 测试缺口

- `setSource` 未走 WAL 的行为无专门测试（并发写场景）
- `preflight.ts` 的 `estimateDirSize` / `checkDiskSpace` 边界用例较少（跨平台 statfs 差异）
- `backup.ts` 的 `avoidCollision` 极端兜底（毫秒时间戳分支）未覆盖
- `cli-args.ts` 的 `detectUnknownFlags` 近似建议阈值分支覆盖不足
- `src/scope.ts` 的 `scope delete` / `clear` 无独立单测（依赖向量服务，向量不可用分支未覆盖）
- `walWrite` 的同步阻塞语义（等锁 10s 抢占 / 陈旧锁 30s）无并发测试

## 结论

本专家测试覆盖核心读写/配置字段校验/还原路径，可执行性良好（⚠️ embedding 与文件系统场景依赖外部环境）；字段级校验（A2 段）是本次新增的覆盖重点。已知缺口集中在并发写、预检边界与 scope 生命周期，建议后续补充。
