## 简介

本文件描述本专家的运维面：配置初始化、备份恢复、诊断、迁移与环境依赖。

## 配置管理

**初始化**：`ki config init [--dir <path>] [--force]` 生成 `<dir|HOME>/.ki/config.yaml`（dataDir/backupDir/vectorDir/embedding/scopeMode/scopes），并尝试创建三个数据目录；已存在时返回 `existed:true` 不覆盖（除非 `--force`）。

**配置查找优先级**：`--config` / `KI_CONFIG_PATH` > `~/.ki/config.yaml|yml|json` > 内置默认值（stderr 提示一次）。

**默认数据目录**：统一 `~/.ki` 用户数据根——`dataDir=~/.ki/kb`、`backupDir=~/.ki/backup`、`vectorDir=~/.ki/vector`。**不做存量路径继承**（旧的 `{项目根}/kb`、`~/.ki-data` 需手动迁移或显式配 `dataDir`）。`KI_DATA_DIR` 仅 `config init` 模板探测生效，运行时不读。

**字段级校验**：字段名/类型/取值非法在加载期 fail-loud（`CONFIG_FIELD_INVALID`，逐项列字段路径 + 拼写建议）；废弃字段与空值走告警，由 `ki doctor` 的「配置字段」项报告。新增配置字段须同步更新 `src/lib/config-schema.ts`。

**apiKey 管理**：
- 明文 `sk-xxx` 或 `${ENV_VAR}` 引用
- 不做隐式环境变量回退（避免跨厂商注入）
- MCP 场景必须在客户端 `env` 字段显式传入 `SILICONFLOW_API_KEY`（MCP 进程不继承 shell 环境）

**scope 白名单**：`scopeMode: strict` 时在配置 `scopes` 中注册；`ki scope delete` 会经 `removeScopeFromConfigFile` 清理配置条目。

## 备份与恢复策略

**备份**：
- `ki backup <scope>`：手动快照备份（tar.gz）
- 导入成功后 `autoBackup` 自动打快照（失败仅 stderr 警告，不阻断导入）
- 备份布局：`<backupDir>/<scope>/snapshots/snapshot.{ts}.tar.gz`（ai-results 子目录已废弃）

**恢复**：
- `ki restore <scope> [--list]`：列出可用备份
- `ki restore <scope> --from-snapshot --yes`：快照覆盖还原（破坏性）；可加 `--timestamp <ts>` 指定快照、直接给 `--from-snapshot <file>` 指定文件
- `ki restore <scope> --rebuild-vector [--group <path>] [--tags t1,t2] --yes`：还原后（或独立）重建向量
- `--backup-dir <dir>` 只控制「从哪读」；还原前安全网快照始终写受管默认 `backupDir`

**运维建议**：定期对 `backupDir` 做 rsync/tar 异地备份；还原前先备份当前状态（命令已自动打安全网快照，异地仍需人工）。

## 诊断与监控

**`ki doctor`**：配置健康检查（等价 `runHealthCheck`，共 11 项）：
- 配置文件存在且字段合法、**配置字段告警**、dataDir/backupDir/vectorDir 可写、apiKey、embedding 连通性/密钥/维度、zvec collection、scopes.default
- 只读；有失败项退出码 1（可作 CI gate）；`-h/--help` 退出 0
- 字段校验失败在 `loadConfig` 阶段即退出 1，不进入健康检查（输出字段路径清单 + docs 指引）

**`ki mcp` 启动预检**：复用同一检查逻辑，报告写 stderr（不污染 stdio）；存在 ❌ 拒绝启动。

**版本兼容**：所有 JSON 带 `version` 字段；读取时 `version > CURRENT_DATA_VERSION` 仅警告；旧格式 `roots` 自动迁移为 `groups`。

## 数据迁移与清理

- **旧默认路径迁移**：升级后数据默认改落 `~/.ki/kb`，旧的 `{项目根}/kb`、`~/.ki-data` **不自动继承**——需手动迁移或显式配置 `dataDir`
- **旧格式自动迁移**：`roots → groups`（`readGroupIndex` 触发，同时把 relations-cache 中 `项目根/` 前缀的 key 重命名或按 `text` 去重合并）
- **旧 kbDir 语义提示**：scope 配了 `kbDir` 且旧路径下仍有 `group-index.json` 时，`ensureScopeDir` 会 stderr 警告「kbDir 语义已变更，数据应位于 `{kbDir}/kb/{scope}`」
- **scope 清理**：`ki scope list` 查看三层（KB / 向量 / 配置注册）并集；`ki scope clear <name> --yes` 清空数据保留 scope（带 `--tags` 只清向量层）；`ki scope delete <name> --yes` 彻底摘除（清向量 + 删 KB 目录 + 移除配置条目，`default` 不可删）

## 环境依赖

| 依赖 | 用途 | 缺失影响 |
|------|------|----------|
| `tar` 命令 | 快照打包 / 解包 | backup、restore 报错提示安装（无替代通道） |
| `SILICONFLOW_API_KEY`（或自定义 `${VAR}`） | embedding 检查与向量重建 | doctor 报 apiKey 失败；restore `--rebuild-vector` 不可用 |
| Node ≥ 18（statfsSync 需 18.15+） | 运行时 / 磁盘预检 | 低版本磁盘预检自动跳过 |
| `npx` + `jiti` | 执行 TS | 无法运行 CLI |

> `git` 已不再是本专家依赖：增量 diff 随 `lib/diff.ts` 删除，source 块不再记录 commit。

## 结论

本专家运维面聚焦"配置可初始化且字段可校验、数据可备份/恢复、环境可诊断、格式可迁移、scope 可清理"，为生产使用提供数据安全与可观测性保障。
