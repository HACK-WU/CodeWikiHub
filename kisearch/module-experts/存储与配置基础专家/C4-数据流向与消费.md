# C4-数据流向与消费：存储与配置基础专家

> 本专家是数据落盘基座，几乎所有 KB 数据文件都由本专家产生/维护，被其他业务模块消费。

## 数据实体总览

| 数据实体 | 来源接口 | 去向 | 消费方 | 业务用途 |
|----------|----------|------|--------|----------|
| `group-index.json` | `writeJson` / `ensureGroupPathInTree` / `setSource` | `kb/{scope}/group-index.json` | 知识索引导入专家（建树 / 写 source）、关系与索引管理专家（manage-index/query-group）、本专家（export 遍历 / scope list） | Group 树结构与 source 块（知识源目录 + 切分参数），支撑索引直查路径 |
| `relations-cache.json` | `writeJson`（`lib/store.ts`） | `kb/{scope}/relations-cache.json` | 关系与索引管理专家（sync-relation/delete-relation）、知识索引导入专家（写 memoryId）、检索与向量客户端专家（原文定位反查）、本专家（export / scope list 计数） | 关系热缓存（Relation + memoryId + sourcePath + isFullText），检索结果定位原文的核心索引 |
| local KB `index.json` | `writeJson` | `kb/{scope}/{groupPath}/index.json` | 关系与索引管理专家（get-module-info）、知识索引导入专家（写 moduleInfo）、本专家（export 收集） | 每个 Group 的 Markdown 原文（module-info），供模块信息查询交付原文 |
| 快照备份 | `backupScopeSnapshot` / `autoBackup` | `<backupDir>/<scope>/snapshots/snapshot.{ts}.tar.gz` | 本专家（`restore --from-snapshot`）+ 人工运维（rsync/tar 异地） | scope 数据目录整体快照，灾难恢复的唯一自动通道 |
| `~/.ki/config.yaml` | `src/config.ts`（init）/ `removeScopeFromConfigFile` | 配置文件（默认 `~/.ki/config.yaml`，`--config` 可覆盖） | 全项目所有模块（`loadConfig` 进程内缓存） | 全局配置（dataDir/backupDir/vectorDir/embedding/scopeMode/scopes/mcp）；加载前经 `config-schema` 字段级校验 |
| `_template/` 目录 | `initScope` | `_template/`（包内置） | 本专家（初始化新 scope） | scope 初始化模板 |

## 逐实体详述

### 1. group-index.json
- **来源接口**：`writeJson`（`lib/store.ts`）、`ensureGroupPathInTree`（`lib/scope.ts`）、`setSource`（`lib/scope.ts`）
- **去向**：`kb/{scope}/group-index.json`
- **消费方**（>3 归纳）：知识索引导入（建树、写 source）、关系与索引管理（manage-index 增删、query-group 查询）、本专家（export 遍历、scope list）；检索客户端通过 `getGroupIndexPath` 定位文件 [基于引用扫描，未深入验证]
- **业务用途**：维护 Group 树层级与知识源信息（source.dir + 切分参数），支撑索引直查路径与重导入基线

### 2. relations-cache.json
- **来源接口**：`writeJson`（`lib/store.ts`）
- **去向**：`kb/{scope}/relations-cache.json`
- **消费方**：关系与索引管理（sync-relation 写入、delete-relation 删除、query-group 热缓存）、知识索引导入（写 memoryId）、检索与向量客户端（memoryId 反查定位原文）、本专家（export 收集、scope list 计数）
- **业务用途**：关系热缓存——检索命中的 `memoryId` 反查得到 `{group, relation, keywords, isFullText}`，是"搜得到 + 定位到原文"的数据基石

### 3. local KB index.json
- **来源接口**：`writeJson`（`lib/store.ts`）
- **去向**：`kb/{scope}/{groupPath}/index.json`
- **消费方**：关系与索引管理（get-module-info 读原文）、知识索引导入（写 moduleInfo）、本专家（export 收集）
- **业务用途**：每个 Group 的 Markdown 原文存档，索引直查时 100% 精准命中交付

### 4. 快照备份（唯一自动备份通道）
- **来源接口**：`backupScopeSnapshot` / `autoBackup`
- **去向**：`<backupDir>/<scope>/snapshots/snapshot.{ts}.tar.gz`
- **消费方**：本专家（`restore --from-snapshot`）+ 人工运维（tar/rsync 异地备份）
- **业务用途**：数据灾备——导入成功后自动打快照，支持整体覆盖还原（ai-results 重放通道已移除，导入输入不再单独备份）

### 5. 配置文件（~/.ki/config.yaml）
- **来源接口**：`src/config.ts`（`ki config init`）、`removeScopeFromConfigFile`
- **去向**：配置文件（用户家目录）
- **消费方**：全项目所有模块（`loadConfig` 进程内缓存）[基于引用扫描，未深入验证]
- **业务用途**：全局配置基座——路径、embedding、scopeMode 护栏、scope 白名单、MCP 默认值

## 数据流图

```mermaid
flowchart LR
    A[用户/AI 输入] --> B[writeJson / walWrite]
    B --> C[(kb/{scope} JSON)]
    C --> D[知识导入专家]
    C --> E[关系管理专家]
    C --> F[检索客户端专家]
    C --> G[export / scope list]
    H[导入成功后] --> I[autoBackup 打快照]
    I --> J[(backupDir/{scope}/snapshots)]
    J --> K[restore --from-snapshot 还原]
    L[(~/.ki/config.yaml)] --> M[config-schema 字段校验]
    M --> N[loadConfig 缓存]
    N --> B
```
