# C1-能力契约：存储与配置基础专家

> 本契约覆盖本专家的公开能力。契约来源标注类名/方法签名（非行号）。
> 代码示例为使用方代码，API 签名真实，环境初始化可占位。

## 1. JSON 存储层（`lib/store.ts`）

### 1.1 `readJson<T>(filePath)`

- **用途**：读取 JSON 文件并做 version 兼容检查。
- **参数**：`filePath` — 绝对路径。
- **返回**：解析后的对象；**文件不存在返回 `null`**。
- **异常**：文件存在但解析失败时抛 `Error`（`code='CORRUPT_JSON'`）；解析成功但 `version > CURRENT_DATA_VERSION` 时仅 `console.warn` 不抛错。
- **约束**：文件不存在不抛错，调用方需处理 `null`。

```ts
// 假设已初始化 scope
import { readJson } from './lib/store.js';
const index = readJson('/path/to/kb/myproj/group-index.json');
if (index) console.log(index.version);
```

### 1.2 `writeJson(filePath, data)`

- **用途**：以 WAL 方式写入 JSON（自动补 `version` + `updatedAt`）。
- **参数**：`data` — 任意可序列化对象；`version` 缺失时自动补 `CURRENT_DATA_VERSION`。
- **返回**：`void`。
- **异常**：无自定义异常（内部走 `walWrite`）。
- **约束**：同步阻塞写入。

```ts
import { writeJson } from './lib/store.js';
writeJson('/path/to/file.json', { scope: 'myproj', items: [1, 2, 3] });
```

### 1.3 `readGroupIndex(scope)` / `ensureScopeDir(scope)` / `initScope(scope)`

- **`readGroupIndex(scope)`**：读 `kb/{scope}/group-index.json`，不存在返回 `null`。
- **`ensureScopeDir(scope)`**：确保 `kb/{scope}/` 存在；`strict` 模式下 scope 未注册抛 `ScopeError`。
- **`initScope(scope)`**：从 `_template/` 初始化新 scope；模板缺失抛错。
- **约束**：`scope` 必须通过 `validateScope` 字符校验。

```ts
import { ensureScopeDir, readGroupIndex } from './lib/store.js';
ensureScopeDir('myproj');
const idx = readGroupIndex('myproj');
```

## 2. WAL 原子写（`lib/wal.ts`）

### 2.1 `walWrite(filePath, data)`

- **用途**：以 WAL 语义写入文件：加跨进程锁 → 写 `.tmp` → 原子 rename → 释放锁。
- **参数**：`filePath` — 目标绝对路径；`data` — 序列化后的字符串。
- **返回**：`void`。
- **异常**：锁获取超时（10s）后视为对方异常退出并抢占，不抛错。
- **约束**：同步阻塞；`data` 应为已序列化的 JSON 字符串（`writeJson` 内部使用）。

```ts
import { walWrite } from './lib/wal.js';
walWrite('/path/to/file.json', JSON.stringify({ a: 1 }));
```

### 2.2 `cleanupTmpFiles(dir)`

- **用途**：清理目录下的残留 `.tmp` 文件（写入中断遗留）。
- **返回**：清理的文件数量。

```ts
import { cleanupTmpFiles } from './lib/wal.js';
const n = cleanupTmpFiles('/path/to/kb/myproj');
```

## 3. Scope 校验与路径（`lib/scope.ts`）

### 3.1 `validateScope(scope)`

- **用途**：校验 scope 合法性。
- **参数**：`scope` — 仅允许 `[a-zA-Z0-9_-]`。
- **异常**：空 → `ScopeError('EMPTY_SCOPE')`；含非法字符（如 `../`、空格）→ `ScopeError('INVALID_SCOPE')`。
- **约束**：所有路径构造函数都会先调用本函数。

```ts
import { validateScope } from './lib/scope.js';
try { validateScope('my-proj'); } catch (e) { /* 非法字符 */ }
```

### 3.2 路径构造函数

| 函数 | 返回 |
|------|------|
| `getKbDir(scope)` | `kb/{scope}/` 绝对路径（优先 scope 级 `kbDir`，即 `{kbDir}/kb/{scope}`） |
| `getGroupIndexPath(scope)` | `kbDir/group-index.json` |
| `getRelationsCachePath(scope)` | `kbDir/relations-cache.json` |
| `getLocalKbDir(scope, groupPath)` | `kbDir/{groupPath}/index.json` |

> `getScanIndexPath` 已移除（scan-index 随增量导入模式一并删除）。

```ts
import { getGroupIndexPath, getRelationsCachePath } from './lib/scope.js';
const gi = getGroupIndexPath('myproj');
const rc = getRelationsCachePath('myproj');
```

### 3.3 `getSource(scope)` / `setSource(scope, source)`

- **`getSource`**：读 group-index.json 的 `source` 块（`{dir, chunkSize?, chunkOverlap?}`），文件不存在或 `source.dir` 缺失返回 `null`。
- **`setSource(scope, source)`**：写 source 块（自动迁移 roots→groups）。`dir` 为唯一必填字段；`chunkSize` / `chunkOverlap` 仅在传入时写入（切分参数持久化，缺失时由消费方回退默认值）。
- **`GroupIndexSource`**：`{dir: string; chunkSize?: number; chunkOverlap?: number}`。`rootName` 与 `commit` 字段已随对应概念（默认根节点、增量 diff 基线）移除，传入也会被丢弃。
- **异常**：group-index.json 不存在抛错（需先 `ensureScopeDir`）；`source.dir` 为空抛错。

```ts
import { setSource, getSource } from './lib/scope.js';
setSource('myproj', { dir: '/repo/src', chunkSize: 1500, chunkOverlap: 200 });
const src = getSource('myproj'); // { dir: '/repo/src', chunkSize: 1500, chunkOverlap: 200 } | null
```

### 3.4 `migrateGroupIndex(data)` / `ensureGroupPathInTree(index, groupPath)` / `listAllScopes()`

- **`migrateGroupIndex(data)`**：将旧格式 `roots` 迁移为 `groups`；无迁移需求返回 `null`。
- **`ensureGroupPathInTree(index, groupPath)`**：确保 groupPath 各段在树中存在（自动补空节点）。
- **`listAllScopes()`**：枚举已初始化 scope（目录含 `relations-cache.json`）。

## 4. 配置加载（`lib/config.ts`）

### 4.1 `loadConfig(explicitPath?)`

- **用途**：加载配置（进程内缓存只读一次）。
- **参数**：`explicitPath` — 对应 `--config <path>`；否则从 `~/.ki/config.yaml → config.yml → config.json` 查找（`KI_CONFIG_PATH` 环境变量等价 `--config`）；都没有用内置默认值（stderr 提示一次）。
- **返回**：`KiConfig`（含 `dataDir/backupDir/vectorDir/embedding/scopeMode/scopes/mcp/_fieldWarnings`）。
- **异常**：
  - `--config` 路径不存在 → 抛错
  - 语法解析失败（YAML/JSON）→ 抛「配置文件解析失败」
  - **字段级校验失败 → 抛 `CONFIG_FIELD_INVALID`**（字段名/类型/取值，见 §4.6）
- **行为语义**：
  - `scopeMode`：`'strict'` 才启用严格模式，其余（含非法值）归 `'default'`
  - `embedding.apiKey`：支持明文 `sk-xxx` 或 `${ENV_VAR}` 引用；引用未设置返回 `undefined`（不做隐式 env 回退）
  - 读到 `.json` 配置（非显式 `--config`）→ stderr 提示建议 `ki config init` 生成 YAML，不阻断
  - **默认路径恒为 `~/.ki` 用户数据根**：`dataDir` 默认 `~/.ki/kb`、`backupDir` 默认 `~/.ki/backup`、`vectorDir` 默认 `~/.ki/vector`。**不做存量路径继承**（旧的 `{项目根}/kb`、`~/.ki-data` 不再自动沿用）
  - `KI_DATA_DIR` 仅在 `ki config init` 模板探测时生效，运行时 `loadConfig` 不读

```ts
import { loadConfig, getVectorDir, getEmbeddingConfig, resolveScope } from './lib/config.js';
const config = loadConfig();
const vectorDir = getVectorDir(config); // 默认 ~/.ki/vector
const scope = resolveScope(config, process.argv[2]); // strict 模式下未注册抛错
```

### 4.2 `resolveDefaultDataPaths(includeEnv?)`

- **用途**：解析 `dataDir` / `backupDir` 的默认值，供 `loadConfig` 与 `ki config init` 模板共用（避免两处默认逻辑漂移）。
- **参数**：`includeEnv` — 默认 `false`。传 `true` 时允许 `KI_DATA_DIR` 覆盖 `dataDir`（仅 `config init` 使用）。
- **返回**：`{dataDir, backupDir}`。

```ts
import { resolveDefaultDataPaths } from './lib/config.js';
resolveDefaultDataPaths();    // { dataDir: '~/.ki/kb', backupDir: '~/.ki/backup' }
resolveDefaultDataPaths(true); // config init：KI_DATA_DIR 可覆盖 dataDir
```

### 4.3 `resetConfigCache()`

- **用途**：清除 `loadConfig` 的进程内缓存（测试与 `removeScopeFromConfigFile` 写回后使用）。

### 4.4 配置取值辅助函数

| 函数 | 返回 | 说明 |
|------|------|------|
| `getScopeDataDir(config, scope)` | scope 数据目录 | 优先 `scopes[scope].kbDir + '/kb/' + scope`，否则 `dataDir/{scope}` |
| `getBackupDir(config)` | 备份根目录 | 即 `config.backupDir` |
| `getVectorDir(config)` | zvec collection 目录 | 即 `config.vectorDir` |
| `getEmbeddingConfig(config)` | `EmbeddingConfig` | 即 `config.embedding` |
| `getScopeMode(config)` | `'default' \| 'strict'` | 即 `config.scopeMode` |
| `getScopeWikiSync(config, scope)` | `WikiSyncConfig \| null` | 无配置返回 `null` |
| `getScopeCleanConfig(config, scope)` | `CleanConfig \| null` | 无配置返回 `null`（调用方用默认值） |
| `getScopeImportConfig(config, scope)` | `ImportConfig \| null` | 无配置返回 `null`（调用方用默认值） |

### 4.5 `resolveScope(config, scope?)`

- **用途**：按 scopeMode 解析实际 scope。
- **行为语义**：`default` 档：缺省/空 → `'default'`，任意值放行；`strict` 档：必须传非空且已注册，否则抛错（fail-loud）。

### 4.6 `validateConfigFields(raw)`（`lib/config-schema.ts`）

- **用途**：对已解析（语法正确）的原始配置对象做**字段级校验**：字段名、类型、取值。`loadConfig` 在语法解析后、宽容归一化前自动调用；也可单独调用做预检。
- **参数**：`raw` — YAML/JSON 解析后的原始对象。
- **返回**：`{errors: ConfigIssue[], warns: ConfigIssue[]}`，`ConfigIssue = {path, message}`。
- **异常**：不抛错——问题以 errors/warns 返回（`loadConfig` 负责把 errors 抛成 `CONFIG_FIELD_INVALID`）。
- **行为语义（分级）**：
  - **errors（阻断加载）**：未知字段名（附 Levenshtein 相近字段建议）、类型不符（如 `dimension: "4096"`）、非法枚举（`scopeMode` 非 `default`/`strict`）、取值非法（`dimension` 非正整数、`mcp.http.port` 非 1-65535、`embedding.baseURL` 非 `http(s)://` 开头）、YAML 合并键 `<<`（解析器不展开，写法不生效）、空 scope 名
  - **warns（不阻断，仅经 `ki doctor` 报告）**：已知废弃字段（scope 级 `sourceDir`）、scope 条目值为 null（YAML 裸写 `default:` 会被忽略）、字符串字段值为空串（按「未配置」处理）
  - **放行不校验**：根层 `x-` 前缀锚点模板键（如 `x-common: &tpl`，内容不校验）
  - `scopes` 为自由键 map，任意 scope 名合法，不会误判为拼写错误

```ts
import { validateConfigFields } from './lib/config-schema.js';
const { errors, warns } = validateConfigFields({
  datadir: '/tmp/kb',                 // → error：非预期字段，您是否想输入 "dataDir"？
  scopes: { default: null },          // → warn：scope 条目为空，将被忽略
});
if (errors.length > 0) throw new Error(`CONFIG_FIELD_INVALID: ${errors.length} 处`);
```

### 4.7 `removeScopeFromConfigFile(scope)`

- **用途**：从配置文件 `scopes` 中移除条目（YAML 用 Document API 保留注释与格式）；无配置文件或条目不存在时返回 `removed:false`（非错误）。
- **返回**：`{removed, configPath?, reason?}`；写回成功后会 `resetConfigCache()`。

import { autoBackup } from './lib/backup.js';

## 6. 预检（`lib/preflight.ts`）

### 6.1 `checkWritable(dir)` / `checkDiskSpace(dir, requiredBytes)` / `estimateDirSize(dir)`

- **`checkWritable(dir)`**：对第一个已存在祖先目录做试写探针；失败抛 `PreflightError('DIR_NOT_WRITABLE')`。
- **`checkDiskSpace(dir, requiredBytes)`**：statfs 校验可用空间（预留 10%）；不足抛 `PreflightError('DISK_INSUFFICIENT')`；无法探测则跳过。
- **`estimateDirSize(dir)`**：递归估算目录字节数；出错返回 0。

```ts
import { checkWritable, checkDiskSpace } from './lib/preflight.js';
checkWritable('/target/dir');
checkDiskSpace('/target/dir', 1024 * 1024);
```

## 7. CLI 参数（`lib/cli-args.ts`）

### 7.1 `failJson(error, code?)` / `toErrorPayload(err)`

- **`failJson`**：输出 `{ok:false, error, code?}` 并 `process.exit(1)`（统一 JSON 错误契约，返回类型 `never`）。
- **`toErrorPayload(err)`**：从任意抛出值提取 `{ok:false, error, code?}`（Error 上的 `code` 字段如 `ScopeError` / `PreflightError` 会一并回显），不退出进程——供命令层自行 `output()` 后 `process.exit(1)`。

```ts
import { toErrorPayload, failJson } from './lib/cli-args.js';
try { /* ... */ } catch (err) { console.log(JSON.stringify(toErrorPayload(err))); process.exit(1); }
```

### 7.2 `detectUnknownFlags(args, knownFlags, valueFlags?, helpText?)`

- **用途**：检出未知 `--flag` 并报错（含近似建议）。
- **行为语义**：未知 flag → failJson 退出码 1；`helpText` 传入时先输出帮助到 stderr。

### 7.3 `parseIntArg(raw, fallback, flagName, {min, max})` / `parseFloatArg(raw, fallback, flagName)`

- **用途**：数值参数解析；非法值回退默认值并 `console.warn`；超 max 限幅。
- **行为语义**：`parseFloatArg` 返回 `undefined` 表示"不过滤"语义（调用方默认值由 fallback 决定）。

## 8. 健康检查（`lib/health-check.ts`）

### 8.1 `runHealthCheck(config)`

- **用途**：执行完整健康检查（配置字段告警、目录可写、apiKey、embedding 连通性/密钥/维度、zvec collection、scopes.default），共 11 项。
- **返回**：`HealthReport {items, pass, warn, fail}`。
- **行为语义**：
  - embedding 用 1 条最短请求（`'test'`）三合一验证，`timeoutMs: 8000`、`retries: 1`
  - **只读不修改**；zvec collection 用目录非空判定（不 open，避开锁冲突）
  - **配置字段项**（`配置字段`）：无 `_fieldWarnings` → pass；有则按 message 归组展示（最多 3 类），状态 warn
  - 配置文件项：字段级校验失败在 `loadConfig` 阶段即抛错，能走到本函数说明语法 + 字段均已通过
  - 无配置文件（`_configPath` 为空）→ 配置文件项 fail，建议 `ki config init`

```ts
import { loadConfig } from './lib/config.js';
import { runHealthCheck, renderHealthReport } from './lib/health-check.js';
const report = await runHealthCheck(loadConfig());
console.log(renderHealthReport(report)); // ✅/⚠️/❌ 报告
```

## 10. Scope 生命周期（`src/scope.ts`）

### 10.1 `executeScopeList()`

- **用途**：列出 KB 层 / 向量层 / 配置注册层三者的并集，每项标注存在于哪层。
- **返回**：`ScopeListResult {ok, scopeMode, vectorAvailable, vectorReason?, count, scopes: ScopeEntry[]}`；`ScopeEntry = {scope, kb, vector, registered, wikiCount}`。
- **行为语义**：向量层枚举走单次 probe + `fastFail`，撞锁立即降级为仅 KB 层（下拉框不因向量锁挂起）；`vectorAvailable:false` 时 `vectorReason` 说明原因。

```ts
import { executeScopeList } from './scope.js';
const { scopes } = await executeScopeList();
console.log(scopes.filter((s) => s.kb).map((s) => s.scope));
```

### 10.2 `executeScopeDelete({scope, yes})`

- **用途**：彻底摘除 scope——清向量文档 + 删 KB 目录 + 移除 `config.scopes` 条目。
- **返回**：`ScopeDeleteResult`：成功 `{ok:true, scope, deletedVectors, kbRemoved, configRemoved}`；失败 `{ok:false, error, requireConfirm?, willDelete?}`。
- **行为语义**：
  - `scope === 'default'` → 直接返回 `{ok:false, error:'default scope 不可删除'}`
  - **向量服务不可用 → 拒绝执行**（`error` 含"拒绝删除以免两层不一致"）——不降级为只删 KB
  - 未传 `yes` → 返回 `requireConfirm:true` + `willDelete:{vectorCount, kbExists, registered}`（预览，不交互等待）

### 10.3 `executeScopeClear({scope, tags?, yes})`

- **用途**：清空 scope 数据但保留 scope 本身——清向量文档 + 清空 KB 目录内容（保留目录与配置条目）。
- **返回**：`ScopeClearResult`：成功 `{ok:true, scope, tags: string[]|'all', deletedVectors, kbCleared}`；失败同上（`willDelete:{vectorCount, kbWillClear}`）。
- **行为语义**：
  - 传 `tags` 时**只清向量层对应 tag，`kbCleared` 恒为 `false`**（tag 是向量层概念，KB 层无 tag）
  - 向量服务不可用 → 同 delete，拒绝执行
  - 未传 `yes` → 返回 `requireConfirm` 预览

```ts
import { executeScopeClear, executeScopeDelete } from './scope.js';
// 先预览（yes: false），确认后再真删
const preview = await executeScopeDelete({ scope: 'old-proj', yes: false });
if (preview.ok === false && preview.requireConfirm) {
  console.log(preview.willDelete); // { vectorCount, kbExists, registered }
  const done = await executeScopeDelete({ scope: 'old-proj', yes: true });
}
const cleared = await executeScopeClear({ scope: 'myproj', tags: ['ki-path'], yes: true });
```

## 11. CLI 命令入口（`src/*.ts`）

### 11.1 `src/backup.ts` — `ki backup <scope> [--list]`

- 无 `--list`：备份 scope 目录快照到 `<backupDir>/<scope>/snapshots/`；scope 未初始化（缺 relations-cache.json）时报错提示先 import。
- `--list`：列出现有快照（只读）。

### 11.2 `src/restore.ts` — `ki restore <scope> [选项]`

- 无操作参数（或 `--list`）：列出可用备份。
- `--from-snapshot [<file>]`：从 tar.gz 快照覆盖还原（破坏性，需 `--yes`）。可直接指定快照文件路径，或 `--timestamp <ts>` 指定（缺省取最新）。
- `--rebuild-vector`：还原后（或独立）从已还原 KB 重建向量；可配合 `--group <path>`（仅重建子树，幂等覆盖）与 `--tags <t1,t2>`（附加自定义标签，只增不减）。
- `--backup-dir <dir>`：指定「从哪读」的备份根目录；**还原前安全网快照始终写入受管的默认 `backupDir`**，不写进自定义目录。
- **约束**：破坏性覆盖前输出「将被覆盖的数据规模」总览；未加 `--yes` 时不交互等待，直接以 `code='CONFIRMATION_REQUIRED'` 退出码 1 退出。

### 11.3 `src/export.ts` — `ki export <scope> --output <dir> [--group <path>] [--yes]`

- 将 scope 本地数据导出为 Markdown 目录（group-index + relations-cache + local KB，不依赖向量库）。
- `--group <path>`：只导出指定 Group 子树（子树提为顶层树）；缺省全量导出。
- `--root-name` 已移除（rootName 概念删除）。

### 11.4 `src/config.ts` — `ki config init [--dir <path>] [--force]`

- 生成 `<dir|HOME>/.ki/config.yaml`；已存在且未加 `--force` 时返回 `existed:true` 不覆盖。
- 同时尝试创建 `dataDir` / `backupDir` / `vectorDir` 三个目录（创建失败不阻断，doctor 会检出）。
- 模板默认路径来自 `resolveDefaultDataPaths(true)`：`KI_DATA_DIR` 仅此处生效。

### 11.5 `src/doctor.ts` — `ki doctor`

- 配置健康诊断（等价 `runHealthCheck`），只读，有失败项退出码 1（可作 CI gate）。
- `-h/--help` 直接打印帮助退出 0（不落入健康检查，避免无意义的失败退出码）。
- 配置字段校验失败在 `loadConfig` 阶段抛错 → 输出「配置加载失败」+ 字段路径清单后退出 1。

## 已知约束汇总

- 所有写 JSON 操作都应走 `writeJson` / `walWrite` 保证原子性，不要直接 `fs.writeFileSync` 覆盖数据文件（`setSource` 是现存例外，见 C0 已知问题）。
- `scope` 字符集仅 `[a-zA-Z0-9_-]`，含路径分隔符的操作必须先 `validateScope`。
- 配置 apiKey 不做隐式环境变量回退（除 `${VAR}` 显式引用）。
- `walWrite` 是**同步阻塞**实现：等锁期间用 `Atomics.wait` 阻塞线程（最长 10s），常驻 MCP 进程中会短暂冻结事件循环，因此工具层的 `withTimeout` 在阻塞期间不会触发。锁仅在「写 .tmp + rename」短区间持有，正常为毫秒级。
- 配置新增字段时必须同步更新 `lib/config-schema.ts` 的 schema 声明，否则会被判为「非预期字段」而 fail-loud（schema 与配置字段无自动同步机制）。
- `config-schema` 校验覆盖字段名/类型/取值，但 `embedding.provider` 不校验枚举（provider 由 baseURL 决定，可自由配置）。
