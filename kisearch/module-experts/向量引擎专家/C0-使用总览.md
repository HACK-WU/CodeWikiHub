# C0-使用总览：向量引擎专家

## 能力清单

本专家覆盖 kisearch 的 **向量检索引擎基座**（基于 `@zvec/zvec` 封装），提供：

| 能力 | 说明 | 入口 |
|------|------|------|
| 引擎生命周期 | create（新建集合）/ open（打开）/ tryOpen / probe / close / destroy / info | `ZvecEngine` 静态工厂与方法 |
| 检索 | 语义（Semantic）/ 全文（FTS）/ 混合（Hybrid + RRF）三种检索 | `engine.search` |
| 写入 | 单条 / 批量 upsert（幂等），带 embedding 自动向量化 | `engine.write` / `engine.writeBatch` |
| 删除 | 按 id 删除 | `engine.delete` |
| Embedding | `EmbeddingProvider` 抽象 + `SiliconFlowProvider` 参考实现（OpenAI 兼容） | `embedding/*` |
| Schema 管理 | create/open 配置校验、schemaAssert 比对、迁移 | `schema/*` |
| Filter | 结构化 Filter 编译为 zvec 类 SQL（含字段白名单） | `filter/compiler.ts` |
| 异常体系 | 基类 + 11 种核心契约异常 + Worker/Embedding 族（共 18 类，跨线程可反序列化） | `errors.ts` |
| 探测 | `probe(dbPath)` 无句柄探测（locked/healthy/corrupted/not_found） | `engine.ts` |

## 能力边界（本专家不做什么）

- **不提供** kisearch 业务层的 scope/tag 过滤语义（由"检索与向量客户端专家"的 `vector-client` 实现）
- **不提供** memoryId 反查 / 原文定位（属检索客户端专家）
- **不持久化** 业务数据（KB JSON），仅管理向量集合
- **不实现** 其他厂商 embedding 提供商（`SiliconFlowProvider` 为参考实现，可扩展）

## 已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|------|----------|----------|
| `CollectionLockedException` | 集合被其他进程持锁打开 | 关闭其他进程/实例；或 `ki restore` 重建 |
| `CollectionAlreadyExistsError` | `create` 时 dbPath 已存在 | 用 `open` 打开而非 create |
| `CollectionNotFoundError` | `open` 时路径不存在 | 先 create 或用 tryOpen |
| `DimensionMismatchError` | embedding 维度 ≠ 集合维度 | 检查 config.embedding.dimension 与集合一致（kisearch 固定 4096） |
| `SchemaMismatchError` | open 时 schemaAssert 比对不一致 | 集合 schema 与 config 不符，重建集合 |
| probe 挂起 | 空目录 / 被持锁时 ZVecOpen 原生阻塞 | 空目录预检已修复为 NOT_FOUND；持锁走 3s 超时 |
| 同进程并发 ZVecOpen 竞态 | 多个 open/probe/create 并发 | 引擎内部已串行排队（`serializeEngineOp`），调用方无需处理 |
| `WorkerUnavailableError`（worker not open state=closed） | worker 被 close 后仍有在途操作提交（如 embedding 网络等待期被 idle close 打断） | 业务层 `vector-client` 的 `withEngine` 已用在途计数 + 自愈重试防护；直接使用引擎时需保证 close 前操作全部完成 |
| 向量维度不匹配 | embedding 模型更换 | 需重建集合（schema 白名单，无 alter API） |

## 子专家导航

无子专家。本专家是独立子项目，被"检索与向量客户端专家"（`vector-client`）强依赖。
