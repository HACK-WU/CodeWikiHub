# C4-数据流向与消费：向量引擎专家

> 本专家管理向量集合数据（`config.vectorDir`），是 kisearch 语义检索的数据源。

## 数据实体总览

| 数据实体 | 来源接口 | 去向 | 消费方 | 业务用途 |
|----------|----------|------|--------|----------|
| 向量集合（zvec collection） | `ZvecEngine.create` / `engine.write` / `writeBatch` | `config.vectorDir`（磁盘持久化） | 检索与向量客户端专家（`vector-client` 的 search/list/delete）、关系与索引管理专家（sync-relation 写入）、知识索引导入专家（import 批量写入） | 语义检索 + 全文检索 + 混合检索的向量与标量数据源 |
| Embedding 向量 | `SiliconFlowProvider.embed` | 内存（Float32Array → worker）→ 集合 dense 字段 | `engine.write` / `engine.search` | 文本向量化，支撑语义检索 |

## 逐实体详述

### 1. 向量集合
- **来源接口**：`ZvecEngine.create`（新建）/ `engine.write` / `engine.writeBatch`（写入）
- **去向**：`config.vectorDir`（zvec 持久化目录）
- **消费方**（>3 归纳）：检索客户端（search/listDocs/listTags/delete）、知识导入（Phase 2 批量向量化）、关系与索引管理（sync-relation 写关系向量）、运维（restore 重建、doctor 探测）
- **业务用途**：语义检索的数据源——`content` 字段兼作 FTS 字段（jieba 分词），`scope/tag/group` 为 indexed 标量字段支撑过滤隔离

### 2. Embedding 向量
- **来源接口**：`SiliconFlowProvider.embed`
- **去向**：内存（主线程 embed → Float32Array + Transferable 零拷贝传 worker）
- **消费方**：`engine.write`（写入）与 `engine.search`（查询）
- **业务用途**：文本 → 向量，语义检索的基础；维度必须与集合一致（4096）
