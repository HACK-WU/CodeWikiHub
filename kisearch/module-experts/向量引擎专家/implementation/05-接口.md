## 异常接口

11 种核心契约异常 + Worker/Embedding 族补充异常（共 18 类，全部继承 `ZvecEngineError`）：
- 核心契约：`DimensionMismatchError` / `InvalidSchemaError` / `InvalidDocInputError` / `InvalidSearchError` / `InvalidFilterError` / `SchemaMismatchError` / `InconsistentUpdateError` / `CollectionNotFoundError` / `CollectionLockedException` / `CollectionCorruptedException` / `CollectionAlreadyExistsError`
- Worker 族：`WorkerSpawnError` / `WorkerCrashedError` / `WorkerUnavailableError`（2026-08-28 补导出到 `index.ts`）/ `WorkerProtocolError` / `CloseTimeoutError`
- Embedding 族：`EmbeddingError` / `EmbeddingConfigError`

**行为语义**：
- `CollectionLockedException` 与 `CollectionCorruptedException` 语义上为"异常"但命名含 Exception（对齐 zvec 契约）
- 各异常带 `code` 字段（如 `COLLECTION_LOCKED`），供上层精确分支
- `WorkerUnavailableError` 的典型触发场景是「在途操作被 close 打断」（业务层已由 `vector-client.withEngine` 在途计数 + 自愈重试防护）

## 版本策略

- 独立子项目：`tsconfig.src.json` 编译 `src/zvec-engine/**` → `dist/zvec-engine`（`npm run build:zvec-engine`）
- 业务层（`vector-client`）从 `dist/zvec-engine/index.js` 导入（先构建后运行）
- 版本随父包 package.json 管理（kisearch 0.2.0-beta）

## 结论

本专家接口面经 `index.ts` 单一门面收敛：引擎方法覆盖全生命周期，异常体系类型化且跨线程可用，独立构建保证与业务层解耦。契约层 C1 已覆盖调用方式，本文件补充导出面与版本策略。
