## 简介

本文件描述向量引擎的测试资产：位置、覆盖、可执行性与缺口。

## 覆盖模式

- **引擎生命周期**：create/open/probe（含空目录 probe 用例，验证 NOT_FOUND 修复）、close/destroy 幂等
- **写入/检索**：write 幂等 upsert、search 三种类型（semantic/fts/hybrid）、维度校验
- **异常**：类型化异常构造与跨线程反序列化（核心契约 11 种 + Worker/Embedding 族，共 18 类）
- **Filter**：白名单字段、值转义、嵌套深度上限
- **Schema**：create/open 铁律校验、schemaAssert 比对、错误映射
- **Embedding**：provider 行为、维度校验错误（actualDim）

## 测试可执行性

- **运行命令**：`npm run test:zvec-engine`（node --test）
- **前置**：`npm run build:zvec-engine`（编译 dist/zvec-engine）
- **环境依赖**：⚠️ `zvec-engine-embedding.test.mjs` 等需真实 embedding API Key（无 key 时走错误分支）；核心引擎测试用 fixture 或 dummy provider，✅ 可跑
- **已知失败**：当前无已知失败（详见 `test/known-failures.md`）

## 测试缺口

- worker crash 场景（`WorkerCrashedError`）测试覆盖不足
- 「在途操作被 idle close 打断」竞态：引擎侧无直接用例，由业务层 `test/vector-idle-race.test.ts`（`npx jiti test/vector-idle-race.test.ts`，⚠️ 需真实 embedding API Key）覆盖
- probe 的 corrupted 状态判定用例较少
- 并发串行化（`serializeEngineOp`）时序用例未覆盖（属 vector-client 侧）
- 大批量写入的查询插队行为（setImmediate 让出）无专门测试

## 结论

本专家测试覆盖引擎生命周期/检索/异常/Filter/Schema/Embedding 核心路径，可执行性良好（✅ 核心可跑，⚠️ embedding 需 API Key）；已知缺口集中在 worker crash 与并发时序，建议后续补充。
