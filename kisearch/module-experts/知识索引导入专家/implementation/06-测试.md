## 覆盖模式

- **直导链路**：目录/单文件两种来源、幂等重导覆盖、relation 真冲突跳过、缺省 group 落点（顶层子目录根 / 散文件落 scope name）、清洗 hook 失败回滚
- **防护**：import 锁并发拒绝、SIGKILL 残留自动清理、中断标记写入/清除、interruptGuidance 引导
- **向量重建**：全量/局部（--group 子树过滤、--tags 合并打标）、updateMemoryIds 回写、幂等重跑
- **HTTP 导入**：upload 扩展名/大小/路径安全校验、run 缺省 group 与 CLI 语义一致（P1-1 回归）、status 响应结构 `{ok, job:{state,...}}`
- **异常矩阵**：非法输入 fail-loud（`ok:false` + error 子串断言）

## 测试可执行性

- **运行命令**：见上表；全量 `npm run test:all`
- **环境依赖**：
  - ✅ `import-scheme-d` / `interrupt` / `error-handling` / `mcp-http-api`（vector 相关用例走 mock/降级路径）常规环境可跑
  - ⚠️ `import-vector-rebuild.test.ts`：**需向量引擎与 embedding 环境，AGENTS.md 2026-08-14 记录其未纳入常规回归**（运行需先配置 embedding API Key）
  - ⚠️ 真实向量化路径需 embedding API Key
- **已知失败**：当前无已知失败（详见 `test/known-failures.md`）
- **环境坑（IDE）**：子进程 env 若继承 `NODE_OPTIONS`/`CODEBUDDY_SAFE_DELETE*`，文件操作达批量阈值（50）会触发 safe-delete 确认挂起——`test/test-config.ts getTestEnv()` 已剥离，但绕过该配置直接跑仍可能挂（AGENTS.md 2026-08-14 记录）

## 测试缺口

- `handleDirectImport` 的 SIGINT/SIGTERM 信号路径无自动化用例（interrupt.test.ts 覆盖的是 interrupt.ts 纯函数层，信号捕获在 import.ts 内）
- HTTP 导入 job 中途失败的 status 状态流转（running → failed）覆盖较薄
- 单文件导入 + 显式 --group 组合、`--tags` 全为保留标签的 NEG 提示路径用例较少
- `progress.ts` 控制台进度函数无断言（低价值，可不补）

## 结论

本专家测试覆盖直导链路 / 防护自愈 / 重建 / HTTP 接口核心路径，常规环境可跑性良好；`import-vector-rebuild` 依赖向量环境未纳入常规回归属已知边界，信号路径与 job 失败流转是主要缺口。
