# C4-数据流向与消费：知识索引导入专家

> 本专家是知识索引的**写入端**，产出的向量数据 / relations-cache / local KB / group-index 被检索、关系管理等模块消费。

## 数据实体总览

| 数据实体 | 来源接口 | 去向 | 消费方 | 业务用途 |
|----------|----------|------|--------|----------|
| content 向量（ki-search，chunk 粒度） | `bulkVectorize` | 向量集合（`config.vectorDir`） | 检索与向量客户端专家（search 召回） | 语义/全文主检索数据源 |
| path/relation 向量（ki-path / ki-relation） | `bulkStorePaths` | 向量集合 | 关系与索引管理专家（路径模糊兜底）、检索客户端 | Group 路径/关系名的模糊定位 |
| 自定义 tag 向量 | `handleDirectImport`（tags 参数 → `vectorBulkStore`） | 向量集合（tags=自定义标签） | 检索客户端（`ki search -t <tag>`） | 按文档标签召回 |
| `relations-cache.json` | `handleDirectImport` Phase 4（`upsertRelation` + memoryIds/tags 回填） | `kb/{scope}/relations-cache.json` | 检索客户端（memoryId 反查）、关系管理（query-group / delete-relation / sync-relation）、本专家 rebuild（collectPathRelationEntries） | 关系热缓存 + memoryIds 定位 + tags 持久化 |
| local KB `index.json` | `handleDirectImport` 步骤 1（`writeLocalKb` 文件级原文） | `kb/{scope}/{groupPath}/index.json` | 关系管理（get-module-info 读原文）、存储专家（export）、本专家 rebuild（collectContentEntries） | Group 级 Markdown 原文存档 |
| `group-index.json`（树 + source 块） | `handleDirectImport` Phase 3/5（`ensureGroupPathInTree` + `setSource`） | `kb/{scope}/group-index.json` | 关系管理（manage-index / query-group）、存储专家、MCP /api/doc/list（Group 树） | Group 树导航 + 知识源记录（dir + 切分参数，无 commit） |
| 中断标记 `import-interrupt.json` | `writeInterruptMark`（SIGINT/SIGTERM） | `kb/{scope}/import-interrupt.json` | vector-client（getEngine 前置引导）、本专家（成功导入/rebuild 清除） | 中断感知与恢复引导 |
| 导入锁 `.import.lock` | `acquireImportLock` | `kb/{scope}/.import.lock` | 本专家（并发拒绝/残留自愈） | 同 scope 导入互斥 |
| 上传暂存目录 `~/.ki/import-uploads/<uploadId>/` | HTTP `/api/import/upload` | 受控目录（base64 落盘） | HTTP `/api/import/run`（作 sourceDir 导入） | Web 导入的文件中转 |

## 逐实体详述

### 1. 向量文档（content / path / relation / tag 四类）
- **来源接口**：`bulkVectorize`（content，chunk 粒度）/ `bulkStorePaths`（path/relation）/ `vectorBulkStore`（tag，每个自定义标签一条）
- **去向**：向量集合
- **消费方**（>3 归纳）：检索客户端（search / tag 过滤）、关系管理（searchPath 路径兜底）、本专家 rebuild（重建数据源闭环）、MCP 工具（ki_search 等）
- **业务用途**：content 支撑主检索；path/relation 支撑 Group 路径模糊定位；tag 支撑标签召回
- **桥接键**：chunk 的 `sourcePath = 文件#N`、tag 向量 docId 与 chunk docId 一并聚合到文件级 relation 的 `memoryIds[]`

### 2. relations-cache.json
- **来源接口**：`handleDirectImport` Phase 4——`upsertRelation`（groupPath + relationText 主键）+ 覆盖导入前置 `vectorDeleteScope`（只清向量不动此文件）
- **去向**：`kb/{scope}/relations-cache.json`
- **消费方**：检索客户端（`getRelationMap` memoryId 反查定位原文）、关系管理（query-group 热缓存 / delete-relation 定位 / sync-relation 追加）、本专家（rebuild 读 relation/path/tag 数据源）
- **业务用途**：关系热缓存——文件级 relation 挂 `memoryIds[]`（chunk + tag docId）、`sourcePath`（幂等判定）、`tags`（打标持久化），支撑"搜得到 + 定位到原文 + 重建可恢复"

### 3. local KB index.json
- **来源接口**：`writeLocalKb`（导入第 1 步，先于向量化写入**未清洗原文**；hook 失败/超限时 `removeFromLocalKb` 回滚）
- **去向**：`kb/{scope}/{groupPath}/index.json`
- **消费方**：关系管理（get-module-info 索引直查）、存储专家（export / restore 快照）、本专家（rebuild 的 collectContentEntries）
- **业务用途**：每个 Group 的 Markdown 原文存档——索引直查 100% 精准 + 重建向量层的自包含数据源

### 4. group-index.json（Group 树 + source 块）
- **来源接口**：Phase 3 `ensureGroupPathInTree`（建树）/ Phase 5 `setSource`（`{dir, chunkSize, chunkOverlap}`，**无 commit**）
- **去向**：`kb/{scope}/group-index.json`
- **消费方**：关系管理（manage-index / query-group）、MCP `/api/doc/list`（前端 Group 树）、存储专家
- **业务用途**：Group 树导航 + 知识源目录与切分参数记录（切分参数持久化供重建口径一致）

### 5. 中断标记 / 导入锁
- **来源接口**：`writeInterruptMark` / `acquireImportLock`
- **去向**：`kb/{scope}/import-interrupt.json`、`kb/{scope}/.import.lock`
- **消费方**：vector-client（getEngine 前置 `interruptGuidance` 引导所有向量命令）、本专家（并发拒绝 / 成功清除）
- **业务用途**：中断感知恢复 + 同 scope 导入互斥（SIGKILL 残留自愈）

```mermaid
    A[源 Markdown 目录/单文件] --> B[handleDirectImport]
    U[HTTP upload 暂存目录] --> B

    B --> D[(relations-cache memoryIds)]
    B --> E[(local KB 原文)]
    B --> F[(group-index 树+source)]
    B --> G[(中断标记/导入锁)]
    C --> H[检索客户端 search]
    D --> H
    D --> I[关系管理 query-group/delete-relation]
    E --> I
    E --> J[rebuild-vector 重建闭环]
    F --> K[/api/doc/list Group 树]
```
