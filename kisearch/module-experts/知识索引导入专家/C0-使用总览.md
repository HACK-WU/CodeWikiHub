# C0-使用总览：知识索引导入专家

## 能力清单

本专家覆盖 kisearch 的 **知识导入链路**：将外部 Markdown 目录（或单文件）原文直导进本地知识索引：

| 能力 | 说明 | 入口 |
|------|------|------|
| 直导导入 | 原文直导（无 AI 依赖）：自动清洗 + 切分 + 向量化 + 建 Group 树 + 落盘，**幂等追加**（重复执行 = 增量更新） | `lib/import.ts` `handleDirectImport`；CLI `ki scan-kb import` |
| 单文件导入 | sourceDir 指向单个 .md 文件（后缀须命中白名单，否则报错） | 同上 |
| HTTP 导入 | upload 落盘 → run 异步 job → status 轮询（前端导入页用） | `lib/mcp-http-api.ts` `/api/import/*` |
| 导入防护 | 同 scope 并发导入拒绝（锁）+ SIGKILL 残留锁自愈 + SIGINT/SIGTERM 中断标记与恢复引导 | `lib/interrupt.ts` |
| 批量向量化 | `bulkVectorize`（一次 bulkStore）/ `vectorizeOne` / `deleteMemory` | `lib/batch-vectorize.ts` |
| 路径向量化 | ki-path / ki-relation 辅助向量，供路径模糊兜底 | `lib/path-vectorize.ts` |
| 自定义标签 | `--tags` 文档级标签：持久化到 relation.tags + 每标签一条内容向量（可被 `ki search -t` 召回） | `handleDirectImport` tags 参数 |
| 向量重建 | 从已还原 KB 重建向量并回写 memoryId；支持 `--group` 子树过滤 / `--tags` 合并打标的局部重建 | `lib/rebuild-vector.ts` `rebuildScopeVectors` |

## 能力边界（本专家不做什么）

- **不提供** 检索 / 原文定位（属检索与向量客户端专家）
- **不提供** 关系写入 / 评分 / Group 树 CRUD / 删除（属关系与索引管理专家，但本专家写入 relations-cache 与 local KB 供其消费）
- **不提供** 备份 / 还原（属存储与配置基础专家；restore 内部复用本专家 `rebuildScopeVectors`）
- **不做** AI 摘要生成：**ai-results.json 输入契约已删除**（`normalizeAiResults` 等已不存在，`lib/ai-results.ts` 仅存类型与落点推导函数）
- **无增量 diff 模式**：`ki scan-kb diff`、`--mode incremental`、`incremental.ts`/`diff.ts` 均已删除——增量更新直接重跑 import（幂等）

## 已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|------|----------|----------|
| `scope "X" 已有导入进行中` | 同 scope 并发导入（或上次被 SIGKILL 后锁残留未自愈场景） | 等待完成；确认无导入进程后可删 `kb/{scope}/.import.lock`（pid 探活通常会自动清理） |
| 导入中断后所有向量命令报「检测到未完成的导入」 | SIGINT/SIGTERM/SIGKILL 中断过导入，残留中断标记 | 按提示执行 `ki restore <scope> --rebuild-vector` 恢复；或重新成功导入后自动清除 |
| 第二次导入后之前导入的文件"消失" | 向量化模式下覆盖导入是 **scope 级全量清空重建**（本次源目录不含前次文件） | 幂等设计：用同一源目录重跑（同 sourcePath 覆盖）；或多次导入的文件并入同一源目录；或用 `--no-vector` 只写 KB 层 |
| `relation 冲突已跳过` | 同 group 下同名 relation 但 sourcePath 不同（不同文件同名） | 重命名文件或指定不同 --group |
| `不支持的文件格式：xxx`（单文件导入） | 单文件后缀未命中白名单（默认 `.md`） | 改名/转换格式，或 config `scopes.<scope>.import.extensions` 配置白名单 |
| `未发现 .md 文件` | 目录内无白名单格式文件（隐藏文件跳过） | 检查白名单配置与文件扩展名 |
| 进度文件 / 断点续跑找不到 | 旧文档描述的进度文件机制已废弃 | 中断恢复走 interrupt 标记 + rebuild；`progress.ts` 现仅是控制台进度展示 |
| HTTP `/api/import/status` 返回 404 | 服务重启后内存 job 丢失 | 重新 upload + run（上传目录文件仍在可重用 uploadId） |
| 导入后搜索不到 | `--no-vector` 模式只写 KB 层不产生向量；或 embedding 未配置 | 向量化模式重导；`ki doctor` 检查 embedding 配置 |
| 搜到的内容与 local KB 原文不一致 | 向量 content 存**清洗后 chunk**、KB 存**原文**，两者刻意不同 | 设计行为；如需调整清洗规则用 `--clean-rules` / config |

## 子专家导航

无子专家。本专家依赖"检索与向量客户端专家"（`vectorBulkStore` / `vectorCountScope` / `vectorDeleteScope`）与"存储与配置基础专家"（store/scope/config/clean/chunker）；其产出（relations-cache / local KB / group-index）被"关系与索引管理专家"消费；`interrupt.ts` 的引导被 vector-client（MCP 服务专家依赖的基础层）前置调用。
