> 本契约覆盖本专家的公开能力。契约来源标注函数签名（非行号）。

## 1. 直导导入（`lib/import.ts`）

### 1.1 `handleDirectImport(args: HandleDirectImportArgs): Promise<ImportResult>`

- **用途**：把外部 Markdown 目录（或单个文件）原文直导进 scope（清洗 + 切分 + 向量化 + 建树 + 落盘），幂等追加。
- **契约来源**：`handleDirectImport(args: HandleDirectImportArgs): Promise<ImportResult>`
- **参数（行为语义）**：
  - `scope: string` — 项目隔离标识
  - `sourceDir: string` — 外部 Wiki 根目录**或单个 Markdown 文件**（绝对路径）
  - `group?: string` — 目标 Group 落点（多级路径如 `wiki/部署运维`，不存在自动新建含父路径）。**缺省（undefined/空）时推断**：目录导入按文件的相对子目录落点（顶层子目录名 = 根节点，根目录散文件落 scope name）；单文件导入落 scope name
  - `chunkSize?: number` — 切分目标长度（字符），默认 1000
  - `chunkOverlap?: number` — 切分重叠字符数，默认 150
  - `maxFileSizeBytes?: number` — 单文件大小上限（字节），超限跳过并告警；默认取 config（1MB）
  - `vector?: boolean` — 默认 true；**false（--no-vector）时只写 KB 层不产生向量**（无法被 ki search 召回），且**不动向量层**（不触发覆盖前置清理）
  - `cleanEnabled?: boolean` — 默认 true；false（--no-clean）关闭全部清洗（含外部 hooks）
  - `cleanRules?: Partial<CleanRules>` — 内置清洗规则覆盖（--clean-rules 解析结果）
  - `tags?: string` — 文档级自定义标签（逗号分隔）：持久化到 relation.tags（无论是否向量化）；向量化时每个 tag 额外写一条内容向量（内部保留标签 ki-search/ki-relation/ki-path 被过滤，全为保留标签时告警不打标）
  - `assets?: boolean` — 本地图片附件收集开关（REQ-20260904-001，默认 true）；`false`（`--no-assets` 或 config `import.assets:false`）时不复制附件，前端对图片引用显示占位块
- **返回**：`ImportResult = {ok:true, action:'import', scope, stats: {total, vectorized, errors, skipped, vector, assets}, errors, groups, source}`——`skipped` 含过大/超限/hook 失败/relation 冲突；`groups` 为涉及的 Group 完整路径列表；**`stats.assets` = 已落盘的唯一附件文件数**（非复制次数：同一附件被多篇 md 引用时仅计一次，否则计数会大于磁盘文件数而困惑用户）；`--no-assets` 或配置关闭时为 0
- **异常**：sourceDir 不存在 / 无白名单文件 / 单文件后缀未命中白名单 / scope 基础索引文件缺失 / 同 scope 已有导入进行中 / 全部文件被跳过时抛 `Error`
- **约束**：
  - **幂等语义**：同 sourcePath 重导覆盖；同 group 同 relation 名但 sourcePath 不同（真冲突）跳过；新文件导入
  - **覆盖前置**：vector 模式下 scope 已有向量 → 先全量删除旧向量再重建（即使本次只导一个文件）
  - 成功后自动清导入锁与中断标记；CLI 层额外触发 autoBackup

```ts
import { handleDirectImport } from './lib/import.js';
const result = await handleDirectImport({
  scope: 'myproj',
  sourceDir: '/path/to/wiki',        // 目录或单个 .md 文件
  group: 'wiki/部署运维',             // 可选：缺省走推断
  tags: 'backend,api',               // 可选
});
console.log(result.stats); // { total(chunks), vectorized, errors, skipped, vector, assets }
```

### 1.2 本地图片附件收集（REQ-20260904-001，`lib/import.ts`）

导入时解析 md 引用的**本地相对路径图片**并复制进 KB，使 Web 前端能显示原文里的图。

- **落盘位置**：`getAssetsDir(scope, groupPath)` = `kb/{scope}/{groupPath}/assets/`（`lib/scope.ts`）。选 group 级而非 scope 级，是为了**与 local KB 同生命周期**：`delete-group` 的 `rmSync` 整 group 子树、backup 的 tar 整 scope 都**自动覆盖附件，零连带代码**。
- **目录结构**：保持相对 md 的原路径（`images/x.png` → `assets/images/x.png`），故前端可直接用原 URL 寻址，**无需映射表**。
- **只收集相对路径**：`isCollectibleRelativeAsset(url)` 排除 http(s) 外链、协议相对 `//`、posix 与 windows 绝对路径、`file://`、`#` 锚点。
- **安全边界**：复制前经 `realpath` 复检仍须落在 `sourceDir` 内——防「后缀伪装成图片的符号链接」越界读宿主机任意文件。
- **不阻断原则**：单附件超限（默认 5MB，`import.maxAssetSize`）/ 后缀不在白名单 / 源目录下未命中 / 越界，均为**告警一行 + 跳过该附件**，不中断导入（与单文件超限跳过的口径一致）。
- **引用提取**：`extractImageRefs(mdText)` 同时覆盖 markdown `![alt](url)` 与 HTML `<img src>`；**仅代码围栏外**（围栏内的示例图片不当真实引用，否则产生无谓告警）；归一化剥 CommonMark 尖括号 destination、尾部 title 与 `#fragment`。返回**顺序语义：先遍历完 markdown 语法、再遍历 HTML `<img>`**（非文档出现顺序）。
- **后缀白名单**：`ASSET_EXTENSIONS = ['.png','.jpg','.jpeg','.gif','.svg','.webp','.ico','.bmp','.avif']`（与服务端 `ASSET_MIME` 对应）。

```ts
import { extractImageRefs, isCollectibleRelativeAsset, collectAndCopyAssets, ASSET_EXTENSIONS } from './lib/import.js';
extractImageRefs('![图](images/a.png)\n<img src="b.png">'); // ['images/a.png', 'b.png']
```

### 1.3 辅助导出（`lib/import.ts`）

- **`deriveChunkRelation(filePath, chunkIndex): string`** — chunk 的 relation 名（`文件名-N`，如 `api-01`）
- **`deriveChunkSourcePath(filePath, chunkIndex): string`** — chunk 的 sourcePath（`文件路径#N`，文件级聚合键）
- **`readFileToChunks(absPath, chunkSize, chunkOverlap): Chunk[]`** — 读文件并切分（未超限返回单 chunk）

## 2. 导入防护（`lib/interrupt.ts`）

### 2.1 中断标记

- **`writeInterruptMark(scope, mark: {processedFiles, totalFiles, signal}): void`** — 原子写 `kb/{scope}/import-interrupt.json`（自动补 scope + interruptedAt）
- **`readInterruptMark(scope): InterruptMark | null`** — 读取；不存在或损坏返回 null
- **`clearInterruptMark(scope): void`** — 清除（成功导入 / rebuild 成功 / 手动恢复后）
- **`interruptGuidance(scope): string | null`** — 有标记返回恢复引导文案（建议 `ki restore <scope> --rebuild-vector`）；由 vector-client 在打开向量库前统一调用

### 2.2 导入锁

- **`acquireImportLock(scope): boolean`** — 获取锁（`.import.lock`）；已有**存活 pid** 的锁返回 false（并发拒绝）；pid 已死或锁损坏 → 自动清理后获取（SIGKILL 残留自愈）
- **`releaseImportLock(scope): void`** — 正常完成释放（同时清除中断标记）
- **`clearImportLock(scope): void`** — 仅删锁（中断路径用，保留标记供引导）

```ts
import { acquireImportLock, releaseImportLock } from './lib/interrupt.js';
if (!acquireImportLock('myproj')) throw new Error('已有导入进行中');
try { /* 导入 */ } finally { releaseImportLock('myproj'); }
```

## 3. 批量向量化（`lib/batch-vectorize.ts`）

### 3.1 `bulkVectorize(entries, scope, options?): Promise<BatchVectorizeResult>`

- **用途**：批量向量化（推荐，一次 `vectorBulkStore`，共享 engine）。
- **返回**：`{ok: Map<path, docId>, errors: [{path, error}]}`。
- **行为语义**：空数组直接返回空结果；失败逐条上报不中断；`onProgress` 完成后回调一次。

```ts
import { bulkVectorize } from './lib/batch-vectorize.js';
const { ok, errors } = await bulkVectorize(entries, 'myproj');
for (const [path, docId] of ok) console.log(path, docId);
```

### 3.2 `vectorizeOne(entry, scope, options?)` / `batchVectorize(...)` / `deleteMemory(memoryId, scope, options?)`

- **`vectorizeOne`**：单条 `vectorStore`（返回 `{ok:true, memoryId} | {ok:false, error}`）。
- **`batchVectorize`**：串行逐条向量化（`bulkVectorize` 的批量版为推荐路径）。
- **`deleteMemory`**：按 docId 删除向量。

### 3.3 `buildVectorizeContent(entry): string`

- **用途**：构造向量化 content 文本（content 纯化契约：直接返回 `entry.text/summary`，关键词经 `keywords` 参数传底层追加）。

## 4. 路径向量化（`lib/path-vectorize.ts`）

### 4.1 `buildGroupPathContent(groupPath): string` / `buildRelationContent(relationText, groupPath?): string`

- **`buildGroupPathContent`**：路径层级空格分隔（含根节点，禁止 `/`）。
- **`buildRelationContent`**：只含 Relation 名称（Group 归属经结构化字段存储）。

### 4.2 `bulkStorePaths(entries, options?): Promise<PathVectorizeResult>` / `storeOnePath(entry, options?)` / `deletePathVector(text, tag, scope, options?)`

- **`bulkStorePaths`**：批量存储路径向量（按 scope 分组）；`PathVectorizeEntry = {text, tag: 'ki-path'|'ki-relation', scope, group?}`。
- **`deletePathVector`**：语义搜索命中**精确同文本**才删（避免误删近似条目）。

## 5. 向量重建（`lib/rebuild-vector.ts`）

### 5.1 `rebuildScopeVectors(scope, deps?, opts?): Promise<RebuildVectorResult>`

- **用途**：从已还原 KB 重建向量并回写 memoryId。
- **契约来源**：`rebuildScopeVectors(scope: string, deps: RebuildDeps = {}, opts: RebuildVectorOptions = {})`
- **参数（行为语义）**：
  - `deps.bulkStore` / `deps.deleteScope` — 依赖注入（测试 mock），缺省用真实实现
  - `opts.groupFilter?: string` — `--group` 过滤：仅重建该 Group 子树（自身或子孙）；**指定后为局部重建（不清空 scope 旧向量）**
  - `opts.tags?: string` — `--tags` 打标：与范围内 relation 已有 tags 合并去重（**只增不减**）
  - `opts.tagsProvided?: boolean` — CLI 层显式传入标记（NEG 提示用）
  - **无 groupFilter 且无 tags → 全量重建**：先清空 scope 旧向量再重建（幂等）
- **返回**：`{ok, scope, stats: {content, relation, path, tag, succeeded, failed, updatedMemoryId, taggedRelations}, errors}`。
- **异常**：scope 数据目录 / relations-cache.json 不存在返回 `ok:false`；清空旧向量失败中止。
- **约束**：数据源完全来自已还原 KB（自包含）；content docId 回写 relations-cache（防悬空引用）；被 `ki restore --rebuild-vector` / `--group` / `--tags` 消费。

```ts
import { rebuildScopeVectors } from './lib/rebuild-vector.js';
const result = await rebuildScopeVectors('myproj');                            // 全量
const part = await rebuildScopeVectors('myproj', {}, { groupFilter: 'wiki' }); // 局部
```

## 6. HTTP 导入接口（`lib/mcp-http-api.ts`）

| 接口 | 方法 | 入参 | 返回 |
|------|------|------|------|
| `/api/import/upload` | POST | `{scope, files: [{name, content(base64)}]}` | `{ok, uploadId, files, total, errors?}`；全败 400 |
| `/api/import/run` | POST | `{scope, uploadId, group?, chunkSize?, chunkOverlap?, vector?, tags?}` | `202 {ok, jobId, scope}`；异步执行 |
| `/api/import/status` | GET | `?jobId=` | `{ok, job: {id, state, phase, progress, result, error, ...}}`；未知 jobId 404 |
| `/api/asset` | GET | `?scope&group&path` | 附件二进制 + 正确 `Content-Type`；详见下方 |

- **约束**：扩展名白名单 `.md/.markdown/.mdx`；`group` 缺省与 CLI 语义一致（推断落点）；job 为进程内存态，服务重启后 404；鉴权模式下 scope 越权返回脱敏 403。

#### 6.1 `GET /api/asset`（REQ-20260904-001）

读取 group 级 `assets/` 目录下导入时复制的本地图片，供 Web 前端渲染原文时寻址。

- **纯文件读取**（不经向量引擎）→ **导入后无需重启即生效**（与 `/api/doc/list` 同模式）。
- **双锚点防穿越**（必须两道都校）：
  - `group`：拒绝对路径与含 `..` / `.` / 空段的值（400）——**`group` 原样进 `path.join` 会搬移下方前缀校验的锚点**，单靠 path 校验会同时失效 → 跳 scope 越权、甚至读 KB 外宿主机文件（该缺陷已由 code review 实机 HTTP 实证并修复）。
  - 解析后的绝对路径必须仍落在 `kbRoot` 与 `assetsDir` 内（否则 403）。
- **404 不伪装**：缺失附件与非图片后缀均返回 **404 + JSON**，不走 SPA fallback。（对比：静态页 fallback 对取不到的路径返回 `index.html` + **HTTP 200**，会把破图伪装成成功且零可诊断信息。）
- **解码容错**：`decodeURIComponent` 失败时回退原值（与导入侧对称），使文件名含裸 `%`（如 `50%.png`）不至永远 404。
- **SVG 安全头**：`X-Content-Type-Options: nosniff` + `Content-Security-Policy: sandbox`（SVG 可含脚本，同源打开会构成 XSS）。
- **鉴权**：已加入 `handleApiRequest` 的 **query scope 越权校验列表**（同 `/tags`、`/doc/list`）——注意这是「生效拦截」列表而非「豁免」列表：**新增带 scope 参数的只读接口必须同步加入，否则该接口不受越权拦截**。effective scope = query `scope` 或 `'default'`（缺省不绕过授权），越权返回脱敏 403（scope 名只写服务端 stderr）。
- **前端调用形态**：URL 由 `web/src/components/MarkdownPreview.tsx` 直接拼接（**不经 `httpApi.ts` 封装**），因为它作为 `<img src>` 而非 fetch 消费。

## 7. CLI 入口（`src/import.ts`）

### 7.1 `ki import`

```
ki import --source <dir|file> [--scope <s>] [--group <path>]
                  [--chunk-size <n>] [--chunk-overlap <n>] [--no-vector]
                  [--tags <tags>] [--no-clean] [--no-assets] [--clean-rules <rules>]
```

- **扁平命令，无子命令层级**（diff/scan/vectorize 已移除）；stdout 输出 `ImportResult` JSON，进度写 stderr；成功后自动备份。
- **不接受任何位置参数**：多传位置参数会被 commander 拒为 `too many arguments`（非 0 退出）；必填项检查先于多余参数检查，故缺 `--source` 时优先报 `required option '--source <sourceDir>' not specified`。
- 历史（2026-09-07）：命令由 `ki scan-kb import` **扁平化为 `ki import`**（源文件同步重命名 `src/scan-kb.ts` → `src/import.ts`）。原登记的「已知边界：保留 scan-kb 壳未扁平化（改面大，用户决策暂缓）」**已由用户拍板解除**：硬切、**不保留兼容别名**，旧调用报「未知命令」+ 可用命令清单（退出码 1）。扁平化必要性：`bin/ki.mjs` 的 COMMANDS 是单级映射且会剥掉子命令名，与 commander 嵌套子命令不兼容（实测直传 `--source` 报 `unknown option`）。

## 已知约束汇总

- 覆盖导入（vector 模式）是 **scope 级全量清空重建**——跨多次导入的文件须在同一源目录内幂等重导
- 单文件导入的后缀必须命中 extensions 白名单（fail-loud，非静默跳过）
- 自定义标签不可使用内部保留标签（ki-search / ki-relation / ki-path）
- 进度文件断点续跑已废弃，勿使用 `progress.ts` 的进度文件函数
