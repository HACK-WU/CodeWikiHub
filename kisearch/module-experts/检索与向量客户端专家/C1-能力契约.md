## 0. 入口对照（CLI ⇄ MCP ⇄ 纯函数）

## 1. 引擎生命周期（`src/lib/vector-client.ts`）

### 1.1 `getEngine(): Promise<ZvecEngine>`

- **用途**：获取进程内唯一 ZvecEngine 单例（首次 `dbPath` 不存在 → create，已存在 → open）。
- **返回**：`Promise<ZvecEngine>`。
- **异常**：`embedding.apiKey` 未配置 → 同步抛错（fail-loud，不做任何隐式 env 回退）；被其他进程持锁 → `CollectionLockedException`（附可操作处置提示）；create/open 超 20s → 抛错并 fire-and-forget 关闭孤儿 engine。
- **约束**：
  - 进程内单例；probe → create/open 全链路经 `serializeEngineOp` **串行排队**（同进程并发 ZVecOpen 同一 dbPath 实测约 62% 概率触发原生竞态永久阻塞）。
  - 失败时自动重置单例缓存，下次调用可重试自愈。

```ts
import { getEngine, closeEngine } from './lib/vector-client.js';
try {
  const engine = await getEngine();
  // ... 使用 engine
} finally {
  await closeEngine();
}
```

### 1.2 `closeEngine(): Promise<void>`（别名 `resetEngine`）

- **用途**：关闭 engine（terminate worker + 释放 LOCK）并重置缓存。
- **行为语义**：**先置空缓存再 close**——close 期间新的 `getEngine` 会走 reopen + 撞锁重试，而非拿到正在 closing 的旧 engine（避免 `WorkerCrashedError` 竞态）。close 本身也经 `serializeEngineOp` 串行化。
- **约束**：**CLI per-call 结束必须调用**，否则 worker 线程持引用导致进程无法退出。

### 1.3 `enableIdleClose(idleMs: number): void`

- **用途**：启用向量库**空闲释放锁**——空闲超过 `idleMs` 自动 `closeEngine` 释放 LOCK，让其他 MCP 实例 / CLI 能错开抢锁；下次调用惰性 reopen（实测约 0.7s）。
- **行为语义**：定时器间隔 `max(500, idleMs/2)`；**在途保护**——`_inFlightOps > 0`（含 embedding 网络阶段）时禁止释放。
- **约束**：**仅供常驻 MCP 层调用，CLI 勿用**（CLI 未启用时 `_idleCloseMs` 恒 0，无副作用）。

```ts
import { enableIdleClose } from './lib/vector-client.js';
enableIdleClose(3000); // 常驻 MCP 进程：空闲 3s 释放锁
```

### 1.4 `ensureVectorAvailable(scope?, opts?): Promise<VectorAvailableResult>`

- **参数**：
  - `scope?: string` — **传入才做中断标记前置检测**（REQ-02），检测到导入中断标记时向 stderr 输出可执行的恢复引导，**不阻断**后续执行。
  - `opts?: { fastFail?: boolean }` — `true` 时单次 probe 不重试，撞锁立即返回不可用（供 scope 枚举等轻量路径使用，避免为等锁白耗十余秒）。
- **返回**：`{ available: boolean; reason?: string; code?: 'LOCKED' | 'CORRUPTED' | 'PROBE_ERROR' }`。
- **行为语义**：
  - 本进程 engine 单例已存在 → 等其 settle 即返回，**不重新 probe**（重 probe 会被自家 LOCK 挡住而误报"被其他进程占用"，导致常驻服务每进程只能用一次）。
  - `dbPath` 不存在 → 可用（首次 store 会 create）。
  - 被其他进程持锁 → `LOCKED`（reason 为含 5 步处置方式的完整提示）。
  - `exists && !healthy` → `CORRUPTED`。
- **异常**：不抛异常，一律转为 `available: false` + `code`。

```ts
import { ensureVectorAvailable } from './lib/vector-client.js';
const avail = await ensureVectorAvailable(scope, { fastFail: true });
if (!avail.available) console.error(`不可用：${avail.code} — ${avail.reason}`);
```

### 1.5 `runWithVectorSource(source, fn)` / `getVectorOpSource()`

- **用途**：标注当前异步链的向量操作来源（HTTP 端点名 / MCP 工具名）。`probeWithRetry` 的撞锁日志会附带该来源，便于从服务端日志直接定位是哪个端点/工具触发撞锁。
- **返回**：`runWithVectorSource` 透传 `fn` 返回值；`getVectorOpSource()` 返回 `string | undefined`（未标注时）。

```ts
import { runWithVectorSource } from './lib/vector-client.js';
runWithVectorSource('/api/search', () => executeSearch({ scope, query }));
```

## 2. 检索与写入（`src/lib/vector-client.ts`）

### 2.1 `vectorSearch({scope, query, limit?, tags?, threshold?})`

- **用途**：混合检索（语义 + FTS + RRF），按 scope + tag 过滤。
- **参数行为语义**：
  - `tags?: string | string[]` — 不传/空 → **不按 tag 过滤**（搜该 scope 下全部 tag）；传值 → 多 tag 以 **OR** 组合。**传数组优于逗号分隔字符串**：tag 值本身可能含逗号，`join/split` 往返会错拆。
  - `threshold?: number` — RRF 融合分阈值，低于则过滤；不传 → 不过滤。**注意：融合分量级远小于 1，不可沿用余弦阈值 0.75**。
  - `limit?: number`（默认 `10`）。
- **返回**：`Promise<VectorSearchResult[]>`，元素为 `{ memoryId, content, score, tag?, group? }`；`score` 越大越相关。
- **异常**：scope 非法 / 向量不可用 / worker 不可用（后者 `withEngine` 自动重置重开重试一次）。

```ts
import { vectorSearch } from './lib/vector-client.js';
const hits = await vectorSearch({ scope: 'myproj', query: '用户登录', limit: 10 });
const filtered = await vectorSearch({ scope: 'myproj', query: '告警', tags: ['ki-search', '告警'] });
```

### 2.2 `vectorStore({scope, text, tags?, group?})`

- **用途**：存储单条（幂等 upsert）。
- **参数行为语义**：`tags` 默认 `ki-search`（单值字段，多 tag 必须分 doc）；`group` 写入结构化 Group 标量字段。
- **返回**：`Promise<{ docId }>`。
- **异常**：`text` 超过 `MAX_TEXT_LENGTH = 50_000` 字符 → 抛错；apiKey 缺失 / 维度不匹配 / 底层写入失败（`result.failed > 0`）→ 抛错。

```ts
import { vectorStore } from './lib/vector-client.js';
const { docId } = await vectorStore({ scope: 'myproj', text: '登录流程', tags: 'ki-search' });
```

### 2.3 `vectorBulkStore({scope, entries})`

- **用途**：批量存储（幂等 upsert，**一次 embedding + 一次 worker upsert**）。
- **参数**：`entries: { text: string; tags?: string; group?: string }[]`。
- **返回**：`{ total, succeeded, failed, results: [{ index, memoryId?, success, error? }] }`。
- **行为语义**：**空数组直接返回 0 计数**（不报错）；逐条失败按 doc id 定位上报，**不整体中断**。

```ts
import { vectorBulkStore } from './lib/vector-client.js';
const r = await vectorBulkStore({
  scope: 'myproj',
  entries: [{ text: 'a', tags: 'ki-search' }, { text: 'b', tags: 'ki-relation' }],
});
console.log(`${r.succeeded}/${r.total}`, r.results.filter((x) => !x.success));
```

### 2.4 `vectorDelete({scope, ids})`

- **用途**：按 doc id 批量删除。
- **返回**：`{ deleted: number; errors: { id, code, reason }[] }`。
- **行为语义**：`scope` 仅作护栏一致性校验（删除按 doc id 全局定位）。**`code === 'NOT_FOUND'` 视为已清理，不算失败**——幂等重删不误报；调用方（如 `executeDeleteGroup`）据此判定是否残留孤儿向量。

```ts
import { vectorDelete } from './lib/vector-client.js';
const r = await vectorDelete({ scope: 'myproj', ids: [docId] });
const real = r.errors.filter((e) => e.code !== 'NOT_FOUND');
```

### 2.5 `generateDocId(text, scope, tag?): string`

- **用途**：生成 doc id，`sha256(text + scope + tag)` 截 32。
- **行为语义**：**tag 参与 id 生成**——同 scope+text 打不同 tag → 不同 docId → 各自独立 doc（支撑"一个内容多 tag 各写一条"）；同 scope+text+tag → 同 docId → 幂等 upsert。
- **约束（⚠️ breaking 迁移影响）**：此 scheme 改变了所有调用 `vectorStore`/`vectorBulkStore` 的链路（sync-relation、scan-kb import、bulk-store、path-vectorize、batch-vectorize）产出的 docId。存量 cache 的 `memoryId`/`memoryIds` 指向的 docId 失效 → 原文召回、按 docId 精确删除、幂等重导在迁移前不可靠。**部署含存量向量数据时需全量 re-import 或 `ki restore <scope> --rebuild-vector` 迁移。**

```ts
import { generateDocId } from './lib/vector-client.js';
const id = generateDocId('登录流程', 'myproj', 'ki-search');
```

## 3. 管理面（`src/lib/vector-client.ts`）

> 管理面函数一律用 `validateScope`（仅字符安全）而非 `resolveScope`（strict 白名单），以便操作"未注册但向量层有数据"的 scope。

### 3.1 `vectorListDocs({scope, tags?, limit?})`

- **用途**：列出 scope 下文档（listIds + fetch）。
- **返回**：`VectorDocInfo[]`（`{ docId, scope?, tag?, content }`）。
- **约束**：**顺序为引擎内部顺序，无排序保证**；`limit` 默认 `10`；`tags` 空/未传 → 不按 tag 过滤。

### 3.2 `vectorFetchDocs(ids): Promise<VectorDocInfo[]>`

- **用途**：按 doc id 批量取回（供 `doc delete` 删前预览与 scope 护栏核对）。空数组返回 `[]`。

### 3.3 `vectorListScopes(scanLimit?): Promise<string[]>`

- **用途**：枚举向量层出现过的所有 scope（distinct）。
- **约束**：引擎无 distinct API → `listIds` 全量 + fetch 取 scope 字段去重；受 `scanLimit`（默认 `10_000`）约束，大库为"已扫描范围内"的结果。

### 3.4 `vectorListTags({scope, scanLimit?})`

- **用途**：枚举 scope 下所有 tag（distinct + 计数）。
- **返回**：`{ tags: {tag, count}[]; scanned: number; truncated: boolean }`；`tags` 按 count 降序、同 count 按 tag 字典序。
- **约束**：`truncated: true` 表示结果受 `scanLimit`（默认 `10_000`）截断，是"已扫描范围内"的近似值。

### 3.5 `vectorCountScope({scope, tags?}): Promise<number>`

- **用途**：统计 scope（可选 tag）下文档数。受 `LIST_ALL_LIMIT = 10_000` 约束。

### 3.6 `vectorDeleteScope({scope, tags?}, onProgress?)`

- **用途**：删除 scope（可选 tag）下**全部**文档（循环分批以覆盖 > 10_000 的情况）。
- **返回**：`{ deleted: number }`；`onProgress(deleted累计)` 供导入覆盖场景做动态进度展示。
- **约束**：**无进展保护**——本批 `res.ok === 0`（全部报错/被锁）时立即退出，避免死循环空转。

```ts
import { vectorDeleteScope } from './lib/vector-client.js';
await vectorDeleteScope({ scope: 'myproj' }, (n) => process.stderr.write(`已清 ${n}\r`));
```

## 4. 原文定位（`src/lib/relation-map.ts`）

### 4.1 `getRelationMap(scope, ttlMs?): Map<string, RelationMapEntry>`

- **用途**：memoryId → `{ group, relation }` 反查映射（带缓存），供检索命中后定位 local KB 原文。
- **参数**：`ttlMs` 默认 `10 * 60 * 1000`（10 分钟，测试可注入小值验证过期重建）。
- **返回**：`Map<string, RelationMapEntry>`（`RelationMapEntry = { group, relation }`）；文件缺失/损坏 → **空 Map，不抛错**（调用方降级为不带定位字段）。
- **缓存策略**：
  - 命中条件：`relations-cache.json` 的 **mtime + size 均未变** 且 距构建未超 TTL（size 兜底毫秒精度下 mtime 未变的原地改写）。
  - 失效：mtime 或 size 任一变化 → **立即失效重建**（避免 10 分钟内反查到 sync-relation/import 后的陈旧映射）；TTL 过期兜底。
  - 懒构建无定时器：首次 O(N)（N = 全部 `hot_relations` 条数），后续 O(1)。
- **行为语义**：**优先多值 `memoryIds`**（全部 chunk memoryId → 同一文件级 relation），无 `memoryIds` 时回退旧数据单值 `memoryId`。`keywords` / `isFullText` 字段已删除（REQ-05），旧数据中的这些字段被忽略。

```ts
import { getRelationMap } from './lib/relation-map.js';
const map = getRelationMap('myproj');
const meta = map.get('some-memory-id');
if (meta) console.log(meta.group, meta.relation);
```

### 4.2 `clearRelationMapCache(): void`

- **用途**：测试辅助，清空全部 scope 的缓存条目。

## 5. 检索编排（`src/search.ts`）

### 5.1 `executeSearch({scope?, query, limit?, threshold?, tags?, includeOriginal?})`

- **用途**：CLI 与 MCP 共享的检索入口（向量检索 + memoryId 反查 + 原文召回 + 去重）。
- **返回**：`{ ok: true; scope; results: SearchHit[] } | { ok: false; error; degraded? }`。
- **行为语义**（按顺序）：
  1. scope 护栏 → `ensureVectorAvailable(scope)`（不可用 → `ok:false` + `degraded:true`）。
  2. **检索策略**（2026-08-28 `6a18a61` 重构）：
     - **显式传 `tags`** → 单次查询（多 tag OR）。
     - **不传 `tags`（默认搜全部）** → `vectorListTags` 枚举 tag → **单次多 tag OR 查询**（`topk = limit × tag数`），**embedding 只做 1 次** → 按 tag 分组各取前 `limit` 条 → 按 `TAG_PRIORITY` 排序（`ki-search` > `ki-relation` > `ki-path` > 自定义垫底）。
     - ⚠️ 与旧"逐 tag 分查"**近似等价**：`topk` 为全局分配，极端场景（单 tag 命中数超过 `limit×N` 且 score 全面占优）下其他 tag 可能被挤出；多数场景因下游 `(group, relation)` 去重而效果一致。
  3. **memoryId 反查**：`getRelationMap` 命中 → 附加 `group` / `relation`。
  4. **原文召回**（仅 `includeOriginal === true`）：命中 `(group, relation)` → `fetchOriginal` 从 local KB 取**文件级原文**，成功置 `originalRetrieved: true` + `original`；失败 → **降级返回向量文档 `content` 兜底**并置 `originalRetrieved: false` + `originalHint`。未命中反查（如 `ki store` 数据）→ 同样降级兜底 + 提示"无法定位本地 KB 原文"。
  5. **多 tag 去重**：同一 `(group, relation)` 因多 tag 写入产生多条命中 → 只保留 **score 最高**的一条，结果按 score 降序。
  6. **多 chunk 原文去重**（仅 `includeOriginal`）：同一 `(group, relation)` 的后续命中删除 `original`、`originalRetrieved` 保持 `true`、标注 `deduplicated: true`。
- **`SearchHit` 字段**（继承 `VectorSearchResult`）：`memoryId` / `content` / `score` / `tag?` / `group?` + `relation?` / `originalRetrieved?` / `original?` / `originalHint?` / `deduplicated?`。
- **约束**：`includeOriginal` 默认 `false`——**默认只返回向量匹配数据，不返回原文**（REQ-09）；CLI `--original` / MCP `include_original` 显式开启。

```ts
import { executeSearch } from './search.js';
const r = await executeSearch({ scope: 'myproj', query: '告警收敛', limit: 5 });
if (r.ok) for (const h of r.results) console.log(h.score, h.group, h.relation);

const withOriginal = await executeSearch({ scope: 'myproj', query: '告警收敛', includeOriginal: true });
if (withOriginal.ok) {
  for (const h of withOriginal.results) {
    if (h.originalRetrieved) console.log(h.original);
    else console.warn(h.originalHint, '(已降级为向量文档)');
  }
}
```

```bash
ki search "告警收敛" --scope myproj --limit 5
ki search "告警收敛" --scope myproj --tags "ki-search,告警"
ki search "告警收敛" --scope myproj --original    # 附加 local KB 文件级原文
```

### 5.2 `fetchOriginal(scope, group, relation)`

- **用途**：从 local KB（`kb/{scope}/{group}/index.json`）按 key 取**文件级原文**（未清洗）。
- **返回**：`{ original: string; hint?: string } | null`。
- **行为语义**：KB 文件存在但该 relation 缺失 → `{ original: '', hint: '原文不可用：本地 KB 缺失 relation "…"（可尝试 sync-relation 或 ki restore <scope> --rebuild-vector）' }`；读取异常 → `{ original: '', hint: '原文不可用：本地 KB 读取异常' }`；KB 文件不存在 → `null`。
- **约束**：同步函数。

```ts
import { fetchOriginal } from './search.js';
const f = fetchOriginal('myproj', 'wiki/docs', '告警收敛机制');
if (f?.original) console.log(f.original);
else console.warn(f?.hint ?? 'KB 文件不存在');
```

## 6. 存储与管理 CLI 纯函数

### 6.1 `executeStore({scope?, text, tags?})` — `src/store.ts`

- **返回**：`{ ok: true; scope; docId } | { ok: false; error }`。
- **行为语义**：scope 护栏 → `ensureVectorAvailable()`（**不传 scope，不做中断标记检测**）→ `vectorStore`。`tags` 缺省 `'ki-search'`。
- **约束**：产物**不带原文定位字段**（不写 relations-cache），故 `ki search` 命中此类 doc 时 `group`/`relation` 缺失、原文召回降级为向量文档。

```bash
ki store "登录流程说明" --scope myproj --tags ki-search
```

### 6.2 `executeBulkStore({scope?, inputFile})` — `src/bulk-store.ts`

- **返回**：`{ ok: true; scope; total; succeeded; failed; results } | { ok: false; error }`。
- **行为语义**：输入文件必须是 **JSON 数组**，每项 `{ text: string; tags?: string }`；缺 `text` → 整体报错 `第 N 条缺少 text 字段`。
- **⚠️ 约束**：这是**向量层专用**批量写入——**只写向量，不写 relations-cache / local KB / group-index 树**。用它写"记忆片段"会产生无 cache 归属的孤儿向量；写知识记忆请用 `ki sync-relation --input`（见关系与索引管理专家）。

```bash
ki bulk_store --scope myproj --input ./vecs.json   # [{"text":"...","tags":"ki-search"}]
```

### 6.3 `executeDocList({scope, tags?, limit?, full?})` / `executeDocDelete({scope, ids, yes})` — `src/doc.ts`

- **`executeDocList` 返回**：`{ ok: true; scope; tags: string[]|'all'; count; docs } | { ok: false; error; degraded? }`；`full` 缺省 `false` → content 截断预览 200 字。
- **`executeDocDelete` 返回**：`{ ok: true; scope; requested; deleted; errors } | { ok: false; error; requireConfirm?; willDelete?; notFound?; scopeMismatch? }`。
- **行为语义**：删前先 `vectorFetchDocs` 取回用于预览与核对（docid 不透明，防删错）；**scope 护栏**——只删归属目标 scope 的 docid，跨 scope 的列入 `scopeMismatch` 跳过；**无 `--yes` 则拒绝并回显将删项预览**（`requireConfirm: true`）。

```bash
ki doc list --scope myproj --limit 20 --tags ki-search --full
ki doc delete <docid> --scope myproj --yes
```

### 6.4 `executeTagList({scope, scanLimit?})` — `src/tag.ts`

## 8. 已知约束汇总

- **doc id = `sha256(text + scope + tag)` 截 32**：tag 参与生成，多 tag 各一 doc；此 scheme 变更是 breaking，存量数据需 re-import 或 `rebuild-vector` 迁移。
- **tag 统一转小写**（写入/查询双侧 `normalizeTag`），`==` 比较即忽略大小写。
- **`content` 字段兼作 FTS 字段**（jieba 分词）。
- **默认搜全部只做 1 次 embedding**（多 tag OR + topk 放大），不再逐 tag 分查 N 次。
- **默认不返回原文**（`includeOriginal` 默认 false），显式开启才读 local KB 文件级原文，取不到时降级为向量文档 content。
- **`ki doc delete` 只删向量层**，不联动 KB——删关系请用 `ki delete-relation`（四层联动），否则 relations-cache 的 memoryId 变悬空引用。
- **`ki bulk_store` 不写 KB/树**，只写向量；写知识记忆用 `ki sync-relation --input`。
- **引擎单例 + 串行化**：同进程并发 `probe/open/close` 必须经 `serializeEngineOp`，否则 62% 概率原生竞态永久阻塞。
- **常驻进程须 `enableIdleClose`**，CLI 须 per-call `closeEngine`，否则锁不释放 / 进程不退出。
- **`vectorDelete` 的 `NOT_FOUND` 视为已清理**（幂等重删不算失败）。
- **`vectorListDocs` / `vectorListTags` / `vectorListScopes` 均为近似结果**（引擎无排序 / 无 distinct，受 scanLimit 约束）。
- **`isFullText` / `keywords` 字段已删除**（REQ-05），不要再依赖；原文可用性改由 `originalRetrieved` 表达。
