# C0-使用总览：检索与向量客户端专家

> 上次全量核对：2026-08-28（git commit `9841255`）

## 能力清单

本专家覆盖 kisearch 的 **检索与向量写入入口**（Vector Adapter）：

| 能力 | 说明 | 入口 |
|------|------|------|
| 语义检索 | hybrid（语义 + FTS + RRF），按 scope/tag 过滤；默认搜全部只做 **1 次 embedding** | `vectorSearch` / `executeSearch` |
| 原文召回（REQ-09） | 显式开启时从 local KB 取**文件级原文**；取不到降级为向量文档并提示 | `fetchOriginal` / `executeSearch(includeOriginal)` |
| memoryId 反查 | memoryId → `{group, relation}`，TTL + mtime/size 双失效缓存 | `relation-map.ts` |
| 引擎生命周期 | 进程内单例、open 串行化 + 超时自愈、空闲释放锁、撞锁重试 | `vector-client.ts` |
| 可用性检测 | `LOCKED` / `CORRUPTED` / `PROBE_ERROR` 原因码 + 中断标记引导 | `ensureVectorAvailable` |
| 单条 / 批量写入 | 幂等 upsert，doc id 含 tag | `vectorStore` / `vectorBulkStore` |
| 文档管理 | list / fetch / delete（scope 护栏 + `--yes` 预览确认） | `vectorListDocs` / `vectorFetchDocs` / `vectorDelete` |
| scope / tag 枚举 | distinct + 计数（近似，受 scanLimit 约束） | `vectorListScopes` / `vectorListTags` |
| 清空 / 计数 | `vectorCountScope` / `vectorDeleteScope`（分批 + 无进展保护） | `vector-client.ts` |
| 管理 CLI | `ki doc list` / `ki doc delete` / `ki tag list` | `doc.ts` / `tag.ts` |
| 存储 CLI | `ki store` / `ki bulk_store` | `store.ts` / `bulk-store.ts` |

## 能力边界（本专家不做什么）

- **不提供** 向量引擎底层 API（`ZvecEngine.create/open/search/write`、schema、Filter 编译、18 类类型化异常 → 属向量引擎专家）
- **不提供** 关系写入 / 评分 / Group 树业务（属关系与索引管理专家）
- **不提供** 知识导入 5-Phase 流程（属知识索引导入专家，但其批量向量化与 rebuild-vector 复用本专家 `vectorBulkStore` / `vectorDeleteScope`）
- **不持久化** KB JSON（属存储与配置基础专家）
- **不写** relations-cache（除 `vectorDelete` 按调用方传入 id 删除外，本层不感知 KB 结构）

## 已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|------|----------|----------|
| `embedding.apiKey 未配置` | 配置缺 apiKey | 在 `embedding.apiKey` 填明文或 `${VAR}` 引用；**无任何隐式 env 回退**（避免非该厂商 baseURL 下注入错误密钥） |
| 向量库被占用（LOCKED） | 另一进程持锁打开集合 | 关掉常驻 `ki mcp/server`；常驻层应 `enableIdleClose`；仍报错可 `ki restore <scope> --rebuild-vector` 或 `--from-snapshot` 重建 |
| 日志里分不清哪个端点撞锁 | 多 HTTP 端点 / MCP 工具共用一个进程 | HTTP 层用 `runWithVectorSource('端点名', fn)` 标注，撞锁日志会附带来源 |
| `worker not open (state=closed)` | embedding 网络期撞上 idle close 窗口 | 已修：`_inFlightOps` 在途计数禁止释放 + `withEngine` 自愈重试一次；**自定义 engine 使用必须经 `withEngine`**，直接 `await getEngine()` 会重演竞态 |
| 检索召回不到刚导入的内容 | 存量数据用旧 docId scheme（tag 未参与 hash） | 新 scheme 为 breaking：全量 re-import 或 `ki restore <scope> --rebuild-vector` 迁移 |
| 检索结果无 `group`/`relation` | doc 来自 `ki store` / `ki bulk_store`（不写 KB） | 属预期：这类数据无原文定位字段，原文召回会降级为向量文档 |
| `originalRetrieved: false` | local KB 缺该 relation，或 memoryId 未命中反查 | 看 `originalHint`；可 `sync-relation` 补写或 `ki restore <scope> --rebuild-vector` 重建 |
| 默认 `ki search` 拿不到原文 | 未加 `--original` / `include_original` | REQ-09：默认只返回向量匹配数据，显式开启才读 local KB |
| `ki doc delete` 后 KB 仍有引用 | 只删了向量层 | 删关系用 `ki delete-relation`（四层联动），否则 relations-cache 的 memoryId 变悬空 |
| 用 `ki_bulk_store` 写知识记忆后查不到 | 它是**向量层专用**，不写 cache/KB/树 | 写记忆改用 `ki sync-relation --input`（CLI）或 `ki_bulk_sync_relation`（MCP） |
| `threshold` 传 0.75 过滤掉全部结果 | 沿用了余弦阈值 | 这里是 **RRF 融合分**（量级远小于 1）；默认 0 不过滤，调阈值先从小值试 |
| 多 tag 用逗号字符串错拆 | tag 值本身含逗号 | `vectorSearch` 的 `tags` 传**数组**而非 `join(',')` |
| `tag list` / `doc list` 结果不完整 | 数据量超 scanLimit | 看返回值 `truncated: true`，加大 `--scan-limit`（默认 10000） |
| CLI 进程跑完不退出 | 忘了 `closeEngine()` | 每个 per-call CLI 的 action 末尾必须 `await closeEngine()` |
| 改 `src/zvec-engine` 后行为没变 | 只改源码未重新构建 | 本层从 `dist/zvec-engine/index.js` 导入（worker 只能加载编译产物），须 `npm run build:zvec-engine` |

## 子专家导航

无子专家。本专家的定位与协作面：

- **向量引擎专家** — 本专家是其上层适配层；改引擎公开导出面（异常/方法/类型）后必须重新构建 dist，本层才能加载到新产物
- **知识索引导入专家** — 复用本专家 `vectorBulkStore` / `vectorCountScope` / `vectorDeleteScope` 做批量写入、清空与重建
- **关系与索引管理专家** — 复用 `vectorSearch`（`searchPath` 语义兜底）与 `vectorDelete`（四层联动删除），依赖 `NOT_FOUND` 语义与 `getRelationMap` 反查
- **存储与配置基础专家** — 提供 `config`（embedding / vectorDir）、`scope`（`validateScope` / `resolveScope`）、`store`（`readJson`）、`interrupt`（中断标记引导）
