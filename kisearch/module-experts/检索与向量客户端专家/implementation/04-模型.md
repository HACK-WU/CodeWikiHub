## 向量集合模型

单一 collection `kisearch`，字段定义见 `buildCreateConfig()`：

| 字段 | 类型 | 说明 |
|------|------|------|
| `dense` | 向量（`dimension` 来自 `config.embedding.dimension`，metric `COSINE`） | embedding 向量 |
| `content` | STRING（**兼作 FTS 字段**，tokenizer `jieba`） | 文档文本，混合检索的关键词侧与返回内容 |
| `tag` | STRING（**indexed**） | 单值标签；写入/查询双侧 `normalizeTag` 转小写 |
| `scope` | STRING（**indexed**） | 项目隔离；一 doc 一个 scope |
| `group` | STRING（**indexed**） | 结构化 Group 路径（`ki-relation` 等向量写入时的归属，可能缺失） |

**doc id**：`generateDocId(text, scope, tag)` = `sha256(text + scope + tag)` 截 32。

```jsonc
{
  "id": "7c1c22b6d42f2e48636eac732812132f",   // docId = sha256(text+scope+tag).slice(0,32)
  "text": "告警收敛通过聚合相似告警降低噪声。",
  "fields": {
    "tag": "ki-search",
    "scope": "myproj",
    "group": "wiki/docs"                       // 可选
  }
}
```

> **tag 是单值字段**：一个内容要打多个 tag，必须写多个 doc（这也是 docId 必须含 tag 的原因）。

## 检索结果模型

### `VectorSearchResult`（`vector-client.ts`，向量层原语）

| 字段 | 类型 | 说明 |
|------|------|------|
| `memoryId` | `string` | = doc id（`sha256(text+scope+tag)` 截 32） |
| `content` | `string` | 文档文本（`hit.text ?? fields.content`） |
| `score` | `number` | RRF 融合分，越大越相关；**量级远小于 1** |
| `tag?` | `string` | 该 doc 的 tag |
| `group?` | `string` | 结构化 Group 字段（可能缺失） |

### `SearchHit`（`search.ts`，交付层）

继承 `VectorSearchResult`，扩展：

| 字段 | 类型 | 说明 |
|------|------|------|
| `relation?` | `string` | 文件级 relation 名（`relations-cache` 的 `hot_relations[].text`）；反查未命中时缺失 |
| `originalRetrieved?` | `boolean` | REQ-09：原文是否成功获取（仅 `includeOriginal` 时出现） |
| `original?` | `string` | REQ-09：local KB 文件级原文（未清洗）；获取失败时为**向量文档 content 兜底**；多 chunk 去重时被删除 |
| `originalHint?` | `string` | REQ-09：原文获取失败提示 |
| `deduplicated?` | `boolean` | REQ-09：同一文件多 chunk 命中的后续条，原文已在前一条返回 |

> **`isFullText` / `keywords` 已删除**（REQ-05）：旧数据的这两个字段被忽略，原文可用性改由 `originalRetrieved` 表达。

```jsonc
{
  "ok": true,
  "scope": "myproj",
  "results": [
    {
      "memoryId": "7c1c22b6d42f2e48636eac732812132f",
      "content": "告警收敛通过聚合相似告警降低噪声。",
      "score": 0.0310,
      "tag": "ki-search",
      "group": "wiki/docs",
      "relation": "告警收敛机制",
      "originalRetrieved": true,
      "original": "## 概述\n告警收敛通过聚合相似告警降低噪声。……"
    },
    {
      "memoryId": "4d9fbe994bfffd3dbc7cc706326012c6",
      "content": "……",
      "score": 0.0294,
      "tag": "告警",
      "group": "wiki/docs",
      "relation": "告警收敛机制",
      "originalRetrieved": true,
      "deduplicated": true
    }
  ]
}
```

上例体现两级去重：同一 `(group, relation)` 的多 tag 命中中，第一条为 score 最高者并携带 `original`；后续条 `deduplicated: true` 且不带 `original`。

## 反查与原文模型

### `RelationMapEntry`（`relation-map.ts`）

| 字段 | 类型 | 说明 |
|------|------|------|
| `group` | `string` | Group 路径（`relations-cache` 的 `groups` 平铺完整路径键） |
| `relation` | `string` | 文件级 relation 名（= `hot_relations[].text`） |

映射构建规则：**优先多值 `memoryIds`**（每个 memoryId 都映射到同一 `{group, relation}`），无 `memoryIds` 时回退单值 `memoryId`。

### `fetchOriginal` 返回值

| 形态 | 触发条件 | 含义 |
|------|----------|------|
| `{ original: string }` | local KB 中有该 relation | 取到文件级原文 |
| `{ original: '', hint }` | KB 文件存在但缺该 relation | `hint` 提示可执行 `sync-relation` 或 `ki restore <scope> --rebuild-vector` |
| `{ original: '', hint }` | 读取异常 | `hint` 为"本地 KB 读取异常" |
| `null` | `kb/{scope}/{group}/index.json` 不存在 | 无 KB 文件 |

章节来源：[src/lib/relation-map.ts](file:///root/knowledge-indexer/src/lib/relation-map.ts)（关键符号：`RelationMapEntry` / `getRelationMap`）与 [src/search.ts](file:///root/knowledge-indexer/src/search.ts)（关键符号：`fetchOriginal`）

## 可用性与文档信息模型

### `VectorAvailableResult`

`{ available: boolean; reason?: string; code?: 'LOCKED' | 'CORRUPTED' | 'PROBE_ERROR' }`

| code | 触发 | reason 内容 |
|------|------|-------------|
| `LOCKED` | probe 报 locked（或 `getEngine` 抛 `CollectionLockedException`） | `lockedHint(dbPath)`：5 步处置提示（停常驻进程 → 确认无并发写 → 等锁自动释放 → `ki restore --rebuild-vector` → `ki restore --from-snapshot`） |
| `CORRUPTED` | `probe.exists && !probe.healthy` | 建议 `ki restore <scope> --from-snapshot` 重建 |
| `PROBE_ERROR` | 其他初始化/探测异常 | `向量服务初始化失败: …` / `向量服务检测异常: …` |

### `VectorDocInfo`

`{ docId: string; scope?: string; tag?: string; content: string }`

### `VectorTagInfo` / tag 枚举返回

`{ tag: string; count: number }`；`vectorListTags` 整体返回 `{ tags, scanned, truncated }`。

### 批量写入结果

`BulkStoreItemResult` = `{ index: number; memoryId?: string; success: boolean; error?: string }`；
`VectorBulkStoreResult` = `{ total, succeeded, failed, results }`。

## 结论

本专家的数据模型围绕一个核心键（**docId = sha256(text+scope+tag)**）与三种"降级可见"的返回结构：`SearchHit`（原文缺失时 `original` 兜底 + `originalHint`）、`VectorAvailableResult`（不可用必带 `code` 与可操作提示）、`RelationMapEntry`（反查失败返回空 Map 而非抛错）。常量分布集中在 `vector-client.ts` 顶部，调参前应先确认与工具护栏时序的约束（如 `ENGINE_OPEN_TIMEOUT_MS` 必须小于 `TOOL_TIMEOUT.READ`）。
