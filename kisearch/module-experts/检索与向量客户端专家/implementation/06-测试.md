## 测试组织原则与通用约定

1. **依赖注入替代真实引擎**：`vector-cli-functions` 通过 mock vector 层，直接断言返回结构（如 `degraded`、`ok:false` 的 error 文案），不依赖真实 embedding 服务即可覆盖大部分分支。
2. **缓存行为用文件系统断言**：`relation-map` 通过改写 `relations-cache.json` 的 mtime/size 触发失效，并断言"缓存命中返回同一 Map 实例"。
3. **降级路径优先断言**：原文召回、向量不可用、反查失败三类降级出口均有独立用例——符合项目"给出路而非静默失败"的错误处理哲学。
4. **实测断言**：读回 `relations-cache.json` / local KB 文件做二次校验，确认不只是内存状态正确。
5. **参数化**：同一场景的多个变体（批量输入的非数组 / 缺 text / 空数组）拆为独立用例，失败可精确定位。

## 测试缺口与补充建议

| 缺口 | 影响 | 建议补充 |
|------|------|----------|
| `ensureVectorAvailable` 的 `fastFail` 分支无用例 | scope 枚举等轻量路径的"撞锁立即返回"行为未验证 | 补 `fastFail: true/false` 两分支 |
| `probeWithRetry` 撞锁重试无用例 | 多实例错开共享的核心路径未覆盖 | 补 mock probe 前 N 次返回 locked 的重试用例 |
| `vectorDeleteScope` 无进展保护无用例 | `res.ok === 0` 的死循环保护未验证 | 补"本批零删除即退出"用例 |
| `vectorDelete` 的 `NOT_FOUND` 语义无用例 | 关系与索引管理专家的 `vectorRemoved` 判定依赖此语义 | 补 `code === 'NOT_FOUND'` 视为已清理的断言 |
| `generateDocId` 的 tag 参与无独立用例 | docId scheme 是 breaking 变更，无回归保护 | 补"同 text 不同 tag → 不同 docId"用例 |
| `runWithVectorSource` 撞锁日志来源标注无用例 | 来源标注是运维排障的关键面 | 补 AsyncLocalStorage 透传断言 |
| `vectorListScopes` / `vectorCountScope` 无用例 | 两者均被导入链路依赖 | 补枚举与计数用例 |
| `ki doc` 的 scope 护栏无用例 | 跨 scope 误删防护未验证 | 补 `scopeMismatch` 跳过断言 |
| `test/cli-aliases.test.ts` 过期用例 | 套件退出码非 0 | 删除或替换该断言（见「已知失败」） |

## 结论

本专家 6 个测试文件覆盖检索、原文召回、反查缓存、写入、管理面、引擎生命周期六条主链路，**实测 78/79 通过**，唯一失败为 `cli-aliases` 中的过期用例（断言目标 `ki scan-kb diff` 已移除，与本专家功能无关）。覆盖缺口集中在引擎可用性与锁策略（`fastFail` / `probeWithRetry` / `vectorDeleteScope` 保护 / `NOT_FOUND` 语义）与 docId scheme 回归保护——建议按上表优先级补齐。
