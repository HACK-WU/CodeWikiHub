## 配置项

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `embedding.baseURL` | string（校验为 `http(s)://` 开头） | — | embedding 服务端点（OpenAI 兼容） |
| `embedding.model` | string | — | embedding 模型名 |
| `embedding.dimension` | number（`positiveInt`） | — | 向量维度，**必须与已存在集合一致**，否则 `DimensionMismatchError` |
| `embedding.apiKey` | string | — | 支持明文或 `${VAR}` 引用；**缺失即 fail-loud，无任何隐式 env 回退** |
| `vectorDir` | string | `~/.ki/vector`（由 `getVectorDir` 决定） | 向量集合持久化目录（单进程独占锁） |
| `scopeMode` | `'default' \| 'strict'` | `default` | `strict` 下 scope 必须显式传且已注册，否则 `resolveScope` 拒绝 |

**配置校验**（`ki doctor`，基于 `src/lib/config-schema.ts`）：上述字段的类型与取值（`httpUrl` / `positiveInt` / `literal`）均强校验，未知字段 fail-loud（附 Levenshtein 拼写建议），废弃字段仅告警。

**配置文件位置**：`~/.ki/config.yaml`。

## 命令行接口

| 命令 | 主要参数 | 说明 |
|------|----------|------|
| `ki search <query>` | `-s/--scope` `-q/--query` `--limit` `--threshold` `--tags` `--original` | 语义检索；query 支持位置参数（REQ-12，`--query` 保留兼容） |
| `ki store <text>` | `-s/--scope` `-t/--text` `--tags` | 单条向量存储；text 支持位置参数 |
| `ki bulk_store` | `-s/--scope` `--input <file>` | 批量**向量层**存储（JSON 数组，每项 `{text, tags?}`） |
| `ki doc list` | `-s/--scope` `--limit` `--tags` `--full` | 列出向量文档（默认截断 200 字） |
| `ki doc delete <docid...>` | `-s/--scope` `--yes` | 按 docid 删除（**无 `--yes` 仅预览**） |
| `ki tag list` | `-s/--scope` `--scan-limit` | 列出 tag（含文档数，近似） |

**退出码**：成功 `0`；参数错误或 `ok:false` 时 `1`。输出统一为 JSON（stdout）。

## MCP 工具

## 日志与输出

- **stdout**：各命令输出 **JSON 结果**（供脚本消费）。
- **stderr**：诊断与提示，包括：
  - **撞锁重试**：`[kisearch][来源] 向量库被其他进程占用，等待 2s 后重试（n/3）...` —— 来源由 `runWithVectorSource` 标注（HTTP 端点名 / MCP 工具名；CLI 路径无来源段）
  - **导入中断引导**：`ensureVectorAvailable(scope)` 检测到中断标记时输出 `⚠ {interruptGuidance}`，引导 `ki restore <scope> --rebuild-vector`
  - **LOCKED 处置提示**：`lockedHint(dbPath)` 的 5 步处置方式
- **无日志文件**：不落盘，不提供日志级别配置。

## 数据存储与锁

| 数据 / 状态 | 落点 | 说明 |
|-------------|------|------|
| 向量集合 | `config.vectorDir`（默认 `~/.ki/vector`） | 单 collection `kisearch`，`dense/content/tag/scope/group` 字段 |
| 独占锁 | 向量库目录内（zvec 维护） | **单进程独占**；常驻层用 `enableIdleClose` 空闲释放，CLI per-call 结束即 `closeEngine` |
| MCP stdio 实例锁 | `~/.ki/mcp-stdio-<pid>.lock` | 多实例进程管理用（属 MCP 服务专家） |
| 导入中断标记 | `kb/{scope}/import-interrupt.json` | `getEngine`/`ensureVectorAvailable` 前置检测并引导恢复 |
| 反查缓存 | 进程内存 | TTL 10min + mtime/size 双失效，进程退出即失 |

**收尾约定**：所有 CLI action 末尾 `await closeEngine()`；常驻服务在 shutdown 时 `closeEngine()`。未启用 `enableIdleClose` 的常驻进程会长期占锁。

## 故障排查

| 现象 | 排查步骤 | 处理 |
|------|----------|------|
| `embedding.apiKey 未配置` | 确认 `embedding.apiKey` | 填明文或 `${VAR}`；无隐式 env 回退是刻意设计 |
| 向量库被占用（LOCKED） | ① 看 stderr 来源标注 ② `ps` 找常驻 ki 进程 ③ 确认常驻层是否 `enableIdleClose` | 停常驻进程；或等锁自动释放；仍失败用 `ki restore <scope> --rebuild-vector` |
| `worker not open (state=closed)` | 检查自定义代码是否绕过 `withEngine` 直接 `await getEngine()` | 所有 engine 使用改走 `withEngine`（自带在途保护 + 自愈重试） |
| 命令跑完进程不退出 | 检查 CLI action 是否 `closeEngine()` | 补 `await closeEngine()` |
| 改了 `src/zvec-engine` 没生效 | 是否重新构建 | `npm run build:zvec-engine`（本层从 `dist` 导入） |
| 检索召回不到刚导入内容 | ① `ki tag list` ② `ki doc list --full` ③ 判断是否命中 docId scheme 变更 | 新 scheme（tag 参与 hash）是 breaking：re-import 或 `ki restore <scope> --rebuild-vector` |
| 结果无 `group`/`relation` | 确认数据来源 | `ki store`/`ki bulk_store` 数据不写 KB，属预期；要定位原文请用 `sync-relation` |
| `originalRetrieved: false` | 看 `originalHint` | KB 缺该 relation → `sync-relation` 补写；KB 读取异常 → `ki restore <scope> --rebuild-vector` |
| `threshold` 过滤掉全部结果 | 是否沿用了余弦 0.75 | 这里是 RRF 融合分（量级远小于 1），从小值试或去掉 |
| 多 tag 过滤结果不对 | tag 值是否含逗号 | `vectorSearch` 的 `tags` 传**数组**而非逗号字符串 |
| `tag list` 结果不全 | 看返回 `truncated` | 加大 `--scan-limit`（默认 10000）；引擎无 distinct，结果本就是近似 |
| 升级后删除/召回异常 | 是否存量数据 | 见"检索召回不到刚导入内容"处理 |
| 测试跑起来挂起 | IDE 注入 `NODE_OPTIONS` | `env -u NODE_OPTIONS -u BASH_ENV npx jiti test/<name>.test.ts` |

## 运维脚本

```bash
# 1) 诊断检索链路（自底向上）
ki tag list --scope myproj                      # 有哪些 tag、是否 truncated
ki doc list --scope myproj --limit 5 --full     # 内容是否写入、tag 是否正确
ki search "关键词" --scope myproj --limit 5      # 召回是否正常

# 2) 带原文检索（REQ-09：默认不返回原文）
ki search "告警收敛" --scope myproj --original

# 3) 清空某 scope 的向量（覆盖导入 / 数据损坏后重建的前置）
ki restore myproj --rebuild-vector              # 按 local KB 原文重建（推荐）
ki restore myproj --from-snapshot --rebuild-vector

# 4) 管理面：查看 + 删除向量文档（先预览后确认）
ki doc list --scope myproj --tags ki-search --limit 20 --full
ki doc delete <docid> --scope myproj            # 仅预览，拒绝执行
ki doc delete <docid> --scope myproj --yes

# 5) 校验配置（字段名/类型/取值）
ki doctor
```

> **删除关系请用 `ki delete-relation`**（四层联动），`ki doc delete` 只删向量层，会让 `relations-cache` 的 memoryId 变悬空引用。

## 关键点与提醒

- **向量库是单进程独占锁**：常驻进程不启用 `enableIdleClose` 会长期占锁，导致所有 CLI 短命令撞锁。
- **docId scheme 含 tag 是 breaking**：部署含存量向量数据时必须规划 re-import 或 `rebuild-vector`。
- **`ki store` / `ki_bulk_store` 写入的是无根数据**：没有 `group`/`relation`，原文召回必然降级。写知识记忆用 `ki sync-relation`。
- **`ki doc delete` 不联动 KB**：删除前先确认 doc 来源。
- **管理面枚举是近似值**：`vectorListScopes` / `vectorListTags` / `vectorListDocs` 均无排序保证且受 `scanLimit` 约束。
- **测试必须剥离 `NODE_OPTIONS`**：否则 IDE 注入的 fs shim 会在批量文件操作时挂起。
- **`cli-aliases.test.ts` 有 1 例过期失败**（`ki scan-kb diff` 已移除），与本模块无关但会让套件退出码非 0，详见 `06-测试.md` 与 `../test/known-failures.md`。

## 结论

本模块的运维面集中在三处：**embedding 配置**（apiKey 缺失即 fail-loud、dimension 变更会导致集合失配）、**独占锁的生命周期**（撞锁重试 + 空闲释放 + CLI per-call 关闭）、**docId scheme 的迁移成本**。日常排障建议按「`tag list` → `doc list` → `search`」自底向上定位，并用 `ki doctor` 兜底配置校验。
