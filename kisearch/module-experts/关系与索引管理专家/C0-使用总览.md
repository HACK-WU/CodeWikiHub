# C0-使用总览：关系与索引管理专家

> 上次全量核对：2026-08-28（git commit `9841255`）

## 能力清单

本专家覆盖 kisearch 的 **关系（Relation）与索引管理**：

| 能力 | 说明 | 入口 |
|------|------|------|
| 关系回写 | 四层写入（relations-cache + local KB + 向量 + Wiki）；支持自定义 tags 打标、非向量化模式 | `sync-relation.ts` |
| 批量关系回写 | 一次 embedding + 一次 worker upsert，含同批去重与逐条容错 | `sync-relation.ts`（`executeBulkSyncRelation`） |
| 评分引擎 | 使用密度评分 + 5 分钟防刷 + 新兴识别 + 冷热分区 + 边界衰减 | `scoring.ts` |
| Group 树 CRUD | create / delete（空节点 + `--force` 级联）/ list-scopes | `manage-index.ts` |
| Group 查询 | 词云 + hot/warm/cold/emerging 分区 + 树渲染（**纯文本输出**） | `query-group.ts` |
| 模块信息查询 | 读 local KB 原文 + 记一次使用（更新评分）+ Relation 语义兜底 | `get-module-info.ts` |
| 关系删除 | 四层联动，wiki 文件移入回收站（非物理删除） | `delete-relation.ts` |
| **目录级删除** | 删除整个 Group 子树（含子 Group）四层数据 + 树节点 | `delete-relation.ts`（`executeDeleteGroup`） |
| **Wiki 历史补齐** | 把 KB 中已有 Relations 全量写回 Wiki（幂等 / `--force` 覆盖） | `wiki-backfill.ts` + `wiki-sync.ts` |
| Wiki 写回 | 单条写回 + 目标目录为空时自动补齐（autoBackfill） | `wiki-sync.ts` |
| 路径解析 | 精确匹配 / 顶层补全 / 部分匹配提示 / 语义兜底（四级） | `group-resolve.ts` |
| 路径搜索 | `ki-path` / `ki-relation` 语义模糊匹配（向量兜底） | `path-search.ts` |

## 能力边界（本专家不做什么）

- **不提供** 批量知识导入（属知识索引导入专家；本专家与其共用 `relations-cache.json` / `group-index.json` / local KB 格式）
- **不提供** 语义检索与原文定位（属检索与向量客户端专家）
- **不提供** 备份 / 还原（属存储与配置基础专家）
- **不做** 内容生成（moduleInfo 由调用方 AI 生成后写入）
- **不做** 破坏性删除的 MCP 暴露——级联删除仅 CLI 可达（NEG-15 决策）

## 已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|------|----------|----------|
| `query-group` 拿不到结构化数据 | 期望返回 JSON 对象 | 该能力返回**已渲染的纯文本** `output`；要结构化数据直读 `relations-cache.json` 或用 `ki doc`/`get-module-info` |
| `--relation 含非法路径字符` 被拒 | relation 含 `/`、`\`、`..` | relation 直接作 wiki 文件名，禁用路径分隔符；改为扁平命名 |
| Wiki 未写回（`synced: false`） | 未配置 source 块 / `wikiSync`，或 `enabled: false` | 配置 `wikiSync: {enabled: true, sourceDir}` 或先执行一次 `scan-kb import` 写 source 块 |
| `enabled: false` 仍写文件（历史 Bug，已修） | 2026-08-27 前，source.dir 存在时不走 enabled 门禁 | 已统一门禁；升级后 `enabled: false` 会同时禁用单条写回与 `wiki-backfill` |
| 开启 wikiSync 后历史关系没落盘 | wikiSync 是事件驱动，只写新增 | 跑一次 `ki wiki-backfill <scope>` 补齐；或依赖写回时的 autoBackfill（目录为空自动触发） |
| 每次 backfill 产生全量 git 脏 diff | 用了 `--force`（刷新 `exportedAt`） | 缺省执行即可（跳过已存在文件）；仅在确需刷新时用 `--force` |
| 模糊路径兜底"没生效" | 调用 `resolveGroupPath` 未传 `scope` | 向量兜底**仅在传 scope 时启用**（`manage-index` 内部即未启用） |
| `delete-relation` 后仍能搜到 | 向量删除失败（`vectorRemoved: false`） | 检查返回值的 `vectorRemoved` / `reason`；残留属孤儿向量，可用 `ki restore <scope> --rebuild-vector` 恢复一致 |
| 目录级删除报"解析为空路径" | group 解析成空串 | 卫兵拦截（防删整个 scope 数据目录），传真实 group 路径 |
| MCP 删节点被拒（非空） | 节点有子节点 / relation / KB 内容 | MCP 仅限空节点；改用 `ki delete-relation -g <group>` 或 `ki manage-index --action delete --force` |
| 非向量化模式写入后搜不到 | `vector: false` / `--no-vector` | 该模式不产生 memoryId，内容不可被 `ki search` 召回；属预期 |
| 评分不涨 | 同一 relation 5 分钟内重复读取/同步 | 防刷间隔 `MIN_RECORD_INTERVAL_MINUTES = 5`；`useCount` 上限 `MAX_USE_COUNT = 10` |
| 批量写入顶层 `vectorStored: false` 但逐条有成功 | 存在部分失败（某条带 `vectorReason`） | 顶层语义为"全部完全成功"；看逐条 `vectorReason` 定位 |
| rootName 相关行为消失 | 沿用旧文档/旧脚本 | rootName 概念已于 2026-08-14 移除，group 即完整相对路径；路径分隔符仅 `/` |

## 子专家导航

无子专家。本专家的协作面：

- **知识索引导入专家** — 共用 `relations-cache.json` / `group-index.json` / local KB；导入是这些数据结构的生产方，改结构须连带（见 ki 强关联记录）
- **检索与向量客户端专家** — 本专家经 `vector-client` 做向量写入/删除/语义兜底
- **存储与配置基础专家** — 提供 `store`/`scope`/`config`（含 `wikiSync` 配置读取）
- **MCP 服务专家** — 本专家的 8 个 MCP 工具注册与 scope 授权在此
