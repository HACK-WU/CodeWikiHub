## 测试组织原则与通用约定

1. **隔离**: 使用临时目录隔离文件系统与配置（`withTempDir` / `withTempScope` 模式），不污染 `~/.ki`。
2. **Mock 向量层**: `sync-relation-bulk-vector` / `delete-group` 通过注入 mock 的 vector 客户端，直接断言 `vectorStored` / `vectorRemoved` / `memMethod` 等返回值，不依赖真实 embedding 服务。
3. **契约优先**: 断言以返回值的字段语义为主（如"部分失败时不删旧向量"），而非实现细节。
4. **实测断言**: 读回 `relations-cache.json` / `index.json` / wiki 文件做二次校验，确认不只是内存状态正确。
5. **参数化**: 同一场景的多个变体（如 autoBackfill 的目录空 / 不存在 / 关闭 / 非空）拆为独立用例，失败可精确定位。

章节来源：[src/delete-relation.ts](file:///root/knowledge-indexer/src/delete-relation.ts)（关键符号：`executeDeleteRelation` / `deleteBySearch`）与 [src/lib/scoring.ts](file:///root/knowledge-indexer/src/lib/scoring.ts)（关键符号：`boundaryDecay` / `partitionByScore`）

## 测试缺口与补充建议

| 缺口 | 影响 | 建议补充 |
|------|------|----------|
| 文档级删除（`executeDeleteRelation`）无独立测试 | wiki 回收站与 `deleteBySearch` 严格匹配（中文边界）未被直接覆盖 | 新增 `test/delete-relation.test.ts`，覆盖 `memMethod` 三级降级与 `.ki/trash` 落点 |
| `batchDelete` 无测试 | CLI `--input` 批量删除路径完全未覆盖 | 补批量删除成功/部分失败用例 |
| `boundaryDecay` 无测试 | 边界衰减的触发条件与单元素退化分支未验证 | 补 `scoring.test.ts`：`triggered` 判定、`originMax` 记录、热区单元素退化 |
| `hybridPartition` / `partitionByScore` 上限截断无测试 | `maxHotCount` 触发时的"先保新兴"规则未验证 | 补大样本构造用例 |
| `resolveGroupPath` 四级降级无独立测试 | 顶层补全 / 多候选 / 向量兜底的存在性校验未被直接覆盖 | 补 `group-resolve.test.ts` |
| 非向量化模式（`vector: false`）单条路径无用例 | `--no-vector` 的 `contentTags: []` 与"搜不到"语义未验证 | 补 `executeSyncRelation({ vector: false })` 用例 |
| `manage-index --force` 级联删除无测试 | `cascadeDeleteGroupData` 与"不清理 wiki"的语义未验证 | 补 CLI 级联用例并与 `delete-relation -g` 做对比断言 |
| MCP 工具层无测试 | zod 参数校验与 scope 过滤未覆盖 | 补 `mcp-tools` 层契约测试 |

## 结论

本专家 7 个测试文件覆盖关系写入（单条/批量）、查询、树管理、目录删除、Wiki 补齐五条主链路，**实测 77 例全绿、0 失败**。覆盖缺口集中在文档级删除、评分纯函数与 MCP 工具层——三者均为契约面而非实现细节缺失，建议按上表优先级补齐。
