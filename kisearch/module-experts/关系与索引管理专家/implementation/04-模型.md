## Relation 模型

`Relation`（`src/lib/scoring.ts` 定义，relations-cache 与知识索引导入链路共用）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `string` | 关系唯一 id，格式 `rel_{三位自增序号}`（`generateNextId` 取全局最大值 +1） |
| `text` | `string` | 关系文本，同时是 local KB 的键与 wiki 文件名（`{text}.md`） |
| `score` | `number` | 当前评分，由 `calculateScore` 计算 |
| `useCount` | `number` | 使用次数，上限 `MAX_USE_COUNT = 10` |
| `lastUsedTime` | `number \| null` | 上次使用时间戳（ms）；`null` = 从未被读取 |
| `isImported` | `boolean` | 是否由导入链路写入（query-group 渲染为 `[📥]`） |
| `memoryId?` | `string` | 内容向量主 docId（`ki-search` 条），向后兼容字段 |
| `memoryIds?` | `string[]` | **全部**内容向量 docId（`ki-search` + 每个自定义 tag 各一）；删除以它为准 |
| `sourcePath?` | `string` | 原始文件相对 posix 路径（导入链路用） |
| `tags?` | `string[]` | 文档级自定义标签（小写、去重、已过滤保留字）；空/undefined 表示仅有默认 `ki-search` |

> **注意**：早期版本的 `isFullText` 字段已删除；`memoryId` 与 `memoryIds` 并存是历史兼容与多 tag 支持的结果。

章节来源：[src/lib/scoring.ts](file:///root/knowledge-indexer/src/lib/scoring.ts)（关键符号：`Relation`）与 [src/sync-relation.ts](file:///root/knowledge-indexer/src/sync-relation.ts)（关键符号：`generateNextId` / `syncSingleRelation`）

## RelationsCache 模型

`relations-cache.json`（落盘路径 `~/.ki/kb/{scope}/relations-cache.json`，经 `store.ts::writeJson` 原子写）：

```jsonc
{
  "version": 1,
  "scope": "my-proj",
  "partition_config": { "hotPercent": 0.3, "warmPercent": 0.5, "reservedEmerging": 10,
                        "recentHours": 48, "minHotCount": 1, "decayStep": 5,
                        "halfLifeHours": 24, "maxHotCount": 10, "maxWarmCount": 50,
                        "maxColdCount": null, "maxKeywordCount": 50 },
  "groups": {
    "wiki/docs": {
      "hot_relations": [
        { "id": "rel_001", "text": "告警收敛机制", "score": 3.33, "useCount": 5,
          "lastUsedTime": 1785000000000, "isImported": false,
          "memoryId": "d0c-abc", "memoryIds": ["d0c-abc", "d0c-def"],
          "tags": ["告警", "收敛"] }
      ],
      "keywords": [],
      "max_hot_count": 10
    }
  },
  "updatedAt": "2026-08-28T00:00:00.000Z"
}
```

**要点**：
- `groups` 是**平铺完整路径键**——`wiki` 与 `wiki/docs` 是彼此独立的键，二者不共享数据。级联操作必须靠 `key === group || key.startsWith(group + '/')` 前缀匹配。
- **只有 `hot_relations` 一个数组**：`warm_relations` / `cold_relations` 不存在，冷热分区是查询时由 `partitionByScore` 现算的。
- `partition_config` 缺省时回退 `DEFAULT_PARTITION_CONFIG`；`max_hot_count` 由 `config.maxHotCount` 初始化。
- `updatedAt` 由存储层维护；`boundaryDecay` 为纯函数，调用方需自行落盘。

章节来源：[src/sync-relation.ts](file:///root/knowledge-indexer/src/sync-relation.ts)（关键符号：`RelationsCache` / `GroupData`）与 [src/query-group.ts](file:///root/knowledge-indexer/src/query-group.ts)（关键符号：`partitionRelations`）

## 评分与分区模型

`PartitionConfig`（`src/lib/constants.ts`）与 `DEFAULT_PARTITION_CONFIG` 当前取值：

| 字段 | 默认值 | 语义 |
|------|--------|------|
| `hotPercent` | `0.3` | 热区席位比例（`totalHotSeats = max(minHotCount, ceil(n * hotPercent))`） |
| `warmPercent` | `0.5` | 温区条数比例（对剩余项取 `ceil`） |
| `reservedEmerging` | `10` | 新兴项在热区的保留席位上限 |
| `recentHours` | `48` | 新兴识别窗口（小时），同时决定 `emerging` 分区口径 |
| `minHotCount` | `1` | 热区席位下限 |
| `decayStep` | `5` | `boundaryDecay` 每步衰减量 |
| `halfLifeHours` | `24` | 评分半衰期（小时） |
| `maxHotCount` | `10` | 热区截断上限（同时是 Group 内关系数淘汰阈值） |
| `maxWarmCount` | `50` | 温区截断上限 |
| `maxColdCount` | `null` | 冷区截断上限，`null` = 不截断 |
| `maxKeywordCount` | `50` | 关键词上限 |

其他常量：`MIN_RECORD_INTERVAL_MINUTES = 5`（防刷间隔）、`MAX_USE_COUNT = 10`（useCount 上限）。

`PartitionResult<T>`：`{ hot: T[]; warm: T[]; cold: T[]; emergingSet: Set<string> }`。

章节来源：[src/lib/constants.ts](file:///root/knowledge-indexer/src/lib/constants.ts)（关键符号：`DEFAULT_PARTITION_CONFIG` / `PartitionConfig`）与 [src/lib/scoring.ts](file:///root/knowledge-indexer/src/lib/scoring.ts)（关键符号：`PartitionResult` / `partitionByScore`）

## Group 树模型

`group-index.json`（`~/.ki/kb/{scope}/group-index.json`）：

```jsonc
{
  "version": 1,
  "scope": "my-proj",
  "groups": {
    "BK-Monitor-Wiki": {           // 节点值即子节点的字典（叶子为 {}）
      "部署运维": {},
      "告警系统设计": { "告警收敛机制": {} }
    }
  },
  "source": { "dir": "/repo/src/docs", ... },   // 可选：wiki 写回目录第一优先级
  "updatedAt": "2026-08-28T00:00:00.000Z"
}
```

**要点**：
- 树节点没有 `_path` / `_relations` 保留键——节点值**纯粹是子节点的字典**，空对象 `{}` 即叶子。
- 无 rootName 概念：路径即完整相对路径，`BK-Monitor-Wiki/部署运维`。
- `source.dir` 存在时，wiki 写回目录优先用它，其次才是配置的 `wikiSync.sourceDir`。

章节来源：[src/lib/scope.ts](file:///root/knowledge-indexer/src/lib/scope.ts)（关键符号：`GroupIndex` / `getSource`）与 [src/lib/group-resolve.ts](file:///root/knowledge-indexer/src/lib/group-resolve.ts)（关键符号：`getDirectChildren` / `pathExistsInTree`）

## 路径解析与搜索模型

`ResolveResult`（`src/lib/group-resolve.ts`）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `resolvedPath` | `string` | 解析后的实际 Group 路径（可能经过补全） |
| `hint` | `string` | 提示信息；空串表示直接匹配无提示 |
| `matched` | `boolean` | 是否匹配成功（路径存在即算成功，即使无 Relations） |
| `candidates?` | `string[]` | 多个顶层 Group 下补全命中时的候选列表 |
| `fuzzyMatched?` | `boolean` | 是否来自向量近似匹配 |
| `fuzzyScore?` | `number` | 向量匹配分数（RRF 融合分） |

`PathSearchResult`（`src/lib/path-search.ts`）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `matched` | `boolean` | 是否找到有效近似匹配（score ≥ 阈值） |
| `rawText` | `string` | 匹配到的原始存储文本 |
| `extractedPath` | `string` | 提取出的路径/名称（未达阈值时为空串） |
| `score` | `number` | RRF 融合分 |

**阈值语义**：`DEFAULT_THRESHOLD = 0`（RRF 分量级远小于 1，不可沿用余弦 0.75）；质量由调用方的存在性/严格匹配校验兜底。异常统一返回 `null`（静默降级）。

章节来源：[src/lib/group-resolve.ts](file:///root/knowledge-indexer/src/lib/group-resolve.ts)（关键符号：`ResolveResult`）与 [src/lib/path-search.ts](file:///root/knowledge-indexer/src/lib/path-search.ts)（关键符号：`PathSearchResult` / `searchPath`）

## 删除结果模型

`DeleteResult`（文档级，`executeDeleteRelation`）：

| 字段 | 说明 |
|------|------|
| `relation` / `group` | 关系名与**解析后**的 group 路径 |
| `deleted` | 等价于 `cacheRemoved` |
| `cacheRemoved` / `kbRemoved` / `wikiRemoved` / `memRemoved` | 四层各自的清理结果 |
| `memMethod` | `'memoryId'`（按 docId 删） / `'search'`（严格匹配兜底） / `'skip'`（向量不可用） / `'none'` |
| `memMemoryId?` / `reason?` | 实际删除的主 docId / 聚合的原因说明 |

`DeleteGroupResult`（目录级，`executeDeleteGroup`）：

| 字段 | 说明 |
|------|------|
| `group` | 解析后的 group 路径 |
| `deleted` | 结构删除是否完成（恒为 true 除非异常） |
| `relationCount` | 级联收集的 relation 总数 |
| `wikiMoved` / `nodeRemoved` | wiki 目录是否移入回收站 / 树节点是否删除 |
| `vectorRemoved` | `false` = 存在残留孤儿向量；无向量可删时为 `true` |
| `reason?` | 向量失败或各层删除失败的聚合说明 |

章节来源：[src/delete-relation.ts](file:///root/knowledge-indexer/src/delete-relation.ts)（关键符号：`DeleteResult` / `DeleteGroupResult` / `executeDeleteGroup`）

## 结论

本专家的数据模型以 `Relation` 为核心（`memoryIds` 多值支撑多 tag 精确清理），`relations-cache.json` 的平铺完整路径键决定了所有级联操作的前缀匹配口径，`group-index.json` 的纯字典树决定了路径解析与补全的实现形态。返回结果模型（特别是 `vectorRemoved` / `memMethod` / `vectorReason`）刻意保留"部分失败"的可观测性，避免静默不一致。与知识索引导入专家共用 `Relation` / `relations-cache` / `group-index` / local KB 四类格式，改动需连带。
