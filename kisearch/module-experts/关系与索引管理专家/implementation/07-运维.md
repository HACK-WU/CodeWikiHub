## 配置项

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `scopes.<scope>.wikiSync.enabled` | `boolean` | 无配置时视为 `true` | Wiki 写回总闸。**显式 `false` 时同时禁用单条 `writeBackToWiki` 与 `backfillWiki`** |
| `scopes.<scope>.wikiSync.sourceDir` | `string` | 无 | Wiki 写回目录。优先级**低于** `group-index` 的 `source.dir`（导入时写入） |
| `scopes.<scope>.wikiSync.autoBackfill` | `boolean` | 无配置时视为 `true` | 目标目录不存在或为空时，写回前先全量补齐历史关系 |
| `scopes.<scope>.maxHotCount` | `number` | `10` | Group 内关系数上限（达上限时淘汰最低分）；同时约束分区热区席位 |

**配置校验**（`ki doctor`，基于 `src/lib/config-schema.ts`）：`wikiSync` 下仅接受 `enabled` / `sourceDir` / `autoBackfill` 三个键，**未知字段 fail-loud**（`CONFIG_FIELD_INVALID`，附 Levenshtein 拼写建议）。

> **已废弃**：`scopes.<scope>.sourceDir`（scope 级）已删除，配置中残留仅告警不阻断，写入无效。勿与 `wikiSync.sourceDir` 混淆。

**配置文件位置**：`~/.ki/config.yaml`。数据目录固定为 `~/.ki/kb`（`KI_DATA_DIR` 仅 `config init` 模板探测生效，运行时不读）。

## 命令行接口

| 命令 | 主要参数 | 说明 |
|------|----------|------|
| `ki sync-relation` | `--scope` `--group` `--relation` `--module-info` `--tags` `--no-vector` | 单条关系回写（四层） |
| `ki sync-relation --input <file>` | 同上（`--group` 等可缺省，由 items 携带） | 批量回写；`--input --no-vector` 走 `syncBatch`（仅 KB + wiki） |
| `ki query-group` | `--scope` `--groups` `--mode` `--hot-count` `--depth` | Group 查询（纯文本输出） |
| `ki manage-index` | `--scope` `--action create\|delete\|list-scopes` `--name` `--parent` `--force` | Group 树管理；`--force` 级联（不动 wiki） |
| `ki get-module-info` | `--scope` `--group` `--relation` | 读取关系原文（**有评分副作用**） |
| `ki delete-relation` | `--scope` `--group` `--relation?` `--input?` | 省略 `--relation` → 目录级删除；`--input` → 批量删除 |
| `ki wiki-backfill <scope>` | `--force` | Wiki 历史补齐（缺省幂等） |

**退出码**：成功 `0`；参数或前置校验失败 `1`（错误以 JSON 输出到 stdout：`{ ok: false, error, code, help }`）。

章节来源：[src/sync-relation.ts](file:///root/knowledge-indexer/src/sync-relation.ts)（关键符号：`executeSyncRelation` / `executeBulkSyncRelation`）与 [src/wiki-backfill.ts](file:///root/knowledge-indexer/src/wiki-backfill.ts)（关键符号：`WIKI_BACKFILL_HELP`）

## MCP 工具

| 工具名 | 参数 | 说明 |
|--------|------|------|
| `ki_sync_relation` | `scope?` `group` `relation` `module_info` `vector?` `tags?` | 单条回写 |
| `ki_bulk_sync_relation` | `scope?` `items[]`（`group` / `relation` / `module_info` / `tags?`）`vector?` | 批量回写（一次 embed） |
| `ki_query_group` | `scope` `groups?` `hot_count?` `depth?` `mode?` `auto_fallback?` | Group 查询 |
| `ki_manage_index_create` | `scope` `name` `parent?` | 建树节点 |
| `ki_manage_index_delete` | `scope` `name` `parent?` | **仅空节点**删除（非空拒绝并给 CLI 指引） |
| `ki_manage_index_list` | 无 | 列 scope（**无参工具**，HTTP 模式下属 `SCOPE_LESS_TOOLS` 白名单） |
| `ki_get_module_info` | `scope` `group` `relation` | 读原文 |
| `ki_delete_relation` | `scope?` `group` `relation` | 文档级删除（**无目录级/批量**） |

**超时**：MCP 工具层 `withTimeout` 对 `ki_sync_relation` 设 WRITE 60s、对 `ki_bulk_sync_relation` 设 BULK 300s（`src/lib/mcp-tools/util.ts::TOOL_TIMEOUT`，含 4 次 embedding 重试余量）。

**scope 授权**：HTTP 模式下，`arguments.scope` 缺省按 `default` 校验；`ki_manage_index_list` 因无 scope 参数走白名单豁免，输出按会话授权过滤。

## 日志与输出

- **stdout**：各命令输出 **JSON 结果**（供脚本消费）。MCP 模式下由工具层包成文本。
- **stderr**：诊断与提示，包括：
  - Group 路径补全 / 未匹配的 `hint`
  - 向量不可用的降级提示（用 `KISearchError` code 标记）
  - `moduleInfo` 超 1000 字符的"内容过长"告警（不切分）
  - autoBackfill 的补齐数量提示
  - `backfillWiki` 的逐条跳过原因
- **无日志文件**：不落盘，不提供日志级别配置。

## 数据存储与清理

| 数据 | 路径 | 清理方式 |
|------|------|----------|
| relations-cache | `~/.ki/kb/{scope}/relations-cache.json` | `delete-relation`（条目/目录）或 `manage-index --force` |
| local KB | `~/.ki/kb/{scope}/{group}/index.json` | 同上（目录级用 `rmSync` 递归删子树） |
| group-index | `~/.ki/kb/{scope}/group-index.json` | `manage-index delete` 或目录级删除的 `removeGroupNode` |
| 向量 | 嵌入式向量库 | 按 `memoryIds` 精确删；失败时以 `vectorRemoved:false` 暴露残留 |
| 外部 Wiki | `{sourceDir}/{group}/{relation}.md` | wiki 文件/目录删除 → 移入 `{sourceDir}/.ki/trash/{group}/`（**不物理删除**） |
| 回收站 | `{sourceDir}/.ki/trash/{group}/` | 需人工清理（系统不自动回收） |

**引擎收尾**：所有命令的 `finally` 块统一 `closeEngine`（关闭 zvec worker 与 embedding worker），避免僵尸进程。

## 故障排查

| 现象 | 排查步骤 | 处理 |
|------|----------|------|
| Wiki 未写回 | ① 看返回值 `wikiReason` ② 确认 `wikiSync.enabled` ③ 确认 `source.dir` 或 `wikiSync.sourceDir` 存在 | 配置目录后跑 `ki wiki-backfill <scope>` 补齐 |
| `enabled:false` 仍在写 | 确认版本 ≥ 2026-08-27（此前 source.dir 存在时会绕过门禁） | 升级；或改走 `wikiSync` 配置 |
| 删除后仍能搜到 | 看 `vectorRemoved` / `memMethod` / `reason` | 残留为孤儿向量：`ki rebuild-vector`（若可用）或检查 API Key；`NOT_FOUND` 属正常幂等 |
| 目录级删除报空路径 | `resolveGroupPath` 解析为空 | 传入真实 group 路径（卫兵防删整个 scope） |
| MCP 删节点被拒 | 看返回的 `children` / relation 数 | 改用 `ki delete-relation -g <group>` 或 `manage-index --force` |
| 批量写入慢 | 确认走的是 `ki_bulk_sync_relation` 而非并发多条 `ki_sync_relation` | 用批量工具（一次 embed + 一次 upsert，实测 2.45s vs 20s） |
| `ki_search` 搜不到刚写入的内容 | ① 是否用了 `--no-vector` ② `vectorStored` 是否为 true ③ `vectorReason` | 非向量化模式无 memoryId，属预期 |
| 评分不涨 | 5 分钟内重复读取 | 防刷预期行为（`MIN_RECORD_INTERVAL_MINUTES = 5`） |
| `ki doctor` 报未知字段 | 看 `CONFIG_FIELD_INVALID` 的拼写建议 | 修正字段名；`wikiSync` 只接受三个键 |

## 运维脚本

```bash
# 1) 开启 wiki 双向同步并补齐历史（推荐组合）
#    ~/.ki/config.yaml 配置 scopes.<scope>.wikiSync
ki wiki-backfill my-proj            # 幂等补齐，不产生 git 脏 diff
ki doctor                            # 校验配置字段名/类型/取值

# 2) 清理整个 Group（含子 Group），wiki 进回收站
ki delete-relation --scope my-proj --group "wiki/docs"

# 3) 只删树节点（不动 wiki），非空需 --force
ki manage-index --scope my-proj --action delete --name "网络治理" --parent "BK-Monitor-Wiki" --force

# 4) 批量回写（推荐多条目场景）
cat > /tmp/batch.json <<'EOF'
{"items":[{"group":"wiki/docs","relation":"告警收敛机制","module_info":"## 概述…","tags":"告警"}]}
EOF
ki sync-relation --scope my-proj --input /tmp/batch.json

# 5) 查看分区与统计
ki query-group --scope my-proj --mode hot,emerging --hot-count 10
```

> **测试环境提示**：本机跑本模块测试必须 `env -u NODE_OPTIONS -u BASH_ENV`，否则 IDE 注入的 fs shim 会在批量文件操作时挂起。

## 关键点与提醒

- **`.ki/trash` 不自动回收**：删除的 wiki 文件会持续占用磁盘，需人工定期清理。
- **回收站路径随 sourceDir**：`{sourceDir}/.ki/trash/`，多个 scope 共用同一 sourceDir 时回收站也共用。
- **`get-module-info` 会写 cache**：高频调用会触发大量 `writeJson` 原子写，注意 I/O 压力。
- **`manage-index --force` 不动 wiki**：与 `delete-relation -g` 的清理范围不同，误用会留下 wiki 残留。
- **MCP 无级联删除**：不可逆操作不通过 MCP 暴露（NEG-15），自动化脚本需走 CLI。
- **配置字段名严格**：`ki doctor` 对未知字段 fail-loud，升级后新增字段需同步 `config-schema.ts`。

章节来源：[src/lib/scope.ts](file:///root/knowledge-indexer/src/lib/scope.ts)（关键符号：`getScopeWikiSync` / `getSource`）与 [src/lib/store.ts](file:///root/knowledge-indexer/src/lib/store.ts)（关键符号：`writeJson`）

## 结论

本模块的运维面集中在三处：**wikiSync 三字段配置**（决定写回目录与补齐行为）、**两条删除路径的语义差异**（是否动 wiki）、**孤儿向量的显式反馈**（`vectorRemoved` / `memMethod`）。日常运维建议固定使用 `ki wiki-backfill`（幂等）+ `ki delete-relation -g`（彻底）组合。
