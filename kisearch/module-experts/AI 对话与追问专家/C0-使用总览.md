# C0-使用总览：AI 对话与追问专家

## 能力清单

| 能力 | 说明 | 入口 |
|---|---|---|
| HTTP 对话路由 | 分派全部 /api/chat/* | handleChatRoutes |
| SSE 流 | 把事件写成 data: {...} 帧 | writeSseStream |
| 会话持久化 | 新建、归档、压缩、原子落盘 | createConversation / chat-store.ts |
| 单库问答 | ki_ask 一次独立问答，不抛错 | runAsk / registerAskTool |
| 提示词配置 | 读写 find / recall / chat 三段配置 | readPromptConfig |
| 工具循环 | AsyncGenerator 驱动模型工具调用 | runToolLoop |
| 工具注册表 | 按能力位与开关决定可用工具 | getChatTool / enabledChatToolEntries |

## 能力边界（本专家不做什么）

- 不实现前端聊天界面：web/src/chat/ 归「可视化前端专家」
- 不实现 ki_recall 内核：归「回想内核专家」
- 不实现 LLM 提供商 SDK：llm-client.ts 只做薄封装
- 不实现事件追问：归「事件治理专家」

## 已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|---|---|---|
| ki_ask 传逗号多库或视图名被拒 | 误以为与 ki_recall 同口径 | ki_ask 一期只吃单个具体库名，多库/视图走 ki_recall |
| 改 maxRounds 没生效 | rounds 是内层工具调用次数而非模型往返轮数 | 改 find.maxToolCalls；ask 侧 ASK_MAX_ROUNDS_DEFAULT=6 / LIMIT=12 |
| 改了超时仍被截断 | 生效值是 min(find.timeoutMs, recall.hardTimeoutMs) | 两侧一起改 |
| prompt-config 路由 3 例既有红 | 基线遗留，非本次引入 | 单跑复验，见 test/known-failures.md |
