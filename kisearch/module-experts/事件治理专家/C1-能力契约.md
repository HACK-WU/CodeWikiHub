# C1-能力契约：事件治理专家

> 本文只写「怎么用」。实现机制、内部状态机与数据结构见 `implementation/`。
> 本次契约基于对模块入口与测试调用点的核对；未采样文件中可能存在未记录的公开方法。

### `createEvent(scope: string, input: CreateEventInput): Promise<EventRecord>`

- **用途**：在指定库创建一个事件并返回记录
- **契约来源**：`createEvent(scope: string, input: CreateEventInput): Promise<EventRecord>`（src/lib/events/event-service.ts）
- **参数**：scope 为库名；input 含标题、描述、类型与可选预期效果，字段由 C1 对应类型约束
- **返回**：Promise<EventRecord>，含 id / shortId / 阶段 / 修订号
- **异常**：成员或参考文档超 50 条抛 EVENT_MEMBER_LIMIT_EXCEEDED / REF_LIMIT_EXCEEDED
- **约束**：同 scope 写入需经 withScopeWriteLock；shortId 删除后不复用
- **代码示例**（使用方代码，签名与源码一致）：

```ts
import { createEvent } from './src/lib/events/event-service.js';
const event = await createEvent('kisearch-memory', { title: '导入锁残留', description: '排查导入锁未释放', typeId: 'bug' });
```

### `transitionEvent(scope: string, input: TransitionInput): Promise<TransitionOutcome>`

- **用途**：推进事件阶段，终态按类型决定关联文档去向
- **契约来源**：`transitionEvent(scope: string, input: TransitionInput): Promise<TransitionOutcome>`（src/lib/events/event-service.ts）
- **参数**：stage 可传阶段 id（如 st_3）或阶段名；input 含 eventId 与修订号
- **返回**：Promise<TransitionOutcome>，含 terminalAction: keep 或 trash
- **异常**：事件已收口抛 EVENT_CLOSED；修订号不匹配抛 REVISION_CONFLICT
- **约束**：状态先写、日志后追加；终态为 trash 时关联文档移入回收站
- **代码示例**（使用方代码，签名与源码一致）：

```ts
import { transitionEvent } from './src/lib/events/event-service.js';
const out = await transitionEvent('kisearch-memory', { eventId: '#38', stage: '已修复', revision: 2 });
```

### `getEventDetail(scope: string, options: EventDetailOptions): EventDetailView`

- **用途**：单事件只读聚合，HTTP 与 MCP 共用同一读取出口
- **契约来源**：`getEventDetail(scope: string, options: EventDetailOptions): EventDetailView`（src/lib/events/event-detail.ts）
- **参数**：options 含事件引用与各 *_Limit 分块上限，传 0 表示该块不返回但仍给 total
- **返回**：EventDetailView，各分块带 total
- **异常**：事件不存在抛 EVENT_NOT_FOUND
- **约束**：HARD_CAP 为 100；各分块默认上限 20
- **代码示例**（使用方代码，签名与源码一致）：

```ts
import { getEventDetail } from './src/lib/events/event-detail.js';
const view = getEventDetail('kisearch-memory', { ref: '#38', refsLimit: 20 });
```

### `listRefs / addRefs / searchRefCandidates`

- **用途**：列举、增删参考文档，以及为 AI 分析找候选文档
- **契约来源**：`listRefs / addRefs / searchRefCandidates`（src/lib/events/refs-service.ts）
- **参数**：addRefs 的键为 sourceScope / group / name 三元组；缺省 sourceScope 按事件所在库归一
- **返回**：引用清单或候选列表
- **异常**：超过 REF_LIMIT=50 抛 REF_LIMIT_EXCEEDED
- **约束**：remove 只解绑不删文档；换 sourceScope 会让同名文档成为独立引用
- **代码示例**（使用方代码，签名与源码一致）：

```ts
import { addRefs } from './src/lib/events/refs-service.js';
await addRefs('kisearch-memory', '#38', [{ sourceScope: 'kisearch-memory', group: '决策记录', name: 'JWT 选型' }]);
```

### `startEventAnalysis(opts)`

- **用途**：启动一轮 AI 分析，可强制覆盖或续接
- **契约来源**：`startEventAnalysis(opts)`（src/lib/events/analysis-runner.ts）
- **参数**：opts 为内联对象类型，含 forceOverwrite / resume / deps / authScopes；无具名入参类型
- **返回**：启动结果；分析正文写入独立 .analysis.json
- **异常**：已有分析在跑抛 ANALYSIS_ALREADY_RUNNING；超时但有正文落 partial
- **约束**：超时或主动停止但有正文时不落 cancelled / failed
- **代码示例**（使用方代码，签名与源码一致）：

```ts
await startEventAnalysis({ scope: 'kisearch-memory', eventId: '#38', deps: { runFind: myRunner } });
```

### `handleGovernanceRoutes(req, res, url, ctx): Promise<boolean>`

- **用途**：/api/governance/* 的唯一分发入口
- **契约来源**：`handleGovernanceRoutes(req, res, url, ctx): Promise<boolean>`（src/lib/governance-http.ts）
- **参数**：剥掉 /api 前缀后只接 /governance 与其子路径；ctx 提供配置与鉴权上下文
- **返回**：true 表示已处理，false 交给上级路由
- **异常**：错误统一包成 GovernanceError；SSE 分支恒返回 200
- **约束**：新增路由只需在此文件加分支，并在 mcp-http-api.ts 保持单行挂载
- **代码示例**（使用方代码，签名与源码一致）：

```ts
const handled = await handleGovernanceRoutes(req, res, url, ctx);
if (!handled) res.writeHead(404).end();
```
