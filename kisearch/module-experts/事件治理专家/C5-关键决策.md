# C5-关键决策：事件治理专家

> 只收有明写证据（代码注释 / commit message / 设计文档）的决策；结构暗示的一律前置 `[推测]`。

## 错误码对外用语义字符串，数值只作分配与撞码检测、不出现在响应体

- **分类**：契约设计
- **决策**：错误码对外用语义字符串，数值只作分配与撞码检测、不出现在响应体
- **背景约束**：需要可读性且可 grep 的对外契约
- **被否决方案及理由**：曾考虑直接对外发数字码；否决理由见 governance-errors.ts 文件头 S06 建议 N1 的取舍
- **重新评估触发条件**：对外响应体开始出现数字码时
- **证据来源**：代码注释：src/lib/governance-errors.ts 文件头

## HTTP 状态只由 HTTP_STATUS 单表决定

- **分类**：一致性
- **决策**：HTTP 状态只由 HTTP_STATUS 单表决定
- **背景约束**：governance-http 曾另有一份本地 STATUS_BY_CODE，新增码时只改一处会让接口仍返回 400 而契约写 409
- **被否决方案及理由**：保留双表；否决理由是两表必然漂移
- **重新评估触发条件**：新增错误码时接口状态与契约不一致
- **证据来源**：代码注释：src/lib/governance-errors.ts 的 HTTP_STATUS 注释

## 参考文档与 AI 查找结论独立成 {eventId}.refs.json

- **分类**：存储
- **决策**：参考文档与 AI 查找结论独立成 {eventId}.refs.json
- **背景约束**：引用是高频小写，与事件主体同文件会互相覆盖
- **被否决方案及理由**：塞进事件主体文件；否决理由见 refs-store.ts 文件头
- **重新评估触发条件**：引用与 lastFind 出现互相清空时
- **证据来源**：代码注释：src/lib/events/refs-store.ts 文件头

## 阶段流转状态先写、日志后追加，日志失败不回滚状态

- **分类**：一致性
- **决策**：阶段流转状态先写、日志后追加，日志失败不回滚状态
- **背景约束**：反序会产生「日志说有、状态说没有」的假记录
- **被否决方案及理由**：先写日志再改状态；否决理由见 stage-log.ts 文件头（S-02 决策 5）
- **重新评估触发条件**：出现日志与状态不一致的假记录
- **证据来源**：代码注释：src/lib/events/stage-log.ts 文件头

## 事件 MCP 旧名不保留别名，写能力统一到 ki_event_edit

- **分类**：兼容
- **决策**：事件 MCP 旧名不保留别名，写能力统一到 ki_event_edit
- **背景约束**：双份维护会让模型在旧名与新名之间随机选
- **被否决方案及理由**：保留 ki_event_docs / ki_event_refs / ki_event_set_stage 别名；否决理由见 mcp-server-factory.ts 注释
- **重新评估触发条件**：模型仍会输出旧工具名时
- **证据来源**：代码注释：src/lib/mcp-server-factory.ts

## 事件详情候选只在分析完成（终态）后显示，后端未就绪时结论区与追问区整块不渲染

- **分类**：产品边界
- **决策**：事件详情候选只在分析完成（终态）后显示，后端未就绪时结论区与追问区整块不渲染
- **背景约束**：避免在半成品状态上做决策
- **被否决方案及理由**：状态机式分阶段渲染；否决理由见需求文档 Q1 / Q10
- **重新评估触发条件**：产品要求边分析边展示时
- **证据来源**：设计文档：.requirements/2026-11-17-event-detail-redesign/requirement.md §11
