# C0-使用总览：事件治理专家

## 能力清单

| 能力 | 说明 | 入口 |
|---|---|---|
| 事件 CRUD | 创建、列表、详情、删除、重开、改名、置顶 | createEvent / listEvents / getEventDetail / deleteEvent |
| 阶段流转 | 唯一的事件状态写入口，终态按类型产出 keep / trash | transitionEvent |
| AI 分析与追问 | 启动 / 取消分析，追问可流式、可手动停止、可续接 | startEventAnalysis / cancelEventAnalysis / analysis-ask-runner |
| 参考文档与 AI 查找 | 增删引用、候选查找、记录最近一次结论 | listRefs / addRefs / searchRefCandidates |
| 事件类型与生命周期 | 类型预设、阶段定义、批量应用 | event-types.ts / governance-http.ts |
| 治理路由 | /api/governance/* 总分发与诊断路径 | handleGovernanceRoutes |
| 回收站 | 删组 / 删文档统一落回收站，支持整组恢复与过期清理 | governance-http.ts / trash-service.ts |
| MCP 写工具 | 事件写能力统一为 ki_event_edit（action 互斥） | registerEventEditTool |

## 能力边界（本专家不做什么）

- 不实现知识检索与原文定位：分析链通过工具层调用检索能力，本专家只编排
- 不实现 Web 页面：EventsPage.tsx 与 components/governance/ 归「可视化前端专家」
- 不实现 HTTP 服务器：治理路由由 mcp-http-api.ts 单行挂到 handleGovernanceRoutes
- 不实现 Token 鉴权：scope 越权由 MCP 服务层与 governance-scope.ts 裁决

## 已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|---|---|---|
| 契约写 409、接口实际返回 400 | 新增错误码只改 GOVERNANCE_CODE_NUMBERS 而忘了 HTTP_STATUS | 只维护 governance-errors.ts 里的 HTTP_STATUS 单表 |
| 加删参考文档后 AI 查找结论消失 | refs-store.ts 覆盖写丢掉 lastFind | saveLastFind 先 readRefs 再 writeRefs，保留 lastFind |
| 流式 SSE 分支把 daemon 打挂 | 非 GovernanceError 异常上抛造成二次 writeHead | SSE 分支统一包成 FIND_FAILED 当事件下发，HTTP 恒 200 |
| 删事件后残留 .ask.json 孤儿 | 删除出口未挂 removeAskFile | removeAskFile 与删除同锁，并在删除前复核事件仍在 |
| 批量跑测试红、单跑全绿 | run-tests.mjs 并发跑固定端口 / 真实 daemon 用例互抢 | 用 --serial 或单跑复验，不拿全量结果当回归证据 |
