# C4-数据流向与消费：ki 可视化前端

> 黑盒视角：前端经手的数据实体 → 来源接口 → 去向 → 消费方 → 业务用途。前端自身**无持久化服务端存储**，浏览器侧仅 localStorage；全部业务数据的最终去向是后端（KB JSON / zvec 向量库），由后端专家资产描述。

## 数据实体清单

| 数据实体 | 来源接口 | 去向 | 消费方（前端内） | 业务用途 |
|---|---|---|---|---|
| scope 选中值 | localStorage `ki-web:scope`（写：ScopeSelect 切换） | localStorage + React Context | 所有页面（hooks queryKey 组成部分、请求 scope 参数） | 跨页面保持当前知识库，切换即全局刷新 |
| 主题偏好 | localStorage `ki-theme`（写：AppShell useTheme） | localStorage + `<body data-theme>` | ki.css 暗色变量（`[data-theme="dark"]`） | light/dark 主题持久化 |
| scope 列表 + 层状态 | `kiScopeList()`（MCP `ki_scope_list`） | react-query 缓存 `['scopeList']` | DashboardPage 统计卡/表格、ScopeSelect 下拉、ServiceBadge | 展示有哪些知识库及 KB/向量层健康度 |
| 健康报告 | `getHealth()`（`/api/health`） | react-query 缓存 `['health']` | HealthBanner（未就绪横幅）、ServiceBadge（徽标）、DashboardPage 健康列表 | 服务可用性诊断与启动指引 |
| 文档列表 + Group 清单 + KB tags | `getDocList()` / `useDocList` / `useGroupDocs`（`/api/doc/list`） | react-query 缓存 `['docList', …]` | BrowsePage 树/列表/过滤、GroupPathSelect 下拉树、DashboardPage 当前 scope 概览 | 知识库结构浏览与定位 |
| 检索命中（含原文） | `kiSearch()`（MCP `ki_search`, include_original=true） | 组件 state（不进缓存） | SearchPage 结果列表、ModuleDrawer 原文 | 语义检索与原文交付验证 |
| 文档原文 | `kiGetModuleInfo()`（MCP `ki_get_module_info`） | ModuleDrawer state | ModuleDrawer 渲染/复制 | 按 group+relation 精确取全文 |
| 上传文件（base64） | 用户文件选择（File API 读取） | `uploadFiles()` → 后端临时上传区 | —（上传后前端不保留） | 导入两阶段的第一阶段 |
| 导入任务状态 | `getImportStatus()` 轮询（`/api/import/status`） | ImportPage state（phase/job） | 进度条、完成统计、失败提示 | 异步导入进度可视与结果反馈 |
| 用户写入内容 | 表单输入（group/relation/markdown/tags/vector） | `kiSyncRelation()` → 后端 KB + 向量层 | WritePage 表单校验/预览/成功提示 | 手工沉淀单篇知识 |
| 可用 tag 列表（向量层） | `fetchTags()`（`/api/tags`，已排除内部保留 tag） | 组件 state | SearchPage tag chips、Import/Write tag combobox | 检索过滤与写入打标 |

## 落地数据说明（黑盒边界）

- **前端不落盘业务数据**：搜索结果、文档列表、导入进度均为内存态（react-query 缓存 10–60s 或组件 state），刷新页面即失
- **localStorage 仅两项**：`ki-web:scope`、`ki-theme`；读写均有 try/catch 静默回退（隐私模式/禁用存储不致命）
- **业务数据持久化全部在后端**：写入链路（upload/run/sync_relation）最终落 `kb/{scope}/`（Group 树、relations-cache、local KB）与 zvec 向量库，归属后端模块；本前端只负责采集与展示 [基于引用扫描，未深入后端持久化细节]

## 消费归纳

- 前端是后端能力（MCP 工具 + `/api/*`）的**唯一图形消费方**；CLI 与 MCP 客户端是平行消费方，互不依赖前端
- 前端消费的接口契约若变更，必须同步 `web/src/api/` 的两个封装文件（见 05-接口.md 的契约耦合表）
