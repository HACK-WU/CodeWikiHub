## 消费的后端契约：/api/* 通道

前端 `httpApi.ts` 封装 ↔ 后端 `mcp-http-api.ts` 路由（HTTP 层鉴权/校验在 `mcp-http.ts` `handleApiRequest`）：

| 前端函数 | HTTP 契约 | 关键返回字段 |
|---|---|---|
| `getHealth()` | `GET /api/health` | `{ ok, report: { pass, fail, warn, items[] } }` |
| `getDocList(scope, {q?, group?, tag?})` | `GET /api/doc/list?scope&q&group&tag` | `{ ok, scope, docs[], total, truncated?, groups[]?, tags[]? }` |
| `uploadFiles(scope, files)` | `POST /api/import/upload`（JSON body，base64） | `{ ok, uploadId, files?, total?, errors[]? }` |
| `runImport(args)` | `POST /api/import/run` | `{ ok, jobId }` |
| `getImportStatus(jobId)` | `GET /api/import/status?jobId` | `{ ok, job: ImportJob }` |
| `fetchTags(scope?)` | `GET /api/tags?scope` | `{ ok, tags: {tag, count}[] }`（排除保留 tag） |

契约细节：`docs` 全量查询有 500 条分页截断（`truncated` 标记），`groups`/`tags` 不受截断；`group` 参数精确返回该组全量。

章节来源：[httpApi.ts](file://web/src/api/httpApi.ts)（关键符号：六个业务函数）；[mcp-http-api.ts](file://src/lib/mcp-http-api.ts)（关键符号：`handleApiRequest`）

## 消费的后端契约：MCP 工具通道

前端 `mcpClient.ts` 经 StreamableHTTP（`POST /mcp`）调用 5 个工具；工具注册于 `src/mcp-server.ts`（`buildKiMcpServer`），实现在 `src/lib/mcp-tools/*`：

| 前端封装 | MCP 工具 | 前端传入要点 | 前端解析要点 |
|---|---|---|---|
| `kiScopeList()` | `ki_scope_list` | `{}` | `scopes[]`、`vectorAvailable/vectorReason`（降级信号） |
| `kiSearch(query, opts)` | `ki_search` | 固定 `include_original: true`；tags 逗号拼接 | `results[]`（含 `original`/`memoryId`/`tag`/`score`）；`ok===false` 业务错误 |
| `kiGetModuleInfo(scope, group, relation)` | `ki_get_module_info` | 三参数直传 | `content`（Markdown 原文） |
| `kiStore(args)` | `ki_store` | `content` → 后端 `text`；tags 拼接 | `ok`（预留，页面未用） |
| `kiSyncRelation(args)` | `ki_sync_relation` | `content` → 后端 `module_info`；`vector` 开关 | `ok` |

统一解包：`res.content[0].text` → `JSON.parse`（会话失效自动重连重试一次）。

章节来源：[mcpClient.ts](file://web/src/api/mcpClient.ts)（关键符号：`callTool` 与五个业务函数）；[mcp-http.ts](file://src/lib/mcp-http.ts)（关键符号：`handleMcpPost`）

## 错误码与错误语义

前端消费侧的错误形态（后端无数字错误码透传到前端，全部字符串化）：

| 形态 | 来源 | 前端处理 |
|---|---|---|
| `HTTP <status>` | httpApi `req` 兜底 | 页面 error 卡展示 |
| `{ error: string }` | /api/* 业务错误 body | 取 `error` 字段展示 |
| MCP tool error（异常） | 传输失败/工具抛错 | callTool 重试一次后抛，页面 catch |
| `ok === false` + `error` | MCP 工具业务失败（JSON 正常返回） | **调用方自查**（目前仅 SearchPage） |
| 403 | scope 越权（RBAC） | 走 `error` 通道展示「Forbidden」（后端已脱敏不下发 scope 名） |

章节来源：[httpApi.ts](file://web/src/api/httpApi.ts)（关键符号：`req`）；[SearchPage.tsx](file://web/src/pages/SearchPage.tsx)（关键符号：`ok === false` 分支）

## 契约耦合表（改后端必连带改前端）

| 后端变更 | 必须连带修改的前端位置 | 备注 |
|---|---|---|
| `/api/*` 端点路径/参数/返回结构 | `web/src/api/httpApi.ts` + 类型定义 | 类型为手工对齐声明（注释「对齐 mcp-http-api.ts 返回」） |
| MCP 工具入参/返回结构 | `web/src/api/mcpClient.ts` + 类型 | 同上（「对齐 ki 后端返回结构」） |
| group/relation/tag 校验规则 | `web/src/lib/validators.ts` | 人工镜像后端 `resolveGroupPath`/`isUnsafeRelationName`，**无共享代码** |
| 新增保留 tag | SearchPage 默认 tags、`/api/tags` 排除逻辑 | 前端写死 `'ki-search'` 默认过滤 |
| `--web` webDir/端口默认值 | vite.config proxy 目标 7423、AppShell 底部版本文案（硬编码「MCP 7423」） | 端口变更双处同步 |
| 导入任务状态机字段 | ImportPage 轮询逻辑 + `ImportJob` 类型 | `state`/`progress`/`result.stats` 结构 |

章节来源：[validators.ts](file://web/src/lib/validators.ts)（关键符号：文件头对齐注释）；[AppShell.tsx](file://web/src/layouts/AppShell.tsx)（关键符号：`ki-sidebar__footer-version` 硬编码文本）；[vite.config.ts](file://web/vite.config.ts)（关键符号：`proxy` 目标）

## 结论

前端接口面的核心事实：**类型是手工对齐的声明而非生成物**，前后端契约靠注释约定与人工同步维护；`ok === false` 不抛异常是 MCP 通道最特殊的语义。修改后端接口时，以本文件的契约耦合表为 checklist 逐项核对，可覆盖全部连带修改点。
