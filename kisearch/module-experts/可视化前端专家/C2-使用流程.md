# C2-使用流程：ki 可视化前端

> 面向「用前端完成一个业务目标」的调用路径。所有流程的前置条件：`ki mcp --http` 已启动（生产访问 `--web` 页面，或开发模式 `npm run dev` + 代理）。

## 流程 1：上传导入一批 Markdown 并验证语义搜索

- **业务目标**：把本地 .md 文件（或整个目录）导入某 scope 的指定 Group，并立即可被语义搜索
- **调用顺序**：
  1. `fetchTags(scope)`（ImportPage 加载已有 tag 列表，`/api/tags`）
  2. 用户选择文件/目录 → 前端读取文本 → base64
  3. `uploadFiles(scope, files)`（`/api/import/upload`）→ 得 `uploadId`（可能伴随部分拒绝 `errors`）
  4. `runImport({ scope, uploadId, group, chunkSize, chunkOverlap, vector, tags })`（`/api/import/run`）→ 得 `jobId`
  5. 每 2s `getImportStatus(jobId)`（`/api/import/status`）直到 `state === 'done' | 'failed'`
  6. 转到 `/search` 验证（或 `/browse` 点「刷新」查看新 Group）
- **事务边界**：upload 与 run 是两阶段；run 之后为异步任务，导入失败不影响已上传文件（重新 run 同一 uploadId 即可）。重复导入同内容 = 幂等追加（覆盖更新）
- **预期结果**：完成态展示 `stats { imported, vectorized, errors }`；导入期间向量库被持锁，搜索可能短暂降级
- **错误处理**：group 格式错误在提交前被 `groupError` 拦截；job 丢失/后端重启 → 提示「任务已失效，请重新导入」

```ts
// 使用方代码（等价于 ImportPage.start() 的核心链路，假设处于 React 事件回调中）
import { uploadFiles, runImport, getImportStatus } from '@/api/httpApi';

const up = await uploadFiles('default', [{ name: 'a.md', content: btoa(unescape(encodeURIComponent('# 正文'))) }]);
if (!up.ok || !up.uploadId) throw new Error(up.error ?? '上传失败');

const run = await runImport({ scope: 'default', uploadId: up.uploadId, group: 'wiki/我的文档', vector: true, tags: '部署,运维' });
if (!run.ok || !run.jobId) throw new Error(run.error ?? '导入触发失败');

const timer = setInterval(async () => {
  const st = await getImportStatus(run.jobId!);
  if (st.job?.state === 'done' || st.job?.state === 'failed') clearInterval(timer);
}, 2000);
```

## 流程 2：语义搜索并查看原文

- **业务目标**：用自然语言找到知识并阅读全文
- **调用顺序**：
  1. `fetchTags(scope)` 填充 tag 选择器
  2. `kiSearch(query, { scope, tags: selectedTags.length ? selectedTags : ['ki-search'], threshold: threshold || undefined, limit })`（tag 语义：选中具体 tag = 精确过滤；未选 = 默认 ki-search）
  3. 检查 `res.ok === false`（业务错误不抛异常）；取 `res.results`
  4. 点击结果 → 直接用命中自带的 `original` 打开 ModuleDrawer（不二次请求）；`original` 缺失时抽屉内再走 `kiGetModuleInfo(scope, group, relation)`
- **事务边界**：无；搜索为只读
- **预期结果**：按 score 降序结果列表（前三名高亮排名），点击可看原文/复制/全屏
- **错误处理**：空 query 不发请求；`ok === false`（如向量库锁）显示后端 error 文案

```ts
// 使用方代码（等价于 SearchPage.run() 核心）
import { kiSearch } from '@/api/mcpClient';
const res = await kiSearch('告警收敛策略是什么', { scope: 'default', tags: ['ki-search'], threshold: 0, limit: 10 });
if ((res as { ok?: boolean }).ok === false) throw new Error('搜索服务暂不可用');
const hits = res.results ?? [];
```

## 流程 3：手动写入一条关系文档

- **业务目标**：往某 Group 写一篇结构化知识（等价 `ki sync-relation` 的可视化）
- **调用顺序**：
  1. `GroupPathSelect` 选/输 Group 路径（数据来自 `useDocList(scope).groups`）
  2. 输入 relation 名 + Markdown 正文（可切预览，MarkdownPreview 渲染）
  3. 可选 tags（combobox：已有选择或输入新建，`tagError` 实时校验）
  4. `kiSyncRelation({ scope, group, relation, content: markdown, vector, tags })`
- **事务边界**：单次调用原子完成（后端负责 KB + 向量层一致性）；同 group+relation 再次写入 = 覆盖
- **预期结果**：成功提示（含是否向量化、标签），表单自动清空
- **错误处理**：group/relation/markdown 任一为空或格式非法 → 提交前拦截；传输错误显示 message

```ts
// 使用方代码（等价于 WritePage.submit() 核心）
import { kiSyncRelation } from '@/api/mcpClient';
await kiSyncRelation({
  scope: 'default',
  group: '告警系统',
  relation: '告警收敛策略',
  content: '## 策略\n\n相同指纹 5 分钟内只报一次…',
  vector: true,
  tags: ['告警'],
});
```

## 流程 4：浏览知识库并按 tag 过滤

- **业务目标**：按 Group 树逐层浏览文档、按文件名搜索、按 tag 过滤
- **调用顺序**：
  1. `useDocList(scope)` 拿全量文档 + `groups`（建树）+ `tags`（KB 层 tag 过滤下拉）
  2. 点击叶子 group → `useGroupDocs(scope, group, tag)` 拿该组全量文档（不受 500 条截断）
  3. 文档列表输入框输入 → `getDocList(scope, { q, tag })` 跨组模糊搜索（limit 2000）
  4. 点击文档 → ModuleDrawer（`kiGetModuleInfo`）
- **事务边界**：无；全部只读。缓存 30s，手动「刷新」= `invalidateQueries()`
- **已知边界**：tag 过滤用 KB 层 tags（`/api/doc/list` 返回），**非** `/api/tags`（向量层）——两处 tag 来源不同是有意设计
- **错误处理**：树为空 → 引导去导入页

## 流程 5：部署形态切换（生产 / 开发）

- **业务目标**：让浏览器用上前端
- **生产**：`cd web && npm install && npm run build`（tsc --noEmit + vite build → `web/dist`）→ `ki mcp --http --web` 静态托管（SPA fallback），浏览器访问 `http://<host>:<port>/`
- **开发**：终端 A `ki mcp --http`（7423）；终端 B `cd web && npm run dev`（5173，`/api` `/mcp` `/healthz` 代理到 7423）→ 访问 `http://127.0.0.1:5173`
- **预期结果**：两种形态下前端行为一致（均同源访问后端）
- **错误处理**：后端未启动 → HealthBanner 横幅指引
