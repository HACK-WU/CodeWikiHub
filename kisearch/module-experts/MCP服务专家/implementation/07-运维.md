## 简介

本文件描述 MCP 服务专家的运维面：部署模式、鉴权、进程管理、监控、升级与排查。

## 部署模式

| 模式 | 命令 | 适用场景 |
|------|------|----------|
| stdio | `ki mcp` | 单 IDE / 单客户端（支持多实例并存，靠空闲释放锁错开） |
| HTTP 本机 | `ki mcp --http` | 本机多 IDE 共享（回环免鉴权） |
| HTTP 后台常驻 | `ki mcp --http --daemon`（`-d`） | 生产/长期运行（脱离终端；可选 `--web` 带前端页面） |
| HTTP 远程 | `ki mcp --http --host 0.0.0.0 --token <t>` | 跨机访问（强制鉴权；Token 按最小 scope 授权） |

**端口**：默认 7423（`--port` 可改）；绑定默认回环 `127.0.0.1`（secure by default）。

## 鉴权与 Token 管理

- **鉴权条件**：回环绑定免鉴权；非回环强制鉴权
- **Token 优先级**：`--token` > `KI_MCP_TOKEN` > 多 Token 存储（`~/.ki/mcp-tokens.json`）；前者为**全权**临时 Token（不受 scope 限制）
- **多 Token 管理**（RBAC）：
  - `ki mcp token generate --scope <单个|逗号分隔|all>`：生成（**`--scope` 必填**），输出 id + 明文（唯一一次）
  - `ki mcp token list`：列出全部（含明文与授权 scope）
  - `ki mcp token update <id> --scope <...>`：改授权（无需换 Token）
  - `ki mcp token delete <id>`：吊销（立即失效；已建会话保留但新请求 401）
- **scope 越权**：HTTP 层拦截 `tools/call` 的 scope 参数，越权 403（scope 名只写服务端 stderr）；无 scope 参数的工具（`ki_scope_list`、`ki_manage_index_list`）走白名单 + 工具层过滤输出
- **安全约定**：Token 绝不入配置文件；文件 0600、目录 0700；`--status` 只报数量不报明文；**存储文件损坏时写操作拒绝（防静默丢失）**

## 进程管理

- **查看状态**：`ki mcp --status`（只读；探测目标 CLI > lock > 配置 > 默认，可探测非默认地址实例）
- **后台常驻**：`ki mcp --http --daemon`（`-d`）；spawn 后 3s 存活探测，退出即 fail-loud。**日志不落盘、无崩溃自动拉起**（用户明确决策）；网络类慢失败可能假报成功，用 `--status` 兜底
- **重启**：`ki mcp restart`（强制 `--http --daemon`）；探测存活 stdio 实例但不静默 kill；非回环 host 先做 Token 预检
- **一键停止**：`ki mcp stop`（定位真实持锁进程，SIGTERM→SIGKILL 兜底 + 身份校验）
- **锁文件**：`~/.ki/mcp-stdio-<pid>.lock`（每实例独立）/ `~/.ki/mcp-http.lock`（含 host/port/pid/web）
- **残留处理**：lock 写失败的实例对 stop/status "失明"（启动时已 stderr 告警）；极端场景用 `ps -ef | grep mcp-server` 人工确认后 kill

## 日志与监控

- **启动预检**：复用 `runHealthCheck`，报告写 stderr；存在 ❌ 拒绝启动
- **版本 banner**：`[kisearch] 版本 vX | PID Y | 启动于 Z`（stderr）
- **鉴权失败**：stderr 日志（限流 5s 一次）+ `/healthz` 的 `authFailures` 计数
- **探活**：`/healthz` 返回 `{ok, pid, version}`；`ki mcp --status` 汇总展示

## 升级注意事项

- 长驻进程不会热加载新代码：升级 `ki` 后需重启 MCP 服务
- `startVersionGuard` 监听 package.json 变化，检测到版本变化告警重启
- **jiti 缓存**：修改插件/源码 `.ts` 后需 `rm -rf /tmp/jiti/` 再重启（见 AGENTS.md）

## 故障排查

| 现象 | 排查路径 |
|------|----------|
| IDE 显示工具(0) | 检查鉴权（`ki mcp --status` 看 authFailures）+ 服务端 stderr |
| 401 Unauthorized | `ki mcp token list` 核对 Token 完全一致（整段复制）；确认该 Token 未被 `delete` |
| 403「scope 不在授权范围内」 | `ki mcp token list` 看授权 scope；`ki mcp token update <id> --scope <...>` 扩权或换 `all` 授权 Token |
| 无参工具被 403 | 该工具缺 `SCOPE_LESS_TOOLS` 白名单登记（新增无 scope 参数工具时必做） |
| `MCP_TOKEN_CORRUPT` | `~/.ki/mcp-tokens.json` 损坏 → 人工检查/恢复该文件；写操作被拒是刻意保护，不要删除文件了事 |
| 非回环启动失败（`MCP_HTTP_TOKEN_REQUIRED`） | 先 `ki mcp token generate --scope <...>`，或设 `KI_MCP_TOKEN` |
| daemon 报成功但连不上 | 存活探测超时按成功处理 → `ki mcp --status` 复核；看 stderr（不落盘，前台复跑才能看到） |
| 端口被占 | `ki mcp --status` + `lsof -i:7423`；换 `--port` |
| 撞向量库锁 | 多实例软冲突：空闲释放锁 3s + 撞锁重试 6s；仍失败则收敛到 HTTP 单例（`ki mcp stop` 后起单例） |
| 工具超时 | 向量库占用 / embedding 服务无响应 → 稍后重试或检查服务 |
| 改动不生效 | 清理 jiti 缓存 + `ki mcp restart` |

## 结论

本专家运维面覆盖部署模式（stdio/HTTP/daemon）、多 Token 与 scope 授权、进程与锁管理、监控、升级与排查，核心是"单持锁进程 + 条件鉴权 + 最小授权 + 可诊断"。生产使用建议统一走 HTTP 共享单例（`--http --daemon`），并**按租户/用途分配独立 Token 与最小 scope**。
