## 简介

本文件描述 MCP 服务专家的测试资产：位置、覆盖、可执行性与缺口。

## 测试位置与框架

| 测试文件 | 覆盖范围 | 框架 |
|----------|----------|------|
| `test/mcp-http.test.ts` | HTTP 单例（会话管理/鉴权/healthz/停止） | jiti + node:assert |
| `test/mcp-stdio-lock.test.ts` | stdio 锁（多实例登记/列举/释放/陈旧锁/pidAlive） | jiti + node:assert |
| `test/mcp-stop.test.ts` | 停止命令（目标定位/信号/身份校验） | jiti + node:assert |
| `test/mcp-token.test.ts` | 多 Token（create/update/delete/list/scope 解析/损坏保护/0600） | jiti + node:assert |
| `test/mcp-http-api.test.ts` | HTTP 扩展接口 `/api/*`（Web UI 数据接口） | jiti + node:assert |
| `test/mcp-daemon.test.ts` | 守护进程化（`--daemon` 启动/存活探测/restart 语义） | jiti + node:assert |
| `test/e2e/*.network.mjs` | 端到端（真实 HTTP 连接，需网络） | node --test |

运行命令：
```bash
npx jiti test/mcp-token.test.ts        # 单跑
node --test test/e2e/*.test.mjs        # e2e（需网络）
npm run test:all                       # 全量
# ⚠️ 本机跑测试建议剥离 IDE 注入（NODE_OPTIONS 会拦截 fs，批量文件操作可能挂起）
env -u NODE_OPTIONS -u BASH_ENV npx jiti test/mcp-token.test.ts
```

## 覆盖模式

- **HTTP 会话**：initialize 新建/复用、会话上限 503、空闲回收、DELETE 关闭
- **鉴权**：回环免鉴权 / 非回环鉴权（多 Token 存储 + 全权临时 Token）/ 401 + authFailures 计数
- **scope 授权 RBAC**（在 `mcp-http.test.ts` 内）：越权 scope → 403；`SCOPE_LESS_TOOLS` 无参工具不被误伤；省略 `arguments` 的越权尝试按 `default` 校验拦截
- **healthz**：探活返回体、幂等单例判定
- **stdio 锁**：多实例登记互不干扰、`listLiveStdioLocks` 排除自身与清理陈旧锁、`releaseStdioLock` 只删自己、`pidAlive` EPERM 视为存活
- **停止**：目标去重、SIGTERM→SIGKILL、verifyPid 身份校验（skipped 场景）
- **Token**：create 生成短 ID 与明文、`updateTokenScopes`/`deleteToken` 的 `TOKEN_NOT_FOUND`、`resolveScopesArg` 非法字符与 `all` 归一化、`listTokensStrict` 损坏抛 `MCP_TOKEN_CORRUPT`、0600 权限

## 测试可执行性

- **运行命令**：`npx jiti test/<name>.test.ts`；全量 `npm run test:all`
- **环境依赖**：
  - `mcp-http.test.ts` 用临时端口驱动 `createMcpHttpServer`（不依赖真实 7423），✅ 可跑
  - `mcp-stop.test.ts` 的 `verifyPid` 用例 ⚠️ 依赖 `/proc/<pid>/cmdline`（Linux）
  - `mcp-daemon.test.ts` ⚠️ 依赖进程 spawn 与存活探测时序；**daemon 测试进程 detached 无 tty**，`ps` 里带 pts 的 mcp-server 是用户前台实例，勿误杀
  - e2e ⚠️ 依赖网络与真实环境；`zvec-engine-e2e.network.mjs` 与 `kisearch-cli.e2e.network.mjs` 需 embedding 环境
  - ⚠️ **IDE 注入陷阱**：`NODE_OPTIONS=--require node-language-shim.cjs` 会拦截 fs，批量文件操作可能挂起等确认；本机手工跑建议 `env -u NODE_OPTIONS -u BASH_ENV`
- **已知失败**：当前无已知失败（详见 `test/known-failures.md`）

## 测试缺口

- `describeListenError` 各错误分支（EADDRINUSE/EACCES/EADDRNOTAVAIL/ENOTFOUND）覆盖不足
- `printHttpStatus` 的 Token 数量输出（无明文校验）未覆盖
- HTTP 会话 `maxSessions` 边界 + `sessionIdleMs` 触发时机的时序用例较少
- `version-guard.ts` 的 package.json 监听告警（watcher 事件）难模拟，覆盖有限
- **`ki_bulk_sync_relation` 无独立单测**（依赖 embedding，走 e2e 覆盖）；`items` 50 条上限边界未验证
- **多 Token 并发写无锁**：并发 `token generate/update/delete` 丢更新场景未覆盖
- **daemon 慢失败假报成功**：网络类超时（>`3s` 探测窗口）分支未覆盖

## 结论

本专家测试覆盖 HTTP 单例 / 锁 / 停止 / 多 Token / scope 授权 / `/api` / daemon 核心路径，可执行性良好（⚠️ 部分依赖 /proc、进程 spawn 与网络）；已知缺口集中在错误分支、并发与时序边界，建议后续补充。
