# C0-使用总览：MCP 服务专家

## 能力清单

本专家覆盖 kisearch 的 **MCP（Model Context Protocol）服务层**，为 AI Agent / IDE 提供标准化的知识索引能力接入：

| 能力 | 说明 | 入口 |
|------|------|------|
| stdio 传输 | 默认模式，每客户端一进程（`ki mcp`）；**支持多实例并存**（靠向量库空闲释放锁错开共享） | `mcp-server.ts` |
| HTTP 共享单例 | 多 IDE 共享同一持锁进程（`ki mcp --http`），根治向量库锁冲突 | `lib/mcp-http.ts` |
| 守护进程化 | `ki mcp --http --daemon`（-d）脱离终端后台常驻；`ki mcp restart` 重启 HTTP 单例 | `mcp-server.ts` + `bin/ki.mjs` |
| MCP 工具注册 | 13 个工具（`ki_search` / `ki_store` / `ki_bulk_store` / `ki_query_group` / `ki_get_module_info` / `ki_sync_relation` / `ki_bulk_sync_relation` / `ki_delete_relation` / `ki_manage_index_create` / `ki_manage_index_list` / `ki_manage_index_delete` / `ki_scope_list` / `ki_tag_list`；`registerManageIndexTools` 一次注册 3 个） | `lib/mcp-tools/*` |
| 工具超时防护 | 每个工具调用带超时上界（READ 30s / WRITE 60s / BULK 300s） | `lib/mcp-tools/util.ts` |
| 启动守卫 | 幂等复用（HTTP 命中健康实例退出）、多实例**提示不阻断**、预检失败拒绝启动 | `mcp-server.ts` |
| stdio 多实例锁 | `~/.ki/mcp-stdio-<pid>.lock`（每实例独立文件），仅用于进程管理定位，不拒绝多实例 | `lib/mcp-stdio-lock.ts` |
| HTTP 锁 | `~/.ki/mcp-http.lock`，持锁者身份（host/port/pid/web）可查 | `lib/mcp-http.ts` |
| 多 Token + scope 授权（RBAC） | `~/.ki/mcp-tokens.json`（0600），每个 Token 绑定授权 scope 集合（含 `all`）；HTTP 层拦截越权 scope | `lib/mcp-token.ts` + `mcp-http.ts` |
| 一键停止 | `ki mcp stop` 按 lock/healthz 定位服务进程，SIGTERM→SIGKILL 兜底 | `lib/mcp-stop.ts` |
| 健康检查 | `/healthz` 端点 + `ki mcp --status` 状态查询（探测目标对齐 restart：CLI > lock > 配置 > 默认） | `lib/mcp-http.ts` |
| 前端静态托管 | `--web`（默认跟随上次）提供 `web/dist` SPA，`--no-web` 显式关闭 | `lib/mcp-http.ts` |
| HTTP 扩展接口 | `/api/*`（Web UI 数据接口，除 `/api/import/*` 归导入专家） | `lib/mcp-http-api.ts` |
| 启动预检 | 复用 doctor 检查逻辑，失败拒绝启动 | `lib/health-check.ts`（属存储与配置专家，本专家为消费方） |
| 版本自检 | 长驻进程版本 banner + 升级监听告警 | `lib/version-guard.ts` |

## 能力边界（本专家不做什么）

- **不实现**各工具的业务逻辑（检索/存储/关系管理），仅做协议封装、参数校验、超时包装与工具注册，业务能力由对应业务专家（检索/导入/关系）提供
- **不提供**批量管理（`ki_manage_index_delete` 仅限空节点，级联删除只在 CLI 暴露）
- **token 不入配置文件**：鉴权凭据只走 CLI 参数 / 环境变量 / `~/.ki/mcp-tokens.json`，绝不写入 YAML
- **不实现健康检查项**：`runHealthCheck` 的实现与检查项清单归「存储与配置基础专家」，本专家只做消费方（启动预检 + `/healthz` 暴露）
- **不实现 `/api/import/*`**：该组 HTTP 接口归「知识索引导入专家」，本专家只负责在 `createMcpHttpServer` 中挂载路由
- **守护进程化在 `bin/ki.mjs` 层**：detached spawn，日志不落盘、无崩溃自动拉起（用户明确决策）

## 已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|------|----------|----------|
| 工具(0) 显示 / 401 | 客户端 Token 配置错误（手抄漏字符/多空格） | 整段复制 `ki mcp token list` 输出的 token 字段；服务端 stderr 有鉴权失败原因 |
| 调用报 403「请求 scope 不在该 Token 授权范围内」 | Token 授权集合不含请求 scope | 用 `ki mcp token update <id> --scope a,b` 扩权，或换用 `all` 授权 Token |
| `ki_scope_list` / `ki_manage_index_list` 被 403 | 这两个工具无 scope 参数，曾按 default 校验被误伤 | 已在 `SCOPE_LESS_TOOLS` 白名单豁免（**新增无 scope 参数的工具必须同步加白名单**）；输出由工具层 `authScopes` 过滤 |
| Token 来源不清楚（改了文件不生效） | 优先级 `--token` > `KI_MCP_TOKEN` > 多 Token 存储 | 非回环启动时会 stderr 打印「鉴权 Token 来源：…」；`--token`/env 为**全权**临时 Token，优先级最高 |
| Token 文件损坏导致全部 Token 失效 | `~/.ki/mcp-tokens.json` 不可解析 | 鉴权路径 fail-closed（全部失效但不崩溃）；**写操作与 list 直接报 `MCP_TOKEN_CORRUPT` 拒绝**，防损坏静默扩散，需人工检查该文件 |
| Token 不生效 | 回环绑定（127.0.0.1）时鉴权被禁用 | 对外监听用 `--host 0.0.0.0` + token（回环下提供 Token 会收到"不生效"提示） |
| 非回环启动报 `MCP_HTTP_TOKEN_REQUIRED` | 未配置任何 Token 且非回环绑定 | `ki mcp token generate --scope <scope>` 创建，或设 `KI_MCP_TOKEN` / 传 `--token` |
| stdio 与 HTTP 并存撞向量库锁 | 多个 stdio 实例或 stdio+HTTP 同时持锁 | 现为**软冲突**：空闲释放锁（3s）+ 撞锁重试（2s×3）错开；真并发仍会撞锁，优先迁移到 HTTP 单例 |
| `ki mcp --http` 启动后 IDE 无工具 | 客户端用 command 型配置而非 URL 型 | 配置 `{ "url": "http://127.0.0.1:7423/mcp" }` |
| `--daemon` 报 `MCP_DAEMON_REQUIRES_HTTP` | 未加 `--http` | daemon 仅 HTTP 模式有意义（stdio 后台会丢失传输通道） |
| `ki mcp restart` / `--status` 探测不到实例 | 实例监听非默认地址，或 lock 丢失 | 探测目标优先级 CLI > lock（pid 存活）> 配置 > 默认；`--status` 会回退读 lock。daemon 网络类慢失败仍可能假报成功，用 `--status` 兜底 |
| `--web` 提示未找到前端产物 | `web/dist/index.html` 未构建 | 在 `web/` 下 `npm install && npm run build`；**不阻塞 MCP 启动**（仅前端不可访问） |
| 升级后改动不生效 | 长驻进程仍执行旧代码 | `ki mcp restart`（jiti 缓存清理见 AGENTS.md） |
| HTTP 端口被占但探活无实例 | 非 ki 进程占用或残留实例 | 换 `--port` 或排查占用进程 |

## 子专家导航

无子专家。本专家依赖业务专家提供的底层能力（检索/存储/关系），并依赖「存储与配置基础专家」的 `loadConfig` / `runHealthCheck` / `SERVICE_NAME`。
