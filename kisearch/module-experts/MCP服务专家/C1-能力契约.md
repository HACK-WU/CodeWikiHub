# C1-能力契约：MCP 服务专家

> 本契约覆盖本专家的公开能力。契约来源标注类名/方法签名（非行号）。
> 代码示例为使用方代码（客户端调用 MCP），API 签名真实。

## 1. MCP Server 入口（`src/mcp-server.ts`）

### 1.1 `buildKiMcpServer(authScopes?: string[] | null): McpServer`

- **用途**：构建 kisearch McpServer 并注册全部工具。
- **参数**：`authScopes` — 该会话的授权 scope 集合；`null`/省略 = 免鉴权（不限）；`['all']` 或具体列表 = 受限（传给 `registerManageIndexTools` / `registerScopeListTool`，由工具层过滤枚举输出）。
- **返回**：`McpServer`（name=`kisearch`，version=当前包版本）。
- **约束**：stdio 与 HTTP 共用此工厂；HTTP 模式下**每会话按其 Token 的授权集合新建实例**（共享 vector-client 模块级单例 engine）。注册顺序：`ki_query_group` → `ki_get_module_info` → `ki_sync_relation` → `ki_bulk_sync_relation` → `ki_manage_index_*`(3) → `ki_search` → `ki_store` → `ki_bulk_store` → `ki_delete_relation` → `ki_scope_list` → `ki_tag_list`。

```ts
import { buildKiMcpServer } from './mcp-server.js';
const server = buildKiMcpServer(null); // 免鉴权（如回环绑定）
// 然后连接 transport（stdio / streamable HTTP）
```

### 1.2 `startMcpServer(): Promise<void>`

- **用途**：CLI 主分发入口，处理 `-h/--help`、`token <子命令>`、`--status`、`stop`、`restart` 与 stdio/HTTP 启动。
- **参数**：无（读 `process.argv`）。
- **返回**：`Promise<void>`。
- **约束**：stdio 模式 stdout 留给协议，诊断写 stderr；`--daemon` 仅 HTTP 模式合法。

**CLI 子命令**（`ki mcp ...`）：
- `ki mcp`：stdio 模式（默认）
- `ki mcp --http [--host] [--port] [--token] [--allowed-hosts] [--web|--no-web] [--daemon|-d]`：HTTP 共享单例
- `ki mcp restart`：重启 HTTP 单例（强制 `--http --daemon`）；**启动前检测存活 stdio 实例但不静默 kill**；非回环 host 时做 Token 预检
- `ki mcp --status`：只读诊断（探测目标优先级 CLI > lock > 配置 > 默认，lock 回退可探测非默认地址实例）
- `ki mcp stop`：关闭本机所有实例并清理 lock
- `ki mcp token generate --scope <scope> | list | update <id> --scope <scope> | delete <id>`：多 Token + scope 授权全生命周期

**参数解析规则**：
- 未知 flag 检测：`known = ['--http','--host','--port','--token','--allowed-hosts','--status','--web','--no-web','--daemon']`，valueFlags 为前四者
- `--web` 与 `--no-web` 同时出现时**以 `--no-web` 为准**（restart 用后者覆盖上次的 `--web` 延续）

## 2. 工具超时辅助（`lib/mcp-tools/util.ts`）

### 2.1 `withTimeout<T>(promise, ms, label): Promise<T>`

- **用途**：为 Promise 附加超时上界。
- **行为语义**：超时后 reject `ToolTimeoutError`（`code='TOOL_TIMEOUT'`）；定时器 `unref` 不阻止进程退出。
- **约束**：底层任务超时后仍可能在后台完成，但调用方不再被阻塞。

```ts
import { withTimeout, TOOL_TIMEOUT } from './lib/mcp-tools/util.js';
const result = await withTimeout(someAsync(), TOOL_TIMEOUT.READ, '查询');
```

### 2.2 `TOOL_TIMEOUT`

- `READ: 30_000`（只读/轻量查询）、`WRITE: 60_000`（单条写入/语义检索）、`BULK: 300_000`（批量写入）。

## 3. MCP 工具契约

所有工具经 `server.tool(name, desc, schema, handler)` 注册；handler 失败返回 `{isError: true, content: [文本错误]}`。

### 3.1 `ki_search`

| 项 | 值 |
|----|----|
| 参数 | `scope?`（默认 default）、`query`（必填）、`limit?`（int>0 默认 10）、`threshold?`（0-1）、`tags?`（逗号分隔） |
| 返回 | `{ok:true, scope, results: SearchHit[]}` |
| 超时 | WRITE（60s） |
| 行为语义 | `tags` 不传 → 搜全部标签（每 tag 最多 limit 条，ki-search 优先）；传值 → 多标签 OR 过滤 |

### 3.2 `ki_store`

| 项 | 值 |
|----|----|
| 参数 | `scope?`、`text`（必填）、`tags?`（默认 `ki-search`） |
| 返回 | `{ok:true, scope, docId}` |
| 超时 | WRITE |

### 3.3 `ki_bulk_store`

| 项 | 值 |
|----|----|
| 参数 | `scope?`、`input`（必填，批量 JSON 文件路径） |
| 返回 | `BulkStoreResult` |
| 超时 | BULK（300s） |

### 3.4 `ki_query_group`

| 项 | 值 |
|----|----|
| 参数 | `scope?`、`groups?` / `group`（单数别名）、`hot_count?`（默认 5）、`depth?`（1-10 默认 4）、`mode?`（默认 hot，逗号分隔）、`auto_fallback?`（默认 true） |
| 返回 | `QueryGroupResult` |
| 超时 | READ（30s） |
| 行为语义 | `auto_fallback=true` 时精确路径未命中自动走向量模糊定位 |

### 3.5 `ki_get_module_info`

| 项 | 值 |
|----|----|
| 参数 | `scope?`、`group`（必填）、`relation`（必填） |
| 返回 | `GetModuleInfoResult`（本地 KB 原文） |
| 超时 | READ |

### 3.6 `ki_sync_relation`

| 项 | 值 |
|----|----|
| 参数 | `scope?`、`group`（必填）、`relation`（必填）、`module_info`（必填 Markdown）、`keywords`（必填 string[]）、`tags?`（逗号分隔自定义标签）、`vector?`（默认 true） |
| 返回 | `SyncRelationResult` |
| 超时 | WRITE |
| 行为语义 | 写入关系时关键词校验（非法关键词列入 `invalid_keywords`）；可触发 Wiki 写回（`wikiSynced`）；`vector:false` 为非向量化模式（仅写 KB 层，不产生 memoryId，无法被 `ki search` 召回） |

### 3.6.1 `ki_bulk_sync_relation`

| 项 | 值 |
|----|----|
| 参数 | `scope?`、`items`（必填数组，1-50 条：`group` / `relation` / `module_info` / `tags?`）、`vector?`（默认 true） |
| 返回 | `BulkSyncRelationResult`（复用 `executeBulkSyncRelation`） |
| 超时 | BULK（300s） |
| 行为语义 | **一次 embedding + 一次向量写入**完成多条写入，比并发多次调用 `ki_sync_relation` 快 N 倍；自动补建 Group 树；单条失败不影响整体返回的错误标记。写多条 Relation 时优先用此工具 |

### 3.7 `ki_delete_relation`

| 项 | 值 |
|----|----|
| 参数 | `scope?`、`group`（必填，支持模糊）、`relation`（必填，精确） |
| 返回 | `DeleteRelationOutcome` |
| 超时 | WRITE |

### 3.8 `ki_manage_index_create` / `ki_manage_index_list` / `ki_manage_index_delete`

| 工具 | 参数 | 说明 |
|------|------|------|
| `ki_manage_index_create` | `scope?`、`name`（必填，不含 `/`）、`parent?` | 创建 Group 节点；超时 WRITE |
| `ki_manage_index_list` | 无参 | 列出所有 scope（**受 `authScopes` 过滤**）；同步，非 timeout 包裹；属 `SCOPE_LESS_TOOLS` 白名单 |
| `ki_manage_index_delete` | `scope?`、`name`、`parent?` | **仅限空节点**（非空拒绝，级联删除只在 CLI 暴露）；超时 WRITE |

> `registerManageIndexTools(server, authScopes)` 一次性注册上表三个工具，`authScopes` 用于枚举类输出过滤。

### 3.9 `ki_scope_list`

- 无参；返回三层（KB / 向量 / 配置注册）并集的 scope 列表，**输出按 `authScopes` 过滤**；向量层枚举走单次 probe + `fastFail`，撞锁立即降级为仅 KB 层（`vectorAvailable:false` + `vectorReason`），不挂起。属 `SCOPE_LESS_TOOLS` 白名单。

### 3.10 `ki_tag_list`

- 参数：`scope?`；返回 scope 下 tag 及文档数。

**新增工具时的强制动作**：若新工具**不带 `scope` 参数**（schema 为 `{}`），必须加入 `mcp-http.ts` 的 `SCOPE_LESS_TOOLS` 白名单，否则无参调用会被 scope 闸门按 `default` 校验而 403。

## 4. HTTP 共享单例（`lib/mcp-http.ts`）

### 4.1 `createMcpHttpServer(opts: HttpAppOptions): McpHttpApp`

- **用途**：创建 HTTP 应用（`createServer` 工厂，不直接 listen）。测试与端到端验证用此工厂直起，可绕过 stdio 守卫。
- **关键可选参数**：`host` / `port` / `token` / `allowedHosts` / `buildServer(authScopes)` / `webDir`（`--web` 静态根目录，null 禁用）/ `stdioLockDir` / `onSession` / `onShutdown`。
- **返回**：`McpHttpApp {server, sessionManager, mcpBindings?}`，`mcpBindings.routePath` 为 MCP 挂载路径。

```ts
import { createMcpHttpServer } from './lib/mcp-http.js';
const app = createMcpHttpServer({ host: '127.0.0.1', port: 7423, buildServer: buildKiMcpServer });
app.server.listen(7423);
```

### 4.2 `startHttpMcpServer({host, port, token?, allowedHosts?, web?, buildServer, onShutdown?})`

- **用途**：启动 HTTP 版 ki mcp（幂等单例）。
- **行为语义**：
  - 回环绑定（`127.0.0.1`/`::1`/`localhost`）→ 免鉴权；非回环绑定 → 强制鉴权
  - 启动前探活 `/healthz`，命中健康实例 → 复用并 `process.exit(0)`
  - Token 来源优先级 `--token` > `KI_MCP_TOKEN` > 多 Token 存储（`~/.ki/mcp-tokens.json`）；非回环且三者皆无 → 报 `MCP_HTTP_TOKEN_REQUIRED` 拒绝启动；非回环启动成功时 stderr 打印来源
  - 回环绑定下提供 Token → 提示「鉴权已禁用，Token 不生效」
  - `--token` 传入会提示「暴露在进程列表/命令历史，推荐用 `KI_MCP_TOKEN`」
  - `allowedHosts` 开启 DNS rebinding 保护（客户端 403 时核对该白名单）
  - `web?: boolean` → 静态目录取 `getPackageRoot()/web/dist`（支持 `KI_WEB_DIR` 覆盖）；缺 `index.html` 时**提示但不阻塞启动**
  - 路由：`/mcp`（MCP 协议）、`/healthz`、`/api/*`（Web UI 数据接口）、`GET /*`（`--web` 时静态 + SPA fallback，防路径穿越）
- **返回**：`Promise<void>`（启动后常驻）。

```bash
# 本机多 IDE 共享（免鉴权）
ki mcp --http

# 远程访问（鉴权）
ki mcp --http --host 0.0.0.0 --token <t>

# 后台常驻 + 前端页面
ki mcp --http --daemon --web
```

### 4.2.1 scope 越权拦截（RBAC 执行点）

- 鉴权模式下 HTTP 层在 `handleMcpPost` 解析 `authScopes` 后，对 `tools/call` 做**全项**校验（`findScopeViolation`）：batch 请求逐项检查，`arguments.scope` 缺失/非法视为 `default` 参与校验（防省略 arguments 绕过）
- **白名单豁免**：`SCOPE_LESS_TOOLS = {'ki_scope_list','ki_manage_index_list'}` 跳过单点校验，安全边界由工具层 `authScopes` 过滤输出兜住
- 越权响应 403，**scope 名只写服务端 stderr 不回显给客户端**（防信息泄露）

### 4.3 `fetchHealthz(host, port, timeoutMs?)` / `probeHealthz(host, port, timeoutMs?)`

- **用途**：GET `/healthz` 并解析返回体 / 判定是否为健康 kisearch 实例。
- **返回**：`HealthzInfo | null` / `boolean`。

### 4.4 `isLoopbackHost(host)` / `probeHost(host)`（`lib/net-addr.ts`）

- **`isLoopbackHost`**：判定回环地址（支持 `127.0.0.0/8` 网段、`::1`、`localhost`；回环 → 免鉴权）。
- **`isLoopbackAddr`**：IPv4/IPv6 网段级判定，供 `isLoopbackHost` 内部使用。
- **`probeHost`**：连接地址归一（`0.0.0.0`/`::`/`localhost` → `127.0.0.1`）。

### 4.5 `printHttpStatus(host, port)`

- **用途**：`ki mcp --status` 输出（lock + 探活 + Token 数量，不回显明文）。
- **行为语义**：探测目标优先级 **CLI > lock（pid 存活）> 配置 > 默认**，因此可探测非默认地址实例。

### 4.6 `describeListenError(err, host, port)`

- **用途**：将 listen 错误（EADDRINUSE/EACCES/EADDRNOTAVAIL/ENOTFOUND）翻译为可诊断文案。

## 5. stdio 多实例锁（`lib/mcp-stdio-lock.ts`）

> 已从「单文件单 pid 单实例锁」改为「**每实例独立 lock 文件**」：`~/.ki/mcp-stdio-<pid>.lock`（文件名即 pid）。lock 仅用于进程管理定位（stop/restart/status），**不再拒绝多实例**——多实例靠向量库空闲释放锁 + 撞锁重试错开共享。

### 5.1 `acquireStdioLock(dir?): StdioLockInfo[]`

- **用途**：登记当前进程的 stdio lock（`wx` 原子独占；已存在则覆盖更新 startedAt）。
- **返回**：**其他存活实例列表**（供调用方提示，不阻断）。
- **行为语义**：写失败不阻塞启动，但 stderr 告警（lock 缺失会导致 `ki mcp stop` / `--status` 对本实例"失明"）。

```ts
import { acquireStdioLock, listLiveStdioLocks, releaseStdioLock } from './lib/mcp-stdio-lock.js';
const others = acquireStdioLock();          // 返回其他存活实例，不拒绝
if (others.length > 0) console.warn(`已有 ${others.length} 个 stdio 实例在运行`);
```

### 5.2 `listLiveStdioLocks(dir?)` / `listStdioLockFiles(dir?)` / `stdioLockPidFromPath(file)`

- **`listLiveStdioLocks`**：列出所有**存活**实例（排除自身，顺带清理陈旧/损坏 lock）；返回 `{pid, startedAt}[]`。
- **`listStdioLockFiles`**：列目录下全部 lock 文件路径（含陈旧，按路径排序）。
- **`stdioLockPidFromPath`**：从文件名解析 pid（非本格式返回 `null`）。

### 5.3 `pidAlive(pid)` / `releaseStdioLock(dir?)`

- **`pidAlive`**：`kill(pid, 0)` 探测，**EPERM 视为存活**（进程存在但无权限）。
- **`releaseStdioLock`**：删除**自己的** lock 文件（文件名即 pid，天然不误删他人）。

### 5.4 `getStdioLockDir()` / `getStdioLockFilePath(pid)`

- 默认目录 `~/.ki`；文件名 `mcp-stdio-<pid>.lock`。

## 6. 多 Token + scope 授权（`lib/mcp-token.ts`）

> 已从「单 Token 全局鉴权」升级为「多 Token + 每 Token 绑定授权 scope 集合」。存储 `~/.ki/mcp-tokens.json`（JSON 数组，0600），**与旧版 `~/.ki/mcp-token` 不兼容**。

### 6.1 `createToken(scopes, filePath?): TokenRecord`

- **用途**：生成并持久化一条 Token（32 字节熵 base64url）。
- **返回**：`TokenRecord {id, token, scopes, createdAt}`（`id` 为 8 位无易混淆字符短 ID）。
- **异常**：存储文件损坏 → `MCP_TOKEN_CORRUPT`（**拒绝写回，防静默丢失现有记录**）。
- **约束**：写回为原子写（同目录临时文件 0600 → rename）；目录 0700。

```ts
import { createToken, resolveScopesArg } from './lib/mcp-token.js';
const record = createToken(resolveScopesArg('team-a,team-b'));
console.log(record.token); // 明文仅此处出现一次
```

### 6.2 `updateTokenScopes(id, scopes, filePath?)` / `deleteToken(id, filePath?)`

- **用途**：按短 ID 改授权集合 / 删除（立即失效）。
- **异常**：`id` 不存在 → `TOKEN_NOT_FOUND`（附"用 `ki mcp token list` 查看 id"指引）；文件损坏 → `MCP_TOKEN_CORRUPT`。

### 6.3 `listTokensStrict(filePath?)` / `listTokens(filePath?)`

- **`listTokensStrict`**：严格读，损坏**抛错**（`MCP_TOKEN_CORRUPT`）。供 CLI `list` 与**所有写操作**使用。
- **`listTokens`**：宽松读，损坏返回 `[]`。供鉴权路径使用（**fail-closed**：所有 Token 失效但不崩溃）。

### 6.4 `findTokenScopes(tokenValue, filePath?): string[] | undefined`

- **用途**：鉴权查询，按 Token 明文返回授权 scope 集合。
- **行为语义**：遍历全部记录用 `crypto.timingSafeEqual` **常量时间比较**（防时序侧信道泄露匹配位置）；未命中返回 `undefined`。

### 6.5 `isScopeAuthorized(authScopes, scope)` / `resolveScopesArg(raw)` / `tokenCount(filePath?)`

- **`isScopeAuthorized`**：`authScopes === null` 免鉴权放行；含 `all` 或含该 scope 则通过。
- **`resolveScopesArg`**：`'all'` → `['all']`；`'a,b'` → `['a','b']`；含 `all` 时归一化为 `['all']`（冗余值忽略）；空或含非法字符抛错（字符集对齐 `validateScope`）。
- **`tokenCount`**：记录数量（供 `--status` 诊断，不含明文）。

### 6.6 `getTokensPath()` / `ALL_SCOPES`

- `getTokensPath()` → `~/.ki/mcp-tokens.json`；`ALL_SCOPES = 'all'`（全部授权保留字）。

**CLI 命令**（`ki mcp token ...`）：

| 子命令 | 必需参数 | 输出要点 |
|--------|----------|----------|
| `generate` | `--scope <单个/逗号分隔/all>`（必填） | 返回 id + token 明文（唯一一次） + 0600 落盘提示 |
| `list` | — | 全部记录（**含明文**，用户明确要求）；损坏时报错而非静默空列表 |
| `update <id>` | `--scope <...>` | 更新授权集合 |
| `delete <id>` | — | 立即失效；已建会话保留但新请求 401 |

## 7. 一键停止（`lib/mcp-stop.ts`）

### 7.1 `stopMcpInstances({host, port, ...})`

- **用途**：关闭本机所有 ki mcp 实例并清理 lock。
- **返回**：`StopReport {stopped: StopEntry[], cleanedLocks: string[]}`。
- **行为语义**：按 stdio lock / http lock / healthz 定位目标（去重排除自身）；SIGTERM 优雅退出（超时 3s）→ SIGKILL 兜底；杀前 `/proc/<pid>/cmdline` 身份校验防误杀（校验不可用则直接发信号）。
- **异常**：目标 `result: 'skipped'`（pid 被复用）时不发信号。

## 8. 健康检查与版本（`lib/health-check.ts` / `lib/version-guard.ts`）

### 8.1 `runHealthCheck(config): Promise<HealthReport>`

- **用途**：执行完整健康检查（配置字段告警 / 目录可写 / apiKey / embedding 连通性与维度 / zvec collection / scopes.default），共 11 项。
- **返回**：`HealthReport {items, pass, warn, fail}`。
- **约束**：只读；`ki mcp` 启动预检复用（有 ❌ 拒绝启动）。
- **归属**：**实现在「存储与配置基础专家」**（`lib/health-check.ts`），本专家只做消费方（启动预检 + `/healthz`）。检查项清单变更以该专家契约为准。

### 8.2 `startVersionGuard(serverName): () => void`

- **用途**：启动版本 banner + 监听 package.json 变化告警（升级后提示重启）。
- **返回**：停止监听的函数（供关闭时调用）。

## 已知约束汇总

- MCP 工具集遵循**零破坏性**约束：不含 delete/force 危险操作（`ki_manage_index_delete` 仅限空节点）。
- stdio 模式 stdout 只走协议；所有诊断/报告写 stderr。
- HTTP 非回环绑定必须提供 Token（`--token` > `KI_MCP_TOKEN` > 多 Token 存储）。
- Token 明文只在 `generate` 成功输出时出现一次（`list` 按需回显，用户明确要求）。
- `--token` / `KI_MCP_TOKEN` 是**全权**临时 Token（不受 scope 限制），优先级高于多 Token 存储。
- **新增不带 `scope` 参数的工具必须同步加入 `SCOPE_LESS_TOOLS`**，否则无参调用被 403。
- Token 写操作「读-改-写」无文件锁（低频运维可接受），并发调用可能丢更新。
- 守护进程（daemon）日志不落盘、无崩溃自动拉起（用户明确决策），网络类慢失败可能假报成功，用 `ki mcp --status` 兜底。
- `ki mcp restart` 不静默 kill 存活 stdio 实例（只提示），非回环 host 会先做 Token 预检。
