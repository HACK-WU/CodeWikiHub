# C2-使用流程：MCP 服务专家

## 流程 1：本地 IDE 接入（stdio 单客户端）

**业务目标**：单个 IDE 通过 stdio 模式使用 kisearch 能力。

**调用顺序**：
1. 配置 IDE 的 MCP 客户端（`command: ki`, `args: ["mcp"]`，env 传入 `SILICONFLOW_API_KEY`）
2. IDE 启动时拉起 `ki mcp`

**事务边界**：单客户端单进程；进程持有向量库锁。

**预期结果**：IDE 中出现 11 个 `ki_*` 工具，可调用查询/写入。

**错误处理**：启动预检失败（缺 API Key / 维度不匹配）拒绝启动，报告写 stderr；多实例冲突时明确拒绝。

**真实代码示例**（IDE 配置）：
```json
{
  "mcpServers": {
    "ki": {
      "command": "ki",
      "args": ["mcp"],
      "env": { "SILICONFLOW_API_KEY": "<your-api-key>" }
    }
  }
}
```

## 流程 2：多 IDE 共享（HTTP 单例）

**业务目标**：多个 IDE / 远程客户端共享同一持锁进程，避免向量库锁冲突。

**调用顺序**：
1. 启动 HTTP 单例：`ki mcp --http`（本机回环，免鉴权）
2. 所有 IDE 配置 URL 型接入：`{ "url": "http://127.0.0.1:7423/mcp" }`
3. 远程访问：`ki mcp --http --host 0.0.0.0 --token <t>`，客户端配置 `Authorization: Bearer <t>`

**事务边界**：HTTP 单例是向量库唯一持锁者；每会话独立 McpServer 实例（共享 engine）。

**预期结果**：多 IDE 共享一个持锁进程，无锁冲突降级。

**错误处理**：
- stdio 与 HTTP 并存 → **不再拒绝**，仅提示（多实例靠空闲释放锁 3s + 撞锁重试 6s 错开共享）；仍撞锁时建议收敛到 HTTP 单例
- 幂等：重复启动命中健康实例 → 复用退出
- 非回环无 Token → `MCP_HTTP_TOKEN_REQUIRED` 报错并引导 `ki mcp token generate --scope <...>`
- `--daemon` 未配 `--http` → `MCP_DAEMON_REQUIRES_HTTP`

**真实代码示例**：
```bash
ki mcp --http                       # 本机共享单例（前台）
ki mcp --http --daemon --web        # 后台常驻 + 前端页面
ki mcp --http --host 0.0.0.0 --token <t>   # 远程（Token 从 token generate 输出获取）
ki mcp --status                     # 查看运行状态（只读）
ki mcp restart                      # 重启后台单例
```

## 流程 3：多 Token 与 scope 授权管理

**业务目标**：为远程/多租户访问配置最小授权的 Bearer Token。

**调用顺序**：
1. `ki mcp token generate --scope <单个|逗号分隔|all>`（**`--scope` 必填**）→ 得到 id + 明文（唯一一次）
2. `ki mcp token list` 查看全部（含明文与授权 scope）
3. 调整权限：`ki mcp token update <id> --scope <...>`（无需换 Token）
4. 吊销：`ki mcp token delete <id>`（立即失效）

**事务边界**：`delete` 立即生效（新请求 401，已建会话保留）；存储为原子写（临时文件 → rename）。

**预期结果**：Token 存储位于 `~/.ki/mcp-tokens.json`（0600，目录 0700）；越权 scope 请求被 HTTP 层 403 拦截。

**错误处理**：缺 `--scope` → `MCP_TOKEN_SCOPE_REQUIRED`；id 不存在 → `TOKEN_NOT_FOUND`（引导 `token list`）；存储损坏 → `MCP_TOKEN_CORRUPT`（**写操作拒绝，防静默丢失**）。

**真实代码示例**：
```bash
ki mcp token generate --scope default          # 单 scope
ki mcp token generate --scope team-a,team-b    # 多 scope
ki mcp token generate --scope all              # 全权（谨慎）
ki mcp token list
ki mcp token update a1b2c3d4 --scope team-a,team-c
ki mcp token delete a1b2c3d4
```

## 流程 4：停止与清理

**业务目标**：关闭本机所有 ki mcp 实例并清理 lock。

**调用顺序**：
1. `ki mcp stop`

**事务边界**：按 lock/healthz 定位服务进程直接发信号；杀前 `/proc/<pid>/cmdline` 身份校验防误杀。

**预期结果**：输出 `{stopped, cleanedLocks}`；无实例时提示未发现。

**错误处理**：升级前启动的旧 stdio 进程不写 lock 无法定位（提示 `ps -ef | grep mcp-server` 人工确认）。

**真实代码示例**：
```bash
ki mcp stop
```

## 流程 5：启动预检与诊断

**业务目标**：验证环境配置可用。

**调用顺序**：
1. `ki doctor`（独立诊断）
2. 或 `ki mcp --http` 自动执行启动预检（等价 doctor，报告写 stderr）

**事务边界**：只读。

**预期结果**：✅/⚠️/❌ 报告；`ki mcp` 启动预检存在 ❌ 拒绝启动（`ki doctor` 退出码 1）。

**错误处理**：embedding 密钥缺失 / 维度不匹配明确报失败项。

**真实代码示例**：
```bash
ki doctor
```
