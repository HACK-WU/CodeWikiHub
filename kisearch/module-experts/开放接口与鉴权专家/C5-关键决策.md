# C5-关键决策：开放接口与鉴权专家

> 只收有明写证据（代码注释 / commit message / 设计文档）的决策；结构暗示的一律前置 `[推测]`。

## /open/v1/* 三层职责、顺序即语义：开关 → 鉴权 → 路由；与 /api/* 各自独立互不调用

- **分类**：边界
- **决策**：/open/v1/* 三层职责、顺序即语义：开关 → 鉴权 → 路由；与 /api/* 各自独立互不调用
- **背景约束**：对外通道不能继承浏览器会话语义
- **被否决方案及理由**：复用 /api 鉴权链；否决理由见 index.ts 文件头
- **重新评估触发条件**：出现跨通道能力复用需求时
- **证据来源**：代码注释：src/lib/open-api/index.ts 文件头

## 不复用 resolveWebPrincipal

- **分类**：安全
- **决策**：不复用 resolveWebPrincipal
- **背景约束**：本机回环请求会直接短路成管理员，且会读浏览器 Cookie
- **被否决方案及理由**：复用 Web 主体解析；否决理由见 auth.ts 文件头
- **重新评估触发条件**：回环请求也需要严格 Bearer 鉴权时
- **证据来源**：代码注释：src/lib/open-api/auth.ts 文件头

## 上传上限取 4GiB 而不是更大

- **分类**：容量
- **决策**：上传上限取 4GiB 而不是更大
- **背景约束**：单次请求的临时磁盘峰值 = 包 + 解包内容
- **被否决方案及理由**：更大的上限；否决理由见 constants.ts 注释
- **重新评估触发条件**：服务器磁盘余量显著提升时
- **证据来源**：代码注释：src/lib/open-api/constants.ts

## 对外通道可经 --no-upload-api 关闭

- **分类**：部署
- **决策**：对外通道可经 --no-upload-api 关闭
- **背景约束**：第三方程序上传通道需可关
- **被否决方案及理由**：常开；否决理由见 git 历史
- **重新评估触发条件**：默认必须开放上传时
- **证据来源**：commit message（reflog）：feat(open-api): 第三方程序上传通道 /open/v1，可经 --no-upload-api 关闭
