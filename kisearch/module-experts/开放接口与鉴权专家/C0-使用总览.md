# C0-使用总览：开放接口与鉴权专家

## 能力清单

| 能力 | 说明 | 入口 |
|---|---|---|
| 唯一分发 | /open/v1/* 三层顺序：开关 → 鉴权 → 路由 | handleOpenApiRequest |
| 能力协商 | ping 返回 contractVersion 与 capabilities | handleOpenApiPing |
| Bearer 鉴权 | 独立于浏览器会话的 Token 解析 | resolveOpenApiPrincipal |
| 只读取件 | doc / asset / events 三类只读端点 | routes/ |
| 上传 | 分片上传会话与暂存目录 | createUploadSession / upload-stream.ts |
| 图集部署 | atlas package 上传与状态 | routes/atlas.ts |
| 权限 | 路由权限表、工具能力位、用户与角色 | auth/ + src/user.ts |

## 能力边界（本专家不做什么）

- 不实现 /api/*：两套路由各自独立、互不调用
- 不实现 MCP 工具逻辑：只做能力位判定
- 不实现浏览器 Cookie 会话：归 web-auth / web-session-store
- 不实现导入内核：上传暂存后交导入链路

## 已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|---|---|---|
| 本机回环请求被当成管理员 | 复用 resolveWebPrincipal | resolveOpenApiPrincipal 独立实现，不读浏览器 Cookie |
| 客户端连上了但调用 404 | 未先 ping 协商能力位 | ki-client 先 pingRemote 再按 capabilities 决定可用命令 |
| 上传体积改了没生效 | 只改服务端常量 | 客户端按 ping 的 maxPackageSize 分批，两侧都要看 |
