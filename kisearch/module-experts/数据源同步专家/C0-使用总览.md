# C0-使用总览：数据源同步专家

## 能力清单

| 能力 | 说明 | 入口 |
|---|---|---|
| 数据源登记 | 本地目录与远端 Git 的增删改查 | addDataSource / removeDataSource / scanDataSources |
| 同步 | 导入 + 计算待删候选，永不直接删 | syncDataSource |
| 定时调度 | daemon 启动时拉起调度器 | startDataSourceScheduler / runScheduledSync |
| 托管克隆 | 复用 clone 前先 fetch，避免远端新目录被误判 | refreshManagedClone |
| 映射与裁剪 | 路径映射、字段映射、待删候选合并 | datasource-mappings.ts / datasource-sync-merge.ts / datasource-prune.ts |
| CLI | ki datasource add/list/remove/sync | src/datasource.ts |

## 能力边界（本专家不做什么）

- 不实现导入内核：复用「知识索引导入专家」的 importAndPersist 链路，护栏不许改 import 内部
- 不实现 HTTP 服务器：路由挂在 mcp-http-api.ts
- 不实现 Web 数据源页面：归「可视化前端专家」
- 不直接删除知识：只产出裁剪候选

## 已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|---|---|---|
| 同步后旧知识凭空消失 | 把「待删候选」当删除动作执行 | syncDataSource 只算候选，删除必须另经确认 |
| 远端新目录被判子目录不存在 | 复用托管 clone 前没 fetch | refreshManagedClone 先 fetch |
| 定时同步没跑 | daemon 未启动（调度器在 HTTP 分支末尾拉起） | 先确认 HTTP 单例存活与 lock |
