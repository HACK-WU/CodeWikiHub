src/lib 按职责切分为若干独立子模块，由上层 CLI 命令与 MCP 工具按需组合调用：scope_config_cli 负责 Group/scope/group-index.json 的读写与路径补全，被 data_store_wal（store/import/wiki-sync）、vector_indexing（batch-vectorize/path-vectorize/rebuild-vector/scoring）以及 mcp-tools 中的 query-group、scope-list、tag-list 等工具共同消费；data_store_wal 通过 store.ts 暴露 ScopeStore 抽象，供 vector_indexing 写入向量元数据、mcp-tools 的 bulk-store/sync-relation 等做持久化，并由 health_version_guards 的 preflight.ts 在写操作前校验磁盘与权限；vector_indexing 封装 ZvecEngine，统一对外暴露 index/search/rebuild 接口，被批量向量化入口与 mcp-tools 的 search 等检索入口复用；ai_markdown_progress 提供条目结构、frontmatter 生成与进度输出，被 import.ts、markdown_gen.ts、wiki-sync.ts 复用；health_version_guards 集中 interrupt/version-guard/preflight/health-check，作为所有写/长驻操作的统一前置守卫；mcp-tools 下的 HTTP/stdio 传输层将上述能力注册为 MCP 工具，形成 CLI 与 MCP 双入口共享同一业务逻辑的架构；chunker、relation-map、net-addr、path-search、wal、progress、constants、config、cli-args 在各子模块间横向复用，构成统一的底层设施。
