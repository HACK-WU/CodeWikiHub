本模块由四个相互独立的纯函数式工具文件组成，均位于 `src/lib/` 下，被上层命令（`ki doctor`、`ki mcp`、`ki import/rebuild-vector/restore/backup/export`）按需引入，依赖方向单向向外：仅依赖 Node `fs`/`path`、`./config.js`、`./scope.js`、`./constants.js` 及 `dist/zvec-engine`。
- `health-check.ts`：定义 `HealthItem`/`HealthReport` 报告模型与 `runHealthCheck` 主流程，串联配置文件存在性、dataDir/backupDir/vectorDir 可写性、apiKey 存在性、embedding 三合一连通/鉴权/维度校验（复用 `SiliconFlowProvider` 并带 8s 超时+1 次重试），并通过 `renderHealthReport` 输出统一文本供 doctor/MCP 共用。
- `version-guard.ts`：读取 `KI_ROOT/package.json` 版本号打印 banner，并通过 `fs.watch` 监听 package.json 变更，在 MCP 长驻进程中检测到升级后向 stderr 告警提示重启，返回清理函数用于优雅关闭。
- `interrupt.ts`：基于 `kb/{scope}/import-interrupt.json` 实现中断标记（含 scope、时间、进度、信号），基于 `kb/{scope}/.import.lock` 实现跨进程导入锁（pid + startedAt，SIGKILL 残留通过 `process.kill(pid,0)` 检测自动清理），并提供 `acquireImportLock`/`releaseImportLock`/`clearInterruptMark` 等接口。
- `preflight.ts`：在写操作前探测目标目录可写性（试写探针）与可用磁盘空间（statfsSync 估算+10% 余量），失败抛出带 `PreflightCode` 的 `PreflightError`，由调用方统一转为 JSON 错误输出。
各文件之间无相互依赖，通过约定路径（`getKbDir`、`getVectorDir`、`KI_ROOT`）与结构化类型进行协作。
