AI 分析产物人工校正（REQ-20261123-001）落地前必须知道的五条代码事实，2026-11-23 源码直读核对。
- 空态冲突：EventAnalysisCard 在「无草稿且无已确认位置」时整卡提前 return 不渲染（D-02），所以人工清空三块后卡片会消失；清空语义必须要求 draft 不置 null，否则「已人工清空」无处可放。
- 胶囊真源：结论里的位置胶囊来自节点正文的反引号 + `codeRef.matchConfirmedLocation`（路径优先、符号次之），`node.ref` 只在正文没写路径时行尾兜底 —— 改 `ref` 字段对界面可见效果很弱，ref 编辑价值低。
- 手工新增位置：`confirmDraftLocations` 依赖 `cur.draft`（无草稿抛 ANALYSIS_DRAFT_NOT_FOUND）且 `targetDir` 复制自 draft；但 targetDir 实际可由 `prompt-config.resolveAnalysisTargetDir(targetDirs, scope)` 从配置解析，故可脱离草稿新增。
- 出口缺标记：MCP `event-list` 的 conclusionPreview 与 `GET /analysis` 都不带「是否人工修订」；加 `edited` 要三处 DTO 同步 —— `src/lib/governance-contract.ts` 的 AnalysisDraftDto 与 AnalysisDraftSummaryDto + `web/src/api/governanceContract.ts` 副本。
- 覆盖边界：重跑/续跑只重写 draft（conclusion/chain/unconfirmed/candidates），`writeDraftStart` 保留 `confirmed[]`；提示文案必须说清「位置保留」，否则用户误以为手工加的位置也会没。
- 关联：写面全集见「AI分析结论的存储与写面（含无编辑接口）」；需求文档 `CodeWikiHub/kisearch/requirements/2026-11-23-AI分析产物人工校正/requirement.md` v3，交互设计 `design/interaction-design.md`。
