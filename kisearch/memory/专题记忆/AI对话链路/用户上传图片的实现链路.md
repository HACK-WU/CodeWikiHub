用户上传图片（REQ-20261123-006）从 HTTP 到上游有**两条路径都必须读图**，漏一条就是静默丢输入。
- 存储：字节落 `{chatDir}/{scope}/assets/{convId}__{uuid}.{ext}`，会话 JSON 只存 `ChatImageRef{id,mime,bytes}`（不存 base64）；imageId 只允许 `[A-Za-z0-9-]{8,40}`，拼路径前校验防穿越
- 上传/读取/删除：`POST|GET|DELETE /api/chat/conversations/:id/images[/:imgId]`，上传按**魔数**判真实格式（png/jpeg/webp，SVG 直接拒），单张上限与张数上限取 `llm.maxImageBytes` / `llm.maxImagesPerMessage`（默认 4MB / 4 张）
- 路径1 `toolLoopPath`：`resolveUserImageParts` 读字节 → `buildUpstreamMessages(input, runtime, parts, missing)` 挂 `image_url` parts（图在前、文本在后）
- 路径2 `pureChatPath`（`supportsTools=false` / 上游报工具不支持 / LLM 未配置）：**同样要传 parts**。曾漏传 → 图静默不发，且本轮被缀上「[图片×N（已省略）]」（该占位符只该给历史轮）
- 历史轮：循环里把非本轮 images 降级为文本占位不重发（上游无状态，成本按轮数放大）
- 读不到：`missing` 计数写进 user 文本「N 张图片未能读取」，不装没这回事
- 回归：`test/chat/user-image-upstream.test.ts`（真实 `runToolLoop` + mock 上游，3 例；已验证抽掉传参时 2 例变红）
- 取舍：前端移除待发图**不删**服务端文件（编辑态会回填原图，删了会毁掉已发送消息里的图），孤儿文件靠删会话/清库级联；`deleteConversationImage` 已有接口但前端无调用方
