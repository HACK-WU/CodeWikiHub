1. executeQueryGroup 返回的是**已渲染的纯文本** output，不是结构化对象；要结构化数据直读 relations-cache.json 或用 get-module-info。
2. relation 名禁用 / \ ..（直接作 wiki 文件名），写入前即拒绝，无半成品。
3. 模糊路径兜底只在 resolveGroupPath 传了 scope 时启用（manage-index 内部未启用）。
4. 删除后仍能搜到 → 看 vectorRemoved / memMethod / reason；残留是孤儿向量，NOT_FOUND 属正常幂等。
5. 非向量化模式（vector:false / --no-vector）不产生 memoryId，内容搜不到，属预期。
6. 评分不涨：5 分钟防刷（MIN_RECORD_INTERVAL_MINUTES=5）+ useCount 上限 10。
7. 批量顶层 vectorStored:false 但逐条有成功 → 顶层语义是「全部完全成功」，看逐条 vectorReason。
8. get-module-info **有写副作用**：读取即 recordUse + 回写 cache，不是纯读。
9. 测试必须 `env -u NODE_OPTIONS -u BASH_ENV npx jiti test/<name>.test.ts`，否则 IDE 注入的 fs shim 会在批量文件操作时挂起。
10. relations-cache 的 groups 是平铺完整路径键，wiki 与 wiki/docs 彼此独立，级联必须前缀匹配。
11. 检查 src/ 全域类型必须用根 tsconfig.json（tsconfig.src.json 只 include src/zvec-engine，用它检查是假阴性）。
12. MCP 无参工具（如 ki_manage_index_list）必须同步加 SCOPE_LESS_TOOLS 白名单，否则 HTTP 模式被 scope 闸门误伤 403。
