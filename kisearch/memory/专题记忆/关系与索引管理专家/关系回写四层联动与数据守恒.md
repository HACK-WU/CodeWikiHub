src/sync-relation.ts::executeSyncRelation 顺序：scope 护栏 → 空值校验 → isUnsafeRelationName 拒绝（含 / \ ..）→ validateScope+ensureScopeDir → 读 cache → resolveGroupPath（不传 scope）→ syncSingleRelation 改内存 → 写 relRec.tags → **writeJson 先落盘 cache** → vectorWriteBack → writeBackToWiki。
- syncSingleRelation 是单条与批量共用的写内核：ensureGroupPath 补建树节点；同名 relation 视为更新（recordUse + 覆盖 local KB）；新增用 generateNextId（rel_NNN 全局最大+1），Group 内达 config.maxHotCount 则淘汰最低分记入 evicted。
- vectorWriteBack 数据守恒：一次 vectorBulkStore 写 [ki-relation, ki-search, ...自定义tags]；**全部失败则不删任何旧向量**；成功后才按 generateDocId 算新集合并删 stale；部分失败保留旧向量并给 vectorReason。
- 回写 rel.memoryIds（全部内容 docId，多 tag 各一）+ rel.memoryId（ki-search 主条，向后兼容）。删除以 memoryIds 为准。
- vector:false / --no-vector 为非向量化模式：只写 KB 层，不产生 memoryId，contentTags=[]，内容无法被 ki search 召回。
- relation 名禁用 / \ ..（直接作 wiki 文件名），写入前即拒绝，无半成品。
