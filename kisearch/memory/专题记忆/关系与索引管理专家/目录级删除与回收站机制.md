src/lib/group-delete.ts（`ki group delete`）与 src/delete-relation.ts（文档级）——**两条删除链路都不进回收站，`.ki/trash` 已不存在**。

- **组级**（`ki group delete "<g>" --yes`，缺省只预览不执行）：只清 relations 分片（含子组）+ `kb/{scope}/{group}/`（含 assets）+ group-index 树节点 + dense 向量 + FTS；失败不阻断元数据删除，以 `degraded` + `orphanIds` 透出。**不触碰 source.dir / wiki 文件**（docs/group.md:99 明示）。
- **辅助向量清扫**：按向量文档上的 `group` 标量字段枚举 `ki-relation` / `ki-path` 删除；跨组共享的确定性 docId 受保护（`sharedKept` / `sharedContentKept`）。
- **文档级**（`ki delete-relation -g -r`，两者必填；只给 `-g` 会报错并提示改用 `ki group delete`）：cache → local KB 原文 → wiki **物理 unlink**（`unlinkWithinSourceDir`，必须落在 `source.dir` 内；历史无 sourcePath 的按文件名兜底）→ 向量三级降级（memoryIds → memoryId → vectorSearch 严格匹配）→ FTS。
- **删除不可逆**：无回收站、无撤销；恢复只能靠 backup 快照或重新导入。
- `ki delete-relation -i items.json` 批量逐条删，单条失败不影响其余。
- 目标存在未结束的 `ki_edit_relation` 草稿时，文档级删除拒绝该条并提示先 cancel/finish 收口。
- 历史误记（2026-10-20 订正）：此前记载「wiki 目录 moveDirToTrash 移入 `.ki/trash/{group}/`，不物理删除，需人工清理」——该实现已随 group 命令族重构移除，勿再引用。
