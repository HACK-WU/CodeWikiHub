1. 改 src/zvec-engine 必须重新构建 dist（worker 只能加载编译产物），否则「改了源码没生效」。
2. 自定义 engine 使用必须经 withEngine，直接 await getEngine() 会重演 idle close 竞态。
3. CLI 命令 action 末尾必须 await closeEngine()，否则进程不退出；常驻进程须 enableIdleClose，否则长期占锁让所有 CLI 撞锁。
4. 存量数据用旧 docId scheme（tag 未参与 hash）→ 升级后召回/精确删除/幂等重导不可靠，需 re-import 或 rebuild-vector。
5. ki store / ki bulk_store 写入的是无根数据（不写 KB），无 group/relation、原文召回降级；**写知识记忆用 ki sync-relation --input，勿用 ki_bulk_store**。
6. ki doc delete 只删向量层，不联动 KB——删关系用 ki delete-relation（四层联动），否则 relations-cache 的 memoryId 变悬空。
7. threshold 是 RRF 融合分（量级远小于 1），勿沿用余弦 0.75；默认 0 不过滤。
8. vectorSearch 的 tags 传数组而非逗号字符串（tag 值可能含逗号，join/split 错拆）。
9. 管理面枚举（vectorListScopes/vectorListTags/vectorListDocs）是近似值：引擎无 distinct/排序，受 scanLimit（默认 10000）约束且无顺序保证，看 truncated 标志。
10. embedding.apiKey 缺失即 fail-loud，无任何隐式 env 回退（避免非该厂商 baseURL 下注入错误密钥）。
11. 异常判定用 duck-typing 而非 instanceof（旧 dist 缺新导出时会崩）。
12. 测试必须 env -u NODE_OPTIONS -u BASH_ENV npx jiti test/<name>.test.ts（IDE fs shim 会在批量文件操作时挂起）。
13. test/cli-aliases.test.ts 有 1 例过期失败（断言已删除的 ki scan-kb diff），与本模块无关但套件退出码非 0。
