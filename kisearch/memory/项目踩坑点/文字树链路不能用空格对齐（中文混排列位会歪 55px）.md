事件分析结论要展示「文字树/数据链路」时，不能用纯文本靠空格右对齐的方式：中文与 ASCII 混排时，等宽字体下中文占 1em、ASCII 约 0.6em，空格补不出稳定列位。

- 实测（demo/ai-analysis-datalink，playwright 量 getBoundingClientRect）：同一 pre 内 4 行靠空格右对齐的备注列 x = 334 / 360 / 373 / 389 px，最大偏差 55px；长行还会把备注继续往右顶。
- 结论：需要列对齐、或希望链路里的 `file:line` 可点时，必须走结构化节点（每行 `{text, note?, ref?}` + flex 布局渲染）；纯文本树只适合「文本即最终形态、不追求列整齐」的场合。
- 附带两条：① pre 要 `white-space: pre` + 容器 `overflow-x: auto`（窄栏横滑），且 `scrollWidth > clientWidth` 时必须显式提示「可横滑」，否则用户会以为内容缺失；② 纵向 `max-height` 别卡在 340px —— 8 步树约 400px，会正好裁掉最后一跳（最关键那一步）。
