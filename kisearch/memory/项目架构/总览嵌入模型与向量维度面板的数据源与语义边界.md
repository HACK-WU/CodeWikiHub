## 数据源（单一来源，两个消费方共用同一 queryKey `['vectorDimensionStatus', scope]`）
- 后端：`GET /api/vector/status`（只读快照文件，**不进 coordinator 队列** ⇒ 导入期间不阻塞；无 submit）与 `POST /api/vector/status/refresh`（走 coordinator，缺省 write 入队）@ src/lib/mcp-http-api.ts:490-531；同源 daemon RPC @ :847/:854 调同一对函数。
- `VectorDimensionSnapshot` 新增 `model` / `provider` / `baseURL` @ src/lib/vector-dimension-snapshot.ts：4 个产出口（读成功 / 读兜底 / 刷新成功 / 刷新兜底）一律由 `configuredIdentity(config)` 从 `config.embedding` **活读**；与 `configured` 同口径 —— **快照文件里也会写一份，但读路径恒覆盖**（实测：把 STALE 模型名/provider/baseURL 手写进 `.vector-status/<sha>.json`，接口仍返回当前配置值）。
- 前端：`getVectorDimensionStatus` / `refreshVectorDimensionStatus` @ web/src/api/tasksApi.ts:56-135（三个新字段**可选** ⇒ 兼容旧 daemon，缺省显示「—」）；`useVectorDimensionStatus(scope)` @ web/src/lib/hooks.ts（AppShell 与总览页共用；`staleTime:0` + **`refetchOnMount:false`** + 不随聚焦/重连 + `retry:false`；queryFn 内 unknown+已过期时补一次 POST refresh）。
- 展示：`DashboardPage` 小面板 —— 容器 `.ki-stats--pair`（2 列）/ `.ki-stat-card--soft`；嵌入模型用新增的 `.ki-stat-value--text`（mono 15px + 单行省略 + `title` 全文）；维度面板 22px 数字 + `.ki-badge--{ok|warn|off}` 角标。

## 语义边界（易误用）
- 两个面板只表达**当前配置**，**不代表索引时实际使用的模型** —— 集合创建只落 dimension 不落 model（src/lib/vector-client.ts:599-623）⇒ 改了模型名而维度不变时**检测不到**（用户 D2 拍板：UI 不加「配置」字样，该风险已接受）。
- 角标由纯函数 `dimensionBadge()` 给出 @ web/src/lib/vectorDimensionCopy.ts：**仅当 `persisted !== undefined`** 才断言「集合一致 / 集合 N 维」，否则一律「未确认」（与顶栏 banner 的 `dimensionNoticeKind` 同口径，守 N9 诚实性）。
- 请求量实测：首屏进入总览 status GET **恰好 1 次**（两个观察者共用）；站内切回总览 **0 次**（refetchOnMount:false，等价于只有 AppShell 一个观察者的改动前行为）。
