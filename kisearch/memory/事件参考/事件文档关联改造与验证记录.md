2026-11-19 把「事件上报一律挂 refs、不挂 docs」改成文档三分法，并补上上传前的事件状态预检。本文是该事件的产物文档，记录改了什么、怎么验的。

**规则变更**（`skills/event-report` §5）：
- 产物文档（debug 报告 / 需求报告 / 复盘）挂 `docs` —— 会改分类为 `event`，可见性随阶段；收口时 `keep` 类型自动转回 wiki、`trash` 类型送进回收站
- 证据文档（库里既有的背景知识）挂 `refs` —— 零改动
- 顺序铁律：**先挂 docs 再推终态**。已收口事件挂不了文档（`bindMembers` 抛 `EVENT_CLOSED`），旧 skill 的「终态例外」在实现上不可能成立
- 数据源文档（`isImported`）改分类被拒，只能走 `refs`

**新增端点** `GET /open/v1/events`：`?event=#3` 查单个（标题 / 类型 / 阶段可见性 / 终态动作 / 是否收口），不传走列表（status / q / limit）。不受 `uploadApi` 开关影响；事件不存在返回 404 + available（至多 5 条未收口）。

**脚本**：`ki_upload.py` 新增 `events` 子命令；`--event` 时自动预检（`precheck_event`）。存在理由：httpflex 在 POST 4xx 时会丢掉响应体，脚本只能拿到状态码，服务端返回的 available 与具体错误码全丢。

**验证**：单测 64 例（open-api events 12 / ping 18 / upload-lifecycle 17 / multipart 17）；真机 e2e 8 步 —— 建事件挂 docs（bound=1、可见性 hidden）、事后上传挂（members=2）、事件不存在（上传 400 与查询 404 都带 available）、逐阶段推到终态（hidden→fts-only→full，两篇转回 wiki 并解绑）、已收口再传（400 EVENT_CLOSED）；Python 侧 import 真实脚本函数验四条路径。

**边界**：trash 类型收口送回收站未实跑；refs 路径未回归。
