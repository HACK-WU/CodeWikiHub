事件文档的「档位切换」链路有三处静默缺陷，均无报错、页面无感，排查事件文档「明明设成不可检索却还能搜到」时按此清单核对。

① ki-path 永不重建：planTransition 只把 dense/fts/relation 放进 write，path 仅在 to==='hidden' 时有摘除分支，全仓无重建调用 → 事件文档从 hidden 回到 full（解绑 / 流转 / 恢复）后，组级 path 向量永久缺失，按组路径的语义检索再也搜不到该组。

② 页面改分类不摘索引：changeLifecycle 只改字段 + 写分片，未调用 applyVisibility；event-service 的私有 enqueueVisibility 只入队不摘除，绑到 hidden 阶段后旧 dense/FTS 仍在 → ki_search 仍能召回，阶段语义被推翻。

③ pending 只在启动时消费：resumeGovernanceTasks 是唯一消费入口，运行期入队的补索引任务不执行，界面「数秒后生效」的提示为假。

- 位置: `src/lib/visibility-index.ts`（planTransition / applyVisibility）、`src/lib/relation-lifecycle.ts`（changeLifecycle）、`src/lib/events/event-service.ts`（enqueueVisibility）、`src/lib/mcp-http.ts`（resumeGovernanceTasks）
- 修法: planTransition 的 hidden→non-hidden 补 'path'；绑定与改分类统一走 applyVisibility；写操作后 fire-and-forget consumePending，并用 in-flight Map 按 scope 串行
