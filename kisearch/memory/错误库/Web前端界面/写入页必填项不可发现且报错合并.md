【错误库｜写入页必填项不可发现且报错合并】
- 报错原文片段：写入失败 / Group、Relation、Module Info 均不能为空（前端本地校验文案，非后端异常；用户新建 Group=test_tag、Relation=tag_ceshi 均已填仍必现）
- 现象：知识写入页点保存即报上述一句，用户坚信「我都填了，是不是系统坏了」。实际真缺的是正文（Module Info），但该项 440px 视口下位于首屏之外（top=1065 / 视口 900），且界面上无必填标记、按钮旁无阻塞提示；界面标签叫「正文」、报错叫 Module Info、后端字段 module_info，三套术语并存导致无法对照。
- 根因：WritePage 原校验写成 !group || !relation || !markdown 三者合并、任一出错都报同一句，用户只能挨个猜；必填的 markdown 未纳入 saveBlockedReason 的派生判断，点之前零提示；正文卡在窄屏单列布局中排在元数据卡之后，是必填项却在首屏外。次要缺陷：错误块复用 .ki-empty 虚线空态样式，读起来像「没有数据」而非报错。
- 解法：① 校验拆成逐字段并让文案绑定界面标签（请填写正文（Module Info）／请填写文档名称（Relation）），先查界面词再查后端字段名；② missingRelation/missingBody 纳入按钮旁阻塞提示，且 scopeErr 必须排在两者之前；③ 文档名称与正文加 * 标记 + aria-required（星号 aria-hidden，必须同时给控件 aria-required 否则屏幕阅读器听不到）；④ 错误块改正红卡片 + role=alert + 「去填写正文」按钮，点击 scrollIntoView 并 focus（preventScroll 避免与 smooth 打架）；⑤ 想允许 Group 留空时禁止引入空 group 键（会撞分片 split 抛错、persistCacheShape 静默丢弃、分片枚举读不到、路径向量撞 docId、doc/list 的 group= 空值已被全部文档占用、删除预览把整个 scope 当要删的组），改为回退到与 scope 同名的真实组（与 import-path.ts resolveGroupForSource 的根目录口径一致），并在成功提示里回显落点；⑥ 前后端必须同口径：executeSyncRelationLocal / executeBulkSyncRelationLocal 入口同样 rawGroup.trim()==='' ? scope : rawGroup，并走 hint 回显落点（路径补全提示改「；」追加不覆盖，批量整批只提示一次），否则出现页面能存而 CLI/MCP 报错的分叉。
- 验证方式：最小复现脚本照抄用户截图条件（新建 scope + 新建 Group + 同名 relation），正文留空必复现该报错，只补正文即写入成功；Playwright 两套走查 temp/verify-write-required.cjs 在 5173 与 7423 各 30/30、temp/verify-write-narrow-a11y.cjs 11/11；web 单测 487/487（新增 9 例 resolveWriteGroup 落点用例 web/test/write-group.test.mjs）；后端 test/sync-relation.test.ts 8 个 suite 全 ok（新增 3 例留空兜底）；前后端 tsc 0；vite build ✓；落点用 ki group list 核对。两个易踩的坑：其一，窄屏初版错误块 body 是 flex:1 1 auto + min-width:0，360px 下正文列被按钮压到约 100px、一句话折 6 行，而 overflowX 仍为 0，只防溢出的断言全部通过——必须同时量正文列宽度与折行数；其二，改「空 group 不再报错」会让既有测试里拿 group:'   ' 当参数缺失样本的用例由红转绿，须把异常样本换成空白 module_info，不可删掉「单条异常不中断整批」的覆盖。另 @container 规则在无 container-type 的祖先下永不生效，窄屏请用 @media。
