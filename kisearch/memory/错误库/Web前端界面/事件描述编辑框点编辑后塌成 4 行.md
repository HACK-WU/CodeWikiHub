用户点「编辑」后事件描述输入框从整段展开塌成 4 行，近 2000 字的长描述没法看也没法改；改为高度随内容自适应、不缩小。

- 现象: 读态 `.gov-desc-text` 无高度上限、整段展开，编辑态 textarea 只有 `rows={4}`，切换后塌掉约 85%
- 根因: 两个状态的高度来源不一致 —— 读态由内容撑开，编辑态从未做过高度同步（不是样式写错）
- 修法: `EventSummaryCard` 内 `bindDesc` + `syncDescHeight`（先 `height='auto'` 再按 `scrollHeight` 设高，可增可减），ref 回调挂载即校准，`ResizeObserver` 兜底宽度变化，`useLayoutEffect` 跟 `descEdit.draft`
- 坑 1: 全局 `box-sizing: border-box` 下 `scrollHeight` 不含上下边框，直接赋值会少 2px 裁掉最后一行 → 用 `offsetHeight - clientHeight`（此刻只剩边框）补齐
- 坑 2: **高度下限不是 CSS `min-height:76px`**，而是 `rows={4}` 的内在高度（textarea 的 `scrollHeight` 不会小于自身内容盒）—— chromium 实测短描述/空描述都停在 95px，min-height 只在低于 76px 时才生效
- 坑 3: 共用类 `.gov-textarea` 还被新建事件弹窗用（`rows={3}`），不许改；新增 `.gov-textarea--fit` 只挂描述内联编辑
- 取舍: `.gov-textarea--fit { resize:none; line-height:1.6 }` —— 手工拖拽后一打字就被拉回内容高度会像 bug，故关掉；行高对齐读态，进出编辑态逐行不跳
- 位置: `web/src/components/governance/event-detail/EventSummaryCard.tsx`、`web/src/styles/governance.css`
- 实测（chromium headless，960px 宽）: 1179 字读态 246px / 编辑态 248px（仅差 2px 边框），4000 字 805px，`scrollHeight-clientHeight` 恒 0（无内部滚动、不裁行），输入变长 248→306、删短回 95
- 已拍板（2026-11-24，用户）: 「保存 / 取消」**维持框下方不动** —— 用户实测变高不影响保存，394 字框高仅约 114px，只有接近 4000 字才到 805px，不值得为此改布局
- 排障提醒: 若看到编辑框仍带右下角拉伸把手、或短描述被撑得很高，说明是**刷新前的旧页面**（旧 CSS `resize:vertical` + 手工拖高），刷新即恢复；校验方法 `curl <web>/assets/index-*.css | grep -o '\.gov-textarea--fit{[^}]*}'`
- 验证: `web/test/event-desc-edit-grow.test.mjs` 9 例绿；web tsc 0 / build ✓ / 全量单测 11 红与既有基线一致；整页真机走查未做（浏览器内高度由隔离 harness 实测）
