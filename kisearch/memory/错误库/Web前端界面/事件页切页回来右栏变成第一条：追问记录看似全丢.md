事件页（/governance/events）切到别的治理页、再点侧栏回来，右栏换成了列表第一条事件，用户以为「追问记录 / 分析卡整块丢了」。数据从未丢：只是眼睛换到了另一条事件上。
- 现象: 选事件 B 并追问过 → 点侧栏「回收站」→ 点侧栏「事件」→ 右栏是 A（列表第一条），追问区 0 条；同一事件的 `GET /analysis/ask` 仍 200、磁盘 `.ask.json` 有记录
- 根因: 侧栏是 `NavLink to="/governance/events"`（不带 query），而选中态只写在 URL 的 `?event=` 上、组件内不持久化；回到页面时 URL 无 event → 首屏 `setActiveId(prev => prev ?? matchDeepLink(...) ?? list.events[0]?.id)` 回落到列表第一条
- 解法: 新增 `web/src/lib/eventsSelection.ts` 按 scope 把「上次看的事件 id」记进 localStorage（key `ki-web:events:last-event:<scope>`）；首屏选中决策改为 **深链 > 记忆 > 第一条**，记忆里那条解析不到（已删 / 不在当前列表）时仍回落第一条
- 位置: `web/src/lib/eventsSelection.ts`、`web/src/pages/EventsPage.tsx`（`loadList` 的选中、`activeId` 变化写记忆）、`web/test/events-selection.test.mjs`
- 验证: `.debug/ask-gone-on-tab-switch-20261123/`（修复前 STEP3 选中变 `evt_mwn1fx8x…`、追问 0 条；修复后切回与整页刷新均恢复 `evt_mwluc4p4…`、追问 1 条）+ 新增 14 例；web 全量 1444/1432（12 红为既有）
- 排查提示: 这类「记录没了」先比对**右栏是不是同一条事件**，别急着查落盘与接口
- 关联: 决策记录/事件页/列表选中态持久化与状态徽标（坑1 深链兜底）
