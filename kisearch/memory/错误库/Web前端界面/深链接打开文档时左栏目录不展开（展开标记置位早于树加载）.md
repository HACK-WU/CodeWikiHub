打开 /browse 深链接（scope+group+relation）时正文能正常打开，但左栏「知识目录」只把目标 Group 高亮、不展开，当前文档在树里看不见；全新浏览器上下文（无 localStorage 记忆）同样复现。

- 现象: `[role="treeitem"][data-ki-group="<group>"]` 的 aria-expanded 为 false；三种 localStorage 起始态（无记忆 / 记忆选中项=目标 / 记忆选中项=别的组）表现一致，说明不是「尊重用户折叠」的持久化语义
- 根因: `web/src/pages/BrowsePage.tsx` 深链接 effect 在 `/api/doc/list` 返回前就 `setActiveGroup(group)`；「选中项变化 → 展开祖先链 + 自身」那条 effect 此时拿到的是空树，`findGroupNode` 返回 null ⇒ 实际什么都没展开，却已把 `revealedActiveGroupRef` 置成目标值 ⇒ 数据到达后 effect 重跑被 `ref === activeGroup` 闸门挡住，永不补做
- 解法: 目标与树解耦 —— 深链接分支把目标挂进 `pendingRevealGroupRef`（`findGroupNode(tree, group)` 命中则立即 `openGroupPath`，否则挂起），新增一次性 effect 依赖 `tree`，树建好后展开并清空挂起（目标不在树里=脏链接，直接放弃）
- 关键取舍: 深链接应用成功后必须 `markBrowseUrlSelfWritten(directTarget)`，否则补上展开后会让「用户手动折叠过的目录」在刷新时被抢回展开 —— 刷新保持折叠完全靠这条 sessionStorage 标记
- 关联工具: `lib/groupTree.ts::openGroupPath`（reveal 祖先链 + 展开自身，目标缺失返回原引用，供调用方判断「还轮不到我处理」）
- 验证: `.debug/deeplink-tree-not-expanded-20261123/`（6 项真机断言 + 2 例单测：外部深链接/浏览入口/全屏 reader=1 均展开，刷新与数据刷新保持折叠，脏链接不崩）
