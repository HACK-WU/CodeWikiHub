浏览页在视图模式下点「编辑文档」曾显示「加载失败：文档不存在」，移动/删除/添加链接/正文图片同样坏，但**读正文正常**。2026-11-25 已修复（未提交）。

- 现象：`GET /api/doc/edit?scope=<视图名>` → 404 `DOC_NOT_FOUND`；`doc/delete` dryRun → **200 `exists:false`**（假回执）；POST 保存/移动/真删除 → 400 `VIEW_NOT_WRITABLE`。根因：`doc/get` 有视图分支而 `doc/edit` 没有，前端又把视图名当库名——`BrowsePage` 的 `ScopedDocumentView.scope` 是导航值、`member` 才是来源库，`openEditor` 只发 scope。
- 修法：前端 `docScope = member || (读正文回填的 scope) || scope`，统一喂给编辑器（`DocumentEditorRequest.member`）、`ReaderLinkComposer.docScope`、移动/删除弹窗、正文 `assetBase`、只读判定（`useScopeReadonly` / `useViewMemberReadonly` 第二参都必须是成员库）。**`ReaderLinkComposer` 不能整替换 scope**：`useDocSearch(scope)` 要全视图搜目标文档，只换「加载/保存当前这篇」。`docList` 的 queryKey / onSaved invalidate 仍用导航值。
- ⚠️ 坑：回落链必须用 `||` 而非 `??`。`member` 可能来自 URL（`&member=` 空值 → `''`），`??` 只挡 null/undefined，空串会短路整条链 → 请求变成 `scope=` → `resolveScope('')` 回落 `default` 库 → 又变回「文档不存在」/ 预检 `exists:false`。scope 名服务端保证非空，空值一律视为「没给」。
- 后端：`rejectIfScopeView(scope, op, config)`（= `assertNotScopeView` + 400 `VIEW_NOT_WRITABLE`）只补在**绕过写锁的两条读通道**（`doc/edit` GET、`doc/delete` dryRun）。不选「后端展开成员猜库」——既有决策：写端点拿原始库名，猜错库比报错严重。
- 同族补齐（聊天侧）：`SourceRef` 加可选 `scope`（后端 `chat-contract.ts` + `toSourceRefs` 从命中 `hit.scope` 填，缺失时不写该键；前端 `chatContract.ts` 镜像），`ChatPanel.viewing` 带 `member` 并传给 `ModuleDrawer`；不换 `fetcher`（MCP→HTTP 会引入 group 编码不匹配）。老会话无该字段 → 回落聊天 scope，落盘向后兼容。契约测试见 `test/chat/contract-sr01.test.ts`。
- 已知未覆盖：`SearchPage` 抽屉 `viewing` 不带来源库、`fetcher=kiGetModuleInfo` 也不回填 → 视图模式下检索结果打开文档时**正文图片仍 404**（该页抽屉不可编辑，无写路径影响）；`ChatPanel` 同理受「老会话无 scope」限制。
- 坑：daemon 必须真重启（`ki mcp restart`），`kill` 后手起 `mcp --http --daemon` 可能被既有实例接管，用 `ps -o lstart` 核对；健康检查路径是 `/healthz`（不是 `/api/healthz`）。
