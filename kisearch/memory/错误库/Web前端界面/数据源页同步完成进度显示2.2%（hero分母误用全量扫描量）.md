## 现象

数据源页（/datasource/:scope）同步成功后，「执行结果」hero 显示 `完成 48 / 2.2%`，而后台任务页同一任务显示 `完成 48 / 100%`。数据源页 hint 为 `扫描 2226 篇`，指标网格 `全量扫描 2226 / 处理 48`。

## 根因

Git 增量同步时 `files.fullScanned` 是**源目录全量**（2226），`files.scanned` 才是**本轮处理量**（48，恒等式 `completed + incomplete + skipped = scanned`）。

- 任务详情（`web/src/lib/taskDetailModel.ts`）hero 分母取 `files.scanned` → 100%
- 数据源详情（`web/src/lib/dataSourceDetailModel.ts` 的 `summary.scanned`）误取 `fullScanned` → 48/2226 = 2.2%

全量/目录同步时二者相等（目录源快照 scanned == fullScanned），所以只走全量走查发现不了；仅 Git 增量暴露。

## 解法

`buildDataSourceDetail` 的 `summary.scanned` 改为 `result.files.scanned`；`fullScanned` 只留给指标网格「全量扫描」。hero 分段条/百分比（`DetailParts.tsx` 的 `completed / max(1,total)`）自动正确。

## 验证方式

1. 单测：`web/test/data-source-status.test.mjs` 断言增量记录（scanned=3 / fullScanned=241）下 `summary.scanned===3` 且百分比 100%；
2. 浏览器 mock 48/2226 增量记录：hero 100%、hint「扫描 48 篇」、指标仍显示全量扫描 2226；
3. 变异测试：把分母改回 `fullScanned` 重建，同一脚本立刻回落到 2.2%（与用户截图一致），证明断言有效。

## 可复用判据

凡是「进度百分比」，分母必须是**本轮处理量**（`files.scanned`），不是「扫描到的总量」；两者在增量场景下相差一个数量级，且分母错了以后页面会显示一个"看起来像失败"的完成态。
