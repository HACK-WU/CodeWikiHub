【错误库｜窄容器里按钮折行与确认条撑破父容器】
- 报错原文片段：无控制台报错（视觉缺陷）。用户口径原话「对话列表这个确认删除也太大了吧，还有取消按钮也有问题」。截图表征：按钮文字被竖排成两行，胶囊圆角被撑成椭圆，就地二次确认条的浅色背景比所在列表行宽出一截。
- 现象：侧栏等窄容器（实测 260px）里的「删除二次确认」条排版崩坏：确认删除按钮 53×26 且文字折两行、取消按钮 38.5×26 折两行、两者圆角均为 999px 呈椭圆；确认条整体 338×68，比所在列表行（251px）宽出 87px；文案「删除后不可恢复」也被压成两行。
- 根因：三个缺陷叠加。其一，通用按钮类缺契约，没有 white-space nowrap 与 flex none，被 flex 压到 40 至 53px 宽后文字折行，26px 高加 999px 圆角折行后变成椭圆；同一个坑此前已在会话浮层底部打过同款局部补丁，说明是基类缺失。其二，确认条是单行平铺 flex，文案加会话名加两个按钮在 260px 里放不下，flex 默认不是换行而是一起压缩所有 item，文案与按钮同时折行，条高由 32px 涨到 68px。其三最隐蔽：确认条 flex 1 0 100% 缺少 min-width 0，flex item 的自动最小尺寸等于内容 min-content（实测 338px）会盖过 flex-basis 100%，导致确认条比父级行宽出 87px。
- 解法：三件套。第一，按钮基类补 flex none 与 white-space nowrap，并删除同类局部补丁。第二，确认条拆成两块：文案块（提示文案 flex none 加 nowrap，会话名 flex 0 1 auto 加 min-width 0 负责收缩省略）与按钮组块（flex none 加 margin-left auto 靠右），容器 flex-wrap wrap 且必须加 min-width 0；提示文案必须包一层元素，匿名文本节点无法设置 flex none 会被一起压缩。第三，确认条内按钮改 22px 高与 6px 圆角，并把取消按钮放到确认删除左侧（破坏性主操作靠右）。
- 验证方式：量测三类指标而非只看肉眼：按钮文字行数（Range 法的 getClientRects 去重行）、容器自身 scrollWidth 与 clientWidth 之差、以及最容易漏掉的容器宽度减去父级行宽。断言确认条不超父级行宽、按钮均单行且高不超过 24px 圆角不超过 8px、条高不超过 56px、名字单行不越界；并回归同页其它按钮（新建会话 64×26、刷新 44×26、发送 62×30 均单行）。实测修复后两按钮 22px 高、6px 圆角、单行，确认条 227×52，5173 与 7423 各 16 项断言全通过，web 单测 192 项全通过。
