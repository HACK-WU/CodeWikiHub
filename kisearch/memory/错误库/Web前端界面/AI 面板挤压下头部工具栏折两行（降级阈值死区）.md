【错误库｜AI 面板挤压下头部工具栏折两行（降级阈值死区）】
- 报错原文片段：无控制台报错（纯布局缺陷）。用户口径原话「当展开AI对话框后，文档内容变窄，以至于那些按钮没有足够的位置，被挤到了第二行。导致看上去非常的不美观」。可量测特征：阅读区容器落在 620~734px 时，.ki-drawer__head--bar 高度必为 93px（单行应为 55px），且第一行只剩被 flex 拉满的搜索框、第二行右侧孤零零一排动作按钮。
- 现象：知识库浏览页阅读态「一行头部」在 AI 对话面板并排（视口 ≥1400）时阅读区被挤压：1440 档 937→557px、1600 档 1097→717px；三个文字动作（添加链接/编辑文档/复制）与宽度切换整组折到第二行。与面板无关的同一缺陷：1200 视口不开面板、容器 697px 同样折两行（更窄的 1100/597px 反而一行 —— 非单调即阈值失配的特征）。
- 根因：三条叠加。其一，降级触发点 620px 与「平铺一行」真实门槛 734px 之间是一条约 114px 宽的**死区**：既不够平铺、又没触发降级，必然折行。其二，容器查询量的是 .ki-drawer--inline 外框，而真正可排宽度少 24px（头部 padding 8px 12px）⇒ 557 档即使降级也差 12.8px 放不下。其三，「清空」常驻等新增控件把固定开销推高（Tag 112 + 搜索下限 240 + 动作组 341.8 + 间隙），而阈值从未同步重校 —— 这是同类缺陷的复发机制。
- 解法：把「恒为一行」当目标，按实测宽度反推阶梯（阈值 = 实测所需行宽 + 24px 内距）：≤910 隐导航文字标签（带标签 154px vs 仅箭头 64px）；≤740（或 ≤820 且抽屉带 .ki-drawer--has-nav）降级 —— 三文字动作收进 ⋯ 菜单、宽度切换分段收成单按钮（92→48px）、「⤢ 全屏」隐文字收成 32px 图标、搜索下限 240→230；≤620 再收 Tag 上限 112→96。降级一律保留入口（⋯ 菜单 / 单按钮 / 图标），禁止用 display:none 让功能不可达。按「导航组是否存在」分两档可避免 740~820 无导航时的无谓降级。
- 验证方式：Playwright 真机（7423）把 .ki-drawer--inline 的 max-width 当自变量扫 480~1100px 求「1 行↔2 行翻转点」（改前 620↔640 与 560↔580；平铺门槛实测 733.8、带标签 890~899）；导航用真实路径取得（点正文本地链接触发 handleLocalLink）。脚本 temp/verify-browse-bar-ladder.cjs 44/44（死区三档 629/697/717 全部 55px 单行、9 档视口、最紧档 557、有导航、结果列表态置灰、⋯ 菜单复制真生效、全屏态 62.5px 不变）+ 既有 verify-single-row-header.cjs 49/49 + 选区快捷键 32/32 + web 单测 384/384 + tsc/build exit 0。
- 关联方案：无（本次为阈值重校，未沉淀 .solutions/）
