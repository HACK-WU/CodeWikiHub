【错误库｜文本包裹式高亮在多次应用后失效（碎片累积）】

- 报错/现象：文档内查找（Ctrl+F）输入 `context` 显示「未找到「context」」，而正文确有 46 处、上下跳按钮禁用。另一表现：先输 `contex`（命中 46）再补成 `context` 变 0，且**重新输入无法自愈**。用户原话「context 内容命名存在，为什么没有找到」。
- 根因：**「清空」不是「应用」的逆操作**。匹配是逐文本节点做的（TreeWalker + 每节点 exec），而清除只把 `<mark>` 的子节点**原样插回、不合并相邻文本节点** ⇒ 搜过 `contex` 后正文的 `context` 变成 `"contex"` + `"t"` 两个相邻节点，再搜 `context` 两个碎片都匹配不到 ⇒ 0 命中；用户逐字打字（c→co→con→…）会让碎片累积，最终必然踩到。配套缺陷：查找框预填词时未同时恢复高亮开关，若此前点过「取消高亮」也会显示「未找到」。
- 解法：① 清除时记录被 mark 触碰的父节点，清完后逐一 `node.normalize()`（只合并相邻文本、不改元素结构）；② 预填词时同步 `setHighlightEnabled(true)`。
- 验证方式：高保真复现须含「逐字输入」与「先短后长」两条（一次性搜索永远正常）；白盒口径 = 复刻收集规则统计 matchable 与界面命中数比对；断言「命中数 === DOM 标记数」而非仅「有命中」。
- **关联方案**：`.solutions/frontend/text-fragment-breaks-highlight-match/`（含白盒排查口径、`normalize` 副作用边界、异步渲染丢标记的复扫兜底）
