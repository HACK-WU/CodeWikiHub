在已有阶段之间插入新阶段时，若所有待插项都按同一个固定锚点（如「插到待处理之后」）处理，**部分已迁移**的状态下顺序会错。2026-11-23 技术债两阶段→四阶段迁移实测：库里已有「已排期」只缺「偿还中」时，按「待处理之后」插入得到 `待处理 / 偿还中 / 已排期 / 已收敛`。

- 正确做法: 每个待插阶段声明**前驱名**（`after`），逐个 `findIndex(after) + 1` 后 splice；前驱本身是刚插进去的也能正确排在它后面。
- 幂等键用**阶段名**而非 revision / 执行次数：部分被手工改过的库也能收敛到目标状态。
- 位置: `src/lib/events/migrate-tech-debt.ts`（`INSERT_STAGES` 的 `after` 字段与 splice 循环）
- 测试形状: 必须覆盖「只缺中间某一条」的半迁移用例 —— 只测完整迁移（缺两条）发现不了这个错序，因为两条都从同一起点插时顺序恰好正确。
- 附带: 写盘前备份 `_types.json.bak`，备份失败即中止；新阶段不带 key，由服务端分配 `st_N`，因此 key 与位置不同序属正常。
