事件文档的「档位切换」链路上有四类静默缺陷，均无报错、页面无感，排查「设成不可检索却还能搜到 / 解绑后搜不到」时按此清单核对；前三条已于 2026-11-16 随 REQ-20261116-004 修复。

① ki-path 永不重建（已修）：planTransition 只把 dense/fts/relation 放进 write，path 仅在 to==='hidden' 时有摘除分支，全仓无重建调用 → 事件文档从 hidden 回到 full（解绑 / 恢复 / rebuild）后组级 path 向量永久缺失。修法：planTransition 的 hidden→non-hidden 补 'path'。注意 transitionEvent 走的是私有 enqueueVisibility（kinds 本就含 path），不经过 planTransition。

② 页面改分类不摘索引（已修）：changeLifecycle 原来只改字段 + 写分片，未调 applyVisibility；event-service 的私有 enqueueVisibility 只入队不摘除，绑到 hidden 阶段后旧 dense/FTS 仍在 → ki_search 仍能召回。修法：changeLifecycle 与绑定路径统一走 applyVisibility / applyVisibilityBatch（from 必须在改字段前算）。

③ pending 只在启动时消费（已修）：resumeGovernanceTasks 是唯一消费入口，运行期入队的补索引任务不执行，界面「数秒后生效」为假。修法：写操作后 fire-and-forget scheduleConsume，并用 in-flight Map 按 scope 串行。

④ 内置类型未落盘时档位误判 full（已修）：visibility-index 的 buildLookups 用 readEventTypes（只读 _types.json），文件不存在时返回空数组 → 用内置类型 et_1/et_2/et_3 的新 scope 把事件文档一律当 full；解绑还因 from===to 短路而不补索引。修法：buildLookups 改用 listTypes（含内置回退）。
