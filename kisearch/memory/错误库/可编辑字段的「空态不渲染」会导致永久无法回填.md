带编辑入口的可选字段，「无值就整块不渲染」看似干净，实际会把唯一入口一起隐藏 —— 2026-11-23 事件类型描述真机走查实测：清空描述后 `.gov-typedesc` 整行消失，页面上再没有任何描述相关按钮，用户无法把它加回来（新建时没写描述也一样）。

- 症状: 清空后 count=0、搜索「编辑描述」「添加描述」均 0 命中；功能不报错，只是永久缺失入口。
- 根因: 渲染条件把「控件」和「内容」捆在同一个分支里（`hasValue ? 渲染文本+按钮 : 不渲染`），内容为空时控件随之消失。
- 正确形状（三态）：有值 → 文本 + 编辑按钮；无值 → 轻量「＋ 添加」入口（不占空行，但必须有按钮）；编辑态 → 输入 + 保存/取消。
- 同类风险面: 任何「有值才显示」的行内编辑（别名、备注、标签行）；判断标准是问一句「清空后用户还能再填吗」。
- 位置: `web/src/pages/EventsPage.tsx`（类型描述行 `gov-typedesc` / `gov-typedesc--empty`）、`web/src/styles/governance.css`
- 验证: 走查必测「清空 → 确认入口仍在 → 重新填入 → 值回来」，只测写入与清空会漏掉这一环。
