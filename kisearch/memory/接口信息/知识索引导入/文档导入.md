【接口信息｜文档导入 CLI】
- 子功能：文档导入
- 所属模块：知识索引导入
- 接口列表：
  - CLI ki import → handleDirectImport @ src/lib/import.ts：把目录或单文件 Markdown 幂等导入知识库。参数：--source <dir|file>（必填）、--scope 目标知识库、--group 指定落点、--tags 自定义标签、--chunk-size/--chunk-overlap 切分、--no-vector 仅写 KB 层、--no-clean 关全部清洗、--clean-rules 覆盖内置规则、--no-assets 关本地图片附件收集
  - 返回 ImportResult：{ok, action:'import', scope, stats:{total, vectorized, errors, skipped, vector, assets}, errors, groups, source}；stats.assets = 已落盘的唯一附件文件数（同一附件被多篇 md 引用只计一次）；source = {dir, chunkSize?, chunkOverlap?}

【命令形态变更 · breaking · 2026-09-07】
- 原 `ki scan-kb import` 已**扁平化为 `ki import`**：scan-kb 壳移除、**不保留兼容别名**。旧调用 `ki scan-kb ...` → 「错误：未知命令 "scan-kb"」+ 19 个可用命令清单 + 退出码 1。
- 源文件同步重命名：`src/scan-kb.ts` → `src/import.ts`（`npm run import` / `test:e2e:import` 亦改名）。
- 现为**扁平命令、无子命令层级**：多传位置参数被 commander 拒为 `too many arguments`；必填项检查先于多余参数检查，缺 --source 时优先报 `required option '--source <sourceDir>' not specified`。
- 扁平化根因：bin/ki.mjs 的 COMMANDS 是单级映射且 scriptArgs 会剥掉子命令名，与 commander 嵌套子命令不兼容（实测直传 --source 报 unknown option），故仅在映射表加一行不可行。

【已订正的历史误记】
- **无 `--dry-run` 选项**：此前记忆记载「--dry-run 试运行」，实测 `ki import -h` 与 src/ 全域均无此选项，属假陈述，已删除。
- 更早移除（2026-08-14，commit fce0b57）：`--mode full|incremental`、`diff` 子命令、`--root-name`、source.commit、git 依赖。增量更新由「重跑同一条 ki import」的幂等追加语义承载；--source 不要求是 git 仓库。
