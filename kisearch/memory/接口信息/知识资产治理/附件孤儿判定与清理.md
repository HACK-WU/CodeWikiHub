附件（图片）孤儿的判定与清理在 2026-11-26 落地（#102）：删文档不让图永久残留，但**默认不删图**，只报告 + 提供显式清理入口；跨 group 移动时图片跟着走。
- 判据: 本 group 内「所有文档正文的图片引用」与「assets 实际文件」的差集。**不引入引用计数表** —— 计数要在 import/doc-edit/move/delete/restore/prune/purge 七处维护，漏一处即误删（不可逆）；而删除时整组 index.json 已在内存，扫一遍是毫秒级
- 跨 group 引用不成立: 导入侧落点校验拒 `..` 越界、读侧 `normalizeImageRef` 拒 traversal ⇒ 图片物理上只属一个 group
- 四个入口: ① `DeleteResult.assetsOrphan`（回执只报告）；② 回收站按引用复制（`writeTrashItem` 的 `assetRels`）；③ `ki assets gc`（默认 dry-run）；④ `doc-move` 跨组搬图（`assets{copied,shared,removedFromSource}`）
- 移动的顺序约束: 先复制到目标组 → 写新位置 → 清旧位置 → **最后**才删原组「已无其它引用」的图；失败回滚只删本次新建的（`copyAssetFiles.created`），共享图始终留原组
- 同名不同内容: 目标组已有同 rel 但内容不同的图时**不覆盖**，保留目标那份 + warning（静默覆盖会换掉目标组其它文档的图）
- 归一化坑: 比对 key 必须与落盘一致 —— `decodeURIComponent` + posix normalize；`./assets/x.svg` 落盘是双层 `assets/assets/x.svg`
- 恢复自洽: gc 删掉的图，恢复文档时从回收站副本回填（真机验证过）
