2026-11-19 删除「AI 查找」旧执行器 runDeepFind（find-runner 里那份约 650 行的循环）时，把仍在对外契约里的能力显式搬去新路径，避免「删函数连能力一起删」。
- 门禁 4 路（FIND_LLM_UNAVAILABLE / FIND_DISCLOSURE_REQUIRED / FIND_TOOLS_UNSUPPORTED / FIND_TOOLS_ALL_DISABLED）：搬到 src/lib/events/find-service.ts 的 runDeepFindSharedCore 开头（取并发槽之前）。
- 45s 硬超时（FIND_TIMEOUT 504 / FIND_CANCELED 499）：同一处，AbortController 合成「前端断开 signal + 硬超时 timer」，`timedOut` 标记区分终态；常量 FIND_HARD_TIMEOUT_MS 从 find-runner 导出。
- 检索模式聚合：run-recall 的 GroundedToolOutcome 新增 searchMode（tool-runner 用 executeSearch 的**实际** mode 回填），内核聚合后经 GroundedResult.mode 透出；deep-find-core 不再硬编码 hybrid（这正是失败用例 ⑤b 的真因，不是断言过期）。
- 顺带修掉新路径两处漏项：`find.tools` 四开关没传进内核（硬编码全开，与事件 #43 同类）、视图成员库未展开导致视图成员候选被判 out-of-scope。
- 测试口径：find-runner.test.ts 全部改走生产入口 runDeepFindAsSearchResult；共享内核的输出契约是 JSON 对象 {summary,candidates:[{scope,group,name,why}]}，不是数组、字段也不是 sourceScope/reason。
- 已知边界：tool-runner 对越界 scope 是「回落到 targets[0]」而不是回一条纠错给模型（旧实现会回错），这条目前无测试覆盖。
