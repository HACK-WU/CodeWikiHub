REQ-20261123-005 策略拍板 C+A：MCP 仍只删空组、CLI 非空组删除也入站、MCP 空组同样入站、清库/删 scope 保持物理删除。
- 硬约束: 组快照**不能**复用 `moveToTrash`（正文空即 `TRASH_CONTENT_MISSING` fail-closed，trash-service.ts:73-79）
- 组条目布局: `.trash/{被删组路径}/__group__<stamp>/` = meta.json + assets.json + assets/<序号>/ + docs/NNNN/{doc.json,content.md}。**附件必须按 group 存一份** —— `getAssetsDir` 是 group 级共享目录（scope.ts:128-131），按篇复制会 N 倍膨胀，写满盘后 fail-closed 会让所有删除失效
- 篇目集合必须取 **relations 分片键 ∪ KB index.json 键的并集**：真正删数据的是 `fs.rmSync(kbGroupDir)`（group-delete.ts:700），只看分片会让 KB 独有正文永久消失且回收站无痕迹；按 `source: both/shard-only/kb-only` 三档恢复
- 不可回滚区: 窗口 1（删 relations 分片，group-delete.ts:673-690）成功后列表已消失，此后任何失败**绝不回滚快照**；仅窗口 1 之前/本身失败才回滚
- 恢复顺序: 先 `ensureGroupPathInTree` 建树 → 逐篇写 KB/元数据 → 逐 group 复制附件 → `enqueueRebuild` 整组一次读改写 → 成功即收缩 docs/，docCount 归 0 才删条目；目标组空节点允许合并、非空拒绝
- 其他: `TrashItem.kind`（存量缺省 doc）、reason 不新增值、counts 口径=条目数（组算 1）、sizeBytes 写入时累加不递归、`PurgeOutcome` 加 kind/docCount、restore 端点必须补 `withScopeWriteLock`
- 备选/否决: 独立 `.trash/_groups/` 根、按篇复制附件、`<子组>__<文档名>` 命名、`reason='group-deleted'`、回收站加「分组」筛选段（与 reason 维度计数重叠）
