事件页「追问这次分析」改成可续接：服务端把进行中的那一轮落盘成运行态，前端回来按它渲染并轮询到落库，切页 / 刷新不再丢那一轮（#82）。
- 为什么: 追问是单次 HTTP 上的 SSE 流，进行中只活在前端组件内存（pending/steps），服务端只在整轮结束才 `appendAskTurn`；客户端断开服务端**不中止**（不监听 close），但用户回来那次 `load` 早于完成、且不会自动补 —— 看着就是“整轮消失”
- 存储: `.events/{eventId}.ask.running.json`（AnalysisAskRunning：id / question / runId / startedAt / updatedAt / answer / steps）；首写**同步**（切页立刻能看到），后续 **800ms 节流**，`finally` 删除；15 分钟无更新视为僵尸（进程被杀）读时清理；`stop()` 按 `id` 只删自己那条（同事件并发两轮不误删）
- 接口: `GET /analysis/ask` 增 `running: AnalysisAskRunningDto | null`；契约 DTO 两处同步（`src/lib/governance-contract.ts` / `web/src/api/governanceContract.ts`）
- 前端: `AskBlock` 挂载读 `running`，`runId` 与当前草稿不一致则不接（分析被重跑）；有运行态每 **2s** 轮询到 `running=null`；接续占位展示问题 + 过程 + 半截答案，期间禁用发送与清空；接续占位与本地 `pending` 互斥（都渲染会重复一遍）
- 位置: `src/lib/events/analysis-ask-store.ts`、`src/lib/events/analysis-ask-runner.ts`、`src/lib/governance-http.ts`、`web/src/components/governance/event-detail/AskBlock.tsx`
- 验证: `test/events/analysis-ask-running.test.ts` 6 例（首写 / 中途步骤 / 成功删除 / 失败删除 / 僵尸 / 并发不误删）+ `web/test/ask-resume.test.mjs` 12 例；真机切页回来出现接续占位（已走 7 步、按钮「追答中…」），完成后 turns 1→2 且占位消失；刷新场景接续、删运行态 4s 内自动收起。证据 `.debug/ask-gone-on-tab-switch-20261123/`
- 边界: 运行态单文件只能表示一轮（后写覆盖前写）；`running.answer` 是节流快照，最终正文仍以落库的 turn 为准
