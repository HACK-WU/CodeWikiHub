侧栏「事件」在任何动态时亮一个无文字无数字的红点（2026-11-25 用户需求，已实施未提交）。

- 判据：① 有 ready/partial/failed 的分析结论且该 runId 未被点开过；② counts 的 eventsMaxUpdatedAt 晚于本机已读水位。任一成立即亮；cancelled 不计。
- 后端：`/api/governance/counts` 新增 `eventsMaxUpdatedAt`（单库取本库、视图取各成员 max，共用 `maxUpdatedAt()`）；与 `eventsOpen` 复用同一批 `readAllEvents`，零额外 IO。**视图必须 max** —— 求和后无法与时间点比较，红点永不灭。
- 前端：新增 `web/src/lib/eventsNotice.ts`，把 `SEEN_ANALYSIS_KEY` 从 EventsPage 上移（两处必须共用，否则「列表徽标已消、侧栏还亮」）+ 新增 `ki-web:events-seen-at`（scope → 水位，只增不减）；`hasEventNotice()` 为纯函数。
- 水位推进放在 `EventsPage.loadList` 成功后（不是侧栏）：一次覆盖进页面清积压、自己的写操作（统一走 `run(fn)` → 成功后必 loadList）、手动刷新；停留期间别人 / AI 的改动不触发 loadList → 红点不被静默吞掉。
- 事件页内不渲染红点（列表行内徽标才是精确提示，侧栏点了没反应 = 死角）。
- 无水位时用**挂载时刻**兜底而非 0，否则首次打开 / 换浏览器会把全部历史当新动态。
- 颜色 `--ki-color-danger`（primary 已被 `.ki-nav-item__busy`「生成中」占用）；窄轨 ≤959px 必须覆盖 `margin-right:-5px`，否则压到计数上。
- 坑：HTTP `DELETE` 事件**不透传** `force`/`confirmTitle`（仅 MCP 工具支持），清理未收口事件必须先 `POST /stage` 到终态。
- 验证：`web/test/events-notice.test.mjs` 20 例、`test/governance-view.test.ts` 16 例、真机 1440 / 900 窄轨 / 暗色（截图 `.debug/sidebar-event-notice-20261125/`）。
