事件类型从「内置只在磁盘文件缺失时生效」改为「读时并集 + 按 name 认领」，2026-11-23 落地。四条口径决定实现形状，改任一条都会静默改变可见性判定。

- 读时不写盘: `listTypes` 返回内存并集，认领结果只活在视图里；转正由下一次任意写操作经 `persist` 落盘（保持「读路径不建目录」这条老约束）。
- 同名即认领: 按 name 命中就只补 `builtin: true`，name/stages/terminalAction 全用盘上值 —— 否则用户对内置调过的阶段与可见性会在每次读时被代码常量打回。
- id 被占就改分配: 内置 id 已被不同名类型占用时，分配 `et_${max+1}` 追加，绝不顶替（顶替会把「线上事故」改名成「技术债」，事件绑定全乱）。
- 描述是唯一破例: 盘上无 `description` 时补内置默认，因为该字段比库晚出生，不补则存量库永远看不到说明。副作用是有意的：清空内置描述 = 恢复默认，自定义类型不受影响。
- 删除守卫只看 `builtin` 字段: 旧固定 id 名单 `BUILTIN_EVENT_TYPE_IDS` 已删，它会把任何库里恰占同 id 的自定义类型误判为不可删。
- 迁移与补齐的目标源不同: 补齐读盘上并集（`listTypes`），迁移只认盘上记录（`readEventTypes`）—— 混用会让「库里没有该类型」永远不可达，误报「已迁移」。
- 位置: `src/lib/events/type-service.ts`（mergeBuiltinTypes / listTypes / deleteType）、`src/lib/events/refs-service.ts`（统一走 listTypes，消除与 visibility-index 的双源）
