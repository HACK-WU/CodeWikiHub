事件列表「刷新」除重取列表与详情，还要把右栏里**子组件自持副本**的部分一起刷（2026-11-24 用户要求）。
- 位置: `web/src/pages/EventsPage.tsx`（refreshList / detailReload / loadDetail / findSummary effect）、`event-detail/EventAnalysisCard.tsx`（reloadSignal 透传）、`event-detail/AskBlock.tsx`、`components/governance/AiAnalyzePanel.tsx`
- 根因（playwright 拦截响应实测）: 刷新早已调 `loadDetail`，详情 props 确实换新（卡头 chip 会变），但追问记录（挂载时读一次）与 AI 分析面板（draft/confirmed 是挂载拷贝）不跟 → 「卡头已是失败、过程区还写外部上传 · 无分析过程」。
- 做法: ① `detailReload` 计数器在 refreshList 递增，经卡片传给 `AskBlock` 重读 `/analysis/ask`（流式中跳过）；AI 查找结论把它列进 effect 依赖。② `AiAnalyzePanel` 改用**引用比对** props.analysis —— 信号递增是同步消费一次的，而新详情异步到达，一次性信号正好漏掉最该刷的那次。
- auto-review + challenger 补的两道护栏: ③ `picked` 只在候选 id 序列变化时重置（无条件重置会把用户手点掉的候选勾回，接着点「确认」提交他没选的位置）；④ `loadDetail` 换事件且 refs 读失败时清空 refs（否则「B 的详情 + A 的参考文档」），refs 失败仍先更新详情并报错，两条 state 同批写避免跨事件串数据。
- 验证: 7 支 playwright 探针（route 改写详情/ask/refs 响应）覆盖刷新同步、勾选保持、跨事件不串、refs 失败仍更新；web tsc 0 / build ✓ / 全量 11 红同基线。
