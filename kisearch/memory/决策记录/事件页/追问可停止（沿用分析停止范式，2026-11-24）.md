事件详情「追问这次分析」支持用户主动停止，与分析侧「停止」同构；关键是停止要**同时改收口语义**，否则一次 abort 会把「我主动停的」显示成「追问失败」。

- 为什么原本停不了：`controller` 只活在 `askEventAnalysis` 局部作用域（上游流式与 fs 沙箱共用它的 signal），外部拿不到；SSE 也不监听 close（断开不中止，这是 #82 接续的前提）。
- 后端：`activeAsks` 从 `{startedAt}` 扩为 `{startedAt, controller, canceledByUser?}`（与分析 `activeRuns` 同构）；新增 `cancelEventAsk(scope,eventId)`（幂等，未运行返回 false）；路由 `POST /governance/events/:id/analysis/ask/cancel`，权限登记 `knowledge.ask`（能发起就能收回；分析停止要 write 是因为发起分析本身要 write，追问发起只要 ask → viewer 能停）。漏登记即 404。
- 收口三选一：有正文 → 正常落库成 turn（同分析 partial「保留已完成部分」）；无正文 → 抛 `ANALYSIS_ASK_CANCELED`（1627 / HTTP 499，对齐 FIND_CANCELED）；停止时**跳过结论补丁提取**（用户刚喊停，再弹「要不要覆盖结论」是拿没看完的半截当真凭据）。
- **不记 `finishedAsks`**：主动停止是用户自己刚做的动作，记 failed 会在事件列表打「追问失败」把他引向排查（同分析侧「不复用 failed」的理由）。契约零改动。
- 每轮开头查 `controller.signal.aborted` 直接 break，停止不必等下一轮上游调用。
- 前端 `AskBlock`：运行中（`asking` 本地流式 / `remote` 接续）把「发送」**整颗换成**「停止」（`gov-btn--danger-ghost`，与分析卡同款）；`stopping` 解锁条件是 `!asking && !remote`（服务端可能还在工具段收尾，早解锁会让两轮同时写同一份运行态文件）；CANCELED 分支**必须挡在「回退普通 POST」之前**（那条兜底会重新发一次完整追问＝把刚停的一轮又跑一遍，用户看不见但真烧钱）；停止用 `gov-hint` 中性提示，不回填输入框。
- 位置：`src/lib/events/analysis-ask-runner.ts`、`src/lib/governance-http.ts`、`src/lib/auth/route-permissions.ts`、`src/lib/governance-errors.ts`、`web/src/api/governanceApi.ts`、`web/src/components/governance/event-detail/AskBlock.tsx`。
- 验证：`test/events/analysis-ask-cancel.test.ts` 4 例（有内容落库不记徽标 / 无内容抛 CANCELED / 幂等 / 停止后不再发起下一轮）、`test/governance-ask-cancel-route.test.ts` 2 例（幂等 200、404）、`web/test/ask-cancel.test.mjs` 11 例；两端 tsc 0、web build ✓、web 全量 1503/11 红（与基线一致）。
- 坑：jiti 跑 TS 测试时，测试入口与 `governance-http` 内部 import 会拿到**两份 `analysis-ask-runner` 实例**（两份 activeAsks），所以路由测试里「运行中 → canceled:true」恒为 false（activeIds 里确实有）——该串联放在 runner 测试内验证，别为此造 mock LLM。
