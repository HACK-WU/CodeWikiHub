事件类型「技术债」从用户自建改为内置，卡点不在加一条常量，而在「内置定义只在 `_types.json` 缺失时生效」这条读路径语义；2026-11-23 评审确认必须先补「内置补齐 / 认领」才能上线，否则已有 scope 完全看不到新内置类型。同日用户拍板四条处置口径，方案定稿。

- 读路径: `listTypes` 在 `_types.json` 存在时整份返回文件内容、内置仅作缺省；首次任意写操作把含内置的完整快照落盘，此后改 `builtin-types.ts` 对已落盘 scope 无效。
- 位置: `src/lib/events/type-service.ts`（listTypes / persist / nextTypeId）、`src/lib/events/builtin-types.ts`
- id 冲突: `nextTypeId` 取 `et_${max+1}`。实测 `kisearch-memory` 的自建技术债正是 `et_4`（内置三条 + 自建一条）。内置若也用 `et_4`，补齐必须按 name 认领同名条目并把 `builtin` 置 true，否则出现两条同名 tab —— `createType` 的 `TYPE_IN_USE` 查重不覆盖内置路径。
- 守卫不对称: `deleteType` 有 `TYPE_BUILTIN` 拦截，`updateType` 无任何 builtin 检查且改名不查重（仅创建时查）→ 内置可被改名、可产生同名类型。已另报事件 #77。
- 无回归项: AI 分析视角 `BUILTIN_TYPE_VIEW` 按 id 映射，`et_4` 不加映射即落 generic，与自建类型现状一致，内置化不必动视角表。
- 实测现状: `kisearch-memory` 技术债 = `[待处理 hidden, 已收敛 full]` + `terminalAction: keep` + `fallbackDays: 90`，首阶段已按内置口径设 hidden，与三条内置同构；仅缺「排期 / 偿还中」中间态。

**2026-11-23 拍板口径**：① 补齐按 name 认领同名并保留 `et_4`（不新分配 id）；② 内置 id 锁 `et_4`；③ 内置技术债阶段定为 4 段（待处理 hidden → 已排期 fts-only → 偿还中 fts-only → 已收敛 full），存量 scope 做一次性中间插入迁移；④ 内置类型名不锁、描述可恢复默认；⑤ 类型描述上限 200 字；⑥「认账不修」独立终态本期不做，用末位命名 + 描述兜住。界面侧已确认：描述行置于类型 tab 条正下方、行尾 ✎ 就地编辑、无描述不渲染、新建弹窗的描述输入在名称之后阶段之前。
