事件页（/governance/events）列表的交互约定：选中态以 URL 为主真源 + localStorage 兜底、深链兜底只判一次、行状态浮标单槽位按优先级互斥显示。
- 位置: `web/src/pages/EventsPage.tsx`（`selectEvent` / `entryDeepLink` / `deepLinkWarned` / `loadList` / 行浮标）、`web/src/lib/eventsSelection.ts`、`web/src/styles/governance.css`（`.gov-ev__running`）
- 选中态（两层真源，2026-11-23 补）: 点选走唯一入口 `selectEvent(id)` 并写入 `?event=`（`replace: true` 不堆历史）；**URL 里没有 event 时**（典型是从侧栏去别的治理页再回来 —— 侧栏链接不带 query）按 scope 从 localStorage 恢复上次看的那条（key `ki-web:events:last-event:<scope>`），优先级 = 深链 > 记忆 > 列表第一条。旧版只靠 URL，切页回来会跳到第一条，看着像追问记录 / 分析卡丢了（坑5）
- 行浮标（2026-11-23）: 同一槽位（**绝对定位标题右侧**，`.gov-ev--running` 建定位上下文 + 标题 `padding-right: 76px` 让位）按优先级显示 **追问中 > 分析中 > 追问完成/失败 > 分析完成/失败**；四者互斥（追问要求分析不在跑），禁止叠加两个浮标。数据同源于 `GET /governance/events/running` 一次 4s 轮询：`ids`（分析中）/ `finished`（分析结束）/ `asking`（追问中）/ `finishedAsks`（追问结束），全部是**进程内 Map**（无磁盘 IO，重启即空 —— 少个提示但不会显示错状态）
- 已读口径（两类必须分开存）: 分析用 `runId`（`ki-web:analysis-seen`）、追问用 `turnId`（`ki-web:events:seen-ask`，失败无 turn → 用 `failed:<at>`）；**不能合进一个 Map**，同一 eventId 只能存一个值会互相覆盖。点开事件即记已读，徽标随即消失
- 坑1（会误报，2026-11-19 真机）: 深链兜底要「值只读一次」+「**判定只做一次**」两条都满足。旧实现只读值、判定仍随 `events`/`status` 重跑：切到排除该事件的筛选就误报「可能已被删除」；切「未收口」还会被兜底 `setStatus('all')` 弹回，而同一帧 `events` 是旧列表，紧跟着就弹误报。现为判完即置 `deepLinkWarned`（找到也置），兜底不再改筛选
- 坑2（性能）: `matchDeepLink` 必须稳定，否则进 `loadList` 依赖数组，每次点选都重拉列表
- 坑3（跨库）: 事件 id 是库内 id；换库要 `selectEvent(null)` 并置 `deepLinkWarned`，否则把「不在本库」误报成「已被删除」；文案已写「可能已被删除，或不在当前知识库 X 中」。选中记忆、追问标记都按 scope 分 key / 按成员库合并，切库不串
- 坑4（样式）: 状态类信息别做成「描边 + 内边距 + 圆角」chip —— 用户会当按钮。用圆点 + 文字，当前阶段主色、已收口弱色
- 坑5（2026-11-23）: 侧栏 `NavLink` 不带 query，所以「点侧栏回事件页」= 整页重挂 + 无 `?event=`。没有记忆兜底时会回落第一条，右栏换成另一条事件；排查「追问记录没了」先确认右栏是不是同一条
- 坑6（2026-11-23）: 正在看的那条事件一旦有追问结束，`activeId` effect 会立刻记为已读 → 「追问完成」浮标看不到（符合设计：结果就在眼前）；要验证完成徽标得先切到列表另一条事件
- 默认值: 状态筛选默认 `all` —— 页头写着「已收口 N」却一条看不到会被当成事件丢了
