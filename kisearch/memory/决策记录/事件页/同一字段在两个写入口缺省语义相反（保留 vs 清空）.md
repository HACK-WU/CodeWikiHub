`dataFlow`（数据链路）在**两个写入口的缺省语义相反**，改任一侧前先看这条 —— 反直觉，极易搞反：

| 入口 | 不传的含义 | 为什么 |
|---|---|---|
| 追问补丁（`analysis-ask-patch`） | **保留旧值** | 追问是沿当前结论继续，大多数轮次不想动链路；清空会让用户每问一次就丢链路 |
| MCP 外部上传（`ki_event_edit action=analysis`，overwrite） | **清空** | 整篇覆盖语义；“保留”会让外部 AI 永远删不掉一条错链路 |

- 实现：补丁侧 `...(p.patch.dataFlow ? {...} : {})` + PATCH 白名单 `has('dataFlow')`（在场才写，null 表示显式清空）；上传侧 `analysis-store.ts` 草稿重建条件展开（不带键）。
- **校验强度也不同**：PATCH 宽松归一（截断 + 提示行，不报错），外部上传严格报错（>40 行 / >3000 字 → `ANALYSIS_EDIT_INVALID`，不截断）—— 前者来源是模型，超一行就整份拒绝会让补丁频繁失效；后者是可对话调用方，报错能被纠正。
