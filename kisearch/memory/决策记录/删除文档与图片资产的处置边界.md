删除文档（进回收站）不会删除文中图片；图片只有在整组删除时才真正消失。核对源码（2026-11-26）后的边界如下。
- 单篇删除: `delete-relation.ts` 全文无 assets 字样，只做三件事 —— 移除关系分片条目、`delete kb[relation]` 写回 `{group}/index.json`、`unlink` wiki 源 `.md`（硬删）。group 级 `assets/` 原样保留
- 存储形态: `getAssetsDir(scope, group)` = `{kbDir}/{scope}/{group}/assets`（scope.ts:128-131），**group 级共享**，图片以 md 相对路径引用（`asset-path.ts`），不是按篇存、也不是 ref 字段
- 进站副作用: `moveToTrash` 传 `assetsDir: getAssetsDir(scope, group)`（trash-service.ts:101）→ `writeTrashItem` 对整个目录 `fs.cpSync` 到条目（trash-store.ts:250-254，复制非移动）。所以回收站预览仍能看到图（`/api/asset?trash=<dirName>`），但条目录占用 = 同组图片总量
- 恢复: 把条目内副本 `cpSync` 合并回 group assets（trash-service.ts:335-337），通常幂等覆盖；因原件从未被删，恢复不会破图
- 孤儿: 单删后该篇独占图片留在 `assets/` 且**无引用计数 / 孤儿 GC / 清理命令**（对 orphan|gc|cleanup|refcount 检索仅命中向量与 FTS，assets 语境 0 命中）
- 整组删除才是连带删除: `fs.rmSync(kbGroupDir, {recursive:true})` 删整个 group 目录含 assets（group-delete.ts:813-824），但删前已按 group 复制快照入站（`assets/<序号>/` + assets.json）
- 默认值: `wikiDelete !== false` 才进站；数据源 prune 的 `wikiDelete=false` 既不进站也照样不碰 assets
