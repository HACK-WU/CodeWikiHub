发现过时或描述错误的文档必须当场修正或删除，不许只在对话里提一句就翻篇；判据与处理顺序写进 agents-md-init §2.8，随 AGENTS.md 第二原则生效。
- 生效前提: 第二原则须含「文档健康行」，老项目要重跑增量更新，否则只活在 skill 里、运行期无人提醒
- 判据: 与代码/现网不符、与现行决策冲突、自相矛盾或重复、彻底失效、结构错位
- 先改后删: 局部偏差走 ki_edit_relation；整篇过期走 ki_sync_relation 覆盖（写前 ki_get_module_info）；只几段失效不必删，改那几段或首行标「⚠️ 已废弃，见 X」
- 删的条件（三条齐）: 已读全文、无独有信息、不断链（先 ki_event_list + ki_event_get 查事件 docs/refs 挂载，再查别处正文引用）；ki_delete_relation 进回收站可恢复、恢复后索引重建数秒；有未收口 ki_edit_relation 草稿会被拒，先 cancel/finish
- 历史与失效的分界: 被推翻的判断按 §5 改正文并留「原判断 X，因 Y 改为 Z」；同一主题被新版取代时删旧版或两处互标「已被 X 取代」，同一仓内保持一致
- 删后: 按 §2.3 重刷项目记忆索引（`文档` 组折叠篇数与篇名会变），收尾汇报写清删了什么、为什么
- 边界: ${scope} 代码知识库未授权不删；跨模块取舍或删了要别人知情的走 event-report；禁忌 39 例外 = 已上报事件或属别人负责范围，收尾 ③ 写明未动原因
- 落点: skill 功能列表 / §2.1 ⑩ / §2.2 ⑦ / §2.7 自查 / §8 禁忌 39·40；AGENTS-template.md 第二原则含 bullet；用户级副本已同步
