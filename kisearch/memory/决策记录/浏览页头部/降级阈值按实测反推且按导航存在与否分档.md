【决策记录｜降级阈值按实测反推且按导航存在与否分档】
- 决策：浏览页一行头部的窄容器降级阈值不写拍脑袋整数，一律按「实测所需行宽 + 头部左右内距 24px」反推（≤910 标签档 / ≤820 带导航降级档 / ≤740 无导航降级档 / ≤620 Tag 档）；「导航组是否出现」这个容器查询看不见的变量，由 JS 在抽屉根节点下发 .ki-drawer--has-nav 告知 CSS。
- 被否决方案 A：一刀切 ≤820 降级。理由：容器 740~820 在无导航时平铺放得下（典型 1280 视口展开左栏目录 = 777px，改前本就是一行平铺），一刀切会让这些档位白丢三个文字动作 —— challenger 质疑成立后拆成两档。
- 被否决方案 B：沿用 PM 报告给的 ≈740。理由：导航组占 64px 时平铺门槛升到 805.8，740 会让「有导航史的用户」在 740~806 仍折两行 —— 同一个 bug 换个入口复现。
- 被否决方案 C：最紧档把「⤢ 全屏」收进 ⋯ 菜单。理由：实测 557 + 双向导航史仍差约 40px；改为「隐文字、保留 32px 图标」同样省 28px 但入口保持可见。
- 触发条件：任何新增/删除头部控件、改按钮文案或宽度后，必须重跑校准探针重算阈值（本次根因即控件增删后阈值未同步）。
- 证据门：Playwright 真机 7423，以「1 行↔2 行翻转点」为判据；改后单行下限 552px（双向导航最坏组合，实测 556）。
