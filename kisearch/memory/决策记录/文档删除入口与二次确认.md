浏览页阅读器头部新增「删除」入口（复制之后、全屏之前），点击弹二次确认，删后关闭阅读器并在页头给 8 秒回执。
- 为什么不是「加个按钮」：后端原本没有删单篇文档的 HTTP 接口（只有 import/prune 与 datasource/prune 两条带 token 的批量通道），新增 `POST /api/doc/delete`（body 带 dryRun=true 走 read 通道做预检，真删走写锁 `doc-relation-delete`）。
- 预检内容：源文件是否存在（`<wiki>/<group>/<relation>.md`，不存在时**不返回路径**，前端据此不显示勾选框）、未结束草稿数、是否数据源管辖。
- 三个已拍板口径：① wiki 源文件给勾选框默认勾上（可只删库留文件，`wikiDelete:false` 复用数据源 prune 的既有实践）；② 数据源管辖的文档**放行**并红字预告「下次同步会重新导入」（与「移动」的 409 阻断刻意不同：移动会产生副本，删除不会）；③ 删除按钮靠文字色（`--ki-color-danger`）区分，红底会让它看起来比编辑更主要。
- 根目录文档允许删（`normalizeGroup(..., allowRoot=true)`），移动源侧仍拒绝。
- 落点：`src/lib/doc-delete.ts`（预检 + 编排）、`src/lib/doc-identity.ts`（从 doc-move 提取的 Group/relation 归一 + 数据源归属判定，删除与移动必须同源）、`web/src/components/DocDeleteDialog.tsx`、`ModuleDrawer.tsx`、`BrowsePage.tsx`、`ki.css`。
- 契约登记三处必做：`route-permissions.ts` 的 exact POST /doc/delete → knowledge.write；`scope-policy.ts` 的 BLOCKED 加 doc-relation-delete、EXEMPT 加 doc-delete-precheck（只读库也要能解释为什么不能删）；窄屏收起阈值 700 → 820（每加一枚文字动作约 +76px，阈值只许单调上调）。
- 编辑器开着时删除按钮禁用（改的正是这篇，删了保存会 404）；Esc 早退条件必须加 deleteOpen。
