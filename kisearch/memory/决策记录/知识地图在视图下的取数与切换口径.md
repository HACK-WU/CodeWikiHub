视图下查看知识地图的口径：按成员库逐个取图集，不合并、也不给视图单独装一份（图集是整幅 HTML，合并不了；`/open/v1/atlas/*` 已显式拒绝视图名）。2026-11-25 用户确认布局并实现。

- 行为：视图 → 逐成员查 `/api/atlas/status?scope=<成员>`；只有 1 个装了 → 直出那份、不出现任何切换控件；≥2 个 → 顶栏成员下拉；0 个 → 空态列成员名 + 「先切到具体成员库再上传」
- 切换器：顶栏 actions 首位，只列已装图集的成员，末尾一行「另有 K 个未配置图集 · M 个读取失败」；选中优先级 = URL `?member=`（replace 不进历史）> 最近上传（`meta.uploadedAt`）> 成员顺序首个。首次进入按最近上传，用户手动切过后 URL 固定住（否则别人给 B 传新版本会把你正在看的 A 弹走）
- 视图下隐藏上传 / 卸载：现状点了会被 `withScopeWriteLock → assertNotScopeView` 拒，但经 `sendAtlasError` 落成 HTTP 500，不是干净文案；空态也不再给 `--scope <视图名>` 命令（`/open/v1` 必返 400）
- 权限依据（纯前端方案成立的关键）：`filterAuthorizedViews` 要求「视图名 ∧ 全部成员」都已授权才列出视图，故前端能列出该视图 ⇒ 成员名全在 authScopes ⇒ 逐成员请求经 `scopeAllowed → isScopeAccessAllowed` 必放行。后端零改动
- 已知边界：视图后续新增成员不会被 CLI 自动补授权（`splitGrants` 的 autoMembers 只补当时成员），此时整个视图会从列表消失，不会出现「部分成员可见」的中间态
- 实现落点：`web/src/lib/atlasTargets.ts`（纯判定 `resolveAtlasView` / `atlasMemberNote` / `toAtlasProbes`，页面与顶栏共用防漂移）、`web/src/lib/hooks.ts`（`atlasStatusOptions` 工厂 + `useAtlasTargets`，scopeList 未就绪时零请求，避免先按视图名查一次闪空态）、`web/src/pages/AtlasPage.tsx`、`web/src/components/AtlasHeaderActions.tsx`（视图分支放在 `canWrite` 早退之前——切成员是读操作，只读账号也要能切）、`web/src/styles/atlas.css`
- 测试：`web/test/atlas-view.test.mjs`（纯判定 + 静态守卫）、`web/test/atlas-view-render.test.mjs`（SSR 渲染真实组件，无 jsdom 也可锁分支）
- 现状根因（已修）：`readStatus(视图名)` 因视图不落盘恒 `exists:false`，页面把它显示成「这个库还没有知识地图」——静默误导
