文档在线编辑的「强制保存（以 KB 覆盖回写目标）」与**写回目标定位**的完整口径（2026-11-12 用户两次裁定）。

## 一、写回目标只认 `wikiSync.sourceDir`

- 开启 wiki 回写（`wikiSync.enabled !== false` 且配了 `sourceDir`）才写文件；否则**只写 KB**，一个文件不碰。
- `group-index.json` 的 `source` 块**彻底退出写回定位**（它是导入源目录；上传方式导入时指向 `/root/.ki/import-uploads/<uuid>` 临时副本）。此前它优先级更高，导致编辑保存 / sync 写回 / 删除全落在副本上，用户在 config 里配的 `wikiSync.sourceDir` 被静默忽略——界面显示保存成功、自己仓库里毫无变化。用户判定为 **Bug**。
- 位置: `src/lib/document-editor.ts::configuredSourceDir`、`src/lib/wiki-sync.ts::resolveWikiRootDir`（`rejectSourceDirAsWikiRoot` 已删）。
- 删除链（`delete-relation.ts`）：目标恒为命名约定镜像 `<wiki>/<group>/<relation>.md`；`sourcePath` 只做 realpath 归属校验，不一致或文件缺失一律拒绝（硬删无回收站，宁可删不掉）。

## 二、强制保存（force）

- `force:true` 跳过源文件侧三道闸门（加载后变化 / 加载时分叉 / 保存时分叉），KB 乐观锁 `DOC_EDIT_CONFLICT` 与索引链路照旧；源文件不可读仍 fail-loud、不重建文件。
- 只对 `CONTENT_DIVERGED` 给入口（`SOURCE_MISMATCH` / `SOURCE_UNAVAILABLE` / `SOURCE_DISABLED` 是定位或权限问题）。
- 用户拍板：加载后源文件再变**也覆盖**；frontmatter **不保留**；**不备份**；阅读页「添加链接」一并支持。
- 体验：强制成功后不自动关窗，就地翻回一致态并给回执；确认框默认焦点「取消」，Esc 用 capture 只关弹窗。

## 三、文案口径（防歧义）

- 禁用「源文件」字样（会被读成数据源/导入源）：统一说 **wiki 回写目标**。
