知识地图图集（REQ-20261120-003）一期形态定稿（v3）：单条上传为唯一写入口、删除为单条软归档、点节点弹右侧抽屉、上传走 MCP+HTTP 双通道、快照正文随条目 JSON 上传。
- D8 写入口：单条上传（画完一张传一张）。HTTP `POST /api/atlas/entry`（base64，单条 ≤5 MB）+ MCP `ki_atlas_save`（传本地绝对路径，不塞 800KB 内容）。**被推翻的旧判断**：v2 曾定「整包 multipart 64 MiB 替换」，因假设了「全部画完再传」，与真实工作流不符；单条化同时消解了体积上限与旧条目清退两个阻断。
- D9 删除：`DELETE /api/atlas/entry/:id` → 进 `_meta.archivedIds`（产物留盘、页面不展示、可被同 id 重传激活）。
- D10 快照：右侧滑出抽屉 `width:min(560px,92vw)`、遮罩 `pointer-events:none`（打开时仍可切图），沿用 demo 已验证形态；**推翻 v2 的「详情区内 230px 面板」**。
- D11 双通道分工按「产物在哪」：本地磁盘 → MCP 传路径；跨机/页面 → HTTP 传 base64；共用 `src/lib/atlas/` 服务层，防校验分叉。
