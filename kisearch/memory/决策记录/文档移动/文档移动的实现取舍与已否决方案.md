文档「移动」到其他 Group 的实现取舍（REQ-20261112-002，2026-11-12）：不重写跨层迁移，改为编排「预检（全只读）→ 物理搬源文件 → executeSyncRelation(skipWikiWriteback + sourcePath) → executeDeleteRelation(wikiDelete:false)」，任一步失败按逆序回滚。

- 位置: `src/lib/doc-move.ts`（编排 + 回滚）、`src/sync-relation.ts`（新增 `sourcePath` / `skipWikiWriteback` / `allowRootGroup`）、`src/lib/mcp-http-api.ts`（`POST /api/doc/move`）、`route-permissions.ts` + `scope-policy.ts`（`doc-move-write`）
- 为什么编排而非重写: FTS docId 含 group ⇒ 移动必然换 id，只能「删旧写新」；sync 链路已覆盖组树/KB/分片/向量/FTS，delete 链路已覆盖清除与 `ki-relation` 跨组共享保护
- ★ 数据源文档必须禁止移动（409 DATASOURCE_BLOCKED）: 数据源同步参数快照不带 `skipDuplicates`（只在上传导入路径）⇒ 移动后下次同步会在原 Group 重新导入一份。**被否决方案**：「允许移动 + 清 `sourcePath` 解除关联」挡不住重新导入
- ★ `writeBackToWiki` 用 `generateMarkdown` 重写内容 ⇒ 移动必须 `skipWikiWriteback`，文件自己 rename（EXDEV 退化 copy+unlink）
- ★ 根目录支持（同日用户追加）: `GroupPathSelect` 新增 `rootOption?: { value, label }`（组件级、传了才显示，**仅移动弹窗开启**；导入/写入页「留空」本身就是根，另加测试挡回退）；选中时输入框留空+占位显示 label，保留键 `__root__` 不进界面；后端 `SyncRelationParams.allowRootGroup` 放行保留键且**不打 `groupSource: scope-fallback`**（显式选择 ≠ 兜底）。源侧仍禁：删除链路按 Group 树定位，根无稳定树节点
- 已知限制: `__root__` 下的文档暂不能移出；`POST /api/doc/edit` 无法用于跨组创建
- 前端其它: 同名冲突提示改「文档名称」（`targetRelation`），窄屏收起阈值 620→700
