知识地图页（/atlas）不再有页内状态行：上传 / 卸载图集的动作上移到顶栏「AI 对话」左侧，且只在知识地图页渲染。
- 决定: 顶栏 actions 组首位渲染 `AtlasHeaderActions`（AppShell 按 `location.pathname.startsWith('/atlas')` 判定）；按钮按 `exists` 切换「上传图集包 / 重新上传」，图集存在时才显示「卸载」；皮肤复用 `ki-topbar__chat-toggle`（32px、≤1100px 收成图标）；导航项「知识地图」由「AI 对话」之后改到「知识库浏览」正下方。
- 弹窗: 上传 / 卸载确认 / 卸载失败三个弹窗统一用站内 `ki-dialog` 骨架（portal 到 body、遮罩点击关、Esc 捕获期关、打开即聚焦、busy 时三位全禁、容器 `:focus` 不画焦点圈），**不用 `window.confirm`** —— 原生弹窗长着浏览器的脸，与全站视觉割裂（用户当场指出）。
- 原因: 图集包自带信息条已写「基于 master @ 071afab 生成 · …」，页面再画一行 commit 就是同一句话说两遍；动作上移后正文只剩图集本体，还省下一条纵向空间。
- 被推翻的判断: 上一版（同一轮）只把状态行改成「裸文本行 + 按钮」，仍留在页内；用户随即拍板整行删除。页面仍保留 `ki-content--atlas`（主区内距清零使 iframe 贴边）。卸载的二次确认也从 `window.confirm` 改成站内弹窗。
- 数据: 状态改走共享缓存 `['atlasStatus', scope]`（`lib/hooks` 的 `useAtlasStatus`），顶栏与页面共用一个请求；上传/卸载成功后 invalidate 一次，页面自己换版本，不需要跨组件消息通道。
- 位置: `web/src/components/AtlasHeaderActions.tsx`、`web/src/pages/AtlasPage.tsx`、`web/src/layouts/AppShell.tsx`、`web/src/lib/hooks.ts`、`web/src/styles/atlas.css`
