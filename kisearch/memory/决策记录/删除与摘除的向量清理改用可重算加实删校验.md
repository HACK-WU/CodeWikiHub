删除与 hidden 摘除的向量清理统一改为「可重算优先、检索兜底、核对实删数」，修掉「删 0 条仍报成功」（事件 #36 / #37，2026-11-16）。

- **可重算优先**：内容向量 docId = `sha256(正文 + scope + tag)`，与 group/relation 无关 ⇒ 删除前必须读正文（`readKbRelationContent` / `extractKbBody`）重算全部 docId；正文**必须在删 KB 之前**取。
- **判据同源**：`src/lib/content-vector-match.ts` 是唯一实现（正文包含候选内容优先 + 同组兄弟正文排除公共段落误判 + 最短 40 字符；标题前缀仅退路；排除 ki-relation/ki-path）。删除与摘除共用。
- **路径向量同源**：`src/lib/relation-path-vector.ts` 统一三种文本形态（纯名 / `relation-NN` 分块 / 历史 `名 | Group: x`）的候选重算与检索兜底。过去 hidden 侧只查纯名 ⇒ 分块导入的文档 hidden 后 `relation-01` 摘不掉。
- **摘除后清 cache ids（根因）**：`applyVisibility` dense 摘除成功后立刻清 `rel.memoryIds` 并落盘。不清的话 cache 长期谎报「已向量化」，毒化 group-delete / rebuild-vector / fts-rebuild；hidden → full 补写时 vectorWriteBack 会回写新 id。
- **元数据失败即停手**：`metadataFailed` 时 4 / FTS / 4.5 / 4.6 全部不摘（磁盘上文档还在，摘了就是「列表里有、点开 404」），并在 reason 说明。
- **检索只在异常路径付费**：delete 侧仅「一条都没删到」时检索；visibility 仅在 ids 全失效时检索，且先 `ensureVector()` fastFail。部分命中不检索，改为 reason 显式报缺口。
- **实删校验**：所有删除核对 `deleted` 与 `errors`（errors 已过滤 NOT_FOUND，非空即真失败），缺口写进 reason。
- ★ 踩坑：`vectorDelete` 走 `withEngine`，**对不存在的 collection 会打开/创建一个空库并留下常驻句柄**（单测进程跑完不退出，visibility-sr03 因此超时）。按 id 删除前先 `scopeCollectionExists(scope)` 短路（已导出）。
- 已知局限：导入型 chunk 若正文被清洗过，重算与「正文包含」都可能失配，只能显式报出让用户重建；同正文的两篇文档共享同一 docId（删 A 会连带 B 失去召回）。
- 位置: `src/lib/content-vector-match.ts`、`src/lib/relation-path-vector.ts`、`src/delete-relation.ts`、`src/lib/visibility-index.ts`
- 验证: 13 个测试文件全绿（新增 31 例）；本地直连与 daemon 重启后 CLI/MCP 两通道各跑四场景，删后检索均 0 条、摘除后 cache ids 已清空；证据 `.debug/delete-vector-residual-20261116/`（E-10~E-15）。代码未提交
