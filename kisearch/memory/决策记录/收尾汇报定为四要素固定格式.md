把「任务收尾给用户看的总结」从模型自发习惯固化为固定四要素：① 状态变更（事件阶段流转 / 关键文件与测试结果 / 是否已提交）② 沉淀落点（写进哪个库·Group·Relation，AGENTS.md「近期工作」记了哪行）③ 剩余边界（已知限制 / 未覆盖测试 / 待复核 / 没做的标「未做」）④ 待用户决定（是否提交 / 是否 breaking / 要不要推终态）。四要素各一行、合计 ≤6 行、为空写「无」。
- 真源: `skills/agents-md-init/SKILL.md` §2.7.1（§2.7 是内部自省表，面向用户的输出格式在 §2.7.1）
- 载体: AGENTS.md 置顶「🧾 第四原则：收尾汇报」+ AGENTS-template.md 同节（两处必须同构）；写入与核对见 §2.1 ⑬ / §2.2 ⑩，禁忌 36 / 37
- 前置: 必须先过 §2.7 自查（该记没记 / 该报没报 / 该收口没收口）再出汇报，否则汇报好看但闭环没做
- 起因: 用户观察到该行为不错并询问「在哪规定的」，核查结论是项目内此前无任何一条规定该展示格式（只规定了收尾要做哪些动作：§2.7 自查 + event-report §10 回执 + 用户画像「禁止擅自提交」）
- 边界: 只汇报已发生的事；逐文件 diff / 完整命令输出 / 记忆正文不进汇报；`📮` 就是回执本身不重复写
- 豁免口径（修订过，旧口径「极短任务可只写一行」因无判据被证会软化）: 仅当改动 ≤1 个文件 且 无事件流转 / 无新沉淀 / 无待决事项 才可只写一行
- 约束: 该置顶章节无条件必写，不随 `ki_recall` 能力探测失败而连带跳过
