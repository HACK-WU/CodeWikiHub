AI 对话图片能力按两条线切分（2026-11-23 用户拍板，五项已全部闭合）。
- **本期**：用户上传图片 = 需求 `REQ-20261123-006`（v5 定稿），落 `CodeWikiHub/kisearch/requirements/2026-11-23-AI对话图片输入/`
- **独立立项**：MCP 工具返回图片 + 知识库文档附图读取（含 AI 分析链路）= 事件 #78；单独理由是涉及 24 个工具返回体契约、上下文预算口径、图片可访问性三块跨模块面
- 沿用 V1 决策：只做输入不做出图（D9）、历史只带最近 1 轮图片（D10）、`llm.supportsImages` 手填不自动探测（D11）、本地图落 `chatDir/{scope}/assets/{convId}__*` 且 KB 图只存引用不复制（D12）
- **不预处理，原图直传**：不做客户端缩放 / 压缩 / 切块，`maxImageBytes`（4MB）是硬拒绝线；界面截图小字识别归模型能力，刻意不验证，只作上线后观察项
- **重发与编辑复用原图**：原图仍在 `{convId}__*` 就复用；`regenerate` 从末条 user 读回 `images`，`edit` 回填待发图列表（可逐张删）
- **图片不计入上下文用量百分比**：`computeContextChars` 零改动，用量条数字与改造前一致；展示层可标“含 N 张图”
- **mime 白名单 = PNG / JPEG / WebP，排除 SVG**：实测 `data:image/svg+xml` 被上游硬拒（400 `UnidentifiedImageError`），传了只会得到看不懂的服务端错误；且 SVG 是文本、魔数校验不可靠，项目对 `.svg` 本就加 `CSP: sandbox` 对待。GIF/BMP/ICO 未验证不纳入。单消息 4 张
- 预算口径（实测）：图片**不进字符预算**（base64 按字符计会撞穿 `maxToolResponseChars=10000`）；若将来要省成本只能降分辨率（token 只随尺寸变，1024²=652 / 1568²=994）
- 实现时必须移除 V1 占位：`src/lib/chat/chat-routes.ts` 对 `conversations/:id/images` 的硬 404「本期不实现（后置 V2）」
