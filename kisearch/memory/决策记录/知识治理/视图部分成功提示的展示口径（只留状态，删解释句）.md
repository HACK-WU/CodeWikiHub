治理页视图下「部分成功」怎么告诉用户，2026-11-20 两轮拍板后的定稿口径：提示条**只留状态**，解释性文案删除。

- 决定: 只保留三类会让人误判「我看到的是全部」的状态 —— 读取失败（buckets[].error）、当前显示 N 条（共 M 条）还有更多、未参与（skipped / 超上限）；没有状态时**整条不渲染**。
- 已删: 「聚合视图：事件按成员库合并展示（编号 #N 为各库独立计数…）；流转 / 编辑 / 删除 / AI 分析会落到事件所属库；新建事件与类型维护请先切到具体知识库。」—— 用户拍板（原话「提示直接不要了」），理由是它只占一行不提供即时判断价值。
- 代价（已告知）: 编号跨库重复、写入口落到事件所属库这两条语义，事件页不再有书面说明（每行仍显示所属库，写入口仍按 eventScope 发请求）。
- 失败库的呈现: 正文只列库名（`读取失败：a、b —— 这些库的数据不在本次结果里`），原始 message 挂 `<p>` 的 `title`（它带服务器绝对路径，不内联）。
- 被推翻的判断: ① 最初想「等产品定口径再动」→ 实测口径可收敛成一句话，先做前端消费；② 第二轮想把提示移到「最近更新」按钮右侧 → 用户改为删除。
- 边界: 分类页 / 回收站页各自的「只读聚合视图：数据来自 X、Y…」未动（它们带成员库清单，仍有用）；单库模式只有截断句，没有 buckets / skipped 概念。
