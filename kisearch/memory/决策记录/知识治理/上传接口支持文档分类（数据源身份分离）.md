对外上传接口 `/open/v1/import/upload` 支持文档分类：新增 `lifecycle`（wiki/temp/event）、`ttlDays`、`event` 三个 query 参数，`ki-upload` skill 同步加 `--lifecycle/--ttl-days/--event`。

**前提决策（2026-11-16 用户拍板 A 方案）**：上传通道的文档**不再算数据源文档**（新建 `isImported=false`），否则被 S-01 R4「数据源强制 wiki」清空分类。数据源同步 / `ki import --source` / Web 上传的文档身份与行为完全不变（`RunImportArgs.isDatasourceDocument` 只有 open/v1 传 false）。

三条语义：① 未传分类 = 新建 wiki，**不跟 group 默认**（上传通道专属口径，与 `ki_sync_relation` 刻意不同）；② 覆盖已有文档且未传分类 → 保持原值（不重置）；③ 目标是数据源文档（isImported）而显式传了分类 → 该文件跳过记入 `lifecycle.lockedSkipped`，不改原文档身份与分类。

**★ 实施踩到的真缺陷**：导入链路接入阶段可见性时，`applyVisibility` 必须显式传 `from: 'full'`。缺省它按「当前语义」现算旧档位，而分类刚在 Phase 4 落盘 → 算成 hidden → `planTransition('hidden','hidden')` 是空操作，接口回显 hidden、全文检索照常命中（真机实测复现）。
