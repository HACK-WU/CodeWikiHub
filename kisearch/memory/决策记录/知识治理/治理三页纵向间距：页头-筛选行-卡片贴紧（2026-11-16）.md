知识治理三页（分类 / 事件 / 回收站）把「页头分隔线 → 筛选行 → 正文卡片」收成一屏操作区：分隔线到筛选行 8px、筛选行到卡片 4px（宽屏），≤900px 工具条塌成多行时卡片间距回 12px；提示 / 说明块仍按整页栅格 16px。

- 用户原话：「这些按钮，直接和下面的卡片挨在一块就行了，没必要分开」「按钮的顶部的空隙太多了，缩小一点」。
- 落点：`web/src/styles/governance.css` —— `.gov-head` 下内距 12 → 8px；`.gov-head + .gov-toolbar` 负 margin -8px；`.gov-toolbar + .gov-card` / `+ .gov-split` / `+ .gov-selbar` 与 `.gov-selbar + .gov-card` 负 margin -12px；`@media (max-width: 900px)` 内同组选择器改 -4px（回 12px，因窄屏工具条是多行，4px 会挤）。
- 手法：不改 `.gov-page` 的 `gap: var(--ki-space-4)`（说明块等兄弟依赖它），用负 margin 局部抵消 gap；media 规则靠后置顺序覆盖外层同特异度选择器。
- 实测（骨架注入同一份 ki.css + governance.css）：1440 / 1000 单行，headToBar 8px、barToCard 4px；900 / 768 / 375 工具条 102px 高（3 行），barToCard 12px；五档 overflowX 全 0。
- 顺带：分类页搜索框 220 → 320px（`LifecyclePage.tsx` inline style）；≤900px 由既有 media `.gov-toolbar .gov-input{width:100% !important}` 接管，所以 `maxWidth:100%` 只是 ≥900px 的兜底。
- 边界：出现 message / 只读 hint 时卡片不再紧跟工具条（中间是提示文本），该分支仍 16px —— 预期行为，不是回归。
- 验收：web 单测 1236/1236、`npm run build` ✓。
