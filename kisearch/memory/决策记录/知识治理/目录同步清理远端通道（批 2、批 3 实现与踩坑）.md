远端 token 通道的「只算不删」已实现（事件 #105 批 2、批 3）：服务端 `POST /open/v1/import/prune` 算候选，`ki-client upload-dir --prune` 调用并打印；删除仍只在本机 CLI 与页面。
- 端点实现在 `src/lib/open-api/routes/prune.ts`：POST 只因为清单要走 JSON body（8 MiB / 5 万条上限），**没有删除语义**；响应剥离 `token` 与 `allCandidateSourcePaths`，并恒返 `deletable:false` + hint。路径在 `/open/v1/import` 前缀下 → 自动受 `uploadApi` 开关与 daemon 漂移守卫覆盖。
- 能力位 `ping.capabilities.prune.query`：客户端据此报 `CONTRACT_TOO_OLD`，不去撞 404（404 与「路径写错」同形）。
- 踩坑一（P0，已修）：`upload-dir` 在「全部文件未变化」时 early return 0，`--prune` 静默不执行——而「本地删了文件、没有新增」恰恰是该功能的主场景。修法：空跑分支补算候选，并把 prune 调用抽成 `runPrunePreview` 供空跑与正常路径复用。
- 踩坑二（已修）：空跑 + `--json` 原本没有任何 stdout 输出（既有缺陷），`--prune` 让它更糟；已在空跑分支补 JSON 块。
- 展示坑（已修）：`__root__` 是存储保留键，凡面向人的出口必须映射成「根」（`groupDisplayName`）。候选清单的组标签在 CLI 与 ki-client 两处都漏了（真机看到 `__root__：1 篇` 才发现）；客户端无该模块，用 `group === '__root__' ? '根' : group` 判。
- 边界：`upload`（单文件）+ `--prune` 直接报 USAGE；只读 Token 打 POST 会 403 `OPEN_API_TOKEN_READONLY`（既定边界，`--prune` 依附上传）；只读库放行（纯读，与页面 dryRun 同口径）。
- 验证：curl 矩阵（正常 / 缺清单 / 空清单 / 视图名 / group 穿越）+ 客户端两条路径（上传后、全未变化）+ `--json` + `__root__` 落点；`open-api-ping` 18、`open-api-readonly` 14、`open-api-upload-scan` 3、ki-client 94 例全绿，两端 tsc 0。
- 已知测试债（已上报 #108）：`test/import-prune-e2e.test.ts` 2 例失败，断言按 2026-11-02 前的「根落点 = scope 名」写的，实际已是 `__root__`；与本功能无关，真机已验证 `__root__` 落点下候选与删除均正常。
