分类页（/governance/lifecycle）文档列表用**客户端分页**（筛选 → 排序 → 切页），不走服务端分页。理由是分类筛选（wiki/临时/事件）、各档计数、按剩余天数排序全在前端算，改服务端分页会让三者只覆盖当前页，页头「事件 3」会和翻页后的行对不上。

- 每页条数：默认 20，选项 20/50/100（数据源页/任务页默认 10，因卡片行高不同；此处是约 34px 的紧凑表格行）
- 「全选」= **当前页**（表头 checkbox 带 `indeterminate` 半选态）；跨页已选保留，批量条追加「其中当前页 N 篇」防闷改
- 改变结果集 ⇒ 回第 1 页：切筛选、改搜索词、切 scope、改每页条数；只改顺序的「排序」也回第 1 页但**不**清空已选
- 已选清空口径：切筛选时**仅当真换视角**才清空（`if (filter !== key)`）——重复点当前 tab 不得清掉已勾选；搜索由 load 统一清空；翻页与排序保留
- 页码收敛：渲染用 `currentPage = min(page, pageCount)`，另有 effect 回写 state，避免数据变少后闪一帧空表
- 截断：前端仍取 `limit: 200`，保存服务端 `total`。**提示条必须独立常驻在结果区上方**，不能只挂分页栏——分页栏在 0 条时收起，而「筛出 0 条」正是最需要它的时候（否则用户会把「未加载」判成「没有该分类文档」）；底部说明块另按截断切换「共 N 篇 / 已加载 N 篇（全部 M 篇）」
- 页码折叠算法抽到 `web/src/lib/pager.ts::pageNumbers`（>7 页时中段折叠），任务页已改为共用，勿再复制第三份

位置：`web/src/pages/LifecyclePage.tsx`、`web/src/lib/pager.ts`、`web/test/governance-lifecycle-pagination.test.mjs`（15 例）。

边界：后端 `/governance/docs` 已支持 `offset` 且返回过滤后全量 `total`，本次未启用（规模 <200 无必要）；事件页与回收站页（`TrashPage` 同样 `limit:200`）仍无分页，未在本次范围；批量操作条非 sticky，滚到列表下方勾选时看不到已选计数（分页前既有）。
