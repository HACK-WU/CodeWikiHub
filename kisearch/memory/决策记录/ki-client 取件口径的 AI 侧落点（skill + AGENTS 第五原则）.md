外部取图能力从 MCP 工具下线后，把「要图走 ki-client」这条口径写到**两处**：AI 决策层 skill `skills/ki-client/SKILL.md`，以及 AGENTS.md 置顶「第五原则」。2026-11-25 建。
- 为何是 skill 而不是塞进 AGENTS 正文：AGENTS 是每次对话全量注入的上下文，只能放“一句话结论 + 触发场景”；命令口径、错误码出路、七条禁忌属于按需查询的内容，写进 AGENTS 会把缓存变成负担。两处分工：AGENTS 回答“什么时候该用”，skill 回答“具体怎么用、踩过什么坑”。
- 第五原则的判据：前四原则（ki-search / 沉淀上报 / 预取 / 收尾汇报）都关于“记忆行为”，而取件是关于“跨机搬运字节”，归不进任何一条 → 单列第五原则，写法同样是“场景清单 + 硬约定 + 口径真源指针”。
- 同批给 `agents-md-init` 补了**「项目专属置顶章节必须原样保留」**（AGENTS-template.md 声明 + SKILL §2.2 步骤 ⑪）：模板只定义 1~4 原则，刷新时最容易把模板里没有的置顶章节当冗余裁掉，不补规则则第五原则下次初始化即丢失。这是**通用**规则（不写 kisearch 专属内容），对其他项目同样成立。
- 易混点（已写进两处）：产品内置 AI 对话里的 `ki_get_image` 仍存在且返回真图片（服务端进程内直调），与“客户端命令行取件”是两条独立通道。
