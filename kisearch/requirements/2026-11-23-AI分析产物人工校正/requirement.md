# AI 分析产物人工校正

> 一句话：**未确认点与已确认位置**允许人工校正；**分析结论不可人工编辑**，只能由「追问补丁 + 用户确认」覆盖。

## 1. 背景与问题

### 1.1 真实场景

用户在事件详情页对 AI 分析追问后，常出现需要落地的修正，但当前无入口：

| 场景 | 用户想做的操作 | 现状 |
|---|---|---|
| 追问发现结论漏了一条成因 | 用 AI 的新结论替换当前结论 | 追问只读：`analysis-ask-runner` 只落 `.ask.json`，从不回写草稿（🟢） |
| 未确认点里有一条已被后续排查证伪 | 删掉这一条 / 改写措辞 | 完全只读（本次开放） |
| 已确认位置里有一条定位错了，或有一处新查到的位置要补进来 | 删除 / 手工新增 | 删除可做；新增只能从 AI 候选里勾（本次开放手工新增） |

> **结论为什么不开人工编辑（2026-11-23 拍板）**：结论是 AI 分析的产物，也是 MCP 读给其它 AI 的事实源。人工直改会让"谁下的判断"混淆、且难以追溯；改结论的正规路径是**再问一次 AI**，由 AI 重新给出结论，人只做"是否采纳"的决定。

### 1.2 代码现状（🟢 代码直读，2026-11-23 核对）

| 产物 | 数据结构 | 读 | 写 |
|---|---|---|---|
| 结论 | `AnalysisDraft.conclusion: string \| null` + `chain: ConclusionNode[]` | `GET /analysis`、`GET /events/:id` | **仅** `PATCH /analysis`（供 AI 补丁覆盖；**前端不提供人工入口**） |
| 未确认点 | `AnalysisDraft.unconfirmed: string[]` | 同上 | `PATCH /analysis`（人工编辑） |
| 已确认位置 | `EventAnalysisDoc.confirmed: ConfirmedCodeLocation[]` | 同上 | 删除 / 人工新增（同上）+ `POST /analysis/confirm`（只认候选） |

关键证据：

- 前端渲染：`EventAnalysisCard.tsx`（结论 / `.gov-unconfirmed` / `.gov-confirmed`）
- 结论归一真源：`src/lib/events/conclusion-chain.ts`
- 严格校验：`src/lib/events/analysis-edit.ts`（阈值从 `conclusion-chain` 导入）
- **长度口径现状**：结论 summary 提示词写"≤120 字"（`analysis-runner.ts`、`prompt-config.ts`），解析层硬截断 2000；追问回答提示词写"不超过 400 字"（`analysis-ask-runner.ts`），服务端硬截断 4000
- **追问只读**：`analysis-ask-runner.ts` 全文无 `updateDraftIfMatch` / `writeAnalysisDoc`
- **视角模板**：`analysis-view.ts` 的 `PROFILES[*].skeleton`（fault/perf 5 槽；change/generic 4 槽）是唯一权威；前端 `analysisView.ts` 只有 `VIEW_LABELS`
- **骨架校验缺失**：`analysis-edit.ts` 只校验五槽白名单与上限

## 2. 需求范围

### 2.1 允许的操作

| 块 | 可做的操作 | 约束 |
|---|---|---|
| 结论 | **不可人工编辑**（阅读只读）；仅由「追问补丁 + 用户确认」整块覆盖 | 补丁必须过视角模板校验；节点 ≤5、每节点 ≤200 字、总结 ≤4000 字 |
| 未确认点 | 新增 / 删除 / 改写 | 单条 ≤300 字、总数 ≤20 条 |
| 已确认位置 | 删除（已有）；**手工新增**（`file:line` + 理由）；编辑理由 | 新增必须服务端验真；`targetDir` 由配置解析而非依赖草稿 |
| 追问结论覆盖 | 追问末端产出补丁；用户确认后整块替换 `conclusion` + `chain` | 不一致才提示；不得自动生效 |

### 2.2 必须共享的规则

1. **统一修订标识**：未确认点 / 位置被改，或"确认采用 AI 补丁"，卡面显示「已人工修订」并记 `editedAt`；不改变 `draft.status`。
2. **统一保存语义**：一次整块提交，`expectedRunId` 只有一个来源；不允许半保存态。
3. **统一空态语义**：区分「AI 没找到」/「已清空」/「从未分析」。
4. **清空不等于删草稿**：清空未确认点后 `draft` 仍存在，卡片不得消失。
5. **勾选确认不吞修订**：`POST /analysis/confirm` 必须继续传 `discardDraft: false`。
6. **重跑只覆盖草稿**：重跑 / 续跑覆盖 `conclusion / chain / unconfirmed / candidates`，**`confirmed[]` 保留**。
7. **视角词表同源**：补丁槽位词与卡面渲染都走 `analysis-view.ts`。
8. **下游自动跟随**：追问上下文、MCP `ki_event_get` / `conclusionPreview`、`GET /events/:id`、前端卡面，四处读到的都必须是当前值。
9. **长度口径统一（H10 拍板）**：**取消软限制**（结论 120 / 追问回答 400），**硬上限统一 4000 字**（用于结论补丁与追问回答），超限截断不报错。
10. **AI 补丁不得自动生效**：必须经用户确认，且只在「与当前结论确实不同」时提示。
11. **结论唯一写路径**：`conclusion` / `chain` 只能由补丁覆盖写入；**接口保留**（供补丁路径），但前端不暴露任何人工编辑入口。

### 3.2 验收清单

1. 追问上下文读到最新的未确认点与已确认位置。
2. `GET /governance/events/:id` 与 `GET /analysis` 返回最新值。
3. MCP `ki_event_get` / `ki_event_list.conclusionPreview` 返回最新值且带 `edited`。
4. 重跑后：结论/未确认点被覆盖、`confirmed[]` 仍在。
5. viewer 账号：无编辑入口，直调写接口被拒。
6. **追问产生补丁 → 弹框 → 确认覆盖后，卡面结论与追问上下文同时为新值。**
7. **补丁结论 4000 字可覆盖、4001 字被拒；追问回答超 4000 截断而非报错。**
8. **编辑态里没有结论输入框**（只有未确认点与位置两块可编辑）。
