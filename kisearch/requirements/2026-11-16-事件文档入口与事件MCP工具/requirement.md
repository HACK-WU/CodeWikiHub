# 事件文档入口与事件 MCP 工具

- 需求 ID：REQ-20261116-004
- 状态：设计中
- 提出日期：2026-11-16
- 来源：用户对事件页的实机走查（截图两处缺口）+ MCP 能力补齐诉求

## 1. 背景

事件（知识治理的第三条链）目前只能在页面创建，且页面本身缺两个入口：新建事件弹窗无法选文档，详情页「关联文档」区没有添加/移除按钮（只有参考文档有）。MCP 侧只有只读的事件枚举与唯一的流转写工具，AI 无法创建事件、也无法维护事件的两类文档。

## 2. 目标

| # | 需求 | 优先级 |
|---|---|---|
| R1 | 新建事件弹窗可选关联文档，随创建一次提交 | P0 |
| R3 | 详情「关联文档」区新增「＋ 添加」 | P0 |
| R4 | 详情「关联文档」行内「×」移除（解绑回 wiki） | P1 |
| R6 | 绑定/解绑后按阶段档位同步索引（当前只改元数据，旧索引残留） | P0 |
| R7 | 绑定前校验文档归属（已属其他未收口事件 → 拒绝）与数据源锁 | P0 |
| R2 | 新建事件弹窗可选参考文档，后端一次事务接收 | P1 |
| R5 | 新增 4 个 MCP 工具：`ki_event_create` / `ki_event_delete` / `ki_event_docs` / `ki_event_refs` | P1 |
| R8 | 同步三处"AI 不能创建事件"旧文案与 `docs/mcp-tools.md` | P1 |

## 3. 不在范围内

- AI 查询参考文档的 MCP 工具（`searchRefCandidates` 的 MCP 化）——用户明确搁置
- 事件源码分析（已有 REQ-20261113-003）
- 事件类型（阶段链）的 MCP 增删改
- AI 对话工具面（`CHAT_MCP_TOOLS`）登记事件写工具

## 4. 验收标准

1. 建事件时选 2 篇关联文档 → 详情区显示 2 篇，`lifecycle=event`、`eventId` 正确；挂到不可检索阶段后 `ki_search` 与 `ki_search(mode=fulltext)` 均搜不到。
2. 详情「＋ 添加」可挂文档；选到已属其他未收口事件的文档时被标注并禁用，后端兜底返回 `DOC_BOUND_TO_OTHER_EVENT`。
3. 详情「×」移除后文档回 `wiki`，`ki_get_module_info` 仍可读，`ki_search` 可召回。
4. 只读 Token 的 `tools/list` 不含 4 个新工具；编辑 Token 可见，且 4 个工具均可成功完成对应动作。
5. `ki_event_delete` 对未收口事件返回 `EVENT_NOT_CLOSED`；不传 `doc_action` 被拒。
6. 全仓 grep 不再出现"事件只能由人在 Web 创建 / AI 不能创建"一类表述。

## 5. 已确认决策

| # | 决策 |
|---|---|
| Q1 | MCP 工具 4 个（create / delete / docs / refs） |
| Q2 | 首版不进 AI 对话工具面，只走 `/mcp` |
| Q3 | 页面同时提供「移除关联文档」入口 |
| Q4 | 移除 = 解绑回 `wiki`，不删除文档、不进回收站 |
| Q5 | 创建时参考文档由后端 `createEvent` 一次事务接收 |
| Q6 | 文档已属其他未收口事件 → 拒绝，不静默改绑 |
| Q7 | 单事件关联文档/参考文档各上限 50 |
| Q8 | 界面 ASCII 布局已确认（弹窗两区块 + 详情区按钮/行内移除） |
| Q9 | `ki-path` 重建同批修复既有 `transitionEvent` / `restore` 同源缺陷（三条路径共用 `planTransition`，不拆两批） |
