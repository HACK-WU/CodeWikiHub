# 需求分析：事件源码分析（只读）

- **来源**：2026-11-13 讨论「文档生命周期 / 事件阶段」时提出 —— AI 分析 bug 类事件时只能看到知识库文档（结论），看不到源码（事实）；2026-11-16 结合已落地的事件模块（`REQ-20261113-004`）与「AI 设置」页完成需求重审与拍板。
- **目标形态**：用户在「AI 设置 → AI 分析」配置目标代码目录（按 scope 映射 + 默认目录）、基础提示词、专属 Skill、预算/思考级别与只读工具开关；在事件详情页（含未收口与已收口事件）点一次 `✨ AI 分析`，ki 注入事件基础信息、阶段进度、事件描述及关联/参考文档清单（仅路径与名称），由 LLM 自主按需调只读知识库工具读文档、调专属文件工具查目标目录，后台异步产出**待确认的代码位置草稿**，经人勾选确认后写入事件。
- **证据声明**：`🟢` = 代码直读（含 file:line）+ 用户界面截图确认；`🟡` = 推理待实现期压测验证。

## 2. 背景与目标场景

### 2.1 当前断点

1. **事件与代码割裂**：事件记录故障与排查结论，但无法直接关联到具体代码位置。
2. **「AI 分析」尚为占位**：事件详情页右上角已有 `✨ AI 分析` 按钮但只弹说明弹窗；「AI 设置 → AI 分析」只有 1 张「未接入」提示词卡片，无 Skill、工具开关、预算与目标目录配置。
3. **缺少事件描述区**：建事件时只有简短标题，无详细现象/报错描述承载区，影响无文档冷启动时的分析线索质量。

### 2.2 目标场景

> 用户在「AI 设置 → AI 分析」配置好目标代码目录与提示词/Skill/工具后，在事件详情页填写事件描述并关联文档，点击右上角 `✨ AI 分析`。即使切走页面或关闭弹窗，分析仍在后台异步运行（≤90s）；完成后在事件「代码位置」区与分析弹窗看到真实工具调用步骤与候选位置（`file:line` + 因果说明 + 置信度 + 未确认点），勾选确认后永久写入事件，`ki_event_list` 也可直接查到。

### 2.3 明确不做

- 不跑测试、不执行命令、不修改目标目录任何文件（永久只读）。
- 不做代码向量化或全文索引建库。
- 不将 `fs_*` 工具开放给通用「AI 对话」或外部 `/mcp` 接口。

## 4. 详细需求

### R1 分析目标目录配置（不限仓库，全局配置栏管理）

- 在 **「AI 设置 → AI 分析」** 新增 **「分析目标目录」** 配置卡片（存在 `PromptConfig` 的分析配置域中）：
  - 支持配置 **默认目录**（可选，所有未单独映射的 scope 兜底）；
  - 支持配置 **scope → 目录路径映射表**（例如 `kisearch-memory → /root/knowledge-indexer`），一个 scope 一条目标目录。
- **不强制要求是 Git 仓库**：任意本地可读目录或 Git 仓库根目录均可。**数据源目录不参与**（2026-11-16 用户纠正：数据源是"知识从哪来"、分析目标目录是"代码在哪"，是两个不同的概念）—— 不提供「填入数据源」按钮，选定 scope 时也**不**自动填充路径。
- **路径校验（两级，2026-11-16 实现口径）**：
  - **保存时**：只校验格式 —— 非空、必须绝对路径（`path.isAbsolute`）、拒绝系统路径（`/` `/proc` `/sys` `/dev`）与空字符；**不校验目录是否存在/可读**（避免用户提前配置还没建好的目录被卡死）。前端点「保存」时先跑一遍同口径的本地校验并**逐行**报错，后端 `validateTargetDirString` 兜底 400。
  - **触发分析时**：实测目录存在、可读且非特殊系统路径，不满足返回 `TARGET_DIR_NOT_CONFIGURED` / `TARGET_DIR_UNREADABLE` 并附前往 AI 设置引导。
- **配置交互（2026-11-16 用户两次拍板后的最终形态）**：
  - **默认目录**：块级草稿 + 显式「保存」+「清除」—— 目录是长路径（通常靠粘贴），逐字符落盘会把半截路径写成配置；未保存草稿**不会被其它字段的保存回传基线冲掉**（后端 `targetDirs` 签名变化时才覆盖本地草稿）。
  - **scope 映射行**：**即时保存** —— 选完 scope（该行路径已合法时）立即落盘、路径输入**失焦**时落盘、点 × 删行立即落盘；新增行填完点了「确认」= 加入并立即生效（不再需要全局保存）。
  - 行内校验失败只提示、**不落盘**（有非法行的整块不提交，其余改动留在草稿里，badge 显示「有未保存改动」）。
- **scope 选择（2026-11-16）**：映射行的 scope 用与「知识视图 / Token 访问范围」同一个可搜索下拉（`ScopeMultiPicker` 的**单选**模式）—— **已选值回显在输入框里**（不再另起一行 chips，行高从 60px 收到 32px），候选右侧只标「只读」（与"能不能读到代码"有关）；不在候选列表里的历史 scope 仍可保留。
- 若命中的目录恰好是 Git 仓库且当前存在 `headCommit`，分析结果与确认后的代码位置附带记录当时的 `commit` 标识；普通目录则记录 `commit: null`。

### R2 事件「描述」功能区（新增）

- `EventRecord` 新增可选字段 `description?: string`（上限如 4000 字符，纯文本/Markdown）。
- **新建事件弹窗（`NewEventModal`）**：标题下方增加可选「事件描述」多行输入框。
- **事件详情页（`EventsPage`）**：事件头与阶段线之间增加「事件描述」展示与就地编辑区（受 `knowledge.write` 门禁，支持保存并发版本号校验）。
- 兼容存量事件：无 `description` 字段按空处理，不阻塞展示与分析。

### R3 「AI 分析」独立配置域与完整配置页面（对齐「AI 对话」布局）

- **数据隔离（`prompt-config.ts`）**：新增独立配置域 `analysis`（平滑兼容承接既有 `analysisPrompt`，老配置无损迁移，旧前端 `PUT` 缺键不覆盖）：
  - `targetDirs`：`{ defaultDir?: string; byScope: Record<string, string> }`
  - `prompt`：基础提示词 `{ content, at }`（内置默认改为对照真实字段：标题、描述、当前阶段进度、文档路径与名称）
  - `skills`：AI 分析专属 Skill 列表（含内置 `code-locate` Skill，支持启停、编辑、新增自定义 Skill、恢复默认；与 `chat.skills` 完全隔离）
  - `maxRounds`：工具轮次上限覆盖（默认 6，可选 1–12）
  - `maxFiles`：单次读取文件数上限覆盖（默认 8，可选 1–30）
  - `reasoningEffort`：思考级别覆盖（复用 `config.yaml` 的 `llm.reasoningEfforts` 档位）
  - `tools`：AI 分析可用工具开关（**全部为只读工具，默认全开**）
- **配置页 UI（`AiSettingsPage` + `PromptConfigLayer`）**：
  - 左侧导航「AI 分析」状态文案由 `未接入 · 提示词可预设` 更新为 `目录 · 提示词 · Skill · 工具`（`AiSettingsPage.tsx` 实际口径，比草案少一个「目标」字以保持与「AI 对话」同列宽）；
  - 右侧移除占位提示条，按「AI 对话」同款分组卡片依次呈现：**分析目标目录 → 基础提示词 → Skill → 分析预算 → 思考级别 → 工具与权限**；
  - **工具与权限** 分两组展示，全默认开启、即时保存，**绝不出现任何写/删工具**：
    - 源码只读（AI 分析专属）：`fs_read`、`fs_grep`、`fs_find`、`fs_ls`
    - 知识库只读（读取上下文中文档正文）：`ki_get_module_info`、`ki_search`、`ki_group_list`、`ki_tag_list`
  - 保留 `use_skill` 工具依赖联动校验：关掉 `fs_*` 等核心工具时提示并联动停用依赖它的 Skill。

### R4 专属只读文件工具与路径沙箱

- **作用域隔离**：`fs_read / fs_grep / fs_find / fs_ls` 仅注册在 AI 分析执行器使用的内部工具集，**不注册进 `CHAT_MCP_TOOLS`，不暴露给 `/mcp`**。
- **工具定义与硬上限**：

| 工具 | 参数 | 上限与安全行为 |
|---|---|---|
| `fs_read` | `path`, `offset?`, `limit?` | 单次 ≤ 200 行 / ≤ 64 KB；超出截断并明确标记 `truncated: true` |
| `fs_grep` | `pattern`, `path?`, `glob?` | 最多返回 60 条 `file:line` + 行内容（截断 ≤ 200 字符）；跳过 `.git` / `node_modules` 及前 8KB 含 `\0` 的二进制文件并计数 |
| `fs_find` | `name`, `path?` | 最多返回 80 条相对路径；自动忽略 `.git` / `node_modules` |
| `fs_ls` | `path?` | 最多返回 200 个目录项（区分文件/目录） |

- **沙箱边界**：所有入参路径必须拒绝绝对路径、`..` 穿越、含 `\0` 字符；经 `fs.realpathSync` 解析后必须仍位于当前分析配置的目标根目录内（`isInside(realRoot, realTarget)`），任何符号链接逃逸返回结构化错误 `OUT_OF_ROOT` 且不回传目录存在性。

### R5 分析上下文构建与异步 Pipeline

- **前置门禁（触发即校验）**：
  1. 权限：`knowledge.write` + scope 访问权；
  2. 合规与模型：`resolveLlmStatus` 必须满足 `enabled === true`、`supportsTools === true`、`kbDisclosureAck === true`（否则返回 `DISCLOSURE_REQUIRED` / `LLM_UNAVAILABLE` / `TOOLS_UNSUPPORTED`）；
  3. 目录与工具：已解析出可读目标目录，且配置中至少开启 1 个 `fs_*` 工具（全关直接拦截提示，不烧 token）；
  4. 频控：单 scope 每日分析次数上限（默认 50，可配）。
- **已收口事件放行**：无论 `closedAt` 是否为空，均可发起分析与保存代码位置。
- **上下文组装（轻上下文原则）**：
  - 系统侧：AI 分析「基础提示词」+ 启用的分析 Skill 目录（`use_skill` 按需加载正文）+ 不可覆盖的「结构化输出与防注入约束尾块」；
  - 用户侧（事件上下文）：
    1. 事件基础信息：`#${shortId} ${title}`、事件类型名；
    2. **当前阶段进度状态**：当前阶段名、阶段序号/总阶段数、是否已收口、阶段流转摘要；
    3. **事件描述**：若填写了 `description` 则原样注入（数据块包裹），未填写标注「（无描述）」；
    4. **关联文档清单与参考文档清单**：**仅列每篇的 `group` 路径 + 文档名**（区分「关联文档」与「参考文档」），**不直接展开正文**；提示 AI 如需查阅文档内容，自行调用 `ki_get_module_info`（或 `ki_search`）。
- **异步运行与过程记录**：
  - 创建/更新 `.events/{eventId}.analysis.json` 为 `status: 'running'` 后立即返回，后台受硬预算约束执行（默认 6 轮、8 文件、总超时 90s）；
  - 每轮真实发生的工具调用（`fs_*`、`ki_*`、`use_skill`）均记录真实工具名、入参摘要、命中计数、耗时，供前端轮询与过程折叠面板实时/完成后展示；
  - 汇总生成候选后，后端必须用目标目录文件做 **二次存在性与行号校验**：文件不存在或行号越界直接剔除，并在 `unconfirmed` 附说明；
  - **可手动停止（2026-11-16 用户要求「弹窗里要有停止按钮」）**：`POST /api/governance/events/:id/analysis/cancel` 只置标记 + `abort`（幂等，未运行返回 `canceled:false`），**终态仍由后台任务自己落盘**——有候选落 `partial`，无候选落新增的 `cancelled` + `ANALYSIS_CANCELED`。不复用 `failed`：失败会把用户引向「去改配置」，而主动停止什么都没配错。
  - **并发口径**：同一 `eventId` 在 `running` 时禁止重复启动（返回当前运行中任务）；**不占有 KB 写锁，不与知识库导入/写入互斥**；KB 只读工具继续走 `OperationCoordinator` 的 `'read'` 车道。

### R6 草稿存储、确认与 `ki_event_list` 透出

- **存储隔离（`.events/{eventId}.analysis.json`）**：与 `{eventId}.json` 和 `{eventId}.refs.json` 分文件存储，避免流转/改描述/加引用并发覆盖；`deleteEvent` 时联动删除。
- **状态模型**：
  - `draft`（可选，待确认草稿）：`{ status: 'running' | 'ready' | 'partial' | 'failed', errorCode?, errorMessage?, targetDir, commit?, candidates: [{ id, file, line, endLine?, snippet, why, confidence }], unconfirmed: string[], steps: [...], stats: { turns, filesRead, tokens, ms }, createdAt, updatedAt }`
  - `confirmed`（已确认代码位置列表）：`[{ id, file, line, endLine?, snippet, why, confidence, targetDir, commit?, confirmedAt }]`
- **确认与操作**：
  - 用户可在草稿中选择任意候选（复选框勾选）→ 确认追加写入 `confirmed`，支持整份丢弃草稿、支持对已确认位置单条移除；
  - 若旧草稿存在未处理的 `ready/partial` 候选，再次点「AI 分析」时提示确认是否覆盖旧草稿；
  - **不做自动采纳**，必须经过人工确认。
- **消费方透出（Q5）**：
  - `GET /api/governance/events/:id` 返回 `analysis`（含 `draft` 摘要/完整态 + `confirmed`）；
  - `ki_event_list` 返回体在每个事件上增加已确认代码位置精简列表（如 `codeLocationsPreview` + `codeLocationTotal`，控制上限防爆上下文）。

| # | 场景 | 期望行为 |

| N1 | 未配置当前 scope 分析目录也无默认目录 | 弹窗/接口拦截返回 `TARGET_DIR_NOT_CONFIGURED`，给出直达「AI 设置 → AI 分析」按钮 |
| N2 | 配置的目录恰在托管 Git 数据源 `clone/sync` 中 | 检查是否正在同步中，若正在 `git reset --hard` 提示「目标仓库正在同步中，请稍后再试」（不阻塞 KB 其他写入） |
| N3 | 分析中用户切页或关闭弹窗/浏览器 | 后端继续执行直至完成或 90s 超时落盘；重进事件页从 `.analysis.json` 恢复「进行中」或「待确认草稿」状态 |
| N4 | 配置中把全部 `fs_*` 工具关闭后点分析 | 入口前置拒绝，提示至少开启一个只读文件工具，不调用 LLM |
| N5 | 未确认 `kbDisclosureAck` 或 LLM 未配置 / 不支持工具 | 返回 `DISCLOSURE_REQUIRED` / `LLM_UNAVAILABLE` / `TOOLS_UNSUPPORTED` + 引导前往设置 |
| N6 | 10 万文件大仓或 grep 命中二进制 | 跳过 `.git` / `node_modules` 及前 8KB 含 `\0` 的二进制文件并计数；严格受 60 条与 90s 总预算控制 |
| N7 | 代码注释或文档中含 Prompt 注入文本 | 所有代码片段与文档正文均以数据块包裹，且输出解析与二次文件路径校验在系统层强制执行 |
| N8 | 事件没有任何文档与描述，仅标题 | 正常注入标题、阶段进度与空清单提示，标注线索较少，AI 可自主用 `ki_search` 或 `fs_find` 探索 |
| N9 | LLM 幻觉出不存在的文件或越界行号 | 后端二次校验 `realpath + 行数`，无效候选剔除并在 `unconfirmed` 留痕 |
| N10 | 草稿确认时事件已被删除 / 只读用户操作 | 确认接口校验事件存在性（不存在报 `EVENT_NOT_FOUND`）；只读用户按钮禁用且 API 返回 403 |
| N11 | 分析进行中用户点「停止」 | 立即 abort 当前上游调用、不再发起新轮次；已完成的步骤与候选保留（有候选 → `partial`，无 → `cancelled`）；重复点幂等不报错；状态与 `failed` 严格区分（详情徽标显示「分析已停止」而非「分析未完成」） |

## 7. 验收标准

| # | 验收项 | 判定方式 |
|---|---|---|
| A1 | 在「AI 设置 → AI 分析」配置 scope 目录、修改提示词/Skill/预算/开关，刷新后完整保留且**完全不影响「AI 对话」** | 单测 + 手工 |
| A11 | 默认目录走显式「保存」（点前不落盘、badge 显示「有未保存改动」）；scope 映射行**即时保存**（选 scope / 路径失焦 / 删行 / 新增行点「确认」后立即生效）；校验（相对路径 / 系统路径 / scope 重复）失败被拦下且逐行给出原因，且**不落盘**；编辑中途清空某行不会删掉已保存的映射；PUT 失败时 badge 显示「保存失败」而不是「已配置」 | 单测 + 手工 |
| A12 | 面板模式（对话配置层）关层时若有未保存目录草稿 → 二次确认「保存并关闭 / 取消」，校验失败不关闭。**已知取舍**：AI 设置页是文档流页面（`hideHeader`），浏览器返回 / 顶栏「返回」直接路由跳转，拦不住 —— 块内 hint 已明示「未保存就离开会丢失」 | 单测 + 手工 |
| A13 | 运行中点「停止」→ 1~2s 内落 `cancelled`（有候选则 `partial` 并保留候选），弹窗标题「分析已停止」、事件详情徽标「分析已停止 · 查看」；未运行时的 cancel 幂等返回 `canceled:false` 且不改状态；停止后不再产生上游 token | 单测 + 手工 |
| A2 | 触发分析前，未配目录 / 未过 `kbDisclosureAck` / 工具全关均被拦截并给出直达设置引导 | 单测 + 手工 |
| A3 | 上下文中仅含事件标题、描述、阶段进度与文档 `group/name` 清单（不含正文）；AI 实际调 `ki_get_module_info` 读取文档正文后再调 `fs_*` | 集成测试（断言上游 messages 与工具调用序） |
| A4 | `fs_read('/etc/passwd')`、`fs_read('../../etc/passwd')`、根外 symlink → 全部 `OUT_OF_ROOT`；>64KB 文件截断标记；`CHAT_MCP_TOOLS` 与 `/mcp` 不含 `fs_*` | 单测 |
| A5 | 触发分析后立即切换页面/关窗，后端异步完成落盘 `.events/{eventId}.analysis.json`，重进事件页可见草稿与步骤时间线 | 集成测试 + 手工 |
| A6 | AI 幻觉路径或越界行号在落盘前被二次校验剔除并记入 `unconfirmed` | 单测 |
| A7 | 草稿可勾选确认写入 `confirmed`（或丢弃）；已确认结果在事件详情与 `ki_event_list` 可见；`deleteEvent` 联动删除 `.analysis.json` | 单测 + 手工 |
| A8 | 已收口事件允许触发分析与确认代码位置；事件分析期间不阻塞同 scope KB 写入/导入 | 单测 |
| A9 | 新建与编辑事件均支持可选「事件描述」，保存与刷新一致 | 单测 + 手工 |
| A10 | 90s 超时返回 `partial` + `TIMEOUT` + 已完成部分；只读用户禁止触发分析、确认位置与改配置 | 单测 |
