# 实施计划：知识地图图集（一期）

设计基线：`design/DESIGN.md` + `S01`~`S05` ｜ 骨架冻结 commit：**无**（不走骨架链）
执行方式：**单窗口串行**（5 个工作项，共享面集中在内核，并行收益吃不过协调成本）

**任一批未过检查点不进下一批**（尤其第 2 批的路由覆盖率——它是「漏登记即 404」的唯一自动防线）。

## 4. 执行方式

单窗口串行，按 `PRE → S-01(+S-05) → S-02(+S-03) → S-04` 连做。

不启用多窗口并行的理由（三选一满足即够）：
1. 工作项只有 5 个，且**共享面（内核）占 1/5**，骨架前置量占比偏高；
2. 第 2 批虽可并行，但两片都小（S-02 约 3 文件 + 2 路由；S-03 约 2 文件），切窗口成本高于收益；
3. 需求契约虽已稳定，但**根砖头 S-01 的行为是其余两片的验收对象**（mock 内核只能验路由、验不了校验链），并行时依赖方仍要等真实实现。

## 5. 风险与回滚

| 风险 | 触发信号 | 处置 |
|---|---|---|
| zip 解析在真实包上失败 | 第 1 批冒烟报 1401/1407 而包来自 `pack_atlas.py` | 抓该包入 `demo/verify/` 作回归样本；必要时降级引入 `yauzl`（改 D2，需拍板） |
| 路由覆盖率测试红且原因不明 | 第 2 批检查点 | 先看 `route-permissions.ts:9` 的枚举逻辑，别改测试迁就实现 |
| iframe 内抽屉打不开 | 第 3 批真机 | 回看 `sandbox` 是否四件套齐全（验证报告 A4） |
| 页面出现裸 JSON | 第 3 批走查 | 查是否先 status 再建 iframe（验证报告 A3） |

**回滚**：一期只新增文件 + 3 处挂载（`bin/ki.mjs` 一行、`routes.tsx` 一条、`AppShell.tsx` 一项）+ 2 条路由登记，逐项可独立 revert；`.atlas/` 目录为纯新增，删目录即回到无图集状态。
