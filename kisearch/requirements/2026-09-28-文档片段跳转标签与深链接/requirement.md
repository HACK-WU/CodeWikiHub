# PM 报告：Markdown 在线编辑与段落跳转

模式：M1 需求定义（严谨档：涉及文档编辑、阅读、导航、权限与持久化）。

证据声明：现状最高为 🟢 代码直读；未运行浏览器，具体视觉与点击体验未经实测。下文以「用户描述」「🟢 代码实证」「假设」区分来源。用户已确认核心范围与索引取舍，产品实现正在独立工作树进行；需求验收尚未完成。

## 1. 执行摘要

- 🟢 用户要解决的是从阅读中的一个知识片段，直接进入其相关资料或目标段落，并保留原阅读位置。目标分为公网地址、本文位置、KiSearch 其他文档、其他文档的位置四种；用户明确要求点击后新开页面。
- 🟢 现有 Markdown 链接已支持外部 HTTP(S) 新页打开；本地 `.md` 链接会在当前抽屉切换文档。`#片段` 在解析本地文档时被丢弃，抽屉状态不在 URL 中；目前没有可复用的文档段落深链接。
- 🟢 最小可用功能是「选中源片段或段落 → 指定目标 → 看见链接标记 → 单击新页直达」，并能在文档刷新、导入更新后明确识别失效目标。仅给链接加 `_blank` 不能完成这条链路。
- 用户确认旧 Markdown 链接维持现状，只有页面新增的跳转链接在新页打开。首期仅交付两项能力：①当前 Markdown 的在线编辑与预览；②从文字、标题或段落创建跳转链接，目标可为外网、本文段落、其他文档或其段落。段落笔记/批注（原 R11）已取消。保存界面增加「保存时向量化」选项，默认关闭；关闭时所有正文/链接修改写 FTS-only，开启时写 dense 向量。`sourceDir` 可选：已配置时严格核验源文件子路径、KB Group、文件名与 KB 文档名；未配置时跳过源文件校验，只提示本次不会写回源 Markdown，允许保存 KB 正文。已配置但校验不通过时拒绝写错文件。均不另跑导入。仅写 KB 的修改不保证随原 Markdown 跨环境迁移。

## 2. 场景与现状

### 2.1 使用场景

| 场景 | 触发与用户动作 | 完成状态 |
| --- | --- | --- |
| 查证外部依据 | 阅读一段结论，点该段的「原始规范」标签 | 新页打开外部网页；原文阅读页保留位置 |
| 跳回本文说明 | 读到例子时点「参数定义」 | 新页打开本文相应标题/段落，而非回到文首 |
| 串联知识库文档 | 读课程概览时点「下一节」 | 新页打开同 scope 的另一篇文档 |
| 精确引用其他文档 | 读故障手册时点「恢复步骤」 | 新页直达另一篇文档指定位置，避免再手动查找 |

场景关系：以上四项是跳转链接的并行目标类型，不增加独立功能。主要角色暂按知识库维护者（添加链接）和读者（点击）分析。

### 2.2 已有能力与缺口

| 判定 | 现状与证据 |
| --- | --- |
| 🟢 已有 Markdown 外链 | `web/src/components/MarkdownPreview.tsx:344-351`：安全 scheme 判定后，HTTP(S) 链接生成 `target="_blank" rel="noopener noreferrer"`。|
| 🟢 已有相对文档链接 | `web/src/lib/documentLinks.ts:26-99` 解析 `.md`/`.markdown`；`BrowsePage.tsx:284-298` 与 `SearchPage.tsx:152-165` 将其切换为当前抽屉的文档。|

现状流程：`读文档 → 点相对 .md 链接 → 当前抽屉替换内容`；位置片段与页面状态未保留。

预期流程：`选中片段/段落 → 添加目标与显示文案 → 保存标签 → 读者点击 → 新页加载指定 scope/文档/位置`；原阅读页和滚动位置保留。

### 2.3 产品形态判断

「标签」在这里应表现为附着在文字、标题或段落上的**可点击引用**，而非现有 relation.tags（用于分类/筛选的文档级标签）。建议 UI 文案使用「添加跳转链接」或「添加引用」，避免与 Tag 过滤混淆。

**D1（原决定，已由后续要求修订）**：用户最初选择 KiSearch 独立标注层、不改 Markdown；跨环境只导入同一批 Markdown 的要求使这种方式不够。随后曾提出写回源 Markdown 并重新导入；该步骤又明确改为直接同步 KB，不再另跑导入。

**D3（已由 D6 修订）**：原先要求每次编辑前必须找到并校验源 Markdown，再同步源文件与 KB。当前规则以 D6/D7 为准：`sourceDir` 未配置不阻止编辑；已配置时仍严格校验文件映射。保存不另跑 `ki import`；是否生成 dense 向量由每次保存的「保存时向量化」选项决定，默认关闭，写入 FTS-only。

**功能结构：在线编辑与预览、跳转链接与段落定位**。编辑器负责修改已打开的 Markdown 文档并预览；工具栏支持在选区、标题或段落插入跳转链接，目标可以是文档或指定段落。两项能力共用文档加载、版本冲突与保存反馈；源文件映射检查和跨环境迁移能力取决于是否配置 `sourceDir`。首期采用 Markdown 源码编辑 + 预览，不扩展富文本编辑或段落笔记/批注。

**sourceDir 配置边界与条件校验**：现有写回目录按 `group-index.json` 的 `source.dir` 优先、`scopes.<scope>.wikiSync.sourceDir` 兜底（`src/lib/wiki-sync.ts:44-58`）；旧的 `scopes.<scope>.sourceDir` 已废弃且会被忽略（`src/lib/config-schema.ts:122-125`）。两处均未配置时，跳过源文件路径和文件名校验，提示「未配置 sourceDir：源 Markdown 不会变化；后续用旧源重导可能覆盖本次修改」，但允许编辑和保存；保存索引类型由「保存时向量化」选项决定。已配置时，每次保存前从当前 KB Relation 的 `sourcePath` 唯一定位源文件，realpath 检查目标仍在配置根目录内，再核验文件子路径 ↔ KB Group、**文件名 stem ↔ KB 文档名完全一致**，并确认文件存在且可写；不一致则阻止写入，不猜路径、不新建同名副本。即使既有导入允许别的命名形式，也不豁免已配置模式的校验。若已同步的 `source.dir` 指向旧环境路径，不能静默写到备用目录或按 `group/relation` 新建另一份文件。未配置模式没有更新源 Markdown；跨环境只导入原文件时无法恢复本次编辑或新增链接。以后才配置 sourceDir 时，先比较当前源文件与 KB 已保存正文；有差异则提示人工合并，不自动用任一版本覆盖另一版本。

**实现参考与边界**：仓库当前注册的相关 MCP 工具是 `ki_edit_relation` 和 `ki_sync_relation`，没有找到 `ki_edit_sync_relation`。`ki_edit_relation` 的草稿、版本校验、清洗切分、FTS locator 与索引发布流程可供在线编辑复用；目标模式由每次保存选择覆盖。现有 Wiki 写回按 `group/relation` 组目标路径并整篇覆盖，不保证命中导入时的 `sourcePath`，不能直接复用。

**搜索影响**：默认关闭向量化时，保存的正文与跳转链接均更新 FTS-only，不进入 dense 语义/混合召回；勾选向量化时写 dense 索引并维持 dense 召回。

| 流程 | 保存结果 | 其他环境只重导 Markdown | 约束 |
| --- | --- | --- | --- |
| 已配置且校验通过 | 源 Markdown 与 KB 同步；按选项更新 FTS-only 或 dense | **可恢复本次编辑与跳转链接** | 源文件、KB、索引状态都反馈 |
| 未配置 | 提示源文件未更新；KB 仍可保存，按选项更新 FTS-only 或 dense | **不可通过原 Markdown 恢复** | 用旧源重导可能覆盖修改 |

**已确认 D2**：旧 Markdown 链接保持原有点击行为；只有用户在页面新增的跳转标签才强制新开页面。此区分也意味着不能仅把新增标签写成普通 Markdown 链接：现有渲染器无法从语法上识别它是否为「页面新增」。

**已确认 D4**：首期只做在线编辑与预览，以及跳转链接和段落定位；采用 Markdown 源码编辑与预览，不扩展富文本编辑。

**已确认 D5（取消 R11）**：段落仅作为跳转链接的来源或目标位置；不创建、显示、保存或搜索段落笔记/批注。

**已确认 D6（修订 D3）**：`sourceDir` 不再是编辑前置条件。未配置时只提示并跳过源文件校验，允许保存 KB 正文；FTS-only 或 dense 索引由保存时选项决定。已配置时保持路径、Group、文件名与 KB 文档名的严格校验，失败时拒绝写入源文件和 KB。

**已确认 D7**：保存时提供「是否向量化」选项，默认关闭。关闭时正文与跳转链接保存到 FTS-only；开启时发布 dense 向量。FTS-only/dense 模式切换沿用现有索引发布流程，确保旧索引在新索引成功后清理。

R1 的「选择文字」是入口语义，不预设字符级永久锚点；第一期建议将其附着到唯一段落/标题。若用户要求精确到任意字词且原文变化后仍可靠，需单独评估更高成本的锚点模型。

### 3.2 负向需求

| ID | 异常场景 | 检测、恢复与用户反馈 |
| --- | --- | --- |
| N1 | 输入 `javascript:`、`data:`、`file:`、协议相对地址或恶意编码 | 创建时拒绝并指出允许的 HTTP(S) 或站内目标；渲染时仍做白名单校验，不能仅信任保存时校验。 |
| N2 | 目标文档被删、改名或移动 | 新页显示「文档不可用/已移动」和返回知识库入口；源标签标记失效，不跳到同名错误文档。 |
| N3 | 来源或目标段落被修改、重复或移除 | 有唯一可信重定位才展示来源标签或滚动到目标；否则将标注标为待修复，或打开目标文档并提示「未能定位到原位置」，提供重新选择入口。 |
| N4 | 同名文档、跨 scope 同名文档或列表被截断 | 以明确文档身份和 scope 定位；目标选择器显示 group 路径；不能靠 basename 猜测目标。 |
| N5 | 无权限访问目标 scope 或编辑标注 | 不渲染目标内容；编辑操作拒绝并给原因；跨 scope 链接不得利用本地已选 scope 绕过权限。 |
| N6 | 编辑过程中切页、断网或并发修改 | 未保存时有状态提示；保存失败可重试且不丢输入；冲突时提示刷新并保留待提交内容。 |
| N7 | 浏览器阻止新页或外站不可达 | 使用真实链接触发用户点击；无法打开时提供「复制链接」；外站不可达由新页处理，源页不丢状态。 |
| N8 | 已写回源文件后重导改变 group/relation，或源文件缺少链接元数据 | 用文件内元数据恢复链接，不依赖旧环境的关系 ID；元数据缺失时明确显示未发现链接，不从相似文档猜测。未配置 sourceDir 的 KB-only 修改不适用此恢复承诺。 |
| N9 | 已配置 sourceDir 时，外部编辑器也修改了 Markdown，或源文件只读/不在本机 | 保存前比较文件版本；冲突/不可写时拒绝覆盖并保留未提交内容，给出可重试或导出路径。未配置 sourceDir 时不尝试源文件写回。 |
| N10 | 已写回源文件后，外部 Markdown 工具清理未知元数据，或导出时叠加 frontmatter | 导入时校验链接数据；不兼容时说明丢失原因；用「添加链接 → 导出/复制修改后的源文件 → 空白环境重导」验证往返保真，不能仅做本机回读测试。 |
| N11 | 已配置 sourceDir，但文件子路径、KB Group 或文档名不匹配 | 在任何文件/KB 写入前 fail-loud；展示配置根、KB 身份与实际文件位置，并指明需重新配置或修正文档映射。未配置 sourceDir 时只提示，不触发该拒绝。 |
| N12 | 已配置 sourceDir 时，在线编辑期间源文件被外部编辑器修改 | 通过加载时版本与保存前版本比较检测冲突；保留编辑内容，提供查看差异/重新加载后重做的路径，不静默覆盖。 |
| N13 | 用户开启向量化，但 dense 写入或旧索引清理失败 | 显示索引发布阶段与状态，保留草稿并允许重试；不能提示保存和向量化均成功。 |
| N14 | FTS-only 更新失败，或应写入的源文件/KB/FTS 只成功一部分 | 显示每个适用写入面的状态与失败阶段；保留草稿并允许重试；不能显示整体保存成功。未配置 sourceDir 时源文件为「未配置、不适用」，不计作写入失败。 |
| N15 | 未配置 sourceDir 的 KB-only 修改遇到旧源重导，或随后配置 sourceDir | 保存时提示旧源重导可能覆盖修改；后来配置源目录时比较源文件与 KB 正文，若有差异则提示人工合并，不自动以任一版本覆盖另一版本。 |

## 4. 优先级判断

| 优先级 | 条目 | Kano 分类 | 价值 | 成本 | 证据与排序理由 |
| --- | --- | --- | --- | --- | --- |
| P0 | R1 创建/管理跳转标签 | 必备 | 高 | 高 | 用户提出的核心动作；缺少就无法建立知识连接。 |
| P0 | R2 四类目标 | 必备 | 高 | 中 | 用户明确点名四类场景，任缺一类则目标未满足。 |
| P0 | R3 新页打开 | 必备 | 高 | 中 | 用户明确指定，且保留阅读上下文是主要价值。 |
| P0 | R4 稳定深链接 | 必备 | 高 | 高 | 新页需冷启动，缺少它会打开列表或文首，不能完成精确跳转。 |
| P1 | R5 预览与反馈 | 期望 | 中 | 中 | 降低误连与定位成本；可在核心链路后完善。 |
| P0 | R7 失效提示、生命周期与权限 | 必备 | 中 | 高 | 失效链接不能误导，且新存储不能越权；首版可靠性门槛。 |
| P1 | R6 可信自动重定位 | 期望 | 中 | 高 | 能减少维护工作，但首版可先明确提示并引导修复。 |
| P0 | R8 按保存选项更新 KB 与 FTS-only/dense，按配置写回源文档 | 必备 | 高 | 高 | 默认全文可检索；用户选择向量化后保留语义/混合召回能力。 |
| P0 | R9 已配置 sourceDir 时的路径/名称一致性门禁 | 必备 | 高 | 中 | 配置存在时必须防止错误映射写坏另一文档；未配置时仅提示并允许 KB-only 保存。 |
| P0 | R10 在线编辑器 | 必备 | 高 | 高 | 用户将在线编辑与预览确认为首期能力；跳转链接与段落定位在此基础上完成。 |

P0 的高成本条目因属于用户明确目标或实现该目标的必要条件而列为交付门槛；优先级并非估算工期。建议先做「文档与标题/段落级定位 + 独立阅读页」，再扩展任意文本范围与跨 scope。

## 5. 待确认清单（一个决策包）

1. **位置粒度**：标题/段落是否满足第一期，还是必须精确到段落中的选中文字？验证方法：提供一篇目标段落较长的真实文档与希望落点。
2. **scope 与共享**：是否要跨 scope、跨部署分享？验证方法：提供实际链接接收者、其授权方式及是否使用同一 KiSearch 实例。默认首版限定同一实例、同一 scope。
3. **编辑权限**：当前 Web 没有用户系统；编辑跳转链接是否沿用已有 token 写入权限，还是仅供本机维护者？验证方法：列出实际部署方式与需要编辑内容的人员。
4. **“本地页面”的边界**：本报告按「当前 KiSearch 文档中的位置」理解；若还包括 Dashboard/Search 等应用页面内的位置，需要另列目标类型。验证方法：给出一个具体的本地目标 URL 或页面名称。
