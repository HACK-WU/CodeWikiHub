# REQ-20261009-002 全屏阅读与AI对话协同及文档引用

> **合并来源**：用户在 2026-10-09 先后提出两条诉求——① 文档全屏后 AI 对话侧边栏被遮挡；② AI 输入框中应能删除已添加的选中文档内容。用户明确"他们是同一个需求"，故合并为一个需求包。
>
> **证据声明**：最高证据等级 `🟢` 代码直读（前后端契约、检索链路、会话落盘、可复用组件均已实读）；**未经运行实测**。涉及"挤不挤、好不好看"的观感判断为 `🔴`，不进结论区。

## 1. 背景与目标

**一句话目标**：让"读文档"与"问 AI"两个动作可以同时进行——用户全屏精读时能看见并操作 AI 面板，并能就当前文档（或其中的段落）直接向 AI 提问。

**用户工作流（H1，本次合并的依据）**：

```
全屏读文档 → 对某段内容有疑问 → 面板就在旁边 → 把该段/该文档加入提问 → 追问
                    ↑ 需求 A：全屏时面板不被隐藏/遮挡
                                        ↑ 需求 B：输入框可引用文档段落且可删除
```

**价值判断**：现状把"全屏精读"与"AI 追问"做成互斥——用户必须退出全屏才能提问，而提问往往针对具体段落（退出后丢失阅读位置）。这是 AI 面板的核心场景之一，属**期望型需求**。

## 3. 用户拍板决策（2026-10-09）

| 编号 | 议题 | 拍板结论 |
|---|---|---|
| Q1 | 引用语义 | **A 软提示** —— 引用文档作为附加提示注入（"优先依据以下内容作答"），AI 仍可全库检索；**不改** `ki_search` 工具参数（不动失控面） |
| Q2 | 引用粒度 | **段落级**（可选中文档内某段/某片段） |

| Q4 | 入口形态 | **按钮 + 选择范式**，参考「添加链接」的交互：先点"添加到对话"按钮 → 再选中文档内容 → 自动添加；**不使用 `@`** |
| Q5 | 需求边界 | **与全屏遮挡问题合并**为一个需求包 |
| Q6 | 阅读器侧入口 | **纳入本次范围**（从全屏阅读器一键引用当前文档/选中段落） |

## 5. 负向需求

| 类别 | 场景 | 应有行为 |
|---|---|---|
| 误操作 | 手滑删掉正要用的引用 | 删除即时生效但不阻断（不引入确认弹窗）；可重开选择器再选 |
| 输入异常 | 中文输入法组合期 | 入口为按钮（不用 `@`），天然规避 IME 组合期误触发 |
| 中途放弃 | 提示词写一半去查文档再回来 | 草稿与引用都不丢（沿用"隐藏不卸载"语义） |
| 状态异常 | 引用文档在别处被删 | 发送时 fail-loud 指出哪条不可用；不整条失败且无解释 |
| 权限/跨域 | 切 scope 或打开跨 scope 会话 | 引用必须清空或标失效；**绝不把 A scope 的文档名发给 B scope** |
| 数据异常 | 引用段落超长 / 引用条数过多 | 有上限与截断提示（可配），不出现"引用 50 段导致请求超时" |
| 重复添加 | 同文档同段落被加两次 | 去重，不出现两个同名标签 |
| 外部依赖 | 模型不支持工具（`tools-unsupported` 降级） | 降级文案需说明引用如何被处理，不得让用户以为引用了却没效果 |
| 并发 | 生成中再次添加/删除引用 | 不破坏 `sendLockRef` 闸门与 `blocked` 判据 |

## 8. P0 验收门槛

1. 全屏阅读器打开后，AI 面板按用户此前的开/关状态呈现，且在全屏内可收发消息（R1/R2）。
2. 全屏阅读器覆盖层不再遮挡面板或其入口（R3）。
3. 输入框可添加文档段落引用、标签可单个删除（R7/R8）。
4. 引用的段落内容真实影响 AI 回答；无引用时行为与现状一致（R9）。
5. 切 scope / 切会话后引用清空，不出现跨 scope 文档名泄漏（R10）。
