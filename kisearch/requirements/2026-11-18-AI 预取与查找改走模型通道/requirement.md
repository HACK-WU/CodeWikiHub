# 需求：AI 预取与查找统一改走模型通道

- 需求 ID：REQ-20261118-004
- 状态：已确认
- 关联：REQ-20261118-003（已完成 `ki_recall` 的确定性通道版本，本需求将其改造为模型通道）
- 日期：2026-11-18

## 1. 背景

`ki_recall`（任务前上下文预取）与「AI 查找」目前都有两条通道：确定性 fast（不调模型）+ 深度 deep（模型工具循环）。

产品判断（用户 2026-11-18 拍板）：**确定性通道没有意义**。

- 它做的事是「抽关键词 + 调几次检索」，这件事调用方 agent 自己就能做，而且做得更好（它看得到完整上下文，服务端只能看 2000 字画像）。
- 保留它会导致「AI 查找」名不副实：用户点了 AI，拿到的是关键词检索结果（default 就是 fast）。
- 服务端再包一层不调模型的检索，只是多余的中间商。

因此两条通道**都取消 fast，只保留模型通道**。

## 2. 范围

| 项 | 内容 |
|---|---|
| 纳入 | `ki_recall` 改单通道；AI 查找取消 fast；AI 设置新增「AI 预取」页；两条通道同构（共用种子召回与装配）；文档与 skill 重写；事件 #38 收敛 |
| 不纳入 | 不改检索算法本身（`executeSearch`）；不做 Web 端的召回结果可视化；不改模型接入层 |

## 3. 需求清单

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| **R1** | `ki_recall` 单通道：种子召回 → 模型工具循环（至少读 1 篇正文）→ 产出清单 | P0 | 同一任务返回 ≥1 条候选或明确「没有」；不存在无模型路径 |
| **R2** | 返回体新增 `summary`（≤3 句结论）与 `uncertainties[]`（判断不了的点）；保留 `candidates` / `nextActions` / `needMore`。**两条通道只同构门禁与错误语义，内核各自独立**（不抽公共 core） | P0 | 0 候选时 `summary` 必须说明查了什么、为什么没有 |
| **R3** | 提示词硬规则：必须先读正文；宁少勿滥；读到的与背景不符要主动排除并说明；不许猜成结论 | P0 | 抽查 10 个任务，无「只凭标题判定」的候选 |
| **R4** | 再次 recall 机制：无会话状态，靠调用方传 `exclude`（已读清单）实现多轮 | P0 | 第二轮不重复推荐已读文档，且 `summary` 不复述上一轮 |
| **R5** | AI 查找取消 fast：删模式切换、默认 deep、删 `capabilities.findDeep` 与前端两处分支、`docs/ai-find.md` 重写 | P0 | `grep -rn "findDeep" src web` 为 0；面板无快速/深度切换 |
| **R6** | 无模型 / 未确认外发 / 不支持 tools → **直接不可用**，错误文案引导「改用 `ki_search` 自己查」 | P0 | 三场景各一条错误码与文案，均含 `ki_search` 指引；不降级、不返回空清单 |
| **R7** | AI 设置新增「AI 预取」能力页：基础提示词 / Skill / MCP 工具 / 上下文窗口 / 工具预算 / 思考级别，**完全复用 AI 查找页样式**；无「检索范围」块 | P0 | 改任一配置后下一次调用行为随之变化；页面无范围配置项 |
| **R8** | `ki_get_module_info` 在工具列表中**默认勾选且不可取消**（否则「必须读正文」无法实现） | P0 | 页面上该开关为锁定态 |
| **R9** | 运行参数：保留频控 20 次/分钟；**删除结果缓存与并发槽**；不加 Token 准入限制（只读 Token 可用） | P1 | 配置项从 5 个减到 2 个（频控 + 超时）；`RECALL_BUSY` 退场 |
| **R10** | 事件 #38 收敛：两条（快速通道不读描述 / 中文长句切词）随 fast 取消而消失，只留「文档过期」 | P2 | #38 更新或关闭 |

## 4. 负向需求

| # | 场景 | 要求 |
|---|---|---|
| N1 | 未配置模型 / 未确认外发 / 不支持 tools | 报错并引导 `ki_search`；不得静默降级、不得返回空清单冒充「没有」 |
| N2 | 模型读了正文但都不相关 | 返回 `candidates: []` + `summary` 说明查了什么；这是合法结论 |
| N3 | 45s 超时 | 返回 `partial` + 已得候选与已完成判断，不整体失败 |
| N4 | 频控打满 | `RECALL_THROTTLED` + `retryAfterSec` |
| N5 | 历史 `origin:'fast'` 的旧候选 | 枚举值保留，只停止产生新值（否则老数据渲染不出来） |
| N6 | 设置页把工具全关 | 明确报错（无工具可用），不静默返回种子 |
| N7 | 候选文档读不到（无权/已删） | 计入 `skipped`/`dropped`，不得当作「没有相关文档」 |

## 5. 关键决策

| # | 决策 | 被否决方案 | 理由 |
|---|---|---|---|
| 1 | 取消 fast，只保留模型通道 | 保留 fast 作降级 | 不走模型不如让 agent 自己 `ki_search`；保留会让「AI 查找」名不副实 |
| 2 | 无模型时**直接不可用**（不降级） | 保留 fast 作应急兜底 | 留着 fast 就会有人拿它当 AI 查找用 |
| 3 | 确定性检索保留为**内部种子召回**（≤20 条给模型），不再是对外通道 | 直接删掉 | 省 token、少空转，已有代码不浪费 |
| 4 | `summary` + `uncertainties` 进返回体 | 只给候选清单 | 清单不知道「整体结论」与「哪里不确定」，agent 要自己再总结一遍 |
| 5 | 多轮靠 `exclude`，**无会话状态** | 引入 `context_id` 续接 | recall 是"一次性召回"，续接会让它退化成 `ki_ask` |
| 6 | 设置页完全复用 AI 查找样式 | 新造一种「参数页」形态 | 复用零成本、心智一致；新形态要教用户重新理解 |
| 7 | `ki_get_module_info` 锁定勾选 | 允许取消 | 取消后「必须读正文」的硬规则无法执行 |
| 8 | 删缓存、删并发、保留频控、不加 Token 限制 | — | 缓存是运维参数不该上 UI；并发限制在低频场景无价值；频控是唯一有效护栏 |

## 6. 影响面

| 受影响功能/方 | 影响类型 | 程度 | 处理 |
|---|---|---|---|
| AI 查找面板 | 展示 | 破坏（少一个切换） | 移除切换与两处能力位分支 |
| 无模型环境 | 流程 | 破坏（功能不可用） | 明确错误文案 + 出路 |
| `prompt-config.json` | 数据 | 降级（新增 recall 域） | 缺字段=默认，不产生硬 issue |
| 历史 `origin:'fast'` 数据 | 数据 | 无感 | 枚举保留 |
| 只读 Token | 权限 | 降级（可用） | 从模型消耗型名单移除 |
| 事件 #38 | — | — | 收敛为单条 |
