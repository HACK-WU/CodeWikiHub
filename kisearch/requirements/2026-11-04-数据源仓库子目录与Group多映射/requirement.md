# 需求分析：数据源仓库子目录与 Group 多映射（页面入口）

- **来源**：用户 2026-11-04 原话（3 点）：
  1. 添加 Git 源这里，可以支持不同的仓库子目录，对应不同的 group 路径。（仅页面）
  2. 数据源详情页面，也要有对应的展示。
  3. 数据源编辑时，可以删除和增加仓库子目录到 group 路径的映射，但至少保留一个。
- **分析口径**：`product-manager`（M1 需求定义，一次成型档）。需求涉及**记录模型 / 同步链路 / HTTP 契约**变更，复杂度中高 ⇒ 需求定稿后转技术设计（`design-craft`），不直接开写。
- **证据声明**：最高 `🟢` = **代码直读** + **用户截图**。
  - 前端：`web/src/pages/DataSourcePage.tsx`、`web/src/components/DatasourceEditDialog.tsx`、`web/src/lib/dataSourceDetailModel.ts`、`web/src/api/httpApi.ts`
  - 后端：`src/lib/datasource.ts`、`src/lib/datasource-types.ts`、`src/lib/datasource-git.ts`、`src/lib/import-path.ts`、`src/lib/mcp-http-api.ts`、`src/lib/import-prune.ts`
  - **未运行产品**：体验（顺不顺）与视觉（好不好看）类判断标 `🟡`，不写成实测结论。
- **前置需求**：`REQ-20261021-003`（数据源 Git 增量同步与页面操作）确立「一个 scope 一条数据源、单子目录、单落点 Group」；`REQ-20261019-002` 确立落点推导唯一实现 `resolveGroupForSource`。

## 0. 已拍板口径（2026-11-04 用户逐条确认）

| # | 问题 | 结论 |
|---|---|---|
| Q1 | 「仅页面」的含义 | **页面是唯一配置入口**；后端（记录模型 / 同步链路 / HTTP 契约）必须配套改造才能生效；**CLI 不提供该能力**（见 Q4） |
| Q2 | 「只读」的边界（两个不同的"只读"，别混） | ① **scope 只读库**（权限）：只拦逐条写入（MCP 工具 / 上传 / 在线编辑），**数据源管理整体放行** —— 后端写入通道登记表把 `datasource-sync / add / add-remote / update / remove / schedule` 全列为 `EXEMPT_OPS`（`src/lib/scope-policy.ts:28-51`）⇒ **只读库对数据源同步与设置完全无影响，映射编辑不新增任何门禁**。<br>② **编辑弹窗「身份字段只读」**（UI 口径，**不是权限**）：当初只是"不让改"，避免旧文档留在旧 group 产生重复。本需求把「子目录 → Group 映射」改为可编辑，**不触及任何只读语义**；「仓库地址 / 分支」仍只读（换源要重置 clone 与 commit 水位，属另一件事）。改 Group 的重复风险提示保留 —— 那是**数据一致性**问题，与只读无关 |
| Q3 | 两个子目录映射到同一 Group | **允许**，但必须提示「多个子目录写入同一 Group，同名文件按同名策略处理」 |
| Q4 | CLI 支持 | **完全不支持**：不新增选项 / 子命令，`ki datasource add` 只能建 1 条映射。仅保留「读输出不撒谎」这一最低一致性要求（`ki datasource list` 需如实反映多映射，呈现方式由设计定） |
| Q5 | 某子目录在远端不存在 | **整个失败**，错误文案必须指明是哪个子目录 |
| Q6 | 映射数量上限 | **20 条**（超出判非法，提示「请拆成多个 scope」） |

## 1. 结论速览

| # | 结论 | 证据 |
|---|---|---|
| 1 | **「仅页面」不是"只改前端"**：一 scope 一条 `datasource.json`，记录只有单个 `git.relativeRoot` + 单个 `group`；页面即便提交多对映射，后端无处存、同步也不按它走。必须是「页面入口 + 后端配套」。 | `src/lib/datasource-types.ts:222-252`、`src/lib/datasource.ts:64-66`、`src/lib/mcp-http-api.ts:3424-3451`、`src/lib/datasource.ts:1411-1414` |
| 2 | **现状只覆盖了一半**：`子目录=docs` + `Group 留空` 时，`docs` 下每个顶层目录会自动变成同名 Group。新需求买到的是「Group 名 ≠ 目录名」与「只挑部分子目录」（不再被迫整仓库导入或只能选一个目录）。 | `src/lib/import-path.ts:73-77` |
| 3 | **「身份字段只读」是 UI 口径、不是权限，与 scope 只读无关**：只读库从来只拦逐条写入，数据源管理全部豁免（`EXEMPT_OPS`）。把「子目录 / 落点 Group」改为可编辑**不破坏任何只读语义**；真正要配套的只有一句告知「改 Group → 旧组文档保留并产生重复」。 | `src/lib/scope-policy.ts:28-51`、`web/src/components/DatasourceEditDialog.tsx:236-239,362-367`、`src/lib/datasource.ts:449-459` |
| 4 | **隐藏地雷：`seenRels` 基线是「相对 sourceDir 的裸路径」**。`docs/guide/a.md` 与 `docs/api/a.md` 都会记成 `a.md` → 基线撞名，增量与待删候选都会算错，可能把在用文档算成待删。基线必须改为 `subdir/rel` 分桶。 | `src/lib/datasource.ts:1332-1341`（`eligibleRels: prevSeen`）、`src/lib/import.ts:1156` |
| 5 | **CLI 单值写入口会静默压平多映射**（Q4 派生风险）：`ki datasource add --force` 现在只比较 `dir` / `group` 两个标量，对已有 3 条映射的记录会退化成 1 条。必须在 CLI 侧 **拒绝** 并指向页面（R9）。 | `src/lib/datasource.ts:444-459` |
| 6 | **待删候选与详情待删树已是「多 Group 集合」语义**，无需改造；「删除某条映射 → 旧文档进候选」天然成立。 | `src/lib/import-prune.ts:290-315`、`web/src/lib/dataSourceDetailModel.ts:349-362` |

## 4. 需求清单

| ID | 优先级 | 需求 | 预期效果 | 验收标准 |
|---|---|---|---|---|
| R1 | P0 | 记录模型支持 1..N 条「子目录 → Group 映射」，旧记录等价迁移（`version` 2→3） | 映射有地方落盘 | 旧 `version:2` 记录读入后等价 1 条映射；升级后首同步的文件数与落点与升级前逐项一致 |
| R2 | P0 | 添加弹窗：映射表替换原「仓库子目录 + 落点 Group」两字段，可增删行（默认 1 行） | 一次登记多个落点 | 可新增/删除行；≥2 行时**只导入被选中的子目录**（未选中目录不再进库） |
| R3 | P0 | 详情抽屉展示映射（只读表格） | 一眼看清「这份源写到哪几个组」 | 参数区出现两列映射表；`（仓库根）`、`自动：按顶层子目录` 有明确表达；本次同步所用映射 ≠ 当前登记时给提示 |
| R4 | P0 | 编辑弹窗可增 / 删 / 改映射，**至少保留 1 条** | 映射可演进，不必移除后重加 | 每行可改子目录与 Group；剩 1 行时删除按钮禁用并给文案；保存后**下次同步**生效 |
| R5 | P0 | 映射校验（就地报错、不阻塞提交） | 防重复导入 / 静默覆盖 | 见 §5 N1-N4；错误定位到具体行，保存按钮置灰，不发请求 |
| R6 | P0 | 映射上限 20 条（Q6） | 防超长表单与同步失控 | 第 21 行无法添加，提示「最多 20 条，请拆成多个 scope」 |

| R10 | P2 | 每条映射的已入库文档数（可选） | 判断哪条映射在产出 | 详情表每行显示该子目录文档数；旧快照无数据时显示「—」而非 0 |

## 5. 负向需求

| ID | 场景 | 期望行为 |
|---|---|---|
| N1 | 子目录 A 是 B 的父目录（`docs` 与 `docs/guide`） | **拒绝**并指出冲突的两行——同一文件会被导入到两个 Group，产生重复文档 |
| N2 | 「仓库根」行与其他行共存 | **拒绝**（根覆盖全部子目录，等价 N1） |
| N3 | 同一子目录出现两次 | **拒绝**（同一文件两次导入） |
| N4 | 删除最后一条映射 / 提交 0 行 | 删除按钮禁用 + 一句「至少保留 1 条映射」；不允许提交 0 行 |
| N5 | 多个子目录映射到同一 Group（Q3） | **允许**，但提示「多个子目录写入同一 Group，同名文件按同名策略处理」 |
| N6 | 某子目录在远端不存在（Q5） | **整源失败**，错误文案必须指明是哪个子目录；可预检时添加即失败（复用既有 clone 预检） |
| N7 | 同步进行中打开编辑 | 沿用既有口径：按钮置灰 + 「同步进行中，任务结束后可编辑」 |
| N8 | 改某行 Group / 删除某行后立刻同步 | 事前明示：改 Group → 旧组文档保留并产生重复；删行 → 该子目录文档进入待删候选（**不自动删**） |
| N9 | 只读库（Q2） | **不拦截**映射编辑 —— 数据源管理在写入通道登记表里整体豁免（`EXEMPT_OPS`），本需求不新增门禁、也不改只读判定；仅当缺少 `datasource.write` / `datasource.update` 权限时隐藏对应入口 |
| N10 | 同步过程中映射被别处改动 | 沿用 `revision` 冲突：`DATASOURCE_STALE` → 「配置已在别处修改，请关闭后重新打开」 |
| N11 | 旧版 daemon 不返回 `mappings` | 页面按单值 `git.relativeRoot` + `group` 降级展示为 1 条，**不显示空表**、置灰编辑（fail-loud，不做静默假功能） |

## 7. 关键假设

| ID | 内容 | 错了会怎样 | 验证方法 |
|---|---|---|---|
| A1 | 一个 scope 仍只有**一条**数据源，映射是它的子结构，不引入「多数据源并存」 | 模型与 `DATASOURCE_EXISTS` 语义整体改变，工作量翻倍 | `mcp-http-api.ts:3443-3451`（🟢 已核实） |
| A2 | 同名策略 / 切分 / 向量化等参数**全体共享**，不按映射单独设 | 编辑弹窗需重构成每行一个参数面板 | Q1/Q2 阶段已确认口径 |
| A3 | 映射语义 = 「扫哪些子目录」+「写到哪个 Group」；未选中的子目录**不再导入** | 若期望"未选中仍自动导入"，与现行为冲突，需另设"默认映射" | 添加 2 条映射后同步，检查未选中目录无文档 |
| A4 | 旧记录迁移后行为与升级前逐项一致（1 条映射 = 现状） | 已上线数据源可能涌现大规模待删候选 | 单测 + 真机对比同步结果 |
| A5 | 仓库地址 / 分支仍不可改（换源仍需移除重加） | 涉及 clone 复用与 commit 水位重置，超出本期 | Q2 已确认 |
