# 导入路径口径对齐与增量导入

> **父需求**：REQ-20260930-002（单 Scope 大规模数据存储与导入可用性）
> **依赖**：REQ-20261009-003 —— 其**实验 2** 已得出「对已存在数据再写一遍即触发引擎收尾 CPU 尾巴（≈660 单核秒）」「向量 id 是内容哈希，重导入时内容未变的片段 id 一致、本可跳过重写与重复 embedding（现状整批重写）」；本需求是把该结论落成产品行为。
> **关联**：REQ-20261009-001（部分成功可用 / 只重试未完成）—— 本需求**不得回归**其语义：文件级提交、未完成清单 `.ki-import-incomplete.json`、`onlyRelPaths` 子集重试。
> **证据**：本需求 `review/debug-report.md`（最小复现 + 生产数据核对 + 浏览器走查）。
> **模式**：PM 一次成型档（🟢 代码直读 + 实机实测；本报告不含 🔴 结论）。
>
> **v3 修订（2026-10-10）**：追加拍板 **D9**（CLI/Web 同默认 `incremental`）、**D10**（增量对同名一律**直接覆盖**，不引入后缀兜底 ⇒ 后缀模板只在 `suffix` 模式生效）。
>
> **v2 修订（2026-10-10）**：拍板 Q1~Q3 → 新增 **D6~D8**；**R3 定为「同名文档处理」下拉第一项且为默认值**（撞名兜底：v2 时拟用自动后缀，v3 按 D10 改为**直接覆盖**）；R6 由"待确认"升为 **P1 必做**（导入前提示+确认）、新增 **A10**；R7（剥离破坏面仅文档层记录）入清单。

## 1. 现状与根因

### 1.1 证据链（全部为运行时 / 磁盘实证）

| # | 证据 | 结论 |
|---|---|---|

**复现结果**

| 实验 | 结果 |
|---|---|
| R1 扁平目录导入 | 2 篇（`foo`→组=scope 名；`sub/x`→组 `sub`） |
| R2 同一目录**带目录名前缀**再导入（suffix） | 5 篇：`foo`+`foo_1`；`sub/x` 落成 `sub` 与 `<scope>/sub` **两份** ⇒ 翻倍；「处理单元」3/3 |

| C2 对照：新 scope 首次用 skip 导嵌套目录 | **skip=1、处理单元 3→2** ⇒ 跳过逻辑本身正常，只在「同 Group + 不同 sourcePath」触发 |

### 1.2 根因树

```text
{进度仍 15594 个处理单元 + 文档翻倍到 3741 + 出现 AGENTS_1 + 跳过"没生效"}
  ▼
{1884 篇被当全新文档写入新组树 ai-docs/*；skip 一次都没触发}
  ▼
{同一物理目录两种入口产出的 rel 起点不同}  ← 根本原因（入口契约不统一）
  ├─ Web 拖目录 / 目录选择器 / webkitdirectory 回退：rel = `<被选目录名>/…`（ImportPage.tsx:834、:787、:914）
  └─ CLI / 「选择文件」：rel = 扁平（无目录前缀）
  ▼
{groupPath 与 sourcePath 双双错位}
  ├─ 落点：`dirname(rel) || scope`（src/lib/import.ts:249-256）⇒ `aiops` vs `ai-docs/aiops` ⇒ 连"同名"都不成立
  └─ 幂等：`sourcePath` 不同 ⇒ 同 sourcePath 覆盖分支不命中
```

### 1.3 「跳过同名文件」为何全程未触发

| 情形 | 实际行为 | 结论 |
|---|---|---|
| 两次都走 Web（rel 都带前缀） | `sourcePath` 完全一致 → 命中**同 sourcePath 幂等覆盖**（`src/lib/import-conflict.ts:64-67`），**进不到策略分支** | 策略不适用 |
| 一次 CLI 扁平、一次 Web 带前缀（本次现场） | 落点组不同 ⇒ 连同名都不算（复现 R3：冲突 0 条） | 无策略可触发 |
| 唯一真命中同组同名的 `AGENTS` / `README` 2 篇 | 命中的是**同 sourcePath 幂等覆盖**（对 `_1`），优先级高于策略 | 策略仍不适用 |

**补充（同批重复 rel）**：同批内若两条 rel 相同（剥离后多目录同拖会产生），第二条会命中同一个「同 sourcePath 覆盖」分支 ⇒ **静默覆盖**（local KB 后者胜出、`relation.memoryIds` 只回填后者，前者 chunk 向量成为**搜得到但无归属的孤儿**，见 `src/lib/import.ts:1535-1544`）。

## 4. 负向需求

| # | 场景 | 要求 |
|---|---|---|
| N1 | 多目录同拖且存在同名文件 | 必须按用户所选策略处理，**不得静默覆盖**；覆盖时被覆盖者的原文与向量都不得残留（无孤儿向量） |
| N2 | 剥离后 rel 含 `..` / 绝对路径 / 空段 | 仍由后端 fail-loud 拒绝（前端不得放宽校验） |
| N3 | 仅"文件名 + 数量"相同、正文已改 | **不得判定为未变**（否则索引停留在旧正文，且无任何提示——静默陈旧） |
| N4 | 正文未变但 tags 变更 | 必须重做该文件的 tag 向量（tag 参与 docId） |
| N5 | 切分参数（chunkSize/overlap）或清洗规则变更 | 不得判定为未变 |
| N6 | embedding provider / model / 维度快照不匹配 | 不得跳过，走现有维度校验路径并显式反馈 |
| N7 | relation 存在但 local KB 缺原文 | 不得判定为未变（否则永久缺原文） |
| N8 | 增量开关下发生系统性向量故障 | 必须保持 REQ-20261009-001 的语义：文件级提交、未完成清单、`onlyRelPaths` 重试；跳过项不得进未完成清单 |
| N9 | 卡片引用的本地图片附件 | 文档与附件必须同规则剥第一段，相对引用不得失效 |
| N10 | 「选择文件」路径（无目录） | 无 `/` 的 rel 不得被剥离（避免把文件名削掉） |
| N11 | 剥离影响面提示 | 用户已选不剥离 → 无；**若改为剥离**，则在 UI/文档明确"被选目录名不再进入组路径，需要时请在 Group 路径里填" |

## 5. 验收标准

| # | 验收 | 判据 |
|---|---|---|
| A1 | 同一目录 Web 连续导入两次（剥离后） | 第二次：文档总数**不变**、无 `_1` 副本、无新增组根；第二次的「处理单元」随 R3 开关下降 |
| A2 | 多目录同拖 + 同名文件（剥后同 rel），三种策略 | skip → 后者跳过、先到者内容正确；suffix → `foo` 与 `foo_1` 两份内容各自正确；overwrite → 仅后者存在，**向量层无前者残留**（按 docId 核对） |
| A3 | 增量开关开、全部文件未变 | 「处理单元」（`progress.total`）不包含未变 chunk；结果中「未变 N 篇」计数 = 参与文件数；文档总数与 `memoryIds` 不变 |
| A4 | 增量开关开、改动 1 篇 | 仅该篇被重新切分/向量化；其余篇 `memoryIds` 逐字节不变 |
| A5 | CLI 回归 | `test:all` 中 import 相关套件全绿；`ki import` 行为与改动前一致 |
| A6 | 离开导入页再回来 | Scope/Group/同名策略/后缀/tags/切分参数清空、页头回「请选择并确认本次导入的 Scope」（**已通过：15/15 实机走查**） |
| A7 | 部分成功分支 | 切页回来仍保留「重试未完成 N 篇」入口与同一 uploadId |
| A8 | Web 与 CLI 同源 | 同一物理目录分别用 `ki import -s S --source <dir>` 与 Web 导入 → `sourcePath` 与组落点一致；再交叉重复导入**都不产生副本** |
| A9 | 附件 | 剥离后 `<img>` 相对引用仍可解析（`/api/asset` 200） |
| A10 | 重复导入预检（R6） | 导入前报出"N 篇与库中已有文档内容一致但 sourcePath 不同"，用户**可取消**；取消后不产生任何写入；确认后按策略继续 |
