# 场景推演结果：AI 对话证据回放与工具预算可配

> 推演时间：2026-10-15 · 推演对象：**设计文档模式** · 输入：`design/DESIGN.md` + `S01/S02/S03_*_DESIGN.md`（challenger 修订后版本）
> **证据性质**：本报告为**推演结论（基于文档推理，未实际执行）**，不构成执行性证据

## 1. 全局理解声明 + 角色清单

### 🌍 全局理解声明

- **业务目标**：消除持续对话中的重复检索与长文档截断，并让使用者按需调整工具预算
- **系统位置**：上游（用户提问 + 会话文件 + 对话配置）→ 本功能（`tool-loop` 消息构造 / 工具执行 / 配置读取）→ 下游（上游模型 + 前端展示 + 会话落盘）
- **整体成功判据（不可破坏的全局约束）**：
  1. 末条恒为本轮 user（`degradedPath` 的 splice 依赖）
  2. N17 反幻觉底线（无命中不得冒充知识库结论）
  3. `reasoning` 永不进 messages（N12）
  4. 旧会话 / 旧配置零报错
  5. 工具返回页面与模型共用同一份文本（N22）
  6. 界面改的值不写 `config.yaml`（REQ-20261014-001 裁决）
  7. 一轮内工具面与预算固定（生成期间不漂移）

### 👥 角色清单

| # | 角色 | 类型 | 职责 |
|---|---|---|---|
| 1 | 知识库使用者 | 用户 | 提问、增删引用、调整工具预算 |
| 2 | 上游模型（LLM） | 自动化程序 | 决定是否调工具、**自主传 limit**、生成回答 |
| 3 | 工具执行链（registry + executeSearch） | 自动化程序 | 参数解析、预算补全、执行、序列化 |
| 4 | 会话文件 | 自动化程序 | 落盘 / 读取 `progress`、`refs`、`compaction` |

## 3. 场景推演详情

### 🎬 场景 A：多轮追问同一文档（核心）

```text
{用户：第 1 轮提问 k8s Deployment}
  ▼
{模型调 ki_search（不传 limit）} ✅ 注入生效值 5
  ▼
{返回 5 条 → 落盘 progress（phase=end，含 response）} ✅
  ▼
{用户：第 2 轮追问 rollout 策略}
  ├─ {collectReplayItems：最近 5 轮} ✅ 收集第 1 轮 tool 证据（≈5K 字符 < 20000）
  ├─ {与本轮 refs 去重} ✅（本轮无引用，无剔除）
  └─ {拼接：问题 → 本轮引用块 → 证据块} ✅ 末条恒为本轮 user 保持
  ▼
{模型基于回放直接作答} ✅（预期收益）
  ▼
{第 3 轮起：第 1、2 轮证据同时回放，受双预算约束} ⚠️ 轮次编号在压缩后语义变化（见问题 2）
```

**数据走向**：`response(内存) → progress(落盘) → collectReplayItems → 证据块 → 本轮 user → 模型` 各跳均有设计 ✅
**设计点**：放置位置 ✅ / 双预算 ✅ / 末条不变量 ✅

### 🎬 场景 B：引用 + 删除引用 + 追问（核心）

```text
{第 1 轮：用户引用文档 A 片段并提问} ✅ refs 落盘（独立字段）
  ▼
{第 2 轮：引用仍在前端 pendingRefs 中（多轮携带）}
  ├─ {本轮引用块含 A} ✅
  └─ {历史证据中的 A 被第 5 步剔除} ✅ 不重复
  ▼
{第 3 轮：用户删除引用后追问"刚才 A 那段关于 X 的部分"}
  ├─ {本轮 refs 为空 → 第 5 步无剔除} ✅
  ├─ {历史轮次 A 作为 ref 证据回放（去重保留最早轮次）} ✅
  └─ {模型仍能看到 A 的原文} ✅ 缺口被补上
```

**设计点**：两级去重 ✅ / 引用归属与留存 ✅（这正是 R2 的目标场景）

### 🎬 场景 C：调工具预算全链路（核心）

```text
{用户：对话配置 → 工具预算 → 返回上限 20K、条数默认 8 → 保存} ✅ 写 prompt-config.json
  ▼
{下一次提问：resolveRuntime 读配置} ✅ budget = {20000, 8}
  ├─ {模型调 ki_search（未传 limit）→ applyBudgetDefault 注入 8} ✅（执行必经点，challenger 修订点）
  ├─ {模型显式传 limit=3 → 不覆盖} ✅
  ├─ {模型传 limit=100 → asInt 钳到 50} ✅
  └─ {返回 JSON 超 20000 → serializeToolResponse(…, 20000) 截断 + 标记} ✅
  ▼
{前端 tool_end.response.limit = 20000 → 文案"超过 20000 字符已截断"} ✅
```

**数据走向**：`prompt-config.json → readPromptConfig → runtime.budget → ①工具执行 ②返回序列化 ③证据单条有界` 三跳均被消费 ✅（无死字段）
**设计点**：注入点 ✅ / 默认值回归（未配置 = 5 / 10000）✅ / 上限钳制 ✅
**⚠️ 问题 1**：见下表——**两个旋钮的组合**未被防护。

### 🎬 场景 D：异常路径

| 异常 | 推演结果 |
|---|---|
| 旧会话（`progress` 无 `response`） | ✅ 逐条跳过，零报错 |
| 脏数据（`response = null`） | ✅ try/catch 降级为无证据（challenger 修订后） |
| 上游 400（消息过长） | ⚠️ **无兜底**，已登记 S-02 §10 Q5 |
| 旧 daemon 不返回新 limits | ✅ 前端降级提示（S-01 §3.6） |
| 生成中进程崩溃 | ✅ 无新增副作用（证据块只是内存态，未新增落盘字段） |

### 🎬 场景 E：压缩后回放 + 预算边界

```text
{会话 10 轮 → 用户手动压缩覆盖前 6 轮} 
  ▼
{下一轮：只遍历现存 messages（第 7-10 轮）} ✅ 已移出轮次天然不回放（压缩不被架空）
  ├─ {轮次编号从 1 重新计数} ⚠️ 见问题 2
  └─ {某轮 3 条证据共 30K > 20000 → 截断当前条 + 停止更旧} ⚠️ 轮内取舍顺序未明确（见问题 3）
```

### 🎬 场景 F：regenerate / edit

| 路径 | 推演结果 |
|---|---|
| `regenerate`（重生成末轮） | ✅ 路由快照截至末条 user（不含被重生成的旧 assistant）⇒ 该轮旧证据不参与，不与新检索叠加 |
| `edit`（编辑重发） | ✅ 服务端原子截断 ⇒ 证据只来自保留的更早轮次 |

### 🎬 场景 G：生成中改配置（意外场景）

| 意外场景 | 概率 | 影响 | 容错 | 结果 |
|---|---|---|---|---|
| 生成中改工具预算 | 中 | 低 | 本轮 runtime 已在生成开始时固定（判据 7） | ✅ 下一轮才生效，与既有"工具面固定"口径一致 |
| 同会话两标签页同时提问 | 低 | 低 | 会话锁 409（既有机制） | ✅ |
| 用户把条数默认值与返回上限往相反方向调 | **中** | **中** | **无防护** | ⚠️ 见问题 1 |

## 4. 问题汇总

| # | 类型 | 角色 | 场景 | 问题描述 | 功能影响（预期 → 实际） | 建议 | 严重度 |
|---|---|---|---|---|---|---|---|
| 1 | 流程缺陷 | 用户 | C / G | **两个旋钮的组合未被防护**：条数默认值调大（如 8）+ 返回上限不变（10000）时，单次返回 JSON 极易超上限被截断 | 预期"调大条数一次拿到更多材料" → 实际"JSON 被截断不闭合，AI 只拿到片段，**效果反而比 5 条完整更差**" | 配置界面加**组合提示**（条数默认 × 每条均长 vs 返回上限：提示"多数返回会被截断，建议同时调大返回上限"）；或在 S-01 §6 补该组合的提示行 | 🟡 |
| 2 | 流程缺陷 | 模型/用户 | A / E | **轮次编号语义在压缩后变化**：`turn` 按现存 messages 计数，压缩后"第 3 轮"实为会话第 9 轮 | 预期"证据带准确轮次归属" → 实际"编号与用户认知不符，模型可能误判时间线先后" | 改为相对表述（"更早第 N 次提问"）或在 `ConversationFile` 记录全局轮次 | 🟢 |
| 3 | 数据问题 | 自动化程序 | E | **轮内多条证据的取舍顺序未定义**：单轮 3 条共 30K 时，谁先占预算未写明 | 预期"按时间保留最新" → 实际"实现可能由首条占满预算、其余丢弃" | S-02 §3.1 第 6 步补"轮内自后向前"的取舍口径 | 🟢 |
| 4 | 遗漏场景 | 用户 | G | "生成中改配置"的行为未在文档写明（虽与既有口径一致） | 预期"文档交代生效时机" → 实际"需读者自行推断" | S-01 §3.5 补一句"生成中改配置：本轮不变，下一次提问生效" | 🟢 |

**统计**：🔴 阻断 **0** · 🟡 警告 **1** · 🟢 建议 **3**
