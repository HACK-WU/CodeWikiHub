# 需求分析：上传导入可「跳过重复文档」

- **来源**：用户 2026-10-19 原话「上传导入这里，希望新增一个功能，可以取消疑似重复文档的导入。」（附导入页预检面板截图）
- **分析口径**：product-manager（M1 需求定义 · 一次成型档）+ 用户 1 轮决策确认（Q1~Q5）
- **证据声明**：`🟢` 最高等级 = **代码直读**（未运行实测）；界面为描述生成的 ASCII 草图，非实测画面
- **已拍板决策**：
  - Q2 → **只做 Web**，不同步 CLI / MCP 参数
  - Q1 → **只做「跳过全部重复」**，不做逐篇勾选；按钮名 **「跳过重复文档」**
  - Q3 → skip 与 `onlyRelPaths` 叠加后为空 → **fail-loud**
  - Q4 → 跳过后**允许**再次全量导入；**落地口径（challenger 意见 2 修正）**：仅「被拦截后改选」可同 `uploadId`（job 已终态 + 参数不同 → 新建 job）；跳过**成功**后补导副本需**重新上传**（成功后前端正常清理 plan，同一 `uploadId` 的复用分支不可达）
  - Q5 → 面板计数用**预检扫描到的 Markdown 数**
  - 追加 → 跳过**仅本批次生效**，不写入 upload session、不形成永久忽略规则
  - 推演补充（2026-10-19，见 §3.5 第 5~11 条）→ 预算前置剔除、幂等复用参数不一致即 409、跳过优先于同名冲突、跳过集为空等同普通导入、跳过项不进未完成清单、判据单一真相、全部重复不落失败红态

## 2. 现状链路

```
浏览器选择文件
  └─▶ 分批 POST /api/import/upload（不带 finalize）──▶ ~/.ki/import-uploads/<uploadId>/
        └─▶ afterUploadsComplete（ImportPage.tsx:1127）
              └─▶ POST /api/import/preflight（只读，sha256 比对全库）
                    ├─ matched = 0 ──▶ POST /api/import/run（全量导入）
                    └─ matched > 0 ──▶ 面板：① 仍然导入（全量，建副本）
                                        ② 取消（零写入，整批放弃）
                                        ⛔ 缺：跳过重复，导入其余
```

- 面板明细字段齐备（`rel / existingGroup / existingRelation / existingSourcePath`），服务端有能力精确算出"应跳过集合"。
- 面板取消分支已于 2026-10-19 修过一次状态机缺陷（`phase` 未迁出 `awaiting-confirm` 导致页面锁死），本次新增第三分支必须遵循同一约束。

## 3. 需求定义

### 3.1 功能定位

在导入页的重复预检面板上新增第三个动作：**跳过本批中「内容与库中已有文档一致、但来源路径不同」的文档，其余照常导入**。默认不勾选、必须用户显式点击；不改变任何既有默认行为。

**不做**：逐篇勾选、跨批次记忆、永久忽略名单、CLI/MCP 参数、预检判据调整。

### 3.2 交互定稿

```
┌────────────────────────────────────────────────────────────────┐
│ [!] 检测到 23 篇内容与库中已有文档一致，但来源路径不同         │
│  • langchain/09-排障速查手册.md ↔ 已有「09-排障速查手册」①      │
│  • …（前 5 条 + 「展开全部 23 篇」②）                          │
│  本批共 96 篇：其中 23 篇疑似重复、73 篇为新内容。③            │
│                                                                │
│  [ 跳过重复文档 ]④   [ 仍然导入 ]⑤   [ 取消 ]⑥                │
└────────────────────────────────────────────────────────────────┘
```

| 编号 | 要求 |
|---|---|
| ① | 明细行沿用现有格式（`rel ↔ 已有「名称」（group，来源 path）`） |
| ② | 明细区可展开查看完整清单；受后端 50 条上限约束时明确写「另有 N 篇未列出」 |
| ③ | 计数用预检扫描数：`本批共 {scanned} 篇：其中 {matched} 篇疑似重复、其余 {scanned-matched} 篇将按当前设置处理`（Q5；**不写"为新内容"**——其中可能含被同名策略、大小上限、hook 失败挡下的文件，属过度承诺；口径 = **已成功上传到服务端的 Markdown**，不含上传失败批次与非 Markdown） |
| ④ | 按钮文案**精确为「跳过重复文档」**；`matched === scanned`（全部重复）时**禁用** + 说明「全部为疑似重复，跳过将不导入任何文件」 |
| ⑤ | 原「仍然导入」，语义不变（全量导入，会新建副本）；建议补一句代价说明 |
| ⑥ | 原「取消」，语义不变（零写入）；仍须把 `phase` 迁出 `awaiting-confirm` |

### 3.3 需求清单

| ID | 需求 | 优先级 | 说明 |
|---|---|---|---|
| **R1** | 新增动作「跳过重复文档」：本批重复项全部不写入（KB / 向量 / FTS / 附件），其余正常导入 | P0 | 核心诉求 |
| **R2** | 跳过判定**由服务端执行**（run 新增开关，服务端按预检同一判据重算），不依赖前端回传清单 | P0 | 保证 >50 条重复、以及与预检之间的库变化都被正确覆盖 |
| **R3** | 全部重复时不可发起"空跳过"：前端禁用 + 服务端 fail-loud | P0 | 防静默 0 篇与假成功 |
| **R4** | 跳过结果可见：结果区显示已跳过重复数，并可展开明细 | P0 | 用户需核对"到底哪些没导" |
| **R5** | 跳过仅本批次生效：不写入 upload session、不成为永久忽略规则；同一 `uploadId` 可再次全量导入 | P1 | Q4 已确认 |
| **R6** | 预检面板明细从「只列 5 条」升级为可展开完整清单 | P1 | 23 篇只见 5 篇无法判断 |
| **R7** | 新增可选参数缺省不传 ⇒ 与改前行为**逐字节等价** | P0 | 回归红线 |

### 3.4 统计口径需求（写进需求，避免实现期各自解释）

| 字段 | 要求 | 理由 |
|---|---|---|
| `stats.files.scanned` | **保持剔除前**的数量（含将被跳过的重复项） | 用户看到"扫描 96"却只选 96 里的 73 会无法解释差异 |
| `stats.files.skipped` | 计入被跳过的重复项 | 既有语义 = "未进入最终处理的文件数" |
| `stats.files.duplicatesSkipped`（新增） | 被跳过的重复项数量；是 `skipped` 的**子集**（类比 `unchanged` 是 `completed` 的子集） | 不破坏恒等式 `completed + incomplete + skipped = scanned` |
| `result.duplicatesSkipped`（新增明细） | `{ path, existingGroup, existingRelation }[]`，带条数上限与截断标记（**上限 500**） | R4 的可展开清单数据源 |
| 进度分母 | 取**剔除后**的文件数 | 否则进度永远到不了 100% |

> 两处明细上限**语义不同、文案须区分**：预检面板（上限 50，既有）截断时写「另有 N 篇未列出」；结果明细（上限 500）截断时写「仅展示前 500 条，共 N 条」，并提示可用导出/浏览页核对。

### 3.5 叠加与边界语义（定稿）

1. `skipDuplicates=true` 且同时传 `onlyRelPaths` ⇒ 最终处理集 = `onlyRelPaths` ∩ 非重复集；**结果为空 → fail-loud**（Q3），不得返回"成功导入 0 篇"。
2. `skipDuplicates=true` 且剔除后为空（全部重复）⇒ fail-loud，错误码需可判别（建议 `ALL_FILES_DUPLICATES`），文案引导改用「仍然导入」。
3. 预检结果只作提示；**实际判定以 run 时刻为准**（服务端重算）。两次计数不一致时以结果为准，不报错。
4. 跳过不影响 `conflictMode` 的既有行为：未被跳过的文件仍按当前策略处理同名冲突。
5. **闸门顺序（推演补充，🔴 B1）**：重复集剔除必须发生在**整批预算预检之前**（预算按文件数/总字节/预计 chunk 判定），且早于进度分母计算。否则"跳过 60 篇后本应在预算内的 40 篇"仍会按 100 篇判超限而失败。
6. **判定优先级（推演补充，🟡 W6）**：同一文件既"内容重复"又"同名冲突"时，**跳过重复优先于冲突策略**，且统计计入 `duplicatesSkipped`，不再计入 `same-name`。
7. **跳过集为空不得报错（推演补充，🟡 W10）**：`skipDuplicates=true` 但实际重复集为空（库为空 / 预检后库被清理）⇒ 等同普通全量导入，不触发 `ALL_FILES_DUPLICATES`。
8. **同 uploadId 幂等复用（推演补充，🔴 B2）**：`/api/import/run` 现有的"同一 uploadId 复用既有 jobId"分支不得吞掉跳过意图——若既有 job 的 `skipDuplicates` 与本次请求不一致，**不得复用**：返回 409 fail-loud，文案「该批次已在导入中（参数不同），请到任务中心查看，或重新上传后再试」。参数一致时可复用。
9. **跳过项与未完成清单（推演补充，🟡 W2）**：被跳过的重复文档**不进** `incomplete` 清单，因此「重试未完成」不会把它们重新导入；用户要补导须重新走整批导入（R5）。
10. **判据单一真相（推演补充，🟢 G4）**：服务端判定必须复用预检同一判据，且不得复制实现（`import-preflight.ts` 已 import `import.ts`，反向 import 会成环）——须抽为独立模块供两侧共用。
11. **全部重复的呈现（推演补充，🟡 W1）**：服务端拦截属于"可纠正的输入问题"，前端**不得复用红色「导入失败」态**（与 2026-10-19「取消不是失败」同型），应呈现为提示 + 引导改用「仍然导入」，且不迁入 `failed`。

## 4. 负向需求

| ID | 场景 | 期望行为 |
|---|---|---|
| N1 | 全部重复时点「跳过重复文档」 | 按钮禁用 + 原因说明；服务端兜底 fail-loud |
| N2 | 预检后库被并发改动（文档被删/新增） | 以 run 时刻判定为准；如实返回实际跳过数 |
| N3 | 与「重试未完成」叠加后交集为空 | fail-loud，文案说明"所选文件全部为疑似重复/不在重试清单" |
| N4 | 用户误点跳过 | 结果区给出"如何补导"（同批再点「仍然导入」即可），无永久标记 |
| N5 | 预检接口失败 | 现状直接导入；此时需明确提示"本次未做重复检查，无法跳过重复" |
| N6 | 等待确认期刷新/关页 | 现状即丢失（需重新上传）；文案不得暗示"已记住你的选择" |
| N7 | 跳过的文档引用了图片附件 | 不复制该文档的附件；被未跳过文档共同引用的附件照常复制 |
| N8 | 反向：内容相同是多位置合法副本 | 用户仍可选「仍然导入」；跳过不得成为默认 |
| N9 | 全量超预算、但剔除重复后在预算内 | 必须按剔除后判定并通过；不得报 `IMPORT_BUDGET_EXCEEDED`（B1） |
| N10 | 同一 `uploadId` 已有按不同参数启动的 job | 409 fail-loud，不得静默按旧参数执行（B2） |
| N11 | 跳过集为空（库为空 / 预检后库被清理） | 等同普通全量导入，不报 `ALL_FILES_DUPLICATES`（W10） |
| N12 | 部分文件未完成 + 部分被跳过 | 未完成清单只含真正失败项；跳过项不出现在「重试未完成」里（W2） |

## 6. 验收标准

| AC | 场景 | 判定条件 |
|---|---|---|
| AC1 | 10 篇中 3 篇疑似重复 | 点「跳过重复文档」后：`duplicatesSkipped=3`、`completed=7`、库中新增文档数 = 7（无副本）、进度到 100% |
| AC2 | 10 篇全部疑似重复 | 按钮禁用且给出原因；直接调接口 → fail-loud（`ALL_FILES_DUPLICATES`），库中零写入 |
| AC3-a | **全部重复被拦截后**改点「仍然导入」 | 面板可恢复；`uploadPlanRef` 与 localStorage 凭据仍在；同一 `uploadId` 可成功导入全部 10 篇（含 3 篇副本） |
| AC3-b | 跳过**成功**后再补导副本 | 本期不支持同 `uploadId` 重导：重新上传后可导入；文案不得承诺"可再导一次"；跳过本身无持久副作用（无忽略名单） |
| AC4 | 60 篇重复 + 40 篇新（超过 50 条明细上限） | 跳过 60 篇、导入 40 篇 —— 证明不依赖前端清单 |
| AC5 | `skipDuplicates` + `onlyRelPaths` 交集为空 | fail-loud，返回可判别错误码与明确文案；不得 202 后 job 成功 0 篇 |
| AC6 | 跳过文档引用的图片附件 | 未被复制；被未跳过文档共同引用者正常复制 |
| AC7 | 结果区 | 显示「已跳过 N 篇疑似重复」，展开明细条目数 = `duplicatesSkipped`（超上限时有截断说明） |
| AC8 | 不传 `skipDuplicates` | 既有单测全绿，且三条入口（CLI `ki import` / `retry-incomplete` / 常规 Web 导入）行为不变（"逐字节等价"不可判定，改为行为等价） |
| AC9 | 后端 50 条明细截断场景 | 面板提示「另有 N 篇未列出」，且跳过仍对全部 60 篇生效 |
| AC10 | 全量超预算、剔除重复后在预算内 | 跳过成功、不报 `IMPORT_BUDGET_EXCEEDED`；日志预算统计基于剔除后数量（B1） |
| AC11 | 同 `uploadId` 已有不同参数的 job | 返回 409 + 可判别文案；库中零新增文档；不返回旧 jobId 冒充成功（B2） |
| AC12 | 跳过 3 篇 + 2 篇未完成 | `incomplete` 只含 2 条；「重试未完成」不含被跳过路径；重试后库中仍无那 3 篇副本（W2） |
| AC13 | 单文件导入且该文件内容重复 | 面板按钮禁用 + 原因；强行调接口 → fail-loud；库中零写入 |
| AC14 | 跳过集为空（库中无同内容文档） | 等同普通导入：全部入库、`duplicatesSkipped=0`、不报错（W10） |
| AC15 | 全部重复被拦截时的 UI | 呈现为可纠正提示（非红色「导入失败」），`phase` 不落 `failed`，操作可继续（W1） |
| AC16 | 面板计数文案 | 不出现"为新内容"表述；实际入库数少于"其余 N 篇"时不视为缺陷（文案已声明"按当前设置处理"）（W3/W11） |

## 8. 关键假设

| ID | 假设 | 错了会怎样 | 验证 |
|---|---|---|---|
| A1 | 用户要的是"跳过重复、其余继续导"，不是整批放弃 | 需求方向错 | 已由用户确认 Q1 |
| A2 | 跳过判据沿用 `sha256 + sourcePath≠rel`，不引入模糊匹配 | 误跳会丢内容 | 需求内已固定判据 |
| A3 | 跳过必须用户显式选择，不默认生效 | 违背多位置合法副本用法 | N8 |
| A4 | 大于 50 条重复是真实可能（本次截图 23 篇，用户目录规模可达数百） | 前端清单方案会漏跳 | AC4 |

### 8.1 术语表（防混用）

| 术语 | 定义 | 不包含 |
|---|---|---|
| **疑似重复文档** | 本次待导入文件的**原文逐字节**（sha256）与库中某文档原文一致，且该文档的 `sourcePath ≠ 本文件 rel` | 同名不同内容；内容相似但不完全一致；同 sourcePath 的幂等重导 |
| **跳过重复** | 本需求新增动作：本批次中把疑似重复文档整体排除，不写 KB / 向量 / FTS / 附件 | 不等同于 `conflictMode=skip` |
| **跳过同名文件** | 既有 `conflictMode=skip`：按「同 Group 同名」或「同 sourcePath」跳过，**与内容是否一致无关** | 不等同于「跳过重复」 |
| **跳过集** | 本次 run 在服务端重算得到的疑似重复集合 | 前端传来的清单（前端清单只用于展示） |
| **本批次** | 一次 `uploadId` 对应的一次导入尝试；不跨上传、不持久化 | 不包含后续重新上传的批次 |
