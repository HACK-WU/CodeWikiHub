## 1. 背景与目标

kisearch 当前有两类人机入口：其一 Web 端「人管知识库」（浏览/搜索/导入/写入），其二 MCP「AI 用知识库」。二者之间没有对话通道——用户想就知识库问一句，必须离开页面去外部 AI 客户端；而 MCP 侧虽然"能检索"，却不在用户当前阅读的上下文里。

本需求在 Web 侧边栏新增一个常驻 AI 对话面板：**多轮对话 + 历史会话 + 归档/删除 + 自定义提示词**，并且**回答前会检索当前 scope 的知识库**（D13，取代 D1）——用户可以在任意页面就知识库直接提问，并拿到**带来源引用**的答案，点开即可核对原文。这正是本面板区别于外部通用 AI 客户端的差异化所在。检索能力**直接复用**既有实现（`executeSearch`，即 MCP `ki_search` 的同一实现），检索策略由注入的「检索 skill」路由，不新建检索链路。

## 3. 范围

### 3.1 本期做

- 右侧常驻可收起对话面板（360~420px），所有页面可用；**顶部一个开关按钮**控制显隐（D15）
- 后端 chat 代理（API key 不落浏览器）
- **知识库检索问答（D13）**：复用 `ki_search`/`executeSearch`，检索策略由注入的**检索 skill** 路由（`fulltext` / `hybrid`）
- **来源引用**：回答给出可核对来源（group / 文档 / 行号），可点击打开原文并高亮
- 多轮对话（L1 会话内记忆）
- **流式输出 + 生成中止**（验证后升为 P0，见 §11-A1）
- **生成中状态反馈**（reasoning 模型的必备适配，见 §11-A2 / R11a）
- 会话 CRUD：新建 / 切换 / 重命名 / 归档 / 删除
- **重新生成 / 编辑并重发**（D14）
- 每会话独立 system prompt（自定义"打开对话时的上下文/提示词"）
- 会话持久化到独立目录，daemon 重启后仍在

### 3.2 本期不做（明确排除）

- 上下文裁剪 / 摘要压缩（L2）
- 跨会话长期记忆（L3）与记忆管理界面
- 多用户 / 权限体系（按单用户本机使用假设）
- **跨 scope 检索**（检索范围强制 = 会话 scope，见 N23）
- **检索以外的工具**：不做写入/删除/导入类工具；不做多步自主规划 Agent（工具轮次有上限，见 R21）
- **检索原始结果落盘 / 回传**：只落"来源引用"，原始工具结果不回传上游（见 §5、N22）

### 4.2 知识库检索问答（2026-09-24 增补，D13 定位反转）

> 决策来源：用户拍板"侧边栏对话就是要检索知识；检索方式设计一个 skill，AI 调用该 skill 后用 kisearch 工具检索，直接复用"。
> 路线：**不新建检索链路** —— 复用 `executeSearch`（与 MCP `ki_search` 同一实现）；"怎么检索"写成 skill 注入模型，由模型自主选择 `fulltext` / `hybrid`。
> ⚠️ 勘误：现有 `ki_search` 的 `mode` **只有 `hybrid`（默认，语义+全文）与 `fulltext`**，**没有"纯语义"模式** → 用户所说"不然就使用语义检索"落地为 `hybrid`（T9 可再拍板是否新增纯语义模式）。

| ID | 需求 | 优先级 | 预期效果 | 验收标准 |
|----|------|:---:|---------|---------|
| R18 | 回答前可检索当前 scope 知识库 | P0 | 回答基于真实文档而非模型记忆 | 问知识库中确有的事实，回答与文档一致；`scope` 由 daemon 强制注入会话 scope；**检索步骤入 `OperationCoordinator`（同 scope）**，生成步骤不入队 |
| R19 | 检索路由 skill（注入模型） | P0 | 该用全文时用全文、该用语义时用语义 | 给出**确切字面片段**（引号内文字 / 报错 / 函数名 / 配置键 / 路径）时走 `mode=fulltext`（**不产生 embedding 调用**），能定位到文档与 group 路径；概念性问题走 `mode=hybrid`；检索无命中时**明确回答"知识库中未找到"，不得编造** |
| R20 | **来源引用**（回答带可核对来源） | P0 | 用户可验证答案并跳回原文 | 回答附来源列表（group / 文档名 / 行号区间），可点击打开原文并高亮命中；复用既有 `ModuleDrawer` + 高亮能力 |
| R21 | 工具轮次与结果预算上限 | P0 | 不被工具循环拖垮 | 单轮问答工具调用 ≤3 次；单次检索结果的条数与片段长度有上限；超限停止检索并作答（不得无限循环） |
| R22 | 模型工具能力声明（`llm.supportsTools`） | P0 | 模型能力不符时不误导用户 | 不支持工具调用时**不得静默退化成"无检索且不说明"**；按 T10 拍板结果 fail-loud（明示本次未检索）或降级为"daemon 预检索一次" |
| R23 | **重新生成** | P0 | 对回答不满意可重试 | 重生成**不新增 user 消息**、不产生重复提问；重生成期间同样可中止 |
| R24 | **编辑并重发** | P1 | 修正提问后重问 | 编辑 user 消息后**原子截断其后所有消息**并重新生成；操作前明确提示"将丢弃其后 N 轮"；与进行中的生成互斥 |
| R25 | 顶部开关 + 面板显隐语义 | P0 | 随处可控且不丢内容 | 顶部按钮控制开/关；**关闭 = 隐藏而非卸载**：生成不中断、内容与思考块保留，重开可见；切页面不影响面板状态 |

**负向需求（检索专项）**：见 §7 的 N17~N23。

**待确认（检索相关）**：T9（"语义检索"的实现口径）、T10（模型不支持工具调用时的降级）、T11（轮次与结果上限默认值）、T12（知识库内容外发的确认口径）、T13（首个交付切片是否含图片能力）。

## 5. 关键设计约束（供设计阶段）

- **落盘位置**：独立目录（如 `~/.ki/chat/`），复用 `writeJson`（WAL 原子写），一个会话一个 JSON 文件；与 `kb/{scope}/` 完全解耦，避免与快照恢复/删除 Group 互相影响
- **⚠️ 写入一致性（质疑意见 2，必须处理）**：`walWrite` 只保证单次写入原子，**不保护"读-改-写"序列**。会话的"读历史 → 追加消息 → 写盘"属 RMW，并发（多标签页 / 重复提交）会导致 Last-Write-Wins **消息静默丢失**。设计要求：daemon 侧按**会话 ID 串行化**（内存队列或互斥）或采用**乐观锁**（版本/`seq` 比对后重试）
- **⚠️ reasoning 永不回传（质疑意见 6，必须处理）**：assistant 的 `content` 才是对话内容；`reasoning` 仅用于展示与复盘。构造上游 `messages` 时必须**排除** reasoning 字段——实测单次思考可达 2635 字（远大于答案本身），误回传将同时放大 token 成本与延迟，并可能诱导模型复述自己的推理
- **API key 安全**：必须在 daemon 侧调用模型；前端只与本机 `/api/*` 通信
- **鉴权与越权白名单**：新增接口须同步登记 `src/lib/mcp-http-api.ts:300-310` 的白名单，否则 token scope 可能越权读写会话
- **布局实现**：`ki-shell` 是 flex 容器（`ki.css:118`），右侧面板作为新 flex 子项插入 `AppShell.tsx:147` 之后；**顶部开关按钮挂在 `ki-topbar`（`AppShell.tsx:148-160`）**；`ki-main` 已是 `flex:1;min-width:0`，不会破坏现有页面
- **⚠️ 面板显隐语义（D15，硬约束）**：顶部按钮的"关闭"= **隐藏，不卸载、不中止生成**。因此**流式累积态（content / reasoning）与"当前会话"状态必须存放在 AppShell 级常驻 store**（面板组件只是视图），否则关面板会触发组件卸载 → 丢内容并连带 abort。仅"切会话 / 删会话 / daemon 退出"才 abort
- **⚠️ 检索复用与排队口径（D13，硬约束）**：检索**必须复用 `executeSearch`**（in-process，与 `ki_search` 工具同源），**不绕 HTTP / MCP 自调用**（多一次鉴权与配置快照，并触发不必要的排队）。排队按既有项目约定（`src/lib/mcp-http-api.ts:318-322`）：**检索步骤入 `OperationCoordinator`（scope 维度），生成步骤不入队** —— 检索是秒级操作，入队不会拖长流；反之不入队会绕过同 scope 单写者调度读到中间态
- **⚠️ 检索结果处理（硬约束）**：进上游上下文的检索结果必须是**瘦身投影**（group / 文档名 / 命中片段 / 行号 / 分数，条数与长度受 R21 限制）；**原始工具结果不落盘、不回传**；会话文件只落 `sources`（来源引用）—— 与 reasoning 同款"结构性隔离"手法
- **检索范围安全**：检索 scope **强制 = 会话 scope**（daemon 注入，模型不可改、不可跨 scope）
- **超时预算（D13 后须重估）**：现设计"首块 30s / 整体 180s"按单轮生成设定；引入工具循环后整体时长 ≈ N 轮检索 + N 轮生成（reasoning 模型单轮首答最坏 12s 量级），**须重新给预算**（建议整体 300s + R21 轮次上限）；首块超时只约束"建立连接并收到首个 chunk"，不约束工具轮次
- **隐私面（D13 放大，硬约束）**：检索后**知识库文档片段会随提问发送至用户自配的模型服务**，比仅发送用户输入更敏感。面板须明示（含检索内容）；"清空全部会话"必须有接口落点（当前 `api/` 无此接口）
- **检索不可用降级**：向量服务 / Collection 不可用或检索报错时，**明示"本次未检索"**并禁止编造答案（N17）；不得静默退化为纯模型回答
- **复用**：回答渲染走 `MarkdownPreview`（含代码块复制、Mermaid），会话列表交互范式参考 `ScopeSelect`
- **响应式**：构造布局实测 1280px 下 `232 左导航 + 300 Browse 文档栏 + 400 对话面板` 使主内容区仅剩 342px（§11-R04），**真实页面基线待补测**；须定最小宽度，窄屏时面板降级为浮层抽屉或自动收起
- **全屏阅读器**：`ki-drawer--fullscreen` 打开时自动收起对话面板，避免空间与层级冲突
- **记忆策略（L1 仅）**：全量历史回传（**仅 `content`**，不含 reasoning 与检索原始结果）；**已知代价** —— 消息数随轮次线性增长，token 与延迟同步上升（教程基线实测）。若单会话超长需给用户提示，并在 L2（裁剪/摘要）落地前接受该成本
- **reasoning 模型适配（验证驱动，硬约束）**：抽测 7/7 模型均表现 reasoning 行为，单次采样首答 1.2s~12s、思考 token 占 completion 的 24%~99% → **流式与生成中状态属于可用性前提，不可后置**。模型由用户配置（D8，**不预置默认**），但**须支持工具调用**方能启用检索（R22 / T10）
- **框架层与工具循环前置门（质疑意见 4 + D13）**：原型为独立进程，未验证 daemon 框架层（鉴权 / 配置快照 / 越权白名单 / 长连接关闭语义）；**工具调用往返亦未验证**。须在真实 daemon 上加一个最小流式端点（含 >15s 长流与至少一次工具往返）验证通过后，方可进入实现

| N22 | **检索结果污染上下文**（D13 新增） | 检索原始结果不得作为消息落盘、不得回传上游；上游只接收瘦身投影，会话只落来源引用 |
| N23 | **跨 scope 检索**（D13 新增） | 禁止：检索 scope 必须等于会话 scope，模型不得指定其他 scope |

## 9. 风险

| 风险 | 等级 | 说明 | 缓解 |
