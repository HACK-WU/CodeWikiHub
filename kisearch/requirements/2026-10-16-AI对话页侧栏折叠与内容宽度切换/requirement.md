# REQ-20261016-004 · AI 对话页侧栏折叠与内容宽度切换

> 来源：用户 @product-manager 走查（M1+M2+M4 组合）→ 用户过确认点（2026-10-16）
> 用户原话：「AI 对话页面优化一下。1、对话列表可以折叠。2、对话内容添加两个按钮，居中 | 铺满。默认是居中。」
> 确认结论：「左侧会话列表 折叠/展开；6 和 7 不用做，其他确认。」

## 1. 背景与目标

`/chat` 独立对话页在宽屏下横向空间严重浪费，且左侧会话列表占据固定 260px 无法收起。目标：**让用户按自己的阅读偏好控制对话区的宽度与干扰程度**，且**不牺牲可读性**。

## 2. 现状取证（🟢 真实页面 Playwright 走查 + 代码直读）

取证脚本：`temp/probe-chatpage-layout.cjs`、`temp/probe-chatpage-fullwidth.cjs`、`temp/probe-chatpage-width-modes.cjs`（走查对象 `http://127.0.0.1:7423/chat`）。

### 2.1 布局实测

| 视口 | grid 列 | 会话列表 | 消息列 / 输入区 | 现象 |
|---|---|---|---|---|
| 1920 | `260px + 1432px` | 260 固定 | 880 居中 | 左右各空 276px（552px / 38.5% 被浪费） |
| 1440 | `260px + 952px` | 260 固定 | 880 居中 | 左右各空 36px（铺满仅多 48px，几乎无感） |
| 1100 | `260px + 612px` | 260 固定 | 588（受挤压） | 已无留白 |
| 900 | 单列 `796px` | 抽屉（`x=-309` 隐藏） | 772（天然铺满） | `☰` 会话列表按钮此时才出现 |

### 2.2 能力缺口

- **会话列表无折叠能力**：全页唯一的「收起/展开侧边栏」按钮属于**左侧主导航**；会话列表容器仅 `class` + `data-open` 两个属性。
- **无任何内容宽度设置入口**：全站 localStorage 只有 `ki.chatPanelWidth`（管右侧 dock 面板 320–720 拖拽），消息列 880 为 CSS 变量硬编码。
- **铺满后的可读性风险（实测）**：同一段 82 字中文，居中 880 时 2 行 / **41 字·行**（段宽 748px）；铺满（容器 1408px）时 1 行 / **82 字·行**（段宽 1034px）。中文舒适阅读区为 25–40 字/行。

## 3. 需求清单

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| **R1** | 左侧会话列表可折叠（桌面 ≥1024），**完全收起（0px）** | P0 | 点折叠 → 列表收起、消息区可用宽度增加；**折叠态下存在可见的展开入口**（复用 `.ki-chatpage__convbtn`，使其在折叠态显示）；刷新后保持；键盘可达；`prefers-reduced-motion` 下无动画 |
| **R2** | 对话内容宽度切换：**居中（默认）/ 铺满** | P0 | 默认 880 居中；切铺满 → 消息列 + 输入区 + 回底浮钮**同步**变宽，`scrollWidth === clientWidth`，不跳滚动位置；刷新后保持 |
| **R3** | **铺满时的行宽护栏（方案 C：铺满 + 内容层分级）** | **P0** | 1920 铺满下：正文文本块（段落/列表）单行宽度上限 **≈1000–1100px**；**代码块、表格、工具卡片真正铺满**（它们受益于宽度） |
| **R4** | 折叠与铺满可**任意组合** | P1 | 4 种组合（展开/折叠 × 居中/铺满）均正常，无布局错乱 |
| **R5** | 窄屏（<1024）隐藏该切换控件 | P1 | 该区间两者等价（可用宽度 <880），不呈现无效控件 |
| **R6** | 控件位置与形态 | P1 | 落在上下文条右侧、「配置」左侧；形态为**二选一分段控件**（非两个独立按钮）；带 `title` 说明 |
| **R7** | 无障碍 | P2 | `role="group"` + `aria-pressed`、焦点可见、可键盘操作 |

### 3.1 明确不做（用户已拍板）

- 会话列表分页 / 「加载更多」（超 50 条会话不可达的问题**本次不处理**）。
- 「清空全部会话」前端入口（`clearConversations` 继续无入口）。
- 第三档「更窄 / 专注」宽度。（不做）

## 4. 负向需求

| # | 场景 | 处置 |
|---|---|---|
| 1 | **误操作**：折叠后找不到会话列表 | 展开入口必须常驻且可见（R1 验收项） |
| 2 | **状态异常**：localStorage 脏值 / 写入失败 | 回落默认（居中 + 展开），不白屏；照抄 `chatPanelPrefs.ts` 的 try/catch 降级 |
| 3 | **极端内容**：超长代码块 / 表格 / 长 URL 在铺满下溢出 | 回归断言 `scrollWidth === clientWidth`（项目已有 `overflow-wrap: anywhere` 修复，需确认不被破坏） |
| 4 | **中途放弃**：切换宽度时正在流式生成 | 不得中断生成、不得丢失已生成内容、不得跳滚动位置 |
| 5 | **状态冲突**：1920 → 900 → 1920 | 窄屏是「忽略」不是「改写」偏好 |
| 6 | **数据异常**：会话列表为空 / 加载失败 | 折叠与宽度切换仍可用 |

## 8. 工程约束

- `ki.css` 改动**必须遵守只追加契约**（`ki.css:3835-3844`）：追加在既有段落之后、复用 `--ki-*` 令牌、新增量以 `--ki-chatpage-*` 声明；`prefers-reduced-motion` 关闭规则须置于相关段之后。
- 偏好键命名遵循 `ki.<camelCase>` 惯例（如 `ki.chatContentWidth`、`ki.chatpageSideCollapsed`）。
- 涉及 `ki.css` 的 `max-height` 等与 demo 同步的项不在本次范围；若新增 demo 同步项须在实现时登记。

### 9.5 偏差与遗留

- **实现层取值未经用户确认**：`--ki-chatpage-prose-max: 1100px`（用户只批了方案 C 的分级思路）。表现为「铺满后段落仍留白、代码块/表格铺满」。
- **桌面新增常驻 `☰`**：此前桌面不可见（原规则只在 `<1024px` 显示）。属必要变更（折叠入口 = 折叠态唯一展开入口），已向用户明示。
- 折叠态左栏保留在 DOM（`visibility:hidden` 对辅助技术亦隐藏）；如列表规模显著增长可考虑 `content-visibility`。
- **本次明确不做**（用户拍板）：会话列表分页/「加载更多」、`clearConversations` 前端入口、第三档「更窄」宽度。

### 9.6 折叠按钮视觉迭代（用户 4 轮反馈后定稿）

| 轮次 | 形态 | 用户反馈 |
|---|---|---|
| 1 | `.ki-chat-iconbtn` 裸灰线条 `☰`（无边框、无背景） | 「总感觉这个折叠按钮不是很明显，一般人看了不知道点了可以折叠」 |
| 2 | 「竖线 + 箭头」+ 描边 | 「这个图标也太丑了点吧」—— **根因：删掉了 Lucide `panel-left` 的外框 `<rect>`**，15px 下退化成 `|‹` 残缺符号 |
| 3 | **Lucide `chevrons-left` / `chevrons-right`**（16px，随折叠态翻转方向）+ 浅灰底胶囊 + 主色箭头 | 用户拍板形状：「用这个表示，颜色换一下」 |
| 4（定稿） | **背景透明** + 主色双箭头 + hover 淡主色底反馈（`color-mix(主色 12%)`） | 「背景要透明的，不要是灰色」 |

- ⚠️ 该规则与基类 `.ki-chat-iconbtn:hover` **特异性相同且位置更靠后** ⇒ hover 反馈必须显式重写；背景透明后，hover 反馈是**唯一**的"可点击"提示，不能省。
- 走查断言 `A2b` 已相应改为「默认背景透明 + hover 有背景反馈」（两条同时校验），固化进 `temp/verify-chat-layout-prefs.cjs`。
