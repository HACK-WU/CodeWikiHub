# 需求：AI Agent 任务前上下文预取（ki_recall）

- 需求 ID：REQ-20261118-003
- 状态：已确认
- 日期：2026-11-18
- 来源：用户提出 + 产品经理视角需求分析（M1）

## 1. 背景与目标

AI Agent（CodeBuddy 等）接到新任务 / 需求 / bug 时，在真正动手前应当先「描述要干什么」，再拿到可能相关的文档，然后才开工。当前 ki 的检索工具都要求调用方**已经知道问什么**，缺少「任务描述 → 该读哪几篇」的原语。

**目标**：提供一个只读、单次调用、不提问的预取能力，把「任务画像 → 文档候选清单 → 建议读取动作」这条链路固化下来，并给出 agent 侧的触发引导。

## 2. 现状（证据）

| 事实 | 证据 |
|---|---|
| `ki_search` 要 query、`ki_get_module_info` 要 group+name、`ki_ask` 要 question，均无「任务→文档清单」形态 | `src/lib/mcp-tools/search.ts:13-26`、`src/lib/mcp-tools/ask.ts:119-136` |
| `ki_ask` 必填单库且明确拒绝视图 / 逗号多库 | `src/lib/mcp-tools/ask.ts:161-181` |
| `ki_ask` 输出为答案 + ≤15 条来源片段，不是文档清单 | `src/lib/chat/ask/ask-runner.ts:143-159` |
| `ki_ask` 5~30s、45s 硬顶、全局 2 并发 / 每库 60s 10 次 | `src/lib/mcp-tools/ask.ts:211-225`、`src/lib/chat/ask/ask-contract.ts:101-103` |
| 「AI 查找」已具备 fast / deep 双通道与产物形状，但以 eventId 为输入 | `src/lib/governance-http.ts:1037-1095`、`src/lib/events/find-runner.ts:364-471` |
| 快速通道 query 只用事件标题 + 关联文档名，描述不参与 | `src/lib/events/refs-service.ts:324` |
| `extractKeywords` 按标点切词，中文无标点长句整句成一个 token | `src/lib/events/refs-service.ts:173-180` |
| 现有 skill 只要求「任何任务前先 ki_search」，未要求先写任务描述，也未要求按推荐清单读全文 | `skills/ki-search/SKILL.md` |

## 3. ki_ask 复用判定

**结论：不直接复用其对外形状，可复用其内层（tool-loop + 检索工具集）。**

| 维度 | ki_ask | 本需求 | 判定 |
|---|---|---|---|
| Scope | 必填单库、拒视图 | 跨库 / 视图 | 不匹配 |
| 输出 | 答案 + 片段来源 | 文档清单 + 下一步动作 | 不匹配 |
| 语义 | 问答，鼓励 context_id 追问 | 单次、不提问 | 不匹配 |
| 时延/配额 | 5~30s / 45s / 2 并发 | 每任务开工前必调 | 不匹配 |
| 准入 | 模型消耗型，只读 Token 不可见 | 见 R8 | 待定 |

## 5. 负向需求

| # | 场景 | 要求 |
|---|---|---|
| N1 | 描述空泛 | 返回 `needMore[]` + 可选「最近热区文档」兜底，不得硬失败 |
| N2 | 外发未确认 / 模型不可用 / 无 tools | 降级确定性通道，`degraded:true` + 原因 |
| N3 | 跨库权限不足 / 库已删 | `skipped[]` 部分跳过、整体成功 |
| N4 | 超时 / 客户端断开 | 返回 `partial:true` + 已得候选，不整体失败 |
| N5 | 并发打满 | 明确 `retryAfter` + 建议改用 `ki_search` |
| N6 | 生命周期 / 可见性 | hidden、事件阶段锁定、临时文档不得召回 |
| N7 | 结果噪声 | 同文档多分块去重、每库配额 ≤3、支持 `exclude[]` |
| N8 | agent 不读就动手 | `nextActions` 给可直接执行的调用参数 |

## 7. 缺口回扫（六维）

| 维度 | 结论 | 处理 |
|---|---|---|
| 场景完整性 | 缺「什么时候不该预取」 | 补进 R4 触发边界 |
| 验收标准可达性 | 命中率类不可离线判 | R1/R2 只判可判定项，质量指标进 R7 |
| 需求一致性 | R1 跨库 vs R8 准入未定 | **范围已定：`scope` 必填、服务端不设默认库**（2026-11-18 用户拍板）；R8 仍进待确认 |
| 角色对齐 | 机器消费者与人（配范围、看审计）未分 | R4 给人，R7 给维护者 |
| 边界/异常覆盖 | N1~N8 覆盖 | 通过 |
| 术语一致性 | 混用描述/画像/预取/召回 | 统一「任务画像（task brief）+ 预取（recall）」 |

## 8. 优先级与下一步

排序理由：R0→R4 为「验证价值 → 能出结果 → 有人调」的最小闭环，任一缺失整套不成立；护栏与分工为期望项；审计可后置但缺了无法判断是否继续投入。

下一步：转 `design-craft` 出技术设计（工具契约、内核抽取边界、配置面、降级矩阵）。
