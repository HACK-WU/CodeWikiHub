# `ki_recall` 召回语料（P6 · 质量验收基准）

- 用途：S-02 验收项 **V5「候选有用性」** 的唯一判据；同时用于校准 S-01 的中文线索抽取规则。
- 编制日期：2026-11-18｜维护人：需求提出者（**不得是 S-01/S-02 的实现者**，见 S-02 §9 注）
- 规模：10 例 = **命中组 5 例** + **未命中组 5 例**

## 0. 怎么用

1. 每例按「任务画像 + hints + scope」原样调一次 `ki_recall`（`mode=fast`）。
2. 只看 `candidates` 的前 3 条（`top3`），按该例的「判定口径」判 **✅ 有用 / ❌ 无用**。
3. 汇总：
   - **命中组**：top3 含目标文档 → ✅（≥4/5 达标）
   - **未命中组**：top3 中「确实相关」的 ≤1 条 → ✅（≥4/5 达标，即不能硬凑）
   - **V5 总判据**：10 例合计 **≥7/10**
4. 每例记录：实际 top3、耗时、`channel`、是否 `needMore`。结果回填到本文件末尾的「实测记录」表（首次执行时创建）。

> **反作弊**：判定「确实相关」时，只有能说出「它对这个任务有什么用」才算相关；说不出来的，一律算无关。

## 4. 边界与维护

- **语料会过期**：文档被删/改名后，H 组需重取 ground truth；每次 V5 执行前先跑一遍存在性校验。
- **不许拿 `ki_search` 的结果反向编造 ground truth**：期望文档必须来自「人先知道该读哪篇」，否则 V5 退化成自证。
- **未命中组是防「硬凑」的**：如果 `ki_recall` 对 M1~M5 都能给出 3 条看似相关的候选，说明它把「语义相近」当成了「有用」，比召回率低更危险。

**结论**：V5 达标（9/10 ≥ 7/10），但 **M5 的误报证明「读一遍再判断」这一步不能省** —— `why` 只能说明"靠什么被检索到"，判断相关性必须由调用方读正文完成（对应 skill 的硬门禁）。
