```markdown
# 开工前预取（task-recall）

## 0. 速览
新任务？→ 判断要不要预取 → **定 scope（库名或视图，必填）** → 写任务画像（2-3 句）→ ki_recall → 读 nextActions 前 2 篇 → 再动手
不需要预取的：闲聊、纯文案、已知位置的单行改动、刚在同一模块做过且记忆仍在
不知道有哪些库？先 ki_scope_list / ki_view_list；本仓约定直接用视图 kisearch-docs

## 1. 什么时候调
- 要调：不熟悉模块 / 跨 3 个以上文件 / 需求或 bug 描述里有症状但没定位 / 上次结论可能过期
- 不调：一句话改错别字、纯样式取值、明确知道文件与行、只做机械迁移

## 2. 怎么写任务画像（不是提问）
四要素，2-3 句，≤2000 字：
目标（要达成什么）/ 涉及（模块·页面·接口名）/ 现象（报错原文·错误码·复现路径）/ 期望（改成什么样）
❌ 不要写成问题句（"这个怎么改？"）—— ki_recall 不回答提问
❌ 不要贴整段日志或代码 —— 用 hints 传强线索（错误码、文件路径、函数名）
✅ scope 必传：查哪几个库/视图由你决定，工具**不会**替你挑；宁可先多发一次 ki_scope_list，也不要漏传

## 3. 怎么用返回
- candidates：先读 rankInScope 靠前、why 里命中线索最多的
- alsoIn：同一条候选在别的库还有同名文档 ⇒ 两个版本可能不一致，**先读一个，必要时对照另一个**；不要假设它们等价
- nextActions：已经给你可直接执行的 ki_get_module_info 参数，照调即可
- needMore：说明画像缺信息 —— 补齐后**最多再调一次**，不要反复重试
- degraded / partial：结果不完整，如实告诉用户"基于有限检索"
- skipped：这些库没参与（无权/不存在），不要让用户以为"没有相关文档"

## 4. 禁忌
🔴 1. 把 ki_recall 当问答（它不是 ki_ask）
🔴 2. 同一任务连续调用 ≥3 次（说明画像或 scope 有问题，先修画像）
🔴 3. 拿到候选不读正文就下结论
🔴 4. 把 needMore 当成向用户反问的借口 —— 先自己补线索
🔴 5. 用 ki_recall 替代 ki_search 做精确关键词检索
🔴 6. 漏传 scope（必填）—— 报错会回可用清单，照着补一次即可，不要反复盲试库名

## 5. 与其他工具的分工
ki_recall → 我只有任务描述，不知道读哪篇
ki_search → 我知道搜什么词
ki_get_module_info → 我知道 group + 名称，要读全文
ki_ask → 我读完了，要一个综合结论
```

## 4. 验收项（本子需求无代码接口）

S-04 交付物是文档与配置资产，没有函数或工具契约，故不设「接口设计」章。对应需求 R4 / R5 的可执行验收项如下（「文件存在」只是前提，真正判据是抽样行为）：

| 验收项 | 方法 | 期望 |
|---|---|---|
| A1 skill 可被加载 | 新会话加载 `task-recall` | 首个动作是「定 scope + 写任务画像 + `ki_recall`」（抽样 ≥5 次，≥4 次） |
| A2 不该调时不调 | 给「改一个错别字」类任务 | 不调用 `ki_recall`（抽样 3 次，3 次） |
| A3 结果被消费 | 给一个真实 bug 任务 | 至少读 1 篇 `nextActions` 指向的文档后才改码 |
| A4 工具选对 | 3 类输入（不知搜什么 / 已知关键词 / 要结论）各 3 次 | ≥8/9 选对工具 |
| A5 文档一致 | `grep -c "ki_recall" docs/mcp-tools.md`，工具数断言 | 24 且表格齐全 |
| A6 漏传 scope 可自愈 | 故意只传 task 调 `ki_recall` | 返回 `RECALL_SCOPE_REQUIRED` + 本次 Token 可用库/视图清单；补传后一次成功，不出现「盲试库名」循环 |

## 8. 关键决策点

| # | 决策 | 被否决方案 | 否决理由 | 重新评估触发条件 |
|---|---|---|---|---|
| D-04-1 | 新建独立 skill `task-recall` | 扩写现有 `ki-search` | `ki-search` 的契约是「已知 scope 的四步走」，塞进「写任务画像」会破坏其触发判据 | 两个 skill 触发重叠导致误用 > 20% |
