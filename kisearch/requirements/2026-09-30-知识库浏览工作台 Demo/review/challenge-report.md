## 📋 设计上下文确认

### 设计目标
- **核心目标**：验证「知识库浏览页已确认的视觉语言」能否原样推广到其余五个页面（总览 / 语义搜索 / 上传导入 / 知识写入 / 后台任务），并给出可直接用于 React 落地的界面规格。
- **衡量标准**：五页在同一外壳下视觉自洽；每页覆盖 正常/加载/空/错误；375–1525px 无横向溢出；单文件零构建可打开。
- **目标优先级**：视觉语言一致性与信息层级（核心）＞ 隐藏态覆盖（次要）＞ 具体组件微交互（辅助）。

### 设计范围
- **覆盖**：五个页面的页面清单、逐页布局、组件状态表、token（沿用 + 4 个新增语义色）、响应式规则、待确认项。
- **排除**：不修改已定稿浏览页 demo；不改任何 React 产品代码；不接真实后端；不定是否推广。
- **系统边界**：与正式页面的接口在「视觉 token + 组件形态」，不涉及路由与数据契约（demo 用 hash 路由）。

### 约束与假设
- **技术约束**：单文件原生 HTML/CSS/JS、零构建、无 CDN/外部字体/图标库。
- **业务约束**：示例数据必须显式标注；不新增产品承诺。
- **资源约束**：demo 需在评审者本地双击可开。
- **隐含假设**（标注失效后果）：① 假设浏览页 demo 是视觉权威（失效则五页基线不稳）；② 假设正式页面长度可控（失效则长列表/分页未验证成为缺口）；③ 假设正式页面可自由改版式（失效则双栏改造需重议）。

## ⚔️ 反对意见

### 意见1：导入阶段只画了一帧，阶段 → 视觉的映射关系缺规约
- **反对理由**：正式导入是状态机（`idle → scanning → uploading → importing → done`，失败再分 `scan / upload / import / cancelled / unknown` 五种阶段，见 `ImportPage.tsx` 的阶段枚举），而 demo 只呈现「上传中 · 39%」这一帧。设计文档的组件状态表写了「进度条 / 阶段徽标」，但没有规定**每个阶段显示什么文案、什么语义色、有没有取消入口、能不能编辑表单**。实现时这几处必然各自发挥。
- **功能影响**：预期「评审确认后的阶段视觉可直接照做」→ 实际「编码者要重新决定 5 个阶段的文案与配色，且大概率与 demo 不一致」，评审结论无法平移。
- **严重程度**：🟡 重要
- **替代方案**：在设计文档补一张「阶段 → 徽标文案 / 语义色 / 进度条形态 / 可用操作」映射表（本轮已补，见设计文档 §10.1）。
- **验证方法**：把 `ImportPage.tsx` 的 `phases` 与 `failureStage` 枚举逐个对表，检查是否每项都有视觉归宿。

### 意见2：跨页路径未闭环，关键跳转仍是假交互
- **反对理由**：方案里的三条跨页路径（检索结果「浏览此 Group」、导入成功「查看目标 Scope」、写入成功「查看写入位置」）在 demo 中分别退化为 toast、跳到浏览 demo 根、跳到浏览 demo 根。而浏览页 demo 不支持任何参数，因此「检索命中 → 直接看到该 Group 的目录与文档」这条真实使用路径**无法被评审**，深链参数名、作用范围、无权限或 Group 不存在时的降级都没定义。
- **功能影响**：预期「评审能点通检索 → 浏览的闭环」→ 实际「只能看到提示文案，闭环未验证；实现时深链语义临时决定，容易与浏览页已有深链接（scope+group+relation）冲突」。
- **严重程度**：🟡 重要
- **替代方案**：设计文档写明深链契约（建议 `#/browse?scope=<s>&group=<g>`：进入后自动展开该 Group、滚动到首篇并高亮；Group 不存在时提示并停在根目录），并在 demo 中至少改为可点击跳转到浏览 demo 并附 `?group=` 占位参数（浏览端未支持时显式提示）。
- **验证方法**：在正式页面从搜索结果点击「浏览此 Group」，检查是否落在正确 Group 且不丢失检索条件。

### 意见3：暗色主题缺 token 映射，新增语义色在暗色下无依据
- **反对理由**：正式外壳有主题切换（`AppShell.tsx` 写 `ki-theme`），而本轮新增了 `--color-warn-soft #fbf3db`、`--color-warn #8a6208`、`--color-danger-soft #fdebec`、`--color-danger-ink #9d3a36` 四个暖色语义 token，且全部以浅底为前提。若直接推广，暗色下徽标/横幅会出现浅底+深字与暗背景的对比不足或光晕感。
- **功能影响**：预期「推广后明暗两种主题都成立」→ 实际「暗色下状态徽标与横幅对比度不达标，需二次返工定色」。
- **严重程度**：🟡 重要
- **替代方案**：设计文档补「暗色 token 映射（待确认）」小节：语义色改为「底色暗化 + 文字提亮」成对定义（如 warn 暗色用 `#3a2f12` 底 + `#e8c877` 字），或明确本轮不支持暗色、推广前先补。
- **验证方法**：在正式页面切到暗色，用对比度检查器测徽标与横幅文字（目标 ≥ 4.5:1）。

### 意见4：真实数据密度未被样本覆盖，长列表/分页能力是空白
- **反对理由**：示例数据用 14 篇文档、6 行文件清单、6 条任务代表真实规模（`ai-docs` 单 scope 1,866 篇、单 Group 最多 111 篇、导入批次 1,240 文件）。设计对「长列表怎么滚动、是否分页、表头是否吸顶、大 Group 展开时是否卡顿」没有一句话。
- **功能影响**：预期「推广后能承载真实知识库」→ 实际「1,866 篇的 Scope 表与 111 篇的 Group 树首次打开时的表现未知，可能出现长列表无虚拟滚动导致的首屏卡顿」。
- **严重程度**：🟡 重要
- **替代方案**：在设计文档「待确认」增加容量问题，并明确最小约定（文档树/结果列表/文件清单的最大高度与内部滚动、列表超过 N 条时的分页或截断提示）。
- **验证方法**：用真实 `ai-docs` scope 打开浏览页与搜索结果列表，记录首屏渲染时间与滚动流畅度。

### 意见5：窄屏表格靠面板内横滑承载，取舍未声明
- **反对理由**：Scopes 表使用 `white-space: nowrap` + `.table-wrap { overflow-x: auto }`。因此「375px 无横向溢出」的实测结论成立，但成立的方式是**列在面板内部横滑**，而不是重排。这是有意取舍，但文档没有任何说明，评审者会按「窄屏也完整可读」理解。
- **功能影响**：预期「窄屏下表格完整可读」→ 实际「375px 需在面板内左右滑动才能看到文档数」，若评审不接受需重新设计移动端表格（卡片化/隐藏次要列）。
- **严重程度**：🟢 建议
- **替代方案**：文档里写明该取舍（已补，见 §10.2），或在 <600px 隐藏「层状态」列改为徽标换行。
- **验证方法**：375px 打开总览页，检查是否需要横滑才能读到关键列。

### 意见6：演示态切换器验证的是"渲染分支"，不是"真实状态转换"
- **反对理由**：四态由固定分支渲染（`mode === 'loading'` 直接短路），加载态由定时器模拟。实测只能证明「四个分支的画面正确」，无法证明真实异步下的过渡质量（骨架与内容切换时的跳动、请求失败回退到上一份结果、并发刷新时工具栏是否抖动）。
- **功能影响**：预期「状态视觉已被验证」→ 实际「过渡与回退行为仍是空白，实现期才发现骨架抖动或结果闪烁」。
- **严重程度**：🟢 建议
- **替代方案**：在实现阶段用真实接口做一次状态走查（首屏加载、失败重试、并发刷新），把过渡规格（骨架最小展示时长、失败是否保留旧数据）写进组件规格。
- **验证方法**：对正式页面做一次慢网络/失败注入走查并录屏。

### 意见7：本轮已修复的三处问题（闭环记录）
- **进度条缺失与文档不一致**：设计文档 §7 待确认项 4 声称「本 demo 在任务页增加进度条」，但实现只有文字百分比。→ 已补：任务列表每行一条 4px 进度条（按状态取强调/警告/失败色），详情面板增加同款进度条。复验：`rowsWithBar=6`、`detailBar=1`。
- **搜索结果卡内交互元素不可聚焦**：「浏览此 Group」是 `<button>` 内的 `<span onclick>`，键盘用户无法触发。→ 已改为 `<article class="result-card">`（鼠标点整卡打开原文）+ 两个真实按钮（标题按钮打开原文、`浏览此 Group` 按钮）。复验：`articles=5`、`openButtons=5`、`linkButtons=5`。
- **写入页「空」态误用红色失败横幅**：空表单被判定为校验失败并显示 danger 横幅，语义过重。→ 已改为中性提示「尚未填写：Group、文档名、正文」，仅真实非法输入或演示「错误」态用红色。

## ✅ 认可点

- **token 完全复用，未新增强调色**：四个新增 token 全部是状态语义色，选中/主按钮/进度填充/分数条仍统一为 `--color-accent #2d6755`，符合「一个强调色锁」。
- **隐藏态真正可看**：每页页头一个「演示状态」分段控件即可切换 正常/加载/空/错误，实测 20 组状态签名与设计意图一一对应，评审不必读代码想象状态。
- **响应式有实测证据**：375/600/960/1200/1525 五档 × 五页 = 25 组 `scrollWidth === clientWidth`，零横向溢出；`prefers-reduced-motion` 已处理。
- **协作风险控制得当**：发现并行会话覆盖同路径文件后，未继续争抢，而是另存 `-v2` 并在文档写明并存关系，保留对方产物供对比。
- **示例数据可辨识**：页面副标题、侧栏脚注、进度卡注释三处标注「静态示例数据」，不易被误读为实时数据。

## ➕ 补充场景与情况

- **只读/无权限 scope**：导入、写入、编辑在目标 scope 不可写时的视觉（当前 demo 的字段仅按「未确认 scope」禁用，没有权限维度）。
- **向量化开关关闭后的连锁提示**：开关文案提到「仅写 FTS」，但关闭后语义检索不可见的后果没有在写入/导入成功反馈里回述。
- **超长文本阈值**：Group 路径与文档名在 demo 用省略号截断，但「多少字符开始截断、悬停是否显示全称」未定（当前靠 `title`）。
- **多标签叠加筛选**：Tags 允许多选，但多选后的结果范围提示只有一条「已按标签过滤」，未说明是 AND 还是 OR。
- **移动端焦点归还**：浏览页 demo 已有「返回目录 → 焦点回到选中文档」，其余四页的覆盖层/抽屉关闭后焦点去向未定义。
- **空 Group 与只含附件目录**：文件清单里附件与跳过项已展示，但「某 Group 下全部文件被跳过」时的目录呈现未定义。
