# 事件参考文档支持上传文件

## 1. 背景与目标

事件详情页「参考文档」卡目前只有两条加入路径：「AI 查找」（检索库内已有文档）与「＋ 添加」（手动挑选库内已有文档）。当证据材料还只存在于本地文件时，用户必须先绕到「知识写入 → 上传导入」页上传，再回到事件页搜索加入。

**目标**：在参考文档卡直接上传文件，上传成功即成为该事件的参考文档。

**边界（用户明确）**：

- 只允许上传**文件**，**不允许上传目录**；
- **单次最多 10 个文件**。

## 2. 现状（代码实证）

| 事实 | 证据 |

| 单事件参考文档上限 **50**，超限抛 `REF_LIMIT_EXCEEDED`，**整批校验全通过才写** | `refs-service.ts:36, 582-587` |
| 同篇不能既关联又参考（`REF_ALREADY_ASSOCIATED`）；被已收口事件锁定的文档拒绝加入 | `refs-service.ts:622-653` |
| 卡头现有动作：`[N 篇]` + `AI 查找` + `＋ 添加` | `web/src/pages/EventsPage.tsx:759-772` |
| 卡头 ≤1080px 自动换行、≤640px 动作整行，加第三个按钮结构安全 | `web/src/styles/governance.css:1577-1592` |
| 上传两步链路：`uploadFiles`（base64 JSON，前端分批 ≤8MB/50 个）→ `runImport`（异步 job）→ 轮询 status | `web/src/api/httpApi.ts:529-624`、`ImportPage.tsx:265-275` |
| 服务端逐文件校验扩展名白名单 + 单文件 `maxFileSize`（默认 1MB）；请求体 `MAX_BODY` 16MB | `src/lib/mcp-http-api.ts:2477-2564` |

| 导入结果含 `created` / `modified`（group + relation），可用于上传后建引用 | `src/lib/import.ts:284-305` |
| 新增 HTTP 路由不登记 `route-permissions` 会 404（历史 P0） | `src/lib/auth/route-permissions.ts` |

## 3. 影响面

| 受影响功能/方 | 影响类型 | 影响程度 | 建议处理 |
|---|---|---|---|
| 参考文档 50 篇上限 | 流程 | 破坏（先导入后失败 → 孤儿文档） | 提交前预检名额，服务端同口径兜底；顺序固定为「先校验 → 再导入 → 再建引用」 |
| 文档身份 `isImported=true`（Web 上传通道现状） | 展示/数据 | 降级（列表显示 📥、分类锁 wiki） | 本期接受，弹窗文案说明；是否放宽单开需求 |
| 目录导入的「清理候选」 | 数据 | 降级（同 group 目录导入 + 开清理时上传件可能进候选） | 落点使用独立 group（`事件参考/…`）隔离 |
| `wikiWriteback` | 外部契约/文件系统 | 降级（回写会影响用户磁盘目录） | 事件上传**不写回**（决策 D3） |
| 事件收口 / 删除 | 流程 | 无感（refs 不随阶段变化） | 无需改动，保持卡片文案「外部引用，不随事件阶段变化」 |
| 关联文档 | 流程 | 降级（同名同 group 上传后加引用会被拒） | 命中时提示「此文档已在关联文档中」，不报红 |
| 检索 / AI 查找候选池 | 展示 | 增益（新文档立即可检索） | 无 |
| 导入任务台账 / 任务中心 | 展示 | 无感（复用现有 job） | 复用 `/api/import/status` |
| 路由权限表 | 权限 | 破坏（漏登记 404） | 新增端点必须登记 `knowledge.write` |

## 4. 需求清单

| # | 需求 | 验收标准（可判定） | 优先级 |
|---|---|---|---|
| R1 | 参考文档卡新增「上传文件」入口 | 写权限可见可点；只读账号禁用且 `title="需要写权限"`，后端 403 兜底；`AI 查找` / `＋ 添加` 行为不变 | P0 |
| R2 | 只收文件，不收目录 | 选择器无 `webkitdirectory`；请求内 `name` 含 `/` 或 `\` 一律 400 拒绝；不出现「选择文件夹」入口 | P0 |
| R3 | 单次最多 10 个文件 | 选择 11 个即阻止提交并提示「单次最多 10 个（本次 11 个）」；服务端对 >10 的请求 400；同批同名文件报「重复相对路径」不静默去重 | P0 |
| R4 | 上传成功即成为该事件参考文档并刷新 | 计数 9→12、新行可直接点开正文、无需手动刷新；同名已存在按 R9 策略处理且不重复建引用（`skipped` 有回显） | P1 |
| R5 | 落点 Group 写入前可见、可改 | 弹窗显示落点，缺省 `事件参考/{短号}-{标题}`；改动后文档确实落在该 group；**不得静默落 `__root__`** | P1 |
| R6 | 逐条 fail-loud + 给路 | 格式不支持 / 超 1MB / 超 10 个 / 参考文档超 50 / 上传失败，各显示具体原因与下一步；禁止只显示「上传失败」 | P0 |
| R7 | 过程与终态反馈 | 上传中禁止重复提交；导入 job 显示「向量化 N/M」；`partial` 明确列未完成篇数 | P1 |
| R8 | 参考文档名额预检 | refs=45 时选 10 个 → 提交前拒绝「最多 50 篇，当前 45，本次至多再加 5 篇」；不得产生孤儿文档 | P0 |
| R9 | 重名冲突策略显式 | 默认不覆盖，列出「N 篇同名已存在，将跳过」；若将来提供覆盖选项必须二次确认并列出将覆盖的文档 | P1 |

**术语口径**：按钮「上传文件」、弹窗标题「上传文件并加入参考文档」，与「＋ 添加」（引用已有文档）区分。

## 5. 负向需求

| # | 场景 | 期望行为 |
|---|---|---|
| N1 | 误拖目录 / 目录与文件混合 | 一期无拖拽入口；若后续加，只拒目录项、文件项照收，被拒项逐条列出 |
| N2 | 选超 10 个 | 阻止提交，不自动截断（截断会让人以为全传了） |
| N3 | 单文件超 1MB | 选择后本地预检标红，不等服务端拒 |
| N4 | 参考文档已满 50 | 提交前拦截；若已部分上传，明示「文件已入库但未加入参考文档」并给补救入口 |
| N5 | 上传中切事件 / 切 scope / 关弹窗 | 结果回填前校验事件快照，不得把 A 事件的上传写进 B 事件的参考文档 |
| N6 | 某批上传失败 / 网络中断 | 展示失败文件名，可只重试失败批 |
| N7 | 只读账号直调接口 | 403 + 明确文案，不出现「看似成功」 |
| N8 | 与已有文档同名 | 默认不覆盖，明确告知将跳过；不静默覆盖他人文档 |

## 8. 已拍板决策

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| D1 | 上传件落点 Group | 缺省 `事件参考/{事件短号}-{标题}`，弹窗内可改 | 可追溯；与目录导入的清理候选隔离；避免沉到 `__root__` |
| D2 | 上传件文档身份 | 接受 `isImported=true`（Web 上传通道现状，本期不动） | 改动会牵动数据源语义与导入页，应单开需求 |
| D3 | 是否 wiki 写回 | **不写回**（`wikiWriteback: false`），与 Web 导入页刻意不同 | 事件页上传是「补证据」，不应在用户 wiki 目录凭空生文件 |
| D4 | 重名冲突默认策略 | `skip`（不覆盖已有文档），并列出被跳过项 | 静默覆盖他人文档风险高于便利收益 |
| D5 | 「最多 10 个」语义 | **选择即限制**：超 10 个整体阻止提交 | 截断会让人误以为全部上传成功 |
| D6 | 一期是否支持拖拽 | 不支持；仅「选择文件」（原生选择器无法选目录） | 最低成本满足「不能上传目录」；拖拽需判 `webkitGetAsEntry().isDirectory`，列 P2 |
| D7 | 上传件可见性 | 普通 wiki 文档，立即可检索，不随事件阶段变化 | 与「外部引用」语义一致；`lifecycle=event` 会与参考文档语义冲突 |

## 9. 关键假设

| 假设 ID | 内容 | 错了会怎样 | 验证方法 |
|---|---|---|---|
| A1 | 上传件应立即可检索、不随事件阶段变化 | 若要「仅本事件可见」，生命周期设计需重做 | 已在 D7 固化 |
| A2 | 入口放卡头第三按钮 | 若改为收进「＋ 添加」下拉，可发现性下降 | 已在 ASCII 确认 |
| A3 | 10 个是「轻量补料」定位 | 若真实场景一次补 20 篇，会成为主要摩擦点 | 上线后按实际使用量复盘 |
| A4 | 复用 `/api/import/{upload,run}`，不新建导入内核 | 若必须新建端点，工作量增加 | 技术设计阶段确认 |

## 10. 建议下一步

2. 技术设计通过后按 `plan-track` 建档实施。
