## 3. 关键实测结论

- 1440 / 1200 / 1024 / 901 / 390 均无横向溢出；390 下新建/编辑弹窗、密码面板、保存按钮均可达。
- 长用户名（64 字）与长 Token 名（64 字）在成员表、编辑弹窗、抽屉、个人中心均正确省略，操作按钮不被挤出。
- Token 表权限列宽度可容纳「只读 / 读写」，无「只读 …」裁切。
- 撤销按钮对比度：浅色 5.15:1、深色 6.33:1，满足 AA。
- 密码面板头部/正文/工具提示三处口径一致；密码框 Enter 直接重置，不再误触账号保存；重置后焦点回到「重置密码」。
- Token 创建成功后焦点落到「复制」按钮并滚动到明文区域。
- 新建账号与编辑账号均使用上方 label；390 下新建弹窗完整可用。
- 抽屉说明文字位于表格上方且在 `<table>` 之外。
- 两个内联面板互斥：一个展开时另一个入口禁用并显示原因；保存拦截保留。
- 密码框 / Token 名称框的 Enter 已加 `isComposing` 守卫（静态检查，未注入真实 IME 事件）。
- 全程无 console / page 错误。

## 5. 未覆盖 / 已知边界

1. **真实产品未实现**：本报告只验证 demo；`web/src/pages/UsersPage.tsx`、后端账号/Token/有效期接口尚未按本需求改造。所有 UI 限制（按钮禁用、隐藏入口）不能替代后端校验。
2. **Token 权限收紧语义**：demo 按账号当前权限动态收紧显示，未改写 Token 的 `readOnly`；账号升回读写后 Token 恢复读写。是否永久降级待拍板。
3. **Token 表单滚动**：桌面为单列；1440×980 下内联表单的「创建 Token」可能需要轻微滚动。未改双列。
4. **其他弹窗排版**：个人中心「修改密码」与「创建 MCP Token」弹窗仍为左侧 label；本轮只统一了新建/编辑账号。
5. **超长用户名 toast**：390 下 64 字用户名的成功 toast 会折成多行约 2.2 秒，属全局 toast 行为。
6. **数据与持久化**：demo 数据在内存中，刷新复位；真实实现需落 `~/.ki/users.json` / Token 存储并处理后端并发与会话失效。
