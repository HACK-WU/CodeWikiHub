# 需求：用户管理页与个人中心改版

> **父需求**：REQ-20261103-001《Web 账号登录与只读权限》
> **当前形态**：可交互 demo，未进入真实产品实现
> **Demo**：`demo/users-page-v2/index.html`（零构建，数据在内存中，刷新复位）
> **依据**：2026-11-04 多轮设计确认、`/frontend-walkthrough` 走查与修复、产物实测

## 1. 背景与目标

原有 Web 账号能力已经提供管理员 / 读写 / 只读三类账号与只读拦截，但用户管理页仍是“把字段平铺在表格里”的形态：权限、状态、密码、Token 分散在多个入口，危险操作与普通编辑混在一起，管理员自身保护与 Token 归属规则也不够直观。

本次改版的目标：

1. **把管理员与普通用户的界面分开**：管理员进入「用户管理」，普通用户进入「个人中心」；成员账号列表只对管理员可见。
2. **把编辑收进一个入口**：成员行只保留「编辑 / 删除」，权限、状态、有效期、密码、MCP Token 全部在编辑弹窗内完成。
3. **把账号安全规则前置**：唯一管理员不可降级/禁用/删除；当前用户不可删除/禁用自己；账号过期或禁用时 Token 同步失效。
4. **把 MCP Token 变成账号资产**：按账号归属、按账号权限收紧、普通用户有数量上限、CLI 创建的 Token 默认归管理员。
5. **把查看与修改分开**：成员行可点击打开只读详情抽屉；抽屉不提供任何写操作。

## 2. 范围

### 2.1 本次做

- 用户管理页 / 个人中心两套页面形态与入口分流。
- 成员账号列表、账号详情抽屉、账号编辑弹窗、新建账号弹窗。
- 账号有效期、状态、权限、密码重置的交互与展示规则。
- 按账号管理 MCP Token（创建、查看、撤销、权限收紧、数量上限、失效展示）。
- 唯一管理员与当前用户的自我保护规则。
- 表格、抽屉、弹窗、提示、日期选择器、响应式与键盘/焦点口径。
- 上述内容的可交互 demo 与验证报告。

### 2.2 本次不做（或不在本子需求内）

- 真实产品代码实现；当前只落 demo 与需求，产品页面未改。
- SSO / OIDC / 多管理员 / 账号分组 / 审计日志。
- MCP Token 的 scope 授权模型（沿用父需求的全 scope 口径）。
- 非回环登录、安全基线、会话存储等父需求已覆盖内容。
- CLI 用户管理命令本身（沿用父需求 `ki user ...`）。

## 3. 角色与账号规则

| 角色 | 页面入口 | 成员管理 | 数据源 / 任务删除 | MCP Token 数量 | Token 权限上限 |
|---|---|---|---|---|---|
| 管理员 admin | 用户管理 + 个人中心 | 全部成员 | 允许 | 不限 | 只读 / 读写 |
| 读写账号 editor | 个人中心 | 不可见 | 不可执行 | 10 | 只读 / 读写 |
| 只读账号 viewer | 个人中心 | 不可见 | 不可执行 | 10 | 仅只读 |

### 3.1 唯一管理员

- 系统中只能有一个 `admin` 账号。
- 管理员权限固定为「全部权限」，不可在 Web 上调整。
- 管理员不可被降级、禁用、删除；Web 只允许修改自己的密码。
- 管理员账号只能通过 CLI 创建：`ki user create <用户名> --role admin`。
- 若未来出现多管理员诉求，需另立需求，不在本次放开。

### 3.2 当前用户自我保护

- 当前登录用户不可删除自己，也不可禁用自己。
- 管理员天然受唯一管理员规则保护；普通用户即使未来获得成员管理能力，也必须遵守本规则。
- 删除成员前必须二次确认，确认文案需列出「登录失效、Token 失效、数据保留口径」等影响。

### 3.3 账号有效期与状态

- 有效期支持「永久」与「指定时间」两种；指定时间必须晚于当前时间。
- 账号状态：启用 / 已禁用 / 已过期。
- 已禁用：立即无法登录，现有会话失效，名下 Token 全部失效；重新启用后 Token 恢复。
- 已过期：立即无法登录，现有会话失效，名下 Token 全部失效；延长有效期到未来后 Token 恢复。
- 过期不是删除：文档、对话、Token 记录仍保留，仅不可用。
- 成员列表需同时展示账号状态与有效期；已过期用 warning 语气，不使用普通灰色。

## 4. 页面结构

### 4.1 管理员：用户管理

页面标题为「用户管理」，包含：

1. **当前登录账号卡片**：管理员身份、固定权限、锁定说明、状态、最近登录、创建时间、账号有效期；提供「编辑」（仅密码）。
2. **成员账号卡片**：仅管理员可见；标题旁标注「仅管理员可见」；右上角「新建账号」。
3. **成员账号列表**：账号、权限、状态、有效期、MCP Token 数量、最近登录、操作。

### 4.2 普通用户：个人中心

页面标题为「个人中心」，包含：

1. **我的账号卡片**：账号名、角色、权限简述、状态、最近登录、创建时间、账号有效期；提供「修改密码」。
2. **MCP Token 卡片**：当前账号的 Token 列表、数量、创建入口。
3. 不展示成员账号列表，不展示详细「我的权限」矩阵；权限只用一句可读描述表达。

### 4.3 管理员个人中心

- 管理员也可以进入个人中心查看自己的账号与 Token。
- 管理员个人中心的 Token 数量显示「已创建 N · 不限」。
- 管理员个人中心不展示成员列表。

## 5. 成员账号列表

### 5.1 列与展示

| 列 | 规则 |
|---|---|
| 账号 | 用户名；超长省略并保留完整 `title`；右侧有「›」提示可点击 |
| 权限 | 管理员 / 读写 / 只读徽标；管理员固定为全部权限 |
| 状态 | 启用 / 已禁用 / 已过期；圆点 + 文案 |
| 有效期 | 永久或到分钟的时间；过期使用 warning 色 |
| MCP Token | 数量；账号禁用/过期时追加「已失效」；0 用弱化色 |
| 最近登录 | 到秒；从未登录显示「—」 |
| 操作 | 仅「编辑」「删除」两个按钮 |

### 5.2 行交互

- 点击行（账号区域）打开账号详情抽屉；点击「编辑 / 删除」只执行对应操作，不打开抽屉。
- 行支持键盘 Enter / Space 打开抽屉；抽屉关闭后焦点回到触发行。
- 行内有可点击箭头，避免“只能靠猜”才知道行可点。
- 长用户名不得撑破表格：固定列宽 + 省略号 + 完整 `title`；操作按钮必须始终可见。

### 5.3 新建账号

- 仅管理员可见「新建账号」。
- 字段：用户名、初始密码、权限（读写 / 只读）、有效期（永久 / 指定时间）。
- 用户名 1–64，只允许字母、数字、点、连字符、下划线；密码 8–128。
- 表单统一使用上方 label 的纵向布局，与编辑弹窗一致。
- 管理员账号不能在此创建，页面需明确提示只能走 CLI。
- 390 宽下弹窗必须完整可用：内容可滚动、底部按钮可达、无横向溢出。

## 6. 账号详情抽屉

- 从成员行打开，宽度与数据源详情抽屉一致（`70vw`，最小 520，最大视口宽）。
- **只读**：不提供编辑、删除、管理 Token、新增 Token 等任何动作。
- 头部展示状态、角色、最近登录；标题为「账号详情 · 用户名」。
- 账号信息展示：账号名、权限徽标、账号有效期、创建时间、账号 ID。
  - 状态与最近登录只在头部出现一次，不在信息区重复。
- MCP Token 区：
  - 标题旁显示数量（例如 `2 / 10`）；管理员显示不限口径。
  - 说明文字放在表格上方、表格之外。
  - Token 以只读表格/列表展示：名称（带 key 图标）、权限、访问范围、创建者、创建时间。
  - 不可出现「管理 Token」按钮。
- 关闭方式：✕、遮罩点击、Esc；关闭后焦点回到触发行。

## 7. 编辑账号弹窗

- 宽度 880px；窄屏自适应。
- 标题「编辑账号 · 用户名」；超长用户名单行省略，关闭按钮始终可见。
- 顶部显示账号元信息（用户名、创建时间、最近登录）。
- 字段：
  - 权限：读写 / 只读；管理员不进入此弹窗。
  - 状态：启用 / 禁用。
  - 有效期：永久 / 指定时间；复用数据源定时同步的自定义时间选择器。
- 密码重置：
  - 从字段列表中移出，作为顶部「重置密码」工具 + 内联面板。
  - 面板包含新密码输入（8–128）、取消、确认重置。
  - **确认后立即生效，与底部「保存」无关**；文案必须与这一行为一致。
  - 面板打开时，账号「保存」被拦下并提示先完成/取消重置。
  - 密码框 Enter 等同确认重置；需处理中文输入法组合态，避免误提交。
  - 确认成功后焦点回到「重置密码」按钮；取消后同样回到该按钮。
- 账号字段保存：
  - 只保存权限、状态、有效期；保存成功后关闭弹窗并刷新列表/抽屉。
  - 有未保存的账号字段变更时，不允许新增 Token（按钮禁用 + 就地原因）。
- 弹窗内两个内联面板互斥：
  - 新增 Token 打开时，重置密码按钮禁用并说明原因。
  - 重置密码打开时，新增 Token 按钮禁用并说明原因。
  - 不允许两个面板同时展开。

## 8. MCP Token

### 8.1 归属与数量

- 每个 Token 必须归属一个账号。
- 管理员创建 Token 数量不限；普通账号最多 10 个。
- 管理员可以为成员创建 Token；普通用户只能为自己创建。
- 成员列表需展示 Token 数量；账号过期/禁用时显示「已失效」。
- CLI 创建的 Token 默认归属管理员，创建者标注为「CLI」，不占用普通用户的 10 个额度。

### 8.2 权限

- Token 权限分只读 / 读写。
- Token 权限不能超过所属账号权限：
  - viewer 只能创建/持有只读 Token；
  - editor 可创建只读或读写 Token；
  - admin 可创建只读或读写 Token。
- 账号从 editor 降为 viewer 后，原有读写 Token 的**实际权限应显示为只读**，并给出「账号为只读，实际权限已收紧」说明。
  - 当前 demo 采用「按账号当前权限动态收紧显示」；是否在保存账号时把 Token 记录永久降级，待产品拍板（见 §11）。
- 只读账号的新增 Token 表单中，读写选项必须禁用，不能只靠提交时静默降级。

### 8.3 创建与展示

- 编辑弹窗与个人中心都提供「新增 Token」；不再使用「管理 Token」二级入口。
- 编辑弹窗内的新增 Token 使用内联面板，不弹二级弹窗。
- 字段：名称（1–64，同一账号下不重名）、权限、访问范围（全部 / 指定知识库）。
- 创建成功后：
  - 明文只显示一次，提供复制按钮；
  - 明文区域必须明确提示「关闭后无法再次查看」；
  - 焦点落到复制按钮，便于键盘用户立即复制；
  - 列表与成员行的 Token 数量同步更新。
- Token 列表字段：名称（key 图标）、权限、访问范围、创建者（本人 / 管理员 / CLI）、创建时间、操作（撤销）。
- 撤销必须二次确认；撤销后数量同步更新，达到上限时「创建 Token」恢复可用。
- 达到 10 个上限时：创建按钮禁用，并在表格外显示可见原因；不能只依赖 `title`。
- 说明文案「用于 MCP 客户端连接本知识库；Token 明文只在创建时显示一次」必须放在表格之外；个人中心放在卡片外/表上方，编辑弹窗与详情抽屉放在表格上方。

### 8.4 失效与恢复

- 账号禁用或过期 → 名下所有 Token 立即失效；详情抽屉要明确告知「以下 Token 已全部失效」。
- 账号重新启用或延长有效期 → Token 恢复；无需重新创建。
- 撤销/删除账号时，Token 的删除/失效口径需在确认文案中写清。

## 9. 交互与视觉口径

### 9.1 表格

- 成员表与 Token 表使用固定布局，避免长文本把操作列挤出视口。
- 成员表列宽在桌面保持稳定；901–1100px 区间需收缩内边距，防止权限/时间列被裁切。
- Token 表头使用弱化底色，行间有分隔线；不要整表一个背景色。
- 权限列宽度必须容纳「只读 / 读写」徽标，不能出现「只读 …」省略。
- 操作列：成员行是带边框的「编辑 / 删除」；Token 行的「撤销」使用低干扰文字按钮，但对比度需满足 AA（浅色 ≥ 4.5:1，深色同理）。
- 长名称使用 `ellipsis + title`；悬停可看全名。

### 9.2 提示与空态

- MCP Token 说明、数量上限、失效说明都必须可见，不能只放在 `title` 或悬浮提示里。
- 空态：无成员 / 无 Token 时给出下一步动作（新建账号 / 新增 Token）。
- 过期、禁用、上限、未保存冲突等状态使用 warning 语气，但不要伪装成错误。

### 9.3 键盘与焦点

- 行可键盘打开抽屉，关闭后焦点回到触发行。
- 弹窗开关、抽屉开关需管理焦点。
- 内联面板隐藏后焦点不能掉到 `body`：
  - 密码重置确认/取消 → 回到「重置密码」；
  - Token 创建成功 → 落到复制按钮。
- Enter 行为必须符合当前上下文：密码框 Enter 确认重置，Token 名称 Enter 创建 Token；中文输入法组合态下不触发提交。
- 两个内联面板的禁用按钮需有就地原因，不能只置灰。

### 9.4 响应式

- 1440 / 1200 / 1024 / 901 / 390 均无横向溢出。
- ≤900：成员表与 Token 表转为堆叠卡片行，隐藏表头，用 `data-label` 补充字段名。
- 390：抽屉全宽；编辑/新建弹窗不超宽，底部按钮可达；密码面板、Token 表单可滚动到操作按钮。
- 深色主题下表格、提示、禁用态、危险操作保持可读。

## 10. 验收标准

### 10.1 管理员与个人中心

- [ ] 管理员页面标题为「用户管理」，成员列表可见；普通用户页面标题为「个人中心」，无成员列表。
- [ ] 管理员可进入个人中心；普通用户无用户管理入口。
- [ ] 当前用户不能删除/禁用自己；管理员不可降级/禁用/删除，权限固定。

### 10.2 列表与抽屉

- [ ] 成员行只有「编辑 / 删除」；点击行打开只读抽屉，点击按钮不打开抽屉。
- [ ] 抽屉宽度与数据源详情一致，无任何写操作按钮；关闭后焦点回到行。
- [ ] 长用户名（64 字）不撑破表格，操作按钮可见；390 编辑标题省略、关闭按钮可见。

### 10.3 编辑与密码

- [ ] 编辑弹窗包含权限、状态、有效期；时间选择器与数据源定时同步一致。
- [ ] 密码重置独立于「保存」，确认后立即生效；文案无「保存后」矛盾。
- [ ] 密码框 Enter 确认重置；确认/取消后焦点回到「重置密码」。
- [ ] 有未保存密码/ Token 草稿时，保存账号被拦下且草稿保留。

### 10.4 Token

- [ ] 普通账号最多 10 个 Token，管理员不限；达到上限有可见提示，撤销后恢复。
- [ ] CLI 创建的 Token 归属管理员并标注 CLI。
- [ ] viewer 只能创建只读 Token；editor/admin 可选择只读或读写；Token 权限不超过账号权限。
- [ ] 账号禁用/过期后 Token 全部失效；成员列表与抽屉均可见。
- [ ] 编辑弹窗内联创建 Token，无二级弹窗；明文只显示一次，焦点到复制按钮。
- [ ] 长 Token 名不撑破编辑弹窗/抽屉/个人中心表格，操作按钮可见。

### 10.5 体验与质量

- [ ] 1440 / 1200 / 1024 / 901 / 390 无横向溢出；深色主题可读。
- [ ] 两个内联面板互斥，禁用按钮有就地原因。
- [ ] 无 console / page 错误。
- [ ] Demo 验证：设计检查 29/29；主回归 82/82、Token 36/36、抽屉 24/24、走查修复 59/59。

## 11. 待拍板 / 未完成

1. **Token 权限收紧方式**：当前 demo 是「按账号当前权限动态收紧显示」，不修改 Token 记录的 `readOnly`；账号升回读写后 Token 恢复读写。若要求降级时一次性永久降级，需要在保存账号时批量改写 Token，并同步后端。
2. **真实产品实现**：当前只有 demo；`web/src/pages/UsersPage.tsx` 等产品页面尚未按本需求改版，后端也尚未提供账号有效期、Token 归属/上限、CLI Token 归属等完整能力。实施前需按父需求的能力矩阵补齐服务端校验；UI 禁用不能作为安全边界。
3. **Token 表单单列**：新增 Token 内联表单在桌面为单列竖排；1440×980 下创建按钮偶尔需要轻微滚动。若要求一屏收口，可在 ≥700px 改为双列（权限 / 访问范围并排）。
