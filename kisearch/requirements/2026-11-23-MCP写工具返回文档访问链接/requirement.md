# PM 报告：MCP 写工具返回文档访问链接

模式：M1 需求定义（一次成型档）
证据声明：最高 **🟢 实证（代码直读）**——MCP 工具返回构造、SDK 请求上下文能力、`/browse` 深链接契约、`--web` 静态服务开关均已读到源码。**未运行实测**（未起 daemon、未真实点开生成出的链接），验收环节必须以真机走查补齐。

**拍板结论（2026-11-23，用户确认）**：U1=**C'（Host 为默认 + `publicUrl` 显式覆盖；评审后按 B3 修订，原 C 的兜底分支不可达）**、U2=A（无前端时省略字段）、U3=A（`url` 绝对地址 + 批量逐条）、**U4=不加开关（默认开启）**、U5=删除不给链接、U6=本期不含读工具、U7=根目录用 `group=__root__`、U8=默认一律给。据此状态由 `草案` → `已确认`，进入技术设计。

## 1. 执行摘要

- 需求成立且落点很窄：**在 MCP 写工具的结果里加一个 `url` 字段**，值形如 `http://<host>:<port>/browse?scope=..&group=..&relation=..`，让「AI 改了文档 → 用户一键跳过去看/改」从 4~6 步缩到 1 步。🟢
- 落点可行但**有一个必须先解决的取址问题**：当前 6 个写工具的回调签名只接 `args`、不接 SDK 的 `extra`（`src/lib/mcp-tools/sync-relation.ts:21`），拿不到请求 Host。SDK 1.29.0 的 HTTP 传输**已经**把 `requestInfo{headers,url}` 传进工具回调（`webStandardStreamableHttp.js:390-393`），所以只需改工具层，不需要动 SDK 或加反代约定。🟢
- 三个必须先定的口径：① 取址用**请求 Host 头**（你的实例是 7433，默认是 7423，**绝不能写死**）；② 只在 daemon 真的提供前端页面（`--web` + `web/dist` 存在）时才给链接，否则**省略字段**而不是给一条 404 链接；③ 单条 `ki_sync_relation` 的结果**目前不回显 group**（`src/sync-relation.ts:1626-1651`），必须先补，否则 URL 只能拿入参猜。🟢
- 明确排除 `ki_store` / `ki_bulk_store`：它们只写向量索引、不落 KB 文件，**在浏览页里根本没有落点**（`src/store.ts:43-49`），给链接就是骗人。
- **可行性 / 复杂度**：整体 `⚠️ 有条件可实施`（3 条前置条件，均有明确满足方式）；整体复杂度 **中**（主导：结构面 + 确定性）。4 条需求中 3 条可实施、1 条有条件；0 待验证、0 阻塞。

### 3.2 负向需求（内联筛选，8 条）

| # | 场景 | 期望行为 |
|---|------|---------|
| N1 | daemon 没开 `--web`（或 `web/dist` 缺失） | **不输出 `url`**（不得给空串、不得给会 404 的链接） |
| N2 | 纯 stdio 直连（无 daemon、无 `requestInfo`） | 同 N1，静默省略；不得因取不到 Host 而报错或降级整个写入结果 |
| N3 | 反代 / 路径前缀（`https://ki.example.com/ki/browse`） | Host 头 + `X-Forwarded-*` 都不可靠时，必须能靠配置项覆盖；覆盖也不存在时宁可省略 |
| N4 | relation 名含中文 / `#` / `&` / `+` / 空格（如 `APIResource把ReadTimeout…`） | 一律走 `URLSearchParams` 编码；**禁止字符串拼接**；空格编码为 `%20` 或 `+` 均可但要能被 `URLSearchParams.get` 还原 |
| N5 | 批量里部分成功 / 部分 skipped / 遭遇 `stopReason` 中断 | 只有真正写入成功的条目带 `url`；被跳过与失败条目一律不带 |
| N6 | 文档在根目录（group 留空 → `__root__`） | URL 用 `group=__root__`（浏览页已支持）；若决定不支持则**显式省略**而非给错链接 |
| N7 | 链接生成后文档被改名 / 移动 / 删除 | 打开时浏览页报「未找到」并可继续浏览（现状行为即可）；不得因这条把链接做成「永久短链」 |
| N8 | 鉴权开启、用户未登录或该账号无此 scope 权限 | 未登录 → 跳登录后**回跳原地址**；无权限 → 明确报无权（不是「文档不存在」）。链接本身不得携带 Token |

| U2 | **web 未开启时的行为** | A 省略字段；B 给相对路径 `/browse?...`；C 给绝对地址 + 提示「未开启前端」 | **A ✅** | 选 B/C 会产出必然 404 或半残链接，AI 会当真转述给用户 |
| U3 | **字段名与粒度** | A `url` 绝对地址 + 批量逐条；B `url` 相对路径；C 批量只给顶层 `urls[]` | **A ✅** | 若在意批量输出膨胀，改 C 需在客户端侧做一次映射 |
| U4 | **是否加开关**（`mcp.http.docLinks`） | A 加；B 不加 | **B ✅ 不加，默认开启** | 远程/多租户没有代码级退路，只能靠**不启 `--web`** 关闭；风险由用户接受 |
| U5 | **删除是否给 group 浏览入口** | A 什么都不给；B 给 `groupUrl` | **A ✅（本期）；B 留后续** | 给错层级会被当死链 |
| U6 | **本期是否一并覆盖读工具（R9）** | A 不含；B 含 | **A ✅** | 读工具输出体量是另一个量级（每次 10 条命中），需单独评估 token 成本 |
| U7 | **根目录文档** | A 用 `group=__root__`；B 省略 | **A ✅**（前端已支持） | 选错会给出打不开的链接 |
| U8 | **远程/多租户是否默认关** | A 仅回环请求默认给；B 一律给；C 一律需显式开启 | **B ✅**（无开关，靠 `--web` 关） | 保守口径会让人误以为功能「时好时坏」 |

> U4 拍板后的一处连带改动：影响面表「安全」一行从「留开关」改为「无开关，退路是关 `--web`」；R3 不再包含开关实现，只保留 `publicUrl` 兜底配置。

## 6. 关键假设

| 假设 ID | 内容 | 错了会怎样 | 验证方法 |
|---------|------|-----------|---------|
| A1 | 生产使用中 daemon 大多以 `--web` 启动（否则功能对多数人无感） | 若多数人不带 `--web`，R6（引导）与整条需求价值都要下调，优先做「提示如何开启 web」 | 你的实例是否 `--web`（你给的 7433 地址说明是）；抽查几个团队实例 |
| A2 | 用户是在**同一网络可达**的机器上打开链接（不是容器内 `127.0.0.1`） | Host 头给出的地址可能对用户不可达 → 必须靠 U1-C 的配置兜底 | 用容器/远程部署各试一次 |
| A3 | AI 客户端会把结果里的 `url` 转述给用户（而非当作内部字段忽略） | R6 的必要性上升；若客户端普遍不转述，可能要改用 `hint` 文案带链接 | 3 个客户端抽测（IDE / Chat / CLI） |
| A4 | 链接是「快照」：文档改名/移动后失效可接受（非短链） | 若要求永久有效，需要引入 docId 路由（前端新页面），复杂度整体升到高 | 问用户是否会转发链接给别人长期使用 |
| A5 | 批量 20 条 × 一条链接的输出膨胀可接受 | 若不可接受，改 U3-C（顶层 `urls[]`）或只给第一条 | 实测一次 20 条 bulk 的 token 增量 |
| A6 | 7413/7433 之类端口由 lock/配置决定，工具层不需要知道「真实监听端口」——用请求 Host 即可 | 若某些客户端经端口转发后 Host 不是用户可访问地址（少见），必须配置覆盖 | 起 daemon → 经 nginx 转发 → 看 Host |

## 8. 明确不做 / 排除项

| 排除项 | 理由（证据） |
|--------|-------------|
| `ki_store` / `ki_bulk_store` 返回链接 | 它们只写向量索引（`src/store.ts:43-49`），不落 KB 文件、不出现在 `/api/doc/list`（该接口读 relations-cache + local KB，`mcp-http-api.ts:1524-1537`）⇒ 浏览页没有落点，给链接必然是死链 |
| 纯 stdio 直连返回链接 | 无 HTTP 请求上下文，拿不到 Host；给死链比不给更糟（N2） |
| 为链接引入「永久 docId 路由」 | 前端现无此路由（`web/src/router/routes.tsx` 只有 `/browse`），属另一量级改造，列为「若 A4 被推翻再议」 |
| 在 `executeSyncRelation` 等业务函数里拼 URL | 会污染 CLI 输出并打破「业务函数不依赖 HTTP 上下文」的分层，也让既有 200+ 直调单测需要改；正确落点是 MCP 工具层 |

### 备选方案（为什么选服务端加字段）

| 方案 | 做法 | 代价 | 结论 |
|------|------|------|------|
| **A 服务端加字段（本需求）** | 工具层注入 `url` | 改 5~6 个工具文件 + 1 个 helper + 1 个上下文 | **选它**：唯一能同时拿到正确 host:port 又保证编码正确的位置 |
| B 靠在提示词/skill 里让 AI 自己拼 | 告诉模型模板，让它拼 | 模型不知道端口（默认 7423 ≠ 实际 7433），中文/`#` 编码常错 | 不选（只作 A 的补充：R6 引导转述） |
| C 只在 MCP `instructions` 下发 base URL | 每个会话给一次基地址，AI 自己拼 | 输出零膨胀，但编码与拼接仍易错，且客户端是否采纳 instructions 不可控 | 不选（可作为 A 的加强项） |
| D 前端加「复制链接」 | 人自己复制分享 | 帮不了「AI 写完 → 人要去看」这条主路径 | 不替代，列为 R10 另立 |
