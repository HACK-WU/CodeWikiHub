# 实施计划：MCP 写工具返回文档访问链接

设计基线：`design/DESIGN.md` v2 + `design/S01` v2 + `design/S02` v2 + `design/S03` v2（评审通过）
骨架冻结 commit：—（本需求不走骨架先行，单窗口串行直接实现）
执行方式：**单窗口串行**（3 个阶段，不是三个并行窗口）

## 1. 前置层（不进批次，先于全部工作项）

| # | 前置项 | 内容摘要 | 完成判据 |
|---|--------|---------|---------|
| P1 | **语义契约定稿** | `WebRuntime` / `DocTarget` / `DocLinkContext` 三个类型与 `docUrl` / `withUrl` / `resolveBase` 三个签名（父文档 §4.1 为唯一权威） | 三个类型与三个签名**逐字落到代码**，之后任何人只调不改；签名变更须回改父文档 §4.1 |
| P2 | **全局清单（配置键）** | `mcp.http.publicUrl`（string，默认无，显式覆盖，含子路径） | `config-schema.ts` + `config.ts` 同步完成（schema 加了不同步解析 = 静默失效，见该文件既有注释）；配置文档条目归 S-03 |
| P3 | **公共代码冻结范围** | `src/lib/mcp-runtime.ts`（快照）与 `src/lib/mcp-tools/doc-link.ts`（取址+拼装） | 两个文件**只增不改**：后续任何需求若需改它们，先回改 S-01 设计，不许在实现窗口里顺手改 |
| P4 | **横切约定** | ① URL 编码**只准** `URLSearchParams`，禁止手拼或 `encodeURIComponent` 拼串；② URL **不含任何凭证**（只有 scope/group/relation）；③ 链接生成失败一律**吞掉**、不得影响写入结果；④ 不新增错误码、不改任何既有错误码 | 四条写进 `doc-link.ts` 文件头注释；实现期出现"要不要加个参数/加个错误码"的念头时以此为准 |
| P5 | **权限模型** | **无新增**：链接是纯字符串，不携带身份；Web 侧沿用既有登录 + scope 鉴权 | 确认无新增权限点（`route-permissions.ts` 零改动）；负向用例沿用现状（无权限 → 提示无权），进 S-03 文案 |

> 前置层只有 P1/P2 会产生代码改动（类型与配置键），P3~P5 是纪律与清单，全部在写业务代码**之前**定稿。

## 1.5 前端视觉基线（壳）

**无（本次不涉及前端页面）**。`/browse` 的读取契约不变（`BrowsePage.tsx:305-342`），本次只生成指向它的 URL；无新增页面、无样式改动，故壳轨不适用，也不触发界面确认闸门。

**为什么 S-03a 并进第 2 批而不是单独一批**：它与 S-02 改的是**同一批文件的同一处**（`server.tool()` 的 description 字面量就在回调旁边）。拆成两批等于同一文件被两批先后触碰，直接违反「同一文件被两个及以上工作项碰 → 一律不同批」——所以要么合并，要么串行重开同一个文件，合并显然更省。

**【批次数告警】** 实现批只有 **2 批**（S-01 → S-02∥S-03）。不是骨架缺口，而是真实依赖结构：S-02 没有 S-01 的 `docUrl` 就无法验证。第 3 批是验证而非编码。

## 3. 每批检查点（批次边界）

| 检查点 | 判据 |
|--------|------|
| ① 类型与测试 | 第 1 批收尾：`npx tsc -p tsconfig.json --noEmit` 无**新增**错误（仓库既有 7 处无关错误不算）；`test/mcp-doc-link.test.ts` 全绿 |
| ② 契约是否需修订 | 仅在此处可改父文档 §4.1。若实现中发现签名必须变（例如还需传 `group` 归一函数），**先回改设计 + 重跑增量评审**，不许只改代码 |
| ③ 主干可编译可运行 | 每批收尾 `npm run build` 通过；第 2 批收尾另跑既有回归 `test/mcp-*`、`test/edit-relation.test.ts`（**必须全绿，因为改了它们的返回字段**） |
| ④ daemon 生效 | 批次收尾不算"验收完成"——daemon 里跑的是旧代码，**必须 `ki mcp restart` 后**才算第 3 批可开始 |

## 4. 执行方式

**单窗口串行**，严格按：前置（P1→P2）→ 第 1 批 S-01 → 第 2 批（S-02 + S-03a + S-03b）→ 第 3 批验证。

**本可并行但本次串行的相邻项**（信息缺失不报错、只让人多等，故显式列出）：

| 相邻项 | 本可 | 本次 | 原因 |
|--------|------|------|------|
| S-03b（docs）与 S-02（代码） | ∥ 可并行 | 已排同批，顺序做 | 同一人、docs 需要对着最终返回体写样例 |
| S-01 的 `doc-link` 单测与 `mcp-http` 置位 | ∥ 可并行 | 顺序做 | 置位点要 import 新模块，先有模块再接线更省来回 |

**验收效力边界**：本计划只保证「设计 §2 承接验收项」范围内达成；若需求侧还有未写进验收标准的期望（例如"希望链接也能出现在 `ki_search` 结果里"），**不会有人报警**——那属 R9，另立需求。
