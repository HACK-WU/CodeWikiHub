# PM 报告：混合检索的文档内高亮与开关

- **模式**：M1 需求定义（一次成型档）
- **触发（三轮）**：

  - 第二轮（口径澄清，推翻 v2 主推方向）：「① 混合搜索向量失败会降级为全文搜索，降级时高亮默认就是开启的；② 开关针对的是混合搜索中的语义向量检索；③ **结果列表不需要高亮，只有点开文档时才展示高亮**；④ 功能其实已经有了，**复用文档内搜索的功能函数接口即可**。」

## 0. 关键结论（先读这一段）

### 0.1 最终口径矩阵（三轮澄清 + 一条代码现状）

| 情形 | 结果列表 | 打开文档的正文 | 自动滚动到首个命中 | 开关 |
|---|---|---|---|---|
| **全文检索**（`resultMode === 'fulltext'`） | 高亮（现状） | 高亮（现状） | **滚动**（现状，不变） | **无效**（禁用灰掉） |
| **混合检索**（`resultMode === 'hybrid'`） | **不高亮**（明确不做） | **开关控制**（默认开） | **不滚动**（v4 新增） | **生效** |
| **降级**（混合 + `degradeReason !== null`） | **高亮**（= 全文待遇，Q1 采纳） | **由开关控制**（Q2 裁决：不看降级） | **不滚动** | **生效** |

**两条判据分开写，不要混用**：

```
// ① 结果列表高亮（全文 或 降级 都算"全文待遇"）
listHighlight = (resultMode === 'fulltext') || (degradeReason !== null)

// ② 打开文档时是否传 highlightQuery + 开关是否可用
docsHighlight = (resultMode === 'fulltext') ? true : 开关为开     // 降级不影响 ← Q2
switchDisabled = (resultMode === 'fulltext')                      // 未检索也可用：偏好应随时可设（§10.4 修正）
```

> **严禁用 `fullTextOnly`**（模式按钮的**选择态**，点击即变、不触发检索）；`resultMode`（`SearchPage.tsx:135`，检索完成时写 `:335`）与 `degradeReason`（`:356-358`，每次检索重设）才是"当前结果"属性。用错会导致"搜完混合 → 点全文不重搜 → 开关错位"（§0.5）。

### 0.2 实现：复用既有文档内搜索能力 + 一处小改

**REQ-20261014-002「文档内搜索」已实施**（工作区未提交：`ModuleDrawer.tsx` / `AppShell.tsx` / `ki.css` 已改，新增 `web/src/lib/docFind.ts` + `web/test/doc-find.test.mjs`；meta 状态「实施中」v4）。可复用清单：

| 已有能力 | 位置 |
|---|---|
| 高亮内核 `applyDocumentHighlights` / `clearDocumentHighlights` | `ModuleDrawer.tsx:159-210`、`:130-137` |
| 定位 + 滚动 `focusDocumentHighlight`（**切 `--active` 与滚动耦合在一起**） | `ModuleDrawer.tsx:219-230` |
| 外部词入口 `highlightQuery` → 生效词 + 自动高亮 | `ModuleDrawer.tsx:370`、`:439-443`、`:568`、`:580-599` |
| **命中导航条**（不展开查找栏时）：`n/m` 计数 + 「取消高亮」+「下一个命中」 | `ModuleDrawer.tsx:1172-1193` |
| 查找栏（Ctrl+F/「找」入口）与纯逻辑 / 单测 | `ModuleDrawer.tsx:1106-1152`、`web/src/lib/docFind.ts`、`web/test/doc-find.test.mjs` |

**改动面（v4 比 v3 多一处）**：
1. `SearchPage.tsx:698` —— `highlightQuery` 按 §0.1 判据传值（+ 开关 state/UI：建议参数行 `.ki-switch`、默认开、localStorage 持久化）；
2. `ModuleDrawer.tsx` —— **新增"打开时不自动滚动"的开关**（Q8）。原因：现有初始定位同时做"标记 active + 滚动居中"（`:585-590` 调 `focusDocumentHighlight`），且 `:605-618` 的 effect 在 `highlightCount` 变化时也会滚动 ⇒ 只在调用处跳过不够，需要引入"用户主动跳转前不自动滚动"的闸门（例如 `autoScrollRef`：打开时 false，用户点「下一个命中」后置 true）。

→ **不再是不改 `ModuleDrawer`**；但仍不改后端 / MCP 契约。**与 REQ-20261014-002 的未提交改动同文件**，须在其之上叠加（§7.3）。

### 0.3 开关语义边界：按"检索模式"生效，无法按"单条结果是否来自向量"生效

用户口径是「开关针对混合搜索中的语义向量检索」。技术边界（🟢）：后端 hybrid **不返回任何分路信息**（`src/search.ts:387` 仅 fulltext 填 `matches`；RRF 融合层只保留 6 字段 `src/lib/vector-client.ts:1044-1051`），前端拿到融合后的列表，无法判断某条来自向量路还是 BM25 路。⇒ 开关只能**按模式**生效（已由 Q2 裁决确认接受）。

### 0.4 "不滚动"的可用性保障（Q8 裁决后的必要配套）

不滚动 ≠ 用户不知道有命中（🟢 现状已具备）：
- 工具条命中导航条显示 **`1/N` 计数**（`ModuleDrawer.tsx:1172-1193`，查找栏未展开时显示）；
- 正文内所有命中处均有 `<mark class="ki-doc-highlight">` 黄色标记；
- 用户点「下一个命中」时照常滚动（主动跳转滚动保留）。

## 1. 目标与范围

- **目标**：混合（语义）检索时，**点开结果文档能直接看到查询词在正文中的命中标记与数量**（默认不跳转、不打断从头阅读），并且可用一个**只作用于混合检索**的开关关掉它；全文检索与结果列表行为保持现状。
- **范围**：`/search` 结果列表 → 打开文档查看器的传参链路；开关本体；`ModuleDrawer` 的"打开时不自动滚动"能力。
- **不在范围**：结果列表高亮（混合不做；全文/降级保持现状）；混合结果卡片内容口径（`r.original ?? r.content` 不改）；后端 / MCP 契约；浏览页；AI 引用预览链路（保持滚动定位）；文档内搜索本身（REQ-20261014-002）。

## 3. 负向需求

| # | 类别 | 场景 | 期望行为 |
|---|---|---|---|
| **N1** | 状态异常 | 开关在"混合结果"下的切换与降级态交叉 | **降级不改变开关语义**（R3）：开关关 → 降级时也不高亮；开关开 → 降级时高亮。不得出现"降级后开关失效" |
| **N2** | 状态异常 | ① 混合 → 全文 → 混合 切模式按钮（不重搜）；② 最近检索回放（`:372`）；③ 带参数 URL 刷新恢复（`:395`） | 开关在全文结果期间**禁用但保留用户值**；切回混合后按用户值生效（不被重置为默认） |
| **N3** | 误操作 | 开关切换时正有文档打开 | 已打开的文档查看器**不闪动、不重置滚动位置**（不因开关变化而改变当前文档） |
| **N4** | 状态异常 | **全屏切换**（正文容器重建） | 高亮保持；**不因重建而自动滚动**（R6 必须涵盖该场景，🟢 `:509-513` 容器重建会重跑渲染后 effect） |
| **N5** | 数据异常 | 混合结果 `original` 缺失（纯向量写入 / 原文召回降级） | 正文仍加载（`fallbackContent` 链路），高亮照常 |
| **N6** | 空结果 | 查询词在该文档中不存在（语义召回常见） | 命中导航条**不出现**（`count === 0`）；查找栏内显示既有 `describeFindMiss`「未找到「x」」；不得报错 |
| **N7** | 参数错误 | 查询词含正则元字符 / 超长 / 纯空白 | 字面量匹配（`escapeRegExp`）；超长走 `clampFindQuery`（≤200）；纯空白不高亮 |
| **N8** | 外部依赖 | 用户主动查找（点「找」/ Ctrl+F） | **不受开关影响**：关闭开关后仍可在文档内自由搜索并滚动跳转（用户主动 ≠ 自动） |

### 10.4 用户反馈修复（同日 · 「当前选择的就是混合检索，怎么关不了？？」+ 截图）

- **根因**：`switchDisabled` 原判据是 `resultMode !== 'hybrid'`，把**未检索（`resultMode === null`）**也判成"开关不适用" ⇒ 刚进页面 / 刷新后（结果属性还是 `null`）开关即为禁用（`aria-disabled=true` + `opacity .5` + `cursor: not-allowed`），点击被 `return` 拦掉；雪上加霜的是禁用态 `title` 文案写死为"全文检索（含降级）的正文高亮始终开启…"，与眼前选中的「混合」模式**对不上**，用户只能理解为"关不了"。
- **修法**：判据改为 **`resultMode === 'fulltext'`**（只有"当前结果是全文"时开关才无意义）；未检索同样可用（**开关是用户偏好，应随时可设**）；禁用态补**可见**说明「全文检索始终高亮」（不再只靠 hover）。
- **验证**：`temp/repro-doc-highlight-switch-disabled.cjs` 由 ❌ 翻转为 ✅（修复前 ① 禁用 + 点击被判定不可用；修复后 ① 可点、② 点击 `true→false` 有反应、③④ 全程可用）；单测 **263/263**（新增「禁用只发生在全文结果」锁定用例）；主 e2e **14/14**、降级 e2e **6/6** 回归通过。
- **口径更新（覆盖 §0.1 原表）**：开关可用性 = `resultMode !== 'fulltext'`（**未检索与混合（含降级）均可用**）。
