# REQ：事件分析数据链路

事件详情页的 AI 分析结论，目前只有「一句话总结 + ≤5 个因果节点（现象 / 直接原因 / 根本原因 / 影响面 / 建议）」，缺少一条直观的**执行路径**。本需求让**所有事件分类**的分析结论都固定给出一段「数据链路」文字树，并按「未确认点」的语法单开一块展示。

配套 demo（形态已确认）：`demo/ui/data-flow-tree/index.html`

## 1. 背景

### 1.1 现状

- 结论区结构：`conclusion`（一句话）+ `chain[]`（≤5 节点，每节点单行 ≤200 字，禁止代码块）。
- 截图里那种「链路：前端打开… → transfer_latest_msg → …」的**文字树，是模型在追问回答里自发产出**的（追问区走 Markdown 渲染），不是模板产物 —— 表现是「偶然有、看模型心情」。
- 产物文件 `{eventId}.analysis.json` 中**没有任何链路 / 数据流字段**；结论卡也不走 Markdown，`chain[].text` 被 `oneLine()` 压成单行，因此现有数据模型装不下多行树。

### 1.2 问题

- 因果链回答「为什么坏」，链路回答「坏在哪条路径上」。排障时缺后者，用户要自己在脑子里把调用链拼出来。
- 部分事件类型（性能优化 / 需求实现 / 技术债等自建类型）本就被要求「不必强求因果」，若没有链路，结论里几乎没有「路径」信息。

### 1.3 目标

1. 所有事件分类的分析结论**固定**包含「数据链路」块（不依赖模型心情）。
2. 形态采用**纯文本树**（等宽、保留空白、可复制），1:1 还原已被认可的截图形态。
3. 位置与「未确认点」同级、单开一块，不嵌在紫色结论壳内。

## 2. 已确认决策（用户拍板，不再追问）

| 编号 | 决策 |
|---|---|
| U1 | **形态 = 纯文本树**：产物存多行文本，前端用等宽 `<pre>` 原样渲染；不做结构化节点数组 |
| U2 | **位置 = 独立成块**：与「未确认点」同一套视觉语法（浅底 + 左 3px 竖条 + 顶部纯文字标题），与「分析结论」「未确认点」三者并列 |
| U3 | **覆盖所有分类**：`fault / perf / change / generic` 四档视角（`et_1~et_3` + `et_4` 与自建类型落 generic）**一个不漏**；只按视角换语义、不换结构、不设豁免 |
| U4 | **缺省口径 = 区块必在、内容可降级**：证据不足时块仍渲染，写明「已检查什么 / 缺什么证据 / 可以怎么追问」，**禁止编造链路** |
| U5 | **位置不可点**：树里的 `file:line` 是纯文本，不做胶囊、不挂代码快照（与现有节点区的可点胶囊刻意不同，接受该落差） |
| U6 | **MCP 外部上传支持写入**：`ki_event_edit action=analysis` 增可选字段，缺省不报错 |
| U7 | **追问补丁支持覆盖链路**：补丁带链路则替换，不带则**保留旧链路**（不得清空） |
| U8 | **人工编辑不开放**：沿用 H12「结论不可人工编辑」——编辑态 UI 不提供链路输入；但 `PATCH /analysis` **接口接受**该字段（供追问补丁采纳），与 H13 对 `conclusion` 的口径一致（**2026-11-24 设计阶段更正**：原文"PATCH 不加该字段"会让补丁永远带不上链路） |
| U9 | **不做局部更新**：「只改链路、不动结论」不支持，改链路 = 整份重传（沿用外部上传的整篇覆盖语义） |

| REQ-07 | 链路块可用性细节：复制按钮、纵向上限、横向滚动提示 | P2 | 复制内容与展示逐字一致；>520px 才纵向滚动 |

## 4. 负向需求

| # | 场景 | 期望行为 |
|---|---|---|
| N1 | 模型证据不足 | 输出标准降级句式，明说未取到；不得生成无依据链路 |
| N2 | 链路超长（>40 行 / 单行 >200 字） | 后端截断到上限并保留树结构完整；前端纵向滚动不折行 |
| N3 | 窄屏 / 深缩进 | 横向滚动，禁自动折行毁树形；溢出时标题行追加「↔ 可横滑」 |
| N4 | 历史分析文件（无新字段） | 归一为空；前端**不渲染**该块（不报错、不迁移、不显示"未取到"） |
| N5 | 追问补丁未包含链路 | 采纳后旧链路必须保留（数据丢失级风险） |
| N6 | 分析被取消 / 失败 / 运行中 | 不显示半截链路，与现有三态文案一致 |
| N7 | 外部上传缺链路 | 允许（不 fail-loud 拒绝）；UI 文案与「AI 未取到」区分（"外部上传未提供链路"） |

## 5. 影响面

### 5.1 写入口（4 处，新增字段必须逐个覆盖）

| # | 入口 | 位置 | 必须做什么 | 漏了会怎样 |
|---|---|---|---|---|
| 1 | AI 分析产出 | `src/lib/events/analysis-runner.ts`（解析 + 建草稿） | 解析 + 归一 | 新分析不产出链路 = 需求未实现 |
| 2 | 外部上传 `ki_event_edit` | `src/lib/mcp-tools/event-edit.ts`（`ALLOWED_FIELDS.analysis` / `KNOWN_FIELDS` / zod schema）+ `analysis-store.saveExternalAnalysis` + `analysis-edit.validateExternalImport` | 三张表登记 + 透传 + 校验 | 漏登记 = 传了报错；不传 = 覆盖后链路消失 |
| 3 | 追问补丁 | `src/lib/events/analysis-ask-patch.ts`（解析 + `diffProposal`）+ `analysis-ask-runner` 提示词 | 支持字段，缺省 = 不改 | 新结论 + 旧链路并存，排障按错方向 |
| 4 | 人工校正 `PATCH /analysis` | `src/lib/events/analysis-store.ts` `saveDraftEdits` | **明确不加**（U8） | 破坏「结论不可人工编辑」边界 |
