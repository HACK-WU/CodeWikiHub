# AI 查找可配置化（检索范围 · 提示词 · Skill · 工具）

- 需求 ID：REQ-20261116-005
- 状态：已确认
- 提出日期：2026-11-16
- 来源：用户对「AI 设置 → AI 查找」分组的走查截图 + 直接诉求「AI 查找希望也像 AI 分析那里一样」
- 依赖：REQ-20261113-004（参考文档与 AI 查找的来源需求）、REQ-20261113-003（AI 分析的配置域范式）

## 1. 背景

「AI 设置」页三个能力分组里，「AI 对话」与「AI 分析」都已有独立配置域，「AI 查找」只有一张「检索词改写提示词」卡，且标明「未接入，改动都不生效」。

原因是形态而非疏漏：现有「AI 查找」是**确定性五步流水线**（理解事件 → 提取线索 → 语义检索 → 排除已用 → 排序取候选），全程不调 LLM，因此提示词、Skill、MCP 工具开关在链路上**没有任何读取点**。

用户诉求（原话要点）：

1. 可以自定义可查询的 scope / 视图，默认是当前选中的 scope；
2. 权限可以调整查询其他 scope；
3. 基础提示词、MCP、Skill 也可以配置；
4. 文件工具暂时不开发。

## 4. 不在范围内

- **文件工具（`fs_*`）**：用户明确本期不做，深度查找工具面只含知识库只读四件套。
- **创建事件时的 AI 查找入口**：本期仅「事件详情 → AI 查找」一个入口（后续按需评估）。
- **AI 对话工具面**：深度查找不登记进 `CHAT_MCP_TOOLS` / `/mcp`。
- **确定性五步算法本身的重构**：快速通道保持现有实现与分数口径（批次内相对分位）。

## 5. 负向需求

| # | 场景 | 期望行为 |
|---|---|---|
| N1 | LLM 未配置 / 未确认外发 / `supportsTools=false` | 专属错误码 + 去设置 / 去确认的引导，不静默返回空 |
| N2 | 配置里出现无权访问的 scope / 视图 | **保存时即拦**；运行期被收回 → 403 明确提示并剔除该库 |
| N3 | 视图成员变更 / 视图被删 | 展开失败如实报错，并说明本次实际查询了哪些库 |
| N4 | 跨库候选加入后源文档被删 / 移动 | 标 `stale`，保留记录（沿用现有口径） |
| N5 | 用户关弹窗 / 超时 | 中断 LLM 调用（AbortController），不留半成品引用，不重复计费 |
| N6 | 预算耗尽 | 返回已有候选 + 「未完成」标注，不报成「没有相关文档」 |
| N7 | 同一事件并发重复触发 | 复用进行中的那次（对齐分析侧 `activeRuns`） |
| N8 | 重复加入同一文档 | 沿用现有去重 + `REF_ALREADY_ASSOCIATED` 提示 |
