# 浏览页全库搜索结果页内打开

## 1. 背景与目标

知识库浏览页的「全库搜索」结果（文件名命中 / 正文命中）当前只有一种打开方式：点击行 → 右侧抽屉滑出（680px，覆盖结果列表右侧区域），结果列表保留。用户希望在结果行上再加一个动作：**直接在当前页面把主区切换为该文档正文**（复用浏览页既有的内联阅读区），并让左侧知识目录同步定位过去。

目标不是替换抽屉，而是**给结果列表增加第二种打开形态**：默认点击仍是抽屉，新增次级动作为页内打开。

## 2. 已拍板决策（2026-10-18）

| # | 决策 | 结论 |
|---|---|---|
| D1 | 「知识目录」指什么 | 页面左侧 Group 树（`LIBRARY INDEX`）；不是查看器右上角的文档大纲（大纲随正文自动生成，无需改动） |
| D2 | 主区行为 | **替换**结果列表：正文占用右侧阅读区，不做"结果 + 正文"三栏并存 |
| D3 | 返回入口 | **不做**。页内打开后没有显式"返回检索结果"按钮；唯一回退路径是修改检索词或切换 tag（见 R5），关闭文档按既有逻辑回落 |
| D4 | 目录同步的适用范围 | 新增的页内打开**与现有抽屉打开路径都同步**（抽屉路径原本不动目录） |
| D5 | tag 过滤导致目标文档在目录不可见 | 只定位到 Group 并提示，不擅自清除用户的 tag 过滤 |

### 3.1 页内阅读态的边界

- 页内阅读态**只在结果行点击「在页内打开」时进入**；从树点击文档、深链接进入仍是原有内联阅读（此时无检索词，不存在结果列表）。
- 结果列表与正文互斥：`结果可见 = 检索词非空 && 未被页内打开显式关闭`。
- 页内阅读时，知识目录**不再按"文件名命中集"过滤**（否则正文命中的文档在目录里不存在）；抽屉路径保持既有过滤口径（结果列表仍可见，目录继续承担命中定位）。
- 关闭文档（Esc / 收起）时，若检索词仍非空 → 回落结果列表（保持既有行为），不进入"无文档 + 有检索词"的空态。
- 页内打开会**清空全库检索词**（2026-10-18 用户反馈）：搜索框属于结果态，留在阅读态会让人误以为"还在检索"；
  正文高亮仍按打开瞬间的 `highlightQuery` 保留，不受清空影响。

> **实施记录（2026-10-18）**：R7 的「页内打开进入阅读覆盖层」已实现并实测（375px 下 `mobileReaderOpen` 生效、覆盖层宽度 375）。
> 但 ≤959px 下「返回目录」按钮与检索入口均为 **HEAD 既有缺陷**（页级工具栏仅在无文档时渲染；检索框位于被 `display:none` 的阅读区），
> 本次不修，建议单独立项（移动端检索入口 + 阅读态返回目录）。

## 4. 负向需求

| ID | 场景 | 预期行为 |
|---|---|---|
| N1 | 结果项缺 `group` / `relation` | 动作禁用并说明原因，不打开空文档 |
| N2 | 文档已被删除 / 改名（结果陈旧） | 打开失败给出错误文案 + 可重试；不白屏 |
| N3 | 快速连点两行 / 打开途中切换 | 只保留最后一次意图，标题与正文一致 |
| N4 | 页内阅读中按 Esc | 按既有优先级（查找栏 → 全屏）后关闭文档 → 回落结果列表 |
| N5 | tag 过滤下目标文档不在目录可见集 | 定位到 Group 并提示"该文档不在当前 tag 过滤下"，不清除 tag |
| N6 | 目标 Group 超过 500 条、文档叶子未加载 | 先补齐该 Group 文档再定位；失败则定位 Group + 提示 |
| N7 | 目标 Group 已选中但被手动折叠 | 显式展开目标 Group，保证高亮行可见 |
