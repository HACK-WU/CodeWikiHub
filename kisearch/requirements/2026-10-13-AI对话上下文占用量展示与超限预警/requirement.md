# PM 报告：AI 对话上下文占用量实时展示

- **模式**：M1 需求定义（一次成型档）
- **触发**：用户提出「AI 对话，希望可以实时展示当前的上下文占用量」，给出参考形态截图（`0.0% · 0 / 1000.0K 上下文已使用`）与现状截图（面板底部 `0/20000`）。
- **v2 修订**：用户澄清口径（见 §0）。
- **证据声明**：最高等级 **🟢**；取证方式 = **代码直读 + 运行实测接口快照 + 用户上传截图**。
  - 代码直读（🟢）：`web/src/chat/*`、`src/lib/chat/*`、`src/lib/config*.ts`

  - 用户上传截图 + 用户口径澄清（🟢）
  - **降级说明**：无 🔴 进结论区；"上线后体验是否够用"类判断标 🟡 并进待确认（§5）。

## 0. 用户口径澄清（2026-10-13，v2 修订依据）

| 项 | 用户裁决 | 对需求的影响 |
|---|---|---|
| 统计单位 | **字数 / 占用的 K 大小**，**不是消息条数** | 口径由 token 改为**字符**；现有「>500 条消息」告警口径被取代 |
| 上限 | **1000K** | 分母确定（不再是"待确认的模型窗口真值"） |
| 实时性 | 要求"实时" | 字符口径**可以真正做到实时**（见 R5）：prompt 侧在请求发出前即已知；生成中正文字符数可本地实时累加 |

> ⚠️ 口径换算假设：**K = 1000 字符**（故 1000K = 1,000,000 字符）。若按 1024 需开口径（A7）。

## 1. 执行摘要

1. **字符口径比 token 口径更适合本项目**：不需要 tokenizer（项目无此依赖）、不依赖上游 `usage`（现被前端丢弃）、且**天然满足"实时"** —— 本轮 prompt 的字符数在请求发出**前**就已确定（token 口径只能等流末尾）。🟢
2. **但字符数必须由后端算**：**"所有落盘消息 content 之和" ≠ "上游实际内容"**，差异有三处（见 §2.2）：① 历史轮次的引用块**不再进入**上游（`tool-loop.ts:203-206,230-235`）；② 工具返回要单独计入（落盘于 `progress[].response`，≤10000 字/次）；③ 系统提示词（会话提示词 + 提示词配置层 skill 规则）前端拿不到。后端在 `buildUpstreamMessages` 之后是**唯一知道"这一轮到底发了什么"的地方**。🟢
3. **现状缺口不变**：后端已有 usage（token 维度，且被前端丢弃），前端无任何上下文用量展示；配置层无窗口字段；只有 `>500 条消息` 的事后告警与上游 400 的原始报错（`chat-routes.ts:110-111`、`llm-client.ts:194-200`）。🟢
4. **需求两条腿**：**可见**（`已用 X / 1000K · Y%`，实时）+ **可行动**（阈值预警 + 出路引导，**取代**消息条数告警）。🟢
5. **成本评估**：工程量低-中（后端 1 处计算 + 1 个落盘/SSE 字段 + 1 个配置项 + 前端 1 个展示元素）；**成本在口径细节**（哪些内容计入、K 基数、阈值余量），这些已在下文定死或列明待拍板。

### 3.1 需求清单

#### R1 · 后端计算并下发「本轮上下文字符数」（P0，核心）

- **要做**：在每轮构造完上游 messages 之后计算 `contextChars = Σ content.length`（可拆 `system / history / refs / tools` 四项分量），随 SSE 下发并在 assistant 消息落盘（与 `usage` 同层级）。
- **口径定死**：
  - 计入：system 组、历史消息 content、本轮 user（含引用块）、工具返回；
  - **不计入**：reasoning（思考过程，N12 不变量）、`sources`（展示用）、落盘的历史 `refs` 字段（历史轮次不再进上游）。
- **取值时机**：取**最后一轮**构造的 messages 规模（= 下一轮将发送的规模，与用户"现在还占多少"的直觉一致）。
- **验收标准**：数值 = 该轮真实 messages 字符数（可与日志/单测逐字节对齐）；同一轮内工具轮次增加时数值随之增长；四条生成路径均落盘。

#### R2 · 上限 1000K（P0）

- **要做**：上限 = **1000K 字符**（1,000,000）。建议做成配置项（`llm.contextChars`，缺省 1000K）以便换模型/换机器；若为常量则集中在一处定义（前后端同源）。
- **验收标准**：改配置后新会话/新请求即生效（配置层已支持热失效）；前端拿到的上限与后端一致。

#### R3 · 面板展示（P0）

- **形态（2026-10-13 用户走查后修订）**：**环形进度**（占用比例画成圆弧，一眼可辨；ok 灰 / ≥80% 黄 / ≥90% 红）
  + **悬停即展开**明细面板（用量 + 四项分量 + 压缩入口）；移开 160ms 收起、**点击固定**（触屏与键盘靠点击 / 聚焦）；
  **无数据 = 虚环且不画弧**（不得画成"用了 0%"）。
  > 原方案为文字 chip（`12.4K / 1000.0K · 1.2%`），用户判定"太丑"且信息密度低 ⇒ 改环形，数字移到悬停面板。
- **要做**：悬停/聚焦显示用量与明细；分母缺省 1000K（缺失时只显示绝对值）。
- **面板结构（2026-10-13 用户给参考图后定稿）**：头部（「上下文窗口」）+ hero（大百分比 + 右侧「已用 / 上限」）+ **组成条**（各分量按上限取宽）
  + **用量分布表**（名称 / K / 窗口占比）+ footer（口径说明 + 实心主操作「立即压缩」）。
- **单位口径**：`K = 1000 字符`，**一律 K 单位**（`482` → `0.48K`；`0` 显示 `0`），**不出现「字」后缀**（用户：「不是显示多少字，而是多少 k」）。
- **开合规则**：悬停即展开；移开 160ms 收起；点击固定；**失焦（点/聚焦到环与面板之外）自动收起**；Escape 关闭。
- **与底栏 `0/20000` 的关系**（重要）：两者都是"字符量"，并排展示易被读成同一件事 —— 建议**合并为一句**，例如底栏显示 `本次 +0.3K · 上下文 12.4K / 1000K · 1.2%`（`0/20000` 作为超长输入的独立护栏保留在悬浮说明里）。
- **验收标准**：数字随每轮问答与流式生成更新；切换会话/scope 后随会话重算，不串台。

#### R4 · 阈值预警 + 出路，取代消息条数告警（P0）

- **要做**：占用达阈值时给出可见提示 + 可执行出路（新建会话 / 编辑或删除早期消息 / 说明"本轮回答可能已受影响"）。
- **建议阈值（考虑字符口径偏差，见 §4 风险）**：≥80% 提示、≥90% 强化（**不建议 95%**：字符口径偏保守但对英文/代码为主的内容偏差方向不稳定）。
- **取代关系**：`conversation-too-long`（>500 条消息）不再作为主口径提示；是否彻底下线见 §5 #3。
- **验收标准**：达阈值当轮出现提示、可关闭；同会话同档位不重复打扰；新建会话后消失。

#### R5 · "实时"的落地方式（P0，字符口径下**成本极低**）

- **已知**：prompt 侧字符数在**请求发出前**确定 ⇒ 可在**流开始时**给出（token 口径只能等流末尾）。
- **三层实时**：
  1. **基数**：流开始即展示本轮上下文基数；
  2. **增量**：生成中把**已生成的 assistant 正文字符数**实时累加（纯前端本地计算，零请求）；
  3. **工具跳变**：每次工具返回后下一轮基数变大（≤10000 字/次），后端每轮可刷新。
- **验收标准**：生成过程中数字可见地增长；数字语义为"当前已占用（含正在生成的正文）"，不得出现"看起来实时但是估算"的模糊态。

#### R8 · 手动压缩上下文（P0，用户追加）

- **要做**：一键把早期对话压缩掉，释放上下文；**可撤销**。
- **两种形态**（同一入口，由后端裁决）：
  - **摘要式**（有模型）：把被移出的消息交给模型生成事实摘要，摘要作为**独立 system 块**持续注入；
  - **截断式**（未配置模型）：直接移出早期消息、不做摘要 —— **返回体与 UI 都必须明示**（不得静默丢历史）。
- **保留窗口**：保留最近 **4 条**消息；可压缩条数 < 2 时**拒绝**并说明原因（不产出无意义摘要）。
- **三条硬约束**（不可逆操作）：
  1. **无备份不压缩**：先复制会话文件为 `c-xxx.compact-backup-<ts>.json`，备份失败即中止；
  2. **摘要失败不落盘**：上游报错/摘要为空 → 压缩失败、会话保持原样（不静默降级为截断）；
  3. **期间变化不写回**：快照与提交时的消息序列不一致（例如刚完成新一轮问答）→ 拒绝并提示重试。
- **撤销**：`DELETE …/compact` 从备份恢复 `messages` 并清除压缩记录；备份缺失/损坏 → **fail-loud**。
- **生成中禁止压缩**（409）：压缩改写消息序列，与生成并发的读-改-写不可交错。
- **压缩后展示必须立即反映新规模**：压缩记录携带**按同一口径重算**的 `contextChars`（system 组 + 保留消息 + 摘要块），
  面板在"压缩时间晚于上一条回答"时优先使用它 —— 否则用户刚压完仍看到压缩前的旧占比（**数字说谎比没数字更糟**）。
- **验收标准**：压缩后消息数下降且可从备份完整撤销；无模型时为截断式且界面明示；压缩后占比立即下降；
  生成中调用返回 409。

#### R6 · 明细（P1）

- **要做**：悬浮/点开显示 `system / 历史 / 引用 / 工具返回` 四项分量 + 条数 + （辅助）token usage。
- **价值**：回答"为什么占了这么多"，指导用户"删哪条消息更有效"。
- **验收标准**：数据全部来自已落盘内容，不额外请求上游。

#### R7 · 会话级占用列表（P2）

- 会话列表显示每会话当前占用（决定"该清哪条"）。验收：不产生 N+1 读取。

### 3.2 负向需求

| # | 场景 | 期望行为 |
|---|---|---|
| N1 | **字符 ≠ token** | 文案用「上下文已用」，**不得**写成"剩余可输入 token"或承诺"到 100% 必然失败"；实际是否触发上游上限由模型 token 窗口决定 |
| N2 | 思考过程很长（reasoning） | **明确不计入**（N12：reasoning 永不进 messages）；若用户以为它占上下文，需在明细里可见地排除 |
| N3 | 历史轮次的引用块 | 不得重复计入（仅当轮），否则数字虚高、预警误报 |
| N4 | 工具返回被截断 | 计入的是**实际发出的文本**（≤10000 字/次）而非原始命中总量 |
| N5 | 生成中 | 数字必须包含"正在生成的正文"且语义明确；不得停留在上一轮假装是当前值 |
| N6 | 中止 / 重生成 / 编辑消息 / 切会话与 scope | 数字必须重算；**陈旧数字比不显示更糟** |
| N7 | 预警打扰 | 同会话同档位只提示一次 + 可关闭；新建会话后恢复 |
| N8 | 已撞上游上限（400） | 除报错外给**出路**（新建会话 / 编辑或删除早期消息），不得只翻译上游英文文案 |
| N9 | 上限配错（配得远大于真实窗口） | 预警静默失效 —— 配置文档需写明该值用于占比与预警 |
| N10 | 压缩时上游失败 / 摘要为空 | **不落盘、不静默降级为截断**；会话保持原样并如实报错（可重试） |
| N11 | 压缩期间用户又完成一轮问答 | 拒绝写回（否则新一轮被静默吃掉）；提示重试 |
| N12 | 撤销时备份缺失 / 损坏 | fail-loud 说明原因，不假装恢复成功 |
| N13 | 未配置模型时压缩 | 必须明示"截断式：早期对话被移出、未做摘要、可从备份撤销"，不得静默丢历史 |
| N14 | 压缩后立即看占比 | 必须显示**重算后**的规模（否则用户以为没生效）——后端在压缩记录里带投影值 |

## 4. 风险与偏差（PM 必须说清的一条）

**字符口径是"仪表"，不是"硬约束"**：

- 中文/混合内容大致 1 token ≈ 1~1.5 字符；英文/代码大致 1 token ≈ 3~4 字符。
- 故 `1000K 字符` 与模型的真实 token 窗口**不等价**：中文为主时约等于 670K~1M token（接近临界），英文/代码为主时仅约 250K token（**显著保守，会提前预警**）。
- **方向是安全的**（偏保守 ⇒ 不会漏报"已满"），代价是英文/代码场景可能提示偏早。建议文案与阈值都按"趋势/提醒"定位，不写成硬性额度。

## 6. 关键假设

| 假设 ID | 内容 | 错了会怎样 | 验证方法 |
|---|---|---|---|
| A1 | "上下文占用量" = **本轮实际发送内容的字符总数**（含 system/历史/引用/工具返回） | 若只算"用户可见的对话文本"，数字会明显偏小、预警失灵 | §5 #6 明细可自证 |
| A2 | 分母 = **1000K 字符**（用户给定），K = 1000 | 若 1000K 实为 token 量或 1024 基数，占比整体偏移 | §5 #4 |
| A3 | "实时" = 流开始时给出基数 + 生成中本地累加正文字符 | 若要求逐字包含工具返回的实时刷新，需后端每轮推送（成本↑） | 观察一次带检索的问答 |
| A4 | 字符口径作为**趋势仪表**可接受（不承诺与 token 窗口等价） | 若被当成硬额度，可能在英文/代码场景提前报警 | §4 |
| A5 | 展示位置：输入区底栏并与 `0/20000` 合并 | 位置返工（低成本） | §5 #1 |
