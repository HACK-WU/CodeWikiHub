# 需求：AI 对话源码只读查看（知识库优先）

**来源**：product-manager M1 报告（2026-11-27，用户确认）
**关联**：`src/lib/events/analysis-fs-tools.ts`（复用）；REQ-20261113-003（分析侧 fs_* 与 code-locate）

## 1. 问题

1. 对话只有知识库工具；知识库只写结论、没写实现时，用户拿不到可核验的代码依据。
2. 现有 fs_* 只读沙箱仅服务事件 AI 分析，`prompt-config.ts` 明确禁止进入对话工具面（Q2 拍板），对话无法下探。
3. 知识库与代码冲突时，对话没有「以代码为准并说明冲突」的路径。

## 2. 需求条目

| ID | 需求 | 验收标准 |
|---|---|---|
| R1 | 对话工具面新增源码只读组（`fs_read` / `fs_grep` / `fs_find` / `fs_ls`），默认开 | 设置页出现分组；对话 SSE 出现 `fs_*`；关闭后不出现 |
| R2 | 知识库优先：证据足够不读代码，不足才下探；来源分标注 | 三组问题集：KB 足够 0 次 `fs_*`；KB 不足有 `fs_*` 且带 `file:line`；冲突以代码为准 |
| R3 | 目录解析：单库 `byScope → defaultDir`；视图用成员库映射、不可配视图目录 | 单库 A/B 各取各；视图两成员各读各；全未映射不暴露 |
| R4 | 通道隔离：仅页面对话，不进 `ki_ask` / `/mcp` | `ki_ask` 与 `/mcp` 工具面无 `fs_*` |
| R5 | 返回体积收口：对话侧 `fs_read` 预算与响应窗口对齐，工具返回前按字节上限自截断 | 工具自报 `truncated`，且不被序列化层二次截断 |
| R6 | 面板与文案：新组、两处「仅限 AI 分析」改写、目录卡片改名、视图只读清单 | 面板无矛盾文案；视图清单只读 |
| R7 | 时间线：`fs_*` 卡片显示动作与 `root:path` | `tool_start` 卡片可读 |

## 3. 已定口径（用户拍板）

| 项 | 结论 |
|---|---|
| 外发口径 | 沿用现有模型外发确认，代码与知识库同档，不新增逐次确认 |
| 权限 | 复用 `knowledge.read`（viewer 可读其可访问库映射的目录） |
| 视图会话 | 视图不可配目录；只读展示成员库映射，AI 自选根 |
| 通道 | 仅页面对话；MCP `ki_ask` / `/mcp` 不开放 |
| 验证 | 真机三组问题集抽样，统计「KB 足够却读代码」比例 |

## 4. 不在范围

通用代码问答、代码写入 / 编辑、代码语义索引、跨轮代码缓存、事件分析链路改动、`/mcp` 对外工具面。
