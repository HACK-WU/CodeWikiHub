# REQ：MCP 上传事件结论 + 事件编辑工具合并

- 状态：设计中
- 日期：2026-11-23
- 设计文档：`design/DESIGN.md` + `design/S01~S03`

## 1. 背景

事件页的「分析结论」（因果链 + 引用 + 未确认点 + 候选位置）目前**只能由站内 AI 分析跑批产生**，外部 AI 客户端无法写回自己的分析结果。同时事件类 MCP 工具已有 3 个（`ki_event_docs` / `ki_event_refs` / `ki_event_set_stage`），加上本次新增能力会变成 4 个，调用面过碎。

目标：
1. 新增 MCP 通道，外部 AI 可直接上传事件结论，页面渲染与确认流程**复用现有 AI 分析模板**，仅增加「来源 + 时间」标识。
2. 把事件类 MCP 写工具**合并为 1 个** `ki_event_edit`（单值 `action`，一次只做一类）。

## 2. 已确认决策（用户拍板，不再追问）

| 编号 | 决策 |
|---|---|
| U1 | 「结论」= 分析卡内的 `conclusion` + `chain`（5 节点以内）；**未确认点一起上传**；**事件描述也要能通过 MCP 修改** |
| U2 | **必须带候选代码位置**（`file:line + why`），否则不上传 |
| U3 | 来源标识只说明**日期时间 + 来源**（MCP 上传 / AI 在线分析） |
| U4 | 已有结论允许覆盖，但需要额外参数 |
| U5 | **允许追问**（外部结论同样可追问） |
| U6 | 外部上传不视为人工修订：不设 `editedAt`，用独立来源字段 |
| U7 | **只做 MCP**，不开 HTTP / `/open/v1` 通道 |
| U8 | 4 个事件写工具合并为 `ki_event_edit`，单值 `action`，一次只做一类 |
| U9 | 旧 3 个工具**直接下线**（不保留别名），并同步 skills 提示词 |

## 3. 需求清单

| ID | 需求 | 验收标准 |
|---|---|---|
| R1 | `ki_event_edit` 单工具支持 5 类 action：`description` / `analysis` / `members` / `references` / `stage`（文档清单参数名 `docRefs`） | 5 条正例各一条测试；action 与字段不匹配时报错 |
| R2 | 存储层新增外部结论写入口：走 analysis 写锁、`running` 拒绝、补齐 `steps/stats` 默认值、生成 `ext_` runId、落 `source`+`importedAt` | 单测：running 409 / 默认值补齐 / source 落盘 / 不设 editedAt |
| R3 | `AnalysisDraft` 增 `source?` / `importedAt?` / `sourceClient?`，后端类型 + 后端契约 + 前端契约三处同步 | 契约测试逐字段比对绿 |
| R4 | 来源透出到事件详情与 `ki_event_get`（**列表不透出**） | 详情接口与 `ki_event_get` 返回体可见 `source` / `importedAt` |
| R5 | 卡头显示「来源 + 时间」：AI 显示完成时间，外部显示上传时间 + 「外部上传」标识 | 两种来源各一张截图 |
| R6 | 外部来源的过程区不再显示「正在读取事件上下文…」与轮次统计 | 截图走查 |
| R7 | 确认逻辑复用（候选位置 → 已确认位置），无候选时给明确提示 | 上传带候选 → 确认 → 已确认 +1 |
| R8 | 前端对 `stats`/`candidates`/`unconfirmed` 缺失全部兜底，不白屏 | 构造缺字段产物仍可渲染 |
| R9 | 覆盖策略：外部草稿重传直接覆盖；覆盖 AI 结论必须显式 `overwrite` | 两条前置各一条测试 |
| R10 | 文档更新：`docs/mcp-tools.md` + 工具描述 | 无旧工具名残留 |
| R11 | `action:'description'` 可改事件描述（内部取 revision，冲突可重试） | 改描述后详情返回新值 |
| R12 | 外部结论允许追问 | 外部产物上发起追问有回答 |
| R13 | 同步 `event-report` / `agents-md-init` 提示词中的旧工具名并重装 | grep 旧工具名 0 命中 |
| R14 | 上传支持可选剔除验真失败项（`skipInvalidCandidates`，默认关闭） | 全部无效时返回明确错误；剔除项在返回体 `dropped[]` 可见 |
| R15 | AI 重跑覆盖外部结论时按来源提示「不可恢复」，服务端 `details.hasExternalDraft` | 重跑弹框文案按来源分档；外部草稿异常数据也能被闸门拦住 |
| R16 | 已确认位置区提示「含 M 处来自上一版结论」 | 外部重传后可辨识旧位置 |

## 4. 负向需求

| ID | 场景 | 期望 |
|---|---|---|
| N1 | 后台分析进行中上传 | 拒绝并提示稍后重试，不落盘 |
| N2 | 只读库 / 只读 Token | 写操作被拦；只读会话看不到该工具 |
| N3 | 事件不存在 | 报事件不存在，不产生孤儿分析文件 |
| N4 | 结论超 4000 字 / 链节点 > 5 / 节点文本 > 200 字 / 未确认点 > 20 条 | **严格报错并指出第几项**，不静默截断 |
| N5 | 候选位置指向不存在的文件或越界行号 | 验真失败并报具体位置与原因 |
| N6 | 同一份结论重复上传 | 覆盖式幂等，不产生第二份草稿 |
| N7 | 覆盖 AI 已有结论未带额外参数 | 拒绝并说明需要 `overwrite` |
| N8 | 载荷缺 `stats`/`candidates`/`unconfirmed` | 服务端补默认值 + 前端兜底，不白屏 |
| N9 | 结论链用了非法节点类型 | 报错并列出合法类型 |
| N10 | 事件描述并发修改 | 提示事件已被他人修改，可重试 |

## 5. 影响面

| 受影响功能/方 | 影响类型 | 程度 | 处理 |
|---|---|---|---|
| 事件详情分析卡 | 展示 | 降级 | 新增来源行，其余不变 |
| 过程面板 | 展示 | 破坏（外部来源） | 新增外部分支，隐藏无过程内容 |
| 后台 AI 重新分析 | 流程 | 破坏风险 | 外部草稿视为已有草稿，需显式覆盖 |
| 确认候选位置 | 数据 | 无感 | 后端零改动 |
| MCP 事件工具面 | 外部契约 | 破坏 | 3 个旧工具下线，1 个新工具 |
| skills 提示词资产 | 外部契约 | 破坏 | 同步改名 + 重装 |
| 事件 `revision` | 数据 | 无感 | 分析产物独立文件，不受影响 |

## 6. 不在范围

- 不开 HTTP / `/open/v1` 通道
- 不做「撤销上传」（用现有「重置分析」）
- 不做结论人工编辑（维持既有 H12）
- 不做多来源细分（只 AI / 外部二元）
- 不改后台分析 runner 的生成逻辑
- 不做上传历史版本（覆盖式）
