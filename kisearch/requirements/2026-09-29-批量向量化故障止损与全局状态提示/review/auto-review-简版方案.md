# 简版实现方案自动审查

审查对象：[实现方案-简版.md](../design/实现方案-简版.md)。方法为需求对照、相关源码静态核对及独立质疑；没有实施代码，也没有运行故障演练。结论：原版方向可行，但四项关键机制原先不足以保证需求成立；修订后静态检查未发现新的阻断性矛盾，仍须在详细设计和实现中验证。

| 严重度 | 发现与源码依据 | 本次修订 |
|---|---|---|
| 高 | `/api/import/config` 经同 scope 操作队列（`src/lib/mcp-http-api.ts`、`src/lib/operation-coordinator.ts`），长任务期间可能阻塞全局告警。 | 改为非阻塞维度快照与独立只读状态接口；过期时显示无法确认。 |
| 高 | 同维度全量重建会先删除旧向量；现有暂存切换只在维度迁移分支执行（`src/lib/rebuild-vector.ts`）。 | 将完整暂存、校验、切换、回滚扩展到有旧集合的全量重建，并要求跨进程写入互斥。 |
| 高 | provider 错误在引擎及客户端被压成通用错误/字符串；内部调度器及外层批次可能继续（`src/zvec-engine/engine.ts`、`src/lib/vector-client.ts`、`src/zvec-engine/embedding/batch-scheduler.ts`）。 | 明确结构化故障逐层传递，在内部队列和外层批次同时止损，单列未处理数量。 |
| 高 | Web job `done` 可包含逐项失败，旧状态映射不足以表示系统故障（`src/lib/mcp-http-api.ts`、`src/lib/import.ts`）。 | 由结果派生 `partial`，系统故障始终 `failed`，另报已部分提交。 |
| 中 | 导入已有失败文件回滚，但扫描预写 KB、提前停止及标签/路径向量仍需收束。 | 明确复用现有回滚并覆盖未处理项和补偿记录。 |
| 中 | 直连 CLI 与 Web 没有共享可发现任务源；心跳若只靠进度回调会误判失联。 | 共享任务登记、独立心跳、注册失败拒绝启动、失联显示未知。 |
| 中 | 新任务列表及按 ID 查询可能泄露无权 scope 的任务存在性。 | 授权过滤先于计数/分页，详情对无权与不存在统一响应。 |

## 尚待详细设计固定

- 永久故障与重试耗尽故障的结构化错误码、停止阈值及在途请求的收束方式。
- 同维度重建切换期间是否必须持续可检索，以及暂存空间、并发写入和崩溃恢复机制。
- 任务记录格式、心跳超时、历史保留与权限测试；不同机器或不同数据目录的任务聚合不在本期。

以上是**设计静态审查**结论，不代表功能已实现或通过端到端验证。
