# 需求分析：浏览页多库合并与跨库唯一键

- **来源**：从 `REQ-20261104-003`（知识视图）的 S-06 子需求拆出，独立立项。
- **拆分理由**：S-06 是整批里唯一**「能点开、但会看错内容」**的模块 —— 它不只是"把多个库的树拼起来"，还要求把浏览页**所有按 `group` 单键索引的内部结构**改成跨库唯一键。改动面集中、风险独立、与视图的定义层/检索层/鉴权层无耦合，适合独立排期与独立验收。
- **依赖**：`REQ-20261104-003` 必须已落地（`/api/doc/list` 认得视图名、`views[].memberMeta` 可用）。本需求**不重复**实现视图解析。
- **证据声明**：🟢 代码直读（下列 `file:line` 均已核对）；**未运行实测**（前端体验类结论按 🟡 处理）。

---

## 0. 问题陈述

视图模式下，顶栏的 scope 是**视图名**。浏览页目前假定"当前只有一个知识库"，三处核心假设会同时失效：

| # | 位置 | 现状键 | 视图下的实际故障 |
|---|---|---|---|
| 1 | `BrowsePage.tsx:195-197` `docsByGroup` / `loadedGroupsRef` | `group` | 两个库的同名组**互相覆盖缓存**：切到 A 库显示 B 库的文档；"明明有文档却显示空" |
| 2 | `BrowsePage.tsx:1104` `knownDocs.find(d => d.group === hit.group && d.name === hit.relation)` | `group + name` | 正文命中来自 B 库，`find` 命中 A 库同名文件 → **打开错误的库的文档** |
| 3 | `matchedDocKeys` / `browseSearchGroups` 的目录过滤 | `group` | B 库的组因 A 库的命中而**被错误显示/隐藏** |

**这三处都是静默的**：不报错、不提示，只是数据不对。用户无法从界面判断"我看到的到底是不是这个库的"。

同时浏览页还有 3 条读路径会拿到视图名而读空（`doc/get` / `useScopeReadonly` / `TagSelect`），属于同一根源。

## 1. 需求清单

### P0 —— 跨库唯一键（本需求的主体）

| ID | 需求 | 验收标准 |
|---|---|---|
| **R-01** | 引入 `DocumentRef { scope, group, relation }` 作为视图模式下文档的唯一标识；所有以 `group` 为键的内部结构改为 `(scope, group)` 复合键 | 两个库都有 `projects` 时，分别展开后各自文档互不覆盖 |
| **R-02** | `docsByGroup` / `loadedGroupsRef` 键改为 `docKey(scope, group)`（用 `\u0000` 分隔，避免 group 内含 `/` 造成歧义） | 跨库同名组的懒加载缓存互不污染 |
| **R-03** | `knownDocs` / `matchedDocKeys` 键加 `scope` | **从 B 库的结果点开，抽屉显示 B 库内容**（同名文档不串） |
| **R-04** | 目录树节点路径以库节点为前缀；`findGroupNode` / `revealGroupPath` 按库节点前缀拼接后的路径查找 | 搜索命中 B 库某组时，A 库同名组不受影响（既不显示为命中，也不被隐藏） |
| **R-05** | 「名称/路径命中」（分桶）与「正文命中」（扁平 `SearchHit[]`）在渲染前归一到统一模型 `BrowseHit { ref, title, snippet, kind }` | 三类命中行均显示来源库徽标；点开后落到 `ref.scope` 对应的库 |

### P1 —— 多库树与读路径

| ID | 需求 | 验收标准 |
|---|---|---|
| **R-06** | 浏览树在视图模式下**每个成员库一个顶层库节点**（库图标 + 略深底色），库内结构维持现状；`__root__` 散文件裸挂在库节点下（不显示"根"） | 3 库视图显示 3 个库节点，展开后各自结构与单库一致 |
| **R-07** | 后端 `/api/doc/list` 认视图名，返回按库分桶 `{ view, buckets: [{scope, docs, groups, total, ...}], tags }`；**不合并同名组** | 一次请求拿到全部成员数据，不产生 N 次 IO |
| **R-08** | 顶层返回合并去重的 `tags`（供 tag 下拉）；`TagSelect` 改窄化读取（`'tags' in data`）适配联合类型 | 视图模式下 tag 下拉可选 |
| **R-09** | 单库 `/api/doc/list` 响应**逐字节不变**（无 `view`/`buckets` 字段） | 单库模式零回归 |
| **R-10** | 深链新增 `member` 参数：`?scope=<视图>&member=<库>&group=&relation=`；`group/relation` 是成员内路径，**必须**配 `member` 才能定位 | 视图模式下从检索页「定位文档 ↗」跳转后，目标文档正确高亮 |
| **R-11** | 单篇正文链路统一用「当前文档上下文 scope」：`docScope = viewMode ? (currentDocMember ?? null) : scope`；`ModuleDrawer` 的 `scope`、`useScopeReadonly`、`TagSelect` 全部用它；为 `null` 时**不发请求** | 视图下打开文档正文非空；只读库按只读呈现 |
| **R-12** | 目录搜索框 `q` 透传给后端逐桶过滤（沿用现状的服务端过滤，不在前端过滤 500 条） | 视图模式输入关键词 → 结果分库展示 |

### 明确不做

| 不做 | 理由 |
|---|---|
| 合并同名组 | 合并后看不出文档属于哪个库，且同名必然撞（R-06 的反面） |
| 前端 fan-out N 次 `getDocList` | 5 库 = 5 次 IO + 5 次 500 条截断 + 5 套独立失败处理 |
| 库节点拖拽 / 排序 / 重命名 | 与视图无关，不在本期 |
| 视图内编辑库内结构（建组/删组） | 写路径按 `REQ-20261104-003` 设计保持"必须指定具体库" |

## 2. 界面

### 2.1 浏览树（视图模式）

```
【现状】单库
┌ 知识目录 ─────────────────────┐
│ 全部文档 · 131 篇        ⟳ ⌄  │
├───────────────────────────────┤
│ ▾ 📁 k8s                     10│
│ ▾ 📁 projects                 4│
└───────────────────────────────┘

【视图模式】每库一个顶层节点，__root__ 散文件裸挂在库节点下
┌ 知识目录 ── 团队知识视图 ──────┐
│ 3 个知识库 · 168 篇      ⟳ ⌄  │
├───────────────────────────────┤
│ ▾ 🗄 k8s                     41│  ← 库节点：库图标 + 略深底色
│   📄 00-学习档案 …            10│  ← 原 __root__，裸挂
│   ▸ 📁 k8s                   10│  ← 库内同名组，路径 k8s/k8s
│   ▸ 📁 projects               4│
│ ▾ 🗄 team-b                  12│
│   ▸ 📁 projects               9│
│   ▸ 📁 部署运维               3│
└───────────────────────────────┘
```

**已知视觉现象（需提前接受）**：若某库名与其内部某组同名（如 scope `k8s` 内含组 `k8s`），会渲染成 `k8s / k8s / 00-评审清单`。不是 bug，靠库图标与底色区分。

### 2.2 检索结果来源库

结果行在文档名右侧显示来源库徽标，**仅当来源库 ≠ 顶栏值**时出现（单库模式不显示，避免重复噪音）。

```
├─ [kisearch] order-api.md      A 库的同名文件
├─ [team-b]   order-api.md      B 库的同名文件   ← 点开必须是 B 库内容
```

> 本图未经用户确认（区块 / 排列 / 入口 / 显隐）。确认后进入界面设计。

## 3. 负向需求

| ID | 场景 | 要求 |
|---|---|---|
| **N1** | 两个库有同名组 | 各自独立展开，**不合并、不覆盖缓存** |
| **N2** | 两个库有同名文档 | 点开结果打开的是**来源库**那一份；抽屉标题区显示来源库 |
| **N3** | 某成员库无 KB 索引 | 该库节点显示"尚未导入"，其余库正常；整体不失败 |
| **N4** | 成员库全部不可读 | 整页给明确空态 + 原因，不留白屏 |
| **N5** | 深链 `?scope=<视图>` 但缺 `member` | 落到视图根（不定位具体文档），并提示"请从目录选择" |
| **N6** | `member` 不在视图成员内 | `400 INVALID_VIEW_MEMBER`（后端，`REQ-20261104-003` 已定义） |
| **N7** | 当前文档上下文 scope 未确定 | **不发 `doc/get` 请求**（避免一次必然空结果的往返） |
| **N8** | 视图成员数 > 20 | 首屏响应体体积需实测；超阈值时改为懒加载（点开库节点才拉该桶） |
| **N9** | 旧版前端 + 新版后端 | 旧前端不认 `buckets`，但也不会选到视图（无视图入口）→ 仅手工改 URL 会空白，可接受 |
