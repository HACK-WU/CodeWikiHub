## 1. 背景

数据源当前只能手动触发同步（页面按钮 / CLI / 添加 Git 源后的首次同步），系统内**没有任何调度器**（`src` 全域无 cron / 定时调度实现）。用户希望数据源能按计划自动同步，避免每次手动点击。

## 3. 需求

### R1 定时配置（页面）
- 每个数据源一个 `schedule` 配置，落在 `datasource.json`；默认 `enabled=false`。
- 模式二选一：
  - **周期**：每隔 `N` 分钟/小时/天（数值由用户输入，无预设档位）。
  - **指定时间**：选择一个日期时间；可选「仅一次 / 每天重复」（重复语义待确认，见 §6 A1）。
- 页面展示：当前模式、下次运行时间、上次自动运行结果、连续失败次数。
- 验收：修改后 15s 内列表/详情反映；关闭后不再触发。

### R2 调度器（daemon）
- 调度器跑在 daemon 内（无 daemon 即不调度）。
- **生命周期按需**：启用计划数为 0 → 不创建任何定时器（零轮询、零开销）；≥1 个 → 只 arm 一个「最近到期」定时器；配置保存/删除数据源/手动同步完成后重算；长间隔分段 arm（规避 Node `setTimeout` 上限）。
- 到期判定以 `lastSync.at` / `nextRunAt` 为基准；到期后 0–60s 抖动错峰。
- 全局同时最多 1 个自动同步；同 scope 已在跑/排队则**跳过本次**，不排队堆积。
- 启动补跑：daemon 启动时若已过预定时间 → 立即补跑**一次**；未过 → 等到点。
- 验收：没有任何启用计划时，进程内无调度定时器；停 daemon 超过一个周期后启动，5 分钟内每源恰好触发 1 次；10 个源同时到期时同一时刻仅 1 个 running。

### R3 任务台账
- 定时触发也写任务台账：`operation='datasource-sync'`，`source` 新增 `scheduler` 或复用 `daemon`（设计定）。
- 成功、失败、部分完成、取消都保留（TTL 1h 既有语义）。
- 验收：任务列表按来源可辨认；定时成功任务同样可见。

### R4 顶栏"运行中"即时显示（含缺陷修复）
- 页面提交同步成功后立即失效 `['tasks']`，顶栏徽章立即变为"N 个任务运行中"。
- 定时任务在下一次任务轮询（空闲 15s）内出现；如需更即时，设计阶段评估降低空闲轮询或事件推送。
- 验收：点击同步后 1s 内顶栏从"后台任务"变为"N 个任务运行中"；任务页同步出现该任务。

### R5 失败提示与继续
- 连续失败计数（成功清零）；达到 3 次在页面显著提示「连续失败 3 次」。
- **不阻断下个预定周期**；不做指数退避、不永久停用。
- 验收：连续 3 次失败后页面有明确提示；第 4 个预定时间仍会自动尝试。

### R6 页面可见与可控
- 列表操作列新增「定时」按钮，打开「定时同步」弹窗（**唯一配置入口**）。
- 列表「上次同步」第二行显示下次运行/模式/失败提示；类型列显示「定时」徽标。
- **详情抽屉只读**：展示定时模式、下次运行、上次自动结果、连续失败次数；**不放任何输入框/开关/保存按钮**。
- 手动同步冷却提示在开启定时后改为「由定时同步接管，下次 12:13」。
- 验收：弹窗键盘可达（Esc 关闭、焦点归还）；窄屏无横向溢出；详情抽屉内无编辑控件。

### R7 不自动删除
- 定时同步只刷新待删候选，删除仍需人工确认。
- 验收：定时同步后库内文档数不因源文件删除而减少。

### R8 互斥与并发
- 定时与手动同步互斥：任务台账 active 检查 + scope 写锁。
- 跨 scope 全局并发 1；共享托管 clone 按 `repoRoot` 串行，`CLONE_BUSY` 记跳过、下轮重试。
- 验收：手动同步进行中到点，不产生第二条 `datasource-sync` 任务。

### R9 可观测与测试隔离
- healthz/detail 暴露调度器状态（启用数、运行中、下次运行、跳过原因）。
- `KI_DISABLE_DATASOURCE_SCHEDULER=1` 可关闭调度（e2e/开发）。
- 验收：关闭变量后 0 次自动触发。

### R10 文案修正
- 页面提示条与 `docs/cli.md`：「普通目录 30 分钟一次」→「普通目录手动同步冷却 30 分钟」。
- 验收：全仓不再出现可被读成"每 30 分钟自动同步"的表述。

## 4. 负向场景

| # | 场景 | 期望行为 |
|---|---|---|
| N1 | daemon 未运行 | 不调度；页面明确「定时同步依赖 daemon 常驻」 |
| N2 | 源目录缺失/不可读 | 失败计数；3 次提示；下个周期继续 |
| N3 | 与手动同步/导入冲突 | 跳过本次，不排队 |
| N4 | 多源同时到期 | 抖动 + 全局并发 1 |
| N5 | 共享 clone 忙 | 跳过并下轮重试，不污染失败状态 |
| N6 | 时钟回拨/休眠唤醒/daemon 重停 | 以持久化的 lastRun/nextRun 计算；补跑去重 |
| N7 | 关闭定时/删除数据源 | 立即停止未来触发；正在跑的允许完成 |
| N8 | 指定时间已过且从未运行 | 启动补跑一次；已运行过则不再补 |
| N9 | 大仓库/大目录 | 仍受导入预算、取消、scope 锁约束 |
| N10 | 测试环境 | 默认禁用调度，避免后台任务污染断言 |

## 5. 影响面

| 受影响方 | 影响 | 处理 |
|---|---|---|
| 后台任务列表/顶栏徽章 | 定时任务周期出现，可能刷屏 | 新增来源标识，可按来源筛选；失败才进入需关注徽章 |
| 页面手动同步冷却 | 定时运行会重置冷却 | 开启定时后按钮区改为"下次运行"，不再显示冷却误导 |
| 待删候选 | 每次同步刷新候选 | 页面注明"由最近一次同步算出"，仍不自动删 |
| 索引/CPU/检索延迟 | 后台同步可能与用户操作争资源 | 全局并发 1 + 抖动 + 可关闭；必要时后续加安静时段 |
| daemon 生命周期 | 无 daemon 即无定时 | 页面/文档明确 |
| CLI `datasource list` | 可只读展示计划（配置仍只在页面） | `--json` 只增字段 |
| 备份 | 定时变更无自动快照 | 文档提示定期 `ki backup` |
| `datasource.json` 兼容 | 旧版本读回会丢弃 `schedule` | 升级先重启 daemon；实施时在 normalize 中保留未知字段或明确版本策略 |
| 测试/开发 | 后台调度干扰 e2e | 环境变量禁用 |

## 6. 待确认 / 假设

| ID | 内容 | 当前处理 |
|---|---|---|
| A1 | 「指定日期时间」= 一次性，还是每天固定时刻？ | 设计同时支持「仅一次 / 每天重复」两个选项，默认仅一次；若只需一种可裁剪 |
| A2 | 「连续 3 次暂停但不影响下个周期」= 仅提示、下周期照跑 | 按字面实现：不做退避、不永久停用，仅累计与提示 |
| A3 | 自由输入的最小间隔 | 设计建议最小 1 分钟（便于验证）；目录源可提示高频全量扫描的风险，不硬拦 |
| A4 | 定时是否绕过页面 30 分钟冷却 | 建议绕过（否则自由输入无意义），但页面明确提示 |
| A5 | CLI 是否只读展示计划 | 建议 `datasource list` 展示（只读），配置仍只在页面 |
