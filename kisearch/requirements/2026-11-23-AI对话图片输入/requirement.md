# PM 报告：AI 对话支持图片输入

**模式**：M1 需求定义（一次成型档）
**证据声明**：最高 `🟢`。取证方式＝**代码直读**（`src/lib/chat/*`、`src/lib/mcp-tools/*`、`web/src/chat/ChatPanel.tsx`）＋ **真实上游调用实测**（Q3，见 `demo/verify/verify-report.md`）。未启动产品、未走查界面，故视觉/体验类结论仍为 `🟡`。
**版本**：v5（2026-11-23 定稿：Q-A 复用原图 / Q-B 白名单 PNG·JPEG·WebP（SVG 实测被上游 400）/ Q-C 不预处理 / Q-D 不计入上下文百分比 / Q-E 界面图确认 —— 五项全部闭合）
**范围**：本文档只覆盖「用户上传图片」这条线（R1~R4 + R8）。MCP 工具返回图片与文档附图读取 = R5，已独立立项（事件见 §9）。

## 1. 执行摘要

1. **能力底座已经验证可用** `🟢`（实测）：当前上游 `deepseek-v4.1-flash-1017` 支持 OpenAI 多模态 `content` 数组 + `data:` URI，模型能准确读图；`image_tokens` 只随像素尺寸增长（240×120→202、1024²→652、1568²→994），**与文件体积无关**（1024² 的 6KB 与 71KB 同为 652）。
2. **本需求是"接线"，不是"造能力"** `🟢`：配置三字段（`supportsImages / maxImagesPerMessage / maxImageBytes`）、会话图片目录与级联删除、图片静态服务 `/api/asset`、前端安全图片渲染白名单**全部已存在**；缺的是前端入口、后端路由（现存硬 404）、消息契约字段、模型客户端 parts 支持这四段。
3. **唯一的结构性风险是"字符预算口径"** `🟢`：现有上下文计数与工具预算都按**字符**算（`CHAT_BUDGET.maxToolResponseChars=10000`、`contextChars`），一张 4MB 图 base64 约 5.3M 字符。图片必须走**独立的图片口径**（张数 + 像素规模），不能混进字符预算 —— 否则进度条与截断都会失真。
4. **一项历史遗留须在实现时同步清理** `🟢`：`chat-routes.ts:467-471` 对 `conversations/:id/images` 返回 404「本期未实现（后置 V2）」，这是 V1 的占位；实现 API-09/10 时必须一并移除，否则新路由被它挡住。
5. **可行性 / 复杂度**：5 条结论中 **5 可实施 / 0 有条件 / 0 阻塞**；整体复杂度 **中**，主导维度 **结构面**（跨前后端 6 项 + 契约双份 parity）。

### 3.1 需求清单

| ID | 需求 | 验收标准 |
|---|---|---|
| **R1** | composer 支持上传 / 粘贴 / 拖拽图片 | 传 1 张 PNG 提问 → 模型回答体现图中内容；`Ctrl+V` 粘贴截图同样生效 |
| **R2** | 图片校验与可读失败 | 按**魔数**校验（不信后缀，防改名伪装）；mime 白名单 **PNG / JPEG / WebP**（SVG 实测被上游 400，拒收并给可读提示）；超张数 / 超体积 / 模型不支持三类均给明确文案；错误码 `IMAGE_INVALID` / `IMAGE_TOO_LARGE` / `IMAGE_COUNT_EXCEEDED` / `IMAGE_UNSUPPORTED` |
| **R3** | 用户消息回显缩略图 | 生成中与刷新后都能看到缩略图；点击放大；渲染沿用 `MarkdownPreview` 的 `isSafeImageSrc` 白名单 |
| **R4** | 本地图片存储与清理 | 落 `{chatDir}/{scope}/assets/{convId}__{imgId}{ext}`；删会话/清空级联删本地图，**绝不删 KB 资产** |
| **R8** | 图片外发告知 | 首次传图前提示"本次会将图片发送给模型服务"；已有 `kbDisclosureAck` 用户补一次即可 |

### 3.2 负向需求

| 场景 | 处置 |
|---|---|
| 超大图 / 超大请求体 | 单图上限 4MB，**硬拒绝线**——不做自动压缩/缩放/切块（Q-C 已拍板）；对话侧 `readJsonBody` 目前**无字节上限**，须补（base64 会放大 4/3） |
| 伪装文件（`.exe` 改名 `.png`） | 魔数校验，拒绝 |
| 模型不支持视觉（`supportsImages=false`） | 发送前拦截并说明"当前模型不支持读图"，**不得**把 base64 当文本塞给模型 |
| 一次贴 10 张图 | 超出上限即拒绝并提示上限，不静默丢图 |
| 剪贴板同时含文本与图 | 两者都收（文本进正文、图进待发列表），不覆盖 |
| 生成中删除会话 | 图片随会话级联清理，不残留孤儿文件 |
| 重发/编辑带图消息 | 需明确语义（复用原图 vs 要求重传），见 Q-A |

## 5. 拍板结果

**已拍板（2026-11-23）**

| # | 决策 | 影响 |
|---|---|---|
| Q-A | **重新生成 / 编辑重发复用原图** | 原图仍在 `{convId}__*` 就复用，不要求重传：`regenerate` 需从末条 user 读回 `images`；`edit` 需把原图回填到待发图片列表（可逐张删除）。图已被清理时明示失败原因 |
| Q-C | **不做图片预处理，原图直传模型** | 不做客户端缩放 / 压缩 / 切块；超限即拒绝并提示；`maxImageBytes` 是**硬拒绝线**，不是预处理阈值；识别效果归模型能力，产品侧只保证"原图送达" |
| Q-D | **图片不计入上下文用量百分比** | `computeContextChars` 口径**不动**（图片不参与字符统计），用量条与既有数字不变；需要时在气泡旁标一句"含 N 张图"（纯展示，不进计算） |
| Q-E | **§3.4 界面图确认** | composer 加「+ 图片」入口 + 待发图片行 + 能力提示；用户消息气泡内缩略图 + 点击放大 —— 作为 `ui-designer` 的设计输入 |
| Q-B | **mime 白名单 = PNG / JPEG / WebP，排除 SVG**；单图 4MB、单消息 4 张 | SVG **实测被上游硬拒**（`HTTP 400 · The image format is illegal and cannot be opened: UnidentifiedImageError`），传了只会得到一句看不懂的服务端错误；且 SVG 是文本、魔数校验不可靠，项目对 `.svg` 本就按不可信内容加 `CSP: sandbox` 对待。GIF/BMP/ICO 未验证，暂不纳入 |

**待确认**：无 —— 五项（Q-A ~ Q-E）已全部闭合。
