# PM 需求报告：Web 账号登录与只读权限

> 模式：M1 需求定义（一次成型档）
> 证据声明：最高等级 **🟢 代码直读**。本次未启动服务、未做浏览器实测；「现状」结论来自代码与项目文档；界面部分为新增页面布局提案。安全风险中「缺防线」为 🟢，「攻击可利用性」未实测（🔴，见 §5）。

## 1. 执行摘要

- 现有系统没有用户、密码、会话概念，只有「绑定地址决定免鉴权 / Bearer Token」两态（🟢 `src/lib/mcp-http.ts:1131`、`src/lib/mcp-http-api.ts:529`）。本次是给 Web 通道增加**第三套身份**。
- Web 写入实际走四条通道：`/api/*`、浏览器直连的 `/mcp` 工具、AI 对话的服务端工具循环、后台定时任务（🟢 `web/src/api/mcpClient.ts:116`、`src/lib/chat/retrieval/tool-loop.ts:166`、`src/lib/chat/mcp-tool-registry.ts:473`）。只读必须服务端全链路拦截，只隐藏按钮或只堵 `/api` 会被绕过。
- “本机免登录”与现有回环免鉴权一致，但必须先补安全课：`/api/*` 目前没有 Origin / Host / Content-Type 校验（🟢 `src/lib/mcp-http-api.ts:524`、`:362`）。新增“创建账号”后，任意网页可尝试以本机管理员身份发起 CSRF/DNS rebinding 请求（缺防线 🟢，可利用性未实测 🔴）。
- 已确认 v1 采用三类账号：**管理员 / 读写账号 / 只读账号**；读写账号可写知识但不得操作数据源页面（含添加 Git 源）；用户与 MCP Token 完全独立。后台任务台账需记录并展示操作者。
- 工作量集中在鉴权链路与只读拦截（高），登录页/用户页本身不大（中）；不建议跳过设计直接编码。

### 2.2 需求本质

```
身份（谁）              ×  数据范围（哪些库）      ×  动作（能做什么）
├─ 本机管理员             ├─ 全部 scope（v1）        ├─ 管理员：全部
├─ 读写账号（editor）     └─ 指定 scope（后续）      ├─ 读写账号：写知识，禁止数据源/账号管理
├─ 只读账号（viewer）                              └─ 只读账号：只读 + 只读工具
└─ MCP Token（独立，不参与本次）
```

本次只做第一列「登录账号」+ 第三列「只读」，第二列固定为全部 scope。

### 2.3 范围

**做**：账号存储、`ki user create`、登录/登出/会话、本机免登录、只读全链路拦截、用户管理页、登录安全与 CSRF 基线、文档。

**不做**：MCP Token 模型改造、scope 级账号授权、SSO/OIDC、多租户、审计日志（v1）。

> 前提：登录功能只在非回环绑定（如 `--host 0.0.0.0`）时对远程有意义；默认回环绑定时本机永远自动管理员，登录页几乎不会出现。

## 4. 需求清单

### R1 账号存储与密码哈希（P0）

`~/.ki/users.json`（0600，原子写）；字段：`id / username / passwordHash / role / readOnly / disabled / createdAt / updatedAt / passwordUpdatedAt / lastLoginAt`。密码 scrypt + 随机盐，不落明文、不进日志。

验收：文件权限 0600；同名（大小写不敏感）→ 409 `USER_EXISTS`；文件损坏 → 登录 503 `USER_STORE_CORRUPT`，`ki user list` 明确报错，不静默当“无账号”；禁用/改角色后下一请求立即生效（鉴权每次重读 `users.json`，不依赖 mtime+size 缓存）。

### R2 `ki user` CLI（P0）

`ki user create <name> [--read-only] [--password-stdin]`；密码交互输入两次（隐藏）或从 stdin 读，不通过 argv/env 传密码。同批建议 `list / reset-password / set-readonly / delete --yes`。

验收：创建后无需重启 daemon 即可远程登录；密码不出现在进程列表/日志；帮助与 `docs/cli.md` 同步。

### R3 登录 / 登出 / 会话（P0）

`POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/me`。Cookie：`HttpOnly`、`SameSite=Strict`、`Path=/`、32 字节随机 session id；默认 7 天滑动；登录成功轮换 session id。

验收：远程未登录访问业务 `/api/*` → 401 `AUTH_REQUIRED` 并跳登录页；登录后刷新保持；登出后旧 Cookie 失效；JS 读不到 Cookie；会话过期时 API / `/mcp` / chat SSE 任一通道 401 都只跳一次登录页。

### R4 本机免登录（P0）

源地址回环且 Host 为回环/本机名 → 自动管理员（`source:'local'`），无需 Cookie。提供关闭开关（配置或启动参数）。

验收：`127.0.0.1` / `localhost` 直连返回 admin；远程 IP → 401；反向代理（Host 为外部域名）→ 不自动管理员；开关关闭后本机也需登录。

### R5 权限模型（P0）

v1 三类账号，`role` 为枚举：

- **管理员（admin）**：全部知识写权限 + 数据源页面全部操作 + 用户管理。
- **读写账号（editor）**：可写知识（上传导入、知识写入、文档编辑、聊天写工具）；数据源页面**只读**（可看列表/详情，不能新增、同步、编辑、移除、定时、清理）；**不得执行任何删除**（数据源详情页的「移除登记」、数据源页的「删除待删文档」、任务详情页的任何删除/清理动作）；不得管理账号。
- **只读账号（viewer）**：只读 + 聊天（工具只读），不得写知识、数据源、账号。

管理员仍受 `ki scope readonly` 约束，不因“管理员”绕过库级保护。

**实现方向（已确认）：能力白名单 + 默认拒绝。** 每个 `/api` 路由、MCP 工具、聊天工具都声明所需能力；角色只映射到能力集合；未声明 = 拒绝。前端通过 `/api/auth/me` 返回的 `permissions` 用 `can('...')` 判断，不直接判角色。

验收：`/api/auth/me` 返回 `{username, role, source, permissions}`；editor 调 `/api/datasource/*` 任一写接口 403 `DATA_SOURCE_FORBIDDEN`；viewer 调任意写接口 403 `USER_READONLY`；editor/viewer 访问 `/api/users` 403 `USER_FORBIDDEN`；新增一条未声明能力的路由必须默认 403，并有覆盖率测试防止漏登记。

### R6 只读全链路拦截（P0）

统一 principal 解析，四通道 + 数据源门禁，全部走能力白名单：

1. `/api/*`：按路由注册表 `method + path → permission` 校验；未登记路由默认 403。viewer/editor 的能力集合见 R5；`/api/datasource/*` 的 GET list/detail 需 `datasource.read`，写接口需 `datasource.write`，remove/prune 需 `datasource.delete`（editor/viewer 均无）。
2. `/mcp`：viewer 只注册读工具（`knowledge.read` 等），构造写工具调用 403；editor 保留知识写工具（`knowledge.write` / `chat.writeTools`）；两者都没有数据源能力（数据源不在 MCP 工具面）。
3. AI 对话工具循环：viewer 的 `toolEntries` 只保留 `readOnly:true` 工具；editor 保留知识写工具；按工具能力注册表过滤。
4. 后台定时同步/重建：无用户上下文，不受影响。
5. 数据源页面：editor 保留入口与只读列表/详情，所有操作按钮隐藏/禁用并显示无权提示；服务端 `datasource.write/delete` 接口必须 admin-only。
6. 聊天会话按 `ownerUserId` 隔离：admin 可看/管全部；editor/viewer 只看/改自己的；旧会话无 owner 仅 admin 可见。
7. 任务详情对无 `datasource.read` 的账号脱敏：不返回 `source` / `remoteUrl` / `subdir` 等数据源参数。

验收：viewer 调 `POST /api/import/upload`、`/api/doc/edit` → 403；editor 调这些接口成功，但调 `/api/datasource/add-remote`、`/sync`、`/update`、`/remove`、`/schedule`、`/prune` → 403；`/mcp` tools/list 对 viewer 无写工具；对话对 viewer 无法调用 `ki_store`；后台同步照常。

### R7 用户管理页（P0）

`/users`：列表（用户名、角色、状态、最近登录）、新建（管理员 / 读写账号 / 只读账号）、切换角色、重置密码、删除。仅管理员可进入。保护：不能删除、降级或禁用最后一个管理员；不能把自己删成零管理员。

验收：上述操作逐项可用；最后管理员操作 409 `USER_LAST_ADMIN`；editor/viewer 访问 `/api/users` → 403 `USER_FORBIDDEN`。

### R8 账号变更即时生效（P1）

改密码/删除/禁用 → 该用户所有会话失效；切换只读 → 下一次写请求立即 403。

验收：改密后旧会话 401；切换只读后下一次写 403；删除后 401；前端收到 403 后刷新权限态并提示。

### R9 登录安全（P0）

失败限速（5 次 / 5 分钟 / IP+账号 → 429 + `Retry-After`）；统一错误文案；常量时间比较；失败日志不含密码；用户不存在时也执行 dummy scrypt；限速 Map 有上限与清理。

验收：第 6 次 429；不存在用户与错误密码响应文案与耗时一致；无法从响应区分账号是否存在；随机用户名不会使限速 Map 无限增长。

### R10 本机访问安全基线（P0）

浏览器写请求校验 `Origin`（同源白名单）；本机自动管理员额外要求 Host 回环；带 Origin 的 JSON 接口拒绝 `text/plain` 等非 JSON Content-Type；会话 Cookie `SameSite=Strict`。

验收：`Origin: http://evil.com` 写请求 403；`Host: evil.com` + 源地址回环 → 不自动管理员；同源正常。

### R11 只读前端体验（P1）

- **viewer**：全局只读横幅；写按钮 `disabled` + 原因；隐藏「上传导入 / 知识写入」导航项；403 显示可操作提示。
- **editor**：知识写入口正常；数据源页面保留入口但列表只读、操作全部禁用并显示无权提示；数据源详情页的「移除登记」与「删除待删文档」按钮隐藏或禁用；任务详情页不暴露任何删除/清理动作；用户管理入口不可见。
- **admin**：全部入口可见。
- 任务页对三类账号可见；操作者列按 Q13 展示。
- 前端统一用 `/api/auth/me` 的 `permissions` + `can('...')` 控制显隐/禁用，不直接判角色。

验收：viewer 能浏览/检索/查看文档且所有写入口不可用；editor 能写知识但无法操作数据源；所有 403 都有可操作提示；无死链/死按钮。

### R12 兼容与恢复（P1）

MCP Token 鉴权不变；Bearer 优先于 Cookie；`/mcp` 回环行为不变（除新增会话支持）。Token 能力集合**不新增** `users.manage` / `tasks.delete`，仍受 scope 约束。非回环启动守卫改为「Token 或未禁用账号至少一个」；按状态区分提示：损坏 `USER_STORE_CORRUPT`、无凭据 `MCP_HTTP_TOKEN_REQUIRED`、账号全禁用 `MCP_HTTP_ALL_ACCOUNTS_DISABLED`、仅 Token/仅账号各有警告；不得降级成「无账号」。users 文件缺失：本机管理员可用，远程登录提示“请在本机执行 `ki user create`”。会话失效/daemon 重启：前端跳登录页，不白屏。文档：`docs/cli.md`、`docs/mcp-http.md`、`README`、`AGENTS.md` 同步。

验收：现有 Bearer 客户端回归通过；上述异常场景逐项符合。

### R13 任务操作者留痕（P0）

`TaskRecord` 新增 `operator` 快照：`{ type: 'user'|'local'|'cli'|'token'|'scheduler'|'legacy', label: string, userId?, tokenId? }`。创建任务时写入，后续不可变；重试任务记录当前操作者，不继承原任务。

展示：任务列表新增「操作者」列（建议放在「来源」之后）；任务详情新增「操作者」行；`ki log` 输出同步；历史任务显示 `—`。操作者对三类账号均可见；任务取消仅管理员可用（v1）。

删除边界：任务详情页不向 editor/viewer 暴露任何删除/清理动作；当前没有任务记录删除接口，待删文档的删除只在数据源页由 admin 执行；未来新增任务删除接口默认 admin-only。

验收：Web 管理员/editor/viewer 触发任务显示对应用户名；本机管理员显示「本机」；CLI 显示「本机 CLI」；定时同步显示「定时同步」；MCP 任务显示 `Token <短ID>`；旧任务显示 `—`；所有任务接口返回 operator。

## 5. 负向需求

| # | 场景 | 检测 | 恢复 / 引导 |
|---|---|---|---|
| N1 | 远程未登录访问 | 401 `AUTH_REQUIRED`；不泄露 scope/文档存在性 | 跳登录页 / JSON 提示登录 |
| N2 | 登录失败 / 暴力破解 | 统一文案；限速；登录后轮换 session | 429 + `Retry-After`；稍后重试 |
| N3 | 只读用户构造写请求 | 服务端 403 `USER_READONLY`（UI 禁用只是体验） | 提示联系管理员调整权限 |
| N4 | 只读绕过（`/mcp` / chat 工具 / 新增写接口） | `/mcp` 只读工具白名单；chat 工具过滤；未知写接口默认拒绝（fail-safe） | 明确错误码与出路 |
| N5 | 删掉最后一个管理员 / 自锁 | 409 `USER_LAST_ADMIN` | 保留至少一个完整管理员；文档写明本机救援路径 |
| N6 | 改密/删除/禁用后旧会话仍可用 | 会话校验用户版本；变更即失效 | 401 → 重新登录 |
| N7 | `users.json` 损坏 / 丢失 | fail-loud `USER_STORE_CORRUPT`，不静默当无账号 | `ki user list` 诊断；备份恢复；不覆盖损坏文件 |
| N8 | 反向代理 / SSH 隧道 / CSRF / DNS rebinding | Host + Origin 校验；启动警告 | 文档说明代理层需自行鉴权；提供关闭本机管理员开关 |
| N9 | editor 直接调用数据源写接口（含 remove / prune 删除） | 403 `DATA_SOURCE_FORBIDDEN`；前端入口隐藏/禁用只是体验 | 提示「读写账号无权管理数据源」 |
| N10 | 旧任务无 operator / operator 被伪造 | 缺失显示 `—`；operator 只由服务端创建时写入，不接受客户端传参 | 任务详情/日志可追溯；不可篡改 |
| N11 | editor 在任务详情页尝试删除/清理 | 当前无任务记录删除接口；待删文档卡片只读；未来新增删除接口默认 admin-only | 页面无入口；接口 403 |

### 2026-11-03 追加需求（用户确认）

- 新增「读写账号」角色：可写知识，但不得在数据源页面进行任何操作（含添加 Git 源）。
- 后台任务新增「操作者」字段，用于显示任务由谁发起。
- editor 不得执行数据源详情页删除（移除登记、删除待删文档）与任务详情页删除/清理动作；未来新增删除入口默认 admin-only。

### 设计评审补充（2026-11-03）

- 聊天会话按 `ownerUserId` 隔离：admin 看全部，editor/viewer 只看/改自己的，旧会话仅 admin。
- MCP Token 不获得 `users.manage` / `tasks.delete`，避免能力白名单给既有 Token 扩权。
- 最后一个 admin 不能被禁用（与删除/降级同一保护）。
- Origin 校验比较 host + port，scheme 允许 http/https（TLS 由代理终止）。
- 任务详情对无 `datasource.read` 的账号脱敏数据源参数。
- users.json 损坏时启动 fail-loud，不降级为「无账号」。
- 登录限速按 IP+用户名存在定向锁定风险，v1 接受。
- 鉴权路径每次重读 `users.json`，移除 mtime+size 缓存（场景推演 P1 修复）。

### 场景推演修复（P2~P7，2026-11-03）

- P2：用户不存在也执行 dummy scrypt，登录失败耗时一致。
- P3：登录限速 Map 设置上限与过期清理，随机用户名不能无限增长。
- P4：401 统一覆盖 API / `/mcp` / chat SSE，只跳一次登录页。
- P5：完全未知路径返回 404；已知但未登记的路由返回 403 + 覆盖率告警。
- P6：启动错误按损坏 / 无凭据 / 账号全禁用 / 仅 Token / 仅账号分别提示。
- P7：旧会话空态说明「历史会话仅管理员可见」；admin 会话列表显示「未归属」徽标。

| A15 | 任务详情页当前无任务记录删除接口；待删文档删除在数据源页 | 若存在未发现的删除入口，需补 admin-only 门禁 | 代码检索 + 页面走查 |
| A16 | 所有 `/api` 路由与 MCP/chat 工具都能纳入能力注册表 | 漏登记的路由会被默认拒绝（安全），但可能误伤读接口；需覆盖率测试 + 全量回归 | 路由盘点 + 正/负向测试 |

## 12. 建议下一步

1. 按本项目流程进入技术设计：鉴权链路、principal 模型、用户/会话文件、API 契约、只读拦截注册表、安全基线。
2. 进入界面设计：登录页、用户管理页、只读态；以 §7 已确认的 ASCII 为输入。
3. 不建议直接编码：涉及鉴权链路、跨通道拦截与数据契约，先设计评审能显著降低返工。
