# 追问与分析共用内核（含追问配置化）

> 一句话：把「AI 分析」与「AI 分析追问」从**两套 runner** 收敛为**一套内核 + 六处参数化**，并让追问的提示词 / skill / 轮次走配置。

## 1. 背景

### 1.1 现状：一套内核 + 两层壳，重复落在最容易漂移的地方

| 已共享（做对了） | 仍是两套（要收） |
|---|---|
| `buildKbReadToolEntries`（4 个只读 `ki_*`）、`createFsToolEntries`（`fs_*`）、`streamChat` 参数（300s / 首字节 30s / idle 60s）、工具响应 10k 截断、DSML 收口提示、`normalizeChain` 归一 | 提示词、上下文组装、工具循环、输出处理、落盘、限流、取消 |

**最扎心的漂移**：追问提示词是**硬编码 6 句**（`src/lib/events/analysis-ask-runner.ts:328-337`），完全不读 `prompt-config`。用户在「AI 设置 → AI 分析」里改提示词、改 skill、开关工具，对追问**零影响**；追问也**没有任何 skill 能力**（无 `use_skill` 工具、不注入 skill 正文）。

### 1.2 成因（不是设计决定，是三次补丁）

```
追问先落地（B2 需求）        → analysis-ask-runner.ts 自带提示词/落盘/限流
追问带工具再调查（11-19）    → 只 import 工具工厂，循环体自己又写一遍
结论改 chain（11-19）        → 追问上下文跟着改（第三个消费点）
prompt-config 四域（11-19）  → 只接了 analysis，ask 没接
```

仓库内已有正确先例：「AI 查找」已把内核抽到 `deep-find-core.ts`，`find-service.ts` 只调 core，旧 `runDeepFind` 已删除。

### 1.3 六处是**真差异**，必须参数化（不是冗余、也不是合并障碍）

| # | 差异 | 分析 | 追问 |
|---|---|---|---|
| 1 | 上下文 | 事件上下文 + 文档清单 + 开场预取 | 同上 + **最近 N 轮问答历史** |
| 2 | 闸门 | 强制 `targetDir` + ≥1 个 fs 工具 + `supportsTools` | 允许无 `targetDir`，降级只剩 `ki_*` |
| 3 | 输出 | 强制唯一 JSON + 候选二次校验 + 2 次格式重试 | 自由文本，硬截 4000 字 |
| 4 | 轮次 | `while(true)` 至自然收口 | 5 轮上限（第 6 轮撤 tools 强制作答） |
| 5 | 落盘 | `draft` + `steps` + 断点续跑文件 | `turns[]`（200 条 / 512KB） |
| 6 | 限流 / 取消 | 无限流、有 `cancelEventAnalysis` | 独立 6 次/60s + 并发 2、**无取消入口** |

> 历史问答属追问的定义（不带才叫坏），`resume` 只有分析后台任务写、追问不引用——**两者在正常实现下不会串台**。串台只会发生在"共用一个 `messages` 变量 / 追问也写 resume"这类错误写法上。

### 1.4 三个真正的工程注意点（非设计障碍）

1. `followupLimiter` 是**模块级单例**（`analysis-ask-runner.ts:73`）：合并时若把分析也接到同一实例，两边互相挤占额度。
2. **SSE 帧形状**：前端有两套解析器（`web/src/api/governanceApi.ts:766-798`），事件产出必须保持形状兼容，否则一处先坏。
3. **有状态机制要重测**：断点续跑（`.analysis.resume.json`，8MB / 7 天 / 终态即删）、取消、僵尸归一（120s）、`runId` 守卫，合并后逐项回归。

## 4. 负向需求

| # | 场景 | 要求 |
|---|---|---|
| N1 | 配置非法（prompt 空、skill 名中文、`maxRounds` 越界、`historyTurns` 过大） | 保存即明确报错，沿用现有 skill 名规则 |
| N2 | 历史轮次调大导致 token 超预算 | 按最近 N 轮裁剪并告知"更早的问答已省略"，**不报错** |
| N3 | 无 `targetDir` 的 scope 下追问 | 必须仍可用（降级只剩 `ki_*`），不得因合并退回硬失败 |
| N4 | 分析侧无限轮次 | 不得被追问的轮次上限误伤 |
| N5 | 旧配置文件无 `analysis.ask` | 走默认值，不报错 |
| N6 | 合并中途中断 | 不留"两套并存 + 双写"的过渡态 |
| N7 | 追问并发 | 限流实例隔离，连续追问不影响分析 |
