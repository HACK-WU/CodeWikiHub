# 上传导入跨页面任务与暂存清理：需求与实现跟踪

> 模式：product-manager M1，一次成型档。证据声明：最高 🟢 代码直读；未运行浏览器场景。代码事实与产品约定分别标注。

## 1. 目标与已确认取舍

用户上传文档时，可以在同一标签页内切到知识库浏览等页面，上传及随后启动的导入继续执行；任务进度和结果可从其他页面查看。关闭或刷新标签页时，尚未完成的上传无需续传，下次由用户重新选择文件、从头上传；不弹关闭确认。已被后端接受的导入任务不因标签页关闭而取消。上传后遗留的暂存文件采用**惰性清理**：下一次有人开始新上传时，清理此前空闲超过 **24 小时**、且不被运行中的导入使用的暂存目录；不做周期扫描。

暂存目录空闲期限为 24 小时；清理触发方式“下一次新上传时顺手清理”已由用户确认。若此后一直无人上传，过期文件继续占用磁盘，直到下一次新上传。

## 2. 现状与问题（代码直读 🟢）

| 现状 | 证据 | 用户影响 |
|---|---|---|
| `/import` 为独立路由；上传计划、文件引用、进度、job 均在 `ImportPage` 内 | `web/src/router/routes.tsx:16`；`web/src/pages/ImportPage.tsx:20-50,389-397` | 切页后页面状态丢失，返回时不能恢复任务视图 |

## 3. 范围与需求清单

| ID | 优先级 / Kano | 需求 | 验收标准 |
|---|---|---|---|
| R1 | P0 / 必备 | 在同一标签页内从上传导入页切到其他页面时，上传、后续启动导入以及状态跟踪继续；切页不表示取消。 | 上传中切到知识库浏览，全部文件仍按本次设置进入目标 scope/group；返回上传页看到同一任务，无重复上传。 |
| R2 | P0 / 必备 | 任务状态在页面之间共享，展示阶段（读取/上传/导入）、进度、失败与最终结果；在其他页面可找到并返回任务。 | 切页期间可看到任务仍在进行；导入成功/失败有明确反馈；返回页可查看已处理数与文件级错误。 |
| R3 | P0 / 必备 | 上传页卸载或网络报错不能静默吞掉失败；同一标签页内上传失败仍可按现有批次重试，不因切页失去恢复入口。 | 在第 N 批构造失败并切页，能从全局任务入口看到失败、返回后重试第 N 批；此前成功批次不重复写入。 |
| R4 | P0 / 必备 | 关闭或刷新标签页时，尚未完成的上传不保证继续，也不提供跨标签页续传；再次打开由用户重新选文件开始新任务；无浏览器关闭确认弹窗。 | 关闭标签页后重新进入上传页，不显示虚假的“上传成功”或可续传状态；新上传可正常完成。 |
| R5 | P0 / 必备 | 只有完整且经后端确认的上传才能启动导入；关闭标签页不能造成“文件全到齐、却永远未启动导入”的含糊终态。导入启动须可判定、可防重复。 | 最后一批上传请求在后端校验并持久化后自动建立导入任务；丢失响应后能按 uploadId 找回同一任务，不会重复导入。 |
| R6 | P0 / 必备 | 后端已接受的导入任务与标签页生命周期解耦；关闭标签页后继续到成功或失败终态。 | `/api/import/run` 已返回成功后关闭标签页，服务仍完成该 job；再次打开时有合理的任务结果查询/失效说明，不把状态未知显示为失败。 |
| R7 | P0 / 必备 | 新上传开始时惰性清理空闲超过 24 小时、且尚未启动导入的暂存目录；无需周期扫描。继续上传或启动导入旧任务时拒绝已过期任务。已导入目录登记为源目录，必须保留供后续编辑/同步使用。 | 下一次新上传仅清理过期且不活跃的未导入目录；已导入目录与正在导入目录保留；旧 `uploadId` 过期后不能继续使用；没有新上传时不要求准点删除。 |
| R8 | P1 / 期望 | 导入成功后，当前打开的知识库浏览、总览、搜索页面中的文档列表/Group/标签数据及时更新。 | 导入中停留在知识库浏览，完成后可看到新文档，无需手动刷新整页；若当前筛选条件排除新文档，不强行改变筛选。 |
| R9 | P1 / 期望 | 任务反馈区分“上传完成”“导入任务已启动”“导入完成”，部分文件失败不得显示成整体无错成功。 | 任一文件上传校验失败或导入处理失败时，反馈包含失败阶段、文件/批次和可采取的下一步。 |

### 范围外

- 关闭或刷新标签页后自动续传本地文件、静默恢复文件权限、在浏览器长期缓存原始文件。
- 根据浏览器连接断开立即删除已成功上传的批次；多批上传中的请求间隔不是可靠的放弃信号。
- 后台周期扫描暂存目录；只有下一次新上传触发过期清理。
- 修改原有文件格式、切分、向量化、同名冲突和权限规则。

## 4. 负向需求与边界

| 场景 | 期望行为 |
|---|---|
| 单个 HTTP 请求传到一半即中断 | 该请求不产生可导入的半文件；此前成功批次保留到惰性清理；不启动导入。 |
| 已完成若干批次后关页 | 无后续导入；下次重新选择文件上传；旧暂存目录满足过期条件后由新上传清理。 |
| 全部批次完成、启动导入请求结果不明时关页 | 必须能区分“未启动”和“已启动”；重试不重复导入（R5）。 |
| 站内切页时上传/导入失败 | 全局任务状态明确失败，保留本标签页可用的重试入口；不把错误藏在已卸载页面。 |
| 用户切到另一 scope | 任务继续绑定发起时的 scope/group/选项；全局状态标明所属 scope，不把结果归到当前选择的 scope。 |
| 同时有多个上传操作 | 不得用后一个任务覆盖前一个任务的进度或结果；若本期仅支持单任务，第二次启动须明确拒绝或排队。 |
| 清理与活跃上传/导入并发 | 清理前再次核对状态与最后活动时间；同一 `uploadId` 的清理、上传和启动导入互斥。 |
| 清理失败或遇到异常目录 | 新上传仍可继续；记录可诊断错误，清理范围仅限受控上传目录。 |
| 服务重启 | 运行中内存 job 可能丢失；前端显示状态不可确认并引导核查，不声称成功或失败；暂存目录仍按惰性规则处理。 |

## 6. 优先级依据

R1-R7 是用户能够放心切页、关页并避免误导或磁盘无限累积的必要条件，Kano 为必备，价值高；其中跨页面任务状态和提交边界的改造成本为中到高，惰性清理成本中。R8-R9 为期望项，价值中到高、成本中：它们决定任务完成后用户是否能立刻看到结果，并避免“部分失败却像成功”的体验。

## 7. 已确认决策

| ID | 内容 | 若不成立的影响 | 验证方法 |
|---|---|---|---|
| D1 | 最后一批上传成功并通过后端校验后，后端立即建立导入任务；标签页关闭不影响该任务。 | 分批上传协议携带总批次数与最终批次的导入选项；服务端按 uploadId 幂等启动并记录 jobId。 | 已按此方案实现；重开页面可查询 uploadId，找回已启动的 job。 |
| D2 | 暂存清理只删除空闲超过 24 小时、尚未启动导入的上传目录；已导入目录作为 source.dir 保留。 | 成功导入后的源文件需支持后续编辑、同步。 | 清理逻辑排除已关联 jobId 的目录。 |

## 8. 实现状态

功能代码已落在独立工作树中，包含跨页面任务状态、最后一批自动启动导入、uploadId 状态恢复，以及只清理未启动导入且闲置超过 24 小时的暂存目录。已导入目录会保留为后续编辑和同步使用的源目录。验收结果与实现偏差在完成交付时补充。
