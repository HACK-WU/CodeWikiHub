# S-04 SKILL 与验证 · 设计

## 1. 术语

| 术语 | 定义 |
|---|---|
| 主库 | 被图集描述的项目知识库，命令里的 `--scope` |
| 图集库 | `<主库>-atlas`，图集包与 md 副本的唯一落点 |
| 关联视图 | 主库已加入、且图集库需要加入的视图 |
| 过渡参数 | `--legacy-scope`，保留一版旧「落点库」语义 |

## 2. 现状（AS-IS）

`skills/atlas-deploy/SKILL.md` 的核心约束是「落点 = 图集所在 scope」与「group 名固定 `知识地图`」。§3.2 要求 `ki import --scope` 与 `ki atlas upload --scope` 同值；§3.3 的「换库迁移」是「新库重做 + 旧库清理」；§5 排障把「AI 检索命中不到」归因为「没做 §3.2 或 group 名不对」，不涉及视图授权。

## 3. 方案（TO-BE）

### 3.1 章节改造对照

| 章节 | 现状 | 改为 |
|---|---|---|
| 概述 / 一句话 | 装进「哪个库」 | 装进「主库对应的图集库」 |
| §0 速览 | ① 校验包 ② 选库 ③ upload ④ 导 md ⑤ 导入 group ⑥ 状态 ⑦ 页面 ⑧ AI | ① 校验包 ② 定主库 ③ upload（自动落图集库）④ 导 md 到图集库 ⑤ `atlas link` 自动发现主库所在视图并补授权 ⑥ 状态 ⑦ 主库页看到图集 ⑧ AI 命中 |
| §1 前置 | 目标库存在可写 | 主库存在可写；图集库可不存在（自动建）；映射已确认 |
| §3.1 upload | `--scope <库>` | `--scope <主库>`，说明推导与 `--atlas-scope` 覆盖 |
| §3.2 同步 AI 层 | 导入「图集所在库」的 `知识地图` | 导入**图集库**的 `知识地图`；新增 `ki atlas link` 步骤 |
| §3.2 纪律 1 | 「落点 = 图集所在 scope」 | 「落点 = 主库对应的图集库」 |
| §3.3 迁移 | 换库重做 + 旧库清理 | 改映射 / 改 `--atlas-scope`；存量 `default` 标注「暂不迁」 |
| §4 验证 | 状态 + 页面 + AI 命中 | 追加「视图仍可见」「主库页出图」「图集库不在正文检索里重复」 |
| §5 排障 | 12 条 | 追加「加入视图后视图消失」「主库页空态」「切到图集库看不到正文」 |
| §6 红线 | 图集包不进 group | 改为「图集包只进图集库 `.atlas/`，md 只进图集库 `知识地图`」 |

### 3.2 新流程（写入 §0 速览）

```
有 dist/atlas.zip + dist/atlas-md/ 吗？
├─ 没有 → 回生成侧（project-atlas）
└─ 有
   ├─ ① 校验包形状（唯一 html / baked / 无外链 / 体积）
   ├─ ② 定主库（--scope kisearch），图集库自动推导为 kisearch-atlas
   ├─ ③ ki atlas upload --scope <主库> --file dist/atlas.zip
   ├─ ④ ki import --scope <图集库> --source dist/atlas-md --group 知识地图 --prune
   ├─ ⑤ ki atlas link --scope <主库>（自动发现包含主库的视图并补授权）
   ├─ ⑥ ki atlas status --scope <图集库> --json
   ├─ ⑦ 主库页 /atlas 直接出图；顶栏显示写入 kisearch-atlas
   ├─ ⑧ ki search --scope <视图> --query "<某页摘要>" 命中
   └─ ⑨ 失败 → §5 排障
```

### 3.3 新增验证（§4）

| # | 项 | 命令 / 判定 |
|---|---|---|
| 1 | 图集库有包 | `ki atlas status --scope kisearch-atlas --json` → `exists:true`，sha 与本地一致 |
| 2 | md 落在图集库 | `ls /root/.ki-data/kisearch-atlas/知识地图/` 有 `README.md` 与分类目录 |
| 3 | 视图仍可见 | `ki view audit-grants` → 无「缺成员授权」；用原 Token `ki_scope_list` 仍能看到该视图 |
| 4 | 主库页回落 | `kisearch` 下打开 `/atlas` 出图，不是「这个库还没有知识地图」 |
| 5 | 切换器按主库 | 视图下切换器项名为 `kisearch`，不出现 `kisearch-atlas` |
| 6 | AI 命中 | `ki search --scope kisearch-docs --query "<某页摘要>"` 命中，`group` 为 `知识地图/...` |
| 7 | 落点唯一 | 新部署路径不写主库；若旧语义曾在主库装过图集，`exists:true` 属存量正常现象，单独确认后再决定清理 |

### 3.4 排障增量（§5）

| 现象 | 原因 | 下一步 |
|---|---|---|
| 加入视图后该视图从列表消失 | 图集库未补授权，`filterAuthorizedViews` 整视图隐藏 | `ki view audit-grants` → `ki mcp token update <id> --scope <原授权>,<图集库>`，或重跑 `ki atlas link --scope <主库>` |
| 主库页仍显示「还没有知识地图」 | 图集库未装 / 前端未获映射（旧 daemon） | `ki atlas status --scope <主库>-atlas --json`；确认前端版本 |
| 切到图集库后浏览页没有正文 | 图集库只存图集 md，不是业务知识 | 正常。浏览正文回主库；图集库只供图集与 AI 引用 |
| 同名图集出现两份 | 存量 `default` 未迁 | 已知并接受；需要清理时按 §3.3 单独处理 |
| `--scope` 写错图集库名 | `ki import` 会静默建库 | 部署前 `ki view show` / `ki scope list` 核对；库名以推导结果为准 |

### 3.5 红线调整（§6）

| # | 红线 |
|---|---|
| 3 | 图集包只进图集库的 `.atlas/`；md 只进图集库的 `知识地图`；**主库不落任何图集产物** |
| 7（新增） | 不跳过 `atlas link` 就宣称「AI 能查到」——未入视图的图集库检索不到 |
| 8（新增） | 不绕过 `atlas link` 手工改 `views.json` 或 Token 授权——会漏掉逐条审计输出与口径校验 |

## 6. 关键决策点

| 决策 | 选项 | 结论与理由 | 重新评估触发条件 |
|---|---|---|---|
| 存量 `default` 是否写入迁移章节 | ① 完整迁移步骤 ② 只标注「暂不迁」 | **②**。用户 2026-11-27 明确暂不动；写迁移步骤会诱导执行 | 用户决定迁移存量时 |
| 是否保留旧纪律「同 scope」 | ① 直接删 ② 标注「已废弃，指向新纪律」 | **②**。避免读过旧版的人继续按旧约束执行 | 旧纪律在文档里完全无引用时 |
| `atlas link` 是否必需步骤 | ① 必需 ② 可选 | **①（当使用视图检索时）**。不加入视图的图集库 AI 查不到，必须显式说明 | 检索侧能自动映射图集库、不再依赖视图成员时 |
| 视图发现与授权默认值 | ① 显式列视图 + 显式 `--grant` ② 自动发现 + 默认补授权 | **②**。用户要求「自动加入视图」；默认不补授权会直接导致视图消失，用 `--no-grant` 保留收紧能力 | 阈值 5（S-02 §9-4）被证实不合适时 |
| 被否决：把三条命令写成脚本 | 提供 `deploy.sh` | 否决。仓库内无部署脚本目录，脚本会与 SKILL 双源；命令已足够短 | 部署步骤增长到 5 条以上时 |
