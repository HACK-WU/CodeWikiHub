# 需求：ki_ask 问答按来源分组上屏

> 归属：AI 对话页（`/chat`）。上游：REQ-20261113-001（`ki_ask` 工具本体）、REQ-20261115-001（`background` 入参）。
> 视觉与交互基线：`demo/ki-ask-grouping/index.html`（2026-11-16 用户确认）。

## 1. 问题

`ki_ask` 是给外部 AI agent 用的 MCP 问答工具，**每次问答都已落盘**为 `{chatDir}/{scope}/ka-<base36>-<32hex>.json`，但：

- **页面看不到**：会话列表只认 `CONV_FILE_RE = /^c-[A-Za-z0-9-]+\.json$/`，`ka-*` 天然被挡在列表外（`chat-store.ts:127`、`ask-store.ts:4-9`）。这是当初刻意的设计，不是 bug。
- **10 分钟后自动消失**：`ka-*` 走滑动 TTL + 60s 定时 GC，过期直接删文件（`ask-gc.ts:48-91`）。用户想起"刚才让 agent 查过什么"时，痕迹已经没了。
- **看不到提问背景**：`background` 只在内存里拼进本轮 user 文本，**从不落盘**（`ask-runner.ts:363-365`），回看时「他为什么这么问」无从判断。

⇒ 用户诉求：在 `/chat` 左侧会话列表里**按来源分组看到这些问答**，点开可读，且不干扰自己的人工会话。

## 2. 需求变更声明（推翻两条既有决策）

本需求不是补漏，是**显式变更**。两条被推翻的决策都必须在此留痕：

| # | 原决策 | 出处 | 新口径 | 为什么可以推翻 |
|---|---|---|---|---|
| C1 | `ki_ask` **不落盘**、**不进 web 会话列表**（写入验收标准） | REQ-20261113-001 R1 / R9；S03 设计不变式「web 会话列表 → 仍无」 | 落盘保留、进列表（**独立分组**、默认折叠） | 原决策的动机是「不污染人工会话列表」；用分组隔离同样达成该目的，且不牺牲可回溯性 |
| C2 | `background` **不落盘**（一次性语义） | REQ-20261115-001 §10-1 | 落盘留痕，**回放时丢弃** | 原决策把「不占上下文」与「不落盘」绑在一起；两者可解耦 —— 存储留痕 + 回放排除，既保留一次性语义，又让回看可理解 |

> C2 的解耦是本需求的核心设计约束：**写入与回放必须分开处理**，否则背景会跨轮重复进入上下文（撑爆 20 条 / 60K 字符预算）。

## 3. 已拍板决策（2026-11-16 用户确认）

| # | 决策点 | 选择 | 理由 |
|---|---|---|---|
| D1 | 分组维度 | **我的会话 / 本地连接 / 各 Token（按 token 名称）** | 远程 MCP 必带 token，token 名是用户可识别的来源标识；本地连接无 token，单独一组 |
| D2 | 详情权限 | **只读回放**，不可续聊、不可改名 / 归档 / 删除 | `ka-*` 无这些字段，凭空造会在界面上做成"点了没反应" |
| D3 | 头部按钮位置 | 切换会话列表按钮移到「居中 / 铺满」**右侧**、配置左侧 | 用户指出的现状可发现性问题 |
| D4 | 背景展示 | 贴在**问题气泡内、问题上方**，引用样式（左竖线 + 小字 + 字数），不折叠 | `demo` 已按此形态确认 |
| D5 | 续接语义 | 一条列表项 = **一个 `context_id` 链**（1~N 轮），不是单轮 | 与 `ki_ask` 的续接模型一致；默认无状态调用即 1 轮 |
| D6 | 本机连接的来源 | **恒为 `local`**（不按 Token 分组） | 🟢 实测：`mcp-http.ts:1332` 绑定回环时鉴权关闭，带不 bearer Token 身份都是 `local`。⇒ Token 分组只在 daemon 对外监听时出现 |

## 4. 需求清单

| # | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| **R1** | 左侧列表新增来源分组：`我的会话`（现有 `最近/已归档` 保留）、`本地连接`、每个 Token 一组 | P0 | 存在 2 个 token（codex / cursor）时列表出现 4 个分组；分组头显示条数、可折叠、折叠态记忆在本次会话内 |
| **R2** | Token 分组名**实时跟随** Token 当前名称；Token 被删除后兜底显示「已删除的 Token（原名）」 | P0 | 改名 `codex`→`codex-old`：刷新后分组名变、历史问答跟到新组；删除该 Token：分组仍在且标题带「已删除」 |
| **R3** | 分组可见性：`本地连接` 仅 admin；Token 组按 `TokenRecord.ownerId` 归属，admin 可见全部 | P0 | 非 admin 用户看不到他人 Token 的分组；admin 全见；无 `ownerId` 的旧 Token 仅 admin 可见 |
| **R4** | 点开 agent 问答 → 只读详情：逐轮「问题 + 答案」，答案下方带来源卡片 | P0 | 两轮问答显示 4 条消息；来源卡片可点击并定位原文；页面无输入框，替换为「仅供回看」条 |
| **R5** | `background` 落盘并显示在问题气泡内；**回放注入上游时丢弃** | P0 | 首轮带背景：详情显示「提问前提 · N 字」+ 全文；次轮续接：上游 messages 不含该背景（回归用例守） |
| **R6** | 保留期与续接 TTL 解耦：列表态保留 **7 天**，10 分钟滑动 TTL 只管 `context_id` 续接 | P0 | 问答产生 11 分钟后：`context_id` 续接报 `ASK_CONTEXT_EXPIRED`，但列表里仍能看到并点开 |
| **R7** | 列表数据走**独立接口**，不并入主列表的目录扫描 | P0 | 主列表请求耗时不受 `ka-*` 文件数影响（构造 500 个 `ka-*` 后主列表 RT 不变） |
| **R8** | 头部切换按钮移到「居中 / 铺满」右侧；窄屏退化为汉堡并拉出抽屉 | P1 | 1440 宽：顺序为 `模型 · 状态 · 居中/铺满 · ≪ · 配置`；768 宽：`居中/铺满` 隐藏，按钮变汉堡、点击拉出抽屉 |
| **R9** | 失效与异常态：临期（≤1 天）/ 超保留期 / 文件损坏的条目需有明确呈现 | P1 | 临期条目显示「仅剩 1 天」；超保留期不出现在列表，直连 URL 提示「已超过 7 天保留期」；损坏文件标「文件损坏」不牵连整页。**不使用「已过期」措辞**（续接 TTL 仅 10 分钟，几乎所有历史条目都"过期"，标记无信息量） |
| **R10** | 搜索跨分组过滤；分组内条目超过 5 条时折叠为「还有 N 条…」 | P1 | 输入关键词后只剩匹配项跨组显示；单组 12 条时默认 5 条 + 「还有 7 条…」 |
| **R11** | （**本期不做**）「以该问答新建会话继续追问」 | P2 | 下一期再议；本期只留按钮位或直接不渲染 |

## 5. 负向需求

| # | 场景 | 期望行为 |
|---|---|---|
| N1 | 在 agent 条目上尝试改名 / 归档 / 删除 | 入口**不渲染**（不是渲染后点了没反应） |
| N2 | Token 被删除 / 归属账号被禁用 | 分组保留，标题标「已删除的 Token」；不整组消失（否则用户以为数据丢了） |
| N3 | `ka-*.json` 损坏或字段缺失 | 单条标 `corrupted`，其余正常返回（沿用主列表口径）；不整体报错 |
| N4 | agent 高频调用（如 200 次） | 分组分页 + 单组上限，不把左栏撑爆；列表 RT 不随条目数线性劣化（`ka-*` 需按时间倒序取前 N） |
| N5 | 问答失败 / 超时（现状不落盘） | 列表不出现该次调用（保持现状），**不伪造成功记录** |
| N6 | 非 admin 用户访问他人 Token 分组的详情接口 | 403 / 404 一致语义，不泄露条目是否存在 |
| N7 | 背景里含敏感信息（日志片段 / 内部地址） | 详情仅授权用户可见；**审计日志仍只记长度**、不记正文 |
| N8 | 时区 / 时间显示 | 列表时间与主列表同口径（相对时间），详情用本地时间 |

**列表结构**（左栏 260px）：

```

────────────────────────────────

    K8s 部署流程梳理      3 分钟前  12 条
    向量重建失败排查        昨天     28 条
⌄ ⌂ 本地连接  本机              3

  ▌ …
  还有 8 条…
```

- 分组头：折叠箭头 + 类型图标（`⌂` 本地 / 钥匙 Token）+ 名称 + 类型徽标 + 条数
- agent 行：标题左侧 2px 类型色竖条（本地=主色 / Token=信息蓝）
- 过期行：整行降透明度 + 「已过期」标

**详情**（只读）：顶部来源 chip（`codex` / `本地连接` + scope + 「只读」）→ 逐轮消息 → 底部只读条替代输入框：
