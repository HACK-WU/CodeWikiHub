## 模型总览

ORM 为 TypeORM 0.3.x，全部采用「装饰器 + 显式表名」的 Active-Record 风格：`@Entity('<snake_case 表名>')`，主键统一 `@PrimaryGeneratedColumn('uuid')`，外键采用「关系对象 + 标量列」双写（`@ManyToOne` + `@RelationId` + 显式 `*Id` 列）。实体通过各模块 `TypeOrmModule.forFeature([...])` 注册，并由 `src/bootstrap` 的 `registerAllEntities()` 汇总注入 `dbConnectionOptions.entities`（见 `src/seed.ts` 的实际调用）。服务侧统一继承 `CrudService<T>` 或 `TenantAwareCrudService<T>`：后者在有 `RequestContext` 用户时自动为查询补 `tenantId` 过滤条件。

表命名与领域对应：`tenant` / `tenant_setting` 属租户域，`feature` / `feature_organization` 属开关域，`referral_code` / `referral_relation` 属返利域，`email_sent` / `email_template` / `custom_smtp` 属通知域。

章节来源：[tenant-aware-crud.service.ts](file://packages/server/src/core/crud/tenant-aware-crud.service.ts)（关键符号：TenantAwareCrudService）、[seed.ts](file://packages/server/src/seed.ts)（关键符号：registerAllEntities）

## 实体基类分层

| 基类 | 位置 | 提供列/关系 |
| --- | --- | --- |
| `Model` | `core/entities/base.entity.ts` | 无列；构造函数拷贝输入键值（`instanceOf` 已标 `@deprecated`） |
| `BaseEntity extends Model`（implements `IBaseEntityModel`） | 同上 | `id uuid`（`@PrimaryGeneratedColumn('uuid')`）、`createdById uuid NULL` + `createdBy → User`（`onDelete: 'RESTRICT'`，`UserPublicDTO` 转换）、`updatedById uuid NULL` + `updatedBy → User`（同 RESTRICT）、`createdAt/updatedAt timestamptz`（`CreateDateColumn`/`UpdateDateColumn`） |
| `TenantBaseEntity extends BaseEntity` | `core/entities/tenant-base.entity.ts` | `tenant → Tenant`（`nullable: true`，`onDelete: 'CASCADE'`）、`tenantId string NULL` 且 `@Index()` |
| `TenantOrganizationBaseEntity extends TenantBaseEntity` | `core/entities/tenant-organization-base.entity.ts` | `organization → Organization`（`nullable: true`，`onUpdate: 'CASCADE'`，`onDelete: 'CASCADE'`）、`organizationId string NULL` 且 `@Index()` |

分层含义：`BaseEntity` 只给「谁创建/更新 + 时间戳」；进入租户域挂 `tenantId`（多租户隔离与级联删除的锚点）；再进入组织域挂 `organizationId`（组织级覆盖，如 SMTP、邮件模板）。9 张表均继承链上三级之一，均含 `id`、`createdById/createdBy`、`updatedById/updatedBy`、`createdAt/updatedAt`，下文各表不再重复列出这些继承列。

章节来源：[tenant-base.entity.ts](file://packages/server/src/core/entities/tenant-base.entity.ts)（关键符号：TenantBaseEntity）、[tenant-organization-base.entity.ts](file://packages/server/src/core/entities/tenant-organization-base.entity.ts)（关键符号：TenantOrganizationBaseEntity）

## 迁移与 Seed 惯例

- **无迁移目录**：本域（乃至 `packages/server/src` 内）不存在 `migrations/` 目录与迁移文件，仓库内也未提供 `schema:sync`/`migration:run` 脚本；表结构由 TypeORM 同步生成 —— `getDbConfig()` 返回 `synchronize: true` 与 `uuidExtension: 'pgcrypto'`。
- **多实例例外**：`initializeApplicationDataSource` 在 `DB_SCHEMA_SYNC_MODE=external` 时强制把 `synchronize` 置为 `false`（由单独的 schema-sync 任务独占 DDL），API 进程不再改表。
- **Seed 入口**：`src/seed.ts` → `seedDefault()` → `SeederModule` + `SeedDataService.runDefaultSeed(false)`：`cleanUpPreviousRuns` → `createConnection` → `resetDatabase` → `seedBasicDefaultData`。`seedBasicDefaultData` 顺序为 Countries → Currencies → Languages → Features（`createFeatures`）→ `seedTenantDefaultData(DEFAULT_TENANT)`。
- **`seedTenantDefaultData` 顺序**：租户（`createDefaultTenant`）→ 角色（`createRoles`，遍历 `RolesEnum` 并标记 `isSystem`）→ 默认设置（`createDefaultTenantSetting`，`fileStorageProvider=LOCAL`）→ 角色权限 → 组织 → 默认 feature toggle（`createDefaultFeatureToggle`）→ 默认邮件模板（`createDefaultEmailTemplates`）→ 管理员/用户。
- **按模块 seed**：`seedModule` 动态调用 `run<Module>Seed(tenantName, organizationName)`，例如 `runTenantSeed`、`runTenantEmailTSeed`（只补发某租户的默认邮件模板）；`Email`（`email_sent`）的 seed 仅用于演示数据（`createDefaultEmailSent` / `createRandomEmailSent`）。
- **幂等写法**：seed 普遍先查重再插入（如 `insertTenant` 先按 `name` 查 `existedTenant`），失败仅 `console.log({error})` 不抛出关键业务错误。

章节来源：[main.ts](file://packages/server/src/main.ts)（关键符号：getDbConfig）、[application-data-source.ts](file://packages/server/src/database/application-data-source.ts)（关键符号：initializeApplicationDataSource）、[seed-data.service.ts](file://packages/server/src/core/seeds/seed-data.service.ts)（关键符号：SeedDataService.seedTenantDefaultData）

## 非列字段与计算列

- `Feature.isEnabled?` / `Feature.imageUrl?`：不是列，由 `FeatureSubscriber.afterLoad` 计算 —— `isEnabled` 取 `toggleFeatures[entity.code]`（来自 `@xpert-ai/server-config`），未配置时为 `true`；`imageUrl` 在 `image` 存在时取 `new FileStorage().getProvider().url(entity.image)`。`Feature.status` 虽是列，但加载为空时会被随机填 `FeatureStatusEnum` 之一（`shuffle` 取首值）。
- `EmailTemplate.title?`：不是列，由 `EmailTemplateSubscriber.afterLoad` 从 `name` 推导 —— `name.split('/')[0].split('-').join(' ')`。
- `CustomSmtp.secretKey?` / `CustomSmtp.secretPassword?`：不是列，`@IsSecret()` + `@Expose({ toPlainOnly: true, name: 'username' | 'password' })`；`@AfterLoad` 先把 `username`/`password` 赋给它们，再调用 `WrapSecrets(this, this)` 打码（默认保留前 6 位，其余替换为 `*`），因此 API 出参里 `username`/`password` 被 `@Exclude` 隐藏、只暴露打码后的 `secretKey`/`secretPassword`。
- `Email.expired`：**本域不存在该字段** —— `email_sent` 实体（类名 `Email`）只有 `name/content/email/isArchived/userId/emailTemplateId`；仓库内带 `@AfterLoad` 计算 `expired` 的实体是 `password-reset`（超 10 分钟）、`api-key` 与 `secret-token`（`differenceInMinutes(now, validUntil) > 0`），属其他模块，不在本域 9 张表内。

## 校验规则汇总

- **实体级（class-validator + Swagger）**：`@IsNotEmpty`（`Tenant.name`、`Feature.name/code`、`Email.name/email/emailTemplateId`、`EmailTemplate.name/languageCode/hbs`、`CustomSmtp.username/password`）、`@IsEmail`（`CustomSmtp.fromAddress`）、`@IsNumber`（`port`）、`@IsBoolean`（`secure`）、`@IsString`/`@IsOptional` 广泛标注；`@ApiPropertyOptional` 区分可空字段。
- **DB 级**：`Tenant.subdomain` 唯一索引、`Feature(name, code)` 复合唯一、`ReferralCode` 两条唯一索引 + 两条 CHECK 正则、`Email.emailTemplateId` 非空、外键级联（`Tenant/Organization/Feature/Template` 为 `CASCADE`，指向 `User` 的关系为 `RESTRICT` 或 `SET NULL`）。
- **服务/DTO 级**：控制器使用 `UseValidationPipe({ transform: true, whitelist: true })` 或 `ValidationPipe`；`UUIDValidationPipe` 校验路由 `id`；业务校验在服务层（子域名查重与格式、组织级禁配 `FEATURE_MEMBERSHIP_PURCHASE`、返利码归属与自引用、注册用户名/邮箱唯一）。

## 已知风险与坑

- **`tenant_setting` 缺 `(tenantId, name)` 唯一约束**：并发写同一 key 可产生重复行，读取时后写入的值不一定生效（`getSettings` 用 `object(pluck...)` 覆盖，顺序不确定）。
- **`feature_organization` 缺唯一约束**：同一 `(tenantId, organizationId, featureId)` 可能多行；`updateFeatureOrganization` 用 `some(item => item.isEnabled === true)` 判定前一状态，多行时状态语义模糊。
- **`custom_smtp` 缺唯一约束**：同作用域多条记录时依赖 `ORDER BY createdAt DESC` 取最新，等价于「最后写入者胜出」，且 `isValidate` 不参与筛选。
- **模板 `name` 依赖目录结构**：`name = "[template-name]/[type]"`，文件移动或改名会改变既有数据的 `name`，而 `createEmailRecord` 只按 `name + languageCode` 匹配，易出现关联不到模板。
- **软删除与级联的交互**：`referral_code`/`referral_relation` 指向 `User` 的关系是 `SET NULL`，用户被物理删除后关系仍保留但失去主体，视图需靠 `deleted: true` 兜底。
- **实体构造副作用很小但要注意**：`Model` 构造函数会无差别拷贝输入键值，传入未声明的键会被赋成实例属性（不会入库），排查字段来源时需意识到这点。
