## 1 定位与何时找

一句话：这四条入口是**同一条运行时链的四个供给位**——运行时准入读 `xpert_to_user_group`（市场审批的产物），桌面端读 `assistant_binding` 的 `code`/`scope` 决定用哪个 Xpert，模板安装的产物就是 `xpert` 行，环境变量经 `EnvStateQuery` 进入运行时上下文。

**何时必须找本子专家：**

- 要从模板装配一个 Assistant，或把现有 Assistant 导出成模板落盘。
- 需要市场列表 / 申请访问 / 审批驳回，或判断「某用户现在能不能跑这个助手」。
- 需要读写系统槽位绑定（`code` ∈ `chat_common` / `xpert_shared` / `clawxpert`，`scope` ∈ `tenant` / `organization` / `user`）或用户偏好。
- 需要排查 Bosi 桌面首次引导（`/api/assistant-binding/bosi/*`）的进度、恢复态与并发冲突。
- 需要 CRUD 环境变量集、设置工作区默认集，或把 env 合进运行时上下文。

**何时不要找本子专家：**

- Assistant 本体定义 / 草稿 / 发布 / DSL 导入导出 → 「助手定义与发布子专家」。
- 运行时准入本体（`PublishedXpertAccessService`）→ 「运行时API与准入子专家」；本域只在写入时用它做"可选性"过滤。
- 工作区本体与 Assistant 文件授权 → 「工作区与文件授权子专家」。

## 3 边界

**做**：模板目录/详情/装配/安装/导出落盘、技能资产同步、市场发现与申请审批、授权落地到 UserGroup、系统槽位与用户偏好、Bosi 桌面引导、环境变量集 CRUD 与默认集。

**不做**：不创建 Assistant 本体（在 `PluginTemplateInstallHandler` → `XpertImportCommand`）、不创建**工作区本体**（`workspaceId` 是入参）、不判定运行/文件权限、不持有模板内容（内容在文件系统）、不做变量注入（合并函数由调用方执行）。

**唯一的准入复用**：绑定面只经 `PublishedXpertAccessService` 做可选性过滤，其余靠 `type === Agent && latest === true && publishAt IS NOT NULL`；市场面的审批权复用 `XpertWorkspaceAccessService.getCapabilities`。

## 4 已知坑

1. **市场授权落地为 UserGroup 成员关系**。`approveRequest` → `ensureAccessGroup` 建/复用（`managedBy = XPERT_MARKETPLACE`、`managedEntityType = XPERT`、`managedEntityId = xpert.id`）的组，把申请人加进 `group.members`，再把组挂进 `xpert.userGroups`，最后回写 `request.accessGroupId`。因此**删组 / 改名 / 手工移除成员会直接改已审批访问**，而 `request.status` 仍是 `approved`。
2. **`AssistantBinding` 三个 partial unique 与 organization 优先回落**。索引谓词 `"scope" = 'tenant'` / `'organization'` / `'user'` 是字符串 SQL，必须与列名逐字符匹配；`getEffectiveBinding` 先查 organization，命中立即返回，否则回落 tenant，都无则 `NONE` + `enabled: false`。
3. **模板安装副作用面大，但"不建工作区"**。一次安装同时写：`xpert` 行、（可选）发布态、该工作区的默认 prompt workflow、技能 / MCP / toolset 组件落盘。失败时仅 `rollbackTemplateXpert` 删 Assistant，**不回滚**已建 prompt workflow；且 `initializeByTemplateId` 失败只 `logger.warn` 返回 `{ status: 'failed' }`，调用方不检查该返回值。**注意口径**：`workspaceId` 是入参、工作区必须已存在且当前用户可创作，安装**不**创建工作区本体。
4. **`desktopBootstrap` 是 `@Exclude` 的服务端恢复态**。实体上标 `@Exclude({ toPlainOnly: true })`，HTTP 出口只经 `BosiBootstrapService.publicProgress()` 暴露 `phase` / `capabilities` / `modelId` / `threadId`；`desktopOnboarding` 未排除但只存 `workspaceId` / `packages` / `connectorIds` / `revision`。
5. **`onModuleInit` 启动回填旧 `assistant_config` 是多实例竞争**。`AssistantBindingService implements OnModuleInit` → `backfillLegacyBindings()` → `backfillLegacySystemBindings()`（先 `tableExists('assistant_config')`）+ `backfillLegacyUserBindings()`，逐行 `findBinding` 先查后写。仓库内**没有**为这段回填加 advisory lock（advisory lock 只在 `BosiBootstrapService`），多 API 实例同时启动只能靠 partial unique 兜底。
6. **环境变量是数据而非进程环境变量**。`Environment.variables` 是 json 行数据，`EnvStateQuery → EnvStateHandler → toEnvState` 只把它摊成 `{ env: { name: value } }`，再经 `mergeRuntimeContextWithEnv` 在请求态合并（请求上下文 env 覆盖环境值）。它**不会**设进 `process.env`，也不影响容器运行时。
7. **`xpert_template.key` 无唯一索引且内容不在库**。去重靠 `findOneOrFailByWhereOptions` 先查后建；`getMCPTemplate` / `getKnowledgePipeline` 并发可写出两行同 `key`，之后计数与 `lastVisitedAt` 会分裂。模板 `export_data`、分类、推荐位全部来自 externalRoot 的 json/yaml。
8. **`accessGroupId` 与 `status` 生命周期不等长**。`accessGroupId` 外键是 `SET NULL`：UserGroup 被删后 `status = 'approved'` 仍成立，但 `hasRuntimeAccess` 已为 false——"已批准"不再是"可运行"的充分条件。
9. **写入侧的强校验容易被绕过**。`upsertBinding` 的 user 分支要求 `xpert.type === Agent && xpert.latest === true`，system 分支用 `buildSystemXpertWhere` 施加 `publishAt IS NOT NULL` + 组织维度双分支；`assistantId` **无外键**，直写仓储可以造出指向已删除助手的绑定，而删除助手不会级联清理。
10. **`environment.isDefault` 无 DB 约束**。工作区内唯一默认靠 `setAsDefault` 的"先关其它再置真"两步写；并发或直写 DB 会产生多个默认值，而 `getDefaultByWorkspace` 只取 `items[0]`，结果随查询顺序漂移。

## 5 症状定位表

| 症状 | 先看 | 常见根因 |
|---|---|---|
| 已审批但运行时不可用 | `hasRuntimeAccess` + `xpert.userGroups` | UserGroup 被删 / 改名 / 成员被手工移除；`approved` ≠ 可运行 |
| 桌面端拿不到槽位 | `getEffectiveBinding` | organization 行不存在且 tenant 行也缺，返回 `NONE` + `enabled: false` |
| 绑定写入 403 | `AssistantBindingService.ensureSystemWriteAccess` / `ensureUserManagedCode` | `code` 的管理归属不符（`clawxpert` 为用户管理，其余为系统管理） |
| 同上助手绑定写入报唯一冲突 | 三条 partial unique | 同一 `(tenantId[, organizationId[, userId]], code)` 在**同 scope** 下已存在 |
| Bosi 引导报 `BosiCreating` | `BosiBootstrapService.locked` | `pg_try_advisory_lock` 抢锁失败，同 tenant/org/user 已有安装在进行 |
| 模板安装成功但助手点不亮 | 安装链的 `publish` 参数 / 模型授权 | `publish` 非显式 `=== true` 则不发布；`prepareInstallation` 模型授权不足抛 `TemplateCapabilityUnavailable` |
| 装完工作区缺默认流水线 | `initializeByTemplateId` 返回值 | 失败被吞成 `{ status: 'failed' }`，且不回滚已建 Assistant |
| 环境变量没生效 | `EnvStateQuery` / 合并函数 | 变量集不是工作区默认集，或调用方未执行 `mergeRuntimeContextWithEnv` |
| 市场里看不见某个助手 | `TENANT_SHARED_WORKSPACE_FILTER` | `settings.access.visibility` 非 `tenant-shared` 且 `organizationId` 与请求组织不匹配 |

## 6 一分钟自查

- 这次改的是**声明式数据**，还是创作草稿 / 发布态 / 文件 ACL？后者不属于本子域。
- 授权状态落在**实体**上吗？市场授权落在 `UserGroup` 上，改组即改权。
- 这次写入的**唯一性**由谁保证？大部分靠服务层先查后写，DB 只有 partial unique 兜底。
- 这次初始化是**幂等命令**还是 seed？本子域无 seed，全部是运行时 `ensure*` / `onModuleInit` 行为。
