## 6 需 DB / 外部依赖的用例

- **真实 Postgres / Redis / 消息队列 / 模型供应商：该模块无此项**。26 个 spec 均不打开数据库连接。
- 假 `DataSource`（**不连库**）：`assistant-binding.service.spec.ts` 直接 `new AssistantBindingService(repo, prefRepo, xpertRepo, dataSource, published)`，其中 `dataSource = { query: jest.fn(async () => [{ name: null }]) }`——`tableExists` 因此恒为 false，`backfillLegacyBindings` 走「旧表不存在」的提前返回分支；`tableHasColumns` 的 `information_schema` 路径与该分支的真实 SQL 语义未被验证。
- 文件系统（临时目录）：`xpert-template/*` 经 `testing/template-test-harness.ts` 用 `mkdtempSync(tmpdir())` 造 `serverRoot`/`dataPath`，并 `jest.mock` 掉 `@xpert-ai/server-core`（`TenantAwareCrudService` 桩）、`@xpert-ai/server-config`、`SkillRepositoryService`、`SkillRepositoryIndexService`；`afterEach(cleanupTemplateFixtures)` 负责 `rmSync` 与 `jest.restoreAllMocks()`。
- 日志噪声：`template-assets.spec.ts` 用 `jest.spyOn(Logger.prototype, 'warn')` 静默并可断言警告路径。
- 无需外部依赖但需 mock 的请求上下文：`assistant-binding.service.spec.ts` 对 `RequestContext.currentTenantId/currentApiPrincipal/getOrganizationId/currentUserId/hasRole/hasRoles/requireOrganizationScope` 全部打桩。

## 7 缺口

- **模板安装链无本子域覆盖**：`PluginTemplateInstallHandler` 的 spec 位于域外 `plugin-resource/commands/install-template.handler.spec.ts`（用 `jest.mock` 替换 `XpertTemplateWorkspaceInitializer`）；本子域 17 个 spec 里没有一个真正跑「`POST :id/install` → 建 Assistant → 工作区初始化」的链。
- **controller 层几乎无覆盖**：`XpertTemplateController`（`parseTemplateInstallInput` 等 5 个解析函数）、`AssistantBindingController`、`EnvironmentController` 均无 spec；只有 `xpert-marketplace.controller.spec.ts` 与 `bosi-bootstrap.controller.spec.ts` 覆盖到 controller 解析层。
- **`environment` 覆盖最薄**：仅 `utils.spec.ts`；`EnvironmentService.setAsDefault` 的「先关其它再置真」互斥、`getDefaultByWorkspace` 的 `isArchived: false` / `IsNull()` 双分支、`EnvStateQuery` → `EnvStateHandler`、`EnvironmentPublicDTO` 抹除 `value` 的行为都没有断言。
- **无 spec 的源文件（抽样）**：`xpert-template/plugin-template-descriptor.ts`、`xpert-template/capabilities/realtime-voice.capability.ts` 与 `realtime-voice.schema.ts`（仅经 `assistant-capability.service.spec.ts` 的 voice 段间接覆盖）、`assistant-binding/bosi/bosi-bootstrap.schema.ts` 与 `bosi-onboarding.schema.ts`（仅经 controller spec 间接覆盖）、`environment/queries/env-state.query.ts`。
- **`xpert_template` 并发写未覆盖**：`getMCPTemplate`/`getKnowledgePipeline` 的「先查后建」在无唯一索引下可能写出同 `key` 两行，现有 spec 未构造该竞态。
- **端到端缺口**：无 HTTP 级 e2e——`XpertTemplateController` 的 400 分支（`workspaceId is required`、`XpertWorkspaceDataScopeInvalid`）、`XpertMarketplace*` 的 403/404 i18n key、`BosiInvalidInput` 的真实响应体都未被端到端验证。

## 8 结论
