## §1 HTTP 端点

### 1.1 `/api/xpert-template/*`

| 方法 | 路径（相对前缀） | 鉴权 | 用途 / 关键行为 |
|---|---|---|---|
| GET | `/`（`?targetApp&templateType`）、`catalog`（`?search&category&pluginName&offset&limit`，limit 默认 48） | 仅登录态 | 模板目录；`catalog` 会追加市场推荐位 |
| GET | `mcps`、`mcps/:key`、`pipelines`、`pipelines/:id`、`skills-market` | 仅登录态 | MCP 模板、知识流水线、技能市场 |
| GET | `/:id`（`?targetApp&templateType&locale`）、`/:id/setup`（`?capabilities`） | 仅登录态 | 模板详情（本地化）与能力装配 setup |
| POST | `/:id/install` | 仅登录态 | 安装模板；缺 `workspaceId` 抛 400，`workspaceDataScope` 非 `shared\|user` 抛 `XpertWorkspaceDataScopeInvalid` |
| POST | `sync-skill-assets`（body `{ mode, validateOnly }`） | 仅登录态 | 技能资产同步，支持仅校验模式 |
| — | 另：`POST｜DELETE /api/xpert/:id/export/template` | `XpertGuard` | 导出模板落盘的真实触发点（`saveExportedXpertTemplate` / `deleteExportedXpertTemplate`），失败统一包 500 |

## §2 服务契约

### 2.1 `XpertTemplateService`

| 方法 | 输入 | 输出 / 语义 |
|---|---|---|
| `getCatalog(input, language)` | `search/category/pluginName/offset/limit` + 语言 | 目录分页 + 推荐位；内容来自 externalRoot 文件 |
| `getTemplateDetail(id, language, variant?)` | 模板 id + 语言 | 详情并串联 `AssistantCapabilityService.compose`（安装前重查模型授权） |
| `saveExportedXpertTemplate(templateId, filePath, dto)` | 导出结果 | 写盘 + `upsertExportedXpertTemplateCatalog` + 回写 `xpert.exportedTemplate`；路径经 `resolveExternalRelativePath` 防越界 |
| `deleteExportedXpertTemplate(templateId)` | 模板 id | 删文件 + `removeExportedXpertTemplateCatalog` |
| `getTemplateSkillBundles` / `getBootstrapDefaultSkillRefs` / `getUserDefaultSkillRefs` | 语言 / 配置 | 技能 bundle 与默认技能引用（供安装与引导） |
| `onApplicationBootstrap` | — | 启动时执行 `EnsureTemplateDirectoryCommand`（补种文件系统，非 DB 写入） |

### 2.2 `XpertTemplateWorkspaceInitializer`（安装语义）

| 方法 | 签名 | 语义 |
|---|---|---|
| `initializeByTemplateId(templateId, workspaceId, language, xpertId?)` | 四个入参 | 取模板详情后调 `promptWorkflowService.initializeDefaultsInWorkspace(workspaceId, template.promptWorkflows, xpertId, template.id)`；成功返回 `{ status: 'initialized', created }`，失败只 `logger.warn` 并返回 `{ status: 'failed' }`。**不创建 Assistant、不创建工作区** |

完整安装链（`PluginTemplateInstallHandler.execute`）顺序：`workspaceAccess.assertCanAuthor(workspaceId)` → `getTemplateDetail` → `yaml.parse(export_data)` → `normalizeDraft` → `capabilities.prepareInstallation` → `XpertImportCommand` → `installer.installComponentsForXpert` → 可选 `XpertPublishCommand` → `initializeByTemplateId`。Bosi 走的 `bootstrap` 参数（`resumeXpertId` / `onImported`）**绝不接受来自 HTTP body**。

### 2.3 `XpertMarketplaceService`

| 方法 | 语义 |
|---|---|
| `findMarketplace(query)` / `getMarketplaceItem(id)` | 发现列表与详情；内部 `findDiscoverableXperts` 用 `TENANT_SHARED_WORKSPACE_FILTER` + 组织分支限定范围 |
| `requestAccess(xpertId, reason?)` | 按 `(tenantId, organizationId, xpertId, requesterId)` 查既有行：`requested｜approved` 原样返回，其余原地复合并清空 `response/reviewerId/reviewedAt/accessGroupId` |
| `approveRequest(requestId, response?)` | `assertCanReviewRequest` → `ensureAccessGroup` 建/复用 UserGroup → 加成员 → 挂 `xpert.userGroups` → 回写 `accessGroupId` 与 `reviewedAt` |
| `rejectRequest(requestId, response?)` | 只写 `reviewerId` / `response` / `reviewedAt`，**不写 `accessGroupId`** |
| `ensureAccessGroup(xpert, tenantId, organizationId, members)` | 私有；`managedBy = XPERT_MARKETPLACE`、`managedEntityType = XPERT`、`managedEntityId = xpert.id`；改名 / 删组会外溢到已审批访问 |
| `hasRuntimeAccess(userId, xpert, tenantId, organizationId)` | 读 `xpert.userGroups[].members` 或 `xpert.workspace.members`；不查文件与创作能力 |
| `canReviewXpert(xpert, user)` / `findReviewableRequests` / `findMyRequests` | 审批权复用 `XpertWorkspaceAccessService.getCapabilities` |

### 2.4 `AssistantBindingService`

| 方法 | 语义 |
|---|---|
| `getEffectiveBinding(code, tenantId, organizationId)` | organization 命中立即返回（`sourceScope: ORGANIZATION`），否则回落 tenant；都无则 `sourceScope: NONE` + `enabled: false` |
| `upsertBinding(scope, code, assistantId, enabled)` | user 分支要求 `xpert.type === Agent && xpert.latest === true`；system 分支用 `buildSystemXpertWhere` 施加 `publishAt IS NOT NULL` + 组织维度双分支；写前须过 `ensureSystemWriteAccess` / `ensureUserManagedCode` |
| `getBindingPreference(code, scope, tenantId, organizationId, userId)` / `upsertBindingPreference(...)` | 偏好按 `(tenantId, organizationId, assistantBindingId, userId)` 唯一；`conversationPreferences` 归一后固定写 `version: 2` |
| `isEffectiveSystemAssistantId(assistantId, tenantId, organizationId)` | 判定某助手是否即当前有效的系统槽位助手 |
| `onModuleInit` → `backfillLegacyBindings` | 启动回填旧 `assistant_config`（先 `tableExists` 探测）；逐行先查后写，靠 partial unique 兜底 |

### 2.5 `EnvironmentService`

| 方法 | 语义 |
|---|---|
| CRUD（继承 `XpertWorkspaceBaseService<Environment>`） | 读写受工作区授权前置检查；`Environment.module` 只注册本表 |
| `setAsDefault(id)` | "先关其它再置真"两步写；工作区内唯一默认**无 DB 约束** |
| `getDefaultByWorkspace(workspaceId)` | 取 `isDefault` 或 `isArchived IS NULL` 的集合，只取首条 |
| `EnvStateQuery(workspaceId)` → `EnvStateHandler` → `toEnvState` | 摊成 `{ env: { name: value } }`；合并由调用方用 `mergeRuntimeContextWithEnv` 完成 |

## §3 最小示例

### 3.1 用模板装配新 Assistant

```ts
await commandBus.execute(new PluginTemplateInstallCommand(templateId, { workspaceId, publish: true, workspaceDataScope: 'shared' }))
// 前置：workspaceId 必须已存在且当前用户 assertCanAuthor 通过；安装不创建工作区
// 失败只回滚 Assistant（rollbackTemplateXpert），已建 prompt workflow 不回滚
```

### 3.2 市场申请 → 审批 → 取运行时访问

```ts
await marketplaceService.requestAccess(xpertId, reason)                 // 落 xpert_access_request，status='requested'
await marketplaceService.approveRequest(requestId, response)            // 建/复用 UserGroup + 加成员 + 回写 accessGroupId
const ok = await marketplaceService.hasRuntimeAccess(userId, xpert, tenantId, organizationId)
// ok 为真只代表"可跑"；创作面与文件面各自独立判定
```

### 3.3 配一个系统槽位绑定

```ts
await bindingService.upsertBinding(AssistantBindingScope.ORGANIZATION, AssistantCode.CHAT_COMMON, assistantId, true)
const effective = await bindingService.getEffectiveBinding(AssistantCode.CHAT_COMMON, tenantId, organizationId)
// effective.sourceScope === 'ORGANIZATION'；组织行缺失时回落 tenant，都没有则 { sourceScope: 'NONE', enabled: false }
// 用户偏好需另走 upsertBindingPreference，两者是不同表
```

```ts
const env = await environmentService.setAsDefault(envId)               // 工作区默认集
const state = await queryBus.execute(new EnvStateQuery(workspaceId))   // { env: { NAME: value } }
const runtime = mergeRuntimeContextWithEnv(context, await environmentService.getDefaultByWorkspace(workspaceId))
```
