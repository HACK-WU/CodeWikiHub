## §1 HTTP 端点

所有路径均为完整路径（全局前缀 `api` + 模块 RouterModule 前缀）。

### 1.1 `/api/xpert-workspace/*`（工作区创作容器面）

| 方法 | 路径（相对前缀） | 鉴权 | 用途 / 关键行为 |
|---|---|---|---|
| GET | `/`、`my?purpose`、`count`、`pagination`、`my/default` | 仅登录态 | 成员感知列表 / 计数 / 分页 / 我的默认工作区；出参 `WorkspacePublicDTO` |
| POST | `/` | 仅登录态 | 创建工作区，201；`ownerId` 强制取 `RequestContext.currentUserId()` |
| POST | `/:workspaceId/default` | 仅登录态 | 设为我的默认工作区 |
| GET | `/:workspaceId`、`/:workspaceId/members` | `WorkspaceAuthoringGuard` | 详情与成员（`UserPublicDTO`）；先 UUID 校验（`WorkspaceIdInvalid`），再 `assertCanAuthor` = `assertCanWrite` |
| PUT / DELETE | `/:workspaceId`、`/:workspaceId/members`、`/:workspaceId/visibility`、`/:workspaceId/soft`(DELETE) | `WorkspaceOwnerGuard` | 更新、成员整体覆盖、可见性、软删；动作 `assertCanManage` |
| POST / PUT | `/:workspaceId/archive`(POST)、`/:workspaceId/recover`(PUT)、`/:workspaceId`(DELETE 硬删) | `WorkspaceOwnerGuard` | 归档 / 恢复 / 硬删 |

`purpose` 语义：集合端点只接受 `authoring`，其余值一律回落 `runtime`（`isAuthoringPurpose`）；`authoring` 目的会**排除**仅靠用户组获得运行时访问的工作区。

### 1.2 `/api/xpert/:id/workspace/*`（Studio 创作文件面）

| 方法 | 路径 | 鉴权 | 用途 / 关键行为 |
|---|---|---|---|
| GET | `:id/workspace/files`、`:id/workspace/file`、`:id/workspace/file/download` | `XpertGuard` | 列目录 / 读 / 下载；全部走 `forAuthoring` 权威 |
| PUT / POST | `:id/workspace/file`(PUT)、`:id/workspace/file/save-binary`、`:id/workspace/file/upload`、`:id/workspace/files/upload`(POST) | `XpertGuard` | 保存 / 二进制写入 / 上传入目录 / 上传；上传上限 10MB，缺文件抛 `WorkspaceFileUploadRequired` |
| DELETE | `:id/workspace/file` | `XpertGuard` | 删除单文件 |

### 1.3 `/api/ai/assistants/:assistantId/workspace/*`（运行时文件面）

| 方法 | 路径 | 鉴权 | 用途 / 关键行为 |
|---|---|---|---|
| GET | `capabilities`、`files`、`file`、`file/download` | `@Public()` + `ApiKeyOrClientSecretAuthGuard` + `AssistantFileAccessGuard`（类级 `@AssistantFileAccess('workspace')`） | 能力查询 / 列目录 / 读 / 下载；**始终**走 `AssistantFilesService.forRuntime(assistantId)` |
| PUT / POST / DELETE | `file`(PUT/DELETE)、`file/upload`、`file/save-binary`(POST) | 同上 | 写 / 删 / 上传 / 二进制写入；查询经 Zod 校验，非法请求 `WorkspaceFileInvalidRequest` |

### 1.4 `/api/ai/conversations/:conversationId/workspace/*`（Workbench 运行目录）

| 方法 | 路径 | 鉴权 | 用途 / 关键行为 |
|---|---|---|---|
| GET / PUT / DELETE | `workspace/files`、`workspace/file`（保留不冲突的旧 `file` 单文件别名） | `@Public()` + `WorkbenchFilesAuthGuard` | 运行目录读写删；`/files` 归 FileAsset 附件，目录归 `workspace/*` |
| POST | `workspace/file/upload`（及旧 `file/upload`）、`workspace/files/upload` | 同上 | 上传（100MB 档）；守卫先加载持久化对话再放行，异助手对话抛 `ForbiddenException` |

### 1.5 `/api/ai/workspace-files/view-sessions`（查看会话与票据）

| 方法 | 路径 | 鉴权 | 用途 / 关键行为 |
|---|---|---|---|
| POST | `view-sessions` | `@Public()` + `EnterpriseChatkit` 绑定 + `AssistantFileAccessGuard`（`'view-session-create'`） | 创建查看会话（cookie） |
| POST | `view-sessions/:sessionId/grants` | 同上 | 签发票据；响应只含 pathname |
| GET / HEAD | `view-sessions/:sessionId/grants/:grantId/content/:fileName` | 同上（`'view-session'`） | 内容下载与 HEAD 探测；有效期 / 撤销在流式返回前复查 |
| DELETE | `view-sessions/:sessionId` | 同上 | 撤销会话并清 cookie |
| — | 过期 / 已撤销会话、project scope 变更 | — | 均拒绝；即使 ChatKit 凭证有效也不放行 |

## §2 服务契约

### 2.1 `XpertWorkspaceAccessService`（能力唯一权威）

| 方法 | 输入 | 输出 / 语义 |
|---|---|---|
| `getAccess(workspace, tenantId, relations?)` | 工作区 + 租户 | `{ workspace, capabilities, isTenantShared }`，供写路径注入能力面 |
| `getCapabilities(workspace, user, tenantId)` | 工作区 + 用户 + 租户 | 四能力位；`archived` 直接判无权限；组织作用域默认含 tenant-shared，`authoring` 目的排除 |
| `getResourceCapabilities(ids, tenantId, user)` | 批量 id | 列表用能力投影，可选 `includePublishedRunAccess` |
| `can(workspace, action, user, tenantId)` / `assertCan(...)` | 四动作之一 | 失败抛 `ForbiddenException('Access denied to workspace')` |
| `assertCanRead` / `assertCanRun` / `assertCanWrite` / `assertCanManage` / `assertCanAuthor` | 同上 | 三档守卫的实际动作；`assertCanAuthor` = `assertCanWrite` |
| `hasPublishedXpertRunAccess(userId, workspaceId)` | 用户 + 工作区 | 原生 SQL 读 `xpert_to_user_group`；UserGroup 走这里时**只补 `canRun`** |
| `applyCurrentReadScope(qb, options)` / `applyMemberReadCondition(qb, ...)` | TypeORM QueryBuilder | 把点读判定镜像进列表 SQL，供 `XpertWorkspaceBaseService` 复用 |

### 2.2 `XpertWorkspaceService`（写路径与成员）

| 方法 | 语义 |
|---|---|
| `createWorkspace(input)` | 只接受 `name/description/status/settings.access.visibility`；`ownerId` 取当前用户；成员须同租户（组织工作区须同组织 `isActive`） |
| `updateWorkspace(id, input)` / `updateVisibility(id, visibility)` | 走 `applyVisibility`：非法值抛 `BadRequestException`；`tenant-shared` 要求 `organizationId` 空，`organization-shared` 要求非空 |
| `updateMembers(id, memberIds)` / `ensureMember(workspace, userId)` / `removeMemberFromOrganizationWorkspaces(...)` | 整体覆盖 / 幂等追加 / 批量移除（排除 `user-default`） |
| `softRemoveWorkspace` / `recoverWorkspace` / `archiveWorkspace` / `deleteWorkspace` | 软删 / 恢复 / 置 `archived` / 硬删 |
| `findAllMy` / `findAllMyEntities` / `findMyDefault` / `setMyDefault` | 成员感知列表（`purpose` 透传）/ 默认工作区链路：显式默认 → 回落 `findUserDefaultWorkspace`（`system.kind='user-default'`） |
| `findUserDefaultWorkspace` / `findOrganizationDefaultWorkspace` / `canAccess(id, userId)` | `canAccess` 返回布尔且允许匿名，**禁止**用作文件 ACL（仅 `XpertGuard` 等创作侧使用） |

配套：`XpertWorkspaceBaseService<T>` 把 read / write / authoring 检查织入 `findOne/create/save/update/delete/softDelete`，并区分 `findOne` 与 **`findOneForRuntime`**（按 run 而非 read 授权）；`EnsurePersonalDefaultWorkspaceCommand` → handler 幂等建个人默认工作区。

### 2.3 `AssistantFilesService`（双入口 + 动作族）

- `forRuntime(assistantId)`：绑定 runtime 权威（只认 `PublishedXpertAccessService.getAccessiblePublishedXpertForCurrentUser`）。
- `forAuthoring(assistantId)`：绑定 authoring 权威（`XpertService.assertCanAuthorById` + `findOneByIdWithinTenant`）；`XpertWorkspaceFilesService`（Studio façade）全部走它。
- 两者返回同一形状动作族：`capabilities` / `list(path, deepth)` / `read` / `download` / `save` / `saveBinary` / `uploadToFolder` / `delete` / `upload`；内部 `bind()` 每次操作重新派发命令，并在取好卷后 `resolveXpertDataVolumeScope` → `VOLUME_CLIENT.resolve(scope).ensureRoot()`。

### 2.4 `ResolveAssistantFileAccessCommand`（授权输入语义）

```ts
type AssistantFileOperation = 'read' | 'write' | 'delete' | 'capabilities'
type AssistantFileEntry = 'runtime' | 'authoring'
type AssistantFileCapabilities = { canList: boolean; canRead: boolean; canWrite: boolean; canDelete: boolean }
type AssistantFileAccess = { scope: XpertDataVolumeScope; capabilities: AssistantFileCapabilities }
new ResolveAssistantFileAccessCommand(assistantId, operation, entry) // entry 由服务端代码选定，绝不来自请求数据
```

## §3 最小示例

### 3.1 建工作区并加成员

```ts
const ws = await workspaceService.createWorkspace({ name, settings: { access: { visibility: 'private' } } })
await workspaceService.updateMembers(ws.id, [memberUserId]) // 整体覆盖；成员须同租户
const caps = await accessService.getCapabilities(ws, RequestContext.currentUser(), RequestContext.getTenantId())
// owner/member => { canRead: true, canRun: true, canWrite: true, canManage: true }
```

### 3.2 运行时读一个 Assistant 文件

```ts
const files = filesService.forRuntime(assistantId) // 入口在服务端选定，绝不来自 HTTP
const caps = await files.capabilities()            // 每次操作重新授权
if (!caps.canRead) throw new ForbiddenException()
const content = await files.read(path)              // 卷作用域由 resolveXpertDataVolumeScope 决定
```

### 3.3 创作态保存文件

```ts
const studio = filesService.forAuthoring(assistantId) // 保留显式创作检查（含草稿）
await studio.save(path, content)
// 运行时被拒时不得回退到本入口；HTTP 也不得传入 entry
```
