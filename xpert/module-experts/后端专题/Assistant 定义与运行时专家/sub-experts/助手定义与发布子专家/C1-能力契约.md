## 1 HTTP 端点（真实前缀 `/api/xpert`）

## 2 服务契约

| 符号 | 语义与前置 | 关键副作用 |
|---|---|---|
| `XpertService.create(entity, ...options)` | 先 `validateTagAssociations`；补默认 `workspaceDataScope` 与 `normalizeXpertAgentConfig` | 走 `XpertWorkspaceBaseService.create`，由 `XpertCreateHandler` 落地 |
| `XpertService.update(id, entity)` / `updateXpert(id, entity)` | **浅层**：`findOne` → 拦截 `workspaceDataScope` 变更 → `assign` → `validateTagAssociations` → `save` | 不处理递归关系；变更 scope 抛 `XpertWorkspaceDataScopeImmutable` |
| `XpertService.saveDraft(id, draft)` | 全量写 `draft` 列；并入 `team.options.templateSource`、回写 `workspaceDataScope/updatedAt/updatedById`、`normalizeMiddlewareNodes` | 把 `validate()` 的 `ChecklistItem[]` 挂到 `draft.checklist` |
| `XpertService.updateDraft(id, draft)` | team 浅合并；仅当 body 含 `nodes`/`connections` 才覆盖图字段；校验用 `nextDraft.nodes ?? xpert.graph.nodes` 兜底 | 只改 team 的补丁不会把已发布图实体化进草稿 |
| `XpertService.publish(id, newVersion, environmentId, notes, marketplace, businessAreaId?)` | 命令化：`XpertPublishCommand` → `XpertPublishHandler.execute()` | 备份旧版本、对账 agent、`graph = pick(draft,'nodes','connections')`、`draft = null`、`publishAt`、`active`、principal、触发器、`EventName_XpertPublished` |
| `XpertService.allVersions(id)` | 以 `workspaceId + type + slug` 取同族 | 只读投影，不改数据 |
| `XpertService.setAsLatest(id)` | 已是 `latest` 则空操作 | 族内 `latest = true` 全部置 false 后置当前行，一次 `save([...])`；**不改 `graph`/`draft`** |
| `XpertService.deleteXpert(id)` | 行 `latest === true` 时按 `name` 族软删 | 否则只软删当前行 |
| `XpertService.validateName(name)` | `convertToUrlPath(name)` 生成 slug，长度 < 5 直接 false | 以 `slug + latest: true` 计数判重，返回布尔 |
| `XpertService.assertCanAuthorById(id, resolvedWorkspaceId?)` | 创作写路径的统一闸门 | 委托 `XpertWorkspaceAccessService.assertCanAuthor` |
| `XpertService.createVersionBackup(entity, sourceId)` | 以 `sourceId` 为源身份做 `assertValidTagAssociations` | 版本备份继承源的已持久化关联（含已停用 tags） |
| `XpertService.validate(draft, context)` | `FreeNodeValidator` + `emitAsync(EventNameXpertValidate, ...)` | 返回 `ChecklistItem[]`（不抛错） |
| **`duplicate`（无 service 方法）** | 由 `XpertController.duplicate` 组合 `XpertExportCommand` → `instanceToPlain` → `XpertImportCommand` | 复制口径为「保真」（不经 `importManaged` 的模型归一） |

命令层入口（`commands/`）：`XpertPublishCommand`、`XpertImportCommand`（含 `normalizeCopilotModels`、`targetXpertId`、`templateSource`）、`XpertExportCommand`、`XpertExportTemplateCommand`、`XpertDeleteExportedTemplateCommand`、`XpertSyncTemplateCommand`、`XpertPublishTriggersCommand`（`{ strict: true, previousGraph }`，失败反向重放）、`XpertCreateCommand`、`XpertDeleteCommand`。

## 3 示例

### 3.1 草稿 → 发布 → 版本回滚

```bash
# 1) 全量保存草稿（只写 draft 列，不影响运行时）
curl -X POST "$HOST/api/xpert/$ID/draft" -H "authorization: Bearer $TOKEN" \
     -H 'content-type: application/json' -d @draft.json

# 2) 发新版本（发布同时把 draft 提升为 graph 并清空 draft）
curl -X POST "$HOST/api/xpert/$ID/publish" -H "authorization: Bearer $TOKEN" \
     -H 'content-type: application/json' -d '{"version":"1.0.1","notes":"fix starters"}'

# 3) 查看版本族（同 workspaceId + type + slug）
curl "$HOST/api/xpert/$ID/version" -H "authorization: Bearer $TOKEN"

# 4) 把指针切到目标版本（只改 latest，不改 graph/draft）
curl -X POST "$HOST/api/xpert/$OLD_VERSION_ID/latest" -H "authorization: Bearer $TOKEN"
```

失败面：步骤 2 若报 `404` 说明该行没有 `draft`；若报 `400 ... userGroups` 说明非创建者且未分配用户组；若报 `500` 说明图里有游离节点或重名节点。步骤 2 中途失败时**已写入的版本备份行与 agent 不会回滚**。

### 3.2 导入 DSL（保真 / 托管）与复制

```bash
# 保真导入：DSL 里的 copilotModel 原样落库
curl -X POST "$HOST/api/xpert/import?workspaceDataScope=shared" -H "authorization: Bearer $TOKEN" \
     -H 'content-type: application/json' -d @dsl.json

# 托管导入：把不可用 copilotModel 换成当前组织可用模型 / 主模型
curl -X POST "$HOST/api/xpert/import/managed" -H "authorization: Bearer $TOKEN" \
     -H 'content-type: application/json' -d @dsl.json

# 复制既有助手
curl -X POST "$HOST/api/xpert/$ID/duplicate" -H "authorization: Bearer $TOKEN" \
     -H 'content-type: application/json' -d '{"basic":{"name":"copy of x"},"isDraft":false}'
```

要点：`workspaceDataScope` 只接受 `shared` / `user`（其他值 400），且**不从 DSL 读取**；`targetXpertId` 有值的导入走「覆盖草稿」分支（覆盖受保护字段被剥离，**不动已发布版本**）；`importAsNewXpert` 侧对同名有短路放行（`nextSlug === currentXpert.slug`）。
