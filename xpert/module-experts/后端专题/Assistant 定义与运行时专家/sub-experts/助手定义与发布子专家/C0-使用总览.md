# 助手定义与发布子专家 —— C0 使用总览

> 契约层第 0 篇（子专家①）。回答四件事：管什么、何时找它、能力清单、不能找它做什么，外加必须先知道的坑。
> 引用写 `file://` 相对仓库根，不写行号；无据可查处写「无此项」，不做推断。

## 1 定位

本子专家负责 **Assistant 的创作侧**：把 `xpert` 表里一行「空壳」推到「可运行版本」，推出后仍能改草稿、换版本、导入导出、改配置与外观。它管「怎么定义与发布」，**不管「发布后谁能调用」**。

- 落点包：`file://packages/server-ai/src/xpert/`（`xpert.controller.ts`、`xpert.service.ts`、`xpert.entity.ts`、`commands/`、`configuration/`、`assistant-appearance/`、`dto/`、`guards/`）。
- 单行状态机：同一 `xpert` 行同时是草稿容器（`draft` 列）、发布产物（`graph` 列）、版本索引（`version`/`latest`）与外部服务账号宿主（`userId`）。
- 校验双轨：`validate()` 返回 `ChecklistItem[]`（建议式，挂 `draft.checklist`，每次存草稿都跑），`check()` 抛错（阻断式，只在发布时跑）。

### 何时找它

| 场景 | 入口一句话 |
|---|---|
| 改定义 / 存草稿 | 编辑器每次改动打 `POST/PUT /api/xpert/:id/draft`，**只写 `draft` 列** |
| 发布 / 发新版本 | `POST /api/xpert/:id/publish`，`draft → graph` 单向提升并清空草稿 |
| 版本回滚 | `POST /api/xpert/:id/latest`，只切同族 `latest` 指针 |
| 迁移助手 | `GET :id/export`（YAML DSL）、`POST /import`、`/import/managed`、`POST :id/duplicate`、`POST :id/sync-template` |
| 改能力 / 外观 | `GET/POST /api/xpert/:id/configuration`、`GET/POST /api/xpert/:id/appearance` |
| 改触发声明 | `GET/POST /api/xpert/:id/trigger-settings`（编辑期） |

### 何时不要找它

- 运行时准入与 `/api/ai/*` 对外面 → 子专家②（`PublishedXpertAccessService` 虽在 `xpert/` 包内，职责属②）。
- 工作区实体与文件卷授权 → 子专家③。
- 模板目录装配、市场审批、系统槽位绑定 → 子专家④。
- Agent 编译与执行、会话本体、项目与任务调度 → 批次 4 / 专家 F。

## 3 边界

- **不管运行时准入**：谁能通过 HTTP 跑到已发布助手，由子专家②的 `PublishedXpertAccessService` 判定（`file://packages/server-ai/src/xpert/published-xpert-access.service.ts`）。
- **不管工作区与文件**：`xpert-workspace/`、`assistant-files/` 与 `XpertController` 内 `:id/workspace/*`、`:id/memory*` 的授权语义归子专家③；本子专家只声明这些路由与创作面同处一个控制器。
- **不管模板市场**：`xpert-template/`、`xpert-marketplace/`、`assistant-binding/` 归子专家④；本子专家只持有 `exportedTemplate` 字段的写回与 `:id/sync-template` 的调用面。
- **邻接不归属**：`:id/trigger-connections`（扫码 QR 的落库与回滚）是运行期写路径，因在同一事务内改写 `graph` 与 `draft`，故在 C1 一并列出，标注为「邻接」。
- `AssistantAppearanceService` 读 `PublishedXpertAccessService`，但写路径只走 `assertCanAuthor` + `pessimistic_write` 行锁，因此归创作侧。

## 4 已知坑（先看这 8 条）

1. **草稿与 `graph` 双列分叉**：`draft` 与 `graph` 是两个独立 json 列，官方同步路径只有 `publish`；同事务同时写两列的例外只有 `trigger-connection.change()` 与 `assistant-trigger.mutate()`，而 `hasConnectionDraftConflict` 只覆盖「触发节点」这一小块。任何旁路直写 json 列都会让两者分叉。
2. **`ensurePrincipalUser` 隐式建账号**：发布（`!xpert.userId` 时）、`POST :id/principal-user`、`:id/chat-api` / `:id/chat-app` 开关期都会创建 `thirdPartyId = xpert:<id>` 的通信用户；账号生命周期与 `app.enabled` 不绑定，**一旦创建不会随停用回收**。`updateChatApi` 先 `updateXpert` 再建账号，创建失败会留下「`api` 已落库但 `userId` 为空」的状态。
3. **`update` 是浅层入口**：`XpertService.update` 只转发 `updateXpert`，后者 `assign` + `super.save`；源码注释明写 `Isolate TypeORM's recursive update type; business callers use the shallow method to keep ts-node inference bounded`，即**不为递归关系（含 `OneToOne`）更新负责**，且没有类型层保护。
4. **`publish` 是多步无事务**：`saveTeamVersion`（备份版本行）与逐节点 `xpertAgentService.create/update/delete` 都发生在最终 `save` 之前，中途抛错**不回滚已创建的备份行与 agent**；只有触发器链有 `previousGraph` 反向重放。另外 `check()` 对游离节点/重名抛的是 `500` 而非 400。
5. **`:id/configuration` 的 64 位 revision 乐观锁**：`revision = sha256([xpert.updatedAt, draft, graph])`，格式必须是 `^[a-f0-9]{64}$`（DTO 层校验），不一致即 409 `AssistantConfigurationStale`；`save` 在 await 之后会重新 `load` 再比一次。注意该端点**会顺带执行一次 `publish(newVersion=true)`**，是唯一由配置页触发的发布入口（与 draft-only 取向相反）。
6. **`trigger-settings`（编辑期）与 `trigger-connections`（运行期）不是一回事**：前者是声明与校验（`list/validate/save`，revision = `sha256([graph, draft])`），后者是 QR 授权连接的落库与回滚；两者都能改同一批触发节点，靠 revision 与草稿冲突检测互相发现，**缺少统一领域服务**，命名也易检索错。
7. **`workspaceDataScope` 不可变**：列为 `@Column({ ..., update: false })`，`updateXpert` 内显式抛 `XpertWorkspaceDataScopeImmutable`；导入/复制的 scope **只由入口参数（查询串 / body）决定，不从 DSL 读**（DSL DTO 不导出该字段）。
8. **配置 / 外观 / 触发设置三个控制器没有类级守卫**：`assistant-configuration.controller.ts`、`assistant-appearance.controller.ts`、`assistant-trigger.controller.ts` 均无 `@UseGuards`，授权全在 service（`assertCanAuthor/assertCanRead` + 组织校验），HTTP 层没有兜底。另有一处口径不一致：`getMyAll/countMy` 用 `publishAt` 非空判「已发布」，`getAllByWorkspace` 用 `version` 非空判，两处定义不同。

## 5 与其它子专家的交接面

| 交接对象 | 本子专家交付 | 对方负责 |
|---|---|---|
| 子专家②（运行时准入） | `publishAt`/`latest`/`graph`/`app`/`channels` 这些「已发布且开放」的落库事实 | 受众判定、`/api/ai/*` 对外面、凭证签发 |
| 子专家③（工作区与文件） | 助手定义与 `:id/workspace/*` 路由归属声明 | 文件卷授权、工作区四动作能力 |
| 子专家④（模板市场与环境） | `exportedTemplate` 写回、`sync-template` 调用面 | 模板目录、市场审批、系统槽位与环境解析 |
