# 运行时API与准入子专家 —— C0 使用总览

> 契约层第 0 篇（子专家②）。回答四件事：管什么、何时找它、能力清单、不能找它做什么，外加必须先知道的坑。
> 引用写 `file://` 相对仓库根，不写行号；无据可查处写「无此项」。

## 1 定位

本子专家只负责「Assistant **已发布之后，谁能通过 HTTP 跑到它**」——即 **运行时对外面 + 多受众准入**。它不定义 Assistant，也不实现文件卷、工作区与模板。

- 落点：`file://packages/server-ai/src/ai/`（`ai.module.ts`、`assistant.controller.ts`、`ai.controller.ts`、`ai-v1.controller.ts`、`thread.controller.ts`、`conversation.controller.ts`、`context|knowledge|store|sandbox-runtime|mcp-apps-runtime|voice|connector-runtime`、`*-guard.ts`、`groups/`）+ `file://packages/server-ai/src/xpert/published-xpert-access.service.ts` + `file://packages/server-ai/src/xpert/enterprise-chatkit-session.service.ts` + `file://packages/server-ai/src/xpert/enterprise-chatkit.controller.ts` + `file://packages/server-ai/src/xpert/xpert-access.controller.ts`。
- 一句话判据：创作面问「是否可编辑」（`XpertGuard` / `WorkspaceAuthoringGuard`），运行时面问「是否已发布且受众匹配」（`PublishedXpertAccessService`），**两者绝不互相代替**。

### 何时找它

| 场景 | 一句话 |
|---|---|
| 某个凭证能看见/调用哪些助手 | `PublishedXpertAccessService` 的四分支查询 |
| 助手检索与运行时能力 | `POST /api/ai/assistants/search|count`、`GET /api/ai/assistants/:id[/runtime-capabilities]` |
| 线程/运行/SSE 的 HTTP 面与凭证约束 | `ThreadsController` + `AssistantThreadScopeGuard` |
| 公共 App / 企业 H5 会话签发 | `POST /api/xpert/:identifier/chatkit-session`、`/enterprise-h5/:platform/bootstrap|session` |
| 模型供应商透传与 LangGraph v1 兼容 | `AIController.proxy*`、`AIV1Controller` |

### 何时不要找它

- **会话 / 线程 / 分支 / 群聊适配器的领域归属是对话与会话专家**：本子专家只负责准入与对外面（`GROUP_CONTROLLERS` 的 `GroupScopeGuard` 只把 conversation grant 收紧到单群路由）。
- 文件与工作区能力（`assistant-files/`、`xpert-workspace/`）→ 子专家③；模板 / 市场 / 环境 / 系统槽位 → 子专家④。
- 知识库、MCP Apps / 连接器、沙箱的领域实现 → 批次 5 工具与知识域、沙箱域；本子专家只保证凭证受众与线程范围。
- 创作侧定义、草稿、发布、版本 → 子专家①。

## 3 边界

- **准入面 vs 领域面**：同一个 `/api/ai` 前缀下混装「准入面」「凭证签发面」「对话/文件/工具领域面」，路径无法承载安全语义；判断真实边界要看类级 `@AllowClientSecretBindings`、是否叠加范围守卫、以及 service 内是否再调 `PublishedXpertAccessService`。
- **不算本子专家**：`GroupAccessService` 的群内业务判定、`ChatConversationService` 的会话语义、`AssistantFilesService` 的授权实现、`SandboxManagedServiceService` 的沙箱实现——本子专家只写清鉴权前置与路由归属。
- **`EnterpriseChatkitModule` 自成一体**：完全不依赖 `AIModule`，且**没有** `RouterModule.register`，靠 `@Controller('xpert')` 自带首段。
- **邻接：`XpertAccessController`**（`file://packages/server-ai/src/xpert/xpert-access.controller.ts`，`GET /api/xpert/accessible/:id` 只回 `{ id, avatar }`）是准入服务的对外最小投影，虽在 `xpert/` 包内，功能属本子专家。

## 4 已知坑（先看这 9 条）

1. **真实前缀是 `/api/ai/assistants`**：全局前缀 `api` + `RouterModule.register([{ path: '/ai' }])` + `@Controller('assistants')`；**不存在 `/api/assistants`**，也不存在无前缀的 `/api/xpert` 之外的别名。
2. **`AssistantsController` 是 `@Public()`，全靠守卫兜底**：类级 `@Public()` + `@AllowClientSecretBindings(SecretTokenBindingType.ENTERPRISE_XPERT)` + `@UseGuards(ApiKeyOrClientSecretAuthGuard)`；`@Public()` 只关闭全局 JWT，**不产生匿名可用性**。新增方法忘挂绑定即静默扩大受众面。
3. **受众与目标 assistant 必须匹配**：`getAccessiblePublishedXpert` 在加载实体**之前**先做 audience 断言（public / enterprise / user 三处 `!== id` 即 403），运行期再由 `assertPublicChatAppXpert` / `assertEnterpriseChatAppXpert` / `assertCurrentUserAccess` 复查应用开关与组织。
4. **准入查询强制 `publishAt` 非空 + `latest`**：各 `build*Query` 与 `getPublishedXpertInTenant`（`publishAt: Not(IsNull())`）都硬编码该约束；`latest` 只在调用方把它放进 `where` 时生效（`findEnterpriseH5Xpert` 另有 `latest = true`）。**源码校正**：`publishAt` 约束**不在** `applyPublishedFilters` 内，父级旧口径需按此为准。
5. **`TENANT_SHARED_WORKSPACE_FILTER` 用原生 SQL 读 `settings` json**：与 `applyPublicChatAppFilter` / `applyEnterpriseChatAppFilter` 直读 `workspace.settings->access->visibility`、`xpert.app->>'public'`、`app->channels->...`；`COALESCE(..., 'private' | 'false')` 的失败方向是收紧（安全），但字段改名会静默改变可见性且无编译期保护。
6. **Enterprise bootstrap 在身份校验之前**：`GET .../bootstrap` 只回 `toEnterpriseH5PublicXpert` 的 12 个白名单字段 + `platform` + `clientConfig`（任何拿到 slug 的人都能读到助手名/描述/头像/starters/features）；`POST .../session` 才走 `resolveContext` → `exchangeIdentity` → `assertIdentity`（provider / externalOrganizationId / subjectId / accountBinding 五项全等）。
7. **匿名 cookie 换设备丢历史 + TTL 上限**：公共 App 会话用 cookie `anonymous.id`（`httpOnly`、`maxAge` 365 天、`sameSite` 依 `secure` 取 `none|lax`），清 cookie 即新匿名用户（`thirdPartyId = public-xpert:<id>:anonymous:<uuid>`），历史与配额随之分叉；`expires_after` 非法/缺省 600、**上限 3600**（`/api/ai/v1/chatkit/sessions` 的 `apiKey.id` 分支不受该上限限制，企业 H5 固定 600s）。
8. **路由注册顺序敏感**：`/api/ai/conversations/:conversationId/files` 曾同时被 `FileUnderstandingController`（FileAsset）与工作台文件控制器注册，命中顺序决定返回体；现改为「`/files` 归 FileAsset，目录走 `/workspace/*`」+ 旧单数路由用数组路径保留。Nest 不做冲突检测，回归测试必须覆盖两种装配顺序。
9. **范围守卫默认放行登录用户**：只有 `AssistantFileAccessGuard` 在缺少 `@AssistantFileAccess(...)` 元数据时 `denied()`；`AssistantThreadScopeGuard` / `GroupScopeGuard` 都先交给共享鉴权、再由领域服务判定。另注意 `applyAssistantScope` 会**直接改写请求头** `organization-id` / `x-scope-level` 并可能替换 `request.user`，绕过它的调用会落到不同组织 scope。
