# 运行时API与准入子专家 —— C1 能力契约

> 契约层第 1 篇（子专家②）。只写运行时**对外面与准入**的契约：真实端点、服务入口、受众矩阵、可跑示例；领域实现（会话/线程/文件/工具/沙箱）不在本篇。
> 引用写 `file://` 相对仓库根，不写行号；无据可查处写「无此项」。

## 2 服务契约

| 符号 | 语义 |
|---|---|
| `PublishedXpertAccessService.getAccessiblePublishedXpert(id, options?)` | 单条准入：先做受众断言（public / enterprise / user / workspace），再 `publishAt` 非空加载；失败 404 `The requested record was not found` 或 403 |
| `PublishedXpertAccessService.getAccessiblePublishedXpertForCurrentUser(...)` | 登录用户维度的单条准入（与上者共享分支语义，需同步演进） |
| `PublishedXpertAccessService.assertCurrentUserAccess(...)` | 运行期对「用户受众 + 组织 + 应用开关」的复查入口 |
| `PublishedXpertAccessService.findAccessiblePublishedXperts` / `countAccessiblePublishedXperts` | 列表准入；先 `select('xpert.id')` + `distinct` 取 id，再 `loadByIds` + `enrichWorkspaceAccess`（一次准入两次 DB 往返） |
| `PublishedXpertAccessService.findAccessiblePublishedResources` / `getAccessiblePublishedResource` | 资源目录；**公开会话直接 403**（不暴露资源目录） |
| `PublishedXpertAccessService.getPublishedXpertInTenant(id)` | 租户内单读，`publishAt: Not(IsNull())` |
| `PublishedXpertAccessService.buildAccessibleQuery(options, resourceParentId?)` | 四分支短路：public → enterprise（`!resourceParentId`）→ workspace API Key → 主查询（四表 join + 组织 OR 租户共享）；尾部统一 `applyPublishedFilters` + `applySearchFilter` |
| `AIController.proxy(...)` / `proxyGetModule(...)` | 供应商代理两条路径：GET 用 `copilot.apiKey` 直连相对路径，POST 用 `GetAiProviderCredentialsQuery` 的 `{ baseURL, authorization }`（行为不一致） |
| `AIV1Controller.chat / create / createChatkitSession` | 兼容层与凭证签发；`createChatkitSession` 内部拒绝「`USER_CONVERSATION` 再签发」「`scope` 与 `apiKey`/已存在 principal 互斥」 |
| `EnterpriseChatkitSessionService.getBootstrap / createSession / resolveContext / assertIdentity` | 企业 H5 两段式；`findEnterpriseH5Xpert` 用原生 QueryBuilder（uuid 按 `id`，否则按 `slug` + `latest = true`） |
| `AssistantFileAccessGuard` / `AssistantThreadScopeGuard` / `WorkbenchFilesAuthGuard` / `GroupScopeGuard` | 范围守卫族；均**不自行验票**（在 `ApiKeyOrClientSecretAuthGuard` 之后运行），`AssistantFileAccessGuard` 缺 policy 元数据即 `denied()` |
| `applyAssistantScope` / `resolveAssistantForRequest` / `assertAssistantAudience` / `assertPublicXpertSessionConversationAccess` | 请求上下文改写与受众断言（会改写 `organization-id` 请求头） |

### 受众矩阵（受众 × 允许端点 × 必需守卫/绑定）

| 受众 | 判定依据（源码符号） | 允许端点 | 必需守卫 / 绑定 |
|---|---|---|---|
| ① 登录用户（jwt） | `RequestContext.currentUserId` + 组织上下文 | 全部 `@Public()` 端点 + `/api/ai/proxy/*` | 无附加绑定（`AssistantFileAccessGuard` 对无 `principalType` 直接放行） |
| ② 租户/工作区 API Key | `currentWorkspaceApiKeyWorkspaceId`（`resourceScope.kind='workspace'`，无 `requestedUserId`） | 助手域全部读取端点 | `ApiKeyOrClientSecretAuthGuard` |
| ③ client secret `API_KEY` | `clientSecretBindingType === API_KEY` | 同②；签发时不设 3600 上限 | `ApiKeyOrClientSecretAuthGuard` |
| ④ `USER_XPERT` | `currentUserXpertId`（`resourceScope.kind='assistant'`，scope 非法即 403） | assistants / threads / conversations / contexts / connectors / workspace-files | 类级 `AllowClientSecretBindings(ENTERPRISE_XPERT)` + 守卫；文件面要求 `USER_XPERT` |
| ⑤ `ENTERPRISE_XPERT` | `currentEnterpriseXpertScope`（需 `enterpriseH5Scope.platform/integrationId`） | 同④；文件面仅 view-session 策略接受 | 类级绑定 + `/api/xpert/:identifier/enterprise-h5/:platform/session` 签发 |
| ⑥ `PUBLIC_XPERT` | `currentPublicXpertId`（scope 非法即 403） | 仅绑定助手自身；资源目录接口显式 403 | `/api/xpert/:identifier/chatkit-session` 签发 + `AnonymousXpertAuthGuard` |

## 3 示例

### 3.1 用 `ENTERPRISE_XPERT` client secret 调 `/api/ai/assistants`

```bash
# client secret 来自企业 H5 session（见 3.2），受众绑定到单个助手
curl -X POST "$HOST/api/ai/assistants/search" \
  -H "authorization: Bearer cs-x-$CLIENT_SECRET" \
  -H 'content-type: application/json' \
  -d '{"limit":20,"offset":0,"metadata":{"slug":"my-assistant","latest":true}}'
```

要点：类级绑定为 `ENTERPRISE_XPERT`，凭证受众与目标 assistant 必须匹配，否则 403 `You do not have access to this assistant.`；`metadata` 只接受 `slug/workspaceId/type/latest/version`。

### 3.2 企业 H5：bootstrap → session

```bash
# 1) 未登录即可渲染应用壳（白名单字段，无身份校验）
curl "$HOST/api/xpert/$IDENTIFIER/enterprise-h5/$PLATFORM/bootstrap"

# 2) 带授权码换 client secret（TTL 600s，绑定 platform + integrationId）
curl -X POST "$HOST/api/xpert/$IDENTIFIER/enterprise-h5/$PLATFORM/session" \
  -H 'content-type: application/json' \
  -d '{"grant":{"type":"authorization_code","code":"<code>"}}'
```

失败面：未绑定账号时返回 `{ status: 'account_binding_required', accountBindingProvider }`；身份五项不一致 → 401 `EnterpriseH5IdentityMismatch`；平台不支持 → 400 `EnterpriseH5PlatformUnsupported`；集成缺失 → 403 `EnterpriseH5IntegrationUnavailable`。
