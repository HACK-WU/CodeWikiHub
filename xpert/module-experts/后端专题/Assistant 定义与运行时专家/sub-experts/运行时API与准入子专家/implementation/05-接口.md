## 1 路由装配与真实前缀

- 全局前缀 `api`（`app.setGlobalPrefix('api', ...)`），`AIModule` 自注册 `RouterModule.register([{ path: '/ai', module: AIModule }])`，因此下列**真实前缀均为 `/api/ai/...`**。
- **校正**：`AssistantsController` 的 `@Controller('assistants')` 在 `AIModule` 之下 → 真实路径是 `/api/ai/assistants`，**不存在 `/api/assistants`**。
- `EnterpriseChatkitModule` **无** `RouterModule.register`，靠 `@Controller('xpert')` 自带首段 → `/api/xpert/:identifier/enterprise-h5/:platform/{bootstrap,session}`。
- `XpertController.createPublicChatkitSession` 位于 `XpertModule`（`path: '/xpert'`）之下 → `/api/xpert/:identifier/chatkit-session`。
- `AIModule.controllers` 共 25 个类：19 个直接列出 + `GROUP_CONTROLLERS`（6 个）。

章节来源：[ai/ai.module.ts](file://packages/server-ai/src/ai/ai.module.ts)（关键符号：AIModule.controllers、RouterModule.register）、[ai/groups/index.ts](file://packages/server-ai/src/ai/groups/index.ts)（关键符号：GROUP_CONTROLLERS）

## 3 Threads 与 Runs 端点详表

同类级鉴权（`@Public()` + `ENTERPRISE_XPERT` 绑定 + `ApiKeyOrClientSecretAuthGuard`）。

| 方法 | 路径 | 用途 | SSE / 语义位 |
|---|---|---|---|
| POST | `/api/ai/threads` | `ThreadCreateCommand` | — |
| POST | `/api/ai/threads/search` | `SearchThreadsQuery` | 显式 `@HttpCode(200)` |
| GET | `/api/ai/threads/:thread_id` | `FindThreadQuery` | — |
| GET | `/api/ai/threads/:thread_id/stream` | 线程活动流 | **SSE**（`text/event-stream` + 30s 注释心跳） |
| PATCH | `/api/ai/threads/:thread_id` | 未实现 | 抛 `UnimplementedException` |
| DELETE | `/api/ai/threads/:thread_id` | `ensureThreadAccess(id,'manage')` → `ThreadDeleteCommand` | 202 |
| POST | `/api/ai/threads/:thread_id/runs`、`runs/stream`、`runs/wait` | 运行创建与流式 | `runs/stream` 为 **SSE** |
| GET | `/api/ai/threads/:thread_id/runs`、`runs/:run_id`、`runs/:run_id/stream` | 运行查询 | `runs/:run_id/stream` 为 **SSE** |
| POST | `/api/ai/threads/:thread_id/runs/:run_id/cancel`、`pause`、`resume` | 运行控制 | `pause` 为 202 |
| DELETE | `/api/ai/threads/:thread_id/display-pause/:pause_id` | 清理暂停展示 | 204 |

运行相关端点普遍经 `AssistantThreadScopeGuard`（沙箱/语音侧）或线程服务内 `ensureThreadAccess`；凭证 scope 与 `conversation` 的 `tenantId`/`organizationId`/`xpertId` 必须全等，public/enterprise 还要求 `createdById === principal.id`。

## 6 Groups（群聊 HTTP 适配器）

`GROUP_CONTROLLERS = [GroupProjectController, GroupsController, GroupComposerController, GroupViewsController, GroupWorkbenchContextController, GroupViewFilesController]`，全部 `@Public()` + `@AllowClientSecretBindings(USER_CONVERSATION)` + `@UseGuards(ApiKeyOrClientSecretAuthGuard, GroupScopeGuard)`；视图族额外叠加 `GroupWorkbenchGuard`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/api/ai/groups`、`candidates`、`groups/:groupId/candidates`、`:groupId`、`:groupId/members`、`:groupId/messages`、`.../runtime/:participantId`、`.../recipients/:participantId/cancel`、`.../members/:participantId/control`、`.../interactions/:interactionId/claim\|respond` | 群创建/候选/成员/消息/控制/交互（逻辑属对话与会话域） |
| GET/POST | `/api/ai/groups/:groupId/members/:participantId/composer/context`、`.../assistants/:assistantId/runtime-capabilities`、`.../resources*`、`.../types`、`.../available`、`.../workspace/files`、`.../:projectId` | 群成员创作上下文与资源授权 |

## 8 鉴权与受众矩阵

| 受众 | 判定依据（源码符号） | 允许的端点 | 所需守卫 / 绑定 |
|---|---|---|---|
| ① 登录用户（jwt） | `RequestContext.currentUserId` + `getOrganizationId` | 全部 `@Public()` 端点（守卫放行登录用户）、`/api/ai/proxy/*`（唯一无 `@Public`） | 无附加绑定；`AssistantFileAccessGuard` 对无 `principalType` 直接放行 |
| ② 租户/工作区 API Key | `currentWorkspaceApiKeyWorkspaceId`（`resourceScope.kind==='workspace'`）且无 `requestedUserId` | 助手域全部读取端点 | `ApiKeyOrClientSecretAuthGuard`；无 `AllowClientSecretBindings` 时按 API Key 处理 |
| ③ client secret `API_KEY` | `clientSecretBindingType === API_KEY`（`createChatkitSession` 由 `apiKey.id` 分支签发） | 同 API Key；`createChatkitSession` 内不受 3600 上限 | `ApiKeyOrClientSecretAuthGuard` |
| ④ `USER_XPERT` | `currentUserXpertId`（`resourceScope.kind==='assistant'`，scope 非法即 403） | assistants / threads / conversations / contexts / connectors / workspace-files | `AllowClientSecretBindings(ENTERPRISE_XPERT)` 类级声明 + 守卫；文件面要求 `USER_XPERT` |
| ⑤ `ENTERPRISE_XPERT` | `currentEnterpriseXpertScope`（需 `resourceScope.kind==='assistant'` + `enterpriseH5Scope.platform/integrationId`） | 同 ④；文件面仅 view-session 策略接受 | 类级 `AllowClientSecretBindings(ENTERPRISE_XPERT)`；企业入口 `/api/xpert/:identifier/enterprise-h5/:platform/session` |
| ⑥ `PUBLIC_XPERT` | `currentPublicXpertId`（scope 非法即 403） | 仅绑定助手自身；资源目录接口显式 403 | `/api/xpert/:identifier/chatkit-session` 签发；公共 App 端点另用 `AnonymousXpertAuthGuard` |

补充约定：`AssistantThreadScopeGuard` 与 `AssistantFileAccessGuard` 都在 `ApiKeyOrClientSecretAuthGuard` 之后运行、**从不自行验票**；`WorkbenchFilesAuthGuard` 继承父守卫并追加 conversation 存在性（404 `ConversationNotFound`）与 principal 断言。

章节来源：[xpert/published-xpert-access.service.ts](file://packages/server-ai/src/xpert/published-xpert-access.service.ts)（关键符号：PublishedXpertAccessService.currentPublicXpertId、PublishedXpertAccessService.currentEnterpriseXpertScope、PublishedXpertAccessService.currentUserXpertId）、[ai/workbench-files-auth.guard.ts](file://packages/server-ai/src/ai/workbench-files-auth.guard.ts)（关键符号：WorkbenchFilesAuthGuard.canActivate）

## 9 跨域适配器归属表

|---|---|---|---|---|
| 会话 / 消息 / 分支 / 产物 | `/api/ai/conversations*` | 对话与会话域 | 只保证受众与凭证绑定 | DELETE 202 |
| 线程与运行 | `/api/ai/threads*` | 对话与会话域（运行控制） | 准入前置 + SSE 心跳 | `thread_id` 与 `threadId` 双风格 |
| 群聊 | `/api/ai/groups/*` | 对话与会话域 | `GroupScopeGuard` 收紧到单群路由 | 共享 ChatKit 鉴权先跑 |

| 知识库 | `/api/ai/knowledges/*`、`/api/ai/v1/kb*` | 批次 5 知识域 | `KnowledgebaseOwnerGuard` 挂载 | — |

## 11 结论

本接口面的阅读顺序应当是「先看类级装饰器，再看方法，最后才看路径」：同一个 `/api/ai` 前缀下并存四类鉴权外壳（`ENTERPRISE_XPERT` 绑定族、无绑定族、群聊 `USER_CONVERSATION` 族、无 `@Public` 的 proxy 族），路径无法承载安全语义。第二，**受众与端点的对应关系由「凭证 + 范围守卫」双保险表达**：凭证决定能看到哪些助手，范围守卫决定能碰哪个线程/文件/群。第三，两个签发入口（`/api/xpert/:identifier/chatkit-session` 与 `/api/ai/v1/chatkit/sessions`）语义不同——前者是匿名公共 App，后者是用户委派/API Key/群会话三态复用，阅读时不可互相套用。
