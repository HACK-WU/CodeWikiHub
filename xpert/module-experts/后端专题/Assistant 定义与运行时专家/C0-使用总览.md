## 0. 契约自足声明

本文是「Assistant 定义与运行时专家」的对外使用契约，不依赖阅读实现层即可决定：**何时找本专家、能得到哪些能力、从哪个入口调、边界在哪、有哪些已知坑**。算法、私有方法与数据结构细节不在本文展开，只给契约级语义与指向实现层的索引；凡源码中未见证据的结论一律不写。

## 1. 专家定位

本域是 Assistant 的**「户籍 + 门禁 + 分发」**：定义（DSL 草稿）→ 发布（版本行）→ 准入（谁能跑）→ 文件授权（能碰哪些文件）→ 创作容器（`XpertWorkspace`）→ 分发（模板 / 市场 / 系统槽位绑定 / 企业 H5）。本域不拥有 Agent 执行链，也不拥有会话本体。

## 2. 何时找这个专家

- 新建 / 改草稿 / 发布 / 回滚版本 / DSL 导入导出 / 复制一个 Assistant。
- 读一个已发布 Assistant 的对外投影、运行时能力、可用模型与模型偏好。
- 判断「谁能跑这个 Assistant」：公共 App、企业 H5、工作区 API-Key、登录用户四类受众。
- 读写在 **Assistant 数据卷**里的文件（运行时侧或 Studio 创作侧）。
- 管理创作容器 `XpertWorkspace`：成员、可见性、默认工作区、软删 / 归档 / 恢复。
- 取模板目录与详情、安装模板、同步技能资产。
- 市场发现、访问申请、审批与驳回。
- 系统槽位绑定（`chat_common` 等）、Bosi 桌面引导、绑定级用户偏好。
- 读写工作区级环境变量集。
- **不需要找本域**：Agent 编译与执行链、会话 / 线程 / 消息本体、工具与 MCP、`xpert-task` —— 请找对应专家。

## 6. 边界（做什么 / 不做什么）

- **`ai/**` 的代码归属在本域**：`AIModule` 的对外准入 / 适配端点（`assistant.controller.ts`、`ai.controller.ts`、`ai-v1.controller.ts`、`assistant-workspace-files.controller.ts` 等）属本域；但其中**会话、线程、分支、群聊适配器**（`thread.controller.ts`、`conversation.controller.ts`、`conversation-branch.controller.ts`、`ai/groups/*`）的**领域归属是「对话与会话专家」**——模块归属 ≠ 领域归属，两者共用 `/ai` 前缀。
- 不含 Agent 编译与执行链、多智能体调度（批次 4）。
- 不含工具、MCP、知识库内容本体（批次 5）。
- 不含 `xpert-project`、`xpert-task` 任务调度（批次 4）。
- 外挂依赖不计入本域：`shared/stream`（SSE 扇出）、`shared/runtime/workspace-files-runtime.module`、`VOLUME_CLIENT`（卷设施）、server-core 的 `UserGroup` / `SecretToken` / `Integration`。

## 7. 已知问题与常见坑（12 条）

1. **三元权限面不可互换**：创作面（`WorkspaceAuthoringGuard` / `XpertService.assertCanAuthorById`）、运行面（`PublishedXpertAccessService`）、文件面（`AssistantFilesService.forRuntime/forAuthoring`）是三个独立闸门，任一处选错即越权。
   做法：绝不用 `XpertService.findOne()`、`XpertWorkspaceService.canAccess()` 或工作区 `canRun` 充当文件 ACL。来源：`implementation/01-架构.md` §6、`C5` D1。
2. **绝不接受 HTTP 传入 authoring 模式**：文件入口 `entry` 只由服务端代码在 `forRuntime()` / `forAuthoring()` 中硬编码（源码注释：`entry is chosen by trusted server code, never request data`）。
   做法：运行时被拒后**不得**回退 authoring；不得把 `entry` 做成查询参数或请求体字段。来源：`C5` D2。
3. **运行时文件必须走 `ResolveAssistantFileAccessCommand`**：8 个运行时文件端点每个操作都重新派发该命令（含已成功 list / capabilities 之后），单点判定并返回 `{ scope, capabilities }`。
   做法：文件列表页 N 次调用 = N 次准入查询，属有意取舍，不要按会话缓存授权结论。来源：`implementation/02-实现.md` 热点路径 1、`C5` D3。
4. **`/api/ai/assistants` 而非 `/api/assistants`**：`AssistantsController` 挂在 `AIModule` 的 `/ai` 前缀下，`/api/assistants` **不存在**；同类还有 `/api/ai/threads`、`/api/ai/conversations`。
   来源：`implementation/05-接口.md` §10「路由前缀校正」。
5. **企业 H5 bootstrap 在身份校验之前**：`GET /api/xpert/:identifier/enterprise-h5/:platform/bootstrap` 为 `@Public()`，未认证即返回白名单助手元数据 + `platform` + `clientConfig`；身份校验推迟到 `/session`，换得的 `ENTERPRISE_XPERT` client secret **TTL 固定 600 秒**。
   做法：该响应只放白名单字段。来源：`C5` D6、`implementation/05-接口.md` §2.5。
6. **公共 App 匿名 cookie + TTL 上限 3600s**：`chatkit-session` 用 httpOnly cookie `anonymous.id`（365 天）标识匿名用户，client secret 的 `expires_after` 缺省或非法归一为 600、**硬上限 3600 秒**。
   做法：换设备 / 清 cookie 即丢历史并累积新的匿名账号。来源：`C2` Recipe 6、`implementation/07-运维.md` §1。
7. **草稿与 `graph` 双列分叉**：`Xpert` 同表内 `draft` / `graph` 双列 + 多行版本；`saveDraft` / `updateDraft` 只动草稿，`publish` 才写 `graph`，两者的同步点极少。
   做法：任何改图写入都必须经事务入口（触发连接的 `change()`），绕过即分叉。来源：`implementation/01-架构.md` §6、`C5` D5。
8. **`ensurePrincipalUser` 隐式建账号**：`PUT /api/xpert/:id/api`、`PUT /api/xpert/:id/app` 在「启用且无 `userId`」时隐式创建助手外部服务账号，账号生命周期与助手启停状态易不一致。
   做法：涉及助手身份的操作先确认 `userId` 是否已存在。来源：`implementation/02-实现.md` 技术债 6。
9. **路由注册顺序敏感（`/files` vs `/workspace/*`）**：同方法同 URL 被两个 controller 注册时 Nest 不报错，命中前者会静默返回空结果（历史现象：文件存在但列表为空）。
   做法：`conversations/:id/files` 归 FileAsset 附件，运行目录走 `conversations/:id/workspace/*`，新增 controller 必须按「同路径不同 controller」排查。来源：`C5` D9。
10. **市场授权落地为 `UserGroup`**：审批通过 = 建 / 复用 `UserGroup` → 申请人入组 → 组入 `xpert.userGroups`；`xpert_access_request.accessGroupId` 与 `xpert_to_user_group` **无反向同步**。
    做法：删组 / 改名后申请仍显示 `approved` 而运行权已失效，撤销只能靠删组或移出成员。来源：`C5` D8、`implementation/03-数据流转.md` §7。
11. **`@Public()` 不等于匿名可用**：是否放行由该路由附加的 `ApiKeyOrClientSecretAuthGuard` + `@AllowClientSecretBindings(...)` + 领域守卫共同决定；受众凭证与目标 Assistant 不匹配回 403，而不是「查不到」。
    来源：`implementation/05-接口.md` §9、`C2` 横向注意点。
12. **启动期副作用在多副本下有竞争面**：绑定回填（`AssistantBindingService.onModuleInit`）无锁、无日志；触发器补偿用 Redis 锁、Bosi 引导用 advisory lock 已加锁；模板目录是共享文件系统，导出模板须挂共享卷，否则只在写入副本可见。
    来源：`C5` D10、`implementation/07-运维.md` §5。
