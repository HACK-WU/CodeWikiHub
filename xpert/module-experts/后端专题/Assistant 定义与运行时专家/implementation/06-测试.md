## 1 测试框架与运行方式

- 框架：Jest + ts-jest。`displayName: 'server-ai'`，`preset: '../../jest.preset.js'`，`testEnvironment: 'node'`，ts 经 `ts-jest` 使用 `<rootDir>/tsconfig.spec.json`，js/mjs 经 `babel-jest`（`babel-jest.config.js`）。
- 依赖解析直指源码（**不依赖已构建产物**）：`moduleNameMapper` 将 `@xpert-ai/server-core` → `../server/src/index.ts`，`@xpert-ai/contracts`、`@xpert-ai/plugin-sdk`、`@xpert-ai/cli-model-profiles`、`@xpert-ai/shadcn-ui/brand-icons` 同理；`transformIgnorePatterns` 按依赖图动态放行 `@xpert-ai/chatkit-types`、`oidc-provider`、`lodash-es`、`jose`、`marked` 等。
- nx target：`packages/server-ai/project.json` 的 `test` 目标为 `@nx/jest:jest`，`jestConfig: packages/server-ai/jest.config.ts`，输出目录 `{workspaceRoot}/coverage/packages/server-ai`，因此 `pnpm nx test server-ai` 可直接运行。
- 单文件运行（调用方实测 2s 级，来自 Step 1 扫描报告记录）：`node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts --runTestsByPath packages/server-ai/src/xpert/xpert.controller.spec.ts`。
- 与构建命令的区分：`pnpm nx build server-ai`（`@nx/js:tsc`）只编译，不跑测试。

## 3 断言与 mock 风格

- 绝大多数为纯单元测试：`Test.createTestingModule({ providers: [{ provide: X, useValue: {...} }] })` 或直接 `new Service(mock1 as never, mock2 as never)`，断言用 `rejects.toBeInstanceOf(ForbiddenException)`、`rejects.toBeInstanceOf(BadRequestException)`、`expect(...).resolves.toMatchObject(...)`。
- 依赖整体以 `jest.mock('@xpert-ai/contracts' | '@xpert-ai/server-core' | '@xpert-ai/plugin-sdk' | '../xpert/xpert.entity', () => ({...}))` 顶层替换，再对 `RequestContext.currentTenantId`/`getOrganizationId`/`currentUserId`/`hasRole` 做 `jest.spyOn(...).mockReturnValue(...)`。
- HTTP 用例风格：`Test.createTestingModule` 挂载真实 controller（如 `AIV1Controller`）→ `.overrideGuard(ApiKeyOrClientSecretAuthGuard).useValue({ canActivate })` → `app = module.createNestApplication({ logger:false }); await app.listen(0,'127.0.0.1')` → 用 `fetch(origin + path)` 断言状态码与 body；i18n 通过 `init({ lng:'en', resources })` 预置断言用 key 文案。
- 日志噪声控制：`jest.spyOn(Logger.prototype,'log'|'warn'|'error').mockImplementation(() => undefined)`（如触发器恢复 spec）。

章节来源：[chatkit-session.http.spec.ts](file://packages/server-ai/src/ai/chatkit-session.http.spec.ts)（关键符号：describe、ApiKeyOrClientSecretAuthGuard 覆盖）、[trigger-bootstrap-recovery.service.spec.ts](file://packages/server-ai/src/xpert/jobs/trigger-bootstrap-recovery.service.spec.ts)（关键符号：XpertTriggerBootstrapRecoveryService 测试）

## 6 无测试与覆盖缺口

- 无 spec 的入口：`xpert/xpert-access.controller.ts`（有 spec 但为轻量）、`xpert/xpert-tag-usage.controller.ts`、`xpert/trigger-connection.controller.ts`（service 有 spec，controller 无）、`xpert/configuration/assistant-trigger.controller.ts`（service 有 spec）、`environment/environment.controller.ts` + `environment.service.ts`、`assistant-binding/bosi/bosi-bootstrap.controller.spec.ts` 之外的 binding 控制器层（`assistant-binding.controller.ts` 无独立 spec，逻辑由 service spec 覆盖）。
- 无端到端：本域没有跨模块 e2e（如“H5 bootstrap→session→ChatKit 调用”整链路），`enterprise-chatkit.controller.spec.ts` 仅覆盖控制器契约。
- 无真实数据库覆盖的回填：`AssistantBindingService.backfillLegacy*` 只在假 `DataSource` 上验证分支，`information_schema` 探测与唯一索引冲突的真实行为未在域内验证。
- 域外但强相关的测试缺口（仅记录，不在本域范围）：`xpert-task/`（Bull + Redis + ActorToken）与 `handoff/` 的真实队列恢复用例。

章节来源：[published-xpert-access.service.spec.ts](file://packages/server-ai/src/xpert/published-xpert-access.service.spec.ts)（关键符号：PublishedXpertAccessService 测试）、[enterprise-chatkit.controller.spec.ts](file://packages/server-ai/src/xpert/enterprise-chatkit.controller.spec.ts)（关键符号：EnterpriseChatkitController 测试）

## 7 可执行性结论

- ✅ 可跑：`pnpm nx test server-ai` 或 `node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts --runTestsByPath <spec>`；配置自洽（ts-jest + tsconfig.spec.json + 源码级 moduleNameMapper），无需先构建 `server-core`/`contracts`。
- 已知失败用例：**未确认**（本轮为只读搜索，**未执行 jest**；Step 1 扫描报告同样未执行）。
- 默认全量运行时会跳过：`ensure-personal-default-workspace.handler.integration.spec.ts`（未设 `PERSONAL_WORKSPACE_PG_E2E=1`）。
- 建议的最小回归面（按接口风险排序）：`published-xpert-access.service.spec.ts`、`assistant-binding.service.spec.ts`、`ai/*.http.spec.ts`（3 个）、`assistant-workspace-files.controller.spec.ts`、`workbench-files-auth.guard.spec.ts`、`enterprise-chatkit-session.service.spec.ts`、`xpert.controller.spec.ts`。
