## 1 环境变量与配置项

| 变量 / 配置 | 用途 | 默认值 / 取值 | 来源文件 |
|---|---|---|---|
| `XPERT_TEMPLATE_DIR` | 外部模板目录（导出模板与 catalog 的落盘根） | 未设置 → `<assetOptions.dataPath>/xpert-template`；以 `serverRoot` 为基准解析相对路径；指向内置模板源码目录内时被判定 `unsafe` 并回落默认值 | `xpert-template/utils/template-paths.ts` |
| `SANDBOX_VOLUME` | 沙箱 / 文件卷根（Docker host 侧） | 空；dev 且未配置时回落 `$HOME/data` | `shared/volume/volume-layout.ts` |
| `SANDBOX_VOLUME_LAYOUT` | 卷目录布局开关 | 仅取值 `legacy-flat` 时生效（需 dev 且未配 `SANDBOX_VOLUME`） | `shared/volume/volume-layout.ts` |
| `IS_DOCKER` | 判断是否容器内运行，决定卷根为 `/sandbox[/<tenantId>]` | 非 `true` | `shared/volume/volume-layout.ts` |
| `HOME` / `USERPROFILE` | 非容器本地数据根 `<home>/data` | 运行环境默认 | `shared/volume/volume-layout.ts` |
| `DB_SCHEMA_SYNC_MODE` | 置 `external` 时 API 以 `synchronize:false` 启动，DDL 交独立 schema-sync 进程 | 未设置（API 正常 synchronize） | `packages/server/src/database/application-data-source.ts` |
| `ConfigService.get('baseUrl')` | 助手模型选择服务拼接对外 URL | 无内置默认值 | `xpert/assistant-model-selection.service.ts` |
| 公共 App `expires_after`（请求体，非环境变量） | ChatKit 会话令牌时长 | 非法或缺省 600s，上限 3600s | `xpert/xpert.controller.ts` |
| 企业 H5 会话 TTL（代码常量） | 企业 client secret 时长 | 固定 600s | `xpert/enterprise-chatkit-session.service.ts` |

## 2 启动副作用与后台任务

### 2.1 绑定回填（AssistantBindingService.onModuleInit）

- `onModuleInit()` → `backfillLegacyBindings()` → `backfillLegacySystemBindings()`：先用 `to_regclass('public.assistant_config')` 判存在，再按 `isSystemManagedAssistant(code)` 把旧表行写成 `assistant_binding`（存在即跳过）。
- `backfillLegacyUserBindings()`：先用 `information_schema.columns` 校验 `assistant_user_preference` 的列齐备（`tableHasColumns`），再按 user scope 回填。
- 两个回填路径均无 Logger，失败以异常冒泡。

章节来源：[assistant-binding/assistant-binding.service.ts](file://packages/server-ai/src/assistant-binding/assistant-binding.service.ts)（关键符号：AssistantBindingService.onModuleInit、AssistantBindingService.backfillLegacySystemBindings、AssistantBindingService.tableHasColumns）

### 2.2 触发器启动补偿（XpertTriggerBootstrapRecoveryService）

- `onApplicationBootstrap()` 分页扫描 `latest = true AND publishAt IS NOT NULL` 的 Xpert（每批 50），从 `graph.nodes` 取 `type='workflow'`、`WorkflowNodeTypeEnum.TRIGGER` 且 `from !== 'chat'` 的 provider。
- 按 provider 的 `bootstrap.mode` 分流：`replay_publish`（缺省）重放发布、`skip` 跳过；重放执行 `XpertPublishTriggersCommand({ strict: false })`。
- 每个 Xpert 抢 Redis 锁 `job:trigger:v2:<xpertId>`（10s），未抢到记 `skipped`；结束打印 `phase=bootstrap_recovery_summary` 的 scanned/replayed/skipped/failed 计数。

章节来源：[xpert/jobs/trigger-bootstrap-recovery.service.ts](file://packages/server-ai/src/xpert/jobs/trigger-bootstrap-recovery.service.ts)（关键符号：XpertTriggerBootstrapRecoveryService.onApplicationBootstrap、XpertTriggerBootstrapRecoveryService.recoverXpert）

### 2.3 模板目录引导（启动建目录与播种）

- `XpertTemplateService.onApplicationBootstrap()` 执行 `EnsureTemplateDirectoryCommand`，失败只记 error、不阻断启动。
- Handler 以单例 `ready` Promise 幂等：建外部根目录 → 建 `templates` / `pipelines` / `skill-packages` → 从内置根按"缺则复制"播种 `templates.json`、`mcp-templates.json`、`knowledge-pipelines.json`、`skills-market.yaml`、`skill-repositories.yaml`、`workspace-defaults.yaml` → `upgradeBuiltinTemplateCatalog` 升级目录 → 日志 `Xpert templates ready at '<externalRoot>'`。

章节来源：[xpert-template/commands/handlers/ensure-template-directory.handler.ts](file://packages/server-ai/src/xpert-template/commands/handlers/ensure-template-directory.handler.ts)（关键符号：EnsureTemplateDirectoryHandler.execute）、[xpert-template/template.constants.ts](file://packages/server-ai/src/xpert-template/template.constants.ts)（关键符号：templateDirectories、templateFiles）

### 2.4 安装期副作用与队列任务

- 模板安装（`/api/xpert-template/:id/install`）= 创建 Assistant + 工作区；随后 `XpertTemplateWorkspaceInitializer.initializeByTemplateId()` 在该工作区初始化 prompt workflows，失败仅 warn 并返回 `{status:'failed'}`（**不**回滚已创建的助手）。
- 本域不注册 Bull 队列；队列任务名 `xpert-task-scheduler` 属 `xpert-task`（域外）。本域后台链路是 `HandoffQueueService` 交接 + `callback.transport = 'redis-pubsub'` 回传，公共 App 流式对话与触发器派发都走这一条。

## 3 迁移与 schema

- 本域唯一的 SQL 迁移目录是 `assistant-binding/migrations/`：`20261003-bosi-bootstrap.sql`（`ALTER TABLE assistant_binding ADD COLUMN IF NOT EXISTS "desktopBootstrap" json NULL`）与 `20261004-bosi-onboarding.sql`（同表 `desktopOnboarding`）。两条均幂等，可重复执行。
- `xpert/`、`xpert-workspace/`、`xpert-template/`、`environment/`、`xpert-marketplace/` 下无 `.sql` 迁移 → 该子模块无此项，表结构由 TypeORM 元数据承担（多实例下由独立 schema-sync 进程执行）。
- `DB_SCHEMA_SYNC_MODE=external` 与 `synchronize` 的关系：`initializeApplicationDataSource` 在 external 模式下用 `{...options, synchronize: false}` 初始化副本数据源，使 API 启动不并发 DDL；判定入口只有 `isSchemaSyncExternallyManaged`。
- 模板导出的落盘约定：`${XPERT_TEMPLATE_DIR}/templates/<id>.yaml` + catalog `templates.json`（分类常量 `exportedXpertTemplateCategory = 'Xpert'`）；写失败抛出的错误串会带上实际 `externalRoot`，排障时以该路径为准。

## 5 多副本注意事项

- **启动回填竞争**：`AssistantBindingService.onModuleInit` 在多副本同时启动时会并发执行表探测 + 写入，未使用分布式锁（无 Logger 亦无锁，属本域最薄的一处实例协调）。
- **可对照的已治理面**：`docs/plans/PLAN_multi_instance_remediation.md` 记录了多实例整改——XpertTask 重复执行改为 `xpert_task_execution` 唯一键 + lease、API 容器设 `DB_SCHEMA_SYNC_MODE=external` 并把 DDL 收敛到独立 `schema-sync` 命令、Session 改 Redis Store；该计划并未覆盖本域绑定回填。
- **域内已带锁的启动任务**：触发器恢复用 `RedisLockService` 按 `job:trigger:v2:<xpertId>` 跨实例互斥，未抢到锁只记 `skipped`，可安全多副本启动。
- **原生 SQL 读 `workspace.settings` 的可见性回落**：`workspace-access.service.ts` 的 `applyCurrentReadScope` / `applyMemberReadCondition` 与 `published-xpert-access.service.ts` 的 `TENANT_SHARED_WORKSPACE_FILTER` 都直接求值 `COALESCE((workspace.settings)::jsonb -> 'access' ->> 'visibility', 'private')`；`settings` 结构迁移或改名会把判定静默回落为 `private`（方向是收紧，但 `tenant-shared` / `organization-shared` 会同时失效）。
- **模板目录是共享文件系统**：启动播种与导出写入同一 `externalRoot`，多副本必须挂共享卷，否则导出模板只在写入副本可见。

章节来源：[docs/plans/PLAN_multi_instance_remediation.md](file://docs/plans/PLAN_multi_instance_remediation.md)（关键符号：独立 Schema Sync Job、`DB_SCHEMA_SYNC_MODE=external`）、[xpert-workspace/workspace-access.service.ts](file://packages/server-ai/src/xpert-workspace/workspace-access.service.ts)（关键符号：XpertWorkspaceAccessService.applyCurrentReadScope）、[xpert/published-xpert-access.service.ts](file://packages/server-ai/src/xpert/published-xpert-access.service.ts)（关键符号：TENANT_SHARED_WORKSPACE_FILTER）

## 6 安全运维

- **TTL 三件套**：公共 App ChatKit 会话默认 600s / 上限 3600s（`normalizeChatkitSessionExpiresAfter` 把非法值归 600 并截断到 3600）；企业 H5 会话固定 600s（`ENTERPRISE_CHATKIT_SESSION_TTL_SECONDS`）；匿名 cookie `anonymous.id` 365 天（httpOnly）。
- **匿名身份**：cookie 缺失时由 `getOrSetAnonymousId` 生成 uuid 并回写，`AnonymousStrategy` 用它作 `thirdPartyId`；换设备或清 cookie 即丢失历史会话（公共 App 的会话过滤依赖 `fromEndUserId`）。
- **`@Exclude` 列**：`AssistantBinding.desktopBootstrap` 标 `@Exclude({ toPlainOnly: true })`（注释明写为 server recovery state），绑定接口即使直接返回实体会剔除该列；Bosi setup 另走最小进度快照。
- **白名单投影**：`XpertProfileController.getProfile` 手工构造字段（tags/workspace/creator 逐项裁剪，不序列化实体与加载关系）；`XpertAccessController` 只回 `{id, avatar}`；企业 H5 bootstrap 在身份校验前只回 `EnterpriseH5Xpert` 白名单。
- **密钥轮换影响面**：client secret 形如 `cs-x-<64 hex>`，落 `secret_token.token`，有效期字段 `validUntil`；`SecretToken.afterLoadEntity` 计算 `expired`，`SecretTokenStrategy.validateToken` 命中过期抛 `UnauthorizedException('Token expired')`。该实体**未见** `revoked` 字段——轮换后旧令牌会一直可用到 `validUntil` 到期，紧急吊销只能靠删除/缩短有效期的行级操作，并使在途公共 App 与企业 H5 会话全部失效。

章节来源：[xpert/xpert.controller.ts](file://packages/server-ai/src/xpert/xpert.controller.ts)（关键符号：XpertController.normalizeChatkitSessionExpiresAfter、XpertController.getOrSetAnonymousId）、[packages/server/src/secret-token/secret-token.strategy.ts](file://packages/server/src/secret-token/secret-token.strategy.ts)（关键符号：SecretTokenStrategy.validateToken）、[assistant-binding/assistant-binding.entity.ts](file://packages/server-ai/src/assistant-binding/assistant-binding.entity.ts)（关键符号：AssistantBinding.desktopBootstrap）、[xpert/xpert-profile.controller.ts](file://packages/server-ai/src/xpert/xpert-profile.controller.ts)（关键符号：XpertProfileController.getProfile）

## 7 运维检查清单

- **发布前**：确认 `XPERT_TEMPLATE_DIR` 未指向内置模板源码目录（启动日志出现 "Ignoring XPERT_TEMPLATE_DIR" 即已回落）；多副本场景确认该目录与 `SANDBOX_VOLUME` 位于共享持久卷。
- **重启后**：观察 4 类信号——`Xpert templates ready at ...`（模板目录就绪）、`bootstrap_recovery_summary` 的 `failed` 计数（>0 且错误多为 trigger provider 未注册）、绑定回填是否抛异常（无日志，只能看启动失败）、每个副本的 Xpert 视图是否一致（验证共享卷生效）。
- **schema 变更**：本域只有两条 `ADD COLUMN IF NOT EXISTS` 迁移可重复执行；如改动 `xpert` 表（`draft`/`graph`/`latest` 唯一索引）或 `xpert_workspace.settings` 结构，必须同步复核原生 SQL 可见性片段与触发器 `change()` 事务入口。
- **凭证与合规**：公共 App 匿名会话上限 1 小时、企业会话 1 分钟粒度固定 10 分钟级短 TTL，安全事件处置按"先删除 `secret_token` 行、再缩短 `validUntil`"执行；`Environment.variables` 中的 `secret` 项属于落库数据，审计范围应含 `environment` 表而不只是进程环境。
