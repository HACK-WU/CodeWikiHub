## §1 入口索引

全局前缀 `api`；模块前缀由 `RouterModule.register({ path: '/ai' })` 给出。**上传入口单独列**（跨域，归属 `AIModule`），本控制器 8 条。

### 1.1 上传入口（跨域，单列）

| 方法 | 路径 | 鉴权 | 用途 |
|---|---|---|---|
| POST | `/api/ai/contexts/file` | 类级 `@Public()` + `@AllowClientSecretBindings(ENTERPRISE_XPERT)` + `ApiKeyOrClientSecretAuthGuard`，再叠 `assertUploadScope` / `assertCanCreateConversationAsset` | multipart → `UploadFileCommand` → `CreateFileAssetCommand` → `EnqueueFileParseCommand`；返回 `AgentFile`（`id == fileId == FileAsset.id`，`storageFileId` 仅兼容桥）；`workspacePath` 被强制置空 |

### 1.2 `FileUnderstandingController`（模块路由 `/ai`，8 条）

| # | 方法 | 路径 | 鉴权 / operation | 用途 |
|---|---|---|---|---|
| 1 | GET | `/api/ai/files/:fileId` | `resolve('read')` | 返回授权后的 `FileAsset` 句柄（直接返回 `resolve` 的 asset） |
| 2 | GET | `/api/ai/files/:fileId/status` | `resolve('read')` | `GetFileParseStatusQuery` → `{fileId,status,error,parsedAt}`；授权通过后资产缺失才 404 |
| 3 | POST | `/api/ai/files/:fileId/parse/retry` | `resolve('parse')` | `RetryFileParseCommand` → 直接转 `ParseFileAssetCommand`（**无状态门禁**，不重置 `status`） |
| 4 | POST | `/api/ai/files/:fileId/search` | `resolve('read')` | `SearchFileChunksQuery({fileId,query?,limit?})`：有 query 走向量 + 关键词 RRF；无 query 按 `orderNo` 顺序列举 |
| 5 | GET | `/api/ai/files/:fileId/preview` | `resolve('read')` | `GetFilePreviewQuery`：summary ≤900 字、artifact ≤12、chunk ≤8；**资产不存在返回 `null`（HTTP 200）** |
| 6 | POST | `/api/ai/files/:fileId/read` | `resolve('read')` | `ReadFileChunkQuery({fileId,chunkId?,orderNo?})`，`orderNo` 缺省 0；chunk 缺失返回 `null`（终态 not-found） |
| 7 | GET | `/api/ai/conversations/:conversationId/files` | `assertConversationAccess('read')` + 公共会话断言（**不走 `authorizeFile`**） | `ListConversationFilesQuery`；与邻域 `/workspace/files` 是两条互不遮蔽的路由 |
| 8 | DELETE | `/api/ai/files/:fileId` | `resolve('delete')` | `DeleteFileAssetCommand` → `FileAssetDeletionService.delete` 全链路清理 |

> 鉴权口径：类级三件套只负责**认证**（API key / client-secret），文件级**授权**落在每个方法内联的 `authorizeFile(fileId, operation)`；命中公共 Xpert 会话 scope 时额外要求 `fileAsset.userId === scope.createdById` 并追加 `assertPublicXpertSessionConversationAccess`。

| `FileAssetAccessService.resolve(input)`；`input = {locator, authority, operation}` | 文件侧**唯一授权入口** | `locator ∈ {fileAssetId} \| {storageFileId}`；`authority ∈ {kind:'current-owner'} \| {kind:'conversation',conversationId?,threadId?}`；`operation ∈ read\|attach\|parse\|write\|delete`。查询强制 `tenantId` 过滤，`organizationId` 为空视为租户级可见；`locator` 不一致同样拒 | `{asset, storageFile?, conversation?}` | **不存在与无权限不区分**，统一 403 `FileAssetAccessDenied`（防枚举）；跨项目复用同一资产的链接 → 409 |

| `FileWorkspaceProjectionService.projectFileAsset(input)` | 对象存储文件 → 工作区投影 | 以 `input.operation ?? (authority.kind==='conversation' ? ## §3 事件/命令入边契约

本域**不发出任何事件/命令**（无 `EventBus`、无 `@EventsHandler`），入向 **10 组**全部为进程内 CQRS 命令/查询注入；漏注册 handler 在启动期 DI 报错，漏处理则功能静默缺失。

| # | 命令 / 查询名 | 来源模块 | 本域动作 | 失败语义 |
|---|---|---|---|---|
| 1 | `CreateFileAssetCommand`、`EnqueueFileParseCommand`、`DeleteFileAssetCommand`、`GetFileAssetByStorageFileQuery` | `AIModule`（`ai/context.controller.ts`） | 上传落句柄、启动解析、按 storageFile 反查、删除资产 | 403 `FileAssetAccessDenied`；`!storageFile` 时抛空 403；cleanup 内页图/目录删除失败被静默吞掉 |
| 2 | `GetFileAssetByStorageFileQuery`、`GetOwnedStorageFileQuery`、`ResolveAuthorizedFileAssetQuery` | `ChatConversationModule`（`conversation.service.ts`） | 会话侧按 storageFile 反查资产、取自有存储文件、按会话/owner 授权 | tenantId/组织/locator 任一不符统一 403 |
| 3 | `AssertFileUploadScopeQuery`、`AttachFileToConversationCommand` | `EnterpriseChatkitModule` | 上传前作用域断言；把资产 attach 到会话 | 403；**独立调用点本轮未定位**（按索引保留） |

## §4 示例

### ① 上传一个文件并启动解析（`ContextsController.create`）

```ts
// 真实调用方：packages/server-ai/src/ai/context.controller.ts
const target = resolveExternalStorageUploadTarget(targetValue, { kind: 'storage', directory: 'contexts', prefix: 'files' })
workspacePath = undefined                                  // 上传体里的 workspacePath 被显式忽略
const conversation = await this.resolveConversationReferences(conversationId, threadId)
const asset = await this.commandBus.execute(new UploadFileCommand({ source: { kind: 'multipart', file }, targets: [target] }))
const destination = getFileAssetDestination(asset, target.kind)
if (!destination || destination.status !== 'success') { throw new BadRequestException(destination?.error || `Failed to upload context file to target '${target.kind}'`) }
const storageFile = getStorageFileFromAsset(asset)
const fileAsset = await this.commandBus.execute<CreateFileAssetCommand, FileAsset>(
    new CreateFileAssetCommand({ storageFile, uploadedFile: file, purpose: purposeValue ?? 'chat_attachment', parseMode, conversationId, threadId, projectId, xpertId, workspacePath })
)
const parsedAsset = parseMode === 'none' ? fileAsset
    : await this.commandBus.execute<EnqueueFileParseCommand, FileAsset>(
          new EnqueueFileParseCommand(fileAsset.id, { runInline: this.shouldRunParseInline(file, parseMode) })  // fast→true；deep→false；其余 size ≤ 2MB
      )
return this.withFileUnderstanding(storageFile, parsedAsset)   // AgentFile：id == fileId == FileAsset.id
```

要点：`StorageFile` 仍会创建（对象存储兼容），但对外句柄一律是 `FileAsset`；`parseMode==='none'` 时**不投递 Enqueue**，解析链完全不启动。

### ② 读解析状态与预览（`FileUnderstandingController`）

```ts
// 真实调用方：packages/server-ai/src/file-understanding/file-understanding.controller.ts
@Get('files/:fileId/status')
async getFileStatus(@Param('fileId') fileId: string) {
    const fileAsset = await this.authorizeFile(fileId, 'read')          // resolve({locator:{fileAssetId}, authority:'current-owner'})
    return this.queryBus.execute(new GetFileParseStatusQuery(fileAsset.id))
}
@Get('files/:fileId/preview')
async getPreview(@Param('fileId') fileId: string) {
    const fileAsset = await this.authorizeFile(fileId, 'read')
    return this.queryBus.execute(new GetFilePreviewQuery(fileAsset.id))  // 资产不存在 → null（HTTP 200）
}
```

要点：**授权先于执行**（拒绝时 `queryBus` 从未被调用）；`/status` 与 `/preview` 的「找不到」语义不同，前端不能把 `null` 当作错误分支。

### ③ 删除文件资产（连带顺序）

```ts
// 真实调用方：packages/server-ai/src/file-understanding/file-asset-deletion.service.ts
async delete(fileAssetId: string): Promise<void> {
    const { asset } = await this.fileAssetAccessService.resolve({ locator: { fileAssetId }, authority: { kind: 'current-owner' }, operation: 'delete' })
    await this.cleanup(asset)
}
/** Dedicated project lifecycle entry; never trusts the supplied project ID as authority. */
async purgeProjectFile(fileAssetId: string, projectId: string): Promise<void> {
    const { project } = await this.projectAccessService.assertCanPurge(projectId)
    const { asset } = await this.fileAssetAccessService.resolve({ /* … operation: 'read' */ })
    if (asset.projectId !== project.id || asset.tenantId !== project.tenantId) { throw new ForbiddenException(t('server-ai:Error.ProjectPurgeFileMismatch', { /* … */ })) }
    await this.cleanup(asset)
}
// cleanup 固定连带顺序（不可换：向量库先于账本）
await this.fileVectorService.deleteFileVectors(fileAssetId, asset)
await this.fileCitationAnchorRepository.delete({ fileAssetId })
await this.fileEmbeddingRepository.delete({ fileAssetId })
await this.fileChunkRepository.delete({ fileAssetId })
await this.fileArtifactRepository.delete({ fileAssetId })
await this.conversationFileLinkRepository.delete({ fileAssetId })
await this.fileAssetRepository.delete({ id: fileAssetId })
await this.deletePageImageStorageKeys(storageProvider, pageImageStorageKeys)
await this.deleteDerivedRootIfLocal(storageProvider, asset)   // 仅本地 provider（path() 绝对路径）才 rm
```

要点：`DELETE /api/ai/files/:fileId` 与项目永久删除走**不同授权入口但共用 `cleanup`**；远端 provider 下派生对象成为孤儿。
