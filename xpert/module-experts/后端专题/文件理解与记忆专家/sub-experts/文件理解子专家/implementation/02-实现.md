## 1. 上传链

**入口真实路径**：`POST /api/ai/contexts/file`（`ContextsController.create`，`@Controller('contexts')` 注册在挂 `/ai` 的 `AIModule` 内；旧注释写的 `/contexts/file` 缺 `/ai` 段）。鉴权同样是 `@Public()` + `@AllowClientSecretBindings(ENTERPRISE_XPERT)` + `ApiKeyOrClientSecretAuthGuard`。

**步骤**：① `FileInterceptor('file')` 收 multipart；② `resolveExternalStorageUploadTarget(targetValue, {kind:'storage', directory:'contexts', prefix:'files'})` 解析目标（默认 storage）；③ `workspacePath` 被**显式置空**（`workspacePath = undefined`）；④ `resolveConversationReferences(conversationId, threadId)` 解析会话，命中后**以会话字段覆盖** `projectId`/`xpertId`/`threadId`；⑤ 授权：公共 Xpert 会话分支只允许 storage target 且禁带 `projectId`，否则非会话时 `assertUploadScope`、会话时 `assertCanCreateConversationAsset(conversation,'upload')`；⑥ `UploadFileCommand` 落对象存储 + `storage_file` 行；⑦ `getFileAssetDestination` 校验 destination.success，取 `getStorageFileFromAsset`；⑧ `CreateFileAssetCommand`（含 `uploadedFile`，用于 sha256）→ `FileAsset`；⑨ `parseMode !== 'none'` 时 `EnqueueFileParseCommand(fileAsset.id, { runInline: shouldRunParseInline(file, parseMode) })`；⑩ 返回 `AgentFile`（`id === fileId === FileAsset.id`，`storageFileId` 仅兼容桥，`status === parseStatus`）。

**`shouldRunParseInline` 判定**：`fast` → true；`deep` → false；其余按 `file.size <= 2_000_000`（2MB）决定。`workspacePath` 形态（工作区已有文件转资产）走 `CreateWorkspaceFileAssetCommand`，见 §8。

## 2. 解析链

**`EnqueueFileParseHandler`**：`findOneByOrFail` → `status = parseMode === 'none' ? 'ready' : 'parsing'`、`error = null` → save；`none` 直接返回；`options.runInline` 为真则 `await` `ParseFileAssetCommand`（同请求内跑完）；否则 `setImmediate(() => commandBus.execute(new ParseFileAssetCommand(id)).catch(warn))` —— **后台解析的返回体是「已入队」的 `FileAsset`，不是结果**。

**`RetryFileParseHandler`**：仅一句 `commandBus.execute(new ParseFileAssetCommand(command.fileAssetId))`，**无状态门禁**（HTTP 侧也无门禁；平台侧门禁在 `WorkspaceFilesRuntimeCapabilityService.retryUnderstanding`，只允许 `failed` 或 `vectorIndexStatus ∈ {failed, unavailable}`，否则 400）。

**`ParseFileAssetHandler.execute`**：① `resolve(..., operation:'parse')`；② `parseMode === 'none'` → `status='ready'` + `parsedAt` 直接返回；③ 置 `status='parsing'`、`error=null` 落库；④ 源解析：有 `storageFile` 用 `FileStorage().getProvider(provider).path(storageFile.file)`；无 storageFile 则用 `createVolumeFileSnapshot` 从卷取快照（拿不到则抛 `File asset "…" does not have a readable storage or workspace source`）；⑤ `parseRunId = randomUUID()`，派生目录 `normalizeRelativePath('contexts', tenantId, 'file-understanding', asset.id, parseRunId)`；⑥ **解析器选择** `FileParserRegistry.getParser(source)`；⑦ `parser.parse(source)`；⑧ `replaceArtifacts`（**先删该资产全部 artifact，再按数组下标写 `orderNo`**）；⑨ `IndexFileChunksCommand` 触发切块 + 向量；⑩ 回写 `status = parsed.status ?? 'ready'`、`summary`、`capabilities`（与 `preview`/`read` 求并集）、`metadata`（并入 `parsed.metadata` + `parser` 名 + `chunkCount`）、`parsedAt`，清 `failedAt`/`error`；⑪ `projectParsedPageImages`（best-effort，且当 `(!conversationId && !projectId) || (!projectId && !xpertId)` 时直接跳过）；⑫ 删除**陈旧页图**（旧 `page_image` 的 storageKey 与对应 run 目录）；⑬ `finally` 释放卷快照。失败则 `status='failed'` + `error` + `metadata.understandingErrorCode ∈ {file_understanding_embedding_unavailable, file_understanding_vector_index_failed, file_understanding_parse_failed}` + `failedAt`。

**解析器逐个（`FileParsers` 静态数组 = provider 注册表；registry 内顺序 pdf → spreadsheet → office → image → archive → text，首个 `supports` 命中者胜）**：

|---|---|---|---|
| `PdfFileParser` | `mimeType === 'application/pdf'` 或扩展名 `pdf` | `summary` + 每页 `page_text`（`anchor.page`）+ 每页 `page_image` | `preview/read/search/ocr`，有页图再加 `vision/page_images`；页图渲染用动态 `import('pdf-to-img')`、scale 2、上限 `FILE_UNDERSTANDING_PDF_RENDER_MAX_PAGES`（默认 300），PNG 经 `provider.putFile` 落到 `<派生目录>/pages/page-0001.png`；有文本且未截断 → `ready`，否则 `partial` |

## 3. 分块与索引

`IndexFileChunksHandler.execute`：① 读 asset（`findOneByOrFail`）；② **清场**：`deleteFileVectors` → 删 `file_citation_anchor` → 删 `file_embedding` → 删 `file_chunk`；③ 按 `orderNo ASC` 读全部 artifact；④ 仅 `CHUNKABLE_ARTIFACT_KINDS = [text, page_text, sheet, slide, table, code_tree, file_manifest, ocr_text]` 且 `content.trim()` 非空者入块；⑤ `chunkText`：`len <= 3600` 单块，否则 3600 窗口 + 240 重叠（`offset = max(end - 240, offset + 1)`，保证前进）；⑥ `orderNo = chunks.length`（**跨 artifact 全局连续**），`anchor = {...artifact.anchor, chunk: orderNo}`，`metadata = {artifactKind, ...artifact.metadata}`；⑦ `save` 后 `rebuildCitationAnchors` 为每块建一行 `file_citation_anchor`：`anchorKey` 依次取 `page:<page>:chunk:<n>` / `sheet:<sheet>:chunk:<n>` / `slide:<slide>:chunk:<n>` / `path:<path>:chunk:<n>` / 兜底 `chunk:<n>`，`label` 为 `Page n` / `Sheet x` / `Slide n` / `path` / `Chunk n`；⑧ `fileVectorService.indexChunks(asset, savedChunks)`；⑨ 返回 `savedChunks`（`ParseFileAssetHandler` 用它写 `metadata.chunkCount`）。

**幂等口径**：全量重建（先删后建），`file_chunk` 无业务唯一键，`orderNo` 是位置而非身份；重复执行结果等价但 **chunk id 会变化**（因此外部不应长期缓存 chunkId）。

**向量侧（`FileUnderstandingVectorService`）**：目标解析 = `CopilotOneByRoleQuery(tenantId, organizationId, AiProviderRole.Embedding, ['copilotModel','modelProvider'])` → `CopilotModelGetEmbeddingsQuery` → 维度取 `options.dimensions ?? options.dimension`，否则 `embedQuery` 探测长度 → `createValidatedFileEmbeddings` 包装（按 12000 字符分批、逐向量校验非空/有限/非零/维度一致）→ 集合名 `file-understanding:<scope>:<id>:<fingerprint>`（scope 优先 `xpert` > `project` > `tenant`）。写：`addDocuments(docs, { ids: chunk.id })`，再写 `file_embedding` 账本（`vectorId = chunk.id`）。搜：先按账本过滤出**同一 collectionName** 的 chunkId 集合，再 `similaritySearchWithScore(query, limit, {tenantId, organizationId, fileAssetId, enabled:true})` 并用该集合**交叉过滤**（两跳，防旧集合残留污染）。删：按账本 `collectionName` 分组 `vectorStore.delete({ids})`。

**`CreateFileArtifactsCommand`**：外部注入 artifact 的旁路（同样先清 vectors/anchors/embeddings/chunks/artifacts 再写），当前**本域内无调用方**（`CreateFileArtifactsHandler` 仅被注册）。

章节来源：[index-file-chunks.handler.ts](file://packages/server-ai/src/file-understanding/commands/handlers/index-file-chunks.handler.ts)（关键符号：IndexFileChunksHandler.execute / chunkText / rebuildCitationAnchors / createAnchorKey）；[file-understanding-vector.service.ts](file://packages/server-ai/src/file-understanding/file-understanding-vector.service.ts)（关键符号：indexChunks / searchChunkIds / deleteFileVectors / resolveVectorTarget / createValidatedFileEmbeddings）；[create-file-artifacts.handler.ts](file://packages/server-ai/src/file-understanding/commands/handlers/create-file-artifacts.handler.ts)（关键符号：CreateFileArtifactsHandler.execute）

## 4. 读取 / 预览 / 搜索（8 端点）

控制器 8 条路由（`@Controller()` 空段 + `/ai` 前缀），每条先授权再投递。**口径修正**：源码中**没有**独立 `POST /files/:fileId/parse`，重解析只有 `parse/retry` 一条。

| # | 方法 / 路径 | 授权 operation | 投递 | 返回 / 失败语义 |
|---|---|---|---|---|
| 1 | `GET /api/ai/files/:fileId` | `read` | —（直接返回 `resolve` 的 `asset`） | `FileAsset`；未授权 403 |
| 2 | `GET /api/ai/files/:fileId/status` | `read` | `GetFileParseStatusQuery` | `{fileId, status, error, parsedAt}`；资产不存在 404 `File asset "…" not found` |
| 3 | `POST /api/ai/files/:fileId/parse/retry` | `parse` | `RetryFileParseCommand` → `ParseFileAssetCommand` | 重解析后的 `FileAsset`；**无状态门禁** |
| 4 | `POST /api/ai/files/:fileId/search` | `read` | `SearchFileChunksQuery({fileId, query?, limit?})` | `FileChunk[]`；`query` 空 → 按 `orderNo` 分页列块 |
| 5 | `GET /api/ai/files/:fileId/preview` | `read` | `GetFilePreviewQuery` | 紧凑预览（文件安全字段 + ≤12 artifact + ≤8 chunk 头）；**资产不存在返回 `null`（200）** |
| 6 | `POST /api/ai/files/:fileId/read` | `read` | `ReadFileChunkQuery({fileId, chunkId?, orderNo?})` | 单 chunk 或 `null`；`chunkId` 分支以 `fileAssetId` 绑作用域 |
| 7 | `GET /api/ai/conversations/:conversationId/files` | `assertConversationAccess(...,'read')`（不走 `authorizeFile`） | `ListConversationFilesQuery` | 授权过的 `FileAsset[]`；公共会话追加 `assertPublicXpertSessionConversationAccess` |
| 8 | `DELETE /api/ai/files/:fileId` | `delete` | `DeleteFileAssetCommand` → `FileAssetDeletionService.delete` | `void` |

**检索实现（`SearchFileChunksHandler`）**：无 query → `find({fileAssetId}, order orderNo ASC, skip/take)`；有 query → **混合检索**：向量路（`searchChunkIds(asset, query, limit*2)`）与关键词路（按空格/CJK 标点切词、长度 ≥2、最多 6 词，`content ILIKE %term%` OR 连接，`orderNo ASC`）并行，再用 **RRR 倒数排名融合** `1/(60+rank+1)` 合并、同分按 `orderNo` 升序；`limit = min(max(limit ?? 8, 1), search ? 30 : 101)`（有 query 上限 30，无 query 上限 101 以便 `hasMore` 前瞻）。

**预览实现（`GetFilePreviewHandler`）**：只 `select` 安全字段（id/storageFileId/originalName/mimeType/size/status/capabilities/workspacePath/summary/error/parsedAt/failedAt/metadata），artifact 取 `take: 13` 后剔除 `summary` 并截 12，chunk 只回 `{chunkId, orderNo, anchor, tokenCount}`；`page_image` 额外附 `createPageImagePreviewFile` 的 `{workspacePath, url, fileName, width, height, size}`。

章节来源：[file-understanding.controller.ts](file://packages/server-ai/src/file-understanding/file-understanding.controller.ts)（关键符号：8 路由 + authorizeFile + listConversationFiles）；[search-file-chunks.handler.ts](file://packages/server-ai/src/file-understanding/queries/handlers/search-file-chunks.handler.ts)（关键符号：SearchFileChunksHandler.execute / reciprocalRankMerge / tokenizeSearch）；[get-file-preview.handler.ts](file://packages/server-ai/src/file-understanding/queries/handlers/get-file-preview.handler.ts)（关键符号：GetFilePreviewHandler.execute / compactMetadata）；[get-file-parse-status.handler.ts](file://packages/server-ai/src/file-understanding/queries/handlers/get-file-parse-status.handler.ts)（关键符号：GetFileParseStatusHandler.execute）；[read-file-chunk.handler.ts](file://packages/server-ai/src/file-understanding/queries/handlers/read-file-chunk.handler.ts)（关键符号：ReadFileChunkHandler.execute）；[list-conversation-files.handler.ts](file://packages/server-ai/src/file-understanding/queries/handlers/list-conversation-files.handler.ts)（关键符号：ListConversationFilesHandler.execute）；[list-project-files.handler.ts](file://packages/server-ai/src/file-understanding/queries/handlers/list-project-files.handler.ts)（关键符号：ListProjectFilesHandler.execute / authorizeFiles）

## 5. 删除与回收

`DeleteFileAssetHandler.execute`：只有一句 `await this.deletion.delete(command.fileAssetId)`。

`FileAssetDeletionService.delete(fileAssetId)`：先 `resolve({locator:{fileAssetId}, authority:'current-owner', operation:'delete'})`，再 `cleanup(asset)`。

`cleanup` 固定顺序（**无事务**）：① 预扫 `page_image` artifact 的 storageKey；② 解析 storage provider；③ `deleteFileVectors(fileAssetId, asset)`（按账本分 collection 删向量）；④ 删 `file_citation_anchor`；⑤ 删 `file_embedding`；⑥ 删 `file_chunk`；⑦ 删 `file_artifact`；⑧ 删 `conversation_file_link`；⑨ 删 `file_asset` 行；⑩ `provider.deleteFile(storageKey)` 逐个删页图（每个 `.catch(() => undefined)`）；⑪ `deleteDerivedRootIfLocal`：`normalizeRelativePath('contexts', tenantId, 'file-understanding', assetId)` → `provider.path()` 必须是绝对路径才 `fsPromises.rm(recursive, force)`。

**项目回收独立入口** `purgeProjectFile(fileAssetId, projectId)`：`projectAccessService.assertCanPurge(projectId)` → `resolve(..., operation:'read')` → 比对 `asset.projectId === project.id && asset.tenantId === project.tenantId`，不符抛 403 `Error.ProjectPurgeFileMismatch`；随后复用同一 `cleanup`。调用方是 `XpertProjectModule` 的 `ProjectPurgeService`（经 `moduleRef.get(FileAssetDeletionService, { strict: false })`）。

**残留面**：远端对象存储下 `contexts/<tenantId>/file-understanding/<assetId>/<parseRunId>/**` 不会被清（`provider.path()` 非绝对路径即跳过）；向量删除、页图删除、目录删除失败**全部静默**。

## 10. 设计模式与热点路径

**模式**：① **CQRS + Handler 注册表**（9 命令 + 16 查询，全部 `@CommandHandler`/`@QueryHandler`）；② **策略注册表**（`FileParsers` 静态数组 = 解析器插件位，`supports` 决定命中）；③ **外观/收口服务**（`FileAssetAccessService` 是所有调用点的公共前置）；④ **账本 + 外置存储**（`file_embedding` 记账，向量本体在 RagVStore）；⑤ **best-effort 副作用**（投影/页图/清理失败只 warn，不污染主链）；⑥ **内置中间件注入工具**（工具面通过 middleware 走统一 toolMap/tracing）；⑦ **能力委托**（`FileRuntimeService` 以 `@RuntimeCapabilityProvider(FileRuntimeCapability)` 实现 `AgentMiddlewareFileApi`，并用 `createScopedApi` 做一次性会话绑定而非在共享实例上持久化会话身份）。

## 12. 技术债

1. **解析任务非持久化**：`setImmediate` 在进程内排队，重启即丢、无重试、无并发上限与背压；`retry` 是唯一补偿手段。`[推测]` 大租户批量上传时解析吞吐受单进程事件循环限制。
2. **`file_asset` 缺 `unique(storageFileId)`**：去重靠 `findOne` + `save`，并发同 `storageFileId` 上传可产生两行。`[推测]` 高并发 ChatKit 重试场景存在重复资产风险。
3. **`cleanup` 无事务**：中途失败可能留下「向量已删、行仍在」的不一致；且所有清理失败静默（仅 `catch(() => undefined)`），无对账入口。`[推测]`
4. **远端 provider 派生目录不回收**：`provider.path()` 非绝对路径即跳过 `fs.rm`，S3/OSS 下 `contexts/<tenantId>/file-understanding/<assetId>/<parseRunId>/**` 成为孤儿对象。
5. **向量状态用「行数近似」**：`vectorIndexStatus === 'ready'` 的条件是 `indexedChunkCount >= chunkCount`，基于 `file_embedding` 行数而非真实向量存在性；账本丢失会被判 `unavailable`。`[推测]` 与 RagVStore 侧漂移时可能误导重试决策。
6. **非 deep 模式静默降级**：向量目标解析失败或索引异常一律返回 `[]`，调用方（含 Agent 工具）无法区分「没有匹配」与「没有索引」。
7. **`CreateFileArtifactsCommand` 无生产调用方**：仅注册未接线，属半成品旁路。
8. **`assertCanLinkToConversation` 的 409 是「已经发生后」的检查**：链接写入与该项目绑定之间没有锁，并发跨 Project attach 仍可能双写。`[推测]`
9. **`parsers/binary-content.spec.ts` 无同名实现**：`[推测]` 该 spec 覆盖 `text-file.ts` 的二进制嗅探断言，命名已与实现脱节。
10. **中间件无钩子**：文件工具面无法在 `beforeAgent` 阶段预注入「当前可见文件清单」，每轮由模型自行调 `parsed_file_list`，多一次模型往返。

## 13. 设计维度

**维度一 · 同步 / 后台二分**：`runInline` 由 `parseMode`（fast 强制内联、deep 强制后台）与体积（≤2MB 内联）共同决定；同一份 `EnqueueFileParseCommand` 因此有两种时序语义，调用方必须读 `status` 而不是假定「返回即有结果」。

**维度二 · fail-open 与 fail-closed 混用**：授权、跨 Project 复用、`projects` 卷治理路径写保护一律 **fail-closed**；投影、页图、清理、非 deep 的向量索引一律 **fail-open（warn + 空值）**；`deep` 模式又把向量失败提升为 **fail-fast**。三条策略共存在一个 handler 内（`ParseFileAssetHandler` 的 try/catch/finally 就是三者的交汇点）。

**维度三 · 全量重建 vs 增量**：chunk / anchor / embedding 三者都选择「删净重算」而非 diff 增量；换来的是幂等语义简单（重跑一次即收敛），代价是重解析期间资产**短暂不可检索**且 chunkId 漂移。

**维度四 · 本域表 vs 外置账本**：向量本体在 RagVStore，域内只保留 `file_embedding` 账本；集合名内嵌 embedding fingerprint，使「换模型 = 换集合」而不需要迁移旧向量。`[推测]` 这也意味着旧集合不会自动清理，长期会积累死集合。

## 14. 结论

- **写链**：`ContextsController.create` → `CreateFileAsset`（按 `storageFileId` 复用）→ `EnqueueFileParse`（状态先落 `parsing`）→（内联或后台）`ParseFileAsset` → 解析器 → `IndexFileChunks`（切块 + 锚点 + 向量账本）。
- **读链**：8 端点全部「先 `authorizeFile`、后投递」；预览刻意瘦身、检索刻意限流（≤30/≤101）、读取刻意终态化（不许扫 orderNo）。
- **两个边界**：可见性靠 `conversation_file_link`（工具面经 `ListProjectFilesQuery`/`ListConversationFilesQuery` 收口），字节可达性靠工作区投影（`metadata.workspace` 记卷与相对路径）。
- **可维护性判据**：新增解析类型只需实现 `FileParser` 并进 `FileParsers`；新增可见性场景应改 `FileAssetAccessService.resolve` 的 authority 分支，而不是在调用点加判断。
- **必须先修的三件事**：解析任务的持久化/重试、`file_asset` 的 `storageFileId` 唯一约束、`cleanup` 的失败可观测量（当前全静默）。
