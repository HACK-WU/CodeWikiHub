## §1 入口索引

全局前缀 `api`。记忆面控制器路径由自身装饰器给出（`@Controller('xpert/:id/memory')`）；存储面由 `RouterModule.register([{ path: '/storage-file', module }])` 给出。**记忆体的文件 CRUD 不在这两个控制器里**：`:id/memory/file[s]` 挂在 `XpertController`，校验与路径语义在本域 `FileMemoryFacade`/`paths.ts`。

### 1.1 文件记忆（`FileMemoryController`，6 条，类级 `@UseGuards(XpertGuard)`）

| # | 方法 | 路径 | 鉴权 | 用途 |
|---|---|---|---|---|
| 1 | POST | `/api/xpert/:id/memory/dream` | `XpertGuard` | `triggerDream(xpert,{reason})`，`reason ∈ manual\|scheduled\|signal_threshold`；同 scope 已有 pending 返回 `{...pending, coalesced:true}`；gate 未过**不报错**，落 `status='skipped'` 并写 `output/gate.json` |
| 2 | GET | `/api/xpert/:id/memory/dream/config` | `XpertGuard` | 磁盘 `config.json` + env 派生的 `defaults`（`dreamerXpertId` / `dreamerAgentKey` / `gate`） |
| 3 | PUT | `/api/xpert/:id/memory/dream/config` | `XpertGuard` | 归一化后写回并回读；缺 dreamer 项报 `FileMemory Dreamer config requires dreamerXpertId and dreamerAgentKey.` |
| 4 | GET | `/api/xpert/:id/memory/dream/runs` | `XpertGuard` | 扫描 `.dream/runs/*`，按 `requestedAt` 倒序；目录缺失返回 `[]`，单 run 读失败静默跳过 |
| 5 | GET | `/api/xpert/:id/memory/dream/runs/:runId` | `XpertGuard` | 运行详情：summary + preflight + report + validation + 8 个 artifact 清单（`status`/`request`/`evidence`/`preflight`/`gate`/`dream_report`/`validation`/`changed_files`） |
| 6 | POST | `/api/xpert/:id/memory/dream/runs/:runId/cancel` | `XpertGuard` | 仅 `queued` 可置 `cancelled` 并写 `finishedAt`；其他状态原样返回（`running` 不可取消） |

## §3 记忆读写与召回契约

### 3.1 写入路径 × 触发时机 × 落盘形态

| 写入路径 | 触发时机 | 判定 / 门槛 | 落盘形态 |
|---|---|---|---|
| 显式 `memory_write`（工具） | 模型在轮次中主动调用 | zod schema 可选 `memoryId` + 必填 `title`/`summary`/`content`；`memoryId` 只能复用 digest 或上次结果给的 `canonicalRef`/`relativePath`（系统策略「绝不要猜测 memoryId」） | 卷上 `<type>/<slug>-<id8>.md`（frontmatter + body），`source:'explicit'`；同时写 `explicit_write` 信号并刷新 `MEMORY.md` 与记分卡 |
| 隐式 writeback（钩子） | `afterAgent` 轮次结束 | 本轮已显式写 → `skipped reason=explicit_write`；摘要空 → `skipped reason=empty_summary`；否则按 scope 键串行裁决 `noop\|upsert\|archive`；upsert 缺字段回落 `noop` | `source:'writeback'`；`upsert` 复用候选 `memoryId`（软去重，**无 DB 唯一约束兜底**）；无模型时只写 `writeback_candidate` 信号 |
| 离线 Dream（HTTP） | `POST /dream`（`manual`/`scheduled`/`signal_threshold`） | gate 默认 30 分钟 + ≥1 条新/更新记忆 + ≥1 会话；同 scope pending 合并；另一 run 持锁 → `partial` | dreamer 助手直接编辑卷上 markdown 与 `MEMORY.md`；证据落 `.dream/runs/<runId>/**`，运行前备份、`finally` 清理 |

### 3.2 召回 × 注入 × 预算

| 环节 | 入口 | 语义与预算 |
|---|---|---|
| 索引 digest | `beforeAgent` → `prepareRecall`（后台） | `listMemoryHeaders`（mtime 缓存）→ `selectSummaryDigestHeaders` 启发式 **6 条** digest |
| 模型筛选 | `FileMemoryRecallPlanner.selectRecallHeaders` | 短名单 **20** → 模型返回 `selectedIds`；默认超时 **1500ms**，超时/失败可 `fallback`；`fallbackOnFailure:false` 直接返回空；`strategy ∈ model\|fallback\|disabled` |
| 详情块 | `buildDetailBlock` | 逐条 `getMemory`（**会写 `detail_read` 信号**），受单轮 **20KB** / 单会话 **60KB** 预算约束，召回超时 **3s**、最多选 **5 条** |
| 注入 | `wrapModelCall` | `messages: [...buildMemoryContextMessages(recall), ...request.messages]` 前置注入 `[indexBlock, digestBlock, detailBlock]`，并附 `buildMemorySystemMessage` |
| 工具面召回 | `memory_search` / `memory_get` | `memory_search` → `recordRecallHits`（`recall_hit`）；`memory_get` → `detail_read` + `updateTopicUsage`；无模型时 `memory_search` 返回 `[]` |
| 会话预算对账 | `wrapModelCall` 日志 | `recallStrategy` / `selected` / `detailBytes` / `surfacedSessionBytes` / `pending` 是排障入口 |

章节来源：[file-memory.middleware.ts](file://packages/server-ai/src/file-memory/file-memory.middleware.ts)（关键符号：MAX_DETAIL_BYTES_PER_TURN / MAX_DETAIL_BYTES_PER_SESSION / beforeAgent / wrapModelCall / buildMemoryContextMessages）、[recall-planner.ts](file://packages/server-ai/src/file-memory/recall-planner.ts)（关键符号：selectRecallHeaders / selectSummaryDigestHeaders / rankHeaders）、[file-memory.writeback.ts](file://packages/server-ai/src/file-memory/file-memory.writeback.ts)（关键符号：decideFileMemoryWriteback）

## §4 示例

### ① 显式写一条记忆（`memory_write` 工具）

```ts
// 真实调用方：packages/server-ai/src/file-memory/file-memory.middleware.ts
tool(async (input) => {
    explicitWriteOccurred = true
    const result = await this.fileMemoryService.writeMemory(xpert, {
        type: assertFileMemoryType(input.type), memoryId: input.memoryId, title: input.title,
        summary: input.summary, content: input.content, tags: input.tags,
        sourceRefs: input.sourceRefs, conversationId: context.conversationId
    })
    return result                                   // { memoryId, relativePath, frontmatter }
}, { name: 'memory_write', schema: memoryWriteSchema })
```

要点：写入落在卷上 `.xpert/memory`，`MEMORY.md` 索引与主题文件由服务维护、不落库；`memoryId` 只能原样复用 digest / 上次工具结果给出的 `canonicalRef`/`relativePath`。

### ② 一次 writeback（`afterAgent` → `enqueue` → 串行裁决）

```ts
// 真实调用方：packages/server-ai/src/file-memory/file-memory.middleware.ts / file-memory.writeback-runner.ts
afterAgent: (state) => {
    if (explicitWriteOccurred) { this.logger.log('[XpertFileMemory] afterAgent skipped reason=explicit_write'); return }
    const summary = summarizeMessagesForWriteback(readStateMessages(state))
    if (!summary) { this.logger.log('[XpertFileMemory] afterAgent skipped reason=empty_summary'); return }
    this.writebackRunner.enqueue({ xpert, messages, conversationId: context.conversationId, getModel: createWritebackModel, prompt })
    // runner 内部：按 createFileMemoryScopeKey 串行 → recordWritebackCandidate → searchMemory(limit 6)
    //            → decideFileMemoryWriteback 裁决 noop|upsert|archive（upsert 复用候选 memoryId）
}
```

要点：无模型时只记 `writeback_candidate` 候选并 warn，**不会落盘**；`softDrain(key, timeoutMs)` 可在调用方限时等待。

### ③ 上传 + 下载一个存储文件（`/api/storage-file`）

```ts
// 上传：packages/server/src/storage-file/storage-file.controller.ts
const asset = await this.commandBus.execute(new UploadFileCommand({
    source: { kind: 'multipart', file },
    targets: [{ kind: 'storage', directory: 'files', prefix: 'files' }]        // key 必须落在 files/<tenantId>/ 内
}))
const storageFile = getStorageFileFromAsset(asset)                              // 取不到 → 400 Failed to upload storage file
// 读取 URL：StorageFileSubscriber.afterLoad 每次加载动态补 fileUrl
const fileUrl = new FileStorage().getProviderInstance().url(storageFile.file)   // LocalProvider: ${environment.baseUrl}/public/<path>
// 删除：DELETE /api/storage-file/:id → service 断言 owner/admin（任何异常一律 403）
await service.deleteStorageFile(id)                                            // findOne → repository.remove → afterRemove 删 file/thumb 对象
```

要点：`storageProvider` 在写行时固化（大写），读取永远按行上的值解析；registry 失配会静默回落 `LocalProvider`，因此「看起来正常」不代表用的是租户配置的 provider。
