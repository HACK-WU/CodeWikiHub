## §1 HTTP 入口索引

全局前缀 `api`；模块前缀由 `RouterModule.register` 给出（`/ai`、`/storage-file`）或控制器自身路径给出（`xpert/:id/memory`）。本域自带端点 **17 条**（8 + 6 + 3），上传入口 2 条为跨域但**必列**。

### 1.1 上传入口（跨域，归属 `AIModule`，含 `@deprecated` 旧入口）

| 方法 | 路径 | 鉴权 | 用途 |
|---|---|---|---|
| POST | `/api/ai/contexts/file` | 同文件侧三件套：`@Public()` + `@AllowClientSecretBindings(ENTERPRISE_XPERT)` + `ApiKeyOrClientSecretAuthGuard`，再叠 `assertUploadScope` / `assertCanCreateConversationAsset` | multipart 上传 → `UploadFileCommand` → `CreateFileAssetCommand` → `EnqueueFileParseCommand`；返回 `AgentFile`（`id == fileId == FileAsset.id`，`storageFileId` 仅兼容桥）；`workspacePath` 被强制置空 |
| DELETE | `/api/ai/contexts/file/:id` | 同上；`!storageFile` 时抛空 `ForbiddenException` | `:id` 是 **storageFileId**：有 FileAsset → `resolve('delete')` + `DeleteFileAssetCommand` + `deleteAuthorizedStorageFile`；无 FileAsset → `assertStorageFileOwner`（严格 owner，无管理员豁免） |
| POST（**已弃用**） | `/api/ai/v1/file` | 同上 | 源码逐字 `@deprecated Use POST /contexts/file`；**只落 storage 目标，不建 FileAsset、不触发解析** |

### 1.2 `file-understanding`（`FileUnderstandingController`，模块路由 `/ai`，8 条）

| 方法 | 路径 | 鉴权 / operation | 用途 |
|---|---|---|---|
| GET | `/api/ai/files/:fileId` | `resolve('read')` | 返回授权后的 FileAsset 句柄 |
| GET | `/api/ai/files/:fileId/status` | `resolve('read')` | `GetFileParseStatusQuery` → `{fileId,status,error,parsedAt}`；授权后资产缺失才 404 |
| POST | `/api/ai/files/:fileId/parse/retry` | `resolve('parse')` | `RetryFileParseCommand` → 直接转 `ParseFileAssetCommand`（**无状态门禁**，不重置 `status`） |
| POST | `/api/ai/files/:fileId/search` | `resolve('read')` | `SearchFileChunksQuery({fileId,query,limit})`：有 query 走「向量 + 关键词 RRF」，无 query 按 `orderNo` 顺序列举 |
| GET | `/api/ai/files/:fileId/preview` | `resolve('read')` | `GetFilePreviewQuery`：summary ≤900 字、artifact ≤12、chunk ≤8；资产不存在返回 `null`（HTTP 200） |
| POST | `/api/ai/files/:fileId/read` | `resolve('read')` | `ReadFileChunkQuery({chunkId|orderNo})`，`orderNo` 缺省 0；chunk 缺失返回 `null`（终态 not-found） |
| GET | `/api/ai/conversations/:conversationId/files` | `assertConversationAccess('read')` + 公共会话断言 | `ListConversationFilesQuery`；与邻域 `/workspace/files` 是两条互不遮蔽的路由 |
| DELETE | `/api/ai/files/:fileId` | `resolve('delete')` | `DeleteFileAssetCommand` → `FileAssetDeletionService.delete` 全链路清理 |

### 1.3 `file-memory`（`FileMemoryController`，`@Controller('xpert/:id/memory')`，6 条）

| 方法 | 路径 | 鉴权 | 用途 |
|---|---|---|---|
| POST | `/api/xpert/:id/memory/dream` | `XpertGuard` | `triggerDream(xpert,{reason})`，`reason ∈ manual\|scheduled\|signal_threshold`；同 scope 已有 pending 时返回 `{...pending, coalesced:true}`；gate 未过**不报错**，落 `status='skipped'` 并写 `output/gate.json` |
| GET | `/api/xpert/:id/memory/dream/config` | `XpertGuard` | 返回磁盘 `config.json` + env 派生的 `defaults` |
| PUT | `/api/xpert/:id/memory/dream/config` | `XpertGuard` | 归一化 `dreamerXpertId`/`dreamerAgentKey`/`gate{...}` 后写回并回读；缺 dreamer 项报 `FileMemory Dreamer config requires dreamerXpertId and dreamerAgentKey.` |
| GET | `/api/xpert/:id/memory/dream/runs` | `XpertGuard` | 扫描 `.dream/runs/*`，按 `requestedAt` 倒序；目录缺失返回 `[]` |
| GET | `/api/xpert/:id/memory/dream/runs/:runId` | `XpertGuard` | 运行详情：summary + preflight + report + validation + artifacts 清单 |
| POST | `/api/xpert/:id/memory/dream/runs/:runId/cancel` | `XpertGuard` | 仅 `queued` 可置 `cancelled` 并写 `finishedAt`；其他状态原样返回 |

> 记忆体的**文件 CRUD 不在此控制器**：`/api/xpert/:id/memory/file[s]` 系列挂在 `XpertController`，校验与路径语义在本域 `FileMemoryFacade`/`paths.ts`。

### 1.4 `storage-file`（`StorageFileController`，模块路由 `/storage-file`，3 条）

| 方法 | 路径 | 鉴权 | 用途 |
|---|---|---|---|
| POST | `/api/storage-file` | **无控制器守卫**，仅全局 `AuthGuard` + `PluginScopeInterceptor` | multipart → `UploadFileCommand`（target `{kind:'storage',directory:'files',prefix:'files'}`）→ 返回登记行；destination 非 success 报 400 |
| POST | `/api/storage-file/url` | 同上（**不设用户边界**） | `axios` 拉取 URL 字节 → `provider.putFile(url)` → `createStorageFile`；失败 400 `Failed to download and store file from URL: <msg>` |

## §3 事件/命令消费契约

本域**不发出任何事件/命令**（`file-understanding` 无 EventBus / `@EventsHandler`；`file-memory` 唯一出站为 Dream 的 `XpertAgentChatCommand` → `XpertAgentModule`）。入向 **10 组**，全部为进程内 CQRS 命令/查询注入：

### ① 上传一个文件并启动理解（`ContextsController.create`）

```ts
// 真实调用方：packages/server-ai/src/ai/context.controller.ts
const target = resolveExternalStorageUploadTarget(targetValue, {
    kind: 'storage', directory: 'contexts', prefix: 'files'
})
workspacePath = undefined                      // 上传体里的 workspacePath 被显式忽略
const conversation = await this.resolveConversationReferences(conversationId, threadId)
// … 会话字段覆盖 projectId/xpertId；@Public 场景只允许 storage target 且禁 projectId
const asset = await this.commandBus.execute(
    new UploadFileCommand({ source: { kind: 'multipart', file }, targets: [target] })
)
const destination = getFileAssetDestination(asset, target.kind)
if (!destination || destination.status !== 'success') {
    throw new BadRequestException(destination?.error || `Failed to upload context file to target '${target.kind}'`)
}
if (target.kind === 'storage') {
    const storageFile = getStorageFileFromAsset(asset)
    const parseMode = this.resolveParseMode(parseModeValue)
    const fileAsset = await this.commandBus.execute<CreateFileAssetCommand, FileAsset>(
        new CreateFileAssetCommand({
            storageFile, uploadedFile: file, purpose: purposeValue ?? 'chat_attachment',
            parseMode, conversationId, threadId, projectId, xpertId, workspacePath
        })
    )
    const parsedAsset =
        parseMode === 'none'
            ? fileAsset
            : await this.commandBus.execute<EnqueueFileParseCommand, FileAsset>(
                  new EnqueueFileParseCommand(fileAsset.id, {
                      runInline: this.shouldRunParseInline(file, parseMode)   // fast→true；deep→false；其余 size ≤ 2MB
                  })
              )
    return this.withFileUnderstanding(storageFile, parsedAsset)                 // AgentFile：id == fileId == FileAsset.id
}
```

要点：`StorageFile` 仍被创建（对象存储兼容），但对客户端与 Agent 的句柄一律是 `FileAsset`；`parseMode==='none'` 时**不投递 Enqueue**，解析链完全不启动。

    const { project } = await this.projectAccessService.assertCanPurge(projectId)
    const { asset } = await this.fileAssetAccessService.resolve({ /* … operation: 'read' */ })
    if (asset.projectId !== project.id || asset.tenantId !== project.tenantId) {
        throw new ForbiddenException(t('server-ai:Error.ProjectPurgeFileMismatch', { /* … */ }))
