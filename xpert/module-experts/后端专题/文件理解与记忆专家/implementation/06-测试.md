## 二、运行方式

两包各自独立配置，`preset: '../../jest.preset.js'`；`moduleNameMapper` 把 `@xpert-ai/server-core`、`@xpert-ai/contracts`、`@xpert-ai/plugin-sdk` 直指源码（免构建）；transform 为 ts-jest（`tsconfig.spec.json`）＋ babel-jest。**无全局 setup/setupFiles**。

```bash
# 1) 文件理解（server-ai）
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --runTestsByPath packages/server-ai/src/file-understanding/file-understanding.controller.spec.ts

# 2) 文件记忆（server-ai）
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --runTestsByPath packages/server-ai/src/file-memory/file-memory.service.spec.ts

# 3) storage-file 必须切到 server 包配置（其 moduleNameMapper 只映射 contracts，spec 内 jest.mock 的是 ../core/* 相对路径）
node node_modules/jest/bin/jest.js --config packages/server/jest.config.ts \
  --runTestsByPath packages/server/src/storage-file/storage-file.service.spec.ts

# 4) 按目录与用例名过滤
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --testPathPattern 'src/(file-understanding|file-memory)/' -t 'FileAssetAccessService'

# 5) Nx 方式（项目名已核实为 server-ai）
corepack pnpm exec nx run server-ai:test --skipNxCache --runInBand
```

## 三、断言与 mock 风格

- **纯手工构造 ＋ 全 mock（主流）**：`file-asset-access.service.spec.ts` 直接 `new FileAssetAccessService(...)` 注入 fake repository/service（`conversationFileLinkRepository`、`storageFileService.findOneInOrganizationOrTenant`、`projectAccessService.assertCan*`），并用 `jest.requireActual` 保留真实 server-core 后仅替换 `RequestContext`。
- **控制器级「授权先于执行」**：`file-understanding.controller.spec.ts` 用 `jest.mock` 桩掉 `@xpert-ai/server-core` 的装饰器与 guard 类，再以 `it.each` 逐 operation 断言 `resolve` 入参（read/parse/delete），并断言拒权时 `queryBus.execute` **从未被调用**；公共 Xpert 会话分支用 `jest.Mock` 切换 `getPublicXpertSessionConversationScope`。
- **真实类 + 假仓储（技术主体授权）**：`technical-principal-attachment-access.spec.ts` 双 spy `server-core` 与 `plugin-sdk` 的 `RequestContext`，用真实 `PublishedXpertAccessService` ＋ 假 query builder 验证 attachment 授权路径。
- **真实文件系统**：`file-workspace-projection.service.spec.ts` mock `@xpert-ai/server-config` 的 `environment`，用 `fsPromises`＋`os.tmpdir()` 真读写并断言投影字节/冲突；`file-memory.service.spec.ts`、`dream.service.spec.ts` 同样 `mkdtemp` 真库（断言 `MEMORY.md` 含相对路径、signals JSONL 的 `explicit_write`/`recall_hit`、usage 计数、`.dream/runs/<id>/output/gate.json`）。
- **解析器：mock loader ＋ 子类桩**：`pdf.parser.spec.ts` mock `PDFLoader`、以 1px PNG 作字节夹具，并**继承覆写** `createPdfToImageDocument/getStorageProvider` 断言 `putFile`；`office.parser.spec.ts` mock Docx/PPTX loader 与 `createRequire` 的 compound 提取器，覆盖「DOCX 文件名下的二进制 Word」等嗅探分支。
- **中间件/工具契约**：`tools/file-understanding.tools.spec.ts` 断言 8 个 `parsed_file_*` 名称**精确列表**且不含旧 `file_*`/`workspace_*` 名称；`file-memory.middleware.spec.ts` 以假 sandbox backend（`globInfo/lsInfo/uploadFiles/downloadFiles`）＋ `xpertFeatures.sandbox.enabled=true` 上下文构造。
- **写回与 Dreamer**：`file-memory.writeback-runner.spec.ts` 断言 user-isolated xpert 的不同用户获得**不同后台槽位**、模型不可用时仍记录 `recordWritebackCandidate`；`xpert-dreamer-invoker.spec.ts` mock `XpertAgentChatCommand` 与 Xpert 仓储，断言 `agentKey`、`options.from='job'`、`store=null` 与「模板不在租户内」报错文案。
- **storage-file**：`jest.mock` 掉 `../core/crud`、`../core/context`、`../file/file-storage/file-storage` 与实体，纯内存断言 owner/ADMIN 删除边界（403 时不调用 `repository.remove`）。

章节来源：[file-understanding.controller.spec.ts](file://packages/server-ai/src/file-understanding/file-understanding.controller.spec.ts)（关键符号：it.each / authorize before executing），[pdf.parser.spec.ts](file://packages/server-ai/src/file-understanding/parsers/pdf.parser.spec.ts)（关键符号：TestPdfFileParser / putFileMock），[file-memory.writeback-runner.spec.ts](file://packages/server-ai/src/file-memory/file-memory.writeback-runner.spec.ts)（关键符号：enqueue / softDrain / recordWritebackCandidate），[storage-file.service.spec.ts](file://packages/server/src/storage-file/storage-file.service.spec.ts)（关键符号：deleteStorageFile / RolesEnum.ADMIN）

## 五、缺口

- **上传→解析→记忆端到端缺失**：没有任何 spec 串起 `contexts/file` 上传 → `Enqueue` → `Parse` → `Index` → 记忆写入；`parse-file-asset.handler.spec.ts` 用 parser 桩验证授权与投影，`enqueue-file-parse.handler`（`setImmediate` 后台与失败仅 warn）**无直接 spec**，`retry-file-parse.handler` 亦无。
- **回收路径未覆盖副作用**：`file-asset-deletion.service.spec.ts` 用 `it.each(['ordinary','purge','wrong-project','denied'])` 只断言仓储删除调用与边界，**未断言页图对象删除、派生目录 `rm`、以及 `StorageFileSubscriber.afterRemove` 删物理文件**（subscriber 无 spec）。
- **权限边界**：`ApiKeyOrClientSecretAuthGuard` 的 client_secret 绑定（含 `ENTERPRISE_XPERT`）无守卫级用例；`XpertGuard` 的缓存命中/失效与 workspace 回落分支无独立断言；`storage-file.controller.ts` 无控制器 spec（`POST /url`、`DELETE :id` 的 HTTP 面未测）。
- **解析器覆盖不均**：仅 text/pdf/office/binary-content 有 spec；`image.parser`（sharp 元数据）、`spreadsheet.parser`（xlsx 表块）、`archive.parser`（unzipper manifest/truncated）与 `FileParserRegistry.getParser` 的 `UnsupportedFileContentError` 均无直接 spec。
- **深度解析与向量**：`file-understanding-vector.service.spec.ts` 覆盖索引/账本/维度校验，但 `parseMode='deep'` 的端到端失败码落库（`metadata.understandingErrorCode`）无集成断言。
- **记忆侧**：`dream.service.spec.ts` 覆盖 coalesced、gate 跳过与 `skipped` 报告保留；但 `cancelRun` 非 queued 分支、`saveDreamConfig` 归一化的边界值、记忆文件 CRUD 的越权路径（xpert.controller 侧）在本域无用例。

章节来源：[file-asset-deletion.service.spec.ts](file://packages/server-ai/src/file-understanding/file-asset-deletion.service.spec.ts)（关键符号：enforces deletion boundary），[file-understanding-vector.service.spec.ts](file://packages/server-ai/src/file-understanding/file-understanding-vector.service.spec.ts)（关键符号：createService / RagCreateVStoreCommand），[dream.service.spec.ts](file://packages/server-ai/src/file-memory/dream.service.spec.ts)（关键符号：coalesced / waitForRunStatus）

## 六、可执行性结论

判定：**✅ 可跑（不实跑，仅给命令与判据）**。判据：

1. 38 个 spec 全部为单元/组件级：Repository、CommandBus/QueryBus、VolumeClient、RagVStore、模型均 mock 或假实现，**不连 PG/Redis/S3**，可直接用第二节命令执行；
2. 两套 jest 配置的 `moduleNameMapper` 直指 workspace 源码，无需先 `nx build`；`server-ai` transform 额外覆盖 `ali-oss/oidc-provider` 等 ESM 包；
3. `storage-file.service.spec.ts` **必须**用 `packages/server/jest.config.ts`（其 mock 目标为 server 包内相对路径，server-ai 配置下无法解析）；
4. 文件系统相关 5 个 spec 依赖 `os.tmpdir()` 可写与 `HOME`（volume 布局默认取 `~/data`），属**环境前置**而非代码缺陷；本域未发现任何 `describe.skip`/known-fail 白名单。
