## 三、存储运维

- **路径约定**：对象存储 key ＝ `<directory>/<tenantId>/<fileName>`（`StorageTargetStrategy` 强制 key 不越出租户目录，越界直接抛错）；上传默认 `contexts/<tenantId>/...`；解析派生输出与 PDF 页图位于 `contexts/<tenantId>/file-understanding/<assetId>/<parseRunId>`（删除侧同构；重放解析会清理旧 run 目录）。LOCAL 卷下物理根为 `assetPublicPath`（缺省 `apps/api/public`），URL 前缀 `environment.baseUrl + '/public'`。
- **记忆与非对象存储文件**：助手卷 `.xpert/memory`（`MEMORY.md` 索引 ＋ 4 类型目录 ＋ `.dream`）；项目卷为共享卷，记忆落 `.xpert/memory/xperts/<xpertId>`；Dream 运行产物 `.dream/runs/<runId>/{evidence,output}`、信号 `.dream/signals`、评分卡 `.dream/scorecards`。路径归一化拒绝 `..` 与绝对路径。
- **清理与配额**：`FileAssetDeletionService.cleanup` 顺序固定：`deleteFileVectors` → 删 anchor → embedding → chunk → artifact → link → asset 行，随后删除页图对象与派生目录 —— **派生目录 `fsPromises.rm` 仅当 `provider.path()` 返回绝对路径（即本地 provider）**，远端 provider 只删 DB 行，会留下孤儿对象。`StorageFileSubscriber.afterRemove` 负责删物理对象（含 thumb），因此删除必须走 `findOne` 后 `remove`（源码注释明写）。**未见 TTL/配额/清理任务**：`storage_file` 有 `deletedAt` 列但删除路径是硬删，表与对象均需自建生命周期策略。
- **去重表维护**：`FileAsset.sha256` 列存在但**无唯一索引、未见写入** ⇒ 去重未实现，重复上传会各建一行资产；`FileEmbedding` 是向量账本（`vectorId` ＋ `collectionName`/`fingerprint`/`dimensions`），删除资产必须走 `deleteFileVectors`，否则向量库/账本孤儿。
- **对象存储切换注意**：历史行 `storageProvider` 落库后不再变化，`FileStorage().getProvider(storageFile.storageProvider)` 按行解析，切换 provider 后旧对象必须保持可读；且 `getProviderInstance` 在 registry 查找失败时会**静默回落内置 LOCAL 实例**（注释「Fall back to built-in providers so bootstrap/tests without Nest context keep working.」），排障时不要据此判断真实 provider。

章节来源：[storage-target.strategy.ts](file://packages/server/src/file/file-upload/strategies/storage-target.strategy.ts)（关键符号：upload / assertContainedInTenantDirectory），[file-asset-deletion.service.ts](file://packages/server-ai/src/file-understanding/file-asset-deletion.service.ts)（关键符号：cleanup / deleteDerivedRootIfLocal / purgeProjectFile），[storage-file.subscriber.ts](file://packages/server/src/storage-file/storage-file.subscriber.ts)（关键符号：afterLoad / afterRemove），[storage-file.service.ts](file://packages/server/src/storage-file/storage-file.service.ts)（关键符号：deleteStorageFile / removeStorageFile），[paths.ts](file://packages/server-ai/src/file-memory/paths.ts)（关键符号：getXpertFileMemoryWorkspacePath / normalizeFileMemoryRelativePath），[file-storage.ts](file://packages/server/src/file/file-storage/file-storage.ts)（关键符号：getProviderInstance）

## 四、解析运维

- **触发链**：上传 → `EnqueueFileParseCommand`（`parseMode='none'` 直接置 `ready`；`runInline` 同步执行；否则 `setImmediate` 后台，失败**仅 `logger.warn`**）→ `ParseFileAssetCommand`（先按 `operation:'parse'` 授权 → `status='parsing'` → 选源（对象存储物理路径或 workspace 卷快照）→ `getParser` → `replaceArtifacts`（先删后存）→ `IndexFileChunksCommand` → 写 `ready/partial` ＋ `capabilities` ＋ `metadata{parser,chunkCount}` ＋ `parsedAt`；异常写 `failed` ＋ `error` ＋ `failedAt` ＋ `metadata.understandingErrorCode`）。**无持久队列、无调度器**（本域 `@Processor/@Cron` 检索 0），进程崩溃即丢任务。
- **重试策略**：HTTP `POST /api/ai/files/:id/parse/retry` 无门禁、直接重放；运行时能力 `retryFileUnderstanding` 有门禁（仅 `failed` 或 `vectorIndexStatus=failed/unavailable`）。重放幂等：解析前删旧 artifacts，索引前删旧 anchors/embeddings/chunks。
- **积压排查**：① `SELECT status, count(*) FROM file_asset GROUP BY status;` —— 长期 `parsing` 多为后台任务丢失；② `file_asset.metadata->>'understandingErrorCode'` 定位 `file_understanding_embedding_unavailable` / `file_understanding_vector_index_failed` / `file_understanding_parse_failed`；③ 对比 `file_chunk` 与 `file_embedding` 行数判断索引是否完整；④ 需要逐文件追日志时抓 `[FILE_VECTOR_DEBUG]`。
- **解析器注册与版本**：`FileParsers` 为静态数组（非插件注册表），升级解析行为＝发布新宿主；PDF 页图走 `createPdfToImageDocument`（可被测试/子类替换）并调用 storage provider 落盘，因此**页图问题优先看 provider 与派生目录**。

章节来源：[enqueue-file-parse.handler.ts](file://packages/server-ai/src/file-understanding/commands/handlers/enqueue-file-parse.handler.ts)（关键符号：setImmediate / Background parse failed），[parse-file-asset.handler.ts](file://packages/server-ai/src/file-understanding/commands/handlers/parse-file-asset.handler.ts)（关键符号：resolveDerivedStorageDirectory / understandingErrorCode / replaceArtifacts / deleteStalePageImageRunDirectories），[file-parser.registry.ts](file://packages/server-ai/src/file-understanding/parsers/file-parser.registry.ts)（关键符号：FileParsers），[file-understanding-vector.service.ts](file://packages/server-ai/src/file-understanding/file-understanding-vector.service.ts)（关键符号：FILE_VECTOR_DEBUG / MAX_EMBEDDING_BATCH_CHARACTERS / resolveEmbeddings）

## 五、记忆运维

- **增长与清理**：记忆是**卷上的 markdown**（非向量库）：`MEMORY.md` 索引 ＋ `user/feedback/project/reference` 目录，frontmatter 带 `usage.confidence/source` 统计；信号以 JSONL 落 `.dream/signals`（读取上限 `MAX_SIGNAL_COUNT=500` 截断）；每次 Dream 在 `.dream/runs/<runId>` 下留 status/evidence/output/validation 产物。**未见任何 TTL 或清理任务** ⇒ `.dream/runs`、signals 与历史记忆文件会持续增长，需自建归档/清理；Dreamer 取证读取上限为 20 会话 / 500 消息 / 200KB。
- **模型依赖**：写回（writeback）需要模型（`getModel`），模型不可用时跳过写回但记录 `recordWritebackCandidate`；Dream 需要配置的 dreamer 助手（`FILE_MEMORY_DREAMER_XPERT_ID` ＋ `FILE_MEMORY_DREAMER_AGENT_KEY`），执行经 `XpertAgentChatCommand`（本域**唯一出站命令**）。
- **沙箱依赖**：记忆读写走 sandbox backend（`XpertSandboxMemoryStore`）；middleware 入口先 `assertFileMemorySandboxFeatureEnabled`（`xpertFeatures.sandbox.enabled === true`），否则抛 `XpertFileMemoryMiddleware requires the xpert sandbox feature to be enabled.`；backend 不可用抛 `Sandbox backend is unavailable for file memory runtime.`
- **并发语义**：Dream 按 scope key（`tenant:project:<projectId>:xpert:<id>` 或 `tenant:<id>[:<userId>]`）串行化；重复触发返回 `coalesced:true`；gate 默认 30 分钟间隔、≥1 条新/改记忆、≥1 个会话，未过时落 `status='skipped'`（**不是错误**）。

章节来源：[types.ts](file://packages/server-ai/src/file-memory/types.ts)（关键符号：FILE_MEMORY_WORKSPACE_PATH / FILE_MEMORY_INDEX_FILENAME / FILE_MEMORY_DREAM_DIR / FileMemoryDreamGateConfig），[sandbox-memory.store.ts](file://packages/server-ai/src/file-memory/sandbox-memory.store.ts)（关键符号：assertFileMemorySandboxFeatureEnabled / XpertSandboxMemoryStore.require / ensureRoot），[dream.service.ts](file://packages/server-ai/src/file-memory/dream.service.ts)（关键符号：MAX_SIGNAL_COUNT / MAX_SESSION_BYTES / triggerDream / coalesced），[file-memory.service.ts](file://packages/server-ai/src/file-memory/file-memory.service.ts)（关键符号：writeMemory / searchMemory / getMemory / signals），[file-memory.middleware.ts](file://packages/server-ai/src/file-memory/file-memory.middleware.ts)（关键符号：XpertFileMemoryMiddleware）

## 六、迁移与数据库

- 本域（file-understanding / file-memory / storage-file）**无 `migrations/` 目录、无 `.sql` 文件**；共 10 张表（自建 6 + 跨域只读 3 + `storage_file` 1）（file-understanding 7 ＋ file-memory 只读 3 ＋ storage-file 1）由实体定义，DDL 属仓库外发布流程。
- 运行时数据源在 `DB_SCHEMA_SYNC_MODE=external` 时强制 `synchronize:false`（多实例下由单一 schema-sync 任务拥有 DDL）；**不要以 synchronize 兜底建表**。
- 唯一建表证据是测试桩：`chat-conversation/commands/handlers/bind-project.handler.integration.spec.ts` 手工 `CREATE TABLE "file_asset" ("conversationId" varchar NULL);`（最小列，非生产 DDL）。上线前需确认 `file_asset`、`file_artifact`、`file_chunk`、`file_citation_anchor`、`file_embedding`、`conversation_file_link`、`storage_file` 等表已就位，否则表现为运行期 SQL 报错而非启动失败。

## 七、日志与排障入口

| 症状 | 观测入口 | 判据 |
|---|---|---|
| 解析卡住 | `file_asset.status='parsing'`；日志 `Failed to parse file asset <id>: <msg>`（warn） | 无队列 ⇒ 进程重启丢后台任务；需人工重试 |
| 解析失败原因不清 | `file_asset.error` ＋ `metadata.understandingErrorCode` | `embedding_unavailable` = 无 Embedding 模型；`vector_index_failed` = 向量库/索引异常；其余 = `parse_failed` |
| 向量索引/检索异常 | 日志 `[FILE_VECTOR_DEBUG][index:*]`、`[FILE_VECTOR_DEBUG][search:*]`（debug）；`file_embedding` 行数 | `reason=no-vector-target` 表示无 embedding/copilot；`no-indexed-chunks-for-collection` 表示账本与集合不一致 |
| 记忆不生成 | `POST /api/xpert/:id/memory/dream` 的 runId → `GET …/dream/runs/:runId`；日志 `File memory dream skipped for <xpert>/<runId>: …` | gate 未过写 `output/gate.json` 且 `status=skipped`；`coalesced:true` 表示已有同 scope 运行 |
| 记忆工具不可用 | 日志 `[XpertFileMemory] sandbox backend is unavailable for <reason>` | xpert 未开 sandbox feature 或 backend 解析失败 |
| 回收未清 | `provider.path(derivedRoot)` 是否绝对路径；对象存储控制台 | 远端 provider 只删 DB；subscriber 异常被 `console.log` 吞掉，注意控制台裸日志 |
| 上传/删除 403 | `POST /api/ai/contexts/file`、`DELETE /api/storage-file/:id` 响应 | 见第八节 |

## 八、常见故障与处置

| 故障 | 根因（结构事实） | 处置 |
|---|---|---|
| 文件长期停在 `parsing` | 后台解析用 `setImmediate`，无队列/无重试调度，崩溃即丢 | 用 `POST /api/ai/files/:id/parse/retry` 重放；随后补建持久队列（当前不存在） |
| 预览为空而不是 404 | `GetFilePreviewHandler` 查不到 asset 时返回 `null`（HTTP 200）；页图依赖对象存储 key | 先用 `GET /api/ai/files/:id/status` 确认资产存在与 `capabilities`，再核对 provider 与派生目录 |
| deep 模式某文件永远失败 | 租户未启用 Embedding 模型或向量库不可用 | 配置 `AiProviderRole.Embedding` 的 Copilot 后重试；错误码见第七节 |
| Dream 不产生变更 | gate 未过（默认 30min/1 记忆/1 会话）或 dreamer 未配置 | 读 `dream/config` 的 `defaults`，用 env/`PUT dream/config` 调整 gate；补 `FILE_MEMORY_DREAMER_XPERT_ID`/`AGENT_KEY` |
| 记忆工具报 sandbox 错误 | xpert 未启用 sandbox feature 或 sandbox backend 不可用 | 开启 xpert sandbox；核对 `SANDBOX_VOLUME` 等卷配置 |
| 删除后对象仍占用存储 | 远端 provider 仅删 DB 行；派生目录清理仅本地生效 | 对远端 provider 建立对象生命周期规则/手工清理；排障时勿只信 DB |
| 调用文件端点 403 | `FileAssetAccessDenied`（租户/组织/locator/所有权不匹配）；个人 Xpert 卷资产在项目会话未 attach；client_secret 绑定非 ENTERPRISE_XPERT；公共 Xpert 会话主体与资产 owner 不一致 | 按第七节鉴权矩阵逐层核对；项目场景需先显式 attach 形成 `ConversationFileLink` |
| 上传 400 `ExternalUploadTargetInvalid` | 外部上传只允许服务端管理的 storage target（`directory`/`prefix` 不得改动、不得加键） | 去掉自定义 target 或使用受支持的字段 |
