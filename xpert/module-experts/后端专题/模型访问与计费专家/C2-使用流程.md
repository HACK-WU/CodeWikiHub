## ① 申请模型访问并获批

- **业务目标**：普通用户为某个 Copilot 模型申请个人授权，管理员审批后 `user_model_grant` 生效（`model-access` 子域）。
- **调用顺序**：`GET /api/model-access/catalog`（`getCatalog`）→ `POST /api/model-access/requests`（`createRequest`）→ `GET /api/model-access/requests/my` → 管理员 `POST /api/model-access/admin/requests/:id/approve`（`approveRequest`，需 `MODEL_ACCESS_REQUEST_EDIT`）。
- **事务边界**：`createRequest` 先 `processDueGrants` 清过期、再查重，最后单次 INSERT，由「`status='requested'` 且区分 `organizationId` 是否为 NULL」的部分唯一索引兜底；`approveRequest` 全程在 `this.dataSource.transaction` 内，一次写入 grant 与两条 `model_access_event`。
- **预期结果**：`model_access_request` 进入终态；`user_model_grant.status='active'` 并落 `validUntil`、`approvedAt`、`approvedById/Name`、`ownershipScope`、`modelSnapshot`；事件表留痕（`Approved` + `GrantActivated`）。
- **错误处理**：理由缺失 → `ModelAccessRequestReasonRequired`；套餐已含 → `ModelAccessPlanIncluded`；已有有效授权 → `ModelAccessAlreadyGranted`；管理员给本人申请 → 403 `ModelAccessManagerCannotRequest`（`assertRequesterIsNotManager` 命中 `canManageTargetScope`）；目标模型已删 → `closeRequestForSystem(ModelDeleted)` 返回 `null` 而非抛错；重复提交回读既有 pending 申请。
- **真实代码示例**：

```ts
// 用户侧：createRequest(input: TModelAccessRequestCreateInput): Promise<IModelAccessRequest>
await modelAccessService.createRequest({ copilotId, copilotModelId, modelType: AiModelTypeEnum.LLM, reason: 'IDE 内调试需要' })
// 管理侧：approveRequest(id: string, input: TModelAccessRequestApproveInput): Promise<IUserModelGrant | null>
const grant = await modelAccessService.approveRequest(requestId, { validUntil: '2026-12-31', note: '已复核' })
// 到期/撤销：extendGrant(id, { validUntil, note })；revokeGrant(id, { reason })
```

## ② 签发 execution grant 并调用 OpenAI 兼容 / native 协议端点

- **业务目标**：CLI / 沙箱宿主为「一次执行」拿到短时凭据，并以该凭据调用模型端点（`model-execution` 子域）。
- **调用顺序**：宿主 `ModelExecutionGrantService.issue(actor, { conversationId, source, environment, tool, prepare?, deadline?, tokenBudget? })` → shell 场景必须 `prepare: true` 得 `status='pending'` → 备妥私有配置 → `activate(id, actor)` 置 `active` → 客户端以 `Authorization: Bearer xpert-exec-<43 位 base64url>` 调 `POST /api/model-execution/openai/v1/chat/completions`，或 `POST /api/model-execution/openai/v1/responses`、`POST /api/model-execution/anthropic/v1/messages`。
- **事务边界**：`begin` 单事务（`pg_advisory_xact_lock('model-execution:{tenantId}:{ownerId}')` → 悲观锁 grant → 预算/并发/速率判定 → 插入 `model_gateway_call`）；`dispatch` 单事务写一次性栅栏 `dispatchedAt`（此后崩溃不释放预占）；`finish` 单事务落不可变 `usageFact`。
- **预期结果**：调用行 `started` → `finish` 后 `settlement_pending` 且 `usageFact` 落库、`reservedTokens` 归零 → `deliver` 成功写入 `usageDeliveredAt`，账本出现扣减行。`watch` 每 5 秒 `revalidate`，撤销/过期即中断在途请求。
- **错误处理**：`Denied` / `Model` / `Unavailable` → 403（凭据失效、上下文与行内列不等、默认模型被移除、协议不可用）；`Budget` / `RateLimit` → 429；`Invalid` / `BridgeUnsupported` / `ConversationRequired` → 400；每次构造都触发 `recordModelExecution(code)` 事件指标。
- **真实代码示例**：

```ts
// 签发（宿主侧，返回体含一次性明文 secret）
const { id, credential } = await grants.issue(actor, { conversationId, source: { type: 'cli_session', cliSessionId }, environment, tool: { id: 'codex', version: '0.4.1' }, prepare: true })
await grants.activate(id, actor)   // pending → active，不重置准备租约
// 调用（native 端点也接受 x-api-key 头，内部包成 Bearer）
// curl -H 'Authorization: Bearer xpert-exec-...' -d '{"model":"assistant-default","messages":[...]}' /api/model-execution/openai/v1/chat/completions
```

## ③ 为外部集成创建网关 API key、调用 `chat/completions`、处理限流与结算

- **业务目标**：外部集成以 API key 走 OpenAI 兼容入口，调用经网关准入并落到积分账本（`model-gateway` 子域）。
- **调用顺序**：`POST /api/model-gateway/keys`（`createKey(nameValue, lifetime = Days90)`）→ `GET /api/openai/v1/models`（`authenticate` + `listAccessiblePublications`）→ `POST /api/openai/v1/chat/completions`（`authenticate` → `requireCallablePublication` → `startCall` → `executeGatewayChat` → `finishCall`）。
- **事务边界**：`startCall` 单事务（对 Key 属主 `User` 行 `pessimistic_write` → 60 秒窗口计数 + 并发计数 → 插入 `model_gateway_call`，`source='external_api'` 必带 `apiKeyId` + `publicationId`）；`finishCall` 折算 CNY 后调 `recordGatewayUsage`（`sourceReference = model-gateway:<requestId>`），失败经 `recordSettlementFailure` 置回 `settlement_pending`。
- **预期结果**：调用行回写 `inputTokens/outputTokens/totalTokens`、`chargedPoints`、`excessPoints`、结算币种；账本出现 `usage` / `personal_usage` 扣减行；`/api/openai/v1/models` 返回 `{object:'list',data:[{id,object:'model',owned_by:'xpert'}]}`。
- **错误处理**：Key 无效/过期 → 401 `authentication_error`；限流 → 429 `rate_limit_error` 且带 `Retry-After`（`ModelGatewayRequestLimitException.retryAfterSeconds`）；余额/会员不可用 → 429 且 `code='insufficient_quota'`（`ModelGatewayNoRemainingPoints`）；模型不可见 → 404 `ModelGatewayModelNotFound`；不可调用 → 403 `ModelGatewayModelNotCallable`；结算失败由 `@Interval(5 分钟) retryPendingSettlements` 每次重放最旧 100 条。
- **真实代码示例**：

```ts
// createKey(nameValue: string, lifetime = ModelGatewayApiKeyLifetimeEnum.Days90): Promise<IModelGatewayApiKeyCreated>
const key = await gatewayService.createKey('ci-bot', ModelGatewayApiKeyLifetimeEnum.Days30)
// startCall({ identity, publication, resolution, requestBody }) / finishCall({ call, resolution, usage, responseBody? })
// 客户端：curl -H 'Authorization: Bearer sk-xpert-<prefix>-<random>' -d '{"model":"gpt-4o-mini","messages":[...],"stream":true}' /api/openai/v1/chat/completions
```

## ④ 会员计划分配与积分调整

- **业务目标**：管理员为成员分配套餐、调整（个人）积分、续费、暂停、恢复、撤销（`membership` 子域）。
- **调用顺序**：`POST /api/membership/admin/users/:userId/assign` → `adjust-points` → `renew` → `pause` → `resume` → `revoke`；个人额度另有 `adjust-personal-points`，批量走 `POST /api/membership/admin/users/bulk`。全部需 `MEMBERSHIP_EDIT`。
- **事务边界**：`assignUser` / `adjustUserPoints` / `resumeUser` 各自在 `dataSource.transaction` 内执行（并取会员分配锁）；`pauseUser` / `revokeUser` 委托 `changeMembershipStatus` 做单次状态迁移加账本留痕。
- **预期结果**：`user_membership` 状态/额度更新（`active ⇄ paused`、`active → expired`）；`membership_point_ledger` 出现调整类行（`assignment` / `renew` / `upgrade` / `adjustment` / `status_change` / `personal_adjustment`）；`user_membership_period` 按 `(tenantId, sourceReference, sourceSequence)` 追加期次。
- **错误处理**：会员套餐特性未启用 → `assertMembershipPlanFeatureEnabled` 抛错；不在管理范围 → `requireManagedMembership`；退款期次要连续尾段否则 `MembershipRefundTailRequired`；`adjustUserPoints` 零变更被 `requireNonZeroPointDelta` 拒绝；归档套餐不可续费。
- **真实代码示例**：

```ts
await membershipService.assignUser(userId, input)        // assignUser(userId: string, input: TMembershipAssignInput): Promise<UserMembership>
await membershipService.adjustUserPoints(userId, input)  // adjustUserPoints(userId: string, input: TMembershipPointAdjustInput): Promise<UserMembership>
await membershipService.pauseUser(userId); await membershipService.resumeUser(userId); await membershipService.revokeUser(userId)
```

## ⑤ 排查「积分被扣两次 / 未扣」

- **业务目标**：判断同一笔模型调用是否重复入账，或已产生用量但账本缺失。
- **调用顺序**：① 取 `callId` / `attemptId` / `requestId`（`GET /api/model-execution/calls` 或 `admin/pending`）→ ② 按 `sourceReference`（`model-usage-charge:<factId>`、`model-usage-charge:<factId>:personal`、`model-gateway:<requestId>`）与 `gatewayRequestId` 反查账本 → ③ 查 `model_usage_delivery_receipt`（`status`、`completedAt`）→ ④ 有事实未投递：`POST /api/model-execution/admin/calls/:id/retry-delivery`；无事实：取证后 `POST /api/model-execution/admin/calls/:id/reconcile`。
- **事务边界**：`MembershipService.recordUsage` / `recordGatewayUsage` 在 `dataSource.transaction` 内先取锁（`acquireUsageSourceLock` / `acquireGatewayRequestLock`）再查重，命中既有账本直接返回——重复投递不会产生第二行。
- **预期结果**：「双扣」在数据层不可能出现第二条：`IDX_membership_ledger_source_reference`（唯一）与 `UQ_membership_ledger_model_usage_request_metric_revision`（唯一）拒绝重复；「未扣」要么补投递后 `delivered=true`，要么维持 `settlement_pending` + `reservedTokens>0` 走人工对账。
- **错误处理 / 禁忌**：`reconcile` 返回 `status:"applied"` **只证明审计已应用，不等于账本投递完成**，仍须查 `delivered`；runbook 明确禁止「以估算补单、直接改库、手动减去预占」；`no_usage` 必须全零 Token 且填币种；已有事实或已投递的调用不可被改写。
- **真实代码示例**：

```sql
-- 幂等底线（唯一索引）：重复投递在此被拒绝
-- IDX_membership_ledger_source_reference (tenantId, sourceReference)
-- UQ_membership_ledger_model_usage_request_metric_revision (tenantId, providerScopeId, requestId, metricKey, revision)
-- UQ_model_usage_delivery_receipt_request (tenantId, providerScopeId, requestId)
SELECT source, "pointsDelta", "sourceReference", "gatewayRequestId", "usageDeliveredAt" FROM membership_point_ledger WHERE "sourceReference" LIKE 'model-usage-charge:%' OR "gatewayRequestId" = :requestId;
```

## ⑥ 余额不足 / 限额拒绝的排障路径

- **业务目标**：把 429/403 精确归因到「余额、限流、并发、预算快照、权限」之一。
- **调用顺序**：① OpenAI 兼容入口 429 `insufficient_quota` → `requireCallablePublication` 判定 `QuotaExhausted` / `MembershipRequired`（`ModelGatewayNoRemainingPoints`）→ 查 `GET /api/membership/me/overview`、`hasConsumableBalance`；② 429 `rate_limit_error` + `Retry-After` → `GatewayAdmissionPolicy.getAdmissionLimits(tenantId)` 读 `TenantSetting.modelGatewayRequestsPerMinute` / `modelGatewayMaxConcurrentRequests`；③ 执行侧 429 `Budget` / `RateLimit` → 查 `GET /api/model-execution/admin/policy` 的 `limits` 与 grant 的 `limits` 快照（`tightenExecutionLimits` 只收紧）；④ 403 `Denied` / `Model` / `Unavailable` → 凭据上下文失配、默认模型被移除、native 协议未声明。
- **事务边界**：本 Recipe 为只读排障；计费与配额校验发生在 `startCall` / `begin` 的事务内，被拒绝时不产生账本行。
- **预期结果**：定位到唯一根因；`userTokenBudget` 口径 = 同付款人 24 小时内 `source='execution_grant'` 的实际用量 + 全部未释放预占。
- **错误处理**：`excessPoints > 0` 表示「已知但未扣满」，与 `pricingStatus='unpriced'`（未知）不是一回事；`reservedTokens` 只是未知消费占用，不等于实际 Token 或金额；指标 `xpert_model_execution_pending{kind="reserved_tokens"}` 不可相加。
- **真实代码示例**：

```ts
// 余额：hasConsumableBalance(access: MembershipModelAccess): Promise<boolean>
// 单次准入：assertCanUse(input)（内部记录 pointsRemaining 与 assertRateLimits）
// 网关限额：new GatewayAdmissionPolicy(tenantSettingRepository).getAdmissionLimits(tenantId)
```

## ⑦ 新增 provider 与模型（copilot-provider + model discovery + copilot）

- **业务目标**：接入一个模型 Provider，导入/登记模型，再把它绑定给 Copilot 供 Agent 运行时使用（`copilot-provider` / `copilot` 子域）。
- **调用顺序**：`POST /api/copilot-provider`（`CopilotProviderUpsertCommand`，落库前用插件 `provider_credential_schema` 校验凭据）→ `GET /api/copilot-provider/:providerId/model-discovery`（`discover` 预览，标记 `configured`）→ `POST /api/copilot-provider/:providerId/model-discovery`（`importModels`）→ 手工模型走 `POST /api/copilot-provider/:providerId/model`（`upsertModel`）→ 绑定 Copilot：`POST /api/copilot` / `PUT /api/copilot/:copilotId`（`COPILOT_EDIT`）设置 `copilotModelId`。
- **事务边界**：`importModels` 在事务内 `pessimistic_write` 锁 provider 行，只追加不更新已有行，并原子写回 `provider.options.modelDiscovery`；`upsertModel` 写入时把 `configuration_source` 固定为 `manual`。
- **预期结果**：`copilot_provider` / `copilot_provider_model` 落库且 `isValid` 为真；`copilot_model` 通过 `copilotModelId` 与 Copilot 绑定；运行时由 `CopilotModelGetChatModelHandler` 按 provider → 自定义模型 `modelProperties` → 参数规则的优先级合并。
- **错误处理**：凭据校验失败则一行都不落库；导入入参非法 → 400 `ModelDiscoverySelectionInvalid`；继承租户级 provider 时不可在非编辑组织内使用其凭据；改名或换模型类型会调 `ModelAccessService.handleConfiguredModelDeleted` 关闭历史授权。
- **真实代码示例**：

```ts
// 发现与导入（控制器路由 @Controller(':providerId/model-discovery')，均需 COPILOT_EDIT）
// GET  /api/copilot-provider/:providerId/model-discovery
// POST /api/copilot-provider/:providerId/model-discovery   { models: [{ model, configuration }] }
// 自定义模型：CopilotProviderModelService.upsertModel(...)（改名/换类型触发授权回收）
```

## ⑧ 查用量统计

- **业务目标**：管理员看台账与汇总，个人看自身消费。
- **调用顺序**：管理员 `GET /api/copilot-usage/ledger`、`ledger/accounts`、`ledger/models`、`ledger/providers`、`ledger/totals`、`GET summary|totals|overview`、`POST details`、`POST quota/adjust|quota/renew`（类级 `MODEL_USAGE_MONITOR`，`repair-organization-usage` 另需 `SUPER_ADMIN`）；个人 `GET /api/membership/me`、`me/overview`、`me/periods`、`me/usage`、`me/usage-summary`、`POST me/details`（`MEMBERSHIP_USE`）。
- **事务边界**：只读查询。`ledger*` 直查 `membership_point_ledger`（`createModelUsageReadQuery` + `LEGACY_USAGE_SOURCES` 兼容谓词）；个人消费由 `USAGE_POINTS_SQL` 以事实行为锚点做反连接去重，避免「事实行 + 扣减行」双计。
- **预期结果**：`ledger*` 返回分页明细与聚合；`summary` 按 dimension 分派 user/model/organization 三种口径；`me/usage` 以 `pointsUsed`、`excessPoints`、`pricingStatus` 呈现本期消费与未知项。
- **错误处理**：读模型对 `unpriced`、缺金额、缺汇率统一返回 `NULL`（前端不得渲染为 0 消费）；`overview` 无时间下限时可能全表分组扫描；`me/details` 固定取前 200 条。
- **真实代码示例**：

```ts
// 管理员：CopilotUsageController.getLedger → service.findModelUsagePage(query, { take, skip })
// 个人：GET /api/membership/me/usage → createMembershipUsageQuery + USAGE_POINTS_SQL（换算率来自 TenantSetting.membershipCnyPerPoint，默认 0.1）
```
