## 专家定位

本专家回答「谁能用哪个模型、以什么凭据调用、这次调用算谁的钱」。它把模型可见性（申请与授权台账）、执行凭据（一次性凭据与准入预占）、对外调用面（OpenAI 兼容与 native 协议）、以及积分账本与会员计划串成一条可审计闭环：任何一次模型调用只有在拿到供应商权威用量事实后才可能产生消费，估算值永远不产生扣费，未知结果只保留占用而不由人工改库释放。

## 何时找这个专家

- 要让某个用户或某个组织「获得某个模型的授权」，或要处理授权申请、审批、延期、撤销。
- 要给 CLI 会话、Agent 调用或 Shell 子执行**发一张模型访问凭据（grant）**，并希望凭据可校验、可中断、可到期。
- 要创建/撤销**网关 API key**，把某个 Copilot 模型发布成对外可调用的 `externalModelId`。
- 要配置或排查**配额与积分**（会员额度、个人积分、超额、限流）以及积分调整入口。
- 要管理**会员计划与周期**（套餐、分配、续费、暂停/恢复、期次与退款）。
- 要查看**用量统计**（模型/用户/组织维度用量、成本、token 台账、请求调用记录）。
- 要**新增 provider 与模型**、配置 provider 凭据、发现并导入远端模型。
- 要排查「调用成功但没有账本行」「预占一直没释放」「429 到底来自限流还是配额」。

## 契约自足声明

本专家的 `C0`（使用总览）+ `C1`（能力契约）+ 三个子专家各自的 `C0`/`C1` 构成完整契约面：**HTTP 端点、服务方法、参数行为语义、错误体、代码示例**均在本层可查，无需再阅读实现层文档即可完成集成与排障；实现细节（算法、私有方法、表结构）不在契约层出现，只在需要定位时按 `file://` 链接回源码。

## 边界

**做什么**

- 授权台账与可见性：模型目录、申请/审批/延期/撤销、到期协调、Copilot 上下线联动。
- 执行凭据与准入：一次性凭据签发与逐请求校验、预算/并发/速率准入与 token 预占、一次性派发。
- 对外调用面：`/api/model-execution/openai/v1`、`/api/model-execution/anthropic/v1/messages` 与 `/api/openai/v1`。
- 用量事实与投递：把权威用量事实投递到既有计费通道，并保留投递对账入口。
- 积分账本、会员计划与周期、配额判定与限流。
- 配置面：provider 凭据、Copilot 与模型配置、模型发现、用量与 checkpoint/知识库存储。

**不做什么**

- 不含对话与会话：会话、消息、线程本体属于批次 3。
- 不含 Agent 执行链：任务调度、工具编排、桌面控制属于批次 4。
- 不含租户/用户本体：租户、组织、用户与权限点定义属批次 1 已建专家（可引用其契约）。
- 不含文件与沙箱：文件存储、沙箱进程与执行宿主属批次 5。
- 不做供应商协议与定价实现：模型清单、参数规则、凭据 schema、价格快照来自模型 Provider 插件。
- 不从请求头或请求体推断租户/组织/付款人：scope 只来自平台身份或自有凭据。

## 已知问题与常见坑

1. **两套 OpenAI 兼容入口混用**
   - 现象：同一段客户端代码换 base URL 后报 `model_execution_failed` 或 `insufficient_quota`，模型名 `assistant-default` 只在其中一侧生效。
   - 触发条件：把网关 API key 用到 `/api/model-execution/openai/v1`，或把执行凭据用到 `/api/openai/v1`。
   - 正确做法：凭据与入口必须配对；`assistant-default` 仅存在于执行侧，网关侧必须使用 publication 的 `externalModelId`。
   - 契约来源：`ModelGatewayOpenAIController.chat`、`ModelExecutionOpenAIController.chat`。
2. **敏感列不显式选取时静默取空**
   - 现象：重试结算或补投递分支像「无事发生」一样跳过，接口返回空占位而无报错。
   - 触发条件：读取默认不返回的敏感列（凭据哈希、加密体、用量事实、结算上下文）时未显式要求选取。
   - 正确做法：走服务方法而非自行查询；确需自定义查询时显式选取这些列，且不要把返回值当作「不存在」的证据。
   - 契约来源：`ModelExecutionMeteringService.finish`、`ModelGatewayService.finishCall`。
3. **GET 设置接口有写副作用**
   - 现象：只读一次 `GET /api/model-gateway/admin/settings` 就产生了新的租户设置记录。
   - 触发条件：租户首次访问该端点。
   - 正确做法：把该端点视为「读并初始化」；审计只读行为时不要据此判断配置曾被人工修改。
   - 契约来源：`ModelGatewayService.getSettings`。
4. **自助查询端点没有权限点，靠三重相等判定**
   - 现象：给账号加了新角色但越权访问仍被拒，或反之担心越权。
   - 触发条件：`/api/model-execution/call-options`、`/calls`、`/revoke-mine` 只依赖租户、组织、用户三者一致且显式拒绝 API principal。
   - 正确做法：不要依赖 `@Permissions` 判断可见性，按调用者上下文断言；新增端点必须复制同样的判定。
   - 契约来源：`ModelExecutionQueryController.list`、`ModelExecutionSessionController.revokeMine`。
5. **预占残留只能经管理端核对释放**
   - 现象：调用早已失败，但用量占位长期不下降，指标里 `reserved_tokens` 居高不下。
   - 触发条件：上游结果未知（worker 丢失、连接中断）后无人处理。
   - 正确做法：走 `admin/pending` 列表拿到项 ID，用 `retry-delivery` 重投或 `reconcile` 提交权威证据；禁止直接改库或手动减预占。
   - 契约来源：`ModelExecutionAdminController.reconcile`、`ModelExecutionAdminController.retry`。
6. **账本唯一性是「一次调用只计一次」的底线**
   - 现象：绕过服务层自行写账本后出现重复扣费或漏扣，且难以回滚。
   - 触发条件：直接以仓储/原生语句写入积分账本表。
   - 正确做法：所有计费写入口只经 `recordUsage` / `recordGatewayUsage`；调用方必须提供稳定的来源标识（幂等键）。
   - 契约来源：`MembershipService.recordUsage`、`MembershipService.recordGatewayUsage`。
7. **定时任务是进程内调度，多副本会并跑**
   - 现象：多副本部署下同一批数据被处理两次，或日志重复刷屏。
   - 触发条件：网关结算重试与留存清理、执行补投递与对账重放、授权到期协调、会员周期结算、检查点清理同时在各副本运行。
   - 正确做法：把这些任务视为「设计为幂等、允许并跑」；排查重复副作用时先看是否同一幂等键被处理两次，而不是假设单副本执行。
   - 契约来源：`ModelGatewayService.retryPendingSettlements`、`ModelAccessSchedulerService.expireDueGrants`、`MembershipPeriodSchedulerService.settleDueMembershipPeriods`。
8. **资格解析路径带自愈写入**
   - 现象：一次 GET 查询后会员/组织范围数据发生变化，复现与审计困难。
   - 触发条件：解析会员与模型访问时命中组织范围不一致或尚未初始化。
   - 正确做法：把这类查询视为可能写库；需要严格控制写副作用时先显式初始化范围，再走只读查询。
   - 契约来源：`MembershipService.findModelAccess`。
9. **向量表未由实体注册**
   - 现象：ORM 视角看不到向量表，但检索功能可用；索引与外键无统一维护点。
   - 触发条件：初次使用向量存储时按运行期语句建表。
   - 正确做法：向量表结构以存储实现为准，不要依赖实体同步；新增维度前先确认已有表定义。
   - 契约来源：`CopilotMemoryStore.ensureTableInDatabase`。
10. **管理员自审被阻断**
    - 现象：管理员给自己提交模型申请直接失败。
    - 触发条件：申请者同时具备该范围的 `COPILOT_EDIT` / `MEMBERSHIP_EDIT` / `MODEL_ACCESS_REQUEST_EDIT`。
    - 正确做法：由另一名有权审批人审批；自动化场景不要试图用管理员账号自审。
    - 契约来源：`ModelAccessService.createRequest`。
11. **native 协议默认关闭**
    - 现象：Responses / Messages 端点返回不可用，但模型在 provider 侧确实支持。
    - 触发条件：租户策略未声明对应 native 协议，或 provider 模型清单未声明 `native_protocols`。
    - 正确做法：两者同时显式声明；仅声明 Chat 桥接协议不等于 native 支持。
    - 契约来源：`ModelExecutionAdminController.setPolicy`、`ModelExecutionNativeController.generate`。
12. **部分 Copilot 读端点无权限点**
    - 现象：登录后即可列出全部 Copilot 配置。
    - 触发条件：读取可用 Copilot 与单个 Copilot 详情。
    - 正确做法：不要把这两个端点当作管理端点使用；需要收敛时在网关层或前端按角色过滤。
    - 契约来源：`CopilotController.findAllCopilots`、`CopilotController.getOne`。
13. **记账可能静默返回「无账本」**
    - 现象：调用成功但查不到账本行，调用方以为落账失败。
    - 触发条件：计费金额为 0、访问来源为自有凭据（direct）、或该范围未启用会员计划。
    - 正确做法：调用方必须显式判断返回值是否为「无账本」，并区分「免费」「未纳管」与「未投递」三种情况。
    - 契约来源：`MembershipService.recordUsage`。
