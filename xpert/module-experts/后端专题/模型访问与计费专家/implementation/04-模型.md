## 1. 实体基类分层

`Model`（构造函数批量赋值，`instanceOf` 已废弃）→ `BaseEntity`（`id uuid` 主键自生成、`createdById/updatedById` 可空 + `createdBy/updatedBy` 关系，外键 `onDelete: RESTRICT`、`createdAt/updatedAt timestamptz`）→ `TenantBaseEntity`（+ `tenant` 关系 `onDelete: CASCADE` 可空、`tenantId` 可空且带 `@Index`）→ `TenantOrganizationBaseEntity`（+ `organization` 关系 `CASCADE` 可空、`organizationId` 可空且带 `@Index`）。同目录另有 `WorkspaceBaseEntity`（附加 `workspaceId`、`publishAt`、`deletedAt` 软删列），本域表未使用。

要点：基类把 `tenantId` / `organizationId` 声明为**可空**，因此「NOT NULL」只在本域实体自己声明的列上（如 `ownerId uuid NOT NULL`）；迁移 SQL 里则统一写成 `NOT NULL REFERENCES tenant(id)` —— 两者口径不同，读表结构时以迁移为准。

## 5. 执行授权与回执表

## 8. 迁移与 seed 惯例

## 10. 已知风险与坑

- **`select:false` 静默 undefined**：`model_execution_grant.credentialHash`、`model_gateway_call.usageFact` / `settlementContext` / `encryptedRequest` / `encryptedResponse`、`model_gateway_api_key.tokenHash` / `encryptedSecret` 都必须显式 `addSelect`；漏写不会报错，只会拿到 `undefined`（`deliver` 与 `retryPendingSettlements` 都靠 `addSelect` 兜住）。
- **`copilot_store_vectors` 未注册**：`copilot-store/vectors/vectors.entity.ts` 整个 `@Entity` 块（含 `@Column(() => 'vector' ...)`）被注释，`CopilotStoreVector` 在仓库中没有任何引用，向量表不会由同步创建。
- **CHECK 约束的互斥代价**：`model_gateway_call` 的 source 只能二选一，插行时必须同时给对 `grantId`（执行授权）或 `apiKeyId` + `publicationId`（外部 API Key），否则被数据库拒绝。
- **`bodyExpiresAt` 留存策略**：只有 `storeBodies=true` 时才写密文请求体并计算过期时间；响应体仅在 `bodyExpiresAt` 存在时加密落库，后续清理依赖网关留存任务，关闭开关不会回删历史密文。
- **`credentialHash` 唯一 + `select:false` 组合**：明文只出现一次（`issue` 返回值），一旦丢失只能重签授权；`xpert-exec-` 前缀与 43 字符正则被 `authenticate` 硬编码，改动格式会使所有在途凭证失效。
- 基类把 `tenantId` / `organizationId` 定为可空，而领域实体与迁移 SQL 又依赖它们做隔离，混用「实体可空 / SQL 非空」口径容易在自定义 DDL 中漏掉 NOT NULL 与外键。
