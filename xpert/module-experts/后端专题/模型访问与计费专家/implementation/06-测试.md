## 测试总览与运行方式

- 本域（model-access、model-execution、model-gateway、membership、copilot 系 10 目录、ai-model）共有 **71** 个测试文件：`.spec.ts` 68 个 + `.test.ts` 3 个。
- 运行器：Jest（Nx target `test` → `@nx/jest:jest`，`jestConfig` 指向 `packages/server-ai/jest.config.ts`）；`displayName: 'server-ai'`，`testEnvironment: 'node'`，TypeScript 经 `ts-jest` + `<rootDir>/tsconfig.spec.json` 转译，`@xpert-ai/contracts`、`@xpert-ai/server-core`、`@xpert-ai/plugin-sdk`、`@xpert-ai/cli-model-profiles` 由 `moduleNameMapper` 指向源码。
- 实测单文件命令（工作目录 `/root/xpert`，耗时 2 秒级）：

```sh
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts --runTestsByPath packages/server-ai/src/model-access/model-access.controller.spec.ts
```

- 也可用 `--testPathPattern` 跑整个子目录；Jest 默认 `testMatch` 同时收集 `*.spec.ts` 与 `*.test.ts`，因此本域 3 个 `.test.ts` 也会被同一配置执行。

## spec 位置与命名惯例

- 与被测文件同目录、同名 + `.spec.ts`（如 `execution-query.controller.spec.ts` 对应 `execution-query.controller.ts`），子模块按其目录分层（`copilot-provider/models/copilot-provider-model.service.spec.ts`、`copilot-user/commands/handlers/check-limit.handler.spec.ts`）。
- 少数历史文件用 `.test.ts` 与短名（`copilot-store/tools.test.ts`、`copilot-store/tests/store.test.ts`、`ai-model/providers.service.test.ts`），断言对象仍是同名服务/模块。
- 集成用例不使用独立目录，而以 `.integration.spec.ts` 或目录内 `testing/` 命名（`model-usage/model-usage-gateway.integration.spec.ts`）；PG 专用用例统一在文件头声明开关变量。
- 领域内被测实体与 DTO 也有独立 spec（`model-access/dto/model-access.dto.spec.ts`、`model-usage-delivery-receipt.entity.spec.ts`、`execution-schema.spec.ts`）。

## 断言与 mock 风格

- **控制器薄壳**：直接 `new XxxController(service as unknown as XxxService)`，service 用字面量对象 + `jest.fn()` 组装，断言「委托调用参数」与返回值透传，`beforeEach` 内 `jest.clearAllMocks()`。
- **权限契约**：用 `Reflect.getMetadata(PERMISSIONS_METADATA, ...)` 与 `Reflect.getMetadata(GUARDS_METADATA, ...)` 反射装饰器元数据，逐个方法校验权限点（`MODEL_ACCESS_REQUEST_VIEW|EDIT`、`MEMBERSHIP_USE`、`MODEL_USAGE_MONITOR`），类级与方法级都覆盖。
- **服务层**：TypeORM `Repository` 以链式 QueryBuilder mock（`createQueryBuilder` 返回自持对象）；`RequestContext.currentUserId` 等上下文用 `jest.spyOn(...).mockReturnValue(...)`；加密相关断言比对 `encryptSecret(...)` 计算结果，并断言 `encryptedSecret` 不出现在对外列表结果里。
- **时间与超时**：`openai-context.spec.ts` 使用假定时器推进到 `MODEL_GATEWAY_UPSTREAM_TIMEOUT_MS` 验证中断路径。
- **模块装配**：`ai-model/providers.service.test.ts` 用 `Test.createTestingModule({ imports: [AIModelModule] }).overrideProvider(AIModelProviderRegistry).useValue(...)` 校验插件 provider 解析。

## env-gated 集成用例与开启方式

- 统一写法：文件头 `const xxx = process.env.<VAR>` 后 `const integration = url ? describe : describe.skip`，未设置环境变量时整块自动跳过，不产生失败。
- 执行 PG（4 个文件）：`execution-admission.integration.spec.ts`、`execution-operations.integration.spec.ts`、`execution-migration.integration.spec.ts`、`execution-grant.lifecycle.spec.ts`。变量 `XPERT_EXECUTION_TEST_DATABASE_URL`；前三个在 `beforeAll` 强制校验库路径以 `/xpert_execution_test_` 开头（`execution-grant.lifecycle.spec.ts` 同样校验），否则抛 `Dedicated test database required`，防止误连应用库。用例自行 `CREATE SCHEMA` 隔离并读取 `model-execution/migrations/*.sql` 建立结构。
- 会员积分投影（1 个文件）：`membership-usage-points.spec.ts`，变量 `XPERT_USAGE_READ_TEST_DATABASE_URL`，以 `default_transaction_read_only=on` 连接只读校验，不建真实表、不写计费数据。
- 网关用量台账（1 个文件）：`copilot-usage/model-usage/model-usage-gateway.integration.spec.ts`，变量 `MODEL_USAGE_TEST_DATABASE_URL`（`const postgres = connectionString ? describe : describe.skip`）。
- 运行示例：`XPERT_EXECUTION_TEST_DATABASE_URL=postgres://.../xpert_execution_test_ci node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts --runTestsByPath packages/server-ai/src/model-execution/execution-admission.integration.spec.ts`。

章节来源：[packages/server-ai/src/model-execution/execution-admission.integration.spec.ts](file://packages/server-ai/src/model-execution/execution-admission.integration.spec.ts)（关键符号：ModelExecutionAdmissionService）、[packages/server-ai/src/membership/membership-usage-points.spec.ts](file://packages/server-ai/src/membership/membership-usage-points.spec.ts)（关键符号：USAGE_POINTS_SQL）、[packages/server-ai/src/copilot-usage/model-usage/model-usage-gateway.integration.spec.ts](file://packages/server-ai/src/copilot-usage/model-usage/model-usage-gateway.integration.spec.ts)（关键符号：MODEL_USAGE_TEST_DATABASE_URL）

## 无测试模块与缺口

- `copilot-organization`、`copilot-knowledge`：目录内无任何 `.spec.ts`/`.test.ts`，控制器行为（超管守卫、批量写入、向量检索）无自动化覆盖。
- `copilot-store`（`tools.test.ts`、`tests/store.test.ts`）与 `ai-model`（`providers.service.test.ts`）只有 `.test.ts`，未覆盖控制器层（如 `AIModelController` 的 `@Public()` 图标端点与 404 分支）。
- `ModelExecutionNativeController` 的 Chat bridge 降级分支、`CopilotController.getOne`/`findAllCopilots` 的「登录用户可读全部配置」现状、`CopilotUserController` 继承端点的无权限状态，均缺少端到端 HTTP 级用例。
- 现有的权限断言集中在装饰器元数据层，属静态契约检查，不能替代守卫在运行时的拒绝路径验证。

## 可执行性结论

- ✅ **可跑**：Jest 配置自包含（源码 alias 映射到同仓 packages），无需先构建产物即可单文件运行；实测命令 2 秒级返回。
- ✅ **无 PG 时自动 skip**：6 个 PG 依赖文件全部走 `describe.skip`，缺失环境变量不报错、不计失败。
- ✅ **未发现未处理的失败用例**：本域未见 `todo`/`xit`/`it.skip` 之外的已知失败记录；集成用例以显式环境变量开关作为唯一前提。
- ⚠️ 注意：PG 用例会创建 schema 与 DDL，必须使用库名以 `xpert_execution_test_` 开头的专用库；`membership-usage-points.spec.ts` 走只读连接，用途不同但同样需要独立库。
