## §1 HTTP 契约

### 1.1 前缀与鉴权基线

| 前缀 | 控制器 | 鉴权基线 |
| --- | --- | --- |
| `/api/copilot` | `CopilotController`（继承 `CrudController`） | 读端点仅登录态；写与 `statistics/*` 需 `COPILOT_EDIT`；`membership-models` 需 `MEMBERSHIP_EDIT` |
| `/api/copilot-provider` | `CopilotProviderController` + `ModelDiscoveryController` | 写与 `model-discovery` 需 `COPILOT_EDIT`；`:id` 与 `:providerId/model*` 仅登录态 |
| `/api/copilot-model` | `CopilotModelController`（纯 `CrudController`） | 仅登录态 |
| `/api/copilot-user` | `CopilotUserController` | 本文件显式声明的端点均需 `COPILOT_EDIT` |
| `/api/copilot-usage` | `CopilotUsageController` | **类级** `PermissionGuard` + `MODEL_USAGE_MONITOR`；`repair-organization-usage` 额外要求 `SUPER_ADMIN` |
| `/api/copilot-organization` | `CopilotOrganizationController` | **类级** `RoleGuard` + `SUPER_ADMIN` |
| `/api/copilot-store` | `CopilotStoreController`（纯 `CrudController`） | 仅登录态 |
| `/api/copilot-checkpoint` | `CopilotCheckpointController` | 无权限点，改为会话访问断言（`read` / `contribute`） |
| `/api/copilot-knowledge` | `CopilotKnowledgeController` | 仅登录态 |
| `/api/ai-model` | `AIModelController` | 图标端点 `@Public()` |

`CrudController` 基类端点（`CopilotModelController` / `CopilotStoreController` 等直接继承、无覆写）的字段与分页约定以 `@xpert-ai/server-core` 的 `CrudController` 契约为准，本文不复制。

### 2.5 存储、检查点与知识库

| 方法 | 用途 | 参数与行为语义 | 返回 | 异常 / 约束 |
| --- | --- | --- | --- | --- |
| `CopilotCheckpointService.getTuple(options)` | 读检查点 | 给了 `checkpoint_id` 则精确取，否则按 `checkpoint_id DESC take 1` 取最新，并拉全部 pending writes | `CheckpointTuple \| null` | 无行返回 `null` |
| `CopilotCheckpointService.upsert(entity)` | 写检查点 | `conflictPaths` 与唯一索引 `(organizationId, thread_id, checkpoint_ns, checkpoint_id)` 一致 | 写入结果 | `organizationId` 可空 → PG 唯一语义下可能重复 |
| `CopilotCheckpointWritesService.upsert(entities)` | 批量写 writes | 事务内逐条序列化后 `upsert` | `void` | 序列化失败即整批回滚 |
| `CopilotCheckpointRetentionService.execute(options?)` | 执行清理 | 循环取候选（`WITH RECURSIVE` 钉住被引用的祖先链、排除仍有 `runControl` 的线程与仍被 `inputCheckpoint` 引用的行），每批在事务内先删 writes 再删 checkpoints；返回计数与 `batchLimitReached` | 执行结果 | 上限 `batchSize(1000) × maxBatchesPerRun(20)` |
| `CopilotCheckpointRetentionService.runScheduledCleanup()` | 定时清理 | `@Cron('0 0 3 * * *')`；先 `pg_try_advisory_lock(840139001)`，拿不到直接跳过（只记 warn）；开关与天数读租户设置，天数受 `MAX_COPILOT_CHECKPOINT_RETENTION_DAYS` 封顶 | `void` | 未开启保留的租户不清理 |
| `CopilotKnowledgeService.getVectorStore(tenantId, organizationId, role)` | 取向量库 | collectionName = `(organizationId \|\| tenantId) + ':' + (role \|\| 'default')`；租户级 embedding Copilot 时退化为 tenant 维度 | 向量库 | 找不到 Embedding 角色 Copilot 抛 `No embedding copilot found`（不静默降级） |
| `CopilotKnowledgeService.similaritySearch(query, options?)` / `maxMarginalRelevanceSearch(query, options?)` | 相似 / MMR 检索 | `options` 含 `role?`、`command`、`k`、`filter`、`score?`；指定 role 命中为空时回退默认 role，并按 `1 - score > (score ?? 0.7)` 过滤 | 命中列表 | 无向量库时返回空 |
| `CopilotKnowledgeService.create` / `update` / `delete` / `createBulk(entities, options)` / `getCommands(options?)` | 知识库 CRUD 与向量同步 | 写路径统一同步 PGVectorStore 并回写 `provider` 与 `vector: true`；`createBulk` 的 `options.clearRole` 会先清同 role 的既有示例 | 实体 / 结果 | 向量同步失败即异常 |
| `CopilotMemoryStore` | LangGraph BaseStore 的 PG 实现 | `ensureTableInDatabase(dimensions)` 用原生 SQL 建 `copilot_store_vectors`；写入用 `ON CONFLICT (prefix, key, field_name) DO UPDATE`；检索用 `copilot_store JOIN copilot_store_vectors` 打分排序 | 存取结果 | `key_in_namespace` 唯一索引不带租户维度（全库 `(prefix, key)` 唯一） |
