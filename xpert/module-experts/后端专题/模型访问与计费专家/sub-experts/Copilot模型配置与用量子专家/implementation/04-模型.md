## 1. 实体基类分层

`Model`（构造函数批量赋值）→ `BaseEntity`（`id uuid` 主键自生成、`createdById/updatedById` 可空 + 关系、`createdAt/updatedAt`）→ `TenantBaseEntity`（+ `tenant` 关系 + `tenantId` 可空且带索引）→ `TenantOrganizationBaseEntity`（+ `organization` 关系 + `organizationId` 可空且带索引）。本子域 11 张表中：4 张配置表 + `copilot_checkpoint` + `copilot_checkpoint_writes` + `copilot_store` + `copilot_knowledge` + `copilot_user` 用 `TenantOrganizationBaseEntity`；`copilot_organization` 与 `model_usage_delivery_receipt` 用 `TenantBaseEntity`（`copilot_organization` 自己再声明 `organization` / `organizationId` 列与关系）。

要点：基类把 `tenantId` / `organizationId` 声明为**可空**，因此「NOT NULL」只出现在实体自己声明的列上；本子域没有 `WorkspaceBaseEntity`（软删 / publishAt）的使用。

## 3. copilot 与 provider 配置表

`copilot`（无自定义索引与唯一约束）

| 列 | 类型 / 默认 | 说明 |
| --- | --- | --- |
| `name` | varchar(100) 可空 | 展示名 |
| `enabled` | bool default false | 只有 true 才进入可用性查询 |
| `role` | varchar(10) 可空 | `AiProviderRole`（Primary/Secondary/Reasoning/Embedding） |
| `showTokenizer` | bool 可空 | 前端开关 |
| `options` | json 可空 | 透传给模型实例 |
| `tokenBalance` | bigint 可空 | `bigintNumberTransformer` 转 Number；作为用户/组织聚合的 `tokenLimit` 来源 |
| `copilotModelId` | varchar 可空（`@RelationId`） | 指向 `copilot_model` |
| 关系 | `modelProvider` OneToOne（`eager`）、`copilotModel` OneToOne（`eager`，`cascade: insert/update/remove/soft-remove/recover`） | 模型随 Copilot 一起写 |

`copilot_model`：`modelType` varchar 可空、`model` 可空、`options` json 可空、`copilot` ManyToOne（`SET NULL`）+ `copilotId`、`referencedModel` 自引用 ManyToOne（`@JoinColumn({ name: 'referencedId' })`）+ `referencedId`。无索引、无唯一约束。

`copilot_provider`：`providerName` 可空、`providerType` 可空、`credentials` **json 明文可空**、`isValid` bool 可空、`options` json 可空、`copilot` OneToOne（`CASCADE`）+ `copilotId`、`models` OneToMany。无索引；`organizationId` 可空是「组织级覆盖租户级」的数据基础，但该唯一性不是在 DB 层保证的，而是 `findVisibleByCopilotIds` 的查询语义。

`copilot_provider_model`：`providerName` 可空、`modelName` 可空、`modelType` varchar 可空、`modelProperties` json 可空、`isValid` bool 可空、`provider` ManyToOne（`CASCADE`）+ `providerId`。无索引；`(providerId, modelName)` 的唯一性只由 `CopilotProviderModelService.upsertModel` 在应用层探测（`findOneByWhereOptions({ modelName, providerId })`）。

## 5. 存储、检查点与知识表

`copilot_store`：`prefix`（varchar NOT NULL）、`key`（NOT NULL）、`value` jsonb NOT NULL、`createdBy` ManyToOne User（`onDelete: 'RESTRICT'`，以 `declare createdBy` 覆写基类关系）。唯一索引 `key_in_org(organizationId, prefix, key)` 与 `key_in_namespace(prefix, key)`——后者不带租户维度，意味着**全库 `(prefix, key)` 唯一**。

`copilot_checkpoint`：`thread_id` varchar(100) NOT NULL、`checkpoint_ns` varchar(1000) NOT NULL、`checkpoint_id` varchar(100) NOT NULL、`parent_id` varchar(100) 可空、`type` varchar(100) 可空、`checkpoint` bytea NOT NULL、`metadata` bytea NOT NULL。索引 `(thread_id, checkpoint_ns, checkpoint_id)` 与唯一索引 `(organizationId, thread_id, checkpoint_ns, checkpoint_id)`；`CopilotCheckpointService.upsert` 的 `conflictPaths` 与后者一致。

`copilot_checkpoint_writes`：`thread_id` / `checkpoint_ns` / `checkpoint_id` NOT NULL、`task_id` varchar(100) 可空、`idx` int 可空、`channel` varchar(100) 可空、`type` varchar(100) 可空、`value` bytea NOT NULL。索引 `(thread_id, checkpoint_ns, checkpoint_id)` 与唯一索引 `(organizationId, thread_id, checkpoint_ns, checkpoint_id, task_id, idx)`。

`copilot_knowledge`：`provider` varchar(100) 可空、`role` varchar(100) 可空、`command` varchar(100) 可空、`input` varchar(10000) 可空、`output` varchar(10000) 可空、`vector` bool default false、`xpert` ManyToOne（CASCADE）+ `xpertId`。无索引。

## 6. 运行期建表（无 `@Entity` 的三张表）

- `copilot_store_vectors`：DDL 来自 `CopilotMemoryStore.CREATE_VECTOR_TABLE`，列 `prefix text NOT NULL`、`key text NOT NULL`、`field_name text NOT NULL`、`embedding $1`（`$1` 被替换为 `vector` 或 `vector(dimensions)`）、`created_at` / `updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP`；`PRIMARY KEY (prefix, key, field_name)`、`FOREIGN KEY (prefix, key) REFERENCES copilot_store(prefix, key) ON DELETE CASCADE`。同名实体的整个 `@Entity` 块在 `vectors/vectors.entity.ts` 中被注释掉，因此 ORM 层没有这张表的元数据。

## 7. 迁移与 seed 惯例

- **本子域没有任何 `.sql` 迁移文件**：`packages/server-ai/src` 下 26 个 `.sql` 全部位于 `agent-invocation`、`model-execution`、`desktop-shell`、`xpert-project` 等目录，`copilot*` 与 `ai-model` 目录内不存在 `migrations/`。11 张注册表依赖 TypeORM 同步建表（`DB_SCHEMA_SYNC_MODE` 非 `external` 时启用 synchronize），3 张向量表依赖运行期 DDL。

## 8. 校验规则

- **HTTP 层**：实体列上的 class-validator 装饰器（`@IsString` / `@IsOptional` / `@IsJSON` / `@IsBoolean` / `@IsNumber`）配合全局校验管道生效；`ModelDiscoveryController` 对导入入参使用 `ZodValidationPipe(modelImportSchema)`，失败转 `ModelDiscoverySelectionInvalid`；参数 `providerId` / `id` 走 `UUIDValidationPipe`。
- **服务层**：`CopilotProviderModelService.upsertModel` 拒绝缺 `modelProperties`（创建时）或缺 `modelName`，`model_configuration` 用 `modelConfigurationSchema.safeParse` 且 `modelType` 必须一致，重名抛 `t('server-ai:Error.ModelNameExists')`；`ModelDiscoveryService.resolve` 校验 provider 的 tenant/organization 与请求上下文相等，否则 `ForbiddenException(ModelDiscoveryProviderScope)`；`CopilotProviderController.findOneModelById` 在 `model.providerId !== providerId` 时抛 `ForbiddenException('Provider model not match')`；`CopilotCheckpointController` 对 `thread_id` 做非空字符串校验（否则 400 `CheckpointThreadRequired`）；`CopilotUsageService.repairOrganizationUsage` 限 `RolesEnum.SUPER_ADMIN`；`CopilotUserService.assertUserUsageGroupInput` 要求 `userId` 与 `provider`。
- **DB 层**：本子域仅有 4 个唯一约束/索引——`UQ_model_usage_delivery_receipt_request`、`key_in_org`、`key_in_namespace`、以及 checkpoint 两张表的 `(organizationId, ...)` 唯一索引；金额/用量列**没有** `CHECK (>= 0)`，也没有唯一键约束聚合行。

## 9. 已知风险

- **`copilot_store_vectors` 未注册**：实体被整块注释，表结构只存在于 `store.ts` 的字符串模板里；`ensureTableInDatabase()` 不传 `dimensions` 时列类型退化为无维度 `vector`，无法建 HNSW 索引，且 `key_in_namespace` 的跨租户唯一会让不同租户写入相同 `(prefix, key)` 直接冲突。
- **凭据明文**：`copilot_provider.credentials` 是 `json` 普通列（无 transformer、无 `select: false`），组织内读租户级 provider 时才靠 `CopilotProviderPublicDto.@Exclude()` 遮挡；任何新增直出路径、日志打印或前端序列化都会泄漏供应商密钥。子域要点称其为「加密列」，源码不支持该结论。
- **聚合列并发更新丢失**：`copilot_organization.upsert` 与 `copilot_user.upsert` 都是「`findOne` → JS 累加 → `save`」，既无行锁也无 `ON CONFLICT DO UPDATE`，且两张表都没有唯一索引兜底；多副本 + 高并发下会出现覆盖写与重复行。`renew` 同样是非原子读改写（`tokenTotalUsed += tokenUsed`，清零当期）。
- **`copilot_user` 缺唯一约束**：注释承诺的唯一键没有落到 DDL，`usageHour` 可空又让「按小时聚合」在 `usageHour IS NULL` 时退化为单行累加；`getUsageSummary` 用 `SUM` + `MAX(tokenLimit)` 兜底，因此重复行只会稀释限额判定。
- **checkpoint 清理窗口**：只 `@Cron('0 0 3 * * *')` 跑一次，单轮最多 `batchSize(1000) × maxBatchesPerRun(20) = 20000` 行；被 `chat_message.outputCheckpoint` 引用链（`WITH RECURSIVE branch_checkpoints`）、仍有 `runControl` 的线程、以及仍被 `inputCheckpoint` 引用的行都会永久保留。清理开关读 `tenant_setting` 的 `copilotCheckpointRetentionEnabled` / `copilotCheckpointRetentionDays`（受 `MAX_COPILOT_CHECKPOINT_RETENTION_DAYS` 封顶），未开启的租户不会清理。
- **`organizationId` 可空 + 唯一索引语义**：`copilot_checkpoint` / `copilot_checkpoint_writes` / `model_usage_delivery_receipt` 的唯一索引首列都是 `organizationId`（可空），PG 中 NULL 不参与唯一冲突，tenant 级（无组织）行可能重复。
- **bigint → Number 的精度**：`copilot`、`copilot_organization`、`copilot_user` 都用 `bigintNumberTransformer` 把 bigint 读成 JS `Number`，超出 2^53 的累计 token 会丢精度。
- **`copilot_store.createdBy` 为 RESTRICT**：删除创建过 store 项的用户会被外键拒绝，需要先清理 `copilot_store` 行。
