## 1. 测试总览与运行方式

- 本子域共 **33 个测试文件**：`*.spec.ts` **30 个** + `*.test.ts` **3 个**。分布：`copilot` 6、`copilot-model` 5、`copilot-provider` 4、`copilot-user` 5、`copilot-usage` 6、`copilot-checkpoint` 4、`copilot-store` 2（`.test.ts`）、`ai-model` 1（`.test.ts`）。
- 运行器：Jest。Nx target `server-ai:test` → `@nx/jest:jest`，`jestConfig: packages/server-ai/jest.config.ts`；配置里 `displayName: 'server-ai'`、`testEnvironment: 'node'`、TS 经 `ts-jest` + `<rootDir>/tsconfig.spec.json` 转译，`moduleNameMapper` 把 `@xpert-ai/server-core`、`@xpert-ai/contracts`、`@xpert-ai/plugin-sdk`、`@xpert-ai/cli-model-profiles` 指向同仓源码，因此**不需要先构建产物**。
- 单文件命令（工作目录 `/root/xpert`）：

```sh
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts --runTestsByPath packages/server-ai/src/copilot/copilot.service.spec.ts
```

- 按目录批量：把 `--runTestsByPath <path>` 换成 `--testPathPattern 'packages/server-ai/src/copilot-usage'`。

章节来源：[packages/server-ai/jest.config.ts](file://packages/server-ai/jest.config.ts)（关键符号：moduleNameMapper）、[packages/server-ai/project.json](file://packages/server-ai/project.json)（关键符号：targets.test）

## 3. PG 依赖用例

- **门控型（1 个）**：`copilot-usage/model-usage/model-usage-gateway.integration.spec.ts` 头三行 `const connectionString = process.env.MODEL_USAGE_TEST_DATABASE_URL` + `const postgres = connectionString ? describe : describe.skip`；未设置变量时整块自动跳过、不报失败。用例自建随机 schema（`model_usage_<uuid>`）并用 `EntitySchema` 只建需要的列，不读取任何 `.sql` 迁移文件（本子域没有迁移文件）。

```sh
MODEL_USAGE_TEST_DATABASE_URL=postgres://user:pass@host:5432/xpert_model_usage_test \
  node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --runTestsByPath packages/server-ai/src/copilot-usage/model-usage/model-usage-gateway.integration.spec.ts
```

- **非门控型（1 个，需重点关注）**：`copilot-store/tests/store.test.ts` 在 `beforeEach` 里 `new Pool({ connectionString: 'postgresql://${DB_USER}:${DB_PASS}@localhost:5432/${DB_NAME}' })`，**没有任何 `describe.skip` 或环境变量前置判断**；在没有本机 PG（或未设 `DB_*`）的环境下该文件会直接连接失败。它同时依赖 `import 'dotenv/config'` 读取 `.env`。
- 本子域**不使用** 父域 `model-execution` 的 `XPERT_EXECUTION_TEST_DATABASE_URL`，也不需要库名前缀校验（那是 `model-execution` 的约束）。

## 4. 无测试模块与缺口

- **完全没有测试的模块（4 个）**：`copilot-organization`（11 个文件，0 个 spec/test，`upsert` / `getUsageSummary` / `renew` 三个聚合写入口无覆盖）、`copilot-knowledge`（0 个 spec/test，`similaritySearch` / `maxMarginalRelevanceSearch` / `createBulk` 与向量库同步无覆盖）、`copilot-store` 的 spec 缺位（只有 2 个 `.test.ts`，`CopilotStoreController` / `CopilotStoreService` 的 CRUD 未覆盖）、`ai-model`（只有 1 个 `.test.ts`，未覆盖 `AIModelController` 的 `@Public()` 图标端点与 404 分支）。
- **控制器层缺口**：`CopilotController.findAllCopilots` / `getOne`（无 `@Permissions`，登录用户可读全部 Copilot 配置）没有 HTTP 级用例；`CopilotProviderController` 的 `:providerId/model` 系列无权限端点也没有；`CopilotUserController` 继承自 `CrudController` 的端点同样无覆盖。
- **权限断言只有静态反射**：`copilot.controller.spec.ts` 与 `copilot-usage.controller.spec.ts` 都只校验装饰器元数据，无法证明守卫在运行时确实拒绝；缺一条「无权限时 403」的端到端路径。
- **关键分支靠 mock 绕过**：`get-chat-model.handler.spec.ts` 把 `ensureCopilotModelContextSize` 与 `prepareMessagesForModel` 分别 `jest.mock`，因此 `context_size` 归一化与 vision 消息裁剪在本文件内并不真实执行（分别由 `utils/context-size.spec.ts`、`model-capabilities.spec.ts` 单独覆盖）。
- **`copilot_store_vectors` 的 DDL 无测试**：`ensureTableInDatabase` 生成的 SQL 只在 `store.test.ts` 里被间接触达，且该文件无门控。
- **风险点未覆盖**：`CopilotCheckpointService.upsert` 的 `organizationId` 可空导致的唯一冲突语义、`CopilotOrganizationService.upsert` 的读-改-写并发、以及 provider 凭据的直出路径，都没有对应用例。

## 5. 可执行性结论

- **可跑（配置层已核实）**：Jest 配置自包含，四个 `@xpert-ai/*` 路径都映射到同仓源码，`ts-jest` 直接转译 TS，无需先执行 `build`。**说明：本次核查为只读检索，未实际执行 Jest**；父专家文档 06 记录过同配置下单文件 2 秒级返回，可作为性能参考。
- **PG 用例两分**：`model-usage-gateway.integration.spec.ts` 缺变量自动 skip（不产生失败）；`copilot-store/tests/store.test.ts` **非门控**，会尝试连接 `localhost:5432`，在 CI 缺 PG 时必然失败，建议为其补 `describe.skip` 门控或改用 `MODEL_USAGE_TEST_DATABASE_URL` 风格变量。
- **静态阅读提示的疑似失败**：`copilot-store/tests/store.test.ts` 的 `batchSearchOps` 用例把 `put(['namespace'], 'key1', { profile: ' I am king' })` 的结果断言为 `{ key: 'key1', value: 'value1' }`，与写入值不一致，需实跑确认；该文件的 `batch` 用例仅断言 `toHaveLength`，通过但不校验内容。
- **未发现跳过的用例**：本子域 spec 中未见 `it.skip` / `xit` / `it.todo`（唯一跳过机制是 `model-usage-gateway.integration.spec.ts` 的 `describe.skip` 条件切换）。
- **补齐优先级建议**：① `copilot-organization` / `copilot-knowledge` 补最小单测（聚合 upsert 与向量检索回退分支）；② 给 `copilot` / `copilot-provider` 的无权限读端点补「登录用户 vs 无组织范围」的行为用例或显式加权限并加反射断言；③ 给 `copilot-store/tests/store.test.ts` 加门控；④ 给 `copilot_checkpoint` / `copilot_organization` 的唯一性与并发语义补集成测试（可用同一 `MODEL_USAGE_TEST_DATABASE_URL` 风格开关）。
