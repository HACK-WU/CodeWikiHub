## 子专家定位

本子专家回答「谁能用哪个模型、以什么凭据调用、这次调用怎么被准入与计量」，是父专家「模型访问与计费专家」的执行内核。它把三件事串成一条链：`model-access` 把「谁能用哪个模型」变成可审批、可过期、可撤销的**授权台账**；`model-execution` 把「一次执行」变成只存哈希的**一次性凭据**、DB 级串行化的**准入预占**与**不可变用量事实**；`model-gateway` 把「外部 API Key」变成受 publication 约束的**调用面**。三目录共用同一张 `model_gateway_call` 表与同一个 Execution 出口（`CopilotTokenRecordCommand`），但不持有积分账本本体，也不解析 provider 与 Copilot 配置。

## 三目录分工

| 目录 | 一句话职责 | 关键服务 | 对外入口 |
| --- | --- | --- | --- |
| `model-access` | 可见性解析 + 申请审批 + 授权台账生命周期 + 事件留痕 | `ModelAccessService`、`ModelAccessSchedulerService` | `/api/model-access` |
| `model-execution` | 执行凭据签发与校验 + 准入预占 + 用量事实与投递 + 自助查询与对账 | `ModelExecutionGrantService`、`ModelExecutionAdmissionService`、`ModelExecutionMeteringService`、`ModelExecutionChatService`、`ModelExecutionReconciliationService` | `/api/model-execution`（含 `/openai/v1`、`/anthropic/v1/messages`、`/admin`） |
| `model-gateway` | API Key 生命周期 + publication 可见性 + 限流准入 + 网关调用结算与重试 | `ModelGatewayService`、`GatewayAdmissionPolicy` | `/api/model-gateway`、`/api/openai/v1` |

## 何时找这个子专家

- 要让用户或组织「获得某个 Copilot 模型的授权」，或要处理申请、审批、驳回、撤回、延期、撤销与到期协调。
- 要给 CLI 会话 / Agent Invocation / Shell 子执行**签发模型访问凭据（execution grant）**，并希望凭据可校验、可中断、可续租、可撤销。
- 要排查「凭据为什么被拒」：grant 撤销/过期、上下文不匹配、默认模型被移出可访问集、工具与精确版本不在租户策略里。
- 要排查「调用为什么被拦」：执行侧 `Budget` / `RateLimit` / `Denied` / `Model`，或网关侧 429 限流与 `Retry-After`。
- 要创建、列出、撤销**网关 API key**，或确认某个外部模型名（publication 的 `externalModelId`）当前是否可调用。
- 要接 **OpenAI 兼容入口**或 **native 协议入口**（Responses / Anthropic Messages），需要确认请求白名单、`store:false`、体积上限与错误体形态。
- 要处理「调用成功但预占不释放」「结算失败待重试」「用量事实已落但未入账」，需要走 `admin/pending` / `reconcile` / `retry-delivery`。
- 要调整**执行策略**（`nativeProtocols`、`chatBridgeProtocols`、`gatewayBaseUrl`、`limits`、`cliPermissions`、`tools`）或**网关限流与留存设置**。

## 边界

**做什么**

- 授权台账：模型目录与可见性解析、申请/审批/驳回/撤回/延期/撤销、到期协调、Copilot 上下线与模型删除的联动。
- 执行凭据与准入：一次性凭据签发与逐请求校验、预算/并发/速率准入与 token 预占、一次性派发栅栏、续租与撤销。
- 对外调用面：`/api/model-execution/openai/v1`、`/api/model-execution/anthropic/v1/messages` 与 `/api/openai/v1`，共用同一 `executeGatewayChat` 执行器。
- 用量事实与投递：落不可变事实、幂等投递到既有计费通道、保留投递对账与人工核对入口。
- 网关面：API Key 生命周期、publication 可见性、租户级限流、调用结算与结算补偿、留存取证。

**不做什么**

- **不做积分账本本体与周期结算**：`MembershipService.recordUsage` / `recordGatewayUsage` 与 `MembershipPointLedger` 的唯一索引属于**会员与积分账本子专家**；本子域只产出事实并调用该出口。
- **不做 Copilot / provider 配置解析**：Provider 凭据、模型目录、native 客户端来自 `CopilotModelService`、`AIProvidersService` 与插件 `NativeModelClient`，属于 **Copilot 模型配置与用量子专家**；本子域只消费已解析结果。
- 不执行 Agent/CLI 进程、不做任务调度与桌面控制、不做沙箱。
- 不注册 CQRS 命令处理器：只用 `CommandBus` 出向投递 `CopilotTokenRecordCommand`。
- 不从请求头或请求体推断租户/组织/付款人：scope 只来自平台身份或自有凭据（源码头部注释明确「client scope headers do not select the gateway's tenant or organization」）。
- 不把估算当消费：无权威用量事实时不生成扣费证据，未知结果只保留预占。
- 不提供批量改库入口：状态补偿只由生命周期任务与管理端对账完成。

## 已知问题与常见坑

1. **两套 OpenAI 兼容入口必须与凭据配对**
   - 现象：换 base URL 后报 `model_execution_failed` 或 `insufficient_quota`，虚拟模型 `assistant-default` 只在其中一侧生效。
   - 正确做法：`/api/openai/v1` 只吃 `sk-xpert-…` API key 且模型名必须是 publication 的 `externalModelId`；`/api/model-execution/openai/v1` 只吃 `xpert-exec-…` 执行凭据。契约来源：`ModelGatewayOpenAIController.chat`、`ModelExecutionOpenAIController.chat`（后者不读 `x-api-key`）。
2. **`select:false` 列漏显式选取会静默取空**
   - 现象：补投递、结算重试分支像「无事发生」一样跳过，接口返回空占位且无报错。
   - 正确做法：`usageFact` / `settlementContext` / `encryptedRequest` / `encryptedResponse` / `tokenHash` / `encryptedSecret` 都必须 `addSelect`；不要用服务返回值证明「列不存在」。契约来源：`ModelExecutionMeteringService.deliver`、`ModelGatewayService.authenticate`。
3. **自助查询端点没有 `@Permissions`，靠三重相等判定**
   - 现象：加了角色但越权访问仍被拒，或反之担心越权。
   - 正确做法：`ModelExecutionQueryController` / `ModelExecutionSessionController` 全类无权限装饰器，只依赖 `tenantId` + `organizationId` + `userId` 三者齐备且相等并显式拒绝 API principal；新增端点必须复制同一判定。契约来源：`ModelExecutionQueryController.list`。
4. **`getSettings` / `getOrCreateSettings` 的 GET 有写副作用**
   - 现象：只读一次 `GET /api/model-gateway/admin/settings` 就产生了新的租户设置行。
   - 正确做法：把该端点视为「读并初始化」，审计只读行为时不要据此判断配置曾被人工修改。契约来源：`ModelGatewayService.getSettings`。
5. **读路径普遍带自愈写**
   - 现象：一次 GET 后授权状态或 Key 状态发生变化，复现与审计困难。
   - 正确做法：`getCatalog` / `findMyRequests` 内联跑授权可用性与申请协调，`listMyKeys` / `listAdminKeys` 顺带 `expireDueApiKeys`；需要严格只读时先显式触发协调任务再查询。
6. **预占残留只能经管理端核对释放**
   - 现象：调用早已失败，但 `reserved_tokens` 居高不下。
   - 正确做法：从 `admin/pending` 拿 `items[].id`（数据库 UUID），用 `retry-delivery` 重投或 `reconcile` 提交权威证据；`no_usage` 才释放预占，`provider_usage` 走同一投递路径。禁止直接改库或手动减预占。契约来源：`ModelExecutionAdminController.reconcile`。
7. **定时任务是进程内调度且多数无锁**
   - 现象：多副本部署下同一批数据被处理两次或日志重复。
   - 正确做法：本子域共 **7 个 `@Interval`**（网关 5：结算重试、过期体清理、调用留存清理、Key 过期、stale call 失败化；执行侧 2：`metering.retry`、`reconciliation.retry`）**全部无分布式锁**，只能依赖幂等键；唯一带 Redis 锁的是 `ModelAccessSchedulerService` 的 `@Cron('0 * * * * *')`。
8. **管理员自审被阻断**
   - 现象：管理员给自己提交模型申请直接失败。
   - 正确做法：申请者若在该范围同时具备 `COPILOT_EDIT` / `MEMBERSHIP_EDIT` / `MODEL_ACCESS_REQUEST_EDIT` 之一即抛 `ForbiddenException`（`ModelAccessManagerCannotRequest`），自动化场景不要用管理员账号自审。契约来源：`ModelAccessService.createRequest`。
9. **native 协议默认关闭，需策略与模型清单双声明**
   - 现象：Responses / Messages 返回不可用（`Unavailable`），但 provider 侧确实支持。
   - 正确做法：`policy.nativeProtocols` 与模型 `protocols` 必须同时包含该协议；只声明 `chatBridgeProtocols` 只意味着可走 Chat 桥接，不等于 native 支持。契约来源：`ModelExecutionNativeController.responses`。
10. **native 体积与头透传两条硬上限**
    - 现象：大响应或大请求头触发 `Invalid`，却看不出是客户端问题。
    - 正确做法：非流式上游响应体累计超过 16MB 即判 `Invalid`；仅转发 `anthropic-` 前缀且长度 ≤ 4096 字节的请求头；native 还要求 `input` 为内联形态（`file` / `image` / `input_image` / `document` 等一律 `Invalid`），递归深度上限 64。
11. **两处 429 语义不同**
    - 现象：同一段 429 处理逻辑在两个入口表现不一致。
    - 正确做法：网关限流错误 `code='rate_limit_exceeded'` 且带 `Retry-After`；其它 429（如额度耗尽）`code='insufficient_quota'` 且无 `Retry-After`；执行侧 429 `type='rate_limit_error'` 但 `code` 固定 `model_execution_failed`。
12. **`applied` 不等于已入账**
    - 现象：`reconcile` 返回 `{status:'applied'}` 就以为账本已扣费。
    - 正确做法：`applied` 只证明证据已被应用；正用量仍需确认投递完成（`retry-delivery` 的 `delivered`、或查询接口的 `delivered` 字段）。契约来源：`ModelExecutionReconciliationService.apply`、`ModelExecutionQueryController.list`。
