## §1 HTTP 契约

### 1.1 基线

| 项 | 取值 |
| --- | --- |
| 前缀 | `/api/membership`（`membership.module.ts` 的 `RouterModule.register([{ path: '/membership' }])`） |
| 控制器 | `MembershipController`（`@ApiTags('Membership')` + `@ApiBearerAuth()`） |
| 全局拦截 | 类级 `TransformInterceptor`（响应统一包装） |
| 鉴权 | 每个端点均 `@UseGuards(PermissionGuard)` + `@Permissions(...)`，**无匿名端点** |
| 权限点 | `MEMBERSHIP_USE`（个人视图）/ `MEMBERSHIP_EDIT`（管理面） |
| 校验 | 带 `@UseValidationPipe()` 的端点按 DTO 严格校验（见 §1.4） |

### 1.2 个人视图端点（`MEMBERSHIP_USE`）

| 方法 路径 | 关键参数 | 行为与返回 |
| --- | --- | --- |
| `GET /api/membership/me` | 无 | 本人会员快照（套餐、当期起止、`pointsGranted/Used/Remaining`、个人积分余额、`personalPointsOnly`） |
| `GET /api/membership/me/overview` | `IMembershipUsageQuery` | 概览：活跃天数、token/积分曲线、`topModels` / `topThreads` / `topXperts` |
| `GET /api/membership/me/periods` | 无 | 本人的期次列表（含 scheduled / completed / cancelled） |
| `GET /api/membership/me/usage` | `IMembershipUsageQuery` + `$take` `$skip` | 用量明细分页（`{items, total}`） |
| `GET /api/membership/me/usage-summary` | `IMembershipUsageQuery` + `$take` `$skip` | 分组汇总分页（含 `usageHour` / `usageChannel` / `provider` / `model` / `xpert` 维度） |
| `POST /api/membership/me/details` | body 为 `IMembershipUsageQuery` | 同明细查询，但固定 `take: 200, skip: 0`（不受分页参数影响） |

### 1.4 DTO 校验规则

| DTO | 规则 |
| --- | --- |
| `CreateMembershipPlanDto` | `code` ≤100、`name` ≤255、`level` 非负整数、`status` 取 `MembershipPlanStatusEnum`、`period` 取 `MembershipPeriodEnum`、`includedPoints ≥ 0`、`allowedModels[]`（`provider` ≤100 必填、`model` ≤255 必填、`copilotId?` UUID）、`modelMultipliers[]`（`multiplier ≥ 0`）、`rateLimits[]`（`period` ∈ `hour|day|week|cycle`，`pointLimit > 0`） |
| `MembershipAssignDto` | `planId` 非空、`currentPeriodStart/End` 为 ISO 日期串、`renewalMode` 取枚举、`source` 取 `MembershipSourceEnum`、`note` ≤255 |
| `MembershipPointAdjustDto` | `pointDelta` 为数字且 `maxDecimalPlaces: 3`、`reason?` 字符串 |
| `MembershipPlanReassignDto` | `targetPlanId` 非空 |
| `MembershipAdminUsersQueryDto` | `search` ≤255、`status` 取 `MembershipAdminUserStatusEnum`、`planId` UUID、`expiringBefore` 日期串 |
| `MembershipBulkActionDto` | `userIds` 数组 1~100 且每项 UUID、`action` 取 `MembershipBulkActionEnum`、`planId?` UUID |

## §2 服务契约

### 2.1 记账（唯一写通道）

| 方法 | 用途 | 参数与行为语义 | 返回 | 异常 / 约束 |
| --- | --- | --- | --- | --- |
| `recordUsage(input: RecordUsageInput)` | 调用/会话路径扣减 | 输入字段：`tenantId`（必填）、`organizationId?`、`copilotOrganizationId?`、`userId`、`provider?`、`model?`、`tokenUsed?`、`priceAmount?`、`priceCurrency?`、`settlementAmount?`、`settlementCurrency?`、`exchangeRate?`、`sourceReference?`、`usageHour?`、`xpertId?`、`threadId?`、`copilotId?`、`modelAccess?`。三道短路：金额缺失/非正 → `null`；`accessSource=direct` → `null`；范围未启用会员计划 → `null`。事务内：来源 advisory 锁 → 按 `(tenantId, sourceReference)` 查重命中即返回既有行 → `findModelAccessWithOrganizationSelfHeal(forUpdate)` → Copilot 范围与模型白名单校验 → 倍率乘在 CNY 金额上 → `pointsFromCny` → 落账（先扣会员额度、`synchronizeCurrentPeriodProjection`、写 `usage` 行，缺口再以 `personal_usage` 行二次裁剪） | `MembershipPointLedger \| null` | 超额时账本照记（`chargedPoints` + `excessPoints`），**事务提交后**抛 `ExceedingLimitException`；`personalPointsOnly` 时只写一条 `personal_usage` 行 |
| `recordGatewayUsage(input: RecordGatewayUsageInput)` | 网关路径扣减 | 输入 = `RecordUsageInput` + `gatewayRequestId`（必填）、`gatewayApiKeyId`（必填）、`modelAccess`（必填）；幂等键由服务自造 `model-gateway:<gatewayRequestId>`，先取 `acquireGatewayRequestLock`；命中已有 `gatewayRequestId` 时聚合 `chargedPoints` / `excessPoints` 并返回首行，不写新行 | `{ chargedPoints, excessPoints, ledger }` | 无会员访问时写 `pointsDelta: 0` 但 `excessPoints = pointsUsed` 的「超额证据行」并返回 `{chargedPoints: 0, …}`；其余扣减语义与 `recordUsage` 同构 |

### 2.2 积分调整

| 方法 | 用途 | 参数与行为语义 | 返回 | 异常 / 约束 |
| --- | --- | --- | --- | --- |
| `adjustUserPoints(userId, input)` | 调整会员额度 | 事务内锁会员行、按 `pointDelta` 调整 `pointsGranted`，写调整类账本（`source='adjustment'`） | 会员对象 | `pointDelta` 不得为 0（`requireNonZeroPointDelta`）；`pointsGranted === null`（无限额度）直接拒绝；`reason?` 透传读者 |
| `adjustPersonalPoints(userId, input)` | 调整个人积分 | 事务内取/建个人积分切片（`membershipId` / `planId` 为空）、按 `pointDelta` 调整并写 `source='personal_adjustment'` 账本 | 调整结果（含 `balance`） | 组织范围调用不可用；用户须符合会员资格（`assertMembershipEligibleUser`） |
| `applyPersonalPointsAdjustment(input)` | 幂等个人积分调整（外部/系统） | 以 `sourceReference` 去重：命中既有行则原样返回；否则加 `acquirePersonalPointsSourceLock` 后落账 | 调整结果 | 同一 `sourceReference` 重复投递不重复加分 |
| `synchronizeAssignedPlanPoints(planId)` | 套餐改额度后回填 | 仅对无 `planSnapshot` 的旧会员回填 `pointsGranted` | 更新条数 | 一次性迁移逻辑，保留在 service 内 |

### 2.3 资格与配额判定

| 方法 | 用途 | 参数与行为语义 | 返回 | 异常 / 约束 |
| --- | --- | --- | --- | --- |
| `isMembershipPlanEnabledForScope(scope, manager?)` | **唯一真值来源** | 读 `FeatureOrganization` 上 `FEATURE_MEMBERSHIP_PLAN` 的启停 | `boolean` | 组织与租户开关口径不同，勿混用 |
| `isMembershipPlanEnabled(input?, manager?)` | 按入参/当前范围判定 | 转发 `isMembershipPlanEnabledForScope`（`organizationId` 有值时按组织判定） | `boolean` | 缺省取当前 scope |
| `isMembershipAccessEnabled(input?, manager?)` | 组合开关 | 组织级开启，或组织未开启时回落租户级开启 | `boolean` | 调用前拦截的第一道闸 |
| `hasActiveMembershipPlan(input?, manager?)` | 是否已存在可用套餐 | 统计 active 套餐（含 catalog 派生套餐） | `boolean` | `repository?.count` 缺失时返回 `false` |
| `findModelAccess(input?, manager?, forUpdate?)` | 解析会员与模型访问 | 回落顺序：组织会员 → （组织有 active plan 时）个人积分 → 租户会员 → 租户个人积分；`organizationId` 缺省 `null`（租户范围）；`forUpdate` 缺省 `false` | `MembershipModelAccess \| null` | **解析过程可能推进状态**（激活/续费/置 Expired） |
| `findModelAccessWithOrganizationSelfHeal(input)` | 带组织自愈的解析 | 仅当「请求组织范围与 Copilot 组织范围一致」且访问组织不匹配时触发：先判 `hasMembershipUsePermission`，再 `ensureScopeInitialized` 开户，然后重查一次 | 同 `findModelAccess` | **读调用也可能落库**；被 `assertCanUse` / `recordUsage` / `recordGatewayUsage` 反复调用 |
| `findPersonalPointsAccess(input)` | 纯个人积分访问 | 余额为 0 返回 `null`；否则以默认套餐 + 合成 `fallbackMembership`（`personalPointsOnly: true`、`pointsGranted: 0`）构造，周期由 `resolveFallbackPeriod` 推导 | 访问对象 \| `null` | 合成对象**不是**持久化会员 |
| `hasConsumableBalance(access)` | 是否仍有可用余额 | 无限额度视为可用；额度为 0 时看个人积分 | `boolean` | 不抛异常 |
| `assertCanUse(input, modelAccess?)` | 调用前配额校验 | 输入至少 `tenantId` / `userId`；`organizationId?`、`copilotOrganizationId?`、`xpertId?`、`copilotId?`、`provider?`、`model?` 可选。`accessSource=direct` 或开关关闭 → 直接放行 | `void` | 无访问抛 `ExceedingLimitException('MembershipPlanRequired')`；`pointsRemaining <= 0` 且个人积分为 0 抛 `MembershipPointsLimitExceeded`；末尾执行限流校验 |
| `assertRateLimits(membership, provider?, model?)` | 套餐限流 | 规则按 `provider` / `model` 匹配（支持 `'*'`），窗口起点由 `rateLimitStart(period, currentPeriodStart)` 给出（`hour` / `day` / `week` / `cycle`），统计 `SUM(ABS(pointsDelta))` | `void` | 只统计 `usage` 与 `personal_usage` 两个 source；达到 `pointLimit` 抛 `ExceedingLimitException` |
| `isModelAllowed(plan, provider, model, copilotId?)` / `assertModelAllowed(...)` | 模型白名单 | 遍历 `allowedModels` 做 provider/model/copilotId 匹配，缺 provider/model 视作通配 | `boolean` / `void` | 不匹配时抛错 |
| `resolveModelMultiplier(plan, provider, model)` / `resolveModelMultiplierForPlan(...)` | 倍率解析 | 取首个匹配规则；缺 provider/model 视作通配，`'*'` 亦通配；默认 1 且下限 0 | `number` | 倍率乘在 CNY 结算金额上，再换算积分 |
| `assertCopilotScopeMatches(access, copilotOrganizationId)` | Copilot 组织一致性 | 请求的 Copilot 组织范围必须与访问范围匹配（租户目录例外） | `void` | 不匹配即抛错 |

### 2.4 套餐、周期、续费与退款

| 方法 | 用途 | 参数与行为语义 | 返回 | 异常 / 约束 |
| --- | --- | --- | --- | --- |
| `findPlans()` | 套餐列表 | 需当前 scope 且会员特性已启用 | `MembershipPlan[]` | 未启用特性即拒 |
| `createPlan(input)` / `updatePlan(id, input)` / `archivePlan(id)` / `deletePlan(id)` | 套餐 CRUD | 事务内校验 `code` 唯一、默认套餐唯一、归档套餐不可为默认 | 套餐对象 / `void` | 有在册会员时删除被拒 |
| `reassignPlanMembers(planId, input)` | 成员迁移 | 事务内把源套餐成员改到 `targetPlanId`，逐条写调整账本 | 更新结果 | `targetPlanId === planId` 抛 400 |
| `assignUser(userId, input)` | 分配套餐 | 事务内取/建会员、写 `assignment` 账本；可指定 `currentPeriodStart/End`、`renewalMode`、`source` | 会员对象 | `planId` 必填且必须属于当前 scope |
| `renewUser(userId)` / `pauseUser(userId)` / `resumeUser(userId)` / `revokeUser(userId)` | 单用户状态动作 | 均在事务内加会员分配锁后推进状态并写 `status_change` / `renew` 账本 | 会员对象 | 外部托管会员不被 `pause` / `revoke` 覆写 |
| `applyBulkUserAction(input)` | 批量动作 | 逐用户调用对应动作，收集成功/失败 | `{ succeeded, failed }` 计数 | 单用户失败不中断整批 |
| `findUsableMembership(input, forUpdate?)` | **读即推进** | 到期后：有 `Scheduled` 期次则 `activateScheduledPeriod`；无则 `renewalMode=auto` 走 `renewMembership`，`manual` 置 `Expired` 并写 `status_change` 账本 | 会员对象 \| `null` | 定时结算与实时调用共用同一推进点 |
| `activateScheduledPeriod(...)` | 激活期次 | 旧期置 `Completed` 并落 `pointsUsed`；会员行改 `planId/planSnapshot/currentPeriodStart/End/pointsGranted`；写 `source='renew'` 赠分账本 | 会员对象 | 以 `planSnapshot` 还原套餐，套餐改动不回溯 |
| `renewMembership(...)` | 自动续费 | `pointsUsed` 归零、结转 `pointsTotalUsed`、`pointsGranted = plan.includedPoints`、新建 `sourceReference: null` 的当前期、写 `renew` 账本 | 会员对象 | 套餐已归档时不可续费 |
| `processDueMembershipPeriods(limit = 100)` | 周期结算批处理 | 取 `status=Active` 且 `currentPeriodEnd <= now` 且套餐 `status=Active` 的会员（`take = min(batch*5, 1000)`），逐条事务内加会员分配锁 + `findMembershipForUpdate` 复核 | `{ scanned, settled, skipped, failed }` | 特性未启用时 `skipped++`；单条失败只累加 `failed` |
| `settleDueMembershipPeriods()` | 调度入口 | `@Cron('0 * * * * *')`，Redis 锁 `scheduler:membership-period-settlement`（TTL 5 分钟）内调 `processDueMembershipPeriods()` | `void` | 未获锁整轮跳过；异常只 `logger.error`，不回抛 |
| `appendMembershipPeriods(input)` / `appendMembershipPeriodsInTransaction(...)` | 追加期次 | `count` 限 1~120；`source=external` 必须给 `sourceReference`；同 `sourceReference` 重复请求按 `userId/organizationId/planSnapshot.planId/count` 全等校验后原样返回；首期必须立即开始 | 期次列表 | 幂等；校验不一致即抛错 |
| `upgradeCurrentMembershipPeriod(input)` | 当期升级 | 以 `sourceReference` 去重后按新快照重算当期 | 结果 | 幂等 |
| `reserveFutureMembershipPeriodsForRefund(input)` | 退款第 1 阶段 | `sourceReference` 非空；`pessimistic_write` 锁该来源期次；已存在 `refund_pending` 直接返回；只取 `Scheduled` 且 `periodStart > now` 且为同 membership **连续尾段**的期次，统一置 `RefundPending` | 处理结果 | 非连续尾段抛 `MembershipRefundTailRequired` |
| `finalizeFutureMembershipPeriodsRefund(input)` | 退款第 2 阶段 | 把 `RefundPending` 置 `Cancelled`，写 `source=status_change`、`pointsDelta: 0` 的说明账本 | 处理结果 | 未预留的期次不受影响 |
| `cancelScheduledMembershipPeriod(...)` / `cancelScheduledMembershipPeriods(...)` / `cancelAdminUserPeriod(userId, periodId)` | 单期撤销 | 只允许撤销最后一个 `Scheduled` 期次；外部管理的期次必须由调用方传入一致的 `sourceReference` | 结果 | 顺序不符抛 `MembershipPeriodCancellationOrder`；外部期次缺来源抛 `ExternalMembershipPeriodCancellationRequired` |
| `ensureScopeInitialized(input?, manager?)` | 幂等开户 | 建默认套餐 + 默认会员，返回 scope 状态 | `IMembershipScopeStatus` | 特性未启用且无显式入参时不落库 |
| `ensureTenantDefaultMembership(...)` / `backfillTenantDefaultMembershipBatch(...)` / `backfillOrganizationDefaultMembershipBatch(...)` / `backfillTenantOrganizationDefaultMembershipBatch(...)` | 默认会员回填 | 批次处理，返回 `{ scanned, assigned, nextCursor }`，`nextCursor` 为 `null` 即停止 | 批次结果 | 由 Bull 队列触发（`concurrency: 2`、`attempts: 5`、`backoff: 10_000`、`removeOnComplete: true`） |

### 2.5 锁方法（并发控制契约）

| 方法 | 锁键第二维 | 语义 |
| --- | --- | --- |
| `acquireTenantDefaultPlanInitializationLock` | `tenant-default-membership-plan` | 全部为 `SELECT pg_advisory_xact_lock(hashtext(tenantId), hashtext(<key>))`：**阻塞等待 + 事务结束自动释放**（不是 `try` 版本，无返回值）；连接类型不是 postgres 时方法直接返回、不加锁 |
| `acquireOrganizationDefaultPlanInitializationLock` | `organization-default-membership-plan:<orgId>` | 同上 |
| `acquireTenantDefaultMembershipLock` | `tenant-default-membership:<userId>` | 同上 |
| `acquireMembershipAssignmentLock` | `organization-membership:<orgId>:<userId>`（组织为空时复用租户默认锁） | 同上 |
| `acquirePersonalPointsLock` | `personal-membership-points:<userId>` | 同上 |
| `acquirePersonalPointsSourceLock` | `personal-membership-points-source:<ref>` | 同上 |
| `acquireUsageSourceLock` | `membership-usage-source:<ref>` | 同上，按「来源」串行化同一笔消费 |
| `acquireGatewayRequestLock` | `model-gateway-request:<requestId>` | 同上 |

读取路径的行锁：`findMembershipForUpdate` / `findActiveMembershipForUpdate` / `findManagedMembershipForUpdate` 走 `pessimistic_write`；退款与追加期次在 query builder 上显式 `setLock('pessimistic_write', undefined, ['period'])`。

## §3 代码示例

### ③ 积分调整

```ts
// 会员额度：pointDelta 非零、最多 3 位小数；无限额度会员会被拒绝

})
```
