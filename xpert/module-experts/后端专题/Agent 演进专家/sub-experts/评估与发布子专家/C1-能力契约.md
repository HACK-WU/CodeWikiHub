## §1 HTTP 入口索引

路径前缀 `/api/agent-evolution`；上下文由 `requestScope()`（租户＋组织）与 `commandContext()`（追加 `actorId/actorRole/actorRoleName/approvalAuthority/actorType:'human'`）注入，分页由 `normalizeQuery` 归一（`page` 默认 1、`pageSize` 默认 20、`search` 截断 200、`sort ∈ createdAt|updatedAt|status`、`order` 仅 `ASC` 否则 `DESC`）。

## §3 发布与回滚契约

| 动作 | 前置（顺序） | 写入表 | 指针变化 | job 语义 |
|---|---|---|---|---|
| `install` | `requireHuman` → release 存在且 provider 有 `releaseProvider` → `status === 'approved'` | `release_package.status = 'installed'` | 不动 | **入队**（`jobType install`，并发 1） |
| `shadow` | `requireHuman` → `releaseOperationContext` → `freezeReleaseGatePolicy` → `capabilities.shadow` → `status ∈ {installed, paused}` | 新增 `release_deployment{channel:'shadow', canaryPercent:0}` ＋ `release_package.status='shadow'` | 不动 | **入队**（并发 2） |
| `canary` | `requireHuman` → `percent ∈ {5,25,50}` → `releaseOperationContext` → `freeze` → `capabilities.canary` → 分支门槛：`shadow → 5%` 需 `sampleCount ≥ shadowMinimumSamples` ＋ `severeErrors === 0` ＋ `minimumElapsed`；扩档需 `expectedNext == percent`（`5→25→50`，跳档 400）＋ canary 阈值 | `completeDeployment(上一档)` ＋ 新增 `{channel:'canary', canaryPercent}` ＋ `release_package{status:'canary', canaryPercent}` | 不动 | **入队**（并发 1） |
| `pause` | `requireHuman` → `status ∈ {shadow, canary}`（否则 `Only Shadow or Canary can be paused`） | `release_package.status = 'paused'` | 不动 | **同步**（返回发布包，HTTP 报错即业务拒绝） |
| `activate` | `requireHuman` → `releaseOperationContext` → `freeze` → `status === 'canary'` → 最新 canary 部署 `canaryPercent === 50` ＋ 生产阈值 → **指针 `activeVersionId === release.rollbackVersionId`** | `completeDeployment` ＋ `release_package.status='active'` ＋ 新增 `{channel:'production', canaryPercent:100}` ＋ 审计 `AUD-<pkg>-activate` | `activatePointerCas`：`activeVersionId → targetVersionId`、`rollbackVersionId → 旧 activeVersionId`、`revision + 1` | **同步**（返回新指针） |
| `rollback` | `actorType === 'agent'` 直接 400（`Agents cannot initiate Production rollback`）→ `releaseOperationContext` → `capabilities.rollback` → **指针 `activeVersionId === release.targetVersionId`** | `release_package.status='rolled_back'` ＋ 审计 `AUD-<pkg>-rollback-<rev+1>` | `rollbackPointerCas`：换回 `rollbackVersionId`，`revision` 与 release 状态同时前推 | **入队**（并发 1；`rolled_back` 为**终态**） |

**命名闸门错误**：`AgentEvolutionShadowGateNotSatisfied`（含 `hours`/`samples` 插值）、`AgentEvolutionCanaryGateNotSatisfied`、`AgentEvolutionProductionGateNotSatisfied`、`Canary can start only after Shadow or resume from paused`、`Production activation requires Canary`、`Release is not the active Production version`、`Active Pointer CAS conflict`（**普通 `Error`，5xx 不是 409**）。

**覆盖与回落契约**：`AgentEvolutionCanaryTestOverride` 四连门（人 ＋ `administrator` ＋ `manual_test` 档 ＋ canary 阶段活跃部署）；`activeKey = sha256(tenant:org:deploymentId:subjectKey)` 唯一索引即一次性保证；消费后回落 `deterministicPercent = sha256(deploymentId:subjectKey).readUInt32BE(0)/2^32*100 < deployment.canaryPercent`；`paused`/`rolled_back` 的 release 在 `resolveExecutionPlan` 中**直接跳过**。

## §4 示例

### ① 跑一次评估并判读闸门

```ts
// evaluation-executor.service.ts（剪裁）：每步跑完立刻校验，多步/单步口径不同
// 每个 evaluator 都作用在同一冻结候选上；缺失 assessment 永不被视为通过
for (const step of change.strategy.definition.evaluations) {
    const result = step.kind === 'golden_replay' ? await this.replay(...) : await target.checkEvaluator!.evaluate(...)
    validateChangeEvaluation(change, result, step.requiredChecks)   // 违规 → inconsistent_evaluation_gate
}
const assessment = results.length ? 'tested' : 'not_applicable'    // 「没跑」≠「通过」
const passed = results.every((result) => result.passed)

// quality-governance.service.ts（剪裁）：五项阻塞原因逐条收集
const gate = reviewGoldenReplay(cases, metrics)                    // { passed, decision: 'reject'|'promote', blockingReasons }
```

判读顺序：先看 `assessment` 是否为 `not_applicable`（无步骤即不算通过），再看 `blockingReasons` 是否为空（`golden_dataset_below_50_cases` / `affected_slice_below_20_cases` / `high_risk_slice_below_10_cases` / `severe_errors_present` / `candidate_does_not_improve_baseline`），最后看落库的 `evaluation_run.gatePassed`。

### ② 发布到金丝雀并观测

```ts
// agent-evolution.controller.ts（剪裁）：阶梯是入队，返回 EvolutionJob
startCanary(@Param('releasePackageId') id: string, @Body() body: StartDeploymentRequest) {
    return this.queue.enqueueReleaseOperation(commandContext(), 'canary', id, body)   // → EvolutionJob
}

// agent-evolution-runtime.service.spec.ts（剪裁）：覆盖只生效一次，之后回落确定性路由
const forcedPlan = await service.resolveExecutionPlan({ /* subjectKey, executionId: 'EXEC-1' */ })
expect(forcedPlan.assignments[0]).toMatchObject({ versionId: release.targetVersionId, selectionReason: 'manual_test_override' })
const followingPlan = await service.resolveExecutionPlan({ /* executionId: 'EXEC-2' */ })
expect(followingPlan).toMatchObject({ executionMode: 'production' })
expect(followingPlan.manualTestOverrides).toBeUndefined()
```

要点：`POST /releases/:id/canary` 的 200 只代表**入队受理**；闸门不满足的失败发生在 worker 内（`GET /jobs/:jobId` 的 `errorCode: evolution_job_failed`）。观测经 `recordRuntimeObservation` 回流并累加 `sampleCount` / `severeErrors` / `candidateAccuracy`（`p95LatencyMs` 取 `max`，只增不减）；`severeError` 且 release 处于 shadow/canary 会自动暂停并写审计 `deployment.auto_paused`。

### ③ 回滚并读指针

```ts
// agent-evolution.controller.ts（剪裁）
rollbackRelease(@Param('releasePackageId') id: string) {
    return this.queue.enqueueReleaseOperation(commandContext(), 'rollback', id)       // → EvolutionJob
}

// agent-evolution-governance.service.ts（剪裁）：指针必须仍是本发布的目标版本
// 否则 Release is not the active Production version；CAS 失败 → Active Pointer rollback CAS conflict
// evolution-runtime.store.ts：revision + activeVersionId 条件 UPDATE，affected !== 1 即抛
```

要点：回滚**入队**且拒绝 agent 主体；成功后 `activeVersionId` 指回 `release.rollbackVersionId`（建包时即固定的基线版本），release 置 `rolled_back`（终态），生产部署行不回收，`resolveExecutionPlan` 对 `rolled_back` 直接跳过——**回不到原 canary 档**，只能重走 `install → shadow → canary`；指针变化以 `revision` 单调前推为准，`GET /active-pointers` 读到的才是生效事实。
