## 迁移与 seed 惯例
- 仓库内**没有 `migrations/` 目录**（`packages/server/src` 下不存在 migration 文件），表结构由 TypeORM 驱动：`initializeApplicationDataSource` 在 `DB_SCHEMA_SYNC_MODE !== 'external'` 时先以传入 options（含 `synchronize`）初始化一次落 DDL，再以 `synchronize: false` 重建连接；当 `DB_SCHEMA_SYNC_MODE === 'external'`（常量 `EXTERNAL_SCHEMA_SYNC_MODE`）时完全不做 DDL。
- seed 入口两条链路：`packages/server/src/seed.ts` → `seedDefault({})`；以及 `core/seeds/seed.ts` 的同名函数 → `SeederModule.forPluings()` → `SeedDataService.runDefaultSeed(false)`。`core/seeds/seed-data.service.ts` 还提供 `runAllSeed`、`runTenantSeed(name)`、`runRolePermissionsSeed(tenantName)` 等。
- 模块级 seed：`core/seeds/seed-module.ts` 的 `seedModule(options)` 用 yargs 读取 `--name`/`--tenant`，动态调用 `run<Name>Seed`，方法不存在时打印 `Method xxx not found in SeedDataService` 并返回。
- 本子专家相关 seed 文件：`user/user.seed.ts`（`createDefaultAdminUsers`、`createDefaultEmployeesUsers`、`createDefaultUsers`、`createRandomSuperAdminUsers`）、`user-organization/user-organization.seed.ts`（`createDefaultUsersOrganizations` 会跳过 `SUPER_ADMIN` 用户）、`employee/employee.seed.ts`（`createDefaultEmployees`、`getDefaultEmployees`、`createRandomEmployees`）+ `employee/default-employees.ts`（`DEFAULT_EMPLOYEES`、`DEFAULT_PEANUT_EMPLOYEES`，明文密码 `123456`）、`organization/organization.seed.ts`（`getDefaultOrganization`、`createDefaultOrganizations`）。`role/role.seed.ts` 属角色子专家，本文不展开。
- 启动期也会触发 seed：`bootstrap/index.ts` 调用 `AppService.seedDBIfEmpty()`。
章节来源：[application-data-source.ts](file://packages/server/src/database/application-data-source.ts)、[seed.ts](file://packages/server/src/seed.ts)、[seed-module.ts](file://packages/server/src/core/seeds/seed-module.ts)、[seed-data.service.ts](file://packages/server/src/core/seeds/seed-data.service.ts)、[user.seed.ts](file://packages/server/src/user/user.seed.ts)、[user-organization.seed.ts](file://packages/server/src/user-organization/user-organization.seed.ts)、[default-employees.ts](file://packages/server/src/employee/default-employees.ts)（关键符号：initializeApplicationDataSource、seedDefault、seedModule、SeedDataService.runDefaultSeed）

## 校验规则
- 实体上的 class-validator：`User`（`@IsEmail email`、`@IsMobilePhone mobile`、`@IsAscii`+`@MinLength(3)`+`@MaxLength(20) username`、`@IsEnum(LanguagesEnum) preferredLanguage`）；`Organization`（`@IsNotEmpty name/currency/defaultValueDateType`、`@Min(0)@Max(100) bonusPercentage`）；`OrganizationContact`（`@IsNotEmpty name/primaryEmail/primaryPhone`、`@IsEnum ContactType/ContactOrganizationInviteStatus`）；`OrganizationLanguage`（`@IsNotEmpty name/level`）；`Employee`（`@IsEnum PayPeriodEnum/CurrenciesEnum`、`@IsNumber` 薪率字段、`@IsDate` 日期字段）；`Invite`（`@IsEmail`+`@IsNotEmpty email`、`@IsEnum InviteStatusEnum`）；`UserGroup`（`@IsString name`）；`CreateInviteDTO`（`emailIds`/`roleId`/`invitedById`/`inviteType` 均 `@IsNotEmpty`）。
- DB 级唯一/外键：唯一索引只有 `email_verification.token`、`invite.token`、`invite.email` 与 `user_group` 的部分唯一索引 `IDX_user_group_managed_entity_unique`；`BaseEntity.createdBy/updatedBy` 为 `RESTRICT`，其余业务关系多为一侧 `CASCADE`。**`user.email`/`mobile`/`username` 只有普通索引**。
- 服务级业务校验：`UserService.getIfExistsUser` 查重后由 UserCreateHandler 抛 `BadRequestException(AccountAlreadyExists)`；`UserService.updateProfile` 校验自身/管理权限、`SUPER_ADMIN_EDIT`、禁止改本人角色、拒绝 `UserType.COMMUNICATION`；`UserService.ensureDeleteWithGuards` 禁止删自己/删最后一个管理员；`UserOrganizationService.prepareCreateEntity`（重复成员、首条成员必须 active、default 唯一化）、`ensureActiveMembershipRemains`、删除时"最后一条成员关系"保护；`UserGroupService.validateMemberIds`（用户须同租户且为当前组织 active 成员）；`OrganizationService.delete`（仍有 `INVITED` 邀请或 user_group 时拒绝）；`InviteService.createBulk`（邀请 `SUPER_ADMIN` 角色时邀请者必须是 SUPER_ADMIN，否则 `UnauthorizedException`；已存在有效邀请或已是租户用户则计入 `ignored`）。
章节来源：[user.service.ts](file://packages/server/src/user/user.service.ts)、[user-organization.services.ts](file://packages/server/src/user-organization/user-organization.services.ts)、[user-group.service.ts](file://packages/server/src/user-group/user-group.service.ts)、[organization.service.ts](file://packages/server/src/organization/organization.service.ts)、[invite.service.ts](file://packages/server/src/invite/invite.service.ts)（关键符号：UserService.getIfExistsUser、UserOrganizationService.prepareCreateEntity、UserGroupService.validateMemberIds、OrganizationService.delete、InviteService.createBulk）

## 已知风险与坑
1. `invite.email` 是**全局唯一索引**（不分租户），而 `InviteService.createBulk` 的查重只在当前 `tenantId` 内进行（`existingInviteEmails`、`tenantUsers` 都带 tenantId 过滤）；跨租户重复邀请不会被业务层拦截，会直接撞 DB 唯一约束。
2. `invite_organization_contact` 的语义未定：handler 里写着 `TODO Make invite and contact as one to one, since an invite is not shared by multiple contacts`，接受邀请时只取 `organizationContact[0]` 更新；`createOrganizationContactInvite` 也只写单元素数组。
3. 托管组唯一部分索引只在 `managedBy`/`managedEntityType`/`managedEntityId` 三者都非空时才生效；而 `UserGroupService.create/update` 会 `stripManagedMetadata` 静默删除这三个字段，因此经 HTTP 无法创建托管组，前端传值也不会报错。
4. 软删只覆盖 `user` 表（`deletedAt`）：其 `role` 关系是 CASCADE 硬删、`UserOrganization` 是 CASCADE、`createdBy/updatedBy` 是 RESTRICT；软删后行仍存在，任何基于默认 Repository 查询（自动排除软删）的"活跃成员/是否存在"判断会与历史 FK 数据不一致。
5. **绕过 service 直写仓库会破坏不变量**：默认组织唯一化、"至少一个 active 成员"、"最后一条成员关系不可删"、删除后的默认组织重指派、FeatureUser 缓存版本刷新（`touchCurrentUserFeatureUserCacheVersion`）与 `EVENT_USER_ORGANIZATION_CREATED/DELETED` 事件全部封装在 `UserOrganizationService` 内。
6. `organization` 自身没有 `organizationId` 列（仅 tenant 级），而 `employee`/`invite`/`organization_contact`/`user_group`/`user_organization` 的 `organizationId` 全部 nullable，DB 层不阻止"无组织"数据产生。
7. `profile_link` 无唯一索引，而 `OrganizationService.findByPublicLink` 用 `findOne({ where: { profile_link } })` 对外暴露（`GET /organization/profile/...` 为 `@Public()`），重复链接时命中不确定。
8. 实体内 class-validator 与实际列型不匹配（`OrganizationContact.budget` 标 `@IsString` 却声明 `number`、`Organization.totalEmployees`/`isDefault` 标 `@IsString`），不要把这些注解当作已生效的输入校验。
章节来源：[invite.service.ts](file://packages/server/src/invite/invite.service.ts)、[invite.accept-organization-contact.handler.ts](file://packages/server/src/invite/commands/handlers/invite.accept-organization-contact.handler.ts)、[user-group.service.ts](file://packages/server/src/user-group/user-group.service.ts)、[user-organization.services.ts](file://packages/server/src/user-organization/user-organization.services.ts)、[organization.service.ts](file://packages/server/src/organization/organization.service.ts)（关键符号：InviteService.createBulk、OrganizationService.findByPublicLink、UserGroupService.stripManagedMetadata）
