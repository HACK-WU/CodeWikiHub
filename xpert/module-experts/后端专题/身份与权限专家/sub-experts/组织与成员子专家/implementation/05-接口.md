## 路由前缀与通用端点
- 全局前缀 `api`，并在 `bootstrap/index.ts` 注册全局守卫 `AuthGuard` + `PluginScopeGuard`；因此所有路径实际为 `/api/<模块前缀>/...`，未标注 `@Public()` 的端点都要求认证。
- 各模块用 `RouterModule.register` 声明前缀：`/user`、`/user-organization`、`/user-groups`、`/organization`、`/organization-languages`、`/organization-contact`、`/employee`、`/invite`。
- 下列 controller 都继承 `CrudController`，未被覆盖时继承标准端点：`GET count`、`GET pagination`、`GET /`、`GET my`、`GET :id`、`POST /`、`PUT :id`、`DELETE :id`、`DELETE :id/soft`、`PUT :id/recover`。
章节来源：[bootstrap/index.ts](file://packages/server/src/bootstrap/index.ts)、[crud.controller.ts](file://packages/server/src/core/crud/crud.controller.ts)、[user-group.module.ts](file://packages/server/src/user-group/user-group.module.ts)（关键符号：CrudController、RouterModule.register）

## contact：无对外 HTTP 入口
- `ContactController` 只有 `GET /`（`@Controller()` 无路径 + 类级 `TenantPermissionGuard`），但 `ContactModule` **没有** `RouterModule.register`，且 `ServerAppModule` 的 imports 中未包含 `ContactModule`（`contact/` 只出现在自身文件内被引用）——因此 `contact` 表在本服务**没有任何挂载的 HTTP 路由**，实体与 service 处于未接线状态。

## 错误语义
- **403 判定**：① 守卫层——`PermissionGuard` 在无 `@Permissions` 元数据时直接放行，有元数据但缺少 `currentUser`/`tenantId`/`roleId` 或无匹配权限即返回 false（Nest 转 403），并按 `tenantId_roleId_permissions` 缓存 5 分钟；`TenantPermissionGuard` 要求 `currentUser.tenantId` 存在，且 `env.allowSuperAdminRole === true` 时 `SUPER_ADMIN` 直接放行。② 控制器内手工判定——`UserController.findById`/`update`/`updatePreferredLanguage`/`search` 的自身与他人区分、`UserOrganizationController.requireAccessibleOrganizationId`、`OrganizationController.ensureAccessibleOrganizationId`、`UserGroupService.assertAccessibleOrganizationId` 抛 `ForbiddenException('Cross-organization access requires tenant-level permissions.')` 一类消息。③ 服务层——`UserService.updateProfile`、`ensureDeleteWithGuards`、`UserGroupService.updateMembers` 的越权分支。
- **400 / 唯一约束冲突**：`RequestContext.requireOrganizationScope()` 抛 `BadRequestException('Organization scope is required for this operation.')`；业务唯一性由服务层预检后返回 400（`AccountAlreadyExists`、`User is already a member of this organization.`、`User must have at least one active organization membership.`、`Cannot remove the last organization membership...`、`Some users are not active members of the current organization.`）；模板中的"唯一约束冲突"在多数路径下**表现为 400 而非数据库错误**，只有绕过 service 直写仓库（如跨租户重复 `invite.email`）才会暴露 DB 唯一索引错误。
- **404 场景**：`UserOrganizationService` 的 `Current organization membership was not found.`；`UserGroupService` 的"组织不在当前租户"/"组不存在"；`UserService` 的 `The user '...' was not found`。基类 `CrudController.findById/findAll` 直接返回 service 结果，**未显式抛 `NotFoundException`**。
- 认证失败（缺失/无效凭据）由全局 `AuthGuard` 统一返回 401，`@Public()` 端点（`GET /user/me` 走 ApiKey/ClientSecret 守卫、`GET /invite/validate`、`POST /invite/{employee,user,contact}`、`GET /organization/profile/...`）不受该守卫约束。
章节来源：[permission.guard.ts](file://packages/server/src/shared/guards/permission.guard.ts)、[tenant-permission.guard.ts](file://packages/server/src/shared/guards/tenant-permission.guard.ts)、[request-context.ts](file://packages/server/src/core/context/request-context.ts)、[user-organization.services.ts](file://packages/server/src/user-organization/user-organization.services.ts)、[user-group.service.ts](file://packages/server/src/user-group/user-group.service.ts)（关键符号：PermissionGuard.canActivate、TenantPermissionGuard.canActivate、RequestContext.requireOrganizationScope、UserOrganizationService.resolveRemainingMemberships）
