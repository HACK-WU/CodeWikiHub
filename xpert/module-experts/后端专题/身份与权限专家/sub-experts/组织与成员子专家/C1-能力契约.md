## 0 通用约定

- 全局前缀 `api`，全局 `AuthGuard` + `PluginScopeGuard`；未标 `@Public()` 的端点都要求认证，缺失 / 无效凭据统一 401。
- 各模块用自己的 `RouterModule.register` 声明前缀：`/user`、`/user-organization`、`/user-groups`、`/organization`、`/organization-languages`、`/organization-contact`、`/employee`、`/invite`。
- 除 `InviteController`、`ContactController` 外，其余 controller 都继承 `CrudController`；未被覆盖时提供标准端点：`GET count`、`GET pagination`、`GET /`、`GET my`、`GET :id`、`POST /`、`PUT :id`、`DELETE :id`、`DELETE :id/soft`、`PUT :id/recover`。
- 错误语义总则：403 来自守卫（`TenantPermissionGuard` / `PermissionGuard` / `RoleGuard`）或 controller 内自判；缺少组织范围返回 400（`Organization scope is required for this operation.`）；业务唯一性冲突多数在服务层预检后返回 400，只有绕过服务直写仓储才会命中数据库唯一索引。

## 1 HTTP 接口契约

### 1.1 `/user`

| 方法 / 路径 | 鉴权 | 用途与关键行为 | 主要错误 |
| --- | --- | --- | --- |
| `GET /user/me` | `@Public()` + `ApiKeyOrClientSecretAuthGuard` | 当前登录用户；`?data={"relations":[],"currentOrganizationId":…,"limitOrganizations":…,"select":…}`；relations 进入 feature context / 组织裁剪 / 兜底三个分支之一 | 身份上下文缺失由守卫处理 |

| `GET /user/:id` | `PROFILE_EDIT` / `ORG_USERS_*` / `ALL_ORG_*` + 控制器自判 | 单人详情；非本人须有管理权限或是当前组织的活跃成员 | 三者都不满足 403 |

| `DELETE /user/reset/:id` | `ACCESS_DELETE_ALL_DATA` | 删除该用户全部数据 | — |
| `POST /user/bulk`、`POST /user/bulk/upload` | RoleGuard + `@Roles(SUPER_ADMIN, ADMIN)` | 批量建用户 / CSV 解析为 `IUserCreateInput[]` | 非租户 scope、无文件、非 CSV、解码失败 400 |

## 2 服务能力契约

### 2.1 `UserService`（[user.service.ts](file://packages/server/src/user/user.service.ts)）

1. `findCurrentUser(id: string, relations?: string[], options?: { currentOrganizationId?, limitOrganizations?, select? }): Promise<User>` — 当前用户唯一读取入口。参数语义：`relations` 命中 feature context 白名单时走 feature 分支；`limitOrganizations` 为真时走组织裁剪分支（`organizations` 至多 1 条，优先级 `currentOrganizationId` → `isDefault=true` → `id ASC`，且要求成员与组织都 `isActive`）；否则兜底 `findOne` 并合并核心关系（`employee` / `role` / `role.rolePermissions` / `tenant`）。异常：未命中由底层查询语义决定（多为空 / 404），身份缺失由守卫处理。约束：关系名经过白名单收敛。
2. `getUserByEmail(email: string): Promise<User>` — 邮箱先 trim + 小写；未命中返回 `null`，不抛。约束：`email` 非唯一索引，命中不确定。
3. `getIfExistsUser(user: IUser): Promise<IUser>` — 按 `email` → `mobile` → `thirdPartyId` → `username` 顺序查重，返回首个命中或 `null`。
4. `createOne(user: User): Promise<InsertResult>` — 直接插入，**不做业务查重**（查重由建用户链路负责）；约束：调用方需保证 email / username 业务唯一。
5. `changePassword(id: string, hash: string)` — 仅写入调用方给出的哈希，不做权限与旧密码校验；约束：只能用于已确认身份的链路。
6. `resetPassword(id: string, hash: string, password: string)` — `hash` 为旧密码明文（仅本人路径校验），`password` 为新密码明文（服务内哈希）。异常：用户不存在 404；技术用户 400；非本人且无 `ALL_ORG_EDIT` / `SUPER_ADMIN_EDIT` 403；本人旧密码不匹配 403。
7. `updateProfile(id: ID | number, entity: User): Promise<IUser>` — 本人或 `ALL_ORG_EDIT` / `SUPER_ADMIN_EDIT` 可调；`entity.hash` 会被重新哈希；技术用户、本人改自己 `role` 被拒。异常：403 / 400 / 用户不存在 404。
8. `updatePreferredLanguage(id, preferredLanguage): Promise<IUser>` — 未命中 404。
9. `isActiveMemberOfOrganization(userId: string, organizationId: string): Promise<boolean>` — 超管视为可访问（无成员记录也算），其余用户必须有该组织的 `isActive` 成员关系；tenant 取当前请求上下文。用途：`GET /user/:id` 的可见性判定。
10. `deleteWithGuards(id: string)` — 顺序：护栏（不能删自己；技术用户禁止；必须有 `role`；目标超管需 `SUPER_ADMIN_EDIT`；目标是超管或管理员时同租户其他管理员数必须 > 0）→ 逐条删成员关系（放行最后一条）并发成员删除事件 → 事务内删账号绑定 + 软删用户。约束：软删不物理清除历史引用。
11. `deleteHardWithGuards(id: string): Promise<DeleteResult>` — 只跑同一套护栏后物理删除，**不收敛成员关系、不发成员事件**；契约上与 `deleteWithGuards` 不对称。
12. `ensureCommunicationUser({ tenantId, thirdPartyId, username?, imageUrl?, preferredLanguage? }): Promise<User>` — 幂等创建 `UserType.COMMUNICATION` 技术用户（缺省语言 English、`emailVerified=true`、随机密码）；已存在直接返回（不更新字段）。
13. `search(text, organizationId?, membership?)` — TRIAL 只返回自己；`membership='non-members'` 排除超管并限制 20 条；无 `organizationId` 时按 email / username / 姓名模糊匹配。返回 `IPagination`，items 经公开 DTO 收敛。
14. 内部构建块（不构成对外的可调用契约）：`findCurrentUserBootstrapOrganizations`、`findCurrentUserFeatureContext`、`ensureDeleteWithGuards`、`deleteUserOrganizations`。

### 2.2 `UserOrganizationService`（[user-organization.services.ts](file://packages/server/src/user-organization/user-organization.services.ts)）

1. `ensureMembership({ organizationId, tenantId, userId }): Promise<IUserOrganization>` — 幂等：已存在即原样返回；新建走 `create` 并补发成员创建事件。约束：不区分超管（超管过滤在 `addUserToOrganization`）。
2. `ensureMembershipInTransaction(manager, { organizationId, tenantId, userId }): Promise<{ membership, created }>` — 事务版本幂等；`created=true` 时调用方须在提交后调 `completeMembershipCreation` 补发事件与缓存失效。
3. `completeMembershipCreation({ organizationId, tenantId, userId })` — 提交后补偿：刷新该用户的当前用户缓存版本 + 发成员创建事件。
4. `addUserToOrganization(user: IUser, organizationId: string): Promise<IUserOrganization | IUserOrganization[]>` — **`role.name === SUPER_ADMIN` 时返回 `[]`（不建成员）**；否则委托 `ensureMembership`（tenantId 取 `user.tenantId`）。
5. `findMembershipByUserAndOrganization({ organizationId, tenantId?, userId })` — `tenantId` 缺省取请求上下文，缺失时抛 400（`Tenant context is required.`）；未命中返回 `null`。
6. `findCurrentUserMembership()` — 需要请求上下文的 userId + organizationId，任一缺失返回 `null`（不抛）。
7. `getCurrentUserDefaultWorkspaceId(): Promise<string | null>` / `setCurrentUserDefaultWorkspaceId(defaultWorkspaceId: string | null)` — 读写当前成员 `preferences.defaultWorkspaceId`；无成员关系 404；值未变化直接返回原记录。
8. `markCurrentUserEntryGuideAutoShown(guideKey, autoShownAt = new Date())` — 幂等（已有 `autoShownAt` 直接返回）；无成员关系 404；返回更新后的成员。
9. `create(entity)` — 不变量：`userId` + `organizationId` 必填（否则 400）；同一 `userId + organizationId + tenantId` 重复 400；`isActive` 缺省 `true` 且**首条成员必须活跃**（否则 400）；`isDefault` 缺省 = 「是否首条」，为 `true` 时把该用户其他成员置为非默认；写后刷新缓存版本。
10. `update(id, entity)` — `isActive === false`（且原为 true）先校验删后仍有活跃成员，否则 400（`User must have at least one active organization membership.`）；`isDefault === true` 先做唯一默认化；两者都刷新缓存版本。
11. `delete(criteria, options?: { allowDeletingLastMembership?: boolean })` — 缺省不允许删除最后一条成员关系（400，提示显式删用户）；显式放行时允许清空。若删的是默认成员或剩余成员无默认，则按「优先活跃成员，否则第一条」补位为默认。异常：成员不存在由查询语义决定（404）。
12. `deleteByOrganizationForOrganizationRemoval({ tenantId, organizationId })` — 供组织删除使用：批量删除该组织全部成员 → 对曾拥有默认组织的用户，若剩余成员无默认则重新指派 → 逐用户刷新缓存版本 → 逐条发成员删除事件；无成员时返回 `{ affected: 0 }`。
13. `findUserIdsByOrganization(organizationId): Promise<string[]>` — 返回该组织成员 userId 列表（不区分活跃）。
14. 内部不变量实现（private，不对外）：`ensureUniqueDefault`（同 `userId + tenantId` 只留一条默认）、`ensureActiveMembershipRemains`（排除待删项后必须仍有活跃成员）、`pickNextDefaultMembership`（活跃优先）、`prepareCreateEntity`。契约含义：这些不变量**只能**通过本服务达成，绕过即失效。

### 2.3 `UserGroupService`（[user-group.service.ts](file://packages/server/src/user-group/user-group.service.ts)）

1. `findAllByOrganizationId(organizationId, filter?): Promise<{ items, total }>` — 强制叠加 tenant + organization 过滤；组织不可访问时先抛错。
2. `findByIdsInOrganization(organizationId, ids): Promise<UserGroup[]>` — ids 去重去空；空数组直接返回 `[]`。
3. `resolveAccessibleOrganizationId(organizationId?): Promise<string>` — 无入参时返回 `RequestContext.requireOrganizationScope()`（缺失 400）；有入参时校验：组织必须在当前租户（否则 404）；请求已绑定组织则必须相同（否则 403）；tenant scope 且具备 `ALL_ORG_VIEW` / `ALL_ORG_EDIT` 放行；否则要求当前用户是该组织活跃成员（否则 403）。
4. `updateMembers(id, memberIds: string[], organizationId?): Promise<UserGroup>` — **覆盖式**：最终成员集合等于 `memberIds`（去重），不做增量合并；`organizationId` 缺省取组自身组织，解析后必须与组一致（否则 403）；成员必须同租户（否则 400）且是该组织活跃成员（否则 400）；组不存在 404。返回保存后的组（含 `members`）。
5. `create(entity)` / `update(id, partial)` / `delete(criteria)` / `findAll` / `findOne` — 全部先要求组织范围（缺失 400）；create / update 会剥离 `managedBy`、`managedEntityType`、`managedEntityId`。约束：托管元数据无法经此服务写入，只能由平台侧直写仓储（三列同时非空时受部分唯一索引约束）。
6. 内部实现（private，不对外）：`validateMemberIds`、`assertAccessibleOrganizationId`、`stripManagedMetadata`、`scopeOrganizationFilter`。

### 2.4 `InviteService`（[invite.service.ts](file://packages/server/src/invite/invite.service.ts)）

1. `createBulk(emailInvites: ICreateEmailInvitesInput, languageCode): Promise<{ items, total, ignored }>` — 邮箱归一化（trim + 小写）；先过滤两类「已占用」地址（同租户 `status=INVITED` 且未过期、同租户已存在用户），被过滤部分只计入 `ignored`。`expireDate` 语义：`InvitationExpirationEnum.NEVER` → `null`；显式周期优先；缺省取 `organization.inviteExpiryPeriod` 或 `DEFAULT_INVITE_EXPIRY_PERIOD`。角色为 `SUPER_ADMIN` 时要求邀请者也是 `SUPER_ADMIN`，否则 401。发信只对 `InvitationTypeEnum.USER` 生效（EMPLOYEE 分支不产出发信）。约束：`invite.email` 全局唯一，跨租户查重不生效。
2. `resendEmail(data, invitedById, languageCode, expireDate)` — 改写**同一行**（`status` 重置为 `INVITED`、刷新 `expireDate` / `invitedById` / `token` / `email`）；异常被捕获后作为返回值返回（不抛出），无稳定返回类型；USER 类型才发信。
3. `sendAcceptInvitationEmail(organization, employee, languageCode)` — 给该租户管理员（`SUPER_ADMIN` / `ADMIN`）逐个发送接受通知；异常被吞掉（不向上抛）。
4. `createOrganizationContactInvite(inviteInput): Promise<Invite>` — 建 `INVITED` 记录（过期时间取 `organization.inviteExpiryPeriod` 或默认周期），`organizationContact` 写单元素数组；**发信整段未启用**。约束：一邀请一联系人是约定而非约束。
5. `validateByToken({ email, token }, relations?): Promise<IInvite>` — JWT 验签（`JWT_SECRET`）+ payload.email 必须等于归一化入参 email + `status=INVITED` +（`expireDate >= now` 或 `expireDate IS NULL`）。异常：任何失败统一 400（不区分原因）。
6. `createToken(email): string` — 由归一化 email 生成 JWT（不带过期时间）。

### 2.5 其他服务

- `OrganizationService`（[organization.service.ts](file://packages/server/src/organization/organization.service.ts)）：`findByPublicLink(profile_link, select?, relation?): Promise<Organization>` — 跨租户查找、不做调用方权限校验、`profile_link` 无唯一索引；`delete(criteria, options?)` — 先拒绝「仍有 `INVITED` 邀请」与「仍有 user_group」（400），再收敛成员关系，最后删除；组织不属于当前租户 400；`generateDemo(id, options)` — 委托演示数据生成命令并置 `createdDemo`。
- `EmployeeService`（[employee.service.ts](file://packages/server/src/employee/employee.service.ts)）：`createBulk(input: IEmployeeCreateInput[]): Promise<Employee[]>`（逐个用基类 create，会补 tenant）；`findAllActive()`（当前租户 + `isActive`）；`findWorkingEmployees(organizationId, forMonth, withUser)` 与 `findWorkingEmployeesCount(...)`（按 `startedWorkOn` / `endWork` 与月份区间判定在岗）；`findWithoutTenant(id, relations?)`；`search(text)`（TRIAL 只返回自己，结果经公开 DTO 收敛）。约束：**没有自定义 `create`**，创建语义继承基类。
- `OrganizationContactService`（[organization-contact.service.ts](file://packages/server/src/organization-contact/organization-contact.service.ts)）：`findByEmployee(id, data)`；`findAllOrganizationContacts(data)`（`findInput.employeeId` 存在时转按员工查询）；`getOrganizationContactByEmployee(data)`（按联系人成员或创建人匹配 + `contactType` + 组织 + 租户）。
- `OrganizationLanguageService`（[organization-language.service.ts](file://packages/server/src/organization-language/organization-language.service.ts)）：无专属公开方法（仅基类 CRUD）。
- `ContactService`：无对外 HTTP 入口，无外部模块消费（无此项）。
