# C1 · 能力契约（认证与凭据子专家）

本文件描述本子专家的对外可用契约：HTTP 接口、服务方法、可观察行为与错误语义。所有路径已按源码核实。

## 1. HTTP 接口契约

全局约定：所有路由默认需要认证；标记为「公开」的端点由 `@Public` 旁路全局守卫。`AuthModule` 的路由前缀是 `/auth`，SSO 控制器挂在 `/auth` 之下，因此 SSO 的真实前缀是 **`/api/auth/sso/*`**（不是 `/api/sso`）。

| 方法 | 路径 | 鉴权 / 公开 | 用途 | 关键参数与行为 | 主要错误 |
| --- | --- | --- | --- | --- | --- |
| GET | `/api/auth/authenticated` | 公开 | 校验当前 token 是否可用 | 无参数；读取请求上下文的 token | 无效 token 返回 `false`（不抛错） |
| GET | `/api/auth/alive` | 需登录 | 探活 | 回显当前主体 | 401（全局守卫） |
| GET | `/api/auth/role` | 需登录 | 判断 token 内角色是否命中 | `?roles=` 数组 | 无显式抛错 |
| POST | `/api/auth/login` | 公开 | 登录并签发登录态 | `email`\|`username` + `password`；`tenant-id` 头参与租户过滤，未命中默认租户时回退 | **凭据错误返回 `null`（HTTP 200）** |
| GET | `/api/auth/refresh` | 公开 + `jwt-refresh` | 刷新并轮换登录态 | `Authorization: Bearer <refreshToken>` | 403 `Access Denied` |
| POST | `/api/auth/signup` | 公开 | 自助试用注册 | 注册体 + `Origin` 头；`deploymentTarget = customer-onprem` 时直接拒绝 | 403 `Public signup is disabled for this deployment.`；409 邮箱已存在 |
| POST | `/api/auth/register` | 需登录 | 受控建号 | 注册体 + `Origin` 头；租户以创建者租户为准 | 400 账号已存在（i18n 键）、401 越权创建超级管理员 |
| GET | `/api/auth/verify` | 公开 | 邮箱验证 | `?token=` | 无效 token 由用户服务决定 |
| POST | `/api/auth/resend-verification` | 需登录 | 重发验证邮件 | 当前用户 + 语言；覆盖旧 token，默认 2 天有效 | 无 |
| POST | `/api/auth/request-password` | 公开 | 申请密码重置 | `{ email }` + `origin` 头 | 400 `Forgot password request failed!`、404 `Email is not correct, please try again.` |
| POST | `/api/auth/reset-password` | 公开 | 执行密码重置 | `{ token, password, confirmPassword }`；密码至少 4 位且两次一致 | 400 `Password Reset Failed (code: 1\|2\|3).` |
| GET | `/api/auth/sso/providers` | 公开 | 发现可用 SSO provider | 无参数；按请求侧 baseUrl 描述回调并按顺序返回 | 租户不可解析时返回空列表（不抛错） |
| GET | `/api/auth/sso/bind/challenge` | 公开 | 读取公共绑定挑战 | `?ticket=` | 400 `SSO binding session has expired. Please sign in again.` |
| GET | `/api/auth/sso/bind/current-user/challenge` | 需登录 | 当前用户确认绑定的挑战视图 | `?ticket=` | 401 `Current login is required.`、400 租户不匹配 |
| POST | `/api/auth/sso/bind/complete` | 公开 | 已有账号完成绑定并签发 | `{ ticket, userName, password }`；成功返回 `location`（带 jwt/refreshToken/userId） | 401 `Incorrect account or password.`、400 ticket 过期、409 身份已占用 |
| POST | `/api/auth/sso/bind/current-user/complete` | 需登录 | 当前登录用户确认绑定 | `{ ticket }`；不签发新 token | 401、400、409 同上 |
| POST | `/api/auth/sso/bind/register` | 公开 | 注册并绑定外部身份 | `{ ticket, email?, password?, confirmPassword?, referralCode? }`；已验证邮箱流程禁止改邮箱 | 400 密码不一致 / 邮箱不可改、409 身份已绑定 |
| GET | `/api/account-binding/me/:provider` | 需登录 | 查询当前用户在某 provider 的绑定 | 租户与用户取自请求上下文，不接受请求体传租户 | 401 `Unauthorized`、400 `Tenant scope is required.` |
| DELETE | `/api/account-binding/me/:provider` | 需登录 | 解绑当前用户与 provider | 同上；不存在时静默成功 | 同上 |
| GET/POST/PUT/DELETE | `/api/api-key`、`/api/api-key/:id`、`/api/api-key/pagination`、`/api/api-key/count`、`/api/api-key/my`、`/api/api-key/:id/soft`、`/api/api-key/:id/recover` | 需登录 | API key 生命周期管理 | 创建时未显式给 `token` 则由服务生成 `sk-x-` 形态密钥 | 401/403（基类声明）、404 不存在、400 非法 id |
| GET | `/api/auth/<provider>` 与 `/api/auth/<provider>/callback` | 浏览器 OAuth 流程 | 社交登录 | 启用列表：GitHub、Google、Facebook、LinkedIn、Twitter、Auth0、飞书 | 失败重定向到前端注册页 |

## 2. 服务能力契约

### 2.1 `AuthService`（登录态与账号生命周期）

| 方法 | 用途 / 参数语义 | 返回 | 异常 / 约束 |
| --- | --- | --- | --- |
| `validateUser(email, password)` | 账号密码校验（Basic 凭据口径）；邮箱大小写不敏感 | `User` | 失败 401；**仅接受已通过邮箱验证的账号** |
| `register(input, languageCode)` | 受控建号；`createdById` 存在时用创建者的租户覆盖入参租户 | `User` | 400 重复账号（i18n）、401 越权；`organizationId` 缺省落到默认组织 |
| `signup(input, languageCode)` | 自助注册；置 `emailVerified = false` 并生成验证 token（默认 2 天有效），随后发验证邮件 | `User` | 同上建号错误 |
| `createToken(user)` | 签发登录态与刷新凭据 | `{ token, refreshToken }` | 依赖签名密钥配置；缺少时签发失败。token 携带用户、租户、员工与角色权限快照 |
| `issueTokensForUser(userId)` | 按用户直接签发并轮换刷新凭据（供 SSO 绑定等流程复用） | `{ jwt, refreshToken, userId }` | 用户不存在 → 404 |
| `refreshTokens(userId, refreshToken)` | 校验刷新凭据并轮换 | `{ token, refreshToken }` | 缺失或不匹配 → 403 `Access Denied`；**成功后旧 refresh 立即失效** |
| `requestPassword(userFilter, languageCode, originUrl?)` | 单用户重置申请（额外带组织上下文发信） | `true` | 找不到用户或发信失败 → 404 `Email is not correct, please try again.` / 500 |
| `requestResetPassword({ email }, languageCode, originUrl?)` | 按邮箱批量生成重置链接 | `true` | 无匹配用户或建链接失败 → 400 `Forgot password request failed!`；**仅单用户场景真正发信，多租户发信路径未启用** |
| `resetPassword({ token, password, confirmPassword })` | 消费重置记录改密；成功后若邮箱未验证会顺带置为已验证 | `true` | 400 `Password Reset Failed (code: 1\|2\|3).`（1=记录过期、2=改密失败、3=通用） |
| `generateResetLink(baseURL, token, email, tenantId?)` | 拼接重置链接；仅当传入 `tenantId` 时才带上该查询参数 | `string` | 无 |
| `verifyEmail(token)` | 消费邮箱验证 token | `void` | 由用户服务决定失败语义 |
| `resendVerificationMail(user, languageCode)` | 重发验证邮件；覆盖既有 token 并重置有效期（默认 2 天） | `User` | 无 |
| `resolveOrBindVerifiedEmail(input)` | 按 `provider + subjectId + tenantId + verifiedEmail` 解析外部身份，未命中则按同租户邮箱匹配并建立严格绑定 | `User \| null` | 必填字段缺失/邮箱非法 → 400；同租户同邮箱匹配到多个用户 → 409；唯一性冲突 → 409 `The external identity or Xpert account was bound by another request.` |
| `registerVerifiedExternalIdentity(input, languageCode)` | 已验证邮箱的外部身份注册：新建用户为普通用户 + 试用角色 + 邮箱已验证，自动建组织并加入成员 | `{ user, created }` | 密码少于 6 位或两次不一致 → 400；`created=false` 表示复用已存在用户 |
| `resolveDefaultOrganizationId(tenantId)` | 解析租户的默认且启用组织 | 组织 id（未命中为空值） | 无 |

内部但决定对外语义的方法（跨模块不可调用，仅说明契约含义）：

- `createStrictVerifiedIdentityBinding(manager, input)`：在同租户同 provider 下维持 **`subjectId` 与 `userId` 双向唯一**；两个方向冲突分别抛不同文案的 409；`profile` 传 `undefined` 时不覆盖既有档案。

### 2.2 `AccountBindingService`（外部身份绑定唯一写入口）

| 方法 | 用途 / 参数语义 | 返回 | 异常 / 约束 |
| --- | --- | --- | --- |
| `bindUser({ tenantId, userId, provider, subjectId, profile? })` | 绑定外部身份；同用户重复绑定复用记录并按需更新档案 | 绑定记录 | 必填缺失 → 400 `'<field>' is required`；用户不在租户内 → 404；身份被他人占用 → 409 |
| `unbindUser({ tenantId, userId, provider })` | 解绑；不存在时静默成功 | `void` | 无 |
| `getUserBinding({ tenantId, userId, provider })` | 查询当前用户在某 provider 的绑定 | 绑定记录 \| `null` | 无 |
| `resolveUser({ tenantId, provider, subjectId })` | 由外部身份反查用户，返回值带角色、角色权限与员工关系 | `User \| null` | 命中绑定但用户为「无密码的占位用户」时返回 `null` |

内部规则（决定 `lark` 与其他 provider 的差异，不可直接调用）：仅 `lark` provider 会同步/清理用户上的旧外部标识；当目标身份已被「占位用户」或技术用户占用时允许回收，否则抛 409；其他 provider 不触碰该旧字段。

### 2.3 `ApiKeyService`（API key 主体解析）

- `resolvePrincipal(apiKey, { requestedUserId?, requestedOrganizationId?, principalType? })` → `IApiPrincipal`
  - **用途**：把一条 API key 解析为技术主体；也是 client secret 的 `API_KEY` 类型复用路径。
  - **参数行为语义**：
    - `requestedUserId` 有值时，主体切换为该用户——**必须能在 key 所在租户内解析到，否则认证失败**；与 key 显式绑定的技术用户相同则直接复用。
    - `requestedOrganizationId` 缺省取 key 的组织上下文。
    - `principalType` 缺省为 `api_key`；client secret 路径显式传 `client_secret`。
  - **返回形态**：主体为 `IApiPrincipal`；`resourceScope` 仅在 key 绑定为 `assistant` 时产出 `{ kind: 'assistant', xpertId }`、为 `workspace` 时产出 `{ kind: 'workspace', workspaceId }`；`integration`/`client`/`knowledgebase` 绑定**不产出** `resourceScope`（尽管契约注释提到知识库将向后兼容为 assistant）。同时带上 `ownerUserId`（凭据归属，审计用）、`apiKeyUserId`（技术主体）、`requestedUserId`、`requestedOrganizationId`。
  - **异常 / 约束**：`assistant`/`workspace` 绑定缺 `entityId` 时直接 401；`resourceScope` 不是权限授予，租户/组织/成员/操作检查仍然适用。
- `create(input)`：未显式给 `token` 时生成密钥（`sk-x-` 前缀），密钥主体形态在创建响应中返回。

### 2.4 `SecretTokenStrategy`（passport 名 `client-secret`）

- **凭据来源**：`x-client-secret` 头，或 `Authorization: Bearer cs-x-…`；两者都缺 → 401 `Authorization header not provided or invalid`。
- `authenticate(req, options)` → 成功产出 `IApiPrincipal`（`principalType: 'client_secret'`，带 `clientSecretBindingType`、`clientSecretId`、`clientSecretExpiresAt`）；失败 401 `Unauthorized`。
- `validateToken(token)`（内部）：`validUntil` 缺失、已过期或记录已标记过期 → 401 `Token expired`；`API_KEY` 类型还会级联校验其绑定的 API key 是否过期（→ `ApiKey expired`）并刷新其最近使用时间。
- **五种绑定类型的可观察差异**：

| 绑定类型 | `entityId` 含义 | 授权范围与主体形态 | 额外约束 |
| --- | --- | --- | --- |
| `API_KEY` | 后端 API key 的 id | 以该 API key 的 `IApiPrincipal` 运行（可被 `x-principal-user-id` 覆盖业务用户） | 级联校验 API key 有效期 |
| `USER_XPERT` | 唯一可访问的 Xpert id | 产出 `resourceScope = { kind: 'assistant', xpertId }`，业务用户为记录创建者；不加载长期 API key | 会话仅代表该 Xpert 的资源范围 |
| `PUBLIC_XPERT` | 公开 Xpert id | 产出 `resourceScope = { kind: 'assistant', xpertId }`，按公开应用规则访问；不设置被代表用户 | 面向公开访问场景 |
| `ENTERPRISE_XPERT` | 唯一可访问的 Xpert id | 产出 `resourceScope = { kind: 'assistant', xpertId }`，主体为绑定解析出的用户 | 必须齐备租户/组织/渠道范围（平台 + 集成 id），且目标 Xpert 处于发布态并由该渠道集成承载；主体带企业渠道范围 |
| `USER_CONVERSATION` | 单个会话 id | 产出 `resourceScope = { kind: 'conversation', conversationId }`；会话属于记录创建者 | 要求创建者为真人用户；认证时强制租户头并删除业务用户覆盖头 |
- **头部影响**：认证后请求的组织作用域会被记录内的持久化值覆写（并在有值时提升为组织级）；`USER_CONVERSATION` 额外删除 `x-principal-user-id` 并强制 `tenant-id`，因此头部不能放宽已持久化的人/租户绑定。
- **路由级约束**：`ENTERPRISE_XPERT` 与 `USER_CONVERSATION` 默认被拒——目标控制器/路由必须显式声明允许的绑定类型，否则 403。

### 2.5 `SecretTokenService`（凭据发放与查找）

| 方法 | 用途 / 参数语义 | 返回 | 异常 / 约束 |
| --- | --- | --- | --- |
| `createHashed({ token, type, entityId, tenantId, organizationId, createdById, validUntil, … })` | 以不可逆表示落库；明文只在签发方手里 | 记录 | 调用方须显式给 `validUntil` 与 `type`，否则认证阶段必然失败或语义退化 |
| `findBySecret(secret)` | 按明文查找记录，同时兼容历史明文存储 | 记录 | 以 `sha256:` 开头 → 401；同值多条取最新一条 |

注意：`SecretTokenCreateCommand` 只透传 `entityId`/`token`/`validUntil`，**用它无法表达绑定类型与归属信息**，不适合签发新形态凭据。

### 2.6 `LocalOutboundActorTokenProvider`（出站委托凭据）

- `isAvailable()` → `boolean`：可签发与否由签名密钥是否存在决定。
- `mint(input?)` → `{ token, expiresAt, audience }`
  - **参数语义**：`user`（缺省取当前请求用户）、`tenantId`、`organizationId`、`roles`、`clientId`、`ttlSeconds`、`audience`、`act`（调用方自定义声明）。
  - **缺省行为**：`ttlSeconds` 缺省/非法回退 15 分钟，**上限 15 分钟，超出被截断**；`audience` 缺省由环境变量决定，缺省值 `xpert`，支持逗号分隔多值。
  - **返回形态**：无状态签名令牌，携带被委托用户、租户、可选组织、角色/权限与随机标识；当调用方处于 API key / client secret 上下文时，`act` 会自动补上凭据来源字段。
  - **异常 / 约束**：缺少签名密钥或缺少租户/用户身份 → 抛错；**仅用于出站调用，无入站校验策略，也不落库**。

### 2.7 密码重置相关契约

| 入口 | 参数 | 行为 / 返回 | 约束 |
| --- | --- | --- | --- |
| `ResetPasswordRequestDTO` | `{ email }` | 申请重置的请求体 | 仅邮箱 |
| `ChangePasswordRequestDTO` | `{ token, password, confirmPassword }` | 执行重置的请求体 | 密码至少 4 位，两次必须一致 |
| `PasswordResetCreateCommand` | `{ email, tenantId?, token }` | 创建重置记录 | 记录实体**不含租户列** |
| `PasswordResetGetCommand` | `{ token }` | 按 token 取最新记录，返回带 `expired` 判定的记录 | 过期窗口为创建后 **10 分钟**，不可配置 |

## 3. 代码示例（真实调用方）

**① 直接为用户签发登录态（SSO 绑定完成后）**

```ts
// packages/server/src/auth/sso/auth-sso-binding.service.ts
const tokens = await this.authService.issueTokensForUser(user.id)
await this.pendingSsoBindingChallengeService.delete(challenge.ticket)
return { location: this.buildSignInSuccessLocation(tokens, challenge.returnTo ?? undefined) }
// location 形如 /sign-in/success?jwt=…&refreshToken=…&userId=…[&returnTo=…]
```

**② 由 API key 解析主体并归一化请求作用域**

```ts
// packages/server/src/api-key/api-key.strategy.ts
const requestedUserId = resolveApiKeyRequestedUserId(req)
const requestedOrganizationId = resolveApiKeyRequestedOrganizationId(req)

const principal = await this.apiKeyService.resolvePrincipal(apiKey, {
  requestedUserId,
  requestedOrganizationId
})
applyRequestedOrganizationScopeHeaders(req, principal?.requestedOrganizationId)
this.success(principal)
```

**③ 签发委派会话的 client secret（只回明文，库内只存不可逆表示）**

```ts
// packages/server-ai/src/ai/ai-v1.controller.ts（ChatKit 会话签发）
const token = `cs-x-${randomBytes(32).toString('hex')}`
const validUntil = new Date(Date.now() + 1000 * expires_after)

await this.secretTokenService.createHashed({
  type: SecretTokenBindingType.USER_CONVERSATION,
  entityId: body.scope.conversationId,
  tenantId,
  organizationId,
  createdById: currentUser.id,
  token,
  validUntil
})
```

**⑤ 铸造出站 actor token（计划任务场景）**


## 5. 结论

- 契约的核心不是「有哪些端点」，而是**凭据类型 × audience**：API key 表达技术身份与资源范围，client secret 在其上表达五种绑定之一，actor token 只出不进。
- 强约束由守卫而非文档保证：`cs-x-` 前缀与 `x-client-secret` 决定凭据类别，绑定类型决定 audience，请求头只能收窄不能放宽。
- 对接方必须显式处理的三个语义点：登录失败是 200 + null、refresh 是 `GET /api/auth/refresh`、企业内嵌与共享会话凭据需要在目标路由上显式声明。
