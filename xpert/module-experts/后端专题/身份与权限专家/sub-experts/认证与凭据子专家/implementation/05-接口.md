## 前缀与全局约定

- 全局前缀 `api` 由启动层设置：`app.setGlobalPrefix('api', { exclude: [...] })`。
- `AuthModule` 通过 `RouterModule.register([{ path: '/auth', module: AuthModule, children: [{ path: '/', module: SocialAuthModule }] }])` 让自身与社交子模块的所有路由落在 `/api/auth/**`；`ApiKeyModule`、`AccountBindingModule` 同样用 `RouterModule.register` 声明 `/api-key`、`/account-binding`。
- 默认所有路由需要认证：全局 `AuthGuard`（`passport(['jwt','basic'])`）在启动时 `app.useGlobalGuards(new AuthGuard(reflector), new PluginScopeGuard(reflector))`；被 `@Public()`（`SetMetadata('isPublic', true)`）标记的方法/类直接放行。

章节来源：[apps/api/src/bootstrap/index.ts](file://apps/api/src/bootstrap/index.ts)（关键符号：setGlobalPrefix、useGlobalGuards）、[packages/server/src/shared/guards/auth.guard.ts](file://packages/server/src/shared/guards/auth.guard.ts)（关键符号：AuthGuard.canActivate）

## AuthController（`/api/auth/*`）

`@Controller()` + `/auth` 前缀 ⇒ 实际路径 `/api/auth/...`。

| 方法 | 路径 | 守卫 / 公开 | 参数 | 职责 | 主要错误 |
| --- | --- | --- | --- | --- | --- |
| GET | `/api/auth/authenticated` | `@Public()` | 无（读 `RequestContext.currentToken()`） | 校验当前 token 是否仍可用 | 无效 token 返回 `false`（JWT 错误被吞） |
| GET | `/api/auth/role` | 需登录 | `?roles=` 数组 | 判断 token 内 `role` 是否命中 | 无显式抛错 |
| POST | `/api/auth/signup` | `@Public()` | `RegisterUserDTO` + `Origin` 头 | 试用注册（发验证邮件） | `ForbiddenException('Public signup is disabled for this deployment.')`；`AuthRegisterTrialHandler` 抛 `ConflictException(email,'email exists')` |
| POST | `/api/auth/register` | 需登录 | `RegisterUserDTO` + `Origin` 头 | 创建用户（同注册链） | 400 账号已存在（i18n `core.User.Error.AccountAlreadyExists`）、401 非 SUPER_ADMIN 越权 |
| POST | `/api/auth/login` | `@Public()` | `IUserLoginInput`（`email` + `password`） | 登录签发 token + 轮换 refresh | **凭据错误返回 `null`（HTTP 200）而非 401** |
| GET | `/api/auth/verify` | `@Public()` | `?token=` | 邮箱验证 | 无效 token 由 `UserService.verifyEmail` 决定 |
| GET | `/api/auth/refresh` | `@Public()` + `AuthGuard('jwt-refresh')` | `Authorization: Bearer <refreshToken>` | 刷新并轮换 refresh | `ForbiddenException('Access Denied')` |
| GET | `/api/auth/alive` | 需登录 | 无 | 探活并回显 `req.user` | 401 由全局 guard 抛 |
| POST | `/api/auth/reset-password` | `@Public()` | `ChangePasswordRequestDTO`（`token`/`password`/`confirmPassword`） | 用重置 token 改密 | `BadRequestException('Password Reset Failed (code: 1|2|3).')` |
| POST | `/api/auth/request-password` | `@Public()` | `ResetPasswordRequestDTO`（`email`）+ `origin` 头 | 发送重置邮件 | `NotFoundException('Email is not correct, please try again.')`、`InternalServerErrorException` |
| POST | `/api/auth/resend-verification` | 需登录 | `@CurrentUser()` + `I18nLang` | 重发验证邮件 | 无 |

DTO 校验要点：`ChangePasswordRequestDTO` 要求 `password` 至少 4 位且 `confirmPassword` 用 `@Match` 与之一致；`request-password` 使用 `UseValidationPipe({ whitelist: true })`。

## AuthSsoController（`/api/auth/sso/*`）

`@Controller('sso')` 挂在 `AuthModule` 下 ⇒ 实际路径 `/api/auth/sso/...`（**不是** `/api/sso`）。

| 方法 | 路径 | 守卫 / 公开 | 参数 | 职责 | 主要错误 |
| --- | --- | --- | --- | --- | --- |
| GET | `/api/auth/sso/providers` | `@Public()` | 无 | 发现当前租户可用 SSO provider 列表 | 租户不可解析时返回 `{ fallbackApplied, providers: [] }` |
| GET | `/api/auth/sso/bind/challenge` | `@Public()` | `?ticket=` | 读取公共绑定挑战（匿名绑定/已验证邮箱注册） | `BadRequestException('SSO binding session has expired. Please sign in again.')` |
| GET | `/api/auth/sso/bind/current-user/challenge` | 需登录 | `?ticket=` | 当前用户确认绑定的挑战视图 | 401 `Current login is required.`、400 租户不匹配 |
| POST | `/api/auth/sso/bind/complete` | `@Public()` | `{ ticket, userName, password }` | 用已有账号完成绑定并签发 token | 401 `Incorrect account or password.`、400 ticket 过期、409 身份已被占用 |
| POST | `/api/auth/sso/bind/current-user/complete` | 需登录 | `{ ticket }` | 当前登录用户确认绑定 | 401/400/409 同上 |
| POST | `/api/auth/sso/bind/register` | `@Public()` | `{ ticket, email?, password?, confirmPassword?, referralCode? }` + `I18nLang` | 注册并绑定（含 `verified_email_signup` 流程） | 400 密码不一致/已验证邮箱不可改、409 身份已被绑定 |

| Google | `GET /api/auth/google` | `GET /api/auth/google/callback` | `GoogleStrategy('google')` |
| Facebook | `GET /api/auth/facebook` | `GET /api/auth/facebook/callback` | `FacebookStrategy('facebook')` |

## 鉴权约定

| 策略名 | 请求头 / 凭据形态 | 产出 principal | 适用场景 |
| --- | --- | --- | --- |
| `jwt` | `Authorization: Bearer <jwt>`，或把 JWT 放进 `x-api-key` 头 | `User`（含 `role.rolePermissions`、`employeeId`） | 浏览器/前端常规 API |
| `basic` | `Authorization: Basic <user:pass>` | `User` | 兼容调用（`validateUser` 要求 `emailVerified`） |
| `ws-jwt` | 握手 `auth.token` → `authorization` 头 → `query.token` | `User` | WebSocket（`WsJWTGuard`） |
| `jwt-refresh` | `Authorization: Bearer <refreshToken>`（`JWT_REFRESH_SECRET`） | `payload + refreshToken` | `GET /api/auth/refresh` |
| `api-key` | `x-api-key: <token>` 或 `Bearer <token>` | `IApiPrincipal`（`principalType: 'api_key'`，含 `resourceScope`/`ownerUserId`/`apiKeyUserId`/`requestedUserId`） | 第三方/集成/Assistant 调用 |
| `client-secret` | `x-client-secret: <secret>` 或 `Bearer cs-x-...` | `IApiPrincipal`（`principalType: 'client_secret'` + `clientSecretBindingType` + `clientSecretExpiresAt`） | 按绑定类型区分：API_KEY / USER_XPERT / PUBLIC_XPERT / ENTERPRISE_XPERT / USER_CONVERSATION |
| 社交策略名（`github` 等） | OAuth 重定向（浏览器） | 回调内临时 user（email/mobile/accessToken） | 社交登录 |

补充约定：
- 组合守卫 `ApiKeyOrClientSecretAuthGuard` 先按 `cs-x-` 前缀或 `x-client-secret` 头判定走 client-secret，否则先试 api-key、失败再回退 `CoreAuthGuard(['jwt','basic'])`。
- 头部影响 principal：`x-principal-user-id`（同租户业务用户覆盖）、`organization-id`（请求组织）、`tenant-id`（登录/租户过滤）；`applyRequestedOrganizationScopeHeaders` 会在认证后把 `organization-id` 覆写为持久化值并把 `x-scope-level` 置为 `ORGANIZATION`，否则落到 `TENANT`。
- `ENTERPRISE_XPERT`/`USER_CONVERSATION` 绑定除认证外还要求目标路由/控制器显式声明允许的绑定类型，否则 `ForbiddenException()`。

## 错误码与错误语义

本子专家范围内未定义统一业务错误码枚举，全部使用 Nest 标准异常 + 固定文案（部分走 i18next key）：

| 异常 | 文案/键 | 触发点 |
| --- | --- | --- |
| `UnauthorizedException` | `Authorization header not provided or invalid` | `ApiKeyStrategy`/`SecretTokenStrategy` 缺凭据 |
| `UnauthorizedException` | `Invalid token` | api key 不存在或无 `createdBy`；client secret 无 `createdById`/无 api key |
| `UnauthorizedException` | `Token expired` / `ApiKey expired` | `SecretTokenStrategy.validateToken` |
| `UnauthorizedException` | `Unauthorized`（`cause.message`） | strategy 内部异常统一包装 |
| `UnauthorizedException` | `Incorrect account or password.` / `Current login is required.` | SSO 绑定完成/当前用户确认 |
| `UnauthorizedException`（无文案） | `password_reset` 缺失（`SecretTokenService` digest 输入、`assertEnterpriseXpertScope` 失败） | 见对应实现 |
| `ForbiddenException` | `Access Denied` | `AuthService.refreshTokens` 刷新失败 |
| `ForbiddenException` | `Public signup is disabled for this deployment.` | `POST /api/auth/signup`（`customer-onprem`） |
| `ForbiddenException`（无文案） | 绑定类型未被路由允许 | `ApiKeyOrClientSecretAuthGuard.assertClientSecretBindingAllowed` |
| `BadRequestException` | `Password Reset Failed (code: 1/2/3).` | `AuthService.resetPassword` |
| `BadRequestException` | `Forgot password request failed!` | `AuthService.requestResetPassword` |
| `BadRequestException` | `SSO binding session has expired. Please sign in again.` / `SSO binding session is invalid. Please start again.` / `The password and confirmation password must match.` / `'<field>' is required.` | SSO 绑定链各入口 |
| `NotFoundException` | `Email is not correct, please try again.` | `AuthService.requestPassword` |
| `ConflictException` | `This <provider> identity is already bound to another Xpert account.` / `This Xpert account is already bound to another <provider> identity.` / `The external identity or Xpert account was bound by another request.` | `AccountBindingService`、`AuthService`、`AuthSsoBindingService` |
| i18n | `core.User.Error.AccountAlreadyExists` | `AuthService.createRegisteredUser` 重复邮箱/用户名 |
| i18n | `server-ai:Error.RegistrationTenantRequired` / `server-ai:Error.RegisteredUserLoadFailed` | 注册缺少租户/落库后读取失败 |

## 与前端记忆路径的差异核实

以下为**源码核实结论**（如与前端口述路径冲突，以本节为准）：

1. **不存在 `/api/auth/custom/*`**：全仓库检索 `auth/custom`、`@Controller('custom')` 均为 0 命中；`/api/auth/custom/login` 只出现在前端单元测试里，是通过 `baseEndpoint: '/api/auth/custom/'` 注入的**前端策略配置示例**，服务端没有该路由。
2. **服务端真实端点名与前端默认配置不一致**：前端 `XpPasswordAuthStrategyOptions` 默认拼出 `request-pass`/`reset-pass`/`logout`/`refresh-token`，而服务端只有 `request-password`、`reset-password`，刷新是 `GET /refresh`，并且**没有 logout 端点**。
3. **`/api/sso` 不存在**：SSO 控制器真实挂载在 `/api/auth/sso/*`；前端 `apps/cloud`（`login.component.ts`、`register.component.ts`、`sso-bind`、`current-user-sso-confirm`）以及拦截器白名单用的都是 `/api/auth/sso/...`。
4. **`/api/dingtalk-identity/login/start` 不存在**：检索 `dingtalk-identity`、`login/start`、`sso-bind`、`sso-confirm` 均 0 命中；Dingtalk 相关只剩被注释的策略/控制器与 `DINGTALK_*` 配置项。
5. **`/api/{provider}/{id}/login?projectId=&redirectUri=` 属于集成登录而非本子专家路由**：该形态出现在前端项目页（`features/chat/project/manage`、`xp-project/github-login`），指向 `/api/github/{integrationId}/login` 之类，由集成/插件侧注册，不在 `auth/`、`account-binding/`、`api-key/`、`secret-token/`、`actor-token/`、`password-reset/` 的 controller 中。
6. **`/api/bosi` 不存在**：账户绑定真实路径是 `/api/account-binding/me/:provider`；当前 cloud 前端尚未调用该端点（检索 0 命中），它主要供插件/客户端使用。

## 结论

- 本子专家对外真正暴露的 HTTP 面很小：`/api/auth/*`（含 `sso/*`）、`/api/account-binding/*`、`/api/api-key/*`，加上社交 provider 的 `/api/auth/<provider>[/callback]`；其余凭据（secret token、actor token、password_reset 实体）都是“策略/服务级”接口。
- 对接方最容易踩的三个坑：登录失败返回 `200 + null`、刷新走 `GET /refresh` 且只需 Bearer refresh token、`/api/auth/custom/*` 与 `/api/sso` 这类“记忆中的路径”并不存在。
- 契约上的强约束来自守卫而非文档：`x-client-secret`/`cs-x-` 前缀决定凭据类别，绑定类型决定 principal 的 audience，头部可覆写的只有同租户业务用户与组织作用域。
