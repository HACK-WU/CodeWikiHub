## §1 HTTP 接口契约

**通用约定**

- 基础路径：全局前缀 `api` + 模块路由声明。角色模块声明的路径为带前导斜杠的 `/roles`，权限模块声明为无前导斜杠的 `role-permissions`（拼写为 `role-permissions`，不是 `rolepermissions` / `roles-permissions`）；两者归一化后分别为 `/api/roles` 与 `/api/role-permissions`，与前端调用一致（`API_PREFIX = '/api'`）。
- 鉴权（全局）：未标 `@Public()` 的路由一律要求 `Authorization: Bearer <jwt>`、Basic 或 `x-api-key`，否则 401。
- 判权（控制器级）：
  - `RoleController` 类级只挂 `TenantPermissionGuard`；仅 create / update / delete / softRemove / softRecover 追加 `@UseGuards(PermissionGuard)` + `@Permissions('CHANGE_ROLES_PERMISSIONS')`。**所有读路由不校验权限点。**
  - `RolePermissionController` 类级同时声明 `@UseGuards(TenantPermissionGuard, PermissionGuard)` 与 `@Permissions('CHANGE_ROLES_PERMISSIONS')`，**其全部路由**（含读）都要求该权限点。
- 两个控制器都继承通用 CRUD 控制器，因此另有继承路由：`GET count`、`GET pagination`、`GET my`、`GET :id`（参数 JSON / UUID 校验）、`DELETE :id/soft`、`PUT :id/recover`。
- 通用错误：401 未认证；403 来自租户守卫（租户标识缺失或不一致）或权限守卫（无权限点）；404 记录不存在；400 业务不变量被违反。

**/api/roles**

| 方法与路径 | 鉴权/判权 | 用途与关键参数 | 主要错误 |
| --- | --- | --- | --- |
| `GET /api/roles` | 仅租户守卫 | 列出当前租户角色 | 401、403 |
| `GET /api/roles/find?data={"findInput":{...}}` | 仅租户守卫 | 按条件查单个角色；`data` 为 JSON 字符串 | 403、404 |
| `GET /api/roles/count` \| `/pagination` \| `/my` \| `/:id` | 仅租户守卫 | 计数 / 分页 / 我的 / 按 id | 403、404 |
| `POST /api/roles` | +`CHANGE_ROLES_PERMISSIONS` | body 为角色部分字段（含租户字段）；返回 201 | 400（缺租户上下文）、403 |
| `PUT /api/roles/:id` | +同上 | 改名 / 更新；返回 202 | 400 `System roles cannot be renamed.`、`System role flags cannot be modified.`、`The requested role was not found in the current tenant.`、403 |
| `DELETE /api/roles/:id` | +同上 | 删除；返回 202 | 400 `System roles cannot be deleted.`、`Cannot delete a role that is assigned to users.`、`Cannot delete a role that is referenced by pending invites.`、403 |
| `DELETE /api/roles/:id/soft`、`PUT /api/roles/:id/recover` | +同上 | 软删 / 恢复；返回 202 | 403、404（**不触发**上述系统角色与引用校验） |

**/api/role-permissions**（下列全部要求 `CHANGE_ROLES_PERMISSIONS`）

| 方法与路径 | 用途与关键参数 | 主要错误 |
| --- | --- | --- |
| `GET /api/role-permissions?data={"findInput":{...}}` | 分页查询权限开关行 | 401、403 |
| `POST /api/role-permissions` | 新增权限开关（角色 id + 权限点 + 启停 + 租户字段）；返回 201 | 400（校验失败）、403 |
| `POST /api/role-permissions/sync-defaults` | 当前租户增量同步默认矩阵；body 可为空；返回 202，响应含 `tenantId`、`inserted`、`enabled`、`roles[]` | 400 `Tenant context is required for role permission sync.`、403 |
| `PUT /api/role-permissions/:id` | 启停单个权限点（body 通常为 `{ enabled }`）；返回 202 | 400（`Cannot modify Permissions for Super Admin` 被包装）、403、404 |
| `DELETE /api/role-permissions/:id` | 删除权限行；返回 202 | 400（`Cannot delete Permissions for Super Admin` 被包装）、403 |
| `GET /api/role-permissions/count` \| `/pagination` \| `/my` \| `/:id`、`DELETE /:id/soft`、`PUT /:id/recover` | 继承的查询 / 软删 / 恢复 | 403、404 |

## §2 服务能力契约

**`RoleService`**（角色读写与不变量）

| 能力 | 签名要点 | 行为语义 |
| --- | --- | --- |
| `create(entity, ...options)` | `Partial<Role>` | 强制 `isSystem = false`；调用前必须存在当前租户上下文，否则 400 |
| `update(id, entity, ...options)` | `id: string \| number` | 系统角色不可改名；`isSystem` 不可被改写（传入必须与现值一致） |
| `delete(criteria, options?)` | `id` 或条件对象 | 依次拒绝：系统角色、仍被用户引用的角色、仍被待接受邀请引用的角色 |
| `createBulk(tenants)` | `ITenant[]` | 为每个租户按 `RolesEnum` 建全套角色行；**不设置** `isSystem` |
| `migrateRoles()` | 无参 | 只读导出当前租户角色（含 `sourceId`），无调用方 |
| `findOneByWhereOptions(options)` | 继承自租户感知基类 | 自动附加当前用户的租户过滤，是「定位本租户记录」的统一入口；未命中抛 404 |
| `findAll` / `findOne` / `countBy` / `findMyAll` / `softRemove` / `softRecover` | 继承 | 均自动按当前用户附加租户范围 |

**`RolePermissionService`**（权限行读写与判权查询）

| 能力 | 签名要点 | 行为语义 |
| --- | --- | --- |
| `updatePermission(id, partialEntity)` | 单行更新 | 目标行所属角色为 `SUPER_ADMIN` 时拒绝（`NotAcceptableException` 被统一包装为 400 `BadRequestException`）；其余正常更新 |
| `deletePermission(id)` | 单行删除 | 同上，`SUPER_ADMIN` 拒绝；异常同样被包装为 400 |
| `updateRoles(tenant, role)` | 单角色 | 按 `DEFAULT_ROLE_PERMISSIONS` 写入该角色的默认权限行（`enabled = true`）；角色名不在矩阵中会抛错；**当前无调用方** |
| `updateRolesAndPermissions(tenants)` | `ITenant[]` | 批量落默认矩阵：先清理退役权限点；DEMO 模式下跳过两个高危权限点；**一次性批量写入**（非逐行事务，失败不保证部分回滚）；入参为空数组时返回空 |
| `syncDefaultRolePermissions()` | 无参 | 当前租户**增量**对齐默认矩阵：只补缺失权限行（`enabled = true`）；对 `SUPER_ADMIN` 额外把「属于默认矩阵但已被置为 false」的现有行回补为启用；返回 `{tenantId, inserted, enabled, roles[]}`；无租户上下文抛 400 |
| `purgeRetiredAnalyticsPermissions(tenantIds)` | `string[]` | 清理退役的历史权限点（分析/订阅/认证/通知等一批历史编码）；空数组直接返回 |
| `migratePermissions()` | 无参 | 只读导出当前租户权限行（含角色名），配套导入能力已注释，**无调用方** |
| `checkRolePermission(tenantId, roleId, permissions, includeRole?)` | `permissions: string[]`，`includeRole` 默认 `false` | 判定语义见下 |
| `onApplicationBootstrap()` | 生命周期 | 应用启动期无租户过滤地删除退役权限点，并把历史权限点 `MEMBERSHIP_PURCHASE` 重命名为 `AIPermissionsEnum.MEMBERSHIP_USE` |

**`checkRolePermission` 的判定语义（务必按此理解）**

- `includeRole = true`：把判定限定到给定 `roleId` —— 即「**这个角色**是否拥有所列权限点」。
- `includeRole = false`（默认）：**不限定角色** —— 只要该租户下任意角色的权限行启用了所列权限点之一即返回 `true`。
- `enabled` 不是参数：只有「启用」的行参与判定，`enabled = false` 的行等于不存在；不存在「按 enabled 反查」的用法。
- 多权限点是**或**语义：传入多个权限点时，命中任意一个即 `true`。
- 权限点字符串来源：平台侧取 `PermissionsEnum`，AI 侧取 `AIPermissionsEnum`（两者取值均为与键同名的大写字符串，见 [packages/contracts/src/role-permission.model.ts](file://packages/contracts/src/role-permission.model.ts)、[packages/contracts/src/ai/role-permissions.ts](file://packages/contracts/src/ai/role-permissions.ts)）；不要写裸字符串。
- 判定不看组织：只按租户 +（可选）角色 + 权限点计算，组织身份不参与。

**默认矩阵与扩展点**

- `DEFAULT_ROLE_PERMISSIONS` 为表驱动的「预置角色 → 默认启用权限点」清单，覆盖全部 5 个角色枚举。
- `setDefaultRolePermissions(role, permissions)` 可用于追加某角色的默认权限点（追加去重，不覆盖既有项）。
- 同步行为要点：`sync-defaults` **只增不删**，不会关闭租户手工关掉的权限点（`SUPER_ADMIN` 的「默认项被关掉」是唯一例外）；DEMO 模式下两个高危权限点永远不会被补齐。

## §3 判权约定

### ① `@Permissions('xxx')` 的权限点取值

- 写法：`@Permissions(...permissions: string[])`，写入装饰器元数据键 `permissions`（常量 `PERMISSIONS_METADATA`，见 [packages/common/src/constants.ts](file://packages/common/src/constants.ts)）。**它只写元数据，本身不做任何校验**，必须同时挂 `PermissionGuard` 才生效。
- 取值来源：`PermissionsEnum`（平台与组织管理、数据源、集成、高危操作等）与 `AIPermissionsEnum`（AI 侧）。取值一律使用枚举成员，勿手写裸字符串。
- 常见取值：

| 取值 | 语义 | 典型落点 |
| --- | --- | --- |
| `PermissionsEnum.CHANGE_ROLES_PERMISSIONS` | 管理角色与权限 | 角色写操作、权限模块类级 |
| `PermissionsEnum.ORG_USERS_VIEW` / `ORG_USERS_EDIT` | 查看 / 管理租户用户 | 用户与用户组 |
| `PermissionsEnum.ALL_ORG_VIEW` / `ALL_ORG_EDIT` | 查看 / 编辑全部组织 | 组织、功能开关、用户 |
| `PermissionsEnum.ORG_INVITE_VIEW` / `ORG_INVITE_EDIT` | 查看 / 发起邀请 | 邀请、组织联系人 |
| `PermissionsEnum.ORG_EMPLOYEES_VIEW` / `ORG_EMPLOYEES_EDIT` / `ORG_TAGS_EDIT` | 员工与标签 | 组织联系人、标签 |
| `PermissionsEnum.DATA_SOURCE_VIEW` / `DATA_SOURCE_EDIT` | 数据源能力 | 数据源 |
| `PermissionsEnum.INTEGRATION_EDIT`、`REFERRAL_VIEW` | 集成、推荐 | 集成、推荐 |
| `PermissionsEnum.ACCESS_DELETE_ACCOUNT` / `ACCESS_DELETE_ALL_DATA` | 高危删除 | 用户模块；DEMO 模式下默认权限矩阵会跳过 |
| `AIPermissionsEnum.*`（如 `KNOWLEDGEBASE_EDIT`、`COPILOT_VIEW` / `COPILOT_EDIT`、`XPERT_EDIT`、`CHAT_VIEW`、`MEMBERSHIP_USE`） | AI 侧能力 | `packages/server-ai` 各模块 |

- 元数据解析顺序：方法级覆盖类级（同一 controller 内方法级注解优先）。多权限点为**或**语义。
- 缓存：判定结果按「租户 + 角色 + 权限组合」缓存 5 分钟，`false` 结果同样被缓存；新增权限组合 = 新增一条缓存。

### ② `@Roles(...)` 的取值

- 写法：`@Roles(...roles: string[])`，写入元数据键 `roles`（常量 `ROLES_METADATA`），只由 `RoleGuard` 读取。
- 取值来自 `RolesEnum`，共 5 个：`SUPER_ADMIN`、`ADMIN`、`AI_BUILDER`、`VIEWER`、`TRIAL`。设计文档中列出的其他角色名已过期，勿作为契约使用。
- 语义：**纯角色白名单**，不查权限点；判定依据是当前用户角色名。它绕开权限点体系，无法被细粒度授予或撤销。
- 实测落点：`SUPER_ADMIN` 用于租户设置、运行时控制、插件初始化、功能升级等平台级操作；`SUPER_ADMIN + ADMIN` 用于用户批量导入、数据源同步；`SUPER_ADMIN + ADMIN + TRIAL` 用于组织演示数据与插件应用初始化。
- 另有环境开关旁路：开启超管旁路开关时，`SUPER_ADMIN` 在租户守卫上直接放行，与 `@Roles` 是两条独立通道。

### ③ `@Public()` 的语义与读取方

- 写法：`@Public()` 写入元数据键 `isPublic = true`。
- 唯一读取方：全局 `AuthGuard`（`jwt` / `basic` 策略）与 WebSocket 守卫 `WsJWTGuard`；命中即跳过认证。
- **不读取它**的守卫：`PermissionGuard`、`RoleGuard`、`TenantPermissionGuard`、`OrganizationPermissionGuard`、插件作用域守卫。
- 结论：`@Public()` 只跳过鉴权，不跳过判权。仓内范式是「`@Public()` + 专用认证守卫」组合（例如个人资料接口用 `@Public()` + API Key / Client Secret 守卫，由该守卫自行完成认证）。

### ④ 守卫组合的推荐写法

| 场景 | 推荐写法 | 说明 |
| --- | --- | --- |
| 权限点判定（首选） | `@UseGuards(TenantPermissionGuard, PermissionGuard)` + `@Permissions(PermissionsEnum.X)` | 租户一致 + 权限点；可把权限注解放类级，方法级可覆盖 |
| 角色白名单 | `@UseGuards(TenantPermissionGuard, RoleGuard)` + `@Roles(RolesEnum.SUPER_ADMIN)` | 仅平台级身份使用；无法细粒度授予 |
| 双重门槛 | `@UseGuards(TenantPermissionGuard, RoleGuard, PermissionGuard)` + `@Roles(...)` + `@Permissions(...)` | 两者都需满足 |
| 仅需租户一致 | `@UseGuards(TenantPermissionGuard)` | 不代表任何权限校验 |
| 完全公开 | `@Public()` | 仅绕过认证；若同方法还有 `@Permissions`，缺用户上下文会返回 403 |
| 非 JWT 凭据 | 追加 `ApiKeyOrClientSecretAuthGuard`（特殊绑定还需 `@AllowClientSecretBindings(...)`） | 由該守卫完成凭据识别 |
| 租户级 / 组织级场景 | 租户级用上表前四行；组织级当前**没有可用守卫**（`OrganizationPermissionGuard` 唯一引用处已被注释，且其判据是员工旧列） | 需要组织级权限点时应自行实现或改用租户级 + 业务层组织校验 |
| CASL | 不适用 | 未接线，勿在守卫中引用策略工厂 |

### ⑤ 新增一个受保护端点的正确做法清单

1. **选型**：优先权限点（`@Permissions`）而非角色白名单；仅平台级身份才用 `@Roles`。
2. **权限点定义**：在 `PermissionsEnum`（或 AI 侧枚举）中新增枚举成员；服务端判定是字符串比对，避免裸字符串。
3. **默认授予**：把新权限点加入 `DEFAULT_ROLE_PERMISSIONS` 对应角色的清单；否则预置角色不会自动拥有该行，需靠 `POST /api/role-permissions/sync-defaults` 增量补齐（只增不删）。
4. **注解**：`@UseGuards(TenantPermissionGuard, PermissionGuard)` + `@Permissions(PermissionsEnum.X)`。
5. **自查项**：
   - 是否真的挂了 `PermissionGuard`？（只写 `@Permissions` 等于没校验；元数据为空守卫会放行）
   - 是否误用 `@Public()` 代替判权？
   - 写接口是否需要 `RoleGuard` / 特殊凭据守卫？
   - 是否漏了类级 vs 方法级的覆盖关系（方法级优先）？
   - 是否预期「任一权限点通过」而实际想要「全部通过」（多权限点是或语义）？
6. **缓存影响**：新权限组合首次请求会回源一次判定，随后缓存 5 分钟；调整角色权限后旧判定最长 5 分钟内继续生效，仓内没有权限缓存失效入口。
7. **自动化护栏**：为 controller 方法补一条元数据断言测试（断言 `@Permissions` 写入的元数据内容），这是当前防「漏注解即放行」的唯一自动化手段。
8. **可见性提醒**：权限通过不等于入口可见，功能开关（Feature）是另一层控制。

```ts
// apps/cloud/src/app/features/setting/roles/roles.component.ts
const { tenantId } = this.user
const permissionToEdit = this.permissions.find((p) => p.permission === permission)

if (permissionToEdit?.id) {
  // 已有行 -> 走 PUT /api/role-permissions/:id
  await firstValueFrom(this.rolePermissionsService.update(permissionToEdit.id, { enabled }))
} else {
  // 缺行 -> 走 POST /api/role-permissions
  await firstValueFrom(
    this.rolePermissionsService.create({ roleId, permission, enabled, tenantId })
  )
}
```

```ts
// apps/cloud/src/app/@core/services/role-permissions.service.ts
syncDefaults() {

// packages/server/src/role/role.controller.ts（节选）
@UseGuards(PermissionGuard)
@Permissions(PermissionsEnum.CHANGE_ROLES_PERMISSIONS)
@HttpCode(HttpStatus.ACCEPTED)
@Put(':id')
override async update(
  @Param('id', UUIDValidationPipe) id: string,
  @Body() entity: Partial<Role>
): Promise<Role> {
  return super.update(id, entity)
}
```
