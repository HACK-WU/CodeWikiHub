## 2. 服务能力契约（同进程跨模块调用）

以下为父专家契约主体。每条格式：用途｜参数（含行为语义）｜返回｜异常｜约束。签名均回源码核实。

### 2.1 `AuthService`（[auth.service.ts](file://packages/server/src/auth/auth.service.ts)）

- `validateUser(email, password)`｜用途：复用型「邮箱+密码」校验｜参数：`email` 忽略大小写；`password` 明文｜返回：`User`｜异常：`UnauthorizedException`（不存在或不匹配）｜约束：**只匹配已验证邮箱的用户**，且不带租户条件（跨租户同邮箱按创建时间取最新）。
- `signup(input, languageCode)`｜用途：免费注册（含验证邮件）｜参数：`input.user.tenant`/`organizationId`/`originalUrl`；邮箱初始未验证｜返回：`User`｜异常：`BadRequestException`（同租户邮箱/用户名已存在）｜约束：`customer-onprem` 部署下该入口被拒。
- `register(input, languageCode)`｜用途：通用注册（注册 / 加入组织 / 受邀接受 / 代客创建）｜参数：传 `createdById` 时以创建者租户覆盖 `input.user.tenant`；代客或导入场景清除 `referralCode`；`organizationId` 缺省时解析租户默认组织｜返回：`User`｜异常：`BadRequestException`（查重冲突、非幂等的待验证注册更新）｜约束：`SUPER_ADMIN` 角色不建成员关系；默认组织解析不到时不发欢迎邮件。
- `createToken(user)`｜用途：签发 access + refresh｜参数：`user` 可只给 `id`（缺角色/员工会自动回查）；角色为空时 payload 的 `role` 与 `permissions` 为 `null`｜返回：`{ token, refreshToken }`｜异常：`NotFoundException`（回查不到用户）｜约束：**不落库**，需要 refresh 可再次使用时必须配合 `updateRefreshToken` 或改用 `issueTokensForUser`。
- `issueTokensForUser(userId)`｜用途：签发并落库（SSO、邀请接受后自动登录）｜参数：用户 id｜返回：`{ jwt, refreshToken, userId }`｜异常：`NotFoundException`｜约束：内部已完成 refresh 落库，返回字段名与 `createToken` 不同（注意 key 差异）。
- `refreshTokens(userId, refreshToken)`｜用途：校验并轮换刷新令牌｜参数：用户 id + 上次下发的 refresh 明文｜返回：`{ token, refreshToken }`（新一组）｜异常：`ForbiddenException('Access Denied')`（无 refresh 记录或不匹配）｜约束：**轮换后旧 refresh 立即失效**，并发刷新需串行化。
- `updateRefreshToken(userId, refreshToken)`｜用途：覆盖已存 refresh｜返回：`void`｜异常：未确认｜约束：只应在令牌签发流程内调用。
- `getAuthenticatedUser(id, thirdPartyId?)`｜用途：读认证主体｜参数：`thirdPartyId` 优先于 `id`｜返回：`User`（带认证所需关联）｜异常：`NotFoundException`（未命中）｜约束：第三方标识与本地 id 互斥语义由调用方决定。
- `isAuthenticated(token)`｜用途：令牌有效性断言｜返回：`boolean`｜异常：签名类错误返回 `false`，其它错误抛出｜约束：仅断言 token 处于有效状态与用户存在，不做权限判断。
- `hasRole(token, roles = [])`｜用途：角色断言｜参数：`roles` 缺省空数组｜返回：`boolean`｜异常：同上（签名错误返回 false）｜约束：空 `roles` 恒为 `false`；token 无角色恒为 `false`。
- `requestPassword(request, languageCode, originUrl?)`｜用途：发送密码重置邮件｜参数：`request` 为按字段匹配用户的条件对象（如 `{ email }`）；`originUrl` 可选｜返回：`boolean`（签名允许返回异常对象，调用方需同时处理抛出）｜异常：`BadRequestException`（查不到用户/发信失败）｜约束：链接指向客户端路由，必须传语言。
- `resetPassword(request)`｜用途：用重置令牌改密｜参数：`{ password, token }`｜返回：`true`｜异常：`BadRequestException('Password Reset Failed (code: 1|2|3)')`｜约束：令牌过期、用户缺失、其它失败共用同一错误前缀；改密成功后未验证邮箱会被置为已验证。
- `verifyEmail(token)`｜用途：完成邮箱验证｜返回：`void`｜异常：`NotFoundException`（令牌不存在或过期）｜约束：令牌有效期 2 天。
- `resendVerificationMail(user, languageCode)`｜用途：重签验证令牌并重发｜返回：更新后的 `User`｜异常：未确认｜约束：会覆盖用户已有验证令牌。

### 2.2 `UserService`（[user.service.ts](file://packages/server/src/user/user.service.ts)，外部最常调用的 10 个）

- `findCurrentUser(id, relations?, options?)`｜用途：读「当前用户视图」｜参数：`relations` 缺省为员工/角色/角色权限/租户；`options.limitOrganizations`、`options.currentOrganizationId` 控制组织集合收敛｜返回：`User`（含组织装配）｜异常：`NotFoundException`｜约束：**需要角色与权限位时用本方法**，不要自行拼装。
- `getUserByEmail(email)`｜用途：按邮箱取用户｜参数：忽略大小写｜返回：`User | null`（未命中返回空，不抛）｜约束：无租户过滤，跨租户同邮箱场景由调用方判断。
- `createOne(user)`｜用途：直接插入用户｜返回：`InsertResult`｜约束：**不走创建守卫**，仅限内部/测试；外部创建用户请用 `AuthService.register` 或用户创建命令。
- `changePassword(id, hash)`｜用途：写入密码哈希｜参数：`hash` 由调用方生成（明文不接受）｜返回：保存后的 `User`｜异常：`NotFoundException`｜约束：不校验旧密码。
- `updateProfile(id, entity)`｜用途：改资料｜参数：本人或具备 `ALL_ORG_EDIT`/`SUPER_ADMIN_EDIT` 权限者｜返回：`IUser`｜异常：`ForbiddenException`（非本人且无权限）、`NotFoundException`｜约束：通信账号与角色字段有额外限制。
- `isActiveMemberOfOrganization(userId, organizationId)`｜用途：判断活跃成员｜参数：依赖当前租户上下文｜返回：`boolean`｜约束：`SUPER_ADMIN` 视为通过（不依赖成员关系）。
- `deleteWithGuards(id)`｜用途：安全删除用户（软删）｜返回：软删结果｜异常：守卫拒绝时抛出｜约束：会一并清理成员关系与外部身份绑定；外部模块删除用户必须走本入口。
- `deleteHardWithGuards(id)`｜用途：物理删除（同守卫）｜返回：`DeleteResult`｜约束：不可恢复，仅管理后台/工厂重置使用。
- `ensureCommunicationUser({ tenantId, thirdPartyId, username?, imageUrl?, preferredLanguage? })`｜用途：幂等获取/创建通信账号｜参数：缺省用户名由第三方标识派生、默认语言英语、邮箱视为已验证｜返回：`User`（带上下文关联）｜约束：仅用于集成/后台账号，默认从用户列表排除，勿用于真人。
- `findOneByIdWithinTenant(id, tenantId, options?)` / `getIfExists(id)`｜用途：租户内定位用户 / 带认证关联读取｜返回：`User`｜约束：跨模块读取请带租户条件，避免越域取数。

### 2.3 `UserOrganizationService`（[user-organization.services.ts](file://packages/server/src/user-organization/user-organization.services.ts)）

- `ensureMembership({ organizationId, tenantId, userId })`｜用途：幂等建立成员关系｜参数：三者必填｜返回：`IUserOrganization`（已存在则返回既有）｜异常：`BadRequestException`（缺用户或组织）｜约束：首次成员自动为活跃 + 默认；成功新建会广播成员关系创建事件。
- `addUserToOrganization(user, organizationId)`｜用途：按用户对象加入组织｜返回：`IUserOrganization | IUserOrganization[]`｜约束：`SUPER_ADMIN` 返回空数组（不建关系），调用方不得据成员关系判断超管。
- `findCurrentUserMembership()`｜用途：读当前请求上下文下的成员关系｜参数：无（依赖用户 + 组织上下文）｜返回：`IUserOrganization | null`（缺少用户或组织上下文返回 `null`）｜约束：`/api/me` 类场景必须已有组织作用域。
- `setCurrentUserDefaultWorkspaceId(defaultWorkspaceId | null)`｜用途：写当前成员关系的工作台偏好｜参数：`null` 表示清除｜返回：未显式声明｜异常：`NotFoundException`（无当前成员关系）｜约束：只影响当前组织的成员关系。
- `getCurrentUserDefaultWorkspaceId()`｜用途：读默认工作台｜返回：`string | null`｜约束：无偏好或成员关系时返回 `null`（不抛）。
- 成员不变量（跨方法契约）：同一用户在同一租户内**至多一个默认组织、至少一条活跃成员关系**；置默认可行会先把其它默认降级；删除最后一条活跃成员关系需显式放行参数；组织删除会批量收敛成员并按规则重指派默认组织。

### 2.4 `InviteService`（[invite.service.ts](file://packages/server/src/invite/invite.service.ts)）

- `createBulk(emailInvites, languageCode)`｜用途：批量创建邀请并发送邮件｜参数：`emailIds`（去重、规范化，非法/重复计入 `ignored`）、`roleId`、`organizationId`、`invitedById`、`organizationContactIds`、`invitationExpirationPeriod`（枚举「永不过期」时过期时间为空）、`startedWorkOn`/`appliedDate`｜返回：`{ items, total, ignored }`｜异常：`UnauthorizedException`（邀请人非超管却要授予超管角色）｜约束：已是租户用户或已有未过期邀请的邮箱被跳过；过期时间取组织配置或默认值。
- `resendEmail(data, invitedById, languageCode, expireDate)`｜用途：重发邀请｜参数：`data` 至少含 `id`/`email`/`roleName`/`organization` 与邀请类型｜返回：`UpdateResult`（更新邀请行）+ 发信（返回语义未显式声明）｜约束：会把状态重置为「邀请中」并重签 token。
- `sendAcceptInvitationEmail(organization, employee, languageCode)`｜用途：邀请接受后的通知邮件｜返回：未声明具体类型｜约束：供接受流程调用，不改变邀请状态。
- `validateByToken({ email, token }, relations = [])`｜用途：校验邀请（公开入口）｜参数：`email` 规范化；`relations` 缺省空数组｜返回：`IInvite`｜异常：`BadRequestException`（签名无效、邮箱不匹配、状态非「邀请中」或已过期）｜约束：token 与邮箱是**成对**凭据，单独任一不可校验；过期邀请不会落状态，只表现为校验失败。
- `createOrganizationContactInvite(inviteInput)`｜用途：向组织联系人发邀请｜返回：`Invite`｜约束：以受限角色发起并把联系人状态置为「邀请中」。

### 2.5 `RolePermissionService`（[role-permission.service.ts](file://packages/server/src/role-permission/role-permission.service.ts)）

- `checkRolePermission(tenantId, roleId, permissions, includeRole = false)`｜用途：判定角色是否具备权限｜参数：`permissions` 为权限位数组；`includeRole` 缺省 `false`（**忽略角色维度**，租户内任一角色命中即通过）｜返回：`boolean`（存在性判定：命中数量 > 0）｜异常：无｜约束：需按角色判定时必须显式传 `includeRole = true`（guard 即如此）；仅统计「启用」状态的权限行。
- `syncDefaultRolePermissions()`｜用途：同步当前租户的默认角色权限｜参数：无（依赖租户上下文）｜返回：未声明｜异常：`BadRequestException`（缺少租户上下文）｜约束：仅在租户创建/初始化流程中调用。

### 2.6 `AccountBindingService`（[account-binding.service.ts](file://packages/server/src/account-binding/account-binding.service.ts)）

- `bindUser({ tenantId, userId, provider, subjectId, profile? })`｜用途：绑定外部身份｜参数：前四项必填（缺失即 `BadRequestException`）；`profile` 可选｜返回：`ExternalIdentityBinding`｜异常：`BadRequestException`（缺参）、`ConflictException`（主体或用户已被占用）｜约束：仅 `lark` 允许回收「通信账号/无密码用户」的旧身份，其余冲突直接失败。
- `resolveUser({ tenantId, provider, subjectId })`｜用途：由外部身份解析用户｜参数：三项必填｜返回：`User | null`（带角色/角色权限/员工装配）｜异常：`BadRequestException`（缺参）｜约束：命中「无密码哈希」的占位用户时返回 `null`，要求调用方转入注册或绑定流程，**不要当作已登录**。
- `getUserBinding({ tenantId, userId, provider })`｜用途：读绑定（供 `/api/me/:provider`）｜返回：`ExternalIdentityBinding | null`｜约束：返回空表示未绑定（对应 `bound: false`）。
- `unbindUser({ tenantId, userId, provider })`｜用途：解绑｜返回：`void`｜约束：语义为幂等删除，未绑定也算成功（对应 204）。

### 2.7 内部成员（**非跨模块契约**，仅作语义索引）

- `AuthService.lockTenantRegistrationScope`（私有，仅注册事务内使用）、`AuthService.resolveDefaultOrganizationId`（私有，注册后解析租户默认组织）、`UserOrganizationService.ensureUniqueDefault` / `ensureActiveMembershipRemains` / `pickNextDefaultMembership`（私有，成员不变量实现）、`AccountBindingService.isGhostUser`（私有，判定无密码占位用户）。外部模块**不得**依赖这些成员，其行为仅通过上文公开契约间接体现。
