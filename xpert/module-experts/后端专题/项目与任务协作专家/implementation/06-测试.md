## 二、运行方式

`server-ai` 与 `server` 各自有独立 jest 配置，`preset: '../../jest.preset.js'`；`moduleNameMapper` 把 `@xpert-ai/server-core`、`@xpert-ai/contracts`、`@xpert-ai/plugin-sdk` 直指源码目录（无需先构建依赖包）；`transform` 为 ts-jest（`tsconfig.spec.json`）＋ babel-jest 混用。**无全局 setup/setupFiles**，fixture 各 spec 自带。

```bash
# 1) 项目域与任务域（server-ai），单文件 / 多文件
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --runTestsByPath packages/server-ai/src/xpert-project/project.service.spec.ts \
                   packages/server-ai/src/xpert-task/xpert-task.service.spec.ts

# 2) business-area（server 包）
node node_modules/jest/bin/jest.js --config packages/server/jest.config.ts \
  --runTestsByPath packages/server/src/business-area/business-area.service.spec.ts

# 3) 按目录/名称过滤
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --testPathPattern 'src/(xpert-project|xpert-task)/'

# 4) Nx 方式（server-ai 项目名已核实；server 项目名以 packages/server/project.json 的 name 为准）
corepack pnpm exec nx run server-ai:test --skipNxCache --runInBand
```

章节来源：[jest.config.ts](file://packages/server-ai/jest.config.ts)（关键符号：displayName server-ai / moduleNameMapper / transform），[jest.config.ts](file://packages/server/jest.config.ts)（关键符号：displayName server），[project.json](file://packages/server-ai/project.json)（关键符号：server-ai.targets.test）

## 三、断言与 mock 风格

- **纯手工构造 + 全 mock（任务域主流）**：`xpert-task.service.spec.ts` 直接 `new XpertTaskService(...)` 注入 fake `Repository`/`SchedulerRegistry`/`RedisLockService`，**无 PG**；断言 job 增删、租约接管、occurrence key、runtimeState schema 等。
- **控制器边界断言**：`xpert-task.controller.spec.ts` 用 `jest.mock` 掉 server-core，断言读走 `findHttpAccessible`、每个写操作都走 `*HttpTask` 方法（`scheduleHttpTask`/`pauseHttpTask`/…），run-as 正确转发——**防的是绕过 HTTP 边界的直连仓库**。
- **Nest 集成（无 DB）**：`views/scheduler-detail.provider.spec.ts`、`plugins/project-tasks/project-tasks.capability.spec.ts`、`views/project-tasks.provider.spec.ts` 用 `Test.createTestingModule` ＋ mock repo 或 `jest.spyOn(RequestContext…)`。
- **内存 store 的策略测试**：`scheduled-task-execution.coordinator.spec.ts` 自建 `Store` 实现，断言「终态不可重试 / 单 owner 互斥 / 过期接管 attempt=2」；无需数据库。
- **真实 JWT**：`scheduled-task-oidc-token.spec.ts` 真实签发并 `verify`，需 `JWT_SECRET` 与 `XPERT_TASK_OIDC_TOKEN_*` 环境变量，断言 act claims（`sub='xpert_task'`）。
- **data-driven cases**：项目侧的 `runtime/testing/project-task-decision.cases.ts` 被 spec 复用（决策流多分支），本域**无 `pg-mem` 或内存 PG 替身**。

章节来源：[xpert-task.controller.spec.ts](file://packages/server-ai/src/xpert-task/xpert-task.controller.spec.ts)（关键符号：findHttpAccessible / scheduleHttpTask），[coordinator.spec.ts](file://packages/server-ai/src/xpert-task/scheduled-task-execution.coordinator.spec.ts)（关键符号：ScheduledTaskExecutionCoordinator.claim / claimExpired），[oidc-token.spec.ts](file://packages/server-ai/src/xpert-task/scheduled-task-oidc-token.spec.ts)（关键符号：XPERT_TASK_OIDC_TOKEN_AUDIENCE / XPERT_TASK_OIDC_TOKEN_TTL_SECONDS）

## 五、缺口

- **无真实 PG 覆盖 `xpert-task`**：`xpert_task`/`xpert_task_execution` 的 occurrence 唯一约束、`(status, leaseExpiresAt)` 索引语义只在内存 store 上验证；coordinator 的条件 UPDATE（`affected === 1`）未在真库上取证。
- **派发运行时**：`runtime/project-task-dispatch.integration.spec.ts` 是唯一真库用例，但**派发适配器/Agent 调用（`AgentInvocationFactoryService`）仍是策略桩**（`IAgentRuntimeStrategy` 的 `start/inspect/cancel` 为 jest.fn）——不覆盖真实 Agent 派发与回执闭环。
- **run-as 确认流**：仅有 `dto/run-as.dto.spec.ts` 的管道级用例（UUID 校验、白名单拒绝）；`acceptProjectTaskRunAs` 的 hash 重算、`affected !== 1 → ProposalChanged`、配置变更主动失效三条路径**由 `xpert-task.service.spec.ts` 间接覆盖，无独立 spec**。
- **调度 job 命中率**：`scheduler.job.ts`（`TaskSchedulerProcessor`）**无直接 spec**；`create.handler.ts`、`delete.handler.ts`、`template-routines.handler.ts` 同样无直接 spec（create 仅被 middleware spec 间接经过）。
- **多副本语义**：`SchedulerRegistry` 是本地内存，`query.handler.ts` 在取不到 cron job 时把返回体 `status` 伪造成 `PAUSED` —— 这个「与 DB 状态可能不一致」的分支只有单元级断言，无多实例集成验证。
- **业务域缺口**：`business-area` 仅 1 个 service spec，`BusinessAreaController` 的 `RoleGuard`/`@Roles` 无守卫级断言；`XpertProjectController` 的 73 条路由无逐条 HTTP 用例（`project.controller.spec.ts` 仅 6.45KB）。

## 六、可执行性结论

判定：**✅ 可跑（不实跑，仅给命令与判据）**。判据：

1. 项目域 48/49 与任务域 11/11 的 spec **不连任何外部服务**（Repository、DataSource、RedisLock、Bull queue 全 mock），可直接用第二节命令 1 本地执行；
2. `project-task-dispatch.integration.spec.ts` 是唯一真库用例，**默认 `describe.skip`**（`const integration = url ? describe : describe.skip`），只有注入以 `/xpert_execution_test_` 开头的库 URL 才解锁，不会污染平台库；
3. `scheduled-task-oidc-token.spec.ts` 依赖 `JWT_SECRET`，未设置时会在签发/校验阶段失败，属**环境前置**而非代码缺陷；
4. `business-area` 必须切到 `packages/server/jest.config.ts`，否则 `moduleNameMapper` 不解析 `@xpert-ai/contracts` 之外的 server 内部路径；
5. 仓库内**未发现 known-fail / skip 白名单说明**；所有 `skip` 均为条件开关。
