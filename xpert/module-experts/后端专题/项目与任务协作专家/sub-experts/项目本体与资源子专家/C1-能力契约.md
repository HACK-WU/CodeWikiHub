## §1 HTTP 入口索引

全局前缀 `api`；本子专家真实路由＝`XpertProjectController`（空前缀 + `RouterModule.register({ path: '/xpert-project' })`，继承 `XpertProjectPlanningController`）＋ `XpertProjectInvitationController`（`invitations`）＋ `XpertProjectAdminController`（`:id/admin`）＋ `BusinessAreaController`（`/business-area`）；下列按主题合并同构行。

| 方法 | 路径 | 守卫 | 用途 |
|---|---|---|---|
| GET/POST | `/api/xpert-project` | 类级三守卫 + `@ProjectPermission(VIEW/CREATE)` | 我的项目列表 / 创建（直选 `toolsetIds`、`knowledgebaseIds` 被有意忽略） |
| GET | `/api/xpert-project/types`、`/type-entry` | 同上（VIEW） | 项目类型目录、按 `applicationKey` 解析类型入口 |
| GET/PUT | `/api/xpert-project/:id` | `XpertProjectGuard` + VIEW/EDIT | 详情 / 更新（须过 `createProjectUpdateValidationPipe`） |
| POST | `/:id/archive` | Guard + MANAGE | 归档，显式写 `status='archived'`；此后拒绝 edit/manage |
| PUT/DELETE | `/:id/soft`、`/:id/recover`、`DELETE /:id` | Guard + MANAGE（物理清除再加 `XpertProjectOwnerGuard`） | 软删 / 软恢复 / 物理清除（要求 owner + archived + 无在途文件） |
| POST/GET | `/import`、`/:id/export`、`/:id/duplicate` | Guard + VIEW/CREATE | 导入 DSL / 导出 `ExportProjectCommand` / 复制 |
| GET/POST/PUT/PATCH/DELETE | `/:id/members[/:userId]` | Guard + VIEW/MANAGE | 成员列表 / 覆盖 / 追加 / 改角色 / 移除（移除同步暂停其 `XpertTask`） |
| GET/POST/DELETE | `/:id/invitations[/:invitationId]` | Guard + MANAGE（另需组织级 `ORG_INVITE_EDIT`） | 邀请列表 / 发邀请 / 撤销（要求项目有 `organizationId`） |
| POST | `/invitations/accept`、`/decline` | **无项目守卫**（token 驱动，service 层校验） | 接受 / 拒绝邀请 |
| POST | `/:id/admin/intervene` | `XpertProjectFeatureGuard` + `PermissionGuard` + `@Permissions(ORG_USERS_EDIT, ALL_ORG_EDIT)` | 组织管理员带显式理由加入项目 |
| GET/PUT/DELETE | `/:id/xperts[/:xpert]`、`/:id/available-xperts`、`/:id/assistant` | Guard + VIEW/MANAGE | 助手家族绑定 / 解绑 / 可绑定清单 |

| GET/PUT/POST/PATCH/DELETE | `/:id/content/instructions`、`/:id/content/skills*` | Guard + VIEW/EDIT | `project.md` 与 `skills/` 读写、技能安装 / 上传 / 启停 / 卸载 |
| GET/PUT/POST/DELETE | `/:id/workspace/files*`、`/:id/files`、`/:id/file/upload`、`/:id/file`、`/:id/assets*`、`GET /:id/activities`、`GET /overview` | Guard + VIEW/EDIT | 工作区文件、卷文件、资产索引、活动流、工作台聚合 |

## §2 服务契约

| 服务 / 关键方法 | 用途 | 参数行为语义 · 异常 |
|---|---|---|
| `XpertProjectService.本体`：`createProject` / `update` / `archive` / `duplicate` / `exportProject` / `importProject` / `deleteProject` / `softRemoveProject` / `ensureManagedProject` / `addXpert` / `removeXpert` / `addToolset` / `addKnowledge` / `addAttachments` / `delAttachment` | 聚合根 CRUD 与资源挂载 | `createProject` 先 `resolveAccessibleCurrentXpert`，再 `forCreate`→`classification` 固化快照；`archive` 显式写 `status='archived'`；`deleteProject` 先 `connectorService.deleteProjectBindings` 再删行；`addAttachments` 逐个 `GetOwnedStorageFileQuery`；400（`ProjectTypeInvalid`/`ProjectApplicationWorkflowRequired`/`Owned`）、409 `ProjectTypeConflict` |
| `XpertProjectTypeService.catalog/list/resolve/classification/forCreate/forConversation/forEnsure/entry/assertPlatformLifecycle` | 类型目录、解析与分类快照 | `catalog` 只列当前已加载插件里的活体类型；`classification` 产出 `{applicationKey, projectTypeKey, applicationInstallationId, projectTypeSnapshot}`；`assertPlatformLifecycle` 两条任一（实况类型或快照 `binding` 为 `entity`）即拒绝平台侧生命周期操作；400 `ProjectTypeUnavailable` |
| `XpertProjectAccessService.resolveAccess/assertCanRead/assertCanUse/assertCanEdit/assertCanManage/assertCanPurge/assertIsOwner` | 授权唯一业务入口（HTTP / 请求上下文） | 角色由 `ownerId` + `xpert_project_membership` 派生（不读 legacy 关系）；`canEdit=[owner,manager,editor]`、`canManage=[owner,manager]`；`assertCanUse` 只拒 `archived`；`assertCanPurge` 要求 `role==='owner' && status==='archived'`；403 `ProjectMembershipRequired`/`ProjectOwnerRequired` |
| `ProjectAccessRuntimeService.listReadable/assertManage/assertEdit` | 插件 / 运行时侧准入 API（无 HTTP） | 以显式 `actor` 取代 `RequestContext`；`listReadable` 单条投影查询（`CASE WHEN ownerId = :userId THEN 'owner' ELSE membership.role END`）+ 一次 assistantIds join；输出 `archived` / `canManage`；403 |
| `XpertProjectXpertBindingService.normalize/contains/resolveCurrent/resolveCurrentById/resolveInitialMembers` | 助手家族归一与初始成员解析 | `normalize` 把历史版本关系就地换成当前版本并去重（读侧归一不回写）；`contains` 按 `isSameXpertFamily` 判定；`resolveCurrentById` 找不到当前版本返回 `null`；`resolveInitialMembers` 走 BFS 且有 256 上限（超界显式失败） |
| `XpertProjectMembershipService.list/add/updateRole/transferOwnership/remove/replaceMembers/interveneAsOrganizationAdministrator` | 成员与角色 | `add` 拒 owner 入表、要求「同租户 USER + 同组织 active」，命中软删行先 `restore` 复用；`remove` 先批量 `pause` 该用户 `XpertTask` 再 `emitAsync('xpert-project.member-removed')`；403；400（`ProjectOwnerAlreadyMember`/`ProjectMemberOrganizationMismatch`） |
| `XpertProjectInvitationService.list/invite/accept/decline/revoke/retryPendingLegacyMembershipSyncs`；`hashProjectInvitationToken` | token 邀请 | `invite` 需 `assertCanManage` + `ORG_INVITE_EDIT` + 项目有 Organization；明文 token 只回一次、库内仅 `tokenHash`（`select:false`）；同项目同邮箱 pending 复用同一行并轮换 hash；`accept` 幂等返回既有成员行、过期先落 `expired` 再抛错；400（`ProjectInvitationInvalid`/`NotPending`/`ProjectOrganizationRequired`）、403（`ProjectInvitationEmailMismatch`） |
| `XpertProjectActivityService.record/list/sanitizeActivityPayload` | 活动流唯一写入口 | 落库前递归剔除键名命中 `/token\|secret\|password\|prompt\|authorization\|apiKey/i` 的字段；`list(projectId, take = 50)` 按 `createdAt DESC` |
| `XpertProjectAssetService.createAsset/list/tree/countProjectAssets/removeAsset` | 资产索引 | `(projectId, path)` 唯一 + `withDeleted` 命中即 `recover` 复用（否则 `create`）；`list` 未传 `parentId` 即 `IsNull()` 只看根层、`take` 夹在 `[1, 200]`；`removeAsset` 是 `softRemove` |
| `XpertProjectContentService` / `XpertProjectWorkspaceFilesService` / `XpertProjectPurgeService` | 卷内容、工作区文件与物理清理 | `isGovernedPath` 拦下 `project.md` 与 `skills/`（普通上传/删除一律 400 `ProjectContentApiRequired`）；`purge` 次序 `assertCanPurge` → `assertPlatformLifecycle` → 拒绝 `uploaded\|scanning\|parsing\|processing\|queued` 文件 → 逐文件 `purgeProjectFile` → 卷删除 → `deleteProject`；400 `ProjectPurgeBusy` |
| `XpertProjectAutomationService.list/listRuns/triggerEvent/createAutomation/updateAutomation/removeAutomation/run` | 旧版自动化 | 读面 `list(projectId, {includeRuns})`、`listRuns(take:100)` 可用；`triggerEvent()` 恒返回 `[]`；四个写方法抛 `GoneException`（410 `LegacyProjectAutomationDisabled`） |
| `BusinessAreaService.createArea/updateArea/deleteArea/validateParent/requireName` | 业务领域字典（closure-table） | 名称去空必填；`validateParent` 拒绝自身父子与「移到后代之下」（沿 `parentId` 上溯 + `visited` 防环）；删除为硬删、级联由 `@TreeParent({onDelete:'CASCADE'})` 承担；400 |

## §3 准入与守卫契约

| 层 | 组件 | 判定输入 | 失败行为 |
|---|---|---|---|
| 0 | 类级 `@Public()` | 无参数 | 只跳过全局 JWT 守卫，**不等于放行** |
| 1 | `XpertProjectAuthGuard`（继承 `ApiKeyOrClientSecretAuthGuard`） | `request.user` 的 `principalType` 与 `clientSecretBindingType` | 403 `ProjectInteractiveSessionRequired`：拒绝 `client_secret` 且非 `SecretTokenBindingType.USER_XPERT` 绑定的主体 |
| 2 | `XpertProjectFeatureGuard` | `RequestContext.currentTenantId()` + `toggleFeatures.FEATURE_XPERT`/`FEATURE_XPERT_PROJECT` + `Feature`/`FeatureOrganization` | 403：缺 tenant、环境开关关闭、组织/租户级 `isEnabled === false`；**feature 未 seed 时放行**（有意的可用性取舍） |
| 3 | `XpertProjectPermissionGuard` | `@ProjectPermission` 元数据 + `:id` + `RequestContext` | 无 `:id` 时退化为 `RequestContext.hasPermissions([permission])`；`XPERT_PROJECT_CREATE` 额外要求 `assertCanRead(projectId)`；403 `ProjectPermissionRequired` |
| 4 | `XpertProjectGuard` / `XpertProjectOwnerGuard`（方法级） | `reflector.getAllAndOverride(XPERT_PROJECT_PERMISSION, [handler, class])` + `:id` | `MANAGE→assertCanManage`、`EDIT→assertCanEdit`、默认 `assertCanRead`；OwnerGuard 只判 `role !== 'owner'`（**不检查 archived**）→ 403 `ProjectOwnerRequired` |
| 5 | Service 内断言（无声明式守卫时的唯一边界） | `assertProjectWritable` / `assertCanPurge` / `assertCanUse` / `assertHttpMutationAccess` | 403 / 400；**邀请 2 条、`xpert-task` 35 条、`business-area` 读端点无项目守卫**，绕过 service 直查仓库即越权 |

插件与运行时侧不走守卫链，改走 `ProjectAccessRuntimeService` 三个方法（`listReadable`/`assertManage`/`assertEdit`）与 `AssertProjectAssistantAccessCommand`；`XpertProjectAuthGuard`/`XpertProjectGuard` 未注册进 `providers`，由 `@UseGuards` 侧实例化。

章节来源：[guards/index.ts](file://packages/server-ai/src/xpert-project/guards/index.ts)（关键符号：XpertProjectAuthGuard / XpertProjectFeatureGuard / XpertProjectPermissionGuard / XpertProjectGuard / XpertProjectOwnerGuard）、[project-permission.guard.ts](file://packages/server-ai/src/xpert-project/guards/project-permission.guard.ts)（关键符号：canActivate / RequestContext.hasPermissions）、[project-access-runtime.service.ts](file://packages/server-ai/src/xpert-project/services/project-access-runtime.service.ts)（关键符号：listReadable / assertManage / assertEdit）

## §4 示例

### ① 建项目（类型解析与快照固化）

```ts
// 真实调用方：packages/server-ai/src/xpert-project/project.controller.ts
const { xpertIds, toolsetIds, knowledgebaseIds, memberIds, ...projectInput } = entity
void toolsetIds; void knowledgebaseIds   // Deprecated direct capability selections are intentionally ignored.
const project = await this.service.createProject({ ...projectInput, xpertIds, status: projectInput.status ?? 'active' })
for (const memberId of initialMemberIds) await this.membershipService.add(project.id, memberId, 'member')
await this.planService.ensureDefaults(project.id)     // 计划族归 ②，由控制器补齐
```

要点：`projectType` 走 `forCreate` → `resolve`（只接受当前已加载插件里的活体类型）→ `classification` 固化 `applicationKey`/`projectTypeKey`/`applicationInstallationId`/`projectTypeSnapshot`；`binding.kind === 'entity'` 的类型不允许普通创建。

### ② 邀请成员（明文 token 只回一次）

```ts
// 真实调用方：packages/server-ai/src/xpert-project/services/project-invitation.service.ts
const token = randomBytes(32).toString('base64url')      // 明文只出现在链接与邮件中
await this.create({ projectId, normalizedEmail, role, tokenHash: hashProjectInvitationToken(token), expiresAt })
// 命中同 (projectId, normalizedEmail, status='pending') 时复用同一行并轮换 tokenHash / expiresAt / lastSentAt
// accept：事务内 createQueryBuilder().addSelect('invitation.tokenHash').setLock('pessimistic_write') 按 tokenHash 定位
```

要点：`tokenHash` 为 `select: false` + `@Exclude({ toPlainOnly: true })`，查询必须显式 `addSelect`；`status='accepted'` 走幂等分支（要求 `acceptedById === currentUser.id` 且成员行存在）；过期时先落 `status='expired'` 再抛 `BadRequestException`。

### ③ 挂载资源（助手家族 + 附件拥有权）

```ts
// 真实调用方：packages/server-ai/src/xpert-project/project.service.ts
await this.addXpert(id, xpertId)            // assertCanManage → resolveAccessibleCurrentXpert → normalize + contains（家族级幂等）
await this.addAttachments(id, [fileId])     // existingAttachmentIds 差集 → GetOwnedStorageFileQuery 拥有权校验 → save
await this.assetService.createAsset(id, { name, path, kind: 'file' })   // (projectId, path) 唯一 upsert（命中软删行先 recover）
```

要点：`toolsetIds`/`knowledgebaseIds` 在创建时被丢弃（新项目这两个集合恒为空），只能事后 `PUT/DELETE :id/toolsets/:toolset`、`PUT/DELETE :id/knowledges/:kb`；受管路径（`project.md`、`skills/`）走内容端点而非文件 API。
