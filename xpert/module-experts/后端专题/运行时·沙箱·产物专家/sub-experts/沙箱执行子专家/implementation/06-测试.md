## 2. 运行命令

`server-ai` 自持 jest 配置（`preset: '../../jest.preset.js'`，`moduleNameMapper` 把 `@xpert-ai/server-core`/`@xpert-ai/contracts`/`@xpert-ai/plugin-sdk` 直指源码，**无需先构建依赖包**）。

```bash
# 1) 单文件（最常用）
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --runTestsByPath packages/server-ai/src/sandbox/sandbox.controller.spec.ts

# 2) 多文件（同一配置下批量）
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --runTestsByPath packages/server-ai/src/sandbox/sandbox.controller.spec.ts \
                   packages/server-ai/src/sandbox/sandbox-terminal.gateway.spec.ts \
                   packages/server-ai/src/sandbox/nsjail/nsjail-runner.client.spec.ts

# 3) 整个子域（按路径模式）
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --testPathPattern 'src/sandbox/'

# 4) 按用例名过滤（-t）
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --testPathPattern 'src/sandbox/' -t 'preview session'
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --testPathPattern 'src/sandbox/' -t 'proxies managed service requests'
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --runTestsByPath packages/server-ai/src/sandbox/sandbox-terminal.gateway.spec.ts -t 'cancel'

# 5) Nx 方式（项目名已核实：server-ai）
corepack pnpm exec nx run server-ai:test --runInBand --skipNxCache
```

**必须用 `packages/server-ai/jest.config.ts`**：本子域全部 34 个 spec 都在 `server-ai` 包内，混用 `packages/server/jest.config.ts`（② 的配置）会因 `moduleNameMapper` 不解析内部路径而失败。Runner 侧 Python 用例不由 jest 驱动，见第 4 节。

章节来源：[jest.config.ts](file://packages/server-ai/jest.config.ts)（关键符号：displayName server-ai / moduleNameMapper / transform）、[project.json](file://packages/server-ai/project.json)（关键符号：server-ai.targets.test）

## 3. 断言与 mock 风格

- **控制器边界断言（主力）**：`sandbox.controller.spec.ts` 直接 `new SandboxController(...)` 注入假 service（组织作用域 `run` 透传回调、上下文服务返回固定 provider/workspace），断言「匿名通配拒绝受保护子路径」「跨租户 tenant hint 被忽略」「符号链接落点被复查」——防的是**越权与路径穿越**，不触真实文件系统。同类还有 `it('maps managed service errors into http exceptions')`，用 `SandboxManagedServiceError` 驱动核对 404/409/400 映射。
- **WS 事件序断言**：`sandbox-terminal.gateway.spec.ts` 用假 socket（`emit` 断言事件名与 payload）＋ 假 adapter（`open/write/resize/close` 为 `jest.fn`），断言成功序 `opened → output → exit → closed` 与失败序 `error → closed`，以及并发 socket 上下文、`input`/`resize` 转发、无适配器报错、显式关闭 vs 断连关闭、**pending open 取消**。
- **Runner 契约以替身驱动**：`nsjail/*.spec.ts` 三件套用替身 Runner client（含 `/health` 能力协商与错误对象），**不拉真实 nsjail**，因此可验证「协议不足即失败」「404 not-found 触发重建并重试一次」等分支。
- **服务级内存替身**：`sandbox-managed-service.service.spec.ts` 注入假 repository/adapter，断言状态回调落库、`lost` 降级、日志路径与 `previewUrl` 派生；`sandbox-job-capacity.service.spec.ts` 用假 `ManagedQueueService`（`getRedis().eval` 为 `jest.fn`）断言 Lua 参数组装与 `SANDBOX_CAPACITY_UNAVAILABLE` 抛出——**不连真实 Redis**。
- **纯函数/DP 断言**：`sandbox-job-progress.spec.ts`（进度行解码与生命周期时间戳）、`sandbox-runtime-definition.registry.spec.ts`（7 个 JSON 定义的白名单/硬约束校验、`timeoutMs > hardDeadlineMs` 拒绝）、`sandbox-work-for.spec.ts`（环境→项目→用户优先级）。
- **动作包校验断言**：`sandbox-action.registry.spec.ts` 用假 `LOADED_PLUGINS` 断言「只接受系统插件」「文件类型/大小/链接数/hash 不符即失败」。

章节来源：[sandbox.controller.spec.ts](file://packages/server-ai/src/sandbox/sandbox.controller.spec.ts)（关键符号：maps managed service errors into http exceptions）、[sandbox-terminal.gateway.spec.ts](file://packages/server-ai/src/sandbox/sandbox-terminal.gateway.spec.ts)（关键符号：pending open 取消用例）、[sandbox-job-capacity.service.spec.ts](file://packages/server-ai/src/sandbox/sandbox-job/sandbox-job-capacity.service.spec.ts)、[sandbox-runtime-definition.registry.spec.ts](file://packages/server-ai/src/sandbox/sandbox-job/sandbox-runtime-definition.registry.spec.ts)、[sandbox-action.registry.spec.ts](file://packages/server-ai/src/sandbox/sandbox-job/sandbox-action.registry.spec.ts)

## 5. 缺口

1. **WS 端到端**：`sandbox-terminal.gateway.spec.ts` 用**已认证的假 socket** 直接注入，`SandboxTerminalAuthGuard` **无独立 spec**——`cs-x-` client-secret 分支、`handshake.auth.token` 形状、`organization-id` 回填、`open` 时 `ChatConversation` 查询失败路径均未被守卫级断言覆盖；也没有「握手失败 → `WsException{status:403}`」的用例。
2. **proxy 预览**：`SandboxPreviewAuthGuard` 与 `SandboxPreviewSessionService` **无独立 spec**——票面/路径不一致、cookie `path` 边界、TTL 过期、`PreviewUnavailable`（400）、`JWT_SECRET` 缺失（500）均无守卫级断言；控制器侧只有间接用例（`proxies managed service requests through the service layer`、`creates a preview session cookie for iframe access`），**请求头清洗与 `location` 重写、`set-cookie` 丢弃、正文路径重写**均未被直证。
3. **清理路径**：`cleanupOrphans` / `cleanupPending` / `cleanedAt` / `requirePreviousAttemptCleanup` 在 34 个 spec 中**命中 0**——孤儿扫描的两批条件、`destroySandbox` 的三种返回分支（无 ref、无 provider、销毁抛错）都没有测试取证。
4. **volume 通配的端到端**：控制器 spec 覆盖了「受保护子路径被拒」「跨租户 tenant 被忽略」「符号链接落点被复查」「运行作业快照拒绝」「Range 重复参数」，但**未覆盖** `download=1` 的 Content-Disposition、416 越界、dev 环境 `normalizeSandboxPublicVolumeSubpath` 归一分支。
5. **运行时自愈的边界**：`withRuntimeRecovery` 的「同 generation 并发去重」与「重建后 generation 递增导致旧调用不再重建」两条竞态分支无专项断言。
6. **健康与容量的时序**：`SandboxRuntimeHealthService` 的 15 秒定时、`pendingProbes` 去重、失败 5 秒短缓存、`onModuleDestroy` 的 HDEL 注销在 spec 中未见（多靠替身直接调用方法）；`waitForCapacity` 的 30 秒心跳续期与「被取消立即抛」也缺显式用例。
7. **托管服务的崩溃恢复**：`onModuleInit` 把 `running`/`starting` 全量置 `lost` 的行为无断言；`requireConversationByThreadId` 的「旧根会话把 threadId 存在 `ChatConversation` 上」兼容分支同样无断言。

章节来源：[sandbox-terminal.gateway.spec.ts](file://packages/server-ai/src/sandbox/sandbox-terminal.gateway.spec.ts)、[sandbox-terminal-auth.guard.ts](file://packages/server-ai/src/sandbox/sandbox-terminal-auth.guard.ts)（关键符号：canActivate）、[sandbox-preview-auth.guard.ts](file://packages/server-ai/src/sandbox/sandbox-preview-auth.guard.ts)（关键符号：canActivate）、[sandbox-job-runtime-capability.service.ts](file://packages/server-ai/src/sandbox/sandbox-job/sandbox-job-runtime-capability.service.ts)（关键符号：cleanupOrphans / requirePreviousAttemptCleanup / waitForCapacity）、[sandbox-managed-service.service.ts](file://packages/server-ai/src/sandbox/sandbox-managed-service.service.ts)（关键符号：onModuleInit / requireConversationByThreadId）

## 6. 可执行性结论

判定：**✅ 可跑（本文件不实跑，仅给命令与判据）**。判据：

1. **单测为主**：34 个 spec 中，`nsjail/*`（3）、根级（7）、`middlewares/*`（9）、`commands/handlers/*`（2）、`sandbox-job/*` 中的 7 个（`sandbox-job-runtime-capability`、`sandbox-job-capacity`、`sandbox-job-progress`、`sandbox-action.registry`、`sandbox-runtime-binding-selector`、`sandbox-runtime-definition.registry`、`sandbox-runtime-health`）共 **28 个为纯单测**，Repository/Redis/Runner 契约全部为替身，可直接用第 2 节命令 1/2 执行。
2. **需外部工具链的 6 个**集中在 `sandbox-job/local-*` 与 `local-browser-runtime*`（`local-runtime-process`、`local-browser-runtime.provider`、`local-browser-runtime-health`、`local-document-python`、`local-document-fonts`、`local-document-dependencies`），在 CI 容器里应**显式分组/排除或标记为环境依赖**，不属代码缺陷。
3. **配置不可混用**：本子域一律 `--config packages/server-ai/jest.config.ts`；`runtime-control`/`health` 才用 `packages/server/jest.config.ts`。
4. **Nx 等价**：`nx run server-ai:test` 与直接 jest 指向同一配置，无全局 setup 文件，fixture 各 spec 自带。
5. **Runner 侧不入 Jest 通道**：`test_runner.py`（`unittest`）、`poc_validate.py` 需容器内 Linux 特权与 mount namespace，**不能**用来判定本子域模块的可执行性；`README.md` 明确 Docker Desktop 结果不构成 native Linux 证据。
6. **优先补测顺序（按风险）**：① `SandboxTerminalAuthGuard`（鉴权唯一门）→ ② `SandboxPreviewAuthGuard`/`SandboxPreviewSessionService`（proxy 唯一准入 + 失效语义）→ ③ `cleanupOrphans`/`requirePreviousAttemptCleanup`（清理证据链）→ ④ 卷通配的 `download`/`416`/dev 归一三分支 → ⑤ `waitForCapacity` 心跳与取消分支。
