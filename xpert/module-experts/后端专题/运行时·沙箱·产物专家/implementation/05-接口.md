## 一、总览：前缀、端点数与模块注册方式

全局 URL 前缀为 `api`。本批 5 模块的 HTTP 面合计 **61 条**＝sandbox 23 ＋ runtime-control 6 ＋ artifacts 24 ＋ workspace-file-access 6 ＋ health 2，另有 **1 个 WS 网关（4 类客户端消息）**。

| 模块 | 注册方式 | 真实前缀 | 端点数 | 类级鉴权装饰器 |
|---|---|---|---|---|
| sandbox | `RouterModule.register([{ path: '/sandbox', … }])` | `/api/sandbox` | 23（HTTP）＋WS | 仅 `@ApiBearerAuth` ＋ `TransformInterceptor`；全局 `AuthGuard` 兜底 |
| runtime-control | **无 RouterModule**，前缀写死在 `@Controller('system/runtime')` | `/api/system/runtime` | 6 | `@UseGuards(TenantPermissionGuard)` |
| artifacts | **无 RouterModule**，三个控制器各写前缀 | `/api/artifacts`、`/api/artifacts/share`、`/api/artifacts/share-session` | 3+2+19=24 | 无 UseGuards，靠全局 `AuthGuard`；4 处 `@Public()` |
| workspace-file-access | `RouterModule.register` ＋ `@Controller()` / `@Controller('content')` | `/api/workspace-files` | 4+2=6 | content 控制器：`@Public()` ＋ `WorkspaceFileAccessGuard` |
| health | 无 RouterModule，`@Controller('health')` | `/api/health` | 2 | 两条均 `@Public()` |

**实测校正（重要）**：① sandbox 的 23 条**不含**任何「配额/策略查询」HTTP 面——配额在服务层（`SandboxJobCapacityService` 经 Redis 租约执行，超限抛 `SandboxJobRuntimeError('SANDBOX_CAPACITY_UNAVAILABLE')`），运行时定义/动作是进程内注册表（`SandboxRuntimeDefinitionRegistry`/`SandboxActionRegistry`），均无控制器；② `artifacts`/`workspace-file-access` **确有 HTTP 面**（见第九~十一节），不是纯服务入口；③ terminal 是「`@Post` ＋ `@Sse()`」同挂的特殊路由，不是标准 `@Sse` 用法。

## 七、SandboxTerminalGateway：WS 终端（namespace sandbox-terminal）

**这是 WebSocket（socket.io），不是 REST**：握手鉴权失败以 `WsException({ status: 403, message })` 抛出，业务失败以 `error`/`closed` 事件下发，**不要用 HTTP 状态码断言**。

- 网关声明：`@WebSocketGateway({ namespace: SANDBOX_TERMINAL_NAMESPACE, cors: { origin: '*' } })`，命名空间常量 `'sandbox-terminal'`；每个 handler 都带 `@UseGuards(SandboxTerminalAuthGuard)`。
- **4 类客户端消息**：`open`、`input`、`resize`、`close`（`SandboxTerminalClientEvent`）。
- **5 类服务端事件**：`opened`、`output`、`exit`、`error`、`closed`（`SandboxTerminalServerEvent`）。
- 握手鉴权：`handshake.auth.token` 以 `cs-x-` 开头 → 走 `AuthGuard('client-secret')` 变体（并把 `organizationId` 复制到握手头）；否则走 `WsJWTGuard` 的 JWT 校验；随后 `assertWorkbenchPrincipal`；`open` 额外要求 `conversationId` 非空且会话可读（查 `ChatConversation`，失败即 403）。
- 会话生命周期：`open` 用 `requestId` 注册 pending（**同一 requestId 重复 open 会把旧请求标记 canceled，迟到解析的会话立即关闭**）；`close` 既可按 `sessionId` 关已开会话，也可按 `requestId` 取消仍在 pending 的 open；`disconnect` 取消全部 pending 并关闭该 socket 的所有会话（`socket_disconnected`）。
- **心跳/超时**：本仓库**未显式配置** socket.io `pingInterval`/`pingTimeout`（未取到直接证据），心跳由 socket.io 默认机制承担；应用级「超时」体现在 pending-open 取消与 Runner 侧空闲/硬 TTL（默认 2 小时空闲回收、24 小时硬租约）。`[待核：socket.io 默认心跳参数未在源码中固化为常量]`
- 错误码（`SandboxTerminalErrorCode`，11 个）：`conversation_not_found`、`conversation_required`、`sandbox_disabled`、`computer_desktop_required`、`unsupported_provider`、`provider_unavailable`、`open_failed`、`input_failed`、`resize_failed`、`close_failed`、`session_not_found`；关闭原因（`SandboxTerminalClosedReason`，6 个）：`client_closed`、`error`、`open_failed`、`process_exited`、`socket_disconnected`、`unsupported_provider`。

章节来源：[sandbox-terminal.gateway.ts](file://packages/server-ai/src/sandbox/sandbox-terminal.gateway.ts)（关键符号：open / input / resize / close / handleDisconnect / handleSessionExit / registerPendingOpen / normalizeError），[sandbox-terminal-auth.guard.ts](file://packages/server-ai/src/sandbox/sandbox-terminal-auth.guard.ts)（关键符号：ClientSecretSocketGuard / SandboxTerminalAuthGuard.canActivate / assertWorkbenchPrincipal），[sandbox-terminal.model.ts](file://packages/contracts/src/ai/sandbox-terminal.model.ts)（关键符号：SANDBOX_TERMINAL_NAMESPACE / SandboxTerminalClientEvent / SandboxTerminalServerEvent / SandboxTerminalErrorCode）

类级 `@UseGuards(TenantPermissionGuard)`；下表「RoleGuard」列指方法级 `@UseGuards(RoleGuard) @Roles(SUPER_ADMIN)`。**注意：三条读端点没有 RoleGuard 装饰器，但服务层 `assertAuthorizedActor()` 仍做同等（更严）校验**。

## 十四、错误语义

- **配额超限**：Redis 三桶租约（`SANDBOX_JOB_GLOBAL_LIMIT` 默认 20 / `SANDBOX_JOB_TENANT_LIMIT` 4 / `SANDBOX_JOB_USER_LIMIT` 2）任一满即抛 `SandboxJobRuntimeError('SANDBOX_CAPACITY_UNAVAILABLE', …, retryable=true)`——这是**作业层**错误，不是 HTTP 端点错误；Runner 侧另有独立准入（见 07）。
- **启动失败**：托管服务 → 400 `service_start_failed`（透传 provider 文案）；沙箱 provider 创建阶段失败（协议不满足、卷越界、Runner 不可达）→ 走 provider 异常，HTTP 上表现为 400 `provider_unavailable` 或 5xx。
- **超时**：`NsjailExecutionRequest.timeoutMs` 由 runner 客户端以 `timeoutMs + 宽限期` 发出；`streamExecute` 超时抛 `NsjailRunnerTimeoutError`（可重试类）；作业执行侧以 `Math.min(input.timeoutMs, definition.hardDeadlineMs)` 收敛（注册表只声明 `hardDeadlineMs`），作业侧 `hardDeadlineAt` 到期后由清理扫描接管。
- **取消**：作业取消 → `cancelled`；WS 侧取消 = `close(requestId)`（pending open 标记 canceled，迟到会话被立即关闭，客户端收到 `closed: client_closed`）。
- **预览签名失效**：无 cookie → 401 `Sandbox preview session is required.`；票面与路径不符/过期/签名错误 → 401 `Sandbox preview session is invalid.`；签名密钥缺失 → 500 `provider_unavailable`。
- **产物不存在**：作用域不匹配与真不存在都返回 404 `Artifact was not found`；**已删除/已吊销/已过期**返回 410（`Artifact was deleted` / `Artifact link was revoked` / `Artifact link expired`）；管理面版本内容缺失 404 `Artifact version was not found`；`workspace-file-access` 的失效一律 404，origin 不符 403。
- **健康探测失败**：任一 indicator 抛错 → Terminus 聚合为 503（`/health`）；`/health/ready` 在 `draining`/`unready` 时 503 并带 `Cache-Control: no-store`；普通请求在 drain 期间收到 503 `RUNTIME_DRAINING` / `RUNTIME_NOT_READY` ＋ `Retry-After: 5`。
- **运行时重启**：`confirmation` 缺失/不符 → 400 `RUNTIME_RESTART_CONFIRMATION_REQUIRED`；已有进行中的重启 → 409；非交互式/非超管/非默认租户 → 403 三兄弟；查询不存在的 `restartId`/`generation` → 404。
- **WS 错误语义**：鉴权失败 `WsException({ status: 403 })`；无 terminal 适配器 → `error{code: unsupported_provider}` ＋ `closed{reason: unsupported_provider}`；会话丢失 → `error{code: session_not_found}`。
