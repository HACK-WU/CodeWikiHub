## 二、运行方式

`server-ai` 与 `server` 各自持有 jest 配置（`preset: '../../jest.preset.js'`，ts-jest ＋ babel-jest 混用，`moduleNameMapper` 把 `@xpert-ai/server-core`、`@xpert-ai/contracts`、`@xpert-ai/plugin-sdk` 直指源码，无需先构建依赖包）。

```bash
# 1) sandbox / artifacts / workspace-file-access（server-ai 包）
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --runTestsByPath packages/server-ai/src/sandbox/sandbox.controller.spec.ts \
                   packages/server-ai/src/sandbox/sandbox-terminal.gateway.spec.ts

# 2) runtime-control（server 包）
node node_modules/jest/bin/jest.js --config packages/server/jest.config.ts \
  --runTestsByPath packages/server/src/runtime-control/runtime-restart-coordinator.service.spec.ts

# 3) 按名称过滤（-t 例：只跑预览 cookie 与代理相关）
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --testPathPattern 'src/sandbox/' -t 'preview session'
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --testPathPattern 'src/sandbox/' -t 'proxies managed service requests'

# 4) Nx 方式（项目名已核实：server-ai / server）
corepack pnpm exec nx run server-ai:test --runInBand --skipNxCache
corepack pnpm exec nx run server:test --runInBand --skipNxCache
```

**Runner 侧（非 Jest）**：`.deploy/nsjail-runner/test_runner.py` 是 `unittest` 套件（11 个测试类，`if __name__ == "__main__": unittest.main()`），另有 `poc_validate.py`（POC 校验，需在容器内 `python3 /app/poc_validate.py`）与 `verify_app_data.py`（`.apps` 挂载/RPC 回归，需 Linux mount namespace）。这三者**不计入 46**，也不由 `nx test` 驱动。

章节来源：[jest.config.ts](file://packages/server-ai/jest.config.ts)（关键符号：displayName server-ai / moduleNameMapper / transform），[jest.config.ts](file://packages/server/jest.config.ts)（关键符号：displayName server），[project.json](file://packages/server-ai/project.json)（关键符号：server-ai.targets.test），[project.json](file://packages/server/project.json)（关键符号：server.targets.test），[test_runner.py](file://.deploy/nsjail-runner/test_runner.py)

## 三、断言与 mock 风格

- **控制器边界断言（主力）**：`sandbox.controller.spec.ts` 直接 `new SandboxController(...)` 注入假 service（`organizationScopeService.run` 透传回调、`sandboxConversationContextService.resolveConversationSandbox` 返回固定 provider/workspace），断言「匿名通配拒绝受保护子路径」「跨租户 tenant hint 被忽略」「符号链接落点被复查」等——**防的是越权与路径穿越**，不验证真实文件系统。
- **错误映射断言**：`it('maps managed service errors into http exceptions')` 用 `SandboxManagedServiceError` 驱动，核对 404 `service_not_found` / 409 `service_name_conflict` / 400 兜底。
- **WS 事件断言**：terminal gateway spec 用假 socket（`emit` 断言事件名与 payload）＋ 假 adapter（`open/write/resize/close` 为 jest.fn），断言成功序（`opened → output → exit → closed`）与失败序（`error → closed`）、pending open 取消语义。
- **守卫级断言**：`runtime-control.controller.spec.ts` 断言方法上的 `TenantPermissionGuard`/`RoleGuard` 与 `@Roles` 元数据仍在（`preserves tenant and role guards on membership and restart endpoints`）。
- **Runner 契约以 stub 驱动**：nsjail 三件套用替身 Runner client（含 `/health` 能力协商），不拉真实 nsjail。
- **服务级内存替身**：`workspace-file-access.service.spec.ts` 自建 cacheManager 替身，断言 HttpOnly 会话 cookie、opaque grant、同源 iframe fetch 无 Origin/Referer 的放行分支、跨 Project 数据作用域复用被拒、跨租户 provider 资源被拒。
- **纯函数/头部断言**：`workspace-file-content.controller.spec.ts`（954B）只测 `buildWorkspaceFileContentDisposition` 的 ASCII 安全与 RFC 5987 编码，并用 `validateHeaderValue` 复核。

章节来源：[sandbox.controller.spec.ts](file://packages/server-ai/src/sandbox/sandbox.controller.spec.ts)（关键符号：maps managed service errors into http exceptions / registered volume routes），[workspace-file-access.service.spec.ts](file://packages/server-ai/src/workspace-file-access/workspace-file-access.service.spec.ts)（关键符号：same-origin iframe fetch previews / delegated runtime session scope），[workspace-file-content.controller.spec.ts](file://packages/server-ai/src/workspace-file-access/workspace-file-content.controller.spec.ts)（关键符号：buildWorkspaceFileContentDisposition）

## 五、缺口

- **WS 终端**：`sandbox-terminal.gateway.spec.ts` 覆盖 4 类消息与关闭语义，但 `SandboxTerminalAuthGuard` **无独立 spec**——`cs-x-` client-secret 分支、`handshake.auth.token` 形状、默认租户/组织头回填、`open` 时的 `ChatConversation` 查询失败路径均只在网关 spec 里被间接绕开（spec 直接注入已认证 socket）。
- **proxy 预览**：`sandbox.controller.spec.ts` 只有 2 条间接用例（`proxies managed service requests through the service layer`、`creates a preview session cookie for iframe access`）；`SandboxPreviewAuthGuard` 与 `SandboxPreviewSessionService` **无独立 spec**——票面/路径不一致、cookie path 边界、TTL 过期、`PreviewUnavailable` 400 分支均无守卫级断言。
- **清理路径**：`cleanupOrphans` / `cleanupPending` / `cleanedAt` 在 sandbox 的 34 个 spec 中**命中 0**——孤儿运行时清理（60s 间隔扫描、`hardDeadlineAt < now` 与 `cleanupPending:true`）与 `requirePreviousAttemptCleanup` 未被测试取证。
- **运行时重启**：coordinator/lifecycle/shutdown 系列有 10 个 spec（含 28.3KB 主线与 rollout-regressions），但 `runtime-drain.middleware.ts`、`runtime-process-signaler.ts`、`runtime-rollout-policy.ts`、`runtime-restart-deadlines.ts`、`plugin-runtime-generation.store.ts`、`plugin-runtime-requirements.ts`、`plugin-convergence-capacity.ts` **无同名 spec**；drain 期间 503 ＋ `Retry-After` 的行为没有测试直证。
- **health**：模块 **0 spec**——DB `count()` 探活、磁盘 `thresholdPercent: 99.999999`、cache set/get、`REDIS_ENABLED` 开关四条分支与 `/ready` 的 503 语义均无测试。
- **artifacts**：仅 service ＋ controller 两个 spec；`ArtifactLink` 的 `expired/revoked` 410 取值、"签名预览 TTL 15 分钟"、分享会话 cookie 的 `sameSite/secure` 组合、CSP 两档 profile 无逐条断言。

章节来源：[sandbox-terminal.gateway.spec.ts](file://packages/server-ai/src/sandbox/sandbox-terminal.gateway.spec.ts)，[sandbox-preview-auth.guard.ts](file://packages/server-ai/src/sandbox/sandbox-preview-auth.guard.ts)（关键符号：canActivate），[health.controller.ts](file://packages/server/src/health/health.controller.ts)（关键符号：check / readiness），[artifacts.service.spec.ts](file://packages/server-ai/src/artifacts/artifacts.service.spec.ts)

## 六、可执行性结论

判定：**✅ 可跑（本次不实跑，仅给命令与判据）**。判据：

1. 46 个 spec 中 43 个（sandbox 去掉本机进程/浏览器相关 6 个以外的多数、runtime-control 10、artifacts 2、workspace-file-access 2）为纯单测，Repository/Redis/Runner 契约均为替身，可用第二节命令 1/2 直接执行；
2. 必须按包切换配置：`sandbox`/`artifacts`/`workspace-file-access` 用 `packages/server-ai/jest.config.ts`，`runtime-control`（含 health 相关）用 `packages/server/jest.config.ts`，跨配置混跑会因 `moduleNameMapper` 不解析内部路径而失败；
3. 需外部工具链的用例集中在 `sandbox-job/local-*` 与 `local-browser-runtime*`，在 CI 容器里应显式分组/排除，不属代码缺陷；
4. `nx run server-ai:test` / `nx run server:test` 与直接 jest 等价（`@nx/jest:jest` 指向同一配置），无全局 setup 文件，fixture 各 spec 自带；
5. Runner 侧 Python 用例（`test_runner.py`、`poc_validate.py`、`verify_app_data.py`）需容器与 Linux 特权，**不能**并入 Jest 通道判定本批模块的可执行性。
