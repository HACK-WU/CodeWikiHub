## 插件包入库链
三步：**来源校验 → digest 计算 → 幂等 upsert**，全部收敛在 `AgentPluginService.importStagedDirectory(root, source, activate, manager)`。

1. **来源获取**。`POST agent-plugins/git` 的输入只有 `{url, ref, subdirectory?}`；`stagePortableGit` 先 `new URL(url)` 断言 `https:` 且无 username/password/hash，再断言 ref 非空、不以 `-` 开头、不含 CR/LF/NUL，然后 `mkdtemp` 到系统临时目录执行 `git init` → `git fetch --depth=1 -- <url> <ref>` → `rev-parse FETCH_HEAD` → `checkout --detach FETCH_HEAD`，返回 `{temp, root, commit}`（`root` 由 `containedPath(temp, subdirectory)` 遏制）。`POST agent-plugins/zip` 走 `FileInterceptor('file', {limits:{fileSize:100MB, files:1}})` → `extractPortableZip` 流式逐条写盘（拒绝符号链接、重复项、反斜杠、绝对路径、越界项，逐条校验声明大小），若解压根只有单一目录且不含 `plugin.json` 则自动下钻一层。
2. **解析与 digest**。`parseAgentPlugin(root)` 产出 `PortablePlugin`；`portablePackageDigest(root)` 用 `sha256` 按「路径 \0 内容 \0」顺序累积（`walkPortablePackage` 只走遏制内的常规文件，跳过 `.git`，把坏链/环/越界项交给 `skipped`），得到 64 位 hex digest。上限：单包 100MB / 10000 文件；遍历中若文件大小变化抛 `Plugin changed during import`。
3. **幂等 upsert**（单事务）：`lockPackageScope` →（`activate` 时先读 `currentPackageBinding(scope, descriptor.name)`）→ 按 `{...scope, digest}` 查既有行 → `packageIntact(existing.rootPath, digest, scope)` 复查磁盘 → 不完整才 `stagePackageFiles`（新 UUID 目录 + `copyPortablePackage` + 复查 digest）并把旧 `rootPath` 交 `retirePackageFiles` 入队 → `save`（既有行保留 `id/createdAt/bindings`，只更新 `descriptor/rootPath`，且仅在 `activate` 时覆盖 `source`）→ `activate` 且默认 binding 变更时 `activatePackage` → 返回结果带 `importStatus: imported | existing | repaired`。事务提交后另起事务做 best-effort `collectPackageGarbage`（失败被 `.catch(() => undefined)` 吞掉）；未提交且已落盘则 `removePackageFiles` 回滚文件。

## descriptor 解析与能力枚举
`parseAgentPlugin` 是唯一的包内解析器，返回 `PortablePlugin = {name, version?, description?, extension?, skills[], servers[], templates?, templateCatalog?, diagnostics[]}`。执行顺序与降级策略：

1. **manifest**：`readJson(root,'plugin.json')`（`containedPath` + `stat.isFile()` + ≤4MB）→ 剔除 `manifestSchema.properties` 未声明的键并记 `unknown_field` 诊断 → 取出 `extensions` 命名空间（优先 `xpertai`，`cn.xpertai` 为旧别名；值非法也优先当前命名空间）→ Ajv 2020 `validateManifest`（失败即整体抛错）→ zod `manifestShape`。
2. **extension**：`extensionShape.strict()` 校验 `version ∈ {1,2}`、`role ∈ {capability,assistant,subagent}`、`templates[]`（`key` kebab-case ≤64，`path` 必须 `templates/**.(yaml|yml|json)`）、`connectors`、`interface`、`middlewares[]`、`experts[]`，并用 `refine` 保证三者 key 唯一 + `version===2 || !templates`；`commands` 键先被剥离单独处理。失败只记 `invalid_extension` 诊断，不阻断导入。
3. **templates**：逐个 `containedPath` + ≤4MB + `normalizeAssistantTemplate({export_data})`；`template.legacy` 为真即报 `Agent Plugin templates require template.schemaVersion 2`；成功则写入 `templateCatalog[key] = {name,title,description,avatar,type}`。
4. **skills**：`skills/` 下每个目录读取 `skills/<dir>/SKILL.md`（≤1MB），用正则切前置 frontmatter 再 `zod` 校验 `{name: kebab-case ≤64, description: 1..1024}`，`skill.name !== 目录名` 即错；单条失败记 `invalid_skill` 并跳过（`ENOENT` 静默）。
5. **commands**：`parseAgentPluginCommands(extension.commands, plugin.skills, report)`——命令必须挂在已识别 skill 上。
6. **servers（`mcp.json`）**：要求 `$schema` 匹配 `mcp.schema.$id`、只允许 `$schema`/`mcpServers` 两个键；每个 server 过 `validateServer`（schema `$defs/server`）；只接受 `type === 'streamable-http'`，其它类型记 `unsupported_transport` 并跳过；URL 必须是 `https:`（`http:` 仅允许 localhost/`[::1]`/`127.x`）且无凭据、无 fragment；header 名必须匹配 token 字符集、值不得含 CR/LF/NUL、不得重复，`authorization`/`proxy-authorization`/`cookie`/`x-api-key` 一律拒绝（「Configure credentials through the host, not package headers」）。

**能力枚举**由此固定为五类：`assistant_template`（`templates`）、`skill`（`skills`）、`mcp`（`servers`）、`middleware`（`extension.middlewares`）、`external_xpert`（`extension.experts`）——`RuntimeResourceService.describe` 与 `AgentPluginInstallationsService.catalog` 都按这个顺序拼 `components`，且 `components` 为空时状态直接降为 `unavailable`。

章节来源：[agent-plugin-parser.ts](file://packages/server-ai/src/agent-plugin/agent-plugin-parser.ts)（关键符号：parseAgentPlugin / PortablePlugin / containedPath）、[runtime-resource.service.ts](file://packages/server-ai/src/agent-plugin/runtime-resource.service.ts)（关键符号：RuntimeResourceService.describe）、[agent-plugin-installations.service.ts](file://packages/server-ai/src/agent-plugin/agent-plugin-installations.service.ts)（关键符号：AgentPluginInstallationsService.catalog）

## 装配与运行
插件的「用起来」分四段，只有第一段会写宿主表。

1. **配置（`POST agent-plugins/bindings`）**：`bindingSchema` 是 `discriminatedUnion('kind')`，`agent_plugin` 分支强制 `availability: 'scope'` 且 `workspaceIds` 清空；`createAuthorizedBinding` 会补 `connectorServers ??= descriptor.extension.connectors`、拒绝旧式 `oauthServers`（要求走 workspace connection）、校验每个 `extension.experts[].reference` 都有映射并对每个目标专家冻结 `publishedResourceVersion(publishAt)`，再算 `version = sha256(JSON.stringify({...input, expertVersions, digest}))`。带 `workspaceIds` 时才逐 workspace 调安装器装组件，并把 `{skills, toolsets, connectors}` 记进 `installations[workspaceId]`。
2. **可见性与引用**：`installedPluginBindings(packages, bindings, scope, workspaceId)` 按 `descriptor.name` 分组，**组织级安装（含 disabled）遮蔽租户级**，`supersededById` 非空的行被剔除；没有任何持久 binding 的包由 `importedPluginBinding(pkg)` 派生出「合成 binding」（id 由 `sha256('installed-agent-plugin:<tenantId>:<pkgId>')` 掩成 UUID 形状，`version` 由 `[id,digest,definition]` 派生），因此「导入即有稳定目录引用」。`AgentPluginInstallationsService.reference()` 是解析入口：binding+version 命中 + `enabled` + scope 级当前配置仍 enabled 才返回 `{binding, pkg}`。
3. **准备（`prepare`）**：以 `pg_advisory_xact_lock(hashtext('agent-plugin:<bindingId>'))` 串行化；先查 `missingExperts` 与 connector 需求，若 `installations[workspaceId]` 已存在且每个需求的 `connectors[key].bindingId` 未变则**直接返回既有 installation**；否则为 `pluginRuntimeComponents(pkg, binding.version)` 逐个 `installer.installRuntimeComponent`，Skill 命中后回写 `SkillPackage.runtimeResourceOnly = true`，MCP 命中后回写 `toolset.schema = JSON.stringify(portableMcpSchema(...))` 与 `options = {...options, needSandbox:false, pluginManaged:false}`，最后把 installation 写回 binding。
4. **注入运行时**：`RuntimeResourceService.resolve(assistantId, selection, projectId)`（注释：「A reference is not an authorization grant. Resolve the actor and scope again on every run/call.」）返回 `ResolvedRuntimeResources = {selection, skillIds, skillSources, toolsetIds, middlewares, experts, templates}`：middleware 一律以 `resource_<bindingId>[_<key>]` 为 node key、`internal expert` 逐个 `publishedExpert` 校验版本、`packages` 按 `definition` 去重（同 packageId 不同 definition 抛 `Error.AgentResourceConflict`），Skill 追加 `skillSources`（`rootPath` 指向包内目录、`runtimePath = agent-plugins/<pkgId>/<skillKey>`、`origin.type='plugin'`、`version = digest`），MCP 工具集逐个用 `matchesPortableMcpSchema` 复查 `category === MCP` + `needSandbox === false` + `pluginManaged === false` 全等，任一不符抛 403。最后 `applyRuntimeResourceGraph` 产**执行期 overlay**（不修改已发布/草稿图），必要时挂 `runtime_resource_skills` 中间件节点；`xpert-agent/collaborators/collaborators.middleware.ts` 消费 `runtimeResources.experts`；`subgraph.handler.ts` 用 `dynamicResources?.toolsetIds` 追加工具集装配。

## 与平台插件的关系
- **共用安装器**：`PluginResourceInstallerService` 是平台插件与 Agent 插件的唯一落库器。Agent 插件传入 `runtimeSource: 'agent-plugin'`，安装器据此写 `needSandbox: false`、`pluginManaged: false`，并把 `runtimeSource` 落进 `options`，`findPluginManagedToolset` 用 `options ->> 'runtimeSource' = 'agent-plugin'` 与平台插件路径（`options ->> 'pluginManaged' = 'true'`）分流——**同一个 workspace 下两条来源可以并存而不互相覆盖**。
- **与 `skill-package`**：Skill 组件经安装器 `skillPackageService.syncPluginSkillBundle` 落 `skill_package`，本子域随后把它标成 `runtimeResourceOnly = true`（迁移 `20260921` 新增该列），语义是「只服务运行时资源，不进技能仓库目录」。
- **与 `xpert-template`**：`AgentPluginTemplateService` 把包内模板翻译成 `TXpertTemplate`（id = `agent-plugin/<name>/<key>`、`source: 'agent-plugin'`、`export_data` 为规范化 DSL、`contentHash` 为 `sha256(export_data)`、`dependencies` 中指向自己的 selector 补 `digest`）；`resolve` 返回 `{component, lock}`，lock 里锁死 `pluginName/version(digest)/source{bindingId,bindingVersion}/components[{type,key,hash}]`，并立即 `retainTemplateReference`（`cleanupEligible = false`）把引用钉住；`assert` 在执行前重查引用、重算 digest、逐条比对 `definitionHash`，任一不符抛 `Error.TemplateDependencyChanged`。安装阶段由 `InstallAgentPluginTemplateResourcesHandler` 把 `portableServer`（含 `connectorMcpAuth`）塞回组件，走 `installComponentsForXpert` 后 `registerTemplateMcp` 记录 toolsets+connectors。
- **与 `xpert-workspace`**：`workspaceOptions/addToWorkspace/workspaceCatalog` 走 `XpertWorkspaceAccessService.assertCanWrite/assertCan(…,'manage')` 并强制 `workspace.organizationId === scope.organizationId`；`options()` 只枚举 `capabilities.canManage` 的工作区。

## 卸载禁用与版本替换
本子域**没有「卸载插件」端点**——README 逐字：「This is not a force-uninstall or cascading deletion feature.」

- **禁用/启用**：`PUT agent-plugins/bindings/:id` → `setEnabled(id, enabled)`：`lockPackageScope` + `pg_advisory_xact_lock('agent-plugin:<id>')`，binding 不存在时回落到「合成 binding」（`importedPluginBinding`）再保存；同时强制 `cleanupEligible = false`。scope 级禁用会连带撤销旧选择（`reference()` 里 `!current?.enabled` 即判 undefined）。
- **工作区增删**：`addToWorkspace` 在同事务内先按 `(<tenant>:<org>, <workspaceId>:<pluginName>)` 取锁，已 enabled 返回 `{status:'already_added'}`，存在但 disabled 抛 409 `Error.AgentPluginWorkspaceDisabled`，否则建一条 `workspaceIds:[workspaceId]` 的新 binding。**没有 remove-from-workspace 端点**——移除靠禁用。
- **版本替换（Git 更新）**：`POST agent-plugins/packages/:id/update {branch}` → 202 + `AgentPluginUpdateProgress`。`start` 在 `store.control` 内创建/续传收据（`phase:'updating'`），`run` 抢 worker 长锁后：`stagePortableGit(url, progress.commit ?? 'refs/heads/<branch>', subdirectory)` → 先落 `progress.commit`（崩溃可续跑同一 commit）→ 校验新包 `descriptor.name` 与旧包一致（否则 `Error.AgentPluginUpdateIdentityChanged`）→ `importStagedDirectory(root, source, activate=true, manager)` → `phase:'completed'` + `result{packageId,status}`。固定 commit 的来源必须显式给 branch（`/^[a-f\d]{40,64}$/i` 判为不可用分支）。
- **清理旧版本**：`GET/POST agent-plugins/packages/:id/cleanup` → `inspect` 为同 name 的每个包标注 `reason ∈ {current, updating, configured, referenced, unreferenced}`，只有 `unreferenced` 且被请求的才会 `assertPackagePath` → `retirePackageFiles` → 删 binding → 删 package；删除动作全部在锁内，事务外再 `collectPackageGarbage` 真正落盘删。`configured` 判定包含 `!cleanupEligible || Object.keys(installations).length`。

章节来源：[agent-plugin-cleanup.service.ts](file://packages/server-ai/src/agent-plugin/maintenance/agent-plugin-cleanup.service.ts)（关键符号：inspect / preview / cleanup）、[agent-plugin-update.service.ts](file://packages/server-ai/src/agent-plugin/maintenance/agent-plugin-update.service.ts)（关键符号：start / run）、[agent-plugin.service.ts](file://packages/server-ai/src/agent-plugin/agent-plugin.service.ts)（关键符号：setEnabled / addToWorkspace）

## 错误语义
| 场景 | 触发点 | 表现 |
|---|---|---|
| 来源不可达 / 格式非法 | `importGit` / `importZip` / `importStagedDirectory` | 统一包成 `BadRequestException`：`Error.AgentPluginImportFailed`（带 reason） |
| 官方源不可达 / manifest 非法 | `DefaultAgentPluginsImporter` | `Error.DefaultAgentPluginsSourceUnavailable` / `Error.DefaultAgentPluginsManifestInvalid` |
| descriptor 非法 | `parseAgentPlugin` 的 manifest 校验 | 直接抛错（Ajv 错误文本透传）→ 上抛为 ImportFailed |
| 组件级非法 | 单条 skill / server / template | **不抛错**，只进 `descriptor.diagnostics`（`invalid_skill`/`invalid_server`/`invalid_template`/`unsupported_transport`/`unknown_field`/`unsafe_path`），目录侧状态降为 `partial` |
| digest 冲突 | `importStagedDirectory` 命中同 digest 行 | **不是错误**：返回 `importStatus: 'existing'`；磁盘损坏则 `'repaired'` |
| 包不存在 | `addToWorkspace` / `createAuthorizedBinding` / `update` / `cleanup` | `NotFoundException`：`Error.AgentPluginNotFound` |
| 更新身份变化 | 更新包 `descriptor.name` 与旧包不同 | `Error.AgentPluginUpdateIdentityChanged` |
| 收据冲突 | 续传 operationId 不匹配 / 有活跃作业 | `ConflictException`：`Error.AgentPluginUpdateChanged` / `Error.AgentPluginUpdateBusy` |
| 版本/摘要漂移 | `loadRuntimeTemplate`、`resolve`、`assert`、`RuntimeResourceCommandsService` | `Error.TemplateDependencyChanged`；Skill 指令源变化为 `Error.PluginCommandSourceChanged` |
| 资源不可用 | `resolve` 找不到 binding、scope 不符、`matchesPortableMcpSchema` 全等失败、`assertToolsetAccess` | `ForbiddenException`：`Error.AgentResourceUnavailable` |
| revision 冲突 | 会话资源 CAS（`RuntimeResourceService.update`/`prepare`） | `ConflictException`：`Error.AgentResourceRevisionConflict` |
| 连接器缺失 | connector 需求无绑定 / 用了 workspace connection | `Error.AgentPluginConnectorConfiguration` / `Error.ConnectorWorkspaceConnectionRequired` |

## 设计模式及落点
| 模式 | 落点 |
|---|---|
| 端口/适配器（只在宿主边界翻译） | `portableMcpSchema` / `connectorMcpAuth`：包内保持标准描述符，`type:'http'` 与 `auth` 只在写 `XpertToolset.schema` 时注入 |
| 内容寻址 + 幂等 upsert | `portablePackageDigest` + `(tenantId,organizationId,digest)` 唯一 + `importStatus` |
| 合成身份（不落库的派生实体） | `importedPluginBinding`（sha256 → UUID 形状 + 派生 version）、`discoverRuntimeResources` 的 `discoveredBinding` |

## 热点路径
1. **`importStagedDirectory`**：单次调用 = 一次全包遍历算 digest +（不完整时）一次全包拷贝 + 再一次 digest 复查 + 一次事务写；`stagePackageFiles` 内部两次 `walkPortablePackage` 是最大常数因子。
2. **`AgentPluginCleanupService.inspect`**：全库 JSON 列 LIKE 扫描（`referencedPackages`）+ 为每个家族成员取锁，随库与版本数线性恶化。
3. **`AgentPluginInstallationsService.prepare`**：首次安装 N 个组件 = N 次 `installRuntimeComponent`（含 MCP 能力加载），且必须持有 binding 锁。
4. **`RuntimeResourceService.resolve`**：每次执行前跑；逐 reference 查库/回落目录/校验 workspace、逐 server 复查 schema 全等、逐 expert 校版本。
5. **`RuntimeResourceService.catalog`**：逐 binding `describe`，非插件类还要各跑一次 `resolve` 探测（失败才标 `unavailable`），再叠加 `discoverRuntimeResources` 的自动发现。
6. **`AgentPluginConnectorService.provider`**：每次 MCP 凭据解析都要重查 scope/user/execution 一致性、工具集、owner binding、有效目录与 schema 全等，然后才取运行凭据。

## 技术债与 hack
1. **`RuntimeResourceController` 不在本模块**：`AgentPluginModule.controllers` 只有两个控制器，`RuntimeResourceController` 由 `ai.module.ts` 注册。`[推测]` 是为规避 `ai` 与 `agent-plugin` 的循环依赖；代价是「本子域路由全景」必须两处并读。
2. **默认 `activate=false`**：`POST agent-plugins/git|zip` 不传 `activate`，因此导入后**不会**自动产生持久默认 binding，目录里出现的是合成 binding；要变成可配置需要再调 `POST agent-plugins/bindings`。`[推测]` 这是刻意的「安装≠配置」。
3. **`AgentPluginService` 无同名 spec**：30 个 spec 中不存在 `agent-plugin.service.spec.ts`，导入编排只被 `workspace-plugin.service.spec.ts`、`defaults/*.spec.ts`、`maintenance/package-maintenance.integration.spec.ts` 间接覆盖。
4. **组件投影函数重复**：`AgentPluginService.components()` 与 `AgentPluginInstallationsService` 导出的 `pluginRuntimeComponents()` 是两个几乎同构的实现（同样映射 skills/servers、同样拼 `agent-plugin-<pkgId>-<version 前 12>`），差异只在收尾 `.map()` 的字段。
5. **`cleanupEligible` 语义面窄**：只有 `activatePackage`（自动默认）置 true，`setEnabled` 与 `retainTemplateReference` 都强制置 false；`[推测]` 该列一旦被别的路径赋 true 就会扩大可回收集合。
6. **保守扫描无索引**：`referencedPackages` 对每个含 json/jsonb/simple-json 列的表做 `CAST(... AS text) LIKE '%token%'`，且 token 含 digest/bindingId/version，全表扫描不可避免。
7. **存储路径是环境约束而非代码保证**：`packageScopeDirectory` = `process.env.XPERT_AGENT_PLUGIN_PATH || 'storage/agent-plugins'`；README 要求「storage root must be on durable storage shared by API workers」，多副本部署下由运维承担。
8. **删除失败无上报**：`collectPackageGarbage` 把失败路径留在 `tenant_setting` 队列里静默重试，没有指标或告警；`[推测]` 长期失败会无感堆积。
9. **ZIP 来源无法自动更新**：`AgentPluginUpdateService.target` 强制 `source.kind === 'git' && source.url`，zip 只能重新上传，且 `source` 是 jsonb 无校验器（唯一消费者是 update service）。
10. **`installations` jsonb 的写入纪律靠锁而非约束**：任何绕过 `prepare` / `registerTemplateMcp` / `createAuthorizedBinding` 直接 `save(binding)` 的代码都会丢写并发投影；代码里没有 DB 约束或版本号兜底。
11. **官方源硬编码**：`DEFAULT_AGENT_PLUGINS_SOURCE` 指向 `https://github.com/xpert-ai/xpert-plugins.git` 的 `main` 分支 `agent-plugins/` 子目录；README 明说「Callers cannot override the official source or target scope」，即离线环境无替代入口。
12. **迁移是手工 SQL**：`migrations/*.sql` 三份为独立 DDL 文件（`20261012` 首次去掉 `organizationId NOT NULL`，`20261015` 新增 `cleanupEligible`），README 要求「deploy Web and API together」「apply … before creating tenant installations」——版本耦合由部署流程承担。

## 设计维度分析
**声明式描述符 vs 宿主投影：只在边界翻译**。`PortablePlugin.servers[].config` 严格限定为 `{type:'streamable-http', url, headers?}`，而宿主需要 `type:'http'` + 可选 `auth:{type:'connector'|'oauth', ...}` + `needSandbox:false` 等本地语义——翻译集中在 `portableMcpSchema`，反向校验集中在 `matchesPortableMcpSchema`（`isEqual(JSON.parse(schema), portableMcpSchema(...))`）。好处是包格式与宿主实现解耦、可移植；代价是**校验是全等比对而非子集比对**，任何宿主侧对 `xpert_toolset.schema`/`options` 的额外写入都会让运行时判定「资源不可用」（403），而不是降级或自愈。

**内容寻址 vs 可变引用：身份不可变、引用可 pin**。包身份 = `digest`（内容哈希），binding 身份 = 合成 UUID，`version` = 由 `[id, digest, definition]`（或 `[...input, expertVersions, digest]`）派生的 sha256。更新只新增默认 binding 并 `supersededById` 链接，历史引用（含会话选择、模板 lock、专家版本）一律不重写——README 逐字承诺这一点。好处是历史会话与已装助手始终可解析；代价是旧包必须留在磁盘上，清理只能由保守扫描 + 显式 `cleanup` 完成，磁盘占用单调增长。

**同步 HTTP vs 后台收据：无队列的作业化**。导入/更新/默认导入三条链统一「HTTP 只创建或续传收据，工作在线程外」，进度写 `tenant_setting`（键含 tenant+organization），默认导入用短控制锁 + 长 worker 锁两级以「不占满连接池」。好处是不引入 Bull/Redis 依赖、续跑语义显式；代价是**所有并发与恢复语义都必须自己实现**（`operationId` 校验、`release` 于进程退出、锁持有者复用同一连接），可观测性也只是收据本身。

**授权与可见性分离**：可见性来自 `installedPluginBindings`（组织遮蔽租户、`supersededById` 剔除、`enabled` 判定），授权来自每次调用重解析的 scope/workspace/connector grant；`assertToolsetAccess` 还专门为「MCP App RPC 比发起 run 活得更久」补了一层校验。好处是目录读取零副作用（README：「Catalog reads do not install skills, toolsets or Connector bindings.」）；代价是每次执行都要付一次多跳查询。

## 结论
实现上，本子域把「便携包」做成了一个可复现、可续跑、可回滚的流水线：**来源校验（HTTPS/no-credential/ref 白名单、ZIP 遏制）→ 内容 digest（路径有序 sha256）→ 幂等 upsert（scope+digest 唯一，`imported|existing|repaired`）→ 声明式解析（Ajv 2020 + zod v3 双轨，组件级失败降级为 diagnostics）→ 声明式配置（binding + 专家版本 + connector 需求）→ 安装器投影（`runtimeSource:'agent-plugin'`）→ 执行期 overlay（`applyRuntimeResourceGraph`）**。全部并发语义由 PG advisory lock 承担，全部进度语义由 `tenant_setting` 收据承担，因此本子域**没有队列表、没有 worker 框架**。

需要重点防守三处：① `installations` jsonb 的写入必须始终在 binding 锁内；② `digest` 是唯一版本身份，包内容变更必须产生新 digest，绝不允许原地改写；③ `matchesPortableMcpSchema` 的全等校验是运行时可用的硬闸门，改动 `XpertToolset.schema`/`options` 的其它路径必须同步考虑它。新增能力时应继续走「descriptor 声明 → 组件枚举 → 安装器投影 → 运行时复查」的既有骨架。
