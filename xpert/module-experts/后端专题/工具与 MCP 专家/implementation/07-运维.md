## 三、子进程 / stdio 运行时运维

启动链路：`McpStdioRuntimeManager.prepareServer()` 组装 spec → `spawn` **runner**（`mcp-stdio-runner.js`，spec 走 `XPERT_MCP_STDIO_RUNNER_SPEC` 传 base64 JSON）→ runner 内部再 `spawn` 真实 MCP server（`detached: true`、`stdio: ['pipe','pipe','pipe']`、`shell: false`），stdio 双向 pipe 透传。

审计与可观测字段（`mcp_runtime_instance` 表 + `GET /api/xpert-toolset/operations/mcp-runtimes`）：

| 字段 | 来源 | 用途 |
|---|---|---|
| `runnerPid` | 宿主 spawn runner 的 pid（`Reflect.get(transport,'_process')`） | 定位 runner 进程 |
| `childPid` | 从 runner stderr 用 `/\[xpert-mcp-stdio-runner\]\s+child pid=(\d+)/` 解析 | 定位真实 MCP server 进程 |
| `stderrTail` | stderr 尾部，`STDERR_TAIL_MAX_BYTES = 16KB` 截断保留 | 排障主入口（runner 会打 `terminating runtime=… reason=…`） |
| `commandLabel` / `commandHash` | `basename(command)+args`；args 命中 `token\|secret\|password\|passwd\|key=` 一律替换成 `[redacted]`；hash 为 sha256 | 变更追踪＋脱敏 |
| `policySnapshot` | provider/startupTimeoutMs/idleTimeoutMs/maxLifetimeMs/allowedCommands(basename) | 复查当时生效策略 |
| `status` / `closeReason` / `startedAt` / `readyAt` / `closedAt` / `startupDurationMs` / `durationMs` | 生命周期事件 | 与 `live` 快照合并展示 |

**终止与僵尸进程**：宿主侧关闭 = `transport.close()`，失败则 `killProcess(runnerPid,'SIGTERM')` + `killProcessGroup(childPid,'SIGTERM')`；runner 侧收到 stdin close/end、父进程 `disconnect`、SIGINT/SIGTERM 都会 `terminate()`，先 `process.kill(-child.pid, SIGTERM)`（Windows 退化为 `child.kill`），**3 秒后补 SIGKILL**。运维端点：`POST /operations/mcp-runtimes/:runtimeId/stop`（单个）、`POST /operations/mcp-runtimes/kill`（按 filter 批量，body 即 filter），两者都要求 `SUPER_ADMIN`。

**残留记录清理**：`McpRuntimeAuditService.onApplicationBootstrap()` 把 DB 里 `status ∈ {starting, running, closing}` 的记录批量改成 `closed`、`closeReason='host-restart-or-lost'`——因为进程随宿主消失，这是**预期行为**，不是异常。

**`pluginManaged` 语义**：`toolset.options.pluginManaged===true` 且带 `options.pluginName` 时视为插件托管，`resolvePluginManagedMcpContract()` 从已加载插件 bundle 里取 `PLUGIN_COMPONENT_TYPE.MCP_SERVER` 组件，并把 `${PLUGIN_ROOT}`/`${PLUGIN_DATA}`（及 `@runtime__*` 旧路径）替换成真实路径；`PLUGIN_DATA` 落在 `process.cwd()/.xpertai-plugin-data/<tenant>/<workspace>/<plugin>/<componentKey>`。契约缺失时**直接抛错**（`not available in the current plugin manifest`），此时表现为"工具发现为空"。插件托管还跳过 toolset 级 runtime 策略，只用服务端策略。

## 四、迁移现状：谁依赖 synchronize、谁有 SQL

| 模块 | `migrations/*.sql` | 结论 |
|---|---|---|
| `xpert-toolset` | **未找到** | 表结构（`xpert_toolset`、`mcp_runtime_instance` 等）只能由实体驱动；无自有 DDL 文件 |
| `xpert-tool` | **未找到** | 同上（`xpert_tool`） |
| `mcp` | **未找到** | 该模块 0 实体、0 表，天然不需要 DDL |
| `mcp-publication` | **未找到** | 8 张自有表（`mcp_publication`、`mcp_publication_capability`、`mcp_capability_catalog`、`mcp_publication_access`、`mcp_api_key`、`mcp_oauth_policy`、`mcp_invocation_audit`、`mcp_task`）无 SQL 文件 |
| `agent-plugin` | **3 份**：`20260921-agent-plugins.sql`、`20261012-agent-plugin-installation-scope.sql`、`20261015-agent-plugin-maintenance.sql` | 建 `agent_plugin_package`（+`IDX_agent_plugin_package_scope`）、`agent_resource_binding`（+`IDX_agent_resource_binding_scope`）；`ALTER TABLE skill_package ADD COLUMN runtimeResourceOnly`；`agent_resource_binding` 追加 `supersededById`、`expertVersions`；第二份把两条 FK 的 `organizationId DROP NOT NULL`（事务包裹）；第三份加 `cleanupEligible boolean NOT NULL DEFAULT false` |

结论（**核实后**）：**不是"全靠 synchronize"也不是"全走迁移"**，而是 `agent-plugin` 明确要求先手工执行 SQL（README 的 Database upgrade / 维护段落逐字要求"在创建租户安装前应用 `20261012`"、"部署前应用 `20261015`"），其余 4 个模块**没有任何 DDL 文件**，其表结构只能依赖宿主的 TypeORM 同步策略（`synchronize`）或平台统一迁移线。因此：

1. 升级 `agent-plugin` 相关版本时，必须把 3 份 SQL 纳入发布清单，且 20260921 的注释要求 `-- Apply in a transaction before enabling composer.resources.`；
2. 升级其余模块时，若宿主关闭了 `synchronize`，`mcp_runtime_instance`、`mcp_publication*` 这批表不会自动出现 → 表现为启动期关系缺失/查询报错；
3. 回滚建议：新增列/nullable 放宽均为向后兼容（`20261012` 只放宽约束），优先保留；不要回滚 `20261015` 的 `cleanupEligible` 默认值语义。

章节来源：[20260921-agent-plugins.sql](file://packages/server-ai/src/agent-plugin/migrations/20260921-agent-plugins.sql)，[20261012-agent-plugin-installation-scope.sql](file://packages/server-ai/src/agent-plugin/migrations/20261012-agent-plugin-installation-scope.sql)，[20261015-agent-plugin-maintenance.sql](file://packages/server-ai/src/agent-plugin/migrations/20261015-agent-plugin-maintenance.sql)，[README.md](file://packages/server-ai/src/agent-plugin/README.md)（关键符号：Database upgrade / Before deploying to databases maintained with the standalone SQL migrations），[mcp-runtime-instance.entity.ts](file://packages/server-ai/src/xpert-toolset/mcp-runtime-instance.entity.ts)（关键符号：@Entity('mcp_runtime_instance') / @Index）

## 五、密钥与凭据运维

| 对象 | 落库形态 | 轮换手段 | 脱敏边界 |
|---|---|---|---|
| `xpert_toolset.credentials` | **json 明文**（`createBuiltinToolset` 里 `// encrypt credentials` 被注释掉） | 重新提交/覆盖该 json（`POST builtin-provider/:name/instance` 带 `id` 走 update） | 实体 `@Exclude({toPlainOnly:true})` + 只由 `GET /:id/credentials`（`ToolsetGuard`）回吐；日志中不得出现 |
| `mcp_api_key.keyPrefix` | 明文 24 字符（`xpert_mcp_` 前缀 + 随机串开头） | 随 `rotate` 换新 | **可用于检索**（`authenticate` 按 prefix 查行），不算秘密 |
| `mcp_api_key.keyHash` | sha256 hex，`select:false` + `@Exclude` | `rotate` = 旧键撤销 + 新键 | 不可逆 |
| `mcp_api_key.encryptedSecret` | `encryptSecret(secret, environment.secretsEncryptionKey)`，仅"可回显"路径写入 | 换 `SECRETS_ENCRYPTION_KEY` 前必须先轮换/重建 Key，否则旧值不可解 | `select:false`；`getOrCreateRevealableCredential` 仅当前用户+同组织可解一次 |
| `mcp_oauth_policy.introspectionClientSecretEncrypted` | 加密列，`select:false` | `PUT oauth-policy` 的 `clientSecret`：省略=保留、`null`=清除、新值=轮换 | DTO 注释逐字写明该语义 |
| `mcp_invocation_audit.argumentSummary` / `mcp_task` 的 payload 类列 | `select:false` | 随任务生命周期 | 默认查询不出现在视图 |
| `mcp_runtime_instance.commandLabel` | args 内 `token/secret/password/passwd/key=` 一律 `[redacted]` | — | 审计列表可直接看 |

运维要点：`SECRETS_ENCRYPTION_KEY` 必须显式设置且**跨副本一致**（API Key 解密在本进程完成）；`rotate` 会立即广播 access 失效（`publishAccessInvalidated`），客户端需在过渡窗口内完成换 Key；`revoke` 不删行，审计可追溯 `revokedAt`/`revokedById`。

## 六、对外发布运维

- **域名与端点**：`mcpPublicationPublicUrl()` = `ConfigService.get('baseUrl') || process.env.API_BASE_URL || 'http://localhost:3000'` + `/api/mcp/p/<encodeURIComponent(slug)>`；`GET mcp-publications/:id/connection-info` 返回该 URL 时**只信服务端 baseUrl**，不读请求 Host（防 Host 头注入）。
- **slug**：`^[a-z0-9]+(?:-[a-z0-9]+)*$`，≤191 字符，**全局唯一**；改 slug 会同步管理侧 slug（`synchronizeManagedSlug`），老客户端 URL 立即失效。
- **协议版本**：表默认 `protocolVersion = MCP_PROTOCOL_VERSION`（`2026-07-28`），服务端信息 `MCP_SERVER_VERSION='1.0.0'`；任务扩展要求请求头 `mcp-protocol-version` 与 `_meta` 版本键同时匹配，否则拒；旧版本客户端走 legacy 兼容层（`mcp-legacy-sessions.ts`、`mcp-legacy-publication-context.ts`），升级前需确认客户端版本分布。
- **认证方式**：`authMethods ∈ {api_key, oauth}`（可并存）。`api_key` 走 `Authorization: Bearer xpert_mcp_…`；`oauth` 需要 enabled 的 `McpOAuthPolicy`（`enable` 会在缺失时直接 400 拒绝），并可从 `/.well-known/oauth-protected-resource/api/mcp/p/<slug>` 发现受保护资源元数据；传输统一 `transport: 'streamable-http'`。
- **启用前置**：`reviewStatus='required'`、无 enabled 能力、缺 OAuth 策略三种情况一律 400 —— 发布"看起来建好了但调不通"基本都收敛到这三条。
- **调用审计与长任务堆积排查**：
  - 审计：`mcp_invocation_audit`（`requestId` 唯一，一次调用一条；`authMethod`/`subjectType`/`subjectId`/`status`），入口 `GET mcp-publications/:id/audit?skip=&take=`；同时打 `event='mcp.request'` JSON 日志与 `applicationMetrics.recordMcpToolCall/recordMcpAuthFailure`。
  - 长任务：`mcp_task`（唯一 `taskId`、唯一 `(publicationId, idempotencyKey)`、`inputHash`、`status ∈ working|input_required|completed|failed|cancelled`、`revision`、`expiresAt`、`pollIntervalMs`），队列 `@PluginJobProcessor({pluginName:'@xpert-ai/platform', queueName:'mcp-publication', jobName:'execute-tool', concurrency:4})` 且 `removeOnComplete/removeOnFail` 带 age+count 上限、`MAX_TASK_PAYLOAD_BYTES` 限制入参体积。
  - 排查顺序：`GET connection-info` 确认版本/端点 → `POST mcp-publications/:id/test` 看四项 checks → `GET …/audit` 看最近 `status='error'` 的 `authMethod` → 客户端按 `tasks/get` 轮询（**没有 REST 轮询端点**）。
- **文件**：`MCP_FILE_MAX_BYTES = 256MB`，下载响应带 `no-store` 与 `nosniff`，勿在前面挂会缓存/嗅探的代理。

## 八、常见故障与处置

| 故障 | 根因（结构事实） | 处置 |
|---|---|---|
| 工具发现为空 | ① `XPERT_MCP_STDIO_RUNTIME_ENABLED` 未开 → 直接抛 disabled；② `pluginManaged` 契约在插件清单里找不到 → 抛 `not available in the current plugin manifest`；③ 能力目录从未 discover | 先核对 env 与 launch 日志，再校验插件 bundle 的 MCP 组件；管理侧调 `POST mcp-capability-catalog/toolsets/:toolsetId/discover` |
| provider 报错 500 但没细节 | `POST builtin-provider/:name/instance` 把所有异常包成 `InternalServerErrorException(err.message)` | 看响应 message 与宿主日志；凭据类失败本身是 400（`ToolProviderCredentialValidationError`） |
| MCP 握手失败 | 协议版本/会话不匹配；`authMethods` 未含所用方式；OAuth 私网地址被拒 | 对齐 `MCP_PROTOCOL_VERSION`（2026-07-28）或走 legacy 兼容层；`XPERT_MCP_OAUTH_PRIVATE_HOST_ALLOWLIST` 显式放行内省主机 |
| Key 失效（401） | 未带 Bearer／非 `xpert_mcp_` 前缀／前缀未命中／已 `revoke`／已过期／hash 不符 | 用 `GET mcp-publications/:id/api-keys` 核对 `revokedAt`/`expiresAt`；`rotate` 换新并把新 secret 一次性发给客户端 |
| 发布建好却调不通 | `reviewStatus='required'` / 无 enabled 能力 / 缺 OAuth 策略 → `enable` 400；或跨 scope 查询得到 404 | 先 `POST mcp-publications/:id/test` 看 checks，再逐项补齐 |
| 任务卡住或重复 | 队列 `mcp-publication/execute-tool` 堆积；同 `idempotencyKey` 不同入参被拒；`expiresAt` 到点 | 查 `mcp_task.status/expiresAt/revision`；客户端按 `tasks/get` 轮询，取消用 `tasks/cancel`（均无 REST 端点） |
| 运行时进程残留 | 宿主关闭走 `transport.close()`，失败才 SIGTERM；异常退出时 runner 会 3s 后 SIGKILL | 用 `POST operations/mcp-runtimes/:runtimeId/stop` 或 `/kill`（SUPER_ADMIN）；对照 `childPid` 手工核进程组 |
| 重启后大量 runtime 记录变 closed | 启动收敛逻辑把 starting/running/closing 全部置 closed | 属预期；不要按这些行告警 |
| 插件包路径失效/导入失败 | 存储根不在共享持久盘、或路径含符号链接、或 ZIP 超限（100MB/10000 文件） | 修正 `XPERT_AGENT_PLUGIN_PATH` 到共享盘；`GET/POST agent-plugins/packages/:id/cleanup` 做保守清理 |
| 升级后表不存在 | `mcp-publication`/`xpert-toolset` 无 SQL 迁移文件，表靠宿主同步或统一迁移线创建 | 确认宿主迁移线包含这些实体；`agent-plugin` 三份 SQL 必须先按序执行 |
