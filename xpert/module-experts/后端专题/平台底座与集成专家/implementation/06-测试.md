## 二、运行方式

两套 jest 配置互不通用：`server` 的 `moduleNameMapper` 只把 `@xpert-ai/contracts` 指到源码；`server-ai` 额外映射 `@xpert-ai/server-core`、`@xpert-ai/plugin-sdk`、`@xpert-ai/cli-model-profiles`、`@xpert-ai/shadcn-ui/brand-icons`。两者 `transform` 均为 ts-jest（`tsconfig.spec.json`）＋ babel-jest（`babel-jest.config.js`），**无全局 setup/setupFiles**，fixture 与 mock 由各 spec 自带。

```bash
# 1) server 侧（data-source / integration / view-extension / tags），单文件或目录
node node_modules/jest/bin/jest.js --config packages/server/jest.config.ts \
  --runTestsByPath packages/server/src/integration/integration-qr.service.spec.ts \
                   packages/server/src/view-extension/view-extension.service.spec.ts

# 2) server-ai 侧（xpert-table / desktop-shell / initialization / mobile / ai-model）
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --runTestsByPath packages/server-ai/src/desktop-shell/desktop-shell.gateway.spec.ts \
                   packages/server-ai/src/initialization/bootstrap.processor.spec.ts

# 3) 目录 / 名称过滤（-t 匹配 it/describe 标题）
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --testPathPattern 'src/(desktop-shell|initialization)/'
node node_modules/jest/bin/jest.js --config packages/server/jest.config.ts \
  --testPathPattern 'src/data-source/' -t 'capability'

# 4) Nx（项目名已核实：server-ai / server）
corepack pnpm exec nx run server-ai:test --skipNxCache --runInBand
corepack pnpm exec nx run server:test --skipNxCache --runInBand

# 5) 协议包（非 jest，node:test）
node --test packages/desktop-protocol/test/protocol.test.cjs
```

章节来源：[jest.config.ts](file://packages/server/jest.config.ts)（关键符号：displayName server / moduleNameMapper / transform / transformIgnorePatterns），[jest.config.ts](file://packages/server-ai/jest.config.ts)（关键符号：displayName server-ai / moduleNameMapper / transformIgnorePatterns），[project.json](file://packages/server-ai/project.json)（关键符号：server-ai.targets.test / @nx/jest:jest），[project.json](file://packages/server/project.json)（关键符号：server.targets.test）

## 三、断言与 mock 风格

- **原型裁剪 + `Object.create`（data-source 主流）**：`data-source-capability.spec.ts` 直接 `Object.create(DataSourceService.prototype)` 再 `Object.defineProperty(service,'queryBus',…)`，并 `jest.spyOn(service,'prepareDataSource')` 返回构造好的 `DataSource`——**不建 Nest 容器、不连库**。
- **`Test.createTestingModule` ＋ 真实注册表（integration 主流）**：`integration-lifecycle.spec.ts` 用真实 `IntegrationStrategyRegistry(new DiscoveryService(new ModulesContainer()), new Reflector())`，其余 provider 全给假值（`getRepositoryToken(Integration) → {}`）；`RequestContext.getScope / getOrganizationId` 用 `jest.spyOn` 固定租户。
- **内存替身（Redis / 锁 / socket）**：`integration-qr.service.spec.ts` 用 `Map` 实现 `get/set/del` 假 Redis，`RedisLockService.runWithLock` 返回 `{acquired:true,value:await operation()}`；`desktop-shell.gateway.spec.ts` 的 `redis.duplicate()` 返回带 `subscribe/publish` 的回调集合，socket 用最小 `emit/disconnect` 桩——**能断言 pub/sub 唤醒路径，但不断言真实 Redis 语义**。
- **装饰器元数据断言（控制器边界）**：`xpert-table.controller.spec.ts` 断言 `PERMISSIONS_METADATA === [DATA_SOURCE_VIEW]` 与 `GUARDS_METADATA === [PermissionGuard]`；`view-extension.controller.spec.ts` 断言 `isPublic` 与 `__guards__` 含 `ApiKeyOrClientSecretAuthGuard`。这是「守卫必须挂在边界上」的静态防回归，而非请求级用例。
- **全局 mock 三大件**：`@xpert-ai/server-core`（`TenantOrganizationBaseEntity`/`REDIS_CLIENT`/`UserService` 等类壳）、`@xpert-ai/plugin-sdk`（`RequestContext` 的 `currentTenantId/getOrganizationId/currentUserId`）、`i18next`（`t: (_key, {defaultValue}) => defaultValue`）——被测代码的 i18n 文案因此被断言为英文默认值。
- **fixture 工厂 + 作用域强绑定**：desktop-shell 两个 spec 都用 `fixture()` 生成 `device/grant/operation` 与 `scope`，并 `jest.spyOn(RequestContext,…)` 回填，保证「跨 scope 一律 403」的负例可写。
- **环境变量型断言**：`mobile.service.spec.ts` 的 secret 泄漏用例临时替换 `process.env`，在 `finally` 里还原；`clawxpert-recovery.service.spec.ts`、`initialization/testing/bootstrap-service.mocks.ts` 把域模块（skill-repository / xpert / membership / model-access / plugin-resource 等 10 余个）整体 mock 成空实现。

章节来源：[data-source-capability.spec.ts](file://packages/server/src/data-source/data-source-capability.spec.ts)（关键符号：Object.create / queryBus / prepareDataSource），[integration-qr.service.spec.ts](file://packages/server/src/integration/integration-qr.service.spec.ts)（关键符号：storage Map / locks.runWithLock / strategy.beginQrAuthorization），[desktop-shell.gateway.spec.ts](file://packages/server-ai/src/desktop-shell/desktop-shell.gateway.spec.ts)（关键符号：jest.mock('@xpert-ai/server-core') / redis.duplicate），[xpert-table.controller.spec.ts](file://packages/server-ai/src/xpert-table/xpert-table.controller.spec.ts)（关键符号：PERMISSIONS_METADATA / GUARDS_METADATA），[mobile.service.spec.ts](file://packages/server-ai/src/mobile/mobile.service.spec.ts)（关键符号：does not expose OpenAI or JWT secrets in deployment config），[bootstrap-service.mocks.ts](file://packages/server-ai/src/initialization/testing/bootstrap-service.mocks.ts)（关键符号：jest.mock 各域模块）

## 五、缺口

- **扫码授权端到端缺失**：`integration-qr.service.spec.ts` 只覆盖服务内状态机（假 Redis 假策略），**没有**「HTTP → 策略 → Redis → 落库 → `/complete` 复用同一集成」的端到端用例；`IntegrationQrController` 本身无 spec（`PermissionGuard+INTEGRATION_EDIT` 只有 05 节的静态结论）。
- **DDL 面几乎无覆盖**：`xpert-table.service.ts` 的 `validateTableName`/`upsertTable`/`activateTable`/`deleteTable`（重命名、`createMode=UPGRADE`、失败置 `status=error`、drop 失败仍软删）**没有直接 spec**，只有 controller 的元数据断言与两个 query handler 的用例；`insertRow`/`executeSql` 同样无 spec。
- **扩展点契约缺回归**：`view-extension` 5 个 spec 都是进程内 provider 假实现，**没有**「插件注册 → 宿主解析 → 清单/动作/远程入口 URL 白名单」的契约测试；`ViewHostDefinitionRegistry` 的 `onModuleInit` 扫描（含 `@ViewHostDefinition('integration')`）无 spec。
- **desktop-shell 只有单侧协议测试**：WS 用例在服务端假 socket 上跑通，协议包侧的 `node:test` 独立；**双端联调（真实 socket.io 握手 + `PROTOCOL_MISMATCH` + 心跳续租）没有集成用例**，`maxHttpBufferSize/transports` 也只由源码常量保证。
- **字典族零覆盖**：`language`/`country`/`currency`/`contact` 无 spec，seed 幂等性（重复执行是否插入重复行、`faker` 颜色导致的 `color` 漂移）无断言；`contact` 因模块未挂载，连「路由是否存在」都没有测试兜底。
- **`export-import` 零覆盖**：模块未注册、核心逻辑被注释，`/import` 的对外语义完全靠源码阅读得出，无测试保护。
- **data-source 的连接编排面**：`prepareDataSource(id)` 的租户/组织 403、`getMyAuthentication` 的 404、`/load` 的 Excel/CSV 分支（依赖 `readExcelWorkSheets`）均无 spec；`DataSourceRuntimeService` 的 revision/`check()` 403 也无 spec。

章节来源：[xpert-table.service.ts](file://packages/server-ai/src/xpert-table/xpert-table.service.ts)（关键符号：validateTableName / upsertTable / activateTable / insertRow / executeSql），[integration-qr.service.ts](file://packages/server/src/integration/integration-qr.service.ts)（关键符号：begin / poll / complete / cancel），[host-definition.registry.ts](file://packages/server/src/view-extension/host-definition.registry.ts)（关键符号：onModuleInit / get），[data-source-runtime.service.ts](file://packages/server/src/data-source/data-source-runtime.service.ts)（关键符号：check / authorize），[import-all.controller.ts](file://packages/server/src/export-import/import/import-all.controller.ts)（关键符号：parse / ImportHistoryCreateCommand）

## 六、可执行性结论

判定：**✅ 可跑（不实跑，仅给命令与判据）**。判据：

1. 本域 29 个 spec 的依赖全部是进程内替身（Repository `{}`、`Object.create` 原型、Map 假 Redis、假 socket、mock 的 `queryBus`），**无需 PG / Redis / 外网 / 对象存储**，可直接用第二节命令 1、2 执行；

4. 协议包用例走 `node --test`（`.cjs`），**不经过 jest 配置**，需单独命令；
5. 仓库内本域**未发现 `describe.skip` / `it.skip` / known-fail 白名单**（`packages/server/src` 与四个 server-ai 子目录逐目录检索为空），因此「跑不动」只可能来自环境（Node/依赖安装）而非条件跳过；
