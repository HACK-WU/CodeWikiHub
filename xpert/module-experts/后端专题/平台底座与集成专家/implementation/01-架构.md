## 专家域职责边界
**做什么**：本域是「平台底座」四条腿——① 外部数据源接入与查询代理（`DataSourceService.prepareDataSource`/`query`/`olap`/`queryCapability`、`DataSourceRuntimeService.open` 的插件代理）；② 工作区自定义物理表（`XpertTableService.upsertTable`/`activateTable`/`executeSql`/`deleteTable`）；③ 第三方集成与扩展点（`IntegrationService.applyStrategyValidation`、`IntegrationQrService.begin/poll/complete`、`ViewExtensionService.listSlotViews`/`executeAction`）；④ 基础字典、客户端壳与 bootstrap（`LanguageService.initialize`、`TagManagementService.directory`、`DesktopShellAuthService.register`、`MobileService.getBootstrap`、`ServerAIBootstrapService.bootstrapOrganization`、`AIProvidersService.providerCredentialsValidate`）。
**不做什么**：不实现模型推理、模型目录与计费（归 `model-access`/`model-gateway`/`copilot`/`model-*`）；不拥有插件与技能的安装仓库（归 `plugin`/`plugin-resource`/`skill-repository`）；不拥有文件理解与记忆；不拥有运行时、沙箱与产物；不拥有身份与权限主体（`user`/`organization`/`role-permission` 只被本域引用）。
**与「模型访问与计费」的分工**：`ai-model` 只做 Provider 注册表门面与凭证 schema 校验，0 张表、无 `TypeOrmModule`；授权解析与计费在 `model-access`（其注入 `AIProvidersService` 使用 `getProvider`），二者是「目录/校验」与「授权/记账」的关系。
**与「平台插件与技能」的分工**：`view-extension` 只消费 `ViewExtensionProviderRegistry`，不安装插件；`xpert-table` 的 SQL/Insert 节点以 `@WorkflowNodeStrategy` 注册策略，受 Agent 编排域调用而非定义它。
**与「身份与权限」的分工**：本域所有鉴权都是「复用」——`PermissionsEnum.DATA_SOURCE_*`/`INTEGRATION_*`/`ORG_TAGS_EDIT`、`PermissionGuard`/`TenantPermissionGuard`、`ApiKeyOrClientSecretAuthGuard`、`RequestContext`，本域不定义权限模型。

章节来源：[data-source.service.ts](file://packages/server/src/data-source/data-source.service.ts)（关键符号：DataSourceService.prepareDataSource）、[xpert-table.service.ts](file://packages/server-ai/src/xpert-table/xpert-table.service.ts)（关键符号：XpertTableService.activateTable）、[ai-model.service.ts](file://packages/server-ai/src/ai-model/ai-model.service.ts)（关键符号：AIProvidersService.providerCredentialsValidate）

## 目录结构与分层
**① 集成与扩展点**：控制器 `IntegrationController`/`IntegrationQrController`（`@Controller('qr')`，`PermissionGuard` + `INTEGRATION_EDIT`）与 `ViewExtensionRoutes`+`ViewExtensionController`（抽象路由类 + `@Public` 子类）；服务层 `IntegrationService`（策略校验/生命周期钩子/principal 用户）与 `ViewExtensionService`（宿主上下文 → provider 清单 → 权限过滤 → 缓存）；基础设施层 `ViewHostDefinitionRegistry`（`DiscoveryService` 扫描 `@ViewHostDefinition`）、`ViewExtensionCacheService`（`CacheManager` + `StrategyBus` 失效）、`IntegrationViewHostCacheSubscriber`（实体级失效）；跨域薄服务 `ConnectorAppIntegrationService`/`ResolveConnectorIntegrationHandler`。
**② 数据源与表格**：控制器 `DataSourceController`（继承 `CrudController`，类级 `@Permissions(DATA_SOURCE_EDIT)`）与 `XpertTableController`（覆写 POST/PUT）；服务层 `DataSourceService`（继承 `TenantOrganizationAwareCrudService`，按 type 分发到 `DataSourceStrategyRegistry`）、`XpertTableService`（继承 `XpertWorkspaceBaseService`，工作区授权 + DDL 动作）；插件边界层 `DataSourceRuntimeService`（`@RuntimeCapabilityProvider(DataSourceRuntimeCapability)`，只暴露代理对象）；编排层 `WorkflowDBSQLNodeStrategy`/`WorkflowDBInsertNodeStrategy` + 两个 validator。
**③ 基础字典与客户端壳**：字典控制器 `LanguageController`/`CountryController`/`CurrencyController`/`ContactController`/`TagController`（后者继承 `CrudController` 并覆写 UPDATE/DELETE 走 `TagManagementService`）；字典种子 `language.seed`/`country.seed`/`currency.seed`/`contact.seed`/`tag.seed`（前四个被 `seed-data.service` 引用）；客户端壳 `DesktopShellController`（HTTP）+ `DesktopShellGateway`（WS）+ `DesktopShellMiddleware`（Agent 工具）；bootstrap 面 `MobileService`、`ServerAIBootstrapProcessor`（Bull）+ `ServerAIBootstrapService`、`ClawXpertRecoveryService`；模型目录面 `AIProvidersService` + 4 个 query handler + 1 个 command handler。

章节来源：[view-extension.service.ts](file://packages/server/src/view-extension/view-extension.service.ts)（关键符号：ViewExtensionService.resolveHostContext）、[data-source-runtime.service.ts](file://packages/server/src/data-source/data-source-runtime.service.ts)（关键符号：DataSourceRuntimeService.open）、[bootstrap.processor.ts](file://packages/server-ai/src/initialization/bootstrap.processor.ts)（关键符号：ServerAIBootstrapProcessor）

## 关键不变量
1. **字典＝只读 + 种子，不提供写端点**：`language`/`country`/`currency` 的控制器只有 `@Get()`（`LanguageController` 另有 `getByName/:name`）且 `@Public()`；country/currency 实体 `isoCode` 只建**非唯一** `@Index()`，唯一性只由种子内容保证；`Language` 有 `@Unique(['code'])`，`createLanguages` 用 `LanguagesEnum` 判定 `is_system`、颜色取 `faker.internet.color()`（**不幂等**：重复执行靠 try/catch 吞错）。多语言解析不在实体而在 `XpertMobileBootstrap`/`Tag.label`/`constants.getDefaultOrganizationWorkspaceName`（按 `RequestContext.getLanguageCode()` 选 `zh_Hans|en_US`）。
2. **`contact` 的继承面 = 基类 CRUD 全量暴露**：`ContactController extends CrudController<Contact>` 只新增 `GET /`（`getAllContact`），`POST`/`PUT`/`DELETE`(`/soft`,`/recover`) 全部由基类提供，类级仅 `@UseGuards(TenantPermissionGuard)`；实体为 `TenantOrganizationBaseEntity`，无唯一索引，`country` 列存 isoCode 字符串而非外键（`contact.seed.ts` 以 `faker.random.arrayElement(countries).isoCode` 写入）。
3. **`data-source` 的凭据边界是「明文存储 + 出口收窄」**：`DataSourceAuthentication.password` 是普通 `@Column()`，无 `@Exclude()`（只有 `dataSource` 关系被排除）；`DataSource.options` 上的 `// @Exclude()` 被注释掉；`prepareDataSource` 在 `authType===BASIC` 时把用户名/密码**回写进 `options`**，随后 `options` 直接作为 runner 构造参数。收窄只发生在列表端点：`DataSourceController.findAlls` 用 `ClassSerializerInterceptor` + `DataSourcePublicDTO`（白名单 `@Expose`），`@Public()` 无、`GET :id` 则返回完整实体（含 `options`，`authentications` 需 `$relations` 才带出）。全模块内检索 `encrypt|decrypt|cipher|AES` **0 命中**，即无加密层。
4. **`xpert-table` 的 Meta→物理表激活**：实体是「逻辑表」（`columns` json + `status` + `physicalSchema`/`physicalTableName`/`version`），`activateTable` 先置 `PENDING_ACTIVATION`，再以 `DBTableAction.CREATE_TABLE` + `DBCreateTableMode.UPGRADE` 建/改物理表，成功后置 `ACTIVE` + `activatedAt`，失败置 `ERROR` + `message`；`upsertTable` 在 ACTIVE 且改名时先 `RENAME_TABLE`，激活失败时**新建表直接删逻辑行、既有表只标 ERROR**。`deleteTable` 在 ACTIVE 时先 `DROP_TABLE`（失败仅记日志）再软删逻辑行 —— DDL 与元数据**不在同一事务**。
5. **`view-extension` 的宿主解析与注册契约**：宿主必须实现 `ViewHostDefinitionContract`（`hostType`/`slots`/`resolve`/`canRead`/可选 `prepareFileAction`），由 `@ViewHostDefinition('integration')` 标注、`ViewHostDefinitionRegistry.onModuleInit` 经 `DiscoveryService` 注册；视图提供者来自插件 `ViewExtensionProviderRegistry`，`listSlotViews` 逐个 `provider.supports(context)`→`readProviderViewManifests`→`normalizeManifest`→`isManifestActiveForContext`，再由 `ViewExtensionPermissionService.filterVisibleManifests` 按 `visible`/`permissions`/`requiredHostAccess` 过滤，最后按 `order` 排序。
6. **`view-extension` 是权限敏感面**：控制器类级 `@Public()` + `@AllowClientSecretBindings(ENTERPRISE_XPERT)` + `@UseGuards(ApiKeyOrClientSecretAuthGuard)`，文件头注释逐字写明「Shared protocol routes; each entry point supplies its own authentication boundary.」；动作执行前必须过 `ensureManifestVisible` + `ensureActionVisible`，`requiredHostAccess` 映射到 `context.runtimeScope.projectAccess` 的 `canRead|canEdit|canManage`。
7. **`desktop-shell` 的设备/授权/执行三源不变量**：`desktop-shell-auth.service.ts` 头注「device credentials cannot authenticate general API calls; grants bind once to an owned thread.」；`desktop-shell.gateway.ts` 头注「every dispatch rechecks persisted epoch and grant; Redis is only a wake-up hint.」；`desktop-shell-operation.service.ts` 头注「DB state is authoritative; notification delivery never authorizes a second execution.」；`shell-approval.ts` 头注「host preparation never executes; approval remains bound to exact arguments on both sides.」；协议包注释「validate both ends of the device channel; no message grants itself execution authority.」。会话生命周期＝`connectionEpoch`（每次连接轮换、旧 socket 被踢）+ `leaseExpiresAt`（心跳续租，断开即置过期）+ `credentialHash`/`credentialExpiresAt`（`timingSafeEqual` 比对）。
8. **`mobile` 的 bootstrap 契约**：`getDeploymentConfig()` 从 `MOBILE_API_BASE_URL|PUBLIC_API_BASE_URL|API_BASE_URL`、`MOBILE_CHATKIT_FRAME_URL|CHATKIT_FRAME_URL` 与 `SANDBOX_TERMINAL_NAMESPACE` 组装 `apiBasePath='/api'`、`aiApiPath='/api/ai'`、`viewHostsPath='/api/view-hosts'` 与 6 项 `capabilities`；`listXperts` 只走 `PublishedXpertAccessService`（`type:Agent + latest:true`），不直接查 `Xpert` 表。
9. **`initialization` 的幂等靠「稳定 jobId + 出队时重查」**：`@OnEvent` 只做入队，4 个 jobId 分别为 `org-bootstrap:{orgId}`、`tenant-skill-repository-bootstrap:{tenantId}`、`user-org-bootstrap:{orgId}:{userId}`、`user-org-cleanup:{orgId}:{userId}`，统一 `attempts:3, backoff:10_000, removeOnComplete:true`；`bootstrapUserInOrganization` 开头「Queue retries outlive membership removal; never restore access from a stale event.」→ `isActiveOrganizationMember` 不通过即返回空结果；`ClawXpertRecoveryService.recover` 复用同一 jobId，且注释「Bull atomically retries only failed jobs, so concurrent clicks cannot enqueue duplicates.」
10. **`ai-model` 与 `model-access` 的边界**：`AIProvidersService` 只持有 `AIModelProviderRegistry`（无 `TypeOrmModule`，故 0 表），对外只有 `getProvider`（失败可抛 `AIModelProviderNotFoundException`）与 `providerCredentialsValidate`（取 `provider_credential_schema` → `ProviderCredentialSchemaValidator.validateAndFilter` → `validateProviderCredentials`）；HTTP 面只有 `@Public()` 的 `GET provider/:name/:iconType/:lang`；其余查询（`ListProviders`/`ListBuiltinModels`/`GetProvider`/`GetModelIcon`）与命令是给本进程其它域（`copilot`/`model-gateway`/`model-access`）用的内部面。

## 组件详细分析
### 数据源与查询代理
`DataSourceService` 是所有外部库访问的唯一入口：`prepareDataSource` 在**租户+组织双条件下**取数据源（否则 `ForbiddenException('Data source scope is required')`），拼上 `authentications` 与 `options`，再交给 `prepareDataSource` 工具函数按 `authType` 注入当前用户凭据；之后所有动作都是「`DataSourceStrategyQuery(type, options)` → `runner` → `try/finally runner.teardown()`」的模板（`getCatalogs`/`getSchema`/`query`/`olap`/`queryCapability`/`import`/`dropTable`/`ping`）。插件侧唯一出口是 `DataSourceRuntimeService.open`：它以 `actor` 与 `RequestContext` 四元组比对授权、限制引擎白名单（mysql/doris/postgres）、用 `updatedAt` 做「数据源已变更→关闭会话」的复核，并返回一个**不暴露 runner 与解析后凭据**的方法代理。
章节来源：[data-source.service.ts](file://packages/server/src/data-source/data-source.service.ts)（关键符号：DataSourceService.getSchema）、[data-source-runtime.service.ts](file://packages/server/src/data-source/data-source-runtime.service.ts)（关键符号：DataSourceRuntimeService.authorize）

### 集成与扩展点
`IntegrationController` 的写路径全部走命令（`IntegrationUpsertCommand`/`IntegrationDelCommand`），handler 负责「先策略校验、再触发 `onUpdate`/`onDelete` 钩子、最后落库」；读路径的 `features` 过滤因 jsonb `Raw` 被注释而退化为 JS `every`。扫码授权是一条独立的 Redis 状态机（`begin`→`poll`→`complete`/`cancel`），所有步骤都在 `RedisLockService.runWithLock` 内串行，会话键按 `tenant:org:user:provider:purpose` 收敛，`complete` 用会话 id 预占集成 id 换取重试幂等，并可用 `getQrAuthorizationIdentity` 归并同一账号的重复授权。`view-extension` 则是「宿主定义（服务端真实对象）→ 插件清单（跨端契约）→ 权限过滤 → 缓存」的四段式，宿主解析结果会进入 `XpertResolvedViewHostContext`（含 `slots`/`hostState`/`capabilities`），缓存键把 `features` 与 `hostState` 的 sha1 摘要并入，避免激活态变化后命中旧清单。
章节来源：[integration-qr.service.ts](file://packages/server/src/integration/integration-qr.service.ts)（关键符号：IntegrationQrService.complete）、[view-extension.cache.service.ts](file://packages/server/src/view-extension/view-extension.cache.service.ts)（关键符号：ViewExtensionCacheService.getManifestCacheKey）

### 客户端壳与 bootstrap
`desktop-shell` 由三件套分工：`DesktopShellAuthService` 管设备（`credentialHash`+`credentialExpiresAt`+`enabled`）与授权（`grants.operation` 上的 `argsHash`/`decision`）、`DesktopShellOperationService` 管执行行（唯一键 `(tenantId,runId,toolCallId)`、`seq` 单调、`outputBytes` 截断、单设备 `DEVICE_BUSY`）、`DesktopShellGateway` 管通道（握手鉴权→`connectionEpoch` 轮换→`ready/command/ack/reconcile/revoked/lease` 六类消息）。`initialization` 把「组织/租户/用户入组」变成事件驱动的 Bull 作业，串起 workspace、environment、模板导入、技能仓库与 ClawXpert；`mobile` 只做只读投影，`ai-model` 只做注册表门面。

## 结论
本域的骨架可以概括为「一个代理层 + 三个契约」：`data-source` 是唯一的外部库代理层，`xpert-table` 在其上叠加 Meta/物理表；三个契约分别是插件视图契约（`ViewHostDefinitionContract` + `XpertExtensionViewManifest`）、双端设备契约（`@xpert-ai/desktop-protocol`）、以及集成策略契约（`IntegrationStrategyRegistry`）。字典族（language/country/currency/contact/tags）刻意保持「只读 + 种子 + 无业务外键」，把一致性责任交给种子与迁移。最需要长期防守的是两处非对称设计：① `data-source` 明文凭据（`options` 的 `@Exclude()` 被注释、`authentication.password` 无排除、`GET :id` 直出实体）与 `DataSourceRuntimeService` 的严格代理之间存在落差；② `xpert-table` 的 DDL 与元数据不在同一事务，`deleteTable` 的 drop 失败仍继续软删。装配面另有三处「存在但未挂载/未注册」的实体：`ContactModule`、`ImportAllModule` 与 `xpert-table` 的 `get-database-schemas.query`，统计路由与能力时必须以装配点为准。
