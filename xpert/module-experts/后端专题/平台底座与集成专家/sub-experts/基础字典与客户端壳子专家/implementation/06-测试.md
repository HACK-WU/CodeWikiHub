## 2. 逐文件覆盖点

**`desktop-shell`（5 文件 / 25 `it`，全部 mock 掉仓储与 Redis，不连真库）**

- `desktop-shell-auth.service.spec.ts`（`describe('Desktop Shell authorization')`，6 条 + 1 条 `it.each`×3）：`currentShellScope` 只用身份字段（传入更宽的 runtime scope 时不多带字段）；`it.each(['userId','tenantId','organizationId'])` 断言**跨键取值被拒**；跨 thread/assistant 的 grant 被拒；过期 grant 与 `enabled=false` 设备被拒；`revokeGrant` 会把在途操作置 `cancel_requested` 但**不能撤销他人 grant**；畸形连接凭据永不被接受。
- `desktop-shell-approval-auth.spec.ts`（`describe('per-operation permission endpoints')`，3 条）：`prepareOperation` 先做会话准入（`queryBus.execute` 恰被调用 1 次）再落 `pending`，且 `grant.operation` 必须精确等于 `{ runId, toolCallId, 'pending', argsHash = sha256(['pwd','/tmp',30]) }`、有效期 ≤ 10 分钟；越权/过期/非法决策分别 403 / 403 / 400；**会话准入失败时 `grants.save` 不得被调用**（不留许可）。
- `desktop-shell-operation.service.spec.ts`（`describe('Desktop Shell operation delivery')`，7 条含 2 条 `it.each`）：`it.each(['pending','rejected'])` 断言未批准/被拒的操作**从不派发**；执行锁内再次复核过期与撤销；`it.each(['runId','toolCallId'])` 断言审批精确绑定这两个字段；重试复用同一持久操作、参数变化即拒；离线/忙碌设备 fail-closed 且不产生排队作业；回执乱序时 `reconcile` 缺失分片、忽略重复与迟到终态；输出按 `cursor` 返回有界增量。
- `desktop-shell.gateway.spec.ts`（`describe('Desktop Shell Gateway')`，5 条；假 socket.io + 假 Redis pub/sub）：Redis 唤醒只路由到**持有该设备连接**的实例；换代后旧 `connectionEpoch` 的连接与其回执被隔离；`report` 的 `ack` 必须回带精确的报告身份（`operationId` / `seq` / `type` / `state`）；撤销与超期转成 `cancel` 并保留 `timed_out` 语义；错误协议版本握手与超尺寸帧被拒。
- `shell-approval.spec.ts`（`describe('Shell two-stage interruption')`，4 条）：两段 `interrupt` 都恢复后才执行；拒绝时返回拒绝且不执行；**仅在宿主返回「一次性已批准许可」时才跳过交互审批**；宿主不可用时同样不执行。

**`initialization`（6 文件 / 55 `it`）**

- `bootstrap.service.spec.ts`（`describe('ServerAIBootstrapService')`，20 条，44.46KB）：组织引导聚焦工作区与成员（不发布模板技能包到公共仓库）；为新组织预装 ClawXpert 模板插件，插件预装失败**不使组织引导失败**；把可用主模型注入默认创作助手、不可用则跳过；租户引导触发统一模板技能同步，且同步失败**要冒泡**；入组引导在无 LLM 时跳过 ClawXpert、在有 LLM 时初始化并绑定；插件准备失败仍继续 ClawXpert；ClawXpert 创建失败**不使入组引导失败**（保留错误）；试用用户获租户默认成员关系且保留组织归属；复用既有个人工作区不标记为「新建」；`SUPER_ADMIN` 跳过个人工作区但仍加入组织工作区；默认技能安装未就绪时重试/就绪时全装/失败原因进聚合错误；成员删除时把用户从非个人组织工作区移除。
- `bootstrap.processor.spec.ts`（`describe('ServerAIBootstrapProcessor')`，9 条）：**先排队补技能、再把 ClawXpert 失败上抛**（顺序被显式断言）；租户事件入队技能仓库引导；租户引导不自行追加仓库同步 job；用户工作区引导完成后才入队 `user-default-skills`；无个人工作区 / 个人工作区已存在时都不入队；组织引导只做工作区初始化；仓库同步与默认技能 job 交回 service。
- `bootstrap-user-organization.spec.ts`（`describe('ServerAIBootstrapService member workspace lifecycle')`，9 条）：非超管成员的入组全流程、ClawXpert 绑定时机、失败保留、trial 用户默认成员关系、个人工作区复用、`SUPER_ADMIN` 分支、成员删除清理。
- `bootstrap-membership-authorization.spec.ts`（`describe('membership authorization for delayed user bootstrap jobs')`，6 条）：**为已移除/停用成员跑完旧 job 时先结束、再读用户/写工作区访问**；Claw 初始化失败后要重查成员资格才允许重试；活跃成员按「入队时的精确 tenant/organization/user」执行；成员资格查询不可用时 fail-closed（不能让队列重试绕过授权）；不完整 tenant 边界的事件不签发宽泛查询；成员被移除后延迟 job 不得安装默认技能。
- `bootstrap-workspace-skills.spec.ts`（`describe('ServerAIBootstrapService default workspace skills')`，3 条）：未就绪时安装已解析的技能并重试；全部就绪时全装；失败原因进入聚合错误。
- `clawxpert-recovery.service.spec.ts`（`describe('ClawXpertRecoveryService')`，8 条）：晚到的模型配置要求只报告不入队；不改写可用 binding；区分「陈旧 binding」与「缺失 binding」；并发请求复用同一稳定 jobId；已有活跃 job 时不重复入队；对保留的 failed 作业 `retry()` 而不新建；组织外用户先被拒（不读 binding）；每次请求都从自身鉴权上下文解析组织。
- 支持文件：`testing/bootstrap-service.fixture.ts`（构造 service 与依赖替身）、`testing/bootstrap-service.mocks.ts`（mock 集合）——**非 spec，不会被 jest 当作用例**。

**`mobile`（1 文件 / 10 `it`）**：`describe('MobileService')` —— bootstrap 不返回凭据字段；`SUPER_ADMIN` 只列活跃租户组织且**不臆造成员关系**；普通成员看不到租户组织；`it.each([ALL_ORG_VIEW, ALL_ORG_EDIT])` 断言仅这两项权限可放开组织可见性；`ADMIN` 无成员关系时即便有租户权限也**不返回组织选择**（守卫 `role === ADMIN` 优先于权限）；bootstrap 必须登录；`xperts` 的搜索与分页归一化 + 只返回可访问的已发布助手摘要；不从 marketplace 分类或陈旧关系推断业务领域；只映射移动端安全字段；部署配置不含 `OPENAI_API_KEY` / JWT secret。

**`tags`（1 文件 / 18 `it`，`describe('Tag catalog management')`）**：目录只列当前作用域与共享标签并把共享/系统标签标为只读；租户管理者只能在租户作用域维护共享标签；用量聚合为租户全量但仍限于当前租户；无编辑权限的成员拿到只读目录；无租户的请求被拒；**路由 id 与请求作用域是权威**（嵌套关联被剥离）；不得经组织作用域改到共享/外来标签；系统标签不可编辑/删除；`it.each` 表覆盖多组非法写入；prompt-only 组织标签不引入旧 category 枚举值；prompt 关联进入用量并可阻止移除在用 target；同一 label 多 target 只建一条共享定义且忽略输入身份；保留旧 category 与本地化名称；同作用域重名被拒；用量来自真实 junction 且组织计数受限；在用标签不可删且移除在用 target 被拒但允许停用；未使用标签可用显式作用域条件删除；显式知识库/文档关联进入计数并阻止删除在用定义。

## 3. 运行命令

```bash

node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --runTestsByPath packages/server-ai/src/desktop-shell/desktop-shell.gateway.spec.ts \
                   packages/server-ai/src/desktop-shell/desktop-shell-operation.service.spec.ts \
                   packages/server-ai/src/initialization/bootstrap.processor.spec.ts \

node node_modules/jest/bin/jest.js --config packages/server/jest.config.ts \
  --runTestsByPath packages/server/src/tags/tag-management.service.spec.ts

# 3) 按目录跑整个子域（两套各一次）
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --testPathPattern 'src/(desktop-shell|initialization|mobile|ai-model)/'
node node_modules/jest/bin/jest.js --config packages/server/jest.config.ts \
  --testPathPattern 'src/(tags|language|country|currency|contact|export-import)/'

  --testPathPattern 'src/initialization/' -t 'membership'

# 5) 单条文件（ai-model 的 .test.ts 需显式路径，避免 testMatch 命名差异）
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
```

## 4. 需外部依赖（PG / WS）的用例

本子域的 13 个测试文件**全部是单元测试**：仓储、Redis、socket、i18next、`RequestContext` 都被 `jest.mock` / 手工替身替换，不连 PG、不连 Redis、不起真实 WS 服务。因此：

| 依赖 | 本子域现状 | 说明 |
|---|---|---|
| PG（真库 + 事务/行锁） | **无集成用例** | `pessimistic_write`（`decideOperation` / `execute` / `receive` / `tags.write` / `tags.remove`）、`UNIQUE(tenantId,runId,toolCallId)` 的幂等、`Tag.name` 的唯一索引 `category_name` 都只被 mock 语义覆盖，**真实锁与唯一约束行为未被验证** |
| Redis（bull + pub/sub） | **mock** | `desktop-shell.gateway.spec.ts` 用假 pub/sub；初始化队列用假 `Queue`；`removeOnComplete` / `jobId` 去重的真实语义未验证 |
| WS（真实 socket.io server） | **mock** | 网关用例用假 socket；握手鉴权、`maxHttpBufferSize = 65536` 的截断行为、1 秒巡检的真实时序未验证 |
| 文件系统 | 间接 | 字典种子与模型图标读盘（`_assets/`）未测；`createCountries` / `createCurrencies` 的失败分支（`reject(null)`）未测 |
| 插件注册表 | **override** | `ai-model` 用 `overrideProvider(AIModelProviderRegistry)`，真实插件装卸后的 `getProvider → undefined` 场景取决于插件环境 |

## 5. 缺口

1. **字典族零覆盖（4 模块 / 0 spec）**：`language` / `country` / `currency` / `contact` 无任何用例；`createLanguages` 的「冲突被吞」、`createCountries` 的 `reject(null)`、`findOneByName` 的 `null` 语义、`is_system` 判定都无回归保护。改种子等于无网改动。
2. **两处未挂载无守卫用例**：`/api/contact`（`ContactModule` 未装配）与 `/api/import`（`ImportAllModule` 无人 import）没有任何「不该被挂载」或「路由前缀缺失」的断言；`ContactModule` 的变化不会让任何用例失败。
3. **`ai-model` 的 `.test.ts` 命名风险**：`providers.service.test.ts` 不以 `.spec` 结尾，是否被默认 `testMatch` 收集取决于 `jest.preset.js`；若未收集须用 `--runTestsByPath` 或放宽 `testMatch`——这是**命名约定导致的执行差异**，不是代码缺陷。
4. **`desktop-shell` 无 controller 级断言**：9 条路由的 `@Post`/`@Get` 形态、`currentShellScope` 之外的守卫元数据（类级 `@Controller()` 无守卫，全靠 service 内 `currentShellScope`）未被断言；路由与权限元数据的漂移不会被测试发现。
5. **`desktop-shell` 无 `receive` 之外的清理路径用例**：`OUTPUT_EXPIRED` / `EXECUTION_UNKNOWN` 的错误码只在网关侧被判「置 unknown」，`result()` 的 `error.code` 投影与 `OUTPUT_EXPIRED` 无直接用例。
6. **`mobile` 未覆盖组织解析的边界**：`defaultOrganizationId` 的三级回落（active → isDefault → 首个）与 `organizations` 为空时的 `null` 分支未见对应 `it`；`getDeploymentConfig` 的 env 覆盖优先级（`MOBILE_API_BASE_URL` → `PUBLIC_API_BASE_URL` → `API_BASE_URL`）只有「不泄漏敏感值」一条断言。
7. **`initialization` 未覆盖 `syncSkillRepository` 与清理路径的边角**：`bootstrap.processor.spec.ts` 覆盖了「交回 service」，但 `bootstrap.service.ts` 的 `syncSkillRepository` 细分支（成功/失败/重试计数）与 `cleanupUserInOrganization` 的非个人工作区移除之外的分支覆盖不全。
8. **`tags` 未覆盖 `usage()` 的 400 分支**：`Error.TagUsageUnsupported`（新 junction 未登记 `usageTargets`）是本子域最危险的隐性契约，spec 未直接构造「未登记 junction」场景；`directory()` 的 `editable` 组合与 `GET count` / `pagination` / `my` 三条继承端点也无用例。
9. **协议层用例不在 jest 体系内**：`desktop-protocol` 的 `node --test` 用例（`LIMITS` / `parseSettings` / `parseReport`）与 `desktop-shell` 的 jest 用例分属两套执行器，CI 上若只跑 jest 会漏掉协议边界。
10. **无性能/负载判据**：1Hz 派发巡检、`tags.directory` 的 N 次 junction 查询、标签写的租户级串行都无基准或上限断言。

## 6. 结论

1. **测试重心极度不均**：`initialization`（6 文件 / 55 `it`，占本子域 `it` 总数的 53%）与 `desktop-shell`（5 文件 / 25 `it`）被重点保护，而四个字典模块与 `export-import` **完全无覆盖**，`contact` 的继承面也没用例——这与「字典只读 + 种子」的设计自洽（风险被推给种子与流程），但意味着**改种子/改常量不会有任何红灯**。
2. **本子域的 spec 全是单元测试**：没有 PG、Redis、真 socket 的集成用例；`pessimistic_write`、唯一键幂等、`argsHash` 绑定这些「契约核心」在测试里是由替身**模拟**的语义，真实数据库行为仍属未验证区。
3. **最值得优先补的三条用例**：① `tags.usage` 的 `TagUsageUnsupported` 负例（对应 §5 缺口 8）；② `desktop-shell` 的 controller 路由/守卫元数据断言（对应缺口 4）；③ 并发下的 `execute` 幂等与 `decideOperation` 409（对应 §4 最小集）。
4. **执行上的两个坑必须写进 CI 说明**：本子域跨两套 jest 配置（`server` 1 个 spec + `server-ai` 12 个），且 `ai-model` 的用例文件名是 `.test.ts`；单跑任何一侧都会漏。
5. **与父级 06-测试.md 的口径一致**：本子域 13 个测试文件（`desktop-shell` 5 + `initialization` 6 + `mobile` 1 + `ai-model` 1 + `tags` 1）＋字典族 0 ＋ `export-import` 0，可作为父级清单的 ③ 子集直接对账。
