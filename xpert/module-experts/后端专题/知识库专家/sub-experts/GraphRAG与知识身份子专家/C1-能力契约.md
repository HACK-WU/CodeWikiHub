# GraphRAG 与知识身份子专家 —— C1 能力契约

> **资产基线**：`2026-10-16 · commit 80f5676fd`（仓库已恢复，符号均回源码核实），继承父域 [C1-能力契约.md](file://.module-experts/后端专题/知识库专家/C1-能力契约.md)。
> **范围**：`graphrag/` 与 `knowledgebase/identity/`。检索侧图谱召回见子专家① C1；Wiki 复用身份层的调用点见子专家④ C1。

## §1 HTTP 端点

### 1.1 前缀与鉴权基线

| 前缀 | 控制器 | 鉴权基线 | 用途 |
| --- | --- | --- | --- |
| `/api/knowledgebase/:id/graph` | `GraphragController`（`@Controller(':id/graph')` + `RouterModule.register({ path: '/knowledgebase' })`；`@UseInterceptors(TransformInterceptor)`） | **零 `@UseGuards`**；仅 `documents/:documentId/retry` 在方法体内显式调 `assertKnowledgebaseWriteAccess(id)` | 进度、重建、实体 / 关系 / 提及 / 目录 / 可视化、手工修正 |
| 无 HTTP 前缀 | `KnowledgeIdentityService`（`knowledgebase/identity/`） | — | **无独立 HTTP 面**：只被图谱抽取链与 Wiki 调用 |

> 注意：`:id` 未加 `UUIDValidationPipe`（与知识库主控制器的 `:id` 不同），非法 id 由服务层处理。

### 1.2 代表端点

| 方法 路径 | 用途与行为 | 主要错误 |
| --- | --- | --- |
| `GET /graph/documents/:documentId/status` | 单文档图谱进度（`GraphDocumentProgressService.getProgress`） | — |
| `POST /graph/documents/status` | 批量进度；body `{ documentIds }`，入参非法 → `Error.KnowledgeGraphDocumentStatusBatchInvalid` | 400 |
| `POST /graph/documents/:documentId/retry` | **唯一在控制器内断言写权限**的端点：`assertKnowledgebaseWriteAccess` → `KnowledgeGraphRetryDocumentCommand` → 返回最新进度 | 403 / 400 |
| `POST /graph/rebuild` | 全库重建（`rebuildKnowledgebase`）；未启用图谱时 `ensureGraphEnabled` 报错；提升图谱修订号并重投可入图文档 | 400 |
| `GET /graph/status` | 启停、计数与最近任务；`error` 为空即正常（成功路径会清空 `graphIndexError`） | — |
| `GET /graph/entities` | 实体分页；`data` 经 `ParseJsonPipe` 支持 `search` / `type` / `origin` / `visibility` 等 `where` | — |
| `POST /graph/entities` | 手工新建实体（body 为 `unknown`，由服务层 `assertNoEntityConflict` 校验） | 400 |
| `PATCH /graph/entities/:entityId` | 手工更新实体 | 404 |
| `DELETE /graph/entities/:entityId` | **软隐藏**：`hideEntity`（置 `visibility`，非物理删） | 404 |
| `GET /graph/entities/:entityId/neighborhood` | 邻域展开：与实体相连的关系与实体集合 | 404（实体不存在） |
| `GET /graph/entities/:entityId/chunks` | 实体关联切片（`getEntityChunks` + `resolveGraphChunks`）；入参 `KnowledgeGraphEntityChunksQuery` | 404 |
| `GET /graph/catalog` | 图目录（`getGraphCatalog`），入参 `KnowledgeGraphVisualizationQuery` | — |
| `GET /graph/visualization` | 可视化数据；`query` 可限制可见性与规模 | — |
| `GET /graph/relations` | 关系分页（`listRelations`，入参同为 `KnowledgeGraphVisualizationQuery`） | — |
| `POST /graph/relations` | 手工新建关系（`resolveRelationEndpoints` + `assertNoRelationConflict`） | 400 |
| `PATCH /graph/relations/:relationId` | 手工更新关系 | 404 |
| `DELETE /graph/relations/:relationId` | **软隐藏**：`hideRelation` | 404 |
| `GET /graph/mentions` | 提及分页（证据锚点：哪个 chunk 的哪段文本） | — |

### 1.3 路由要点

- **写权限断言不统一**：只有 `documents/:documentId/retry` 在控制器里显式断言；`rebuild`、实体 / 关系的 `POST|PATCH|DELETE` 的授权以服务实现为准，接入前建议先做一次真实越权验证。
- **`DELETE` 语义是 `hide`**：实体 / 关系删除都不落物理删除，只改 `visibility`。
- **库级段写作 `:id/graph`**：与知识库主控制器的 `:id` 同层，KB 级资源一律 `/api/knowledgebase/<kbId>/graph/...`。

## §2 服务契约

### 2.1 `GraphragService`（`graphrag/graphrag.service.ts`）

| 方法 | 用途 | 参数与行为语义 | 异常 / 约束 |
| --- | --- | --- | --- |
| `isEnabled(knowledgebase)` | 启停判定 | `knowledgebase?.graphRag?.enabled === true` | — |
| `enqueueDocuments({knowledgebaseId, documentIds, reason})` | 入图队列 | 空 `documentIds` 或图谱未启用 → `return []`（静默）；跳过无 `contentHash` 的文档；结构化图谱文档仅在可 resume 时入队；逐个 `createGraphIndexJob` 后立即 `dispatchJobs` | — |
| `dispatchJobs(jobs, userId?)` | 派发 | `graphQueue.add({userId, tenantId, organizationId, knowledgebaseId, graphIndexJobId})`；投递失败把任务置失败并写 `dispatchError` | — |
| `processIndexJob(graphIndexJobId)` | 单任务处理（消费者侧） | 抽取（`extractDocumentGraph`）→ 归一 → `persistExtraction` 写图 → `syncEntityVectors` → 终态；失败同时写 KB `graphStatus = FAILED` 与 `graphIndexError` | 任务不存在 404 |
| `markJobSuccess` / `markJobFailed` / `updateGraphStatusFromJobs` | 终态写回（私有） | 成功清空错误列；无 job 时按聚合结果回落图谱状态 | — |
| `rebuildKnowledgebase(knowledgebaseId)` | 全库重建 | `ensureGraphEnabled` 前置；提升图谱修订号并重投可入图文档 | 400 |
| `getStatus(knowledgebaseId)` | 图谱状态 | 返回启停、计数与最近任务；`error` 为空即正常 | — |
| `listEntities(knowledgebaseId, params?)` | 实体分页 | 支持 `search` / `type` / `origin` / `visibility` 等 `where` | — |
| `listRelations(knowledgebaseId, query?)` / `listMentions(knowledgebaseId, query?)` / `getGraphCatalog(knowledgebaseId, query?)` / `getVisualization(knowledgebaseId, query?)` | 关系 / 提及 / 目录 / 可视化 | 均按 KB 限定范围 | — |
| `getNeighborhood(knowledgebaseId, entityId)` | 邻域展开 | 返回相连关系与实体集合 | 实体不存在 404 |
| `getEntityChunks(knowledgebaseId, entityId, query)` | 实体关联切片 | 由 `resolveGraphChunks` 取切片 | 实体不存在 404 |
| `createEntity` / `updateEntity` / `createRelation` / `updateRelation` | 手工修正 | 冲突检测走 `assertNoEntityConflict` / `assertNoRelationConflict`；关系端点由 `resolveRelationEndpoints` 解析 | 404 / 400 |
| `hideEntity(knowledgebaseId, entityId)` / `hideRelation(knowledgebaseId, relationId)` | 软隐藏 | 保留数据、退出可见集 | 404 |
| `clearDocument(knowledgebaseId, documentId)` | 文档级清理 | 删除该文档在图谱中的贡献并重算受影响实体 / 关系 | — |
| `clearKnowledgebase(knowledgebaseId, preservePublications?)` | 库级清理 | `preservePublications` 决定是否保留发布记录语义 | — |
| 抽取与落库内部件 | `extractDocumentGraph` / `persistExtraction` / `upsertEntity` / `upsertRelation` / `recomputeEntityFromContributions` / `recomputeRelationFromContributions` / `refreshEntityMentionCounts` / `pruneEntities` / `syncEntityVectors` / `expandEntities` / `resolveGraphChunks` / `buildEntitySummary` | 均为 `private`，不承诺稳定签名 | — |

### 2.2 抽取与结构化写入面

| 组件 | 方法 | 语义 |
| --- | --- | --- |
| `KnowledgeGraphExtractionService` | `extract` | 批量抽取：按 `batches` 逐批调结构化模型，合并 `entities` / `relations`，输出 `candidateId` 供归一映射 |
| | `extractOnce` | 复用抽取快照：优先读 `job.extractionSnapshot`，避免重复调模型 |
| | `resolveIdentities(model, observations)` | 把抽取实体映射为身份观察记录，调用身份层裁判 |
| | `assertCurrent(kb, jobId)` | 并发护栏：KB 悲观锁 + 复查任务状态 |
| | `formatChunksForExtraction(chunks)` | 把 chunk 组装成带 `chunkId` 的抽取输入 |
| | `resolveExtractionChatModel` | 解析抽取用 chat 模型（带 `abortController` 与 usage 回调） |
| `StructuredGraphRuntimeService`（`@RuntimeCapabilityProvider(KnowledgeGraphRuntimeCapability)`） | `publish(input)` | 复杂授权（文档可读 + KB 可写 + `systemManagedType === 'agent-writer'` + `ownerXpertId` / `ownerAgentKey` 匹配）→ `graphRag.enabled` 检查 → 锁内预留快照（复查 `contentHash` / `disabled` / `hardDeletePendingAt`，校验 `chunkIds` 集合完全一致）→ 提交后 `dispatchJobs`；内容哈希 / 发布纪元 / 快照哈希未变时返回 `{unchanged: true}` |
| | `status(input)` | 返回最近一次结构化发布的 `KnowledgeGraphPublicationResult`，非结构化发布返回 `null` |
| | `retract(input)` | 等价于 `publish({ ...input, entities: [], relations: [] })` |
| | `queryEntities(input)` / `readNeighborhood(input)` | 走 `BoundedGraphReader`（有界读）而非控制器服务 |

### 2.3 知识身份（`knowledgebase/identity/`）

| 方法 | 用途 | 参数与行为语义 | 异常 / 约束 |
| --- | --- | --- | --- |
| `KnowledgeIdentityService.resolve(source, input, runtime)` | 单条归一 | 等价于批量归一并取第一条 | 身份错误族 |
| `KnowledgeIdentityService.resolveBatch(source, inputs, runtime)` | 批量归一（推荐入口） | 必须带提取标识；每条候选键必填、≤512 且不可重复；模型调用在事务外；回写前比对目录指纹 | 非法 / 陈旧 / 忙碌 |
| `assertSource(manager, source)` | 来源校验 | 写前确认来源仍有效 | 身份错误族 |
| 语义裁判阶段（`private judge` / `catalogue` / `readResolved` / `addCandidate` / `lockSource`） | 歧义判定与落库 | 名称类歧义全量取回；语义结果有界且从不授权合并；域 / 范围文本仅作证据；目录并发修改 → 返回 `null` 重试 | — |
| `canMatchIdentity(left, right)`（`knowledge-identity-policy.ts`） | 可匹配性前置 | `kind` 不同即不可匹配；同为 `entity` 时类型冲突或同 namespace 标识符值冲突即不可匹配；其余交由裁判 | — |
| `selectIdentityCandidates(incoming, candidates)` | 候选选择 | 排序键：`identified` > `named` > `similarity` > `id`；过滤 `identified \|\| named \|\| index < 8` | — |
| `identityText(name, descriptor)` / `cosineIdentitySimilarity(left, right)` | 裁判文本与相似度 | 相似度长度不等或零向量返回 `-1` | — |

## §3 代码示例

### ① 打开图谱 → 单文档重试 → 读邻域

```ts
// 真实链条：源文档 durable FINISH 后 publish 发 KnowledgeGraphEnqueueCommand / KnowledgeGraphRetryDocumentCommand
const jobs = await graphragService.enqueueDocuments({ knowledgebaseId, documentIds, reason: 'document' })
// 图谱未启用时 jobs 为 []，不报错；调用方需自行判断长度

const progress = await graphProgressService.getProgress(knowledgebaseId, documentId)
// HTTP 等价：POST /api/knowledgebase/<kbId>/graph/documents/<docId>/retry（控制器内先 assertKnowledgebaseWriteAccess）

const { items } = await graphragService.listEntities(knowledgebaseId, { where: { search: '水权' } })
const neighborhood = await graphragService.getNeighborhood(knowledgebaseId, items[0].id)
const chunks = await graphragService.getEntityChunks(knowledgebaseId, items[0].id, { take: 20 })
const status = await graphragService.getStatus(knowledgebaseId)   // status.error 为空即正常
```

### ② 手工修正与软隐藏

```ts
await graphragService.createEntity(knowledgebaseId, { name: '水资源使用权', type: 'concept', aliases: [] })
await graphragService.updateEntity(knowledgebaseId, entityId, { description: '...' })
await graphragService.hideEntity(knowledgebaseId, entityId)   // 软隐藏，数据仍在
// HTTP 等价：POST/PATCH/DELETE /api/knowledgebase/:id/graph/entities[/:entityId]
```

### ③ 身份归一（批量优先）

```ts
// 抽取链内部调用形态：observations 由 KnowledgeGraphExtractionService.resolveIdentities 组装
const resolved = await identityService.resolveBatch(
    source,          // { knowledgebaseId, tenantId, organizationId, consumer, extractionId, sourceDocumentIdSnapshot, sourceContentHash, sourcePublicationEpoch }
    observations,    // 每条含 candidateKey（必填、≤512、不可重复）与 descriptor
    { model }        // 模型在事务外调用
)
// 目录被并发修改时返回 null 语义 → 需重试，不要当成数据错误
```
