## 1. KB CRUD 与权限断言

- **创建**：`KnowledgebaseService.create` 先经 `KnowledgeKeywordAnalyzerService.forCreate` 解析分析器与 `VectorStoreSettingsService.forCreate` 校验向量库（`Error.KnowledgeVectorStoreUnavailable`），再 `super.save`；唯一名冲突在 `create` 与 `updateKnowledgebase` 两处兜底：先做显式 `name` 查重（`Error.NameExists`），再在 `catch` 中用 `getQueryFailedErrorCode(error)` 读 `driverError.code ?? driverError.errno`，命中 `23505` / `1062` / `duplicate key` / `UNIQUE constraint` / `Duplicate entry` 时翻译为 `BadRequestException`。
- **读**：`findOneByIdString` 先经 `super.findOneByIdString` + `assertKnowledgebaseCrudReadAccess`（无 `workspaceId` + `Private` + 非创建者 → `knowledgebaseAccessDenied()`），再用 `addKnowledgebaseAccessSelect` / `stripKnowledgebaseAccessSelect` 临时补齐再剥离访问字段；`getSafeReadRelations` 对 `$relations` 做白名单校验，越界即 403。`findOneDetail` 追加 `canManage`（`canManageKnowledgebase` 用 try/catch 把 `ForbiddenException` 折为 `false`）。
- **写断言族**：`assertKnowledgebaseWriteAccess` → `assertKnowledgebaseWriteAccessWithError(..., knowledgebaseAccessDenied)`；`assertKnowledgebaseTaskWriteAccess` → 同一实现传 `knowledgebaseTaskAccessDenied`；`assertKnowledgebaseTaskReadAccess`（private）判定「无 `workspaceId` + `Private` + 非创建者」→ `knowledgebaseTaskAccessDenied()`。**注意**：本子域 service 内并没有名为 `assertKnowledgebaseReadAccess` 的方法——该名存在于 `KnowledgeDocumentService`，本子域的读侧对应物是 `assertKnowledgebaseCrudReadAccess`（private）。
- **租户库短路**：`assertKnowledgebaseWriteAccessWithError` 先查 `tenantLibraries.find(...)`，命中则要求 `assertTenantLibraryAdministrator()`（超管 + 租户 scope）后直接返回；否则走工作区/创建者分支。
- **更新**：`updateKnowledgebase` 汇聚 ① `metadataSchema` 归一（`validateAndNormalizeMetadataSchema`）② `applicationTags` 归一 ③ embedding 模型变更（`resolveEmbeddingModelTarget` → `resolveEmbeddingModelUpdateState`）④ `graphRag` 开关状态机（`DISABLED` / `REBUILD_REQUIRED`）⑤ wiki 降级（`wikiStatus = 'rebuild_required'`）⑥ 检索设置校验（`assertKnowledgebaseRetrievalSettings`）；若 patch 落到 `REBUILD_REQUIRED` 则**同一次调用内**直接 `startEmbeddingRebuild(id)`。含 `keywordAnalyzer` 时改走 `keywordAnalyzers.saveSettings`（事务 + 条件 SQL）。

## 2. 检索链实现

- **门面**：`KnowledgeRetriever extends BaseRetriever`，`invoke` 负责 LangChain callback 生命周期，`retrieveDetailed` 组装 `tenantId / organizationId / knowledgebases / query / k / score / rerankThreshold / filters{fixed,request,dynamic} / retrieval / variables / xpertId / threadId` 投 `KnowledgeSearchQuery`，捕获异常时 `dispatchCustomEvent(ChatMessageEventTypeEnum.ON_RETRIEVER_ERROR)` 后重抛；返回前对每个文档套 `DocumentChunkDTO` 并 `omit(doc.metadata, 'children')`。
- **编排**：`KnowledgeSearchQueryHandler.execute` 按 `tenantId + organizationId + id In(...)` 取库；外部库走 `searchExternalKnowledgebase`，内部库走 `searchInternalKnowledgebase`。模式由 `resolveRetrievalMode` 决定（`vector` / `keyword` / `graph` / `hybrid`）。
- **三类候选召回**：`VectorKnowledgeCandidateRetriever`（`source = 'vector'`，PG 走 `compileKnowledgeFilterToPostgres`，Milvus 走 `compileKnowledgeFilterToMilvus` 并并发 `countStructuredFilterCandidates`，非结构化后端回退 `similaritySearchWithScore`；含 `MAX_PROJECTION_SEARCH_EXPANSIONS = 4` 的投影翻倍与问题向量过滤）；`KeywordKnowledgeCandidateRetriever`（`source = 'keyword'`，非 PG 直接抛 `Error.KeywordRetrievalPostgresRequired`；`MAX_KEYWORD_TERMS = 12` / `MAX_KEYWORD_CANDIDATES = 400` / `KEYWORD_OVERSAMPLING = 4` / `KEYWORD_REFILL_GROWTH = 2`）；`GraphKnowledgeCandidateRetriever`（`source = 'graph'`，投 `KnowledgeGraphSearchQuery` 并携带 `createKnowledgeGraphFilterScope(...)`，把 `result.failed` / `result.error` 原样带出）。
- **融合**：`hybrid` 且 `usesWeightedRrf(kb, retrieval)` 为真时走 `searchWithWeightedRrf`——权重取 `fusion.weights ?? DEFAULT_KNOWLEDGE_RRF_WEIGHTS`，`contentScope === 'wiki'` 或 GraphRAG 未启用时 graph 权重置 0，`validateRrfWeights` 先校验（非有限或负 → `Error.RrfWeightInvalid`；全零 → `Error.RrfPositiveWeightRequired`），再 `weightedRrfFusion.fuse(batches, { rankConstant, weights })` 并写诊断 `fusionMode: 'weighted_rrf'`。否则走 `legacyWeightedFusion.fuse([vectorResult, graphResult], { graphWeight: retrieval?.graphWeight ?? kb.graphRag?.graphWeight ?? 0.35 })`，图检索失败时降级为纯向量并写 `hybridGraphFallbackReason`。
- **rerank 与 citation**：`finalizeRetrievalResults` 在存在 rerank 模型且 `merged.length > 0` 时取 `getRerankModel`，以 `tableContextText(doc)` 替换 `pageContent` 后调 `rerank(documents, query, { topN: min(len, topK), scoreThreshold: rerankThreshold })`，把返回的 `relevanceScore` 回填到原文档；失败包成 `KnowledgeRetrievalFailure('rerank', 'rerank_failed', ...)`。Agent 工具面输出由 `formatKnowledgebaseRetrievalToolOutput` 生成 `{ chunks, citations, instructions, diagnostics }`，citation 链接形如 `xpert://knowledgebase/chunk?...`。

章节来源：[knowledgebase/retriever.ts](file://packages/server-ai/src/knowledgebase/retriever.ts)（关键符号：KnowledgeRetriever.retrieveDetailed / toTool / toFilterOptionsTool / toGraphExplorerTool）、[knowledgebase/retrieval/vector-knowledge-candidate.retriever.ts](file://packages/server-ai/src/knowledgebase/retrieval/vector-knowledge-candidate.retriever.ts)（关键符号：VectorKnowledgeCandidateRetriever.retrieve）、[knowledgebase/retrieval/keyword-knowledge-candidate.retriever.ts](file://packages/server-ai/src/knowledgebase/retrieval/keyword-knowledge-candidate.retriever.ts)（关键符号：KeywordKnowledgeCandidateRetriever.retrieve / extractKeywordTerms）、[knowledgebase/retrieval/graph-knowledge-candidate.retriever.ts](file://packages/server-ai/src/knowledgebase/retrieval/graph-knowledge-candidate.retriever.ts)（关键符号：GraphKnowledgeCandidateRetriever.retrieve）、[knowledgebase/queries/handlers/knowledge-search.handler.ts](file://packages/server-ai/src/knowledgebase/queries/handlers/knowledge-search.handler.ts)（关键符号：KnowledgeSearchQueryHandler.execute / searchWithWeightedRrf / validateRrfWeights / finalizeRetrievalResults）、[knowledgebase/citation.ts](file://packages/server-ai/src/knowledgebase/citation.ts)（关键符号：formatKnowledgebaseRetrievalToolOutput / createKnowledgebaseCitationUrl）

## 3. 向量读写（KnowledgeDocumentStore）

- **写**：`addKnowledgeChunks(chunks, { ids })` 逐 chunk 校验 `documentId` 必填（缺失抛 `Chunk '<id>' has no document id`）、按 `metadataSchema` 校验 document / chunk 两侧 metadata（`validateFilterMetadata`），再 `fillMetadata` 补 `enabled/knowledgeId/documentId/model/provider/embeddingModelFingerprint/embeddingDimensions/embeddingRevision/chunkId/source/blobType/loc/filterAttributes`；`addKnowledgeDocument` 是同族另一入口；`addGraphDocuments` 面向图谱实体向量。`updateChunk` 是「读旧 → 删 → 合并 metadata → 按同一物理 id 重写」。
- **Embedding 与文本分离**：`prepareChunksForEmbedding` 在 `metadata.searchContent` 存在时把 `pageContent` 换成 `searchContent`、把原文存进 `metadata.fullPageContent`；`restorePageContent` 在检索侧还原。
- **物理 id**：`createVectorId` 在配置了 `vectorIdCollectionName` 时走 `createCollectionScopedVectorId`，否则退化为原始 chunkId；`resolveVectorIds` 在 id 数量与 chunk 数不一致时返回 `undefined`（放弃自定义 id）。
- **读**：`similaritySearchWithScore(query, k, filter)` 默认补 `filter.enabled = true`；`structuredSimilaritySearchWithScore` 要求底层 store 实现同名方法，否则抛 `Vector store '<type>' does not support knowledge filter v2.`；`createSearchSession(query, reuseUnstructuredQuery)` 用闭包缓存 `embedding`（`getEmbedding = () => (embedding ??= this.vStore.embeddings.embedQuery(query))`），使一次检索的多次窗口扩展只 embed 一次——源码注释「Request-local embedding reuse; no shared model or store state is changed by expansion.」
- **过滤属性与 schema 扩展**：`partialUpdateFilterAttributes`、`ensureFilterV2Schema`、`getFilterAttributesByChunkIds` 均为「底层有则调用、无则返回 0 / false / null」的可选能力探测；`rerank(docs, query, { topN })` 直接转发 `this.rerankModel.rerank`。

## 4. 向量存储抽象

- **命令入口**：`RagCreateVStoreCommand(embeddings, { collectionName, vectorStore })` → `RagCreateVStoreHandler.execute`：`const vectorStore = command.config.vectorStore ?? environment.vectorStore`，`switch` 命中 `VectorTypeEnum.PGVECTOR` 走内置分支 `createPgVectorStore`，`default` 走 `this.vectorStoreRegistry.get(vectorStore)?.createStore(embeddings, config)`，都拿不到则抛 `InternalServerErrorException(i18n.t('xpert.Error.UnsupportedVectorStore', ...))`（`lang` 由 `mapTranslationLanguage(RequestContext.getLanguageCode())` 决定；该键在 `en.json` 中未命中）。
- **内置 PG 分支**：`createPgVectorStore` 硬编码 `tableName: 'knowledge_document_vector'`、`collectionTableName: 'knowledge_document_collection'` 与列名映射 `id / vector / content / metadata`，随后 `ensureTableInDatabase()` + `ensureCollectionTableInDatabase()` 运行期建表。`environment` 与 `DATABASE_POOL_TOKEN` 是它的两个运行期输入（`ConfigService.get<IPGVectorConfig>('pgvector')` 目前未被使用，代码如下）。
- **插件策略**：`VectorStoreRegistry` 由 plugin-sdk 提供，`RagVStoreModule` 直接 `providers: [..., VectorStoreRegistry]`；`VectorStoreSettingsService.options()` 只暴露 `PGVECTOR` 与「注册表里真的存在」的 `MILVUS`，`forCreate` 拒绝未安装的后端（`Error.KnowledgeVectorStoreUnavailable`），`assertUnchanged` 拒绝创建后改库（`Error.KnowledgeVectorStoreImmutable`）。
- **PG 实现细节**：`KnowledgePGVectorStore extends PGVectorStore` 覆盖 `getByIds`（带 `collection_id` 过滤）、`similaritySearchVectorWithScore`（`filter.sourceOnly === true` 时手写 SQL，排除 `metadata.questionGenerationId`）、`addVectors`（`ON CONFLICT (id) DO UPDATE` 幂等 upsert，rowCount 不匹配抛 `Error.KnowledgebaseVectorCollectionConflict`；数量不等抛 `Error.KnowledgebaseVectorBatchInvalid`）、`structuredSimilaritySearchWithScore` / `structuredSimilaritySearchVectorWithScore`（`INNER JOIN knowledge_document_chunk` 与 `knowledge_document`，按固定别名 `d` / `c` 注入编译后的谓词，并返回 `candidateDocumentCount` / `candidateChunkCount`）。

## 5. embedding 重建与 collection 切换

- **启动**：`startEmbeddingRebuild(id)` —— 先 `assertKnowledgebaseWriteAccess`，`REBUILDING` 时抛 `Embedding rebuild is already running`；缺 `pendingCopilotModel` / `pendingEmbeddingModelFingerprint` 抛 `Pending embedding model is required for rebuild`；指纹与 active 相同时**直接清空 pending 并回 `READY`**；只允许从 `REBUILD_REQUIRED` / `REBUILD_FAILED` 起步（否则抛 `Embedding rebuild cannot start from status '<x>'`）；随后生成 `rebuildTaskId = shortuuid()`、`pendingEmbeddingRevision = (pending ?? active ?? 0) + 1`，置 `REBUILDING` 并入队 `rebuild-knowledgebase-embedding`（载荷 `TKnowledgebaseRebuildEmbeddingJob`）。
- **执行**：`KnowledgebaseRebuildEmbeddingConsumer`（`@Process({ concurrency: 1 })`）用 `captureRequestContext` + `runWithCapturedRequestContext` 还原请求上下文后调 `processEmbeddingRebuildJob`；后者 `assertCurrentRebuildTask` → `getPendingVectorStoreForRebuild().clear()` → 全量取 chunk（`order: { createdAt: 'ASC' }`）→ `findAllEmbeddingNodes` → 按 `embeddingBatchSize || 10` 分批 `addKnowledgeChunks(batch, { ids })`，FAQ 库走 `buildFAQVectorWriteFromMetadata`，普通库对问题向量走 `buildQuestionVectors` 并 `recordRebuiltQuestionVectors` 回写。
- **切换**：`promoteEmbeddingRebuild` 在 `dataSource.transaction` 内再次 `assertCurrentRebuildTask`，把 `pending*` 提升为 active（`copilotModel` / `embeddingCollectionName` / `embeddingModelFingerprint` / `embeddingDimensions` / `embeddingRevision`）并 `status = READY`，同时批量回写 chunk `metadata.{model,provider,embeddingModelFingerprint,embeddingDimensions,embeddingRevision}`（`model` 取 `getEmbeddingModelName(saved.copilotModel)`）；事务外 fire-and-forget 调 `cleanupEmbeddingCollection(promoted, oldCopilotModel, oldCollectionName)`，失败仅 `logger.warn`。
- **失败与撤销**：`markEmbeddingRebuildFailed` 对陈旧任务只 `logger.warn('Skip stale embedding rebuild failure ...')` 不覆盖状态，否则写 `status = REBUILD_FAILED` + `embeddingRebuildError`；`cancelPendingEmbeddingModel(id)` 在非 `REBUILDING` 时清空全部 pending 字段并回 `READY`。

## 6. 结构化过滤与 metadataSchema

- `filter/knowledge-filter.ts` 是过滤器编译中心：`createKnowledgeFilterRegistry` 把 `metadataSchema` 与内置字段（如 `document.folderPath`）合成 `KnowledgeFilterFieldDefinition` 注册表；`prepareKnowledgeFilter` 产出 `PreparedKnowledgeFilter`（含 `effective` / `sources` / `registry` / `diagnostics`）；`validateKnowledgeFilter` 校验动态过滤器的字段与操作符，非法时**回退到 fixed 边界**并在诊断中记 `invalid_dynamic_filter`（`retriever.ts` 注释：「Exact field/operator/type validation belongs to KnowledgeFilterCompiler, where an invalid dynamic filter can safely fall back to the fixed boundary and be audited as invalid_dynamic_filter.」）。
- 两种后端编译：`compileKnowledgeFilterToPostgres` → `{ sql, parameters }`（谓词只引用固定别名 `d`（`knowledge_document`）与 `c`（`knowledge_document_chunk`））；`compileKnowledgeFilterToMilvus` → `{ expression, values }`；`createMilvusFilterAttributes` 把 document + chunk metadata 折叠成 `filterAttributes` 供 Milvus 侧过滤。图检索范围由 `KnowledgeGraphFilterScopeService` 收敛。
- **元数据写入校验**：`KnowledgeDocumentStore` 的 `validateFilterMetadata` 按 `KBMetadataFieldDef.scope`（`document` / `chunk`）与 `type`（`string|enum|datetime|number|boolean|string[]|number[]|object`）逐字段校验，`enum` 还要求命中 `enumValues`；不合法抛 `Metadata '<key>' must match schema type '<type>'.`。`KnowledgebaseService.validateAndNormalizeMetadataSchema` 是写侧归一入口，`metadataSchema` 列默认 `[]`。
- **过滤候选发现**：`countStructuredFilterCandidates`、`listStructuredFilterFolderCandidates`、`listStructuredFilterValueCandidates`（内部 `structuredFilterOptionValueExpression`）、`listStructuredGraphEvidence` 提供 Agent 工具面的「活值」查询，分别由 `KnowledgeFilterValueOptionsQuery` / `KnowledgeFolderOptionsQuery` / `KnowledgeGraphExploreQuery` 路由。

## 7. 关键词分析器

- `KnowledgeKeywordAnalyzerService` 以 `KeywordAnalyzerRegistry`（plugin-sdk）为策略源：`options(organizationId)` 列注册项；`forCreate(value, organizationId)` 在缺省时取 `DEFAULT_KNOWLEDGE_KEYWORD_ANALYZER` 的绑定；`binding/parseAnalyzer/sameKeywordAnalyzer/resolve` 共同维护 `KnowledgeKeywordAnalyzer`（`provider` + `revision` + `source.kind: 'builtin' | 'plugin'`），revision 不匹配抛 `Error.KeywordAnalyzerRevisionMismatch`。
- `vector / query / queryPlan` 是三条分析入口（索引向量、查询 tsquery、`keywordQueryPlan` 组合词项与标识符），均先 `resolvePersisted` 再调用策略的 `analyze(text, 'index' | 'query')`。
- **`update: false` 的条件 SQL 独占写**：`change` 用一条 CTE 语句
  `UPDATE "knowledgebase" kb SET "keywordAnalyzer" = $1::jsonb WHERE kb."id" = $2 AND tenantId IS NOT DISTINCT FROM $3 AND organizationId IS NOT DISTINCT FROM $4 AND kb."keywordAnalyzerLocked" = false AND NOT EXISTS(... "knowledge_document" d ... sourceType IS DISTINCT FROM 'folder') AND NOT EXISTS(... "knowledge_document_chunk" c ...)`
  并 `RETURNING id`；无返回行即抛 `Error.KeywordAnalyzerLocked`。源码注释：「This conditional write serializes with the first document's lock update on the same KB row.」`External` 类型知识库直接拒绝（`Error.KeywordAnalyzerExternal`）。
- `saveSettings` 把 `change` 与 `manager.getRepository(Knowledgebase).save({ ...knowledgebase, keywordAnalyzer })` 包在同一个 `dataSource.transaction` 里；`KeywordChunkSubscriber.beforeInsert/beforeUpdate` 在写 chunk 前执行 `UPDATE "knowledgebase" SET "keywordAnalyzerLocked" = true WHERE "id" = $1 AND "keywordAnalyzerLocked" = false` 做串行化；`beforeUpdate` 在没有 `pageContent` 变更时**主动删除** `entity.keywordVector`（注释：「Derived search data is never accepted from an external chunk patch.」）。
- 索引名集中声明于 `KnowledgeKeywordIndexService`：`KNOWLEDGE_KEYWORD_FTS_INDEX`、`KNOWLEDGE_KEYWORD_TITLE_INDEX`、`KNOWLEDGE_KEYWORD_VECTOR_INDEX`、`KNOWLEDGE_KEYWORD_TRIGRAM_INDEX`、`KNOWLEDGE_DOCUMENT_NAME_TRIGRAM_INDEX`；`status()` / `vectorStatus()` 通过 `pg_index` 的 `indisready AND indisvalid` 判断可用性并缓存 `ready`，非 Postgres 抛 `Error.KeywordIndexPostgresRequired`。

## 9. 热点路径

1. **检索融合**：每次 Agent 调用都走「候选召回 → 融合 → rerank」。`usesWeightedRrf` 为真时三路并发（`Promise.all`）；`createSearchSession(query, reuseUnstructuredQuery)` 的 embedding 复用是唯一避免重复 embed 的手段——`vector-knowledge-candidate.retriever.spec.ts` 的 `MAX_PROJECTION_SEARCH_EXPANSIONS = 4` 翻倍搜索会多次调用同一 session。
2. **rerank**：`finalizeRetrievalResults` 在 `rerankModelId` 或请求级 `rerankModel` 存在时必然调用模型，且用 `tableContextText(doc)` 重写 `pageContent`，是延迟与 token 的主要来源；异常直接升级为 `KnowledgeRetrievalFailure`，**无降级**。
3. **重建期的写阻断**：`assertNotRebuilding` 在 `:id/file`（`uploadFile` 内显式调用）、`startEmbeddingRebuild`、`cancelPendingEmbeddingModel`、`delete` / 文档删除等入口生效；重建是全库重嵌的长任务，阻断窗口与 `chunkNum` 成正比。
4. **日志写入**：`KnowledgeSearchQueryHandler` 每次检索都 `retrievalLogService.create({...})`，失败仅 `logger.error`，不阻塞返回——写放大与 DB 压力需关注。

## 11. 技术债

1. **融合策略双轨并存**：`WeightedRrfFusion` 与 `LegacyWeightedFusion` 同时保留且都被注入 `KnowledgeSearchQueryHandler`，行为分支由 `fusion?.mode === 'weighted_rrf'` 独占决定；`LegacyWeightedFusion` 只消费 `vector` / `graph` 两个 batch，keyword 分支在旧路径中被忽略。
2. **向量表非实体（运行期建表）**：`knowledge_document_vector` / `knowledge_document_collection` 由 `createPgVectorStore` 硬编码并 `ensureTableInDatabase()` 建表，不在 TypeORM 实体元数据里，`synchronize` 不管理其结构与维度；多副本并发首次建表依赖 `IF NOT EXISTS` 语义（未逐行核对 pgvector 内部 DDL）。
3. **`update: false` 列陷阱**：`keywordAnalyzer` / `keywordAnalyzerLocked` 普通 `save()` 不生效，只有 `change` 的条件 SQL 与 subscriber 的加锁 UPDATE 能写；误用会产生「改了不生效」且无报错。
4. **维度不匹配的报错面**：维度只在 embedding 查询时由 `resolveEmbeddingDimensions` 解析并按指纹派生 collection，没有「写入时比对表维度」的检查；换模型后若未走重建，错误会在检索/写入时以底层驱动异常形式暴露。
5. **rerank 无降级**：模型缺失或调用失败直接抛 `Error.KnowledgeRerankModelUnavailable` / `KnowledgeRetrievalFailure`，没有「跳过 rerank 返回融合结果」的回退分支。
6. **重建清理是 best-effort**：`promoteEmbeddingRebuild` 事务外 fire-and-forget 调 `cleanupEmbeddingCollection`，失败只 `logger.warn`，旧 collection 可能长期残留（存储成本 2×）。
7. **`UnsupportedVectorStore` i18n 键缺失**：`create.handler.ts` 使用 `xpert.Error.UnsupportedVectorStore`，但该键在 `packages/server-ai/src/i18n/en.json` 中未命中，实际返回键名本身。
8. **`ConfigService.get('pgvector')` 读而未用**：`createPgVectorStore` 里 `const _config = this.configService.get<IPGVectorConfig>('pgvector')` 之后未再引用（下划线命名），属死代码。

## 12. 设计维度分析

**维度一：检索可组合性——「候选批次契约」而非「管道串联」。** 三类召回实现同一个 `KnowledgeCandidateRetriever` 接口，返回结构化 `KnowledgeRetrievalBatch`（含 `candidates[{document, rank}]`、`diagnostics`、`exhausted`、`budgetLimited`、`failed`、`error`），融合器实现 `KnowledgeCandidateFusion<TOptions>`。这样做的收益是：失败可以在融合前被识别（`WeightedRrfFusion.fuse` 首句即检查 `failedBatch` 并抛错，而不是静默丢一路），权重可以逐路置 0（graph 在 `contentScope === 'wiki'` 时强制置 0），预算与耗尽信息可以在 FAQ 语义重填（`refillFAQCandidates`）中继续流转。代价是契约变重——每个新召回源都必须自带诊断与 `rank`，否则 `VectorKnowledgeCandidateRetriever` 里那句 `KnowledgeCandidateRankMissing` 会直接 500。

章节来源：[knowledgebase/retrieval/types.ts](file://packages/server-ai/src/knowledgebase/retrieval/types.ts)（关键符号：KnowledgeRetrievalBatch / KnowledgeCandidateRetriever / KnowledgeCandidateFusion / KnowledgeRetrievalFailure）、[knowledgebase/retrieval/weighted-rrf.fusion.ts](file://packages/server-ai/src/knowledgebase/retrieval/weighted-rrf.fusion.ts)（关键符号：WeightedRrfFusion.fuse）、[knowledgebase/retrieval/vector-knowledge-candidate.retriever.ts](file://packages/server-ai/src/knowledgebase/retrieval/vector-knowledge-candidate.retriever.ts)（关键符号：Error.KnowledgeCandidateRankMissing）

**维度二：存储可替换性——「命令分派 + 能力探测」双层。** 上层只认 `KnowledgeDocumentStore`；`RagCreateVStoreHandler` 用 `switch` 保留内置 PG 快路径，其余类型落到 `VectorStoreRegistry` 插件策略，无匹配即抛错而不静默降级。面对不同后端能力差异（结构化过滤、filter attributes 局部更新、按 id 取回），`KnowledgeDocumentStore` 用「方法存在性探测」而非接口继承：`structuredSimilaritySearchWithScore` 不支持时抛明确错误，`partialUpdateFilterAttributes` / `ensureFilterV2Schema` / `getFilterAttributesByChunkIds` 不支持时返回中性值。收益是新增后端不必实现全能力；代价是能力缺失只在使用该能力时才暴露（`similaritySearchVectorWithScore` 的 `sourceOnly` 分支仅 PG 实现）。

章节来源：[knowledgebase/vector-store.ts](file://packages/server-ai/src/knowledgebase/vector-store.ts)（关键符号：KnowledgeDocumentStore.structuredSimilaritySearchWithScore / partialUpdateFilterAttributes / ensureFilterV2Schema）、[rag-vstore/commands/handlers/create.handler.ts](file://packages/server-ai/src/rag-vstore/commands/handlers/create.handler.ts)（关键符号：RagCreateVStoreHandler.execute / VectorStoreRegistry）、[rag-vstore/knowledge-pg-vector.store.ts](file://packages/server-ai/src/rag-vstore/knowledge-pg-vector.store.ts)（关键符号：KnowledgePGVectorStore.similaritySearchVectorWithScore）

**维度三：换模型的在线性——「double-write + 原子提升」。** 换 embedding 模型不改历史 collection：`resolveEmbeddingModelUpdateState` 先写 `pending*` 并把 KB 置 `REBUILD_REQUIRED`，`startEmbeddingRebuild` 与 `promoteEmbeddingRebuild` 用 `rebuildTaskId + pendingEmbeddingRevision` 做任务身份，提升在单事务内把 pending 搬成 active，`assertNotRebuilding` 在窗口期阻断其它写操作。向量物理 id 由 collection 名派生（`createCollectionScopedVectorId`），使新旧 collection 可共存而不撞主键。这套设计把「不可避免的停机写窗口」压缩成 brief 的原子替换，但代价是存储 2× 与写阻断的业务影响。

## 13. 结论

实现层面的主线是「**一个聚合服务 + 一组能力契约 + 显式的窗口阻断**」：`KnowledgebaseService` 把作用域、权限、模型、向量工厂与重建全部内聚，向量读写被强制收口到 `KnowledgeDocumentStore`，检索被拆成「候选批次 → 融合 → rerank → citation」四段且每段都有明确失败语义。可改进优先级：① 收敛 `LegacyWeightedFusion` 双轨（明确弃用条件或让旧路径也支持 keyword）；② 为向量表引入显式迁移或维度自检，避免运行期建表与 `synchronize` 的空白；③ 给 rerank 增加可配置降级；④ 修掉 `UnsupportedVectorStore` i18n 键缺失与 `ConfigService.get('pgvector')` 死代码；⑤ 把 `assertNotRebuilding` 的调用点清单固化到一处，避免新写路径绕过。
