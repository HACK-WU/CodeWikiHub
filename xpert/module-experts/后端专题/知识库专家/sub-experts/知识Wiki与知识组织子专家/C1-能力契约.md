## §1 HTTP 端点

### 1.1 前缀与鉴权基线

| 前缀 | 控制器 | 鉴权基线 | 用途 |
| --- | --- | --- | --- |
| `/api/knowledgebase/:knowledgebaseId/wiki` | `KnowledgeWikiController`（`@Controller(':knowledgebaseId/wiki')` + `RouterModule.register({ path: '/knowledgebase' })`；`:knowledgebaseId` 走 `UUIDValidationPipe`） | **零 `@UseGuards`**；授权靠 `KnowledgeWikiService` 内部（非 `ready` 状态查询要求管理权限） | 状态、配置、重建、重试、页面浏览、文档状态 |
| `/api/knowledgebase/:knowledgebaseId/wiki` | `KnowledgeWikiOrganizationController`（同前缀；类级 `ValidationPipe({ transform: true, whitelist: true, forbidNonWhitelisted: true })`） | **零 `@UseGuards`** | 目录、taxonomy、placement、分类运行、分类图 |

> 两个控制器挂在同一前缀下，靠方法 + 路径段区分；`KnowledgeWikiModule.controllers = [KnowledgeWikiController, KnowledgeWikiOrganizationController]`。

### 1.2 代表端点

| 方法 路径 | 用途与行为 | 主要错误 |
| --- | --- | --- |
| `GET /wiki/status` | `getStatus`：启停后的状态与可用性、`canManage`、不确定调用计数与 `recoveryActions`（`retry_job` / `full_rebuild`、`failureReason`、`canRetry`、`requiresAdditionalChargeConfirmation`） | 禁用态返回 `disabled` 语义 |
| `PUT /wiki/config` | `updateConfiguration(id, UpdateKnowledgeWikiConfigDTO)`；配置写入后若判定「需重建」且带 `confirmModelCharges` 则触发重建 | 400 `Error.KnowledgebaseWikiStateReadOnly` |
| `GET /wiki/documents/status` | `getDocumentStatus(kbId, query.documentIds)`；query 经 `ValidationPipe({ transform: true, whitelist: true })` | 400 |
| `POST /wiki/rebuild` | `rebuild(kbId, RebuildKnowledgeWikiDTO, userId)`；未启用即 400；源非空时必须确认计费 | `Error.KnowledgebaseWikiDisabled`、`Error.KnowledgebaseWikiRebuildChargeConfirmationRequired` |
| `POST /wiki/jobs/:jobId/retry` | `retry(kbId, jobId, RetryKnowledgeWikiJobDTO, userId)`；先退休被取代的旧任务；仅失败任务可重试；存在不确定调用时要求额外确认 | `…JobNotFound` / `…JobRetryInvalid` / `…RetryChargeConfirmationRequired` |
| `GET /wiki/pages` | `query.status && query.status !== 'ready'` → `KnowledgeWikiService.listPages`（需管理权限）；否则 `KnowledgeWikiBrowseService.list` | 403、`Error.KnowledgebaseWikiPaginationInvalid` |
| `GET /wiki/pages/:pageId` | `getPage` 结果再叠加 `browse.placement(...)`（返回 `placement`） | `Error.KnowledgebaseWikiPageNotFound` |
| `GET /wiki/folders` | `KnowledgeWikiBrowseService.taxonomy(id, query)`：目录树 + 计数（`pageCount` / `unclassifiedCount` / `total`）与 `enabled` / `revision` | — |
| `PATCH /wiki/taxonomy` | `organization.configure(id, body.enabled, body.revision)`：启停分类与修订号推进 | `Error.KnowledgebaseWikiOrganizationInvalid` / `…Conflict` |
| `POST /wiki/folders` | `organization.saveFolder(id, body)`：新建目录 | 同上 |
| `PATCH /wiki/folders/:folderId` | `organization.saveFolder(id, body, folder, body.version)`：带版本更新 | 400 / 409 |
| `DELETE /wiki/folders/:folderId?version=` | `organization.deleteFolder(id, folder, query.version)`；`@HttpCode(204)`；目录非空即拒 | `Error.KnowledgebaseWikiFolderNotEmpty` |
| `PATCH /wiki/pages/:pageId/placement` | `organization.movePage(id, page, body.folderId, body.version)`：改页面归属 | 400 / 409 |
| `GET /wiki/classification-runs/status` | `classification.status(id)`：当前活跃 job 概览 | — |
| `GET /wiki/classification-runs?runId=` | `classification.list(id, query.runId)`；返回项含 `outcome` / `stale` / `requiresAdditionalChargeConfirmation` | — |
| `POST /wiki/classification-runs` | `classification.start(id, body.unclassifiedOnly)`：创建 run / job（**不落 placement**） | 400 |
| `POST /wiki/classification-runs/apply` | `classification.apply(id, body.jobIds)`：在事务内把分类结果写成 placement | 400 / 409 |
| `GET /wiki/graph?type=&depth=&take=` | `browse.graph(id, query)`：节点（含 `sourceCount`）+ 边（`sectionAnchor`），受 `truncated` 保护 | — |

### 1.3 路由要点

- **`status` 决定读模型**：页面列表在两个读模型间自动切换（`ready` / 缺省 → browse；其他 → 管理视图 `listPages`，非 `ready` 状态查询需要管理权限）。
- **组织控制器校验更严**：`forbidNonWhitelisted: true` 会让未知字段直接 400，客户端不要多传键。
- **`DELETE folders` 返回 204**：删除成功无响应体，只带 `?version=`。

## §2 服务契约

### 2.1 `KnowledgeWikiService`（`knowledge-wiki.service.ts`）

| 方法 | 用途 | 参数与行为语义 | 异常 / 约束 |
| --- | --- | --- | --- |
| `getStatus(knowledgebaseId)` | Wiki 状态 | 启停 / 可用性、`canManage`、不确定调用计数与恢复动作（推荐动作：重试任务 / 全量重建） | 未启用时为禁用态 |
| `updateConfiguration(knowledgebaseId, input)` | 更新配置 | 配置写入后按指纹判定「需重建」；传入 `confirmModelCharges` 时自动触发重建 | 400（配置非法 / 只读态） |
| `listPages(knowledgebaseId, params?)` | 管理视图页面列表 | 分页参数有校验；非 `ready` 状态需管理权限 | 403、`Error.KnowledgebaseWikiPaginationInvalid` |
| `getPage(knowledgebaseId, pageId)` | 页面详情 | 返回 `KnowledgeWikiPageDetail`（含链接 `resolveLinks`） | `Error.KnowledgebaseWikiPageNotFound` |
| `getDocumentStatus(knowledgebaseId, documentIds)` | 按文档查状态 | 每行含进度与 `uncertain` | 400 |
| `rebuild(knowledgebaseId, input, userId)` / `retry(knowledgebaseId, jobId, input, userId)` | 重建 / 重试入口 | 控制器直接调用；实际生成逻辑在 `KnowledgeWikiGenerationService` | 见 §1.2 错误列 |
| 内部件 | `getScope` / `assertWikiEnabled` / `isPageServiceable` / `toDiagnosticPage` / `resolveLinks` / `canManage` / `pageScope` / `countPages` / `countJobs` / `getInvocationStatus` / `toRecoveryAction` / `getSourceCleanupStatus` | 均为 `private`，不承诺稳定签名 | — |

### 2.2 生成链（`KnowledgeWikiGenerationService`）

| 方法 | 用途 | 关键语义 |
| --- | --- | --- |
| `enqueueSource(input)` | 单源入队 | Wiki 未启用即返回空；读 `_source_state`（`lastEventType` / `eligible` / `cleanupPending` / `generationPending` / `desiredRootJobId`）；源不可用转为撤回路径；写 `wikiStatus` / `wikiBuildError` |
| `rebuild(input)` | 全库重建 | `assertRebuildSources` 先查已发布页面；源为空/无可用源时报 `knowledge_wiki_empty_sources`；非空需计费确认；写 `wikiRevision` / `wikiStagedRevision` / `wikiStatus`；`expectedChildren` / `succeededChildren` / `failedChildren` 记账 |
| `retry(input)` | 任务重试 | 先退休被取代的旧任务；查 `status = failed` 的 job 与 `status = indeterminate` 的调用；给出 `JobNotFound` / `JobRetryInvalid` / `RetryChargeConfirmationRequired` 三类错误 |
| `processJob(jobId)` | 消费者侧分派 | 心跳 + `lease.acquire(job)`；取不到租约即退出；按 `job.type` 分派（`source_map` → `processSourceMap`、重建 → `processRebuild`、`identity_resolve` → `KnowledgeWikiIdentityResolverService`、`page_reduce` → `KnowledgeWikiPageReduceService`、`classify` → `KnowledgeWikiClassificationService.process`、收尾 → `KnowledgeWikiFinalizeService`）；非当前代或已终态直接跳过 |
| `processSourceMap(job)` | 源映射 | 按 `batches` 调结构化模型，写 `_source_map_result`（唯一键含 `candidateKey`），并把候选名交给身份层 |
| `processRebuild(job)` | 重建批量 | 为目标源组装子 job（`stage` / `configFingerprint` / `generatorVersion` / `spendEnvelope`），投递后进入等待 |
| `failJob` / `invalidateSourcePages` / `prepareRebuildSourceState` | 失败与失效 | 失败写 `errorCode` 与状态；失效把相关页面置脏并标记投影状态；重建前准备好源状态 |

### 2.3 投影、撤回与对账

| 组件 | 方法 | 关键语义 |
| --- | --- | --- |
| `KnowledgeWikiProjectionService` | `stage(kb, page, version)` | 生成稳定 chunk id（`uuidv5('wiki:<pageId>:<versionId>:root')`）、metadata 带 `wikiPageId` / `wikiPageVersionId` / `wikiPageKey` / `wikiPageType` / `wikiRevision` / `sectionAnchor` / `projectionStatus` / `searchContent`；`getActiveVectorStore(kb.id, true)` → `addKnowledgeDocument`；成功置 `projectionStatus = 'ready'` |
| | `retireVersions(kb, versionIds)` | 删投影 chunk 与向量并把版本置 `disabled` |
| | `retireSupersededVersions(knowledgebaseId?)` | 按「已发布 + 非 disabled + 不是 activeVersion」选取，单批 `take(50)`；失败只写 `projectionError` 与 warn |
| | `ensureProjectionDocument(kb)` | 以 `sourceKey = 'system:knowledge-wiki'` 找或建投影文档（`name: 'Wiki'`、`filePath: '.system/wiki'`、`status: FINISH`、`metadata: { systemManaged: true, systemManagedType: 'knowledge-wiki' }`），并在 `_projection_state` 里记 `projectionDocumentId` |
| `KnowledgeWikiRetractionService` | `enqueue(input)` / `process(job)` | 源禁用 / 硬删后的页面与投影回收，维护 `_source_state` |
| `KnowledgeWikiReconcilerService` | `reconcile(...)`（`@Interval`） | 退休被取代 job、重派发、回收过期租约、版本升级重算 |
| `KnowledgeWikiJobLeaseService` / `KnowledgeWikiJobFenceService` / `KnowledgeWikiJobFenceService` | 租约 / 栅栏 / 代次 | 并发控制三件套：`lease.acquire` 取不到即退出；栅栏用 `generationRevision` / `generationAttempt` 判代次 |
| `KnowledgeWikiInvocationBudgetService` / `KnowledgeWikiModelInvocationService` | 预算与调用记账 | `_model_invocation` 记录 `stage ∈ map\|dedup\|reduce\|classify\|links`、`billingStatus`、`reconciliationStatus`（含 `indeterminate`）——`requiresAdditionalChargeConfirmation` 的数据来源 |
| `KnowledgeWikiIdentityResolverService` / `KnowledgeWikiPageReduceService` / `KnowledgeWikiPageSchedulerService` / `KnowledgeWikiFinalizeService` / `KnowledgeWikiLinkService` / `KnowledgeWikiIndexService` / `KnowledgeWikiRebuildCoordinatorService` / `KnowledgeWikiJobDispatcherService` | 阶段实现 | 身份解析、多来源归并、页面调度、收尾发布、页面链接、检索索引、重建协调、job 投递 |
| `KnowledgeWikiGenerationConsumer` | `@Processor({ name: JOB_KNOWLEDGE_WIKI_GENERATION })` | 队列 `knowledge-wiki-generation`（`knowledgebase/wiki/types.ts`） |

## §3 代码示例

### ① 配置 → 状态 → 重建（含计费确认）

```ts
// PUT /api/knowledgebase/:knowledgebaseId/wiki/config
await wikiService.updateConfiguration(knowledgebaseId, { enabled: true, modelId, confirmModelCharges: false })

const status = await wikiService.getStatus(knowledgebaseId)
// status.recoveryActions[] ∈ { retry_job, full_rebuild }，含 failureReason / canRetry / requiresAdditionalChargeConfirmation
if (status.indeterminateInvocationCount > 0) {
    // 不可自动重试：先人工确认「可能已计费但结果未落地」
}

// POST /api/knowledgebase/:knowledgebaseId/wiki/rebuild（非空 Wiki 必须显式确认计费）
await wikiGenerationService.rebuild({ knowledgebaseId, userId, confirmModelCharges: true })
```

### ② 页面浏览 + 按文档查状态

```ts
// GET /wiki/pages：status 缺省或 'ready' 走 browse 读模型，否则走管理视图
const pages = await browseService.list(knowledgebaseId, { status: 'ready', search: '水权', groupTypes: ['concept'] })
const page = await wikiService.getPage(knowledgebaseId, pages.items[0].id)
const placement = await browseService.placement(knowledgebaseId, pages.items[0].id)

// GET /wiki/documents/status
const progress = await wikiService.getDocumentStatus(knowledgebaseId, documentIds)  // 行内含 uncertain
```

### ③ 分类运行：启动 → 复核 → 应用

```ts
const { runId } = await classificationService.start(knowledgebaseId, true)          // unclassifiedOnly
const runs = await classificationService.list(knowledgebaseId, runId)              // 复核 outcome / stale
const confirmed = runs.jobs.filter((job) => !job.requiresAdditionalChargeConfirmation).map((job) => job.jobId)
await classificationService.apply(knowledgebaseId, confirmed)                      // 事务内写 placement
// 需要人工调整时：PATCH /wiki/pages/:pageId/placement（带 version）
```
