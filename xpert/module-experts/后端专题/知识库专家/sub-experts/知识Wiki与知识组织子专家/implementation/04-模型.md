## 2. 执行与计费表

### 2.1 knowledge_wiki_job
- 唯一约束：`(knowledgebaseId, jobKey)`；索引：`(knowledgebaseId, status, isCurrent)`、`(rootJobId, status)`。
- 关系：`knowledgebase`（非空，CASCADE）。
- 列：`knowledgebaseId` uuid；`classification` jsonb 可空；`rootJobId` / `parentJobId` / `sourceDocumentIdSnapshot` uuid 可空；`pageKey` varchar(768) 可空；`sourceLifecycleGeneration` / `sourcePublicationEpoch` int 可空；`sourceContentHash` varchar(128) 可空；`jobKey` varchar(768)；`type` varchar(32)；`status` varchar(32) 默认 `queued`；`isCurrent` bool 默认 true；`generationRevision` int；`executionAttempt` / `generationAttempt` int 默认 0；`configFingerprint` varchar(128)；`generatorVersion` varchar(120)；`billingPrincipalId` uuid 可空；`spendEnvelope` jsonb 可空（`maxModelInvocations` / `maxEstimatedTokens`）；`expectedChildren` / `succeededChildren` / `failedChildren` int 默认 0；`errorCode` varchar(120) 可空；`error` / `dispatchError` text 可空；`dispatchAttempts` int 默认 0；`dispatchAfter` / `lockedAt` / `leaseExpiresAt` / `heartbeatAt` / `completedAt` timestamptz 可空。
- 取值域：`type ∈ {classify, source_map, identity_resolve, page_reduce, retract, rebuild, finalize}`；`status ∈ {queued, running, succeeded, failed, stale, cancelled}`。
- 业务约束：jobKey 为幂等键（含 revision 与 fingerprint），子任务以 `父 jobKey + ':' + suffix` 派生。

章节来源：[knowledge-wiki-job.entity.ts](file://packages/server-ai/src/knowledgebase/wiki/entities/knowledge-wiki-job.entity.ts)（关键符号：KnowledgeWikiJob / 表名：knowledge_wiki_job）

### 2.2 knowledge_wiki_model_invocation
- 唯一约束：`requestId`、`(jobId, generationAttempt, stage, callOrdinal, inputFingerprint)`；索引：`(knowledgebaseId, status)`。
- 关系：`knowledgebase`、`job`（均非空 CASCADE）。
- 列：`requestId` varchar(1024)；`stage` varchar(32)（`map|dedup|reduce|classify|links`）；`callOrdinal` / `generationAttempt` int；`inputFingerprint` varchar(128)；`status` varchar(32) 默认 `prepared`（`prepared|running|reconciling|succeeded|failed|indeterminate`）；`reconciliationStatus` varchar(32) 默认 `not_available`（`not_available|pending|recovered|not_executed|indeterminate`）；`providerRequestId` varchar(120) 可空；`modelId` uuid、`modelName` varchar(200)、`billingPrincipalId` uuid；`tokenUsage` jsonb 可空；`structuredOutput` jsonb 可空；`billingStatus` varchar(32) 默认 `pending`（`pending|delivered|failed`）；`errorCode` varchar(120) 可空；`error` text 可空；`reconciliationDeadline` timestamptz 可空；`reconciliationAttempts` int 默认 0；`completedAt` timestamptz 可空。
- 业务约束：`(jobId, generationAttempt, stage, callOrdinal, inputFingerprint)` 唯一是「同输入不重复付费」的 DB 层保证。

## 3. 页面与版本表

### 3.1 knowledge_wiki_page
- 唯一约束：`(knowledgebaseId, pageKey)`、`(knowledgebaseId, identityId)`、`(knowledgebaseId, slug)`；索引：`(tenantId, organizationId, knowledgebaseId, status)`、`(knowledgebaseId, pageType, updatedAt)`。
- 关系：`knowledgebase`（CASCADE）；`identity` → `KnowledgeIdentity`（可空，`onDelete: 'NO ACTION'`）。
- 列：`pageKey` varchar(768)；`pageType` varchar(32)（`summary|entity|concept|index`）；`canonicalName` / `normalizedCanonicalName` varchar(512)；`identityId` uuid 可空；`slug` varchar(600)；`status` varchar(32) 默认 `building`（`building|ready|stale|failed|archived`）；`projectionStatus` varchar(32) 默认 `pending`（`pending|ready|failed|disabled`）；`activeVersionId` uuid 可空；`sourceCount` / `inboundLinkCount` / `outboundLinkCount` int 默认 0；`publishedAt` timestamptz 可空；`version` 为 `@VersionColumn` int 默认 1。
- 业务约束：`version` 是发布/搬迁的乐观锁；`identityId` 唯一约束意味着「一个身份在一个 KB 内只映射一页」。

- 关系：`knowledgebase`、`page`（均非空 CASCADE）。
- 列：`producerJobId` uuid；`generationAttempt` / `generationRevision` int；`generatorVersion` varchar(120)；`configFingerprint` varchar(128)；`expectedPageVersion` int；`title` varchar(512)；`summary` / `contentMarkdown` text；`aliases` jsonb 默认 `'[]'::jsonb`；`contentHash` varchar(128)；`status` varchar(32) 默认 `building`；`projectionStatus` varchar(32) 默认 `pending`；`projectionEmbeddingRevision` int 可空；`projectionEmbeddingFingerprint` varchar(128) 可空；`projectionError` text 可空；`publishedAt` timestamptz 可空。

## 8. 迁移与 seed
本子域**没有独立迁移文件**：`packages/server-ai/src/knowledgebase/migration/` 下只有 knowledge-filter-v2 相关实现，wiki 表不在其中；表的建立依赖部署期一次性的 schema 同步（`runSchemaSync` → `dataSource.synchronize()`，且显式设置 `synchronize: false` 后单独调用 `synchronize()`），由实体装饰器元数据驱动。**无 seed**：本子域没有数据种子文件；`_projection_state`、`_taxonomy`、`knowledge_wiki_page` 的索引页均在运行时按需创建。

章节来源：[schema-sync.ts](file://apps/api/src/schema-sync.ts)（关键符号：runSchemaSync）+ [entities/index.ts](file://packages/server-ai/src/knowledgebase/wiki/entities/index.ts)（关键符号：实体导出清单；无迁移与 seed 文件）

## 9. 校验规则
- 服务端独占列：客户端请求体出现 `wikiStatus` / `wikiAvailability` / `wikiRevision` / `wikiActiveRevision` / `wikiStagedRevision` / `wikiBuildError` / `wikiRebuildRequiredReason` / `wikiGeneratorVersion` / `wikiConfigFingerprint` / `canManageWiki` / `canManageDocumentDeletions` 任一即 400。
- 配置：`extractionGranularity ∈ {focused, standard, exhaustive}`；`contentGenerationRequirements` / `extractionFocus` 去空格后长度 ≤ 4000；仅 `Standard` 类型 KB 允许 wiki；启用时必须有可用模型（`copilotId` + `model`）。
- 组织：目录名 NFKC + trim 后非空、≤120、不含 `/`；描述 ≤1000；同父级重名（NFKC + 小写）拒绝；每 KB 目录 ≤200；禁止形成环（`validateWikiFolderMove`）；删除目录时无子目录且无 placement。
- 乐观锁：folder / placement / taxonomy 的 `version` 或 `revision` 不匹配返回冲突；`index` 页禁止搬迁。
- 查询与模型输出：页面搜索 ≤200 字符、`take ∈ [1,100]`；模型输出按 zod 边界（canonicalName ≤512、aliases ≤20、facts ≤100、单 fact 文本 ≤4000、原子块 ≤50、suggestedLinks ≤50、单次 map 页数 ≤200）。

## 10. 已知风险
- **表数量口径**：准确数是 **15 张**。若统计只剩 14，通常是漏掉组织文件中的 3 张之一，或把 `entities/index.ts` 的 12 个导出文件等同于表数；`knowledge-wiki.entities.spec.ts` 只断言 12 张表名（不含 taxonomy / folder / placement），容易误导统计。
- **`_page_reduce_input*` 与 `_page_contribution` 的分工**：前者是「本次调用的输入快照 + 幂等指纹」（可 stale、可被新尝试取代），后者是「已生成版本的来源台账」（供增量 reduce 复用、撤回定位、链接建议取 `payload.suggestedLinks`）；evidence 只在 `_page_evidence` 与 `_page_reduce_input_source.evidence` 中。混用会导致重复计费或证据丢失。
- **快照列语义**：`sourceDocumentIdSnapshot` / `sourceChunkIdSnapshot` 无外键，源文档删除后行仍存在；「来源是否仍可用」必须与 `_source_state` 的 `eligible` / `cleanupPending` 组合判断。
- **无 KB 级联的三张表**：`_page_reduce_input`、`_page_reduce_input_source`、`_source_map_result` 只有裸 `knowledgebaseId` 列，KB 硬删时缺少 DB 级联保护。
- **软删与 RESTRICT**：`identityId` 关系为 `NO ACTION`，folder 的父子与 placement 的 folder 关系为 `RESTRICT`，删除顺序错误会直接触发外键错误而非业务提示。
- **唯一约束硬冲突**：`_page` 上 `(knowledgebaseId, identityId)` 与 `(knowledgebaseId, slug)` 两个唯一索引使身份合并/改名必须走事务内冲突处理，写错会抛 23505。

章节来源：[knowledge-wiki.entities.spec.ts](file://packages/server-ai/src/knowledgebase/wiki/entities/knowledge-wiki.entities.spec.ts)（关键符号：KnowledgeWikiPageReduceInput / KnowledgeWikiPageContribution）+ [knowledge-wiki-page.entity.ts](file://packages/server-ai/src/knowledgebase/wiki/entities/knowledge-wiki-page.entity.ts)（关键符号：KnowledgeWikiPage 索引）

## 11. 结论
数据模型把「权威状态」与「可重算派生」分得很干净：权威状态（状态机、revision、指纹）落在 `knowledgebase` 表的 11 个 wiki 列上，15 张 wiki 表承载任务树、页面与版本、证据与台账、来源代际、投影指针与组织树。设计上依赖三类 DB 级保证：jobKey / fingerprint 唯一约束提供幂等、`version` / `revision` 提供乐观锁、CASCADE 与 RESTRICT 表达生命周期。主要风险集中在无外键的裸 `knowledgebaseId` 列、快照列语义容易误读，以及组织三表未被实体测试覆盖导致的口径混乱。
