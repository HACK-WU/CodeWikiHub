## 框架与运行方式

- 框架：Jest + ts-jest（`transform` 用 `tsconfig.spec.json`），`testEnvironment: 'node'`，preset 复用根 `jest.preset.js`。
- 关键映射：`moduleNameMapper` 把 `@xpert-ai/server-core`、`@xpert-ai/contracts`、`@xpert-ai/plugin-sdk`、`@xpert-ai/cli-model-profiles`、`@xpert-ai/shadcn-ui/brand-icons` 指向 workspace 源码而非构建产物，因此单测直接跑 TS 源。
- Nx 目标：`packages/server-ai/project.json` 的 `test` executor 为 `@nx/jest:jest`，`jestConfig: packages/server-ai/jest.config.ts`，产物输出到 `coverage/packages/server-ai`。
- 单文件运行（已实测命令形式）：

```bash
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --runTestsByPath packages/server-ai/src/knowledgebase/knowledgebase.controller.spec.ts
```

- `rag-web` 需要 ESM 旗帜（库依赖 Playwright 的动态 `import()`）：

```bash
node --experimental-vm-modules 'node_modules/.bin/jest' \
  'packages/server-ai/src/rag-web/provider/playwright/playwright.test.ts' \
  -c 'packages/server-ai/jest.config.ts' --detectOpenHandles
```

章节来源：[jest.config.ts](file://packages/server-ai/jest.config.ts)（关键符号：moduleNameMapper、transformIgnorePatterns）、[project.json](file://packages/server-ai/project.json)（关键符号：targets.test）、[rag-web/README.md](file://packages/server-ai/src/rag-web/README.md)（关键符号：experimental-vm-modules）

## 断言与 mock 风格

- **服务层用 CQRS 查询对象做断言**：`knowledgebase.service.spec.ts` 导入 `CopilotModelGetEmbeddingsQuery`、`CopilotModelGetRerankQuery`，通过 `queryBus.execute.mock.calls` 过滤 `instanceof` 断言模型解析调用次数与 `options`；对卷客户端用 `jest.spyOn(VolumeSubtreeClient.prototype, 'readFile')` 分别 mock 成功与 `ForbiddenException`。
- **控制器层用普通对象 stub + 直接 new**：`knowledgebase.controller.spec.ts` 手工构造 `KnowledgebaseController`，只注入 `getSafeReadRelations`/`findAll` 等少量方法，断言 `findAll` 收到的 `where` 是「客户端 OR 分支 × (我的 | 组织共享)」展开后的 4 条条件，并直接断言 `permission.value === [Organization, Public]`；`jest.spyOn(RequestContext, 'currentUserId')` 注入身份。
- **流水线主测**：`document.job.spec.ts` 与 `commands/handlers/load.handler.spec.ts` 是摄取链路（解析→切片→embedding）的两块主测，配套 `document.controller.spec.ts`（HTTP 层）与 `document.service.spec.ts`（服务层）。
- **integration 风格**：自建 Postgres 连接与 `pg_temp` 表 + 原生 SQL 断言，连接参数来自 `process.env.DB_HOST ?? '127.0.0.1'`、`DB_PORT ?? 5432`、`DB_USER ?? 'postgres'`、`DB_PASS ?? 'ocap_password'`、`DB_NAME ?? 'ocap'`（如 `knowledge-wiki-document-status.integration.spec.ts`）。
- **解析/向量化在单测中的 mock 深度未逐文件核对 → 未确认。**

## integration 默认 skip 与 env 开关

开关形式统一为「env 存在/等于 `1` 时 `describe`，否则 `describe.skip`」，因此**默认全 skip**。

| 环境变量 | 判定形式 | 解锁的测试 |
|---|---|---|
| `KNOWLEDGE_WIKI_PG_E2E=1` | `=== '1'` | wiki 7 个（document-status、organization 之外的 6 个 + …）+ `knowledge-document/document-list.integration.spec.ts`、`document-publication.integration.spec.ts` + `rag-vstore/knowledge-pg-vector.store.integration.spec.ts` |
| `KNOWLEDGE_IDENTITY_PG_E2E=1` | `=== '1'` | `knowledgebase/identity/knowledge-identity-postgres.integration.spec.ts` |
| `KNOWLEDGE_GRAPH_PG_E2E=1` | `=== '1'` | `graphrag/retry-postgres.integration.spec.ts`、`graphrag/graph-contribution-postgres.integration.spec.ts` |
| `KNOWLEDGE_KEYWORD_PG_E2E=1` | `=== '1'` / 布尔常量 | `knowledgebase/analyzer/keyword-analyzer.integration.spec.ts`、`knowledgebase/retrieval/keyword-knowledge-candidate.retriever.integration.spec.ts` |
| `KNOWLEDGE_TAGGING_PG_URL` | 真值 | `knowledgebase/tags/knowledge-tag.integration.spec.ts`（同时作为 fixture 连接串） |
| `WIKI_V15_PG_URL` | 真值 | `knowledgebase/wiki/knowledge-wiki-organization.integration.spec.ts` |
| `BOM_GRAPH_PG=1` | `=== '1'` | `graphrag/bounded-graph-reader.spec.ts`（`.spec.ts` 但仍是 PG 门控） |
| `XPERT_JIEBA_PLUGIN_PATH` | 可选 | `keyword-analyzer.integration.spec.ts` 的分词插件路径 |
| `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PASS` / `DB_NAME` | 带默认值 | 上述 PG 套件的连接参数（默认 `127.0.0.1:5432 / postgres / ocap_password / ocap`） |

## 可执行性结论

- **✅ 可跑**：配置齐备（`jest.config.ts` + ts-jest + 源码 moduleNameMapper），单文件与整包命令均可构造；`rag-web` 需 `--experimental-vm-modules`。
- **约 17 个域内套件（仓库级约 30 个）默认 skip**，需显式注入 env 才能覆盖 DB 行为。
- **已知失败：未执行 jest，未确认。** 静态扫描未发现必然失败的用例，但缺乏执行证据。
- 建议的最小回归集：`knowledgebase.controller.spec.ts` + `knowledge-document/document.job.spec.ts` + `knowledge-document/commands/handlers/load.handler.spec.ts` + `graphrag/graphrag.service.spec.ts`（全为纯单测，无需 DB）。
