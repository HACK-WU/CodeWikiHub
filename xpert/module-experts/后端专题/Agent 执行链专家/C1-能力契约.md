# C1 · 能力契约（Agent 执行链专家）

> 契约层 CR2 / CR5 / CR7。本文只写「对外可依赖的语义」：入口、参数行为、返回、异常与约束。
> 路径均以仓库根为基准的相对 `file://` 引用；不含实现算法、私有方法与方法体内细节。
> 逐端点明细见各子专家 `implementation/05-接口.md` 与父 `implementation/05-接口.md`（本文不复制表格）。

## §1 HTTP / WS 接口契约（域级入口索引）

### 1.1 路由前缀与真实路径

全局前缀 `api` 由引导层设置（`app.setGlobalPrefix('api')`），本域不做例外。

| 入口组 | 真实前缀与端点 | 鉴权形态 | 逻辑归属 |
|---|---|---|---|
| Agent 定义与直连对话 | `/api/xpert-agent`：`chat`（SSE）、`xpert/:id/test/:key`、`middlewares`、`middlewares/:provider/tools`、`middlewares/:provider/tools/:toolName/test` + 继承 CRUD | 全局 `AuthGuard`（controller 无 `@UseGuards`） | 本域（子专家 ①） |
| Invocation 读取与控制 | `/api/agent-invocations`：`GET :id`、`POST :id/cancel`、`POST :id/respond` | 全局 `AuthGuard` + 显式 `findOwned()` 四元组 | 本域（子专家 ②） |
| 投递读据与重排 | `/api/agent-invocations/:id/delivery`、`POST .../delivery/redrive` | 全局 `AuthGuard` + 收据属主 / 回复目标校验 | **逻辑属「对话与会话专家」**（文件在 `handoff/`，controller 注册在本域模块） |
| 运行时绑定 | `/api/agent-runtime-bindings`：`GET`、`POST`、`PUT :id` | 显式 `requireResourceAdmin()`（org scope） | 本域（子专家 ②） |
| 执行账本只读面 | `/api/xpert-agent-execution`：`GET :id/log`、`GET :id/state`、`GET :id/checkpoints`、`GET xpert/:id/agent/:key` | 显式执行访问断言 + 组织范围包装 | 本域（子专家 ②） |
| Prompt 工作流 | `/api/prompt-workflow/*`（7 端点） | `@UseGuards(WorkspaceAuthoringGuard)`（全端点） | 本域（子专家 ③） |
| 协作文档 | WS namespace `/api/collaboration`（无 HTTP controller） | 不透明 `sessionId` + `clientKey`（非 Nest Guard） | 本域（子专家 ③） |

**路径校正（易错）**：`/api/xpert/chat` **不存在**。真实入口是 `/api/xpert-agent/chat`（**无 id**，Agent 直连调试，本域）与 `/api/xpert/:id/chat`（**带 id**，注册在 `/api/xpert` 定义面，非本域 Agent 直连入口）。中间件工具面同理只在 `/api/xpert-agent/middlewares*` 下。

**跨域注册提示**：`delivery` / `redrive` 的 HTTP 逻辑不在本域（本域无该项逻辑归属）；本域只保证相邻的 CAS 与账本不变量，改动需两侧确认。

### 1.2 `POST /api/xpert-agent/chat`（Agent 对话入口，SSE）

- 请求体：Agent 对话请求（可选 `environmentId`，命中则先解析环境后注入调用上下文）；`action === 'resume'` 时另带目标执行与 `decision`（可选 `patch`）。
- 响应：`text/event-stream` + `Connection: keep-alive`；服务端每 30s 发一条注释心跳；客户端断开即终止上游订阅。
- 注意：Swagger 的 `@ApiBearerAuth()` 只是注解，**不是**运行时守卫。
- 参数行为语义与 `resume` 的 `decision` / `patch` 含义见 §2 的 `XpertAgentService.chatAgent`。

### 1.3 `/api/agent-invocations/*`（调用控制面）

| 端点 | 语义 | 关键约束 |
|---|---|---|
| `GET :id` | owner-scoped 观察读取（只读，不改记录） | 先过四元组校验；native 目标走只读 inspect 分支；读取本身可能触达一次状态收敛（见 §2 的 `inspect`） |
| `POST :id/cancel` | 请求取消一次调用 | **native 目标一律 `Unsupported`（422）**；需策略声明取消能力，否则 `Unsupported` |
| `POST :id/respond` | 回填人工交互 `{interactionId, response}`（严格校验，多字段即 400） | **native 目标一律 `Unsupported`（422）**；状态非 `waiting` 或交互 id 不匹配即 `InteractionConflict`（409） |

native 图/任务的取消与审批保留各自既有路由，不经这两个端点（避免绕开图/任务自身授权链）。

### 1.4 WS `/api/collaboration`（消息与鉴权）

| 方向 | 名称 | 要点 |
|---|---|---|
| 连接 | 握手 | 从 `handshake.auth`（回退 query）取 `sessionId`/`clientKey`/`documentId`；失败 emit `error` 后 `disconnect(true)` |
| 连接成功（出） | `sync`、`presence-snapshot` | 加入 `collaboration:<documentId>` 单房间后下发初始快照 |
| 入 | `update` | 提交 CRDT 更新；**先落库再** `update-ack` |
| 入 | `sync-request` | 带 state vector 取增量，回 `sync` |
| 入 | `presence` | 白名单投影后刷新在线状态；异常 emit `error` |
| 出 | `update` / `presence` / `presence-remove` | 只扇出到该文档房间（本地先发、Redis 跨节点） |

鉴权靠不透明凭据（只存哈希、有 TTL），`cors.origin='*'`；无 Nest Guard。服务端错误统一走 `error`，不映射 HTTP 状态，也不触发 `update-ack`。

### 1.5 索引指针

- 逐端点明细（方法/路径/鉴权/参数/错误码）：父 `implementation/05-接口.md`；Agent 面、Invocation 面、中间件/Prompt/协作面分别见三个子专家的 `implementation/05-接口.md`。

## §2 服务能力契约（主体）

### 2.1 `XpertAgentService.chatAgent(request, options)`

- **用途**：以草稿态团队发起一次 Agent 直连对话，返回事件流（SSE 上游）。
- **参数（行为语义）**：
  - `request`：团队标识、入口 agentKey、初始状态（缺省时注入人类输入变量）；`action === 'resume'` 时读 `target.executionId` 与 `decision`（可选 `patch`，含 `toolCalls` / `update` / `agentKey` 三类补丁）。
  - `options`：语言、时区、可选环境；本入口固定以「草稿、无长期记忆、来源=调试器」的隐式上下文执行。
- **返回**：`Observable<MessageEvent>`（事件统一包装为 `{ data: { type, event, data } }`）。
- **异常**：团队/节点不存在即 `NotFound`；`resume` 缺目标字段会在运行期取属性时抛错（无前置校验）。
- **约束**：这是**调试入口**，与发布执行共用一条命令但上下文不同；`resume` 只恢复被中断的图，不重新派发新工作。

### 2.2 `CompileGraphCommand` / `XpertAgentGraphValidator` / `XpertAgentNodeValidator`

- **用途**：把「Agent 定义 + 图」编译为可执行图；校验草稿图与节点选项。
- **参数（行为语义）**：编译命令携带入口 agentKey、团队快照与选项（含 leader、根执行、线程、根取消信号、草稿标记）；校验以「草稿校验事件」的订阅者身份被触发。
- **返回**：编译返回 `{ graph, agent, xpertGraph }`（可执行图）；校验返回校验项列表（规则码 + 字段 + 级别）。
- **异常**：入口 agent 缺失即 `NotFound`。
- **约束**：**校验与编译不串联**——「编译前必须过校验」不成立；伙伴数 > 1 走 swarm，否则走 subgraph；native 编译的**文件物理位置**在 `agent-invocation/` 但语义属本能力（子专家 ①）。

### 2.3 `XpertAgentExecutionService`

| 方法 | 语义 | 返回 | 约束 |
|---|---|---|---|
| `create(entity)` | 新建一次执行记录 | 实体（含 id） | 忽略调用方传入的审计时间戳；`completedAt` 初值由状态决定 |
| `update(id, entity)` | 终局化/续写执行记录 | 更新后的实体 | 事务内行锁重读后合并；重复终局化保留已记录的结束时间；状态回到运行态即清空结束时间 |
| `recordUsage(id, usage)` | 累加用量与定价 | void | 事务内累加；仅非「估算」类型且带明细时写定价列 |
| `interruptRunning(ids, threadId, error)` | 批量中断仍在运行的执行 | 受影响行数 | 只命中「运行态且线程匹配」的行，不误伤已终态行；调用方须已完成租户范围鉴权 |
| `findAllByParentId(id, options?)` | 列出子执行 | 分页结果 | 只读 |

- **用途**：执行与用量账本的**唯一写入面**；HTTP 只暴露只读面。
- **约束（明写）**：终局化不得重放初始行（会覆盖较新的时间戳与用量计数）；`updatedAt` 不能替代结束时间；历史停止态记录的结束时间不可由元数据写入建立。

### 2.4 `AgentInvocationRuntime.scoped(scope)` → `{ start, inspect, cancel, respond }`

- **用途**：一次调用的唯一状态转移入口（授权、幂等、pin、CAS）。
- **参数（行为语义）**：
  - `scope` 身份面：租户 / 组织 / 用户 / 工作区（+ 可选项目）+ **父执行 ID** + 调用方 Agent 身份（callerAgentKey / callerXpertId）。`scoped()` 强校验其中「租户、组织、用户、父执行、调用方 Agent」五项，缺项即 `InvalidScope`（403）。HTTP 侧另以 `{id, ownerId, tenantId, organizationId}` **四元组**收口。
  - `capabilities`：本调用可见的能力表；`authorize`：目标授权回调；`signal`：取消信号；`isSuspension`：判定「挂起」而非「失败」。
  - `start(request)`：`target`（provider/reference/revision/configuration 组成的 pin 目标）、`callId`（≤1024 的幂等键）、`input`、可选异步回复与项目关联。
- **返回**：`AgentInvocation` 快照，`status ∈ { queued, running, waiting, cancelling, succeeded, failed, cancelled, unknown }`（**仅 `succeeded|failed|cancelled` 为终态**）；启动返回时可能仍是运行中，也可能带启动围栏（`startPendingUntil`）。
- **异常**：`InvalidScope`(403)、`CallConflict`(409，同一幂等键但请求/目标不一致)、`ProviderChanged`(409，pin 失效)、`ProviderUnavailable`(503)、`DispatchUnknown`(409，含糊启动)、`Unsupported`(422，缺取消/交互能力)、`ConcurrentUpdate`(409，CAS 重试超限)。
- **约束（行为语义）**：
  - `inspect` 是**只读观察**，绝不重启；但当启动围栏已过期且无启动回执时，读取本身会触达一次「收敛为 `unknown`」的状态转移——**读操作不是绝对无副作用**。
  - `cancel` 是**请求**：先落「取消中」再交由策略；终态记录直接返回；取消不构成终止证明，也不取消 Project Task。
  - `respond` 只在 `waiting` 且交互 id 匹配时成功，否则 `InteractionConflict`。
  - 重复调用同一 `callId` 会挂回原记录；已终态直接返回，非终态只在「仍排队」或「等待且策略声明按检查点恢复」时续跑。

### 2.5 `AgentInvocationFactoryService`

| 成员 | 用途 | 约束 |
|---|---|---|
| `createScopedApi(identity)` / `api()` | 按调用方身份取得 scoped API（`{start, inspect, cancel, respond}` + `capabilities`） | 每次都新建，不缓存首个调用方身份 |
| `createCapturedApi(scope)` | 用持久化身份重建 API（宿主重放） | 不采信下一个图轮次的环境 scope |
| `existingApi(id)` | 幂等复用原调用的 scoped API | 仅项目作用域且非 captured 时按记录还原其**原始** scope（跨轮次但不跨 actor/会话/工作区/助手） |
| `resolve(bindingId)` | 把绑定解析为 pin 目标 | 校验工作区归属与启用状态；不符即 `NotFound` |
| `claimResults(callId, tasks)` | 认领已终局任务的执行结果 | 只对带异步派发意图且 `succeeded/failed/cancelled` 的任务执行；缺命令通道即 `Unsupported` |
| `awaitResult(id, options?)` | 单任务有界等待 | 等待窗口耗尽返回 `pending` 快照语义；返回前认领结果 |
| `waitForTasks(request, options?)` | 多任务有界等待（`task_status` 工具底座） | 观察窗口 = `min(请求超时 ?? 内联等待, 内联等待上限)`（默认 2s / 上限 60s，可按环境变量调整）；窗口耗尽正常返回 `pending`，**不挂起父级、不暗示完成**；返回前按调用方作用域认领结果 |
| `getResourceCard(id)` | 资源卡投影 | 缺失依赖时返回 `null`；资源卡本身不授访问权 |
| `resolveBackgroundTarget` / `resolveGroupTarget` / `listProjectBindings` | 后台/群组/项目可选目标解析 | 统一过「后台目标断言」；项目助手 + 计算机环境缺模型来源即报错 |

### 2.6 `AgentInvocationMonitorService`（`process` / `deliver` / `claim` / `reconcile` / `withAccess`）

- **用途**：恢复与投递的后台通道（对账、租约领取、续跑派发）。
- **参数/返回**：均为内部驱动面（无 HTTP）；`reconcile()` 无参、返回空；`claim(状态, 处理器)` 抢占租约，成功返回处理权，被占返回空；`withAccess(请求, 处理器)` 在恢复原始 actor/租户/组织并复核成员资格后执行，失败即不执行。
- **约束**：扫描节拍固定（约 5s，单轮限量），`busy`/`stopping` 门闩只防本进程重入；**polling 是唯一持久恢复机制**，本地事件只提前唤醒；续跑前会重校验每个依赖的访问权，父执行仍在运行则整体推后；「先到的完成事件不得重放后来的人工审批」。

### 2.7 `AgentMiddlewareRuntimeService`

| 方法 | 用途 | 参数语义 / 返回 | 约束 |
|---|---|---|---|
| `createScopedApi(scope?)` | 组装该调用的受控能力视图 | 返回 `{ createModelClient, getModelProvider?, wrapWorkflowNodeExecution, emitMiddlewareEvent?, capabilities? }`；作用域含租户/组织/用户/工作区/项目/助手 | 每次都新建；仅当有绑定工作区作用域时额外注册工作区文件等能力；**缺能力即显式失败** |
| `createModelClient(copilotModel, options, scope?)` | 取得模型客户端 | 返回模型客户端；`purpose: 'observe'` 不记配额 | 与 `expectedExecutionModel` 不符即拒绝执行；超额中断当前请求 |
| `getModelProvider(provider, scope?)` | 解析模型 provider 连接 | 必须同时具备 provider 与租户，否则报错；无候选即「未配置」 | 模型/凭据的创建属「模型访问与计费专家」 |
| `emitMiddlewareEvent(event)` | 统一中间件事件出口 | 统一事件类型与时间字段后经聊天事件送出 | 事件体不得携带跨租户上下文 |
| `wrapWorkflowNodeExecution(run, params)` | 把工作流节点执行包上执行账本语义 | 返回内部状态；输出用于落库与事件 | 与 `XpertAgentExecutionService` 的规则一致（中断归 `interrupted`） |

- **边界（明写）**：不得把全局 capability registry 或执行 runner 工厂交给插件；草稿态上下文与发布态上下文分离，草稿态先做创作权限断言。

### 2.8 `PromptWorkflowService`

- **作者态方法**：`createInWorkspace` / `updateInWorkspace` / `upsertInWorkspaceByKey` / `archiveInWorkspace(ByKey)` / `duplicateInWorkspace` / `initializeDefaultsInWorkspace` / `getUsage`。
  - 约束：`(workspaceId, name)` 唯一（同名并发撞约束）；id 与 workspace 必须一致否则 `NotFound`；复制名自动派生、耗尽即 400；默认初始化在事务内加锁补插、返回 `{created, skipped}`。
- **运行时方法**：`validateCommandProfile` / `snapshotCommandProfile` / `resolveRuntimeCommandProfile`（+ 能力作用域解析与批量/键解析）。
  - 参数语义：命令档案中的工作空间命令条目必须带有效工作空间并以存在的工作流为目标，否则 400；`snapshotCommandProfile` 在发布时把「引用」固化为「可离线回放的快照」；运行时取值优先快照、否则取当前配置。
  - 约束：已禁用/已归档条目在运行时被排除；「空关联」被定义为全局可见（清空即放大可见范围）。
- **CQRS 解析面**：`ResolvePromptWorkflowInvocationQuery` 返回展开后的对话输入或 `null`（已展开的文本命令不二次覆盖）；无解析结果时原样返回输入。

### 2.9 `CollaborationService.createScopedApi(defaults)` → `CollaborationApi`

- **用途**：宿主把 CRDT 文档读写、会话与在线状态以绑定身份的 API 暴露给插件。
- **参数语义**：`defaults` 固定租户/组织/用户与「虚拟协作者」身份（会话/助手/执行维度），缺省回落请求上下文。
- **方法面（10 个）**：文档确保/读取/取状态、提交更新、创建会话、列出与写入/移除在线状态、归档、删除。
- **异常（HTTP 侧同源）**：文档不存在 404；只读会话提交更新 403；序列冲突/超限 400；provider 授权拒绝 403。
- **约束**：服务实例本身也实现该 API（无参版本）；权威 CRDT 状态留在平台；物化失败只降级为「失败 + 重试」，**绝不回滚已提交的更新**；更新历史有保留窗口，早于窗口的重放不再命中判重。

### 2.10 `ExecutionCancelService.cancelExecutions(executionIds, reason?)`

- **用途**：请求停止一次或多次执行（协作式）。
- **参数语义**：id 去重；`reason` 进入取消错误的语义（默认「用户取消」）。
- **返回**：`void`。
- **异常**：不抛——广播失败与订阅失败**只告警**。
- **约束**：先广播 `ai:execution:cancel`、再对本地登记的信号发起中止；**本副本照常停，其他副本可能静默丢取消**；不强杀 CPU-bound；与队列/进程取消是**两条独立链路，互不替代**；取消不构成终止证明。

## §3 代码示例（真实调用方）

### ① 触发一次 Agent 对话（含 SSE / 流式要点）

```ts
// 真实调用方：packages/server-ai/src/xpert-agent/xpert-agent.controller.ts
@Header('content-type', 'text/event-stream')
@Header('Connection', 'keep-alive')
@Post('chat')
@Sse()
async chatAgent(@Res() res: Response, @Body() body: TXpertAgentChatRequest, @I18nLang() language, @TimeZone() timeZone) {
    let environment = null
    if (body.environmentId) {
        environment = await this.environmentService.findOne(body.environmentId)
    }
    const observable = await this.service.chatAgent(body, { language, timeZone, environment })
    return observable.pipe(
        // 每 30s 发一条注释事件，防中间代理掐断长连接
        keepAlive(30000),
        takeUntilClose(res)
    )
}
```

要点：SSE 头 + 心跳；客户端断开即终止上游订阅；`@ApiBearerAuth()` 只是 OpenAPI 注解，真正的守卫是全局 `AuthGuard`（controller 上没有 `@UseGuards`）。

### ② 起一次调用并有界等待结果

```ts
// 真实调用方：packages/server-ai/src/agent-invocation/native-graph-adapter.ts
```

```ts
// 真实调用方：packages/server-ai/src/agent-invocation/invocation-factory.service.ts
// 有界等待 + 结果认领（等待窗口耗尽返回 pending，不挂父级）
awaitResult: async (id, options) => {
    const result = await awaitInvocationTasks(
        controls,
        { callId: id, taskIds: [id], mode: 'all', timeoutMs: options?.timeoutMs },
        options?.signal
    )
    await claimResults(id, result.tasks)
    return result.tasks[0]
},
waitForTasks: async (request, options) => {
    const result = await awaitInvocationTasks(controls, request, options?.signal)
    await claimResults(request.callId, result.tasks)
    return result
}
```

要点：`scope` 必须由已经过鉴权的上下文构造；`callId` 复用即幂等命中/冲突；等待结果与认领结果都按调用方作用域收口，超窗正常返回 `pending`。

### ③ 取消一次执行（协作式语义与终态归一）

```ts
// 真实调用方：packages/server-ai/src/chat-conversation/commands/handlers/cancel-external-assistant.handler.ts
const ids = descendants.filter((item) => item.status === Status.RUNNING).map((item) => item.id)
const reason = t('server-ai:Error.ExternalAssistantCancelledByUser', {
    defaultValue: 'This external assistant execution was cancelled by the user. Do not retry without a new user request.'
})
await this.cancellations.cancelExecutions(ids, reason)
// 不覆盖已与取消请求竞态获胜的完成态
await this.executions.interruptRunning(ids, execution.threadId, reason)
```

要点：取消只是请求；只有「运行态且线程匹配」的行会被归一为中断并写入结束时间；已终态行不会被误伤，`unknown` 必须保持可见。
