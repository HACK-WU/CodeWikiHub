## §1 HTTP 入口

### 1.1 前缀来源

全局前缀 `api` 由引导层设置；`/api/xpert-agent` 由 `file://packages/server-ai/src/xpert-agent/xpert-agent.module.ts` 的 `RouterModule.register([{ path: '/xpert-agent', module: XpertAgentModule }])` 提供，controller 自身是空 `@Controller()`。

### 1.2 端点

| 端点 | 形态 | 语义 | 约束 |
|---|---|---|---|
| `chat` | `POST` + `@Sse()`，`@Header('content-type','text/event-stream')`、`@Header('Connection','keep-alive')` | 草稿态 Agent 直连对话 | `keepAlive(30000)` 注释心跳；`takeUntilClose(res)`：客户端断开即终止上游订阅；`body.environmentId` 命中则先 `environmentService.findOne` 再注入调用上下文 |
| `xpert/:id/test/:key` | `POST` | 单节点调试 | 执行 `WorkflowTestNodeCommand(id, key, body.state)`；任意错误 → `HttpException(getErrorMessage(err), 500)` |
| `middlewares` | `GET` | 列草稿可用中间件策略 | 无参数；不包装错误 |
| `middlewares/:provider/tools` | `POST`，体 `{ xpertId?, options? }` | 列该 provider 的工具 | 错误 → `BadRequestException`（400） |
| `middlewares/:provider/tools/:toolName/test` | `POST`，体 `{ xpertId?, options?, parameters? }` | 试跑单个工具 | 错误 → `BadRequestException`（400） |
| 继承 CRUD 面 | `CrudController<XpertAgent>` | `xpert_agent` 读写，含 `count`/`pagination`/`my`/`:id` | 权限口径沿用全局 `AuthGuard`；`@ApiBearerAuth()` 只是 OpenAPI 注解 |

- 鉴权：controller 上**无 `@UseGuards`**，`file://packages/server-ai/src/xpert-agent/xpert-agent.controller.ts` 依赖全局 `AuthGuard`。
- 路径校正：`/api/xpert/chat` 不存在；带 id 的 `/api/xpert/:id/chat` 属定义面调试入口，非本子专家。
- 不在本子专家：`/api/agent-invocations/*`、`/api/agent-runtime-bindings/*`、`/api/xpert-agent-execution/*`（子专家 ②）；`/api/prompt-workflow/*`、WS `/api/collaboration`（子专家 ③）。

## §2 服务契约（主体）

### 2.1 `XpertAgentService.chatAgent(params, options)`

- **用途**：以草稿态团队发起一次 Agent 直连对话，返回事件流（SSE 上游）。
- **入参（行为语义）**：`params` 为 `TXpertAgentChatRequest`——`xpertId`、`agentKey`、可选 `state`（缺省注入 `{ [STATE_VARIABLE_HUMAN]: {} }`）、可选 `environmentId`；`action === 'resume'` 时读 `target.executionId` 与 `decision`（可选 `patch`）。`options` 为 `TChatOptions`（语言、时区、环境）。
- **内部行为（已核实）**：`FindXpertQuery({ id: xpertId }, { relations: ['agent'], isDraft: true })` → `XpertAgentChatCommand`，选项固定 `isDraft: true`、`store: null`、`from: 'debugger'`；`resume` 时传 `execution: { id: request.target.executionId, category: 'agent' }` 与 `resume: { decision, ...(patch ? { patch } : {}) }`。
- **返回**：`Observable<MessageEvent>`。
- **约束**：这是**调试入口**，与发布执行共用一条命令但上下文不同；`resume` 只恢复被中断的图，不重新派发新工作；`resume` 缺目标字段无前置校验。

### 2.2 `XpertAgentService` 定义面与中间件方法（全部已核实）

| 成员 | 可见性 | 语义 |
|---|---|---|
| `update(id, entity)` | public | 覆写 CRUD 更新（`assign + repository.save`） |
| `getMiddlewareStrategies()` | public | 草稿可用中间件策略列表，配合 `resolveMiddlewareSource(strategy)` 还原展示元数据 |
| `getMiddlewareTools(provider, body)` | public | 取 `getDraftXpertMiddlewareContext(body?.xpertId)` + `createDraftXpertMiddlewareRuntime(...)`，用 `createMiddlewareNode(provider, options)` 造 `WorkflowNodeTypeEnum.MIDDLEWARE` 节点，`normalizeSchema(...)` 归一 zod → JSON Schema |
| `testMiddlewareTool(provider, toolName, body)` | public | 同上装配后单工具试跑 |
| `getDraftXpertMiddlewareContext(xpertId?)` | private | 先 `assertCanAuthorById(xpertId)`，再 `FindXpertQuery({ id }, { isDraft: true })`；返回 `{ xpertId, xpertFeatures, workspaceId, workspaceDataScope }` |
| `createDraftXpertMiddlewareRuntime(draftContext)` | private | 以草稿上下文构造仅面向作者的 scoped runtime |
| `createMiddlewareNode` / `normalizeSchema` / `resolveMiddlewareSource` | private | 节点构造 / schema 归一 / 来源解析 |

### 2.3 图命令：`CompileGraphCommand` / `XpertAgentSwarmCommand` / `XpertAgentSubgraphCommand`

- **`CompileGraphCommand`**：`Command<{ graph: CompiledStateGraph<any, any, any>; agent: IXpertAgent; xpertGraph: TXpertGraph }>`。
- **分派（已核实）**：`CompileGraphHandler.execute` 调 `GetXpertWorkflowQuery` 取 `{ agent, graph: xpertGraph }`，再 `getSwarmPartners(xpertGraph, agent.key, partners)`；`partners.length > 1` → `XpertAgentSwarmCommand`，否则 → `XpertAgentSubgraphCommand`（携 `isStart: true`、`channel: channelName(agent.key)`、`partners: []`）。
- **`XpertAgentSwarmHandler`**：为每个 partner 用 `@langchain/langgraph-swarm` 的 `createHandoffTool` 生成 handoff 工具并 `createSwarm(...)`。
- **`XpertAgentSubgraphHandler`**：legacy 单 agent 子图。
- **约束**：分派条件是**伙伴数**，不是「是否配了 leader」；`getSwarmPartners` 的收集口径决定形态，改判定要先改收集。`getSwarmPartners` 实现来自 `@xpert-ai/contracts`，`file://packages/server-ai/src/xpert-agent/agent.ts` 亦对外暴露同名符号。

### 2.4 草稿校验：`XpertAgentGraphValidator` / `XpertAgentNodeValidator`

- **触发方式（已核实）**：两者与 `plugins/`、`workflow/` 下各 validator 一样，用 `@OnEvent(EventNameXpertValidate)` 订阅草稿校验事件；**不被 `CompileGraphHandler` 调用**。
- **返回**：校验项列表（`ruleCode` + 字段 + `level`）。
- **规则码（已核实）**：`AGENT_SUBGRAPH_BUILD_CYCLE`（`graph-validator.ts` 顶部导出常量）；`AGENT_STRUCTURED_OUTPUT_FILE_UNDERSTANDING_CONFLICT`、`AGENT_FILE_UNDERSTANDING_EMBEDDING_UNAVAILABLE`（`agent-validator.ts`，`level: 'warning'`）。
- **约束**：校验与编译**不串联**，「编译前必须过校验」不成立；校验侧不写业务表。

### 2.5 native 编译三件套（文件在 `agent-invocation/`，语义属本子专家）

| 符号 | 文件 | 契约要点 |
|---|---|---|
| `NativeAgentCompiler` | `file://packages/server-ai/src/agent-invocation/native-agent.compiler.ts` | `compile` 派发 `XpertAgentSubgraphCommand`，复用 `agent.ts` 的 `messageEvent` 与 `TAgentSubgraphParams` |
| `AgentInvocationGraphService` | `file://packages/server-ai/src/agent-invocation/agent-invocation-graph.service.ts` | `compileExperts` / `compileLocal` 复用 `collaborators.middleware.ts` 的 `collaboratorToolDeclaration`；`wrap` 生成 `bindingId = xpert:${target.id}:${entry}`、`provider = 'xpert'`、`revision = sha256({ publishAt, graph, (draft), entry })`；`revision` 仅在 `isDraft` 时纳入 `target.draft` |
| `wrapNativeAgentInvocation` | `file://packages/server-ai/src/agent-invocation/native-graph-adapter.ts` | 以 `${bindingId}:${callId}` 作幂等 `callId`，把 `nativeInputDigest`（sha256）写进 `parameters`，保证同一 `callId` 不可复用于不同输入 |

- **约束**：这三者由 `XpertAgentModule.providers` 注册；调用侧 `runtime.scoped({...})` → `api.start({ target, callId, input })`，运行时账本语义属子专家 ②。

## §3 示例（真实调用方）

### ① 编译一个多智能体图

```ts
// 真实调用方：file://packages/server-ai/src/xpert-agent/commands/handlers/compile-graph.handler.ts
const { agent, graph: xpertGraph } = await this.queryBus.execute(new GetXpertWorkflowQuery(xpert.id, agentKeyOrName, options?.isDraft))
const partners = []
getSwarmPartners(xpertGraph, agent.key, partners)      // 来自 @xpert-ai/contracts
if (partners.length > 1) {
  swarmOrGraph = await this.commandBus.execute(new XpertAgentSwarmCommand(agentKeyOrName, xpert, { ...options, rootController, signal: rootController.signal, partners }))
} else {
  swarmOrGraph = await this.commandBus.execute(new XpertAgentSubgraphCommand(agentKeyOrName, xpert, { ...options, isStart: true, channel: channelName(agent.key), partners: [] }))
}
```

要点：伙伴数决定编排形态；swarm 用 `@langchain/langgraph-swarm` 的 `createHandoffTool`；**校验不在这条链上**。

### ② 用 `chatAgent` 触发一次草稿态对话（SSE）

```ts
// 真实调用方：file://packages/server-ai/src/xpert-agent/xpert-agent.controller.ts
@Header('content-type', 'text/event-stream')
@Header('Connection', 'keep-alive')
@Post('chat') @Sse()
async chatAgent(@Res() res: Response, @Body() body: TXpertAgentChatRequest, @I18nLang() language, @TimeZone() timeZone) {
    let environment = null
    if (body.environmentId) environment = await this.environmentService.findOne(body.environmentId)
    const observable = await this.service.chatAgent(body, { language, timeZone, environment })
    return observable.pipe(keepAlive(30000), takeUntilClose(res))
}
```

要点：`@ApiBearerAuth()` 只是注解；真正守卫是全局 `AuthGuard`（controller 无 `@UseGuards`）。

### ③ HITL 恢复：`decision` 的归一与拒绝条件

```ts
// 真实调用方：file://packages/server-ai/src/xpert-agent/commands/handlers/invoke.handler.ts
if (shouldRejectResumeWithGraph(options.resume)) { /* 拒绝带图恢复 */ }
```

```ts
// 归一入口：file://packages/server-ai/src/xpert-agent/xpert-agent.service.ts
resume: request.action === 'resume' ? { decision: request.decision, ...(request.patch ? { patch: request.patch } : {}) } : undefined,
from: 'debugger'
```

要点：`shouldRejectResumeWithGraph` 在 `invoke.handler.ts` 与 `chat/commands/handlers/chat-common-input.ts` 各有一处实现/使用；`patch` 含 `toolCalls` / `update` / `agentKey` 三类补丁语义，缺目标字段无前置校验。
