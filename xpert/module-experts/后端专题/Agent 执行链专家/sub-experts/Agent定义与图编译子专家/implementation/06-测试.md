## 2. 框架与运行方式

Jest + ts-jest（`tsconfig.spec.json`）+ babel-jest 处理 `node_modules` 中的 ESM 包，`testEnvironment: 'node'`，preset `../../jest.preset.js`。`moduleNameMapper` **直连源码**，不需要先构建依赖包：`^@xpert-ai/server-core$` → `<rootDir>/../server/src/index.ts`、`^@xpert-ai/contracts$` → `<rootDir>/../contracts/src/index.ts`、`^@xpert-ai/plugin-sdk$` → `<rootDir>/../plugin-sdk/src/index.ts`、`^@xpert-ai/cli-model-profiles$`、`^@xpert-ai/shadcn-ui/brand-icons$` 同理。`transformIgnorePatterns` 由 `transformSeedPackages` 反向推导，只对白名单包做转译。

Nx 目标 `test` 使用 `@nx/jest:jest` executor，`jestConfig` 固定指向本包配置，因此以下命令均可用（实测可用命令）：

```bash
# 全量服务器 AI 测试（仓库根）
pnpm nx test server-ai
# 单文件：先定位再按路径运行
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --runTestsByPath packages/server-ai/src/xpert-agent/graph-validator.spec.ts
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --runTestsByPath packages/server-ai/src/xpert-agent/collaborators/collaborators.integration.spec.ts
# 图案过滤（一次跑本子域全部用例）
pnpm nx test server-ai --testPathPattern=xpert-agent
```

本子域 33 个文件实测**均无 `typeorm` / `DataSource` 依赖**，无环境变量门控，无 `it.skip` 条件分支，因此全量可在无 PG、无 Redis 的机器上直接执行。

章节来源：[jest.config.ts](file://packages/server-ai/jest.config.ts)（关键符号：`moduleNameMapper`/`transform`/`transformIgnorePatterns`）、[project.json](file://packages/server-ai/project.json)（关键符号：`targets.test.executor`/`upgrade`）

## 3. 断言与 mock 风格

- **`jest.mock` 前置打桩 + 手工构造**：`xpert-agent.service.spec.ts` 顶部用 `jest.mock` 替换 `@xpert-ai/server-core`、`../shared`、`../xpert/queries`、`../xpert/xpert.service`、`../shared/agent/middleware-runtime/index`、`@xpert-ai/plugin-sdk`、`./commands`、`./xpert-agent.entity`，再 `new XpertAgentService({} as any, commandBus, queryBus, runtime, xpertService)`，并把 `agentMiddlewareRegistry` 直接挂到实例上（`(service as any).agentMiddlewareRegistry = {...}`）——不启 Nest 容器。
- **断言偏向「命令对象形状」与调用顺序**：`invoke-sandbox-target.spec.ts` 用 `commandBus.execute.mockRejectedValue(stopBeforeAcquisition)` 在运行时边界截断，然后断言 `expect(commandBus.execute).toHaveBeenCalledTimes(1)`、`expect(command).toBeInstanceOf(SandboxAcquireBackendCommand)`、`expect(command.params).toMatchObject({ provider, workFor, volumeScope, workspaceBinding, workingDirectory })`。`chat.handler.spec.ts` 同理：把 `XpertAgentInvokeCommand` 的 `options.execution` 就地改写（`checkpointNs`/`checkpointId`/`title`/`metadata`），再断言最后一次 upsert 的 `objectContaining`。
- **流式结果靠 rxjs 收口**：`await lastValueFrom(stream.pipe(toArray()))` 是 `chat.handler.spec.ts` 的标准写法；用例名显式区分「终局化不得覆盖已持久化 usage」「成功终局写入运行时字段」「取消时保留运行时字段且不覆盖最新 checkpoint」。
- **`FakeStreamingChatModel` 承载模型边界**：来自 `shared/agent/fake-streaming-chat-model.ts`（经 `xpert-agent/agent.ts` 第 28 行再导出），图与流式用例围绕它断言投影，不触真实模型。
- **validator 断言形状而非副作用**：`graph-validator.spec.ts` 直接 `new XpertAgentGraphValidator()` 后 `expect(validator.handle({ draft })).toEqual([expect.objectContaining({ ruleCode: AGENT_SUBGRAPH_BUILD_CYCLE, level: 'error', field: 'connections', value: 'Child → Main → Child' })])`——比对 `ruleCode`/`level`/`field`/`value` 四元组与人类可读路径。

章节来源：[xpert-agent.service.spec.ts](file://packages/server-ai/src/xpert-agent/xpert-agent.service.spec.ts)、[invoke-sandbox-target.spec.ts](file://packages/server-ai/src/xpert-agent/commands/handlers/invoke-sandbox-target.spec.ts)、[chat.handler.spec.ts](file://packages/server-ai/src/xpert-agent/commands/handlers/chat.handler.spec.ts)、[graph-validator.spec.ts](file://packages/server-ai/src/xpert-agent/graph-validator.spec.ts)、[fake-streaming-chat-model.ts](file://packages/server-ai/src/shared/agent/fake-streaming-chat-model.ts)（关键符号：`FakeStreamingChatModel`）

## 6. 缺口与不可执行项

1. **图编译分叉无直接单测**：`xpert-agent/` 的 32 个 spec 中**不存在** `compile-graph.handler.spec.ts`。`getSwarmPartners > 1 → swarm` 与 `NotFound` 分支（含 `draft is ...` 文案）只被 `agent.test.ts` 间接覆盖到 `getSwarmPartners` 一层，`CompileGraphHandler.execute` 自身的命令链与 `channel`/`isStart` 传参无断言。
2. **多智能体图生成无直接单测**：**不存在** `create-swarm.handler.spec.ts`。`XpertAgentSwarmHandler` 的 handoff 工具按 `conn.type === 'agent'` 连边过滤、`RunnableLambda` 执行壳、`parentId`/`predecessor` 写入、`ON_AGENT_START`/`ON_AGENT_END` 投影、`installThreadPauseGuards` 全部无覆盖。
3. **native 分支的覆盖面偏薄且跨子域语义**：本子域侧只在 `collaborators.integration.spec.ts` 的若干用例中间接触达 native 路径（如 checkpoint 独立性、`PARALLEL_DELEGATION_TOOL` 出现）；`native-agent.compiler.spec.ts` 物理与目录归属均在 `agent-invocation/`。**`native-graph-adapter.ts` 无任何独立 spec**（其所在目录 5 个 `native*` 文件中只有 `native-agent.compiler.spec.ts`），`wrapNativeAgentInvocation` 的 `callId` 三段回退、`nativeInputDigest`、`DispatchUnknown`/`ConcurrentUpdate`/`MissingResult` 四个错误分支无断言。
4. **controller 层零 spec**：没有 `xpert-agent.controller.spec.ts`，`@Sse()` 头、`keepAlive(30000)` 心跳、`takeUntilClose(res)` 断开语义、`environmentId` 分支、`BadRequestException`/`HttpException` 包装均无测试。
5. **`agent.ts` 的导出面只覆盖一半**：6 个用例全部针对 `createMapStreamEvents`；`messageEvent`、`getChannelState`、`TAgentSubgraphResult` 无直接断言。
6. **`XpertAgentService` 私有路径与 `update` 未覆盖**：`normalizeSchema` 的 zod/JSON 双分支与异常返回 `null`、`createMiddlewareNode` 的节点形状、`resolveMiddlewareSource` 的 `builtin` 分支之外的反向查找边界（多插件同名）、以及被覆写的 `update`（整实体 `assign + save`）都没有用例。
7. **校验与编译解耦这一事实无回归保护**：既没有「编译前必须过 validator」的断言，也没有「validator 不阻断编译」的反向断言，一旦未来接线变更不会有测试报警。
8. **`graphrag` 跨域读 `knowledgebaseIds` 的契约无本域侧测试**：`bounded-graph-reader.spec.ts` 在 `graphrag/` 目录（`jest.mock` 了 `xpert-agent.entity`），本子域侧没有对应「json 引用悬空」的回归用例。

章节来源：[compile-graph.handler.ts](file://packages/server-ai/src/xpert-agent/commands/handlers/compile-graph.handler.ts)（关键符号：`CompileGraphHandler.execute`）、[create-swarm.handler.ts](file://packages/server-ai/src/xpert-agent/commands/handlers/create-swarm.handler.ts)（关键符号：`XpertAgentSwarmHandler.execute`）、[agent.spec.ts](file://packages/server-ai/src/xpert-agent/agent.spec.ts)、[invoke.handler.spec.ts](file://packages/server-ai/src/xpert-agent/commands/handlers/invoke.handler.spec.ts)

## 7. 结论

✅ **可跑。** 本子域 33 个测试文件全部是零外部依赖的构造式单测或内存 fixture 集成，在 `pnpm nx test server-ai --testPathPattern=xpert-agent` 或单文件 `--runTestsByPath` 下可直接执行；`moduleNameMapper` 直连源码，无需先构建 `contracts` / `plugin-sdk` / `server`。

覆盖强度分布明显不均：**流式投影、validator、协作者中间件、native 协作路径** 是本子域最厚的一层（`collaborators.integration.spec.ts` 18 例 + `subgraph.handler.spec.ts` 20 例 + `invoke.handler.spec.ts` 13 例）；而**图编译分叉、swarm 图生成、controller HTTP 面、`native-graph-adapter` 执行壳** 四块是空白区——恰好都是「本子域最核心且最贵」的路径。由于本子域无 PG/Redis 依赖，补测成本主要在图装配的可构造性，而非环境准备。
