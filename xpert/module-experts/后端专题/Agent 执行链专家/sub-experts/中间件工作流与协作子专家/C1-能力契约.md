# C1 · 能力契约（中间件运行时 · Prompt 工作流 · 协作子专家）

> 契约层 CR2。只写「对外可依赖的语义」：入口、参数行为、返回、异常与约束；不含实现算法与私有方法体细节。
> 路径以仓库根为基准相对 `file://` 引用；不写行号。父级域契约见 `file://.module-experts/后端专题/Agent 执行链专家/C1-能力契约.md`，本文不重复父级正文。

## §1 HTTP / WS 入口

### 1.1 `/api/prompt-workflow/*`（7 端点，**全部** `@UseGuards(WorkspaceAuthoringGuard)`）

前缀来自 `file://packages/server-ai/src/prompt-workflow/prompt-workflow.controller.ts` 的 `@Controller('prompt-workflow')`（该模块未注册 `RouterModule`），叠加全局 `api` 前缀。

| 端点 | 形态 | 语义 |
|---|---|---|
| `GET by-workspace/:workspaceId` | GET，`@Query('data', ParseJsonPipe)` 分页、可选 `?published=` | 列出 workspace 内模板 |
| `POST workspace/:workspaceId` | POST，体 `PromptWorkflowInput` | 建模板 |
| `PUT workspace/:workspaceId/:id` | PUT，体 `PromptWorkflowInput` | 改模板 |
| `POST workspace/:workspaceId/:id/archive` | POST | 归档（软删） |
| `POST workspace/:workspaceId/:id/duplicate` | POST | 复制（名字自动派生） |
| `GET workspace/:workspaceId/:id/usage` | GET | 用量口径 |
| `POST workspace/:workspaceId/validate-profile` | POST，体 `TXpertCommandProfile` | 校验命令档案 |

- **约束**：`@ApiBearerAuth()` 只是 OpenAPI 注解；真正的作者态闸门是 `WorkspaceAuthoringGuard`。运行时解析**不经这条面**。

### 1.2 WS `/api/collaboration`（消息与鉴权）

`@WebSocketGateway({ namespace: '/api/collaboration', cors: { origin: '*' }, transports: ['websocket'] })`。

| 方向 | 名称 | 要点 |
|---|---|---|
| 连接 | 握手 | `client.handshake.auth`（回退 `handshake.query`）取 `documentId` / `sessionId` / `clientKey`；`resolveSession` 失败即 `client.emit('error', { message: 'Invalid or expired collaboration session.' })` 后 `disconnect(true)` |
| 连接成功（出） | `sync`、`presence-snapshot` | 先 `client.join(\`collaboration:${documentId}\`)`，再下发初始状态与在线快照（含 `selfClientId`） |
| 入 | `update` | 组装 `{ documentId, updateBase64, origin, expectedSequence? }` 后 `applyUpdateForSession`；**成功才** `client.emit('update-ack', result)` |
| 入 | `sync-request` | 带 state vector 取增量，回 `sync` |
| 入 | `presence` | 白名单投影后刷新在线状态；异常 `client.emit('error', { message })` |
| 出 | `update` / `presence` / `presence-remove` | `server.to(room(documentId)).emit(eventName, event.payload)`，只扇出到该文档房间 |
| 断开 | — | `handleDisconnect` 调 `removePresenceForSession` |

- **约束**：鉴权靠不透明凭据（服务端只存哈希、有 TTL、`timingSafeEqual` 比对）；无 Nest Guard；服务端错误统一走 `error`，不触发 `update-ack`。

### 1.3 不在本子专家

`/api/xpert-agent/*`（含 `middlewares*` 三端点）→ 子专家 ①；`/api/agent-invocations/*`、`/api/agent-runtime-bindings/*`、`/api/xpert-agent-execution/*` → 子专家 ②。

## §2 服务契约（主体）

### 2.1 `AgentMiddlewareRuntimeService`（`file://packages/server-ai/src/shared/agent/middleware-runtime/middleware-runtime.service.ts`）

| 成员 | 语义 | 约束 |
|---|---|---|
| `createScopedApi(scope = {})` | 组装该调用的受控能力视图，返回 `AgentMiddlewareRuntimeApi` | 每次都新建；仅在具备绑定工作区作用域时才额外注册工作区文件等能力 |
| `createModelClient(copilotModel, options)` | 取得模型客户端 | 转 `AgentMiddlewareModelRuntimeService.createModelClient` |
| `getModelProvider(provider)` | 解析模型 provider 连接 | 必须同时具备 provider 与租户，否则报错；无候选即「未配置」 |
| `wrapWorkflowNodeExecution(run, params)` | 把工作流节点执行包上执行账本语义 | 与执行账本规则一致 |
| `emitMiddlewareEvent(event)` | 统一中间件事件出口 | 经聊天事件送出；事件体不得携带跨租户上下文 |
| `resolveSelectedConnectorRuntimeBindings(scope)` | 解析选中的 connector 运行时绑定 | 受 scope 约束 |
| `api` getter | 无参版本的门面 | 供宿主内部取用 |

- **`AgentMiddlewareRuntimeApi` 形状（SDK 定义）**：`createModelClient<T>(copilotModel, options)`、`getModelProvider?(provider)`、`wrapWorkflowNodeExecution<T>(run, params)`、`emitMiddlewareEvent?(event)`、`capabilities?: RuntimeCapabilityRegistry`。
- **边界（明写）**：不得把全局 capability registry 或执行 runner 工厂交给插件；平台能力经 `platformCapabilities.require(...)` 在服务内部取用后转发为 scoped API。
- **模块面**：`AgentMiddlewareRuntimeModule` 是 `@Global()`，以 `XPERT_AGENT_MIDDLEWARE_RUNTIME_TOKEN`（来自 `@xpert-ai/plugin-sdk`）做 provide 与 export。

### 2.2 `AgentMiddlewareModelRuntimeService`（`.../model-runtime.service.ts`）

- **用途**：模型 client 构造、provider 连接解析（含计价 / 限额）、执行包裹与事件出口。
- **出向**：`CopilotGetOneQuery` / `GetCopilotProviderModelQuery` / `CopilotCheckLimitCommand` / `CopilotTokenRecordCommand`；`AIModelGetProviderQuery` → `IAIModelProviderStrategy`。
- **约束**：`purpose: 'observe'` 类调用不记配额；与 `expectedExecutionModel` 不符即拒绝执行；超额中断当前请求。

### 2.3 `PromptWorkflowService`（`file://packages/server-ai/src/prompt-workflow/prompt-workflow.service.ts`）

**作者态方法**

| 方法 | 语义 | 约束 |
|---|---|---|
| `createInWorkspace(workspaceId, input)` | 在 workspace 建模板 | 先断言写权限 |
| `updateInWorkspace(workspaceId, id, input)` | 改模板 | id 与 workspace 必须一致 |
| `upsertInWorkspaceByKey(workspaceId, key, input)` | 按键 upsert | 返回 `{ operation: 'created' \| 'updated', workflow }`；`key` 走 `normalizeWorkflowKey` |
| `archiveInWorkspace(workspaceId, id)` | 按 id 归档 | — |
| `archiveInWorkspaceByKey(workspaceId, key)` | 按键归档 | 找不到即 `NotFoundException`；返回 `{ operation: 'deleted', workflow }` |
| `duplicateInWorkspace(workspaceId, id)` | 复制 | 用 `createCopyName` 派生名（如 `X Copy`）；关联、标签、`associatedXpertIds` 一并复制，`archivedAt: null` |
| `initializeDefaultsInWorkspace(workspaceId, inputs, xpertId?, sourceTemplateId?)` | 默认初始化 | 事务内加锁补插；空输入直接返回 `{ created: [], skipped: [] }`；重名输入先抛错；只在匹配 `sourceTemplateId` 且未归档时补写 `associatedXpertIds`；返回 `{ created, skipped }` |
| `getUsage(workspaceId, id)` | 用量口径 | 先断言读权限 |

**运行时方法**

| 方法 | 语义 | 约束 |
|---|---|---|
| `validateCommandProfile(workspaceId, profile)` | 校验命令档案 | 工作空间命令条目必须带有效工作空间并以存在的工作流为目标，否则 400 |
| `snapshotCommandProfile(...)` | 发布时把「引用」固化为可离线回放的快照 | 只处理 `enabled !== false` 且 `source === 'workspace_prompt_workflow'` 且尚未有 `snapshot` 的条目；查 `findActiveWorkflowMap` 后 `mergeWorkflowWithEntry` |
| `resolveRuntimeCommandProfile(xpert)` | 运行时解析（优先快照、否则当前配置） | 已禁用 / 已归档条目被排除；返回 `{ xpertCommands, workspaceCommands }`，再经 `resolveCapabilityScopes` 注入 `runtimeCapabilities` |

### 2.4 CQRS 解析面：`ResolvePromptWorkflowInvocationQuery`

- **形状（已核实）**：`extends Query<PromptWorkflowInvocationResolution | null>`，构造入参 `(xpert: Pick<IXpert, 'id' | 'workspaceId' | 'commandProfile' | 'graph' | 'agent'>, input: TChatRequestHuman)`；`static readonly type = '[Prompt Workflow] Resolve invocation'`。
- **语义**：仅当输入形如 `/name args` 时介入，返回展开后的对话输入或 `null`；**已展开的文本命令不二次覆盖**；无解析结果时原样返回输入。
- **调用方**：`file://packages/server-ai/src/shared/agent/message.ts` 在生成人类输入时派发该查询。

### 2.5 `CollaborationService.createScopedApi(defaults)` → `CollaborationApi`

- **用途**：宿主把 CRDT 文档读写、会话与在线状态以绑定身份的 API 暴露给插件。`CollaborationService` 自身 `implements CollaborationApi`，并持有 `readonly api: CollaborationApi = this.createScopedApi()`。
- **`CollaborationApi` 方法面（SDK 定义，10 个）**：`ensureDocument`、`getDocument`、`getDocumentState`、`applyUpdate`、`createSession`、`listPresence`、`upsertVirtualPresence`、`removeVirtualPresence`、`archiveDocument`、`deleteDocument`。
- **会话面（服务实现，网关注入使用）**：`resolveSession`、`getStateForSession`、`applyUpdateForSession`、`listPresenceForSession`、`upsertPresenceForSession`、`removePresenceForSession`、`retryMaterialization`、`onBroadcast`。
- **语义要点（已核实）**：`applyUpdate` 的注释即契约——「Authorize, deduplicate, merge, persist, broadcast, and materialize an update」；`getDocument` / `getDocumentState` 会触发「read repair」式物化；`createSession` 签发的浏览器凭据限定**单文档**（read 或 write）；`archiveDocument` 停编辑保文档，`deleteDocument` 软删平台文档并通知 provider。
- **异常（HTTP / 调用侧同源）**：文档不存在 `NotFoundException`；只读会话提交更新被拒；序列冲突 / 超限 400；provider 授权拒绝 403。
- **约束**：权威 CRDT 状态留在平台；物化失败只降级为「失败 + 重试」，**绝不回滚已提交的更新**；`pruneUpdates` 有保留窗口（见 C0 §5.11）。

### ① 宿主构造 scoped runtime 与模型出口

```ts
// 真实调用方：file://packages/server-ai/src/shared/agent/middleware-runtime/middleware-runtime.service.ts
const runtime = service.createScopedApi({ tenantId: 'tenant-1', organizationId: 'org-1' })
const connection = await runtime.getModelProvider?.('zhipuai')
```

```ts
// 边界断言：file://packages/server-ai/src/shared/agent/middleware-runtime/middleware-runtime.provider-boundary.spec.ts
expect(getModuleMetadata(SandboxModule, MODULE_METADATA.IMPORTS)).not.toContain(AgentMiddlewareRuntimeModule)
expect(getModuleMetadata(AgentMiddlewareRuntimeModule, MODULE_METADATA.PROVIDERS)).not.toContain(provider)
```

要点：插件侧只能拿到 `createScopedApi(scope)` 的返回值与其中的 `capabilities`；缺能力时 `require(...)` 显式失败。

### ② 作者态建模板 + 运行时解析斜杠命令

```ts
// 真实调用方：file://packages/server-ai/src/prompt-workflow/prompt-workflow.controller.ts
@UseGuards(WorkspaceAuthoringGuard)
@Post('workspace/:workspaceId')
async createInWorkspace(@Param('workspaceId') workspaceId: string, @Body() body: PromptWorkflowInput) {
    return this.service.createInWorkspace(workspaceId, body)
}
```

```ts
// 真实调用方：file://packages/server-ai/src/shared/agent/queries/resolve-prompt-workflow-invocation.query.ts
new ResolvePromptWorkflowInvocationQuery(xpert, humanInput)   // 返回展开结果或 null
```

要点：作者态与运行时是两套一致性语义——发布时 `snapshotCommandProfile` 固化快照，运行时优先取快照。

### ③ 客户端提交一次 CRDT 更新

```ts
// 真实调用方：file://packages/server-ai/src/collaboration/collaboration.gateway.ts
@SubscribeMessage('update')
async update(@MessageBody() data: unknown, @ConnectedSocket() client: Socket) {
    const result = await this.collaboration.applyUpdateForSession(state.session, {
        documentId, updateBase64, origin, expectedSequence
    })
    client.emit('update-ack', result)     // 仅在持久化成功后 ack
}
```

要点：失败走 `client.emit('error', ...)` 且**不发 ack**；`update` 成功后由服务在提交后广播（本地先发、Redis 跨节点）。
