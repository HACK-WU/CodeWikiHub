# C1 · 能力契约（Agent 调用与执行账本子专家）

> 契约层 CR2。只写「对外可依赖的语义」：入口、参数行为、返回、异常与约束；不含实现算法与私有方法体细节。
> 路径以仓库根为基准相对 `file://` 引用；不写行号。父级域契约见 `file://.module-experts/后端专题/Agent 执行链专家/C1-能力契约.md`，本文不重复父级正文。

## §1 HTTP 端点

### 1.1 `/api/agent-invocations/*`（调用控制面）

| 端点 | 语义 | 关键约束 |
|---|---|---|
| `GET :id` | owner-scoped 观察读取 | `findOwned(id)` 先校验；`isNativeInvocation(...)` 走 `native.inspect` 只读分支，否则 `factory.createCapturedApi(scope).inspect(id)` |
| `POST :id/cancel` | 请求取消一次调用 | native 目标直接 `invocationError('Unsupported')`；非 native 走 `capturedApi.cancel(id)` |
| `POST :id/respond` | 回填人工交互 | 体为 `z.object({ interactionId: z.string().min(1), response: json }).strict()`，失败即 `InvalidRequest`；native 目标 `Unsupported`；未通过 owner 校验即 `NotFound` |

- **`findOwned` 的真实口径**：取 `RequestContext.currentUserId()` / `currentTenantId()` / `getOrganizationId()`，任一缺失或 `id` 非 uuid 即 `NotFound`；随后按 `{ id, ownerId, tenantId, organizationId }` 查库，并要求 `invocation.scope` 四元组与请求一致，且 `scope.callerXpertId` 存在或 `callerType === 'project_agent'`。
- 鉴权：controller 无 `@UseGuards`（显式调用型）。
- native 图 / 任务的取消与审批保留各自既有路由，不经这两个端点。

### 1.2 `/api/agent-runtime-bindings/*`（admin-only）

| 端点 | 语义 | 关键约束 |
|---|---|---|
| `GET` | 列出本组织绑定 | `requireResourceAdmin()`（org scope）；按 `createdAt DESC` |
| `POST` | 建绑定 | zod `.strict()`（`title` 1–200；`workspaceIds` uuid 数组 1–100；`provider` 1–100；`reference` 1–200；`configuration` 默认 `{}`）；未知字段 → `BadRequestException` |
| `PUT :id` | 改绑定 | 体为 `z.object({ enabled: z.boolean() }).strict()`；`affected` 为 0 → `NotFound` |

- **`provider` 白名单（已核实）**：`provider === 'xpert' || 'xpert-task'` → `invocationError('InvalidRequest')`（内置运行时不经绑定暴露）。
- **workspace 归属（已核实）**：`workspaceIds` 去重后用 `bindings.manager.getRepository(XpertWorkspace).countBy({ ...scope, id: In(workspaces) })` 比对数量，不符即 `InvalidScope`。
- **`target.revision` 建时固定**：`target = { bindingId: id, provider, reference, revision: randomUUID(), configuration }`；`id` 亦为 `randomUUID()`。改配置 / 版本必须新建绑定。

### 1.3 交叉引用（逻辑不属本子专家）

| 端点 | 说明 |
|---|---|
| `GET /api/agent-invocations/:id/delivery`、`POST .../delivery/redrive` | **逻辑属「对话与会话专家」**：`RuntimeDeliveryController` 物理在 `handoff/runtime-messaging/`，注册在 `AgentInvocationModule.controllers`，对外同一前缀 |
| `/api/xpert-agent-execution/:id/{log,state,checkpoints}`、`GET xpert/:id/agent/:key` | 执行账本**只读面**（本子专家：服务写入、HTTP 只读） |
| `/api/xpert-agent/*` | 子专家 ①；`/api/prompt-workflow/*`、WS `/api/collaboration` → 子专家 ③ |

- WS / GraphQL / gRPC 面：**无此项**。

## §2 服务契约（主体）

### 2.1 `AgentInvocationRuntime.scoped(access)` → `{ start, inspect, cancel, respond }`

- **用途**：一次调用的唯一状态转移入口。
- **`start` 行为（已核实）**：`structuredClone(request)` → `validateRequest(request)` → `authorizeAgentInvocation(() => access.authorize(request.target))` → `access.signal?.throwIfAborted()` → `id = agentInvocationId(access.scope, request.callId)` → `store.read(id, access.scope)`。命中已有记录时：`assertScope` → 请求规范化不一致即 `CallConflict` → `pinned(record)`；已终态直接返回。
- **`inspect` 行为（已核实）**：`store.read` → `assertScope` → `authorize` → `pinned`；已终态返回；若 `status === 'running'` 且 `startPendingUntil > now` 则原样返回（围栏内不判失效）；无 `handle` 且围栏已过期时经 `updateLatest` 触达一次「收敛为 `unknown`」的写入——**读操作不是绝对无副作用**。
- **`agentInvocationId(scope, callId)`**：对 `canonical({ scope, callId })` 做 sha256 并整形为 UUID 形态的字符串。
- **CAS 提交（已核实）**：写回时 `revision: record.invocation.revision + 1`，`startPendingUntil` 在 `begin` 时置 `now + 120_000`、`finish` 或终态时清空；`replace(next, record.invocation.revision)` 返回 `false` 即重读重试。
- **pin**：`pinned(record)` 用 `registry.getPinned(target.provider, record.providerSource)`，缺失即 `ProviderChanged`。
- **身份校验**：`assertScope(record, scope)` 用 `canonical` 全量比对 `record.invocation.scope` 与访问 scope，不一致即 `NotFound`。
- **异常族**：`InvalidScope`、`CallConflict`、`ProviderChanged`、`ProviderUnavailable`、`DispatchUnknown`、`Unsupported`、`ConcurrentUpdate`、`InteractionConflict`、`NotFound`、`InvalidRequest`（由 `file://packages/server-ai/src/agent-invocation/invocation-errors.ts` 的 `invocationError(...)` 统一产出）。
- **状态**：`queued | running | waiting | cancelling | succeeded | failed | cancelled | unknown`；仅 `succeeded | failed | cancelled` 为终态。

### 2.2 `TypeOrmAgentInvocationStore`（CAS 与同事务观察历史）

| 成员 | 语义 | 约束 |
|---|---|---|
| `insert(record)` | 首次占位（`orIgnore`），返回是否真正插入 | 与 `start` 的「先持久化再派发」配套 |
| `read(id, scope)` | 按 owner scope 读取 | — |
| `replace(record, expectedRevision)` | CAS 提交 | `affected !== 1` → `false`（**不是异常**）；同事务 `appendEvent` 并 `UPDATE agent_invocation_wait SET "nextCheckAt" = now()` |
| `appendEvent(manager, record)` | append-only 事件（`agent_invocation_event`） | 唯一 `(invocationId, revision)` |

### 2.3 `AgentInvocationFactoryService`

| 成员 | 用途 | 约束 |
|---|---|---|
| `createScopedApi(identity)` / `api()` | 按调用方身份取得 scoped API | 每次新建，不缓存首个身份 |
| `createCapturedApi(scope)` | 用持久化身份重建 API | 不采信下一个图轮次的环境 scope |
| `existingApi(id)`（内部） | 幂等复用原调用的 scoped API | 记录缺失时按 `createCapturedApi(previous)` 还原；`inspect`/`cancel`/`respond` 均经它代理 |
| `resolveBackgroundTarget` / `resolveGroupTarget` / `listProjectBindings` | 后台 / 群组 / 项目目标解析 | 统一走 `createCapturedApi(scope).resolve(bindingId)` |
| `claimResults(callId, tasks)` | 认领已终局任务结果 | 只对符合条件任务执行 |
| `awaitResult(id, options?)` / `waitForTasks(request, options?)` | 有界等待 | 返回前 `claimResults`；窗口耗尽返回 `pending` |
| `getResourceCard(id)` | 资源卡投影 | 资源卡本身不授访问权 |

### 2.4 `AgentInvocationMonitorService`

- **`@EventsHandler(TaskObservationCommittedEvent)` 的 `handle()`** → `void this.reconcile().catch(...)`；`reconcile()` 为扫描入口，`process(wait)` 处理单个 wait，`deliver(wait)` 由独立 dispatcher 驱动、**不被观察扫描 await**。
- **`claim` 为 private**：租约领取成功后才有处理权（外部契约只需知道「同一 wait 行不会双写」）。
- **`withAccess(request, handler)` 为 private**：恢复原 actor/租户/组织并复核成员资格。
- **可观测口径（已核实）**：扫描中 `SELECT COUNT(*) ... FROM agent_invocation_wait WHERE state IN ('waiting','ready','blocked')`；`unknownSince` 超 `HOST_TASK_WAIT_POLICY.unknownGraceMs` → `outcome = 'unavailable'`；`deadlineAt` 过期 → `'timeout'`；`outcome === 'attention'` 且 `deadlineAt` 过期 → `state = 'blocked', lastError = 'awaiting_user'`。
- **约束**：**polling 是唯一持久恢复机制**；`busy`/`stopping` 门闩只防本进程重入。

### 2.5 等待与续跑

- **wait 行（已核实）**：`AgentInvocationWaitEntity` → `@Entity('agent_invocation_wait')`；关键列 `state ∈ { 'waiting' | 'ready' | 'delivered' | 'stale' | 'blocked' }`、`request`、`outcome`、`deadlineAt`、`unknownSince`、`nextCheckAt`、`leaseToken`、`leaseUntil`。`AgentInvocationWaitStore` 建档时 `state: 'waiting'`、`nextCheckAt: now`、`deadlineAt: now + HOST_TASK_WAIT_POLICY.maxWaitMs`，并用 `orIgnore()`。
- **有界等待（已核实）**：`awaitInvocationTasks(api, input, signal?, policy = HOST_TASK_WAIT_POLICY)` 中 `timeoutMs = Math.min(request.timeoutMs ?? policy.inlineWaitMs, policy.maxInlineWaitMs)`。
- **命令与查询（已核实）**：`file://packages/server-ai/src/agent-invocation/task-wait-control.ts` 导出 `CancelTaskWaitsCommand`（SQL：`SET state = 'stale', "leaseToken" = NULL, "leaseUntil" = NULL, "lastError" = 'parent_cancelled'`，命中范围含 `parentExecutionId` 派生、`threadId` 匹配、以及 wait.id 落在该父执行派生的 invocation 集合内）与 `CheckTaskWaitClaimQuery`。

### 2.6 `ExecutionCancelService.cancelExecutions(executionIds, reason?)`

- **行为（已核实）**：id 去重 → `redis.publish('ai:execution:cancel', JSON.stringify(payload))`（失败仅 `logger.warn`）→ `applyCancel(uniqueIds, reason)`。
- **订阅侧**：`onModuleInit` 用 `redis.duplicate()` 建独立 subscriber 订阅同名 channel，收到消息调 `applyCancel`；`onModuleDestroy` 用 `closeRedisSubscriber('execution-cancel.redis', ...)` 收尾。
- **配套**：`register(executionId, controller)` / `unregister(executionId, controller?)` 维护本地 `AbortController` 登记表；`file://packages/server-ai/src/shared/execution/execution-abort-scope.ts` 提供父子级联订阅与 `unsubscribe`。
- **约束**：返回 `void`、**不抛**；本副本照常停、其他副本可能静默丢取消；取消不构成终止证明。

### 2.7 `XpertAgentExecutionService`（执行与用量账本，唯一写入面）

| 方法 | 语义 | 约束 |
|---|---|---|
| `create(entity, ...options)` | 新建执行记录 | 忽略调用方审计时间戳 |
| `update(id, entity)` | 终局化 / 续写 | 事务内行锁重读后合并；重复终局化保留已记录结束时间；回到运行态即清空 |
| `recordUsage(id, usage)` | 累加用量与定价 | 事务内累加 |
| `interruptRunning(ids, threadId, error)` | 批量中断仍在运行的执行 | 只命中「运行态且线程匹配」的行 |
| `findAllByParentId(id, options?)` / `findAllByXpertAgent(...)` | 子执行 / 按 Agent 列出 | 只读 |

- **`completedAt` 口径（已核实）**：`execution-timing.ts` 的 `isExecutionStopped(status)` = `{ SUCCESS, ERROR, TIMEOUT, INTERRUPTED }`；`executionCompletedAt(nextStatus, previous)` 在「下一态已停且上一态未停」时返回 `new Date()`。

| 方法 | 语义 |
|---|---|
| `startTask(input)` | 启动一次后台任务，返回 `AgentMiddlewareAssistantTaskResult` |
| `getTaskStatus(...)` | 查询任务状态 |

## §3 示例（真实调用方）

### ① 起一次调用并有界等待

```ts
// 真实调用方：file://packages/server-ai/src/agent-invocation/native-graph-adapter.ts
const api = runtime.scoped({
  scope: { ...context.scope, parentExecutionId },
  capabilities, signal: config.signal ?? context.signal,
  authorize: () => context.authorize(), isSuspension: isGraphInterrupt
})
const result = await api.start({
  target: context.target,
  callId: `${context.target.bindingId}:${callId}`,
  input: { prompt: '', parameters: { nativeInputDigest } }
})
```

```ts
// 真实调用方：file://packages/server-ai/src/agent-invocation/invocation-factory.service.ts
waitForTasks: async (request, options) => {
  const result = await awaitInvocationTasks(controls, request, options?.signal)
  await claimResults(request.callId, result.tasks)   // 返回前按调用方作用域认领结果
  return result                                     // 窗口耗尽正常返回 pending
}
```

要点：`scope` 必须由已经过鉴权的上下文构造；`callId` 复用即幂等命中或 `CallConflict`。

### ② 取消一次执行（协作式 + 终态归一）

```ts
// 真实调用方：file://packages/server-ai/src/chat-conversation/commands/handlers/cancel-external-assistant.handler.ts
const ids = descendants.filter((item) => item.status === Status.RUNNING).map((item) => item.id)
await this.cancellations.cancelExecutions(ids, reason)      // 先广播再本地 abort
await this.executions.interruptRunning(ids, execution.threadId, reason)  // 不覆盖已竞态获胜的完成态
```

要点：只有「运行态且线程匹配」的行会被归一为中断并写结束时间；已终态行不被误伤；`unknown` 保持可见。

### ③ 处理 CAS 冲突（重读重试）

```ts
// 真实调用方：file://packages/server-ai/src/agent-invocation/invocation-runtime.ts
if (!(await this.store.replace(next, record.invocation.revision))) { /* 重读重算 */ }
// 真实调用方：file://packages/server-ai/src/agent-invocation/typeorm-invocation.store.ts
if (result.affected !== 1) return false
```

要点：`false` 是冲突不是异常；事件表唯一冲突会回滚整个 `replace` 事务。
