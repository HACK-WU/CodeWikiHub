## 0. 契约自足声明

本文是本子专家的对外使用契约：不读实现层即可决定「何时找本子专家、能拿到什么能力、调哪个入口、边界在哪、有哪些已知坑」。算法、私有方法与数据结构细节不在本文展开，只给契约级语义与实现层索引。

## 1. 定位

本子专家是**对话账本的主体**：会话/线程/目标/读状态与消息的持久化与授权、消息反馈、分支（写模型）、脉络地图（只读视图）、线程运行控制（pause/resume/租约）、`/api/chat` 主聊天流与语音入口、会话摘要任务。

对外只有三条主线：**读侧统一过 `ChatConversationService.assertAccess`**、**消息只有一个写入口 `ChatMessageUpsertCommand`**、**分支只有一个入口 `ConversationBranchCommand`**；控制面只有一个写者许可 `ChatExecutionAdmissionService.run`。

## 2. 何时找这个子专家

- 需要新建/更新/删除会话、按 `threadId` 反查会话、读会话详情与工作台导航/侧边栏：找本子专家。
- 需要写一条消息，或授权读取一条消息（含建议问题、任务摘要、文件变更统计投影）：找本子专家。
- 需要从未锚定的历史点分叉出新会话（保留检查点与文件链接）：找分支能力。
- 需要脉络地图（话题视图、项目下拉、在地图上创建/改名/侧聊/分支/定位）：找地图能力。
- 需要线程运行控制（pause/resume/线程态、租约与过期 run 回收）或取消一次会话：找本子专家。
- 需要消息反馈的授权 CRUD 与摘要联动、语音合成与转写：找本子专家。
- 需要群内成员、发布幂等、收据账本、HITL 交互：找子专家②（群聊协作）。
- 需要异步投递一条消息、取消/暂停传播、死信与回执重驱：找子专家③（投递队列与运行时消息）。
- 需要模型执行本身、Assistant 定义与版本、执行链：**不在本域**，找对应专家。

## 5. 边界

**本域拥有（逻辑与 HTTP 同域）**：`/api/chat-conversation/*`、`/api/chat`、`/api/chat-message/*`、`/api/chat-message-feedback/*`；这四个前缀由 `conversation.module.ts`、`chat-message.module.ts`、`feedback.module.ts` 的 `RouterModule.register` 注册（`/api/chat` 由控制器自挂 `chat`）。

**跨域适配器（HTTP 在别处、逻辑在本子专家）**：

| 端点族 | 物理注册 | 目录归属 |
|---|---|---|
| `/api/ai/conversations*`（CRUD、检索、goal 正式路由、线程、任务摘要、消息 CRUD/检索、会话内反馈） | `ai/conversation.controller.ts` | Assistant 定义与运行时专家 |
| `/api/ai/threads*`（线程检索、history、copy、runs、run stream/wait、cancel/pause/resume、display-pause、context-usage、usage） | `ai/thread.controller.ts` | 同上 |
| `/api/ai/conversations/:id/branch` | `ai/conversation-branch.controller.ts` | 同上 |
| `/api/ai/conversations/:id/workspace/files**`、`/artifacts/**` | `ai/workbench-files.controller.ts`、`ai/conversation-artifacts.controller.ts` | 同上 |

**不负责**：

- 群聊协作（成员、发布幂等、收据、HITL、群内助手运行时）：子专家②（`chat-group/`）。
- handoff 投递队列、路由、取消传播、死信与 redrive、运行时消息 inbox/续跑：子专家③（`handoff/`）。
- 模型执行本身（`XpertChatCommand` 与 Agent 运行时）、Assistant 定义与版本、SSE 扇出设施（`shared/stream`，本域仅作消费方）。
- 检查点能力的定义：本域只在分支事务内复制检查点。

## 6. 已知坑（10 条）

1. **消息 `sequence` 依赖会话行锁**：契约是「最高已分配序号，在会话行锁内分配」，唯一索引 `(conversationId, sequence)`；私有路径不分配、常驻 `NULL`，排序退化为父链 + `createdAt`——**不得假定它存在，也不得当翻页游标用**。
2. **`messageEnvelope` 不是命令、不是授权、不是运行时主体**：真实目的地由已授权命令决定；**禁止写入 prompt 文本、凭据或授权声明**；第三方 payload 不决定宿主 provenance/presentation。
3. **非法 envelope 对公开隐藏、对运行时保留**：非法/未知持久化版本不进公开历史，但**仍参与模型祖先与重试**（隐藏 ≠ 未参与推理）；`readChatMessageEnvelope` 读侧静默吞异常，无法区分「无信封」与「损坏信封」。
4. **`chat_conversation_attachment` 已 `@deprecated` 的双路径**：新路径是 `FileAsset` + `ConversationFileLink`；授权读取与分支复制必须并行维护两套关系，可见性差异多源于此。
5. **地图无 entity**：它是 view-extension provider（`platform.conversation-map`、slot `AGENT_WORKBENCH_SLOT`、key `topics`）；宿主类型、槽位或 key 变化时会**静默消失**（返回空清单、不报错）；搜索的 `page.total` 是扫描范围而非命中数，客户端需按 `searchOffset` / `nextSearchOffset` 续读。
6. **会话无归档字段**：`ChatConversation` 只有 `status` / `error`；归档与置顶落在用户偏好与群成员偏好上，会话级归档能力缺失。
7. **pause 受理 ≠ 检查点完成 + 租约 15s / 90s**：202 只表示 `pausing`，只有 `finish` 在「`pausing` + 有检查点 + `interrupted`」时确认 `paused`；进程租约 15s 续约、90s 寿命，到期由替代进程在**一个事务**内把未收尾 run 标错（不重放工具、不制造假 pause）；无租约旧 run 不按时间猜死，只能显式 stop。
8. **`assertAccess` 的三种 operation 语义**：`read` 只读；`contribute` 参与写入、取消、目标改写、工作区文件保存/上传/删除；`manage` 还可改删会话；`purpose='group'` 一律拒绝，`group_assistant_runtime` 仅群运行时私有会话放行。
9. **分支幂等冲突与写放大**：幂等键为 `(createdById, branchSource->>'threadId', branchSource->>'requestId')`，命中且参数一致返回原会话，不一致抛 `request_conflict`；事务内逐消息、逐检查点、逐文件复制，且**不复制 pending writes**；锚点缺检查点即 `checkpoint_unavailable`。
10. **绕过服务层直查仓库即越权**：消息读、反馈读、文件关系过滤同理；新增读取方必须复用 `assertAccess` 族授权，而不是自建查询。
