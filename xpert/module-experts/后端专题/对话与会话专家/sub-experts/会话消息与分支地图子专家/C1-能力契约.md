## §1 HTTP 接口契约

### 1.1 本域拥有的四个前缀

全局前缀 `api` 由宿主 bootstrap 设置；模块前缀由各模块 `RouterModule.register` 注册，控制器自身不含路径段（`ChatController` 例外，自挂 `chat`）。

| 前缀 | 控制器（注册位置） | 鉴权 | 代表端点（方法 路径 → 用途） | 主要错误 |
|---|---|---|---|---|
| `/api/chat-conversation` | `ChatConversationController`、`ChatConversationSidebarController`（`conversation.module.ts`） | 登录态 + 组织域包裹 + `assertAccess` | `GET /my`；`POST /unread/xperts`（未读汇总）；`GET /by-thread`、`GET /entry-by-thread`；`GET /:id`、`PUT /:id`（`manage`，仅白名单字段）、`DELETE /:id`；`GET /:id/state`（线程态）；`GET /:id/workbench-navigation`；`POST /:id/read-state`；`POST /:id/cancel`（`contribute`）；`GET /xpert/:id`；`GET /:id/attachments`（弃用附件族）；`GET /:id/files`、`GET /:id/file`、`GET /:id/file/download`、`PUT /:id/file`、`POST /:id/file/upload`、`DELETE /:id/file`；`GET/PUT/PATCH/DELETE /:id/goal`（已弃用兼容路由，指向 `/ai/conversations/{id}/goal`）；`GET /my/sidebar`、`PATCH /:id/sidebar` | 403 `ConversationAccessDenied`；400 `InvalidThreadAssistantId`；403 `ConversationXpertImmutable`；404 |
| `/api/chat` | `ChatController`（`@Controller('chat')`） | 登录态 | `POST ''`（`@Sse` 主聊天流，`keepAlive(30000)`，连接关闭即释放）；`GET /synthesize`（`@Sse` 语音合成，连接关闭触发 abort）；`POST /speech-to-text`（上传转写） | 由命令内部校验与上传管道决定 |
| `/api/chat-message` | `ChatMessageController`（`chat-message.module.ts`） | 登录态 | `GET /:id/suggested-questions`（先取消息 → 会话授权 → 建议问题命令） | 403；404 |
| `/api/chat-message-feedback` | `ChatMessageFeedbackController`（`feedback.module.ts`） | 登录态 | `GET /`、`GET /my`（无用户直接 403）、`GET /:id`、`POST /`（201）、`PUT /:id`（202）、`DELETE /:id`（202） | 403；404 |

**约定**：会话侧控制器不挂自有守卫（仅 `@ApiBearerAuth()`）；授权三件套为「全局鉴权 + 组织域包裹 + `assertAccess`」。

### 1.2 跨域适配器（逻辑在本子专家、注册在 `ai/**`，目录归属「Assistant 定义与运行时专家」）

## §2 服务能力契约

### 2.1 `ChatConversationService`（`file://packages/server-ai/src/chat-conversation/conversation.service.ts`）

- `create(entity, ...options)`：创建后**容错**初始化查看者读状态（失败仅告警，不阻断创建）。
- `update(idOrWhere, partial, ...options)`：`options` 按白名单合并并**拒绝 `projectId` 迁移**（`Error.ConversationProjectImmutable`）。
- `assertAccess(conversationOrId, operation: 'read' | 'contribute' | 'manage' = 'read')`：返回已授权会话实体；`purpose='group'` 一律拒绝；`group_assistant_runtime` 仅群运行时私有放行；Project 会话转项目访问断言。
- `findOneByThreadId(threadId)`：会话表未命中回退线程表，均未命中 404。
- `findOneDetail(id, { select, relations })`：`executions` 关系单独经查询总线拼装。
- `markRead(conversationId, lastReadMessageId?)`：需登录用户；未传消息 ID 时回落到会话时间兜底，返回读状态。
- `getThreadState(id)`：返回最近执行所属运行态，无则 `null`。

### 2.2 `ChatMessageService`（`file://packages/server-ai/src/chat-message/chat-message.service.ts`）

- `findOneAuthorized(id, { relations?, operation? = 'read' })`：先轻量取行拿到 `conversationId`，再经会话级授权查询，最后按 `relations` 二次读取并复核 `conversationId` 一致；无 `conversationId` 直接 403。
- `deleteByIds(ids)`：逐条软删，**自身不含授权**，调用方必须先授权。
- 约束：`messageEnvelope` 不在公开写白名单；公开投影只暴露**合法呈现策略**下的信封；`filterAuthorizedFileRelations` 对越权关系静默剔除。

### 2.3 `ChatMessageFeedbackService`（`file://packages/server-ai/src/chat-message-feedback/feedback.service.ts`）

- `findAllAuthorized(options)`：**必须给出 `conversationId`**（否则 403），关系字段先做安全断言，再按 `read` 授权。
- `createAuthorized(input)` / `updateAuthorized(id, input)` / `deleteAuthorized(id)`：按 `contribute` 授权，写入前校验目标消息归属。
- `triggerSummary(id)`：按 `contribute` 取回后**异步**触发摘要；失败仅告警，不影响 HTTP 结果。

### 2.4 `ConversationBranchService`（`file://packages/server-ai/src/chat-conversation/conversation-branch/conversation-branch.service.ts`）

- `branch(conversationId, { sourceThreadId, afterMessageId, requestId })`：幂等键 **`requestId`**（与作者、源线程共同去重）；命中即复用既有分支会话，参数不一致抛冲突；未命中则校验锚点路径与图版本、逐文件重授权后复制谱系、检查点与文件链接，返回新会话。
- `findExistingBranch(...)`：幂等查询（事务内二次调用兜住并发）。
- 失败语义六码：`message_not_in_thread`、`message_not_complete`、`checkpoint_unavailable`、`graph_changed`、`state_not_supported`、`request_conflict`。
- 约束：源 ID 只是审计数据、**不建立外键级联**；复制**保留原 `messageEnvelope`**；不复制 pending writes。

### 2.5 `ConversationMapService`（`file://packages/server-ai/src/chat-conversation/conversation-map/service.ts`）

- `read(context, query)`：只读分页投影（`projectId` 缺省取运行时项目，越权 403）。
- `projectOptions(context, offset = 0)`：返回 `{ projects, nextOffset }`，`nextOffset` 为 `null` 表示到底。
- `act(context, action)`：动作 `create` / `rename` / `side-chat` / `branch` / `locate`，非法动作 400；`create` 以 `requestId` 同时作为会话 ID 实现幂等，`branch` 转分支命令，`side-chat` 转线程复制。
- 三者入口先做宿主上下文与请求上下文一致性校验；**无 entity、无表**，投影剔除运行时消息与非法角色。

## §3 代码示例

### 例 1 · 写一条消息（`sequence` 语义）

```ts
// packages/server-ai/src/ai/conversation.controller.ts（createMessage，节选）
return new ChatMessageDTO(
    await this.commandBus.execute(
        new ChatMessageUpsertCommand({ ...this.pickMessageMutation(body), createdById, conversationId })
    )
)
```

- 写侧唯一入口是 `ChatMessageUpsertCommand`；适配器侧的写白名单**不含 `messageEnvelope`**，信封只能由受信生产者路径携带。
- 建会话侧：地图 `act.create` 在 advisory 锁内以 `requestId` 作会话/线程 ID，派发 `ChatConversationUpsertCommand` 后 `threads.ensurePrimary`。
- `sequence` 只有群发布路径推进；私有会话消息不分配，读侧按父链 + `createdAt` 排序，**不要当游标**。

### 例 2 · 从某消息分支出新会话

```ts
// packages/server-ai/src/ai/conversation-branch.controller.ts
return new ConversationDTO(await this.commands.execute(new ConversationBranchCommand(conversationId, input)))
```

- 同一 `requestId` 重复调用返回同一分支会话；参数不同抛分支冲突；锚点必须满足 `role='ai'`、`status='success'` 且带有效输出检查点。

### 例 3 · 读脉络地图

```ts
// packages/server-ai/src/chat-conversation/conversation-map/service.ts（read 分支，节选）
// scope() → conversation() → 线程页 / 会话页投影；带 search 时按有界会话页扫描并回填 nextSearchOffset
```

- 视图入口是 view-extension `platform.conversation-map`（slot `AGENT_WORKBENCH_SLOT`、key `topics`、动作 `act`）；AI 段只合并纯文本，人类消息摘要截断 600 字符。
- 搜索分页：`page.total` 是扫描范围而非命中数，`matches` 只匹配 title/preview/answer。

### 例 4 · 取消一次会话（协作式语义）

```ts
// packages/server-ai/src/chat-conversation/conversation.controller.ts（POST :id/cancel，节选）
await this.service.assertAccess(id, 'contribute')
return this.commandBus.execute(new CancelConversationCommand({ conversationId: id }))
```

- 取消是**协作式**（信号传递）而非强杀；会话侧先取消执行，再尽力通知 handoff（失败仅告警）；结果统一记为 `dead(canceled:...)`，不进死信、不重试。
