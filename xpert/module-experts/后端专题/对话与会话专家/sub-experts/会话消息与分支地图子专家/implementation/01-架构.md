## 子域职责边界
**负责**：会话生命周期（`chat_conversation`/`chat_conversation_thread`/`chat_conversation_goal`/`chat_conversation_read_state`）、消息持久化与授权读取（`chat_message`）、消息反馈（`chat_message_feedback`）、分支写模型（`conversation-branch/`）、脉络只读视图（`conversation-map/`）、线程运行控制（pause/resume/租约）、`/api/chat` 主聊天流与语音转写/合成、会话摘要任务。

**不负责**：群聊协作（`chat-group/`，子专家②）；handoff 投递队列与运行时消息闭环（`handoff/`，子专家③）；模型执行本身（`XpertChatCommand` 与 Agent 运行时）；`ai/**` 下的 HTTP 适配器按目录归其他专家域，本子域只提供被调用的服务与命令。

| 维度 | 分支 `ConversationBranchService`（写模型） | 地图 `ConversationMapService`（只读视图） |
|---|---|---|
| 持久化 | 事务内写 `chat_conversation` + `chat_conversation_thread` + `chat_message` + `copilot_checkpoint` + `conversation_file_link` | **无 entity、无表**；只投影既有行 |
| 入口 | 仅 `ConversationBranchCommand`（调用方不 import 本模块） | `@ViewExtensionProvider('platform.conversation-map')`，slot `AGENT_WORKBENCH_SLOT`、key `topics` |
| 并发控制 | 源线程 `pessimistic_write` 行锁 + `requestId` 幂等（部分索引） | `scope()` 宿主上下文与 `RequestContext` 比对；仅 `create` 动作用 advisory lock |
| 授权 | `assertAccess(contribute)` + 发布版 Xpert + Project 运行访问 + 逐 `fileAssetId` 重授权 | `scope()` + `assertAccess(read\|contribute\|manage)` + `assertCanReadXpert` |
| 失败语义 | `branchConflict` 六码：`message_not_in_thread`/`message_not_complete`/`checkpoint_unavailable`/`graph_changed`/`state_not_supported`/`request_conflict` | `ForbiddenException` + `ConversationMap.InvalidQuery`/`InvalidAction` |
| 冲突副作用 | 复制谱系/检查点/文件链接，写放大；不启动 run | 读放大；`create`/`rename`/`side-chat`/`branch` 分别转交既有命令 |

## 关键不变量
### envelope 边界（4 条）
1. `messageEnvelope` 是唯一 provenance/presentation 契约，**不是命令、模型角色、运行时主体、路由请求或授权凭证**；执行仍归 `XpertChatCommand` 与既有 Agent 运行时。
2. **不得**把 prompt 文本、凭据或授权声明写入 envelope；第三方 payload 不决定宿主 provenance/presentation。
3. 公开 mutation 白名单**不含**该字段；**分支复制保留原 envelope**（含已审计的目的地与关联）。
4. 非法/未知持久化版本对公开历史隐藏，但运行时水合保留用于执行与诊断；`presentation='runtime'` 只是不进公开历史，**隐藏 ≠ 未参与推理**。
章节来源：[MESSAGE-ENVELOPES.md](file://packages/server-ai/src/chat-message/MESSAGE-ENVELOPES.md)（关键符号：TChatMessageEnvelope / Boundaries and persistence）、[message-envelope.schema.ts](file://packages/server-ai/src/chat-message/message-envelope.schema.ts)（关键符号：parseChatMessageEnvelope / readChatMessageEnvelope）

### sequence 与会话行锁
`ChatConversation.lastMessageSequence` 注释明写「allocated under the conversation row lock」，`ChatMessage.sequence` 可空并受唯一索引 `(conversationId, sequence)` 约束；会话级排序以 `lastMessageSequence` 为准。本子域的私有路径不分配 `sequence`（推进点在群聊发布，属子专家②）。
章节来源：[conversation.entity.ts](file://packages/server-ai/src/chat-conversation/conversation.entity.ts)（关键符号：ChatConversation.lastMessageSequence）、[chat-message.entity.ts](file://packages/server-ai/src/chat-message/chat-message.entity.ts)（关键符号：ChatMessage.sequence / Index(['conversationId','sequence'])

### 分支幂等
幂等键为 `(createdById, branchSource->>'threadId', branchSource->>'requestId')` 部分索引；命中但参数不一致抛 `request_conflict`；事务内二次查询兜住并发；源 ID 只是审计数据，**不建立外键级联**，源会话删除不牵连目标会话。
章节来源：[conversation-branch.service.ts](file://packages/server-ai/src/chat-conversation/conversation-branch/conversation-branch.service.ts)（关键符号：ConversationBranchService.findExistingBranch / branch）、[20260922-conversation-branch.sql](file://packages/server-ai/src/chat-conversation/migrations/20260922-conversation-branch.sql)

### 地图无表
`ConversationMapModule` 的 providers 只有 `ConversationMapService` 与 `ConversationMapViewProvider`，无 `TypeOrmModule.forFeature`、无 entity、无 controller；所有读取经 `conversations`/`threads`/`projects`/`db` 既有服务，写动作转交既有命令（`ChatConversationUpsertCommand`/`ConversationBranchCommand`/`copyThread`）。
章节来源：[conversation-map.module.ts](file://packages/server-ai/src/chat-conversation/conversation-map/conversation-map.module.ts)（关键符号：ConversationMapModule.providers）、[service.ts](file://packages/server-ai/src/chat-conversation/conversation-map/service.ts)（关键符号：ConversationMapService.act）

### pause 语义
pause 为**无 body 控制命令**，返回 202 + `pauseId`；**受理 ≠ 检查点完成**（受理仅表示 `pausing`）；同一活跃暂停的重复请求返回同一 token；旧执行不能暂停替代它的新 run；只有 `finish()` 在 `pausing` + 有检查点 + `status==='interrupted'` 时确认 `paused`。进程租约 15s 续约、90s 寿命，到期由替代进程在**一个事务**内把未收尾 run 标错，**不重放工具、不制造假 pause**；无租约旧 run 不按时间猜测回收，需显式 stop。
章节来源：[thread-run-control.md](file://packages/server-ai/src/chat-conversation/thread-run-control.md)、[thread-run-control.service.ts](file://packages/server-ai/src/chat-conversation/thread-run-control.service.ts)（关键符号：ThreadRunControlService.requestPause / finish / recoverExpiredRun）、[thread-run-lease.ts](file://packages/server-ai/src/chat-conversation/thread-run-lease.ts)（关键符号：RUN_LEASE_KEY / RUN_LEASE_MS）

## 结论
本子域是一个「单授权闸门 + 双写读语义」的结构：读侧一切会话/消息/反馈访问收敛到 `ChatConversationService.assertAccess`（消息侧再包一层 `ChatMessageService.findOneAuthorized`），写侧消息只有一个入口 `ChatMessageUpsertCommand`，分支只有一个入口 `ConversationBranchCommand`，控制面只有一个写者许可 `ChatExecutionAdmissionService.run`。分支与地图构成一对刻意的不对称设计——分支用事务、行锁、检查点复制换取不可变的独立谱系；地图用零表投影与宿主上下文比对换取免迁移与低耦合。需要持续警惕的是：`sequence` 在私有路径为空、envelope 非法版本读侧静默、租约到期会直接把 run 标错（而非伪造暂停），以及地图投影的读放大与搜索分页语义。
