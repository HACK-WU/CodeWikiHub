## 测试缺口
1. **地图 provider 契约缺端到端**：`conversation-map.module.spec.ts` 只验证模块边界与 CQRS 装配，没有断言 `AGENT_WORKBENCH_SLOT` 下清单字段（`order`/`activation.requiredFeatures`/`view.entry`）与 `getRemoteComponentEntry` 的真实产物读取。
2. **`sequence` 无覆盖**：本子域私有路径从不分配 `sequence`，没有一个 spec 断言「唯一索引 + 行锁分配」在会话侧的行为（该契约当前由群聊路径承担）。
3. **`/api/chat` SSE 生命周期缺覆盖**：`chat.controller.ts` 的 `keepAlive(30000)`/`takeUntilClose` 与 `synthesize` 的 `res.on('close')` 中止没有对应 spec；`chat.handler.spec.ts` 只覆盖命令层的分派与校验。
4. **租约续约的时钟边界**：`maintainLeases` 的 15s 定时器与 `take: 50` 上限只在集成用例中间接覆盖，未见「续约失败 → 重试 → 过期回收」的定向用例。
5. **反馈摘要联动**：`triggerSummary`/`deleteSummary` 的失败仅 warn 的语义没有专项断言（controller spec 侧重授权边界）。
6. **子域无 e2e/HTTP 全链路**：本子域没有 `*.e2e.spec.ts`；`/api/chat` 与分支 HTTP 只经由 `conversation-entry.http.spec.ts`、`workbench-navigation.http.spec.ts` 等边界用例间接覆盖。

## 结论
本子域的测试重心明确：控制面（`thread-run-control` 单测 + 真库集成）、分支面（服务单测 + 检查点纯函数 + 迁移真库）、地图面（服务/投影单测 + 模块边界）、消息面（授权读取与信封解析）。真库用例全部要求显式开关并落到一次性库/schema，属刻意设计；缺口集中在「宿主集成」（view-extension 清单与远端组件入口）、「传输生命周期」（SSE）与「异步副作用」（摘要、租约续约）三类。补测优先级建议为：pause/stop 的 HTTP 全链路 → 地图 provider 清单契约 → SSE 生命周期。
