# C1 · 能力契约（群聊协作子专家）

> 层级：**契约层（CR2 / CR5 / CR7）** ｜ 父专家：后端专题 / 对话与会话专家
> 资产基线：**2026-10-15 · commit `c07bb83d`**
> 本文只描述对外能力：HTTP 入口、服务入口、真实调用示例、来源索引；不含算法与表结构细节。

## §1 HTTP 接口契约

### 1.1 端点族与注册归属

群接口的**物理注册全部在 `packages/server-ai/src/ai/groups/**`**，由 `ai/groups/index.ts` 的 `GROUP_CONTROLLERS` 聚合进 `ai.module.ts`（`RouterModule.register([{ path: '/ai', module: AIModule }])`），因此对外前缀是 `/api/ai/groups/*`；控制器统一 `@Public()` + `@AllowClientSecretBindings(USER_CONVERSATION)`，守卫为 `ApiKeyOrClientSecretAuthGuard` + `GroupScopeGuard`（工作台族再加 `GroupWorkbenchGuard`）。

| 控制器 | 路径 | 代表端点（方法 路径 → 用途） |
|---|---|---|
| `GroupsController` | `groups` | `GET /`（群目录/侧边栏摘要）；`GET /candidates`、`GET /:groupId/candidates`（邀请候选）；`POST /`（建群，`groupCreateSchema`）；`GET /:groupId`（**成员可见快照**：消息 + 收据 + 运行态 + 待处理交互 + `hasMore`）；`POST /:groupId/members`、`DELETE /:groupId/members/:participantId`；`GET /:groupId/messages/:messageId/runtime/:participantId`（单次执行视图）；`POST /:groupId/messages`（人类发送：`submit` + `flush`）；`PATCH /:groupId/preferences`（本人偏好）；`POST /:groupId/members/:participantId/control`（pause/cancel/resume）；`POST /:groupId/messages/:messageId/recipients/:participantId/cancel`（撤回单条投递）；`POST /:groupId/interactions/:interactionId/claim`、`POST /:groupId/interactions/:interactionId/respond`；`@Sse /:groupId/stream`（观察者流，`last-event-id` 游标） |
| `GroupProjectController` | `groups/:groupId/project` | `GET`（读群项目绑定）；`PUT`（写群项目绑定） |
| `GroupComposerController` | `groups/:groupId/members/:participantId/composer` | `GET /context`（项目/锁定/忙碌）；`GET /types`、`GET /available`（可选资源）；`GET /assistants/:assistantId/runtime-capabilities`；`GET /assistants/:assistantId/resources`、`POST .../resources/validate`、`POST .../resources/authorize`；`GET /assistants/:assistantId/workspace/files`；`GET /:projectId/files`、`GET /:projectId` |
| `GroupWorkbenchContextController` | `groups/:groupId/workbench` | `GET /context`（群工作台上下文，由 `GroupWorkbenchGuard.resolve` 解析并绑定已发布主 Assistant 的私有运行时） |
| `GroupViewsController` | `groups/:groupId/workbench` | 继承 `ViewExtensionRoutes`：复用私有会话 Views 的清单/数据/动作路由（不重复定义 manifests、dataSource 与动作处理器） |
| `GroupViewFilesController` | `groups/:groupId/workbench/workspace-files/view-sessions` | `POST`（建视图会话）；`POST /:sessionId/grants`（授权）；`DELETE /:sessionId` |

**约定**：适配器只做 Zod 边界校验与转发，群权限判定一律下沉到 `GroupAccessService.authorize`；`GroupScopeGuard` **对 JWT 登录用户直接放行**，因此不要以「能进路由」推断「能操作该群」。

### 1.2 请求校验的契约面（对外可观察）

- 发送：`groupHumanSendSchema`（`clientMessageId`、`text` 1–32000、`mentions` ≤32、可选 `replyToMessageId`）；历史：`groupHistorySchema`（`before`、`limit` 1–100 默认 50）；偏好：`groupPreferencesSchema`（至少一个键）。
- 交互应答：`groupClaimSchema`（`claimId`）、`groupInteractionResponseSchema`（`toolMessages`/`decisions` ≤32、序列化 ≤128000）。
- 错误语义：`groupDenied()` 403、`groupInvalid()` 400、`groupConflict()` 409；对外错误正文经 `groupExecutionError` 去凭据并截断 2000 字符。

## §2 服务能力契约

### 2.1 `GroupMessagesService`（`file://packages/server-ai/src/chat-group/group-messages.service.ts`）

- `send(groupId, input)`：程序化/助手侧发送入口，先经群授权再发布。
- `submit(groupId, input)`：人类入口；按 mention 解析收件人（未声明的 `@` 抛 400，去重后 ≤16），无 mention 回落到群主 Assistant（无默认助手即群拒绝）。
- `publish(group, author, input, root?, publicationId?, projection?, causedByMessageId?, hostContext?)`：**幂等键 `groupPublicationId`**；执行顺序为前置校验 → 锁群会话行 → 回复链校验与反爆炸 → 写消息（`sequence` 仅新建时在锁内自增）→ 收据 fan-out → 群行 `revision++` → 返回公开投影。
- `snapshot(groupId, before?, limit = 50)`：该调用者的成员可见投影（`sequence DESC` 取 `limit+1` 判 `hasMore`）。
- `preferences(groupId, { readSequence?, pinned?, archived? })`：只更新本人行，`readSequence` 单调前进并封顶到 `lastMessageSequence`。

### 2.2 `GroupOutboxService`（`file://packages/server-ai/src/chat-group/group-outbox.service.ts`）

- `reconcile()`：共享扫描驱动（模块初始化注册为 `HandoffOutboxAdapter`）；轮转 100 条活跃收据并推 `FinishGroupChatCommand`，再取 20 条到期 `wake & pending` 收据投递；单条失败以 `allSettled` 隔离。
- `flush(groupId)`：提交后主动投递该群「待唤醒且到期」的收据。
- `route(recipientId, tenantId)`：消费端只收 `recipientId`；重查成员有效性（被移除置 `blocked(member_removed)`），改写为 `AGENT_CHAT_DISPATCH_MESSAGE_TYPE` 并复用 handoff 入队。
- `deliver(row)`（内部阶段）：数据库租约抢占（`leaseToken` + `leaseUntil=now+60s` + `attempts+1`）后入队；失败按 `min(300s, 5s*2^n)` 退避，`attempts>=9` 置 `failed`。
- 消费策略：`@HandoffProcessorStrategy(GROUP_MESSAGE_TYPE, { policy: { lane: 'main' } })`，由 `GroupMessageProcessor.process` 转 `route`。

### 2.3 `GroupAccessService`（`file://packages/server-ai/src/chat-group/group-access.service.ts`）

- `authorize(groupId, manage = false)`：**唯一身份/授权入口**，返回 `{ group, actor, scope }`；请求带 API 凭据时要求绑定类型 `USER_CONVERSATION`、资源范围为该会话、租户/组织一致且未过期，否则 401/群拒绝；`manage=true` 额外要求 `role='owner'`。
- `withDeliveryActor` / `withRootUser`：在 `withGroupRuntime` 作用域内，用**持久化绑定**重建请求上下文（重验收据状态与助手 `runtimeConversationId`），执行者身份由 `groupDeliveryUserId(source)` 决定。

### 2.4 `GroupMembersService`（`file://packages/server-ai/src/chat-group/group-members.service.ts`）

- `create(input)`：单事务写入群会话（`purpose='group'`）、owner 成员、助手私有运行时会话 + 线程、助手成员（含运行时绑定）。
- `add(groupId, input)`：需 `manage`；命中既有成员即 `active=true` 并**恢复同一运行时绑定**；活跃成员 `>= 32` 抛 409。
- `remove(groupId, participantId)`：拒绝 owner 与默认助手；置 `active=false`，把相关未完成收据置 `canceled/member_removed`、交互置 `canceled`，并派发取消命令。
- `publicMember` / `publicMembers`：对外成员投影入口。

### 2.5 `GroupInteractionsService`（HITL，`file://packages/server-ai/src/chat-group/group-interactions.service.ts`）

- `register(...)`：仅在 LangGraph interrupt 载荷下工作，`interactionId = "{executionId}:{sha256(requests)}"` 以 `orIgnore` 幂等插入。
- `claim(groupId, interactionId, claimId)`：锁群行 + 交互行，要求 `assignedUserId = 当前人类`、`claimId` 未被占用、成员 active、线程 `interrupted` 且交互晚于 `runtimeContinuationBlockedAt`；**成功后才返回私有请求体**。
- `respond(groupId, interactionId, input)`：要求 `claimId` + `claimedBy` 匹配、请求与决策逐项匹配、关联收据处于 `blocked`；写 `control` 并把收据回 `pending`，交互置 `completed`，提交后 `outbox.flush`。

### 2.6 `GroupRuntimeService`（`file://packages/server-ai/src/chat-group/group-runtime.service.ts`）

- `prepare(job)`：先校验 `groupDeliveryId`/`tenantId`/组织头齐全（不得放宽查询条件），在 `withRootUser` 内重验成员与可访问性；准入事务锁群行 + 目标运行时线程行 + 收据行，产出 `send` / `resume` / 阻断结论（`blocked/runtime_blocked`、`blocked/composer_project_changed`、`blocked/authorization_revoked`）。
- `finish(recipientId, dispatchFailed, dispatchFinished)`：对账调度与租约之间的进程丢失（线程 busy + 同一执行 + 无租约 + 超 120s → 标错）、登记 HITL、把可见 AI 输出逐条 `publish`（`publicationId='output:{id}'`，末条答案 `intent='reply'`）、写收据终态与成员 `contextSequence`、`revision++`、`outbox.flush`。
- 命令入口：`PrepareGroupChatCommand`、`FinishGroupChatCommand`、`ResolveGroupDeliveryContextCommand`、`GetGroupConversationEntryCommand`。

### 2.7 「无此项」的服务面

- 群内**个人视角历史读取**：无此项（`snapshot` 是群级公开投影）。
- 群成员的**偏好代办**（owner 代改他人偏好）：无此项。
- 群表**数据库级级联**：无此项（零外键，清理靠应用层）。

## §3 代码示例

### 例 1 · 发布一条群消息并查成员可见投影

```ts
// packages/server-ai/src/ai/groups/group.controller.ts（节选）
@Post(':groupId/messages')
async send(
    @Param('groupId', UUIDValidationPipe) id: string,
    @Body(new ZodValidationPipe(groupHumanSendSchema, groupInvalid)) input: z.output<typeof groupHumanSendSchema>
) {
    const message = await this.messages.submit(id, input)
    await this.outbox.flush(id)
    return message
}

@Get(':groupId')
snapshot(
    @Param('groupId', UUIDValidationPipe) id: string,
    @Query(new ZodValidationPipe(groupHistorySchema, groupInvalid)) input: z.output<typeof groupHistorySchema>
) {
    return this.messages.snapshot(id, input.before, input.limit)
}
```

- `submit` 在同一事务落「消息 + 全部收据」（发布强一致），`flush` 只是加速：**入队不等于送达**，恢复主机制是 `reconcile` 轮询。
- `snapshot` 返回**该调用者的成员可见投影**，不是全局消息流水；私有载荷不会出现。

### 例 2 · HITL 交互 claim 与 respond

```ts
// packages/server-ai/src/ai/groups/group.controller.ts（节选）
@Post(':groupId/interactions/:interactionId/claim')
claim(
    @Param('groupId', UUIDValidationPipe) id: string,
    @Param('interactionId', UUIDValidationPipe) interactionId: string,
    @Body(new ZodValidationPipe(groupClaimSchema, groupInvalid)) input: z.output<typeof groupClaimSchema>
) {
    return this.interactions.claim(id, interactionId, input.claimId)
}

@Post(':groupId/interactions/:interactionId/respond')
respond(
    @Param('groupId', UUIDValidationPipe) id: string,
    @Param('interactionId', UUIDValidationPipe) interactionId: string,
    @Body(new ZodValidationPipe(groupInteractionResponseSchema, groupInvalid))
    input: z.output<typeof groupInteractionResponseSchema>
) {
    return this.interactions.respond(id, interactionId, input)
}
```

- 只有 `assignedUserId` 本人能认领；第二个标签页会被 `groupConflict()` 拒绝；`respond` 后交互置 `completed`，由下一次 `flush` 恢复执行。

### 例 3 · 观察者 SSE

```ts
// packages/server-ai/src/ai/groups/group.controller.ts
@Sse(':groupId/stream')
stream(@Param('groupId', UUIDValidationPipe) id: string, @Headers('last-event-id') cursor?: string) {
    return this.streams.observe(id, cursor)
}
```

- 游标加密并双重绑定 `groupId` / `viewerId`，不匹配或超长即 `resync`；断开只卸载 reader，**不取消模型、不确认工具**。
