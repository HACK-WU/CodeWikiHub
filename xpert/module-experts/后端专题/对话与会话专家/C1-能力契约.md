## §2 服务能力契约（主体）

### 2.1 `ChatConversationService`（`chat-conversation/conversation.service.ts`）
- **用途**：会话写模型 + 全域统一授权闸门。
- **参数与行为语义**：`create(entity, ...options)` → 创建后**容错**初始化查看者读状态（失败仅告警，不阻断创建）；`update(idOrWhere, partial, ...options)` → `options` 走白名单合并并拒绝 `projectId` 迁移；`assertAccess(conversationOrId, operation: 'read' | 'contribute' | 'manage' = 'read')` → 三者差异：`read` 只读、`contribute` 参与写入/取消/目标改写、`manage` 还可改删会话；`purpose='group'` 一律拒绝，`group_assistant_runtime` 仅对群运行时私有会话放行。
- **返回**：`assertAccess` 返回已授权会话实体（调用方拿到即可安全继续）；`findOneByThreadId(threadId)` 返回会话（会话表未命中时回退线程表，均未命中 404）。

### 2.2 `ChatConversationService` 读侧与文件族（同上文件）
- **用途**：详情、线程态、已读、旧附件族与工作区文件。
- **参数与行为语义**：`findOneDetail(id, { select, relations })` → `executions` 关系单独经查询总线拼装；`markRead(conversationId, lastReadMessageId?)` → 需登录用户，未传消息 ID 时回落到会话时间兜底，返回读状态；`getThreadState(id)` → 返回最近执行所属的运行态，无则 `null`；`getAttachments(id)` → 返回旧附件族公开 DTO（**弃用路径**）；工作区文件族（`/:id/files`、`/:id/file`、`/download`、`/upload`）→ 读取要求 `read`，保存/删除/上传要求 `contribute`，Project 会话额外要求项目编辑权限。
- **异常**：缺用户 400；越权 403 `ConversationAccessDenied`；Project 受管控内容路径写入 403。
- **约束**：绕过本服务直查仓库即越权。

### 2.3 `ChatMessageService`（`chat-message/chat-message.service.ts`）
- **用途**：消息的授权读取与文件关系授权过滤；写入统一走 `ChatMessageUpsertCommand`。
- **参数与行为语义**：`findOneAuthorized(id, { relations?, operation? })` → 先做组织/租户范围取回，再经会话级授权查询（默认 `read`），无 `conversationId` 直接 403；`findOneInOrganizationOrTenant(id, options)` → 范围取回，供上层自行授权；`deleteByIds(ids)` → 逐条软删，**自身不含授权**，调用方须先授权；`filterAuthorizedFileRelations(message, conversationId)` → 会话不匹配即 403，旧附件与新文件资产两条路径分别过滤后返回。
- **异常 / 约束**：403（越权、会话不匹配）；`messageEnvelope` 不在公开写白名单，公开投影只暴露**合法呈现策略**下的信封。

### 2.4 `ChatMessageFeedbackService`（`chat-message-feedback/feedback.service.ts`）
- **用途**：反馈的授权 CRUD 与摘要联动。
- **参数与行为语义**：`findAllAuthorized(options)` → **必须给出 `conversationId`**（否则 403），关系字段先做安全断言，再按 `read` 授权；`createAuthorized(input)` / `updateAuthorized(id, input)` / `deleteAuthorized(id)` → 按 `contribute` 授权，写入前校验目标消息归属；`triggerSummary(id)` → 按 `contribute` 取回后异步触发摘要。
- **异常 / 约束**：403；控制器「我的反馈」入口在无用户时直接 403；摘要失败仅告警、不影响 HTTP 结果。

### 2.5 `ConversationBranchService`（`chat-conversation/conversation-branch/conversation-branch.service.ts`）
- **用途**：从未锚定的历史点分叉出新会话（写模型）。
- **参数与行为语义**：`branch(conversationId, { sourceThreadId, afterMessageId, requestId })` → 幂等键 **`requestId`**（与作者、源线程共同去重）：命中即**复用既有分支会话**，参数不一致抛冲突；未命中则校验锚点路径与图版本、逐文件重授权后复制消息谱系、检查点与文件链接，返回新会话。
- **返回**：新（或既有）`ChatConversation`。
- **异常 / 约束**：请求体非法 400；无用户 403；越权 403（`contribute`）；锚点不可用/图版本变更/源线程不一致 → 分支冲突。复制**保留原 `messageEnvelope`**，`branchSource` 只是审计数据、无级联。
- **内部分阶段（非对外入口，仅供审计对齐）**：`prepareBranch`（路径快照 + 图版本校验）、`loadBranchPath`（沿父链回溯，供只读导航）、`findExistingBranch`（幂等查询）。

### 2.6 `ConversationMapService`（`chat-conversation/conversation-map/service.ts`）
- **用途**：脉络地图只读投影与动作；**无实体、无表**。
- **参数与行为语义**：`read(context, query)` → 只读分页投影（`projectId` 缺省取运行时项目，越权 403）；`projectOptions(context, offset = 0)` → 返回 `{ projects, nextOffset }`（`nextOffset` 为 `null` 表示到底）；`act(context, action)` → 动作 `create | rename | side-chat | branch | locate`，非法动作 400。三者入口先做宿主上下文与请求上下文一致性校验。
- **约束**：`create` 以 `requestId` 同时作为会话 ID 实现幂等；`branch` 转分支命令；投影剔除运行时消息与非法角色。

### 2.7 `GroupMessagesService`（`chat-group/group-messages.service.ts`）
- **用途**：群发布、成员可见快照、成员偏好。
- **参数与行为语义**：`send(groupId, input)` → 程序化发送，先经群授权再发布；`submit(groupId, input)` → 人类输入，按 mention 解析收件人，缺省回落到群主 Assistant（无主 Assistant 抛群拒绝）；`publish(group, author, input, root?, publicationId?, projection?, causedByMessageId?, hostContext?)` → 幂等键 **`groupPublicationId`**，命中且内容一致复用同一 messageId，内容不一致抛冲突，`reply` 必须命中未被回复的原请求；`snapshot(groupId, before?, limit = 50)` → 成员可见投影（消息 + 收据 + 运行状态 + HITL 交互，多取一条判 `hasMore`）；`preferences(groupId, { readSequence?, pinned?, archived? })` → `readSequence` 单调前进（以 `min(lastMessageSequence, 入参)` 落库）。
- **异常 / 约束**：群拒绝 403；群冲突；作者不活跃/不属于该群即拒绝；链式深度与同根规模超阈值硬拒绝。

### 2.8 `GroupOutboxService`（`chat-group/group-outbox.service.ts`）
- **用途**：群收据的恢复扫描与投递改写；实现 outbox 适配器（模块初始化注册、销毁注销）。
- **参数与行为语义**：`reconcile()` → 扫描在途与待重试收据并轮转长任务（受 `Promise.allSettled` 隔离）；`flush(groupId)` → 立即投递该群「待唤醒且到期」的收据；`route(id, tenantId)` → 消费端只收 `recipientId`：重查成员有效性（被移除置 `blocked(member_removed)`）后改写为 `AGENT_CHAT_DISPATCH_MESSAGE_TYPE` 并复用 handoff 入队；`deliver`（**内部投递阶段，非对外入口**）→ 数据库租约抢占后入队，失败按指数退避、尝试上限后置失败。
- **约束**：入队成功不等于送达；扫描是恢复主机制，本地事件与队列只是加速。

### 2.9 `GroupAccessService.authorize(groupId, manage = false)`（`chat-group/group-access.service.ts`）
- **用途**：群能力的唯一身份/授权入口。
- **参数与行为语义**：返回 `{ group, actor }`；当请求携带 API 凭据时要求绑定类型为 `USER_CONVERSATION`、资源范围为该会话、租户/组织一致且凭据未过期，否则群拒绝/401；随后按当前用户解析群身份与成员（`manage` 更严）。
- **异常 / 约束**：403 / 401；**JWT 登录用户不经 `GroupScopeGuard`**，此处是真正的闸门。

### 2.10 `HandoffQueueService`（`handoff/message-queue.service.ts`）
- **用途**：handoff 队列的唯一入队入口（模块为 `@Global`）。
- **参数与行为语义**：`enqueue(message, options?)` → 标 `handoff:enqueue` 权限，统一补齐 `id/version/attempt/maxAttempts`（缺省 3）并解析路由后入队，返回 `{ id }`；`enqueueMany(messages, { delayMs? })` → 批量入队，返回 id 列表（源码未见权限注解）；`enqueueAndWait(message, { timeoutMs?, onEvent? })` → 标 `handoff:wait` 权限，返回 `ProcessResult`（`ok` / `retry` / `dead`），**仅本进程回调、best-effort**。
- **异常 / 约束**：入队失败会同时 reject 等待者并抛出；跨实例等待只会超时（默认 2 分钟）；`dead(canceled:...)` 会 resolve 等待者但不进死信。

### 2.11 `HandoffRouteResolver.resolve(message)`（`handoff/dispatcher/handoff-route-resolver.service.ts`）
- **用途**：把一条消息解析为「队列 + lane + 总超时 + 空闲超时」的投递决议。
- **行为语义（优先级）**：消息头 `handoffQueue`（含 `queue` 别名）> `typePolicies[type].queue` > 命中规则 `target.queue` > `defaultQueue`；lane / timeout / idleTimeout 同源解析。
- **约束**：路由配置来自 YAML（`HANDOFF_ROUTING_CONFIG_PATH`）；未设置时仅告警并使用内置默认快照。

### 2.12 `RuntimeMessageInboxService`（`handoff/runtime-messaging/runtime-message-inbox.service.ts`）
- **用途**：运行时事件（`result` / `input_request`）的幂等收件与结果认领。
- **参数与行为语义**：`receive(message)` → 校验租户/组织/用户、事件结构、outbox 记录存在、事件与 outbox 一致、消息 ID 与事件派生 ID 一致，任一不符抛「无效」；随后在重授权回调内落库；`lockInbox(manager, reply, event)` → 以**消费键唯一**做幂等入库并锁定（`input_request` 使用独立后缀键，与最终结果不争抢），返回 inbox 行；`claimWait(command)` → 逐个 invocation 授权，只有 `result` 事件参与，且要求消费者执行仍在运行、同线程，否则抛访问错误。
- **异常 / 约束**：`consumer_outcome_unknown` **不会自动重放**；等待与异步追单共用同一消费键；状态读取不认领结果。

### 例 1b · 写入一条消息（`sequence` 语义）
```ts
// packages/server-ai/src/ai/conversation.controller.ts（createMessage，节选）
return new ChatMessageDTO(
```

- **`sequence` 语义**：会话上的「最高已分配序号」在会话行锁内分配；当前**只有群发布路径推进它**，普通会话消息不分配（读侧按父链与创建时间排序）。因此不要把 `sequence` 当游标用。
- 公开写白名单**不含** `messageEnvelope`：写入方只能通过受信生产者路径携带信封。

### 例 3 · 群聊发布并查成员可见投影（`snapshot`）
```ts
// packages/server-ai/src/ai/groups/group.controller.ts（GroupsController，节选）
@Post(':groupId/messages')
async send(
    @Param('groupId', UUIDValidationPipe) id: string,
    @Body(new ZodValidationPipe(groupHumanSendSchema, groupInvalid)) input: z.output<typeof groupHumanSendSchema>
) {
    const message = await this.messages.submit(id, input)
    await this.outbox.flush(id)
    return message
}

@Get(':groupId')
snapshot(
    @Param('groupId', UUIDValidationPipe) id: string,
    @Query(new ZodValidationPipe(groupHistorySchema, groupInvalid)) input: z.output<typeof groupHistorySchema>
) {
    return this.messages.snapshot(id, input.before, input.limit)
}
```
- **语义**：`submit` 落发布与收据，`flush` 立即触发投递；`snapshot` 返回**该调用者的成员可见投影**（含收据与交互），不是全局消息流水。

```ts
)
```
- **限制**：`enqueueAndWait` 只在**同一进程**收到回调；跨实例部署时调用方会一直等到 `timeoutMs`（默认 2 分钟）。跨实例请改用状态查询或轮询。
- 返回值判定：`status === 'dead'` 视为失败（取 `reason`），`status === 'retry'` 属异常返回；`dead(canceled:...)` 会正常返回但不进死信。

### 例 5 · 取消一个会话（协作式语义）
```ts
// packages/server-ai/src/chat-conversation/conversation.controller.ts（POST :id/cancel，节选）
await this.service.assertAccess(id, 'contribute')   // 取消需要 contribute
return this.commandBus.execute(new CancelConversationCommand({ conversationId: id }))
```
- **语义**：取消是**协作式**（信号传递，不强杀同步 CPU 代码）+ 扫描式；会话侧先取消执行，再尽力通知 handoff（失败仅告警、不阻断取消）。
- 结果统一记为 `dead(canceled:<reason>)`：**不进死信、不重试**；扫描与 abort 之间已完成的作业可能正常结束，失败可见性依赖日志与回执。
