## 0. 契约自足声明

本文是「对话与会话专家」的对外使用契约，不依赖阅读实现层即可决定：**何时找本专家、能得到什么能力、调哪个入口、边界在哪里、有哪些已知坑**。凡涉及算法、私有方法与数据结构细节，一律不在本文展开，只给出契约级语义与指向实现层的索引。

## 1. 专家定位

本域是平台**对话账本与投递账本的持有者**：会话/线程/目标/读状态与消息的持久化与授权、分支（写模型）与脉络地图（只读视图）、群聊协作（成员、发布幂等、收据、HITL）、handoff 投递队列（4 队列/4 消费者/路由/取消/死信）与运行时消息闭环（delivery → inbox → 续跑）。三种投影语义——`messageEnvelope`、`sequence`、群收据——是全域对外一致契约。

## 2. 何时找这个专家

- 需要**新建/更新/删除会话**，或按 `threadId` 反查会话、读取会话详情与工作台导航：找本域。
- 需要**写一条消息或授权读取一条消息**（含建议问题、任务摘要、资源卡片投影）：找本域。
- 需要**从未锚定的历史点分叉出新会话**（保留检查点与文件链接）：找本域分支能力。
- 需要**会话列表/未读/已读/侧边栏/摘要/消息反馈**：找本域。
- 需要**群聊**（成员、发送、成员可见投影、偏好、HITL 交互、群内助手运行时）：找群聊协作子专家。
- 需要**异步投递一条消息并可能等待结果**、需要**取消/暂停/恢复**、需要**查看或重驱一次投递回执**：找投递队列与运行时消息子专家。
- 需要**模型执行、Assistant 定义与版本、执行链本身**：**不在本域**，请找对应专家。

## 6. 边界（做什么 / 不做什么 / 适配器在哪）

**本域拥有**（逻辑与 HTTP 同名域）：

| 前缀 | 控制器 | 授权承担方 |
|---|---|---|
| `/api/chat-conversation/*` | `ChatConversationController`、`ChatConversationSidebarController` | 全局鉴权 + 组织域包裹 + `ChatConversationService.assertAccess` |
| `/api/chat` | `ChatController`（无 `RouterModule`） | 登录态 + 命令内部校验 |
| `/api/chat-message/*` | `ChatMessageController` | 登录态 + 会话级授权查询 |
| `/api/chat-message-feedback/*` | `ChatMessageFeedbackController` | 登录态 + `findAllAuthorized` 族授权 |

**跨域适配器（HTTP 在别处、逻辑在本域）**：

| 端点族 | 物理注册位置 | 归属专家域 | 本域角色 |
|---|---|---|---|
| `/api/ai/conversations*`（CRUD/检索/目标/消息/反馈/线程/摘要/产物） | `ai/conversation.controller.ts`、`ai/thread.controller.ts`、`ai/conversation-artifacts.controller.ts`、`ai/workbench-files.controller.ts` | Assistant 定义与运行时专家 | 提供 `ChatConversationService`/`ChatMessageUpsertCommand`/`ChatConversationGoalService` 等被调能力 |
| `/api/ai/groups/*`（快照、成员、消息、偏好、控制、HITL、群工作台） | `ai/groups/*` | Assistant 定义与运行时专家 | 提供 `chat-group/` 全部服务与命令 |
| `/api/agent-invocations/:id/delivery`、`.../redrive` | `agent-invocation.module.ts` 的 controllers | 执行链域 | inbox/delivery 实体与服务仍在本域源码树 |

**共享设施（不计入本域源码范围）**：`shared/stream`（`SseStreamModule` + `RedisSseStreamService`）是运行时可复用的 SSE 扇出设施，本域仅作为消费方出现。

**与 `copilot-checkpoint` 的关系**：本域通过 `TypeOrmModule.forFeature` **直引实体** `CopilotCheckpoint` / `CopilotCheckpointWrites`（`chat-conversation/conversation.module.ts`），分支复制在其事务内复制检查点；检查点能力的**定义与演进归 `copilot-checkpoint` 域**，本域只是消费者——该域字段/语义变更会直接冲击本域分支契约。

**不做什么**：不执行模型；不拥有 Assistant 定义与版本；不拥有执行链（消费者只调用本域服务）；不承担 SSE 扇出实现。

## 7. 已知问题与常见坑（16 条）

1. **`sequence` 依赖会话行锁，单会话是写热点**：契约是「最高已分配序号，在会话行锁内分配」，更新复用原值；当前只有群发布路径推进它，普通私有会话消息常驻空值，排序退化为父链 + 创建时间——跨域读取方**不得假定 `sequence` 恒存在**。
2. **`messageEnvelope` 是唯一 provenance/presentation 契约**：它**不是命令、不是授权授予**，真实目的地由已授权命令决定；**禁止写入 prompt 文本、凭据或授权声明**；分支复制**保留原 envelope**；非法/未知版本对公开历史隐藏、**但仍参与运行时推理与重试**（隐藏 ≠ 未参与）。
3. **`chat_conversation_attachment` 已 `@deprecated`**：新路径是 `FileAsset` + `ConversationFileLink`，旧关系仍在实体上并存，授权读取需双路径过滤，分支复制两套关系都复制——可见性差异多源于此。
4. **`GroupScopeGuard` 对 JWT 用户直接放行**：该守卫只在凭据为 `client_secret`/`api_key` 时收紧，且要求绑定类型必须为 `USER_CONVERSATION` 并存在 `params.groupId`；**不要用登录态直连群路由做隔离假设**，JWT 路径完全依赖服务侧 `GroupAccessService.authorize`。
5. **`enqueueAndWait` 仅本进程回调（best-effort）**：worker 或 waiter 在别的实例时不会回调，调用方只会等到超时（默认 2 分钟）；跨实例应改用轮询/状态查询。
6. **取消是协作式（`AbortSignal`）+ 扫描式**：`waiting/delayed/paused` 移除 job，`active` 只尽力 abort，扫描与 abort 之间存在「已完成」竞态；取消结果统一记为 `dead(canceled:...)`，**不进死信、不重试**，因此可能掩盖真实失败。
7. **`consumer_outcome_unknown` 不得自动重放**：结果模糊时应先按回执检查**同一执行身份**，再人工 redrive；传输重试与 redrive 都不会重启 CLI 或分配替代消费者。
8. **Redrive 不改 Invocation、不清用户 stop**：`redrive` 只重新授权原回复目标并重排阻塞/失败传输，保留 claim/phase 与用户 stop 屏障；显式 stop 场景应在手工轮次读取结果。
9. **无租约的僵尸 run 不会被自动回收**：租约到期只回收「持有租约的未收尾 run」（标错并中断其执行/消息状态）；**旧 run 不按时长猜死**，只能显式 stop。
10. **地图（`conversation-map`）无 entity**：它注册为 view-extension provider（provider key `platform.conversation-map`、slot `AGENT_WORKBENCH_SLOT`、view key `topics`、依赖 `CONVERSATION_MAP_FEATURE`）。宿主类型、槽位或 key 变化时会**静默消失**（`getViewManifests` 返回空数组，不报错）。
11. **群发布靠 `groupPublicationId` 幂等 + 收据增长**：同键重复发布复用同一 messageId（内容不一致抛冲突）；成员可见性由 `chat_message_recipient` 收据逐条增长决定，收据是**投递账本而非第二个执行队列**。
12. **会话无归档字段**：`ChatConversation` 只有 `status`/`error`，归档/置顶落在用户偏好与群成员偏好上；**`TChatConversationStatus` 取值以 contracts 为准**：`idle · busy · pausing · paused · interrupted · error`。
13. **群会话反爆炸阈值是硬拒绝**：`hop >= 8` 或同根消息数 `>= 32` 直接失败；调整需同步测试与文档，跨域调用方不要假设可无限链式回复。
14. **级联语义不对称**：会话→消息/线程/目标/读状态/反馈是数据库级联，但群聊三表与 `branchSource` 无外键，删除会话时遗漏即产生孤儿收据/交互。
15. **装配分散**：分支能力以命令为唯一入口，`ConversationBranchModule` 不在 `ChatConversationModule` 的 imports 中，调用方需自行注册命令处理器；反查 API 归属要同时看 `ai/**`、`agent-invocation.module.ts` 与本域模块注释。
16. **`revision` 不是消息计数或回放游标**：它既做公开快照版本，也会因不追加消息的更新（成员/投递失败）前进；摘要队列只对非群、有消息的会话生效，反馈触发的摘要失败仅告警。
