## 二、框架与运行方式

Jest + ts-jest（`tsconfig.spec.json`）与 babel-jest 混用；`preset: '../../jest.preset.js'`；`moduleNameMapper` 把 `@xpert-ai/server-core`、`@xpert-ai/contracts`、`@xpert-ai/plugin-sdk` 直接指向源码目录，因此无需先构建依赖包；`transformIgnorePatterns` 白名单化了一批 ESM 依赖。

实测可用命令：

```bash
# 1) 整包（nx executor @nx/jest:jest，project name = server-ai）
corepack pnpm exec nx run server-ai:test --skipNxCache --runInBand

# 2) 直连 jest，单文件/单目录（本域最常用）
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --runTestsByPath packages/server-ai/src/chat-conversation/conversation.service.spec.ts

# 3) 按名称过滤
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --testPathPattern 'src/(handoff|chat-group)/'
```

章节来源：[jest.config.ts](file://packages/server-ai/jest.config.ts)（关键符号：moduleNameMapper / transform / transformIgnorePatterns），[project.json](file://packages/server-ai/project.json)（关键符号：server-ai.targets.test）

## 三、断言与 mock 风格

- **纯单元**：直接 `new Controller(...)` / `new Service(mockDb, mockQueue, ...)` 注入 `jest.fn()` 桩；断言调用参数与返回对象（如 `conversation.controller.spec.ts` 覆盖 goal 弃用路由）。
- **Nest 集成（无 DB）**：`Test.createTestingModule({ controllers, providers })` + `createNestApplication({ logger: false })`，再用 `fetch` 打真实 HTTP 边界（`conversation-entry.http.spec.ts`、`workbench-navigation.http.spec.ts`、`runtime-delivery.controller.spec.ts`）。
- **守卫与元数据**：`jest.spyOn(GroupScopeGuard.prototype, 'canActivate').mockResolvedValue(true)` 覆盖控制器 spec；`Reflect.getMetadata(GUARDS_METADATA / ALLOWED_CLIENT_SECRET_BINDINGS_METADATA, Controller)` 断言守卫顺序与绑定类型。
- **数据库偏好**：多数 case 用 Repository/DataSource mock（`findAndCount`、`createQueryBuilder` 链）；确需真库时用 `describe`/`describe.skip` 开关 + 自建连接。
- **无全局 setup/setupFiles**：共享 fixture 在各 spec 内自带。

## 五、需外部依赖的用例与开启方式

| 变量 / 脚本 | 开启的用例 | 约束（源码明写） |
|---|---|---|
| `XPERT_PAUSE_TEST_DATABASE_URL` | `thread-run-control.integration.spec.ts` | 指向以 `_test` 结尾的一次性库；覆盖并发行锁、租约续约/接管、消息与续跑更新 |
| `CHATKIT_BRANCH_TEST_DATABASE_URL` | `conversation-branch/*` 三个真库用例 | 显式 opt-in、隔离 schema，绝不使用平台配置库 |
| `THREAD_REFERENCE_TEST_DATABASE_URL` | `thread-reference.integration.spec.ts` | 库名必须以 `_test` 结尾，否则抛错 |
| `THREAD_REFERENCE_TEST_REDIS_URL` | `thread-cursor.store.integration.spec.ts` | 真实 Redis |
| `XPERT_EXECUTION_TEST_DATABASE_URL` + `XPERT_EXECUTION_TEST_REDIS_URL` + `XPERT_EXECUTION_TEST_REDIS_CONTAINER` + `XPERT_RECOVERY_CHILD` | `queue-recovery.worker.spec.ts` / `queue-recovery.cases.ts` | 库名须以 `xpert_execution_test_` 开头、Redis 必须是 `127.0.0.1`；子进程以 SIGKILL 模拟崩溃 |
| `REDIS_HOST`（含 `REDIS_PORT`/`REDIS_DB`/`REDIS_PASSWORD`/`REDIS_USER`） | `enqueue-agent-chat-message.handler.e2e.spec.ts` | 无 `REDIS_HOST` 时整组 skip；会自动把 `HANDOFF_ROUTING_CONFIG_PATH` 指向 `docker/handoff-routing.example.yaml`，默认 `db=15` |
| `node tools/scripts/verify-runtime-recovery.mjs` | 端到端恢复验收 | 自建一次性 PostgreSQL/Redis 容器与随机端口，跑完即删，不触碰业务库与平台凭据 |

`runtime-messaging/README.md` 明写：数据库测试使用真实 PostgreSQL/TypeORM + 隔离 schema 与受控适配器，覆盖事务回滚、重复回执、等待/回复竞态、当前轮次 claim、线程准入、stop/approval 屏障、绑定撤销、恢复、投影与迁移重放；**这些测试「不构成 live Redis、已部署平台、真实模型或 Computer CLI 的验收」**，滚动策略为「先部署消费者再部署生产者」。

章节来源：[thread-run-control.md](file://packages/server-ai/src/chat-conversation/thread-run-control.md)，[runtime-messaging/README.md](file://packages/server-ai/src/handoff/runtime-messaging/README.md)，[verify-runtime-recovery.mjs](file://tools/scripts/verify-runtime-recovery.mjs)（关键符号：XPERT_EXECUTION_TEST_DATABASE_URL / XPERT_EXECUTION_TEST_REDIS_URL）

## 六、无测试与缺口

- 无 `chat.controller.spec.ts`：`POST /api/chat` 的 SSE 流与 `GET /api/chat/synthesize` 没有 HTTP 层 spec，仅有命令处理器/语音服务级用例。
- 侧边栏只有服务级 spec（`conversation-sidebar.service.spec.ts`），`ChatConversationSidebarController` 的 HTTP 校验无专测。
- `GroupScopeGuard` 的 JWT 直通分支（非 client_secret/api_key 直接放行）在 `group-scope.guard.spec.ts` 中没有断言，该 spec 只覆盖 client_secret 绑定与守卫顺序。
- 群路由中 `GroupWorkbenchGuard` 无独立 spec，仅在控制器 spec 中以 override 形式绕过。
- `chat-conversation` 的真库用例全部是 opt-in，CI 若不注入变量则整组 skip。

章节来源：[group-scope.guard.spec.ts](file://packages/server-ai/src/ai/groups/group-scope.guard.spec.ts)（关键符号：GroupScopeGuard.canActivate），[packages/server-ai/src/chat-conversation/conversation-sidebar.service.spec.ts](file://packages/server-ai/src/chat-conversation/conversation.service.spec.ts)（关键符号：ChatConversationSidebarService.list）

## 七、可执行性结论

判定：**✅ 可跑**。无 DB/Redis 依赖的 spec 可在本地直接以 jest 直连方式运行（上面的命令 1–3）；真库/真 Redis 组按上表注入变量后解锁；`verify-runtime-recovery.mjs` 提供免手工准备基础设施的端到端恢复验收。**已知失败：仓库内无任何明写的 known-fail / skip 说明记录**（`skip` 均为条件开关，不是失败豁免）。
