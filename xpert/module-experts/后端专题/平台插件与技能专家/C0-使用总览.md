## 专家定位

本专家负责「插件与技能的准入 — 落地 — 运行」闭环：插件作为包从市场来源（内置公开目录 / git / github / 平台注册表 / npm）、本地代码目录或上传归档进入平台，经 SDK 兼容校验、归属层级判定、暂存（staging）、数据库结构预检、运行期模块加载与路由/策略注册后成为进程内能力；插件导出的可移植资源（SKILL / MCP_SERVER / TOOLSET / APP / HOOK）按固定矩阵安装到工作区、智能体或组织；技能包的安装、创作、上传、分享与卸载，技能仓库与仓库索引的登记、同步与市场聚合亦归本专家。一句话：**凡涉及「这台机器装了哪些插件、装完什么时候生效、插件能力落到哪个工作区或智能体」的问题，都找这个专家。**

## 何时找这个专家

- 要装 / 卸 / 升级插件（`POST /api/plugin`、`POST /api/plugin/archive`、`POST /api/plugin/update`、`DELETE /api/plugin/uninstall`）。
- 要配市场来源：内置公开目录、自建 git / github 目录、平台注册表条目（`/api/plugin/marketplace/sources`、`/api/plugin/marketplace/registry`）。
- 要走系统初始化向导批量装插件（`/api/system/setup/plugins`）。
- 要从模板或插件把 portable 资源装到工作区 / Xpert / 组织（`/api/plugin/:name/resources/*`、模板安装命令）。
- 要启用插件导出的 MCP Server 组件并取连接信息或凭据（`/api/plugin/:name/resources/mcp/*`）。
- 要建技能仓库、登记来源、同步索引（`/api/skill-repository`、`/api/skill-repository-indexes`）。
- 要上传 / 下载 / 编辑 / 分享技能包（`/api/skill-package/*`）。
- 排查「插件装完 404 或 `EntityMetadataNotFoundError`」。
- 排查启动期插件失败、进程迟迟不就绪、日志里看不到插件配置。

本批次交付 `C0-使用总览.md` + `C1-能力契约.md` 两篇即构成该专家的自足契约面：据此可完成上文「何时找」列出的全部任务，包括选定入口、判断鉴权与作用域要求、预期返回与错误码、以及本次变更是否需要重启。契约层只承诺可达成的行为语义与交互边界；磁盘落点、并发锁的具体实现、建表细节属于实现层，不在契约承诺范围内。凡两篇契约未列出的能力或字段，一律视为「不承诺」。

## 边界

**做什么**

- 插件包的准入与安装编排、SDK 兼容与命名空间校验、结构预检、进程内装配与运行状态上报。
- 插件实例（含层级、作用域、配置、待重启标记）的持久化与可见性判定；卸载/升级护栏与重启分流。
- 插件市场来源与平台注册表的聚合、缓存、图标与详情读取。
- 已加载插件的组件到 workspace / xpert / organization 的落点安装、模板安装、App 编排、MCP 组件启用。
- 技能包与技能仓库、仓库索引的安装、创作、文件读写、分享、同步与卸载。

**不做什么**

- **不含插件 SDK 本体**：`@xpert-ai/plugin-sdk` 是已发布外部包，本专家只消费其契约（`RequestContext`、`StrategyBus`、`XpertToolProviderRegistry`、`SkillSourceProviderRegistry`、组件与状态常量），不实现也不发布它。
- **不含 `packages/plugins/*` 内置插件实现**：那是插件产出侧，不是平台侧。
- **不含 xpert / 工作区 / 工具集本体**：本专家只调用它们的服务与守卫，实体归属与生命周期归批次 3、5 专家。
- **不含 MCP 发布物的持久化与协议实现**：发布物与 API Key 归 MCP 发布模块（批次 5）；本专家只负责「启用/停用插件 MCP 组件」这一步。
- **不含对话与执行链**：Agent 会话、Hooks 的执行时机与技能中间件的 Prompt 组装归批次 3、4 专家；本专家只提供策略、配置与数据。
- **不拥有插件表的 DDL**：装配阶段只刷新 ORM 元数据，建表由插件结构预检负责。

## 已知问题与常见坑（12 条）

1. **插件路由前缀文档与代码不一致**
   - 现象：按文档拼 `/api/skill-repository/indexes` 调用返回 404。
   - 触发条件：照抄 `AGENTS.md` 的 API Endpoints 小节（写作 `indexes at /skill-repository/indexes`）。
   - 正确做法：真实控制器前缀是 `skill-repository-indexes`——索引市场读 `GET /api/skill-repository-indexes`，同步 `POST /api/skill-repository-indexes/sync/:repositoryId`。
   - 契约来源：[AGENTS.md](file://AGENTS.md)、[skill-repository-index.controller.ts](file://packages/server-ai/src/skill-repository/repository-index/skill-repository-index.controller.ts)

2. **启动期插件钩子超时/失败即致命，且启动日志不含配置与异常文本**
   - 现象：进程一直不就绪（readiness 关闭），最终被判定为替换失败；`plugin.startup.failed` 里只有 `code` 与 `stage`，看不到插件配置和异常原文。
   - 触发条件：任一插件引导钩子超过默认 30s，或插件模块无法被解析；恢复预算耗尽后进程以保活方式阻塞而非崩溃退出。
   - 正确做法：用日志中的 `code`（如 `PLUGIN_STARTUP_TIMEOUT`）+ `stage` 定位；不要期待日志含配置内容；先在库中停用/卸载可疑插件再重启，或修复后手动重启。
   - 契约来源：[plugin-startup-step.ts](file://packages/server/src/plugin/plugin-startup-step.ts)、[plugin-startup-state.ts](file://packages/server/src/plugin/plugin-startup-state.ts)、[plugin.module.ts](file://packages/server/src/plugin/plugin.module.ts)

3. **动态装配顺序不可颠倒**
   - 现象：`EntityMetadataNotFoundError`（插件实体查不到），或插件路由 404（动态路由被挂到尾部处理器之后）。
   - 触发条件：先加载插件模块再合并 ORM 元数据；或注册路由时未把新增的请求处理层前移到尾部 404/错误处理器之前。
   - 正确做法：安装、刷新与启动恢复都必须遵守「合并插件 ORM 元数据 → 载入插件模块 → 注册路由与策略」；任何绕过该顺序的加载都会失败。
   - 契约来源：[plugin-management.service.ts](file://packages/server/src/plugin/plugin-management.service.ts)、[plugin-orm-metadata.ts](file://packages/server/src/plugin/plugin-orm-metadata.ts)、[plugin-http-routes.ts](file://packages/server/src/plugin/plugin-http-routes.ts)

4. **`packageDir` 是瞬态字段**
   - 现象：从库中读回 `sourceConfig` 永远拿不到已解包目录，误判「磁盘拷贝丢失」。
   - 触发条件：该字段在持久化前被删除；HTTP 也永不允许携带（仅服务端归档上传流程内部可用）。
   - 正确做法：需要目录时永远重新暂存（code 源插件走 `POST /api/plugin/refresh`）；排查安装问题不要以库里的 `sourceConfig` 判断磁盘状态。
   - 契约来源：[source-config.ts](file://packages/server/src/plugin/source-config.ts)、[plugin.controller.ts](file://packages/server/src/plugin/plugin.controller.ts)

5. **每租户唯一公开技能仓库**
   - 现象：手工注册 `workspace-public` 仓库被拒；并发调用可能产生重复行。
   - 触发条件：`skill_repository` 上有 partial unique（`provider='workspace-public' AND organizationId IS NULL AND deletedAt IS NULL`），且 `register` 直接拒绝 `workspace-public` 与 `file` 两个 provider。
   - 正确做法：一律用 `POST /api/skill-repository/workspace-public/ensure`（幂等）获取/创建，不要手工 `POST /api/skill-repository`。
   - 契约来源：[skill-repository.entity.ts](file://packages/server-ai/src/skill-repository/skill-repository.entity.ts)、[skill-repository.service.ts](file://packages/server-ai/src/skill-repository/skill-repository.service.ts)

6. **技能 zip 上传无显式体积上限，zip-slip 防护未确认**
   - 现象：技能包上传路径的 `FileInterceptor('file')` 未声明 `limits`，实际只受全局 body/multer 配置约束；其解包实现未确认存在与插件归档等价的越界条目校验。
   - 触发条件：向 `POST /api/skill-package/workspace/:workspaceId/upload` 或 `POST /api/skill-repository/:id/upload` 上传超大或含越界路径条目的 zip。
   - 正确做法：契约层只承诺「插件归档 100MB 上限」；技能包上传的体积与条目安全**不在契约承诺范围内**，部署侧应在网关补体积限制与内容审查。
   - 契约来源：[skill-package.controller.ts](file://packages/server-ai/src/skill-package/skill-package.controller.ts)、[plugins/zip/archive.ts](file://packages/server-ai/src/skill-repository/plugins/zip/archive.ts)

7. **Hook `command` 是可执行代码边界**
   - 现象：安装 Hook 组件后，Agent 运行期会以 shell 形式执行插件声明的命令。
   - 触发条件：把 `HOOK` 组件装到 Xpert 且该 Hook 配置了命令；执行依赖沙箱后端，缺少沙箱时直接判定失败。
   - 正确做法：把 Hook 当作可执行代码做来源审查；不要把不受信任的第三方 Hook 装进受信任边界。
   - 契约来源：[plugin-hooks.middleware.ts](file://packages/server-ai/src/plugin-resource/plugin-hooks.middleware.ts)

8. **市场来源可从任意 GitHub / Git URL 拉取**
   - 现象：登记 `type: 'git' | 'github'` 来源后，平台会拉取远端仓库内容并按 `sparsePath` 寻找清单；远端内容最终会被加载进本进程。
   - 触发条件：创建或刷新市场来源（`POST /api/plugin/marketplace/sources`、`POST /api/plugin/marketplace/sources/:id/refresh`），仅需 SuperAdmin。
   - 正确做法：把「登记来源」视为引入可执行内容的授权动作；只登记可信仓库，并把 `ref` 固定到不可变版本。
   - 契约来源：[plugin-marketplace.service.ts](file://packages/server/src/plugin/marketplace/plugin-marketplace.service.ts)、[plugin-marketplace-source.entity.ts](file://packages/server/src/plugin/marketplace/plugin-marketplace-source.entity.ts)

9. **setup 向导与公开仓库保障强依赖 PostgreSQL**
   - 现象：非 PG 部署下 setup 向导直接失败；公开技能仓库的串行化写入被跳过，只剩唯一索引兜底。
   - 触发条件：向导取锁依赖 `pg_try_advisory_lock(hashtext(...))`；公开仓库写入锁仅在连接类型为 postgres 时生效。
   - 正确做法：契约上把 setup 向导与公开仓库保障视为 PostgreSQL-only；非 PG 环境不要依赖这两条路径的并发正确性。
   - 契约来源：[setup-plugins.store.ts](file://packages/server/src/plugin/setup/setup-plugins.store.ts)、[skill-repository.service.ts](file://packages/server-ai/src/skill-repository/skill-repository.service.ts)

10. **全局 `PluginScopeGuard` 与 `AuthGuard` 一起注册**
    - 现象：插件端点的作用域声明一改，等于改动**全局**鉴权面；未标注或标注为系统全局的路由直接放行。
    - 触发条件：在插件控制器上增删作用域元数据，或新增插件控制器。
    - 正确做法：改动插件路由的作用域标记必须与安全评审同步；调用方遇 403 先区分是作用域拒绝还是角色不符。
    - 契约来源：[plugin-scope.guard.ts](file://packages/server/src/shared/guards/plugin-scope.guard.ts)、[apps/api bootstrap](file://apps/api/src/bootstrap/index.ts)

11. **市场图标缓存头与 `Vary` 不可剥离**
    - 现象：图标跨租户串味，或按旧 hash 取到 404。
    - 触发条件：`GET /api/plugin/marketplace/assets/icon` 要求 `name` 必填且 `hash` 为 64 位小写 hex；响应带 `Cache-Control: private, max-age=86400, immutable` 与 `Vary: Authorization, tenant-id, organization-id, x-scope-level`。
    - 正确做法：客户端与 CDN 不得剥离 `Vary`；hash 不匹配即 404，负结果不应被缓存。
    - 契约来源：[plugin-marketplace.controller.ts](file://packages/server/src/plugin/marketplace/plugin-marketplace.controller.ts)

12. **已加载插件的作用域收敛语义容易误判**
    - 现象：同名插件在组织级、本租户全局与系统全局各有一份时，「当前生效的是哪一个」不符合直觉。
    - 触发条件：读侧收敛顺序为「当前组织 > 本租户全局 > 系统全局」，同名取**最后一条**命中记录；全局组织场景下会跳过租户级。
    - 正确做法：判断插件是否生效一律以服务端返回的描述符字段（`effectiveInCurrentScope` / `scopeRelation` / `loadStatus`）为准，不要自行按等级推断。
    - 契约来源：[effective-loaded-plugins.ts](file://packages/server-ai/src/plugin-resource/effective-loaded-plugins.ts)

## 术语与作用域速查

| 术语 | 取值 | 语义 |
| --- | --- | --- |
| `level` | `system` / `tenant` / `organization` | 插件归属层级；决定默认重启语义与可见范围（列默认 `organization`） |
| `scopeKey` | `system:global` / `tenant:<tenantId>:global` / `<organizationId>` | 实例的授权与可见性作用域键；显式值优先 |
| `runtimePolicy` | `install` / `update` / `uninstall` 各取 `hot` 或 `restart` | 未声明时 `system` / `tenant` 默认需重启、`organization` 默认热加载 |
| `pendingRestart` | `true` / `false` | 已落库但当前进程未加载；对外表现为 `PLUGIN_LOAD_STATUS.PENDING_RESTART` |
| `componentType` | `SKILL` / `MCP_SERVER` / `TOOLSET` / `APP` / `HOOK` / `ASSET` | 可移植组件类型；决定可安装目标 |
| 组件 → 目标矩阵 | organization → 仅 `TOOLSET`；workspace → `SKILL` / `MCP_SERVER` / `APP`；xpert → `HOOK` | `ASSET` 永不安装；显式选择器与目标不符即 400 |
| `sharedSkillId` | `shared-skill-<uuid>` / `template-bundle__…` / `plugin:<plugin>:skill:<key>` | 技能资产跨来源的共享标识，前缀即来源契约 |
| 索引 `mode` | `full` / `incremental` | `full` 软删未出现项；`incremental` 只增量写入；去重键为 `repositoryId + skillId` |
