# C1 · 能力契约 — 插件资源与模板安装子专家

| 项 | 值 |
| --- | --- |
| 覆盖范围 | `packages/server-ai/src/plugin-resource/**` 的对外 HTTP 面、服务面与 CQRS 契约 |
| 不覆盖 | 插件下载 / 加载 / 重启判定（子专家①）、技能包与仓库（子专家③）、MCP Publication 持久化、模板 DSL 语义 |
| 契约层约定 | 只承诺可观察行为语义与交互边界；不含私有方法名、行号与实现模式 |
| 错误码口径 | 带 `server:` / `server-ai:` 前缀者为 i18n 键；`PLUGIN_RESOURCE_*` 为 contracts 中的稳定业务码；其余为源码字面 message |

## §1 HTTP 契约

全局前缀 `/api`；除显式 `@Public()` 外均要求已认证。本子域的控制器统一挂 `TransformInterceptor`。

### 1.1 `/api/plugin/:name/resources`（组件落点与 MCP）

| 方法 | 路径 | 鉴权 | 用途与关键参数 | 主要错误 |
| --- | --- | --- | --- | --- |
| GET | `.../resources/state` | 登录态 | 组件状态：query `target`（必填，`organization` / `workspace` / `xpert`）+ `workspaceId` / `xpertId` / `agentKey`；返回 items（含 `staleDefinition`、`runtimeType`、`runtimeId`、`status`） | 400 `Query is required`；400 `target must be organization, workspace or xpert`；400 `workspaceId is required`；400 `xpertId is required` |
| POST | `.../resources/install-workspace` | 登录态（服务侧 `assertCanAuthor`） | body `{workspaceId, components[]}`；只接受 `SKILL` / `MCP_SERVER` / `APP`；返回 `{installations, pendingAuth}` | 400 `Request body is required`；400 `workspaceId is required`；404 `PLUGIN_RESOURCE_NO_MATCHING_COMPONENTS`；400 选择器与目标不匹配 |
| POST | `.../resources/install-organization` | `RoleGuard` + `SUPER_ADMIN` | body `{components[]}`；唯一合法组件类型 `TOOLSET` | 同上（目标为 organization） |
| POST | `.../resources/install-xpert` | 登录态（`assertCanAuthor(xpert.workspaceId)`） | body `{xpertId, agentKey?, components[]}`；只接受 `HOOK` | 400 `Request body is required`；400 `xpertId is required`；400 `Xpert workspaceId is required` |
| POST | `.../resources/mcp/:componentKey/enable` | `RoleGuard` + `SUPER_ADMIN` | 启用插件 MCP Server：preflight → 解析/创建 Publication → 提交能力绑定 →（非组织级插件）为当前组织开 access grant | 失败时回滚上次有效 catalog 与 Publication 快照；无请求体 |
| POST | `.../resources/mcp/:componentKey/disable` | 同上 | 组织级插件关闭 Publication 并置 `installation.enabled = false`；tenant / system 级只撤销当前组织 grant | 无请求体 |
| GET | `.../resources/mcp/:componentKey/connection-info` | 同上 | 取连接信息；要求 Publication `active`，非组织级还要求当前组织 grant 已启用 | 无请求体 |
| POST | `.../resources/mcp/:componentKey/credential` | 同上 | 一次性返回 `{connectionInfo, apiKey, secret}`；scope 由 `managedMcpClientScopes` 计算（含 MCP Apps 的 Resource scope） | 无请求体 |

**组件选择器契约**（`components[]`，用于三个安装端点）：`componentType`（6 个枚举之一）、`componentKey`（必填）、`pluginName`、`targetAgentKey`、`policyOverrides`（`enabled`、`defaultToolsApprovalMode`、`enabledTools`、`tools[<tool>.approvalMode]`，审批模式仅 `prompt` / `approve` / `deny`）、`events[]`、`auth`（`on_install` / `on_first_use`）。
- 非法选择器（缺 `componentKey`、`componentType` 不在枚举内）被**过滤掉**，`components` 为空数组视为「未选择」。
- 选择集存在但**无任何匹配组件** → 404 `PLUGIN_RESOURCE_NO_MATCHING_COMPONENTS`（message 为 `server-ai:Error.NoMatchingPluginComponents`）。
- 选择器命中但目标不支持的组件类型 → 400 `Selected plugin resources cannot be installed to <target>`。

### 1.2 `/api/plugin-applications`（App 编排，7 个端点）

| 方法 | 路径 | 鉴权 | 用途与关键参数 | 主要错误 |
| --- | --- | --- | --- | --- |
| GET | `/api/plugin-applications/status` | 登录态 | App 状态汇总（含健康检查结果；读路径最重） | 无（缺 tenant / organization 或非 ORGANIZATION scope 时直接返回 `not_installed`，不发查询） |
| GET | `/api/plugin-applications/catalog` | 登录态 | 可信 App 目录（只来自进程内已加载插件的 `meta`，不经市场响应或本地化文案） | 无 |
| GET | `/api/plugin-applications/detail` | 登录态 | query `pluginName` + `appName` | 400 `pluginName and appName are required` |
| POST | `/api/plugin-applications/initialize` | `RoleGuard`（`SUPER_ADMIN` / `ADMIN` / `TRIAL`）+ Zod `.strict()` | body 只收 `pluginName` / `appName` / `operationId` / `embeddingModelId?` / `visionModelId?` / `toolsets[{key, toolsetId}]`（≤100，`key` 唯一，`toolsetId` 必须 UUID）；**注入 `tenantId` / `organizationId` / `workspaceId` / `credentials` 一律 400** | 400 `server-ai:Error.ApplicationInitializeRequestInvalid`；400 `scope_not_supported`；400 `organization_scope_required`；400 `application_preflight_failed`；400 `application_suite_runtime_unavailable`；400 `invalid_vision_model` / `invalid_embedding_model`；400 `server-ai:Error.ApplicationToolsetProviderRequired`；400 `server-ai:Error.ApplicationToolsetConfigurationRequired`；409 `application_installation_conflict`；409 `application_assistant_name_conflict` |
| POST | `/api/plugin-applications/prepare` | 同上三角色 + Zod `.strict()` | body 只收 `{pluginName, appName}`；为配置分配工作区（先 `orIgnore` 占位再 `pessimistic_write` 锁行），**不接受任何 toolset 选择** | 400 `server-ai:Error.ApplicationInitializeRequestInvalid`；400 `server-ai:Error.ApplicationSetupScopeRequired`；400 `server-ai:Error.ApplicationSetupConflict` |
| POST | `/api/plugin-applications/bind-toolset` | 同上 | body `{pluginName, appName, key, toolsetId}`（`toolsetId` 必须 UUID）；锁内 `assertCanAuthor` 后绑定 | 400 `server-ai:Error.ApplicationInitializeRequestInvalid`；400 `server-ai:Error.ApplicationToolsetSelectionInvalid` |
| POST | `/api/plugin-applications/discard-configuration` | 同上 | body `{pluginName, appName}`；锁内校验、扫全实体后删除配置工作区与安装行 | 400 `server-ai:Error.ApplicationSetupConflict`；400 `server-ai:Error.ApplicationSetupScopeRequired` |

**App Assistant 套件相关错误码**（服务层，出现在 initialize 的解析阶段）：`server-ai:Error.ApplicationSuiteInvalidTopology`、`server-ai:Error.ApplicationSuiteUndeclaredDelegation`、`server-ai:Error.ApplicationStandaloneAssistantConnected`、`server-ai:Error.ApplicationToolsetDependencyInvalid`。

## §2 服务契约

| 服务 · 方法 | 用途 | 关键参数与行为语义 | 返回 / 异常 |
| --- | --- | --- | --- |
| `PluginResourceInstallerService.installToWorkspace(pluginName, workspaceId, components?)` | 装到工作区 | 先 `assertCanAuthor(workspaceId)`；`components` 为空表示「取全部目标合法组件」 | `{installations, pendingAuth}`；404 `NO_MATCHING_COMPONENTS` / `Plugin '<n>' has no workspace installable components` |
| `installToOrganization(pluginName, components?)` | 装到组织 | 目标固定 `organization`，因此组件类型只能是 `TOOLSET`；安装行 `workspaceId` / `xpertId` / `agentKey` 均为 `NULL` | `{installations, pendingAuth: []}` |
| `installToXpert(pluginName, xpertId, components?, agentKey?)` | 装到智能体 | 先 `getTeam(xpertId)` 并要求 `workspaceId`（否则 400 `Xpert workspaceId is required`）→ `assertCanAuthor` → `installComponentsForXpert` | `{installations, pendingAuth, xpert}` |
| `installComponentsForXpert(xpert, runtimeComponents, defaultAgentKey?)` | 落表 + 改写 draft | 逐个组件：`installRuntimeComponent` → `attachRuntimeComponent` → 若 `runtimeNodeKey` 变化或未启用则补存；最后一次性 `updateDraft`；Agent 归属顺序 `targetAgentKey ?? defaultAgentKey ?? 主 Agent` | `{installations, pendingAuth, xpert}`；400 `Xpert id and workspaceId are required` |
| `installRegisteredRuntimeToolProviderToOrganization({pluginName, componentKey, provider, sourceScopeKey})` | 组织级 runtime Provider 安装 | 只在 `XpertToolProviderRegistry` 中查找来源一致且 `componentType === TOOLSET` 的注册项；**manifest 元数据被刻意排除**；provider 名不一致即 400 | `{installation, previousInstallation, previousToolset}`；配套 `rollbackRegisteredRuntimeToolProviderInstallation(prepared)` |
| `resolveRuntimeComponents(pluginName, selectors?, target?)` | 解析安装集 | 解析加载根（当前组织 → 租户全局 → system 全局，失败即 404）→ 合并 manifest 组件与运行期 Provider 组件（按身份去重，Provider 覆盖 manifest）→ 选择器匹配（无匹配 404）→ 目标合法性过滤（显式选择器被过滤掉就 400）→ 有选择器时按 `targetAgentKey` 还原「一个组件挂多 Agent」的基数 | `RuntimeComponent[]` |
| `resolveRuntimeType(componentType)`（内部） | 组件类型 → 运行体类型 | `SKILL → skill_package`、`MCP_SERVER|TOOLSET → toolset`、`HOOK → hook_profile`、`APP → app_connector`，未知类型 400 | `PluginResourceRuntimeType` |
| `findInstallation(workspaceId, xpertId, agentKey, pluginName, componentType, componentKey)`（内部） | 安装行去重 | 工作区维度按 `workspaceId`；组织维度按 `workspaceId IS NULL` + 显式 tenant/organization 收口；xpert 维度按 `xpertId`（及 `agentKey`） | `PluginResourceInstallation | null` |
| `installRuntimeComponent(runtimeComponent, workspaceId, xpertId, agentKey?, replaceNativeCapabilityCatalog?)` | 内部安装入口 | 生成 / 复用运行体 → `status` / `config`（MCP 相关字段经 `preserveManagedMcpConfig` 保留）→ `definitionHash` 覆盖 → `enabled = true` | 已保存的安装行 |
| **参数语义**：`selectors`（组件选择器）、`declaredScope` | 作用域声明 | `declaredScope` **不是**组件安装方法的参数，它落在 `plugin_application_installation.declaredScope`（`PluginApplicationScope = tenant|organization|personal`，由可信 App 定义解析得出），并驱动 initialize 的访问判定；**当前宿主初始化仅支持 `organization`** | — |
| `applyPluginResourceOrganizationScope(query, alias?)` | 组织维度收口 | 从 `RequestContext.getScope()` 取 tenant/organization；tenant 缺失抛 400 `A tenant scope is required to manage plugin resources.`；organization 缺失时强制 `organizationId IS NULL` | QueryBuilder |
| `PluginApplicationService.getStatuses()` / `getCatalog()` / `getDetail(pluginName, appName)` | 读路径 | 全部从进程内可信注册表出发；目录按 `${pluginName}:${app.name}` 去重并内联资源，工作区 `sharing` 强制 `private` | 状态 / 目录 / 详情 |
| `PluginApplicationService.initialize(input)` | 编排写路径 | 顺序不可交换：`resolveApplication` → `operationId` 必填 → `assertInitializationAccess` → 已 `ready` 先 `refreshHealth`（仍健康即返回）→ preflight（scope / role / 模型 / toolset）→ 模型解析 → 套件校验 → `applicationToolsets.prepare` → `claimInstallation` → 逐段创建 + 分段落库 + 失败补偿 | `PluginApplicationStatusSummary`；失败置 `status = failed`、`errorCode = 'initialization_failed'` |
| `prepare(input)` / `bindToolset(input)` / `discardConfiguration(input)` | 配置三件套 | 由 `PluginApplicationSetupService` 承载；一律在行锁内执行；`discard` 仅在无 Xpert / 无知识库 / 引用仅含 workspace|toolset 且全实体扫描通过时删除 | 安装行 / 删除结果 |
| `PluginMcpServerService.enable(pluginName, componentKey)` | 启用 | preflight（`componentKey` / `provider` / `sourceScopeKey`）→ 解析或创建 Publication → 提交能力绑定；失败回滚 | `IPluginMcpServerActivationResult` |
| `disable` / `connectionInfo` / `credential` | 停用 / 连接信息 / 凭据 | 组织级与 tenant/system 级行为不同（见坑 2 类语义）；`credential` 为一次性响应 | 各自结果类型 |
| `synchronizeEnabled(...)` / `disableInstalledServers(pluginName, sourceScopeKey?)` | 生命周期收敛 | `onModuleInit` 订阅 `StrategyBus.events$`，`REMOVE`（非 refresh）与 Provider upsert 异步触发；`onApplicationBootstrap` 再补一次收敛 | `void` |
| `PluginHooksMiddleware` | 运行期 Hook | 按事件与工具名匹配后执行 `command`；`PreToolUse` 阶段任一命令失败即返回 false 阻断 | 布尔 |
| `PluginTemplateInstallCommand(templateId, workspaceId, language, basic?, publish?, locale?, capabilities[], bootstrap?)` | 模板安装契约 | `capabilities` 参与实际 templateId 计算；`bootstrap.resumeXpertId` / `onImported` **仅服务端注入**；失败且非恢复态时 `rollbackTemplateXpert` | `PluginResourceInstallResult` |
| `PluginTemplateSyncDependenciesCommand` | 依赖补跑 | 先解析依赖组件，**再**加载导入图（`XpertService.getTeam`），因为安装会改写 draft 的 middleware 绑定 | 安装结果 |
| `ListPluginResourceComponentStatesQuery(pluginName, {target, workspaceId?, xpertId?, agentKey?})` | 状态聚合 | 安装态 + `staleDefinition` + Publication 访问授权 | `IPluginResourceComponentState[]` |

## §3 示例

**示例 1 · 把模板声明的 portable 资源装进工作区**

```ts
const installer = /* PluginResourceInstallerService */
const workspaceResult = await installer.installToWorkspace('@xpert-ai/plugin-demo', workspaceId, [
  { componentType: 'skill', componentKey: 'officecli' },
  { componentType: 'mcp_server', componentKey: 'cut', policyOverrides: { defaultToolsApprovalMode: 'approve' } }
])
// 未显式选择时传 undefined，表示「该插件在 workspace 目标下的全部合法组件」
// 非法选择器被过滤；无匹配 → 404 PLUGIN_RESOURCE_NO_MATCHING_COMPONENTS；目标不支持 → 400
```

**示例 2 · App 初始化并绑定 toolset**

```ts
await applications.initialize({
  pluginName: '@xpert-ai/plugin-demo',
  appName: 'connector',
  operationId: crypto.randomUUID(),
  toolsets: [{ key: 'primary', toolsetId }]   // toolsetId 必须是 UUID
})
// 幂等：ready 且健康时直接返回；并发时由 unique scopeKey 认领，冲突方回读现状
await applications.bindToolset({ pluginName: '@xpert-ai/plugin-demo', appName: 'connector', key: 'primary', toolsetId })
```

**示例 3 · 启用 MCP 组件并取凭据**

```ts
await mcpServers.enable('@xpert-ai/plugin-demo', 'cut')        // SUPER_ADMIN
const info = await mcpServers.connectionInfo('@xpert-ai/plugin-demo', 'cut')
const oneShot = await mcpServers.credential('@xpert-ai/plugin-demo', 'cut')  // {connectionInfo, apiKey, secret}
```

语义要点：`credential` 是一次性响应，凭据**不进 App 配置面**；停用语义按插件 level 分流。
