# C1 · 能力契约 — 插件安装与运行时子专家

| 项 | 值 |
| --- | --- |
| 覆盖范围 | `packages/server/src/plugin/**` 的对外 HTTP 面与服务面 |
| 不覆盖 | 组件落点（子专家②）、技能包与仓库（子专家③）、`packages/plugin-sdk` 与内置插件实现 |
| 契约层约定 | 只承诺可观察行为语义与交互边界；不含私有方法名、行号与实现模式 |
| 错误码口径 | 带 `server:` / `server-ai:` 前缀者为 i18n 键（来自 `packages/server/src/i18n/*.json`），其余为源码中的字面 message |

## §1 HTTP 契约

全局前缀 `/api`；除显式 `@Public()` 外均要求已认证，并经过全局 `PluginScopeGuard` 的作用域比对。

### 1.3 `/api/system/setup/plugins`（初始化向导）

| 方法 | 路径 | 鉴权 | 用途与关键参数 | 主要错误 |
| --- | --- | --- | --- | --- |
| GET | `/api/system/setup/plugins` | `TenantPermissionGuard` + `RoleGuard`（`SUPER_ADMIN`） | 向导状态：`phase ∈ idle|installing|restarting|completed`，items、失败原因、重启回执 | 400 `server:Error.SetupPluginAdmin`；400 `server:Error.SetupPluginOrganization` |

### 1.4 上传与跨域约定

- **上传**：仅 `POST /api/plugin/archive`，字段名 `file`，服务端硬上限 100MB；解包支持 `.zip` / `.tgz` / `.tar.gz` / `.tar`，按魔数优先、扩展名/MIME 兜底。
- **鉴权**：除 `/marketplace/public` 外全部需要登录；`PluginScopeGuard` 全局注册，未标注或标注为系统全局即放行，否则 403 `Plugin endpoint is not available in the current tenant or organization scope`。
- **作用域来源**：控制器与服务只读 `RequestContext`（`getScope` / `getOrganizationId` / `currentTenantId`），**不接受请求体中的 tenantId / organizationId**。

## §3 示例

**示例 1 · 安装插件并判断是否需要重启**

```ts
const result = await pluginManagementService.installPlugin({
  pluginName: '@xpert-ai/plugin-demo',
  source: 'npm',
  config: { apiKey: '...' }
})
if ('restartRequired' in result && result.restartRequired) {
  // 已落 pendingRestart:true，磁盘已 staging，等待进程重启收敛
} else if ('runtimeConvergence' in result) {
  // 已热装，记录 generation 供前端轮询收敛
}
```

语义要点：`installPlugin` 的返回形状本身就是「生效时机」的契约；system/tenant 级默认走 staging 分支，organization 级默认热装，声明 `runtimePolicy` 后以声明为准。

**示例 2 · 刷新市场来源**

```ts
const source = await pluginMarketplaceService.createSource({
  name: 'team-plugins',
  type: 'github',
  url: 'owner/repo',
  ref: 'main',
  sparsePath: 'catalog',
  enabled: true
})
await pluginMarketplaceService.refreshSource(source.id)   // 单来源
await pluginMarketplaceService.refreshSources()            // 全量
```

语义要点：来源 URL / `ref` / `sparsePath` 决定拉取内容，远端即代码；刷新只更新目录快照，不触发插件安装。

**示例 3 · 按 level 与 scope 查询可见插件**

```ts
const visible = await pluginInstanceService.findVisibleInOrganization(organizationId)
const loaded = pluginManagementService.findLoadedPlugin('@xpert-ai/plugin-demo', organizationId) // 可回退全局
const scope = resolvePluginScope({ tenantId, organizationId, defaultTenantId })
// scope.scopeKey ∈ { 'system:global', 'tenant:<id>:global', organizationId }
```

语义要点：写侧 persisted 真相是 `plugin_instance`（`scopeKey` 三类取值 + `level` + `pendingRestart`）；读侧生效顺序是「当前组织 > 本租户全局 > system 全局」。
