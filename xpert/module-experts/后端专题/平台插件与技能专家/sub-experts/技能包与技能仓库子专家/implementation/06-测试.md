## 覆盖缺口
- **`SkillRepositoryController` 的业务端点无测试**：`register` / `updateRepository` / `deleteRepository`（含「系统托管仓库不可修改」分支）、`availables`、`workspace-public/ensure` 与 `:id/upload`（zip 直传）都只在 service 层被间接覆盖；控制器 spec 只覆盖 `select-options`。
- **`SkillRepositoryIndexController.sync` 无测试**：`UUIDValidationPipe`、`mode` 默认值与异常包装为 500 的逻辑未被断言；service 侧 `sync` 只有 2 个用例，`full` 模式软删、`finally` 中 `updateLastSyncAt`、缺 `skillId` 的 400、重复行告警均**没有被测试直接固定**。
- **来源策略覆盖不均**：`github` 只有 1 个用例（且只测 `scanGithubSkills` 的元数据补全），`listSkills` 的 tarball 拉取、`installSkillPackage`、`uninstallSkillPackage` 与 Bull 队列路径（`GithubRequestProcessor`）无测试；`workspace-public` 与 `zip` 两个策略**没有专属 spec**（仅在 service spec 中间接覆盖）；clawhub 是唯一被系统覆盖的策略。
- **文件系统边界**：`createWorkspaceSkillPackage` 的 4 个体积上限（50 文件 / 1MB 文本 / 5MB 二进制 / 20MB 整包）与 zip 上传路径未声明 `limits` 的事实都没有测试固定；`extractSkillsFromZip` 的归档条目安全校验（对 `../` 与绝对路径的处理）没有用例。
- **并发与锁**：`withWorkspacePublicRepositoryLock` 的 advisory lock 只在 mock 层面被断言（`skill-repository.service.spec.ts` 校验调用形状），没有真实 PostgreSQL 并发用例；`sync` 的并发重复行场景同样只有单线程模拟。
- **跨域调用链**：`PluginResourceInstallerService` 调 `syncPluginSkillBundle`、`TemplateSkillSyncService` 调 `syncTemplateSkillBundle` 分别由各自域的 spec 覆盖（如 `template-skill-sync.service.spec.ts` 断言 `validateOnly: true` 与 `skipAccessCheck: true` 的透传），本子域 spec 只覆盖被调方行为，接口形状的回归网分布在两个域。

## 可执行性结论
- **本次未实测**：该检索会话为只读任务，无终端执行能力，**没有运行上述任何命令**，因此本文所有结论均来自静态证据（spec 文件内容、用例计数、`jest.config.ts` 配置），不包含任何实测通过率、耗时或 flaky 记录。
- **可执行性判断（静态）**：命令形状与仓库约定一致（`--config packages/server-ai/jest.config.ts` + `--runTestsByPath <spec>`），`jest.config.ts` 已把 `@xpert-ai/contracts` / `@xpert-ai/plugin-sdk` / `@xpert-ai/server-core` 映射到源码，且本子域 spec 不依赖数据库、Redis 或外网（clawhub 与 GitHub 的联网用例集中在 `describe('ClawHubSkillSourceProvider live')` 一类分组，属于需要显式筛选才运行的部分）。因此**单文件级运行预期是自洽的**：`skill-package.service.spec.ts` 用 `mkdtemp` 建临时目录并自行 mock 依赖，其它 spec 全部是 mock 驱动。
- **前置条件**：仓库根目录已 `pnpm install`（`jest.preset.js`、`node_modules/jest/bin/jest.js`、`node_modules/ts-jest` 可用）；`packages/server-ai/tsconfig.spec.json` 存在；若只跑本子域，建议保留 `--runTestsByPath` 以避免触发其他域的联网/集成用例。
- **可信度分级建议**：把 `skill-package.service.spec.ts`（46 个）+ `clawhub/strategy.spec.ts`（14 个）+ `skills-middleware/index.spec.ts`（20 个）视为**可依赖的回归基线**；把 `github/strategy.spec.ts`、`skill-repository.controller.spec.ts`、`simple-skill-index.dto.spec.ts`（各 1 个）视为**符号级冒烟**；`repository-index/`、`workspace-public/`、`zip/` 的同步与直传逻辑为**待补强区**。
