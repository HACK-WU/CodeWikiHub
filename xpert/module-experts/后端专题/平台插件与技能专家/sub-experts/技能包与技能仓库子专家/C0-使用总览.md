## 子专家定位

本子专家拥有「**文件形态的智力资产**」：技能包（`skill_package`）的安装、创作、文件读写、分发与卸载；技能仓库（`skill_repository`）与仓库索引（`skill_repository_index`）的登记、同步与市场聚合；以及围绕它们的两层策略——四个来源策略（clawhub / github / workspace-public / zip）与两个 Agent 中间件策略（`SkillsMiddleware` 消费端、`SkillCreatorMiddleware` 生产端）。它的结构可以一句话概括：**仓库定义「能从哪拿」，索引定义「有哪些」，技能包定义「这里已经有一份」**；数据库只保存「索引行 + 安装行」与三个弱引用（`packagePath` / `sharedPackagePath` / `sharedSkillId`），技能内容始终是工作区 `skills/` 或组织共享目录下的真实文件。凡涉及「技能从哪来、工作区里现在有哪几份技能、某份技能怎么发到市场」的问题，都找这个子专家。

## 何时找它

- 要登记 / 修改 / 删除技能来源仓库，或查「当前可选的来源策略有哪些」（`/api/skill-repository`、`GET /api/skill-repository/source-strategies`）。
- 要把某个仓库的技能清单同步成市场可搜索的索引（`POST /api/skill-repository-indexes/sync/:repositoryId`），并纠结 `full` 还是 `incremental`。
- 要在市场里按关键词搜技能（`GET /api/skill-repository-indexes`，`search` 参数）。
- 要从索引把技能包装进工作区（单条 `install`、整仓库 `install-repository`、GitHub 直连 `install-github`）。
- 要在工作区里创作技能、读写技能目录里的单个文件、上传 / 下载技能包 zip。
- 要把工作区自建技能分享成组织共享技能并发布到公开仓库（`…/:id/share`、`POST /api/skill-repository/workspace-public/ensure`）。
- 要把公开仓库的整体 zip 直传到公开仓库（`POST /api/skill-repository/:id/upload`）。
- 要排查「技能装了但市场搜不到」「分享后 snapshot not found」「索引越同步越旧」这类问题。

## 边界

**做什么**

- 技能包安装态（`skill_package`）与工作区 `skills/` 目录下的内容、组织共享技能快照。
- 技能仓库（`skill_repository`）与仓库索引（`skill_repository_index`）的登记、同步、市场读取。
- 四个来源策略与两个 Agent 中间件策略；公开仓库的惰性创建与分享发布。

**不做什么**

- **不管插件本体与插件安装**（市场来源、安装编排、SDK 兼容、重启判定、卸载护栏）→ **子专家① 插件安装与运行时**。
- **不管插件资源落点与模板安装**（组件 × 目标矩阵、App 编排、MCP 组件启用）→ **子专家② 插件资源与模板安装**；本子专家只被其调用（`syncPluginSkillBundle`）。
- **不管工作区本体与成员权限**（工作区实体、成员/角色、访问判定实现）→ **工作区专家（批次 3）**；本子专家只消费 `WorkspaceAuthoringGuard` 与 `assertCanWrite`，不定义权限语义。
- 不拥有模板定义与 bundle 生成（`XpertTemplateService.getTemplateSkillBundles` 由 `xpert-template` 拥有、本子专家只消费）。
- 不负责 Agent 运行期的 Prompt 组装细节与技能选择策略的最终裁决（属批次 3/4 专家的调用方），本子专家只提供策略与数据。
- 不实现 `@xpert-ai/plugin-sdk` 的 `SkillSourceProviderRegistry` 本体，只提供 4 个实现并在 `skill-repository` 模块中构造导出。

## 已知问题与常见坑（12 条）

1. **索引前缀文档与实现不一致**
   - 现象：按 `/api/skill-repository/indexes/sync/:repositoryId` 调用返回 404。
   - 触发条件：照抄 `AGENTS.md`（API Endpoints 小节，`AGENTS.md:292` 写作「indexes at `/skill-repository/indexes`」）。
   - 正确做法：真实控制器前缀是 `skill-repository-indexes`——市场读 `GET /api/skill-repository-indexes`，同步 `POST /api/skill-repository-indexes/sync/:repositoryId`。
   - 契约来源：[AGENTS.md](file://AGENTS.md)、[skill-repository-index.controller.ts](file://packages/server-ai/src/skill-repository/repository-index/skill-repository-index.controller.ts)
2. **每租户唯一公开技能仓库，且必须走 `ensure` 或服务方法创建**
   - 现象：手工 `POST /api/skill-repository` 注册 `workspace-public` 被 400；并发调用理论上可能产生重复行。
   - 触发条件：`skill_repository` 上有 partial unique `IDX_skill_repository_workspace_public_tenant_unique`（`provider='workspace-public' AND organizationId IS NULL AND deletedAt IS NULL`），且 `register` 直接拒绝 `workspace-public` 与 `file`。
   - 正确做法：一律走 `POST /api/skill-repository/workspace-public/ensure` 或服务侧 `ensureWorkspacePublicRepository()`；它内部经 `withWorkspacePublicRepositoryLock` 在同一事务内取 PostgreSQL `pg_advisory_xact_lock(hashtext(tenantId), hashtext(provider))` 后「先查后建」，**非 PostgreSQL 会直接跳过该锁**，只剩唯一索引兜底。
   - 契约来源：[skill-repository.entity.ts](file://packages/server-ai/src/skill-repository/skill-repository.entity.ts)、[skill-repository.service.ts](file://packages/server-ai/src/skill-repository/skill-repository.service.ts)
3. **`publisher` 是属性名，物理列名是 `author`**
   - 现象：手写 SQL / 原生条件里用 `publisher` 查询静默查空；`findMarketplace` 的搜索永远匹配不到发布者。
   - 触发条件：`SkillRepositoryIndex.publisher` 声明为 `@Column({ name: 'author' })`；服务内搜索按 `author::jsonb ->> 'handle' | 'displayName' | 'name'` 三键提取。
   - 正确做法：写查询用 `author`，读 DTO / 序列化用 `publisher`（`SimpleSkillIndexDto` 对外仍暴露 `publisher`）。
   - 契约来源：[skill-repository-index.entity.ts](file://packages/server-ai/src/skill-repository/repository-index/skill-repository-index.entity.ts)、[skill-repository-index.service.ts](file://packages/server-ai/src/skill-repository/repository-index/skill-repository-index.service.ts)
4. **`skill_package.skillIndexId` 可空 + 外键 `onDelete: 'CASCADE'`**
   - 现象：删掉一条索引行，工作区的安装行会被数据库连带删除，但**磁盘上的 `skills/` 目录不会回收**。
   - 触发条件：`skillIndex` 为 `@ManyToOne(..., { onDelete: 'CASCADE', nullable: true })`，而级联是数据库级行为，不会回调服务层的 `strategy.uninstallSkillPackage`。
   - 正确做法：删除索引前先显式卸载技能包；把「列缺失 / 目录残留」优先当作卷问题排查。
   - 契约来源：[skill-package.entity.ts](file://packages/server-ai/src/skill-package/skill-package.entity.ts)、[skill-package.service.ts](file://packages/server-ai/src/skill-package/skill-package.service.ts)
5. **技能包写操作必须过 `WorkspaceAuthoringGuard`，判定依据是「工作区写权限」**
   - 现象：非 UUID 的 `workspaceId` 直接 400；有成员身份但无写权限仍被拒绝。
   - 触发条件：守卫取 `request.params.workspaceId`，`isUUID` 失败即 400 `server-ai:Error.WorkspaceIdInvalid`（默认文案 `A valid Workspace ID is required.`）；随后 `XpertWorkspaceAccessService.assertCanAuthor(workspaceId)` 直接转调 `assertCanWrite` → `assertCan(workspaceId, 'write')`。
   - 正确做法：把该守卫理解为「**工作区写权限**」而非「成员身份/MANAGE」；`POST /skill-package/install` 与 `DELETE /skill-package/uninstall` 未挂守卫，但服务层仍各自断言写权限，缺的只是 HTTP 级的工作区 id 前置校验。
   - 契约来源：[workspace-authoring.guard.ts](file://packages/server-ai/src/xpert-workspace/guards/workspace-authoring.guard.ts)、[workspace-access.service.ts](file://packages/server-ai/src/xpert-workspace/workspace-access.service.ts)、[skill-package.controller.ts](file://packages/server-ai/src/skill-package/skill-package.controller.ts)
6. **`sharedSkillId` 前缀即来源契约，中途改格式等于让已发布快照失联**
   - 现象：改了前缀生成规则后，同一条技能包在公开仓库里出现两条索引行，或旧快照再也找不到。
   - 触发条件：工作区分享为 `shared-skill-<uuid>`（复用既有值即覆盖发布）；模板 bundle 为 `template-bundle__<provider>__<编码仓库名>__<编码技能 id>`（由 `xpert-template` 生成）；插件组件为 **`plugin:<pluginName>:skill:<componentKey>`**（`syncPluginSkillBundle` 内部拼装）；公开仓库 zip 直传为 `workspace-public-upload__<编码路径>`。
   - 正确做法：新增来源必须复用自己的稳定前缀且幂等；不要用随机值替代。
   - 契约来源：[skill-package.service.ts](file://packages/server-ai/src/skill-package/skill-package.service.ts)、[plugin-resource-installer.service.ts](file://packages/server-ai/src/plugin-resource/plugin-resource-installer.service.ts)
7. **索引去重键是应用层契约，`incremental` 只增不减**
   - 现象：市场里出现重复技能；下架技能长期留在市场。
   - 触发条件：表上**没有** `(repositoryId, skillId)` 唯一约束；`sync` 用 `buildSkillRepositoryIndexKey` 建 Map 去重、重复旧行按 `compareSkillRepositoryIndexFreshness`（先 `updatedAt` 后 `createdAt` 降序）判新并软删多余行；仅 `mode === 'full'` 会软删「既有但本轮未返回」的行。
   - 正确做法：并发同步期间接受市场短暂重复；长期方案是周期性跑一次 `full`，不要只依赖 `incremental`。
   - 契约来源：[skill-repository-index.service.ts](file://packages/server-ai/src/skill-repository/repository-index/skill-repository-index.service.ts)
8. **软删与残留：仓库软删、索引软删、卷上目录三者互不联动**
   - 现象：`DELETE /api/skill-repository/:id` 后索引行仍能被市场读到；`full` 同步软删索引后工作区目录仍在。
   - 触发条件：仓库删除是 `deletedAt` 软删（不触发索引 CASCADE）；`findMarketplace` 只按索引行 `deletedAt IS NULL` 收敛，`leftJoinAndSelect('skill.repository')` 仍能带出已软删仓库。
   - 正确做法：删仓库视作「清理起点」而非终点，需另行清理索引与卷；排查「删了还在」时同时看三处。
   - 契约来源：[skill-repository.service.ts](file://packages/server-ai/src/skill-repository/skill-repository.service.ts)、[skill-repository-index.service.ts](file://packages/server-ai/src/skill-repository/repository-index/skill-repository-index.service.ts)
9. **技能 zip 上传无显式体积上限，归档越界校验未确认等价**
   - 现象：上传超大包或含越界路径条目的归档时，防护强度不确定。
   - 触发条件：`POST /api/skill-package/workspace/:workspaceId/upload` 与 `POST /api/skill-repository/:id/upload` 的 `FileInterceptor('file')` 均未声明 `limits`。
   - 正确做法：契约层不承诺技能包上传的体积与条目安全，部署侧在网关补体积限制与内容审查。
   - 契约来源：[skill-package.controller.ts](file://packages/server-ai/src/skill-package/skill-package.controller.ts)、[plugins/zip/archive.ts](file://packages/server-ai/src/skill-repository/plugins/zip/archive.ts)
10. **直连 GitHub 安装不落仓库行，卸载时靠 metadata 兜底**
    - 现象：卸载这类技能包时找不到对应 `skill_repository` 行。
    - 触发条件：`installGithubSkillPackages` 用内存仓库对象（`buildDirectGithubRepository`）调策略；落行时显式 `skillIndexId: null` 并把 `provenance` 写进 metadata。
    - 正确做法：理解卸载的 provider 解析顺序是 `skillIndex?.repository?.provider ?? metadata?.source`；不要指望能在仓库列表里找到它。
    - 契约来源：[skill-package.service.ts](file://packages/server-ai/src/skill-package/skill-package.service.ts)
11. **体积上限常量只覆盖「创作」一条路径**
    - 现象：以为 50 文件 / 1MB 文本 / 5MB 二进制 / 20MB 整包是全局约束，结果 zip 导入与 bundle 同步完全不受限。
    - 触发条件：四个常量仅在 `createWorkspaceSkillPackage` 中生效。
    - 正确做法：把上限理解为「创作入口的护栏」，不是技能包的存储契约。
    - 契约来源：[skill-package.service.ts](file://packages/server-ai/src/skill-package/skill-package.service.ts)
12. **`file`（zip）来源不参与索引，`sync` 的 `soft` 参数已废弃**
    - 现象：给 zip 来源建仓库后同步永远为空；带 `soft` 查询参数调用同步没有任何效果。
    - 触发条件：`ZipSkillSourceProvider.listSkills` 恒返回空数组、`installSkillPackage` 直接抛错；`soft` 在 `SkillRepositoryIndexController.sync` 中仅被 `ParseJsonPipe` 接收后忽略。
    - 正确做法：zip 只走「上传直装 / 直传公开仓库」两条路；同步接口只用 body 的 `mode`。
    - 契约来源：[plugins/zip/strategy.ts](file://packages/server-ai/src/skill-repository/plugins/zip/strategy.ts)、[skill-repository-index.controller.ts](file://packages/server-ai/src/skill-repository/repository-index/skill-repository-index.controller.ts)

## 术语与作用域速查

| 术语 | 取值 | 语义 |
| --- | --- | --- |
| `provider` | `clawhub` / `github` / `workspace-public` / `file` | 来源策略名；前两个可人工登记，后两个系统托管 |
| 索引 `mode` | `full` / `incremental` | `full` 软删本轮未出现项；`incremental` 只增不减 |
| 去重键 | `repositoryId + skillId` | 应用层维护，表上无唯一约束 |
| `skillIndexId` | 非空 / 空 | 非空＝市场安装态（不可分享、不可改 Markdown）；空＝工作区自建技能（可编辑、可分享） |
| `sharedSkillId` | `shared-skill-<uuid>` / `template-bundle__…` / `plugin:<plugin>:skill:<key>` / `workspace-public-upload__…` | 跨来源共享标识，前缀即来源契约 |
| bundle `status` | `created` / `updated` / `unchanged` / `missing` | `syncTemplateSkillBundle` 的返回状态；`missing` 仅出现在 `validateOnly` 且无公开仓库时 |
