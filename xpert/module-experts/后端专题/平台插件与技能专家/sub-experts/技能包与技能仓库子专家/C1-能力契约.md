## 鉴权约定（本子专家相关部分）

- 全局前缀 `/api`，除显式 `@Public()` 外均要求登录态；本子专家的全部端点**均需登录态**，没有公开端点。
- `WorkspaceAuthoringGuard` 判定依据：`request.params.workspaceId` 必须是 UUID（否则 400 `server-ai:Error.WorkspaceIdInvalid`，默认文案 `A valid Workspace ID is required.`），随后 `XpertWorkspaceAccessService.assertCanAuthor(workspaceId)`；其实现直接转调 `assertCanWrite` → `assertCan(workspaceId, 'write')`。**判定的是工作区写权限**，不是成员身份，也不是管理权。
- 服务侧另一道：`XpertWorkspaceBaseService` 的 `assertWorkspaceWriteAccess`（写）/ `assertWorkspaceReadAccess`（读），技能包服务统一经私有 `assertWorkspaceWritePermission` 调用前者。
- **未挂守卫的两个端点**：`POST /api/skill-package/install`、`DELETE /api/skill-package/uninstall`——它们没有 `workspaceId` 路径参数，HTTP 层不做工作区校验，但服务层仍校验写权限。

### 2.3 `SkillRepositoryIndexService`（继承 `TenantOrganizationAwareCrudService<SkillRepositoryIndex>`）

| 方法 | 用途 | 参数与行为语义 | 返回 / 异常 / 约束 |
| --- | --- | --- | --- |
| `findMarketplace(options?, search?)` | 唯一市场读路径 | 按 `tenantId` + `deletedAt IS NULL` 收敛；organization 维度命中 `organizationId = :organizationId OR organizationId IS NULL`；`where.repositoryId`（字符串或数组）与 `where.skillId` 过滤；`search` 覆盖 `name` / `skillId` / `skillPath` / `description` / `tags` / **`author::jsonb ->> 'handle'\|'displayName'\|'name'`** / `repository.name`，共 9 条 `ILIKE`；`order` 白名单 `name`/`skillId`/`skillPath`/`createdAt`/`updatedAt`，否则默认 `updatedAt DESC`；`skip`/`take` 直接透传 | `{items, total}`，每项 `repository` 经本地化 |
| `sync(repositoryId, { mode })` | 同步仓库索引 | 缺 `repositoryId` → 400 `repositoryId is required to sync skill repository indexes.`；既有行按 `compareSkillRepositoryIndexFreshness`（`updatedAt` 后 `createdAt` 降序）建 `repositoryId:skillId` Map 并把多余行记为重复；策略 `listSkills` 返回项缺 `skillId` → 400 `Skill repository index item.skillId is required.`；本轮项按同键去重（有重复打日志），逐条合并既有行后 `create`；**`mode === 'full'`** 额外把「既有但本轮未出现」的 id 与重复 id 合并 `softDelete`，`incremental` 不删任何行 | 本轮保存后的索引数组；策略异常统一转 400；`finally` 中无条件 `updateLastSyncAt(repositoryId)`；表上**无** `(repositoryId, skillId)` 唯一约束 |

## §3 代码示例

> 以下均为真实调用点节选（签名已核实）。

**① 登记技能仓库（provider 与 credentials / options 语义）** — 模板资产同步路径：

```ts
// packages/server-ai/src/xpert-template/template-skill-sync.service.ts
const saved = await this.skillRepositoryService.register({
    ...(existing?.id ? { id: existing.id } : {}),
    name,
    provider,
    options: repositoryEntry.options ?? null,
    credentials: repositoryEntry.credentials ?? null
} as SkillRepository)
```

语义：`provider` 必须来自 `GET /api/skill-repository/source-strategies` 的可选集（`clawhub` / `github` 等）；`workspace-public` 与 `file` 会被 400 拒绝。`credentials` 是 jsonb 自由对象——github 策略读 `credentials.token`，缺省回落 `process.env.GITHUB_TOKEN`；`options` 同为 jsonb——clawhub 读 `officialOnly` / `maxSkills` 等（默认 `maxSkills = 100`）。二者不传时显式写 `null`，以便与「配置变化」的比较保持一致。

**② 同步索引：`incremental` 与 `full` 各一次真实调用** — 同一调用点的两种模式：

```ts
// packages/server-ai/src/xpert-template/template-skill-sync.service.ts
const mode: TemplateSkillSyncMode = input.mode ?? 'incremental'   // 'incremental' | 'full'

const syncedItems = await this.skillRepositoryIndexService.sync(repository.repositoryId, { mode })
// 返回：本轮保存后的索引项数组；长度 0 表示策略未返回任何技能
const status: TemplateSkillSyncStatus = syncedItems.length ? 'updated' : 'unchanged'   // 'created' | 'updated' | 'unchanged' | 'missing' | 'failed'
```

```ts
// full：额外把「既有但本轮未出现」的索引行 softDelete；incremental 只增不减
await this.skillRepositoryIndexService.sync(repositoryId, { mode: 'incremental' })
await this.skillRepositoryIndexService.sync(repositoryId, { mode: 'full' })

// HTTP 等价入口（SkillRepositoryIndexController.sync）：
// POST /api/skill-repository-indexes/sync/<repositoryId>
// { "mode": "full" }        // 缺省 incremental；query 参数 soft 已废弃并被忽略
```

**③ 从仓库安装技能包到工作区** — 启动与默认技能回灌路径：
