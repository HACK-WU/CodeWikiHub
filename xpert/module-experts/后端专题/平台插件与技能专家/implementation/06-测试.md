## 1. 分布总览与命名惯例

本范围四个目录共 **69** 个 spec：`packages/server/src/plugin` 39、`packages/server-ai/src/plugin-resource` 16、`packages/server-ai/src/skill-package` 7、`packages/server-ai/src/skill-repository` 7。

- **命名惯例**：测试文件与被测文件同目录同名前缀，后缀 `.spec.ts`；HTTP 端到端用例用 `.http.spec.ts`；真正依赖外部服务的用 `.integration.spec.ts`。子目录内继续沿用被测模块结构（`commands/handlers/`、`queries/handlers/`、`application-toolsets/`、`repository-index/`、`plugins/<strategy>/`）。
- **标记治理**：范围内无 `it.only` / `describe.only`；`describe.skip` 仅出现在两个按环境变量开关的 integration spec 中（条件三元，非硬编码跳过）。

章节来源：[plugin.controller.spec.ts](file://packages/server/src/plugin/plugin.controller.spec.ts)（关键符号：describe PluginController）、[skill-package.service.spec.ts](file://packages/server-ai/src/skill-package/skill-package.service.spec.ts)（关键符号：describe SkillPackageService）

## 2. 框架与运行方式

- **框架**：Jest + `ts-jest`（`tsconfig: '<rootDir>/tsconfig.spec.json'`），`testEnvironment: 'node'`，preset `../../jest.preset.js`；`transformIgnorePatterns` 由种子包列表递归解析依赖生成，允许转换 `@xpert-ai/plugin-sdk` 等 ESM 包。
- **两个 config 的差异**：`packages/server/jest.config.ts`（displayName `server`）只映射 `@xpert-ai/contracts`；`packages/server-ai/jest.config.ts`（displayName `server-ai`）额外映射 `@xpert-ai/server-core` → `packages/server/src/index.ts`、`@xpert-ai/plugin-sdk`、`@xpert-ai/cli-model-profiles`、`@xpert-ai/shadcn-ui/brand-icons`（`.cts`），并支持 `cts` 扩展名与 pnpm 路径形式的转换白名单。**跨包测试必须用对应包自己的 config**，否则会解析不到 `@xpert-ai/server-core` 等别名。
- **实测命令**（工作目录 `/root/xpert`，单文件运行为秒级）：

```bash
node node_modules/jest/bin/jest.js --config packages/server/jest.config.ts \
  --runTestsByPath /root/xpert/packages/server/src/plugin/plugin.controller.spec.ts
node node_modules/jest/bin/jest.js --config packages/server-ai/jest.config.ts \
  --runTestsByPath /root/xpert/packages/server-ai/src/skill-package/skill-package.service.spec.ts
```

章节来源：[packages/server/jest.config.ts](file://packages/server/jest.config.ts)（关键符号：moduleNameMapper）、[packages/server-ai/jest.config.ts](file://packages/server-ai/jest.config.ts)（关键符号：transformIgnorePatterns）

## 3. 断言与 mock 风格

- **纯单测直构**：`new XxxController(service as never)` + `jest.fn()` 提供 service，只断言调用参数与返回值（`skill-repository.controller.spec.ts`、`skill-repository-index.controller.spec.ts`），其中后者还用 `Reflect.apply` 直接调用 `findAll` 以覆盖 `$take`/`$skip` 字符串归一化。
- **装饰器元数据断言**：用 `ROLES_METADATA`、`GUARDS_METADATA`、`PATH_METADATA`、`METHOD_METADATA`、`HEADERS_METADATA` 校验鉴权/角色/路由与缓存头是否被改动（`plugin-resource.controller.spec.ts`、`plugin-marketplace.controller.spec.ts`）。
- **真实 Nest HTTP 集成**：`Test.createTestingModule` + `app.listen(0, '127.0.0.1')` + `fetch`，通过 `overrideGuard(RoleGuard).useValue({ canActivate: () => allowed })` 切换角色放行，断言状态码（201/202/400/403）与「service 未被调用」（`application-initialize.http.spec.ts`、`setup-plugins.controller.spec.ts`）；测试内先 `init({ lng: 'en', resources: ... })` 提供 i18n 词条。无真实数据库断言。
- **模块级 mock**：`jest.mock('./xxx.service', () => ({ XxxService: class {} }))` 占位以避开 `@xpert-ai/server-core` 依赖；对 `@xpert-ai/plugin-sdk`、`typeorm`、`@xpert-ai/server-config` 做显式手写 mock（`plugin-instance.loader.spec.ts`、`plugin-marketplace-shared.integration.spec.ts`）。
- **文件系统夹具**：`fs.mkdtempSync(os.tmpdir())` 造目录，`execFileSync('tar', ['-czf', ...])` 造真实 tgz，`afterEach` 递归清理；断言异常类型与消息（`plugin-archive.spec.ts` 期望 `BadRequestException` 且消息含 `Failed to extract plugin archive bad.zip`）。

章节来源：[plugin-resource.controller.spec.ts](file://packages/server-ai/src/plugin-resource/plugin-resource.controller.spec.ts)（关键符号：PluginResourceController.installOrganization）、[application-initialize.http.spec.ts](file://packages/server-ai/src/plugin-resource/application-toolsets/application-initialize.http.spec.ts)（关键符号：describe application initialize HTTP validation）、[plugin-archive.spec.ts](file://packages/server/src/plugin/plugin-archive.spec.ts)（关键符号：extractPluginArchive）

## 5. 需真依赖的用例与开启方式

- **PostgreSQL（schema 同步）**：`plugin/plugin-schema-scope.integration.spec.ts` 以 `process.env.XPERT_SCHEMA_TEST_DATABASE_URL ? describe : describe.skip` 开关；开启后创建随机 schema、`scopePluginSchemaSynchronization` + `dataSource.synchronize()` 断言仅更新目标插件表，含 30s 超时与 `DROP SCHEMA ... CASCADE` 清理。
- **Redis + PostgreSQL（市场多副本共享缓存）**：`marketplace/plugin-marketplace-shared.integration.spec.ts` 需同时存在 `MARKETPLACE_TEST_REDIS_URL` 与 `MARKETPLACE_TEST_POSTGRES_URL` 才运行，用两个 redis client / 两个 DataSource 模拟副本，验证共享缓存与分布式锁。
- **文件系统相关（无需额外环境变量）**：`plugin-archive.spec.ts`（写临时 tgz/zip）、`plugin-instance.loader.spec.ts`（mock 掉 typeorm 与 DB 探测）、`plugin-marketplace-shared.integration.spec.ts` 内的临时目录构造。
- **开启方式**：导出上述环境变量（例如 `XPERT_SCHEMA_TEST_DATABASE_URL=postgres://...`）后，用 2 节中对应包的 jest config 定向运行这两个文件即可；未设置时它们会整组 `describe.skip`，不影响其余 67 个 spec。

章节来源：[plugin-schema-scope.integration.spec.ts](file://packages/server/src/plugin/plugin-schema-scope.integration.spec.ts)（关键符号：describePostgres）、[plugin-marketplace-shared.integration.spec.ts](file://packages/server/src/plugin/marketplace/plugin-marketplace-shared.integration.spec.ts)（关键符号：integration 开关）、[plugin-instance.loader.spec.ts](file://packages/server/src/plugin/plugin-instance.loader.spec.ts)（关键符号：jest.mock('@xpert-ai/server-config')）

## 7. 测试可执行性结论

- ✅ **可跑**：69 个 spec 均可执行，无 `.only` 阻塞；跨包用例必须使用各自包的 jest config（`packages/server/jest.config.ts` 与 `packages/server-ai/jest.config.ts`），单文件定向运行实测为秒级。
- ⏭️ **PG/Redis 用例自动 skip**：未设置 `XPERT_SCHEMA_TEST_DATABASE_URL`（schema 作用域）或 `MARKETPLACE_TEST_REDIS_URL` + `MARKETPLACE_TEST_POSTGRES_URL`（市场多副本）时整组跳过，套件不会失败但相应能力未被验证；CI 需要这部分覆盖时必须显式注入这三个变量。
- 📄 **文件系统用例免依赖**：归档解包与 loader 用例使用临时目录与手写 mock，不需要数据库或外部服务即可运行。
- 🧭 **优先级建议**：改动 05 文档所述路由/守卫时，至少回归 `plugin.controller.spec.ts`、`plugin-resource.controller.spec.ts`、`plugin-marketplace.controller.spec.ts`、`skill-repository-index.controller.spec.ts` 与 `application-initialize.http.spec.ts`。
