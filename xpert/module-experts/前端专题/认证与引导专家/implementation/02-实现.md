## 登录链

**页面**：`UserLoginComponent` 构造 `FormGroup{userName, password, rememberMe}`（`mobile` / `captcha` 已被注释，但 `submit()` 仍保留 `type === 1` 分支与 `getCaptcha()`），从 `XP_AUTH_OPTIONS` 读 `forms.login.{showMessages,redirectDelay,strategy}` 与 `forms.register.enablePublicSignup`；`checkRememberdMe()` 从 cookie 回填 `email` / `rememberMe`。

**提交**：`submit()` 做手工 dirty 校验后 `firstValueFrom(this.authService.authenticate(this.strategy, {...form.value, userName: userName.toLowerCase()}))`。

**分发与落盘**：`XpAuthService.authenticate('email', data)` → `getStrategy('email')` → `AuthStrategy.authenticate({userName,password,rememberMe})` → 组装 `IUserLoginInput{email,password}` → `AuthService.login()`（`POST /api/auth/login`）→ `map` 内写 `store.userId / store.token / store.refreshToken`、`store.restoreRememberedScope(user.id)`、`store.user`，返回 `XpAuthResult(true, res, '/', [], messages)`；`tap(() => this.rememberMe(args))` 用 `CookieService` 写/删 `email` 与 `rememberMe`。因为 `XpAuthResult` 未携带 token 对象，`processResultToken` 不触发。

**跳转**：页面取 `route.snapshot.queryParams.returnUrl || result.getRedirect()`，`redirectDelay` 后 `router.navigateByUrl(redirect)`（默认 `/`）。SSO 错误通过 query 参数在页面上解析：`error`（`invalid_credentials` / `invalid_tenant` / `interaction_expired` 映射表）、`ssoMessage`、`ssoError + ssoProvider`。

章节来源：[login.component.ts](file://apps/cloud/src/app/auth/login/login.component.ts)（关键符号：`UserLoginComponent.submit`、`resolveSsoErrors`、`checkRememberdMe`）、[auth-strategy.service.ts](file://apps/cloud/src/app/@core/auth/auth-strategy.service.ts)（关键符号：`AuthStrategy.authenticate`、`AuthStrategy.login`、`rememberMe`）

## 策略族实现

**抽象基类** `XpAuthStrategy`：`setOptions(options)` 以 `deepExtend({}, defaultOptions, options)` 合并；`getOption(key)` 走 `getDeepFromObject`（点号路径）；`createToken(value, failWhenInvalidToken)` 用 `getOption('token.class')` 造 token，无效即抛 `NbAuthIllegalTokenError`；`getActionEndpoint(action)` 拼 `baseEndpoint + <action>.endpoint`；另有 `createFailResponse` / `createSuccessResponse`。6 个抽象动作：`authenticate` / `register` / `requestPassword` / `resetPassword` / `logout` / `refreshToken`，外加 `getName()`（读 `options.name`）。

**现役 email 策略** `AuthStrategy extends XpAuthStrategy`（`@core/auth`）：`static setup({name}) → [AuthStrategy, options]`；`name` 由 `XpAuthOptions` 传入 `'email'`；动作全部委托 `@core/state` 的 `AuthService`，并自持 `static config`（login/register/logout/requestPass/resetPass 的 redirect 与默认文案）与 `refreshTokenReq = signal<Observable<XpAuthResult>>(null)` 做刷新合流。

**通用策略模板** `XpPasswordAuthStrategy`：完整实现 6 个动作（`http.request(method, url, {body, observe:'response'})` + `handleResponseError`），默认 `baseEndpoint = '/api/auth/'`、`login.endpoint = 'login'`、`resetPass.resetPasswordTokenKey = 'reset_password_token'`（从 `ActivatedRoute.queryParams` 取）；**未在策略表注册**，仅被 `password-strategy.spec.ts` 覆盖（该 spec 用 `baseEndpoint: '/api/auth/custom/'` 验证 6 条端点）。`NbDummyAuthStrategy` 同理（`delay` + `alwaysFail`）。`XpPasswordAuthStrategy.setup(options)` 是两者共用的注册范式。

**新增策略的接入点（三步）**：① 写 `class X extends XpAuthStrategy` 并实现 6 动作 + `static setup`；② 在 `AuthModule` 的 `XpAuthModule.forRoot({ strategies: [X.setup({ name: 'x' })] })` 加一项；③ 在 `defaultAuthOptions.forms.<form>.strategy` 或页面传参里把 `strategyName` 指过去。**只写策略类不注册表 → 调用时运行期 `TypeError`**。

章节来源：[auth-strategy.ts](file://apps/cloud/src/app/auth/strategies/auth-strategy.ts)（关键符号：`XpAuthStrategy.setOptions`、`createToken`、`getActionEndpoint`）、[auth-strategy.service.ts](file://apps/cloud/src/app/@core/auth/auth-strategy.service.ts)（关键符号：`AuthStrategy.setup`、`refreshToken`）、[password-strategy.ts](file://apps/cloud/src/app/auth/strategies/password/password-strategy.ts)（关键符号：`XpPasswordAuthStrategy.handleResponseError`、`resetPassword`）、[password-strategy-options.ts](file://apps/cloud/src/app/auth/strategies/password/password-strategy-options.ts)（关键符号：`passwordStrategyOptions`）

## 注册与密码链

**注册**：`UserRegisterComponent.register()` 先 `validateReferralCode()`（返利码若启用则 `ReferralService.validateCode`，不通过直接 `return`），再 `service.register('email', form.getRawValue())` → `AuthStrategy.register`：先在**客户端**比对 `password !== confirm`（不等直接返回失败 `XpAuthResult`），再把 `fullName` 拆成 `firstName/lastName` 组装 `IUserRegistrationInput{user{...}, password, confirmPassword, referralCode}`，调 `AuthService.signup()`（`POST /api/auth/signup`）；成功返回 `XpAuthResult(true, null, false, [], [])`（**不带 token，自动登录的 `switchMap(login)` 已被注释**），页面提示"Signup success, please active the link in your email"；错误按状态映射：`409` → `err.error?.error`，`400` → `err.error?.message`，其余 → 默认文案。`enablePublicSignup` 来自 `environment.deploymentTarget !== 'customer-onprem'`，为假且无 `ticket` 时构造期直接 `navigate(['/auth/login'])`。

**忘记密码**：`ForgotPasswordComponent.requestPass()` → `XpAuthService.requestPassword('email', {email})` → `AuthStrategy.requestPassword` → `AuthService.requestPassword`（`POST /api/auth/request-password`）；失败抛 `result.getErrors()[0]` 并 toast 失败文案，成功 toast `Auth.RequestPasswordSuccess`（页面**不跳转**）。

**重置密码**：`ResetPasswordComponent.resetPass()` → `XpAuthService.resetPassword('email', form.value)` → `AuthStrategy.resetPassword`：`route.snapshot.queryParamMap.get('token')` 取重置 token，两端密码不一致直接返回失败结果；否则 `AuthService.resetPassword({token,password,confirmPassword})`（`POST /api/auth/reset-password`），成功后 `delay(2000)` 再 `router.navigate(['/auth/login'])`。表单校验为 `minLength(8)` + `matchValidator('password','confirmPassword')`，强度用 `passwordStrength()` 映射 4 档。

章节来源：[register.component.ts](file://apps/cloud/src/app/auth/register/register.component.ts)（关键符号：`UserRegisterComponent.register`、`validateReferralCode`、`loadSsoProviders`）、[forgot-password.component.ts](file://apps/cloud/src/app/auth/forgot-password/forgot-password.component.ts)（关键符号：`ForgotPasswordComponent.requestPass`）、[reset-password.component.ts](file://apps/cloud/src/app/auth/reset-password/reset-password.component.ts)（关键符号：`ResetPasswordComponent.resetPass`、`strength`）

## 邀请接受与邮箱验证

**接受邀请**：路由 `/auth/accept-invite` 懒加载 `AcceptInvitePageComponent`，**唯一带显式例外的准入页**——`NoAuthGuard.canAccessInviteRoute` 在 `routeConfig.path === 'accept-invite'` 且同时存在 `email` 与 `token` 查询参数时直接放行（允许已登录用户走邀请链）。组件 `ngOnInit` 订阅 `route.queryParams` → `loadInvite(email, token)` → `InviteService.validateInvite(['role','organization'], {email, token})`，失败置 `inviteLoadErrorMessage = 'Invitation no longer valid'`。表单由 `AcceptInviteFormComponent` 承担（`fullName` / `password` / `repeatPassword` / `referralCode`（默认 disabled，`ReferralService.getAvailability(invitation.tenantId)` 开启）/ `agreeTerms`），提交回调 `submitForm` 走 `InviteService.acceptUserInvite({user, password, referralCode, organization, inviteId})`，成功后 toast `Auth.ACCEPT_INVITE.PROFILE_UPDATED` 并 `navigate(['/auth/login'])`（**不自动登录**）。

**邮箱验证**：`VarifyEmailComponent` 构造即订阅 `route.queryParams`（`startWith(snapshot)`）→ `AuthService.verifyEmail(token)`（`GET /api/auth/verify?token=`），成功置 `Auth.VarifyEmailSuccess`，失败把 `err.error` 当消息展示；页面不发任何写操作。

**返利码跨页保持**：`referral-registration-session.ts` 提供 `save/get/clearRegistrationReferralCode`，键 `xpert.registration.referral-code` 存 **sessionStorage**，被 register（`?ref=` 入参即存）、sso-bind（跳注册时透传）、accept-invite-form 复用，注册/绑定成功后 `clear`。

## OIDC 与 SSO 双轨

**轨道 A：SSO 登录入口（登录页内）**。`UserLoginComponent` 用 `toSignal(http.get('/api/auth/sso/providers'))` 拉到 `SSOProviderDescriptor[]`（`provider/displayName/icon/order/startUrl`，失败降级 `[]`），`openProvider()` 用 `new URL(provider.startUrl, origin)` 并透传 `returnTo`，最终 `window.location.assign()` 硬跳。回跳后由 query 参数区分成功/失败（同登录链的 `resolveSsoErrors`）。

**轨道 B：SSO 绑定（票据两跳）**。`/auth/sso-bind`：`route.queryParamMap` 取 `ticket` → `loadChallenge()` 打 `GET /api/auth/sso/bind/challenge?ticket=`；两条出路——「打开已有账号表单」（`mode='login'`，`POST /api/auth/sso/bind/complete {ticket,userName,password}`）或「去注册」（`navigate(['/auth/register'], {queryParams:{ticket, ref}})`）。`/auth/sso-confirm`（当前登录用户确认）：`GET /api/auth/sso/bind/current-user/challenge` → `POST /api/auth/sso/bind/current-user/complete {ticket}`。两页统一按 HTTP 状态落文案：`400` → 票据过期（清 `challenge` 回挑战态）、`401` → 凭据/登录态失效、`409` → 身份冲突，成功后 `window.location.assign(result.location)` 交还后端。

**轨道 C：OIDC consent**。`/auth/consent` 仅在 `environment.mcpOAuthEnabled` 为真时注册（当前三份 environment 均为 `false`）。`OidcConsentComponent` 从查询参数取 `interaction`，用 `inject(XP_API_BASE_URL)`（`normalizeApiBaseUrl(environment.API_BASE_URL)`）拼 `GET ${base}/oidc/interaction/:id/consent`（`withCredentials: true`）渲染 `clientId/clientName/scopes/resources`；`allow()` / `deny()` 通过动态创建 `<form method="post">` + 隐藏 input `decision` **原生提交**到同一路径（不返回 JSON，直接由后端 302）。

章节来源：[sso-bind.component.ts](file://apps/cloud/src/app/auth/sso-bind/sso-bind.component.ts)（关键符号：`SsoBindComponent.loadChallenge`、`submit`、`handleSubmitError`）、[current-user-sso-confirm.component.ts](file://apps/cloud/src/app/auth/current-user-sso-confirm/current-user-sso-confirm.component.ts)（关键符号：`CurrentUserSsoConfirmComponent.submit`、`loadChallenge`）、[consent.component.ts](file://apps/cloud/src/app/auth/consent/consent.component.ts)（关键符号：`OidcConsentComponent.submitDecision`、`XP_API_BASE_URL`）

## 登出与令牌清理

**入口**：`/auth/logout` → `XpLogoutComponent.ngOnInit()` 立即 `logout(strategy)`（strategy 取 `forms.logout.strategy` = `'email'`）。

**链路**：`XpAuthService.logout('email')` → `AuthStrategy.logout()` → `from(this._logout())`。`_logout()` 的顺序是刻意设计的：① 先 `new HttpContext().set(SKIP_AUTH_REFRESH, true)`，② `DELETE artifactShareSessionUrl()`（`/api/artifacts/share-session`，`withCredentials`）并 `timeout(5000)`，失败被 `catch` 吞掉（注释：Logout must still clear local authentication if the API is offline）；③ `this.authService.logout()`——**`@core/state` 的 `AuthService.logout()` 是空实现**（原 `patchState` 已注释），即登出**不调用任何后端认证端点**；④ `store.clear()`（akita 重置：`token/refreshToken/userId/...` 清空）；⑤ `store.serverConnection = 200` 复位连接态。

**收尾**：`XpAuthService.logout` 在 `result.isSuccess()` 时再 `tokenService.clear()`（删 `localStorage.auth_app_token`，生产中通常本就不存在），返回 `redirect = '/'`；`XpLogoutComponent` 按 `forms.logout.redirectDelay` 延时 `router.navigateByUrl('/')`，随后由 `authGuard` 把用户带到 `/auth/login?returnUrl=...`。刷新失败路径另有一条：`TokenInterceptor` 捕获 `auth/refresh` 自身 401 时直接 `this.auth.logout().subscribe()`。

章节来源：[logout.component.ts](file://apps/cloud/src/app/auth/logout/logout.component.ts)（关键符号：`XpLogoutComponent.logout`）、[auth-strategy.service.ts](file://apps/cloud/src/app/@core/auth/auth-strategy.service.ts)（关键符号：`AuthStrategy._logout`、`SKIP_AUTH_REFRESH`）、[auth.service.ts（@core/state）](file://apps/cloud/src/app/@core/state/auth.service.ts)（关键符号：`AuthService.logout`）

## 守卫族实现

**`authGuard`（函数式，主力）**：`inject(Router/Store/AuthStrategy)` → `!!store.token` 为真即放行；否则先 `await firstValueFrom(authStrategy.logout())`（清本地台账）再 `router.navigate(['/auth/login'], {queryParams:{returnUrl: state.url}})` 返回 `false`。挂载点：`app-routing.module.ts` 的 `artifacts/auth/:artifactLinkSlug`，以及 `features-routing.module.ts` 的十余条路由；`onboarding-routing.module.ts` 的 `plugins` 步也用它。

**`NoAuthGuard`（auth 包，类式）**：判定顺序为「`accept-invite` + `email` + `token` 例外 → `!store.token` 放行 → `await XpAuthService.isAuthenticated()` 为假放行 → 否则 `router.navigate(['/home'])`」。挂载于 `request-password` / `reset-password` / `accept-invite` / `verify` 四条路由。

**`onboardGuard`（函数式，返回 Observable）**：`TenantService.getOnboard()`（内部 `shareReplay(1)` 的 `#isOnboarded`）→ `onboard.tenant` 有值则 `/home/`，`onboard.error` 则 `/onboarding/unknown`，都不是则放行。同一判据在 `AppInitService.init()` 里再走一遍，实现「刷新直达 /onboarding」与「已初始化直达 /home」双向收敛。

**`inviteGuard`（函数式，**当前未挂载**）**：读 `route.data.expectedPermissions`，`combineLatest([store.userRolePermissions$ → store.hasPermission, store.selectedOrganization$ → organization?.invitesAllowed])`，两者皆真才放行，否则 `router.navigate(['/'])`（`tap` 副作用写法，返回值即布尔流）。

**`dirtyCheckGuard` / `DirtyCheckGuard`**：类式 `DirtyCheckGuard.canDeactivate`（已标 `@deprecated`）同时兼容 `component.isDirty$()`（函数）与 `component.isDirty()`（signal），脏则 `ZardAlertDialogService.confirm` 弹「ConfirmExitDirtyData」；函数式 `dirtyCheckGuard` 是其精简重申，`take(1)` 收尾。使用方为 `features/setting/integration/routing.ts`（三处 `canDeactivate: [DirtyCheckGuard]`）与 `features.module.ts` providers。

## 热点路径

1. **全站每次请求**：`TokenInterceptor.addAuthenticationToken`（`store.token` 或 `store.refreshToken` 拼头）→ `APIInterceptor` / `LanguageInterceptor` / `TenantInterceptor` 串行；这是本域被调用频次最高的代码。
2. **登录提交**：`UserLoginComponent.submit` → `XpAuthService.authenticate` → `AuthStrategy.login` → `POST /api/auth/login` → `Store` 六次写入（含 `restoreRememberedScope`）。
3. **401 刷新风暴**：`TokenInterceptor.intercept` 的 `refreshTokenInProgress` 分支 + `AuthStrategy.refreshToken` 的 `signal` 合流，任一环节改动都会影响对话 socket 重连。
4. **准入判定**：`authGuard`（每次路由切换，纯内存）；`onboardGuard` → `TenantService.getOnboard()`（有 `shareReplay(1)`，但首次会打 `GET /api/tenant` 类接口）。
5. **向导步 2**：`tenantService.onboard` → `POST /api/tenant/onboard`（列在 `ANONYMOUS_AUTH_PATHS`）→ `authStrategy.login()` 自动登录 → `stepper.next()`。
6. **向导步 3**：`SetupPluginsService.status/start` 2s 轮询直到 `completed`，然后整页 `location.assign('/')`。
7. **登出**：`DELETE /api/artifacts/share-session`（5s 超时、吞错）→ `store.clear()` → `/` → `authGuard` 兜到登录页。

## 技术债与 hack

1. **令牌容量双轨（最高风险）**：auth 包 `XpAuthTokenService` + `XpTokenLocalStorage('auth_app_token')` 与 `Store.persist.token` 并存；email 策略从不返回 token 对象，`processResultToken` 不触发 → 现场只有 `Store` 有值。[推测] 由此推断 `NoAuthGuard` 第二段 `XpAuthService.isAuthenticated()` 在生产中恒为 `false`，该分支只能放行不能拦截；`onTokenChange` / `onAuthenticationChange` / `isAuthenticatedOrRefresh` 三件套全仓无消费方（仅 `auth.component.ts` 注释提及"showcase"）。
2. **`XP_AUTH_TOKENS` 工厂返回 `{}` 而非数组**：`{ provide: XP_AUTH_TOKENS, useFactory: () => ({}) }`。[推测] 若 `localStorage.auth_app_token` 里存在历史写入的合法 JSON 包，`XpAuthTokenParceler.getClassByName` 会执行 `{}.find(...)` 抛 `TypeError`（当前因无写入方而未被触发）。
3. **登出不通知后端**：`AuthStrategy._logout()` 只删 `/api/artifacts/share-session`（5s 超时、吞错）后本地清库；`@core/state` 的 `AuthService.logout()` 是空方法（`patchState` 被注释），因此**没有 `POST /api/auth/logout`**。ki 归档的 `/api/auth/custom/logout` 与现役链路不符。
4. **端点口径修正**：ki 路标记的 `/api/auth/custom/{login,register,logout,refresh-token,request-pass,reset-pass}` 实测只见于 `XpPasswordAuthStrategy` 的默认模板与 `password-strategy.spec.ts`（该 spec 显式 `baseEndpoint: '/api/auth/custom/'`）；现役 email 策略使用 `C_API_AUTH = '/api/auth'` 下的 `/login`、`/signup`、`/refresh`、`/request-password`、`/reset-password`、`/verify`、`/authenticated`、`/alive`。
5. **未挂载/死代码**：`inviteGuard`（无路由引用）、`@core/auth/no-auth.guard.ts` 的 `NoAuthGuard`（跳转目标 `/pages/dashboard` 已不存在）、`NbDummyAuthStrategy`、`XpPasswordAuthStrategy`、`auth/components/*`（`XpMenuGroupComponent` / `XpMenuItem` 均标注 `@deprecated ... during auth package migration`）。
6. **命名遗留**：`NbAuthSimpleToken` / `NbAuthJWTToken` / `NbAuthIllegalTokenError` / `NbAuthSocialLink` / `nbStrategiesFactory` / `NbStrategyToken` 与 `Xp*` 前缀混用，`XpAuthStrategyOptions` 内仍引用 `NbStrategyToken`。
7. **登录页残枝**：`mobile` / `captcha` 控件已从表单移除，但 `submit()` 仍保留 `type === 1` 分支、`getCaptcha()` 仍访问 `this.mobile` / `this.captcha`（`form.controls` 不存在 → 若被触发将抛错）[推测]。
8. **两套「NoAuthGuard」+ 两套「authGuard」同名不同物**：`@core/auth` 与 auth 包各一份 `NoAuthGuard`（判据与跳转目标不同），`xpert/routes.ts` 另有语义完全不同的 `authGuard`（按 xpert 授权判定），检索与评审极易误伤。
9. **配置漂移**：密码最小长度三处不一致（注册页 `minLength(6)`、重置页与向导 `minLength(8)`；`defaultAuthOptions.forms.validation.password.minLength = 4`）；返利码存 sessionStorage（新标签即失效）、rememberMe 存 cookie、令牌存 localStorage，三种存储语义无统一约定。
10. **向导不可回退**：`plugins` 步完成后 `location.assign('/')` 整页重载；`attention` 阶段直接 `return` 让用户停在页面，无重试按钮文案兜底；`tenant-details` 的 `onStepChange` 在 `selectedIndex === 2` 时直接跳外链式导航，步骤语义与 URL 不是一一对应。

## 设计维度

1. **入口单一化 vs SSO 双轨**：策略表把「表单类认证」收敛为 `strategyName`，但 SSO/OIDC 走独立页面与后端票据（不经 `XpAuthService`）。维度上的取舍是：**统一抽象**（把 SSO 也做成策略，收益是页面复用，代价是授权码跳转与 XHR 语义冲突）vs **双轨现状**（收益是各流程可独立演进，代价是准入与错误文案分散在 4 个页面）。
2. **令牌归属：内存台账 vs 浏览器存储**：现役 `Store`（akita 持久化，可枚举、可与组织作用域一起清）对比 auth 包 `localStorage` 容量（可换存储实现、带 ownerStrategyName 以便刷新）。维度取舍决定「刷新令牌能否被守卫直接读到」以及「登出是否真能清干净」。
3. **守卫判定：同步快判 vs 异步慢判**：`authGuard` 用内存 `store.token`（零延迟、白屏前就拦截），`@core/auth` 的 `NoAuthGuard` 用 `GET /api/auth/authenticated`（权威但多一次 RTT 且可能失败）。维度取舍是「首屏延迟」与「令牌撤销后的真实性」。
4. **向导状态：组件内 signal vs 全局步骤机**：`tenant-details` 的步进状态（`tenantCompleted` / `aiModelSetupRequested` / `primaryCopilotCreatedInOnboarding`）留在组件内，URL 只有 `tenant` / `plugins` 两段。维度取舍是「可刷新恢复」与「实现简单」，当前偏向后者（依赖 `onboardGuard` + `authGuard` 做兜底分流）。

## 结论

实现层面，本域的可复述骨架只有三条：**页面 → `XpAuthService` → 策略表 → `@core/state` `AuthService`**（认证）、**`Store.token` → `authGuard` → 业务路由**（准入）、**`onboard` → 自动登录 → `stepper.next()` → 插件安装 → 整页重载**（引导）。三条骨架各自的"唯一真相"分别是策略表项、`store.token`、`tenantService.onboard` 的返回，改动时只要守住这三处，其余页面级差异都可安全重构。

阅读与改动建议：① 新增登录方式只动策略表 + 一个策略类；② 新增公共页必须同时评估路由白名单与 `ANONYMOUS_AUTH_PATHS` 两处；③ 任何令牌结构 / 刷新语义改动按"全站回归（含对话 socket 重连）"对待；④ 清理顺序建议先合并令牌容量（技术债 1、2），再删除未挂载的 `inviteGuard` / `@core` 版 `NoAuthGuard`，最后统一 `Nb*` 命名与密码长度口径。
