## 1. 运维边界与入口

- 本域没有服务端部署对象；对应服务端面在 `packages/server/src/auth/**`（含 `sso/**`）、`invite/`、`tenant/`（见后端专家文档）。
- 前端可用杠杆只有五类：**构建/运行配置**、**路由准入（守卫矩阵）**、**环境变量（含 OIDC 开关）**、**localStorage 令牌存储**、**文案与依赖落盘**。
- 线上 URL：`/auth/{login,consent,register,register-result,request-password,reset-password,accept-invite,verify,logout,sso-bind,sso-confirm}` 与 `/onboarding/{'',tenant,plugins,unknown}`。

章节来源：[auth-routing.module.ts](file://apps/cloud/src/app/auth/auth-routing.module.ts)（关键符号：`routes`）、[onboarding-routing.module.ts](file://apps/cloud/src/app/onboarding/onboarding-routing.module.ts)（关键符号：`routes`）

## 2. 构建与运行

| 动作 | 命令 / 配置 |
|---|---|
| 开发服务 | `corepack pnpm nx serve cloud`（`@angular/build:dev-server`，默认 `development`，`proxyConfig: apps/cloud/proxy.conf.cjs`） |
| 生产构建 | `corepack pnpm nx build cloud`（默认 `production`；`fileReplacements` 把 `environment.ts` → `environment.prod.ts`；输出 `dist/apps/cloud`；启用 Service Worker `ngsw-config.json`） |

- 构建**依赖 `contracts` 产物**（`targets.build.dependsOn`），而 `test` 目标不含该依赖（测试经 `moduleNameMapper` 直连 contracts 源码）。

- 升级本域代码后若浏览器仍加载旧 chunk，先清 Service Worker 缓存（生产构建启用 SW）。

章节来源：[project.json](file://apps/cloud/project.json)（关键符号：`targets.build.dependsOn`、`targets.serve.proxyConfig`、`assets`）

## 3. 环境变量与配置

| 变量 | 默认 / 生产占位 | 对本域的作用 |
|---|---|---|
| `VITE_API_BASE_URL` | dev `http://localhost:3000`；prod 字面量 `DOCKER_API_BASE_URL` | 决定登录/刷新/找回等 `/api/auth/*` 的真实落点；代理侧同源哨兵（`same-origin`/`self`/`/`）会回落到 `API_BASE_URL` |
| `VITE_DEPLOYMENT_TARGET` / `DEPLOYMENT_TARGET` | dev `local`；prod 字面量 `DOCKER_DEPLOYMENT_TARGET` | **决定是否允许自助注册**：`enablePublicSignup = deploymentTarget !== 'customer-onprem'` |
| `mcpOAuthEnabled`（代码内常量，非 env） | dev/jest/prod **均为 `false`** | 决定 `/auth/consent` 路由**是否注册**；开启需改环境文件 |
| `XP_API_BASE_URL`（`InjectionToken`） | — | OIDC consent 的请求根（`{base}/oidc/interaction/...`），**宿主提供方未在本域核实** |
| OIDC / SSO 客户端配置 | 无前端配置 | 前端只消费 `GET /api/auth/sso/providers` 返回的 `providers[].startUrl`；**clientId/secret/redirect URI 全在服务端** |
| `VITE_CHATKIT_FRAME_URL`、`VITE_MCP_APP_SANDBOX_*` | `/chatkit` 等 | 非本域，仅作共存参考 |

- **代理**：`proxy.conf.cjs` 只代理 `/api` 与 `/artifacts/share`，目标由 `VITE_API_BASE_URL` 推导（`localhost`→`127.0.0.1`、去掉尾 `/api`、`changeOrigin/xfwd/secure:false`）。
- **令牌存储策略**：`main.ts` 的 `persistState({ key: '_xpertStore' })` 把 akita `PersistStore` 写进 localStorage；首次启动还会回填遗留键 `token`、`_userId`、`_organizationId`、`_activeScopeLevel`、`serverConnection`、`preferredLanguage`。遗留 `XpTokenLocalStorage` 另用键 `auth_app_token`。**清登录态 = 清 `_xpertStore`（必要时连同遗留键）**。

章节来源：[environment.ts](file://apps/cloud/src/environments/environment.ts)（关键符号：`environment.mcpOAuthEnabled`）、[@core/auth/auth.module.ts](file://apps/cloud/src/app/@core/auth/auth.module.ts)（关键符号：`enablePublicSignup`）、[store.service.ts](file://apps/cloud/src/app/@core/state/store.service.ts)（关键符号：`createInitialPersistState`）、[proxy.conf.cjs](file://apps/cloud/proxy.conf.cjs)（关键符号：`resolveProxyTarget`）

## 4. 路由与准入矩阵

**全站如何被守卫保护**（顶层路由 + 本域守卫）：

| 路径 | 守卫 | 部署含义 |
|---|---|---|
| `/onboarding/**` | 无模块级守卫；`''`(welcome)/`tenant` 用 `onboardGuard`，`plugins` 用 `authGuard`，`unknown` 无守卫 | 首启引导：已开通用户会被 `onboardGuard` 送回 `/home`；`plugins` 必须已登录 |
| `/auth/**` | 4 个子路由用 `NoAuthGuard`（request-password、reset-password、accept-invite、verify），其余无守卫 | 登录/注册/SSO 页面对未登录用户开放；已登录访问密码类页面跳 `/home` |
| `/artifacts/auth/:artifactLinkSlug` | `authGuard` | 产物分享鉴权页 |
| `/sign-in/success` | **无守卫** | SSO/OIDC 回跳落点，靠 query `jwt/refreshToken/userId/returnTo` 自举 |
| `/plugins/marketplace` | **无守卫** | 公共插件市场页 |
| `/x-chatkit/**`、`/x/**` | 顶层**无守卫**（内层分流详见对话域运维） | **公共页免登录是显式白名单**，新增公共页必须显式评估 |
| `/`（features 模块） | 各子路由 `authGuard`（+ `NgxPermissionsGuard`、`featureGate`）：`chat`、`explore`、`xpert`、`settings`、`copilot`、`project`、`agent-evolution`、`plugins*`、`operations`、`xpert-access-requests` | 企业内页面必须登录；`xpert` 路由还负责置 `appService.inWorkspace` |
| `**` | `redirectTo: ''` | 兜底收敛 |

- `authGuard` 拒绝时的动作是「**先 `authStrategy.logout()` 清本地身份，再跳 `/auth/login?returnUrl=<原 URL>`**」——排障时看到 `/auth/login?returnUrl=` 即说明命中此守卫。
- 改动守卫矩阵需逐路由核对（含 `NoAuthGuard` 对 `accept-invite` 的 `email`+`token` 例外），新增公共页必须显式评审。

章节来源：[app-routing.module.ts](file://apps/cloud/src/app/app-routing.module.ts)（关键符号：`routes`）、[features-routing.module.ts](file://apps/cloud/src/app/features/features-routing.module.ts)（关键符号：`authGuard`、`featureGate`）、[auth.guard.ts](file://apps/cloud/src/app/@core/auth/auth.guard.ts)（关键符号：`authGuard`）、[auth-准入边界-全站.md](file://CodeWikiHub/xpert/memory/关联关系/前端专题/auth-准入边界-全站.md)（关键符号：免登录例外清单）

## 5. 前端依赖落盘状态与修复

- **现状（本会话实测）**：`/root/xpert/node_modules/@xpert-ai` **整个作用域目录不存在**（`ENOENT`），因此 `@xpert-ai/store`、`@xpert-ai/headless-ui`、`@xpert-ai/contracts` 等均不可解析。
- **对 spec 的影响**：ki 归档的 `14 spec = 13 PASS / 1 FAIL` 中，那 1 个失败即**环境级 `@xpert-ai/store` 缺依赖**；在依赖缺失的工作区里 14 个 spec 会在收集阶段全部失败（详见 `06-测试.md` §6 的候选归因）。
- **修复**：`cd /root/xpert && corepack pnpm install`——仓库 `packageManager: pnpm@10.24.0`，`.npmrc` 固定 `node-linker=hoisted`、`strict-peer-dependencies=false`、`auto-install-peers=true`；**不要用裸 `pnpm`/`npm`**，否则会重建出不兼容的 `node_modules` 链接结构。
- 关键声明位：`@xpert-ai/store` 固定在 `apps/cloud/package.json`（`"3.9.1"`，**非 `catalog:`**），而 `@xpert-ai/chatkit-*` 走 workspace catalog；排查「某个 @xpert-ai 包缺」时先区分这两类。

章节来源：[apps/cloud/package.json](file://apps/cloud/package.json)（关键符号：`dependencies['@xpert-ai/store']`）、[.npmrc](file://.npmrc)（关键符号：`node-linker`、`auto-install-peers`）

## 6. i18n 与文案

- 本域文案集中在 `auth/i18n/{zh,zhHans,zhHant}.ts`，由 `@core/theme/translate.ts` 以 `ZhHans as AuthZhHans / ZhHant as AuthZhHant` 合并进全局字典；键形如 `Auth.Login`、`Auth.SignupSuccess`、`Auth.SSO_BIND.*`、`Auth.SSO_CONFIRM.*`、`Auth.ACCEPT_INVITE.PROFILE_UPDATED`。
- **降级策略**：组件普遍用 `translateService.instant(key, { Default: '…' })`（或 `get(key, {Default})`），**缺键不会白屏**，会显示英文兜底；排障看到英文即说明该语言包缺键。
- 登录/注册页的标题与品牌信息来自租户设置（`store.tenantSettings$` 的 `app_logo`/`app_name`/`tenant_title[_lang]`），**不是静态文案**。
- onboarding 壳组件提供语言切换菜单（`injectLanguage()` + `LanguagesEnum`，排除 `Chinese`），切换即 `translate.use(lang)`。

章节来源：[auth/i18n/zhHans.ts](file://apps/cloud/src/app/auth/i18n/zhHans.ts)（关键符号：`ZhHans.Auth.SSO_BIND`）、[auth.component.ts](file://apps/cloud/src/app/auth/auth.component.ts)（关键符号：`XpAuthComponent.title`、`XpAuthComponent.onLanguage`）

## 7. 日志与排障入口

**登录失败定位路径（推荐顺序）**：

1. **看 URL query**：`/auth/login?returnUrl=` 是 `authGuard` 的产物；`?error=…`、`?ssoError=&ssoProvider=`、`?ssoMessage=` 是 SSO/OIDC 回调失败（`login.component.ts` 有固定映射表）。
2. **看 Network**：过滤 `/api/auth`。`POST /api/auth/login` 返回 **200 但无 `user`** 也会被前端判为失败（后端「失败返回 200+null」语义）；`GET /api/auth/refresh` 带的是 `Authorization: Bearer <refreshToken>`。
3. **看 Console**：`AuthStrategy.login` 的 `catchError` 会 `console.error(err)`；`AppInitService.init` 的 `catch` 打 `console.log(error)`，后台水合失败打 `Deferred current-user hydration failed`。
4. **看 localStorage**：`_xpertStore`（akita persist）内的 `token/refreshToken/userId`，以及遗留键 `token`、`_userId`、`_organizationId`；`serverConnection` 记录最近一次连接状态（登出会置 200）。
5. **看 onboarding 步**：`onboardGuard` 依赖 `GET /api/tenant/onboard`；`SetupPluginsComponent` 的 `disconnected`/`waitingTooLong` 信号直接反映 `/api/system/setup/plugins` 连通性。

章节来源：[token.interceptor.ts](file://apps/cloud/src/app/@core/interceptors/token.interceptor.ts)（关键符号：`ANONYMOUS_AUTH_PATHS`、`TokenInterceptor.addAuthenticationToken`）、[login.component.ts](file://apps/cloud/src/app/auth/login/login.component.ts)（关键符号：`UserLoginComponent.resolveSsoErrors`）

## 8. 常见故障与处置

| 故障 | 根因定位 | 处置 |
|---|---|---|
| **登录后循环重定向到 `/auth/login`** | `authGuard` 只认 `store.token`；若 token 存在但服务端始终 401 → 拦截器刷新失败 → `logout()` 清空 → 再跳登录，形成循环 | 清 localStorage `_xpertStore`（必要时含遗留键）后重登；确认 `VITE_API_BASE_URL` 指向同一后端；确认 `/api/auth/refresh` 未被反代剥离 `Authorization` 头 |
| **token 过期后大量请求失败** | `TokenInterceptor` 仅在 401 且非匿名白名单时刷新；并发刷新由 `refreshTokenInProgress` + `shareReplay(1)` 去重 | 检查是否命中匿名白名单（`/api/auth/login`、`/api/auth/sso/*`、`/api/tenant/onboard` 的 401 **不会**刷新）；检查 `SKIP_AUTH_REFRESH` 上下文（登出清理专用）是否被误用 |
| **邀请链接失效** | `/auth/accept-invite` 需 query 同时带 `email` 与 `token`（`NoAuthGuard` 的例外条件）；`GET /api/invite/validate` 失败即 `Invitation no longer valid` | 重新签发邀请；核对邮件链接是否被 IM/邮件网关截断 query；已登录用户访问该页会走 `NoAuthGuard` 例外（放行），不被踢到 `/home` |
| **OIDC 回调失败** | `/auth/consent` 需 `mcpOAuthEnabled = true` + `?interaction=`；请求必须带 `withCredentials` cookie | 打开环境文件确认 `mcpOAuthEnabled`；确认 `XP_API_BASE_URL` 为绝对地址且与授权服务同源可带 cookie；`error=invalid_tenant` 说明授权目标租户不可用 |
| **SSO 绑定失败** | 400（ticket 过期）、401（账号/口令错）、409（身份已被占用） | 重新发起 SSO 登录拿新 ticket；409 需管理员处理既有绑定；Redis 不可用时服务端绑定链会 500（后端硬依赖） |
| **onboarding 卡在某步** | · welcome/tenant 步：`onboardGuard` 探测失败会跳到 `/onboarding/unknown`；· tenant-details 提交后登录失败会跳 `/auth/login?returnUrl=/onboarding/plugins`；· plugins 步用 `authGuard`，安装期间容忍 0/502/503/504 并在 180s 后置 `waitingTooLong` | welcome 步卡住 → 查 `GET /api/tenant/onboard`；tenant 步卡住 → 查 `POST /api/tenant/onboard` 与随后的 `POST /api/auth/login`；plugins 步卡住 → 查 `GET/POST /api/system/setup/plugins`，`installing` 阶段**刷新页面是安全的**（会续跑已落盘任务）；安装完成会自动 `location.assign('/')` |
| **注册按钮缺失** | `deploymentTarget === 'customer-onprem'` 时 `enablePublicSignup = false` | 属预期行为；SSO 的 `verified_email_signup` 流程仍可用 |

章节来源：[login.component.ts](file://apps/cloud/src/app/auth/login/login.component.ts)（关键符号：`UserLoginComponent.submit`）、[tenant-details.component.ts](file://apps/cloud/src/app/onboarding/tenant-details/tenant-details.component.ts)（关键符号：`TenantDetailsComponent.onboard`）、[setup-plugins.component.ts](file://apps/cloud/src/app/onboarding/plugins/setup-plugins.component.ts)（关键符号：`SetupPluginsComponent.monitor`）、[accept-invite.component.ts](file://apps/cloud/src/app/auth/accept-invite/accept-invite.component.ts)（关键符号：`AcceptInvitePageComponent.loadInvite`）
