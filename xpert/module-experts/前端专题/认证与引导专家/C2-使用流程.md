## R1 邮箱密码登录（含失败与账号未验证分支）
- **业务目标**：已注册用户用邮箱 + 口令换取全站令牌，并回到 `returnUrl` 或 `/`。
- **调用顺序**：`/auth/login`（无守卫）→ `UserLoginComponent` 表单 `{userName, password, rememberMe}` → `submit()` 手工 dirty 校验 → `XpAuthService.authenticate('email', {…form.value, userName: userName.toLowerCase()})` → `getStrategy('email')` 表内定址 → `AuthStrategy.authenticate` 组 `IUserLoginInput{email,password}` → `AuthStrategy.login` → `AuthService.login`（`POST /api/auth/login`）→ `map` 内写 `store.userId/token/refreshToken/restoreRememberedScope/user` → `XpAuthResult(true, res, '/')` → 页面取 `returnUrl || getRedirect()`，`redirectDelay` 后 `navigateByUrl`。
- **时序边界**：`AuthStrategy.login` 的返回值不带 token 对象，故 `XpAuthService.processResultToken` **不触发**（`auth_app_token` 无写入）；`rememberMe` cookie 由策略侧 `tap(() => this.rememberMe(args))` 写/删，而失败结果经 `catchError` 转成正常 `next` 值，因此失败同样会执行该 `tap`。
- **预期结果**：`store.token` 非空；后续 `authGuard` 放行；`/home` 或原目标页可达。
- **错误处理**：后端「失败返回 200 + null」由 `if (!user)` 兜成 `XpAuthResult(false, res, false, login.defaultErrors)`；4xx/网络错误走 `catchError` 并 `console.error(err)`，文案统一为 `Login/Email combination is not correct, please try again.`。**账号未验证分支（实测口径）**：登录页没有独立的「未验证」文案分支——未验证账号在服务端表现为登录失败，前端一律落同一默认文案；「未验证」在前端是注册链语义（R2 的 `/auth/verify?token=`）。
- **真实代码示例**：
```ts
// auth/login/login.component.ts —— 提交与跳转
const result = await firstValueFrom(
  this.authService.authenticate(this.strategy, { ...this.form.value, userName: this.form.value.userName?.toLowerCase() }))
const redirect = this.route.snapshot.queryParams.returnUrl || result.getRedirect()
if (redirect) setTimeout(() => this.router.navigateByUrl(redirect), this.redirectDelay)
// @core/auth/auth-strategy.service.ts —— 令牌六写（XpAuthResult 不带 token，processResultToken 不触发）
this.store.userId = user.id; this.store.token = token; this.store.refreshToken = refreshToken
this.store.restoreRememberedScope(user.id); this.store.user = user
```
章节来源：[login.component.ts](file://apps/cloud/src/app/auth/login/login.component.ts)（关键符号：`UserLoginComponent.submit`、`checkRememberdMe`、`resolveSsoErrors`）、[auth-strategy.service.ts](file://apps/cloud/src/app/@core/auth/auth-strategy.service.ts)（关键符号：`AuthStrategy.authenticate`、`AuthStrategy.login`、`rememberMe`）、[auth.service.ts（auth）](file://apps/cloud/src/app/auth/services/auth.service.ts)（关键符号：`XpAuthService.getStrategy`、`processResultToken`）

## R2 注册并完成首次登录
- **业务目标**：自助注册账号 → 收激活邮件 → 完成邮箱验证 → 首次登录（R1）。
- **调用顺序**：`/auth/register`（无守卫，`enablePublicSignup` 门控）→ `UserRegisterComponent.register()` → `validateReferralCode()`（启用时 `ReferralService.validateCode`，不通过直接 `return`）→ `XpAuthService.register('email', form.getRawValue())` → `AuthStrategy.register`（先客户端比对 `password !== confirm`）→ `AuthService.signup`（`POST /api/auth/signup`）→ 成功 `XpAuthResult(true, null, false, [], [])` → 页面提示 `Auth.SignupSuccess`（"Signup success, please active the link in your email"）→ 邮件链接 `/auth/verify?token=`（挂 `NoAuthGuard`）→ `VarifyEmailComponent` 订阅 `queryParams` → `AuthService.verifyEmail(token)`（`GET /api/auth/verify`）→ 提示 `Auth.VarifyEmailSuccess` → 用户手动走 R1 登录。
- **时序边界**：注册**不落令牌、不自动登录**（`signup → switchMap(login)` 段已被注释；`XpAuthResult` 的 `redirect = false` 故不跳转）；`/auth/register-result` 仍注册在路由表但模板为空，当前流程不跳转至此。
- **预期结果**：用户收到激活邮件；验证页只发一次 GET，不发任何写操作。
- **错误处理**：`409 → err.error?.error`、`400 → err.error?.message`、其余 → `register.defaultErrors`；客户端密码不一致 → `"The passwords don't match."`；`enablePublicSignup = deploymentTarget !== 'customer-onprem'` 为假且无 `ticket` 时构造期直接 `navigate(['/auth/login'])`；verify 失败把 `err.error` 直接当消息展示。
- **真实代码示例**：
```ts
// auth/register/register.component.ts
this.service.register(this.strategy, data).subscribe((result) => { … this.messages = [this.getTranslation('Auth.SignupSuccess', { Default: '…' })] })
// @core/auth/auth-strategy.service.ts —— 注册只回结果对象，不带 token
return this.authService.signup(registerInput).pipe(map(() => new XpAuthResult(true, null, false, [], [])))
// auth/verify-email/verify-email.component.ts
.map((params) => params['token']).pipe(switchMap((token) => this.authService.verifyEmail(token)))
```

## R3 忘记密码 → 重置 → 重新登录
- **业务目标**：已注册用户在不登录的前提下申请重置邮件、改密、再登录。
- **调用顺序**：`/auth/request-password`（挂 `NoAuthGuard`）→ `ForgotPasswordComponent.requestPass()` → `XpAuthService.requestPassword('email', {email})` → `AuthStrategy.requestPassword` → `AuthService.requestPassword`（`POST /api/auth/request-password`）→ 页面 toast，**不跳转**；邮件链接 `/auth/reset-password?token=`（挂 `NoAuthGuard`）→ `ResetPasswordComponent.resetPass()` → `XpAuthService.resetPassword('email', form.value)` → `AuthStrategy.resetPassword` 从 `route.snapshot.queryParamMap.get('token')` 取令牌（**不从表单传**）→ `AuthService.resetPassword({token,password,confirmPassword})`（`POST /api/auth/reset-password`）→ `tap` 内成功 toast / 失败抛错 → `delay(2000)` → `router.navigate(['/auth/login'])` → 回到 R1。
- **时序边界**：`delay(2000)` 位于 `tap` 之后，因此成功提示先显示、再跳登录；表单校验为 `minLength(8)` + `matchValidator('password','confirmPassword')`，强度条由 `toSignal(passwordControl.valueChanges)` 驱动。
- **预期结果**：新口令生效后用新口令登录成功；两个 no-auth 页在已登录时会被 `NoAuthGuard` 送回 `/home`。
- **错误处理**：重置失败统一 `resetPass.defaultErrors`（服务端的 `400 Password Reset Failed (code: 1|2|3)` 被吞）；策略内 `res.status === 400` 分支因未用 `observe: 'response'` 而不可达 —— [推测] 死分支。
- **真实代码示例**：
```ts
// @core/auth/auth-strategy.service.ts —— 重置令牌只来自路由 query
const token = this.route.snapshot.queryParamMap.get('token')
if (password !== confirmPassword) return of(new XpAuthResult(false, null, null, ['The password and confirmation password do not match.']))
return this.authService.resetPassword({ token, password, confirmPassword }) …
```
章节来源：[forgot-password.component.ts](file://apps/cloud/src/app/auth/forgot-password/forgot-password.component.ts)（关键符号：`ForgotPasswordComponent.requestPass`）、[reset-password.component.ts](file://apps/cloud/src/app/auth/reset-password/reset-password.component.ts)（关键符号：`ResetPasswordComponent.resetPass`、`strength`）、[auth-strategy.service.ts](file://apps/cloud/src/app/@core/auth/auth-strategy.service.ts)（关键符号：`AuthStrategy.requestPassword`、`AuthStrategy.resetPassword`）

## R4 接受邀请加入组织（`invite.guard` 路径实测口径）
- **业务目标**：被邀请人点邮件链接 → 校验邀请有效 → 补全姓名/口令 → 开户进组织 → 回登录页登录。
- **调用顺序**：`/auth/accept-invite?email=&token=`（挂 `NoAuthGuard`）→ `NoAuthGuard.canAccessInviteRoute` 命中即**无条件放行** → `AcceptInvitePageComponent.ngOnInit` 订阅 `queryParams` → `loadInvite` → `InviteService.validateInvite(['role','organization'], {email, token})`（`GET /api/invite/validate`）→ 渲染 `AcceptInviteFormComponent` → `submitForm` → `InviteService.acceptUserInvite({user,password,referralCode,organization,inviteId})`（`POST /api/invite/user`）→ toast `Auth.ACCEPT_INVITE.PROFILE_UPDATED` → `navigate(['/auth/login'])`。
- **时序边界（`invite.guard` 写实）**：本域有**两个不同物**——① 页面准入实际由 `NoAuthGuard` 的 `accept-invite` 例外承担（要求 query 同时含 `email` 与 `token`，已登录用户也被放行）；② `inviteGuard` 的判据是 `route.data.expectedPermissions` + `store.hasPermission` + `selectedOrganization.invitesAllowed`，属**组织内邀请管理页**准入，且全仓库仅有定义、**当前无任何路由引用**（未挂载）。改邀请相关准入时必须分别评估这两者。
- **预期结果**：邀请校验通过并渲染表单（失效则表单不渲染）；开户成功后不自动登录，回登录页。
- **错误处理**：校验失败或返回空 → `inviteLoadErrorMessage = 'Invitation no longer valid'`；提交失败 → `toastrService.danger(error, null, 'Could not create your account')`；邀请 `expireDate` 过期由服务端拒绝。
- **真实代码示例**：
```ts
// auth/guards/no-auth.guard.ts —— 唯一「已登录也能进免登录页」的口子
private canAccessInviteRoute(route: ActivatedRouteSnapshot): boolean {
  return route.routeConfig?.path === 'accept-invite' && route.queryParamMap.has('email') && route.queryParamMap.has('token') }
// auth/accept-invite/accept-invite.component.ts
this.invitation = await this.inviteService.validateInvite(['role', 'organization'], { email, token })
await this.inviteService.acceptUserInvite({ user, password, referralCode, organization, inviteId }); this.router.navigate(['/auth/login'])
```
章节来源：[no-auth.guard.ts（auth 包）](file://apps/cloud/src/app/auth/guards/no-auth.guard.ts)（关键符号：`NoAuthGuard.canAccessInviteRoute`、`NoAuthGuard.canActivate`）、[accept-invite.component.ts](file://apps/cloud/src/app/auth/accept-invite/accept-invite.component.ts)（关键符号：`AcceptInvitePageComponent.loadInvite`、`submitForm`）、[invite.guard.ts](file://apps/cloud/src/app/@core/guards/invite.guard.ts)（关键符号：`inviteGuard`、`expectedPermissions`、`invitesAllowed`）

## R5 OIDC 登录与 consent
- **业务目标**：OIDC/MCP 客户端发起授权后，用户在本站看到授权请求并 allow/deny，授权码流交还后端完成。
- **调用顺序**：`/auth/consent`（**仅当 `environment.mcpOAuthEnabled` 为真时注册**，本仓库 dev/jest/prod 三份环境均为 `false`）→ `OidcConsentComponent` 从 `?interaction=` 取值 → `GET ${XP_API_BASE_URL}/oidc/interaction/{interaction}/consent`（`withCredentials: true`）→ 渲染 `clientId/clientName/scopes/resources` → `allow()` / `deny()` → 动态建 `<form method="post">` + 隐藏 `decision` 整页提交到同一路径。
- **时序边界**：前端**不生成也不校验** `state/nonce`，只透传 `interaction`（由后端授权码流持有）；提交是「带外表单 POST」而非 XHR，浏览器离开 SPA，回调与令牌签发全在后端；`interaction` 缺失即 `loadFailed`；`loading/loadFailed/submitting` 任一为真时提交被忽略。
- **预期结果**：`interaction` 合法时页面展示申请范围；提交后浏览器整页跳走，SPA 不再参与。
- **错误处理**：GET 异常 → `loadFailed = true`（无重试入口）；回调失败回到登录页由 query 解析：`?error=invalid_credentials|invalid_tenant|interaction_expired`（`#oidcErrorMap` 本地映射）、`?ssoMessage=`、`?ssoError=&ssoProvider=`。
- **真实代码示例**：
```ts
// auth/consent/consent.component.ts —— 带外提交，规避 XHR 与 302 的语义冲突
const form = document.createElement('form'); form.method = 'post'
form.action = `${this.#apiBaseUrl}/oidc/interaction/${encodeURIComponent(this.interaction)}/consent`
decisionInput.name = 'decision'; decisionInput.value = decision
document.body.appendChild(form); form.submit()
```
章节来源：[consent.component.ts](file://apps/cloud/src/app/auth/consent/consent.component.ts)（关键符号：`OidcConsentComponent.ngOnInit`、`submitDecision`、`XP_API_BASE_URL`）、[auth-routing.module.ts](file://apps/cloud/src/app/auth/auth-routing.module.ts)（关键符号：`environment.mcpOAuthEnabled`）、[login.component.ts](file://apps/cloud/src/app/auth/login/login.component.ts)（关键符号：`UserLoginComponent.resolveSsoErrors`、`#oidcErrorMap`）

## R6 SSO 绑定（sso-bind / sso-confirm）
- **业务目标**：把外部身份提供方账号绑定到既有 Xpert 账号（匿名票据）或由当前登录用户确认绑定（已登录票据）。
- **调用顺序**：① 登录页/注册页 `GET /api/auth/sso/providers` 取 `providers[].startUrl`（失败静默降级 `[]`）→ `openProvider()` → `window.location.assign(startUrl + returnTo)`；② 回跳 `/auth/sso-bind?ticket=` → `GET /api/auth/sso/bind/challenge`，两条出路：打开已有账号表单（`POST /api/auth/sso/bind/complete {ticket,userName,password}`）或去注册（`navigate(['/auth/register'], {queryParams:{ticket, ref}})`）；③ `/auth/sso-confirm?ticket=` → `GET /api/auth/sso/bind/current-user/challenge` → `POST /api/auth/sso/bind/current-user/complete {ticket}`；④ 成功一律 `window.location.assign(result.location)` → `/sign-in/success?jwt=&refreshToken=&userId=&returnTo=`。
- **时序边界**：挑战-完成两跳（ticket 服务端持有 `expiresAt`）；`SignInSuccessComponent` 在 `/sign-in/success` 做 query 三写 + `restoreRememberedScope` + `AppInitService.init()`，`user.id !== userId` 时**静默 return**；`returnTo` 必须以 `/` 开头且非 `//` 才走路由，否则整页跳。
- **预期结果**：绑定成功后回到 `/` 或 `returnTo`；票据过期则停在 sso-bind 页给出「重新发起 SSO」提示。
- **错误处理**：`400` 票据过期（清 `challenge` 回挑战态）、`401` 凭据错/登录态失效（sso-confirm 提示重新登录）、`409` 身份冲突（保留 ticket 供重试）；注册侧 `flow === 'verified_email_signup'` 会把邮箱锁死。
- **真实代码示例**：
```ts
// auth/sso-bind/sso-bind.component.ts
await firstValueFrom(this.#http.post<CompleteSsoBindingResponse>('/api/auth/sso/bind/complete', { ticket: this.ticket, userName, password }))
window.location.assign(result.location)   // 交还后端
// @core/auth/signin-success/sign-in-success.component.ts —— 回跳落点三写 + 水合
this._store.token = jwt; this._store.userId = userId; this._store.refreshToken = refreshToken
await this._appInitService.init()
```
章节来源：[sso-bind.component.ts](file://apps/cloud/src/app/auth/sso-bind/sso-bind.component.ts)（关键符号：`SsoBindComponent.loadChallenge`、`submit`、`handleSubmitError`、`openRegister`）、[current-user-sso-confirm.component.ts](file://apps/cloud/src/app/auth/current-user-sso-confirm/current-user-sso-confirm.component.ts)（关键符号：`CurrentUserSsoConfirmComponent.loadChallenge`、`submit`）、[sign-in-success.component.ts](file://apps/cloud/src/app/@core/auth/signin-success/sign-in-success.component.ts)（关键符号：`SignInSuccessComponent`）

## R7 登出与 token 清理
- **业务目标**：清空本地身份（含刷新令牌与组织作用域），回到登录可达状态。
- **调用顺序**：`/auth/logout`（**无守卫**）→ `XpLogoutComponent.ngOnInit` → `logout(strategy='email')` → `XpAuthService.logout` → `AuthStrategy.logout()` → `_logout()`：`new HttpContext().set(SKIP_AUTH_REFRESH, true)` → `DELETE artifactShareSessionUrl()`（`timeout(5000)`，失败吞掉）→ `this.authService.logout()` → `store.clear()` → `store.serverConnection = 200` → 返回 `XpAuthResult(true, null, '/')` → `XpAuthService.logout` 成功时 `tokenService.clear()` → 页面 `redirectDelay` 后 `navigateByUrl('/')` → 由 `authGuard` 兜到 `/auth/login?returnUrl=`。
- **时序边界**：**没有 `POST /api/auth/logout`** —— `@core/state` 的 `AuthService.logout()` 是空实现（原 `patchState` 已注释）；登出**不通知后端**，因此多标签页不同步（无 `storage` 事件监听），其他标签页要到下一次 401 才被动收敛。
- **预期结果**：`_xpertStore` 内 `token/refreshToken/userId` 清空，`activeScopeLevel` 降回 `TENANT`；再访问受保护路由必落登录页。
- **错误处理**：清理接口 4xx/5xx/超时**仍判成功**（源码注释：Logout must still clear local authentication if the API is offline）；另一条被动失效路径是 `TokenInterceptor` 捕获 `auth/refresh` 自身 401 → `this.auth.logout().subscribe()`。
- **真实代码示例**：
```ts
// @core/auth/auth-strategy.service.ts —— 登出顺序（刻意设计）
const context = new HttpContext().set(SKIP_AUTH_REFRESH, true)
try { await firstValueFrom(this.http.delete(artifactShareSessionUrl(), { …ARTIFACT_SHARE_SESSION_HTTP_OPTIONS, context }).pipe(timeout(5000))) }
catch { /* Logout must still clear local authentication if the API is offline. */ }
this.authService.logout(); this.store.clear(); this.store.serverConnection = 200
```

## R8 onboarding 向导（welcome → tenant-details → plugins）
- **业务目标**：首启部署建「租户 + 默认组织 + 超管」→ 自动登录 → 装插件 → 进主应用。
- **调用顺序**：`/onboarding/`（welcome，`onboardGuard`）→ `WelcomeComponent.navigateTenant()` → `/onboarding/tenant`（`onboardGuard`）→ `TenantDetailsComponent.onboard()` → `TenantService.onboard({name: DEFAULT_TENANT, superAdmin:{…,hash: password, preferredLanguage}, defaultOrganization:{…}})`（`POST /api/tenant/onboard`）→ `tenantCompleted.set(true)` → `afterOnboard(tenant.organizations[0])`：`authStrategy.login({email,password})` + `store.setOrganizationScope(org)` + `copilotServer.refresh()` → `stepper.next()` → `onStepChange(selectedIndex === 2)` → `navigateHome()` → `/onboarding/plugins`（**`authGuard`**）→ `SetupPluginsComponent.load()` → `SetupPluginsService.status()`（`GET /api/system/setup/plugins`），`installing` 则用已有 `items.map(packageName)` 续跑 `start()` → `monitor()` 2s 轮询 → `completed` 后 1.5s `enterOrganization()` → `location.assign('/')`。
- **时序边界**：模板 `<z-stepper [linear]="true">` ⇒ **不可跳步**；步 2 的守卫是 `authGuard`，而 token 只能由步 1 的 `afterOnboard` 自动登录产生 —— 这就是「三步不可跳」的结构性依据；步骤态只存在组件 signal（`tenantCompleted` / `aiModelSetupRequested` / `primaryCopilotCreatedInOnboarding`），刷新即回守卫判定。
- **预期结果**：租户建立并自动登录成功；插件装完整页重载（保留组织作用域）；已建租户的实例访问 welcome/tenant 会被 `onboardGuard` 送回 `/home/`。
- **错误处理**：`onboard()` 失败 → `toastrService.error(getErrorMessage(error))` 并停在本步；自动登录失败 → `/auth/login?returnUrl=/onboarding/plugins`；`onboardGuard` 探测出错 → `/onboarding/unknown`；`monitor()` 对 `0/502/503/504` 记 `disconnected`、累计 180s 置 `waitingTooLong`，`phase === 'attention'` 直接 `return`（无重试按钮文案兜底）。
- **真实代码示例**：
```ts
// onboarding/tenant-details/tenant-details.component.ts
tenant = await this.tenantService.onboard({ name: DEFAULT_TENANT, superAdmin: { … hash: password, preferredLanguage }, defaultOrganization: { … } })
await this.afterOnboard(tenant.organizations[0])   // 内部 authStrategy.login() + setOrganizationScope()
this.stepper.next()
// onboarding/plugins/setup-plugins.component.ts —— 2s 轮询与整页重载
if (phase === 'completed') { await this.delay(1500); if (!this.#destroyed) this.enterOrganization() }  // location.assign('/')
```
章节来源：[tenant-details.component.ts](file://apps/cloud/src/app/onboarding/tenant-details/tenant-details.component.ts)（关键符号：`TenantDetailsComponent.onboard`、`afterOnboard`、`onStepChange`、`skipAiModelSetup`）、[setup-plugins.component.ts](file://apps/cloud/src/app/onboarding/plugins/setup-plugins.component.ts)（关键符号：`SetupPluginsComponent.load`、`monitor`、`enterOrganization`）、[onboarding-routing.module.ts](file://apps/cloud/src/app/onboarding/onboarding-routing.module.ts)（关键符号：`onboardGuard`、`authGuard`）、[onboard.guard.ts](file://apps/cloud/src/app/@core/guards/onboard.guard.ts)（关键符号：`onboardGuard`）

## R9 新增一种登录方式（策略接入全流程）
- **业务目标**：新增一种登录方式（另一供应商 / 手机验证码等），**不改任何页面代码**。
- **调用顺序（四步）**：① 写 `class X extends XpAuthStrategy`，实现 6 个抽象动作（`authenticate / register / requestPassword / resetPassword / logout / refreshToken`）并加 `static setup({name})`（可整体参照未注册的模板 `XpPasswordAuthStrategy.setup`）；② 在 `@core/auth/auth.module.ts` 的 `XpAuthModule.forRoot({ strategies: [X.setup({ name: 'x' })] })` 里加一项；③ 在 `defaultAuthOptions.forms.<form>.strategy`（或页面传参）把 `strategyName` 指过去；④ 若该策略要参与令牌容量，让结果带 token 对象（`createToken(...)`）以便 `processResultToken` 落盘。
- **时序边界**：策略在 **DI 工厂** `nbStrategiesFactory` 中实例化（`injector.get(strategyClass)` → `strategy.setOptions(options)`），注册表是唯一扩展点；「只写策略类不注册表」不会有编译期提示。
- **预期结果**：页面从 `XP_AUTH_OPTIONS` 读到新 `strategyName` 后即可用；`XpAuthResult` 仍是页面唯一需要处理的返回面。
- **错误处理**：名字未注册 → 调用时同步抛 `TypeError: There is no Auth Strategy registered under '<name>' name`（`XpAuthService.getStrategy`）；`requireValidToken` 为真且令牌非法 → `createToken` 抛 `NbAuthIllegalTokenError`，由策略 `handleResponseError` 收进 `errors`。
- **真实代码示例**：
```ts
// auth/auth.module.ts —— 策略表的唯一实例化点
options.strategies.forEach(([strategyClass, strategyOptions]) => { const strategy = injector.get(strategyClass); strategy.setOptions(strategyOptions); strategies.push(strategy) })
// @core/auth/auth.module.ts —— 现役策略表只有一行
XpAuthModule.forRoot({ strategies: [AuthStrategy.setup({ name: 'email' })], forms: { … } }).providers
// auth/strategies/auth-strategy.ts —— 非法令牌前置拦截（注释明写语义）
if (failWhenInvalidToken && !token.isValid()) throw new NbAuthIllegalTokenError('Token is empty or invalid.')
```

## R10 给新页面加准入（选择正确守卫）
- **业务目标**：为新增页面选对守卫与落点，避免「能进页面但接口 401」或白屏。
- **调用顺序（选择表）**：

| 页面语义 | 用哪个守卫 | 判据 → 不通过落点 |
| --- | --- | --- |
| 已登录才能看（业务页） | `authGuard`（`@core/auth`，函数式） | `!!store.token` → 先 `await authStrategy.logout()` 清本地，再 `/auth/login?returnUrl=<原 URL>` |
| 未登录才能看（登录/密码/验证页） | auth 包 `NoAuthGuard`（类式） | `accept-invite` + `email` + `token` 例外放行 → `!store.token` 放行 → 否则问 `XpAuthService.isAuthenticated()`；通过则 `/home` |
| 首启引导步 | `onboardGuard`（函数式） | `TenantService.getOnboard()`：有租户 → `/home/`；探测错 → `/onboarding/unknown`；否则放行 |
| 组织内邀请管理（权限 + 开关） | `inviteGuard`（函数式，**当前未挂载，需自行挂载并验证**） | `expectedPermissions` 命中 `hasPermission` 且 `selectedOrganization.invitesAllowed` → 否则 `/` |
| 有脏数据时离开确认 | `dirtyCheckGuard`（函数式）/ `DirtyCheckGuard`（`canDeactivate`，已 `@deprecated`） | `isDirty()` 为真 → `ZardAlertDialogService.confirm`；取消即留在原页 |

- **时序边界**：守卫只读**内存** `store.token`（同步、零 RTT），不要在守卫里发业务请求；`authGuard` 只在无 token 时做一次本地清库（含 5s 超时的 artifact 清理请求）——弱网会拖慢首次跳登录；新增**免登录**页必须同时评估路由白名单与请求侧 `ANONYMOUS_AUTH_PATHS` 两处。
- **预期结果**：新页面在任何状态下都有确定落点，不出现白屏或「先渲染再 401」。
- **错误处理**：守卫不通过应返回 `false` **并显式 navigate**（或返回 `UrlTree`）；类式守卫要 `async` 且 `await` 异步判据；`xpert/routes.ts` 另有一个同名不同物、按 `XpertAPIService.getChatApp(name)` 判定的 `authGuard`，检索与评审时勿混。
- **真实代码示例**：
```ts
// @core/auth/auth.guard.ts —— 同步快判 + 清本地再跳登录
if (!!store.token) return true
await firstValueFrom(authStrategy.logout())
router.navigate(['/auth/login'], { queryParams: { returnUrl: state.url } }); return false
// @core/guards/onboard.guard.ts —— 首启分流
if (onboard.tenant) { router.navigate(['/home/']); return false } else if (onboard.error) { router.navigate(['/onboarding/unknown']); return false }
return true
```
