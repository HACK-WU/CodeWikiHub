## 1. 前端服务契约

### 1.1 `XpAuthService`（认证门面，11 个公开方法）

定义处：`auth/services/auth.service.ts`。它是 UI 与策略之间**唯一**的中间层，全部动作以 `strategyName` 参数化（不存在无策略名的调用）。

| # | 方法 | 用途 | 参数与策略语义 | 返回 / 异常 |
|---|---|---|---|---|
| 1 | `getToken()` | 读当前令牌 | 无 | `Observable<XpAuthToken>`（来自 `XpAuthTokenService`，**非** `Store.token`） |
| 2 | `isAuthenticated()` | 令牌是否有效 | 无 | `Observable<boolean>` = `token.isValid()`；读令牌存储，不看 `Store` |
| 3 | `isAuthenticatedOrRefresh()` | 有值但失效则先刷新 | 无 | 刷新成功 → 再判有效；失败 → `false`。本域未挂载 |
| 4 | `onTokenChange()` | 令牌变更广播 | 无 | `Observable<XpAuthToken>`（`tokenChange()`，空值被过滤） |
| 5 | `onAuthenticationChange()` | 登录态广播 | 无 | `onTokenChange()` 映射 `isValid()`；注释标注 showcase，无生产消费方 |
| 6 | `authenticate(name, data?)` | 登录 | `data` 透传策略（email 策略收 `{userName,password,rememberMe}`） | `Observable<XpAuthResult>`；成功后经 `processResultToken` 落 token |
| 7 | `register(name, data?)` | 注册 | 同上 | 同上；注册链结果不带 token |
| 8 | `logout(name)` | 登出 | 无 `data` | 策略成功时 `tokenService.clear()` |
| 9 | `requestPassword(name, data?)` | 申请重置 | 直通策略 | `XpAuthResult`；**不写令牌** |
| 10 | `resetPassword(name, data?)` | 执行重置 | 直通策略 | `XpAuthResult`；**不写令牌** |
| 11 | `refreshToken(name, data?)` | 刷新令牌 | `data` 可为现有 token 对象 | 成功后 `processResultToken` 落 token |

- 约束 1：`getStrategy(name)` 未命中时**同步抛** `TypeError("There is no Auth Strategy registered under '<name>' name")`——只写策略类不注册策略表 = 运行期崩溃，无编译期保护。
- 约束 2：`processResultToken(result)` 仅在 `result.isSuccess() && result.getToken()` 时落盘；现役 email 策略从不返回 token 对象，因此该分支在生产链路不触发。
- 约束 3：返回值统一为 `XpAuthResult`（`isSuccess` / `getToken` / `getRedirect` / `getErrors` / `getMessages`），页面只处理「成功/失败 + 跳哪里」，不解析 HTTP。

章节来源：[auth.service.ts](file://apps/cloud/src/app/auth/services/auth.service.ts)（关键符号：`XpAuthService.authenticate`、`getStrategy`、`processResultToken`、`onTokenChange`）· [auth-result.ts](file://apps/cloud/src/app/auth/services/auth-result.ts)（关键符号：`XpAuthResult.getRedirect`、`getErrors`）

### 1.2 `XpAuthStrategy` 抽象契约（实现新策略必须提供的成员）

**必须实现（abstract，全部返回 `Observable<XpAuthResult>`）**：`authenticate(data?)`、`register(data?)`、`requestPassword(data?)`、`resetPassword(data?)`、`logout()`、`refreshToken(data?)`。

**必须自带的声明**：`protected defaultOptions`（本策略的完整默认选项）+ 选项里的 `name`（`getName()` 读的就是它）；注册范式为 `static setup(options): [XpAuthStrategyClass, options]`。

**可直接复用的已实现能力**：

| 成员 | 语义与约束 |
|---|---|
| `setOptions(options)` | `deepExtend({}, this.defaultOptions, options)`，实例选项由此生效 |
| `getOption(key)` | 走 `getDeepFromObject`，点号路径取值；缺失返回 `null` |
| `createToken(value, failWhenInvalidToken?)` | 用 `token.class` 造 token；`failWhenInvalidToken` 为真且 `!isValid()` 时抛 `NbAuthIllegalTokenError`，**必须由策略自行拦截**（坏 token 不得进存储） |
| `getName()` | 返回 `options.name` |
| `createFailResponse()` / `createSuccessResponse()` | 401 / 200 的空 `HttpResponse`，供模板法分支使用 |
| `getActionEndpoint(action)` | `baseEndpoint + <action>.endpoint`；任一缺失返回 `''` ⇒ **可选端点可被停用** |

章节来源：[auth-strategy.ts](file://apps/cloud/src/app/auth/strategies/auth-strategy.ts)（关键符号：`XpAuthStrategy.createToken`、`getActionEndpoint`、`setOptions`）· [auth-strategy-options.ts](file://apps/cloud/src/app/auth/strategies/auth-strategy-options.ts)（关键符号：`XpAuthStrategyOptions`）

### 1.3 策略表结构（`XpAuthOptions` / `XpAuthStrategyOptions`）与注入令牌

- `XpAuthStrategyOptions = { name: string; token?: NbStrategyToken }`（策略选项的最小公共面）。
- `XpAuthStrategies = [XpAuthStrategyClass, XpAuthStrategyOptions][]`（**类 + 选项二元组数组**）。
- `XpAuthOptions = { forms?: any; strategies?: XpAuthStrategies }`。
- `defaultAuthOptions.forms`（各页行为由它规定）：`redirectDelay: 500`、`strategy: 'email'`、`showMessages.{success,error}`、`register.{terms, enablePublicSignup}`、`validation.password.{required, minLength: 4, maxLength: 50}`。

| 注入令牌 | 语义 |
|---|---|
| `XP_AUTH_OPTIONS` / `XP_AUTH_USER_OPTIONS` | 合并后选项 / 调用方原始选项 |
| `XP_AUTH_STRATEGIES` | 实例化后的策略数组（`XpAuthService` 的唯一依赖） |
| `XP_AUTH_TOKENS` / `XP_AUTH_FALLBACK_TOKEN` | 令牌类注册表 / 反序列化兜底类（默认 `NbAuthSimpleToken`） |
| `XP_AUTH_INTERCEPTOR_HEADER` | 默认 `'Authorization'` |
| `XP_API_BASE_URL` | consent 页用的 API 根（**提供方不在本模块内**） |

装配：`XpAuthModule.forRoot(options)` → `nbOptionsFactory`（`deepExtend(defaultAuthOptions, options)`）与 `nbStrategiesFactory`（逐个 `injector.get(strategyClass)` 后 `setOptions`）；落地注册点是 [auth.module.ts（@core）](file://apps/cloud/src/app/@core/auth/auth.module.ts)。

章节来源：[auth.options.ts](file://apps/cloud/src/app/auth/auth.options.ts)（关键符号：`XpAuthOptions`、`defaultAuthOptions`、`XP_AUTH_STRATEGIES`）· [auth.module.ts](file://apps/cloud/src/app/auth/auth.module.ts)（关键符号：`nbStrategiesFactory`、`nbOptionsFactory`、`XpAuthModule.forRoot`）

### 1.4 token 服务关键面（`TokenService` / `TokenStorage` / `TokenParceler`）

| 类型 | 关键面 |
|---|---|
| `XpAuthToken`（abstract） | 抽象 `getValue()` / `isValid()` / `getOwnerStrategyName()` / `getCreatedAt()`；具体 `getName()` / `getPayload()` |
| `NbAuthSimpleToken` | `NAME='nb:auth:simple:token'`；`isValid() = !!getValue()`（非空即有效） |
| `NbAuthJWTToken` | 解 JWT payload，`iat` 推导 `createdAt`，`isValid()` 叠加 `exp` 判定 |
| `NbAuthOAuth2Token` / `NbAuthOAuth2JWTToken` | `access_token` / `refresh_token` / `token_type` / `expires_in`；本域未使用 |
| `XpAuthTokenService` | `token$: BehaviorSubject`；`tokenChange()`（`filter(!!value)` + `share()`）、`get` / `set` / `clear`、`publishStoredToken`（构造时自发布一次） |
| `XpTokenStorage` / `XpTokenLocalStorage` | `get/set/clear`；localStorage 键 `auth_app_token`；换存储只需覆盖 provider |
| `XpAuthTokenParceler` | `wrap` / `unwrap`，包裹体 `{name, ownerStrategyName, createdAt, value}`；`unwrap` 按 `name` 找回类，回退 `XP_AUTH_FALLBACK_TOKEN` |
| `XpAuthTokenNotFoundError` / `NbAuthIllegalTokenError` / `NbAuthEmptyTokenError` / `NbAuthIllegalJWTTokenError` | 缺失 / 非法 / 空 / 非三段 JWT，由策略的 `handleResponseError` 收进 `errors` |

- **现场真相（必读）**：现役 token 台账在 `Store`（Akita `persistState({ key: '_xpertStore' })`），写入方只有 `AuthStrategy`（`Store.token` / `Store.refreshToken`）；`auth_app_token` 在生产路径**没有写入者**，所以 `XpAuthService.onTokenChange()` 不反映登录态变化——**全站登录态以 `Store` 为准**。
- 过期语义：`XpAuthToken` 自身不含过期；只有 JWT / OAuth2 子类由 `exp` / `expires_in` 计算 `getTokenExpDate()`，`isValid()` 才具时间意义。

章节来源：[token.ts](file://apps/cloud/src/app/auth/services/token/token.ts)（关键符号：`XpAuthToken`、`NbAuthSimpleToken`、`NbAuthJWTToken`）· [token.service.ts](file://apps/cloud/src/app/auth/services/token/token.service.ts)（关键符号：`XpAuthTokenService.tokenChange`、`publishStoredToken`）· [token-storage.ts](file://apps/cloud/src/app/auth/services/token/token-storage.ts)（关键符号：`XpTokenLocalStorage`）· [token-parceler.ts](file://apps/cloud/src/app/auth/services/token/token-parceler.ts)（关键符号：`XpAuthTokenParceler.wrap`）

## 2. 守卫契约（准入矩阵）

**本节是本域最核心的对外契约**——全站访问边界由这 5 个守卫 + `NoAuthGuard` 的例外规则决定。下表可照抄使用：

| 守卫 | 类型 / 位置 | 判定条件 | 拒绝时跳转目标 | 例外 |
|---|---|---|---|---|
| `authGuard` | `CanActivateFn` · `@core/auth/auth.guard.ts` | `!!store.token`（只读本地 store，**不发请求**） | 先 `await authStrategy.logout()` 清本地，再 `router.navigate(['/auth/login'], {queryParams:{returnUrl: state.url}})` | 无 |
| `NoAuthGuard` | 类 · `auth/guards/no-auth.guard.ts`（auth 路由在用） | ①`accept-invite` 例外命中 → 放行；②`!store.token` → 放行；③否则 `await authService.isAuthenticated()`，未认证 → 放行 | 已登录 → `router.navigate(['/home'])` | `routeConfig.path === 'accept-invite'` **且** query 同时含 `email` 与 `token` → **无条件放行** |
| `NoAuthGuard` | 类 · `@core/auth/no-auth.guard.ts`（**未挂载**，另一实现） | `await authService.isAuthenticated()`（HTTP） | 已登录 → `['/pages/dashboard']`（路由表中已不存在） | 无 |
| `inviteGuard` | 函数 · `@core/guards/invite.guard.ts`（**未挂载**） | `route.data.expectedPermissions.some(store.hasPermission)` **且** `selectedOrganization?.invitesAllowed` | 不满足 → `router.navigate(['/'])` | 无 |
| `onboardGuard` | 函数（返回 `Observable`）· `@core/guards/onboard.guard.ts` | `TenantService.getOnboard()`：有 `tenant` → 已开通；有 `error` → 探测失败；两者皆无 → 可引导 | `tenant` → `['/home/']`；`error` → `['/onboarding/unknown']` | 两者皆无 → 放行（进入 welcome / tenant 步） |
| `dirtyCheckGuard` / `DirtyCheckGuard`（`@deprecated`） | `CanDeactivateFn<IsDirty>` · `@core/guards/dirty-check.guard.ts` | `component.isDirty()`（signal / 函数 / 布尔兼容） | 不脏 → `true`；脏 → 弹 `ZardAlertDialogService.confirm`（`XP.KEY_WORDS.Confirm` / `XP.MESSAGE.ConfirmExitDirtyData`） | 用户取消 → 阻止离开（`false`），留在原页 |

**挂载实况**：

| 路由 | 守卫 | 说明 |
|---|---|---|
| `/onboarding`（根壳） | 无 | 子路由各自守卫 |
| `/onboarding`（welcome）、`/onboarding/tenant` | `onboardGuard` | 已开通用户被送回 `/home/`，不可重入 |
| `/onboarding/plugins` | `authGuard` | **必须已登录**（步 2 的 `afterOnboard` 自动登录才产生 token） |
| `/onboarding/unknown` | 无 | `onboardGuard` 的兜底落点 |
| `/auth/{request-password,reset-password,accept-invite,verify}` | `NoAuthGuard` | 未登录可用；已登录（除邀请例外）跳 `/home` |
| `/auth/{login,register,register-result,logout,sso-bind,sso-confirm,consent}` | 无 | 靠页面自身逻辑 |
| `artifacts/auth/:artifactLinkSlug`、`features/**`（`/chat`、`/explore`、`/xpert`、`/settings`、`/plugins`、`/operations` 等） | `authGuard`（部分叠加 `NgxPermissionsGuard`） | 企业内页面必须登录 |
| `/x-chatkit/**`、`/x/**`、`/sign-in/success`、`/plugins/marketplace` | **无** | 免登录是显式白名单，新增公共页必须显式评审 |

**`TokenInterceptor` 侧的两条硬约束**：`ANONYMOUS_AUTH_PATHS` = `/api/auth/login`、`/api/auth/sso/providers`、`/api/auth/sso/bind/{challenge,complete,register}`、`/api/tenant/onboard`（这几条 401 **不刷新**）；`addAuthenticationToken` 对 `auth/refresh` 请求注入 `store.refreshToken`，其余注入 `store.token`。

## 4. 代码示例（真实调用方）

① **走一次登录并读取 token**（表单 → 策略 → 落 `Store` → 拦截器读取）：

```ts
// login.component.ts（剪裁）
const result = await firstValueFrom(
  this.authService.authenticate(this.strategy, {          // this.strategy = forms.login.strategy = 'email'
    ...this.form.value,
    userName: this.form.value.userName?.toLowerCase()
  })
)
const redirect = this.route.snapshot.queryParams.returnUrl || result.getRedirect()
if (redirect) setTimeout(() => this.router.navigateByUrl(redirect), this.redirectDelay)

// @core/auth/auth-strategy.service.ts（剪裁）：令牌落地（唯一写入方）
this.store.userId = user.id
this.store.token = token
this.store.refreshToken = refreshToken
this.store.restoreRememberedScope(user.id)
```

```ts
loadInvite = async (email: string, token: string) => {
  try {
    this.invitation = await this.inviteService.validateInvite(['role', 'organization'], { email, token })
    if (!this.invitation) throw new Error()
  } catch (error) {
    this.inviteLoadErrorMessage = 'Invitation no longer valid'
  }
  this.loading = false
}

submitForm = async (input: IUserRegistrationInput) => {
  const { user, password, referralCode } = input
  const { id: inviteId, organization } = this.invitation
  await this.inviteService.acceptUserInvite({ user, password, referralCode, organization, inviteId })
  this.toastrService.success('Auth.ACCEPT_INVITE.PROFILE_UPDATED')
```
