## R1 打开编排画布并编辑
- **业务目标**：进入某 Xpert 的编排页，加载草稿并渲染为可拖拽节点图；编辑结果落回同一份草稿。
- **调用顺序**：路由 `/xpert/x/:id/agents` → `injectParams('id')` → `xpertService.paramId.set(id)` → `saveDraftSub`（`#refresh$` → `xpertService.onRefresh()` → `combineLatest([paramId$ → getXpertTeam(id) → initRole, #reload])`）→ `initRole`：`buildEditableXpertDraft(xpert)` + `store.update({ draft })` + `#reload.next(INIT)` → `subscribeOnReloadData`（`delay(100)` → 设 `position/scale` → `releaseInvalidParentNodes()` → `detectChanges()`）→ 画布 `nodes/connections` computed → `f-flow/f-canvas` 渲染。
- **事务-时序边界**：唯一网络边界是 `GET /api/xpert/:id/team`；其后全是同步内存写（`store.update(structuredClone(...))`），没有事务概念；重绘被显式延后 100ms（`delay(100)`），首帧与 `#reload` 之间存在时序窗口。
- **预期结果**：画布出现 draft 的节点与连线；点选节点后右侧面板按 `node.type` 分派（agent / xpert / toolset / knowledge / workflow）；面板改值经 `linkedModel.update` 写回 draft。
- **错误处理**：`getXpertTeam(id)` 链路上**未见 `catchError`**（初始化流出错不会自愈，需刷新页面）；`EReloadReason.MOVED` 被 `reload$` 过滤，拖拽不触发重绘。
- **真实代码示例**：
```ts
// studio.component.ts
readonly paramId = injectParams('id')
readonly viewModel = toSignal(this.apiService.store.pipe(map((state) => state.draft)))
public selectionChanged(event: FSelectionChangeEvent): void { this.selectionService.setNodes(event.fNodeIds) }
```

## R2 草稿自动保存（1s 去抖 → `:id/draft`）
- **业务目标**：编辑无需点保存即落库；保存过程中继续编辑不得丢改动。
- **调用顺序**：任意命令（`createConnection`/`moveConnection` 之外的 `moveNode`/`updateWorkflowNode`/`updateXpertAgent` 等）→ `store.update` → `#reload.next(reason)` → `saveDraftSub`：`calculateHash(JSON.stringify(storage))` → `unsaved.set(true)` → `debounceTime(1000)` → 等 `!settingsEditing()` → `saveDraft()`；手动路径为 header `saveDraft()` 与 `Ctrl+S`（`handleCtrlS`）。
- **事务-时序边界**：先 `structuredClone` 快照再交给 `DraftSaveQueue` **串行**提交（相邻同请求共享同一 Promise）；并发计数 `pendingDraftSaves`——最后一个请求返回才 `draftSaving.set(false)`；保存期间又有编辑则以 `unsaved.set(!isEqual(this.storage, snapshot))` 保持 dirty；设置弹窗打开时（`settingsEditing`）自动保存被挂起。
- **预期结果**：静默 1s 后发出 `POST /api/xpert/:id/draft`，成功则 `pristineDraft.set(saved)`、`savedEvent$.next(true)`（面板据此刷新变量）。
- **错误处理**：`draftSaveError.set(getErrorMessage(error))` + `toastr.error`；`unsaved` 保持 true，下一次去抖或发布前 `saveDraft()` 会重试。
- **真实代码示例**：
```ts
// domain/xpert-api.service.ts（saveDraftSub 节选）
map(() => calculateHash(JSON.stringify(this.storage))),
distinctUntilChanged(),
tap(() => this.unsaved.set(true)),
debounceTime(SaveDraftDebounceTime * 1000),
switchMap(() => this.settingsEditing$.pipe(filter(() => !this.settingsEditing()), take(1),
  switchMap(() => (this.unsaved() ? this.saveDraft() : EMPTY))))
```
章节来源：[xpert-api.service.ts](file://apps/cloud/src/app/features/xpert/studio/domain/xpert-api.service.ts)（关键符号：`saveDraftSub`、`SaveDraftDebounceTime`、`saveDraft`、`unsaved`、`pristineDraft`、`draftSaving`）、[draft-save-queue.ts](file://apps/cloud/src/app/@shared/xpert/assistant-settings/draft-save-queue.ts)（关键符号：`DraftSaveQueue.save`）

## R3 撤销 / 重做（双轨）
- **业务目标**：既能回滚状态，又能以「语义步骤」列给用户直接跳转。
- **调用顺序**：`Ctrl+Z` / `Ctrl+Y`（`onKeyDown`）或工具栏 `undo()`/`redo()` → `XpertStudioApiService.undo/redo` → `stateHistories`（语义栈）出栈入栈 + `#stateHistory.jumpToPast/jumpToFuture(cursor)` → `#reload.next(null)`；工具栏 `histories` computed 把 `past+future` 反转成菜单，`onGoToHistory(index)` → `gotoHistoryIndex(index)`。
- **事务-时序边界**：跳转是纯内存操作（不回写服务端），但跳转后 draft 哈希变化 → 仍进入 1s 去抖自动保存（撤销结果也会落库）；`stateHistory` 以 `comparatorFn: negate(isEqual)` 深比较判变化，语义条目追加被 `debounceUntilChanged(2000)` 与 cursor 去重。
- **预期结果**：画布回到上一语义步；`historyHasPast/historyHasFuture` 控制按钮可用态；`clearHistory()` 可把 present 重置为第 0 步。
- **错误处理**：`gotoHistoryIndex(index)` 依赖 `stateHistories().past[index - 1].cursor`，越界会抛错（未见守卫，如实记录）；`undo()` 用 `?? 0` 兜底。
- **真实代码示例**：
```ts
// domain/xpert-api.service.ts
undo() {
  const cursor = this.stateHistories().past[this.stateHistories().past.length - 2]?.cursor ?? 0
  this.stateHistories.update((state) => ({ past: state.past.slice(0, state.past.length - 1),
    future: [...state.past.slice(state.past.length - 1), ...state.future] }))
  this.#stateHistory.jumpToPast(cursor)
  this.#reload.next(null)
}
```
章节来源：[xpert-api.service.ts](file://apps/cloud/src/app/features/xpert/studio/domain/xpert-api.service.ts)（关键符号：`undo`、`redo`、`gotoHistoryIndex`、`clearHistory`、`stateHistories`）、[toolbar.component.ts](file://apps/cloud/src/app/features/xpert/studio/toolbar/toolbar.component.ts)（关键符号：`historyHasPast`、`histories`、`onGoToHistory`）

## R4 发布版本（草稿 → publish → 版本行）
- **业务目标**：把当前草稿固化为一个可运行的版本记录。
- **调用顺序**：header `publish()` → `XpertPublishVersionComponent` →（`unsaved()` 为真则先 `saveDraft()`）→ `xpertAPI.publish(id, newVersion, { environmentId, releaseNotes, businessAreaId, marketplace? })` → 成功 `toastr.success` + `studioService.refresh()` + `xpertService.published$.next(result)` + `close()`。
- **事务-时序边界**：两段 HTTP（先草稿后发布）**非原子**；`newVersion=true` 产新版本记录、`false` 覆盖当前版本；`releaseNotes` 少于 10 字符在提交前被 `releaseNotesError` 本地拦下。
- **预期结果**：`versions` 随后端 `#refresh$` 重取，header 版本菜单出现新行；宿主（知识库流水线）经 `published$` 得到通知并刷新。
- **错误处理**：`toastr.error(getErrorMessage(error))` 并复位 `loading`；业务域拉取失败置 `businessAreaLoadFailed` 并降级为空列表，不阻塞发布。
- **真实代码示例**：
```ts
// header/publish/publish.component.ts
const obser: Observable<any> = this.studioService.unsaved() ? this.studioService.saveDraft() : of(true)
obser.pipe(switchMap(() => this.xpertAPI.publish(this.xpert().id, this.newVersion(), {
  environmentId: this.environmentId(), releaseNotes: this.releaseNotes(), businessAreaId: this.businessAreaId(),
  ...(this.agentMarketplaceEnabled() ? { marketplace: this.marketplacePayload() } : {}) })))
```
章节来源：[publish.component.ts](file://apps/cloud/src/app/features/xpert/studio/header/publish/publish.component.ts)（关键符号：`publish`、`newVersion`、`agentMarketplaceEnabled`、`businessAreaLoadFailed`、`releaseNotesError`）、[header.component.ts](file://apps/cloud/src/app/features/xpert/studio/header/header.component.ts)（关键符号：`publish`、`latestPublishDate`）

## R5 版本查看与 `resume()` 回到已发布态
- **业务目标**：查看同 family 的历史版本、切换版本，或丢弃草稿回到已发布态。
- **调用顺序**：`versions`（`#refresh$ → paramId$ → xpertAPI.getVersions(id)`）→ header 倒序展示、`latestPublishDate` 取 `team()?.publishAt`；`selectVersion(id)` → `router.navigate(['../../', id, 'agents'])`；`resume()` → `xpertAPI.update(team().id, { draft: null })` → `refresh()` → 重新 `GET team` → `buildEditableXpertDraft` 回退到 `xpert.graph`。
- **事务-时序边界**：`resume()` 是「服务端先置空、前端整体重载」两步；返回前内存仍是旧草稿；重载 `tap` 内 `#stateHistory.clear()` 与 `pristineDraft.set(xpert.draft)` 会把历史与草稿一并重置；版本切换 = 跳到另一条 Xpert 记录，不携带本页 draft。
- **预期结果**：`resume()` 后画布回到已发布图，`unsaved` 归零；版本菜单可来回切换多条记录。
- **错误处理**：`resume()`/`versions` 链路未见 `catchError`（失败仅表现为界面无变化，如实记录）。
- **真实代码示例**：
```ts
// domain/xpert-api.service.ts / header.component.ts
public resume() { this.xpertAPI.update(this.team().id, { draft: null }).subscribe(() => { this.refresh() }) }
readonly versions = toSignal(this.#refresh$.pipe(switchMap(() => this.paramId$.pipe(distinctUntilChanged())),
  switchMap((id) => this.xpertAPI.getVersions(id))))
selectVersion(id: string) { this.router.navigate(['../../', id, 'agents'], { relativeTo: this.route }) }
```
章节来源：[xpert-api.service.ts](file://apps/cloud/src/app/features/xpert/studio/domain/xpert-api.service.ts)（关键符号：`resume`、`refresh`、`versions`、`initRole`）、[header.component.ts](file://apps/cloud/src/app/features/xpert/studio/header/header.component.ts)（关键符号：`selectVersion`、`versions`、`latest`、`draftSavedDate`）

## R6 执行调试、检查点与重跑
- **业务目标**：在画布上跑当前草稿（整图或单 Agent），看清每个节点在跑什么、卡在哪，并能从某检查点重跑。
- **调用顺序**：（a）预览：`ChatConversationPreviewComponent.chat({ isDraft: true })` → `POST /api/xpert/:id/chat`（SSE）→ `onChatEvent` → `processEvents(event, executionService)` → `setAgentExecution/setContextUsage` → 画布 `executions` 染色；（b）单 Agent：`startRunAgent()`（先 `validateParameterValues`）→ `chatAgent({ action: 'run' | 'resume' })`（SSE）→ 事件分支再交 `processEvents`；（c）检查点：选中执行 → `inspectorExecutionId` → `forkJoin(getOneLog, getCheckpoints)` + effect 拉 `getOneState` → `snapshotCache`；`rerunFromCheckpoint()` → `requestPreviewRetry(messageId, checkpointId)` → 预览面板 effect 消费 nonce → `preview.retryMessage(...)` → `chat({ retry: true, … })`。
- **事务-时序边界**：SSE 长连接只负责实时增量，HTTP 负责骨架与历史（会话 `getById(relations: ['messages'])`、日志 / 检查点 / 快照）；收到 `RUNTIME_STREAM_INTERRUPTED_EVENT` 直接 error 且不重试 POST（防重复执行）；重跑完成由 `ON_AGENT_END`（`!parentId` 且 `checkpointNs === ''`）或 `ON_CONVERSATION_END` 判定并自动选中该执行。
- **预期结果**：节点/连线出现 running 态与悬浮执行卡片；`contextUsageByAgentKey` 在 Agent 执行面板显示；检查器列出分组变量并支持重跑。
- **错误处理**：`onChatError` → `toastr.error` + `markError`（把 RUNNING 执行批量置 ERROR）；检查器加载失败 toastr；缺 `messageId/checkpointId` 时提示 `XP.Xpert.ExecutionRetrySourceMissing`；`ON_TOOL_*`/`ON_RETRIEVER_*` 分支为注释态，未处理事件走 `default` 打 `console.log`。
- **真实代码示例**：
```ts
// panel/agent-execution/execution.component.ts
this.#agentSubscription = this.xpertAgentService.chatAgent(request).subscribe({
  next: (msg) => { if (msg.event === 'error') { this.onChatError(msg.data) }
    else { const event = JSON.parse(msg.data)
      if (event.type === ChatMessageTypeEnum.EVENT) { processEvents(event, this.executionService) } } },
  error: (error) => { this.onChatError(getErrorMessage(error)) } })
// components/state-inspector/state-inspector.component.ts
rerunFromCheckpoint() {
  const messageId = this.retryMessageId(); const checkpointId = this.selectedCheckpointId()
  if (!messageId || !checkpointId) { this.#toastr.error('XP.Xpert.ExecutionRetrySourceMissing', '',
    { Default: 'Retry source message not found' }); return }
  this.executionService.requestPreviewRetry(messageId, checkpointId)
}
```

## R7 Copilot 辅助编排
- **业务目标**：让助手在了解当前画布上下文的前提下给建议，并能驱动画布跳转/刷新。
- **调用顺序**：宿主 `providers` 覆盖 `CopilotServerService` → `XpertStudioCopilotServerService.getCopilotModels(type)`（按当前 xpert 收敛模型候选）→ 面板 `CopilotModelSelectComponent`；上下文方向：`effect` → `assistantFacade.setStudioContext({ targetXpertId, baseDraftHash, unsaved })` → 助手请求上下文带 `targetXpertId/unsaved/baseDraftHash`；助手侧 effect `navigate_to_studio` → `router.navigate(['/xpert/x', xpertId, 'agents'])`、`refresh_studio` → `emitStudioRefresh` → 画布 effect → `apiService.refresh()`。
- **事务-时序边界**：Copilot **不直接写 draft**——真正的编辑仍走画布命令 + 1s 去抖保存；`studioRefresh` 带 `nonce` 去重，且仅在「路由 xpertId 与当前 id 一致」时生效。
- **预期结果**：模型下拉只出现该 xpert 的 Copilot 模型；助手能定位/刷新画布，草稿未保存状态会同步给助手（助手可据此提醒先保存）。
- **错误处理**：`XpertAssistantFacade` 以 `{ optional: true }` 注入，非 assistant-shell 环境缺失时 effect 直接 `return`；宿主销毁与 xpertId 不匹配时调 `clearStudioContext()`。
- **真实代码示例**：
```ts
// xpert-studio-copilot-server.service.ts
override getCopilotModels(type: AiModelTypeEnum) {
  return this.#xpertId$.pipe(distinctUntilChanged(),
    switchMap((xpertId) => (xpertId ? this.getXpertCopilotModels(xpertId, type) : of([])))) }
// studio.component.ts
this.#assistantFacade.setStudioContext({ targetXpertId: currentXpertId,
  baseDraftHash: pristineDraft ? calculateHash(JSON.stringify(pristineDraft)) : null, unsaved: this.apiService.unsaved() })
```

## R8 画布复用嵌入（知识库流水线）
- **业务目标**：在别的页面复用整套编排画布，而不是复制一份实现。
- **调用顺序（接入 5 步）**：① `imports: [XpertStudioComponent]`；② 宿主 `providers: [XpertService]`；③ 保证路由参数含 `id`（画布内 `injectParams('id')` → `xpertService.paramId.set`）；④ 模板放 `<xp-xpert-studio />`；⑤ 需要联动时订阅 `xpertService.published$`。
- **事务-时序边界**：画布的 `providers`（`XpertStudioApiService`/`SelectionService`/`XpertExecutionService`/`JsonSchemaWidgetStrategyRegistry` + `CopilotServerService` 覆盖）是**组件级**，每个实例独立 store / 选中态 / 执行态；同一 `id` 即同一草稿端点，宿主与 Studio 共享同一份编排（无第二存储）。
- **预期结果**：流水线页拿到与 Studio 一致的画布与草稿读写；发布成功后宿主刷新（知识库 `refresh()`）。
- **错误处理**：宿主无 `id` 时 `paramId$` 的 `filter(nonBlank)` 使初始化链不触发 → 画布空白且无显式报错（需宿主自行保证 id）。
- **真实代码示例**：
```ts
// features/xpert/knowledge/knowledgebase/pipeline/pipeline.component.ts
@Component({ selector: 'xp-knowledgebase-pipeline', imports: [RouterModule, XpertStudioComponent], providers: [XpertService] })
export class KnowledgebasePipelineComponent {
  private publishedSub = this.xpertService.published$.subscribe({ next: () => { this.knowledgebaseComponent.refresh() } }) }
```
