## 1. 运维边界说明

- Studio 是前端模块：**没有**服务端部署、实例、数据库、定时任务等运维对象；对应的服务端运维面在 `xpert` / `xpert-agent` / `xpert-agent-execution` 等 NestJS 模块（见 `.fe-index/xpert-server/modules/*.md`）。
- 本模块可见的运维杠杆只有四类：**路由准入**（谁能进入画布）、**特性开关**（功能可见性）、**运行配置**（API 基址/代理/帮助站点）、**资产与日志**（i18n 语言包、NGXLogger 级别）。
- 线上 URL 形态：`useHash: false`（`app-routing.module.ts:45-48`），Studio 完整地址为 `/xpert/x/:xpertId/agents`。

章节来源：[app-routing.module.ts](file://apps/cloud/src/app/app-routing.module.ts)（关键符号：`useHash`、`SelectivePreloadingStrategy`）

## 3. 特性开关（featureGate）现状

- `featureGate(featureKeys, redirectCommands)`：先 `hydrateFeatureContext()`（3s 超时）再校验 `store.hasFeatureEnabled(key)`，不满足则 `createUrlTree(redirectCommands)`（`features/feature-gate.ts:10-39`）。
- 现有用法：`xpertMarketplaceRouteGate`（`FEATURE_XPERT + FEATURE_XPERT_MARKETPLACE` → `/explore`）、`xpertProjectRouteGate`（`FEATURE_XPERT + FEATURE_XPERT_PROJECT` → `/chat`）（`features-routing.module.ts:14-22`，应用于 `:54`、`:169`）。
- **Studio 路由当前未挂任何 featureGate**；模块内唯一与特性开关相关的判断在发布对话框：`agentMarketplaceEnabled = featureContextHydrated() && store.hasFeatureEnabled(FEATURE_XPERT_MARKETPLACE)`，用于决定是否提交 marketplace 字段（`header/publish/publish.component.ts:82-88,239-244`）。
- 结论：以 `AiFeatureEnum.FEATURE_XPERT` 关闭特性时，`/xpert/...` 路由仍可进入（由服务端鉴权失败兜底）——这是当前实现的客观状态。

章节来源：[feature-gate.ts](file://apps/cloud/src/app/features/feature-gate.ts)（关键符号：`featureGate`、`hydrateFeatureContext`）、[publish.component.ts](file://apps/cloud/src/app/features/xpert/studio/header/publish/publish.component.ts)（关键符号：`agentMarketplaceEnabled`）

## 7. 日志（NGXLogger）

- **全局配置**：`app.module.ts:57-62` `LoggerModule.forRoot({ level: WARN, serverLogLevel: ERROR, enableSourceMaps: true })`；另有 `provideLogger()`（`@core/providers/logger.ts:5-13`）在 **production 用 WARN、开发用 DEBUG**，`serverLoggingUrl` 目前被注释（未上报服务端日志）。
- **Studio 内用法**：`XpertStudioComponent` 注入 `NGXLogger`（`studio.component.ts:160`，字段 `logger`），但在 studio 目录内检索 `logger` 仅命中"导入 + 注入"两处，**未见 `logger.debug/info/warn/error` 调用**——即画布本身几乎不打日志。
- **实际日志发生在 @core 服务层**：`XpertAPIService`（`xpert.service.ts:129`）、`XpertAgentService`（`xpert-agent.service.ts:12`）、`XpertToolsetService`（`xpert-toolset.service.ts:29`）、`XpertAgentExecutionService`（`xpert-agent-execution.service.ts:13`）等均注入 `NGXLogger`；调整 Studio 相关问题排查粒度需要改这些服务的日志级别或 `provideLogger()`。
- 其余运行期"类日志"信号：浏览器 `console.log`（未处理事件，`processEvents` default 分支，`panel/agent-execution/execution.component.ts:554-556`）与 `console.warn`（拖拽到无效分组，`studio.component.ts:713-717`）。

## 8. 在线排查要点

- **SSE 流中断**：`/api/xpert/:id/chat`、`/api/xpert-agent/chat` 走 `fetch-event-source`；服务端下发 `RUNTIME_STREAM_INTERRUPTED_EVENT`（如 `RUNTIME_RESTARTING`）时前端**主动 error 且不重试 POST**（避免重复执行）（`fetch-event-source.ts:95-117`）——排查"回复半截消失"时优先看该事件。
- **401 自动恢复**：SSE 通道在 401 时刷新令牌并重试一次（`fetch-event-source.ts:78-84`）；连续失败会直接终止流。
- **画布"改动丢失"**：草稿保存是 1s 去抖 + `DraftSaveQueue` 串行（`domain/xpert-api.service.ts:96,261-334,375-398`）；若保存接口持续失败，`draftSaveError` 与 toastr 会给出错误文案，同时 `unsaved` 保持为真。
- **版本错乱**：确认当前 `xpertId` 指向的是同一 family 的哪条版本记录（header 的版本菜单会切换路由到另一 id），以及 `latest` 标记是否被 `POST /api/xpert/:id/latest` 变更过。

章节来源：[fetch-event-source.ts](file://apps/cloud/src/app/@core/services/fetch-event-source.ts)（关键符号：`RuntimeStreamInterruptedError`、`auth.refreshToken`）、[xpert-api.service.ts](file://apps/cloud/src/app/features/xpert/studio/domain/xpert-api.service.ts)（关键符号：`draftSaveError`、`DraftSaveQueue`）
