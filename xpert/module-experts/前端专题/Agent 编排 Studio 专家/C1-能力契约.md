## 1. 前端组件对外契约

**1.1 `XpertStudioComponent` 契约面**

| 契约项 | 内容 |
|---|---|
| 形态 | standalone 组件，选择器 `xp-xpert-studio`，`ChangeDetectionStrategy.OnPush`，模板 `studio.component.html` |
| 输入 / 输出 | **无 `@Input` / `@Output`**：入场契约 = 路由参数 + DI |
| 路由参数 | `id`；组件内 `injectParams('id')`（`ngxtension/inject-params`），effect 写入 `XpertService.paramId` |
| 必需 provider（宿主） | `XpertService`（`paramId` / `onRefresh` / `published$` 的唯一来源） |
| 可选 provider | `XpertAssistantFacade`（`{ optional: true }`）：提供则启用助手上下文同步与 `studioRefresh` |
| 组件级 providers（自备） | `XpertStudioApiService`、`SelectionService`、`XpertExecutionService`、`JsonSchemaWidgetStrategyRegistry`、`...provideJsonSchemaWidgets()`；并以 `{ provide: CopilotServerService, useClass: XpertStudioCopilotServerService }` 覆盖 |
| 对外成员 | `sidePanel`（`model<'preview' \| 'variables' \| 'environments' \| 'commands'>`）、`viewModel` / `xpert` / `team` / `id` / `rootAgent`、`nodes` / `connections` / `groups` / `xperts` / `startNodes`、`executions` / `toolMessages` / `runningToolsets` / `selectAgentStatus`、`centerGroupOrNode`、`selectionChanged` / `onSelectNode` / `onFocusNode`、`onDropToGroup` |

**1.2 复用画布必须提供什么**

1. **`XpertService`**：放在复用组件的 `providers`（知识库流水线即 `providers: [XpertService]`），否则注入失败。
2. **xpertId 来源**：路由参数 `id`（组件自动读入并写入 `xpertService.paramId`），或宿主直接 `xpertService.paramId.set(teamId)`——缺失时 draft 为空，所有资源位流也不产出。
3. **可导航的路由上下文**：组件 imports 内含 `RouterModule`，`selectVersion()` / `gotoWorkspace()` 会 `navigate`，复用方需处在可导航的路由树中。
4. **（可选）`XpertAssistantFacade`**：仅当需要助手协作（`setStudioContext` / `clearStudioContext` / `studioRefresh`）时提供。
5. **（可选）发布感知**：订阅 `XpertService.published$` 以在发布成功后刷新外部视图（知识库流水线用它触发 `knowledgebaseComponent.refresh()`）。

## 3. store 与服务能力契约

**3.1 draft store 与草稿保存语义**

| 契约点 | 用途 / 参数行为语义 / 返回 / 异常 |
|---|---|
| `store` | `createStore({ name: 'xpertStudio' }, withProps<IStudioStore>({ draft: null }))`；唯一状态切片 `IStudioStore.draft`；`get storage()` 读当前 draft |
| `viewModel` / `_draft` / `xpert` | `draft` 的 signal 视图 / linkedModel（写即整体替换草稿）/ `attrModel(_draft, 'team')` |
| `pristineDraft` / `unsaved` | 最近一次服务端确认快照 / 脏标记（保存后按 `isEqual(storage, snapshot)` 重算） |
| `draftSaving` / `draftSaveError` | 串行保存进行中（`pendingDraftSaves` 归零才置 false）/ 最近一次失败文案 |
| `savedEvent$` | `BehaviorSubject<boolean>`，保存前后广播；面板据此刷新可用变量 |
| `reload$` / `reload()` | 重绘总线；`EReloadReason.MOVED` 被过滤（拖拽不触发重绘） |
| `saveDraft()` / `resume()` | `saveDraft()` 返回 Observable：`structuredClone` 快照 → `DraftSaveQueue` 串行 → `POST /api/xpert/:id/draft`，成功后写 `pristineDraft`，失败写 `draftSaveError` 并 rethrow；`resume()` = `PUT /api/xpert/:id {draft:null}` + `refresh()` |
| `refresh()` / `refreshSettingsView()` / `settingsEditing` | 重取 team（`#refresh$`）/ 只重绘不排产自动保存 / 设置弹窗打开时阻断自动保存队列 |

**3.2 `XpertStudioApiService` 编辑命令与查询方法**

| 方法 | 用途 / 参数行为语义 / 返回 / 异常 |
|---|---|
| `undo()` / `redo()` / `gotoHistoryIndex(index)` / `getHistoryCursor()` / `clearHistory()` | 双轨历史：`#stateHistory`（elf 快照栈）+ `stateHistories`（`TStateHistory{reason,cursor,createdAt}`）；跳转后发 `#reload.next(null)`；`clearHistory()` 保留 present 为唯一步 |
| `createConnection({sourceId,targetId})` / `removeConnection(sourceId,targetId)` / `updateConnection(key, updater)` | 连接增删改；目标节点不存在时连接创建**静默 return（不抛错）**；reload 语义 `CONNECTION_CHANGED` |
| `moveNode(key, position)` / `resizeNode(key, size)` | `moveNode` 只写 store + `MOVED`（被 `reload$` 过滤，不重绘）；`resizeNode` 发 `RESIZE` |
| `createAgent(position, agent?, fromKey?)` / `createToolset(position, toolset)` / `createKnowledge(position, knowledge)` | 建节点后 `#reload(AGENT_CREATED / TOOLSET_CREATED / KNOWLEDGE_CREATED)`；`createAgent` 传 `fromKey` 时自动连线 |
| `removeNode(key)` / `expandXpertNode(key)` / `pasteNode(node)` | 删除节点 / 展开外部专家为内部图（`ExpandTeamHandler` 会按需拉 `getXpertTeam`）/ 粘贴（agent、workflow 两类分支） |
| `updateNode(key, fn)` / `updateWorkflowNode(key, fn)` / `updateXpertAgent(key, entity, { emitEvent }?)` | 节点级写回并重算 `hash`；`updateNode` 抛 `Node with key ${key} not found!`，`updateWorkflowNode` 抛 `Workflow node with key ${key} not found`；`emitEvent:false` 可抑制 `#reload` |
| `updateXpertTeam(fn, reason?)` / `updateXpertOptions(options, reason)` / `updateXpertAgentConfig(config, reason?)` / `updatePrimaryAgent(fn)` | 对 `draft.team`（`Partial<IXpert>`）浅合并后 `#reload(XPERT_UPDATED)` |
| `autoLayout()` / `getNode(key)` / `getToolset(id)` / `getKnowledgebase(id)` / `getVariables({ xpertId, workflowKey?, agentKey?, type })` | 自动布局（`Promise<void>`，elkjs 只回写 `position`）/ 内存查节点 / 工具集详情缓存 `{ toolset$, refresh$ }` / 知识库详情缓存 / 变量候选（workflow 与 agent 两个分支） |

**3.3 `XpertExecutionService` 执行态契约**

| 成员 | 用途 / 参数行为语义 / 返回 / 异常 |

① 加载编排并保存草稿（宿主写入 `paramId`，头部触发保存）：

```ts
// studio.component.ts（剪裁）
readonly paramId = injectParams('id')

effect(() => { if (this.paramId()) this.xpertService.paramId.set(this.paramId()) })

// header/header.component.ts（剪裁）
saveDraft() { this.apiService.saveDraft().subscribe() }
@HostListener('window:keydown', ['$event'])
handleCtrlS(event: KeyboardEvent) {
  if (!this.apiService.settingsEditing() && (event.metaKey || event.ctrlKey) && event.key === 's') {
    this.saveDraft()
  }
}
```

② 发布版本（先确保草稿已落盘，再固化并刷新）：

```ts
// header/publish/publish.component.ts（剪裁）
publish() {
  this.loading.set(true)
  const obser: Observable<any> = this.studioService.unsaved() ? this.studioService.saveDraft() : of(true)
  obser.pipe(switchMap(() =>
    this.xpertAPI.publish(this.xpert().id, this.newVersion(), {
      environmentId: this.environmentId(), releaseNotes: this.releaseNotes(), businessAreaId: this.businessAreaId()
    })
  )).subscribe({
    next: (result) => { this.studioService.refresh(); this.xpertService.published$.next(result) },
    error: (error) => this.#toastr.error(getErrorMessage(error))
  })
}
```
