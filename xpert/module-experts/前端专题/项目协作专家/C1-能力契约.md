## 1. 前端契约

### 1.1 `XpertProjectFacade` 成员语义

定义处 `features/project/project.facade.ts`，`@Injectable({ providedIn: 'root' })`，注入 `XpertProjectApiService` 与 `@core` 的 `XpertTaskService`。信号面（逐成员）：

| 成员 | 类型 | 语义与约束 |
|---|---|---|
| `project` / `projects` | `Signal<IXpertProject \| null>` / `Signal<IXpertProject[]>` | 当前详情 / 列表页集合 |
| `projectsTotal` | `Signal<number>` | 列表总数（用于分页按钮） |
| `plans` / `tasks` | `Signal<IXpertProjectPlan[]>` / `Signal<IXpertProjectTask[]>` | overview 回填的聚合；计划/任务写操作就地更新 |
| `conversations` | `Signal<IChatConversation[]>` | 项目会话列表（`loadConversations` 填充） |
| `assets` / `assetsTotal` / `assetCount` | `Signal<...>` | 资产当前页 / 查询总数 / **仅根查询**更新的计数 |
| `activities` / `automations` | `Signal<...>` | 概览活动流与项目自动化（overview 回填） |
| `scheduledTasks` | `Signal<IXpertTask[]>` | `XpertTaskService.getAll({ where: { projectId }, take: 50, desc })` |
| `projectInstruction` / `projectSkills` / `projectContentError` | `Signal<...>` | 项目指令、技能摘要、两路 `allSettled` 失败合并错误 |
| `projectAccess` | `Signal<TXpertProjectAccessSummary \| null>` | 权限摘要；**`null` = pending / 不可用 / 被拒（fail-closed）** |
| `loading` / `error` | `Signal<boolean> \| Signal<string \| null>` | 列表加载态与错误 |
| `projectLoading` / `projectError` | 同上 | 详情加载态与错误（与列表态分离） |
| `conversationsLoading` / `conversationsError`、`assetsLoading` / `assetsError` | 同上 | 会话、资产各自的伴生态 |
| `hasProject` | `Signal<boolean>` | `Boolean(project())` 派生 |

方法面（全部 `async`，返回服务端实体或 `null`；序号守卫为私有实现，`#projectsLoadSequence`/`#projectLoadSequence`）：
`loadProjects(query)`（子集过滤器＋`status/skip/take`，返回 `items`，失败写 `error` 并返回 `[]`）· `loadProject(id)`（清空聚合子集→拉主记录→并发派生 overview/content/access/scheduledTasks，返回 `IXpertProject|null`）· `loadConversations(projectId = project()?.id)`（无 id 清空返回 `[]`）· `createProject(input)`（抢序号防旧列表覆盖）· `updateProject(input)` / `saveProjectInstructions(content)` · `reloadScheduledTasks(projectId?)` / `reloadProjectContent(projectId?)` · `addXpert(xpertId)` / `removeXpert(xpertId)` · `createPlan(input)` / `updatePlan(planId,input)` / `createMilestone(planId,input)` / `updateMilestone(planId,milestoneId,input)` / `createSprint(planId,input)` · `createTask(input)` / `updateTask(taskId,input)` / `reorderTasks(items)` / `loadTaskRelations(taskId)`（返回 `{conversations, executions}`）· `loadAssets(projectId,{parentId,kind,skip,take,append})` / `createAsset(input)` / `uploadAsset(file)` · `createAutomation(input)` / `updateAutomation(automationId,input)`。

### 1.3 `project-entry` 与 `project-chat-create` 解析函数

- `navigateProjectEntry(router, entry)`：`entry.kind === 'project'` → `entry.projectId ? router.navigate(['/project', entry.projectId]) : Promise.resolve(false)`；否则（`kind === 'assistant'`）→ `router.navigate(entry.projectId ? ['/chat/x', entry.slug, 'p', entry.projectId, 'c'] : ['/chat/x', entry.slug, 'c'], { queryParams: { view: entry.viewKey, viewSelection: entry.selectionId } })`。
- `XpertProjectEntry`（契约类型）闭合二分支：`{ kind:'project'; projectId?; projectType }` 与 `{ kind:'assistant'; xpertId; slug; projectId?; viewKey; selectionId? }`；`XpertProjectTypeRef` 只认 `applicationKey` + `projectTypeKey` 非空字符串。
- `chatProjectCreateRequest(event, data?)`：识别 `project.create-entry`（返回 `{kind:'entry', projectType}` 或 `null`）与 `project.create`（`name` 去空白后必须非空；`projectType` 存在但畸形时整体返回 `null`）。
- `executeChatProjectCreate(api, router, request, assistantId, select)`：`kind:'entry'` → `api.typeEntry(type, { xpertId: assistantId })` 后 `navigateProjectEntry`；`kind:'create'` → `api.create({ name, xpertIds:[assistantId], projectType? })` 后回调 `select(project.id)`（由调用方决定选中语义，对话域传 `onChatProjectChange`）。

章节来源：[project-entry.ts](file://apps/cloud/src/app/features/project/project-entry.ts)（关键符号：`navigateProjectEntry`）、[project-chat-create.ts](file://apps/cloud/src/app/features/project/project-chat-create.ts)（关键符号：`ChatProjectCreateRequest`、`chatProjectCreateRequest`、`executeChatProjectCreate`）、[xpert-project-type.model.ts](file://packages/contracts/src/ai/xpert-project-type.model.ts)（关键符号：`XpertProjectEntry`、`XpertProjectTypeRef`、`GENERAL_PROJECT_TYPE`）

## 2. 后端接口调用面

口径：基址 `API_XPERT_PROJECT = '/api/xpert-project'`；任务面基址为 `@core` `XpertTaskService` 的 `/api/xpert-task`。**逐端点参数与消费场景的完整清单见 `implementation/01-架构.md`（组件详细分析）与 [C0-使用总览.md](file://.module-experts/前端专题/项目协作专家/C0-使用总览.md) §3，此处只列契约必需项。** 后端 `xpert-project` 域**尚未建专家**（`.module-experts/后端专题/T0-专题总览.md` 批次 5 候选），端点语义以服务端源码为准。

| 端点（节选，均为 `/api/xpert-project` 下） | 用途 / 消费方 |
|---|---|
| `GET /my`（`data` JSON：where/order/skip/take） | 我的项目分页 → `XpertProjectFacade.loadProjects` |
| `GET /types`、`GET /type-entry` | 类型目录与入口解析 → `project-list`（`types`/`typeEntry`）、`project-chat-create` |
| `GET /:id`（`relations:['owner','xperts']`）、`GET /overview?projectId=`、`GET /:id/access` | 详情 / 概览 / 权限摘要 → `loadProject` 及其派生 |
| `GET/POST/PATCH/DELETE /:id/members[/:userId]`、`PATCH /:id/owner` | 成员与所有权 → `project-members-dialog` |
| `GET/POST/DELETE /:id/invitations[/:invitationId]`、`POST /invitations/accept`、`POST /invitations/decline` | 邀请生命周期 → `project-members-dialog`、`project-invitation-accept` |
| `GET/PUT /:id/content/instructions`、`GET/POST/PATCH/DELETE /:id/content/skills*` | 指令与技能 → `project-config` |
| `/:id/plans*`、`/:id/tasks*`、`/:id/assets`、`/:id/automations*`、`/:id/file/upload` | 计划/任务/资产/自动化与资产上传 → 门面写路径 |
| `/:id/workspace/{files,file,file/upload}`、`/:id/conversations`、`/:id/activities` | 工作区文件与会话/活动 → `project-assets`、`project-tasks` |
| `POST /api/xpert-task/:id/run-as/proposal`、`POST /api/xpert-task/:id/run-as/accept` | run-as 提案/接受 → `project-config`（经 `XpertTaskService.proposeRunAs`/`acceptRunAs`） |

## 3. 代码示例（真实调用方）

① **加载项目列表与详情（门面 + 伴生态 + 序号守卫）**：

```ts
// project-list.component.ts（剪裁）：列表页以 effect + 防抖驱动查询
effect((onCleanup) => {
  const query = this.query()
  this.skip.set(0)
  const timer = setTimeout(() => void this.facade.loadProjects({ ...query, take: 50 }), 200)
  onCleanup(() => clearTimeout(timer))
})

// project-shell.component.ts（剪裁）：壳按路由 id 加载详情
this.#route.paramMap.pipe(map((params) => params.get('id') ?? ''), distinctUntilChanged(), takeUntilDestroyed(this.#destroyRef))
  .subscribe((id) => { this.id.set(id); if (id) void this.facade.loadProject(id) })
```

② **创建项目内会话并挂载 ChatKit（面板锁定项目）**：

```ts
// project-chat-panel.component.ts（剪裁）
readonly identity = computed(() => {
  const projectId = this.projectId().trim()
  const assistantId = this.assistantId()
  return projectId && assistantId ? `project-chat:${projectId}:${assistantId}` : null
})
readonly control = injectHostedAssistantChatkitControl({
  identity: this.identity,
  assistantId: this.assistantId,
  projectId: computed(() => this.projectId().trim() || null),
  frameUrl: this.chatkitFrameUrl,
  composer: computed(() => ({ projects: { enabled: true, locked: true, label: this.project()?.name || this.projectId() } })),
  initialThread: this.initialThreadId,
  onThreadChange: ({ threadId }) => this.threadChanged.emit(threadId)
})

// project-shell.component.ts（剪裁）：URL 驱动会话与线程
onChatThreadChanged(threadId: string | null) {
  if (threadId === this.chatThreadId()) return
  void this.#router.navigate([], { relativeTo: this.#route, queryParams: { threadId }, queryParamsHandling: 'merge', replaceUrl: true })
}
```

③ **解析 `type-entry` 入口与创建事件**：

```ts
// project-list.component.ts（剪裁）：打开项目先解析受管入口
async openApplication(project: IXpertProject) {
  if (!project.applicationKey || !project.projectTypeKey) return this.#router.navigate(['/project', project.id])
  return await navigateProjectEntry(this.#router, await firstValueFrom(
    this.#api.typeEntry({ applicationKey: project.applicationKey, projectTypeKey: project.projectTypeKey }, { projectId: project.id })
  ))
}

// project-chat-create.ts（剪裁）：对话域 ChatKit effect → 解析 → 建项目或跳宿主视图
const projectRequest = chatProjectCreateRequest(event)   // clawxpert-conversation-detail.component.ts 侧
await executeChatProjectCreate(this.#projectApi, this.#router, request, assistantId, (projectId) =>
  this.facade.onChatProjectChange?.(projectId)
)
```
