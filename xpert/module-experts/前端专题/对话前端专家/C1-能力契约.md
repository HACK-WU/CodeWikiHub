### 1.1 `WorkbenchChatFacade` 成员语义

定义处：`features/chat/workbench-chat/workbench-chat.facade.ts`。它是页面骨架 `ClawXpertConversationDetailComponent` 的**唯一依赖**，共 31 个成员（含 7 个可选），由三个实现体分别满足。

| 成员 | 类型 | 语义与约束 |
|---|---|---|
| `definition` | `WorkbenchChatDefinition` | `{ titleKey, defaultTitle }`，来自 `getAssistantRegistryItem(...)`；作 iframe 标题 |
| `identity` / `userId` | `Signal<string \| null>` | 逻辑身份（非用户身份）／登录用户 id；`identity` 是 `runtimeKey` 组成部分，变则重建会话 |
| `assistantId` | `Signal<string \| null>` | 当前绑定的 Xpert id；必须来自可用列表，否则为 `null` |
| `xpertId` | `Signal<string \| null>` | 触发器/任务查询 scope（`currentXpert()?.id ?? assistantId()`） |
| `currentXpert?` / `assistantTitle?` / `assistantAvatar?` | `Signal<...> \| ...` | 可选展示面：完整 xpert 实体、标题、头像 |
| `initialLayout` / `defaultViewKey` | `Signal<XpertWorkbenchInitialLayoutEnum \| null>` / `Signal<string \| null>` | 决定 ChatKit 面板初始布局与默认视图；空串归一为 `null` |
| `chatkitFrameUrl` | `Signal<string \| null>` | iframe 地址（经 `sanitizeAssistantFrameUrl`）；`null` ⇒ `viewState === 'error'` |
| `threadId` | `Signal<string \| null>` | 路由解析出的线程 id——**路由为真源**，不是本地状态 |
| `group?` | `Signal<{ id: string } \| null>` | 群组会话；注释契约：按会话 id 绑定，不加载私有 Assistant thread |
| `projectId?` / `chatkitMountProjectId?` / `chatkitProjectSelection?` | `Signal<...>` | 当前 Project 路由作用域／**仅初始**挂载绑定／初始草稿意图；三者语义不同 |
| `projectAccess?` | `Signal<TXpertProjectAccessSummary \| null>` | `null` = pending 或不可用/被拒 |
| `loading` / `loadingUserPreference` | `Signal<boolean>` | 绑定态加载／用户偏好加载——**三态分离**，宿主据此保留或清空 iframe |
| `viewState` | `Signal<WorkbenchChatViewState>` | `'organization-required' \| 'wizard' \| 'ready' \| 'error'` 四态闭合联合 |
| `suppressAutoResume` / `pendingConversationStartId` | `Signal<boolean>` / `Signal<number>` | 抑制自动恢复（避免向导期间抢跑）／自增序号，驱动一次启动意图 |

| `viewErrorMessage()` | `() => string` | 视图错误文案；**函数而非 signal**（按需取值） |

### 1.2 `WORKBENCH_CHAT_FACADE` 注入约定

`new InjectionToken<WorkbenchChatFacade>('WORKBENCH_CHAT_FACADE')`。三个提供点全部用 **`useExisting`（不是 `useClass`）**，保证同一路由内门面实例唯一：

1. `ChatXpertWorkbenchComponent`：`{ provide: WORKBENCH_CHAT_FACADE, useExisting: XpertWorkbenchFacade }`（`/chat/x/:slug[/p/:projectId]/c[/:threadId]`）。
2. `ClawXpertConversationPaneComponent`：`{ provide: WORKBENCH_CHAT_FACADE, useExisting: ClawXpertScopedConversationFacade }`，并同块提供 `CLAWXPERT_CONVERSATION_SCOPE` 与 `ViewClientCommandRegistry → ScopedConversationCommands`。
3. 无提供者时骨架 `{ optional: true }` 注入失败，回落 `inject(ClawXpertFacade)`（完整页面形态）。

消费方只有骨架一处：`readonly facade = this.#providedFacade ?? inject(ClawXpertFacade)`。**约定**：可选成员用「存在性探测 + `getOptionalSignalValue`」读取，不在 token 上再拆子契约；可选方法 > 5 个时才是拆子契约的触发条件。

### 1.3 `injectAssistantChatkitRuntime` / `injectHostedAssistantChatkitControl` 宿主状态机接口

- `injectAssistantChatkitRuntime(input)`：= **绑定运行时 + 宿主控制**的组合封装（助手 shell 用，如 `features/xpert/assistant-shell/assistant.facade.ts`），返回 `{ config, control, hasSource, isConfigured, loading, refresh, status }`。
- `injectHostedAssistantChatkitControl(input)`：直接返回 `Signal<ChatKitControl | null>`，是三个宿主的落地函数（ClawXpert 会话详情、`PublicChatkitComponent`、项目会话面板）。
- **状态机**：`status: AssistantRuntimeStatus` 六态 `'idle' | 'loading' | 'ready' | 'missing' | 'disabled' | 'error'`；`missing` = 无 `sourceScope` 或配置不完整，`disabled` = `enabled === false`，`error` = 请求失败或 frame URL 为空。**先看 `status` 再怀疑 iframe**。
- **重建判据**：`runtimeKey`（identity:assistantId:groupId:delegatedConversationId:requesterXpertId:frameUrl:apiUrl:token:organizationId）变化 ⇒ `sessionRevision++` + `createChatKit(options)`；未变 ⇒ `currentControl.setOptions(options)` 原地刷新。`loading()` 为真时只在**同一 `securityScope`** 内保留 iframe，否则清空 control。
- **输入侧约定**：`ReactiveChatKitOption<T> = T | Signal<T>`（静态值与响应式值混用）；`initialThread` 用 `untracked` 读取；`CHATKIT_ATTACHMENT_MAX_BYTES = 50 MiB` 须与 server parser 对齐。

章节来源：[assistant-chatkit.runtime.ts](file://apps/cloud/src/app/features/assistant/assistant-chatkit.runtime.ts)（关键符号：`injectAssistantChatkitRuntime`、`injectHostedAssistantChatkitControl`、`AssistantRuntimeStatus`、`runtimeKey`、`securityScope`、`CHATKIT_ATTACHMENT_MAX_BYTES`）

### 1.4 `ASSISTANT_REGISTRY` 注册契约

表项形状：`AssistantRegistryItem = { code: AssistantCode; featureKeys: AiFeatureEnum[]; management: 'system' | 'user'; labelKey; defaultLabel; titleKey; defaultTitle; descriptionKey; defaultDescription }`——i18n **双写**（key + 默认文案），缺译文时回退默认值而非报错。

注册三项：`CHAT_COMMON`（`system`，`FEATURE_XPERT`）、`XPERT_SHARED`（`system`，同特性位）、`CLAWXPERT`（**`user`**，`[FEATURE_XPERT, FEATURE_XPERT_CLAWXPERT]`）。取用入口为 `getAssistantRegistryItem(code)`（`find(...) ?? null`）；`ClawXpertFacade` 以非空断言取 `definition`，路由准入与门面标题都以此为唯一来源。**新增助手 = 加表项**（不改分支）；漏注册的唯一表现是入口不出现。

## 3. 实时通道契约

命名空间 `chat`，地址 `${getWebSocketUrl(API_BASE_URL)}/chat`；握手鉴权 `auth: (cb) => cb({ token: store.token })`；事件名只用 `message`（双向），另有 socket.io 内建 `connect` / `disconnect` 与服务端 `exception`。

| 事件（`ChatGatewayEvent`） | 方向 | 载荷 / 语义 |
|---|---|---|
| `ack` | 服务端 → 客户端 | 收妥确认；客户端据此 `clearRetryMessage()`（2s 内未收到即**原样重发**） |
| `message_stream` | 服务端 → 客户端 | 增量正文片段，客户端拼接进尾消息 |
| `message` | 服务端 → 客户端 | 完整消息负载（客户端发送亦复用同名事件，自动补 `organizationId`） |
| `conversation_created` | 服务端 → 客户端 | 新会话落库，客户端写回 `conversation` 与列表 |
| `chain_start` / `chain_end` / `chain_aborted` | 服务端 → 客户端 | 回合起止；`chain_aborted` 携带 `conversationId` / `id` |
| `step_start` / `step_end` / `tool_start` / `tool_end` / `agent` | 服务端 → 客户端 | 步骤与工具粒度起止、Agent 级消息 |
| `error` | 服务端 → 客户端 | 回合失败，客户端把最后一条消息置 `status: 'error'` |
| `cancel_chain` | 客户端 → 服务端 | 取消在跑回合（经 `message` 事件提交），服务端回 ACK |
| `exception` | 服务端 → 客户端 | 错误通道；`status === 401` 且 `socketId === socket.id` 时置未连接并 `refreshToken()` 后重连 |

**重连与可靠性语义**：`connect()` 仅在 `!socket || disconnected || !connected` 时建连；并发刷新由 `refreshTokening` 去重。客户端**未显式配置** `transports` / `pingInterval`，沿用 socket.io 默认（long-polling 起步 + 自动重连）——多副本部署需要粘性。2s 重发是「至少一次」，端到端幂等依赖服务端按 `clientMessageId` 去重。**注意**：本域当前活跃链是 HTTP 控制面 + SSE（`POST /api/chat` 与 `/api/ai/threads/:id/runs/:runId/stream`），socket 通道在本域无路由级消费者。

章节来源：[chat.service.socket.ts](file://apps/cloud/src/app/@core/services/chat.service.socket.ts)（关键符号：`ChatWebsocketServer.connect`、`ChatWebsocketServer.message`、`ChatWebsocketServer.namespace`、`ChatWebsocketServer.refreshToken`、`clearRetryMessage`）· [chat.model.ts](file://packages/contracts/src/ai/chat.model.ts)（关键符号：`ChatGatewayEvent`、`ChatGatewayMessage`）· [chat.service.socket.ts](file://apps/cloud/src/app/features/chat/chat.service.socket.ts)（关键符号：`ChatWebsocketService.chatListener`、`cancelMessage`、`message`）

## 4. 代码示例（真实调用方）

① **通过门面发起一次会话与消息发送**（骨架消费启动意图；发送经 client-command 落到 `ChatKitControl`）：

```ts
// clawxpert-conversation-detail.component.ts（剪裁）
effect((onCleanup) => {
  const pendingStartId = this.facade.pendingConversationStartId()
  const control = this.control()
  if (!pendingStartId || this.facade.loading() || this.facade.viewState() !== 'ready' || !control) return
  let cancelled = false
  const timer = setTimeout(() => { if (!cancelled) void this.facade.beginPendingConversation(pendingStartId, control) })
  onCleanup(() => { cancelled = true; clearTimeout(timer) })
})
```
