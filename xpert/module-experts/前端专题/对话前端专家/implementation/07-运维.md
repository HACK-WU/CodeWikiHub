## 1. 运维边界与入口

- 对话域没有服务端部署对象（实例/DB/定时任务）；对应服务端面在 `packages/server-ai` 的 chat / assistant / assistant-binding 模块（见后端专家文档）。

## 5. 实时通道运维

- **端点**：`io(`${getWebSocketUrl(API_BASE_URL)}/chat`)`，命名空间 `chat`；`getWebSocketUrl` 同源时返回 `ws(s)://<当前 host>`（协议随页面 `https:` → `wss:` 自动切换）。
- **鉴权**：握手回调里带 `{ token: store.token }`；服务端 `WsJWTGuard`。token 失效时服务端发 `exception {status:401}` → 客户端 `refreshToken()`（刷新登录态）后**重建连接**，并发刷新由 `refreshTokening` 去重。
- **重连与心跳**：客户端**未显式配置** `transports`/`reconnection`/`pingInterval`，全部沿用 socket.io 默认（先 HTTP long-polling 再升级 WebSocket、默认心跳与自动重连）。
- **可靠性兜底**：每条 `message` 发出后起 2s 定时器，期间未收到 `ack` 就**原样重发**——无次数上限、无指数退避；这也是排障时"日志里看到重复消息"的正常来源。
- **多副本部署注意**：默认 `transports` 下，长轮询握手 + WebSocket 升级**需要连接粘性（sticky session / `ip_hash` / 共享 adapter）**；否则升级请求落到另一副本会握手失败并反复重连。若要免粘性，需要在反代与应用侧统一改为纯 `websocket` 传输。
- **CORS**：服务端网关 `cors.origin: '*'`；前端通常同源，跨域部署时注意浏览器对 `ws://` 混合内容的拦截（https 页面必须 `wss://`）。
- **现状提示**：该 socket 通道在本域**当前无路由级消费者**（消费者在 `@shared/chat/preview` 等外部组件）；排障时先确认是"通道挂了"还是"根本没人用这条通道"。

章节来源：[chat.service.socket.ts](file://apps/cloud/src/app/@core/services/chat.service.socket.ts)（关键符号：`ChatWebsocketServer.connect`、`ChatWebsocketServer.namespace`、`ChatWebsocketServer.refreshToken`、`ChatWebsocketServer.resetRetryMessage`）、[utils.ts](file://apps/cloud/src/app/@core/utils.ts)（关键符号：`getWebSocketUrl`）

## 6. ChatKit 宿主部署

- **iframe 地址**：`environment.CHATKIT_FRAME_URL`（dev `/chatkit`，prod `DOCKER_CHATKIT_FRAME_URL`）。解析顺序：`sanitizeAssistantFrameUrl`（空/`DOCKER_` 前缀 → `null`，**不挂载**）→ `normalizeAssistantFrameUrl`（本地 `/chatkit` 补 `/index.html`，保留 query/hash）。
- **静态托管**：构建产物里的 `./chatkit`（来自 `@xpert-ai/chatkit-ui/dist/app`）就是被 iframe 加载的应用；同一份资源还提供 `./assets`（前端共享）与 `./pets`。
- **协议与源**：
  - 同源部署（推荐）：`/chatkit` 与宿主同源，postMessage 无跨域限制；
  - 跨域部署：iframe 必须是 **https**（或与宿主同协议的绝对 URL，`//` 形式也支持），且 iframe 侧需允许被宿主 frame（`X-Frame-Options`/`frame-ancestors` 指向宿主域）；
  - `sanitizeAssistantFrameUrl` 只做**前缀哨兵**校验，不做 host 白名单 —— 跨域部署时源校验责任在 iframe 侧协议与宿主 CSP 上。
- **鉴权**：iframe 不持有登录态；它通过宿主的 `api.getClientSecret` 换取短时 `client_secret`（宿主 `POST /api/ai/v1/chatkit/sessions`）。因此**宿主必须能访问 `/api/ai/*`**（`resolveAbsoluteApiBaseUrl(API_BASE_URL) + '/api/ai'`），并且该绝对地址必须是 iframe **可达**的（跨域部署最常见故障）。
- **主题**：宿主读 `--background`/`--foreground` CSS 变量与 `data-theme`/`class` 变更（`MutationObserver`）下发 `colorScheme`，故站点主题切换会影响 iframe 外观，无需重载。
- **附件与沙箱**：单附件上限 50 MiB、最多 5 个；MCP app 沙箱仅在 `MCP_APP_SANDBOX_PROXY_URL` + 白名单都配置时启用。

章节来源：[assistant-chatkit-frame-url.ts](file://apps/cloud/src/app/features/assistant/assistant-chatkit-frame-url.ts)（关键符号：`normalizeAssistantFrameUrl`）、[assistant-chatkit.runtime.ts](file://apps/cloud/src/app/features/assistant/assistant-chatkit.runtime.ts)（关键符号：`sanitizeAssistantFrameUrl`、`resolveAssistantMcpAppsOptions`、`CHATKIT_ATTACHMENT_MAX_BYTES`）、[assistant-chatkit-theme.ts](file://apps/cloud/src/app/features/assistant/assistant-chatkit-theme.ts)（关键符号：`injectAssistantChatkitTheme`）

## 8. 特性开关

- 开关实现是 **`featureGate(featureKeys, redirectCommands)`**：内部 `hydrateFeatureContext` 取当前用户特性上下文（**3s 超时**，超时按"未水合"处理 → 一律回落），再要求 `store.hasFeatureEnabled(...)` 全为真。
- 对话域用到的特性位：`AiFeatureEnum.FEATURE_XPERT`（工作台路由 `/chat/x/:name`、legacy groups）、`FEATURE_XPERT` + `AiFeatureEnum.FEATURE_XPERT_CLAWXPERT`（ClawXpert 段，回落 `/explore`）。
- 助手可用性还有第二层判定：`ASSISTANT_REGISTRY` 中 `CLAWXPERT` 的 `featureKeys = [FEATURE_XPERT, FEATURE_XPERT_CLAWXPERT]`、`management: 'user'`（用户自绑），`CHAT_COMMON` / `XPERT_SHARED` 为系统助手。
- 运维含义：**灰度/回滚 ClawXpert 只需关特性位**（用户会被送到 `/explore`），不需要发版；但公共页 `/x-chatkit/h5/*` 不经过 `featureGate`，关特性位**不影响**该入口。

章节来源：[feature-gate.ts](file://apps/cloud/src/app/features/feature-gate.ts)（关键符号：`featureGate`、`hydrateFeatureContext`、`FEATURE_HYDRATION_TIMEOUT_MS`）、[routes.ts（对话域）](file://apps/cloud/src/app/features/chat/routes.ts)（关键符号：`featureGate([AiFeatureEnum.FEATURE_XPERT])`、`canActivateChild`）

## 10. 常见故障与处置

| 故障 | 判断 | 处置 |
|---|---|---|
| 消息发出去不刷新 | Network 无失败但界面不动 | 先确认宿主是 ChatKit 路径（会话内消息由 iframe 负责）还是 socket 路径；若为 socket，检查是否每条 `message` 都收到 `ack`（未收到会 2s 重发，表现为重复消息） |
| 连接一直失败/反复重连 | WS 面板握手失败或 401 | ① 反代是否放行 `/socket.io/` 与 `Upgrade`；② 多副本是否有粘性；③ 401 时确认 `refreshToken()` 是否成功（失败会卡在未连接态） |
| iframe 白屏 / 一直"Preparing assistant" | Console 无异常但 iframe 空 | ① `CHATKIT_FRAME_URL` 是否被 `DOCKER_` 哨兵吞掉；② `/chatkit/index.html` 与 `./assets`、`./pets` 是否随构建产出；③ 跨域时 iframe 是否允许被 frame |
| 宿主握手失败（无 `onReady`） | Network 里 `POST /api/ai/v1/chatkit/sessions` 失败或跨域被拦 | 检查宿主算出的绝对 `/api/ai` 地址是否被 iframe 访问到；确认绑定态（`injectAssistantBindingRuntimeState` 的 `isConfigured`/`status`）与发布态刷新 |
| 命令不生效（视图点了没反应） | 控制台/命令返回 `unsupported` / `stale_context` | iframe 发来的 `hostId` 必须等于当前 `assistantId`；路由切换后注册表按 `active()` 生效范围切换，跨路由的旧命令会主动失效 |
| 打开 ClawXpert 被弹回 `/explore` | — | 特性位 `FEATURE_XPERT` / `FEATURE_XPERT_CLAWXPERT` 未开，或特性上下文水合超过 3s |
| 附件上传失败 | — | 单文件 >50 MiB 或数量 >5 会被前端直接拦截（不发请求），先排除这条 |
| spec 跑不起来 | 收集阶段即失败 | 环境依赖缺失（`node_modules` 未安装 / `packages/contracts` 未构建）；按 06-测试的"需外部依赖的用例与开启方式"处理 |

章节来源：[assistant-chatkit.runtime.ts](file://apps/cloud/src/app/features/assistant/assistant-chatkit.runtime.ts)（关键符号：`injectAssistantBindingRuntimeState`、`CHATKIT_ATTACHMENT_MAX_BYTES`）、[apps/cloud/jest.config.ts](file://apps/cloud/jest.config.ts)（关键符号：`moduleNameMapper`）
