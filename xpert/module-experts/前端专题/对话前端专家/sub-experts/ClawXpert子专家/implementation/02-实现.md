## 绑定向导链

三段式：**门面状态** → **向导 UI** → **创建/发布兜底**。

- **向导可见性来自门面**：`ClawXpertComponent` 模板按 `facade.loading()` → `facade.viewState() === 'wizard'` → `'error' || !organizationId` 的顺序分支，`wizard` 分支挂 `xp-clawxpert-binding-wizard`。
- **选择与保存**：`ClawXpertBindingWizardComponent` 用 `searchControl` + `searchText`（`toSignal`）过滤 `facade.availableXperts()`（匹配 `id/slug/name/title/titleCN`），`selectXpert(id)` 只写表单，`savePreference()` 落 `facade.savePreference(assistantId)`；`cancelWizard()` 回到 `resolvedPreference()?.assistantId`；`orphanedPreference()` 为真时提示「原绑定已不可用」。
- **新建出口**：`openCreateWizard()` 以 `category: BLANK_XPERT_DIALOG_CATEGORY.CLAW`、`completionMode: 'publish'`、`initialTemplateId: CLAWXPERT_TEMPLATE_ID`、`lockStartMode: true` 打开 `XpertNewBlankComponent`；`status === 'published'` 时 `facade.bindPublishedXpert(result.xpert)`。
- **首次运行对话框**：`ClawXpertComponent` 订阅 `queryParamMap`，命中 `?onboarding=clawxpert` 时 `handleEntryOnboardingRoute()` → `loadEntryOnboardingXpertCount()`（`XpertAPIService.getMyAll` 取 `total`）→ `shouldCreateClawXpertAfterEntryOnboarding(count)` 决定是否 `openSetupDialog()`（CDK `Dialog` + `disableClose: true`），最后 `clearEntryOnboardingQuery()` 清参。`ClawXpertSetupWizardComponent` 负责模型提供方（`CopilotConfigFormComponent`）、推荐模板勾选、`isolateWorkspaceData` 开关与「完成初始化」按钮。
- **创建链（`ClawXpertBootstrapService`）**：`resolveFirstAvailableLlmModel()` → `createClawXpert()`（`prepareTemplatePlugins` → `ensureDefaultWorkspace` → `installTemplate` → `refreshDraftSnapshotBeforePublish` → `publishCreatedXpertOrFallback`）→ `bindAndOpenCreatedClawXpert()`（`AssistantBindingService.upsert` → `pendingCreatedClawXpert.set` → `router.navigate(['/chat/clawxpert','c'])`，失败则回滚 `#pendingCreatedConversationXpertId`）。
- **模板创建**：`createTemplateXpert(template, model)` 复用同一「插件 → 工作区 → 安装 → 发布」骨架，`createTemplateInstallName()` 生成 `<slug>-<uid6>` 安装名。

## 会话面板与详情（消息渲染与滚动）

**结论先说**：本子域**不渲染消息**——消息面（列表、流式、滚动跟随）由 ChatKit iframe 承载；宿主的职责是**装配 iframe、同步线程与作用域、把事件翻译成宿主动作**。

- **面板装配**：`ClawXpertConversationPaneComponent` 模板只有一行 `<xp-clawxpert-conversation-detail />`，全部逻辑在 `providers`：scope token（`useFactory` 取 `input.required`）、作用域门面 → `WORKBENCH_CHAT_FACADE`、`ScopedConversationCommands`、`ScopedSkillTrialIntent`、路由活性回调、`ClawXpertWorkbenchViewUrlState`。
- **骨架 → 宿主控制**：`ClawXpertConversationDetailComponent` 用 `injectHostedAssistantChatkitControl` 得到 `control`，输入字段来自门面与群组 scope：`chatkitAssistantId`（群组态优先 `#workbenchConversationScope()?.xpertId`）、`chatkitGroup`（群组态返回 `null`）、`chatkitProjectId`、`chatkitInitialThread`、`chatkitDelegatedConversation`、`assistantRequestContext`（`buildAssistantRequestContext` 汇总 workspace/xpert/执行焦点）；`startScreen` 来自 `injectFrequentQuestionsStartScreen({ xpert, active })`。
- **回灌宿主**：`onThreadChange` → `facade.onChatThreadChange(threadId)`；`onThreadLoadEnd` → `facade.syncConversationProject?.(threadId)`（父级契约的可选方法）；`onResponseStart` / `onResponseEnd` → `facade.patchActiveConversationStatus('busy' | 'idle')`；`onProjectChange` → `facade.onChatProjectChange?.(...)`。
- **布局与滚动（宿主侧）**：宽度由 `startChatkitPanelResize`（指针捕获 + `clampChatkitWidth`，越界超过最小宽度一半即 `onMaximize`）与常量组 `CLAWXPERT_CHATKIT_{MIN,DEFAULT,MAX}_WIDTH_PX`（384 / 460 / 960）控制；面板 class 由 `createWorkspacePanelClasses` / `createWorkspaceLayoutClasses` 工厂生成；「宠物态」判定读 DOM 属性 `data-chat-minimized-to-pet` / `data-display-mode` / `data-chat-open`。子域内**唯一的滚动容器显式声明**在 `file-change-review.component.html`。
- **消息相关副作用**：`onEffect` 经 `getTaskSummaryResourceTarget` 解析为 `workspace_file` / `file_change_set` / `file_change` / `artifact` / `browser` / `url` 六类目标（`file_change_set` 上限 1024 项）；`onLog` 经 `shouldRefreshWorkspaceFilesFromLogEvent`（白名单 `sandbox_write_file` / `sandbox_append_file` / `sandbox_edit_file` / `sandbox_multi_edit_file` / `write_memory` + 旧后缀 `create_file` / `str_replace` / `full_file_rewrite` / `delete_file`）触发 `fileListReloadKey`（300ms 去抖）；`assistant.tool.completed` 由 `createAssistantToolCompletedHostEvent` 桥到宿主事件总线；沙箱预览由 `getSandboxPreviewTargetFromEffectEvent` 解析 `localhost:<port>` 或 `workbench.browser.preview`。
- **消息内链接**：`installConversationMapLinks` 读 `?mapConversation/mapThread/mapMessage` 三参 → 走同一授权接口 `conversations.resolveWorkbenchNavigation` 后 `open(...)`，并注册 `workbench.navigation.copy-link`；`focusConversationMapMessage` 对 `not_ready` 做 5s 内 100ms 轮询重试，`stale_context` 转 `AbortError`。

## 作用域会话门面

`ClawXpertScopedConversationFacade implements WorkbenchChatFacade, OnDestroy`，行数不多但承担三件事：

1. **字段委托**：`definition` / `userId` / `assistantId` / `xpertId` / `currentXpert` / `assistantTitle` / `assistantAvatar` / `initialLayout` / `defaultViewKey` / `chatkitFrameUrl` / `loading` / `loadingUserPreference` / `viewState` 直接取共享门面；`identity` 改为 `` `${shared.identity()}:${scope()}` `` ——**身份里带作用域**，这是多面板共存的关键。
2. **本地面板状态**：`threadId` / `activeConversation` / `suppressAutoResume`（默认 `true`，作用域面板默认不自动续接）为自有 signal；`pendingConversationStartId` 仅在 `scope() === 'task' && active()` 时透出共享值；`active` = 「URL 作用域 === 本面板作用域」。
3. **URL ↔ 状态同步**：构造期 `effect` 内做三件事——首帧从 `clawXpertScopedThreadId(url, scope)` 或 `entries.assistantThread(owner)` 恢复线程；后续只在 `routed || scope === 'task'` 时更新线程；assistant 作用域把线程写回 `entries.setAssistantThread(owner, threadId)` 并在「路径无线程但有线程」时 `navigateByUrl(..., { replaceUrl: true })` 补全 URL。
4. **四个宿主回调的取舍**：`beginPendingConversation` 只在 task 作用域执行并清空 composer；`ensureConversationEntry` 一次性（`entryInitialized`）且要求 `viewState() === 'ready'`；`onChatThreadChange` 在 `resetInProgress` / `nullGuardUntil` 内不写状态，非当前路由只记不跳；`setActiveConversation` / `patchActiveConversationStatus` 都先过 `ownsCurrentBinding()`。

## 群组工作台 scope

`createGroupWorkbenchScope` 是 44 行的纯函数工厂，返回 `computed`，语义是「**解析前不给个人视图**」：

- **输入**：`groupId` / `identity` / `assistantId` / `ready` 四个取值函数 + `api.getContext` + `onError`。
- **key**：`ready() ? JSON.stringify([identity(), groupId(), assistantId()]) : null` —— 任一维变化即换 key，`resolved` 里的旧 key 立刻不再匹配，`computed` 随即返回 `null`（测试：`invalidates immediately across groups and ignores an old response`）。
- **effect**：`cleanup` 置 `cancelled`，`getContext(groupId)` 回来后校验 `context.assistantId === assistantId && context.conversationId`；不符即抛 `Invalid group Workbench context` 交 `onError`；失败不回退（测试：`never falls back after denial`）。
- **消费侧**：骨架 `groupWorkbenchScope` → `#workbenchConversationScope` → `chatkitAssistantId` / `chatkitInitialThread` 与 `viewRuntimeScope`（含 `groupId` / `projectId` / `conversationId`）；`ClawXpertFixedViewStackComponent` 的 `conversationScope` 在 `runtimeScope()?.groupId` 存在时**忽略**本地 conversationId。

## 工具偏好与触发器读写

**工具与 skill 偏好（`ClawXpertToolPreferencesComponent`）**

- **两类数据源各自 `toSignal`**：`toolState` 由 `triggerDraft()` + `middlewareProviders` + `ready` 三元 `computed` → `switchMap` 后 `forkJoin`：toolset 节点走 `XpertToolsetService.getOneById(id, { relations: ['tools'] })`，middleware 节点走 `XpertAgentService.getAgentMiddleware(provider, options, xpertId)`；单个源失败**不炸整页**，转成 `errors` 数组（`buildSourceErrorState`）。
- **skill 状态**：`skillState` 由 `SkillPackageService.getAllByWorkspace(workspaceId, { relations: ['skillIndex', 'skillIndex.repository'] })` 构建；`skillWorkspaceId` = `facade.currentWorkspaceId()`。
- **写入是乐观 + 串行**：`toggleTool` → `facade.setToolEnabled(sourceType, nodeKey, metadata, toolName, enabled)`；`toggleSkill` → `enqueueSkillPreferenceUpdate`（`#skillPreferenceSaveQueue` 把并发的 skill 写操作**串成队列**，避免相互覆盖）。
- **批量与包管理**：`selectedSkillIds` + `setSelectedSkillsEnabled`（顺序保存，全成功才 toastr）、`uninstallSkill` / `uninstallSelectedSkills`（`injectConfirmDelete` 二次确认）、`downloadSkillPackage`（blob → `triggerSkillPackageDownload`）、`installSkill` / `openSkillInstallDialog` / `openSkillUploadDialog`、`refreshSkills()`（`skillRefreshTick++`）。
- **门控**：`isBlocked = viewState() !== 'ready' || !xpertId()`；`blockedState()` 按 `skillsOnly` / 组织 / 绑定分三种文案。

**触发器（`ClawXpertTriggerConfigEditorComponent`）**——「草稿副本 + dirty 判定」：

- `workingItems = signal(cloneItems(facade.triggerEditorItems()))`；构造期 `effect` 在 `untracked` 内把门面值重新克隆进本地，**不覆盖用户正在编辑的副本**（门面变化时才同步）。
- `dirty = !isEqual(workingItems(), facade.triggerEditorItems())`（`lodash-es`）；`invalid` 用 `hasJsonSchemaRequiredErrors(provider.configSchema, config)` 逐项校验，`chat` 提供方与无配置字段的提供方豁免。
- `addTrigger(provider)`：拒绝 `chat`、拒绝重复提供方，`nodeKey = genXpertTriggerKey()`，默认值来自 `buildJsonSchemaDefaults(provider.configSchema)`；`reset()` 丢弃；`save()` 仅在 `dirty && !invalid` 时调 `facade.saveTriggerDraft(workingItems())`。

## 文件变更审查入口

- **标签页模型**：`FileChangeReviewTab`（`kind: 'file-review'`，含 `conversationId` / `resource` / `revision`）；`createFileChangeReviewTab(threadId, conversationId, resource)` 用 `file-review:${threadId ?? conversationId ?? 'current'}` 作 id ——**每线程一个标签**；`upsertFileChangeReviewTab` 重开时**只递增 `revision`，不换端点**（注释：opening another saved range never changes its endpoints）。
- **两种范围**：`selectScope('selected' | 'conversation')`；`conversation` 先 `service.listChanges(conversationId)` 取全量路径，`selected` 直接用 `tab.resource`（`file_change_set` 展开 `changes`）。
- **批量并发硬编码 4**：`for (let offset = 0; offset < targets.length; offset += 4)`，每批 `Promise.all` 拉 `service.loadReport(resource)`；`request = ++this.request` 序号在**每批之后**校验，`ngOnDestroy` 再自增作废；路径与 `report.workspacePath` 不一致时按 `unavailable` 处理。
- **行数统计**：`countFileChangeLines(report)`（来自 `@xpert-ai/chatkit-types`）聚合 `counts` 与 `totals`；**diff 组件另有一套统计**：`FileChangeDiffComponent.init` 用 Monaco `getLineChanges()` 累加 added/removed 并 `stats.emit`，高度取 120–600 之间。
- **视图状态**：`sideBySide` / `wordWrap` / `showWhitespace` / `showMetadata` / `showFiles` / `collapsed`（`toggle` / `toggleAll` / `allCollapsed`）；`hasReviewText(report)` 判定 before/after 是否含文本。
- **工作区文件与产物**：`ClawXpertConversationFilesComponent` 把 7 个读写函数（`loadWorkspaceFiles` / `loadWorkspaceFile` / `downloadWorkspaceFile` / `saveWorkspaceFile` / `uploadWorkspaceFile` / `saveWorkspaceBinaryFile` / `deleteWorkspaceFile`）按「有 Project 走 `ChatConversationService`，否则走 `AiWorkspaceFilesService`」分派；`WorkbenchArtifactPanelComponent` 用同样的双分派喂 `FileDocumentState`；`workbench-artifact-tabs.ts` 负责把工具事件里的文件转成标签（`fileTabsFromToolEvent`、`attachWorkspaceFile`、`updateArtifactTab` 会 `revokeObjectURL` 旧 url）。

## 绑定状态与错误态

- **两个入口都走 `ClawXpertBindingState`**：`preference` / `availableXperts` / `loading` / `hasLoadedXperts` / `errorMessage` / `showWizard` 六个信号被门面直接暴露给视图。
- **冷启动**：构造期 `restore(scope)`（读 `ClawXpertConfigurationCache`）→ `effect` 在 `organizationId` 存在时 `refresh(scope)`；`refresh` 并行 `get(CLAWXPERT, USER)` + `getAvailableXperts(USER, CLAWXPERT)`，`isCurrent()`（`requestId` + scope 双判）过期即整体丢弃。
- **跨路由传递新绑定**：`refresh` 里若 `currentUrl() === '/chat/clawxpert/c'` 且 `bootstrap.pendingCreatedClawXpert()` 有值，则把该 xpert 合并进 `preference` 与 `availableXperts`（并集去重），命中后 `clearPendingCreatedClawXpert`。
- **错误分级**：`isAccessRejected(error)`（401/403/404）→ 删缓存、清 `preference` / `availableXperts` / `hasLoadedXperts`，并**必写** `errorMessage`；其它错误仅在「从未加载过」时才给文案（`getErrorMessage` 或 i18n `XP.Chat.ClawXpert.LoadFailedDesc`）。
- **视图分流**：`ClawXpertComponent` 的 `loading` / `wizard` / `error + !organizationId` 三分支只渲染一个说明节点；`ClawXpertOverviewComponent` 另有一套更完整的四态（loading / 无组织 / error / wizard），并复用 `ClawXpertBindingWizardComponent`。
- **解绑与恢复**：`facade.clearPreference()` 与 `facade.cancelWizard()` 是向导的两个出口；`mergeAvailableXpert` 用于把新建 xpert 并入可绑列表。

## 设计维度分析

**维度一：作用域优先 vs 共享优先**——本子域把「同一页面多份对话」当作默认前提，于是所有可变状态都做了归属划分：作用域（`CLAWXPERT_CONVERSATION_SCOPE` + `active()`）、所有者（`ownerKey = [userId, organizationId, xpertId]`）、请求（`#requestId` / `request` 序号）、队列（`#skillPreferenceSaveQueue`）。共享门面只保留**真正跨作用域**的字段（绑定、偏好、触发器、任务），其余下沉到面板实例。收益是「路由切换不丢 composer、后台响应不抢路由」；代价是面板必须常驻（DOM 与 iframe 成本），且任何新增共享字段都要先回答「它属于哪个 scope」。判定标准很清晰：**能否在 URL 里找到它的作用域**。

**维度二：宿主薄、iframe 厚**——消息渲染、滚动、流式增量、输入框全在 ChatKit iframe 内；宿主只做四件事：装配（`control` + `chatkit*` 输入）、同步（线程/项目/已读）、翻译（`onEffect`/`onLog` → 标签页、刷新、预览）、授权（命令经 `ViewClientCommandRegistry` 白名单）。这让本子域几乎没有「渲染性能」问题，但把所有**协议耦合**压到了事件翻译层——`assistant-tool-host-events.utils.ts` 与 `clawxpert-sandbox-preview.utils.ts` 都用「预设键名递归 + `visited` 去环 + JSON 字符串兜底解析」来对抗 payload 形状漂移。风险在于：一旦 iframe 侧改字段名，宿主侧的失败模式是**静默不刷新**（不报错、不提示）而非报错，排查必须先看事件名再怀疑键名。

## 结论

- **子域的实现重心是「归属」**：作用域归属（`task` / `assistant`）、所有者归属（user + org + xpert）、请求归属（序号/键），三者共同保证多面板共存与后台响应不串。
- **绑定向导是「状态机 + 两种创建出口」**：向导本体只做选择与保存，创建/发布/兜底全在 `ClawXpertBootstrapService`，`pendingCreatedClawXpert` 是跨路由传递新绑定的唯一通道。
- **会话面在 iframe 内**：宿主不渲染消息、不管理滚动；宿主侧的可视化重心是**布局与标签页**（`workspaceTabs` / `reviewTabs` / `fixedViewTabs` / `browserTabs`）与**面板 class 工厂**。
- **工具偏好与触发器是两种写模式**：偏好在共享门面做乐观更新（+ 串行队列），触发器在组件做草稿副本（+ `dirty` / `invalid` 门控）；后者天然更安全，前者更即时。
- **文件审查入口已闭环**：标签页唯一化（每线程一个）、范围可切换（selected / conversation）、过期批次作废、行数统计与 diff 视图双轨。
- **优先治理项**：拆 88 KB 骨架；裁定 `settings` 作用域归属；集中魔数；统一文件变更行数统计口径；为事件翻译层补形状漂移的显式告警。
