## 逐文件覆盖点

**门面与状态（`clawxpert.facade` / `clawxpert-binding-state` / `configuration-cache`）**：绑定读取与归一、发布与绑定新 xpert、任务摘要与 `taskRefreshTick`、会话偏好与用户偏好读写、触发器草稿加载/保存、`viewState` 各分支、缓存快照的写入与失效（父级口径：「facade（绑定/发布/任务/会话全链路）+ 绑定向导与状态归一 + bootstrap 与配置缓存」）。

**外壳与作用域（`clawxpert.component` / 作用域门面 / 视图 URL 状态 / 工作台布局存储）**：外壳的 loading / wizard / error 分流与 `?onboarding` 处理；作用域门面覆盖**两个作用域的线程完全隔离**（`keeps task and assistant threads independent across route switches`）、**按 user+org+binding 恢复 assistant 线程**（`restores only the assistant entry persisted for this user, organization and binding`）、**后台响应不劫持任务路由**（`remembers a background assistant response without hijacking the task route`）、**空白 composer 不重复重置**（`does not reset an initialized blank composer when returning from another entry`）、**新任务动作只作用于 task 面板**（`applies the explicit new-task action only to the task pane`）、**保留 query/hash**（`preserves workbench query parameters when the active assistant creates a thread`）以及频繁问题 start screen 走 `/api/xpert/xpert-1/frequent-questions`。

**群组 scope（`group-workbench-scope`）**：解析前不出个人视图、跨组立即失效并丢弃旧响应、身份变化重新校验、拒绝后不回退（`never falls back after denial`）、`assistantId` 不一致/`conversationId` 为空视为非法（`it.each` 两条）、私人会话与未就绪时不发请求。

**偏好面板（`tool-preferences` / `trigger-config-editor` / `preferences-editor` / `overview`）**：skill 与 tool 的加载与失败态、乐观开关与 pending 集合、批量启停与卸载、安装/上传对话框回调、触发器草稿的 `dirty` / `invalid` / `save` / `reset`、SOUL.md 与 USER.md 的编辑态、概览四态与热力图数据。

**文件与产物（`file-change-review` / `file-change-diff` / `workbench-artifact-tabs` / `workbench-artifact-panel` / `clawxpert-conversation-files` / `clawxpert-managed-services-browser` / `clawxpert-sandbox-preview.utils`）**：`selected` / `conversation` 两种范围与分批加载、`unavailable` 条目、计数合计、diff 交互参数、产物标签去重与 `revokeObjectURL`、工作区文件读写双分派、受管服务预览会话键与日志/重启/停止、沙箱预览目标解析（含 `sandbox_service_start` 与 `workbench.browser.preview` 两条入口）。

**事件与工具函数（`assistant-tool-host-events.utils` / `clawxpert-task-summary-effect.utils` / `clawxpert-workspace-file-refresh.utils` / `fixed-views` / `panel-resize` / `conversation-map-navigation` / `workbench-project-navigation`）**：`lg.tool.end` 与 `component` 两条工具完成路径、任务摘要资源目标六类判定与 1024 上限、写文件工具白名单与嵌套键递归、别名视图匹配与 `openMode` 过滤、面板宽度 clamp 与拖拽越界最大化、地图链接复制与 `focusMessage` 重试、Project 视图打开与「不改聊天 Project」约束。

## 运行命令

```bash
# 单文件（推荐；绕开 Nx 项目图）
cd /root/xpert && node node_modules/jest/bin/jest.js \
  --config apps/cloud/jest.config.ts \
  --runTestsByPath apps/cloud/src/app/features/chat/clawxpert/clawxpert.facade.spec.ts

# 本子域全量
cd /root/xpert && node node_modules/jest/bin/jest.js --config apps/cloud/jest.config.ts \
  --runTestsByPath $(find apps/cloud/src/app/features/chat/clawxpert -name '*.spec.ts')

# Nx 方式（含缓存，改代码后加 --skip-nx-cache）
cd /root/xpert && corepack pnpm nx test cloud --testPathPattern="features/chat/clawxpert" --skip-nx-cache 2>&1 | tail -60
```

- 依赖前置：`corepack pnpm install`（`packageManager: pnpm@10.24.0`、`.npmrc` 固定 `node-linker=hoisted`）；契约包按需 `corepack pnpm nx build contracts`。
- `@nx/jest:jest` 默认 `passWithNoTests: true`：路径写错会「0 用例、退出码 0」，务必核对输出的用例数。
- 若环境注入 `NODE_OPTIONS` / `BASH_ENV`，用 `env -u NODE_OPTIONS -u BASH_ENV` 前缀剥离后再跑。

## 缺口

- **22 个非 spec 文件无同名 spec**：`clawxpert-assistant-settings.component.ts`、`clawxpert-binding-target.service.ts`、`clawxpert-conversation-pane.component.ts`、`clawxpert-conversation-start-intent.service.ts`、`clawxpert-heatmap.utils.ts`、`clawxpert-scheduled-tasks.component.ts`、`clawxpert-skill-trial-intent.service.ts`、`clawxpert-template.constants.ts`、`file-change-review.types.ts`，以及 `conversation-detail/{chatkit/conversation,chatkit/layout,chatkit/overlay-controls,chatkit/workspace-layout,chatkit/workspace-panels,composer/references,composer/request-context,composer/skill-trial,citations/knowledgebase,workspace/browser,workspace/tabs}`。其中 `clawxpert-conversation-entry.store.ts` 与 `clawxpert-conversation-scope.ts` 由 `clawxpert-scoped-conversation.facade.spec.ts` **间接覆盖**。
- **无可用于回归的子域「整体链」**：`?onboarding` 引导链、创建/发布/绑定链的**端到端组合**（`ClawXpertComponent` → `ClawXpertBootstrapService` → facade 刷新）只有分段单测，无跨组件集成用例。
- **`settings` 死口径无 spec**：路由 `settings → c` 与 `clawXpertConversationScope` 判 `assistant` 的矛盾，`clawxpert-assistant-settings.component.spec.ts` 不存在，该不一致不会被测试捕获。
- **无守卫/权限类负向用例**：`isAccessRejected`（401/403/404）分支仅在 `clawxpert-binding-state.spec.ts` 层面被覆盖，未与真实 `AssistantBindingService` 错误体联动。
- **i18n 与文案**：`blockedState()` 四组文案键、`ScheduledTasksHeading` 的截断字面量均无断言。
- **父级口径的已知失败项**：本子域两个巨型 spec（conversation-detail 110 行、facade 53 行）是父级失败清单的首选候选（环境级 + 基线漂移），失败清单**待复跑确认**。

## 结论

- **可执行性**：✅ 具备。Jest 配置、`moduleNameMapper`（`^@xpert-ai/contracts$` 直连源码、`environments/environment` 系列映射）与 setup 垫片均已就绪；全部用例离线化（`HttpTestingController` + `jest.fn()`），无真实网络。前提是**依赖已安装**（本会话为只读检索，未核实 `node_modules` 落盘状态）。
- **覆盖结构健康度**：32 spec 对 32 非 spec 文件，覆盖率按文件计约 **59%**（32/54）；但**巨型 spec 集中度过高**——两个文件（约 163 行 `describe|it`）承载近四成用例，回归信号集中在骨架与门面。
- **最强回归面**：作用域门面的「线程隔离 + 持久化 + 不劫持路由」六例、群组 scope 的五例失效语义、`group-workbench-scope` 与 `workbench-project-navigation` 的纯函数边界——这三处是子域最容易被误改、也最值得保留的回归。
- **最弱回归面**：`drafts/intents`（skill 试用意图 TTL、会话开始意图计数）、`conversation-detail/{chatkit,composer,citations,workspace}` 内的纯函数（标签/浏览器/面板 class 工厂）、`clawxpert-scheduled-tasks` 与 `clawxpert-assistant-settings`。
- **推荐动作**：`corepack pnpm install` → 按「运行命令」第 2 条跑本子域全量 → 把父级失败清单中属于 `clawxpert/**` 的行替换为实测 `●` 块；随后补三类用例（作用域切换 × 布局恢复、群组 scope × 固定视图标签回收、文件审查分批 × 过期批次丢弃），并为事件翻译层加「键名漂移」的显式失败用例。
