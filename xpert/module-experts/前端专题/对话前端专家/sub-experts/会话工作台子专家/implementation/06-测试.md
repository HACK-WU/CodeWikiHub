## 运行方式与命令

```bash
# 单文件（推荐：绕开 Nx 项目图）
cd /root/xpert && node node_modules/jest/bin/jest.js \
  --config apps/cloud/jest.config.ts \
  --runTestsByPath apps/cloud/src/app/features/chat/xpert-workbench/xpert-workbench.facade.spec.ts

# 本子域 5 个 spec 全量
cd /root/xpert && node node_modules/jest/bin/jest.js --config apps/cloud/jest.config.ts \
  --runTestsByPath \
  apps/cloud/src/app/features/chat/xpert-workbench/xpert-workbench.facade.spec.ts \
  apps/cloud/src/app/features/chat/xpert-workbench/conversation-entry.resolver.spec.ts \

  apps/cloud/src/app/features/chat/workbench-chat/workbench-loading-indicator.component.spec.ts

# Nx 方式（含项目图/缓存）
cd /root/xpert && corepack pnpm nx test cloud \
  --testPathPattern="features/chat/(xpert-workbench|workbench-chat)" --skip-nx-cache 2>&1 | tail -60
```

- **前置**：`corepack pnpm install`（`node-linker=hoisted`）；否则全部 spec 在收集阶段即失败。
- **`NODE_OPTIONS` / `BASH_ENV` 注入**（IDE shim）时用 `env -u NODE_OPTIONS -u BASH_ENV` 前缀剥离。
- **`passWithNoTests: true` 陷阱**：路径写错会「0 用例、退出码 0」，务必核对输出里的用例数（本子域应为 **5 suites / ≈54 tests**）。
- 本子域 spec **不需要** `packages/contracts` 构建产物：它们的 `@xpert-ai/contracts` 导入都是精确包路径，`moduleNameMapper` 的 `^@xpert-ai/contracts$` 会直连源码。

## 逐文件覆盖点

**1. `xpert-workbench.facade.spec.ts`（28 例，本子域回归主力）**

- 加载与身份：`loads the accessible xpert for the current slug`（断言 `viewState='ready'`、`xpertId/assistantId`、`identity='chat-xpert-workbench:xpert-1'`、`initialLayout`、`defaultViewKey`）；`shows an error when the slug is not accessible`。
- 群组适配：`chooses the group adapter from purpose on the normal conversation route without a personal binding`（断言 `identity='chat-group:group-1'`、`threadId()===null`、不调 `getAvailableXperts`、`onChatThreadChange`/`syncConversationProject` 均 no-op）；`does not mount a group whose entry belongs to another organization`（跨组织 → `error`）；`restores the ordinary adapter when leaving a group on the same route component`。
- 入口错误：`shows entry access errors instead of mounting a private chat`（`viewErrorMessage()` 直传 `'Access denied'`）。
- 空会话入口：`starts a blank chat at the Assistant entry even when previous conversations exist`（**关键否定断言**：`findAllByXpert` 不被调用、不导航）；`focuses the composer on a blank entry`；`preserves the selected assistant view without resuming a previous thread`（`?view=` 保留、不 resume）。
- thread 同步：`syncs ChatKit thread changes into the xpert workbench route`（`navigate(['/chat/x','sales','c','thread-2'])` + `preserve`；清空时 `suppressAutoResume()===true`）；`preserves complete workbench view state across consecutive thread switches`；`does not leave the Project route when ChatKit clears the active thread`。
- Project 作用域：`defaults an opted-in Assistant to automatic creation…`（`chatkitProjectSelection()==={mode:'auto-new'}`）；`it.each(['none','auto-new'])` 清理旧 Project/view query；`adopts a persisted first-send Project without changing the mounted ChatKit identity`（**identity 不变**、`chatkitMountProjectId` 时段行为）；`keeps the first-send ChatKit mount and active conversation when opening its project receipt`；`ignores late project lookups after the user switches conversations`；`it.each(['project-b', null])` 采纳历史作用域；`syncs ChatKit Project changes into the workbench route and starts a blank scoped chat`；`changes Project and business selection in one route without moving the old conversation`；`preserves access when opening a Case in the same Project and restores state on cancelled navigation`（`navigate` mock 返回 `false` → 回滚）；`keeps the Project scope in a blank project-local conversation`。
- Project 权限：`it.each([['member'…],['editor'…]])` 加载权限；`ignores a slow Project access response after the route switches to another Project`（迟到响应丢弃）；`fails closed while Project access is pending or denied`（403 → `null`）。
- 测试设施：`createMockChatKitControl()` 完整实现 `ChatKitControl`（`setOptions`/`focusComposer`/`setThreadId`/`sendUserMessage`/`setComposerValue`/`fetchUpdates`/`sendCustomAction`）与 `settle()` 宏任务等待。

**2. `conversation-entry.resolver.spec.ts`（6 例）**：正常解析（断言 `getEntryByThreadId('thread','org')` 参数）；群组成员无个人 ClawXpert 特性仍放行；私聊保留特性门控（`RedirectCommand` + `createUrlTree(['/chat'])`）；新私聊同样被门控且不拉线程；新会话不取元数据；授权错误 fail-closed（返回 `{entry:null, error}` 而非抛错/选私聊适配器）。

**3. `frequent-questions-start-screen.spec.ts`（10 例）**：手动配置先渲染（`greeting` + 去重后的 `prompts`）；自动结果合并去重（`EXPORT REPORT` 与 `Export report` 归一）；失败/空结果保留手动内容；`active=false` → `startScreen()` 为 `null`；自动关闭时保留 6 条手动问题且**零请求**（`http.expectNone`）；opener 关闭时回落 legacy `starters`/`description` 且不要求组织；禁用/历史/无组织三种情况不生成；生成请求路径与 locale 精确断言（`/api/xpert/expert-1/frequent-questions?locale=zh-Hans`）；切专家/切组织取消前序请求（`first.cancelled===true`）；切语言重新加载并清空生成项。

**4. `workbench-assistant-menu.component.spec.ts`（8 例）**：复用既有助手列表并过滤重复/`latest===false`；按助手路由切换且**不携带**上一会话或 view query；群组发现/打开（成员头像 2 个、`conversationRoute('g')`）与 `[data-create-group]` 存在；当前助手标记 `aria-current="page"` 且重复点击只 emit 不导航；tenant 作用域改用 `('tenant','chat_common')`；业务域按 id 过滤（不导航不 emit）+ 搜索与可清除过滤组合；过滤键的键盘事件不冒泡（Escape 例外）；失败显示 `role="alert"` 且 Retry 复位。

**5. `workbench-loading-indicator.component.spec.ts`（2 例）**：300ms 内不显形、ready 后无 `role="status"` 且聊天内容存在；400ms 后显形（`h-0.5` + `pointer-events-none` + `sr-only` 含 `XP.Common.Loading`），卸载后 399ms 仍不显形（定时器随组件销毁取消）。

## 门面契约相关用例与缺口

**存在什么**：与契约**语义**相关的断言分散在消费侧实现 spec 里——例如 `xpert-workbench.facade.spec.ts` 间接验证了 `identity` 在群组/私聊两种取值、`viewState` 的四态取值、`threadId` 在群组下为 `null`、`projectAccess` fail-closed、`suppressAutoResume` 置位；`clawxpert-scoped-conversation.facade.spec.ts`（属 ClawXpert 子专家）用 `const scoped: WorkbenchChatFacade = facade(scope)` 显式把两个实现按契约类型使用，是对「三实现同形」最强的静态约束。

**缺什么（明确缺口）**

| # | 缺口 | 说明 | 建议 |
| --- | --- | --- | --- |
| 1 | **无契约测试套件** | 没有任何 spec import `WORKBENCH_CHAT_FACADE` 做「每个实现都必须满足」的共享行为断言；也没有对 `workbench-chat.facade.ts` 任何一行代码的测试 | 新增 `workbench-chat.facade.spec.ts`：遍历「实现清单」跑共享不变量（非 ready → `identity()===null`；`viewState` 取值属四态；`beginPendingConversation` 幂等；`patchActiveConversationStatus` 无会话时 no-op） |
| 2 | **契约外隐式成员无守护** | `refreshTaskSummaries` / `currentWorkspaceId` 靠 `hasTaskSummaryRefresh`、`getOptionalSignalValue` 结构探测，无任何 spec 断言其存在性/缺省行为 | 在契约测试中显式断言「缺失时骨架走 null 分支」 |
| 3 | **装配点无直接 spec** | `ChatXpertWorkbenchComponent`（`useExisting` 绑定、模板一行）无 spec；一旦有人把 `useExisting` 改成 `useClass`，本子域无一例会失败 | 加 3 行式断言：`TestBed.createComponent(ChatXpertWorkbenchComponent)` 后 `inject(WORKBENCH_CHAT_FACADE) === inject(XpertWorkbenchFacade)` |
| 4 | **`viewState` 的 `wizard` 分支** | 5 个 spec 中**无一处**断言 `viewState()==='wizard'`；实现里该分支的判断序在 `errorMessage` 之后，稳态可能不可达 | 补一条时序敏感用例，把可达性写成显式契约 |
| 5 | **`onChatProjectChange` 的 view 参数分支** | 只覆盖「同项目 + view」与「case 打开」两条；`viewParameters` 的 `JSON.stringify` 断言仅 1 处 | 补 query 归一（null 清理）的边界用例 |
| 6 | **零件 `WorkbenchAccountComponent` 零测试** | `xp-workbench-account` 仅 18 行，但它是骨架头部唯一账号入口 | 低优先级；可并入契约测试的渲染冒烟 |
| 7 | **i18n 键无守护** | 各 spec 用 `TranslateModule.forRoot()` 与 `Default` 文案；键改名不会失败（`XP.Chat.XpertWorkbench.*` 与 `XP.Chat.ClawXpert.FrameMissing` 混用更易漏） | 若要守护，需引入键清单断言（仓库内暂无先例） |

## 缺口

- **契约层零覆盖**（缺口 1、2）：本子域最重要的资产 `workbench-chat.facade.ts` 既无 spec 也无契约套件，是资产盘点与测试覆盖之间最大的落差。
- **装配层零覆盖**（缺口 3）：`useExisting` 是本子域最容易写错、后果最严重（状态分叉）的一行，却无测试。
- **环境依赖**：本子域 5 个 spec 全部离线（`HttpTestingController` / `jest.fn()`），只需 `node_modules` 落盘；不依赖 `packages/contracts` 产物。
- **跨子域测试归属模糊**：`clawxpert-scoped-conversation.facade.spec.ts` 同时断言了本子域契约与 ClawXpert 装配（它用 `WorkbenchChatFacade` 类型 + `injectFrequentQuestionsStartScreen`），两个子专家的覆盖点存在重叠，盘点时需去重（父级 `06-测试.md` 把 `workbench-chat` 记为「3 非 spec / 3 spec」，本会话实测 **5 / 3**）。
- **未能核实**：本会话仅只读检索，未实际执行 jest，因而**未能给出本子域 5 个 spec 的 PASS/FAIL 实测结果**；父级文档记录的失败清单（4 环境级 + 1 contracts + 5 真实断言候选）未点名本子域任何 spec，故本子域基线按「可跑、待复跑确认」对待。

## 结论

- **现状：5 spec / ≈54 例，全部集中在「宿主实现 + 零件」**，其中 `xpert-workbench.facade.spec.ts` 一个文件占 28 例，是本子域唯一的重回归面。
- **测试风格与父级一致**：`jest.mock` 整个 barrel（`@core` / `assistant-chatkit.runtime` / `project-api.service`）+ TestBed + `HttpTestingController`，断言主轴是**命令行参数、signal 取值与否定断言**（不导航、不请求）。
- **最重要的一条是「identity 不因 Project 采纳而改变」**：它被 3 条用例从不同角度保护（首发采纳、Receipt 打开、迟到响应），说明 iframe 重挂是本子域最贵的失效模式。
- **首要补测动作**：新建 `workbench-chat.facade.spec.ts` 作为**契约套件**（对 3 个实现跑同一组不变量）＋ 补 `ChatXpertWorkbenchComponent` 的 `useExisting` 同一性断言；这两项能把缺口 1/2/3 一次覆盖，成本极低而收益最高。
- 运行命令与计数口径见本文 §「运行方式与命令」；契约的逐成员语义见 `implementation/05-接口.md`。
