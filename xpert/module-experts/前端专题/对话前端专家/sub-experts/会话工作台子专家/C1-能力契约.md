**1.1 `WorkbenchChatFacade` 逐成员表（31 成员：21 必需 + 10 可选；可选成员标注 `?`，另有契约外隐式成员见文末）**

**1.2 `WORKBENCH_CHAT_FACADE` 注入与生命周期**

- 定义形式：`new InjectionToken<WorkbenchChatFacade>('WORKBENCH_CHAT_FACADE')`——**无 `providedIn`、无 `factory`**；无祖先 provider 时 `inject(WORKBENCH_CHAT_FACADE)` 抛 `NullInjectorError`，故骨架用 `{ optional: true }` 回落 `inject(ClawXpertFacade)`。
- 提供方式：必须 `useExisting`。三个解析结果实测为：`ChatXpertWorkbenchComponent` → `XpertWorkbenchFacade`；`ClawXpertConversationPaneComponent` → `ClawXpertScopedConversationFacade`；无 provider → `ClawXpertFacade`。
- 生命周期：token 实例 = 提供它的组件注入器中的那份 facade；两个提供点**互不共享**。宿主组件销毁 → 注入器销毁 → facade 失效（`ClawXpertScopedConversationFacade.ngOnDestroy` 另置 `destroyed` 以阻断迟到回写）。
- 可见性：`useExisting` 提供的是**组件级**注入器，同一页面内多个骨架/零件实例拿到同一份宿主 facade——这是「一个页面一个会话上下文」的实现方式。

## 2. 入口路由契约

三种形态共四条路径，由 `xpertWorkbenchConversationMatcher` 唯一匹配（`/chat` 前缀由父级路由拼装）：

| # | 路径 | 段数 | `posParams` | 说明 |
|---|---|---|---|---|
| ① | `/chat/x/:name/c` | 3 | `name` | 空会话入口；`x/:name`（`pathMatch: 'full'`）会重定向到此，保留 query / fragment |
| ② | `/chat/x/:name/c/:threadId` | 4 | `name`、`threadId` | 指定线程 |
| ③ | `/chat/x/:name/p/:projectId/c` | 5 | `name`、`projectId` | Project 隔离形态（空会话） |
| ④ | `/chat/x/:name/p/:projectId/c/:threadId` | 6 | `name`、`projectId`、`threadId` | Project 隔离 + 指定线程 |
| 路由项 | `resolve: { conversationEntry: resolveConversationEntry }`、`canActivate: featureGate([FEATURE_XPERT])`、`data.title` | — | — | matcher 不在 `x` 段匹配或段位非法时返回 `null` |

`resolveConversationEntry`（`ResolveFn<ConversationEntryResolution>`）的解析顺序：① 取 `threadId`；② 有线程时用 `store.organizationId` 调 `getEntryByThreadId(threadId, organizationId)`；③ `entry.purpose !== 'group' && !hasFeatureEnabled(FEATURE_XPERT_CLAWXPERT)` → `RedirectCommand(createUrlTree(['/chat']))`，**群组无条件放行**；④ `catchError` 转成 `{ entry: null, error: getErrorMessage(error) || 'XP.Chat.ClawXpert.LoadFailedDesc', organizationId }`——**错误必须阻断会话初始化，不许降级为私聊**，宿主据此把 `viewState` 判为 `'error'`（跨组织群组同样直接 `'error'`）。

章节来源：[routes.ts](file://apps/cloud/src/app/features/chat/routes.ts)（关键符号：`xpertWorkbenchConversationMatcher`、`resolveConversationEntry`、`featureGate`）· [conversation-entry.resolver.ts](file://apps/cloud/src/app/features/chat/xpert-workbench/conversation-entry.resolver.ts)（关键符号：`ConversationEntryResolution`、`assertWorkbenchConversationHint` 同类判定）

## 3. 代码示例（真实调用方）

① **以门面实现一个宿主**（装配点 + URL 驱动门面的必需面）：

```ts
// xpert-workbench.component.ts（剪裁：装配三行，组件无 inputs / outputs）
@Component({
  selector: 'xp-chat-xpert-workbench',
  imports: [CommonModule, ClawXpertConversationDetailComponent],
  providers: [XpertWorkbenchFacade, { provide: WORKBENCH_CHAT_FACADE, useExisting: XpertWorkbenchFacade }],
  template: `<xp-clawxpert-conversation-detail class="min-h-0 flex-1" />`
})
export class ChatXpertWorkbenchComponent {}
// 门面侧（语义剪裁）：URL 派生 threadId / projectId / viewState，identity 非 ready 时为 null
currentUrl = toSignal(this.#router.events.pipe(filter((e) => e instanceof NavigationEnd), startWith(null)), …)
viewState = computed(() => (this.organizationId() ? (this.xpertId() ? 'ready' : 'error') : 'organization-required'))
```

② **复用到新页面**（三步：实现门面 → 提供 token → 复用骨架；状态写回必须走路由）：

```ts
// 1) 实现 21 个必需成员（参考 XpertWorkbenchFacade 的职责划分：URL 派生 / 可得性加载 / 会话写回 / Project 采纳）
// 2) providers: [YourFacade, { provide: WORKBENCH_CHAT_FACADE, useExisting: YourFacade }]
// 3) 可选成员按形态取舍：group / projectId / chatkitMountProjectId / chatkitProjectSelection /
//    projectAccess / onChatProjectChange / syncConversationProject / currentXpert / assistantTitle / assistantAvatar
// 线程与 Project 一律 navigate 回写（刷新后状态不丢，骨架可跨形态复用）
await this.#router.navigate(['/chat/x', slug, 'c', threadId], { queryParamsHandling: 'preserve' })
```
