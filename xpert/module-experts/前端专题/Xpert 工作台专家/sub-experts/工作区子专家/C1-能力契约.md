## 1. HTTP 调用面

口径：`API_PREFIX = '/api'`；`XpertWorkspaceService = API_PREFIX + '/xpert-workspace'`、`XpertAPIService = API_PREFIX + '/xpert'`（文件族拼 `/:id/workspace/*`）、`AiWorkspaceFilesService` 前缀 `/api/ai/assistants/:id/workspace`；查询串统一 `?data={...}`。

| 分组 | 方法 + 路径（前端调用点） | 用途 | 归属 / 明细指向 |
|---|---|---|---|
| 集合与默认 | `GET /api/xpert-workspace/my?purpose=authoring`（`getAllMy`）、`GET /my/default`（`getMyDefault`）、`POST /:workspaceId/default`（`setMyDefault`） | 工作区集合、默认工作区读/设；`purpose` 仅 `authoring` 被识别 | **工作区与文件授权子专家**（`C0/C1`） |
| 详情与成员 | `GET /:workspaceId`（`getOneById(id, { relations: ['owner','members'] })`）、`GET /:workspaceId/members`、`PUT /:workspaceId/members`（body = `string[]`） | 设置面详情；成员**整体覆盖** | 同上 |
| 更新 / 可见性 | `PUT /:workspaceId`（`update`）、`PUT /:workspaceId/visibility`（`updateVisibility`，body `{ visibility }`） | 改名与可见性三态 | 同上 |
| 归档 / 删除 | `POST /:workspaceId/archive`（`archive`）、`DELETE /:workspaceId`（硬删）、`PUT /:workspaceId/soft` / `POST /:workspaceId/recover` | 危险区动作 | 同上 |
| 资源分页 | `GET /api/xpert-workspace/by-workspace/:id`（基类 `getAllByWorkspace`，可加 `published`） | 资源页按工作区取数 | 同上；助手侧另有 `GET /api/xpert/by-workspace/:workspaceId` |
| 文件族（authoring·本子域） | `GET /api/xpert/:id/workspace/files`（`getWorkspaceFiles`）、`GET /:id/workspace/file`、`GET /:id/workspace/file/download`、`PUT /:id/workspace/file`、`POST /:id/workspace/file/save-binary`、`POST /:id/workspace/file/upload`、`DELETE /:id/workspace/file` | 浏览 / 读 / 下载 / 保存（文本与二进制）/ 上传 / 删除 | 服务端 `AssistantFilesService.forAuthoring`；归属**工作区与文件授权子专家** |
| 文件族（runtime·对照，对话域消费） | `GET|PUT|POST|DELETE /api/ai/assistants/:id/workspace/*`（`AiWorkspaceFilesService` 同名 7 方法） | 运行时会话文件面；`mode: 'readonly'｜'editable'` 决定是否传写回调 | 服务端 `forRuntime`；消费方在**对话域** |
| 权限准入 | 非 HTTP：`WorkspaceAuthoringGuard` / `WorkspaceOwnerGuard`（非 UUID 先抛 `WorkspaceIdInvalid`） | 工作区读写与管理准入 | 同上（前端只声明，不实现） |

## 2. 前端服务与组件契约

### 2.1 能力集的消费方式（只读、缺省放行、不当安全边界）

- 服务面：`canRead / canRun / canWrite / canManage(workspace)`，入参 `Pick<IXpertWorkspace, 'capabilities'>`，实现为 `workspace?.capabilities?.canX ?? true`——**能力位缺失即放行**，与后端「不满足即四项全 false」相反。
- 组件面：宿主 `computed` 派生 `canWriteWorkspace` / `canManageWorkspace` 供全子树 `inject` 消费；`canEditVisibility = !!workspace && canManageWorkspace`；资源页新建/删除用 `canWrite`，`openSettings` 用 `canManage`。
- 唯一的「能力位驱动副作用」：设置对话框 `onUpdated()` 若 `capabilities?.canRead === false` 直接 `close('updated')`；`canRun` 在本子域**无消费点**（运行权可能来自 UserGroup，不出现在成员列表）。

章节来源：[xpert-workspace.service.ts](file://apps/cloud/src/app/@core/services/xpert-workspace.service.ts)（关键符号：`canRead`、`canRun`、`canWrite`、`canManage`、`isTenantShared`）· [home.component.ts](file://apps/cloud/src/app/features/xpert/workspace/home/home.component.ts)（关键符号：`canWriteWorkspace`、`canManageWorkspace`、`openSettings`）· [settings.component.ts](file://apps/cloud/src/app/features/xpert/workspace/settings/settings.component.ts)（关键符号：`onUpdated`、`workspaceRevision`）

### 2.2 `XpertWorkspaceHomeComponent`：宿主即上下文

- 列表：`getAllMy({ order: { updatedAt: DESC } }, { purpose: 'authoring' })`；`workspace` 是 `computed` 从列表挑选（`equal: a?.id === b?.id`）；菜单渲染 `filteredWorkspaces()`（`debouncedSignal(searchWorkspace, 300)`）。
- 双写选中：`selectWorkspace(ws)` 同时 `router.navigate(['/xpert/w/', ws.id])` 与 `store.setWorkspace(ws)`；反向由 effect 三方同步（路由 id 命中 → `setWorkspace`；选中态命中 → `syncWorkspaceRoute`；都不命中 → 回落 `workspaces[0]`）。
- `section` 由 `NavigationEnd` 后取 `route.snapshot.firstChild?.routeConfig?.path`，派生 `type` / `allTags` / `isAll` / `isTools` 等；`syncWorkspaceRoute` 仅改 `/xpert/w/*` 前缀且保留子段与 fragment，**剔除 `section` 查询参数**。

章节来源：[home.component.ts](file://apps/cloud/src/app/features/xpert/workspace/home/home.component.ts)（关键符号：`workspaces`、`filteredWorkspaces`、`selectWorkspace`、`syncWorkspaceRoute`、`isStandaloneWorkspaceRoute`）· [routes.ts（工作区）](file://apps/cloud/src/app/features/xpert/workspace/routes.ts)（关键符号：`redirectToSelectedWorkspace`、`section`）

### 2.3 设置面：可见性与成员

- 对话框：`data: { id }` → `getOneById(id, { relations: ['owner','members'] })`（`derivedAsync`）；`selectedMenus` 三页签，apiKeys 页复用 `XpertDevelopApiKeyComponent`（`bindingType: WORKSPACE`）；关闭事件 `'deleted'｜'archived'` → 壳层 `workspaceService.refresh()` + 回 `/xpert/w`。
- 可见性：`update()` 三重短路（无 id / 无 `canManage` / `loading`）；`shared ? (isTenantWorkspace ? 'tenant-shared' : 'organization-shared') : 'private'`，仅在 `canEditVisibility()` 且与 `currentVisibility()` 不同时 `updateVisibility`；**失败只 toast、`savedVisibility` 不动**（开关回弹到服务端真值）。
- 成员：`toObservable(workspaceId) → filter(nonNullable) → switchMap(getMembers)`；写路径 `uniqBy([...members, ...users], 'id')` 本地合并后 `updateMembers(id, members().map(u => u.id))`；`UserRoleSelect` 用 `excludeUserIds` + `loadOnEmptySearch`，返回空不提交。

章节来源：[general.component.ts](file://apps/cloud/src/app/features/xpert/workspace/settings/general/general.component.ts)（关键符号：`update`、`canEditVisibility`、`currentVisibility`、`savedVisibility`、`archive`、`delete`）· [members.component.ts](file://apps/cloud/src/app/features/xpert/workspace/settings/members/members.component.ts)（关键符号：`members`、`allMembers`、`updateMembers`、`removeMember`、`openAddUser`）

### 2.4 文件操作面：7 回调 → authoring 端点

- `XpertWorkspaceFilesComponent` 只做映射：`loadFiles / loadFile / saveFile / saveBinaryFile / uploadFile / deleteFile / downloadFile` → `XpertAPIService` 的 `getWorkspaceFiles / getWorkspaceFile / saveWorkspaceFile / saveWorkspaceBinaryFile / uploadWorkspaceFileToFolder / deleteWorkspaceFile / downloadWorkspaceFile`（实际路径 `/api/xpert/:id/workspace/*`）。
- `xpertId` 解析：`merge(of(null), assistantBindingService.changes$.filter(code===CLAWXPERT && scope===USER)).pipe(switchMap(get), map(b => b?.assistantId?.trim() || null), catchError(() => of(null)), startWith(null))`；模板 `@if (xpertId())` 渲染 `FileWorkbenchComponent`（`layout="library"`），否则空态；回调侧 `requireXpertId()` 缺失即 `throw new Error('Claw Xpert is not configured')`。
- 下载：先 `firstValueFrom` 取 blob，`item?.hasChildren` 时文件名加 `.zip`；**本页不读路由 `:id`**，也不做本地能力判定。

章节来源：[files.component.ts](file://apps/cloud/src/app/features/xpert/workspace/files/files.component.ts)（关键符号：`xpertId`、`loadFiles`、`saveFile`、`uploadFile`、`deleteFile`、`downloadFile`、`requireXpertId`）· [workbench.types.ts](file://apps/cloud/src/app/@shared/files/workbench/workbench.types.ts)（关键符号：`FileWorkbenchFilesLoader`、`FileWorkbenchFileSaver`、`FileWorkbenchFileDownloader`、`FileWorkbenchLayout`）

### 2.5 `redirectToSelectedWorkspace`：入口改写守卫

- 取 `appQuery.getValue().selectedWorkspace?.id ?? persistQuery.getValue().workspaceId`；`section` 映射：`skills→clawxpert-skills`、`knowledges→clawxpert-knowledges`、`connectors→clawxpert-connectors`、`files|settings→同名`。
- 有 id → `router.createUrlTree(['/xpert/w', workspaceId, ...(routeSegment ? [routeSegment] : [])])`；无 id → 返回 `true`（**放行**，由宿主空态处理）。**它是重定向函数，不是权限守卫**；写权限由 `WorkspaceAuthoringGuard` / `WorkspaceOwnerGuard` 兜底。
- 子段 `settings` 实为 `redirectTo: '/chat/clawxpert'`（`pathMatch: 'full'`）；`prompt-workflows` 带 `canDeactivate: [(c) => c.confirmLeave()]`。

章节来源：[routes.ts（工作区）](file://apps/cloud/src/app/features/xpert/workspace/routes.ts)（关键符号：`redirectToSelectedWorkspace`、`path: 'settings'`、`canDeactivate`）· [routes.ts（父级）](file://apps/cloud/src/app/features/xpert/routes.ts)（关键符号：`path: 'w'`、`loadChildren`、`scopeContext`）

## 3. 示例（真实调用方）

① **加载工作区并读能力**（结构示意：符号与调用形态已回源码核实）：

```ts
// home/home.component.ts：宿主集中取数 → 派生门控信号 → 子页面 inject 消费
readonly workspaces = toSignal(this.#workspaceService.getAllMy({ order: { updatedAt: DESC } }, { purpose: 'authoring' }))
readonly workspace = computed(() => this.workspaces()?.items.find((_) => _.id === this.selectedWorkspace()?.id))
readonly canWriteWorkspace = computed(() => this.#workspaceService.canWrite(this.workspace()))     // capabilities?.canWrite ?? true
readonly canManageWorkspace = computed(() => this.#workspaceService.canManage(this.workspace()))
// 子页面（资源页）：inject(XpertWorkspaceHomeComponent) 读 above，不自行取工作区
```

② **改可见性**（结构示意：三重短路 + 三态推导 + 失败保留真值）：

```ts
// settings/general/general.component.ts
update() {
  if (!this.workspaceId() || !this.canManageWorkspace() || this.loading()) return
  if (this.name() !== this.workspace()?.name) { /* update(id, { name }) → toast + updated.emit */ }
  const visibility = this.shared()
    ? (this.isTenantWorkspace() ? 'tenant-shared' : 'organization-shared')   // organizationId 为空 → tenant-shared
    : 'private'
  if (this.canEditVisibility() && visibility !== this.currentVisibility()) {
    this.#workspaceService.updateVisibility(this.workspaceId(), visibility).subscribe({
      next: (updated) => { this.#workspaceService.refresh(); this.updated.emit(updated) },
      error: (err) => this.#toastr.error(getErrorMessage(err))   // 不改 savedVisibility，开关回弹
    })
  }
}
```

③ **在工作区文件里上传与下载**（结构示意：绑定解析 + authoring 端点 + `.zip` 命名）：

```ts
// files/files.component.ts
readonly xpertId = toSignal(
  merge(of(null), this.#bindingService.changes$.pipe(filter((e) => e.code === CLAWXPERT && e.scope === USER))).pipe(
    switchMap(() => this.#bindingService.get(CLAWXPERT, USER)), map((b) => b?.assistantId?.trim() || null),
    catchError(() => of(null)), startWith(null)))
private requireXpertId() { const id = this.xpertId(); if (!id) throw new Error('Claw Xpert is not configured'); return id }
readonly uploadFile = (file: File, path = '') => firstValueFrom(this.#xpertAPI.uploadWorkspaceFileToFolder(this.requireXpertId(), file, path))
readonly downloadFile = async (item: TFile) => ({
  kind: 'blob' as const,
  blob: await firstValueFrom(this.#xpertAPI.downloadWorkspaceFile(this.requireXpertId(), item.fullPath)),
  fileName: item.hasChildren ? `${item.name}.zip` : item.name
})
```
