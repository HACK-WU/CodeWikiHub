| `updateMembers(id, members: string[])` | [xpert-workspace.service.ts](file://apps/cloud/src/app/@core/services/xpert-workspace.service.ts) | 请求体为 **id 数组**，语义是**整体覆盖** | 前端 | 后端 | 后端权威；不提供增删单条接口 |

**与 UserGroup 的模型关系**：`UserGroup` 在本子域**没有任何类型**（`workspace/**` 对 `UserGroup` 零引用）。后端口径是「用户组只补 `canRun`」，其读在 `hasPublishedXpertRunAccess`（原生 SQL 读 `xpert_to_user_group`）；因此成员集合与运行权集合**不是同一集合**，前端不得用成员列表反推 `canRun`。

## 建模边界

**只在前端存在的模型（后端无对应契约）**

1. `XpertWorkspaceRequestOptions`、`WorkspaceOverviewCounts`、`WorkspaceOverviewState`、`XpertFilterEnum`、`homeRouteMatchOptions`、`isStandaloneWorkspaceRoute` / `isMarketplaceWorkspaceRoute`。
2. `section → routeSegment` 映射（在 `routes.ts` 与 `home.component.ts` 各一份）。
3. `UserRoleSelectComponent` 的 `{ users: IUser[] }` 返回形状与 `excludeUserIds` / `loadOnEmptySearch` 输入。
4. `ClawXpertConversationFilesMode` 与 `FileWorkbench*` 回调族（共享层私有契约）。
5. 概览页的 5 项计数语义（一次拉 1000 条再 `items.length`，是**展示口径**而非统计口径）。

**不在本子域建模（明确归属）**

- 能力四动作的判定、`assertCan*`、UserGroup→`canRun` 桥接：后端「工作区与文件授权子专家」。
- 卷作用域与物理路径（`xperts` / `user-xperts`、`resolveXpertDataVolumeScope`）：后端 + `shared/volume`。
- 运行时会话文件（Workbench）与对话附件 `FileAsset`：对话域 / `ai/file-understanding`。
- 消息、任务、积分等无关模型。

章节来源：[settings-page.component.ts](file://apps/cloud/src/app/features/xpert/workspace/settings/settings-page.component.ts)（关键符号：`queryLimit`、`countItems`、`metrics`）、[home.component.ts](file://apps/cloud/src/app/features/xpert/workspace/home/home.component.ts)（关键符号：`XpertFilterEnum`、`isMarketplaceWorkspaceRoute`）、[members.component.ts](file://apps/cloud/src/app/features/xpert/workspace/settings/members/members.component.ts)（关键符号：`UserRoleSelectComponent`、`excludeUserIds`）、[AGENTS.md](file://AGENTS.md)（关键符号：三元权限面）

## 校验规则

| # | 规则 | 落点 | 行为 |
| --- | --- | --- | --- |
| 1 | 可见性归一 | `getXpertWorkspaceVisibility` | 非 `tenant-shared`/`organization-shared` 一律按 `private` 呈现（含未知值） |
| 2 | 可见性取值来源 | `general.update()` | `shared ? (isTenantWorkspace ? 'tenant-shared' : 'organization-shared') : 'private'`，其中 `isTenantWorkspace = !organizationId` |
| 3 | 最小写请求 | 同上 | 名称未变不发 `update`；可见性未变不发 `updateVisibility`；无 `canManage` 或 `loading` 时整个 `update()` 短路 |
| 4 | 失败保留真值 | 同上 | 写失败仅 toast，`savedVisibility` 不动，开关回弹到服务端值 |
| 5 | 成员覆盖去重 | `members.component` | 合并时 `uniqBy(..., 'id')`，提交 `string[]`；owner 参与展示与排除，不参与删除 |
| 6 | 空选择不提交 | 同上 | 对话框 `closed` 返回 `null` → `EMPTY`，不发请求 |
| 7 | 入口守卫回落 | `redirectToSelectedWorkspace` | 无工作区 id 时返回 `true`（交由宿主空态），有则 `createUrlTree` |
| 8 | URL 改写白名单 | `syncWorkspaceRoute` | 仅当 `['xpert','w',...]` 前缀成立才改写；保留子段与 fragment；剔除 `section` |

## 结论

- **三层类型边界清楚**：契约层（`IXpertWorkspace` / 可见性 / 能力集 / `TFile`）、@core 服务层（`canX()` 呈现包装、请求选项）、子域私有类型（筛选、概览、路由匹配、对话框返回）。判定语义全在契约层与后端，前端只有投影。
- **唯一「反安全默认」处**：`canX()` 的 `?? true`。它让 UI 在能力位缺失时放行，是模型层最需要显式决策的一点（改为 `?? false` 会立即收紧所有资源页入口）。
- **两个同名文件服务是两条并列通道**：authoring（本子域）与 runtime（对话域），模型上不可互换、不可回退。
- **成员 ≠ 权限全集**：模型中成员是用户数组且无角色；`canRun` 可能来自 UserGroup 而不出现在成员列表，前端不得反向推断。
