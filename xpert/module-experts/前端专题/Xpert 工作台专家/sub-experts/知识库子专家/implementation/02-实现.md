## ① 知识库列表与详情链

**列表**：`KnowledgebaseHomeComponent` 先用 `toSignal` 合成上下文——`Store.selectOrganizationId()` → `ClawXpertBindingTargetService.getCurrentUserTarget()` → `XpertWorkspaceService.getAllMy(undefined, { purpose: 'authoring' })`，得到 `target.workspaceId` 与对应 `workspace`，派生 `workspaceId` 与 `canWriteWorkspace`（`workspaceService.canWrite(workspace)`）。构造期 `effect` 在上下文就绪后调 `loadPreferences(workspaceId)` + `loadKnowledgebases()`；后者用 `#requestVersion` 做竞态守卫，取 `getAllByWorkspaceOnly(workspaceId, { relations: ['createdBy'], order: { updatedAt: DESC } })`，再用 `hydrateCardStatistics()` 对每张卡片 `forkJoin({ detail: getDetail, folders: getAll(sourceType=FOLDER, take 1), documents: getAll(sourceType≠FOLDER, take 1) })` 补 `documentNum / chunkNum / folderNum`。偏好（favorites / pinned / recents / sections / scope-rail-width-v2）存 `localStorage`，key 为 `xpert:knowledge:${userId}:${workspaceId}:${kind}`，`removeUnavailablePreferences()` 清理已消失的 id；`newKnowledgebase()/editKnowledgebase()` 打开 `XpertNewKnowledgeComponent` 对话框，关闭后按需 `loadKnowledgebases()`。

**详情**：`KnowledgebaseComponent` 用 `myRxResource({ request: () => ({ id: paramId() }), loader: getDetail })`，失败时 `toastr.danger` + `router.navigate(['/xpert/w'])` + `EMPTY`；暴露 `type/faq/wikiEnabled/avatar/external/pipelineId/pipeline/documentNum/xpertCount/xperts` 等 computed，`refresh()` = `#knowledgebase.reload()`。页头动作：`back()`（尊重 `?returnTo=/xpert/*`，否则回 `/xpert/knowledges`）、`deleteKnowledgebase()`（被助手引用时换用 `DeleteWithExpertsWarning` 文案）、`downloadPipeline(id)`、`openXpert()`（`window.open('/xpert/x/:id/agents')`）、`openApiKey()`、`openConfiguration(initialSection)`（对话框关闭返回真值则 `refresh()`）、`apiEnabled` 的 `linkedModel` 直写 `update(id, { apiEnabled })`。`effect` 负责默认落点：FAQ 库命中根或 `/documents` → 跳 `faq`，未启用 Wiki 命中 `/wiki` → 跳默认页，均 `replaceUrl: true` 并保留查询参数。

## ② 文档上传与摄取进度

**入口菜单**：`DocumentImportMenuComponent` 渲染 `DOCUMENT_IMPORT_SOURCES`（`files` / `url` / `pipeline` / `remote` / `crawl` 可用；`folder` / `online` 标注 `available: false` 渲染为禁用项）。`files` 直接走隐藏 `<input type="file" multiple>`；`url|crawl|remote` 先开 `DocumentImportSourceDialogComponent` 收集外部文档描述；`pipeline` 打开 `KnowledgeDocumentPipelineComponent` 对话框并拿 `{ taskId }`，随后 `knowledgebaseAPI.pollTaskStatus(kbId, taskId)` 跟随任务（`takeWhile` 校验知识库未切换），每次进度都 `imported.emit()` 让表格刷新——**提交先于建档**，所以即使表格为空也要跟任务。

**导入对话框**：`DocumentImportDialogComponent` 分区（tags / parser / chunks / images / audio / questions / table，`graph` 仅在 `graphRag.enabled` 时出现），`editDocument` 存在时载入 `getReprocessCapabilities` 决定 `canRechunk`；上传用 `KnowledgeFileUploader(kbId, kbAPI, file, { parentId, path })` 且逐文件 `upload()`；`ready` 要求「有文档 + 所有上传 `status()==='done'` + 未 busy + 未被外部锁 + 策略加载完成 + 无配置错误」；提交 `saveAndProcess(mode)`：新建走 `createBulk/updateBulk` + `startParsing(mode)`，编辑既有文档走 `updateBulk` + `startParsing(id, 'rechunk'|'full')`，而**流水线文档（带 `sourceConfig`）保持原任务处理路径**（不再 `startParsing`）。打开前由 `KnowledgeDocumentDialogService` 重新 `getDetail` 并二次判 `REBUILDING`，`importing` / `editing` 集合做并发去重。

**进度**：`DocumentViewState` 的 `effect` 侦测在途状态（`WAITING/RUNNING/TRANSFORMED/SPLITTED/UNDERSTOOD/EMBEDDING`）→ `documentDelayRefresh$ → debounceTime(REFRESH_DEBOUNCE_TIME) → refresh()` 重取列表（`select` 含 `progress/processMsg/processBeginAt/processDuation/processDuration/version`）；知识库级由 `graphStatus === INDEXING` 或 `vectorMutationLocked` 驱动 `knowledgebaseDelayRefresh$ → knowledgebaseComponent.refresh()`（注释明确：**普通解析只刷文档列表，知识库级轮询仅用于 GraphRAG 索引与重建锁这类聚合态**）。创建向导第三步 `KnowledgeDocumentCreateStep3Component` 用 `delayRefresh$ → debounceTime(5000) → refresh()` 调 `getStatus(pendingIds)` 局部合并，首屏任务文档为空时 `setTimeout(2000)` 重新 `reload()` 任务。

**失败/重跑**：行内 `startParsing(row)` 单条重跑；批量重处理走 `documents/settings/settings.component.ts`（先 `getReprocessCapabilities` → `canRechunk` → `startParsing(ids, mode)`）；GraphRAG 单文档失败用 `retryGraphDocument` 并自增 `graphProgressRefresh`；Wiki 单文档失败用 `retryJob(kbId, jobId, confirmAdditionalModelCharge)`；`stopJob()` 先本地把同 `jobId` 置 `CANCEL`、`progress=0` 再 `stopParsing(doc.id)`。

## ③ 切片与预览

## ④ 检索测试（`/api/knowledgebase/:id/test`）

`KnowledgeTestComponent` 是纯编排：`knowledgebase` 来自详情壳，`testSettings = linkedSignal(source: knowledgebase, computation: …)` —— 子页面刷新时**保留本地未保存的测试参数**（只跟随 `graphRag.enabled` / `wikiConfig` 与 `contentScope` 回落）。派生链：`isFAQ` → `recall`（FAQ 走 `normalizeKnowledgebaseFAQRecall`）→ `score / topK / retrievalMode / retrievalSettings`（`mode`、`entityTopK`、`neighborHops`、`graphWeight`、`communityTopK`、`fusion`）；`showDocumentTestControls = isDocumentKnowledgebaseType(type)`，`showContentScope = 文档库 && wikiConfig.enabled`。过滤字段 = 8 个系统字段（`document.fileName|folderPath|fileExtension|mimeType|category|sourceType|createdAt|updatedAt`）+ `knowledgebase.metadataSchema` 映射（`metadata.*` / `chunk.metadata.*` 前缀）。`test()` 组装请求：`{ query: query(), k: topK() ?? 10, score: score() ?? null, rerankThreshold: recall()?.rerankThreshold ?? null, rerankModel: 三段回退（显式模型对象 → undefined（沿用已保存模型） → null（不重排））, filters: requestFilter() ? { request } : undefined, retrieval: retrievalSettings(), contentScope? }`，成功写 `results`（`DocumentInterface<DocumentMetadata>[]`）与 `diagnostics`，失败写 `error`，`complete` 时 `#logs.reload()` 刷新检索日志；`selectLog(log)` 只回填 query 并清空结果。

## ⑤ 标签与 FAQ 操作

**标签**：`KnowledgeTagsComponent` 是「目录 + 打标」双模组件——`documentId` 有值时按文档展示 `assigned`（`source === 'automatic'` 时额外给「确认手工」动作），无值时为知识库选标目录；`options` 过滤 `getTagTargets(tag).includes('knowledgebase') && tag.isActive !== false && availableIds.has(tag.id)`；`canEdit` 完全取后端 `catalog.canEdit`；每次 `mutate()` 后 `refresh()`，并用 `revision` 做竞态守卫。服务面 `KnowledgeTagsService`：`list` / `select` / `remove` / `documentTags` / `addManual` / `removeManual` / `usage`。刷新注入 `injectDocumentTags(kb, documents)` 只在 `automaticTagging.enabled && isDocumentKnowledgebaseType(type)` 时生效，按当前页文档 id 排序后 100 个一批，`timer(0, 5000)` + `document.visibilityState === 'visible'` 门 + `exhaustMap` + `catchError(() => EMPTY)`（保留上一快照，下一 tick 重试）。

**FAQ**：`KnowledgeFAQComponent` 用 `PAGE_SIZE = 20`、`statusFilter`（all / enabled / disabled）、`search`（`FormControl` 非空）、`selectionModel`、`inspectorMode`（create / detail / edit）与 `#loadRequestId` 竞态守卫；`busy` 聚合 loading / deleting / updatingStatus / reprocessing / **vectorMutationLocked**；`vectorMutationLocked` 时 `effect` 起 `timer(0, 3000)` 刷详情（等待重建结束）。动作覆盖删除、启停、批量重处理（`reprocessingEntryIds` 追踪每行）、导入对话框与导出。FAQ 编辑器与表单拆成 `faq-editor.component.ts` + `faq-form.ts`，导入用 `faq-import-dialog.component.ts`。

## ⑥ 图谱与 Wiki 入口

**图谱**：`KnowledgeGraphComponent` 以 `cytoscape` 直连 DOM（`viewChild('graphCanvas')`），持 `#cy` / `#graphDataKey` / `#requestId`，接 `getGraphCatalog` / `getGraphVisualization` / `getGraphRelations` / `getGraphMentions` / `getGraphNeighborhood` 与实体关系 CRUD；过滤维度 `origins`（`extracted/structured/manual/curated`）与 `visibilities`（`active/hidden`）；`ResizeObserver` + `MutationObserver` 跟随容器与主题变化。索引动作下沉到 `KnowledgeGraphIndexActionsComponent`：`canRebuild` 要求 `status.enabled && status !== INDEXING && !requesting`，`rebuild()` 后立即 `getGraphStatus`，并在 `INDEXING` 期间以 `timer(2500, 2500) + exhaustMap + takeWhile(..., true)` 轮询（错误只报一次）；`KnowledgeGraphIndexErrorComponent` 展示索引错误，`KnowledgeGraphPropertiesComponent` 展示选中项属性，`graph-canvas-style.ts` 集中样式/主题变量。配置页另有入口 `rebuildGraph()`（成功后 `refreshGraphStatus()` + `pollGraphStatus()`）。

**Wiki**：`KnowledgeWikiComponent` 组合 `KnowledgeWikiService`（`getStatus` / `getTaxonomy` / `saveFolder` / `deleteFolder` / `movePage` / `getGraph` / `getPages` / `getPage` / `classify` / `getClassificationStatus` / `applyClassifications` / `rebuild` / `retryJob`）。状态派生 `canManage`、`enabled`、`indexing`、`recoveryActions`（仅 `canManage` 时暴露），`view` 在 `read | graph` 间切换且 `graphVisited` 懒加载，多个 `#xxxRequest` 计数器做竞态守卫，分类运行用 `classifying + #classificationTimer` 轮询，`pageFolderPath` 由 `taxonomy.folders` 逐级上溯拼接。**入口守卫**：`knowledgebaseWikiGuard` 用 `pathFromRoot` 里第一个 `id` 取详情，非文档库或未启用 → `router.createUrlTree(getKnowledgebaseDefaultRoute(...), { queryParams: route.queryParams })`，异常 → `toastr.danger` + `/xpert/w`。文档级进度由 `injectDocumentWikiProgress` 轮询（`timer(0, 5000)`、按 `KNOWLEDGE_WIKI_DOCUMENT_STATUS_BATCH_SIZE` 分批、`exhaustMap`、缓存 key 含 `version/updatedAt/status/disabled`），失败重试在 `DocumentWikiProgressComponent` 内联（`retryJob(..., requiresAdditionalChargeConfirmation)`）。配置面在 `configuration.component.ts`：`save()` 前若 Wiki 已启用且模型变更则 `requiresPaidWikiRebuild()` → 确认「可能产生模型费用」，`rebuilding` 时拒绝保存，返回后按 `hasRebuildingStatus` 进入 `pollRebuildStatus()`（`timer(0, 2000) → getDetail` 直到非 `REBUILDING`）。

## ⑦ pipeline 复用画布

**装配（4 行）**：`KnowledgebasePipelineComponent` 的装饰器是 `imports: [RouterModule, XpertStudioComponent]`、`animations: [routeAnimations]`、`providers: [XpertService]`；类体只做两件事——`inject(KnowledgebaseComponent)`（拿到详情壳以调 `refresh()`）与构造期订阅 `xpertService.published$.subscribe({ next: () => this.knowledgebaseComponent.refresh() })`。**数据从哪来**：① 画布侧数据（团队、节点、连线、草稿）由 `XpertStudioComponent` 自己 `injectParams('id')` 读 `xpertId` + 注入同一个 `XpertService`（本页 `providers` 提供）拉取，宿主不传任何输入；② 设计器数据来自知识库详情 `knowledgebase().pipeline / pipeline()`，与路由 `xpert/:id` 的 `:id` 是**两个不同 id**（前者 `xpertId`、后者 `knowledgebaseId`），所以 `paramId` 语义在此页是 xpertId；③ 发布事件回流：Studio 发布组件 `published$.next(result)` → 本页订阅 → 知识库详情 `reload()`。

**相邻两处**：`knowledgebase/pipelines/pipelines.component.ts` 是列表包装（`imports: [RouterModule, XpertPipelinesComponent]`），若详情已有 `pipelineId` 则 `effect` 相对跳到 `./:pipelineId`，否则用 `onPipelineCreated(pipeline)` 跳新流水线；`documents/pipeline/pipeline.component.ts`（`KnowledgeDocumentPipelineComponent`）是**另一条**流水线——三步导入向导：从 `getDetail(kbId).pipeline.graph.nodes` 过滤 `WorkflowNodeTypeEnum.SOURCE` 得到源节点，配 `documentSourceStrategies$` 与 `integrationAPI.selectOptions({ provider: service })` 选集成，`taskId` 后由 `myRxResource` 拉 `getTask(kbId, taskId, { relations: ['documents'] })`，第二步 `saveAndProcess()` 提交 `processTask(kbId, taskId, { sources: { [sourceKey]: { documents } }, stage: 'prod' })`（重复点击只提交一次、提交期间 `dialogRef.disableClose = true`，失败保留批次并 `toastr.error`）。

## 热点路径

1. **列表 → 详情**：`/xpert/knowledges` → 上下文（工作区目标）→ `getAllByWorkspaceOnly` → `hydrateCardStatistics`（N 卡 × 3 请求）→ 打开卡片 `router.navigate(['/xpert/knowledges', id])` → 详情 `getDetail` → 默认子路由重定向。
2. **上传 → 摄取 → 进度**：菜单 → `DocumentImportDialogComponent`（上传 → 校验 → 提交）→ `createBulk/updateBulk` + `startParsing` → 表格 `documentDelayRefresh$` 轮询 → 行内进度/阶段视图 → 失败 `startParsing` 重跑或 `getReprocessCapabilities` 决定 rechunk。
3. **检索测试环**：详情 → `/test` → 参数编排（本地 `linkedSignal` 保留）→ `POST /:id/test` → `results` + `diagnostics` → `getLogs` 刷新 → 点历史日志回填 query。
4. **派生态等待**：开自动打标 → `injectDocumentTags` 每 5s 刷当前页标签；开图谱 → `injectDocumentGraphProgress`（活跃 5s / 落定 30s）+ 索引动作 2.5s；开 Wiki → `injectDocumentWikiProgress` 5s；重建 embedding → 配置页 2s、FAQ 页 3s 刷详情。
5. **画布复用与发布回流**：`/xpert/knowledges/:kbId/xpert/:xpertId` → 画布（Studio）→ 发布 → `published$.next` → 本页 `knowledgebaseComponent.refresh()`。

## 技术债与 hack

1. **轮询密度高且分散**：同一知识库页面可能并存 6 组 `timer`（表格去抖、标签 5s、Wiki 5s、图谱 2.5s / 5–30s、FAQ 3s、配置 2s）；[推测] 大列表 + 多开关同时开启时请求量显著，且**没有全局可见性门**（只有标签轮询检查 `document.visibilityState`）。
2. **列表统计是 N+1**：`hydrateCardStatistics` 对每张卡片发 1 次 `getDetail` + 2 次 `getAll({ take: 1 })`；卡片数量增长时首屏代价线性上升。[推测] 后端若提供批量统计接口可直接砍掉该链。
3. **`published$` 订阅未退订**：`KnowledgebasePipelineComponent` 在字段初始化处 `subscribe`，无 `OnDestroy` / `takeUntilDestroyed`（父级 02 已登记同形态问题）；[推测] 依赖组件级 provider 随视图回收。
4. **`new/*` 与 `documents/*` 的双通道**：同一批处理表单既有对话框通道（导入对话框）又有路由通道（`documents/:id/settings`、`create/`、`pipeline/`），校验分支靠 `input()` 拼装；[推测] 两条通道的默认值来源（`documentProcessingDraft` vs `knowledgebase.parserConfig`）容易漂移。
5. **占位与死代码**：`connect.component.ts` 的 `#integrations`（`myRxResource`）与部分 model 被注释；`documents/pipeline/pipeline.component.ts` 留着一个注释掉的 `console.log` effect；`documents/create/create.component.ts` 的 `updateFileDocs` 是空实现；`documents/import` 的 `import-model.ts` 里 `folder`、`online` 两个源 `available: false` 但仍渲染为禁用项。
6. **测试断言与模板字符串逐字耦合**：`test.component.spec.ts`、`new.component.layout.spec.ts` 等用 `readFileSync` 锁模板片段，任何格式调整都会失败（父级 06-测试已确证同类真实失败 1 例）。
7. **检索测试的「本地保留」语义**：`linkedSignal` 刻意不跟随父级刷新，[推测] 用户可能把「页面上的参数」误读为「已保存参数」，且该状态不落库、切路由即丢。
8. **图谱画布直接接管 DOM 与观察者**：`cytoscape` 实例、`ResizeObserver`、`MutationObserver` 都在组件内自管理，销毁路径分散（`#destroyRef`、`onCleanup`、字段清理混用）；[推测] 主题切换与容器尺寸变化的回归面较大。
9. **无集成级覆盖**：摄取流水线、检索参数、真实轮询节奏没有集成测试（父级 06-测试 §7 已列为缺口），本子域 62 个 spec 多为 UI 片段与纯函数断言。

## 设计维度

1. **知识库类型维度**（决定整页能力面）：文档库 / FAQ / External / Wiki 开关 —— 影响默认路由（`getKnowledgebaseDefaultRoute`）、检索测试控件（`showDocumentTestControls` / `showRetrievalSettings` / `showContentScope`）、文档面可用性（External 重定向到 `/test`）、派生态轮询是否启动（`automaticTagging.enabled`、`graphRag.enabled`、`wikiConfig.enabled`）。
2. **数据新鲜度维度**（四档）：一次性取数（详情、列表）· 状态驱动轮询（在途文档 / 索引 / 重建）· 事件触发刷新（`published$` → 详情 `reload()`）· 用户显式刷新（`refresh()` / `reload()` / `retry*`）。
3. **权限与作用域维度**（三层）：路由级 `KNOWLEDGEBASE_EDIT` → 页面级 `canWriteWorkspace()` / `canManage(item)` / `catalog.canEdit` → 后端 service 断言（真正的边界）；可见性 `permission` 只参与列表分组，不参与判定。
4. **状态归属维度**：详情资源（后端真源）· 页面局部信号（表格选择、过滤器、检查器）· 本地偏好（`localStorage`：收藏/置顶/最近/侧栏宽度）· 任务态只读镜像（`progress/status` 只展示与驱动轮询，不本地推算）。

## 结论

- **七条链共享一条主轴**：`getDetail（详情资源）→ 子页面派生 → 写接口 → reload`；列表与统计是外壳，轮询是新鲜度补偿，`published$` 是唯一的跨域事件。
- **改动优先级**：先看 `KnowledgebaseComponent`（详情真源）与 `DocumentViewState`（轮询/刷新），再看各派生态的 `inject*` 函数，最后才动具体页面——它们决定整页请求节奏。
- **最容易回归的三类改动**：轮询常量/批次大小、检索测试请求体形状、画布复用的 provider 与 `paramId` 语义。
- **技术债集中在四处**：分散轮询与可见性门缺失、列表统计 N+1、未退订订阅、双通道表单默认值漂移；建议按「技术债与 hack」逐条排期。
- 接口清单与数据链分别见父级 `implementation/05-接口.md`（§5 知识库面）与本文同目录 `03-数据流转.md`。
