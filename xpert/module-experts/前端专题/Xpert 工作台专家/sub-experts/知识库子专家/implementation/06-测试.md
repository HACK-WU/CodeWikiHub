## spec 清单与运行命令

### 运行方式

单文件（绕 Nx 项目图，最快）：

```bash
cd /root/xpert && node node_modules/jest/bin/jest.js --config apps/cloud/jest.config.ts \
  --runTestsByPath apps/cloud/src/app/features/xpert/knowledge/knowledgebase/test/test.component.spec.ts
```

整个子域（`--runTestsByPath` 可接多个路径；或用 Nx 的路径模式）：

```bash
cd /root/xpert && node node_modules/jest/bin/jest.js --config apps/cloud/jest.config.ts \
  --runTestsByPath apps/cloud/src/app/features/xpert/knowledge/knowledgebase/wiki/wiki.component.spec.ts \
  apps/cloud/src/app/features/xpert/knowledge/tags/document-tags-refresh.spec.ts
```

```bash
cd /root/xpert && corepack pnpm nx test cloud --skip-nx-cache \
  --testPathPattern="features/xpert/knowledge" --runInBand
```

- `moduleNameMapper` 已把 `@xpert-ai/contracts` 指到源码、`environment` 指到 `environment.jest.ts`，因此**不需要先 build contracts**；`transformIgnorePatterns` 对 `@xpert-ai/chatkit-types`、`lodash-es`、`nanoid`、`marked`、`echarts`、`zrender` 做 ESM 白名单。
- 唯一前置是依赖落盘（`corepack pnpm install`，`.npmrc` 为 `node-linker=hoisted`）；本机 `node_modules` 缺失时全部 spec 在收集阶段即失败。

## 缺口

1. **列表与详情壳 0 覆盖**：`home.component.ts`（`loadKnowledgebases` / `hydrateCardStatistics` / 偏好持久化）、`home.utils.ts`（`splitKnowledgebases` 等纯函数**最该单测**）、`knowledgebase.component.ts`（默认路由重定向 effect、`apiEnabled` 直写、删除保护文案）均无 spec。
2. **文档表格主体无覆盖**：`documents.component.ts`（27.7KB）与 `document-view-state.ts`（27.6KB）只有外围（进度列、进度注入、导入对话框）被覆盖；`REFRESH_DEBOUNCE_TIME` 去抖、文件夹浏览、批量移动、原文件下载、检查器尺寸等分支无断言。
3. **画布复用链 0 覆盖**：`knowledgebase/pipeline/pipeline.component.ts`（`providers: [XpertService]` + `published$` 订阅 + `knowledgebaseComponent.refresh()`）与 `pipelines/pipelines.component.ts` 都没有 spec——本子域与 Studio 的**唯一硬契约**反而无回归网（父级 06-测试 §7 亦标注跨域契约无覆盖）。
4. **检索测试只锁模板、不锁请求**：`test.component.spec.ts` 锁的是模板片段顺序与 `@if` 分支，`test()` 的请求体（`rerankModel` 三段回退、`contentScope` 条件下发、`filters:{request}`）与 `complete → #logs.reload()` **无断言**。
5. **派生态轮询节奏无覆盖**：`timer` 周期（5000 / 2500 / 3000 / 2000ms）、`ACTIVE_POLL_MS` / `SETTLED_POLL_MS`、批次常量、可见性门只被间接触及；改变量不会触发任何失败用例。
6. **重建锁与派生态重试的端到端行为缺测**：`vectorMutationLocked` 的门控虽在 `import-dialog` / `document-dialog.service` 有零散断言，但「重建中禁止上传/删除/FAQ 操作」这一不变量没有跨组件用例。
7. **文本断言脆弱**：`new.component.layout.spec.ts`、`new.component.faq-type.spec.ts`、`test.component.spec.ts` 等 `readFileSync` 断言与模板逐字耦合（父级已确证同风格的真实失败 1 例，位于 `xpert/` 而非本子域）；建议改语义断言或快照。
8. **图谱画布与 Wiki 图谱的真实渲染路径**：`cytoscape` / `mermaid` 渲染分支在 mock 下不可达，样式与主题观察者（`ResizeObserver`、`MutationObserver`）无覆盖。

## 结论

- **可执行性：✅ 具备，但前置是依赖落盘**。`apps/cloud/jest.config.ts` 的 transform、`moduleNameMapper`（contracts 源码直连 + environment 替换）、`setupFilesAfterEach` 与 jsdom 垫片齐备，全部用例离线化（HTTP 层用 `useValue` 假服务 / `jest.mock` 空类）。
- **覆盖结构**：62 个 spec 集中在**导入/重处理**（10）、**文档进度与派生态进度**（8）、**切片与分析预览**（6）、**Wiki**（5）与 **FAQ**（4）；三类「最重的实现文件」（列表、详情壳、文档表格主体）+ 画布复用宿主反而 0 覆盖。
- **跑测试的正确姿势**：先 `node node_modules/jest/bin/jest.js --config apps/cloud/jest.config.ts --runTestsByPath <spec>` 单文件验证（最快绕开 Nx 图），再 `--testPathPattern="features/xpert/knowledge" --runInBand` 跑全子域（含 timer 的用例必须串行）。
- **改动前必读**：`import-dialog.component.spec.ts` + `pipeline-submission.spec.ts`（写路径门控）与 `document-wiki-status.spec.ts` + `document-graph-status.spec.ts`（轮询语义）——它们锁定了本子域最容易回归的两类行为；改 `REFRESH_DEBOUNCE_TIME`、批次常量或 `startParsing` 调用形态务必同步更新这四类用例。
- **优先级建议**：① 给 `home.utils.ts` / `document-view-model.ts` / `knowledgebase-route.ts` 补纯函数单测（零环境成本）；② 给 `pipeline.component.ts` 补一条「订阅 `published$` → 调 `knowledgebaseComponent.refresh()`」的注入级用例（守住与 Studio 的跨域契约）；③ 把检索测试的请求体断言补上。
