## 职责与边界

**做什么（七件事）**

1. **知识库列表页**：`KnowledgebaseHomeComponent` 拉「当前创作工作区」的知识库卡片，提供 scope 侧栏（all / favorites / recents / personal / team）、置顶与收藏、最近访问、卡片统计（文档数 / 切片数 / 文件夹数）、新建与编辑对话框入口、删除确认。
2. **知识库详情壳**：`KnowledgebaseComponent` 以 `getDetail` 为唯一数据源，承载 documents / faq / configuration / test / graph / wiki / xpert 子路由与页头动作（删除、导出流水线 DSL、打开助手、API Key、配置对话框、返回）。
3. **文档面**：上传（文件 / URL / 网页抓取 / 远程文件 / 流水线任务）、文件夹树、批量选择与移动、原始文件预览与下载、摄取进度列与阶段视图、失败重跑与重处理（rechunk）。
4. **切片面**：文档 → 切片列表 / 详情、切片问题（生成 / 重生成 / 删除）、表格元数据、分析快照预览（DOCX / 扫描件覆盖层）、切片预估预览（配置对话框内）。
5. **检索测试面**：`/api/knowledgebase/:id/test` 的输入编排与结果 / 诊断展示，外加检索日志回填。
6. **FAQ / 标签面**：FAQ 分页检索、编辑器、导入导出、启停与重处理；知识库选标 / 文档手工打标 / 自动打标配置。
7. **图谱 / Wiki 入口 + 流水线复用**：GraphRAG 画布与实体关系编辑、Wiki 阅读 / 目录 / 图谱 / 分类 / 重建，以及 `pipeline.component.ts` 复用 `XpertStudioComponent` 画布承载知识库推理流水线。

**不做什么（逐条给出「谁家」）**

### 与后端知识库专家的分工

**前端只做呈现与交互编排**，四条口径：① 后端 DTO（`IKnowledgebase` / `IKnowledgeDocument` / `KnowledgeTagCatalog` / `KnowledgeWikiStatusResponse`）→ 视图模型与本地偏好，不做领域判断；② 一切写操作统一为「调接口 → `reload()` / 重新拉取」，前端不维护权威副本（`KnowledgebaseComponent.refresh()` = `#knowledgebase.reload()`）；③ 不复制后端规则——可见性、`canEdit`、`canManage`、重处理能力等均以后端返回字段为准（如标签面直接消费 `catalog.canEdit`，切片重跑消费 `getReprocessCapabilities`）；④ 轮询与去抖只是**新鲜度补偿**，不构成一致性保证，最终口径归后端的 `status/progress` 与派生索引的最终一致语义。

## 关键不变量

1. **pipeline 复用 `XpertStudioComponent` 的接入契约（冻结）**：宿主只允许三件事——`imports: [RouterModule, XpertStudioComponent]`、`providers: [XpertService]`、`inject(KnowledgebaseComponent)`；画布自身**无 `@Input` / `@Output`**，靠 `injectParams('id')` 取 `xpertId` 并从 `XpertService` 读团队，因此「改画布构造契约（新增必填 provider、改 `paramId` 语义）」会连带影响本页；`XpertService` 是组件级 provider，页面级 `published$` 只在同一实例内可见。
2. **摄取进度 = 状态驱动轮询 + 去抖，不是推送**：表格面由 `effect` 侦测 `WAITING/RUNNING/TRANSFORMED/SPLITTED/UNDERSTOOD/EMBEDDING` 触发 `documentDelayRefresh$ → debounceTime → refresh()`；知识库级（`graphStatus === INDEXING`、`REBUILDING`）走 `knowledgebaseDelayRefresh$ → refresh()` 重取详情；创建向导第三步用 `debounceTime(5000) + getStatus(ids)` 只补在途文档；Wiki / 标签 / 图谱进度各自 `timer`（5000 / 5000 / 5000–30000ms）并按批（100 / `KNOWLEDGE_*_DOCUMENT_STATUS_BATCH_SIZE`）拉取；标签轮询额外加 `document.visibilityState === 'visible'` 门。
3. **检索测试的输入输出形状固定**：`POST /api/knowledgebase/:id/test`，请求 `{ query, k, score, rerankThreshold, rerankModel, filters:{request}, retrieval, contentScope? }`，响应 `{ documents, diagnostics }`；`contentScope` 仅在文档库且 `wikiConfig.enabled` 时下发；试跑不落库，`complete` 后仅 `reload()` 检索日志。
4. **可见性只影响列表分组，不决定可访问**：`permission` 为 `Private`（或缺失）→ personal，`Organization` / `Public` → team；`scope='all'` 不做过滤；收藏 / 置顶 / 最近是 `localStorage` 偏好（key 含 `userId + workspaceId`），不参与权限判定；管理动作另有门槛 `canManage = canWriteWorkspace() && item.workspaceId === 当前 workspaceId`；真正的授权边界在后端 service 断言。
5. **详情壳是唯一数据源**：子页面一律 `inject(KnowledgebaseComponent)` 读 `knowledgebase()`；`getDetail` 失败 → `toastr.danger` + 回 `/xpert/w`；写操作完成 → `refresh()`（`reload()`）→ 全页面同步；列表页卡片统计是**额外补全**（`getDetail` + 两次 `getAll({select:['id']})`），不改变详情口径。
6. **类型分流与默认落点**：`getKnowledgebaseDefaultRoute` 依类型给出 `faq` / `documents` / 根；未启用 Wiki 访问 `/wiki` 由 `knowledgebaseWikiGuard` 重定向并**保留 queryParams**；`External` 类型在文档面 `effect` 重定向到 `../test`。
7. **重建锁（REBUILDING）会阻断写操作**：上传入口（`uploadIntoFolder`、`DocumentImportDialogService` 打开前重新 `getDetail` 再判）、文档行内动作、FAQ 操作均以 `vectorMutationLocked` / `status === REBUILDING` 早退；配置页 `save()` 同样拒绝。

## 结论

- **职责一句话**：本子域 = 知识库的「列表 → 详情 → 文档/切片 → 检索测试 → FAQ/标签 → 图谱/Wiki → 流水线宿主」八段前端面，后端只提供 DTO 与任务态，前端负责编排与新鲜度补偿。
- **最脆的三处契约**：① `pipeline.component.ts` 的画布复用接入（`providers: [XpertService]` + 无输入输出 + `published$`）；② 轮询去抖常量与批次大小（改动即改变请求量与「多久看到进度」的观感）；③ 检索测试的请求/响应形状（与后端 `POST /:id/test` 逐字对应）。
- **单一真源**：详情页一切数据来自 `getDetail` 资源，`refresh()` 是唯一同步手段；列表页的卡片统计与本地偏好都是**附加层**，不得反向成为权限或一致性依据。
- **边界清晰**：可见性只做分组、写操作受重建锁约束、真正的授权在后端断言——这三点决定了本域「出问题先看后端状态与 DTO 字段，再看前端编排」的排障顺序。
- 实现细节、热点路径、关键类清单与技术债见同目录 `implementation/02-实现.md`；数据链与测试口径见 `03-数据流转.md`、`06-测试.md`。
