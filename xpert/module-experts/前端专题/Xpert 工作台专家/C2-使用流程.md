## R1 打开助手管理页并编辑保存
- **业务目标**：作者打开 `/xpert/x/:id` 能看到助手（有草稿时看到草稿形态），改基础信息并保存后表单进入干净态、页面显示最新草稿。
- **调用顺序**：`xpert/routes.ts` 的 `path: ':id'` → `XpertComponent`（`providers: [XpertService]`）→ `XpertService` 构造：`#paramId = injectParams('id')` → `paramId`（`linkedModel`，`compute: () => this.#paramId()`）→ `paramId$ = toObservable(paramId)` → `distinctUntilChanged → filter(nonBlank) → switchMap(#refresh$ → getXpertTeam(id))`（9 项 relations）→ 回调 `latestXpert.set(value)` + `xpert.set(value.draft?.team ?? value)`。编辑：`XpertBasicManageComponent.openBasic()` 打开 `XpertBasicComponent` → `saveDraft()`：Agent 分支 `xpertAPI.upadteDraft(id, { team: …, options, … } as TXpertTeamDraft)`（`PUT /api/xpert/:id/draft`）；其它类型分支 `xpertAPI.update(id, { …basicValue, options })`（`PUT /api/xpert/:id`）→ 成功后 `toastr.success` + `markAsPristine()` + `xpertService.refresh()` + `close()`。
- **时序边界**：`#refresh$` 是 `BehaviorSubject`，`switchMap` 保证 id 变化时取消上一次在途请求；`latestXpert` 恒为服务端完整返回（含 `draft`/`graph`/`version`），`xpert` 为「草稿优先」投影——Agent 的编辑面是草稿层，其它类型编辑已发布层（`team = type === Agent ? draft()?.team : xpert()`）；前端不改本地缓存，写后一律 `refresh()` 重取（无自动失效）。
- **预期结果**：表单初值来自 `xpert()`（Agent = `draft?.team`，无草稿时 `{ team: omitXpertRelations(xpert()) }`）；保存成功对话框关闭、`XP.Messages.SavedDraft`/`UpdatedSuccessfully` 提示；`latestXpert().version`（发布态）不变。
- **错误处理**：`XpertService` 订阅**无 error 回调**，`getTeam` 4xx/5xx 时 `latestXpert/xpert` 保持 `null`（页面空态）且错误上抛控制台；保存失败 `toastr.error(getErrorMessage(err))` 并复位 `loading`，表单保持脏态（`IsDirty` 阻止误关闭）。
- **真实代码示例**：
```ts
// xpert.service.ts —— 草稿优先投影与刷新链
private xpertSub = this.paramId$
  .pipe(
    distinctUntilChanged(),
    filter(nonBlank),
    switchMap((id) => this.#refresh$.pipe(switchMap(() => this.getXpertTeam(id))))
  )
  .subscribe((value) => {
    this.latestXpert.set(value)
    this.xpert.set(value.draft?.team ?? value)
  })
// basic.component.ts —— 编辑面按类型选层；保存成功后 refresh + close
readonly draft = computed<Partial<TXpertTeamDraft> | null>(() => {
  if (this.xpert()) { return this.xpert().draft ?? { team: omitXpertRelations(this.xpert()) } }
  return null
})
readonly team = computed(() => (this.type() === XpertTypeEnum.Agent ? this.draft()?.team : this.xpert()))
// saveDraft().subscribe({ next: (value) => { … this.xpertService.refresh(); this.close() } })
```

## R2 发布助手并让 Studio 与流水线同步
- **业务目标**：在 Studio 内发布助手后，明确「谁会被自动刷新、谁不会」——知识库流水线页即时重取，其它列表页需手动或重进。
- **调用顺序**：Studio 发布对话框 `XpertPublishVersionComponent.publish()` → 先判 `studioService.unsaved() ? saveDraft() : of(true)` 落盘 → `xpertAPI.publish(id, newVersion, { environmentId, releaseNotes, businessAreaId, marketplace? })`（`POST /api/xpert/:id/publish`）→ 成功后 `studioService.refresh()` → **`xpertService.published$.next(result)`**；本域订阅方 `KnowledgebasePipelineComponent` 构造期订阅 → `next: () => this.knowledgebaseComponent.refresh()` → `KnowledgebaseComponent.refresh()` = `#knowledgebase.reload()`。
- **时序边界**：`published$` 是内存 `Subject<IXpert>`：不跨标签页、不重放（晚订阅者收不到历史发布）；`XpertService` 为组件级 provider（`XpertComponent` / `XpertStudioComponent` / `KnowledgebasePipelineComponent` 各持一份），发布方与订阅方必须落在同一 provider 作用域才送达；全仓仅「Studio 发布组件 emit、知识库流水线 subscribe」这一对（代码实测）。
- **预期结果**：在流水线页内发布 → 知识库详情立即重取；工作区助手列表（`myRxResource`/`derivedAsync`）与工具集页**不订阅**该事件，发布后不自动刷新。
- **错误处理**：publish 400（`XpertBusinessAreaInvalid`）/403 → `toastr.error(getErrorMessage(error))` 且不广播；作用域错配时静默失效（无报错）；跨标签页同步当前不支持（07-运维处置：刷新页面或切路由触发 `XpertService.refresh()`）。
- **真实代码示例**：
```ts
// pipeline.component.ts —— 本域唯一订阅方（复用画布 + 订阅发布广播）
@Component({ imports: [RouterModule, XpertStudioComponent], providers: [XpertService] })
export class KnowledgebasePipelineComponent {
  readonly knowledgebaseComponent = inject(KnowledgebaseComponent)
  readonly xpertService = inject(XpertService)
  private publishedSub = this.xpertService.published$.subscribe({
    next: (pipeline) => { this.knowledgebaseComponent.refresh() }
  })
}
// xpert.service.ts —— 广播载体本身（无重放、不跨页）
readonly published$ = new Subject<IXpert>()
```
章节来源：[pipeline.component.ts](file://apps/cloud/src/app/features/xpert/knowledge/knowledgebase/pipeline/pipeline.component.ts)（关键符号：`KnowledgebasePipelineComponent.publishedSub`）、[xpert.service.ts（本域）](file://apps/cloud/src/app/features/xpert/xpert/xpert.service.ts)（关键符号：`XpertService.published$`）、[publish.component.ts（Studio）](file://apps/cloud/src/app/features/xpert/studio/header/publish/publish.component.ts)（关键符号：`XpertPublishVersionComponent.publish`）、[02-实现.md](file://.module-experts/前端专题/Xpert 工作台专家/implementation/02-实现.md)（关键符号：`published$ 发布广播与订阅方`）

## R3 配置一个工具集并跑工具测试
- **业务目标**：打开一个工具集详情（`/xpert/tool/:id`），改配置/工具清单/凭据并保存，再跑一次工具调用测试，看到结果或结构化错误。
- **调用顺序**：`XpertStudioAPIToolComponent`：`toObservable(injectParams('id')) → distinctUntilChanged → switchMap(getById(id, { relations: ['tools','createdBy'] }))` 写入 `toolset` model；编辑器 `configure = viewChild('configure', { read: XpertConfigureToolComponent })`（openapi/odata/mcp 三族均 `extends XpertConfigureToolComponent`，统一 `formGroup/isValid()/isDirty()/refreshForm()`）；保存 `saveToolset()`：`configure().formGroup.value`（`schema` 回落已加载值）+ **仅当 `toolsDirty()` 时**带 `tools`（否则 `omit(value, 'tools')`）；工具级改写 `onToolsChange`（按 `name` 合并、缺失者标 `deletedAt`）；凭据面独立：`/:id/credentials`、`builtin-provider/:provider/credentials-schema`（`XpertToolBuiltinAuthorizeComponent` 绑定 / `XpertToolBuiltinCredentialComponent` 凭据表单）；测试：`XpertToolTestDialogComponent`（`DIALOG_DATA { tool, enableAuthorization }`，把 toolset 重写为 `{ ...toolset, credentials, tools: null }`）→ `XpertToolsetToolTestComponent.testTool()` → `toolService.test({ ...tool, toolset, parameters })`（`POST /api/xpert-tool/test`，`responseType: 'text'`）。
- **时序边界**：`toolsDirty` 是「本轮是否改过工具清单」的闸门，未改则不回写 `tools`（避免覆盖服务端列表）；`testResult`、`toolsDirty`、`selectedToolIds` 均为前端 signal，路由切换即丢；`isValid()` 守卫通过才应提交。
- **预期结果**：save 成功后 `XP.Messages.UpdatedSuccessfully` + `markAsPristine()` + `refreshForm()`；测试结果字符串化渲染（`JSON.stringify(result, null, 2)`），失败时错误文本同时进 toastr 与结果区。
- **错误处理**：详情加载失败 `toastr.error(getErrorMessage(error))`；测试失败由 `normalizeToolTestError`（`@core`）把 JSON 字符串 body 还原为结构化错误；`stopTestTool()` 可中断测试订阅。
- **真实代码示例**：
```ts
// api-tool.component.ts —— 保存时只有 dirty 才回写 tools
if (this.toolsDirty()) { value.tools = this.toolset().tools.filter((_) => !_.deletedAt) }
else { value = omit(value, 'tools') }
this.toolsetService.update(this.toolset().id, value).subscribe({ next: () => { … this.toolsDirty.set(false) } })
// tool-test/test/tool.component.ts —— 测试链与结果回显
this.#testSubscription = request$.subscribe({
  next: (result) => { … this.testResult.set(typeof result === 'string' ? result : JSON.stringify(result, null, 2)) },
  error: (error) => { const message = getErrorMessage(error); this.#toastr.error(message); this.testResult.set(message) }
})
```

## R4 挂载知识库并跑流水线
- **业务目标**：把知识库挂到助手上，并在知识库的「流水线」页用 Studio 画布编排流水线、发布后让本页自动刷新。
- **调用顺序**：助手侧——`IXpert.knowledgebase` 由 `injectGetXpertTeam` 的 `knowledgebase` relation 投影（9 项之一，注意是单数），画布上呈现为 `knowledge` 节点（`TXpertTeamNodeSpec.knowledge`）；知识库侧——`/xpert/knowledges`（权限 `AIPermissionsEnum.KNOWLEDGEBASE_EDIT`）→ `:id` 惰性加载 `knowledgebase/routing.ts` → `xpert/:id → KnowledgebasePipelineComponent`（`imports: [XpertStudioComponent]` + `providers: [XpertService]` + `inject(KnowledgebaseComponent)`）→ 订阅 `published$` → `refresh()`。反向入口：知识库详情页 `openXpert(xpert)` 以 `window.open('/xpert/x/:id/agents')` 跳回助手管理页（跨链回到 R1）。
- **时序边界**：复用的画布**无 `@Input`/`@Output`**，只靠 `injectParams('id')` 与 `XpertService` 契约工作；该页出现 Studio 工具栏属设计预期；`paramId` 语义在 `/xpert/knowledges/:kbId/xpert/:xpertId` 下变为 xpertId（改路由层级会静默失效）。
- **预期结果**：流水线可编排并发布；发布后本页 `published$` 触发 `knowledgebaseComponent.refresh()`（见 R2）；助手侧能看到知识库挂载（管理页展示与画布节点同源）。
- **错误处理**：`XpertService` 必须由复用方 `providers` 提供（缺 provider 即注入失败）；`filter(nonBlank)` 组合下缺路由参数**静默不加载**；知识库内部资源（文档/切片/FAQ/wiki/图）的错误语义归知识库子专家。
- **真实代码示例**：
```ts
// pipeline.component.ts —— 复用画布的装配面
imports: [RouterModule, XpertStudioComponent]
providers: [XpertService]
readonly knowledgebaseComponent = inject(KnowledgebaseComponent)
// knowledgebase.component.ts —— 刷新钩子与反向跳转
refresh() { this.#knowledgebase.reload() }
openXpert(xpert: IXpert) { window.open(['/xpert/x', xpert.id, 'agents'].join('/'), '_blank') }
```

## R5 在工作区里创建并打开助手
- **业务目标**：从 `/xpert/w/*` 落位到目标工作区，创建新助手，并按类型被送到正确的控制台；助手壳携带工作区/助手上下文。
- **调用顺序**：`/xpert/w` → `redirectToSelectedWorkspace` 取 `AppQuery.selectedWorkspace?.id ?? PersistQuery.workspaceId`，把 `?section=` 映射为 `clawxpert-skills | clawxpert-knowledges | clawxpert-connectors | files | settings`；`/xpert/w/:id` → `XpertWorkspaceHomeComponent`；`xperts` 子页用 `myRxResource` 拉 `getAllByWorkspace(workspaceId, { where: { type: Agent, latest: true }, relations: ['createdBy','tags','knowledgebase'], order: updatedAt DESC })`；创建 `newBlank()`（`canWriteWorkspace()` 门禁 → `XpertNewBlankComponent` 对话框 `width: '1360px'`、`completionMode: 'create'`）→ `closed` 回调 `openXpert(result.xpert)` → 三分支导航（Knowledge → `/xpert/knowledges/:kbId/xpert/:id`；Copilot → `/xpert/x/:id/copilot`；其它 → `/xpert/x/:id/agents`）。
- **时序边界**：工作区列表**不订阅** `published$`（`refresh()` 手动重取）；`prompt-workflows` 离开前 `canDeactivate` 确认；`/xpert/w/:id/settings` 段重定向 `/chat/clawxpert`（当前源码）；助手壳门面从 `router.url` 正则解析 `^/xpert/w/([^/]+)` 与 `^/xpert/x/([^/]+)/agents`，把 `env.workspaceId`/`env.xpertId` 注入 `requestContext`。
- **预期结果**：无 `:id` 的 `/xpert/w` 被改写为选中工作区 URL；新助手创建后直达对应控制台；共享助手（pet）在整个 `/xpert/**` 常驻并带上工作区/助手上下文。
- **错误处理**：`canWriteWorkspace()` 为假时创建/删除/导入直接 `return`（无提示）；工作区 id 缺失时 `redirectToSelectedWorkspace` 放行、由壳组件空态处理；删除失败 `toastr.error`。
- **真实代码示例**：
```ts
// workspace/xperts.component.ts —— 创建后按类型分流
newBlank() { … .closed.subscribe((result) => { if (result?.xpert?.id) { this.openXpert(result.xpert) } }) }
private openXpert(xpert: IXpert) {
  if (xpert.type === XpertTypeEnum.Knowledge && xpert.knowledgebase?.id) {
    this.router.navigate(['/xpert/knowledges', xpert.knowledgebase.id, 'xpert', xpert.id]); return }
  if (xpert.type === XpertTypeEnum.Copilot) { this.router.navigate(['/xpert/x/', xpert.id, 'copilot']); return }
  this.router.navigate(['/xpert/x/', xpert.id, 'agents']) }
// workspace/routes.ts —— 默认工作区回落
const workspaceId = appQuery.getValue().selectedWorkspace?.id ?? persistQuery.getValue().workspaceId
return workspaceId ? router.createUrlTree(target) : true
```

## R6 DSL 导入助手
- **业务目标**：把一个 YAML DSL 文件导入为「覆盖当前助手草稿」的改动（图纸 + 记忆），发布态不受影响，生效仍需发布。
- **调用顺序**：manage `importDsl()` → `selectDslFile()` → `uploadYamlFile<TImportedXpertDsl>(file)` → 若 `importedDsl.team.features?.sandbox?.enabled` 则 `getSandboxProviders()` → `createOverwriteDraftFromDsl(xpert, importedDsl, sandboxProviders)` + `groupImportedDslMemories(importedDsl.memories)` → `toastr.confirm`（文案明示「覆盖草稿、发布态不变；含记忆则清空替换」）→ `saveDraft(id, overwriteDraft)`（`POST /api/xpert/:id/draft`）→ 有记忆则 `clearMemory` + 按类型 `bulkCreateMemories` → `xpertComponent.xpertService.refresh()` → 提示发布后生效。
- **时序边界**：两个写点（草稿、记忆）**非事务**：`draftSaved` 标志只用于区分记忆阶段失败；导入会先清空现有记忆再写新记忆；另一条路径——工作区 `importDSL()` 走 `XpertBasicDialogComponent` 收集基础信息后 `XpertAPIService.importDSL(dsl, { workspaceDataScope })`（`POST /api/xpert/import`），成功跳 `/xpert/x/:id`。
- **预期结果**：`refresh()` 后 `xpert()`（草稿优先）显示 DSL 图纸；`latestXpert().version` 不变；提示「发布后才生效」。
- **错误处理**：解析/装配异常 → `toastr.error`（附 `translateImportError`）；记忆替换失败 → warning `XP.Xpert.ImportMemoryIncomplete`，留下「草稿已换、记忆半成品」中间态；`saveDraft` 400/409 直接 error。
- **真实代码示例**：
```ts
// manage.component.ts —— 覆盖草稿 + 记忆替换 + refresh
importedDsl = await uploadYamlFile<TImportedXpertDsl>(file)
const sandboxProviders = importedDsl.team.features?.sandbox?.enabled
  ? await firstValueFrom(this.#xpertService.getSandboxProviders()) : []
overwriteDraft = createOverwriteDraftFromDsl(xpert, importedDsl, sandboxProviders)
groupedMemories = groupImportedDslMemories(importedDsl.memories)
await firstValueFrom(this.#xpertService.saveDraft(xpert.id, overwriteDraft))
if (groupedMemories) { await firstValueFrom(this.#xpertService.clearMemory(xpert.id))
  for (const [type, memories] of Object.entries(groupedMemories)) { … bulkCreateMemories(xpert.id, { type, memories }) } }
this.xpertComponent.xpertService.refresh()
```

## R7 处理与 Studio 的跨域
- **业务目标**：本域以「供给方 + 宿主」身份支撑 Studio 三条桥——可编辑草稿的源头、可选注入的助手门面、可被复用的画布。
- **调用顺序（三条桥）**：
  ① **draft 源头**：Studio `XpertStudioApiService` 从 `../../draft/index` 引入 `buildEditableXpertDraft` 与 `deriveChatTriggerInputParametersFromDraft`；装配器以 `omit(xpert,'agents')` 为基底，草稿存在时覆盖 `team/nodes/connections`，`nodes` 三级回落（`draft.nodes → graph.nodes → ToNodeViewModelHandler`）并统一 `normalizeMiddlewareNodes`，末尾 `applyChatTriggerInputParametersToDraft`。
  ② **门面可选注入**：`XpertAssistantShellComponent`（`/xpert/**` 根壳）`providers: [XpertAssistantFacade]`；Studio `inject(XpertAssistantFacade, { optional: true })`，构造期三个 `effect`：把 `paramId` 写回 `xpertService.paramId`；当 `assistantFacade.xpertId() === 当前 id` 时 `setStudioContext({ targetXpertId, baseDraftHash: calculateHash(JSON.stringify(pristineDraft)), unsaved })`，否则 `clearStudioContext()`；监听 `studioRefresh()` 的 nonce → `apiService.refresh()`。
  ③ **画布复用**：pipeline 组件 `imports: [XpertStudioComponent] + providers: [XpertService]` + 订阅 `published$`（见 R4）。
- **时序边界**：`setStudioContext` 三字段全等则不动（幂等）；Studio 销毁时 `#destroyRef.onDestroy → clearStudioContext() + subscriptions$.unsubscribe()`；`optional` 注入缺失时**不报错**（静默降级）；`utils.ts` 的 `injectGetXpertTeam`（9 relations）与 `XpertService` 三信号是双方共享层，改签名=跨域回归。
- **预期结果**：在 `/xpert/x/:id/agents` 内打开 Studio 时，助手请求带上 `targetXpertId/unsaved/baseDraftHash`；助手侧 `emitStudioRefresh(id)`（`nonce: Date.now()` 保证同值也触发）能让 Studio 重取；流水线页无感获得完整画布。
- **错误处理**：`buildEditableXpertDraft` 输出结构变化会同时破坏画布初始化与管理页投影；`XpertAssistantFacade` 改签名让 Studio 静默降级（可选注入不抛错）；画布新增必填 provider 会连带影响流水线——三处改动必须同时回归 Studio（见 ki 关联登记的`改动风险`）。
- **真实代码示例**：
```ts
// studio.component.ts —— 可选注入 + 上下文同步 + 刷新事件
readonly #assistantFacade = inject(XpertAssistantFacade, { optional: true })
effect(() => {
  if (this.paramId()) { this.xpertService.paramId.set(this.paramId()) } })
effect(() => {
  const assistantRouteXpertId = this.#assistantFacade.xpertId()
  if (!currentXpertId || assistantRouteXpertId !== currentXpertId) { this.#assistantFacade.clearStudioContext(); return }
  this.#assistantFacade.setStudioContext({
    targetXpertId: currentXpertId,
    baseDraftHash: pristineDraft ? calculateHash(JSON.stringify(pristineDraft)) : null,
    unsaved: this.apiService.unsaved() }) })
// assistant.facade.ts —— 三字段幂等写入
setStudioContext(context: AssistantStudioRuntimeContext | null) {
  if (!context?.targetXpertId) { this.clearStudioContext(); return }
  const current = this.#studioRuntimeContext()
  if (current?.targetXpertId === context.targetXpertId && current?.baseDraftHash === context.baseDraftHash &&
      current?.unsaved === context.unsaved) { return }
  this.#studioRuntimeContext.set(context) }
```

## R8 排障：四类高频故障
- **业务目标**：把「助手加载不出 / 发布不生效 / 工具测试失败 / spec 依赖缺失」按现象收敛到具体通道与代码位点。
- **调用顺序（排查路径）**：

| # | 现象 | 判断与排查点 | 处置 |
| --- | --- | --- | --- |
| 1 | 助手加载不出（侧栏无名称、面板空态） | `GET /api/xpert/:id/team` 的 401/403/404；`data=` 查询串（9 relations）是否完整；`latestXpert()/xpert()` 是否为 `null`；注意订阅**无 error 回调**，失败不弹提示 | 修正路由 `id`；确认助手归属/工作区可见性（后端 `XpertGuard`）；看控制台与网络面板 |
| 2 | 发布不生效（列表/知识库不刷新） | `published$` 是**内存事件、不跨标签页**；生产方是 Studio 发布对话框、消费方仅知识库流水线；两者须同一 `XpertService` provider 作用域 | 刷新页面或切路由触发 `refresh()`；跨标签页同步当前不支持 |
| 3 | 工具测试失败 | `POST /api/xpert-tool/test`（`responseType:'text'`）；`normalizeToolTestError` 是否把 JSON 字符串 body 还原；工具集凭据是否已授权（`/:id/credentials`） | 先补授权再重试；错误文本会同时进 toastr 与结果区 |
| 4 | spec 大面积失败（`Cannot find module`） | `/root/xpert/node_modules` 是否存在（当前不存在）；`jest.mock('@milkdown/crepe'…)` 未带 `{ virtual: true }` 的 spec 在加载阶段即失败 | `corepack pnpm install` 后按 06-测试复跑并重新标定失败清单 |

- **时序边界**：排障前先判定「哪条通道/哪个 provider 作用域」——`GET team`（数据面）、`published$`（内存事件）、`/api/xpert-tool/test`（文本响应）、Jest 模块解析（环境面）；同一现象在不同通道下根因不同。
- **预期结果**：能落到具体文件/符号（`XpertService.xpertSub`、`publishedSub`、`normalizeToolTestError`、`proxy.conf.cjs` 代理链），不停留在「网络问题」。
- **错误处理**：失败静默的三处需牢记——① `xpertSub` 无 error 回调；② 可选注入门面缺失不报错；③ `published$` 晚订阅错过事件；另：环境级缺依赖时 `nx build cloud` 直接失败（Angular builder 解析 `node_modules` 资产）。
- **真实代码示例**：
```ts
// xpert.service.ts —— 加载失败是静默的（无 error 回调；filter 掉空参数）
private xpertSub = this.paramId$.pipe(
  distinctUntilChanged(),
  filter(nonBlank),   // 参数缺失 => 静默不加载；4xx/5xx => 信号保持 null
  switchMap((id) => this.#refresh$.pipe(switchMap(() => this.getXpertTeam(id))))
).subscribe((value) => { this.latestXpert.set(value); this.xpert.set(value.draft?.team ?? value) })
```
