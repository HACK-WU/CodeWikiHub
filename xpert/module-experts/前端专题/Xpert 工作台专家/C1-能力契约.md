## 1. 前端契约

### 1.1 `XpertService`：投影、刷新与发布广播

定义位置：`features/xpert/xpert/xpert.service.ts`（`@Injectable()`，**非 root**）。消费方必须由宿主提供实例：`XpertComponent`、`XpertStudioComponent`、`KnowledgebasePipelineComponent` 各自 `providers: [XpertService]`。

| 成员 | 类型 | 语义与约束 |
|---|---|---|
| `paramId` | `WritableSignal<string \| null>`（`linkedModel`） | 由 `injectParams('id')` 计算，`update` 原样返回——Studio 会反向写回以复用画布；**不是**本地状态真源 |
| `paramId$` | `Observable<string>` | `toObservable(paramId)`；链 `distinctUntilChanged → filter(nonBlank) → switchMap(#refresh$ → getXpertTeam(id))`，参数为空时**静默不加载** |
| `getXpertTeam` | `(id: string) => Observable<IXpert>` | `injectGetXpertTeam()`，固定 9 项 relations |
| `latestXpert` | `Signal<IXpert>` | 服务端完整返回（含 `draft`/`graph`/`version`）；读「已发布态字段」只认它 |
| `xpert` | `Signal<Partial<IXpert>>` | `value.draft?.team ?? value`——**草稿优先投影**，只做一层回落、不深合并 |
| `published$` | `Subject<IXpert>` | 发布广播；同 provider 实例内可见、不重放、不跨标签页 |
| `refresh()` / `onRefresh()` | `void` / `Observable<void>` | 触发 / 暴露 `#refresh$`（`BehaviorSubject`）；写操作后必须显式调用 |

消费约定：① 判「是否有草稿」用 `latestXpert()?.draft`，判「当前编辑形态」用 `xpert()`；② 编辑器与 switcher 读 `xpert()`，需要 `versions`/导出模板等已发布字段再读 `latestXpert()`；③ 无自动失效订阅，任何写路径（对话框、DSL 导入、模板同步）以 `refresh()` 收尾；④ 订阅 `published$` 必须与发布方处于**同一 provider 作用域**。

章节来源：[xpert.service.ts](file://apps/cloud/src/app/features/xpert/xpert/xpert.service.ts)（关键符号：`XpertService.paramId`、`XpertService.latestXpert`、`XpertService.xpert`、`XpertService.published$`、`XpertService.refresh`）

### 1.2 `utils.ts`：注入工厂与 key 生成器

- `injectGetXpertTeam()`：`inject(XpertAPIService)` 后返回 `(id) => getTeam(id, { relations })`，relations 为**冻结常量 9 项**：`agent`、`agent.copilotModel`、`agents`、`agents.copilotModel`、`executors`、`executors.agent`、`executors.copilotModel`、`copilotModel`、`knowledgebase`。本域、Studio、`XpertAssistantFacade` 共用同一口径。
- `injectGetXpertsByWorkspace()`：返回 `(workspace) => getAllByWorkspace(workspace, { where: { latest: true }, order: { updatedAt: DESC } }, true)`——**第三个实参 `published = true`**（协作者/切换器候选口径）。
- `genAgentKey()`：`letterStartSUID('Agent_')`；同族生成器覆盖各节点类型前缀；`genWorkflowKey(type)` 对 `WorkflowNodeTypeEnum.IF_ELSE` 特判返回 `genXpertRouterKey()`，其余 `type ? letterStartSUID(upperFirst(type) + '_') : null`；`genXpertAgentToolKey` 标注 `@deprecated`。**去重由调用方负责**。
- 同文件还导出 ChatKit effect 的类型与白名单式解析器（`getChatKitEffectData` / `getChatKitEffectXpertId` / `getChatKitPromptWorkflowEffect` / `getChatKitWorkspaceSkillEffect`），供 `XpertAssistantFacade` 使用。

章节来源：[utils.ts](file://apps/cloud/src/app/features/xpert/utils.ts)（关键符号：`injectGetXpertTeam`、`injectGetXpertsByWorkspace`、`genAgentKey`、`genWorkflowKey`、`genXpertAgentToolKey`）

### 1.3 `buildEditableXpertDraft`：输入输出语义

签名 `buildEditableXpertDraft(xpert: IXpert): TXpertTeamDraft`（定义在 `draft/editable-draft.util.ts`，并从 `draft/index.ts` 统一出口导出）。它是 **Studio draft 的唯一源头**：

- **输入**：`IXpert`（完整实体，含可选 `draft` 与 `graph`）。**输出**：`TXpertTeamDraft` = `{ team, nodes, connections }`，整体经 `applyChatTriggerInputParametersToDraft` 包裹（会把 chat 触发器参数投影进 `team.agentConfig.parameters`）。
- **team**：`baseTeam = { ...omit(xpert, 'agents'), id: xpert.id }`；有草稿时叠加 `draft.team`，`id` 回落 `draft.team?.id ?? xpert.id`。
- **nodes 三级回落**：`draft.nodes → xpert.graph?.nodes → new ToNodeViewModelHandler(xpert).handle().nodes`，且**必经** `normalizeMiddlewareNodes`。
- **connections 二级回落**：`draft.connections → xpert.graph?.connections → new ToConnectionViewModelHandler(xpert).handle()`。
- **消费方**：Studio `XpertStudioApiService`、`@core/services/xpert-settings-context.service.ts`、设置域 `assistant-triggers.component.ts`（读写触发器草稿）、本域知识库流水线（间接）。同族函数 `readTriggerEditorItemsFromDraft` / `upsertTriggerEditorItemsIntoDraft` 在缺主 Agent 节点时抛 `XPERT_DRAFT_PRIMARY_AGENT_NODE_MISSING`。

章节来源：[editable-draft.util.ts](file://apps/cloud/src/app/features/xpert/draft/editable-draft.util.ts)（关键符号：`buildEditableXpertDraft`）· [xpert-draft-trigger.util.ts](file://apps/cloud/src/app/features/xpert/draft/xpert-draft-trigger.util.ts)（关键符号：`applyChatTriggerInputParametersToDraft`、`upsertTriggerEditorItemsIntoDraft`、`XPERT_DRAFT_PRIMARY_AGENT_NODE_MISSING`）

由 `XpertAssistantShellComponent` 在 `providers` 提供（全 `/xpert/**` **共享一个实例**）。Studio 侧以 `inject(XpertAssistantFacade, { optional: true })` 消费，**缺失时静默降级**（Studio 仍可用，但上下文与刷新通道消失）。

| 身份 | `assistantCode` / `runtime` / `assistantId` / `control` / `status` | `assistantCode = AssistantCode.XPERT_SHARED`；运行时来自 `injectAssistantChatkitRuntime({ displayMode: 'pet', … })` |

③ **用注入工厂取 team（9 项 relations 为冻结契约）**：

```ts
// utils.ts（原样摘录）：工厂内部固定 relations，调用方无法传入
export function injectGetXpertTeam() {
  const xpertService = inject(XpertAPIService)
  return (id: string) => xpertService.getTeam(id, {
    relations: ['agent', 'agent.copilotModel', 'agents', 'agents.copilotModel',
      'executors', 'executors.agent', 'executors.copilotModel', 'copilotModel', 'knowledgebase']
  })
}

// xpert/xpert/xpert.service.ts：以 refresh$ 驱动重取
readonly getXpertTeam = injectGetXpertTeam()
switchMap((id) => this.#refresh$.pipe(switchMap(() => this.getXpertTeam(id))))
```

④ **以 `buildEditableXpertDraft` 装配草稿供 Studio 使用**：

```ts
// draft/editable-draft.util.ts（剪裁，回退序即契约）
export function buildEditableXpertDraft(xpert: IXpert): TXpertTeamDraft {
  const baseTeam = { ...omit(xpert, 'agents'), id: xpert.id }
  if (xpert.draft) {
    return applyChatTriggerInputParametersToDraft({
      team: { ...baseTeam, ...(xpert.draft.team ?? {}), id: xpert.draft.team?.id ?? xpert.id },
      nodes: normalizeMiddlewareNodes(xpert.draft.nodes ?? xpert.graph?.nodes ?? new ToNodeViewModelHandler(xpert).handle().nodes),
      connections: xpert.draft.connections ?? xpert.graph?.connections ?? new ToConnectionViewModelHandler(xpert).handle()
    })
  }
  return applyChatTriggerInputParametersToDraft({ team: baseTeam, /* graph 回落同上（少一层 draft） */ } as TXpertTeamDraft)
}

// studio/domain/xpert-api.service.ts（消费方，Studio 域）：buildEditableXpertDraft(this.team())
```
