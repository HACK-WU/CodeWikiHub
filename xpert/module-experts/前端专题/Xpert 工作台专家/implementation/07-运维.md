## 3. 环境变量与 API base / 代理

- **开发代理**（`apps/cloud/proxy.conf.cjs`）：`/api` 与 `/artifacts/share` 转发到 `resolveProxyTarget()`；目标解析顺序 `VITE_API_BASE_URL` →（`same-origin`/`self`/`/` 视为同源）→ `API_BASE_URL` → 默认 `http://127.0.0.1:3000`，并把 `localhost` 归一为 `127.0.0.1`、剥掉尾部 `/api`。
- **构建期/运行期 base**：`environment.API_BASE_URL`（`environment.jest.ts` 为 `http://localhost:3000`）经 `normalizeApiBaseUrl` 处理：空值、`DOCKER_*`、`same-origin|self|/` → 返回空串（同源相对请求）；支持 `{tenant}` 占位符按主机名解析多租户域名。
- **本域相关变量**：`API_BASE_URL`（后端地址，SSE 场景 `XpertAPIService.chat` 会拼 `baseUrl + apiBaseUrl`）、`CHATKIT_FRAME_URL`（助手 iframe）、`CODE_XPERT_URL`/`DATA_ONTOLOGY_URL`（外链工具）、`mcpOAuthEnabled`、`MCP_APP_SANDBOX_PROXY_URL`、`MCP_APP_SANDBOX_ALLOWED_DOMAINS`；以上均为 `IEnvironment` 字段，模块内不直接 `process.env`。
- **请求头/令牌**：普通 HTTP 由 Angular `HttpClient` 拦截器链注入；SSE 通道另在 `fetch-event-source` 内附 `Authorization`、`Language`、`X-Scope-Level`、`Organization-Id` 并在 401 时刷新令牌重试一次。

章节来源：[proxy.conf.cjs](file://apps/cloud/proxy.conf.cjs)（关键符号：`resolveProxyTarget`、`module.exports`）、[environment.jest.ts](file://apps/cloud/src/environments/environment.jest.ts)（关键符号：`environment.API_BASE_URL`、`IEnvironment`）、[url.ts](file://apps/cloud/src/app/@core/providers/url.ts)（关键符号：`normalizeApiBaseUrl`、`resolveTenantApiBaseUrl`）

## 4. 前端依赖落盘状态

- **现状**：本机 `/root/xpert/node_modules` **不存在**（访问报 `ENOENT`），即前端依赖整体未落盘；`apps/cloud/package.json` 中声明的 `@milkdown/crepe`（`^7.22.1`）等同样缺席。
- **对 spec 的影响**：凡 `jest.mock('@milkdown/crepe'|'mermaid'|'@xterm/xterm', …)` **未带 `{ virtual: true }`** 的 spec，Jest 注册 mock 时仍需真实解析模块 → 套件在加载阶段即失败（本域 `@milkdown/crepe` 直接命中 12 个 spec：`knowledge` 10 + `workspace/prompt-workflows` 2）。这也是归档 55 个失败里 53 个「环境级缺依赖」的主要成因（明细见 06-测试 §5）。
- **修复方式**（按推荐顺序）：
  1. `cd /root/xpert && corepack pnpm install`（按 `.npmrc` 的 `node-linker=hoisted` 重新落盘；pnpm 版本由 `packageManager: pnpm@10.24.0` 固定）→ 预期直接消除绝大多数环境级失败。
  2. 若某个 mock 属**遗留防御**（组件并不真的使用该库），删除该行 `jest.mock(...)`；必须保留时改为 `jest.mock('<pkg>', factory, { virtual: true })`。
  3. contracts 相关失败：`pnpm nx build contracts`（`cloud:build` 已声明依赖，但单跑 spec 时只有 `moduleNameMapper` 指向源码）。
- **运行面影响**：依赖缺失时 `nx build cloud` / `nx serve` 直接失败（Angular builder 解析 `node_modules/monaco-editor`、`@xpert-ai/chatkit-ui`、`packages/ui` 等资产）；本机当前不具备构建与运行条件。

章节来源：[proxy.conf.cjs](file://apps/cloud/proxy.conf.cjs)（关键符号：`resolveProxyTarget`）、[jest.config.ts](file://apps/cloud/jest.config.ts)（关键符号：`moduleNameMapper`、`transformIgnorePatterns`）、[project.json](file://apps/cloud/project.json)（关键符号：`targets.build.options.assets`）

## 5. 特性开关与权限点

- **本域没有 feature flag**（模块内无 `FeatureEnum`/`enabled` 开关读取）；准入通过**权限点 + 后端守卫**实现：
  - `AIPermissionsEnum.KNOWLEDGEBASE_EDIT`：`/xpert/knowledges` 首页、`connect`、`create-from-pipeline` 三段（`NgxPermissionsGuard`，越权 `redirectTo: '/settings'`）。
  - `AIPermissionsEnum.COPILOT_EDIT`：创建向导入口可达性（`blank-wizard-state` 内 `permissions$`）。
  - 后端 `XpertGuard`（助手创作）、`WorkspaceAuthoringGuard`/`WorkspaceOwnerGuard`（工作区）、`AssistantFileAccessGuard`（工作区文件）。
- **可裁剪的运行期行为（等效开关）**：`environment.mcpOAuthEnabled`（MCP OAuth 流）、`MCP_APP_SANDBOX_*`（MCP App 沙箱代理与域名白名单）——只影响相关工具面板，不影响管理页加载。

章节来源：[routing.ts（知识库）](file://apps/cloud/src/app/features/xpert/knowledge/routing.ts)（关键符号：`AIPermissionsEnum.KNOWLEDGEBASE_EDIT`、`NgxPermissionsGuard`）、[environment.jest.ts](file://apps/cloud/src/environments/environment.jest.ts)（关键符号：`mcpOAuthEnabled`、`MCP_APP_SANDBOX_ALLOWED_DOMAINS`）

## 6. i18n 与文案

- **键风格**：`XP.<域>.<词条>`，本域集中在 `XP.Xpert.*`（侧栏与面板：`XP.Xpert.Agents`、`XP.Xpert.Copilot`、`XP.Xpert.Authorization`、`XP.Xpert.Memory`、`XP.Xpert.Logs`、`XP.Xpert.Monitoring`、`XP.Xpert.Assistant`）与 `XP.Messages.*`（`XP.Messages.SavedDraft`、`XP.Messages.UpdatedSuccessfully`）；提示类键含 `XP.Xpert.PublishedSuccessfully`、`XP.Xpert.TemplatePluginSkills{InstallFailed,NoMatchingComponents,MissingRuntimePackages,InstallFailedDetail}`。
- **模板写法**：`{{ 'XP.Xpert.Agents' | translate: { Default: 'Agents' } }}`——**Default 兜底**意味着缺词条时页面仍可读，只退化英文。
- **词条位置**：`apps/cloud/src/assets/i18n/{en,en-US,zh-CN,zh-Hans,zh-Hant}.json`（5 个语言文件；`TemplatePluginSkills*` 四键实测在 5 个文件中均已存在）。
- **组件库文案**：`packages/ui/src/i18n/` 作为 `assets/locales/xp-ui/` 打包（headless-ui 组件内文案）。
- **核对手段**：文案键存在性有 spec 直接断言（`blank-plugin-resource-error.util.spec.ts` 用 `readFileSync` 校验 5 个语言文件），新增键务必同批补齐 5 个文件。

章节来源：[xpert.component.html](file://apps/cloud/src/app/features/xpert/xpert/xpert.component.html)（关键符号：`XP.Xpert.Agents`、`XP.Xpert.Monitoring` 翻译管道）、[blank-plugin-resource-error.util.spec.ts](file://apps/cloud/src/app/features/xpert/xpert/blank/blank-plugin-resource-error.util.spec.ts)（关键符号：`readFileSync`、`TemplatePluginSkillsInstallFailed`）

## 7. 日志与排障入口

- **日志器**：`XpertAPIService`、`XpertWorkspaceService`、`XpertToolsetService`、`XpertToolService` 等均 `inject(NGXLogger)` 并保存 `#logger`；前端**不落盘**，仅浏览器控制台。
- **可观测信号**：
  - `GET /api/xpert/:id/team` 的状态码与 `?data=` 查询串（9 项 relations 是否完整编码）。
  - `XpertService.latestXpert()`/`xpert()` 是否为 `null`（`XpertComponent` 侧栏名称、`switcher` 列表均依赖它）。
  - `fetch-event-source` 对 `RUNTIME_STREAM_INTERRUPTED_EVENT` 的处理（流中断会以 error 结束，而非静默成功）。
  - 助手侧信道：`XpertAssistantFacade` 的 `requestContext`（`env.workspaceId`/`env.xpertId`/`targetXpertId`/`unsaved`）与 `studioRefresh`/`promptWorkflowRefresh`/`workspaceSkillRefresh` 的 nonce。
- **测试期排障**：`--runTestsByPath` 单跑 + Jest 输出中 `●` 开头的失败块；`Cannot find module '<pkg>'` 一律按第 4 节处置。
- **网络代理**：开发态代理目标解析结果由 `resolveProxyTarget()` 决定，`VITE_API_BASE_URL` 与 `API_BASE_URL` 不一致时以 `VITE_API_BASE_URL` 优先。

章节来源：[xpert.service.ts（@core）](file://apps/cloud/src/app/@core/services/xpert.service.ts)（关键符号：`XpertAPIService.#logger`、`XpertAPIService.baseUrl`）、[assistant.facade.ts](file://apps/cloud/src/app/features/xpert/assistant-shell/assistant.facade.ts)（关键符号：`XpertAssistantFacade.requestContext`、`XpertAssistantFacade.studioRefresh`）

## 8. 常见故障与处置

| 症状 | 首选排查 | 处置 |
|---|---|---|
| 管理页加载不出（侧栏无名称、面板空态） | `GET /api/xpert/:id/team` 的 401/403/404；后端 `XpertGuard` 的 `createdById`/`canAccess`；`data=` 参数是否被截断 | 修正路由 `id`；确认助手归属或工作区可见性；注意 `XpertService` 订阅**无 error 回调**，失败不会弹提示，需看控制台与网络面板 |
| 保存草稿无效 | `PUT /api/xpert/:id/draft`（Agent）或 `PUT /api/xpert/:id`（Copilot）的 400/409；`basic` 是否走错分支（`xpert().type`） | 按 `getErrorMessage` 提示修正草稿内容；Agent 类型必须带 `team.agent` |
| 发布后列表/知识库不刷新 | `published$` 是**内存事件、不跨标签页**；生产方是 Studio 发布对话框，消费方是 knowledge pipeline | 刷新页面或切换路由触发 `XpertService.refresh()`；跨标签页同步需另建机制（当前不支持） |
| 版本号/版本列表异常 | `latestXpert().version`；`GET /api/xpert/:id/version`（Studio 域） | 版本是同一 family 下的独立 Xpert 记录，切换版本＝路由跳转，删除版本＝`DELETE /api/xpert/:id` |
| 工具测试失败 | `POST /api/xpert-tool/test`（`responseType:'text'`）；`normalizeToolTestError` 是否把结构化错误还原；工具集凭据是否已授权 | 先补 `/api/xpert-toolset/:id/credentials` 授权，再重试；结果区会同时显示错误文本 |
| 知识库 wiki 打不开 | `knowledgebaseWikiGuard` 的 `getDetail` 结果（类型是否文档库、`wikiConfig.enabled`） | 非文档库或未启用 wiki 会重定向默认页；接口异常时看 `toastr.danger` 文案 |
| spec 大面积失败（`Cannot find module`） | `/root/xpert/node_modules` 是否存在 | `corepack pnpm install`；随后按 06-测试 §1 复跑并按 §5 重新标定失败清单 |
| 构建失败（资产解析不到） | `node_modules/monaco-editor`、`@xpert-ai/chatkit-ui`、`packages/ui/styles.css` 是否就绪 | 先装依赖再 `pnpm nx build contracts && pnpm nx build cloud` |
