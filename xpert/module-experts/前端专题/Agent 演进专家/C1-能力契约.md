> **跨端校对（2026-10-16，与后端资产对齐）**：后端 `agent-evolution` 实测 **48 端点**，本文清单的 24 条**全部命中**；后端另有 **5 条本清单未列**：`GET /runtime-observations`、`GET /audit-events`、`GET|POST /experiences`、`POST /capability-executions/resolve`、`POST /simulations/conformance`（最后两条与能力执行/一致性模拟相关）。另：本文曾记 job 状态含 `pending`，契约枚举实为 `queued|running|completed|failed|cancelled`（**无 `pending`**）。后端权威口径见 [.module-experts/后端专题/Agent 演进专家/implementation/05-接口.md](file://.module-experts/后端专题/Agent 演进专家/implementation/05-接口.md)。

### 1.1 `AgentEvolutionFacade` 状态成员（signal / computed）

`@Injectable({ providedIn: 'root' })`，但实际由壳组件 `providers: [AgentEvolutionFacade]` 提供——**一个工作台一个实例**。

| 成员 | 类型 | 语义与约束 |
| --- | --- | --- |
| `lifecycleRecords` | `Signal<EvolutionLifecycleRecord[]>` | 变更生命周期记录源（`GET /changes`，`pageSize: 200`）；`load` / `refreshChanges` 落库 |
| `contextLifecycleRecords` | `Signal<EvolutionLifecycleRecord[]>`（computed） | 按 `selectedTargetId` + `showFixtures` + `dashboard().targets` 过滤；**依赖不足则不刷新** |
| `changes` | `Signal<EvolutionChange[]>` | 富变更记录（`GET /changes/records`）；是 `publication.mode === 'version_write'` 等策略判定的来源 |
| `dashboard` | `Signal<AgentEvolutionDashboard>` | 17 字段聚合体；初值 `EMPTY_EVOLUTION_DASHBOARD` |
| `eventPage` / `candidatePage` / `releasePage` | `Signal<EvolutionPage<T>>` | 三个分页信封（`LearningEvent` / `EvolutionCandidate` / `ReleasePackage`），初值为私有 `EMPTY_PAGE` |
| `providerError` | `Signal<string \| null>` | **数据源不可用**：仅 `/changes` 与 `/changes/records` 失败时置位（原文，不 toastr） |
| `error` | `Signal<string \| null>` | 一般错误面：其余端点失败与 `withMutation` 失败时置位（带 toastr，可命中 i18n 映射） |
| `loading` / `synchronizing` / `mutating` | `Signal<boolean>` | 全量加载 / 目标同步 / 治理动作进行中；写操作前先看 `mutating()` |
| `activeJob` / `loadedAt` | `Signal<EvolutionJob \| null>` / `Signal<Date \| null>` | 当前作业与**最近一次成功加载时间**（判定「已加载」的正规依据） |
| `selectedTargetId` / `showFixtures` | `Signal<string>` / `Signal<boolean>` | 上下文选择：`'all'` 表示全部；夹具默认隐藏（`targetType === 'test_fixture'`） |
| `selectedCandidateId` / `selectedDatasetSnapshotId` / `selectedEvaluationRunId` / `selectedReleasePackageId` | `Signal<string \| null>` | 四类资源选择；`selectTarget()` 与 `resetScopeContext()` 会清空 |
| 上下文 computed 族 | `Signal<...[]>` | `visibleTargets`（去夹具）、`selectedTarget`、`contextTargets`、`contextEvents`、`contextProposals`、`contextChanges`、`contextCandidates`（**要求 `strategy` 存在**）、`contextDatasets`、`contextEvaluations`（按可见候选 id 反查）、`contextReleases`、`contextPointers` |
| `latestCandidate` / `latestEvaluation` / `latestRelease` / `latestProposal` / `isEmpty` | `Signal<... \| null>` / `Signal<boolean>` | 「选中优先、否则取首条」的落地指针；`isEmpty` = 事件 + 候选 + 发布三者皆空 |

### 1.2 `AgentEvolutionFacade` 生命周期与写操作方法

| 方法 | 参数 / 返回 | 语义与门槛 |
| --- | --- | --- |
| `load({ silent? })` | `{ silent?: boolean }` → `Promise<unknown \| null>` | 17 路并发聚合；写 `dashboard`（`EMPTY_EVOLUTION_DASHBOARD` 打底 + 服务端返回 + 各分页 items）、`lifecycleRecords`、`changes`、三个分页对象、`loadedAt`；随后 `normalizeSelections()` |
| `refreshChanges()` | `Promise<void>` | 只刷 `/changes` + `/changes/records`（可选带 `activeJob` 的 `getJob`）；成功清 `providerError`，失败置位且**两源都不落库** |
| `resetScopeContext()` | `void` | 自增 `#scopeRevision` / `#loadRevision`，清空全部 signal 与选择，重置 `selectedTargetId = 'all'` |
| `loadLearningEvents(query)` | `{ page?, search?, targetId?, status? }`（默认 `pageSize: 50`） | 单独推进 `eventPage` **并同步** `dashboard.events`；作用域变更后丢弃 |
| `synchronize()` | `Promise<boolean>` | `POST /targets/synchronize` → `load({ silent: true })` → toastr |
| `reviewEvent(eventId, reviewStatus)` | `'pending' \| 'ignored' \| 'golden'` → `Promise<boolean \| null>` | 事件复核；成功后静默重载 |
| `createProposalForEvent(event)` | `LearningEvent` → `Promise<ImprovementProposal \| null>` | 门控：同目标 + `sameEvolutionScope` + 非 `ignored` + 非 `L1`；先 `diagnose` 再 `createProposal`，本地 `dashboard.update` 前置合并（不重载） |
| `buildCandidate(proposal, changeSet)` | `ImprovementProposal` + `Record<string, string \| number \| boolean \| string[]>` | `POST /candidates` 后重载并选中新候选 |
| `createDataset(request)` | `CreateDatasetSnapshotRequest` | `POST /datasets` 后重载并选中快照 |
| `evaluateCandidate(candidate, dataset)` / `evaluateLatestCandidate()` | `EvolutionCandidate \| null`、`DatasetSnapshot \| null` | 前置：候选 `ready \| evaluating` **且** 数据集与候选同 `targetId` 同 scope；缺失时 toastr warning 并返回 `null`；成功后按 `runId` 选中评估 |
| `approveCandidate` / `rejectCandidate` | `(candidateId, evaluationRunId, reason)` | 转 `decideCandidate` → `POST /changes/:id/decisions`；`candidateHash` 取自 `dashboard.candidates`（缺省空串），`evaluationRunId` 优先用生命周期记录中的 run |
| `approveAndPublishChange(change, reason)` | `EvolutionChange` + `string` | 仅 `version_write` + `pending_approval` + 候选存在 + `evaluation.passed` + reason 非空；服务端返回非 `approved` 时不发布（`pending_approval` 提示「等待其余审批」） |
| `publishApprovedChange(change)` | `EvolutionChange` | 仅 `version_write` + `approved \| publishing` + `evaluation.passed`；失败统一包装为 `ApprovedPublicationFailed` i18n |
| `packageRelease(candidateId, evaluationRunId, approvalIds)` | `Promise<ReleasePackage \| null>` | `POST /changes/:id/publication` 后重载并选中发布包 |
| `runReleaseAction(release)` | `ReleasePackage` → `Promise<EvolutionJob \| null>` | 状态机：`approved`→install、`installed`→shadow、`shadow`→canary 5%、`canary < 50`→25/50、`canary ≥ 50`→activate、`active`→create experience；有 job 则 `waitForJob` |
| `pauseRelease` / `rollbackRelease` | `releasePackageId` | 暂停直接返回 `true`；回滚等待 job |
| `createCanaryTestOverride(releasePackageId, request)` | `CreateEvolutionCanaryTestOverrideRequest` | 灰度手工测试覆盖；成功后 toastr |
| `selectTarget(targetId)` | `string` | 写 `selectedTargetId` 并清空四类资源选择 |
| 私有：`waitForJob` / `withMutation` / `reportError` / `matchesContext` / `normalizeSelections` / `clearResourceSelections` | — | `waitForJob` 60×1s 轮询；`withMutation` 置 `mutating` 并把异常收成 `error` + `null` 返回 |

### 1.4 `types` 关键类型与 `EMPTY_*` 空态

- `AgentEvolutionDashboard`：17 个数组字段（`targets`、`versions`、`bundles`、`events`、`diagnoses`、`clusters`、`experiences`、`proposals`、`candidates`、`datasets`、`evaluations`、`approvals`、`releases`、`deployments`、`pointers`、`audits`、`canaryTestOverrides`）。
- `EMPTY_EVOLUTION_DASHBOARD`：上述 17 字段的空数组**常量**；门面初值与 `resetScopeContext()` 都用它，`load()` 用它打底再覆盖。
- 模块私有 `EMPTY_PAGE = { items: [], total: 0, page: 1, pageSize: 20 }`：三个分页对象的初值（**未导出**，`pageSize` 与真实请求的 50/100 不同，不可作为「是否已加载」判据）。
- `EvolutionViewStatus`（`'success' | 'warning' | 'neutral' | 'danger'`）、`evolutionApprovalGatePresentation(riskLevel, approvals, currentRoleName)` → `{ administratorPath, hasAdministratorApproval, requiredApprovals, progress, passed }`（R3/R4 需 3 人、其余 2 人；管理员路径 1 人）、`isEvolutionAdministratorRole(roleName)`（`SUPER_ADMIN` / `ADMIN`）。
- 摘要适配：`learningEventPresentation(event)` / `evolutionSummaryPresentation(summary)` 把「结构化 JSON 字符串」拆成可本地化字段（`EvolutionSummaryFieldPresentation.labelKey = XP.AgentEvolution.SummaryField.<key>`），普通散文则原样保留 `text`；解析失败时**隐藏实现数据**并退回 `decisionPoint` / `subjectRef`。
- 工具与范围：`shortId`、`percent`、`evolutionScopeId(scope)`、`sameEvolutionScope(left, right)`、`evolutionScopeLabel(scope, missingLabel)`；另 `export type { EvolutionSimulationResult }`。

// release.component.ts（剪裁）：发布包状态 → 下一步动作
readonly release = computed(
  () => this.facade.contextReleases().find((item) => item.releasePackageId === this.selection()?.releasePackageId) ?? null
)
readonly primaryAction = computed<ReleaseAction | null>(() => {
  const release = this.release()
  if (release?.status === 'approved' && this.target()?.capabilities.install)
    return this.releaseAction('InstallImmutableVersion')
  if (release?.status === 'shadow' && this.target()?.capabilities.canary)
    return this.releaseAction('StartCanary5', deploymentGatePassed(this.deployments().at(-1), 'shadow',
      this.gatePolicy()!.shadowMinimumSamples, this.gatePolicy()!.shadowMinimumDurationHours))
  /* … canary < 50 → ExpandCanary(25|50)；canary ≥ 50 → ActivateProduction；active 且无经验 → CreateStableExperience */
  return null
})
async performPrimaryAction() {
  if (confirmed) await this.facade.runReleaseAction(release)   // 内部：install/shadow/canary/activate/createExperience + waitForJob
