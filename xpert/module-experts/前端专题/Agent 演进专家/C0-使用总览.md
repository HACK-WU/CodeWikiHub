## 1. 定位与何时找

### 1.1 定位

「Agent 演进专家」是 Xpert 前端的**演进治理工作台**：把「学习信号 → 改进提案 → 候选版本 → 评估与审批 → 发布（安装/影子/金丝雀/生产）→ 效果与回滚」这条闭环在一个页面族里读出来、点下去。它由三层构成——**壳**（`AgentEvolutionComponent`，5 个 tab + 目标选择 + 4s 轮询）、**门面**（`AgentEvolutionFacade`，一次 `load()` 聚合 17 路数据并派生上下文 computed 族）、**数据源**（`AgentEvolutionApiService`，`API_AGENT_EVOLUTION = /api/agent-evolution`）。页面子集五个：`overview`（KPI/待办/闭环计数）、`targets`（目标与生产指针）、`learning`（事件→提案→候选）、`evaluation`（数据集→指标对比→审批）、`release`（阶段推进/灰度/回滚），外加四类资源详情页与两个共用件（变更选择器、变更面板）。

### 1.2 何时找

1. 要改 **`/agent-evolution/*` 的路由、tab、副标题、目标选择或夹具开关**——先看 [routes.ts](file://apps/cloud/src/app/features/agent-evolution/routes.ts) 与 [agent-evolution.component.ts](file://apps/cloud/src/app/features/agent-evolution/agent-evolution.component.ts)。
2. 页面**数据不刷新 / 刷新错位**（组织切换、目标切换、夹具开关后列表未变）——看门面的 computed 依赖链与 `#scopeRevision` / `#loadRevision`。
3. 出现**「数据源不可用」横幅或 Retry 按钮**——`facade.providerError()` 语义与恢复路径。
4. 要**新增/修改一个演进接口调用**——`AgentEvolutionApiService` 是唯一出口，基址常量 `API_AGENT_EVOLUTION`。
5. 要判断**某个变更/发布记录当前处于哪一步、为什么卡住**——`changeDetailPresentation` 的 `steps` / `blockedBy` / `reasons` / `result`。
6. 要动**审批门、角色路径与「还差几人」**——`evolutionApprovalGatePresentation` 与 `AISPermissionsEnum` 中的 `EVOLUTION_MANAGE`（`@xpert-ai/contracts` 的 `AIPermissionsEnum`）。
7. 要动**发布阶段的下一步动作或闸门**（安装/影子/金丝雀/激活/生成经验）——`release.component.ts` 的 `primaryAction` 与 `deploymentGatePassed`。
8. 要动**图表配色或指标口径**（生产 vs 候选对比图、运行时曲线）——`readAgentEvolutionChartTheme` 与评估/发布两页的 `EChartsOption`。
9. 要排查**候选与数据集的兼容性**（同 Target 同 Scope 才可选）——`compatibleDatasets` 与 `sameEvolutionScope`。
10. 要确认**测试为什么报依赖失败**——`9 spec` 的失败归因与环境级依赖（`@xpert-ai/store`）。

## 4. 边界

1. **不含后端实现**：实体/表（19 表）、生命周期投影、发布执行器、作业队列归**后端 Agent 演进专家（批次 5 未建）**；本域只记录自身调用的路径与语义。
2. **不含聊天工作台本体**：`changeWorkbenchLink` 只产出 `/chat/x/:xpertId/c?view=…&viewSelection=…&viewParameters=…` 的跳转参数，工作台归**对话前端专家**。
3. **不含权限体系定义**：`EVOLUTION_VIEW` / `EVOLUTION_MANAGE` 定义在 `@xpert-ai/contracts`，本域只消费（路由准入、`hasPermission` 判定）。
4. **不含图表渲染原语**：本域只提供 `EChartsOption` 与主题取色；渲染与响应式归 `@shared/charts/echarts.directive` 与 `echarts`。
5. **不含其他域数据**：`dashboard` 里的 `experiences` / `audits` / `deployments` / `canaryTestOverrides` 只用于本域判断与文案（如「是否已生成经验」），其写入归后端。
6. **本域无对外复用面**：`AgentEvolutionFacade` / `AgentEvolutionApiService` / `EMPTY_EVOLUTION_DASHBOARD` 在域外无引用——改动不影响其他前端域，反之亦然。

## 5. 已知问题与常见坑

1. **① `providerError` 是「数据源不可用」，不是「没有数据」**：只有 `/changes` 与 `/changes/records`（`listChanges` / `listLifecycleRecords`）失败才置位，其余端点失败走 `error` + toastr。恢复入口是页面上的 Retry（`facade.load()`）；`refreshChanges()` 成功后会清空它。**看到它时不要当成空列表处理**。（来源：[agent-evolution.facade.ts](file://apps/cloud/src/app/features/agent-evolution/agent-evolution.facade.ts)（关键符号：`providerError`、`refreshChanges`））
2. **② `refreshChanges()` 是半失败即整体不落库**：`Promise.all([listChanges, listLifecycleRecords])` 任一失败，两个 signal 都保持上一快照（`changes()` 不会拿到成功的那一半），`providerError` 写入 `getErrorMessage(error)`——所以「列表里少了一条刚改的记录」通常是刷新失败而非后端没返回。（来源：[agent-evolution.facade.ts](file://apps/cloud/src/app/features/agent-evolution/agent-evolution.facade.ts)（关键符号：`refreshChanges`、`#loadRevision`））
3. **③ 分页三兄弟（`eventPage` / `candidatePage` / `releasePage`）必须一致推进**：它们在 `load()` 里与 `dashboard` 同批赋值；只有 `loadLearningEvents()` 允许单独推进，但它**同时**写 `eventPage` 与 `dashboard.events`。只改一处会造成「列表 / 统计 / 图表互不同源」。（来源：[agent-evolution.facade.ts](file://apps/cloud/src/app/features/agent-evolution/agent-evolution.facade.ts)（关键符号：`load`、`loadLearningEvents`、`eventPage`、`candidatePage`、`releasePage`））
4. **④ 版本上下文缺失会导致图表误读**：评估页与发布页的一切数值都挂在 `queryParams.changeId` 上（`selection` → `resource` → `candidate` / `evaluation`；发布页再多一层 `releasePackageId` → `gatePolicy` / `canaryPercent`）。`changeId` 缺失或指向被筛掉的记录时，页面会**退化为「第一条可见记录」或空壳**——读图前先确认上下文。（来源：[evolution-change-presentation.ts](file://apps/cloud/src/app/features/agent-evolution/shared/evolution-change-presentation.ts)（关键符号：`selectedEvolutionEntry`、`changeFilter`））
5. **⑤ computed 依赖不满足时「刷新不触发」**：`contextLifecycleRecords` 依赖 `lifecycleRecords` / `selectedTargetId` / `showFixtures` / `dashboard().targets` 四者；原地 mutate 对象或漏更新 `dashboard` 都会让视图停留在旧值（`test_fixture` 判定也会失真）。改数据一律走 `set` / `update`。（来源：[agent-evolution.facade.ts](file://apps/cloud/src/app/features/agent-evolution/agent-evolution.facade.ts)（关键符号：`contextLifecycleRecords`、`matchesContext`、`normalizeSelections`））
6. **⑥ `EMPTY_*` 常量误用会掩盖「已加载」状态**：`EMPTY_EVOLUTION_DASHBOARD`（导出）与私有 `EMPTY_PAGE`（`page: 1, pageSize: 20`）表达「未加载 / 已重置」，由 `resetScopeContext()` 回填；而 `load()` 的真实请求用 `pageSize: 50/100`。**不要用 `pageSize` 或长度判断是否已加载**——用 `loadedAt()`、`loading()`、`providerError()`。（来源：[agent-evolution.facade.ts](file://apps/cloud/src/app/features/agent-evolution/agent-evolution.facade.ts)（关键符号：`EMPTY_PAGE`、`resetScopeContext`、`loadedAt`）、[agent-evolution.types.ts](file://apps/cloud/src/app/features/agent-evolution/agent-evolution.types.ts)（关键符号：`EMPTY_EVOLUTION_DASHBOARD`））
7. **⑦ 组织/作用域切换期间不要手工复位**：壳层 effect 已做 `resetScopeContext()` + `load()`，门面又用 `#scopeRevision` / `#loadRevision` 丢弃陈旧响应；在组件里另写「切作用域时清空」会与修订号机制打架（表现为闪烁或旧数据回填）。（来源：[agent-evolution.component.ts](file://apps/cloud/src/app/features/agent-evolution/agent-evolution.component.ts)（关键符号：`effect`、`resetScopeContext`））
8. **⑧ 大部分治理按钮的门槛是「三重条件」，不是单个状态**：`canReview` = `EVOLUTION_MANAGE` + 评估通过 + `pending_approval`；`canPublish` 还叠加 `publication.mode === 'version_write'` 或 `approved/publishing`；`canPackage` 要求候选已批准 + `evaluation.gate.passed` + `capabilities.install` + 审批门通过。按钮灰掉时逐条核对，别只改状态判断。（来源：[change-panel.component.ts](file://apps/cloud/src/app/features/agent-evolution/changes/change-panel.component.ts)（关键符号：`canReview`、`canPublish`、`combinedPublication`））
9. **⑨ `candidate` 类详情路由会自动改写 URL**：访问 `/agent-evolution/candidates/:id` 命中记录后立即 `navigate(['/agent-evolution/evaluation'], { queryParams: { changeId }, replaceUrl: true })`；给该路径做深链/埋点时要考虑这次替换导航。（来源：[agent-evolution-detail.component.ts](file://apps/cloud/src/app/features/agent-evolution/detail/agent-evolution-detail.component.ts)（关键符号：`kind === 'candidate'`、`router.navigate`））
10. **⑩ 测试失败先排除环境**：基线 9 spec = 8 PASS / 1 FAIL，失败为**环境级 `@xpert-ai/store` 缺依赖**（整文件级模块解析失败，非断言失败）。复跑前先 `corepack pnpm install`；若仍失败且指向依赖解析，按环境问题处理而非改断言。（来源：[Agent 演进专家.md](file://CodeWikiHub/xpert/memory/专题记忆/前端专题/Agent 演进专家.md)（关键符号：`测试状态`、`9 spec = 8 PASS / 1 FAIL`））
11. **⑪ 灰度手工测试覆盖有双重前置**：`showManualTestOverride` 要求「管理员角色」且 `gatePolicy.profile === 'manual_test'`，`canCreateManualTestOverride` 再要求状态为 `canary`、`subjectKey`/`reason` 非空、`expiresInMinutes` 为 1–120 整数——条件不满足时按钮静默不可点。（来源：[release.component.ts](file://apps/cloud/src/app/features/agent-evolution/release/release.component.ts)（关键符号：`showManualTestOverride`、`canCreateManualTestOverride`））
12. **⑫ 作业未结束时的「无变化」是正常的**：`waitForJob` 只是 60×1s 的等待窗口（注释明示超时窗口不是作业超时），之后靠 4s 轮询继续收敛；页面 4s 轮询还会跳过 `document.hidden` 与 `loading()`——后台标签页里进度不动是设计行为。（来源：[agent-evolution.facade.ts](file://apps/cloud/src/app/features/agent-evolution/agent-evolution.facade.ts)（关键符号：`waitForJob`、`activeJob`）、[agent-evolution.component.ts](file://apps/cloud/src/app/features/agent-evolution/agent-evolution.component.ts)（关键符号：`setInterval`、`document.hidden`））
