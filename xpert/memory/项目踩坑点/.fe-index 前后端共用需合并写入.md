# .fe-index/ 前后端共用，并发写入必须合并而非覆盖

## 现象

前端索引（frontend-index）与后端索引（backend-index）共用同一份 `.fe-index/INDEX.md` 与 `.fe-index/config.json`。两个会话并发建库时，直接用 write_to_file 全量写入会覆盖对方的登记行/配置条目。

## 本项目实测（2026-10-14）

- 前端会话写 `config.json`（仅 frontend 条目，约 17:13:04）→ 后端会话随后读到并**合并写回**（frontend + backend 两条，mtime 17:13:04.851）。
- 前端会话写 `INDEX.md`（仅 xpert-cloud 行，17:13:34）→ 后端会话合并写回两行 + 后端消费入口章节（17:13:54）。

## 结论与约定

1. 写 `.fe-index/INDEX.md` / `config.json` 前**先读当前内容**，只增改自己应用的条目/行，不动其他行。
2. `config.json` 中前后端各一条，按 `kind` 区分（frontend / backend），两个 skill 各取所需。
3. 派生产物（`{slug}/` 目录）默认不入库：`.gitignore` 已有 `/.fe-index/*/`，`INDEX.md` 与 `config.json` 入库。
4. 每次写入后校对：`.fe-index/INDEX.md` 应包含所有已建应用的完整行集合。

## 相关路径

- 登记表：`/root/xpert/.fe-index/INDEX.md`
- 声明文件：`/root/xpert/.fe-index/config.json`
- 前端索引：`.fe-index/xpert-cloud/`（slug xpert-cloud，root apps/cloud）
- 后端索引：`.fe-index/xpert-server/`（slug xpert-server，root /root/xpert）
