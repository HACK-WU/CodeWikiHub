[强关联] 工具与 MCP 专家 与 平台插件与技能专家 + Assistant 定义与运行时专家（共用同一张工具集配置表与同一个落库安装器）
- 强度：必改——改安装器写工具集的方式（`runtimeSource`/`pluginManaged` 标记、`toolRepo.delete` 时机、能力 catalog 刷新）→ 工具集读面与 MCP 发布必改；改助手侧挂载关系（`xpert_to_toolset` / `XpertAgent.toolsetIds`）→ 本域只读目录模型必须同步
- 原因：三类「插件」共用 `XpertToolset`/`XpertTool` 作为唯一落点，靠 `options` 上的字符串约定区分来源；助手域持有 M2M `xpert_to_toolset`，本域只提供读模型（`getAllByWorkspace` + `afterLoad` 生成 `ToolsetCatalogItem`）
- A 端（本域）：`XpertToolsetService.create/createBuiltinToolset/updateToolset/afterLoad` @ file://packages/server-ai/src/xpert-toolset/xpert-toolset.service.ts；`ToolRuntimeService.loadToolsets` @ file://packages/server-ai/src/tool-runtime/tool-runtime.service.ts；`McpCapabilityCatalogService`（能力台账刷新）
- B 端（平台插件与技能专家）：`PluginResourceInstallerService.installComponentsForXpert/installRuntimeComponent/ensureMcpToolset`、`resolveRuntimeType` @ file://packages/server-ai/src/plugin-resource/plugin-resource-installer.service.ts；`PluginResourceInstallation` @ file://packages/server-ai/src/plugin-resource/plugin-resource-installation.entity.ts；`skill_package.runtimeResourceOnly`（迁移新增，表属技能域）
- B 端（Assistant 定义与运行时专家）：`Xpert.toolsets` + `@JoinTable('xpert_to_toolset')` @ file://packages/server-ai/src/xpert/xpert.entity.ts；`XpertAuthoringService.getAvailableToolsetsFromContext`（助手目录读模型）@ file://packages/server-ai/src/xpert/middlewares/xpert-authoring.service.ts；运行时统一走 `ToolsetGetToolsCommand`
- 改哪一侧会连带改另一侧：① 安装器写工具集是「先 `toolRepo.delete({toolsetId})` 再 `updateToolset`」⇒ 改本域工具级联语义会与安装器的删后重建冲突；② 来源标记（`options.pluginManaged` / `options.runtimeSource:'agent-plugin'`）只是字符串约定 ⇒ 任何绕过安装器直接建工具集的代码都会落进「无来源」灰区，且 `McpRuntimeAuditService.findResourceInstallation` 的审计回填会失效；③ 助手侧 M2M 写入归助手域 ⇒ 本域改 `afterLoad` 的 `label/description/schema` `??=` 回填会连带改助手目录展示
- 边界面：平台插件（`packages/server/src/plugin/**`、`LOADED_PLUGINS` 驱动）归平台插件与技能专家；Agent 插件（`agent-plugin/**`，PortablePlugin）与 MCP 发布（`mcp-publication/**`，8 表）归本域；三者准入、来源与生命周期互不相同
