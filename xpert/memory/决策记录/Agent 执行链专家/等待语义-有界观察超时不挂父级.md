【决策记录｜waitForTasks 是有界观察，超时不挂父级】\n- 分类：等待语义 / Agent 交互模型\n- 动机（避坑）：现象——让等待挂起父级或让长任务靠 LLM 轮询循环；后果——父图被无谓阻塞、token 成本随轮询线性上升、`pending` 被误读为完成\n- 决策：`waitForTasks` 支撑 `task_status` 工具，与单任务 `awaitResult` 互补；**观测窗口耗尽正常返回 `pending`**，不挂起父级、不暗示任务完成；**只有人工交互才挂起图**；`unknown` 在 `pending` 中归一为 `unavailable`\n- 背景约束：图适配器提供通用 wait/resume 桥；后台调用返回任务引用；持久 provider 会话默认单写者；并行编码任务使用隔离工作区（除非共享策略显式允许）\n- 被否决方案：让长任务依赖 LLM 轮询循环（文档明写「A long-running tool must not require an LLM polling loop.」）；把等待当作同步阻塞\n- 重新评估触发条件：新增非 CLI 域作业时，先扩 `runtime-task` 统一策略\n- 关联代码：agent-invocation/invocation-factory.service.ts；plugin-sdk/src/lib/agent/runtime/capability.ts\n- 证据来源：agent-invocation/README.md 逐字——「invocation-task-wait: bounded observation for Agent-driven status polling; only human interactions suspend.」「An elapsed observation window returns `pending` normally; it does not suspend the parent or imply task completion.」
