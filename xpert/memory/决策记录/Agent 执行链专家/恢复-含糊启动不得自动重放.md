【决策记录｜含糊启动不得自动重放】\n- 分类：恢复 / 幂等\n- 动机（避坑）：现象——launch/进程状态不明时自动重试；后果——重复外部副作用、重复消耗配额，且无法区分「没起来」与「起来了但回执丢了」\n- 决策：含糊启动必须保持 `unknown` 且**永不自动重放**；已提交的 pending dispatch 意图可重排，但重排必须携带原 call ID 与当前授权；只有**尚无任何 launch receipt** 时，已验证的 preflight 失败才可记为 failed\n- 背景约束：持久化启动 fence 最长 120s，期内后台巡检**不做中间态失效判定**；`reserved` consumer 恢复同一 execution ID，`started` 后只检查该 execution；`consumer_outcome_unknown` 保持 blocked，`redrive` 只复核同一条已记录的 execution identity\n- 被否决方案：传输重试或 redrive 重新启动 CLI / 分配替代 consumer（明确否决）；把含糊启动按时间推断为失败\n- 重新评估触发条件：无此项（「Exactly-once remote side effects are not promised.」）\n- 关联代码：handoff/runtime-messaging/README.md；agent-invocation/README.md\n- 证据来源：agent-invocation/README.md 逐字——「Checkpoint it before sending the initial task; ambiguous launch or process state must not trigger an automatic replay.」；runtime-messaging/README.md 逐字——「Neither transport retries nor redrive relaunches the CLI or allocates a replacement consumer.」
