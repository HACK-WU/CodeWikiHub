【决策记录｜终局化不得重放初始行；completedAt 只表真终态】\n- 分类：账本写入规则 / 时间语义\n- 动机（避坑）：现象——用初次 `create` 的整行快照做终局化写回，或用 `updatedAt`/`elapsedTime` 反推结束时间；后果——覆盖更新的审计时间戳与用量计数、时间线出现伪造的结束时刻\n- 决策：`create`/`update` **忽略调用方 `createdAt`/`updatedAt`**；整行重放初值被禁止；`completedAt` **只**记录成功/失败/超时/中断的墙钟时间，**恢复为 running/pending 时清空**，重复终局化与元数据更新保留已记录终点；`elapsedTime` 不用于重建日历时间，`updatedAt` 不能替代结束时间\n- 背景约束：运行时回调仍可持久化自己的 metadata 与 checkpoint 字段；`recordUsage` 必须在事务内执行\n- 被否决方案：用 `updatedAt` 或 `elapsedTime` 回填历史 `completedAt`（文档明写不可靠、迁移明确不 backfill）；重放初始行\n- 重新评估触发条件：无此项——迁移明确「历史行的真实结束时间无法可靠恢复，任务时间线留空为未知」\n- 关联代码：xpert-agent-execution/agent-execution.service.ts；xpert-agent-execution/migrations/20261008-execution-completed-at.sql\n- 证据来源：xpert-agent-execution/README.md 逐字——「Finalization must not replay the initial database row, which can overwrite newer timestamps and usage counters.」「`completedAt` records the wall-clock time when an execution succeeds, fails, times out or is interrupted. Resuming to running/pending clears it; the next stop records a new timestamp.」
