【决策记录｜中间件只暴露 scoped API，不得把全局 registry 传给插件】\n- 分类：安全边界 / 能力注入\n- 动机（避坑）：现象——把全局 capability registry 或 runner factory 交给插件；后果——插件可跨租户解析能力、绕过 owner/workspace 校验\n- 决策：invocation factory 为每次操作捕获**不可变身份 scope**，只向 runtime 策略暴露 scoped runner capability，**不暴露全局 capability registry 或 runner factory**；中间件侧由 `createScopedApi(scope)` 组合 actor token/artifacts/collaboration/connector/workspace files/model client，能力集合随 scope 变化，**缺能力时显式失败**\n- 背景约束：runner factory 构造**不执行任何启动或 I/O**；正常调用与绑定授权仍先于策略派发；**草稿态与发布态上下文分离**（`getDraftXpertMiddlewareContext` / `createDraftXpertMiddlewareRuntime`）\n- 被否决方案：把全局 registry / runner factory 直接交给插件（README 逐字否决）；在 feature 模块里重复 provider 化 runtime service（`middleware-runtime.provider-boundary.spec.ts` 断言消费模块必须 import runtime 模块而非自行 provide，且 file/actor-token/connector/知识文档视觉资产的 scoped factory 由其领域模块 own）\n- 重新评估触发条件：新增宿主集成能力时，须走 scoped factory 注册，不得扩到共享门面\n- 关联代码：shared/agent/middleware-runtime/middleware-runtime.service.ts；middleware-runtime.provider-boundary.spec.ts；execution-scope.ts\n- 证据来源：agent-invocation/README.md 逐字——「It does not expose the global capability registry or the runner factory.」；middleware-runtime.service.ts 注释逐字——「Stable facade that assembles invocation-scoped middleware capabilities. Domain behavior lives in focused runtime services so this class only owns capability composition and scope-specific host integrations.」「Do not capture the first caller identity on this shared facade or resolve factories before discovery.」\n- 备注：`provider-boundary.spec.ts` 实际文件名为 `middleware-runtime.provider-boundary.spec.ts`，其断言对象是**模块 provider 归属**（谁 provide / 谁 import）；「不把全局 registry 传给插件」的直接证据是 README 原文与 `createScopedApi` 实现
