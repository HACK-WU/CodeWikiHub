【决策记录｜预算无隐式默认，未知费用不等于免费】
- 分类：性能取舍
- 动机：避坑：给 token 预算设隐式默认或把 unpriced 折算为 0 → 用户以为有硬性成本上限、实际超支，且无法区分「免费」与「未知」
- 决策：tokenBudget / userTokenBudget 均可选，未配置时不参与准入；准入用「估算输入 + 请求输出长度（缺省取 catalog 输出上限）」预占，**估算不注入额外 max_tokens、不作为用量事实**；未知结果保留预占并进 settlement_pending，由权威证据或人工核对释放
- 背景约束：单笔在途请求无法给出严格金额上界；pricingStatus 存在 priced/free/unpriced（查询侧另有未解析的 pending），unpriced 与免费必须可区分
- 被否决方案：按授权里的 maxInputTokens/maxOutputTokens 做每请求硬上限（字段被读入后丢弃、不做迁移）
- 重新评估触发条件：业务提出「严格货币预算/硬性成本上限」要求，或要把 unpriced 自动折算为 0（当前禁止）
- 关联代码：execution-admission.service.ts、execution-usage-schema.ts、execution-policy.defaults.ts @ packages/server-ai/src/model-execution/
- 证据来源：docs/model-execution.md（明写 Token budgets have no implicit defaults、an unknown charge must remain distinct from a free call）
