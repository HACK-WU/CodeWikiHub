【决策记录｜多副本下的幂等定时任务：进程内 Interval + Redis 锁/cursor/advisory lock】
- 分类：架构设计
- 动机：避坑：@Cron/@Interval 随每个 API 副本各自注册 → 多副本并跑重复结算、重复失效与重复告警（正确性靠唯一索引兜底但产生写放大与噪声指标）
- 决策：需「同 tick 只跑一次」的任务用 Redis 锁（scheduler:model-access-lifecycle、scheduler:membership-period-settlement，TTL 5 分钟）+ CACHE_MANAGER cursor（model-access:lifecycle-cursor:v1，TTL 24 小时）或 PG 会话级 pg_try_advisory_lock（检查点留存）；纯重放型维护任务（网关 5 个 @Interval、metering/reconciliation 的 30 秒重试）不加锁，改为按状态过滤小批量 + 唯一索引幂等 + FOR UPDATE SKIP LOCKED；积压指标明示为进程本地量、多副本不可相加
- 背景约束：多 API 副本共享同一数据库，无集中式调度器；锁获取失败即跳过本轮（仅日志降级）；游标丢失则从头扫描
- 被否决方案：无（未引入集中式 scheduler）
- 重新评估触发条件：引入集中式调度/单副本 worker；把积压指标改为分布式聚合
- 关联代码：model-access-scheduler.service.ts、membership-period-scheduler.service.ts、retention.service.ts、model-gateway.service.ts
