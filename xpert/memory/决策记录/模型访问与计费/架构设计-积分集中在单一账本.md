【决策记录｜积分集中在单一账本，唯一索引是幂等底线】
- 分类：架构设计
- 动机：避坑：多个扣费来源（copilot-usage 事实、model-execution 投递、model-gateway 结算与留存归档）各写各表 → 重复扣费无法在数据库层拦截、对账口径分裂
- 决策：所有扣减与调整都写 membership_point_ledger（事实行 source='model_usage' 与扣减行共表，靠 source 区分；个人积分行以 :personal 后缀区分）；幂等由 IDX_membership_ledger_source_reference 与 UQ_membership_ledger_model_usage_request_metric_revision 在 DB 层兜底；recordUsage/recordGatewayUsage 事务内先取锁再查重，命中即返回既有结果
- 背景约束：三/四模块共享该表；pointsDelta numeric(28,10) 支持小额与负值；读模型用反连接避免事实行与扣减行双计；excessPoints>0（未扣满）与 unpriced（未知）必须分开呈现
- 被否决方案：无
- 重新评估触发条件：列语义变更导致四方口径互相牵制；硬编码前缀（model-usage-charge: 与 :personal）需要收敛
