【决策记录｜架构设计：作用域单点与 /explore 回落入口】
- 分类：架构设计
- 动机：避坑：现象——各页自行读 ScopeService、或给 `/explore` 加特性开关守卫 / 改路由前缀；后果——切换组织后部分页面停留旧数据、切换入口分裂，且对话域 ClawXpert 缺开关时的回落目的地失效，用户被守卫拦死而不是落到可用兜底页（C0 坑 7/8）
- 决策（单点）：作用域状态与切换收敛到 `ExploreScopeService`（activeScope / isTenant / organizationName / key / choose）；页面只 inject 服务、不得自行读写作用域；切换一律 `choose(organizationOnly?)` → ExploreScopeDialogComponent → ScopeService.switchToTenant / switchToOrganization，且不初始化任何资源
- 决策（传播）：`key` 是四页（壳 / 广场 / 应用详情 / 模板详情）统一比对键与 effect 触发源，切换后各自重取并丢弃旧响应；`key` 组成即作用域身份，改动等同语义变更
- 决策（回落）：`/explore` 保持仅 authGuard、无特性开关守卫，且市场开关关闭时壳仍可用（`normalizeExploreTab` 回落 skills）
- 背景约束：`choose(true)` 只允许组织（organization_scope_required 场景）、取消返回 false；`agentMarketplaceEnabled` 需 featureContextHydrated === true，未水合按关闭处理；广场 Agent/应用实体与 Xpert 工作台同源、按 activeScope/key 过滤（dual-scope 语义一致）
- 被否决方案：无
- 重新评估触发条件：新增作用域级别或新探索页面需接入作用域时；对话域回落目标或特性开关守卫策略调整时
- 关联代码：features/explore/explore-scope.service.ts、explore-scope-dialog.component.ts、explore-route-state.ts、explore.component.ts；apps/cloud/src/app/features/chat/routes.ts（canActivateChild + featureGate）
- 证据来源：01-架构.md（关键不变量 1/2/5、结论「回落语义必须保持」）、C0-使用总览.md（边界与已知坑 7/8）、关联事实 explore-回落与作用域关联.md：**ClawXpert 缺功能开关回落 `/explore`**；广场按作用域过滤与工作区 dual-scope 一致；改 /explore 前缀或作用域机制会波及对话域守卫与两侧内容过滤
