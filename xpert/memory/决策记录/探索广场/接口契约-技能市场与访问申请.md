【决策记录｜接口契约：技能市场与访问申请——前端只做调用与分级展示】
- 分类：接口契约
- 动机：避坑：现象——前端自行推断权限、或另建一套审批 UI/语义、或给技能市场自带开关守卫；后果——市场可见性与审批结果口径分叉（显示可用但准入为假）、准入规则变更时漏改、且与 `/explore` 的回落兜底语义冲突致缺开关用户无路可走（C0 坑 3/4/7）
- 决策（访问申请）：可见性三态由服务端裁决——`accessStatus ∈ { not_requested, requested, approved, rejected, accessible, owned }`，前端 `canUseExpert` 只认 owned|accessible|approved，`requested` 固定「待审批」，`rejected`/`not_requested` 可再次申请；审批动作只对 `GET /api/xpert-access-requests/reviewable` 数据生效，复用共享件 `XpertAccessRequestReviewListComponent`（approve/reject 后本地移除并 `changed` 回传）
- 决策（技能市场）：前端只做「调用面 + 展示面」——市场索引（/api/skill-repository-indexes）、可见仓库（/api/skill-repository/availables）、官方位（/api/xpert-template/skills-market）、安装（POST /api/skill-package/install）、分享（POST /api/skill-package/workspace/:workspaceId/:id/share，仅 isLocalSkill = 无 skillIndex 的工作区自建技能、快照语义）均经 @core 服务直调；热榜 `skillHotScore = downloads*2 + stars + versions` 是前端派生，分页 PAGE_SIZE = 20
- 决策（回落约束）：`/explore` 不得加特性开关守卫——它是对话域 ClawXpert 缺功能开关的回落目标；市场开关关闭时技能市场仍须可用（tab 回落 skills）
- 背景约束：技能包/仓库索引/插件 App 编排/市场索引的服务端实现归后端「平台插件与技能专家」（/api/skill-package、/api/skill-repository-indexes、/api/plugin-applications）；访问申请归「Assistant 定义与运行时专家」（xpert_access_request 面）；accessStatus / canReview / reviewableCount / initializationAccess 全由服务端给出
- 被否决方案：无
- 重新评估触发条件：出现「已审批但不可用 / 已拒绝仍可用」的线上不一致；或访问申请扩展为组织级 / 多级审批时
- 关联代码：packages/contracts/src/ai/xpert-marketplace.model.ts（TXpertMarketplaceAccessStatus / IXpertAccessRequest / canReview）、@core/services/xpert-marketplace.service.ts、features/explore/skills/skills.component.ts、features/xpert-access-requests/review-requests-list.component.ts
- 证据来源：C1-能力契约.md（§2 后端接口调用面、§1.3 组件 IO）、01-架构.md（关键不变量 4/6、结论）、关联事实 explore-回落与作用域关联.md：**ClawXpert 缺功能开关回落 `/explore`**；广场按作用域过滤，改作用域机制影响广场与工作区两侧内容过滤
