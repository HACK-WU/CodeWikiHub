【决策记录｜安全合规：权限位三分 ＋ 夹具生产门禁（404 不可区分语义）】
- 分类：安全合规
- 动机（避坑）：**现象** 用一个粗粒度权限位同时管读写；或让一致性夹具（`test_fixture` provider）在生产可写。**后果** 只读巡检者获得治理写权，或演练夹具在生产造出带 `RP-<simulationId>` 命名、`capabilities` 近乎全 false 的假发布包，污染指针对照表
- 决策：权限**三分**——一切读端点 `@Permissions(EVOLUTION_VIEW, XPERT_EDIT)`（**或**语义）、一切写端点（含 `/targets/synchronize`、`/capability-executions/resolve`、`/simulations/conformance`、`/examples/conformance-field-mapping/run`）`EVOLUTION_MANAGE`、`EvolutionBaselineController` 的只读端点**三位任一**；基线返回值以 `canManage = RequestContext.hasPermission(EVOLUTION_MANAGE)` 表达可写性。夹具另加生产门禁：`assertConformanceEnabled()` 在 `environment.production && AGENT_EVOLUTION_ENABLE_CONFORMANCE !== 'true'` 时抛 `NotFoundException`
- 背景约束：服务层还有一层**不在装饰器里**的判定——`approvalAuthority` 由角色名派生（`SUPER_ADMIN`/`ADMIN` → `administrator`），`manual_test` 档与一次性覆盖要求 administrator，回滚拒绝 agent 主体，R4 提案拒绝 agent 主体，治理入口统一先过 `requireHuman`；夹具 404 **与「不存在」不可区分**（不是 403/400），且门禁**只读 `environment.production`、不叠加 `NODE_ENV`**，而闸门策略的生产判定是 `environment.production || NODE_ENV === 'production'`——**两处口径不同**
- 被否决方案：无显式否决记录；404（而非 403）语义是明写的选择，其含义是**不向未授权者暴露夹具入口存在**
- 重新评估触发条件：若未来生产需要「受控演练」，应新增独立端点与审批链，而不是把 `AGENT_EVOLUTION_ENABLE_CONFORMANCE=true` 作为常规开关（它是高风险开关）；统一两处 production 判定口径时需同步复核二者
- 失败面：provider 侧另有同款 `assertTemplateConformanceEnabled()` ＋ `authorizeScope` 二次校验（两处独立声明均需满足）；基线读是「管理员只做读巡检」的唯一通道
