【决策记录｜可靠性：金丝雀一次性覆盖（同主体同部署只生效一次）】
- 分类：安全合规（可靠性：一次性语义）
- 动机（避坑）：**现象** 为了「验收方便」让管理员创建的强制路由长期有效（或可反复续期）；**后果** **永久覆盖事故**——某个主体被无声地钉在候选版本上，绕过确定性百分比路由，指标被污染且没人知道它还在生效
- 决策：一次性由三层物理机制共同保证——① **UQ `(activeKey)`**（`activeKey = sha256(tenant:org:deploymentId:subjectKey)`）保证「同主体同部署至多一条活跃覆盖」；② 消费即 `status:'consumed'` ＋ 记录 `consumedByExecutionId` ＋ 清空 `activeKey`（让位给后续创建）；③ `expiresAt` 到期由读路径惰性翻 `expired`；消费后 `resolveExecutionPlan` 的判据是 `!consumedOverride && !deterministicSelection → continue`，即**回落到** `deterministicPercent = sha256(deploymentId:subjectKey)` 的确定性路由
- 背景约束：创建需**四个 AND**（人 / `administrator` / 发布包 `gatePolicy.profile==='manual_test'` 且当前进程 `manualTestProfileEnabled()` / release 处于 `canary` 且有活跃 canary 部署）；参数上限 `subjectKey ≤ 200`、`reason ≤ 500`、`expiresInMinutes ∈ [1,120]`（缺省 **30**）；同一 `executionId` 重试**返回已消费结果**（幂等重试不会被当成「再给一次机会」）
- 被否决方案：「为同一主体重复创建覆盖以续期」——实现为发现活跃覆盖**直接返回旧值、不续期**（源码逐字：`if (existing && existing.expiresAt.getTime() > Date.now()) return existing.value`）
- 重新评估触发条件：需要「长时间观测某主体」时应新增显式的**观测模式**（且与闸门样本隔离），**不得**把一次性覆盖改成可续期；`activeKey` 唯一索引**不带租户维度**（值本身含 tenant/org 哈希），若未来改为不含租户的 key，必须同步加租户维度
- 失败面：读路径（`GET /dashboard`、`GET /releases/:id/canary-test-overrides`）会就地翻 `expired` 且**不写审计** ⇒ 高并发下有写竞争与审计缺口；消费动作固定写 `AUD-<overrideId>-consumed`
