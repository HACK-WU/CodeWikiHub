【决策记录｜滚动升级：先部署消费者，再部署生产者】
- 分类：兼容处理
- 动机：避坑——现象：新版生产者先上线并开始写新 provenance/新事件字段；后果：旧宿主在严格命令边界直接拒绝新 source/correlation 字段，事件已提交但无人能消费
- 决策：迁移与启动顺序固定为——先执行 xpert-project/migrations/20261006-project-task-runtime.sql，再执行 handoff/runtime-messaging/migrations/20261006-runtime-reliable-replies.sql，**然后启动新版宿主**；滚动时**先部署消费者，再部署生产者**；两份迁移均为加性、IF NOT EXISTS、可重复执行
- 背景约束：同类约束还有 20260922-conversation-branch.sql 与 20261005-message-envelope.sql 必须先于对应能力部署；仓库无统一 migration runner（由发布流程手工按序 psql 执行）
- 被否决方案：先部署生产者、后部署消费者（与文档要求相反）
- 重新评估触发条件：引入严格向后兼容的事件信封与灰度开关（旧宿主可忽略未知字段）
- 关联代码：runtime-messaging/migrations/20261006-runtime-reliable-replies.sql、chat-message/migrations/20261005-message-envelope.sql、chat-conversation/migrations/20260922-conversation-branch.sql
