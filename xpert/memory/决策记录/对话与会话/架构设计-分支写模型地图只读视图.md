【决策记录｜分支=写模型 / 地图=只读无表视图】
- 分类：架构设计
- 动机：避坑——现象：若把「脉络导航」做成持久化表；后果：每次会话/消息语义变化都要同步改两张表，且地图与真相可能漂移（还要承担迁移、回填与并发更新）
- 决策：**分支是写模型** —— ConversationBranchService.branch 在 dataSource.transaction 内对源线程 pessimistic_write 行锁，复制消息谱系（含 parentId/messageEnvelope/检查点/fileAssets 链接、重算 messageHash/messagePathHash）并写 branchSource 与 metadata.forkGraphRevision，requestId 幂等；**地图是只读视图** —— ConversationMapService 无 entity、无表、无迁移，scope() 做 host context 与 RequestContext 三重比对后 read/projectOptions/act，每次查询重算
- 背景约束：两者共用同一批实体却对一致性给出不同答案：分支用事务+行锁+检查点换可独立续跑（写放大、长事务）；地图用零表投影换免迁移与低耦合（读放大、依赖 view-extension 与 CONVERSATION_MAP_FEATURE / slot AGENT_WORKBENCH_SLOT）
- 被否决方案：无（未见为地图建表的正式否决记录；ConversationMapModule 确无 TypeOrmModule.forFeature）
- 重新评估触发条件：地图查询规模增长到每次重算不可接受；或宿主不再提供 view-extension Discovery
- 关联代码：conversation-branch.service.ts、conversation-branch.module.ts、conversation-map/service.ts、conversation-map/provider.ts、conversation-map.module.ts
- 证据来源：conversation-branch.module.ts 模块注释（callers use the command without importing this module）+ conversation-map.module.ts（无 forFeature）+ branch service 顶部不变量注释（明写）
