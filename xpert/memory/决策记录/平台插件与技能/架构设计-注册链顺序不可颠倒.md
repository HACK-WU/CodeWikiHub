【决策记录｜注册链顺序不可颠倒：先合并 ORM metadata → 再 lazyLoad → 最后注册路由与策略】
- 分类：架构设计
- 动机：避坑：先 lazyLoader.load() 再合并实体 → 插件 Repository 在活 DataSource 无元数据，任何查询立即 `EntityMetadataNotFoundError`；路由注册顺序错 → 插件 controller 挂到尾部 404 处理器之后，表现为「装成功但全 404」
- 决策：固定执行 ① collectPluginOrmMetadata + validatePluginEntityTableNames + registerPluginOrmMetadataInDataSource（声明 namespace 时表名前缀必须匹配 `plugin_<namespace>_`）② snapshotModuleIds / snapshotHttpRouteStack 后 lazyLoader.load ③ registerPluginControllerRoutes（把新 Express 层移到 404/错误处理器之前）+ registerInstalledPluginStrategies + 手动 onPluginBootstrap。注册只刷新 metadata，**DDL 由加锁的 schema preflight 独占**（Redis 锁 `xpert:plugin:schema-sync`）
- 背景约束：宿主无 migrations/ 目录（synchronize 式建表），插件实体只能运行期合并 + preflight 建表；重名实体直接抛 ConflictException，禁止静默覆盖宿主表
- 被否决方案：无（以不变量注释固定顺序）
- 重新评估触发条件：Nest 的 LazyModuleLoader 或 Express 栈结构变更导致 snapshotHttpRouteStack / moveNewExpressLayersAheadOfTailHandlers 失效；或引入按插件独立 DataSource
