【决策记录｜运行前置条件必须显式断言：SDK 兼容 + 无用户时必须显式 scope】
- 分类：接口契约
- 动机：避坑：插件把 @xpert-ai/plugin-sdk 写进 dependencies 或声明跨 major 的 peer range → 宿主与插件各持一份 SDK 实例，运行期出现类型与注册表分叉且难以定位；bootstrap 后台同步没有登录用户却按「当前用户为空」构造查询 → 跨租户泄漏或误改他组织资源
- 决策：① SDK 契约**显式断言**：包名不匹配、@xpert-ai/plugin-sdk 出现在 dependencies、artifactNamespace 嵌套与非嵌套值不一致等直接抛 PluginSdkValidationError；安装候选与已安装状态各有断言函数（assertPluginSdkInstallCandidate / assertInstalledPluginSdkCompatibility）阻断不兼容包；peer range 漂移以 warning 暴露在 PluginInstance.meta.sdkCompatibilityWarnings。② 无登录用户的同步路径必须显式解析 scope：tenantId 缺失直接 400，organizationId 为空时强制 `organizationId IS NULL`，**绝不发出无 scope 的管理查询**
- 背景约束：SDK 兼容只对「安装候选」硬阻断，运行期 peer range 漂移仅告警（仍赖插件自觉）；scope 解析依赖 RequestContext.getScope() 中存在已恢复的作用域
- 被否决方案：无（以断言 + 注释固定）
- 重新评估触发条件：出现插件在宿主内多实例 SDK 的真实事故（届时应把 peer range 漂移升级为阻断）；或需要支持跨租户后台运维视角（需新的显式 scope 凭证机制）
- 关联代码：plugin-sdk-versioning.ts、plugin-scope.guard.ts @ packages/server/src/plugin/ 与 shared/guards/；plugin-resource-installation-scope.ts @ packages/server-ai/src/plugin-resource/
- 证据来源：plugin-sdk-versioning.ts 的 PluginSdkValidationError 抛出点与 warnPluginSdkCompatibility；plugin-resource-installation-scope.ts:1-3 Why this exists（Never issue an unscoped management query when the tenant is missing.）
