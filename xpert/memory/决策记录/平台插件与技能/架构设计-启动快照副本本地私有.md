【决策记录｜启动快照副本本地私有，永不写回期望 DB 配置】
- 分类：架构设计
- 动机：避坑：上一次重启因某插件候选配置失败；若把「回滚」实现为改写期望配置 → 多副本各自回滚到不同状态、人工修复必须反写 DB，失败进程可能进入崩溃循环
- 决策：快照按副本（XPERT_INSTANCE_ID / HOSTNAME 派生）落在**本地**、权限收紧、内容用 `__xpert_plugin_encrypted__` 信封加密，且**永不写回期望的数据库配置**；未完成的候选 boot 只尝试一次，随后由 supervisor 恢复上次被接纳的配置；快照只恢复代码与配置，**DB migration 必须保持向后兼容**
- 背景约束：回滚后的旧代码会读新 schema，因此迁移不能依赖「只有新版代码理解」的列语义；恢复耗尽的进程以 keep-alive 阻塞而非崩溃退出
- 被否决方案：把快照内容或回滚结果写回期望 DB 配置（被 never change the desired database configuration 直接否定）
- 重新评估触发条件：引入集中式配置中心并需跨副本统一回滚；或决定允许破坏性迁移（须先取消本不变量并给出回滚窗口）
- 关联代码：plugin-startup-state.ts、plugin-startup-watchdog.ts @ packages/server/src/plugin/；runtime-plugin-admission.ts @ packages/server/src/runtime-control/
- 证据来源：plugin-startup-state.ts:1-4 三行不变量注释 + runtime-plugin-admission.ts（New/returning boots are fenced…，明写）
