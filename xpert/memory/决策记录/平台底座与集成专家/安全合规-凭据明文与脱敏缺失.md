【决策记录｜安全合规：凭据明文落库 + 脱敏只在出口】
- 分类：安全合规
- 动机（避坑）：**现象** `data_source_authentication.password` 是普通 text 列（无加密、无 `select:false`、无 `@Exclude`），`data-source.entity.ts` 里 `options` 上方的 `// @Exclude()` **处于注释态**，`prepareDataSource` 在 `authType=BASIC` 时还把当前用户 `username/password` **回写进 `options`** 后直接交给 runner；**后果** 任何新增读取面（关系展开、导出、日志字段、新 DTO）都会带出明文连接凭据，唯一兜底只剩库级权限
- 决策：本域不做应用层加密，改用「**出口收窄 + 白名单 DTO + 严格代理**」三层——① 只有 `GET /api/data-source`（列表）挂 `ClassSerializerInterceptor` + `DataSourcePublicDTO` 白名单（`options`/`authentications` 不下发）；② 插件侧唯一出口 `DataSourceRuntimeService.open` 要求 actor 三元组与 `RequestContext` 逐项相等、引擎白名单 `mysql|doris|postgres`、`engineCatalog==='internal'`、逐方法 `check(write)`，并用 `updatedAt` 做 revision 复核（源码逐字「Proxy preserves method receivers and never exposes resolved credentials or the runner.」）；③ 集成侧列表用 `IntegrationPublicDTO` 把 `options` `@Exclude()`
- 背景约束：**实测本批 14 表无任何加密列**（模块内 `encrypt|decrypt|cipher|AES` 0 命中；`core/utils/crypto.ts` 的 AES-256-GCM 工具注释写明用于 GitHub token，本域未调用）；`integration.options`（含 `botToken`）无任何隐藏并会进入 `hostSnapshot`；个人凭据 `validUntil = now + 30d` 硬编码且**无续期/失效路径**；`authType≠BASIC` 时账号密码由前端写进 `options`，换密必须同时改 `options`
- 失败面：`GET /:id`（可 `$relations=["authentications"]`）与 `GET /:id/authentication` 直出明文；`data_source.options` 默认出网；`integration.options.botToken` 经 `hostSnapshot` 进入插件 `context`（仅 `INTEGRATION_VIEW|INTEGRATION_EDIT` 兜底）
- 被否决方案：无（未见对「给凭据加列级加密 / 恢复 `@Exclude()`」的显式否决记录）
- 重新评估触发条件：新增任何 `options`/`password` 读取面（导出、事件、日志字段、`$relations` 展开），或合规要求「库内不可读」时——须改为列级加密 + `select:false`，并恢复注释态的 `@Exclude()`，同步复核 `DataSourcePublicDTO` 白名单与宿主快照
- 边界：本决策保护的是**回显**而不是**存储**；`desktop_shell_device.credentialHash` 是本域唯一「摘要而非明文」的凭据列，可作正例对照
- 对照口径：**不要按同批工具域经验推断本域有加密层**——工具域是 `mcp_api_key.keyHash + encryptedSecret`（`select:false`）三层脱敏，本域不成立
