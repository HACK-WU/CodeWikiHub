【决策记录｜架构设计：视图扩展点走宿主注册表 + 双失效缓存】
- 分类：架构设计
- 动机（避坑）：**现象** 宿主（如集成详情页）与视图（插件提供的卡片）若硬编码在服务端，每加一个宿主/视图都要改核心代码并重新发版；反之若完全不缓存，清单读取会按「宿主 × 插件」扇出、每次请求都穿透到全部 provider；**后果** 扩展点变成发版瓶颈，或热路径被插件扇出拖垮（实现层把 `listSlotViews` 与 initialization 作业、desktop-shell 巡检并列为热点路径）
- 决策：宿主走**装饰器 + 发现**注册（`@ViewHostDefinition('integration')` → `ViewHostDefinitionRegistry.onModuleInit` 用 `DiscoveryService` + `Reflector` 建表，新增宿主只需新增一个 provider 类）；视图走**插件注册表**（`ViewExtensionProviderRegistry`），解析链固定 `provider.supports(context) → readProviderViewManifests → normalizeManifest → isManifestActiveForContext → filterVisibleManifests → 按 order 排序`，单 provider 异常只 `logger.warn` 不影响整体；缓存以 `VIEW_EXTENSION_CACHE_SERVICE_TOKEN` 暴露（清单 60s、view data `min(ttlMs, 30s)`），**两条失效链**——实体级 `IntegrationViewHostCacheSubscriber`（insert/update/remove → `invalidateHostIdentity`）与全局 `StrategyBus.events$` → `clearAll()`，清单键并入 `features + hostState` 的 sha1 摘要
- 背景约束：控制器类级 `@Public()`，安全完全落在 `ApiKeyOrClientSecretAuthGuard` + `AllowClientSecretBindings(ENTERPRISE_XPERT)` 与宿主 `canRead`/manifest `permissions` 上（文件头逐字「Shared protocol routes; each entry point supplies its own authentication boundary.」）；`hostSnapshot` 会带出 `options.botToken`（仅 `INTEGRATION_VIEW|INTEGRATION_EDIT` 兜底）；注册表是**进程内内存**，插件升级/重装后必须重启宿主；remote component 强约束 `protocolVersion === 1` + `isolation === 'iframe'`，响应 `Cache-Control: no-store`
- 失败面与排障口径：`Unknown view host '<type>'`（注册表未命中，404）/ `View host … was not found`（`resolve` 回 null，404）/ 403「视图不显示」（`canRead` 或 manifest/action 权限不通过）；同键宿主**静默覆盖**、无冲突检测与卸载钩子
- 范围口径：`view-extension` **0 表**——本决策不引入任何新表，宿主事实在服务端对象、清单事实在插件、缓存事实在进程内
- 被否决方案：无（未见对「硬编码宿主/视图」的显式否决记录）
- 重新评估触发条件：出现第二个 `@ViewHostDefinition` 宿主、或要求插件热更新「不重启即生效」时——须把注册表改为可刷新，并复核缓存键与两条失效链是否仍覆盖新宿主
- 与插件域边界：本域只**消费** `ViewExtensionProviderRegistry`，不安装插件（安装归平台插件与技能专家）——排障「视图不显示」要先分「插件未装/未激活」与「宿主不可读」两类
