【决策记录｜可靠性-任务执行走派发账本与三唯一索引】
- 分类：架构设计
- 动机（避坑）：**现象** 先启动 Invocation 再落库，或在本域再造一份运行时账本、把派发意图/凭据序列化给任务视图；**后果** 崩溃后产生孤儿执行与重复启动，且凭据、路由与配置泄漏到读模型
- 决策：执行只走 `xpert_project_task_execution` 这一条派发账本——三个唯一索引（`invocationId`、`(projectId,createdById,dispatchRequestId)`、`(taskId,sourceKey)`）+ `dispatchState ∈ pending|submitted`；**先固化意图再启动**（注释逐字「commit the attempt and pinned intent before invoking an adapter.」）；`dispatchIntent` 为 `select:false` 的服务端恢复意图；运行时状态一律读投影，不落第二账本
- 派发顺序：授权 → 项目行锁 → 按 `(projectId,createdById,dispatchRequestId)` 查重放（同 id 但 `input`/`caller`/`replyTo.threadId`/`target` 任一不一致 → 409 `Conflict`）→ `expectedRevision` CAS → 生成 `specificationSnapshot` + digest → 前驱依赖与在途尝试门禁 → 写 `pending` + `dispatchIntent` → `submit` 启动成功后 CAS 成 `submitted`
- 背景约束（身份）：`invocationId = agentInvocationId(scope,'project-task:<requestId>')` 预先确定，**重放绝不新造 callId**（逐字「Replays keep the original scope; unknown or missing receipts never permit another launch」）；启动失败但已存在持久记录时返回该记录（逐字「A launch failure can already have a durable unknown receipt. Return that handle, not a retry hint.」）
- 背景约束（补偿）：`@Interval(5000)` 补偿扫描只重放 pin 住的意图（取 `dispatchState='pending' AND dispatchNextAttemptAt <= now` 前 20 条）；`dispatch_blocked` 为终态不再重试，`dispatch_unavailable` 60s 后重试
- 被否决方案：在本域再建一份运行时账本（注释逐字「Read projection from the associated Invocation, never a second runtime ledger.」）；把 `dispatchIntent` 序列化到任务视图（注释逐字「Server-only recovery intent; never serialize credentials, routing or configuration to task views.」）
- 重新评估触发条件：`dispatchIntent` 的 `select:false` 与补偿扫描强耦合——一旦引入备份/数据修复脚本或更换存储，必须先保证恢复链显式 `addSelect('attempt.dispatchIntent')`，否则 intent 解析失败直接归类 `Invalid`、补偿不可用
- 409 语义：`IDX_project_task_execution_dispatch` 命中但意图不一致 = **防护生效而非故障**；错误码规则为 `Scope→403`、`NotFound→404`、`Invalid→400`，其余一律 409（`Conflict`/`Busy`/`Dependencies`/`State`/`Owned`/`Evidence`/`DecisionRequired`）
