【决策记录｜租户设置请求级缓存】
- 分类：性能取舍
- 动机：优化、避坑：逐请求查设置表 → 放大数据库压力
- 决策：TenantSettingsMiddleware 以 forRoutes('*') 覆盖所有请求，按 tenantSettings_租户id 缓存 5 分钟并挂到 request.tenantSettings；同时保留直读数据库的接口（GET /api/tenant-setting）；写路径不失效缓存（牺牲一致性换吞吐）
- 背景约束：设置被多个模块按请求读取；中间件覆盖全部 HTTP 请求
- 被否决方案：无
- 重新评估触发条件：出现「设置变更需秒级生效」的需求（写路径开始 bump 版本或清缓存）
- 关联代码：TenantSettingsMiddleware.use @ packages/server/src/tenant/tenant-setting/tenant-settings.middleware.ts；TenantSettingService.saveSettngs @ packages/server/src/tenant/tenant-setting/tenant-setting.service.ts
- 证据来源：tenant-settings.middleware.ts JSDoc（明写 Cache TTL: 5 minutes）
