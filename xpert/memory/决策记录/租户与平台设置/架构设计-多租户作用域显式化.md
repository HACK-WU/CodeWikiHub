【决策记录｜多租户作用域显式化】
- 分类：架构设计
- 动机：优化、避坑：用 organizationId 空值承载作用域语义 → 接口语义歧义与越权风险
- 决策：请求作用域由 RequestScopeContext{tenantId, level, organizationId} + X-Scope-Level 头显式表达（兼容旧 Organization-Id）；资源按 tenant-owned / organization-owned / inheritable 三分类（assistants、features、plugins 归 inheritable）；organizationId 为空只是存储层兼容表示，不得上浮到 UI/接口语义；tenant scope 仅 super admin
- 背景约束：既有数据以 organizationId 空值落库；前端已在发 Organization-Id 头，需兼容存量客户端
- 被否决方案：以 organizationId 空/非空直接承载作用域语义——否决理由：空值会被误解为无归属资源
- 重新评估触发条件：出现需要跨组织共享的新资源类型，或接口不再接受 Organization-Id 头
- 关联代码：RequestScopeContext（docs/plans/PLAN_isolate_tenant_org.md 提案）、FeatureOrganizationService.updateFeatureOrganization @ packages/server/src/feature/feature-organization.service.ts
- 证据来源：docs/plans/PLAN_isolate_tenant_org.md（明写）
