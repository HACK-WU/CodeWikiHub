【决策记录｜草稿优先投影与发布广播】
- 分类：其他（数据一致性——ki 原记录分类为「数据一致性」）
- 动机：ki 明写背景约束——编辑态与运行态隔离（已发布版本是运行时对象），管理页与 Studio 都展示草稿形态；发布是低频显式动作，订阅方即时刷新、不轮询
- 决策 1：XpertService 订阅回调 latestXpert.set(value) + xpert.set(value.draft?.team ?? value)——存在草稿时展示草稿形态；投影只做一层回落、不深合并；latestXpert 保留完整响应（含 draft/graph/version）
- 决策 2：发布感知走内存事件 published$（Subject<IXpert>）——Studio 发布成功 xpertService.published$.next(result)，知识库流水线订阅后 knowledgebaseComponent.refresh()
- 背景约束：写后须显式 refresh() 才更新（无自动失效订阅）；published$ 不跨标签页、不重放（晚订阅者收不到）；XpertService 为组件级 provider，发布方与订阅方须在同一作用域（全仓仅一对 emit/subscribe）
- 被否决方案：无（ki 未记录「管理页固定已发布版 / 轮询 / 服务端推送」方案的评审痕迹）
