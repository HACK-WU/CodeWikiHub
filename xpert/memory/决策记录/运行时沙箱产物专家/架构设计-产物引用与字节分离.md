【决策记录｜架构设计-产物引用与字节分离（表内只存可移植引用）】
- 分类：架构设计
- 动机（避坑）：**现象** 产物既有字节（可能很大）又有元数据与访问策略，若把字节写进表、或把主机绝对路径写进列；**后果** 数据库被大对象撑爆、备份与迁移成本失控，且一旦 `workspacePath` 类字段泄露就暴露宿主文件系统布局（注释逐字：without leaking host filesystem paths）；另一侧，Agent/插件重试会重复登记同一产物，幂等只做在应用层「先查后写」在并发下会建出多个同源容器与重复版本
- 决策：**字节与引用分离 ＋ 幂等交给数据库** —— `artifact_version.workspaceFileRef`（json **非空**）只存指向 Workspace Files 卷的可移植引用，字节由 `WorkspaceFiles.uploadBuffer(artifact-snapshots/uuid)` 落卷；读取时经 VolumeClient 还原，并在**读取期**重算 `sha256` 复核（不符即拒绝、记 `denied`、返回 410/409），把「内容正确」的验证成本从写入期推到读取期
- 决策（幂等三处）：`artifact` 用 **4 条部分唯一索引**（按 `organizationId`/`userId` 是否 NULL 切分同一业务约束）保证「同来源同作用域只有一个容器」，应用层 `findExistingArtifact` 命中即复用行并把 `status` 复位 `active`；`artifact_version` 用 `['tenantId','organizationId','artifactId','versionNumber']` 抗版本号并发、`['artifactId','idempotencyKey']` 抗重放（`ensureArtifactVersionWithDefaults` 强制 `idempotencyKey`，返回 `created|reused`）；`artifact_link` 用 `slug` 唯一 ＋ 部分唯一（`status='active'` 的 `shareKey`）保证 URL 稳定且同 key 同时只有一条有效分享
- 背景约束：`artifact_version` **版本不可变**（改内容只能新增版本，展示策略改在 `artifact_link`）；`artifact_link.versionMode`（默认 `latest`）决定链接指向哪一版；分享响应固定附带 `X-Xpert-Artifact-Version`/`X-Xpert-Artifact-SHA256`，`text/html` 额外下发 CSP（`strict`/`interactive` 两档 profile）；`artifact_access_log.artifactId` 与 `workspaceFileRef` 均**无外键**，是刻意的弱引用
- 被否决方案：无（未见对「仅应用层去重」「允许同名重复容器」或「字节入表」的显式否决记录）
- 重评条件：需要同一来源多容器（多环境/多版本并存）、要引入对象存储直传，或大产物读取的内存峰值（整文件读入 ＋ sha256）不可接受时
