【决策记录｜架构设计-门面信号聚合与伴生态】

- 分类：架构设计
- 动机：项目工作区六个子页共享同一棵「项目 → 计划/任务/资产/会话/自动化」数据，需要一处可订阅的聚合面，页面不该直连 API 各自维护加载态
- 避坑（现象→后果）：无序号守卫时旧列表响应会覆盖新建项（刚建的项目在列表里消失）；只读 `loading` 而漏掉详情态伴生态会得到错误的空壳；overview 等可选数据失败若上抛会让整壳白屏
- 决策：页面只读 `XpertProjectFacade` 信号——主聚合按页面分区（projects/project/plans/tasks/conversations/assets/activities/automations/scheduledTasks/projectInstruction/projectSkills/projectAccess），伴生态严格成对（loading/error、projectLoading/projectError、conversationsLoading/conversationsError、assetsLoading/assetsError）+ `projectContentError` 合并指令与技能两路 `allSettled` 失败；写路径统一「先打服务端、成功后局部回填」，不做乐观写
- 背景约束：`loadProject` 先清空全部聚合子集再拉主记录，主记录到手即以 `#projectLoadSequence` 守卫并发派生 overview/content/access/scheduledTasks 并丢弃过期响应；`loadProjects` 用 `#projectsLoadSequence`，`createProject` 主动自增序号；overview 失败被静默吞掉；`assetsTotal` 与 `assetCount` 语义不同（后者仅根查询更新）；对话框族经 `DIALOG_DATA`/`input()` 直连 API，不做门面中转（两大刻意例外之一）
- 被否决方案：无
- 重新评估触发条件：出现跨项目/跨页共享实例的缓存需求，或需要离线、弱网与乐观写的体验；复跑测试基线（13 spec 中 4 PASS / 9 FAIL 为 `@xpert-ai/store` 缺依赖的环境级「整文件加载失败」，须先 `corepack pnpm install`）
