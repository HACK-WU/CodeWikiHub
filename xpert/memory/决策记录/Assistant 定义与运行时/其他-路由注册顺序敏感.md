【决策记录｜路由注册顺序敏感：同方法同 URL 只允许一个 controller】
- 分类：其他（工程纪律）
- 动机：避坑——两个真实控制器同时注册 GET /ai/conversations/:conversationId/files 时命中前者（FileAsset 附件列表）返回空数组，现象是「文件存在但列表为空」，后果是功能静默失效且无编译期错误
- 决策：约定唯一注册——FileAsset 保留 /api/ai/conversations/:id/files，Workbench 运行目录整体迁到 /api/ai/conversations/:id/workspace/*，只保留不冲突的旧单数路由；xpert-sdk-js 客户端同步采用新路径；新增 controller 时必须按「同路径不同 controller」排查冲突
- 背景约束：Nest 不做冲突检测；企业 H5 与创作用面 URL 首段同为 xpert 但深度不同（EnterpriseChatkitModule 无 RouterModule.register），按首段聚合路由白名单的网关会把 @Public() 企业端点误判为创作用面
- 被否决方案：无
- 重新评估触发条件：xpert-sdk-js 或外部消费者仍调用旧路径且无法升级（判据：旧路由出现真实调用量）
