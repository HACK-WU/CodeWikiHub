【决策记录｜草稿与发布态隔离：统一「仅草稿保存」】
- 分类：兼容处理（数据一致性口径）
- 动机：避坑——发布后的版本是运行时对象（对话与调用按版本运行），半成品编辑若直接落 graph 会污染正在跑的版本
- 决策：编辑先入 Xpert.draft，1s 去抖自动 POST /api/xpert/:id/draft；只有 publish 才把草稿固化为版本行（XpertPublishHandler 写 graph 并置 draft=null）；前端 resume() 可丢弃草稿回到已发布版本
- 背景约束：saveDraft 与 updateDraft 语义刻意分开（PUT :id/draft 只在 body 命中 nodes/connections 时才覆盖图字段）；**已知例外**：POST :id/configuration 会顺带 publish(newVersion=true)，与整体取向相反
- 被否决方案：无可追溯记录
- 重新评估触发条件：出现实时协同编辑，或「逐次编辑生成审计版本」的需求
- 关联代码：xpert.service.ts（saveDraft/updateDraft）、commands/handlers/publish.handler.ts、configuration/assistant-configuration.service.ts
