【决策记录｜邀请接受拆三条公开路径】
- 分类：接口契约
- 动机：无
- 决策：邀请接受按接受者类型拆为三条 @Public 路径（/api/invite/user、/employee、/contact），创建侧（/api/invite/emails）受 ORG_INVITE_EDIT 权限点保护；三条路径均以「注册新用户」为前提，各自落不同归属（成员关系 / 仅状态 / 新建租户+组织+联系人）
- 背景约束：被邀请人此时尚未登录，无法过认证守卫；三条路径的业务后果差异大（联系人路径会新建租户）
- 被否决方案：无
- 重新评估触发条件：出现「已登录用户接受邀请」的统一入口需求，或需要把三条路径合并为单一契约（如引入邀请 token 统一载荷）
- 关联代码：InviteController.acceptUserInvite / acceptEmployeeInvite / acceptOrganizationContactInvite @ packages/server/src/invite/invite.controller.ts；invite/commands/handlers/{invite.accept-user,invite.accept-employee,invite.accept-organization-contact}.handler.ts
- 证据来源：invite.controller.ts 的 @Public 标注与三个 handler 的 docstring（明写步骤；accept-employee 的 employee 创建整段被注释，属实现与文档不一致）
