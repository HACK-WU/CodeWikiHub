【决策记录｜入站凭据固定为五种】
- 分类：技术选型
- 动机：无
- 决策：入站凭据按用途拆分为五类并各自维护入口：① 登录 JWT + refresh（jwt / jwt-refresh / ws-jwt / basic）② x-api-key 长期 API key ③ x-client-secret 或 Bearer cs-x- 的短期 client secret（按绑定类型分派）④ 出站 actor token（typ:'actor'，TTL 封顶 900s）⑤ 外部身份绑定。所有入站凭据最终归一为 User 或 IApiPrincipal 两种主体
- 背景约束：既有浏览器会话、第三方长期调用、短时委托会话与无用户上下文的出站归因；createdById 单字段无法区分「API-key 授权 / 委托用户会话 / 公开助手会话」（docstring 明写）
- 被否决方案：无
- 重新评估触发条件：出现新凭据形态需求（如标准 OAuth2 客户端凭据流），或下游重新出现直接读 apiKey.type / entityId 做资源判定的代码（代码扫描命中数回升）
- 关联代码：IApiPrincipal @ packages/contracts/src/api-key.model.ts；SecretTokenBindingType @ packages/contracts/src/secret-token.model.ts；SecretTokenStrategy.authenticate @ packages/server/src/secret-token/secret-token.strategy.ts；LocalOutboundActorTokenProvider.mint @ packages/server/src/actor-token/outbound-actor-token.provider.ts
- 证据来源：packages/contracts/src/secret-token.model.ts 与 api-key.model.ts 的 docstring（明写）；docs/plans/PLAN_api_principal_identity.md（明写）
