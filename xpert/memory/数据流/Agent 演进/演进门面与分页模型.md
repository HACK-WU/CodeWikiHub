【数据流｜演进门面与分页模型】
- 实体类型：前端模型（signal / computed 聚合体，无本地持久化、无 NgRx）；服务端投影为 `@xpert-ai/contracts` 的 EvolutionLifecycleRecord / EvolutionChange / LearningEvent / EvolutionCandidate / ReleasePackage 等
- 结构（聚合体）：`AgentEvolutionDashboard` 17 数组字段（targets、versions、bundles、events、diagnoses、clusters、experiences、proposals、candidates、datasets、evaluations、approvals、releases、deployments、pointers、audits、canaryTestOverrides），初值 `EMPTY_EVOLUTION_DASHBOARD`
- 结构（分页与空态）：`eventPage` / `candidatePage` / `releasePage`（`EvolutionPage<T>`，初值私有 `EMPTY_PAGE = { items: [], total: 0, page: 1, pageSize: 20 }`）；「已加载」判据是 `loadedAt() !== null`，不是长度或 pageSize
- 结构（状态与失败面）：`providerError`（string|null，仅变更源失败）/ `error`（其余端点与写操作失败，带 toastr）/ `loading` / `synchronizing` / `mutating` / `activeJob`
- 生产方：`AgentEvolutionApiService`（`API_AGENT_EVOLUTION` 唯一 HTTP 出口）→ `AgentEvolutionFacade.load()` 17 路 Promise.all 聚合；`refreshChanges()` 4s 轮询只刷 /changes + /changes/records；`loadLearningEvents()` 单独推进 eventPage 并同步 dashboard.events
- 主要消费方：壳（tab / 目标选择 / 夹具开关 / 轮询）、overview / targets / learning / evaluation / release 五页、changes/change-panel 与 shared 变更选择器；evaluation 与 release 页另消费 `providerError`（role="alert" 横幅）
- 业务用途：把「学习信号 → 改进提案 → 候选版本 → 评估审批 → 发布（安装/影子/金丝雀/生产）→ 效果与回滚」闭环聚合成一份可读快照，并驱动治理动作的前端编排与呈现
- 关键约束：三个分页对象必须与 dashboard 同批赋值（只改一处 ⇒ 列表/统计/图表不同源）；computed 依赖（contextLifecycleRecords 四依赖）须走 set/update，原地 mutate 不触发刷新
- 详细流向：见 .module-experts/前端专题/Agent 演进专家/implementation/01-架构.md（关键设计约束与不变量、架构总览图）与 C1-能力契约.md（§1.1 / §1.3）
