【数据流｜事件入边十条】
- 实体类型：**接口面（命令/查询）而非表** —— 10 组入边全是 CQRS 命令/查询注入；本域**发出 0 条**（`file-understanding` 无 `.publish(`/`@EventsHandler`）；`file-memory` 唯一出站是 Dream 的 `XpertAgentChatCommand`（→ XpertAgentModule 的 dreamer）
- 入边 #1 AIModule（`ai/context.controller.ts`）：`CreateFileAssetCommand`、`EnqueueFileParseCommand`、`GetFileAssetByStorageFileQuery`、`DeleteFileAssetCommand` —— 上传落地句柄、启动解析、按 storageFile 反查、删除资产
- 入边 #2 XpertModule（`chat-file-assets.ts`）：`AssertFileUploadScopeQuery`、`GetOwnedStorageFileQuery`、`GetFileAssetByStorageFileQuery`、`ResolveAuthorizedFileAssetQuery`、`CreateFileAssetCommand`、`CreateWorkspaceFileAssetCommand`、`EnqueueFileParseCommand`、`AttachFileToConversationCommand` —— 对话输入文件归一（storageFileId / workspacePath / data URL 三形态，上限 `MAX_INLINE_PARSE_BYTES = 2_000_000`、`MAX_DATA_URL_BYTES = 25 * 1024 * 1024`）
- 入边 #3~#5 会话与消息面：ChatConversationModule（`GetFileAssetByStorageFileQuery`/`GetOwnedStorageFileQuery`/`ResolveAuthorizedFileAssetQuery`，解析会话附件与工作区相对路径）、ChatMessageModule（历史消息附件回读，供重试重建输入）、ChatModule（执行期附件句柄校验）
- 入边 #6~#7 项目面：XpertProjectModule（`GetOwnedStorageFileQuery`/`AttachFileToConversationCommand`）、XpertProjectAccessModule（经 `FileAssetAccessService` 注入 `XpertProjectAccessService.assertCanEdit/assertCanPurge`，作为 attach/purge 的写边界判定）
- 入边 #8~#10 运行时与消息组装面：FileRuntimeModule（`ResolveAuthorizedFileAssetQuery`/`GetOwnedStorageFileQuery`，实现 `AgentMiddlewareFileApi.resolveFile`）、shared/runtime 工作区文件能力（`CreateWorkspaceFileAssetCommand`/`GetFileUnderstandingStatusQuery`/`EnqueueFileParseCommand`/`SearchFileChunksQuery`/`ValidateFileUnderstandingReferencesQuery`/`ResolveAuthorizedFileAssetQuery`）、shared/agent ＋ shared/commands（`ResolveAuthorizedFileAssetQuery`/`ReadFileAssetSourceQuery`/`GetFilePreviewQuery`/`GetOwnedStorageFileQuery`）
- 生产方：上列各跨域模块（依赖方向单向清晰：会话/项目/知识库/运行时 → 本域）；主要消费方：本域 10 组 handler（`file-understanding/commands/handlers/index.ts`、`queries/handlers/index.ts`）
- 用途：让同一批文件资产被六类调用方共享时，**租户/组织过滤与 `resolve` 授权只有一份** —— 若各调用方直连实体或自建查询，授权会被复制并迅速发散（绕过 `resolve` 直查仓储即越权），删表/改列的影响面也不可枚举
- 边界（本域不发事件）：需要「资产删除后通知下游重索引」时必须先定义事件契约，否则下游只能轮询或依赖已知缺口；漏订阅表现为「调用方报 DI 找不到 handler」或功能静默缺失
- 边界（未定位项）：`EnterpriseChatkitModule` 与 `SuperAdminOrganizationScopeModule` 两组的独立调用点**本轮未定位**（按索引保留）
- 跨域只读依赖窄面：`knowledge-document/document.service.ts` 三处与 storage 加载类 handler 两处都只用 `GetOwnedStorageFileQuery` 取句柄，**不反向持有本域实体**
