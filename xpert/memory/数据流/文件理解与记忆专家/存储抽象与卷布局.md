【数据流｜存储抽象与卷布局】
- 实体类型：表 ＋ 卷（`storage_file` 索引行 1 张 ＋ 对象存储/卷上的字节与派生目录；`storage-file` 21 非 spec / 1 spec / **1 张表**）
- 结构 `storage_file`：`file`(NOT NULL，对象存储 key)、`url`、`thumb`、`originalName`、`encoding`、`recordedAt`(timestamptz)、`deletedAt`(timestamptz，**删除路径未使用**)、`size`(默认 0)、`mimetype`、`storageProvider`(varchar，`@Exclude({toPlainOnly:true})` 不对外序列化)；**无自定义索引、无唯一约束**（继承基类 `tenantId`/`organizationId` 索引与 FK CASCADE）；非持久字段 `fileUrl`/`thumbUrl`（`afterLoad` 动态补，`thumbUrl` 已注释停用）
- 结构（易踩点）：`recordedAt` 是 `timestamptz` 列却用 `@IsNumber` 校验（与列类型不一致，**未确认**是有意还是笔误）；校验装饰器密度是本域最高的一张表
- 结构（卷布局约定）：对象存储 key 强制 `<directory>/<tenantId>/<fileName>`（`assertContainedInTenantDirectory` 断言不越界；目录/文件名分别 `normalizePathSegment`/`normalizeRelativePath` 归一与拒 `..`）；上传默认 `contexts/<tenantId>/files-<ts>-<rand><ext>`；解析派生物统一 `contexts/<tenantId>/file-understanding/<assetId>/<parseRunId>`（`parseRunId` 每轮 `randomUUID()`）；记忆库 `.xpert/memory/**`
- 生产方（唯一写入点）：`StorageTargetStrategy.upload`（`@FileUploadTargetStrategy('storage')`）→ `provider.putFile` ＋ `StorageFileService.createStorageFile`（写行 ＋ `normalizeStorageProvider` 归一为大写、缺省回落 `LOCAL`）；其返回值 `referenceId` 即 `storageFile.id`
- 主要消费方：`FileAssetAccessService`（句柄解析）、`ParseFileAssetHandler`（`provider.path(file)` 取源，无 storageFile 时退回卷快照）、加载类 handler（`GetOwnedStorageFileQuery`）、`StorageFileSubscriber`（`afterLoad` 补 `fileUrl`；`afterRemove` 删 `file`/`thumb` 物理对象）、知识库（只取源句柄，不共享解析结果）
- 用途：把「对象存储里有什么」与「字节句柄 ＋ 理解状态」分开 —— 注释逐字「StorageFile owns object storage; FileAsset owns parser status, capabilities, context links, and workspace projection metadata.」⇒ 任何「文件内容问题」改 `file_asset`，「字节问题」改 `storage_file`
- 边界（静默回落）：`FileStorage.getProvider(name)` 先查 `FileStorageRegistryBridge` 注册表，**失败静默回落内置 LOCAL**（注释：Fall back to built-in providers so bootstrap/tests without Nest context keep working.）⇒ **排障时不要据此判断真实 provider**；真实名字来自租户设置 `fileStorageProvider` 或 `environment.fileSystem.name`；仓库内只有 LOCAL 实现，S3/OSS 经 `@FileStorageProvider` 外部插件注册（**未在仓库中找到实现**）
- 边界（删除与孤儿）：`storage_file` 删除走 `repository.remove`（**硬删**，注释说明为触发 `afterRemove` 的 entity 参数），`deletedAt` 列保留但无软删写入点；派生目录 `fsPromises.rm` **仅当 `provider.path()` 返回绝对路径（本地 provider）** 才执行，远端 provider 只剩 DB 删除 ⇒ 孤儿对象；页图/目录删除失败一律 `catch(() => undefined)` 静默
- 用途与消费边界：投影 `workspacePath` 供沙箱/运行时只读消费（`view_image` 等按 POSIX 相对路径取用）；`file_chunk`/`file_artifact` 等只按 `fileAssetId` 过滤，**行级租户隔离完全依赖上游 `FileAssetAccessService`**
