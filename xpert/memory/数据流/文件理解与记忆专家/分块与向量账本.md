【数据流｜分块与向量账本】
- 实体类型：表（索引与授权三张：检索/读取单元 ＋ 引用锚点 ＋ 向量账本；三张均**无唯一约束、无外键**）
- 结构 `file_chunk`（检索与读取单元）：`fileAssetId`(NOT NULL)、`artifactId`(可空)、`orderNo`(默认 0)、`content`(text NOT NULL)、`tokenCount`(默认 0)、`anchor`(json，含 `chunk` 序号)、`metadata`(json，含 `artifactKind`)；索引 `['fileAssetId']`、`['artifactId']`
- 结构 `file_citation_anchor`（引用锚点目录）：`fileAssetId`、`artifactId`(可空)、`chunkId`(可空)、`anchorKey`(NOT NULL，形如 `page:1:chunk:0`/`sheet:…`/`slide:…`/`path:…`，无锚点时 `chunk:<n>`)、`label`、`locator`(json=FileAnchor，含 `page`/`sheet`/`slide`/`path`/`rowStart`/`rowEnd`/`chunk`/`label`)、`metadata`(json)；索引 `['fileAssetId']`、`['anchorKey']`（**非唯一**）
- 结构 `file_embedding`（向量**账本**）：`fileAssetId`、`chunkId`、`provider`、`model`、`vectorId`、`metadata`(json，含 `collectionName`/`fingerprint`/`dimensions`)；**无向量列**；索引 `['fileAssetId']`、`['chunkId']`
- 生产方：`IndexFileChunksHandler`（开头**先删** anchors/embeddings/chunks，对 8 类 `CHUNKABLE_ARTIFACT_KINDS`（text/page_text/sheet/slide/table/code_tree/file_manifest/ocr_text）按 **3600 字符 / overlap 240** 切块，`anchor.chunk` 记顺序号，`rebuildCitationAnchors` 重建锚点）；`FileUnderstandingVectorService.indexChunks`（`addDocuments({ids: chunk.id})`，集合名含 scope 与 fingerprint）
- 主要消费方：`SearchFileChunksHandler`（有 query 时向量召回 ＋ 关键词 `ILIKE`（最多 6 token）经倒数排名融合 `1/(60+rank)`；无 query 纯顺序列举）、`ReadFileChunkHandler`、`GetFilePreviewHandler`、`GetFileUnderstandingStatusHandler`（计 `indexedChunkCount`）、`searchChunkIds` 交叉过滤、删除链
- 用途：把「解析产物」切成模型可读窗口（chunk）＋ 媒体可引用坐标（anchor）＋ 可核对账本（embedding），使检索结果可回溯到页/表/幻灯片/路径，并让「索引完整度」可判定
- 检索上限口径：`limit = min(max(limit ?? 8, 1), search ? 30 : 101)`（有 query ≤30，顺序列举 ≤101）；工具面 `parsed_file_read` 明示「缺 chunk 是终态 not-found，禁止靠递增 `orderNo` 反枚举探测」
- 边界（删除顺序）：**向量本体不在本域** —— 账本只记 `vectorId` 与集合元数据，因此删除必须「先删库、再删账本」（`deleteFileVectors` 在 `cleanup` 序列最前）；`anchorKey` 无唯一约束，重放安全靠「先删后建」
- 边界（未确认项）：`file_citation_anchor` 的**生产读取点未找到**（是否死表**未确认**）；`file_embedding` 的向量集合所在 RagVStore 归邻域 rag-vstore
