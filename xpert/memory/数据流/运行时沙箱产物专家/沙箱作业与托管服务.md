【数据流｜沙箱作业与托管服务】
- 实体类型：表（沙箱自建 2 张：执行账本 ＋ 运行时快照；均 `extends TenantOrganizationBaseEntity`，隔离键是租户＋组织）
- 结构 `sandbox_job`（Provider 无关的沙箱执行证据）：唯一 `['tenantId','idempotencyKey']`；索引 `['tenantId','status','hardDeadlineAt']`（扫孤儿）、`['tenantId','businessResourceType','businessResourceId']`（按业务资源反查）；`status ∈ waiting|starting|running|succeeded|failed|cancelled|lost`、`attempt`(int 默认 0)、`cleanupPending`(bool 默认 false)/`cleanedAt`、`errorCode`/`errorMessage`(text)、`hardDeadlineAt`/`startedAt`/`finishedAt`；`runtimeProfile`/`sandboxRuntimeVersion`/`action`/`actionVersion`/`pluginName`/`provider`/`runtimeBindingId`/`runtimeArtifactKind|Reference|Digest`；json `progress`/`outputs`；**`containerRef` 已 `@deprecated`**
- 结构 `sandbox_managed_service`（会话/线程内后台托管服务）：唯一 `['conversationId','name']` ＋索引 `['conversationId']`；FK `conversationId → ChatConversation` **onDelete: CASCADE**；`provider`/`name`/`command`(text)/`workingDirectory`(text)/`requestedPort`/`actualPort`/`previewPath`(text)；`status ∈ starting|running|stopping|stopped|failed|lost`、`transportMode ∈ none|http`、`ownerExecutionId`/`ownerAgentKey`（**字符串弱引用、无 FK**）、`startedAt`/`stoppedAt`/`exitCode`/`signal`；json `runtimeRef`/`metadata`
- 生产方：`SandboxJobRuntimeCapabilityService.run/cancel`（`prepareAttempt` ＋ 状态回写；经 `@RuntimeCapabilityProvider('platform.sandbox.jobs')` 暴露，**不走 HTTP 控制器**）、`cleanupOrphans`（60 秒间隔扫 `hardDeadlineAt < now` 与 `cleanupPending:true`）、`SandboxManagedServiceService.startByConversationId/startByThreadId`（经 `NsjailSandbox.startService` 的 `onStateChange` 反复覆盖快照）
- 主要消费方：同能力的 `getJob`/`getActionHealth`（插件按 `jobId` 回读）、`waitForAttachedJob`（重启后同幂等键的 waiting/starting/running 会被重挂）、`requirePreviousAttemptCleanup`（清理未成功前拦住新尝试）；`SandboxManagedServiceService.listBy*/getBy*/getLogsBy*/proxyByConversationId`、`SandboxPreviewSessionService.createSession`（读 `previewUrl` ＋ `transportMode`）
- 用途：`sandbox_job` 是幂等、重挂、审计、取消与孤儿清理的**唯一执行账本**（插件业务状态仍在插件自己的表里）；`sandbox_managed_service` 是 dev server 类托管服务的台账与预览入口，语义是「最后一次观测」而非历史
- 写法口径：两表**只增改、从不显式 delete**（托管服务行随会话 CASCADE 删除）；`sandbox_managed_service` 的状态/端口/`runtimeRef` 被 `onStateChange` 反复覆盖；`sandbox_job` 的 `progress`/`status`/`cleanup*` 全靠 `update` 回写
- 边界：状态枚举与 `transportMode` 全为 varchar、**无 DB 级 enum/CHECK**（合法性靠 TS 联合类型与服务层）；`sandbox_job.outputs`（json）只含 `destination.folder` 等路径元数据，输出文件本体如何从卷回收**未确认**；托管服务日志在 `.xpert/managed-services/<id>/{stdout,stderr}.log`
- 弱引用清单：`sandbox_job.runtimeArtifactKind|Reference|Digest`、`sandbox_job.runtimeRef`、`sandbox_managed_service.ownerExecutionId`/`ownerAgentKey` —— 任一改名都会让「孤儿托管服务反查」失效
