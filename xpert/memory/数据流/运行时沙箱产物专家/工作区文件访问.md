【数据流｜工作区文件访问】
- 实体类型：**无表** —— 会话与授权全在 Cache（`cacheManager`），身份由 `JWT_SECRET` 签名的 JWT cookie 承载；`workspace-file-access` 实测 8 非 spec / 2 spec / **0 张自建表**
- 结构（两段式之一 · 查看会话）：`createSession` ＝ `resolveViewFileAccessContext` ＋ `assertAssistantFileAccess`，记录「看哪个 View、哪个宿主、哪个运行范围」（tenant/组织/用户/host/view/dataScope），写 cookie `xpert_workspace_file_access`，Cache TTL 1 小时（`WORKSPACE_FILE_ACCESS_TTL_MS`）
- 结构（两段式之二 · 授权 grant）：`createGrant` ＝ `requireAuthenticatedSession` → `resolveViewFileResource` → `assertContextMatchesSession`（与 session 逐维完全一致）→ `assertPortableReference`；记录的是**单文件的可移植引用 ＋ 用途**，TTL = `expiresAt - now`（**跟 session 走，不独立续期**）
- 结构（路径解析）：grant **不存主机路径** —— 读取时 `resolveAuthorizedFile` 先 `resolveWorkspaceVolumeScope(grant.reference,…)`（该函数自 `file-understanding` 导入）再 `volumeClient.resolve(...)`；`fileName` 只参与匹配、**不参与拼路径**
- 生产方：`WorkspaceFileAccessController.createSession/createGrant/revokeSession`（POST `/api/workspace-files/view-sessions`、POST `…/:sessionId/grants`、DELETE `…/:sessionId`；四条管理路由走全局 `AuthGuard`）
- 主要消费方：`WorkspaceFileContentController.streamContent/headContent`（GET/HEAD `/api/workspace-files/content/:sessionId/:grantId/:fileName`，**类级 `@Public()` ＋ `WorkspaceFileAccessGuard`**，另做 `assertRequestOrigin`）、管理下载 `GET …/grants/:grantId/content/:fileName`（登录态，`StreamableFile` ＋ `Cache-Control: private, no-store`/`nosniff`）
- 用途：让同源 iframe / 附件流在不带 `Authorization` 头的场景下，仍能按「会话 ＋ 单文件短时授权」拿到卷内字节，同时**不向客户端暴露主机路径**
- 边界（易失）：进程重启即全部失效、多副本不共享；失效会话/授权一律 404（避免探测存在性）；origin 校验对「同源 iframe fetch 无 Origin/Referer」与「下载附件流」有显式放行分支，其余 403 `Error.WorkspaceFileAccessDenied`
- 边界（实现分散）：cookie 手工解析在 `workspace-file-access.guard.ts`、`sandbox-preview-auth.guard.ts` 与 terminal 守卫中各写一份 —— **改协议易漏改**
