【数据流｜跨域注册的 8 张表（归属判断陷阱）】\n- 实体类型：本模块 `forFeature` 注册或 `manager.getRepository` 直读、但**物理归属在别处**的表\n- 清单与影响：\n  - `agent_runtime_delivery`：**`forFeature` 注册** + 由本模块暴露 `RuntimeDeliveryController`；物理在 `handoff/runtime-messaging`，投递/消费收据语义属「对话与会话专家」，本域只保证相邻 CAS 与账本不变量\n  - `agent_runtime_inbox`：`forFeature` 注册；物理同上；inbox 认领与 `consumer_outcome_unknown` 处置**不归本域**\n  - `user` / `user_organization`：`forFeature` 注册（交付/收据 owner 解析）；25 / 13 个模块共同引用，**不能**作为归属依据\n  - `chat_conversation_thread` / `chat_conversation`：未注册，**直读**（判定阻塞/回写线程）；归属「对话与会话专家」\n  - `xpert_workspace`：未注册，**直读**（校验 workspace 归属）；归属「Assistant 定义与运行时专家」\n  - `xpert_project`：未注册，**直读**（校验 `project_agent` 作用域）；归属项目域\n- 判断影响小结：① 「注册方」≠「物理归属」② 「直读方」≠「拥有方」③ 公共表被多模块共同注册，任何按注册方推断归属的结论都不可靠\n- 详细流向：见 .module-experts/后端专题/Agent 执行链专家/C4-数据流向与消费.md §6（含逐表影响表）
