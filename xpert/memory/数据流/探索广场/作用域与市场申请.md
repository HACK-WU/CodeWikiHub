【数据流｜作用域与市场申请】
- 实体类型：前端模型（signal / 服务端投影联合）；本域无实体持久化，市场与申请形状来自 `@xpert-ai/contracts`（IXpertMarketplaceItem / IXpertAccessRequest / TXpertMarketplaceAccessStatus）
- 结构（作用域）：`ExploreScopeService` 只读派生 `activeScope`（直通 ScopeService.activeScope）、`isTenant`（level === RequestScopeLevel.TENANT）、`organizationName`、`key = ${userId}:${tenantId}:${level}:${organizationId（仅组织态）}`
- 结构（切换载荷）：`ExploreScopeSelection = { kind: 'tenant' } | { kind: 'organization', organization }`；`choose(organizationOnly?)` 返回 boolean（取消为 false）；`choose(true)` 只允许组织
- 结构（市场三态）：`accessStatus ∈ { not_requested, requested, approved, rejected, accessible, owned }`；`canUseExpert` 只认 owned|accessible|approved；`requested` 按钮禁用；申请 reason 上限 500（null = 取消，'' = 无理由）
- 生产方：`ExploreScopeService.choose()`（→ ExploreScopeDialogComponent → ScopeService.switchToTenant / switchToOrganization）；`XpertMarketplaceService.requestAccess(xpertId, {reason})`；accessStatus / canReview / reviewableCount / initializationAccess / preflight 均由服务端裁决
- 主要消费方：壳、广场、应用详情、模板详情四页均以 `scope.key()`（广场另拼 `language()`）为 effect 触发源重取并丢弃旧响应；广场 `handleExpertAction` 三分支；审批对话框关闭时 `changed` 回传决定是否重取
- 业务用途：让「租户 ↔ 组织」浏览与「申请 → 审批 → 可用」的可见性按作用域收敛；前端只做分级展示，不做权限推断
- 关键约束：`key` 是切换唯一比对键；切换动作不初始化任何资源；租户态模板详情不请求 readiness；新增页面忘接 `key()` 会在切换后停留旧数据
- 详细流向：见 .module-experts/前端专题/探索广场专家/implementation/01-架构.md（关键不变量与组件分析）与 C1-能力契约.md（§1.1 / §1.2）
