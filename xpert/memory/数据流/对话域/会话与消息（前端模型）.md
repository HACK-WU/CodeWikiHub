【数据流｜会话与消息（前端模型）】
- 实体类型：前端模型（全部为「内存态 + 契约 DTO 投影」：signal/computed/linkedModel；无 DB/ORM/持久化层）
- 结构：IChatConversation（id/xpertId/threadId/status:'busy'|'idle'/messages/executions/task/options.parameters）、TCopilotChatMessage（IChatMessage & {event?/error?/expanded?}）
- 结构（续）：PendingFollowUp（mode:'queue'|'steer'，前端独有）、ChatMessageEventTypeEnum（17 个流事件）、ChatMessageStepCategory（List/WebSearch/Files/Program/… 渲染分发键）
- 生产方：历史 GET /api/chat-conversation/:id?relations=messages… 与 GET /api/ai/conversations/:id/messages；增量走 SSE（ChatService.chat / executeChatRequest）与遗留 socket（ChatGatewayEvent）
- 生产方（前端）：sendMessage 先乐观 appendMessage(humanMessage, id=uuid)；ON_MESSAGE_START 插入 ai 占位（status:'thinking'）后把分片就地合并进尾消息
- 主要消费方：ChatService.messages() → filterLatestMessages 去重合并（每父链保留 createdAt 最新子节点、原顺序返回）→ ai-message/thought/canvas/component-message 渲染分发
- 主要消费方（跨域）：Studio 预览与 @shared/chat 复用同族消息结构——filterLatestMessages 是共享纯函数契约，改去重语义会双向回归
- 业务用途：对话内容本体——把历史、流式增量、执行记录与反馈组装为可持续渲染的会话视图
- 关键约束：前端无持久化、重进以历史补拉为准；busy 态由 answering/localChatRequestActive 驱动；执行记录纯投影「零新增数据」
- 关键约束（续）：断流由 startJoinedRunStream(threadId, runId, lastEventId) 1s 重连续传；socket 分支 2s 无 ack 原样重发（[推测] 重发可能造成重复回合）
- 详细流向：见 .module-experts/前端专题/对话前端专家/implementation/03-数据流转.md（结构清单见 04-模型.md §4）
