【数据流｜目标与基线与能力版本】
- 实体类型：表（4 张：`agent_evolution_target` / `_capability_version` / `_capability_bundle` / `_active_pointer`）
- 结构 `agent_evolution_target`：`targetId`、`providerKey`、`status`、`providerVersion`、`artifactSchemaVersion`、`descriptor`(json 快照)；**UQ `(tenantId, organizationId, targetId)`**
- 结构 `agent_evolution_capability_version`：`versionId`（= `${targetId}:${changeId}`）、`targetId`、`sequence`(int)、`artifactHash`、`sourceCandidateId`(nullable)、`value`(json)；**UQ `(…, versionId)`** ＋ **UQ `(…, targetId, sequence)`**；**不可变**——hash 变即抛 `Immutable capability version`，重试只返回旧行
- 结构 `agent_evolution_capability_bundle`：`bundleId`、`bundleHash`、`value`(json)；UQ `(…, bundleId)`、**非唯一** idx `(…, bundleHash)`
- 结构 `agent_evolution_active_pointer`：`pointerId`、`targetId`、`scopeType`/`scopeKey`、`channel`、`activeVersionId`、`revision`(int)、`value`(json)；**UQ `(…, targetId, scopeType, scopeKey, channel)`**；`channel='production'` 的行才代表生效版本
- 生产方：`AgentEvolutionStore.upsertTarget`（← POST `/targets/synchronize`）、`EvolutionBaselineService.publish`（`previewBaseline` 后铺初版）、`EvolutionPublicationExecutor.package`（调用方事务内分配 `CapabilityVersion` + `PUB-<changeId>`）、`saveBundle`（runtime `createBundle` 与评估双 bundle）、`EvolutionRuntimeStore.activatePointerCas/rollbackPointerCas`
- 主要消费方：`AgentEvolutionRuntimeService.resolveExecutionPlan`（生产版本唯一入口，无指针即 404）、`getCapabilityBundle/getCapabilityVersion`、GET `/capability-versions|/capability-bundles|/active-pointers`、baseline `inspect` 的 `managed_release` 判定、`createProposal` 的 `production_baseline_required`
- 用途：「不可变仓库 + 一行可变指针」——版本与束只写不改，指针是全模块唯一生效点（发布本身不改任何 Agent 运行时行为，切换发生在消费方 `resolve` 时）
- 边界：`revision` 是**应用层版本列**（`expectedRevision + 1` 手写），不是 `@VersionColumn`；列与 `value` JSON 的重复字段是查询副本，DB 层无一致性约束；无外键、无软删
- 增长面：`resolveExecutionPlan` 每次解析都 `createBundle` **新增一行**（`bundleHash` 非唯一、无 TTL / 清理）
