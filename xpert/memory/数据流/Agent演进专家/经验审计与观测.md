【数据流｜经验审计与观测】
- 实体类型：表（3 张：`agent_evolution_experience` / `_audit_event` / `_runtime_observation`）
- 结构 `experience`：`experienceId`(`EXP-<uuid>`)、`targetId`、`sourceReleasePackageId`、`status`、`scopeType`/`scopeKey`、`value`(json，`evidence` 内含生产观测数与稳定天数)；**UQ `(…, experienceId)`**；idx `(…, targetId, scopeKey, status)`
- 结构 `audit_event`：`auditId`、`releasePackageId`(nullable)、`candidateId`(nullable)、`action`、`value`(json：`actorId`/`actorRole`/`summary`/`occurredAt`)；**UQ `(…, auditId)`**、非唯一 idx `(…, releasePackageId)`；baseline 类审计两者皆空
- 结构 `runtime_observation`：`observationId`(`OBS-<uuid>`)、`targetId`、`deploymentId`(nullable)、`executionId`、`severeError`(boolean)、`scopeType`/`scopeKey`、`value`(json)；**UQ `(…, observationId)`**、idx `(…, targetId, deploymentId)`
- 生产方：`saveAudit`（governance 审计助手、`change.service.audit`、baseline publish、runtime store 的自动暂停 / CAS / 覆盖创建与消费、夹具）、`EvolutionRuntimeStore.saveRuntimeObservation`（按 `observationId` 幂等，**同事务**内锁 deployment 行累加统计）、`saveExperience`（**仅** `POST /experiences` → `createExperience`，按 `sourceReleasePackageId` 去重复用 id 与 `createdAt`）
- 主要消费方：GET `/audit-events`、GET `/experiences`、GET `/runtime-observations`、`getDashboard` 的 `audits`、四道闸门（依赖 deployment 统计而非观测表本体）
- 用途：三表分职——`audit` **留痕**（只追加）· `experience` **沉淀**（需 release `active` ＋ 生产闸门达标，人工创建）· `runtime_observation` **观测**（驱动统计与 `severeError` 自动暂停）
- 边界：三表**都没有 TTL 与清理任务**（模块内 `@Cron`/`DELETE FROM`/`retention`/`cleanup` 全 0 命中）；`experience` 与 `learning_event` 之间**没有代码连线**（闭环只在数据形状上成立）；`deploymentId` 为空的观测**只入观测表、不累加统计**（静默跳过）
- 系统主体动作：auto-pause 写 `actorId:'agent-evolution-runtime'`、`actorRole:'system_safety_guard'`、`auditId: AUD-<observationId>-auto-pause`；`auditId` 常为确定性字符串（`AUD-<releasePackageId>-activate`、`AUD-<overrideId>-consumed`）与随机 `AUD-<uuid>` 混用
