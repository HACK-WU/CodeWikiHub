【数据流｜变更与生命周期八表】
- 实体类型：表（8 张：`agent_evolution_learning_event` / `_diagnosis` / `_event_cluster` / `_proposal` / `_candidate` / `_dataset_snapshot` / `_evaluation_run` / `_approval`）
- 结构 `learning_event`：`eventId`、`idempotencyKey`、`targetId`、`bundleHash`、`scopeType`/`scopeKey`、`value`(json)；**UQ `(…, idempotencyKey)`**；idx `(…, targetId, scopeType, scopeKey)`；`reviewStatus ∈ pending|ignored|golden`
- 结构 `proposal` / `candidate`：proposal 有 `requestId`(nullable)、`proposalId`(`PROP-<changeId>`)、`revision`(int **恒 1**)、`targetId`、`status`、`value` —— **UQ `UX_evolution_proposal_request(tenant, org, targetId, requestId)`** ＋ UQ `(…, proposalId, revision)`；candidate 有 `candidateId`、`targetId`、`artifactHash`、`status`、`value`，UQ `(…, candidateId)`、非唯一 idx `(…, artifactHash)`，artifact 与 definition **双不可变**
- 结构 `evaluation_run` / `approval`：evaluation_run 有 `runId`、`candidateId`、`status`、**`gatePassed`(boolean 冗余判据列)**、`value`，UQ `(…, runId)`；approval 有 `approvalId`、`candidateId`、`candidateHash`、`decision`、`value`，UQ `(…, approvalId)`，**无 `(candidateId, actorId)` 唯一索引**（同 actor 改判靠应用层拦）
- 结构 `diagnosis` / `event_cluster` / `dataset_snapshot`：diagnosis（`diagnosisId`、`correctionSignature`、`value`）；event_cluster（`clusterId`、`correctionSignature`、`status ∈ collecting|proposal_ready`，同签名命中**复用 `clusterId`** 并取并集）；dataset_snapshot（`snapshotId`、`datasetId`、`snapshotHash`、`value`，**无 scope 列**，`snapshotHash` 只哈希 `caseId/revision/evidenceRef` 三字段）
- 生产方：`saveLearningEvent`（运行时能力 `ingestLearningEvent`；**无 HTTP 写端点**，HTTP 只有 PATCH 复核 `reviewStatus`）、`AgentEvolutionAnalystService.diagnose`（`DIA-<uuid>`）、`EvolutionChangeStore.create`（`.orIgnore()` ＋ 复读 digest 比对）/`save`/`saveEvaluation`、`saveApproval`（`APR-<uuid>`）、`saveDataset`
- 主要消费方：`EvolutionChangeStore.assemble`（从 proposal/candidate/evaluation_run/approval/release_package **五表拼装** `EvolutionChange`）、`EvolutionChangeService.prepare` 的学习证据四重门、`EvolutionPublicationExecutor` 的三绑定过滤、`reviewHumanApprovals` quorum、GET `/learning-events|/diagnoses|/clusters|/proposals|/candidates|/datasets|/evaluations`
- 用途：让「请求身份 / 候选 / 评估 / 审批 / 发布」各自为自己的阶段权威（变更本体从不整表落库），并让学习信号可幂等入账、可人工分类
- 边界：`learning_event.bundleHash` 只是随事件带来的字符串，仓库内**没有**把它 join 回 `capability_bundle` 的查询；`proposal.revision` 恒 1（不会出现 revision 2）；`dataset_snapshot`/`evaluation_run` 无 scope 列，跨组织隔离只靠 `tenantId/organizationId`，scope 一致性由 `value.scope` + `sameScope` 应用层校验
