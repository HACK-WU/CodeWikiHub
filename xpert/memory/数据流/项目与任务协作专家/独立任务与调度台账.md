【数据流｜独立任务与调度台账】
- 实体类型：表（`xpert-task` 6 张：任务主体 + 模板 + 自动任务两表 + 便签 + 执行台账）
- 结构 `xpert_task`：`name(100)`/`schedule(50)`/`options json`/`timeZone`/`prompt`/`status varchar(20) ∈ paused|archived|scheduled`/`statusReason text`/`runtimeState json`/`xpertId`（FK CASCADE）/`agentKey`/`projectId uuid`（FK CASCADE）/`runAsUserId`（FK User RESTRICT）/`pendingRunAsUserId`+`RequestedById`+`RequestedAt`+`pendingRunAsConfigurationHash(64)`/`deletedAt`（`@DeleteDateColumn`）——**无版本列**
- 结构 `xpert_task_execution`：唯一 `uq_xpert_task_execution_occurrence(taskId,occurrenceKey)` + `@Index(status,leaseExpiresAt)`；`scheduledAt`/`status varchar(16) default 'pending'`/`ownerId(128)`/`leaseExpiresAt`/`attempt default 0`/`conversationId`/`executionId`/`startedAt`/`completedAt`/`lastError`/`failureCode(64)`（仅允许 `'LOCAL_RUNTIME_UNAVAILABLE'`）
- 结构 `xpert_task_template`：唯一 `uq_xpert_task_template_source_scope_key(source,tenantId,organizationId,createdById,key)`；`title(160)`/`prompt json`（字符串或 I18nObject）/`defaultOptions json`/`icon(64)`/`builtin default false`
- 结构 `auto_task` / `auto_task_template`：`title(160)`/`prompt text`/`repo(255)`/`branch(255)`/`schedule(255)`/`frequency varchar(32) default 'daily' ∈ once|daily|weekly`/`enabled default true`/`templateId`/`runAt`/`timeZone`/`pushChannel`/`params json`/`lastRunAt`/`nextRunAt`；template 侧唯一 `uq_auto_task_template_scope_key(tenantId,organizationId,createdById,key)`（内置约 18 条 seed）
- 结构 `schedule_note`：`title(160)`/`content text`/`date date`（`YYYY-MM-DD`）/`remindAt`/`type varchar(16) default 'note' ∈ note|task`/`status varchar(16) default 'pending' ∈ pending|done`
- 生产方：`CreateXpertTaskCommand` 处理器（`schedule` 置 null、`status=SCHEDULED`，入队 `xpert-task-scheduler`）、`XpertTaskService.*HttpTask`（schedule/pause/archive/unarchive/test/soft/recover）、`ScheduledTaskExecutionCoordinator.claim/markRunning/bindRun/refreshLease/finish`（`insertIfAbsent` 用 `.orIgnore()`）、模板与便签端点、`runDueAutoTasks`
- 主要消费方：`XpertTaskService` 进程内 cron 与 `onModuleInit` 重建（只重建 `options || schedule` 存在者）、`platform.scheduler` 视图与 `GET /schedule/*`、`recoverExpiredScheduledTaskExecutions`（下一分钟 `@Cron('30 * * * * *')` 接管、`attempt+1`）、跨域链 `ChatConversationUpsertCommand → XpertAgentExecutionUpsertCommand → XpertChatCommand`
- 关键约束：**三套调度并存**——进程内内存 `SchedulerRegistry` cron + 队列 `xpert-task-scheduler` + `@Cron('0 * * * * *')` auto-task 扫描（Redis 锁 `scheduler:xpert-auto-task` TTL 5 分钟）；租约 `SCHEDULED_TASK_LEASE_MS = 5 分钟`，`ownerId = XPERT_INSTANCE_ID || HOSTNAME || randomUUID`，终态或未过期租约返回 `null`
- 状态语义坑：`unarchive → PAUSED` 且不排程、`recover` 只软恢复不重建 job（恢复后必须显式 `PUT /:id/schedule`）；`QueryXpertTaskHandler` 取不到本地 job 时把返回体 `status` 伪造成 `PAUSED`，与库内可能不一致——排障以 DB `status` 与 `xpert_task_execution` 为准
- 业务用途：跨项目周期/自动化排程的**唯一入口**（旧版项目自动化下线后的替代路径）+ 执行台账与租约（同一时段至多一次）
