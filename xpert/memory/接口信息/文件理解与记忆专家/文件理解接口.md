【接口信息｜文件理解接口】
- 子功能：上传落地（建句柄 ＋ 启动理解）、句柄与解析状态、检索/读取/预览、解析重试、删除、会话附件列举
- 所属模块：文件理解与记忆专家（子专家：文件理解）
- 接口列表（一）`FileUnderstandingController` 真实前缀 `/api/ai`（`@Controller()` 空前缀 ＋ `RouterModule{path:'/ai'}`），类级 `@Public()` ＋ `@AllowClientSecretBindings(ENTERPRISE_XPERT)` ＋ `@UseGuards(ApiKeyOrClientSecretAuthGuard)`，共 **8 条**：
  - GET `/api/ai/files/:fileId`（授权后的句柄，operation `read`）、GET `/files/:fileId/status`（`GetFileParseStatusQuery` → `{fileId,status,error,parsedAt}`）
  - POST `/files/:fileId/parse/retry`（`RetryFileParseCommand` → 直接 `ParseFileAssetCommand`，**无状态门禁**，operation `parse`）
  - POST `/files/:fileId/search`（有 query 走「向量召回 ＋ `ILIKE` 关键词」RRF 融合；无 query 按 `orderNo` 顺序列举）、POST `/files/:fileId/read`（`chunkId|orderNo`，缺省 0；缺 chunk 返回 `null` 且是**终态 not-found**）
  - GET `/files/:fileId/preview`（只 select 轻字段：summary 截 900 字、artifact ≤12、chunk ≤8；**资产不存在返回 `null` ＋ HTTP 200 而非 404**）
  - GET `/api/ai/conversations/:conversationId/files`（先 `assertConversationAccess({kind:'conversation'},'read')` 再 `ListConversationFilesQuery`）
  - DELETE `/api/ai/files/:fileId`（`DeleteFileAssetCommand` → `FileAssetDeletionService.delete` 全链路清理）
- 接口列表（二）上传/删除入口（跨域 `ContextsController`，同前缀 `/api/ai`）：
  - POST `/api/ai/contexts/file`（multipart `file` ＋ `target`/`purpose`/`parseMode`/`conversationId`/`threadId`/`projectId`/`xpertId`；**`workspacePath` 被显式置空**；返回 `AgentFile`）→ `UploadFileCommand` → `CreateFileAssetCommand` → `EnqueueFileParseCommand`
  - DELETE `/api/ai/contexts/file/:id`（`:id` 是 **storageFileId**：有 FileAsset 走 `resolve({operation:'delete'})` ＋ `DeleteFileAssetCommand`；无则 `assertStorageFileOwner(id)`（**严格 owner、无管理员豁免**））
- 关键约束：每个方法先 `authorizeFile(fileId, operation)` → `FileAssetAccessService.resolve({locator, authority:'current-owner', operation})`（`operation ∈ read|attach|parse|write|delete`）；**「不存在」与「无权限」不区分**，统一 403 `FileAssetAccessDenied`（防枚举）；公共 Xpert 会话场景额外要求 `fileAsset.userId === scope.createdById`；`target` 只允许服务端管理的 storage target（改 `directory`/`prefix` 或加键即 400）
- 主要错误码：403 `FileAssetAccessDenied` / 空消息 `ForbiddenException`；404 `File asset "…" not found`（仅 status 在授权通过后）；400 `ExternalUploadTargetInvalid` / `Chat request file is too large`(25MB) / `Invalid chat request file data URL`；409「同一 FileAsset 的 link 复用于另一项目」；解析失败**不抛 HTTP 错**，落 `status='failed'` ＋ `metadata.understandingErrorCode` 三态（`…embedding_unavailable`/`…vector_index_failed`/`…parse_failed`）
- 邻域提醒：`GET /api/ai/conversations/:id/files` 与 `/api/ai/conversations/:id/workspace/files` 是两条不同路由（有 spec 断言二者不互相遮蔽）
