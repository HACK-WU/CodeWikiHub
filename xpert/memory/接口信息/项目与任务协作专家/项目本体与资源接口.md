【接口信息｜项目本体与资源接口】
- 子功能：项目 CRUD 与生命周期、类型目录与分类快照、成员/角色与 token 邀请、资源挂载（助手/工具集/知识库/附件/会话）、内容与技能（`project.md`、`skills/`）、工作区文件与资产索引、活动流与工作台总览、旧版自动化（只读遗留）
- 所属模块：项目与任务协作专家
- 接口列表（前缀 `/api/xpert-project`，共 102 条真实路由；`XpertProjectController` 96 = 自身 73 + 继承 planning 23，已扣 4 条注释 VCS/GitHub 路由）：
  - 项目与类型：`POST /`（201 创建；直选 `toolsetIds`/`knowledgebaseIds` 被有意忽略）・`GET ''`/`/my`/`/count`/`/pagination`/`/available`/`/overview`・`GET /types`、`/type-entry`・`GET|PUT /:id`・`GET /:id/access`・`POST /:id/archive`・`DELETE /:id/soft`・`PUT /:id/recover`・`DELETE /:id`（物理清除）・`POST /import`、`GET /:id/export`、`POST /:id/duplicate`・`PATCH /:id/owner`・`PUT /:id/workspace`（恒定 400 `ProjectWorkspaceBindingDeprecated`）
  - 成员与邀请：`GET|PUT|POST /:id/members`、`PATCH|DELETE /:id/members/:userId`・`GET|POST /:id/invitations`、`DELETE /:id/invitations/:invitationId`・`POST /invitations/accept`、`POST /invitations/decline`（无项目守卫，token 驱动）・`POST /:id/admin/intervene`（组织级 `ORG_USERS_EDIT`/`ALL_ORG_EDIT`）
  - 资源与内容：`GET|PUT|DELETE /:id/xperts[/:xpert]`、`GET /:id/available-xperts`、`PUT /:id/assistant`・`GET|PUT|DELETE /:id/toolsets[/:toolset]`、`/:id/knowledges[/:kb]`、`/:id/attachments[/:file]`・`GET /:id/conversations`・`GET|PUT /:id/content/instructions`・`GET|POST|PATCH|DELETE /:id/content/skills[/install|/upload|/file]`
  - 文件·资产·活动·自动化：`GET|PUT|DELETE /:id/workspace/files`、`/:id/workspace/file[/upload]`・`GET /:id/files`、`POST /:id/file/upload`、`DELETE /:id/file`・`GET /:id/assets`、`/:id/assets/tree`、`POST|PUT|DELETE /:id/assets[/:assetId]`・`GET /:id/activities`・`GET /:id/automations`、`/:id/automations/runs`（可读）与写路径 `POST|PUT|DELETE /:id/automations*` 及 `.../run`（全部 410 Gone）
- 守卫口径（四层）：类级 `@Public()`（**只跳过全局 JWT 守卫，≠放行**）+ `@UseGuards(XpertProjectAuthGuard, XpertProjectFeatureGuard, XpertProjectPermissionGuard)` + `@ProjectPermission(XPERT_PROJECT_VIEW|CREATE|EDIT|MANAGE)`；方法级再叠 `XpertProjectGuard`，仅 `DELETE /:id` 与 `PATCH /:id/owner` 加 `XpertProjectOwnerGuard`；最后业务断言在 `XpertProjectAccessService`（`assertProjectWritable` 拒 archived 编辑、`assertCanPurge` 要求 `owner` + `archived`）；相邻前缀 `/api/xpert-task`（35 条无守卫，靠 `*HttpTask` 断言）与 `/api/business-area`（读无守卫，写 `RoleGuard`+`SUPER_ADMIN`/`ADMIN`）
- 关键文件：`project.controller.ts`（96 条，继承 `project-planning.controller.ts` 的 23 条）・`project-invitation.controller.ts`（2 条）・`project-admin.controller.ts`（1 条）
- 关键约束：`PUT /:id/workspace` 恒定 400；物理 purge 要求 `owner` + `archived` 且无 `uploaded/scanning/parsing/processing/queued` 文件（否则 400）；邀请库内只存 `tokenHash`（`select:false` + `@Exclude`），明文只回一次；移除成员先批量 `pause` 其 `XpertTask` 再 `emitAsync('xpert-project.member-removed')`；受治理路径（`project.md`、`skills/`）不能走普通文件 API；技能 ZIP ≤ 25MB、工作区文件 ≤ 10MB；`PATCH :id/content/skills` 缺布尔 `enabled` → 400 `Error.ProjectSkillEnabledRequired`
- 主要错误码：403（`assertCanRead/Edit/Manage`）・400 `ProjectOrganizationRequired`/`ProjectMemberAlreadyExists`/`ProjectInvitationInvalid`/`ProjectInvitationNotPending`・403 `ProjectInvitationEmailMismatch`・404 `ProjectInvitationNotFound`・410（自动化写路径）
