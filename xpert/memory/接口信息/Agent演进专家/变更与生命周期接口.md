【接口信息｜变更与生命周期接口】
- 子功能：变更提交（Zod 严格校验）与夹具提交、生命周期投影读取（列表 / 富记录 / 单条）、评估 / 审批 / 发布三条写路径（代理后回读投影）、基线只读检视
- 所属模块：Agent 演进专家（`EvolutionLifecycleController`，类级 `@UseGuards(PermissionGuard)`，前缀 `/changes`；另 `EvolutionBaselineController` 前缀 `/baselines`）
- 接口列表（8 ＋ 1 条，真实前缀 `/api/agent-evolution/changes` 与 `/api/agent-evolution/baselines`）：
  - POST `/changes`（`EVOLUTION_MANAGE`；`evolutionSubmissionSchema` 全对象 `.strict()`，多余字段 400 `invalid_strategy_submission` → 写 Proposal 行 ＋ 投递 `change_preparation` job）
  - POST `/changes/conformance-template`（`EVOLUTION_MANAGE` ＋ **夹具 404 门禁**；`fixtureInput` 生成输入后复用 `prepare`）
  - GET `/changes`（`lifecycle.list` → `lifecycleRecord()` 投影分页，`pageSize` 上限 200）
  - GET `/changes/records`（富变更记录，可带 `targetId`）
  - GET `/changes/:id`（单条投影）
  - POST `/changes/:id/evaluations`（可传 `datasetSnapshotIds`）
  - POST `/changes/:id/decisions`（候选哈希 ＋ `evaluationRunId` ＋ `strategyHash` **三绑定**）
  - POST `/changes/:id/publication`（产出发布包 `PUB-<changeId>`）
  - GET `/baselines/:targetId`（`EVOLUTION_VIEW｜XPERT_EDIT｜EVOLUTION_MANAGE` **三位任一**，是「管理员只做读巡检」的唯一通道；不写库、返回体带 `canManage`）
- 关键约束：读一律经 `lifecycleRecord()`（不落库的纯函数投影，`release.status` **优先**于 `change.status`）；写路径由 `EvolutionLifecycleService` 代理 `EvolutionChangeService` 后回读投影；变更「assembled, never persisted whole」（由 proposal/candidate/evaluation_run/approval/release_package 五表拼装）
- 主要错误码：400（`change_not_found`、`invalid_strategy_submission`、`strategy_not_allowed`、`learning_evidence_gate_failed`、`review_snapshot_mismatch`、`immutable_approval_changed`、`publication_not_in_strategy` 等）
- 逐端点明细：见 .module-experts/后端专题/Agent 演进专家/implementation/05-接口.md 与 sub-experts/变更与生命周期子专家/{C0,C1}.md
