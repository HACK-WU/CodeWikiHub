【接口信息｜认证接口与守卫矩阵】

- 子功能：认证端点（策略面 + 生效面）、邀请/返利/引导端点、OIDC/SSO 端点、前端服务与守卫准入矩阵
- 所属模块：认证与引导专家（前端专题）
- 接口列表：
  - 策略面 6 条（`XpPasswordAuthStrategyOptions` 默认表，`baseEndpoint='/api/auth/'`，生产未注册、仅 spec 覆盖）：POST /api/auth/custom/login ｜ POST /api/auth/custom/register ｜ POST /api/auth/custom/request-pass ｜ PUT /api/auth/custom/reset-pass ｜ DELETE /api/auth/custom/logout ｜ POST /api/auth/custom/refresh-token
  - 生效面（`AuthStrategy`（name=`email`）→ `AuthService`，真实前缀 `/api/auth/*`）：POST /login、/signup、/register、/request-password、/reset-password、/sso/bind/register ｜ GET /refresh、/verify?token=、/authenticated、/sso/providers
  - 非认证前缀同域端点：GET /api/invite/validate、POST /api/invite/user、GET /api/referral/availability|/validate、GET|POST /api/tenant/onboard、GET|POST /api/system/setup/plugins
  - OIDC/SSO：GET|POST {XP_API_BASE_URL}/oidc/interaction/{interaction}/consent（后者原生整页表单、非 XHR）、GET /api/auth/sso/bind/challenge、POST /sso/bind/complete、POST /sso/bind/register、GET|POST /sso/bind/current-user/{challenge,complete}
- 前端服务与守卫契约：`XpAuthService` 11 个方法全部按 `strategyName` 参数化（未注册名字同步抛 `TypeError`）；守卫族——`authGuard`（只判 `!!store.token`、不发请求；失败先 `await authStrategy.logout()` 清本地再 → `/auth/login?returnUrl=<原 URL>`）、`no-auth.guard`（`NoAuthGuard` 两段判 + `accept-invite` 且 query 同时含 email+token 前无条件放行，其余已登录 → `/home`）、`invite.guard`（`route.data.expectedPermissions` 命中 `hasPermission` 且 `selectedOrganization.invitesAllowed`，不满足 → `/`）、`onboard.guard`（`TenantService.getOnboard()`：有 tenant → `/home/`、探测 error → `/onboarding/unknown`、两者皆无放行）、`dirty-check`（`CanDeactivateFn<IsDirty>` + 确认框，类版 `DirtyCheckGuard` 已 `@deprecated`）
- 关键约束：`/api/auth/custom/*` 只存在于历史 ki 记忆与 `password-strategy.spec.ts` 的 baseEndpoint 用例，生产源码零引用、后端源码核实不存在——沿用即「静默 404 → 统一兜底文案」的难查故障；端点口径以生效面为准，与后端冲突时以 .module-experts/后端专题/身份与权限专家 为准
- 逐端点明细：见 .module-experts/前端专题/认证与引导专家/implementation/05-接口.md
