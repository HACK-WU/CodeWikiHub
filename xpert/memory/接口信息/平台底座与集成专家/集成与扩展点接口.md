【接口信息｜集成与扩展点接口】
- 子功能：集成实例 CRUD/试连/provider 目录/select-options、扫码授权会话（begin→poll→complete→cancel）、视图扩展七条协议路由（槽位清单、视图数据、manifest、remote component 入口、参数选项、动作、文件动作）、connector 受限集成面（无 HTTP）
- 所属模块：平台底座与集成专家（子专家：集成与扩展点）
- 前缀与协议口径：全局前缀 `api`；`IntegrationController` 与 `ViewExtensionController` 均 `@Controller()` 空前缀，路径段全由 `RouterModule.register`（`/integration`、`/view-hosts`）或 `@Controller('qr')` 给出；`ViewExtensionRoutes` 是**无装饰器的共享路由类**（同族入口另有两个：`/api/ai/groups/:groupId/workbench` 与移动端 `deployment.viewHostsPath`）
- 接口列表（集成 7 条，登录态；类级仅 `TransformInterceptor`，靠全局 `AuthGuard`）：
  - 读：GET `/api/integration`（分页，`items` 逐个包 `IntegrationPublicDTO`，`options` 被 `@Exclude`）、GET `/select-options`（`provider` 过滤 + `features` 逗号分隔，**features 的 DB 过滤被注释**改 JS `every`）、GET `/providers`（`INTEGRATION_PROVIDERS` 常量全集 + 当前组织策略 `meta`）
  - 写：POST `/test`（当前组织策略 `validateConfig`，异常统一 **500**）、POST `/api/integration`（**201**，派 `IntegrationUpsertCommand`）、PUT `/:id`（**202**）、DELETE `/:id`（**202**，先 `runStrategyDeleteHook` 再删行）
- 接口列表（扫码 4 条，类级 `PermissionGuard` + `INTEGRATION_EDIT`，`Cache-Control: no-store`）：POST `/api/integration/qr/providers/:provider`（回 `{id,authorizationUrl,expiresAt,intervalSeconds}`）、GET `/qr/sessions/:id`（**只回 `{status}`**，绝不含 `deviceCode`/`options`）、POST `/qr/sessions/:id/complete`（要求 `authorized`，回 `{id,name,slug,provider,outcome:created|reused}`）、DELETE `/qr/sessions/:id`（幂等）
- 接口列表（视图 7 条，类级 `@Public()` + `ApiKeyOrClientSecretAuthGuard` + `@AllowClientSecretBindings(ENTERPRISE_XPERT)`，**每个入口自带鉴权边界**）：GET `/api/view-hosts/:hostType/:hostId/slots/:slot/views`（`?isDraft`，清单 60s 缓存）、`…/views/:viewKey/{data,manifest,remote-component/entry}`、`…/views/:viewKey/parameters/:parameterKey/options`、POST `…/views/:viewKey/actions/:actionKey` 与 `…/actions/:actionKey/file`（`FileInterceptor('file')`）
- 关键文件：`integration/{integration.controller.ts,integration-qr.controller.ts,integration.service.ts,integration-qr.service.ts,commands/handlers/upsert.handler.ts,connector-app/connector-app-integration.service.ts}`、`view-extension/{view-extension.controller.ts,view-extension.service.ts,view-extension.utils.ts,host-definition.registry.ts}`
- 关键约束（集成写路径）：次序固定「策略 `validateConfig`（只回填 `name/description/slug/provider/options/features` 六字段）→ 生命周期钩子（provider 变化先 `previous.onDelete`）→ 落库」，钩子抛错整体不落库并降级 400；凭据只放 `options`，只有列表端口径剪掉它
- 关键约束（扫码与视图）：会话只在 Redis（按 `tenant:org:user:provider:purpose` 收敛同键旧会话，全部步骤在 `RedisLockService.runWithLock` 内串行），`complete` 以会话 id 作集成 id 换崩溃重试幂等；视图解析链 `assertEnterpriseXpertViewHost → 注册表命中 → resolve → canRead` 再 `normalizeManifest`（公共键 `providerKey__manifestKey`、`dataSource.mode` 强制 `platform`、`title` 必须有非空 `en_US`、`runtime.featureProviders` 由宿主重算）
- 主要错误码：404 `Unknown view host` / `View host … was not found` · 403 `No permission to access this view host` / `The current Project role does not allow this extension action` · 400 `file is required`、策略校验失败 · 404 `Error.IntegrationQrExpired` · 409 `INTEGRATION_QR_BUSY`（锁未拿到，属正常表现）· 502 `Error.IntegrationQrUnavailable` / `Error.IntegrationQrPollFailed` · 500（`POST /test` 兜底）
