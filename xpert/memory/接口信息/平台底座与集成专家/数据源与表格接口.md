【接口信息｜数据源与表格接口】
- 子功能：数据源 CRUD 与下拉、ad-hoc/已落库试连、catalog/schema 元数据、SQL/OLAP/能力查询代理、个人认证（30 天）、xlsx-csv 装载、xpert-table 逻辑 Meta 与物理表激活/改名/删除、行列操作（无 HTTP，走工作流节点）
- 所属模块：平台底座与集成专家（子专家：数据源与表格）
- 接口列表 A（`/api/data-source` **16 条**；`@Controller()` + `RouterModule.register('/data-source')`，类级 `@Permissions(DATA_SOURCE_EDIT)`）：
  - 列表/下拉：GET `/api/data-source`（覆盖为 `DATA_SOURCE_VIEW` + `ClassSerializerInterceptor`——**唯一脱敏出口** `DataSourcePublicDTO`）、GET `/sql-select-options`、GET `/sql-schema-select-options?dataSource=`
  - 单条/测试：GET `/:id`（**直出实体、无 DTO**；`$relations=["authentications"]` 即回显凭据）、PUT `/:id`（`dsService.update` 后发 `DataSourceUpdatedEvent`，留 `@todo`）、POST `/ping`（body 即完整定义，**不落库**）、POST `/:id/ping`（以库内为底、请求体覆盖，`authentications[].userId` 强制改写为当前用户）
  - 元数据/查询：GET `/:id/catalogs`、GET `/:id/schema?catalog&table&statement`、POST `/:id/query`（body `{query}`，转发 `Accept-Language`）、POST `/:id/olap`（`@HttpCode(200)`，**整体恒 200**，逐项读 body `status`）、POST `/:id/capabilities/query`（`DATA_SOURCE_VIEW`，键名白名单先校验）
  - 认证/装载：GET|POST|DELETE `/:id/authentication`（按 `{tenantId,dataSourceId,userId}` upsert，`validUntil = now+30d`）、POST `/:id/load`（`FileInterceptor('file')` + `params` 内 `sheets` JSON）
- 接口列表 B（`/api/xpert-table` **6 条**；`@Controller('xpert-table')` **无 RouterModule**、类级仅 `TransformInterceptor`）：POST `/api/xpert-table`（覆写为 `upsertTable`，**保存即激活**）、PUT `/:id`（ACTIVE 改名先 `RENAME_TABLE`）、GET `/databases`（`DATA_SOURCE_VIEW`）、GET `/schemas?databaseId=`、POST `/:id/activate`（无列 400）、DELETE `/:id`（**204**，ACTIVE 先 `DROP_TABLE`，失败仅日志再软删）
- 无 HTTP 出口：`XpertTableService.insertRow/executeSql` 只经 `@WorkflowNodeStrategy(DB_SQL)`/`(DB_INSERT)` 与助手工作流暴露；`DataSourceRuntimeService.list/open` 只给插件（`@RuntimeCapabilityProvider`，capability `platform.datasource.workbench`）
- 关键文件：`data-source/{data-source.controller.ts,data-source.service.ts,utils.ts,data-source-runtime.service.ts,queries/handlers/olap-query.handler.ts}`、`xpert-table/{xpert-table.controller.ts,xpert-table.service.ts,plugins/sql/strategy.ts,queries/handlers/xpert-database-adapter.handler.ts}`
- 关键约束：代理骨架统一 `prepareDataSource`（强制 tenant+organization，否则 403 `Data source scope is required`；`authType=BASIC` 注入当前用户 `username/password` 到 `options`）→ `DataSourceStrategyQuery` → `try/finally runner.teardown()`；**无查询超时、无行数上限、无 SQL 白名单**（唯一限量是 schema 取样 `LIMIT 10`）；策略缺失**不回落**（`DataSource strategy not found for type: …`）；OLAP 有会话级 runner 复用（10 分钟）；建表列由 `columns` 映射后以 `createMode: UPGRADE` 提交
- 主要错误码：ping/catalogs **恒 500**（catalogs 常为「配置错误」）· query/capabilities **恒 400** · OLAP **恒 200** · schema 500 · 未找到认证行 404 · 无列激活 400 · `Table <name> is not active.` 400
